## Référence de l’API

Ark UI ne fournit pas de primitive de liste dédiée. Moduix construit ce composant avec l’outil officiel
[Ark factory](https://ark-ui.com/docs/guides/composition#the-ark-factory) et suit les recommandations d’Ark concernant la
[composition](https://ark-ui.com/docs/guides/composition), les [styles](https://ark-ui.com/docs/guides/styling) et les
[ref](https://ark-ui.com/docs/guides/ref).

## Anatomie

La composition habituelle côté utilisateur reste concise :

```text
List / List.Root
└─ List.Item | li
```

| Partie               | Rôle                                                                                              |
| -------------------- | ------------------------------------------------------------------------------------------------- |
| `List` / `List.Root` | Racine sémantique de la liste qui contrôle le marqueur, l’espacement, la taille et le ton.       |
| `List.Item`          | Partie facultative de type Ark pour disposer d’un slot `li` stable et de la prise en charge de `asChild`. |

## Composition

### Composition recommandée

Utilisez `<List>` pour un contenu non ordonné, et `as="ol"` lorsqu’une sémantique ordonnée est nécessaire.
N’utilisez `asChild` que pour remplacer `List` par un unique élément sémantique `<ul>` ou `<ol>`, ou
`List.Item` par un unique élément sémantique `<li>`.

### Quand créer une composition personnalisée

`List` ne fournit ni machine à états interne, ni utilitaires de structure imbriquée, ni API de rendu des marqueurs.
Pour le style courant des éléments, utilisez `className` et le CSS natif, par exemple `li::marker`.
Réservez `asChild` aux composants appartenant au code appelant qui transmettent la ref et les props et
rendent l’hôte sémantique requis.

Conservez les éléments comme enfants `li` directs. L’espacement intégré et le style des marqueurs ne s’appliquent
qu’aux éléments directs de la liste.

### Propriétés par défaut

| Prop      | Valeur par défaut    | Remarques                                                                                       |
| --------- | -------------------- | ----------------------------------------------------------------------------------------------- |
| `gap`     | `sm`                 | Espacement entre les éléments directs de la liste.                                              |
| `size`    | `md`                 | Token de taille typographique.                                                                  |
| `tone`    | `default`            | Chemin de couleur sémantique pour le texte et les marqueurs.                                    |
| `marker`  | `auto` sémantique    | `disc` pour `ul`, marqueurs de liste ordonnée du navigateur pour `ol`, ou `none`.               |
| `as`      | `ul`                 | Bascule l’hôte natif de la liste entre `ul` et `ol`.                                            |
| `asChild` | `false`              | Remplace l’hôte sémantique par l’unique élément enfant fourni par le code appelant.             |

### Comportement

- Les props de liste ordonnée telles que `start`, `reversed` et `type` sont disponibles avec `as="ol"`.
- Utilisez `marker="none"` pour masquer les marqueurs tout en conservant la sémantique de liste. Dans ce cas, `List` ajoute `role="list"`, sauf si vous remplacez explicitement `role`.
- `List.Item` est facultatif. Utilisez de simples éléments `li` lorsque le slot d’élément exporté n’apporte aucun avantage.

et les variables CSS publiques `--moduix-list-*` répertoriées ci-dessous. Cette liste de variables correspond à
l’API CSS publique.

### Points d’accroche CSS

`List` expose une surface de style volontairement réduite :

- racine : `data-scope="list"`, `data-part="root"`, `data-slot="list-root"`
- élément : `data-scope="list"`, `data-part="item"`, `data-slot="list-item"`
- `data-gap="xs" | "sm" | "md" | "lg" | "xl" | "2xl"` pour les styles dépendant de l’espacement
- `data-marker="auto" | "disc" | "decimal" | "none"` pour les styles dépendant du marqueur
- `data-size="xs" | "sm" | "md" | "lg" | "xl"` pour les styles de taille typographique
- `data-tone="default" | "muted" | "subtle" | "primary" | "destructive"` pour les chemins de couleur sémantiques
- le sélecteur natif `li::marker` pour remplacer la couleur ou l’épaisseur du marqueur
