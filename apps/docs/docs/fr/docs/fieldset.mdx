## Choisir le bon composant

Utilisez `Fieldset` pour plusieurs contrôles associés avec une seule légende. Utilisez `Field` pour un
contrôle avec sa propre étiquette, description et message de validation.

## Exemple de base

Organisez `Fieldset`, `Fieldset.Legend`, le texte explicatif ou d'erreur facultatif et les contrôles associés.

## Anatomie

```text
Fieldset.Root | Fieldset.RootProvider
├─ Fieldset.Legend
├─ grouped controls
├─ Fieldset.HelperText (optional)
└─ Fieldset.ErrorText (optional)
```

| Partie | Rôle |
| ---------------------------- | ------------------------------------------------------------------------ |
| `Fieldset` / `Fieldset.Root` | Crée un état et rend le `fieldset` natif.                   |
| `Fieldset.RootProvider` | Rend l’état `useFieldset` créé en externe.                         |
| `Fieldset.Legend` | `legend` natif et nom de groupe disponible.                                |
| `Fieldset.HelperText` | Description associée à la racine via `aria-describedby`.                   |
| `Fieldset.ErrorText` | Message de validation dans une région live polie, affiché uniquement avec `invalid`. |

## Composition

### Composition recommandée

Laissez un `Fieldset.Legend` visible à l’intérieur de la racine. Transférez directement les `disabled`, `invalid` et `id`
à la racine. Ark associe la légende, le texte d’aide présent et le texte d’erreur actif au groupe de champs.

La racine, le fournisseur, la légende, le texte explicatif et le texte d'erreur transmettent les références à leurs éléments DOM rendus.
Utilisez `asChild` avec un enfant sémantique lorsque l'hôte utilisateur doit être propriétaire de la partie.

### Quand créer une composition personnalisée

Utilisez `useFieldset` depuis `@moduix/react` avec `Fieldset.RootProvider` lorsque l’état est créé en dehors de
l’arbre rendu. Utilisez `useFieldsetContext()` ou `Fieldset.Context` dans un enfant qui doit lire cet état.
N’imbriquez pas le provider dans `Fieldset.Root` pour une même instance d’état.

### Propriétés par défaut

| Surfaces | Propriété | Par défaut |
| ----------------- | --------- | ------------ |
| `Fieldset.Root`   | `disabled` | `false`     |
| `Fieldset.Root`   | `invalid`  | `false`     |

### Notes de comportement

- `Fieldset.Legend` rend le `legend` natif, par opposition au wrapper hérité supprimé.
- Le navigateur désactive les contrôles natifs à l’intérieur d’un groupe de champs désactivé.
- Les descendants `Field` d’Ark héritent de l’état désactivé du groupe de champs. Définissez `invalid` sur les composants `Field` imbriqués
  lorsque des contrôles individuels nécessitent un état invalide.
- `Fieldset.ErrorText` n'est pas dans le DOM tant que `invalid` n'est pas vrai.
- `useFieldsetContext()` et `Fieldset.Context` fournissent aux descendants le même état Ark que `useFieldset`.
- Fieldset ne possède pas de valeur, de navigation au clavier, de rappel ou de `HiddenInput`.
- L'ancien `render` et les exportations plates telles que `FieldsetLegend` ne sont pas pris en charge ; utiliser `asChild`
  et des parties de l'espace de noms.

### Hooks de style

Chaque partie DOM possède un `data-scope="fieldset"` Ark et un `data-part` correspondant à l'anatomie. Racine et légende
fournir `data-disabled` et `data-invalid` ; moduix ajoute également des hooks `data-slot="fieldset-*"`.
Utilisez `className` pour les remplacements locaux et les variables `--moduix-fieldset-*` pour la personnalisation au niveau du thème,
en particulier le espacement interne de la légende et les tokens de bordure racine.
