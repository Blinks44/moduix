## Choisir le bon composant

Utilisez `Field` lorsqu'un contrôle nécessite une étiquette visible, un texte explicatif, un texte d'erreur
ou l'état général des `disabled`, `invalid`, `required` et `readOnly`.

- Sélectionnez **`Field`** pour un seul champ et son libellé ou texte explicatif.
- Sélectionnez **`Fieldset`** lorsque plusieurs champs associés nécessitent une légende commune.
- Utilisez un contrôle distinct lorsque les relations ARIA au niveau du champ ou l'état partagé ne sont pas requis.

## Anatomie

`Field` suit les composants d’Ark UI et conserve leurs noms dans l’API publique de moduix.

```text
Field
├─ Field.Label
├─ Field.Input | Field.Textarea | Field.Select | custom control
├─ Field.HelperText
├─ Field.ErrorText
└─ Field.RequiredIndicator
```

| Partie | Rôle |
| ------------------------- | -------------------------------------------------------------------------- |
| `Field` / `Field.Root` | Contexte racine et norme `<div role="group">`.                    |
| `Field.RootProvider` | Racine qui opère sur une instance de `useField()` créée en dehors de l'arborescence.       |
| `Field.Context` | Accès à l’état actuel du champ sans effectuer de rendu.                   |
| `Field.Label` | Une étiquette associée à l’ID du contrôle actuel.           |
| `Field.Input` | Entrée native de bas niveau dans le style Ark. De préférence `Input`.       |
| `Field.Textarea` | Zone de texte de bas niveau dans le style Ark. De préférence `Textarea`.         |
| `Field.Select` | Sélection native associée aux propriétés ARIA et d'état de champ.             |
| `Field.HelperText` | Texte explicatif inclus dans `aria-describedby`.                         |
| `Field.ErrorText` | Texte d’erreur rendu uniquement lorsque `Field` possède l’état `invalid`.     |
| `Field.RequiredIndicator` | Marqueur visuel obligatoire avec `fallback` en option.              |
| `Field.Item` | Contexte de champ pour un contrôle groupé via `value` ; sa ref pointe vers le wrapper de ligne. |

## Composition

### Composition recommandée

Conservez un libellé visible à la racine, rendez exactement un contrôle moduix principal, comme `Input`,
`Textarea` ou `NativeSelect`, et ajoutez un texte d’aide ou d’erreur si une description ou un retour de validation est nécessaire.

### Quand créer une composition personnalisée

Utilisez `Field.Item value` avec la racine `target` lorsque le champ contient plusieurs contrôles natifs,
et le libellé doit pointer vers l’un d’eux. `Field.Input`, `Field.Textarea` et `Field.Select` restent disponibles pour
une composition avancée dans le style Ark, mais le code d’application ordinaire doit utiliser les composants moduix dédiés.

### Propriétés par défaut

| Surfaces | Par défaut | Remarques |
| ------------------------ | ------------ | --------------------------------------------------------- |
| `Field` / `Field.Root` | — | Aucun comportement supplémentaire ; les valeurs par défaut d’Ark s’appliquent. |

### Comportement

- `Field.ErrorText` n'est pas dans le DOM sauf si la racine a `invalid`.
- Les longues étiquettes, le texte explicatif et le texte d’erreur reviennent à la ligne dans le champ au lieu de déborder.
- `Field.RootProvider` doit recevoir l'état de `useField()` importé de `@moduix/react`,
  et ne doit pas être imbriqué dans `Field.Root` pour la même instance de champ.
- Utilisez `Field.Context` ou `useFieldContext` de `@moduix/react` lorsqu’un contrôle personnalisé a besoin de l’état actuel du champ. Un import direct depuis Ark n’est nécessaire que pour les API de bas niveau non exportées par moduix.
- `Field.Item` transmet sa ref au wrapper de ligne moduix rendu autour de ses enfants.
- `Field` ne rend pas d’input masqué : les composants composés tels que `Checkbox` et `RadioGroup` possèdent leurs propres parties de formulaire natives.

### Points d’accroche CSS

Ark ajoute `data-disabled`, `data-invalid`, `data-readonly` et `data-required` aux parties correspondantes.
`Field.ErrorText` est rendu uniquement lorsque le contexte du champ courant est invalide. Les identifiants du texte d’aide
et du texte d’erreur sont inclus dans l’attribut `aria-describedby` du contrôle lorsque ces parties sont présentes. Chaque partie DOM
conserve également le hook stable `data-slot="field-*"`.
