## Référence API

`Sidebar` utilise [Ark UI Splitter](https://ark-ui.com/docs/components/splitter) pour le redimensionnement, l’état replié, les interactions au clavier et l’accessibilité. Son anatomie sémantique de navigation s’inspire du [Sidebar de shadcn/ui](https://ui.shadcn.com/docs/components/radix/sidebar), tandis que son contrat d’état conserve la forme d’Ark.

<PrimitiveReference href="https://ark-ui.com/docs/components/splitter" />

## Choisir le bon composant

- Choisissez **`Sidebar`** pour une navigation d’application qui doit être redimensionnable, se replier en barre d’icônes et rester à côté du contenu principal.
- Choisissez **`Splitter`** lorsque les deux panneaux sont des zones de contenu ordinaires plutôt qu’une paire navigation/inset.
- Composez un `Dialog` ou un `Drawer` adaptatif autour de la navigation lorsque celle-ci doit devenir un overlay sur les petits écrans plutôt qu’un panneau replié.

## Composition

### Composition recommandée

Conservez toutes les parties de la disposition comme enfants directs de la racine. Pour une barre latérale gauche, affichez `Panel`, `ResizeTrigger`, `Trigger`, puis `Inset`. Pour une barre latérale droite, affichez `Inset`, `Trigger`, `ResizeTrigger`, puis `Panel`. Le déclencheur a une largeur flex effective nulle et reste centré au-dessus de la ligne de redimensionnement sans être rogné par les panneaux. Utilisez `Collapsible` pour les éléments de menu imbriqués et `Menu + Avatar` pour les actions du compte. Ajoutez `Menu.Indicator` directement dans `Sidebar.MenuButton` ; Sidebar le place à l’extrémité inline et le masque dans le panneau replié. `Input`, `GroupAction`, `GroupContent`, `MenuAction`, `MenuBadge` et `Separator` couvrent les éléments récurrents d’une enveloppe d’application sans ajouter d’état propre à Sidebar. Composez `Sidebar.Tooltip` autour des boutons de menu à icône lorsque le panneau replié nécessite des libellés visibles au survol. Considérez les recettes suivantes comme les parcours de migration officiels :

1. **Libellés du panneau replié :** `Sidebar.Tooltip` autour de `Sidebar.MenuButton`.
2. **Enveloppe adaptative :** `Sidebar` sur ordinateur + `Drawer` sur les écrans compacts, en réutilisant les parties visuelles de Sidebar.
3. **Persistance :** conservez la largeur dans un `size` contrôlé, mettez-la à jour depuis `onResize(details)` et enregistrez-la depuis `onResizeEnd(details)` dans l’état ou le stockage de l’application.

`Sidebar` est la forme racine courte, équivalente à `Sidebar.Root`.

### Quand créer une composition personnalisée

Transmettez directement `panels`, `defaultSize`, un `size` contrôlé et les rappels Splitter lorsque la disposition standard fondée sur des longueurs CSS ne convient pas. Utilisez `useSidebar()` pour accéder à `collapsed`, `state`, `side` et `toggleSidebar`. Utilisez directement `Splitter` lorsque l’application nécessite les API de bas niveau du provider, du registre, de plusieurs panneaux ou du contexte complet.

`panelId` modifie l’id de navigation par défaut ainsi que le handle de redimensionnement associé ; l’id de l’inset reste `"content"`. Les parties de disposition Sidebar n’acceptent volontairement pas d’id distincts : elles conservent ainsi un contrat de panneau Ark unique entre les panneaux affichés, le déclencheur et `useSidebar()`. Utilisez directement `Splitter` lorsque la disposition exige un id d’inset personnalisé ou plus de deux panneaux.

Utilisez `asChild` sur les boutons de menu et de sous-menu pour composer des liens de routeur. Conservez un seul enfant sémantique capable de recevoir les props et la ref fusionnés.

Gardez dans `Sidebar` les parties liées à Splitter : `Panel`, `Inset`, `ResizeTrigger`, `Trigger` et `useSidebar()`. Réutilisez les parties visuelles (`Header`, `Input`, `Content`, `Footer`, `Group`, `Menu` et les parties d’élément associées) dans un `Drawer` lorsque les écrans compacts nécessitent un overlay plutôt qu’un panneau repliable.

### Propriétés par défaut

| Valeur                           | Valeur par défaut                                                  |
| -------------------------------- | ------------------------------------------------------------------ |
| Id des panneaux                  | `"sidebar"` et `"content"`                                      |
| Taille initiale de Sidebar       | `"16rem"` (256px)                                                 |
| Contraintes de Sidebar           | `minSize: "12rem"`, `maxSize: "18rem"`, `collapsedSize: "3rem"` |
| Contraintes du contenu           | Aucun minimum                                                       |
| Côté                             | `"left"`                                                          |
| Orientation                      | `"horizontal"` (fixe pour la disposition sidebar/inset)           |
| `panelId` de la racine           | `"sidebar"`                                                       |
| `size` du bouton de menu         | `"md"`                                                            |

### Notes sur le comportement

Ark accepte les pourcentages et les longueurs CSS pour dimensionner les panneaux. Les longueurs CSS sont mesurées côté client ; une disposition rendue sur le serveur peut donc se décaler après l’hydratation. Utilisez des pourcentages lorsqu’une disposition SSR stable est importante. `Trigger` fournit `aria-expanded`, appelle d’abord le gestionnaire `onClick` de l’utilisateur et ignore le basculement par défaut si ce gestionnaire a appelé `preventDefault()`.

Ark conserve le déplacement au pointeur, le redimensionnement avec les flèches, l’état de focus et les objets details des rappels : `onResize(details)`, `onResizeEnd(details)`, `onCollapse(details)` et `onExpand(details)`.

Le repli et le déploiement des panneaux suivent immédiatement les tailles Ark. Sidebar n’anime volontairement pas la largeur du panneau, car une transition CSS flex serait en retard sur le redimensionnement au pointeur et au clavier. Le contenu Collapsible, le contenu contextuel, les infobulles et l’icône du déclencheur conservent leurs propres transitions.

## Styles

Le panneau de navigation utilise les tokens card, tandis que l’inset utilise l’arrière-plan de l’application. Les données de panneau par défaut configurent une barre de `3rem`. Dans les panneaux repliés, `Sidebar.Label` et les libellés de groupe sont retirés de la disposition avec un modèle visuellement masqué, les menus imbriqués et `Sidebar.Input` sont cachés, et les SVG ainsi que les éléments portant `data-sidebar-icon` sont centrés. Les libellés restent accessibles aux technologies d’assistance sans occuper de place dans la disposition flex. Marquez les ancres non SVG, comme Avatar, le libellé d’espace de travail Select ou la marque, avec `data-sidebar-icon` ; leurs dimensions propres sont conservées. Placez dans `Sidebar.Label` le texte, les valeurs, les libellés et les indicateurs repliables qui doivent quitter la disposition visuelle dans le panneau replié. Les éléments terminaux des groupes et des menus sont automatiquement masqués en mode icônes uniquement.

La largeur du panneau relève de l’état Ark et non du CSS visuel. Redéfinissez `panels`, `defaultSize` et le `size` contrôlé pour personnaliser les largeurs déployée, minimale, maximale et repliée. `panelId` modifie l’id de navigation par défaut ; utilisez directement `Splitter` pour un id d’inset personnalisé ou plus de deux panneaux. Utilisez les variables publiques `--moduix-sidebar-*` pour les espacements internes, les dimensions des éléments, les couleurs et le décalage vertical du déclencheur.

L’interface de redimensionnement se limite volontairement à une ligne. Sa couleur au repos correspond à la bordure ; au survol et pendant le déplacement, elle se rapproche légèrement de `--moduix-color-muted-foreground`, tandis que le focus au clavier utilise la couleur focus-ring de Sidebar. Ne redéfinissez les variables `--moduix-splitter-resize-trigger-line-color-*` que si le produit nécessite un retour visuel plus marqué.

### Hooks de style

Chaque partie sémantique accepte `className` et fournit un hook stable `data-slot="sidebar-*"`. Les parties de l’enveloppe appartenant à Sidebar fournissent aussi `data-scope="sidebar"` et `data-part`, tandis que `Sidebar.Input` et `Sidebar.Separator` conservent volontairement les scopes des primitives de base. Les parties de disposition fondées sur Ark conservent les attributs d’état de Splitter.

`Sidebar.Panel` ajoute `data-state="expanded"` ou `"collapsed"`. La racine, le panneau, l’inset, le déclencheur de redimensionnement et le déclencheur flottant fournissent `data-side`. `MenuButton` et `MenuSubButton` fournissent `data-active`, `MenuButton` fournit `data-size`, et les parties d’enveloppe supplémentaires conservent des hooks stables `data-slot="sidebar-*"` pour les dispositions ou thèmes personnalisés. L’état de redimensionnement reste disponible avec les attributs Ark `data-focus`, `data-dragging`, `data-disabled` et `data-orientation`.
