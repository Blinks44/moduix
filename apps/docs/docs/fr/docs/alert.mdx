## Référence de l’API

Ark UI ne fournit pas de primitive `alert` dédiée. Moduix construit ce composant avec la
[fabrique Ark](https://ark-ui.com/docs/guides/composition#the-ark-factory) officielle et suit les recommandations d'Ark en matière de
[composition](https://ark-ui.com/docs/guides/composition), de [styles](https://ark-ui.com/docs/guides/styling) et de
[ref](https://ark-ui.com/docs/guides/ref).

Les parties publiques sont `Alert.Root`, `Alert.Indicator`, `Alert.Content`, `Alert.Title`,
`Alert.Description` et `Alert.Actions`.

## Choisir le bon composant

Utilisez `Alert` lorsque le message doit rester en ligne dans la mise en page et participer au message normal.
flux de documents.

- Choisissez **`Alert`** pour le statut en ligne, la validation et les messages système dans les formulaires, les panneaux ou le contenu de la page.
- Choisissez **`Toast`** pour les notifications passagères qui apparaissent en dehors du flux de documents et se dissolvent d'elles-mêmes.

## Anatomie

```text
Alert / Alert.Root
├─ Alert.Indicator (optional)
├─ Alert.Title
├─ Alert.Description
└─ Alert.Content (optional)
   ├─ Alert.Title
   ├─ Alert.Description
   ├─ Alert.Actions (optional)
   └─ Extra custom blocks
```

| Partie | Rôle | `data-part` |
| ---------------------- | ------------------------------------------------------------- | ------------- |
| `Alert` / `Alert.Root` | Emplacement racine. Applique les styles de statut et la sémantique.               | `root` |
| `Alert.Indicator` | Fente d'indicateur en option. Taille les icônes SVG enfants de manière cohérente.  | `indicator` |
| `Alert.Content` | Wrapper de colonne de contenu facultatif pour le texte et les actions groupés. | `content` |
| `Alert.Title` | Emplacement de titre d’alerte. Rend `p` par défaut.                     | `title` |
| `Alert.Description` | Emplacement de message pris en charge.                                      | `description` |
| `Alert.Actions` | Ligne d'habillage facultative pour les éléments d'action à l'intérieur du contenu.     | `actions` |

## Composition

### Composition recommandée

Utilisez `Alert`, `Alert.Title` et `Alert.Description` directement pour le chemin de message en ligne commun.

Utilisez `status` pour l'intention : `info`, `success`, `warning` ou `error`.

Ajoutez `Alert.Indicator` lorsque l’alerte nécessite un repère visuel explicite. Le composant intentionnellement
évite d’ajouter des propriétés ou des emplacements spéciaux pour les actions.

### Quand créer une composition personnalisée

Ajoutez `Alert.Content` lorsque le texte d'alerte doit rester dans une colonne avec des contrôles en ligne supplémentaires,
état de rejet local ou blocs personnalisés supplémentaires. Utilisez `Alert.Actions` pour une ligne d'action encapsulée
à l'intérieur de cette colonne de contenu, et `Alert.Title asChild` lorsque le plan du document nécessite un autre
élément de titre.

Utilisez `Alert.Title asChild` lorsque le plan du document nécessite un élément de titre différent :

```tsx
<Alert.Title asChild>
  <h2>Billing issue</h2>
</Alert.Title>
```

### Propriétés par défaut

| Accessoire | Par défaut | Valeurs / Remarques |
| -------- | --------- | --------------------------------------------------------------- |
| `status` | `info` | `info`, `success`, `warning`, `error` |
| `role` | Automobile | `role="status"` par défaut, `role="alert"` pour `status="error"` |

### Comportement

- `Alert.Root` est par défaut `role="status"` et passe à `role="alert"` pour `status="error"`.
- Ces rôles créent des régions vivantes polies et affirmées. Montez l'alerte avant de mettre à jour son message
lorsqu'une annonce est requise ; le contenu déjà présent au chargement de la page peut ne pas être annoncé.
- Remplacez `role` lorsque la surface est une légende statique au lieu d'un retour en direct. Par exemple, utilisez
`role="note"` pour des informations statiques supplémentaires.
- `Alert.Indicator` est par défaut `aria-hidden="true"`.
- `Alert.Title` restitue `p` par défaut et utilise Ark `asChild` pour le polymorphisme des titres.
- La signification essentielle doit rester dans le titre ou la description, car l'indicateur reste
`aria-hidden`.
- `Alert.Content` est facultatif. Utilisez-le lorsque le titre, la description et les contrôles supplémentaires doivent en partager un
colonne de contenu à côté de l’indicateur.
- `Alert.Actions` est facultatif. Utilisez-le lorsque des boutons ou des liens doivent partager l'action encapsulée par défaut
style de ligne.
- Le composant est intentionnellement présentationnel. Il ne gère pas l'état de rejet, le focus ou
comportement du clavier pour les actions intégrées.

## Styles

Utilisez `className` sur la racine ou les pièces pour les styles locaux. Remplacez les variables CSS `--moduix-alert-*` sur le
root lorsque l’alerte nécessite un thème local.

Les `--moduix-alert-bg`, `--moduix-alert-border-color`, `--moduix-alert-color` et
Les variables `--moduix-alert-indicator-color` remplacent chaque état. Utilisez la correspondance
Variables `--moduix-alert-<status>-*` lorsqu'un seul état doit changer.

Les statuts intégrés lisent également les jetons de palette partagée :

| Statut | Jeton partagé | Par défaut |
| --------- | ---------------------------- | ---------------------------- |
| `info` | `--moduix-color-card` | carte du thème |
| `success` | `--moduix-color-success` | `oklch(0.627 0.194 149.214)` |
| `warning` | `--moduix-color-warning` | `oklch(0.795 0.184 86.047)` |
| `error` | `--moduix-color-destructive` | thème destructeur |

### Points d’accroche CSS

- Sélecteurs `data-slot` stables : `alert-root`, `alert-indicator`, `alert-content`, `alert-title`,
`alert-description` et `alert-actions`
- Sélecteurs de style Ark : `data-scope="alert"` avec `data-part="root"`, `indicator`, `content`,
`title`, `description` ou `actions`
- `Alert.Root` écrit l'état sélectionné dans `data-status`
