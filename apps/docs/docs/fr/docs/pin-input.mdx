## Choisir le bon composant

Utilisez `PinInput` lorsqu’une valeur courte de longueur fixe doit être saisie dans plusieurs champs d’un caractère.

- Choisissez **`PinInput`** pour les mots de passe à usage unique, les codes PIN, les codes de secours et les codes d’invitation.
- Choisissez **`Input`** lorsqu’un seul champ de texte simple suffit.
- Choisissez **`PasswordInput`** lorsque la valeur est une chaîne confidentielle unique avec un bouton de visibilité.

## Anatomie

```text
PinInput / PinInput.Root
├─ PinInput.Label
├─ PinInput.Control
│  ├─ PinInput.Input[index=0]
│  ├─ PinInput.Input[index=1]
│  └─ PinInput.Input[index=2]
└─ native input (automatic)
```

| Partie                         | Rôle                                                                  |
| ------------------------------ | --------------------------------------------------------------------- |
| `PinInput` / `PinInput.Root`   | Machine d’état racine, nombre de champs, tableau de valeurs, validation et options de formulaire. |
| `PinInput.RootProvider`        | Affiche un Pin Input à partir de l’état renvoyé par `usePinInput`.     |
| `PinInput.Label`               | Libellé accessible du groupe de saisie du code.                       |
| `PinInput.Control`             | Conteneur des champs indexés visibles.                                |
| `PinInput.Input`               | Un champ visible d’un caractère. Transmettez un `index` à partir de zéro. |
| `PinInput.Inputs`              | Affiche les champs indexés standard depuis le contexte Ark.           |
| `PinInput.Separator`           | Aide décorative moduix pour le regroupement. Ce n’est pas une partie primitive Ark. |
| `usePinInput` / `RootProvider` | Possession externe de l’état et méthodes impératives.                 |

## Composition

### Composition recommandée

Utilisez la forme racine courte `<PinInput>`, affichez un `Label` visible et conservez `Control` autour de `Inputs`.
La racine affiche toujours le champ natif pour préserver la soumission du formulaire, la synchronisation de la
réinitialisation et la saisie automatique OTP.

### Quand créer une composition personnalisée

Utilisez des parties `Input` explicitement indexées pour les dispositions groupées ou les propriétés propres à chaque
champ. Utilisez `PinInput.RootProvider` et `usePinInput` lorsque l’état doit être possédé en dehors de l’arbre affiché.
Conservez des index Ark continus sur l’ensemble du code.

### Propriétés par défaut

| Propriété        | Valeur par défaut | Remarques                                                              |
| ---------------- | ----------------- | ---------------------------------------------------------------------- |
| `count`          | -                 | Nombre de champs. Transmettez-le pour le SSR et le rendu indexé.       |
| `type`           | `numeric`         | `numeric`, `alphabetic` ou `alphanumeric`.                             |
| `placeholder`    | `''` dans moduix  | Ark utilise `○` par défaut ; moduix le masque sans `placeholder`.      |
| `otp`            | `false`           | Ajoute la saisie automatique des codes à usage unique.                 |
| `mask`           | `false`           | Masque les valeurs visibles comme dans un champ de mot de passe.       |
| `blurOnComplete` | `false`           | Retire le focus du dernier champ lorsque la saisie est terminée.       |
| `selectOnFocus`  | -                 | Sélectionne la valeur actuelle d’un champ lorsqu’il reçoit le focus.   |
| `pattern`        | -                 | Expression régulière personnalisée pour les caractères acceptés.      |
| `defaultValue`   | `[]`              | Valeur non contrôlée sous forme de tableau de chaînes.                 |
| `value`          | -                 | Valeur contrôlée sous forme de tableau de chaînes.                     |

### Comportement

`value` et `defaultValue` sont des tableaux de chaînes. `onValueChange(details)` et
`onValueComplete(details)` exposent `details.value` et `details.valueAsString`.
`onValueInvalid(details)` expose la valeur rejetée `details.value` et son `details.index`.

Utilisez `type` et `pattern` pour valider la valeur. `Field.Root` et `Fieldset.Root` peuvent fournir les états
désactivé, invalide, requis et lecture seule via le contexte Ark. Les parties Ark prennent en charge `asChild`,
et `ids` permet de fournir des identifiants stables aux libellés ou descriptions externes.

Utilisez `autoSubmit` uniquement lorsqu’un code complet doit soumettre son formulaire propriétaire. Les interactions
au clavier restent celles d’Ark : les flèches passent d’une cellule à l’autre, Retour arrière revient après avoir
effacé, Suppr efface la cellule courante et le collage remplit les cellules restantes.

### Points d’accroche CSS

- La racine et son fournisseur exposent `data-slot="pin-input-root"` et `data-slot="pin-input-root-provider"`.
- Les parties Ark conservent `data-scope="pin-input"` et `data-part="root" | "label" | "control" | "input"`.
- Les styles de l’état racine utilisent `data-disabled`, `data-invalid`, `data-complete` et `data-readonly`.
- Les styles d’état du champ utilisent `data-disabled`, `data-invalid`, `data-complete`, `data-filled` et `data-index`.
- `PinInput.Separator` expose `data-slot="pin-input-separator"` et est décoratif par défaut.

## Accessibilité

Ark gère le transfert du focus, la répartition du contenu collé, la modification au clavier, les données de formulaire
du champ masqué et la saisie automatique. La racine affiche automatiquement son champ de formulaire natif ; configurez
sa participation au formulaire avec des propriétés racine telles que `name` et `form`.
