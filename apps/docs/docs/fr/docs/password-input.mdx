## Choisir le bon composant

Utilisez `PasswordInput` lorsqu’une valeur confidentielle unique doit rester masquée par défaut tout en permettant
à l’utilisateur de l’afficher.

- Choisissez **`Input`** pour les champs de texte simples sans bouton de visibilité.
- Choisissez **`PasswordInput`** pour les mots de passe, les clés d’API et les autres chaînes confidentielles.
- Choisissez **`InputGroup`** lorsque le champ nécessite une action intégrée personnalisée sans rapport avec la visibilité du mot de passe.

## Exemple de base

Utilisez `PasswordInput.Field` pour le champ et le déclencheur de visibilité standard. Il comprend les icônes
moduix par défaut tout en préservant l’état et le comportement d’accessibilité d’Ark.

## Anatomie

```tsx
<PasswordInput>
  <PasswordInput.Label />
  <PasswordInput.Field />
</PasswordInput>
```

Pour une personnalisation avancée, remplacez `PasswordInput.Field` par ses parties Ark explicites :

```tsx
<PasswordInput>
  <PasswordInput.Label />
  <PasswordInput.Control>
    <PasswordInput.Input />
    <PasswordInput.VisibilityTrigger>
      <PasswordInput.Indicator />
    </PasswordInput.VisibilityTrigger>
  </PasswordInput.Control>
</PasswordInput>
```

| Partie                                 | Rôle                                                                           |
| -------------------------------------- | ------------------------------------------------------------------------------ |
| `PasswordInput` / `PasswordInput.Root` | Possède l’état de visibilité du mot de passe et l’état du champ.               |
| `PasswordInput.RootProvider`           | Affiche la même partie racine à partir d’un objet d’état `usePasswordInput`.    |
| `PasswordInput.Label`                  | Libelle le champ et reçoit les états requis, désactivé, invalide et lecture seule. |
| `PasswordInput.Field`                  | Affiche le contrôle, le champ, le déclencheur de visibilité et l’indicateur par défaut. |
| `PasswordInput.Control`                | Positionne ensemble le champ et le déclencheur de visibilité.                  |
| `PasswordInput.Input`                  | Champ natif dont le `type` alterne entre `password` et `text`.                 |
| `PasswordInput.VisibilityTrigger`      | Bouton qui bascule l’état de visibilité.                                       |
| `PasswordInput.Indicator`              | Affiche le contenu visible ou masqué ; moduix fournit les icônes par défaut.    |

## Composition

### Composition recommandée

Utilisez `PasswordInput.Field` pour le contrôle, le champ, le déclencheur de visibilité et l’indicateur par défaut.
Transmettez à `PasswordInput` les propriétés de visibilité racine, d’état du formulaire, d’identifiants, de traductions
et de gestionnaire de mots de passe.

### Quand créer une composition personnalisée

Utilisez directement `Control`, `Input`, `VisibilityTrigger` et `Indicator` lorsque la structure, les icônes ou les
styles des parties doivent différer de `PasswordInput.Field`. Utilisez `asChild` uniquement lorsqu’une partie doit
afficher un élément sémantique personnalisé unique.

### Propriétés par défaut

| Propriété                        | Valeur par défaut     | Remarques                                                     |
| -------------------------------- | --------------------- | ------------------------------------------------------------- |
| `autoComplete`                   | `"current-password"` | Défini sur le champ par la machine d’état racine.             |
| `defaultVisible`                 | `false`               | État de visibilité initial non contrôlé.                      |
| `visible`                        | non contrôlé          | État de visibilité contrôlé.                                  |
| `PasswordInput.Field`            | —                     | Affiche les parties visibles par défaut et transmet les propriétés du contrôle. |
| `onVisibilityChange`             | -                     | Reçoit les détails Ark ; lisez `details.visible`.             |
| `translations.visibilityTrigger` | valeur Ark par défaut | Fonction utilisée pour les libellés localisés du déclencheur. |
| `ignorePasswordManagers`         | `false`               | Ajoute les indications prises en charge pour ignorer les gestionnaires de mots de passe. |

### Notes sur le comportement

- Contrôlez la visibilité avec `visible` et `onVisibilityChange(details)`.
- Contrôlez directement la valeur du champ sur `PasswordInput.Input` avec les propriétés natives `value` et `onChange`.
- Utilisez directement les propriétés racine Ark UI telles que `name`, `required`, `disabled`, `readOnly`, `invalid`, `ids` et `translations`.
- Utilisez `usePasswordInput` avec `PasswordInput.RootProvider` lorsqu’un autre composant a besoin du même état de visibilité hors de l’arbre affiché.
- `PasswordInput.Input`, `PasswordInput.VisibilityTrigger` et `PasswordInput.Indicator` exposent
  `data-state="visible" | "hidden"` pour les styles.

## Styles

`PasswordInput` applique des styles au conteneur du contrôle, à la zone de texte et au déclencheur de visibilité
avec les tokens `--moduix-password-input-*`, superposés au contrat partagé des champs.

### Hooks de style

- La racine et son fournisseur exposent `data-slot="password-input-root"` et `data-slot="password-input-root-provider"`.
- Les parties Ark conservent `data-scope="password-input"` et les valeurs de `data-part` pour `root`, `label`,
  `control`, `input`, `visibility-trigger` et `indicator`.
- Les styles d’état utilisent `data-state="visible" | "hidden"` sur le champ, le déclencheur et l’indicateur, ainsi que
  `data-disabled`, `data-invalid`, `data-readonly` et `data-required` lorsqu’Ark les fournit.
- Ark n’expose pas de variables CSS d’exécution propres à Password Input ; moduix ajoute les variables
  `--moduix-password-input-*` pour les styles visuels par défaut.
