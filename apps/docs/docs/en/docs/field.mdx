## Choosing the right component

Use `Field` when one control needs a visible label, helper text, error text, or shared
`disabled`, `invalid`, `required`, and `readOnly` state.

- Choose **`Field`** for one control and its label or descriptive text.
- Choose **`Fieldset`** when several related fields need one shared legend.
- Use a standalone control when no field-level ARIA wiring or shared state is needed.

## Anatomy

`Field` follows Ark UI's field parts and keeps their names in the public moduix API.

```text
Field
├─ Field.Label
├─ Field.Input | Field.Textarea | Field.Select | custom control
├─ Field.HelperText
├─ Field.ErrorText
└─ Field.RequiredIndicator
```

| Part                      | Role                                                            |
| ------------------------- | --------------------------------------------------------------- |
| `Field` / `Field.Root`    | Root context and default `<div role="group">`.                  |
| `Field.RootProvider`      | Root powered by a `useField()` instance owned outside the tree. |
| `Field.Context`           | Renderless access to the current field state.                   |
| `Field.Label`             | Label linked to the current control id.                         |
| `Field.Input`             | Low-level Ark-shaped native input escape hatch. Prefer `Input`. |
| `Field.Textarea`          | Low-level Ark-shaped textarea escape hatch. Prefer `Textarea`.  |
| `Field.Select`            | Native select wired with field ARIA and state props.            |
| `Field.HelperText`        | Helper text included in `aria-describedby`.                     |
| `Field.ErrorText`         | Error text rendered only when `Field` is `invalid`.             |
| `Field.RequiredIndicator` | Visual required marker with optional `fallback`.                |
| `Field.Item`              | Item-scoped field context for grouped controls via `value`; its ref targets the row wrapper. |

## Composition

### Recommended composition

Keep one visible label in the root, render exactly one primary moduix control such as `Input`,
`Textarea`, or `NativeSelect`, and add helper or error text when it needs description or validation
feedback.

### When to go custom

Use `Field.Item value` with root `target` when a field contains multiple native controls and the
label should point to one of them. `Field.Input`, `Field.Textarea`, and `Field.Select` remain
available for advanced Ark-shaped composition, but ordinary application code should use their
dedicated moduix controls.

### Default props

| Surface                | Default | Notes                                                  |
| ---------------------- | ------- | ------------------------------------------------------ |
| `Field` / `Field.Root` | —       | No additional behavioral defaults; Ark defaults apply. |

### Behavioral notes

- `Field.ErrorText` is absent from the DOM until the root is `invalid`.
- Long labels, helper text, and error text wrap inside the field instead of overflowing it.
- `Field.RootProvider` must receive state from `useField()` imported from `@moduix/react`
  and should not be nested inside `Field.Root` for the same field instance.
- Use `Field.Context` or `useFieldContext` from `@moduix/react` when a custom control needs the
  current field state. Direct Ark imports are only for lower-level APIs not exported by moduix.
- `Field.Item` forwards its ref to the moduix row wrapper it renders around its children.
- `Field` does not render a hidden input; composed controls such as `Checkbox` and `RadioGroup` own
  their own native form parts.

## Styling

Style `Field` through `className`, Ark `data-scope="field"` / `data-part="..."` attributes,
moduix `data-slot="field-*"` hooks, and the public `--moduix-field-*` CSS variables shown below.

### Styling hooks

Ark adds `data-disabled`, `data-invalid`, `data-readonly`, and `data-required` to the relevant
parts. `Field.ErrorText` is only rendered while the current field context is invalid, and helper or
error text ids are included in the control's `aria-describedby` when present. Every DOM part also
keeps a stable `data-slot="field-*"` hook.
