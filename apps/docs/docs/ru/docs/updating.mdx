# Обновление и миграция

moduix поддерживает две модели владения, и обновляются они по-разному. Сначала определите используемый
путь; не перезаписывайте файлы, исходным кодом которых владеете, как если бы они были зависимостью пакета.

| Способ установки | Модель обновления |
| --- | --- |
| Пакет `@moduix/react` | Менеджер пакетов устанавливает новую версию библиотеки. |
| Исходный код из опубликованного реестра | Приложение владеет файлами; проверяйте и объединяйте обновления каждого компонента. |

## Обновления через пакет

Перед изменением версий прочтите [Историю изменений](../../docs/changelog). Используйте `npm update`, только
если вам нужны новейшие релизы, допускаемые диапазонами, уже указанными в `package.json`:

```bash
npm update @moduix/react @ark-ui/react
```

Чтобы явно выбрать актуальные релизы и обновить объявленные диапазоны, установите последние релизы moduix и
Ark UI вместе:

```bash
npm install @moduix/react@latest @ark-ui/react@latest
```

Для мажорной миграции целенаправленно выберите мажорную версию moduix, затем следуйте соответствующей
записи в истории изменений.

После обновления проверьте lockfile, запустите проверку типов и тесты приложения, а также протестируйте
компоненты, названные в истории изменений. Страницы компонентов описывают актуальную композицию, доступные
части и переменные стилизации, если обновление меняет контракт компонента.

## Обновления компонентов из реестра

Компоненты реестра — это исходный код в вашем приложении. Используйте CLI shadcn, чтобы изучить актуальный
элемент, проверить его diff и объединить его с локальными настройками.

```bash
npx shadcn@latest view @moduix-react/button
npx shadcn@latest add @moduix-react/button --dry-run
npx shadcn@latest add @moduix-react/button --diff
```

Просмотрев diff, установите элемент в ветку или чистое рабочее дерево и объедините изменения, которые хотите
сохранить:

```bash
npx shadcn@latest add @moduix-react/button
```

Повторите это для каждого компонента, которым вы владеете. CLI также определяет общие файлы основы moduix и
зависимости элементов, поэтому один раз импортируйте `@/lib/moduix/styles/style.css` в точке входа приложения.

## Обновления пресетов темы

Пресеты, управляемые пакетом, поставляются с `@moduix/react`, поэтому обновление пакета также обновляет
определения их токенов. Проверяйте разделы [Темы](../../docs/themes) и [Токены](../../docs/tokens), если
релиз меняет плотность или общие визуальные значения по умолчанию.

Пресет, исходным кодом которого владеете вы, проверяйте перед объединением нового CSS так же, как любой другой
элемент реестра:

```bash
npx shadcn@latest view @moduix-react/theme-soft
npx shadcn@latest add @moduix-react/theme-soft --dry-run
npx shadcn@latest add @moduix-react/theme-soft --diff
```

Размещайте переопределения приложения после импорта пресета. Так сохраняется каскад: если вышестоящий
пресет получает новый токен, решения вашего бренда всё равно имеют приоритет.

## Миграция на v2

В v2 примитивы Base UI заменены на Ark UI. Это мажорная миграция: части компонентов, контекст и
низкоуровневые пропы теперь следуют контрактам Ark.

1. Установите v2 и соответствующую peer dependency Ark UI.

   ```bash
   npm install @moduix/react@2 @ark-ui/react
   ```

2. Проверьте страницу каждого используемого компонента и скомпонуйте явные части заново там, где прежний API
   Base UI имел более плоскую структуру или другие имена.
3. Замените импорты прежних внутренних иконок moduix иконками, исходным кодом которых владеет приложение.
4. Для файлов из реестра используйте `add --diff` перед объединением обновлённого элемента.

Полная сводка критических изменений и актуальная политика версий приведены в
[записи истории изменений v2.0.0](../../docs/changelog#v200--july-19-2026).
