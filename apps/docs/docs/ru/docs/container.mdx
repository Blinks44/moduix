## Справочник API

В Ark UI нет отдельного примитива `container`. Moduix строит этот компонент с помощью официального
[Ark factory](https://ark-ui.com/docs/guides/composition#the-ark-factory), следуя рекомендациям Ark по

[ref](https://ark-ui.com/docs/guides/ref).

## Анатомия

`Container` — единственный корневой примитив компоновки, построенный на композиции фабрики Ark.

```text
Container / Container.Root
└─ дочерние элементы
```

| Часть                          | Назначение                                               |
| ------------------------------ | -------------------------------------------------------- |
| `Container` / `Container.Root` | Корневая обёртка компоновки. Управляет шириной содержимого и боковыми отступами. |

## Композиция

### Рекомендуемая композиция

Используйте `Container` для каркасов страниц, текста статей, разделов документации, экранов настроек и других
компоновок, которым нужна центрированная колонка содержимого с предсказуемыми боковыми отступами.

`Container.Root` — тот же компонент, предоставленный как согласованный с Ark алиас пространства имён.

Используйте `size` для выбора ширины содержимого, а `gutter` — для управления отступами от краёв. Используйте
`asChild`, когда обёртка также должна иметь семантику `main`, `section` или `article`. Для `asChild` нужен ровно
один семантический дочерний элемент; ref будет указывать на него, а не на стандартный `div`.

### Когда нужна собственная композиция

`Container` намеренно состоит только из корневого компонента. У него нет дополнительных частей, свойств слотов
или вложенных помощников компоновки.

Для настройки достаточно:

- передать `className` для локальной компоновки или стилизации поверхности;
- переопределить переменные `--moduix-container-*`, если странице нужны другие ширина или расчёт боковых отступов;
- использовать `asChild`, когда DOM-узлом должен быть другой элемент;
- скомпоновать с `Bleed`, когда дочерний элемент должен выйти за пределы ограниченной текстовой колонки.

### Свойства по умолчанию

| Свойство  | По умолчанию | Значения / примечания                |
| --------- | ------- | ------------------------------------ |
| `size`    | `lg`    | `xs` (40rem), `sm` (48rem), `md` (64rem), `lg` (72rem), `xl` (90rem), `full` (без ограничения) |
| `gutter`  | `md`    | `none`, `sm`, `md`, `lg`             |
| `asChild` | `false` | Композиция фабрики Ark               |

### Особенности поведения

- `Container` не управляет вертикальными интервалами. Добавляйте интервалы между разделами снаружи или на дочерних элементах.
- `size="full"` снимает только ограничение максимальной ширины. Выбранный боковой отступ продолжает применяться, если
  не используется `gutter="none"`.
- Корневой компонент предоставляет `data-scope="container"`, `data-part="root"`, `data-slot="container-root"`,
  `data-size` и `data-gutter` для стилизации и тестов.

## Стилизация

Используйте CSS-переменные у корневого компонента, когда оболочке страницы нужны другие вычисления отступов или другая шкала
ширины. Используйте `className` для локальной стилизации блока, например внутренних отступов, границ или фонов.

### Хуки стилизации

- `Container` и `Container.Root` предоставляют `data-slot="container-root"` у корневого компонента.
- `data-scope="container"` и `data-part="root"` предоставляют хуки корневого компонента, согласованные с Ark.
- `data-size` выбирает предустановку ширины: `xs`, `sm`, `md`, `lg`, `xl`, `full`.
- `data-gutter` выбирает предустановку отступов: `none`, `sm`, `md`, `lg`.
- Переменные `--moduix-container-*` управляют только горизонтальными отступами и вычислением максимальной ширины; вертикальные интервалы и
  компоновка дочерних элементов остаются ответственностью окружающего CSS компоновки.
