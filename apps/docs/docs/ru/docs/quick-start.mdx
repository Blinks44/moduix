# Быстрый старт

moduix поддерживает два равнозначных подхода к использованию в production:

- Установите `@moduix/react`, чтобы управлять установкой и обновлениями через менеджер пакетов.
- Установите компоненты через shadcn CLI, чтобы исходный код, стили и утилиты находились в вашем репозитории.

Оба подхода предоставляют одни и те же компоненты, контракты, согласованные с Ark, и систему токенов. Выбирайте
подход в зависимости от того, как хотите владеть кодом и обновлять его.

Вам нужны React 18 или 19, `@ark-ui/react` и фреймворк или сборщик, способный импортировать CSS из npm-пакетов.
Интерактивные компоненты должны рендериться внутри клиентской границы, если фреймворк этого требует.

Доступность — общая ответственность: Ark UI отвечает за поведение примитивов, moduix — за контракт обёрток и
значения по умолчанию, а приложение — за подписи, содержимое, сообщения валидации и пользовательский сценарий.

## Установить как пакет

Используйте этот вариант, если хотите хранить moduix в `node_modules` и получать обновления через обычный процесс
управления пакетами.

### 1. Установите пакет

Компоненты, CSS и дизайн-токены поставляются вместе. React 18 или 19 и Ark UI — peer dependencies:

<PackageManagerTabs command="install @moduix/react @ark-ui/react" />

`react`, `react-dom` и `@ark-ui/react` остаются в бандле приложения, поэтому moduix не поставляет дублирующиеся
runtime-библиотеки фреймворка или примитивов.

### 2. Добавьте стили

Один раз импортируйте обязательную базовую таблицу стилей в точке входа приложения:

```tsx
import '@moduix/react/style.css';
```

Эта таблица стилей обязательна. Она предоставляет общие дизайн-токены и стили базового слоя, на которые
опираются стили компонентов. Стили компонентов по-прежнему загружаются вместе с импортируемыми компонентами.

Все дизайн-токены moduix используют пространство имён `--moduix-*`. В проекте можно сохранить собственные имена
токенов и выборочно сопоставить их в таблице стилей, которая загружается после `style.css`; см. [Токены](/ru/docs/tokens).

Если нужен необязательный reset, импортируйте его явно перед основной таблицей стилей:

```tsx
import '@moduix/react/reset.css';
import '@moduix/react/style.css';
```

Так `style.css` отвечает только за глобальную основу, а CSS неиспользуемых компонентов может не попасть в бандл
приложения.

Для готовой визуальной отправной точки импортируйте один необязательный пресет после `style.css`; см.
[Темы](/ru/docs/themes).

### 3. Используйте компонент

Импортируйте каждый компонент из соответствующего подпути `@moduix/react/*`:

```tsx
import { Button } from '@moduix/react/button';
import { Dialog } from '@moduix/react/dialog';

export function Example() {
  return (
    <Dialog>
      <Dialog.Trigger asChild>
        <Button>Open dialog</Button>
      </Dialog.Trigger>
      <Dialog.Backdrop />
      <Dialog.Positioner>
        <Dialog.Content>
          <Dialog.Header>
            <Dialog.Title>Project settings</Dialog.Title>
            <Dialog.Description>Review the settings for this project.</Dialog.Description>
          </Dialog.Header>
          <Dialog.Footer>
            <Dialog.CloseTrigger asChild>
              <Button variant="outline">Close</Button>
            </Dialog.CloseTrigger>
          </Dialog.Footer>
        </Dialog.Content>
      </Dialog.Positioner>
    </Dialog>
  );
}
```

Всё готово, когда кнопка использует стили moduix, открывает Dialog при работе с клавиатурой и указателем, а после
закрытия фокус возвращается на кнопку.

## Установить через shadcn CLI

Используйте этот способ, если хотите хранить исходный код компонентов и стили в репозитории. shadcn CLI читает
реестр moduix, разрешает зависимости и записывает файлы по настроенным алиасам.

### 1. Настройте shadcn

Создайте `components.json` в корне проекта с конфигурацией реестра moduix:

```json title="components.json"
{
  "$schema": "https://ui.shadcn.com/schema.json",
  "style": "new-york",
  "rsc": false,
  "tsx": true,
  "tailwind": {
    "config": "",
    "css": "",
    "baseColor": "",
    "cssVariables": true,
    "prefix": ""
  },
  "aliases": {
    "components": "@/components",
    "ui": "@/components/ui",
    "lib": "@/lib",
    "hooks": "@/hooks",
    "utils": "@/lib/utils"
  },
  "registries": {
    "@moduix-react": "https://moduix.dev/r/react/{name}.json"
  }
}
```

Объект `tailwind` требуется схемой конфигурации shadcn, но moduix не использует Tailwind и не требует его установки.
Пустые пути и `baseColor` не позволяют CLI искать файлы Tailwind или скачивать цветовую палитру shadcn.

Оставьте `rsc: false` для приложений с клиентским рендерингом. В приложении с React Server Components установите
`rsc` в `true`, чтобы shadcn мог добавить директиву `use client` в сгенерированные компоненты, которым она нужна.

Проверьте, что проект разрешает алиас `@/*` к каталогу с исходным кодом. Типичная структура с `src` использует:

```json
{
  "compilerOptions": {
    "paths": {
      "@/*": ["./src/*"]
    }
  }
}
```

Так `shadcn` CLI получает алиасы и URL реестра, необходимые для размещения сгенерированных файлов в исходном коде
вместо буквального каталога `@`. В [настройке фреймворка](#выберите-фреймворк) указано, нужно ли добавить тот же
алиас в конфигурацию сборщика и какой корневой каталог исходного кода использовать.

### 2. Проверьте элемент реестра

Перед записью исходных файлов проверьте текущую конфигурацию и элемент реестра:

```bash
npx shadcn@latest info --json
npx shadcn@latest search @moduix-react --query "confirmation dialog"
npx shadcn@latest view @moduix-react/dialog
npx shadcn@latest add @moduix-react/dialog --dry-run
```

Ищите по нужному интерфейсу, а не по привычному названию библиотеки. Реестр содержит компоненты, темы и объявленные
для них зависимости. О том, как использовать тот же процесс поиска через shadcn MCP, см. [руководство по AI](/docs/ai).

### 3. Добавьте компонент

Добавляйте элементы из размещённого реестра moduix:

<PackageManagerTabs command="shadcn@latest add @moduix-react/button" dlx />

Чтобы добавить больше компонентов, выполните ту же команду с именем другого элемента реестра, например
`@moduix-react/accordion`.

Реестр устанавливает только общие runtime-файлы, которые нужны каждому компоненту. Он не добавляет глобальный шрифт,
поэтому типографика продолжает наследоваться от приложения.

### 4. Импортируйте сгенерированные стили

Импортируйте базовую таблицу стилей из файлов, которые `shadcn` добавил в проект:

```tsx
import '@/lib/moduix/styles/style.css';
```

Если при таком способе установки нужен необязательный reset, установите его отдельным элементом реестра:

```bash
npx shadcn@latest add @moduix-react/reset
```

Затем импортируйте его перед основной таблицей стилей:

```tsx
import '@/lib/moduix/styles/reset.css';
import '@/lib/moduix/styles/style.css';
```

В примерах ниже предполагаются `@/components` и `@/lib`. Если проект использует другие алиасы, обновите
`components.json` и импортируйте сгенерированные файлы по соответствующим путям.

### 5. Используйте сгенерированный компонент

Импортируйте компоненты из сгенерированных файлов в своём проекте:

```tsx
import { Button } from '@/components/moduix/button';
import { Accordion } from '@/components/moduix/accordion';
```

Большинство компонентов собираются из именованных частей. Это сохраняет доступность поведения, позволяя управлять
разметкой, компоновкой и стилизацией в приложении-потребителе.

Процесс владения исходным кодом вдохновлён [shadcn/ui](https://ui.shadcn.com/), а анатомия компонентов и поведение
взаимодействий остаются согласованными с [Ark UI](https://ark-ui.com/).

## Настройте слои порталов

Эта настройка относится к обоим способам установки. Такие компоненты, как `Dialog`, `Popover`, `Menu` и `Select`,
рендерят содержимое оверлеев в порталах. Изолируйте корневой элемент приложения, чтобы портальные подложки и
всплывающие элементы стабильно отображались над остальной страницей и не конкурировали с локальными значениями
`z-index`.

```tsx title="layout.tsx"
<body>
  <div className="root">{children}</div>
</body>
```

```css title="styles.css"
.root {
  isolation: isolate;
}
```

Если приложение поддерживает Safari в iOS 26, проверьте прокрученное модальное окно с интерфейсом браузера. Когда
содержимое остаётся видимым под подложкой, сохраните позиционирование `body` документа, чтобы абсолютные подложки
могли покрывать весь визуальный viewport.

```css title="styles.css"
body {
  position: relative;
}
```

## Стилизация

moduix работает с уже используемым в проекте способом стилизации:

- Нативный CSS с глобальными селекторами, каскадными слоями и CSS-переменными.
- CSS Modules с помощью `className` и свойств классов слотов компонентов.
- Утилитарные классы Tailwind CSS для компоновки и разовой стилизации.
- CSS-in-JS-библиотеки, которые добавляют классы или передают ограниченные областью действия стили через собственные обёртки.

Плотность по умолчанию задаёт `--moduix-size-md: 36px` для основных элементов управления и `--moduix-size-sm: 32px`
для строк всплывающих списков. Поскольку компоненты используют общую шкалу, изменение этих токенов одновременно
обновляет связанные поля ввода, триггеры, кнопки и элементы, подобные пунктам меню.

На страницах компонентов перечислены их публичные CSS-переменные и хуки стилизации. Для изменений во всей системе
используйте общие семантические токены, а переменные компонентов — только для осознанных исключений. Полная иерархия
описана в [Токенах](/ru/docs/tokens), а рецепты анимации — в [Анимациях](/docs/animations).

## Устранение неполадок

| Симптом | Проверка |
| --- | --- |
| Компоненты рендерятся без стилей | Один раз импортируйте корректную точку входа `style.css` после необязательного reset. |
| Не удаётся найти импорт с исходным кодом в проекте | Проверьте алиас `@/*` в TypeScript и сборщике, затем `components.json`. |
| Всплывающий элемент отображается под содержимым страницы | Добавьте `isolation: isolate` корневому элементу приложения и избегайте несвязанных глобальных `z-index`. |
| Серверный рендеринг сообщает о клиентских API | В фреймворках, где это необходимо, размещайте интерактивные компоненты ниже клиентской границы. |
