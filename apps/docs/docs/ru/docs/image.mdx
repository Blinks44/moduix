## Справочник API

`Image` — обёртка moduix для `<img>` вокруг [Unpic React](https://unpic.pics/img/react/).
В Ark UI нет отдельного примитива изображения для этого компонента.

## Базовый пример

Используйте `Image` с URL поддерживаемого CDN изображений и указывайте размеры для стандартной ограниченной
раскладки. Unpic генерирует адаптивные `srcSet` и `sizes`, а браузер заранее резервирует место под изображение.

## Анатомия

```text
Image / Image.Root
└─ img

picture (native)
├─ Image.Source
└─ Image / Image.Root
```

| Часть                   | Назначение                                                               |
| ----------------------- | ------------------------------------------------------------------------ |
| `Image` / `Image.Root` | Адаптивное нативное изображение; Unpic создаёт `srcSet`, `sizes` и стили. |
| `Image.Source`         | Адаптивный `<source>` для нативного элемента `<picture>`.               |

## Композиция

### Рекомендуемая композиция

`Image` — сокращённая форма корня, эквивалентная `Image.Root`. Используйте `width` и `height` со
стандартным `layout="constrained"`, чтобы сохранить соотношение сторон ресурса и избежать сдвигов раскладки. Для
удалённых URL поддерживаемых провайдеров Unpic определяет провайдера и автоматически генерирует преобразованные
записи `srcSet`.

Используйте `priority` только для изображений, которые должны загрузиться сразу, например для основного hero-блока
над сгибом. Он включает нетерпеливую загрузку и высокий приоритет получения, если не переданы соответствующие нативные атрибуты.

### Когда нужна собственная композиция

Используйте нативный `<picture>` с `Image.Source`, когда нужны художественное кадрирование или источники для разных
медиавыражений. Оставляйте `Image` последним дочерним элементом для резервного изображения. Передавайте `fallback`, `options` или
`operations`, если нераспознанный URL должен использовать определённого провайдера Unpic.

Для выбора формата поместите `Image.Source` со значением `type` перед эквивалентным источником без `type`; браузер использует
первый поддерживаемый формат.

### Свойства по умолчанию

| Свойство               | По умолчанию                | Примечания                                                              |
| ---------------------- | --------------------------- | ----------------------------------------------------------------------- |
| `layout`               | `constrained`               | Вписывается в переданные размеры и уменьшается при необходимости.       |
| `loading`              | `lazy`                      | Становится `eager`, когда задан `priority`.                             |
| `decoding`             | `async` для изображений без `priority` | Нативные значения имеют приоритет; при `priority` свойство не задаётся. |
| `objectFit`            | `cover`                     | Применяется встроенными стилями, которые генерирует Unpic.              |
| `--moduix-image-radius` | `var(--moduix-radius-md)` | Стандартный видимый радиус moduix.                                      |

### Особенности поведения

- `fixed` сохраняет заданные размеры в CSS-пикселях и может выйти за пределы более узкого родителя, тогда как
  `fullWidth` заполняет ширину контейнера.
- `alt` обязателен для содержательных изображений. Для декоративных используйте `alt=""`; тогда Unpic применяет
  `role="presentation"`, если вы не переопределите роль.
- Unpic генерирует `srcSet` из URL источника. Используйте `breakpoints`, когда его стандартные адаптивные
  ширины не подходят.
- `background="auto"` создаёт низкоразрешённый фон у поддерживаемых провайдеров. Он остаётся после загрузки, поэтому
  используйте его только для непрозрачных изображений или передайте вместо него осознанное значение фона.
- `unstyled` отключает встроенные стили раскладки, которые генерирует Unpic; стили отображения, радиуса и хуки
  `data-slot` moduix остаются доступными. Используйте его, когда для художественно кадрированных источников нужны другие правила
  адаптивной раскладки, а затем задайте эти правила в собственном CSS.

## Примеры

### Художественное кадрирование

Используйте `Image.Source`, чтобы на больших экранах выбрать более широкий вид офиса, а на меньших — портретное
резервное изображение. Первый источник для настольных устройств запрашивает AVIF, а эквивалентный источник предоставляет резервный
вариант для браузеров без поддержки AVIF. `Image.Source` должен оставаться внутри нативного элемента `<picture>`.

### Фиксированный размер

Используйте `layout="fixed"`, когда изображение должно сохранять точные размеры в CSS-пикселях. Убедитесь, что у его родителя
достаточно места: фиксированные изображения не уменьшаются, чтобы поместиться в более узком контейнере.

Используйте `layout="fullWidth"` для hero-блока или полосы медиа, которая должна заполнить ширину содержащей
раскладки. Передайте `height`, если высота кадрирования должна оставаться фиксированной.

### Хуки стилизации

- `data-slot="image-root"` стилизует отрисованный `<img>`.
- `data-slot="image-source"` выбирает узел источника внутри нативного `<picture>`.
- `className` на `Image` — рекомендуемый способ локальной стилизации. По умолчанию корень является блочным элементом.
