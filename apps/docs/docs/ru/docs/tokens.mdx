# Токены

Стили moduix построены на пользовательских свойствах CSS. Начните с семантических цветовых токенов для поверхности,
текста, границ, колец фокуса и оверлеев, затем настройте токены интервалов, скруглений, размеров, типографики,
анимации, теней и слоёв, когда продуктовой системе нужен другой ритм.

Если вы используете moduix как npm-пакет, один раз импортируйте `@moduix/react/style.css`. Если вы устанавливаете
исходные файлы с помощью `shadcn`, один раз импортируйте `@/lib/moduix/styles/style.css`. Обе точки входа загружают
одну и ту же основу токенов.

Reset остаётся необязательным в обоих вариантах. Пользователю npm нужно импортировать `@moduix/react/reset.css` перед
`style.css`. В варианте с исходным кодом в проекте сначала выполните `npx shadcn@latest add @moduix-react/reset`,
затем импортируйте `@/lib/moduix/styles/reset.css` перед `style.css`.

Для тщательно подобранной отправной точки используйте [Темы](/ru/docs/themes). Пресеты переопределяют небольшой слой
семантических токенов после `style.css`. На этой странице описаны системные и общие токены; на странице каждого
компонента перечислены алиасы и селекторы состояния, специфичные для компонента, которые можно безопасно настраивать.

## Выберите уровень переопределения

1. Измените примитив темы, например `--moduix-primary`, для визуального решения уровня всего продукта.
2. Измените общее значение семейства, если связанные компоненты должны меняться вместе.
3. Изменяйте алиас компонента, только когда этот компонент должен намеренно отличаться.
4. Ограничьте переменную контейнером функции для единичного локального исключения.

Если не уверены, начинайте выше в списке. Небольшое семантическое переопределение проще поддерживать, чем повторять
одно и то же значение во множестве алиасов компонентов.

## Модель токенов

Токены организованы слоями, чтобы общие изменения оставались небольшими и осознанными:

| Слой | Примеры | Используйте для |
| --- | --- | --- |
| Примитивы темы | `--moduix-primary`, `--moduix-spacing-2`, `--moduix-size-md`, `--moduix-radius` | Задания визуального языка приложения или пресета. |
| Семантические алиасы | `--moduix-color-primary`, `--moduix-spacing-md`, `--moduix-radius-md` | Чтения вычисленных значений в компонентах и стилях приложения. |
| Общие значения семейства | `--moduix-popup-item-min-height`, `--moduix-focus-ring-width` | Синхронизации связанных элементов управления, строк всплывающих списков и состояний. |
| Алиасы компонентов | `--moduix-input-height`, `--moduix-select-item-min-height` | Создания осознанного исключения для одного компонента или экземпляра. |

Предпочитайте наиболее высокий подходящий слой. Переопределяйте `--moduix-primary`, когда меняется цвет бренда,
`--moduix-popup-item-min-height`, когда всем поверхностям в стиле меню нужна другая плотность, и
`--moduix-select-item-min-height`, только если Select должен намеренно отличаться.

Алиасы компонентов используют цепочки резервных значений, а не скопированные значения. Поэтому тема может
переопределить небольшую группу примитивов, а типографика, геометрия иконок, кольца фокуса и размеры компонентов
продолжат изменяться согласованно.

## Использование moduix с существующей дизайн-системой

moduix владеет только переменными `--moduix-*`. Ваши существующие токены `--primary`, `--space-2` и другие не
считываются, не перезаписываются и не сбрасываются. Сопоставьте значения, которыми хотите поделиться, в таблице
стилей, загружаемой после `style.css`:

```css
:root {
  --moduix-primary: var(--product-action-primary);
  --moduix-primary-foreground: var(--product-action-on-primary);
  --moduix-background: var(--product-surface-canvas);
  --moduix-foreground: var(--product-text-primary);
  --moduix-radius: var(--product-radius-md);
  --moduix-spacing-2: var(--product-space-2);
  --moduix-size-md: var(--product-control-height-md);
}
```

Можно сопоставить только токены, которыми владеет ваша система; остальные значения moduix по умолчанию продолжат
работать. Исключения, специфичные для компонентов, следуют тому же соглашению, например `--moduix-dialog-*` и
`--moduix-button-*`.

Исключение — состояние времени выполнения Ark UI: переменные `--height`, `--available-width` и `--transform-origin`
остаются без префикса, поскольку Ark записывает их в соответствующие части компонентов. moduix не объявляет эти
значения на `:root`.

Используйте эту страницу для решений уровня системы, а страницу нужного компонента — для локальных алиасов. Ни один
вариант установки не требует отдельной таблицы ссылок на переменные во время выполнения.

## Плотность и шкала элементов управления

Шкала по умолчанию компактна, но не тесна:

| Токен | Значение по умолчанию | Предназначение |
| --- | --- | --- |
| `--moduix-size-xs` | `24px` | Маленькие элементы управления с иконками и компактные действия. |
| `--moduix-size-sm` | `32px` | Строки всплывающих списков и вторичные компактные элементы управления. |
| `--moduix-size-md` | `36px` | Стандартные поля ввода, кнопки, триггеры, пагинация и составные элементы управления. |
| `--moduix-size-lg` | `40px` | Намеренно более просторные элементы управления. |
| `--moduix-size-xl` | `48px` | Выразительные элементы управления и макеты, ориентированные на касание. |

Большинство основных элементов управления вычисляются через `--moduix-size-md`; элементы в меню, Select, Combobox,
палитрах команд и похожих всплывающих списках вычисляются через `--moduix-size-sm`. Благодаря этому триггер и его
всплывающий список визуально связаны, но список получает немного более плотный информационный ритм.

```css
:root {
  --moduix-size-md: 36px;
  --moduix-size-sm: 32px;
}

[data-moduix-theme='compact'] {
  --moduix-size-md: 34px;
  --moduix-popup-item-min-height: 30px;
}
```

## Массовые переопределения стилей

Некоторые переменные намеренно расположены выше отдельных компонентов. Их изменение обновляет сразу несколько
компонентов, пока переменная `--moduix-<component>-*`, специфичная для компонента, не переопределит резервное значение.

| Группа переменных | Что изменяет | Типичные потребители |
| --- | --- | --- |
| <code>--moduix-backdrop-bg</code><br /><code>--moduix-backdrop-filter</code> | Цвет и размытие фона по умолчанию | Command Palette, Dialog, Drawer, Lightbox, Tour |
| <code>--moduix-duration-\*</code><br /><code>--moduix-ease-\*</code><br /><code>--moduix-transition-\*</code> | Общие время и сглаживание анимации | Элементы управления, оверлеи, вкладки, аккордеоны, поля ввода, toast |
| <code>--moduix-popup-motion-\*</code> | Время и фазы анимации содержимого всплывающего окна | Popover, Menu, Tooltip, Hover Card, Floating Panel, модальные поверхности и пикеры |
| <code>--moduix-scale-popup</code><br /><code>--moduix-scale-dropdown</code> | Масштаб открытия и закрытия всплывающего окна по умолчанию | Dialog, Popover, Tooltip, Menu, Toast, Select, Combobox |
| <code>--moduix-popup-\*</code> | Общие плотность и интервалы списков всплывающих окон | Menu, Select, Combobox, CommandPalette |
| <code>--moduix-spacing-\*</code><br /><code>--moduix-size-\*</code> | Общие плотность и шкала элементов управления | Элементы управления, геометрия иконок, строки всплывающих списков, ритм макета |
| <code>--moduix-focus-ring-\*</code><br /><code>--moduix-color-ring</code> | Общие геометрия и цвет кольца фокуса | Кнопки, поля ввода, составные элементы управления, триггеры всплывающих окон |

Используйте эти токены, когда нужно масштабное визуальное изменение всей системы. Используйте токены, специфичные для
компонента, например `--moduix-dialog-backdrop-bg` или `--moduix-popover-transition`, когда один компонент должен
отличаться.

Краткая таблица выше — индекс между компонентами. В подробном обзоре ниже представлены те же токены в их естественных
разделах: анимация — в Motion, масштаб — в Elevation & Layers, а общие значения фона, всплывающих списков и анимации
всплывающих окон — в Shared Component Defaults.

```css
:root {
  --moduix-backdrop-bg: oklch(0.12 0.03 250 / 0.34);
  --moduix-transition-default: 240ms cubic-bezier(0.22, 1, 0.36, 1);
  --moduix-scale-popup: 0.96;
  --moduix-popup-motion-duration: 220ms;
  --moduix-popup-motion-easing: cubic-bezier(0.22, 1, 0.36, 1);
}

.command-surface {
  --moduix-popup-item-min-height: var(--moduix-size-sm);
}
```

Дробные токены интервалов, например `--moduix-spacing-1-5` и `--moduix-spacing-3-5`, выводятся из соседних
примитивных шагов. Пресету плотности достаточно переопределить целочисленные примитивы; промежуточные отступы
компонентов, геометрия иконок и смещения фокуса изменятся автоматически.

## Область переопределения

Задавайте токены уровня проекта в `:root`. Значение на `[data-moduix-color-scheme='dark']` или другом родительском
контейнере наследуется только компонентами, отрендеренными ниже этого элемента; стандартным оверлеям через портал
нужно значение на корне документа, `body` или контейнере портала в этой области.

```css
:root {
  --moduix-primary: oklch(0.52 0.18 145);
  --moduix-radius: 0.75rem;
  --moduix-backdrop-filter: blur(4px);
}

.dense-panel {
  --moduix-spacing-1: 3px;
  --moduix-spacing-2: 6px;
  --moduix-spacing-3: 10px;
  --moduix-size-sm: 30px;
  --moduix-size-md: 34px;
}
```

Для повторно используемой темы храните переопределения в отдельной таблице стилей, загружаемой после `style.css`.
Ограничьте файл атрибутом, например `[data-moduix-theme='brand']`, когда несколько тем должны сосуществовать.
Разовые настройки компонента держите рядом с функцией, чтобы они незаметно не превращались в глобальные решения
дизайн-системы.
