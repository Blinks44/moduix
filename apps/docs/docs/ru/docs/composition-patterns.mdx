# Паттерны композиции

moduix сохраняет композицию Ark на виду. Вместо того чтобы сводить поведение к одному большому набору пропов,
большинство компонентов предоставляют корневую часть с состоянием и части, которые отвечают за семантику,
макет и стилизацию.

Это даёт предсказуемую последовательность настройки:

- используйте поставляемые части напрямую;
- повторно экспортируйте их под именами, специфичными для продукта;
- оборачивайте только те части, которым нужны повторяющиеся стили продукта или макет.

Эти паттерны одинаковы как при использовании `@moduix/react`, так и при установке исходного кода из реестра.

## Установите с shadcn, если хотите владеть кодом

Используйте npm-пакет, если вам нужны обновления через менеджер пакетов, импорты компонентов из
`@moduix/react/*` и стили из `@moduix/react/style.css`.

Используйте реестр `shadcn`, если исходный код компонентов должен находиться в приложении. Он записывает
выбранный компонент и требуемые ему стили, иконки и утилиты moduix в проект, поэтому их можно изменять
напрямую и импортировать из `@/components/moduix/*`.

Компоненты, исходным кодом которых вы владеете, не получают обновления пакета автоматически. Когда
становится доступна новая версия moduix, добавьте её через `shadcn`, затем проверьте и объедините
получившийся diff на своих условиях. Одноразовая настройка реестра и команды компонентов описаны в
[Быстром старте](/docs/quick-start#install-with-the-shadcn-cli).

## Начните с документированного дерева частей

Прежде чем создавать обёртки, начните с анатомии на странице компонента. Используйте `className`,
CSS-переменные, `data-slot` и атрибуты состояния Ark на тех частях, которые действительно отвечают за эти
задачи.

Корневые экспорты, такие как `Popover`, `Tooltip` и `Select`, — это краткая форма `*.Root`. Корни
всплывающих компонентов и компонентов, похожих на диалоги, автоматически отрисовывают поддерево оверлея
через портал, поэтому структура остаётся видимой без отдельной обёртки `Portal`.

Например:

```text
Dialog / Dialog.Root
├─ Dialog.Trigger
├─ Поддерево оверлея (автоматически отрисовывается через портал)
│  ├─ Dialog.Backdrop
│  └─ Dialog.Positioner
│     └─ Dialog.Content
│        ├─ Dialog.Title
│        ├─ Dialog.Description
│        └─ Dialog.CloseTrigger
```

Используйте `portalled={false}` для отрисовки в потоке и `portalRef` для пользовательского контейнера,
когда компонент поддерживает эти пропы. Используйте `Dialog.RootProvider` как альтернативную точку входа
для состояния, если объект состояния находится за пределами отрисованного поддерева.

## Назначение структурных частей

Не каждый примитив предоставляет все части ниже. Начните с анатомии на странице компонента, затем сохраняйте
видимыми части, которые она документирует, когда продукту нужно их переопределять.

| Часть | Ответственность |
| --- | --- |
| `Backdrop` | Обеспечивает модальное разделение и нацеливание для взаимодействий вне компонента. |
| `Positioner` | Отвечает за размещение в области просмотра или относительно якоря, а также за прокрутку. |
| `Content` | Отрисовывает интерактивную поверхность и получает атрибуты состояния. |
| `Arrow` | Соединяет содержимое всплывающего окна, привязанного к якорю, с его триггером, если примитив поддерживает эту часть. |

Не скрывайте эти узлы в обёртках продукта, если только контракт продукта намеренно не убирает точки их
переопределения.

## Используйте `asChild`, когда другой элемент должен владеть DOM-узлом

Используйте `asChild`, когда часть moduix должна присоединить своё поведение к существующему семантическому
элементу.

```tsx
import { Button } from '@moduix/react/button';
import { Popover } from '@moduix/react/popover';
// shadcn copy-owned: import { Button } from '@/components/moduix/button';
// shadcn copy-owned: import { Popover } from '@/components/moduix/popover';

export function FiltersPopover() {
  return (
    <Popover positioning={{ gutter: 8 }}>
      <Popover.Trigger asChild>
        <Button variant="outline">Filters</Button>
      </Popover.Trigger>
      <Popover.Positioner>
        <Popover.Content>Choose one or more filters.</Popover.Content>
      </Popover.Positioner>
    </Popover>
  );
}
```

Сохраняйте один семантический дочерний элемент, способный получать пропы Ark. Если дочерний компонент
поглощает ref, обработчики событий или атрибуты, `asChild` не будет работать корректно.

## Передавайте `ids` только для связей между примитивами

Большинство композиций автоматически формируют собственные связи. Когда два примитива должны указывать на
один и тот же триггер или узел описания, передавайте ID вместо того, чтобы вручную задавать aria-связи.

```tsx
import { Avatar } from '@moduix/react/avatar';
import { Tooltip } from '@moduix/react/tooltip';
import { useId } from 'react';

export function AssigneeTooltip() {
  const id = useId();

  return (
    <Tooltip ids={{ trigger: id }}>
      <Tooltip.Trigger asChild>
        <Avatar ids={{ root: id }}>
          <Avatar.Fallback name="Sam Ortiz" />
        </Avatar>
      </Tooltip.Trigger>
      <Tooltip.Body>Sam Ortiz is online</Tooltip.Body>
    </Tooltip>
  );
}
```

Так формирование связей доступности остаётся в Ark, вместо того чтобы вручную дублировать атрибуты `aria-*`.

## Сначала повторно экспортируйте API продукта

Если продукту нужны более короткие импорты или брендированная поверхность, прежде чем писать новые
абстракции начните с повторного экспорта. Он сохраняет исходное поведение и одновременно предоставляет
приложению стабильный локальный API.

```tsx
import { Dialog as DialogBase } from '@moduix/react/dialog';
// shadcn copy-owned: import { Dialog as DialogBase } from '@/components/moduix/dialog';

export const Dialog = DialogBase;
export const DialogTrigger = DialogBase.Trigger;
export const DialogBackdrop = DialogBase.Backdrop;
export const DialogPositioner = DialogBase.Positioner;
export const DialogContent = DialogBase.Content;
export const DialogTitle = DialogBase.Title;
export const DialogDescription = DialogBase.Description;
export const DialogCloseTrigger = DialogBase.CloseTrigger;
```

Это путь настройки с наименьшим риском:

- потребители импортируют из слоя продукта, а не напрямую из `@moduix/react/*` или
  `@/components/moduix/*`;
- поведение Ark остаётся нетронутым;
- переход от использования пакета к установке с исходным кодом остаётся простым;
- обёртки можно добавить позже только там, где они действительно нужны.

## Оборачивайте только части, которым нужна стилизация продукта

Если требования дизайна выходят за пределы нескольких utility-классов, оборачивайте только части, которым
нужна пользовательская стилизация. Сохраняйте структуру видимой и передавайте остальные пропы без изменений.

<div className="docs-reference">
  <Tabs values={[{ label: 'Code', value: 'Code' }, { label: 'Styles', value: 'Styles' }]} className="docs-tabs">
    <Tab value="Code">

```tsx file="../../en/docs/_snippets/composition-patterns/product-dialog.tsx"

```

    </Tab>
    <Tab value="Styles">

```css file="../../en/docs/_snippets/composition-patterns/product-dialog.module.css"

```

    </Tab>

  </Tabs>
</div>

Сохраняйте структуру видимой и передавайте поведение без изменений. Если обёртка только переименовывает
часть и добавляет класс, этого обычно достаточно.

Перед выпуском обёртки убедитесь, что она по-прежнему передаёт ref, `className`, обработчики событий,
`asChild`, объекты подробностей колбэков Ark и атрибуты доступности, которые принимает исходная часть. Не
заменяйте нативную кнопку, label или input универсальным элементом ради удобства стилизации.

## Выносите состояние за пределы дерева, только когда меняется владение

Сохраняйте объекты подробностей Ark без изменений. Например, состояние открытия диалога по-прежнему
использует `onOpenChange(details)` и читает `details.open`.

Используйте хелперы состояния компонента только тогда, когда состоянию нужно находиться за пределами
отрисованного поддерева:

- `Component.Context` для разового чтения в строке;
- `useComponentContext()` внутри потомков, уже находящихся под корневой частью;
- `useComponent()` вместе с `Component.RootProvider`, когда состояние создаётся за пределами
  отрисованного дерева.

```tsx
import { Dialog, useDialog } from '@moduix/react/dialog';

export function DialogFromExternalState() {
  const dialog = useDialog();

  return (
    <Dialog.RootProvider value={dialog}>
      <Dialog.Trigger>Open dialog</Dialog.Trigger>
      <Dialog.Backdrop />
      <Dialog.Positioner>
        <Dialog.Content>State is owned by useDialog().</Dialog.Content>
      </Dialog.Positioner>
    </Dialog.RootProvider>
  );
}
```

Не отрисовывайте `Root` и `RootProvider` для одного экземпляра состояния.

## Простое правило для выбора нужного уровня

- Нужна только возможность использования? Оставайтесь на поставляемых частях.
- Нужны пути импорта продукта? Сначала повторно экспортируйте.
- Нужна повторяющаяся визуальная система продукта? Оборачивайте конкретные части, отвечающие за неё.
- Нужно другое поведение? Используйте явное дерево частей вместо того, чтобы придумывать новые пропы
  верхнего уровня.
