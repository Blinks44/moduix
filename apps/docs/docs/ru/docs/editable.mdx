## Выбор подходящего компонента

- Выберите **`Input`** или **`Textarea`**, когда значение всегда должно выглядеть редактируемым.
- Выберите **`Editable`**, когда поверхность по умолчанию содержит текст только для чтения, а редактирование —
  осознанное действие.
- Используйте **`Field`** вокруг `Editable`, когда вспомогательный текст, текст ошибки или общее состояние формы должны быть
  видны вне дерева частей редактируемого компонента.

## Базовый пример

Используйте части в стиле Ark: `Editable`, `Editable.Label`, `Editable.Area`, `Editable.Input` и
`Editable.Preview`. Добавьте `Editable.Controls` для стандартного сценария редактирования, подтверждения и отмены.
Обёртка добавляет стилизацию, атрибуты `data-slot` и иконки триггеров по умолчанию.
По умолчанию moduix переходит в режим редактирования по двойному щелчку, чтобы сократить случайные правки.

## Анатомия

```text
Editable.Root
├─ Editable.Label
├─ Editable.Area
│  ├─ Editable.Input
│  └─ Editable.Preview
├─ Editable.Control или Editable.Controls
│  ├─ Editable.EditTrigger
│  ├─ Editable.SubmitTrigger
│  └─ Editable.CancelTrigger

Editable.RootProvider
└─ то же дерево частей, подключённое к состоянию Ark `useEditable()`
```

| Часть                        | Назначение                                                        |
| ---------------------------- | ----------------------------------------------------------------- |
| `Editable` / `Editable.Root` | Корневое состояние, колбэки, свойства формы и настройка доступности. |
| `Editable.RootProvider`      | Корневой компонент на основе экземпляра `useEditable()`.         |
| `Editable.Label`             | Видимая метка для редактируемого поля ввода.                      |
| `Editable.Area`              | Общая поверхность для частей поля ввода и предпросмотра.         |
| `Editable.Input`             | Текстовое поле, отображаемое во время редактирования.            |
| `Editable.Preview`           | Текст в режиме чтения или плейсхолдер вне режима редактирования. |
| `Editable.Control`           | Необязательная обёртка для кнопок редактирования, подтверждения и отмены. |
| `Editable.Controls`          | Стандартный сценарий элементов управления редактированием, подтверждением и отменой. |
| `Editable.EditTrigger`       | Кнопка, переходящая в режим редактирования.                      |
| `Editable.SubmitTrigger`     | Кнопка, подтверждающая значение.                                  |
| `Editable.CancelTrigger`     | Кнопка, отменяющая изменения значения.                            |

## Композиция

### Рекомендуемая композиция

Держите `Input` и `Preview` соседними элементами внутри `Area`, а `Controls` размещайте после `Area` для
стандартного сценария триггеров. Для однострочных полей кнопки триггеров отображаются справа и выровнены по вертикальному центру.
Композиции с textarea используют ту же структуру и могут задать
`--moduix-editable-control-align: start`, чтобы элементы управления оставались выровненными по верхнему краю многострочной поверхности.

### Когда нужна собственная композиция

Используйте moduix `Editable.Context` или `useEditableContext()`, когда повторно используемым дочерним частям или встроенному чтению состояния
нужно состояние редактируемого компонента. Используйте moduix `useEditable()` с `Editable.RootProvider`, когда состояние или
методы должны находиться вне отрисованного дерева Editable. Используйте `asChild` для семантически корректного пользовательского
корневого элемента поля ввода, например textarea.

### Свойства по умолчанию

| Свойство         | По умолчанию | Примечания                                                                                                           |
| ---------------- | ------------ | -------------------------------------------------------------------------------------------------------------------- |
| `activationMode` | `dblclick`   | moduix использует двойной щелчок по умолчанию; передайте `focus`, `click` или `none`, когда нужен другой режим активации Ark. |
| `selectOnFocus`  | `true`       | Ark выделяет текст поля при получении фокуса.                                                                        |
| `submitMode`     | `both`       | `Enter` и потеря фокуса подтверждают значение по умолчанию; используйте `none` с явными элементами подтверждения.   |

### Особенности поведения

`value` и `defaultValue` отвечают за текстовое значение. `edit` и `defaultEdit` отвечают за режим редактирования. Свойства колбэков Ark
сохраняют объекты details, поэтому `onValueChange`, `onValueCommit`, `onValueRevert` и
`onEditChange` получают те же данные, что и в Ark UI.

`Enter` подтверждает изменения, а `Escape` отменяет их. Когда `Editable.Input` отрисовывает textarea через `asChild`,
Cmd/Ctrl + Enter подтверждает значение. `name` и `form` передаются в Ark для нативной
отправки формы. `disabled` запрещает активацию, а `readOnly` сохраняет видимое значение, не
позволяя его изменять.

Задайте `translations.input`, когда полю ввода требуется контекстное доступное имя; `Editable.Label`
остаётся видимой меткой.

### Хуки стилизации

- `data-slot="editable-root"`, `editable-root-provider`, `editable-label`, `editable-area`,
  `editable-input`, `editable-preview`, `editable-control`, `editable-edit-trigger`,
  `editable-submit-trigger`, and `editable-cancel-trigger`.
- Ark также добавляет атрибуты `data-scope="editable"` и `data-part` для каждой примитивной части.
- Селекторы состояния включают `data-focus` на `Label` и `Area`; `data-disabled` на `Area`, `Input`
  и `Preview`; `data-readonly` / `aria-readonly` на элементах управления только для чтения; `data-invalid` на
  `Label`, `Input` и `Preview`; `data-required` на `Label`; `data-placeholder-shown` на `Area`
  и `Preview`; а также `data-autoresize` на `Input` и `Preview`.
