## Выбор подходящего компонента

Используйте `Dialog` для форм, подтверждений, подробностей и вторичных сценариев, которые остаются в контексте
текущей страницы. Используйте `Drawer`, когда поверхность должна быть привязана к краю области просмотра.

## Анатомия

```text
Dialog
├─ Dialog.Trigger
└─ Overlay subtree (automatically portalled)
   ├─ Dialog.Backdrop
   └─ Dialog.Positioner
      └─ Dialog.Content
         ├─ Dialog.CloseTrigger or Dialog.CloseIcon
         ├─ Dialog.Title
         ├─ Dialog.Description
         ├─ Dialog.Header (moduix layout sugar)
         ├─ Dialog.Body (moduix layout sugar)
         └─ Dialog.Footer (moduix layout sugar)

Dialog.RootProvider
└─ the same automatically portalled content tree connected to moduix useDialog()

Dialog.Context
└─ a render function with the current dialog state and methods
```

| Часть                    | Назначение                                                       |
| ------------------------ | ---------------------------------------------------------------- |
| `Dialog`                 | Управляет открытым состоянием, жизненным циклом фокуса и закрытием диалога. |
| `Dialog.Trigger`         | Открывает диалог.                                                |
| `Dialog.Backdrop`        | Необязательный фоновый слой модального окна.                     |
| `Dialog.Positioner`      | Плавающий позиционер для размещения содержимого.                 |
| `Dialog.Content`         | Контейнер поверхности диалога.                                   |
| `Dialog.Title`           | Доступный заголовок диалога.                                     |
| `Dialog.Description`     | Доступное вспомогательное описание.                              |
| `Dialog.CloseTrigger`    | Закрывает диалог.                                                |
| `Dialog.Context`         | Рендерит дочерние элементы с текущим состоянием и методами диалога. |
| `Dialog.RootProvider`    | Подключает части к состоянию, созданному через `useDialog()` из moduix. |

Импортируйте `useDialog()`, когда состояние диалога должно находиться вне отрендеренного дерева. Читайте его внутри
переиспользуемых дочерних элементов через `Dialog.Context` или `useDialogContext()` из `@moduix/react`.

## Композиция

Корневой компонент автоматически переносит `Backdrop` и `Positioner` в портал. Для встроенного рендеринга используйте
`portalled={false}`, а для собственного контейнера — `portalRef`; структурные части остаются явными и доступными для стилизации.

### Рекомендуемая композиция

Сохраняйте `Backdrop`, `Positioner` и `Content` явными. Это оставляет точки структурной настройки и напрямую
соответствует Ark UI. Для немодальных диалогов не рендерите `Backdrop`.

Используйте `Dialog.Trigger asChild` и `Dialog.CloseTrigger asChild` с одной семантической дочерней кнопкой.
`Dialog.CloseIcon` — готовая композиция moduix, объединяющая Ark `CloseTrigger` с кнопкой закрытия библиотеки.

### Когда нужна собственная композиция

Для управляемого из React состояния используйте `open` с `onOpenChange(details)`. Колбэк получает объект сведений Ark,
поэтому читайте значение из `details.open`.

Используйте `useDialog()` из moduix вместе с `Dialog.RootProvider`, когда состояние и методы должны находиться вне
отрендеренного дерева диалога. Не рендерите `Dialog` для того же хранилища.

Используйте `ids`, когда отдельно скомпонованным частям нужны стабильные общие идентификаторы доступности.
`initialFocusEl` и `finalFocusEl` задают явные цели фокуса. `role="alertdialog"` моделирует подтверждение опасных
или критических действий.

Используйте `lazyMount` и `unmountOnExit` вместо условного рендеринга корневого компонента. Используйте `present`
только когда анимация выхода под управлением JavaScript должна контролировать смонтированное состояние.

### Свойства по умолчанию

По умолчанию содержимое оверлея в портале монтируется лениво и размонтируется после анимации выхода. Задайте
`unmountOnExit={false}`, чтобы сохранять его после первого открытия; отключайте оба свойства жизненного цикла только
когда нужен немедленный первоначальный рендеринг.

| Поверхность              | По умолчанию | Примечания                                         |
| ------------------------ | ------- | ------------------------------------------------------ |
| `Dialog`                 | —       | Дополнительных настроек поведения нет; применяются значения Ark. |

### Особенности поведения

- Модальные диалоги удерживают фокус, предотвращают фоновую прокрутку, скрывают нижележащее содержимое от
  вспомогательных технологий и восстанавливают фокус после закрытия.
- `modal={false}` отключает удержание фокуса и блокировку прокрутки; в этом режиме фон не нужен.
- `closeOnEscape`, `closeOnInteractOutside`, `trapFocus`, `preventScroll`, `restoreFocus`, `persistentElements` и
  колбэки внешнего взаимодействия передаются в Ark UI без изменений.
- Для доступного имени нужен `Dialog.Title` или `aria-label` на корневом компоненте.
- Все идентификаторы отрендеренных частей закрытия должны быть уникальными. Каноническая базовая композиция использует
  один `Dialog.CloseIcon`; если нужны несколько элементов закрытия, задайте дополнительным частям явные уникальные `id`.
- Вложенное содержимое получает `data-has-nested` и `--nested-layer-count`. Moduix использует эти хуки, чтобы уменьшить
  родительский диалог и сместить его вниз, сохраняя визуальную многослойность активного вложенного диалога.
- Открытие из меню и быстрые изменения состояния используют управляемый контракт `open`. Подтверждение несохранённых
  изменений использует два хранилища `useDialog()` из moduix и перехватывает `onOpenChange` родительского хранилища.

### Хуки стилизации

- Слоты moduix: `dialog-trigger`, `dialog-backdrop`, `dialog-positioner`, `dialog-content`,
  `dialog-title`, `dialog-description`, `dialog-close-trigger`, `dialog-close-icon`,
  `dialog-header`, `dialog-body` и `dialog-footer`.
- Анатомия Ark: `data-scope="dialog"` с `data-part="trigger|backdrop|positioner|content|title|description|close-trigger"`.
- Состояние: `data-state="open|closed"`, `data-has-nested`, `data-nested`, `data-current` и
  `data-value`.
- Переменные времени выполнения: `--layer-index` и `--nested-layer-count`.
- `Dialog.CloseIcon` позиционируется абсолютно относительно `Dialog.Content`; его размещение не зависит от
  `Dialog.Header`.
