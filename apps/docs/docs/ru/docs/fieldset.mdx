## Выбор подходящего компонента

Используйте `Fieldset` для нескольких связанных элементов управления с одной легендой. Используйте `Field` для одного
элемента управления с собственной меткой, описанием и сообщением о валидации.

## Базовый пример

Скомпонуйте `Fieldset`, `Fieldset.Legend`, необязательный поясняющий текст или текст ошибки и связанные элементы управления.
`Fieldset.Root` остаётся доступен как псевдоним, соответствующий Ark.

## Анатомия

```text
Fieldset.Root | Fieldset.RootProvider
├─ Fieldset.Legend
├─ grouped controls
├─ Fieldset.HelperText (optional)
└─ Fieldset.ErrorText (optional)
```

| Часть                        | Назначение                                                               |
| ---------------------------- | ------------------------------------------------------------------------ |
| `Fieldset` / `Fieldset.Root` | Создаёт состояние и отрисовывает нативный `fieldset`.                   |
| `Fieldset.RootProvider`      | Отрисовывает внешне созданное состояние `useFieldset`.                   |
| `Fieldset.Legend`            | Нативный `legend` и доступное имя группы.                                |
| `Fieldset.HelperText`        | Описание, связанное с корнем через `aria-describedby`.                   |
| `Fieldset.ErrorText`         | Вежливое live-сообщение валидации, отрисовываемое только при `invalid`.  |

## Композиция

### Рекомендуемая композиция

Оставляйте один видимый `Fieldset.Legend` внутри корня. Передавайте `disabled`, `invalid` и `id` непосредственно
в корень. Ark связывает легенду, смонтированный поясняющий текст и активный текст ошибки с fieldset.

Корень, provider, легенда, поясняющий текст и текст ошибки передают refs своим отрисованным DOM-элементам.
Используйте `asChild` с одним семантическим дочерним элементом, когда пользовательский host должен владеть частью.

### Когда нужна собственная композиция

Используйте `useFieldset` из `@moduix/react` вместе с `Fieldset.RootProvider`, когда состояние создаётся вне
отрисовываемого дерева. Используйте `useFieldsetContext()` или `Fieldset.Context` в потомке, которому нужно прочитать
это состояние. Не оборачивайте provider в `Fieldset.Root` для того же экземпляра состояния.

### Свойства по умолчанию

| Поверхность       | Свойство  | По умолчанию |
| ----------------- | --------- | ------------ |
| `Fieldset.Root`   | `disabled` | `false`     |
| `Fieldset.Root`   | `invalid`  | `false`     |

### Особенности поведения

- `Fieldset.Legend` отрисовывает нативный `legend`, в отличие от удалённой устаревшей обёртки.
- Браузер отключает нативные элементы управления внутри недоступного fieldset.
- Потомки Ark `Field` наследуют недоступное состояние от fieldset. Устанавливайте `invalid` на вложенных компонентах `Field`,
  когда отдельным элементам управления нужно невалидное состояние.
- `Fieldset.ErrorText` отсутствует в DOM, пока `invalid` не равно true.
- Длинные легенды, поясняющий текст и текст ошибки переносятся внутри fieldset, а не выходят за его границы.
- `useFieldsetContext()` и `Fieldset.Context` предоставляют потомкам то же состояние Ark, что и `useFieldset`.
- Fieldset не владеет значением, навигацией с клавиатуры, колбэком или `HiddenInput`.
- Устаревший `render` и плоские экспорты, такие как `FieldsetLegend`, не поддерживаются; используйте `asChild`
  и части пространства имён.

### Хуки стилизации

Каждая DOM-часть имеет `data-scope="fieldset"` Ark и `data-part`, соответствующий анатомии. Корень и легенда
предоставляют `data-disabled` и `data-invalid`; moduix также добавляет хуки `data-slot="fieldset-*"`.
Используйте `className` для локальных переопределений и переменные `--moduix-fieldset-*` для настройки на уровне темы,
особенно токенов отступов легенды и границы корня.
