## Справочник API

`Sidebar` использует [Ark UI Splitter](https://ark-ui.com/docs/components/splitter) для изменения размера,
состояния сворачивания, взаимодействия с клавиатурой и доступности. Его семантическая анатомия навигации
основана на [Sidebar из shadcn/ui](https://ui.shadcn.com/docs/components/radix/sidebar), а контракт состояния
сохраняет форму Ark.

<PrimitiveReference href="https://ark-ui.com/docs/components/splitter" />

## Выбор подходящего компонента

- Выбирайте **`Sidebar`** для навигации приложения, которая должна изменять размер, сворачиваться в панель
  иконок и располагаться рядом с основным содержимым.
- Выбирайте **`Splitter`**, когда обе панели являются обычными областями содержимого, а не парой навигации
  и inset.
- Компонуйте адаптивный `Dialog` или `Drawer` вокруг навигации, когда на маленьких экранах она должна быть
  оверлеем, а не свёрнутой панелью.

## Базовый пример

Явно отрендерите панель навигации, настоящий handle изменения размера Ark и основной inset. Стандартные id
и ограничения панелей позволяют использовать распространённую раскладку с левой боковой панелью без

## Композиция

### Рекомендуемая композиция

Держите все части раскладки прямыми дочерними элементами корня. Для левого sidebar рендерите `Panel`,
`ResizeTrigger`, `Trigger`, затем `Inset`. Для правого sidebar рендерите `Inset`, `Trigger`,
`ResizeTrigger`, затем `Panel`. Триггер имеет нулевую фактическую flex-ширину и остаётся по центру над
линией изменения размера, не обрезаясь ни одной из панелей. Используйте `Collapsible` для вложенных
элементов меню и `Menu + Avatar` для действий учётной записи. Добавляйте `Menu.Indicator` прямо внутрь
`Sidebar.MenuButton`; Sidebar располагает его у inline-конца и скрывает в свёрнутой панели. `Input`,
`GroupAction`, `GroupContent`, `MenuAction`, `MenuBadge` и `Separator` покрывают повторяющиеся элементы
оболочки приложения, не добавляя дополнительного состояния sidebar. Компонуйте `Sidebar.Tooltip` вокруг
кнопок меню с иконками, когда в свёрнутой панели нужны видимые подписи при наведении. Считайте следующие
рецепты официальными путями миграции:

1. **Подписи свёрнутой панели:** `Sidebar.Tooltip` вокруг `Sidebar.MenuButton`.
2. **Адаптивная оболочка:** настольный `Sidebar` + `Drawer` на компактных экранах, повторно использующий
   визуальные части sidebar.
3. **Сохранение:** храните ширину в управляемом `size`, обновляйте её из `onResize(details)` и сохраняйте
   из `onResizeEnd(details)` в состоянии приложения или хранилище.

`Sidebar` — короткая корневая форма, эквивалентная `Sidebar.Root`.

### Когда нужна собственная композиция

Передавайте обычные `panels`, `defaultSize`, управляемый `size` и колбэки Splitter, когда стандартная
раскладка с CSS-длинами не подходит. Используйте `useSidebar()` для `collapsed`, `state`, `side` и
`toggleSidebar`. Используйте `Splitter` напрямую, когда приложению нужны низкоуровневые API провайдера,
реестра, нескольких панелей или полного контекста.

`panelId` меняет стандартный id навигации вместе с соответствующим handle изменения размера; id inset
остаётся `"content"`. Части раскладки Sidebar намеренно не принимают отдельные id: это сохраняет один
контракт панели Ark для отрендеренных панелей, триггера и `useSidebar()`. Используйте `Splitter` напрямую,
когда раскладке нужен пользовательский id inset или более двух панелей.

Используйте `asChild` на кнопках меню и подменю для композиции ссылок роутера. Оставляйте один
семантический дочерний элемент, способный принять объединённые props и ref.

Держите части, связанные со Splitter, внутри `Sidebar`: `Panel`, `Inset`, `ResizeTrigger`, `Trigger` и
`useSidebar()`. Повторно используйте визуальные части (`Header`, `Input`, `Content`, `Footer`, `Group`,
`Menu` и связанные части элементов) внутри `Drawer`, когда компактным экранам нужен оверлей вместо
сворачиваемой панели.

### Свойства по умолчанию

| Значение                  | По умолчанию                                                    |
| ------------------------- | ---------------------------------------------------------------- |
| Id панелей                | `"sidebar"` и `"content"`                                      |
| Начальный размер sidebar  | `"16rem"` (256px)                                                |
| Ограничения Sidebar       | `minSize: "3rem"`, `maxSize: "18rem"`, `collapsedSize: "3rem"`  |
| Ограничения содержимого   | Нет минимума                                                     |
| Сторона                   | `"left"`                                                         |
| Ориентация                | `"horizontal"` (фиксирована для раскладки sidebar/inset)        |
| Корневой `panelId`        | `"sidebar"`                                                      |
| `size` кнопки меню        | `"md"`                                                           |

### Особенности поведения

Ark принимает проценты и CSS-длины для размеров панелей. CSS-длины измеряются на клиенте, поэтому
отрендеренные на сервере раскладки могут смещаться после гидратации; используйте проценты, когда важна
стабильная SSR-раскладка. `Trigger` предоставляет `aria-expanded`, сначала вызывает пользовательский
`onClick` и пропускает стандартное переключение, если обработчик вызвал `preventDefault()`.

Ark сохраняет перетаскивание указателем, изменение размера стрелками, состояние фокуса и объекты details
колбэков: `onResize(details)`, `onResizeEnd(details)`, `onCollapse(details)` и `onExpand(details)`.

Сворачивание и разворачивание панелей сразу следует размерам Ark. Sidebar намеренно не анимирует ширину
панели, поскольку CSS-переход flex отставал бы от изменения размера указателем и клавиатурой. Содержимое
Collapsible, всплывающее содержимое, подсказки и иконка триггера сохраняют собственные переходы.

## Стилизация

Панель навигации использует токены card, а inset — фон приложения. Стандартные данные панели настраивают
панель `3rem`. Свёрнутые панели исключают из раскладки `Sidebar.Label` и подписи групп с помощью
визуально скрытого паттерна, скрывают вложенные меню и `Sidebar.Input`, а SVG и элементы с
`data-sidebar-icon` центрируют. Подписи остаются доступны вспомогательным технологиям, не занимая место
во flex-раскладке. Помечайте не-SVG-якоря, например Avatar, метку рабочего пространства Select или метку
бренда, атрибутом `data-sidebar-icon`; их собственные размеры сохраняются. Помещайте сворачиваемый текст,
значения, метки и индикаторы в `Sidebar.Label`, если они должны покинуть визуальную раскладку в свёрнутой
панели. Завершающие элементы групп и меню автоматически скрываются в состоянии только с иконками.

Ширина панели — состояние Ark, а не визуальный CSS. Переопределяйте `panels`, `defaultSize` и управляемый
`size`, чтобы настроить развёрнутую, минимальную, максимальную и свёрнутую ширину. `panelId` меняет
стандартный id навигации; для пользовательского id inset или более двух панелей используйте `Splitter`
напрямую. Используйте публичные переменные `--moduix-sidebar-*` для внутренних отступов, размеров
элементов, цветов и вертикального смещения триггера.

Интерфейс изменения размера намеренно состоит только из линии. Её цвет покоя совпадает с границей, при
наведении и перетаскивании он немного сдвигается к `--moduix-color-muted-foreground`, а фокус с клавиатуры
использует цвет focus-ring Sidebar. Переопределяйте переменные
`--moduix-splitter-resize-trigger-line-color-*`, только когда продукту нужна более заметная обратная связь.

### Хуки стилизации

Каждая семантическая часть принимает `className` и предоставляет стабильный хук `data-slot="sidebar-*"`.
Части оболочки, принадлежащие Sidebar, также предоставляют `data-scope="sidebar"` и `data-part`, тогда как
`Sidebar.Input` и `Sidebar.Separator` намеренно сохраняют scopes базовых примитивов. Части раскладки на
основе Ark сохраняют атрибуты состояния Splitter.

`Sidebar.Panel` добавляет `data-state="expanded"` или `"collapsed"`. Корень, панель, inset, триггер
изменения размера и плавающий триггер предоставляют `data-side`. `MenuButton` и `MenuSubButton`
предоставляют `data-active`, `MenuButton` предоставляет `data-size`, а дополнительные части оболочки
сохраняют стабильные хуки `data-slot="sidebar-*"` для пользовательской раскладки или темы. Состояние
изменения размера по-прежнему доступно через Ark `data-focus`, `data-dragging`, `data-disabled` и
`data-orientation`.
