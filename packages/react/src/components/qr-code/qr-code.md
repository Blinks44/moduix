# QR Code

## Upstream docs

- Ark UI: https://ark-ui.com/docs/components/qr-code (accessed 2026-08-12)
- Chakra UI: https://chakra-ui.com/docs/components/qr-code (accessed 2026-08-12)
- shadcn/ui: https://ui.shadcn.com/llms.txt (accessed 2026-08-12; no QR code component)

## Purpose

`QrCode` renders a QR code as an Ark UI-managed SVG with optional overlay and download support.

## Upstream model to preserve

The wrapper follows Ark UI `QrCode` directly. `QrCode` owns the encoded value, generation options,
element ids, and QR code API. `QrCodeFrame` renders the SVG, `QrCodePattern` renders the QR modules,
`QrCodeOverlay` renders centered custom content, and `QrCodeDownloadTrigger` exports the current frame
as an image.

Keep the component composition explicit and Ark-shaped. Do not add an automatic single-component
render path that hides `QrCodeFrame` or `QrCodePattern`.

## Current behavior contract

- `QrCode` is the public root export.
- `defaultValue` creates uncontrolled state; `value` plus `onValueChange(details)` creates
  controlled state.
- `encoding` passes Ark/Zag QR generation options such as `ecc: 'L' | 'M' | 'Q' | 'H'` and
  `boostEcc`.
- `id`, `pixelSize`, and `ids` are forwarded to Ark.
- `QrCodeDownloadTrigger` requires `fileName` and `mimeType`; it preserves Ark's `quality` option.
- `QrCodeRootProvider` is preserved for externally owned Ark QR state. Import `useQrCode()` from
  `@moduix/react`. `QrCodeContext` and `useQrCodeContext()` are also available from moduix for
  reading the current QR API in descendants; keep Ark-only type aliases as escape hatches.

## Anatomy and exported parts

```text
QrCode
├─ QrCodeFrame
│  └─ QrCodePattern
├─ QrCodeOverlay
└─ QrCodeDownloadTrigger

QrCodeRootProvider
└─ same part tree connected to useQrCode() from @moduix/react
```

| Export                   | `data-slot`                | Notes                                      |
| ------------------------ | -------------------------- | ------------------------------------------ |
| `QrCode`                 | `qr-code-root`             | Ark root, value state, ids, and variables. |
| `QrCodeRootProvider`     | `qr-code-root-provider`    | Root for an external `useQrCode()` API.    |
| `QrCodeFrame`             | `qr-code-frame`            | SVG frame generated by Ark.                |
| `QrCodePattern`           | `qr-code-pattern`          | SVG path for QR modules.                   |
| `QrCodeOverlay`           | `qr-code-overlay`          | Centered overlay content.                  |
| `QrCodeDownloadTrigger`   | `qr-code-download-trigger` | Button that downloads the current image.   |

No duplicate root alias such as `QrCodeRoot` is exported.

## Composition

```tsx
import {
  QrCode,
  QrCodeContext,
  QrCodeDownloadTrigger,
  QrCodeFrame,
  QrCodeOverlay,
  QrCodePattern,
  QrCodeRootProvider,
  useQrCode,
  useQrCodeContext,
} from '@moduix/react/qr-code';

export function QrCodeDemo() {
  return (
    <QrCode defaultValue="https://moduix.dev/docs/qr-code">
      <QrCodeFrame>
        <QrCodePattern />
      </QrCodeFrame>
    </QrCode>
  );
}
```

Use `QrCodeOverlay` with high error correction when central content covers part of the code:

```tsx
<QrCode defaultValue="https://moduix.dev/docs/qr-code" encoding={{ ecc: 'H' }}>
  <QrCodeFrame>
    <QrCodePattern />
  </QrCodeFrame>
  <QrCodeOverlay>MX</QrCodeOverlay>
</QrCode>
```

## Upstream feature coverage

- Basic rendering: supported with `QrCode` / `QrCodeFrame` / `QrCodePattern`.
- Controlled value: supported through `value` and `onValueChange(details)`.
- Download: supported through `QrCodeDownloadTrigger` with `fileName`, `mimeType`, and optional
  `quality`.
- Error correction: supported through `encoding.ecc` and `encoding.boostEcc`.
- Fill customization: supported through `className`, SVG `style`, and `--moduix-qr-code-fill`.
- Overlay: supported through `QrCodeOverlay`; consumers should use stronger error correction when the
  overlay is large.
- Root provider: supported through moduix `useQrCode()` and `QrCodeRootProvider`.
- `asChild`: preserved on every Ark part.
- `id` and `ids`: preserved for stable machine, root, and frame ids.

## Accessibility and state

Ark renders the root as a `div`, the frame as an `svg`, the pattern as a `path`, the overlay as a
`div`, and the download trigger as a native `button`. Refs forward to those Ark elements. The QR
image is visual content. When it conveys information, add `role="img"` and an `aria-label` to
`QrCodeFrame`; use adjacent text or `aria-hidden="true"` when the QR code is redundant.

There is no roving focus or QR-specific keyboard navigation. `QrCodeDownloadTrigger` is a native button
and keeps normal button focus, keyboard activation, `disabled`, and `asChild` behavior from Ark.

State attributes are minimal for QR code. Ark supplies `data-scope="qr-code"` and `data-part` on
parts, plus runtime CSS variables on the root:

| Part | Runtime CSS variables                                      | Notes                 |
| ---- | ---------------------------------------------------------- | --------------------- |
| Root | `--qrcode-pixel-size`, `--qrcode-width`, `--qrcode-height` | Generated by Ark/Zag. |

## Defaults and styling

The download trigger follows Button's `--moduix-size-md` default; the visual QR overlay remains independently sized.

Moduix adds default classes, stable `data-slot` hooks, SVG sizing, overlay styling, and a
button-like default style for `QrCodeDownloadTrigger`. The root has no border, background, padding, or
radius by default.

Primary CSS variables:

| Variable                              | Default                                                                 |
| ------------------------------------- | ----------------------------------------------------------------------- |

| `--moduix-qr-code-fill`               | `currentColor`                                                          |

| `--moduix-qr-code-max-width`          | `100%`                                                                  |

## Intentional sugar and differences from upstream

- Moduix adds CSS Modules, token-backed defaults, and stable `data-slot` hooks.
- Moduix keeps `QrCode` as the root import, exports every styled Ark part as a flat value, and
  re-exports `useQrCode()` for the normal `QrCodeRootProvider` path.
- Moduix does not add form integration, hidden inputs, value text, or local state around Ark.
- Moduix does not force a default overlay or download button; consumers opt into those parts.

## Upstream comparison

| Source    | Finding                                                              | Decision                                                |
| --------- | -------------------------------------------------------------------- | ------------------------------------------------------- |
| Ark UI    | Explicit `Root` / `Frame` / `Pattern` anatomy and details callbacks. | Required correctness: preserve unchanged.               |
| Chakra UI | Optional closed wrapper can hide the explicit part tree.             | Rejected complexity: keep Ark-shaped parts.             |
| shadcn/ui | No equivalent QR code component.                                     | Intentional difference: publish moduix's registry item. |

## Agent notes

- Keep the wrapper thin and preserve Ark callback details.
- Keep `QrCodeFrame` and `QrCodePattern` explicit in examples and docs.
- When changing visual defaults, keep `--moduix-qr-code-*` tokens, docs examples, and registry output in
  sync.
- Keep `QrCodeContext`, `useQrCode()`, and `useQrCodeContext()` aligned as the moduix-owned
  advanced state surface; consumers can import Ark-only types directly when needed.
