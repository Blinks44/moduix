# Animations

moduix provides shared motion tokens for floating and modal content. Define them once to give every
supported overlay the same duration, easing, fade, scale, or slide behavior. When one component needs
different motion, override its component-level variables instead.

The components use Ark `data-state` attributes to select entry and exit keyframes. When content closes,
Ark keeps it mounted until its exit animation finishes.

Shared `--moduix-duration-*`, `--moduix-ease-*`, `--moduix-transition-*`, and `--moduix-scale-*` tokens
affect many parts of the system. Use `--moduix-popup-motion-*` when only overlay content should change
across the project.

When the operating system requests reduced motion, the foundation changes shared duration tokens to
`0.01ms` and disables the shared pulse, fade, slide, and spin animations. Components with specialized
continuous motion, such as Marquee and indeterminate Progress, keep their own
`prefers-reduced-motion` behavior.

## Choose the motion API

### Shared popup motion

Use `*-starting-*` for entry and `*-ending-*` for exit. The shared variables apply to the following
content parts: `Popover.Content`, `Menu.Content`, `Tooltip.Content`, `HoverCard.Content`,
`FloatingPanel.Content`, `Dialog.Content`, `CommandPalette.Content`, `Lightbox.Content`,
`Tour.Content`, `NavigationMenu.Content`, `Select.Content`, `Combobox.Content`, `DatePicker.Content`,
and `ColorPicker.Content`.

For example, this makes all supported popup content enter from and exit toward the left with one
timing curve:

```css
:root {
  --moduix-popup-motion-duration: 220ms;
  --moduix-popup-motion-easing: cubic-bezier(0.22, 1, 0.36, 1);
  --moduix-popup-motion-starting-opacity: 0;
  --moduix-popup-motion-ending-opacity: 0;
  --moduix-popup-motion-starting-scale: 1;
  --moduix-popup-motion-ending-scale: 1;
  --moduix-popup-motion-starting-translate-x: -0.75rem;
  --moduix-popup-motion-ending-translate-x: -0.75rem;
}
```

Use `:root` for the normal portalled overlay setup. A variable placed only on a local wrapper does
not reach content portalled to `document.body`; it does work for a component rendered with
`portalled={false}`.

### Component-local overrides

Component-level variables take precedence over the shared fallback. Use them for a local exception to
a project-wide rule, and put the class on the visual part listed in the table. Anchored surfaces retain
Ark's transform origin, so scale-based recipes still open from the trigger side.

| Surface         | Apply the class to       | Motion variables                                                            |
| --------------- | ------------------------ | --------------------------------------------------------------------------- |
| Popover         | `Popover.Content`        | `--moduix-popover-transition`, `--moduix-popover-content-*`                |
| Menu            | `Menu.Content`           | `--moduix-menu-transition`, `--moduix-menu-popup-*`                        |
| Tooltip         | `Tooltip.Content`        | `--moduix-tooltip-transition`, `--moduix-tooltip-popup-*`                  |
| Hover Card      | `HoverCard.Content`      | `--moduix-hover-card-transition`, `--moduix-hover-card-content-*`          |
| Floating Panel  | `FloatingPanel.Content`  | `--moduix-floating-panel-transition`, `--moduix-floating-panel-*`          |
| Dialog          | `Dialog.Content`         | `--moduix-dialog-transition`, `--moduix-dialog-content-*`                  |
| Command Palette | `CommandPalette.Content` | `--moduix-command-palette-transition`, `--moduix-command-palette-content-*` |
| Lightbox        | `Lightbox.Content`       | `--moduix-lightbox-transition`, `--moduix-lightbox-content-*`              |
| Tour            | `Tour.Content`           | `--moduix-tour-transition`, `--moduix-tour-content-*`                     |
| Navigation Menu | `NavigationMenu.Content` | `--moduix-navigation-menu-transition`, `--moduix-navigation-menu-content-*` |
| Select          | `Select.Content`         | `--moduix-select-transition`, `--moduix-select-content-*`                 |
| Combobox        | `Combobox.Content`       | `--moduix-combobox-transition`, `--moduix-combobox-content-*`              |
| Date Picker     | `DatePicker.Content`     | `--moduix-date-picker-transition`, `--moduix-date-picker-content-*`       |
| Color Picker    | `ColorPicker.Content`    | `--moduix-color-picker-transition`, `--moduix-color-picker-content-*`      |

When `NavigationMenu` uses a `Viewport`, the shared tokens also affect viewport sizing and directional
content motion. Use `--moduix-navigation-menu-viewport-*` when you need to customize the viewport itself.

`Dialog`, `CommandPalette`, `Lightbox`, and `Tour` also expose `*-backdrop-*` variables on their
`Backdrop` part. Backdrops use their own transition variable and animate only `opacity` and `blur`; they
do not use shared scale or translate values. Shared popup content can animate `opacity`, `scale`, and
`translate-x` or `translate-y`. Backdrop blur values use CSS filters such as `blur(4px)` or `none`.

### State motion

These components keep separate motion systems and do not accept `--moduix-popup-motion-*`:

| Component   | Visual part                            | Supported customization                                                                                                                   |
| ----------- | -------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| Accordion   | `Accordion.ItemContent`                | `--moduix-accordion-item-content-transition`, `--moduix-accordion-item-content-open-opacity`, `--moduix-accordion-item-content-closed-opacity` |
| Collapsible | `Collapsible.Content`                  | `--moduix-collapsible-content-transition`, `--moduix-collapsible-content-open-opacity`, `--moduix-collapsible-content-closed-opacity`          |
| Drawer      | `Drawer.Content` and `Drawer.Backdrop` | `--moduix-drawer-transition`, `--moduix-drawer-backdrop-transition`; direction and drag own the transform                                      |
| Swap        | `Swap.Indicator`                       | `--moduix-swap-transition` and separate enter/exit opacity and scale variables                                                               |
| Tree View   | `TreeView.BranchContent`               | `--moduix-tree-view-transition`, `--moduix-tree-view-content-transition-duration`                                                             |

Toast uses Ark runtime layout variables for stacking and dismissal. Keep its `--x`, `--y`, `--scale`,
`--height`, and `--opacity` values intact. The recipes on this page are not a Toast API.

## Ready recipes

Choose motion by purpose, then keep one consistent recipe for similar surfaces:

| Product intent                              | Start with                          |
| ------------------------------------------- | ----------------------------------- |
| Quiet disclosure without spatial meaning   | Fade                                |
| Surface arriving from a nearby edge         | The matching Slide direction        |
| Anchored menu or picker opening from trigger| Zoom or Lift                        |
| Short, friendly confirmation                | Soft Pop, used sparingly            |

Put these variables on `:root` to apply the recipe to all supported popup content. For one exception,
use the matching component variables from the table above.

### Fade

```css
:root {
  --moduix-popup-motion-starting-opacity: 0;
  --moduix-popup-motion-ending-opacity: 0;
  --moduix-popup-motion-starting-scale: 1;
  --moduix-popup-motion-ending-scale: 1;
  --moduix-popup-motion-starting-translate-y: 0;
  --moduix-popup-motion-ending-translate-y: 0;
}
```

## Component recipes

### Glass focus

For modal backdrops, apply the first class to `Dialog.Backdrop` and the second to `Dialog.Content`. Replace `dialog` with
`command-palette`, `lightbox`, or `tour` for the matching modal family.

```css
.glassFocusBackdrop {
  --moduix-dialog-backdrop-transition: 220ms var(--moduix-ease-out);
  --moduix-dialog-backdrop-starting-opacity: 0;
  --moduix-dialog-backdrop-ending-opacity: 0;
  --moduix-dialog-backdrop-starting-blur: none;
  --moduix-dialog-backdrop-ending-blur: none;
}

.glassFocusContent {
  --moduix-dialog-transition: 220ms cubic-bezier(0.22, 1, 0.36, 1);
  --moduix-dialog-content-starting-opacity: 0;
  --moduix-dialog-content-ending-opacity: 0;
  --moduix-dialog-content-starting-scale: 0.96;
  --moduix-dialog-content-ending-scale: 0.98;
  --moduix-dialog-content-starting-translate-y: 0.75rem;
  --moduix-dialog-content-ending-translate-y: 0.75rem;
}
```

### Soft scale

Use this soft-scale recipe on picker content. Apply the class to `Select.Content`. For `Combobox`, `ColorPicker`, or `DatePicker`, replace the
`select` prefix with `combobox`, `color-picker`, or `date-picker`.

```css
.softScalePicker {
  --moduix-select-transition: 180ms cubic-bezier(0.22, 1, 0.36, 1);
  --moduix-select-content-closed-opacity: 0;
  --moduix-select-content-closed-scale: 0.96;
}
```

### Relaxed disclosure

Apply this class to `Accordion.ItemContent`. For `Collapsible.Content`, use the
`--moduix-collapsible-content-*` prefix instead.

```css
.relaxedDisclosure {
  --moduix-accordion-item-content-transition: 240ms var(--moduix-ease-out);
  --moduix-accordion-item-content-closed-opacity: 0;
}
```

### Emphasized swap

Apply the class to `Swap.Indicator` when the outgoing item should recede and the next one should
arrive with more energy.

```css
.emphasizedSwap {
  --moduix-swap-transition: 180ms cubic-bezier(0.22, 1, 0.36, 1);
  --moduix-swap-enter-starting-opacity: 0;
  --moduix-swap-enter-starting-scale: 0.82;
  --moduix-swap-exit-ending-opacity: 0;
  --moduix-swap-exit-ending-scale: 1.08;
}
```

## Usage rules

- Put component-local motion variables on the visual part that owns the animation; set shared popup
  variables on `:root` for default portalled overlays.
- Keep entry and exit values symmetric unless asymmetric motion is intentional.
- Set scale to `1` for pure fade or slide motion.
- Use `--moduix-popup-motion-*` for one rule covering popup content across the project; use component-local
  variables only for the exception.
- Do not replace Drawer transforms or Toast runtime layout variables: both are coordinated with
  interaction and dismissal state.
- Exit animation works by default. Use `present` only when JavaScript must explicitly own whether a
  part is mounted; it is not needed for ordinary CSS recipes.
