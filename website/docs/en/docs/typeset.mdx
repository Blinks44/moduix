## API Reference

`Typeset` applies a consistent reading rhythm to the semantic HTML inside its boundary. It does not
render or parse Markdown, sanitize content, or decide the content width. Your application remains
responsible for those decisions.

moduix builds `Typeset` with the
[Ark factory](https://ark-ui.com/docs/guides/composition#the-ark-factory). `Typeset` and
`Typeset.Scroll` therefore accept native `div` props, refs, and `asChild` composition.

## Basic

Wrap HTML that your renderer has already produced in `<Typeset>`. Use `asChild` only when the outer
container needs to be semantic, such as an `article` or `section`. Keep lists as native `<ul>` and
`<ol>` elements: Typeset provides their markers and spacing without utility classes.

## Anatomy

```text
Typeset
└─ Typeset.Scroll (optional)
```

| Part | Role |
| --- | --- |
| `Typeset` / `Typeset.Root` | Scoped root that styles semantic descendants. |
| `Typeset.Scroll` | Focusable horizontal scroller for a wide rendered block. |

## Composition

### Recommended composition

Parse, sanitize, render, and size Markdown in your application. `Typeset` only styles descendants
inside its root and intentionally has no width prop. Wrap a wide table or another block in
`Typeset.Scroll` when horizontal scrolling is the better result.

### When to go custom

If a subtree needs its own visual treatment, use semantic HTML directly, then add `.not-typeset` or
`data-not-typeset` to exclude that element and all of its descendants. Give every user-facing
`Typeset.Scroll` an `aria-label` or `aria-labelledby`. moduix adds `role="region"` when the scroller
has an accessible name, unless you provide another role. You can also set a custom `tabIndex`.

### Default props

| Part | Default | Notes |
| --- | --- | --- |
| `Typeset` | `div` | Use `asChild` with exactly one semantic child to render a different container. |
| `Typeset.Scroll` | `div`, `tabIndex={0}` | The default focus makes a wide static table reachable with the keyboard. Add an accessible name to a user-facing scroller to give it `role="region"`. |

### Behavioral notes

The `Typeset` root does not manage state, keyboard interactions, form controls, or hidden inputs.
`Typeset.Scroll` is keyboard-focusable by default so the browser can scroll a wide static block.
Styles add space before rendered blocks and avoid `:last-child`, `:has()`, and `:empty`, so appending
streamed content does not change the layout of earlier blocks.

Use `--moduix-typeset-size`, `--moduix-typeset-leading`, and `--moduix-typeset-flow` to control the
reading rhythm. Font variables are optional; colors, borders, and radius come from the active moduix
theme. Element rules live in the `moduix.components` layer and use low-specificity `:where()`
selectors, so normal application CSS can override individual elements without `!important`.

### Styling hooks

- `data-slot="typeset"` targets the root container.
- `data-slot="typeset-scroll"` targets the optional overflow wrapper and its focus-visible state.
- `[data-scope="typeset"][data-part="root"]` and `[data-part="scroll"]` expose stable anatomy
  hooks.
