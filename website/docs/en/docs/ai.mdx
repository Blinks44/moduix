# AI

moduix keeps its public API and source structure readable for both developers and AI assistants.
Give an assistant the smallest piece of documentation that answers the question, then tell it which
ownership model your project uses.

## Choose the right context

| Task                                             | Give the assistant                |
| ------------------------------------------------ | --------------------------------- |
| A product overview or a component discovery task | [`llms.txt`](/llms.txt)           |
| Help with one component, guide, or error         | That page's **Copy Markdown**     |
| A broad repository-level review                  | [`llms-full.txt`](/llms-full.txt) |

Every MDX page has a canonical Markdown URL such as `https://moduix.dev/docs/button.md`. It contains
the page without the docs interface, so it is the best default context for a focused implementation
or debugging task.

## Ask about the current page

When an assistant needs one page without the docs interface, use **Copy Markdown** below the page
title. Component pages also have an **Open** menu with GitHub, **View as Markdown**, ChatGPT, and
Claude shortcuts.

Give the assistant the URL and a concrete goal. For example:

```text
Read https://moduix.dev/docs/dialog.md. Add a confirmation dialog to our delete action.
We use @moduix/react/dialog from the npm package. Keep the Ark composition explicit and make the
trigger a button.
```

## Install with an AI assistant

Before an assistant writes an import or install command, tell it where the moduix code should live:

| Project model              | Tell the assistant to use                                                                    |
| -------------------------- | -------------------------------------------------------------------------------------------- |
| Package-managed components | `@moduix/react/*` imports and `@moduix/react/style.css`                                      |
| Copy-owned components      | The configured `@moduix-react` registry, the project's `components.json`, and its CLI runner |

For a copy-owned project, the assistant should read the component page and inspect `components.json`
before adding a registry item. The [Quick start](/docs/quick-start) guide has the complete registry
configuration.

## Use the moduix Skill

The moduix Skill and the shadcn registry serve different purposes. The Skill installs instructions
for an AI agent; the shadcn registry installs component source, styles, and utilities into your
project.

Install the moduix Skill from the repository with Skills CLI:

```bash
npx skills add https://github.com/Blinks44/moduix --skill moduix
```

Before changing code, the Skill checks existing imports and `components.json`, reads the canonical
docs, and uses shadcn discovery plus dry-run or diff checks for copy-owned updates. It does not
choose the ownership model for you. Invoke it as `$moduix` in skill-aware agents.

## Connect shadcn MCP

The shadcn MCP server can use the hosted moduix registry. moduix does not need a separate MCP
server: configure the registry in the consuming project, then connect shadcn to your AI client.

### 1. Configure the registry

Add the moduix registry URL to the consuming project's `components.json`:

```json
{
  "registries": {
    "@moduix-react": "https://moduix.dev/r/react/{name}.json"
  }
}
```

The registry contains components, themes, and shared support items. Recipes remain documentation;
install the components they list. See [Quick start](/docs/quick-start) for the complete
`components.json` configuration.

### 2. Connect the AI client

For clients supported by the shadcn initializer, run it in the consuming project and choose the
matching client. For example:

```bash
npx shadcn@latest mcp init --client cursor
```

Codex currently uses manual MCP configuration. Add the server to `~/.codex/config.toml`, then
restart Codex:

```toml
[mcp_servers.shadcn]
command = "npx"
args = ["shadcn@latest", "mcp"]
```

The [shadcn MCP guide](https://ui.shadcn.com/docs/mcp) has the current setup for Claude Code,
Cursor, VS Code, Codex, and other supported clients.

### 3. Discover before installing

Ask the assistant to inspect the relevant docs and registry item before it changes files. These
prompts cover components, themes, and multi-component recipes:

```text
Find the moduix component for an editable text field. Show the component documentation and registry
item before proposing code.
```

```text
Read https://moduix.dev/recipes/login-simple.md. List the moduix components it uses and the
application code I need to connect before proposing changes.
```

```text
Find a high-contrast moduix theme. Show how it is applied before changing the project.
```

### 4. Use the CLI when needed

Use the CLI when MCP is unavailable or when you want a command-line review trail. In a copy-owned
project, inspect the configuration, search by product need, view the item, and preview the change:

```bash
npx shadcn@latest info --json
npx shadcn@latest search @moduix-react --query "confirmation dialog"
npx shadcn@latest view @moduix-react/dialog
npx shadcn@latest add @moduix-react/dialog --dry-run
```

For an already-installed item, inspect the generated-file diff before updating it:

```bash
npx shadcn@latest add @moduix-react/dialog --diff src/components/moduix/dialog.tsx
```

Run `add` without preview flags only after the item, dependencies, target paths, and ownership
model are correct. Do not use `--overwrite` without an explicit decision to replace local changes.

## Review generated code

Treat generated code as a draft. Before merging it, check that it:

- uses the documented moduix parts and callback detail objects instead of invented aliases;
- keeps the correct package or registry ownership model;
- passes your normal typecheck, tests, and accessibility review.

MCP can discover either ownership model, but only copy-owned projects should use registry `add`
commands. Package-managed projects keep `@moduix/react/*` imports and update through their package
manager. The [Updating and migration](/docs/updating) guide explains the copy-owned update workflow.
