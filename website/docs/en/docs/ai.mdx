# AI

Use this guide when an AI assistant reads moduix documentation or changes a project that uses moduix.

This page documents a workflow, not a runtime API. moduix does not export an AI utility, package, or hook. The relevant sources are the public documentation and, for copied components, the moduix registries.

## Choose the right context

Give the assistant only the documentation needed for the task.

| Task | Context |
| --- | --- |
| Discover available documentation | [llms.txt](/llms.txt) |
| Work with one component or guide | Use **Copy Markdown** on that page, or add `.md` to its URL |
| Review several related areas | [llms-full.txt](/llms-full.txt) |

State the framework, styling system, ownership model, and expected change in the prompt:

```text
Read https://moduix.dev/docs/button.md. Add a destructive action to our React application.
We use @moduix/react with CSS Modules. Import Button from @moduix/react/button and show the
proposed diff before changing files.
```

## Install the moduix Skill

moduix publishes the consumer-facing Agent Skill `moduix` from the repository's `skills/moduix` directory. It helps compatible agents identify the project's framework, styling track, and ownership model before changing code. The Skill provides instructions only; it does not install moduix packages or copy registry components.

Install only the `moduix` Skill from the repository:

<PackageManagerTabs command="skills add https://github.com/Blinks44/moduix --skill moduix" dlx />

Run the command from the project where the agent will use moduix. In agents that support explicit invocation, use `$moduix` for moduix tasks.

## State how moduix is managed

moduix supports two ownership models:

- **Package-managed:** the project imports a public `@moduix/*` package. Updates come through the package manager.
- **Copy-owned:** the shadcn CLI copies an item from a moduix registry into the project. The project owns and maintains the generated files.

Use the package and registry that match the project:

| Setup | Package import | Registry namespace |
| --- | --- | --- |
| React with CSS Modules | `@moduix/react/<component>` | `@moduix-react/<name>` |
| Solid with CSS Modules | `@moduix/solid/<component>` | `@moduix-solid/<name>` |
| React with Tailwind CSS | `@moduix/react-tailwind/<component>` | `@moduix-react-tailwind/<name>` |
| Solid with Tailwind CSS | `@moduix/solid-tailwind/<component>` | `@moduix-solid-tailwind/<name>` |

See [Quick Start](./quick-start) for package installation and registry configuration. Do not ask an assistant to copy registry source into a package-managed project unless you intend to change the ownership model.

## Connect the shadcn MCP server

The optional MCP server is provided by shadcn, not moduix. It lets an AI assistant inspect and install items from shadcn-compatible registries configured in the project's `components.json`.

For Codex, add the server to `~/.codex/config.toml`:

```toml
[mcp_servers.shadcn]
command = "npx"
args = ["shadcn@latest", "mcp"]
```

Restart Codex after changing the configuration. For other clients, follow the [shadcn MCP documentation](https://ui.shadcn.com/docs/mcp).

## Review generated changes

Before accepting a change, check that the assistant:

- selected the correct framework, styling system, and ownership model
- used documented public imports and APIs
- did not overwrite local changes
- kept accessibility behavior and application-owned state intact
- ran the project's focused type checks, lint checks, and tests

Documentation and registry metadata provide context, but the application still owns its data, routing, handlers, and final review.
