## Use in a route

Render `ResetPassword` in the route reached from a verified reset link and pass its real submit
handler. Replace the default `/sign-in` link with your application route.

Verify the reset token on the server before accepting the password. Show an expired or already-used
token as a route-level state with a link to request a new email. During submission, disable duplicate
requests, validate the confirmation field, and attach a safe server error to the form. After success,
invalidate the token and take the user to sign in or an authenticated session according to your policy.
