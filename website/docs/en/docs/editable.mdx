## Usage

<Usage />

Use `Editable` as the root and compose it from `EditableLabel`, `EditableArea`, `EditableInput`,
and `EditablePreview`. Add `EditableControls` for the standard edit, submit, and cancel flow.
moduix adds styles, `data-slot` hooks, and default trigger icons. By default, users enter edit mode
with a double-click, which helps prevent accidental changes.

## Choosing the right component

- Choose **`Input`** or **`Textarea`** when the value should always be available for editing.
- Choose **`Editable`** when the value is usually read-only and editing should be an explicit action.
- Wrap **`Editable`** in **`Field`** when helper text, error text, or shared form state should appear
  outside the component.

## Examples

### Textarea

Use `EditableInput asChild` with a native `<textarea>` for multiline content. The textarea gets a
minimum height, the preview keeps line breaks, and the controls stay at the top. Press Cmd/Ctrl +
Enter to save; Enter inserts a new line.

### Custom triggers

Render your own `Button` in each trigger with `asChild`. `EditableContext` switches between the edit

the visible text.

Use moduix `useEditable()` and `EditableRootProvider` when controls outside the component tree
need access to `Editable` state and methods. Pass `activationMode: 'dblclick'` to the hook to match
the root component's default activation behavior. The provider replaces `Editable` for this
state instance. See [Share state outside the tree](/docs/composition-patterns#root-provider).

## Composition

Keep `EditableInput` and `EditablePreview` as siblings inside `EditableArea`, then place
`EditableControls` after the area for the standard edit, submit, and cancel flow. Use
`EditableRootProvider` instead of `Editable` when state created by `useEditable()` must be
shared with controls outside the rendered tree. Use `EditableContext` or `useEditableContext()` for
custom content that depends on the current edit state. In Solid, the store exposed by `useEditable()`
and context is an accessor, so read state as `editable().editing`.

## Styling

Use `className` in React or `class` in Solid and Vue on exported parts for structural styles. Tailwind
variants use native utilities and consumer classes. CSS Modules variants also expose the variable
below, which keeps the area and the square triggers the same height. Data attributes and `data-slot`
hooks are shared by both styling tracks.

The root fills the width of its container, so switching between preview and input does not shift the
layout. With `autoResize`, the root follows the text width instead. To limit the width, set
`max-width` on the root with a class.

- Ark part selectors: `data-scope="editable"` and
  `data-part="root|area|label|preview|input|edit-trigger|submit-trigger|cancel-trigger|control"`.

  `data-required`, `data-placeholder-shown`, and `data-autoresize`.
- `EditableControls` shares the `editable-control` slot with `EditableControl`.

## Keyboard

| Key | Action |
| --- | --- |
| `Enter` | Saves the value when submitMode allows it. |
| `Esc` | Cancels the edit and restores the previous value. |

## API reference

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `value` | `string` | — | Value for controlled use. |
| `defaultValue` | `string` | — | Initial value when it is not controlled. |

| `onValueCommit` | `(details: ValueChangeDetails) => void` | — | Called when the edit is saved. |
| `onValueRevert` | `(details: ValueChangeDetails) => void` | — | Called when the edit is canceled. |
| `activationMode` | `'focus' \| 'dblclick' \| 'click' \| 'none'` | `'dblclick'` | What starts editing: `focus`, `click`, `dblclick`, or `none`. |
| `submitMode` | `'enter' \| 'blur' \| 'both' \| 'none'` | `'both'` | What saves the edit: `enter`, `blur`, `both`, or `none`. |
| `selectOnFocus` | `boolean` | `true` | Selects the text when editing starts. |
| `edit` | `boolean` | — | Edit mode for controlled use. |
| `onEditChange` | `(details: EditChangeDetails) => void` | — | Called when edit mode starts or ends. |

| `maxLength` | `number` | — | Maximum number of characters. |

| `readOnly` | `boolean` | `false` | Shows the value but prevents changes. |

| `required` | `boolean` | `false` | Requires a value before form submission. |
| `form` | `string` | — | Id of the form the underlying input belongs to. |
