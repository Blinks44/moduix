## Choosing the right component

- Choose **`Input`** or **`Textarea`** when the value should always be available for editing.
- Choose **`Editable`** when the value is usually read-only and editing should be an explicit action.
- Wrap **`Editable`** in **`Field`** when helper text, error text, or shared form state should appear
  outside the component.

## Basic

Use `Editable` as the root and compose it from `Editable.Label`, `Editable.Area`, `Editable.Input`,
and `Editable.Preview`. Add `Editable.Controls` for the standard edit, submit, and cancel flow.
The moduix wrapper adds styles, `data-slot` hooks, and default trigger icons. By default, users
enter edit mode with a double-click, which helps prevent accidental changes.

## Anatomy

```text
Editable.Root
├─ Editable.Label
├─ Editable.Area
│  ├─ Editable.Input
│  └─ Editable.Preview
├─ Editable.Control or Editable.Controls
│  ├─ Editable.EditTrigger
│  ├─ Editable.SubmitTrigger
│  └─ Editable.CancelTrigger

Editable.RootProvider
└─ same part tree connected to Ark `useEditable()` state
```

| Part                         | Role                                                   |
| ---------------------------- | ------------------------------------------------------ |
| `Editable` / `Editable.Root` | Component state, callbacks, form props, and accessibility wiring. |
| `Editable.RootProvider`      | Root connected to a `useEditable()` instance.                    |
| `Editable.Label`             | Visible label for the input and preview.                          |
| `Editable.Area`              | Shared container for the input and preview.                       |
| `Editable.Input`             | Text input shown while editing.                                   |
| `Editable.Preview`           | Read-only value or placeholder shown outside edit mode.           |
| `Editable.Control`           | Optional container for the edit, submit, and cancel buttons.      |
| `Editable.Controls`          | Convenience wrapper for the standard edit, submit, and cancel flow. |
| `Editable.EditTrigger`       | Button that enters edit mode.                                     |
| `Editable.SubmitTrigger`     | Button that commits the current value.                            |
| `Editable.CancelTrigger`     | Button that reverts the current value.                            |

## Composition

### Recommended composition

Place `Editable.Input` and `Editable.Preview` as siblings inside `Editable.Area`. Put
`Editable.Controls` after the area to use the standard trigger layout. For a single-line input,
the controls appear on the right and are vertically centered. Textarea compositions use the same
structure. Set `--moduix-editable-control-align: start` to align the controls with the top of the
multiline area.

### When to go custom

Use moduix `Editable.Context` or `useEditableContext()` when reusable child parts or custom content
need access to the current edit state. Use `useEditable()` with `Editable.RootProvider` when the
state or methods need to live outside the rendered `Editable` tree. `RootProvider` replaces
`Editable.Root` for that state instance. Use `asChild` when the input should render as another
semantic element, such as a native `<textarea>`.

### Default props

| Prop             | Default    | Notes                                                                                                                 |
| ---------------- | ---------- | --------------------------------------------------------------------------------------------------------------------- |
| `activationMode` | `dblclick` | moduix uses double-click by default. Pass `focus`, `click`, or `none` to choose a different Ark activation mode. |
| `selectOnFocus`  | `true`     | Ark selects input text when the input receives focus.                                                                 |
| `submitMode`     | `both`     | `Enter` and blur commit by default. Use `none` when only explicit submit controls should commit the value. |

### Behavioral notes

The `value` and `defaultValue` props set the text value. The `edit` and `defaultEdit` props control
edit mode. Ark callback props keep their `details` objects, so `onValueChange`, `onValueCommit`,
`onValueRevert`, and `onEditChange` receive the same payload shapes as in Ark UI.

Press `Enter` to commit the value and `Escape` to revert it. When `Editable.Input` renders as a
textarea through `asChild`, Cmd/Ctrl + Enter commits the value. `name` and `form` are forwarded to
Ark for native form submission. `disabled` prevents interaction, while `readOnly` keeps the value
visible without allowing edits.

Set `translations.input` to provide a context-specific accessible name for the input.
`Editable.Label` remains the visible label.

### Styling hooks

- Target parts with `data-slot="editable-root"`, `editable-root-provider`, `editable-label`,
  `editable-area`, `editable-input`, `editable-preview`, `editable-control`,
  `editable-edit-trigger`, `editable-submit-trigger`, and `editable-cancel-trigger`.
- Ark also emits `data-scope="editable"` and `data-part` attributes for each part.
- State selectors include `data-focus` on `Label` and `Area`; `data-disabled` on `Area`, `Input`,
  and `Preview`; `data-readonly` / `aria-readonly` on read-only controls; `data-invalid` on
  `Label`, `Input`, and `Preview`; `data-required` on `Label`; `data-placeholder-shown` on `Area`
  and `Preview`; and `data-autoresize` on `Input` and `Preview`.
