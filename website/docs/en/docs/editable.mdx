## Choosing the right component

- Choose **`Input`** or **`Textarea`** when the value should always be available for editing.
- Choose **`Editable`** when the value is usually read-only and editing should be an explicit action.
- Wrap **`Editable`** in **`Field`** when helper text, error text, or shared form state should appear
  outside the component.

## Basic

`Editable` ships for React and Solid in both the CSS Modules and Tailwind packages. The live preview
uses the React CSS Modules package; the framework tabs show native source for the same public contract.

Use `Editable` as the root and compose it from `Editable.Label`, `Editable.Area`, `Editable.Input`,
and `Editable.Preview`. Add `Editable.Controls` for the standard edit, submit, and cancel flow.
moduix adds styles, `data-slot` hooks, and default trigger icons. By default, users enter edit mode
with a double-click, which helps prevent accidental changes.

## Anatomy

```text
Editable.Root
├─ Editable.Label
├─ Editable.Area
│  ├─ Editable.Input
│  └─ Editable.Preview
├─ Editable.Control or Editable.Controls
│  ├─ Editable.EditTrigger
│  ├─ Editable.SubmitTrigger
│  └─ Editable.CancelTrigger

Editable.RootProvider
└─ same part tree connected to Ark `useEditable()` state
```

| Part                         | Role                                                   |
| ---------------------------- | ------------------------------------------------------ |
| `Editable` / `Editable.Root` | Component state, callbacks, form props, and accessibility wiring. |
| `Editable.RootProvider`      | Root connected to a `useEditable()` instance.          |
| `Editable.Label`             | Visible label for the input and preview.               |
| `Editable.Area`              | Shared container for the input and preview.            |
| `Editable.Input`             | Text input shown while editing.                        |
| `Editable.Preview`           | Read-only value or placeholder shown outside edit mode. |
| `Editable.Control`           | Optional container for edit, submit, and cancel buttons. |
| `Editable.Controls`          | Convenience wrapper for the standard trigger flow.   |
| `Editable.EditTrigger`       | Button that enters edit mode.                          |
| `Editable.SubmitTrigger`     | Button that commits the current value.                 |
| `Editable.CancelTrigger`     | Button that reverts the current value.                 |

## Composition

Keep `Editable.Input` and `Editable.Preview` as siblings inside `Editable.Area`, then place
`Editable.Controls` after the area for the standard edit, submit, and cancel flow. Use
`Editable.RootProvider` instead of `Editable.Root` when state created by `useEditable()` must be
shared with controls outside the rendered tree. Use `Editable.Context` or `useEditableContext()` for
custom content that depends on the current edit state. In Solid, the store exposed by `useEditable()`
and context is an accessor, so read state as `editable().editing`.

need access to `Editable` state and methods. Pass `activationMode: 'dblclick'` to the hook to match
the root component's default activation behavior. The provider replaces `Editable.Root` for this
state instance.
