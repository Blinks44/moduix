## Choosing the right component

- Choose **`Input`** or **`Textarea`** when the value should always appear editable.
- Choose **`Editable`** when the value is usually read-only and users enter edit mode intentionally.
- Wrap **`Editable`** in **`Field`** when helper text, error text, or shared form state should appear
  outside its part tree.

## Basic

Use the Ark-style parts: `Editable`, `Editable.Label`, `Editable.Area`, `Editable.Input`, and
`Editable.Preview`. Add `Editable.Controls` for the standard edit, submit, and cancel flow.
The moduix wrapper adds styles, `data-slot` attributes, and default trigger icons.
By default, moduix enters edit mode on double-click to help prevent accidental edits.

## Anatomy

```text
Editable.Root
├─ Editable.Label
├─ Editable.Area
│  ├─ Editable.Input
│  └─ Editable.Preview
├─ Editable.Control or Editable.Controls
│  ├─ Editable.EditTrigger
│  ├─ Editable.SubmitTrigger
│  └─ Editable.CancelTrigger

Editable.RootProvider
└─ same part tree connected to Ark `useEditable()` state
```

| Part                         | Role                                                   |
| ---------------------------- | ------------------------------------------------------ |
| `Editable` / `Editable.Root` | Component state, callbacks, form props, and accessibility wiring. |
| `Editable.RootProvider`      | Root connected to a `useEditable()` instance.                    |
| `Editable.Label`             | Visible label for the input and preview.                          |
| `Editable.Area`              | Shared container for the input and preview.                       |
| `Editable.Input`             | Text input shown while editing.                                   |
| `Editable.Preview`           | Read-only value or placeholder shown outside edit mode.           |
| `Editable.Control`           | Optional container for the edit, submit, and cancel buttons.      |
| `Editable.Controls`          | Convenience wrapper for the standard edit, submit, and cancel flow. |
| `Editable.EditTrigger`       | Button that enters edit mode.                                     |
| `Editable.SubmitTrigger`     | Button that commits the current value.                            |
| `Editable.CancelTrigger`     | Button that reverts the current value.                            |

## Composition

### Recommended composition

Keep `Input` and `Preview` as siblings inside `Area`, and place `Controls` after `Area` for the
standard trigger layout. For single-line inputs, the trigger buttons appear on the right and are
vertically centered. Textarea compositions use the same structure. Set
`--moduix-editable-control-align: start` to align the controls with the top of the multiline area.

### When to go custom

Use moduix `Editable.Context` or `useEditableContext()` when reusable child parts or inline state
reads need access to the edit state. Use moduix `useEditable()` with `Editable.RootProvider` when
state or methods must be managed outside the rendered `Editable` tree. Use `asChild` when the input
needs a custom semantic host, such as a textarea.

### Default props

| Prop             | Default    | Notes                                                                                                                 |
| ---------------- | ---------- | --------------------------------------------------------------------------------------------------------------------- |
| `activationMode` | `dblclick` | moduix uses double-click by default. Pass `focus`, `click`, or `none` to choose a different Ark activation mode. |
| `selectOnFocus`  | `true`     | Ark selects input text when the input receives focus.                                                                 |
| `submitMode`     | `both`     | `Enter` and blur commit by default. Use `none` when only explicit submit controls should commit the value. |

### Behavioral notes

`value` and `defaultValue` control the text value. `edit` and `defaultEdit` control edit mode. Ark
callback props preserve their `details` objects, so `onValueChange`, `onValueCommit`,
`onValueRevert`, and `onEditChange` receive the same payload shapes as in Ark UI.

`Enter` commits the value, and `Escape` reverts it. When `Editable.Input` renders a textarea through
`asChild`, Cmd/Ctrl + Enter commits the value. `name` and `form` are forwarded to Ark for native
form submission. `disabled` blocks activation, while `readOnly` keeps the value visible without
allowing it to change.

Set `translations.input` when the input needs a context-specific accessible name. `Editable.Label`
remains the visible label.

### Styling hooks

- `data-slot="editable-root"`, `editable-root-provider`, `editable-label`, `editable-area`,
  `editable-input`, `editable-preview`, `editable-control`, `editable-edit-trigger`,
  `editable-submit-trigger`, and `editable-cancel-trigger`.
- Ark also emits `data-scope="editable"` and `data-part` attributes for each primitive part.
- State selectors include `data-focus` on `Label` and `Area`; `data-disabled` on `Area`, `Input`,
  and `Preview`; `data-readonly` / `aria-readonly` on read-only controls; `data-invalid` on
  `Label`, `Input`, and `Preview`; `data-required` on `Label`; `data-placeholder-shown` on `Area`
  and `Preview`; and `data-autoresize` on `Input` and `Preview`.
