Use `RadioGroup` when people need to choose exactly one option from a visible set, such as a
framework, plan, or account type. Use `Checkbox` for independent choices and `Switch` for a setting
that takes effect immediately.

## API Reference

`RadioGroup` follows the Ark UI radio-group primitive and adds moduix styling, stable `data-slot`
attributes, and the `Option` convenience component. The component is exported from
`@moduix/react/radio-group`.

<PrimitiveReference href="https://ark-ui.com/docs/components/radio-group" />

## Basic

For most groups, use `RadioGroup.Option` to render a labelled item with a control and visible text.
Each item includes its native hidden input automatically. If the group belongs to a native form, pass

## Anatomy

```text
RadioGroup.Root
├─ RadioGroup.Label
├─ RadioGroup.Indicator
└─ RadioGroup.Item[value]
   ├─ RadioGroup.ItemControl
   ├─ RadioGroup.ItemText
   └─ <input> (automatic)

RadioGroup.RootProvider
└─ RadioGroup.* + useRadioGroup()

RadioGroup.Option
└─ RadioGroup.Item + ItemControl + ItemText + <input> (automatic)
```

| Part                           | Role                                                        |
| ------------------------------ | ----------------------------------------------------------- |
| `RadioGroup` / `.Root`         | Owns value state, keyboard navigation, orientation, and forms. |
| `RadioGroup.RootProvider`      | Connects parts to state created with `useRadioGroup()`.    |
| `RadioGroup.Label`             | Accessible label for the group.                             |
| `RadioGroup.Item`              | One selectable option; renders a `label` by default.        |
| `RadioGroup.Option`            | Convenience item with a control, text, and hidden input.   |
| `RadioGroup.ItemControl`       | Visual radio control; supports the moduix `size` prop.      |
| `RadioGroup.ItemText`          | Visible option text.                                        |
| `RadioGroup.Indicator`         | Optional active-item indicator using Ark measurement vars.  |

## Composition

### Recommended composition

`RadioGroup` is the short form of `RadioGroup.Root`. Use `RadioGroup.Option` for the common labelled
item. It accepts the Ark item props, the moduix `size` prop, and `className`. The class is applied to
the underlying `Item`, so nested parts remain targetable through their `data-slot` hooks.

### When to go custom

Use `RadioGroup.RootProvider` with `useRadioGroup()` from `@moduix/react` when the state must be
created before the group renders, shared with controls outside the rendered tree, or read by a
separate part of the interface. Pass the returned store to `RootProvider` and do not render `Root`
and `RootProvider` for the same state instance.

Use the explicit `Item` tree when nested parts need their own placement or class names, or when
`RadioGroup.Item asChild` must let another element own the item DOM node. The direct child of an
`Item` using `asChild` must still be a semantic `label`.

For advanced state reads, use `RadioGroup.Context`, `RadioGroup.ItemContext`,
`useRadioGroupContext()`, or `useRadioGroupItemContext()` from `@moduix/react`.

### Default props

| Prop                             | Default | Notes                                                   |
| -------------------------------- | ------- | ------------------------------------------------------- |
| `RadioGroup` / `RadioGroup.Root` | -       | Ark defaults apply; moduix adds no root behavior defaults. |
| `RadioGroup.Option size`         | `md`    | Control diameter and indicator-dot scale.               |
| `RadioGroup.ItemControl size`    | `md`    | Moduix control diameter and indicator-dot scale.        |

### Behavioral notes

`RadioGroup.Root` accepts Ark props such as `value`, `defaultValue`,
`onValueChange(details)`, `name`, `form`, `orientation`, `disabled`, `invalid`, `readOnly`,
`required`, `ids`, and `asChild`. In the callback, read the selected value from `details.value`.

Each `RadioGroup.Item` renders its native form input automatically. The input supports native form
submission, validation, and reset, so you do not need to add an input part yourself. Set `name` on
the root when the selected value should be included in `FormData`.

Ark manages the controlled and uncontrolled value state, roving focus, WAI-ARIA behavior, and
keyboard navigation. <kbd>Tab</kbd> moves focus to the checked item, or to the first item when none
is checked. <kbd>Space</kbd> checks the focused item, and the arrow keys move to and check the next
or previous item.

`Field.Root` provides a visible label, helper text, and error text, but it does not pass its state to
`RadioGroup`. Pass `disabled`, `invalid`, `readOnly`, and `required` to the group itself.
`Fieldset.Root` passes its Ark `disabled` and `invalid` state to nested radio groups.

Every styled part forwards its ref to the corresponding Ark DOM part. The automatic native input is
internal and is not a separate public ref target.

## Styling

Style `RadioGroup` through `className`, stable `data-slot="radio-group-*"` hooks, Ark
`data-scope`, `data-part`, and `data-state` attributes, and the public `--moduix-radio-*` CSS
variables below.

### Styling hooks

- Ark anatomy hooks: `data-scope="radio-group"` and `data-part` on the root, label, item,
  item-control, item-text, item-hidden-input, and indicator.
- Ark state hooks: `data-state="checked|unchecked"`, `data-disabled`, `data-readonly`,
  `data-invalid`, `data-required`, `data-focus`, `data-focus-visible`, `data-hover`,
  `data-active`, and `data-orientation`.
- Ark indicator variables: `--transition-property`, `--left`, `--top`, `--width`, and `--height`.
- moduix hooks: `data-slot="radio-group-root"`, `radio-group-root-provider`, `radio-group-label`,
  `radio-group-item`, `radio-group-item-control`, `radio-group-item-text`, `radio-group-item-hidden-input`, and
  `radio-group-indicator`.
