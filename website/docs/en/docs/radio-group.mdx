Use `RadioGroup` as the root and give every option a value. `RadioGroupOption` renders a labelled
item with its control, text, and native input.

## Choosing the right component

Use `RadioGroup` when people need to choose exactly one option from a visible set, such as a
framework, plan, or account type. Use `Checkbox` for independent choices and `Switch` for a setting
that takes effect immediately.

## Composition

`RadioGroup` follows the Ark UI radio-group primitive and adds moduix styling, stable `data-slot`
attributes, and the `RadioGroupOption` convenience component. It is exported from
`@moduix/react/radio-group`, `@moduix/solid/radio-group`, and `@moduix/vue/radio-group`.

Use `defaultValue` for an uncontrolled group. Use `value` with `onValueChange(details)` when another
part of the application owns the selected value. When state must be created outside the rendered
tree, use `RadioGroupRootProvider` with `useRadioGroup()` from the matching framework package. Do not render
`RadioGroup` and `RadioGroupRootProvider` for the same state instance. React reads the store as an
object; Solid reads its reactive state through the returned accessor; Vue exposes the reactive store directly to the
template.

`RadioGroupOption` includes `RadioGroupItemHiddenInput` in its fixed composition. When composing
`RadioGroupItem` directly, add `RadioGroupItemHiddenInput` yourself. Use the explicit item tree
when nested parts need custom placement or when `asChild` should let another element own the item
DOM node. In Solid, `asChild` uses a render function; in Vue, use `as-child`. In both cases the
direct child must remain a semantic `label`.

`Field` provides a visible label, helper text, and error text, but it does not pass its state to
the group. Pass `disabled`, `invalid`, `readOnly`, and `required` to `RadioGroup` itself.
`Fieldset` passes its Ark `disabled` and `invalid` state to nested radio groups.

## Styling

Use `className` in React or `class` in Solid and Vue on exported parts for structural styles. For state-based
styles, prefer Ark data attributes such as `data-state`, `data-disabled`, and `data-orientation`,
together with moduix `data-slot` selectors. Tailwind variants use native utilities and consumer
classes; the component variables below customize the CSS Modules variants. Data attributes and
`data-slot` hooks are shared by both styling tracks.

## Keyboard

| Key | Action |
| --- | --- |
| `Tab` | Moves focus into the group, to the selected option. |
| `ArrowDown` / `ArrowUp` / `ArrowLeft` / `ArrowRight` | Moves to the next or previous option and selects it. |
| `Space` | Selects the focused option. |
