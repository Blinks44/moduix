# List Selection

`useListSelection` manages selected values in a `ListCollection` while your application owns the
markup and interaction model.

## API reference

<PrimitiveReference href="https://ark-ui.com/docs/collections/list-selection" />

The hook is provided by Ark UI, not re-exported by Moduix. Import it from the collection entry point
for the framework in your application:

`@moduix/react-tailwind`, or `@moduix/solid-tailwind`. This page documents the Ark UI hook that can
be used alongside any of those packages.

## API essentials

### Configuration

| Option                    | Description                                                        | Default     |
| ------------------------- | ------------------------------------------------------------------ | ----------- |
| `collection`              | `ListCollection` whose values can be selected.                    | required    |
| `selectionMode`           | `'single'`, `'multiple'`, `'extended'`, or `'none'`.               | `'single'`  |
| `deselectable`            | Whether selecting the current value again can clear the selection. | `true`      |
| `initialSelectedValues`   | Initial values for uncontrolled selection.                         | `[]`        |
| `resetOnCollectionChange` | Whether to clear selection when the collection changes.           | `false`     |

`initialSelectedValues` is read when the selection is created. Use `setSelectedValues` or another
action to change the selection later. In Solid, state properties are accessors, so read them as
`selection.selectedValues()` and `selection.isEmpty()`; action methods keep the same call shape as
in React.

### State and actions

| API                                | Description                                               |
| ---------------------------------- | --------------------------------------------------------- |
| `selectedValues`                   | Currently selected values.                                |
| `isEmpty`                          | Whether no value is selected.                             |
| `firstSelectedValue`               | First selected value in collection order, or `null`.     |
| `lastSelectedValue`                | Last selected value in collection order, or `null`.      |
| `isSelected(value)`                | Checks whether a value is selected.                       |
| `canSelect(value)`                 | Checks whether the value can be selected in this mode.   |
| `isAllSelected()`                  | Checks whether every collection value is selected.        |
| `isSomeSelected()`                 | Checks whether at least one collection value is selected. |
| `select(value, forceToggle?)`      | Selects according to the current mode.                   |
| `deselect(value)`                  | Removes one selected value.                               |
| `toggle(value)`                    | Toggles one value.                                        |
| `replace(value)`                   | Replaces the selection with one value.                    |
| `extend(anchorValue, targetValue)` | Extends selection between two values in collection order. |
| `setSelectedValues(values)`        | Sets the selected values, subject to the current mode.    |
| `clear()`                          | Clears selection when `deselectable` is `true`.           |
| `resetSelection()`                 | Creates a new empty selection with current settings.      |

`replace(null)` leaves the current selection unchanged. Use `resetSelection()` when you need an
empty selection even if `deselectable` is `false`.

## Interaction and accessibility

`useListSelection` does not listen for pointer or keyboard events and does not add ARIA attributes.
Choose the semantics that match your markup:

- Use native buttons with `aria-pressed` when each option is an independent toggle, as in the
  examples.
- Keep focus management, keyboard shortcuts, and live status messages in your interaction layer.
- For Shift-click or another range gesture, keep the anchor value in application state and call
  `extend(anchorValue, targetValue)`. For modifier-key toggling, call `select(value, true)`.
- Use `Listbox` when users need a conventional option picker with listbox semantics and keyboard
  behavior. `Select` and `Combobox` also manage their own selection state.

When a collection changes, keep `resetOnCollectionChange: false` if temporary filtering should keep
the selection. Set it to `true` for a new dataset. If removed values must no longer remain selected,
filter with `collection.has(value)` and call `setSelectedValues` from an event handler or effect, not
during render.
