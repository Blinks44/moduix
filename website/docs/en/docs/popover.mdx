## Choosing the right component

Use `Popover` for compact interactive content that opens from a trigger. Use `Tooltip` for short,
non-interactive hints. Use `Dialog` for larger workflows that need the user's full attention.

## Anatomy

```text
Popover / Popover.Root
├─ Popover.Anchor (optional)
├─ Popover.Trigger
│  └─ Popover.Indicator (optional)
└─ Overlay subtree (automatically rendered in a portal)
   └─ Popover.Positioner
      └─ Popover.Content
         ├─ Popover.Arrow
         │  └─ Popover.ArrowTip
         ├─ Popover.Header
         │  ├─ Popover.Title
         │  └─ Popover.Description
         ├─ Popover.Body
         ├─ Popover.Footer
         └─ Popover.CloseTrigger / Popover.CloseIcon

Popover.RootProvider
└─ the same part tree connected to state from moduix usePopover()

Popover.Context
└─ a render prop with the current popover state
```

| Part                         | Role                                                                  |
| ---------------------------- | --------------------------------------------------------------------- |
| `Popover` / `Popover.Root`   | Owns state, opening and closing, focus, dismissal, and positioning.    |
| `Popover.RootProvider`       | Connects the parts to state created with `usePopover()`.              |
| `Popover.Context`            | Exposes current state through a render prop for descendants.          |
| `Popover.Anchor`             | Optional reference element used for positioning.                      |
| `Popover.Trigger`            | Button that toggles the popover and can have a trigger `value`.       |
| `Popover.Indicator`          | Optional indicator for the trigger's state.                           |
| `Popover.Positioner`         | Floating layer that exposes Ark positioning CSS variables.            |
| `Popover.Content`            | Visible interactive popover surface.                                  |
| `Popover.Arrow` / `ArrowTip` | Optional positioned arrow and its visible tip.                       |
| `Popover.Title`              | Accessible title associated with the content.                         |
| `Popover.Description`        | Accessible description associated with the content.                    |
| `Popover.CloseTrigger`       | Low-level trigger that closes the popover.                             |
| `Popover.CloseIcon`          | Moduix helper that combines Ark's close trigger with an icon button.  |
| `Popover.Header` / `Body`    | Moduix layout helpers with stable slots.                               |
| `Popover.Footer`             | Moduix action-row helper with a stable slot.                           |

Use the short `Popover` root form in application code. `Popover.Root` remains available when the
explicit Ark name makes the composition easier to read.

## Composition

`Popover` and `Popover.Root` render `Positioner` in a portal by default. Set `portalled={false}`
to keep it in the current DOM tree, or pass `portalRef` to choose a custom portal container. When
using `Popover.RootProvider`, configure `portalled` in `usePopover()` and pass only `portalRef` to
the provider. Keep the structural parts explicit so you can style and configure them independently.

### Recommended composition

For the usual case, use `Popover` with `Popover.Trigger`, `Popover.Positioner`, and
`Popover.Content`. Configure placement, collision handling, and offsets through the root's
`positioning` prop. Set `positioning.sameWidth` when the popover should match its reference width.

### When to go custom

Use `Anchor` when a different element should determine the popover's position. Use `asChild` with
one semantic child when your own element should render the trigger, anchor, content, or close
trigger. Set `portalled={false}` when a popover inside another overlay must stay in its parent's
DOM tree.

The root already enables `lazyMount` and `unmountOnExit`. Change these props only when you need the
content to mount eagerly or remain in the DOM after closing.

### Default props

By default, popover content mounts on the first open and is removed after its exit animation. Set
`unmountOnExit={false}` to keep it mounted after the first open. Set both lifecycle props to
`false` only when the content must render from the start.

| Prop                     | Default | Notes                                                        |
| ------------------------ | ------- | ------------------------------------------------------------ |
| `autoFocus`              | `true`  | Moves focus to the first focusable element when the popover opens. |
| `closeOnEscape`          | `true`  | Closes the popover when the user presses Escape.              |
| `closeOnInteractOutside` | `true`  | Closes the popover after interaction outside it.              |
| `lazyMount`              | `true`  | Defers mounting the content until the first open.             |
| `modal`                  | `false` | Traps focus, locks scrolling, and hides outside content from assistive technology. |
| `portalled`              | `true`  | Renders the positioner in a portal.                          |
| `portalRef`              | `-`     | Targets a custom portal container.                           |
| `skipAnimationOnMount`   | `false` | Keeps the initial enter animation enabled.                   |
| `unmountOnExit`          | `true`  | Removes the content after its exit animation.                |
| `defaultOpen`            | `-`     | Initial open state for uncontrolled usage.                   |
| `open`                   | `-`     | Controlled open state.                                       |
| `ids`                    | `-`     | Stable IDs for the trigger, content, title, description, anchor, and close trigger. |
| `initialFocusEl`         | `-`     | Function that returns the element to focus when the popover opens. |
| `positioning`            | `-`     | Ark floating-positioning options.                            |
| `present`                | `-`     | Controls presence for JavaScript-driven animation lifecycles. |

### Behavioral notes

- Refs point to the underlying Ark DOM parts. `Trigger` and `CloseTrigger` point to buttons, while
  `Anchor`, `Positioner`, `Content`, `Arrow`, `ArrowTip`, `Title`, `Description`, `Indicator`,
  `Header`, `Body`, and `Footer` point to their rendered elements.
- `onOpenChange` receives a details object such as `{ open }`. Read the next open state from
  `details.open`, not from a positional callback argument.
- When several triggers share one popover, give each trigger a `value` and handle
  `onTriggerValueChange(details)`. The active trigger is available in `details.value`, and Ark
  marks it with `data-current`.
- `modal` is a boolean. When `true`, it traps focus, locks scrolling, blocks outside interaction,
  and hides outside content from assistive technology. A modal popover is always portalled, even
  when `portalled={false}` is passed to the root.
- Use `Popover.Title` to give the popup an accessible name and `Popover.Description` for supporting
  text. Ark connects these parts to `Content` through their IDs.
- Create external state with `usePopover()` and pass it to `Popover.RootProvider`. Configure
  `portalled` in `usePopover()` too; do not wrap the same state instance in `Popover` or
  `Popover.Root`.
- `Popover.Context` and `usePopoverContext()` expose the same Ark state to descendants. Use the
  context hook when a child component needs the state, or `Popover.Context` when a render prop is
  clearer.
- `Popover.Arrow` renders the default `ArrowTip`. Render `ArrowTip` explicitly only when you need
  to customize it.
- `Popover.CloseIcon` uses `aria-label="Close popover"` by default and is positioned in the
  content corner. Pass your own accessible label when the action needs different wording.
- Escape and outside interaction close the popover by default. The corresponding dismissal
  callbacks receive Ark event objects unchanged, and each behavior can be disabled separately.
- Use `ids` when separately composed parts need stable trigger, content, title, description, anchor,
  or close-trigger IDs.
- CSS exit animations target Ark's `data-state="closed"` presence state. Use `present` for a
  JavaScript-controlled presence lifecycle.
- When content can exceed the available height, put the scrollable region in `Popover.Body`.

### Styling hooks

Every rendered part accepts `className`. Ark parts retain `data-scope="popover"` and their
`data-part` values, while moduix adds `data-slot="popover-*"` to rendered wrappers. `Popover` and
`Popover.RootProvider` provide state but do not render DOM elements. For state-aware styling,
target `data-state="open|closed"`, `data-placement`, `data-side`, `data-value`, `data-nested`,
`data-has-nested`, `data-expanded`, and `data-current` when several valued triggers share one
popover.

`Positioner` exposes `--reference-width`, `--reference-height`, `--available-width`,
`--available-height`, `--x`, `--y`, `--z-index`, and `--transform-origin`. `Content` exposes
`--layer-index` and `--nested-layer-count`. `Arrow` exposes Ark's arrow measurement variables.
Content wraps long unbroken strings and disables its motion when the user prefers reduced motion.
