## Choosing the right component

- Choose **`Input`** for plain text values.
- Choose **`DateInput`** when users need keyboard-editable date segments.
- Choose **`DatePicker`** when users need a popup or inline calendar. `DateInput` is keyboard-first and
  does not include a calendar.

## Anatomy

```text
DateInput
├─ DateInputLabel
├─ DateInputControl
│  ├─ DateInputSegments
│  └─ DateInputSeparator (optional, range layouts)
└─ DateInputHiddenInput[index] (explicit, one per submitted date)

Advanced customization:

DateInputSegmentGroup
└─ DateInputSegmentContext
   └─ DateInputSegment

DateInputRootProvider
└─ same part tree connected to a useDateInput() store
```

| Part | Role |
| ---- | ---- |
| `DateInput` | Owns date values, locale formatting, segment focus, and validation. |
| `DateInputHiddenInput` | Native Ark form control that must be composed explicitly for submission. |
| `DateInputRootProvider` | Connects the parts to state created by `useDateInput()`. |
| `DateInputLabel` | Accessible label for the date input. |
| `DateInputControl` | Visual frame around one or more segment groups. |
| `DateInputSegmentGroup` | Groups segments for one date index. |
| `DateInputSegment` | Editable or literal segment supplied by Ark UI. |
| `DateInputSegments` | Renders one locale-aware segment group for the common case. |
| `DateInputSeparator` | Presentational text used between range groups. |
| `DateInputContext` | Renderless access to the current date input state. |
| `DateInputSegmentContext` | Render helper for locale-aware segment rendering. |

## Composition

Use `DateInput` with `DateInputControl` and `DateInputSegments` for the standard field. Keep the
state uncontrolled with `defaultValue`, control it with `value` and `onValueChange(details)`, or
create it with `useDateInput()` and connect the parts through `DateInputRootProvider`. Values use
the `DateInputDateValue[]` shape from `@internationalized/date`, not strings.

`DateInputHiddenInput` is explicit because the root does not add native inputs. Render one hidden
input for each submitted date and use matching `index` values for a range. Use
`DateInputSegmentGroup`, `DateInputSegmentContext`, and `DateInputSegment` only when the default
`DateInputSegments` rendering is not enough.

## Styling

Use `className` in React or `class` in Solid on exported parts for structural styles. Tailwind
variants use native utilities and consumer classes. CSS Modules variants also expose the component
variables below. Data attributes and `data-slot` hooks are shared by both styling tracks.

### CSS Properties

<CssPropertiesSection properties={DateInputDocs.dateInputOverrideCssProperties} />

### Styling hooks

- Stable `data-slot` selectors: `date-input-root`, `date-input-root-provider`, `date-input-label`,
  `date-input-control`, `date-input-segment-group`, `date-input-segment`, and
  `date-input-separator`.
- Ark part selectors use `data-scope="date-input"` and the corresponding `data-part` values.
- Ark state attributes include `data-disabled`, `data-readonly`, `data-invalid`, and `data-focus`
  on the control and segment groups, together with `data-type`, `data-editable`, and
  `data-placeholder-shown` on segments.
