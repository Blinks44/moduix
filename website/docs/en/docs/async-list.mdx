# Async List

`useAsyncList` manages asynchronous collection data and request state without rendering markup. It
keeps items, filtering, sorting, pagination, loading, and errors together while your component
chooses the list structure and status UI.

## Server-driven list

Use the `load` arguments to pass the current filter, cursor, sort descriptor, and abort signal to
your API. Return the current page as `items` and a cursor only when another page is available.
`setFilterText` starts a new load immediately, while `loadMore()` appends the next page.

The copyable example expects `GET /api/users?query=...&cursor=...&sort=...&direction=...` to return
`{ users: User[], nextCursor?: string }`. It keeps already loaded items visible while filtering,
sorting, or loading another page. Pass `signal` to `fetch` so a superseded request can be cancelled.

For server-side sorting, read `sortDescriptor` in `load`, as the example does. For client-side
sorting, provide `sort` instead. It receives the currently loaded `items`, the selected `descriptor`,
and `filterText`, and may return `{ items }` directly or from a promise. Client-side sorting only
reorders items already in memory, so server-side sorting is usually the right choice with pagination.

## API essentials

### Configuration

| Option                  | Description                                                     | Default     |
| ----------------------- | --------------------------------------------------------------- | ----------- |
| `load`                  | Required function that returns the next `{ items, cursor }`.   | -           |
| `sort`                  | Optional synchronous or asynchronous client-side sorter.       | -           |
| `autoReload`            | Loads the initial items when the component mounts.             | `false`     |
| `initialItems`          | Items shown before the first successful load.                  | `[]`        |
| `dependencies`          | Stable primitive values that trigger a new load when changed.  | `[]`        |
| `initialFilterText`     | Initial value passed to `load` as `filterText`.                | `''`        |
| `initialSortDescriptor` | Initial `{ column, direction }` sort descriptor.               | `undefined` |
| `onSuccess`             | Callback with `{ items }` after a successful load or sort.     | -           |
| `onError`               | Callback with `{ error }` after a failed load or sort.         | -           |

Use stable primitive values in `dependencies`. If a dependency comes from an object or array,
derive the value that should actually trigger a reload before passing it to the hook.

### `load` contract

`load` receives the current request context:

| Value             | Description                                                     |
| ----------------- | --------------------------------------------------------------- |
| `signal`          | `AbortSignal` for the active request, or `undefined`.          |
| `filterText`      | Current value set by `setFilterText`.                          |
| `cursor`          | Cursor for the page requested by `loadMore()`.                 |
| `sortDescriptor`  | Current `{ column, direction }` selection, when one exists.    |

Return `{ items }` for the last page, or `{ items, cursor }` when more data is available. A sort
descriptor uses an item key for `column` and either `'ascending'` or `'descending'` for
`direction`.

### State and actions

| State             | Meaning                                                  |
| ----------------- | -------------------------------------------------------- |
| `items`           | Items currently in the list.                             |
| `filterText`      | Current filter text.                                     |
| `cursor`          | Cursor returned by the latest load.                      |
| `sortDescriptor`  | Current sort descriptor.                                 |
| `loading`         | A load or sort operation is in progress.                 |
| `sorting`         | A sort operation is in progress.                         |
| `empty`           | `items` is empty.                                        |
| `hasMore`         | The latest result included a cursor.                     |
| `error`           | Error from the latest failed load or sort.               |

| Action                 | Meaning                                             |
| ---------------------- | --------------------------------------------------- |
| `reload()`             | Clears items and starts a fresh load.               |
| `loadMore()`           | Loads the current cursor and appends the result.    |
| `abort()`              | Cancels the active request.                         |
| `setFilterText(value)` | Sets the filter and starts a new load.              |
| `clearFilter()`        | Clears the filter text and starts a new load.       |
| `sort(descriptor)`     | Applies a sort descriptor.                          |

## Integration and accessibility

- `autoReload` is `false` by default. Call `reload()` when the initial request should be started
  manually.
- `reload()` clears the current items before loading. Show a full loading state only when there are
  no items; keep the existing list visible for filtering, sorting, and `loadMore()`.
- Pass `signal` to every cancellable request. An `AbortError` from a superseded request is ignored
  and does not populate `error` or call `onError`.
- `fetch` does not reject for HTTP error responses. Check `response.ok` and throw an error from
  `load` when the response is not usable.
- Give search controls an accessible label, expose loading text with `role="status"`, and expose
  failures with `role="alert"`. Use `aria-busy` on the list container when background loading
  keeps its current items visible.
- Add debouncing in the application when filtering should wait until the user pauses typing.

The hook owns data and request state only. CSS Modules can use your application stylesheet, while
Tailwind can use native utilities and consumer class overrides. There are no `async-list` CSS
variables, Moduix component exports, or registry commands to configure.
