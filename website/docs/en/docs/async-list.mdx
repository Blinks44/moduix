# Async List

## API reference

<PrimitiveReference href="https://ark-ui.com/docs/collections/async-list" />

`useAsyncList` is an Ark UI hook for data that arrives asynchronously. It keeps the current items
and request state together, and exposes actions for reloading, loading more items, filtering,
sorting, and aborting a request. It does not render any markup, so your component decides how to
present the list, loading, empty, and error states.

The hook comes from `@ark-ui/react/collection`. `@moduix/react` does not re-export it, but its
`Button` and `Input` components are used in the examples below.

If your application does not already depend on Ark UI, install it first:

```bash
npm install @ark-ui/react
```

```tsx
import { useAsyncList } from '@ark-ui/react/collection';
```

## Loading

Set `autoReload: true` when the first request should run after the component mounts. It defaults to
`false`, so without this option call `list.reload()` when your application is ready to load data.

Pass the `signal` received by `load` to `fetch` or another cancellable API. This lets the hook
cancel a request when a newer load replaces it.

The runnable example uses a small local data set and a short delay to demonstrate the initial load
and refresh states. It also includes the empty and error branches that you can connect to your own
loader.

Because `reload()` clears the current items before loading fresh data, show a full loading state
when `list.loading` is true and there are no items. During filtering and sorting, the hook keeps
the current items available while the new operation is pending.

## Configuration

| Prop                    | Purpose                                                     | Default     |
| ----------------------- | ----------------------------------------------------------- | ----------- |
| `load`                  | Required function that loads the data.                      | -           |
| `sort`                  | Optional synchronous or asynchronous client-side sorter.   | -           |
| `autoReload`            | Run the initial load when the component mounts.             | `false`     |
| `initialItems`          | Items to show before the first successful load.             | `[]`        |
| `dependencies`          | Values that trigger a reload when they change.              | `[]`        |
| `initialFilterText`     | Initial value passed to `load` as `filterText`.             | `''`        |
| `initialSortDescriptor` | Initial `{ column, direction }` sort descriptor.            | `undefined` |
| `onSuccess`             | Called with `{ items }` after a successful load or sort.     | -           |
| `onError`               | Called with `{ error }` after a failed load or sort.        | -           |

`dependencies` accepts `string`, `number`, `boolean`, `null`, and `undefined`. Keep objects and
arrays out of the list and derive stable primitive values instead.

## `load`

The `load` function receives the current list state and returns the next set of items.

Each call receives:

| Value            | Purpose                                                     |
| ---------------- | ----------------------------------------------------------- |
| `signal`         | Abort signal for the active request. It may be `undefined`. |
| `filterText`     | Current text set through `setFilterText`.                   |
| `cursor`         | Cursor from the previous result when loading more items.    |
| `sortDescriptor` | Current sort column and direction.                          |

Return an object with `items` and, when more data is available, a `cursor` for the next load:

```tsx
const list = useAsyncList<User, string>({
  autoReload: true,
  async load({ cursor, signal }) {
    const params = new URLSearchParams();

    if (cursor != null) params.set('cursor', cursor);

    const response = await fetch(`/api/users?${params}`, { signal });
    if (!response.ok) throw new Error('Could not load users');

    const data: { users: User[]; nextCursor?: string } = await response.json();
    return {
      items: data.users,
      cursor: data.nextCursor,
    };
  },
});
```

`sortDescriptor.column` is a key of the item type, and `direction` is either `'ascending'` or
`'descending'`.

## State and actions

| State            | Meaning                                      |
| ---------------- | -------------------------------------------- |
| `items`          | Items currently in the list.                 |
| `filterText`     | Current filter text.                         |
| `cursor`         | Cursor for the next page.                    |
| `sortDescriptor` | Current sort descriptor.                     |
| `loading`        | A data load is in progress.                  |
| `sorting`        | A sort operation is in progress.             |
| `empty`          | The current item array is empty.             |
| `hasMore`        | A cursor exists for another page.            |
| `error`          | Error from the most recent failed load.      |

| Action                 | Purpose                                        |
| ---------------------- | ---------------------------------------------- |
| `reload()`             | Clear the items and start a fresh load.         |
| `loadMore()`           | Load the current cursor and append the result.  |
| `abort()`              | Cancel the active request.                      |
| `setFilterText(value)` | Set the filter text and start a new load.       |
| `clearFilter()`        | Clear the filter text.                          |
| `sort(descriptor)`     | Apply a sort descriptor.                        |

## Filtering

The hook does not filter items by itself. It stores `filterText` and passes it to `load`, so
filtering can happen on the server or in the application:

```tsx
import { Input } from '@moduix/react/input';

function UserSearch() {
  const list = useAsyncList<User>({
    autoReload: true,
    async load({ filterText, signal }) {
      const params = new URLSearchParams({ query: filterText });
      const response = await fetch(`/api/users?${params}`, { signal });

      if (!response.ok) throw new Error('Search failed');
      return { items: await response.json() };
    },
  });

  return (
    <Input
      type="search"
      aria-label="Search users"
      value={list.filterText}
      onChange={(event) => list.setFilterText(event.currentTarget.value)}
    />
  );
}
```

`setFilterText` starts a load immediately. Add debouncing in the application when you want to wait
until the user pauses typing. The hook cancels superseded requests, and the server or your loader
defines the matching rules and result limits.

## Pagination

Return a cursor while more data is available, then call `loadMore()`:

```tsx
import { Button } from '@moduix/react/button';

{
  list.hasMore && (
    <Button type="button" onClick={() => list.loadMore()} loading={list.loading}>
      {list.loading ? 'Loading…' : 'Load more'}
    </Button>
  );
}
```

`hasMore` is derived from the cursor in the latest result. Do not calculate it separately.

## Sorting

For server-side sorting, read `sortDescriptor` in `load`:

```tsx
function useServerSortedUsers() {
  return useAsyncList<User>({
    autoReload: true,
    async load({ sortDescriptor, signal }) {
      const params = new URLSearchParams();

      if (sortDescriptor) {
        params.set('sort', String(sortDescriptor.column));
        params.set('direction', sortDescriptor.direction);
      }

      const response = await fetch(`/api/users?${params}`, { signal });
      if (!response.ok) throw new Error('Could not sort users');

      return { items: await response.json() };
    },
  });
}
```

For client-side sorting, provide `sort`:

```tsx
function useClientSortedUsers() {
  return useAsyncList<User>({
    autoReload: true,
    async load({ signal }) {
      const response = await fetch('/api/users', { signal });
      if (!response.ok) throw new Error('Could not load users');
      return { items: await response.json() };
    },
    sort({ items, descriptor }) {
      const direction = descriptor.direction === 'ascending' ? 1 : -1;

      return {
        items: items.toSorted(
          (a, b) =>
            String(a[descriptor.column]).localeCompare(String(b[descriptor.column])) * direction,
        ),
      };
    },
  });
}
```

The `sort` function receives the current `items`, `descriptor`, and `filterText`. It may return the
sorted items directly or from a promise.

Client-side sorting only sorts the items that are already loaded. Prefer server-side sorting when
pagination is also controlled by the server; sorting one loaded page can produce misleading results.

## Dependencies

Use `dependencies` when an external filter should reload the list:

```tsx
function useDepartmentUsers(department: string) {
  return useAsyncList<User>({
    autoReload: true,
    dependencies: [department],
    async load({ signal }) {
      const params = new URLSearchParams({ department });
      const response = await fetch(`/api/users?${params}`, { signal });

      if (!response.ok) throw new Error('Could not load users');
      return { items: await response.json() };
    },
  });
}
```

## Errors

Handle failed and superseded requests separately. Pass `signal` to cancellable requests, and use
`reload()` when the user retries a failed request.

- Check `response.ok`; `fetch` does not reject for HTTP error statuses.
- Pass `signal` to every cancellable request.
- Filtering and sorting keep the current items available while work is pending. `reload()` clears
  the current items before loading a fresh result.
- Requests that end with an `AbortError` are ignored by the hook and do not set `error` or call
  `onError`.
- Use `reload()` for retry actions.
- Treat `error` as unknown application input and narrow it before reading `.message`.
- Use `onSuccess` and `onError` for external effects, not to duplicate the hook's item or error
  state.
