# Styling

moduix provides component styles and a shared CSS foundation, but it does not require a particular
styling tool. Keep using the approach your application already uses: CSS Modules, Panda CSS,
Tailwind CSS, plain CSS, or another strategy. The component API stays the same in each case.

Import the foundation stylesheet once from your application entry point:

```tsx
import '@moduix/react/style.css';
```

moduix does not install Panda CSS or Tailwind CSS for you. The examples below style the same
`ProjectChecklist` composition with each tool, so only the styling syntax changes. They assume that
the corresponding tool is already configured in your application.

## Choose where to make a change

| Goal                                             | Preferred surface                                              |
| ------------------------------------------------ | -------------------------------------------------------------- |
| Adopt a complete visual direction                | A curated [Theme preset](/docs/themes)                         |
| Change a system-wide color, size, radius, or gap | A primitive or semantic token from [Tokens](/docs/tokens)      |
| Keep a family of controls or popup rows aligned  | A shared family token such as `--moduix-popup-item-min-height` |
| Make one component intentionally different       | A documented `--moduix-<component>-*` alias                    |
| Style one product composition                    | `className` on each part that needs styling, preferably local CSS |

Choose the highest-level surface that matches the scope of the decision. Use a token when the change
should reach several components, and move to a rendered part when the change belongs to one
composition.

## Style parts

Give `className` to the part that owns the visual change. This keeps the component anatomy explicit
and limits the rule to the product component. For stateful styling, combine that class with the
documented Ark `data-*` attributes on the same part. Use a public CSS variable when the component
exposes the value you need to change.

### Hidden parts

When a product wrapper owns the composition but does not expose one of its inner parts as a prop,
target that part with its stable `data-slot`. You can then style an internal trigger without relying
on DOM order or generated class names:

```css
.root {
  [data-slot='accordion-item-trigger'] {
    padding-inline: var(--moduix-spacing-4);

    &[data-state='open'] {
      color: var(--moduix-color-primary);
    }
  }
}
```

Use this as an escape hatch, not as a replacement for `className`. Parts such as `Dialog.Content`
and `Tooltip.Content` render in a portal by default, so put `className` on the portalled part itself
or scope its variables to the portal container.

## Panda CSS

If your application already uses Panda CSS, generate classes for the same `ProjectChecklist` parts.
The token names in this example come from your Panda theme, not from moduix.

```tsx
import { Accordion } from '@moduix/react/accordion';
import { css } from '../styled-system/css';

const root = css({
  maxW: '2xl',
  p: '3',
  borderWidth: '1px',
  borderColor: 'blue.200',
  borderRadius: 'xl',
  bg: 'blue.50',
});
const accordion = css({ display: 'flex', flexDirection: 'column', gap: '3' });
const item = css({
  overflow: 'hidden',
  borderWidth: '1px',
  borderColor: 'blue.200',
  borderRadius: 'lg',
  bg: 'white',
  transition: 'colors',
  '&[data-state=open]': { borderColor: 'blue.500', boxShadow: 'lg' },
});
const trigger = css({
  display: 'grid',
  gridTemplateColumns: 'minmax(0, 1fr) auto',
  gap: '3',
  alignItems: 'center',
  w: 'full',
  px: '4',
  py: '4',
  bg: 'blue.50',
  color: 'gray.950',
  fontWeight: 'semibold',
  textAlign: 'left',
  transition: 'colors',
  _hover: { bg: 'blue.100' },
  _focusVisible: { outlineWidth: '2px', outlineColor: 'blue.500', outlineOffset: '-1px' },
  '&[data-state=open]': { bg: 'blue.100', color: 'blue.700' },
});
const triggerCopy = css({ display: 'flex', gap: '3', alignItems: 'center', minW: '0' });
const step = css({
  display: 'grid',
  flexShrink: '0',
  placeItems: 'center',
  w: '7',
  h: '7',
  borderWidth: '1px',
  borderColor: 'blue.300',
  borderRadius: 'xl',
  bg: 'blue.100',
  color: 'blue.700',
  fontSize: 'xs',
  fontWeight: 'semibold',
});
const title = css({ minW: '0' });
const indicator = css({ flexShrink: '0', color: 'blue.700' });
const content = css({
  borderTopWidth: '1px',
  borderColor: 'blue.200',
  bg: 'blue.50',
  color: 'gray.950',
});
const body = css({ px: '4', py: '4', color: 'gray.700', lineHeight: '6' });

export function ProjectChecklist() {
  return (
    <section className={root}>
      <Accordion className={accordion} collapsible defaultValue={['outcome']}>
        <Accordion.Item className={item} value="outcome">
          <Accordion.ItemTrigger className={trigger}>
            <span className={triggerCopy}>
              <span className={step}>01</span>
              <span className={title}>Define the project outcome</span>
            </span>
            <Accordion.ItemIndicator className={indicator} />
          </Accordion.ItemTrigger>
          <Accordion.ItemContent className={content}>
            <Accordion.ItemBody className={body}>
              <p>
                Write one sentence that makes the next decision obvious to everyone on the project.
              </p>
            </Accordion.ItemBody>
          </Accordion.ItemContent>
        </Accordion.Item>
      </Accordion>
    </section>
  );
}
```

## Troubleshooting

| Symptom                                  | Most likely check                                                                 |
| ---------------------------------------- | --------------------------------------------------------------------------------- |
| A variable has no effect                 | Check that the component page lists it and your override loads after `style.css`. |
| A popup ignores a wrapper-scoped value   | It may be portalled. Put the variable on its part, root, or portal container.     |
| A state selector never matches           | Inspect the exact Ark attribute, such as `data-state` or `data-disabled`.         |
| A class reaches the root but not a part  | Put `className` on the exported part that owns the visual property.               |
| A utility class loses to component CSS   | Prefer a documented CSS variable, or verify the cascade order of a local class.   |

Before increasing selector specificity, use your browser's developer tools to inspect the rendered
part, its `data-slot`, state attributes, and resolved custom properties.
