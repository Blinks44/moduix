## Anatomy

```tsx
<ImageCropper>
  <ImageCropper.Viewport>
    <ImageCropper.Image />
    <ImageCropper.CropArea />
  </ImageCropper.Viewport>
</ImageCropper>
```

| Part                                 | Role                                                                                 |
| ------------------------------------ | ------------------------------------------------------------------------------------ |
| `ImageCropper` / `ImageCropper.Root` | Root component that owns crop and transform state, ARIA attributes, and runtime CSS variables. |
| `ImageCropper.RootProvider`          | Root connected to a `useImageCropper` instance created outside the component tree.   |
| `ImageCropper.Viewport`              | Viewport that clips overflow and provides the surface for panning the image.         |
| `ImageCropper.Image`                 | Image element that Ark transforms as the user edits the crop.                        |
| `ImageCropper.Selection`             | Focusable crop area and keyboard target. It is removed from the tab order when `fixedCropArea` is enabled. |
| `ImageCropper.Grid`                  | Non-interactive horizontal or vertical crop guide. Requires `axis`.                  |
| `ImageCropper.Handle`                | Resize handle for a position from `ImageCropper.handles`. Requires `position`.       |
| `ImageCropper.CropArea`              | Ready-made selection with both grids and every resize handle. It does not accept `children` or `asChild`. |

## Composition

Use `ImageCropper.CropArea` for the standard selection. It owns the two grids and all resize handles,
so do not pass `children` or `asChild`. Use `className`, `gridClassName`, and `handleClassName` to
style the selection and its generated parts.

Use `ImageCropper.Context` for controls inside the root. Create `useImageCropper()` and pass it to
`ImageCropper.RootProvider` when a toolbar, preview, or form logic needs the cropper instance outside
the component tree. For one state instance, render either `Root` or `RootProvider`.

Use controlled `zoom`, `rotation`, or `flip` with the matching change callback when another part of
the application owns that state. Ark passes the updated value in the callback's `details` object.
`fixedCropArea` keeps the selection fixed and makes the viewport the panning surface.

### Styling hooks

Use the stable `data-slot` hooks `image-cropper-root`, `image-cropper-root-provider`,
`image-cropper-viewport`, `image-cropper-image`, `image-cropper-selection`, `image-cropper-grid`,
and `image-cropper-handle` for local styling. Ark also exposes `data-scope="image-cropper"`,
`data-part`, and state attributes such as `data-fixed`, `data-shape`, `data-pinch`, `data-ready`,
`data-disabled`, `data-measured`, `data-dragging`, `data-panning`, `data-axis`, and `data-position`
on the relevant parts.

Ark writes `--crop-width`, `--crop-height`, `--crop-x`, `--crop-y`, `--image-zoom`,
`--image-rotation`, `--image-offset-x`, and `--image-offset-y` on the root. These are read-only
runtime values for synchronizing custom UI. Do not override them. Use the documented
`--moduix-image-cropper-*` properties for visual customization.
