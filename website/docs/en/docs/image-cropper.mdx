## Anatomy

```tsx
<ImageCropper>
  <ImageCropper.Viewport>
    <ImageCropper.Image />
    <ImageCropper.CropArea />
  </ImageCropper.Viewport>
</ImageCropper>
```

| Part                                 | Role                                                                                 |
| ------------------------------------ | ------------------------------------------------------------------------------------ |
| `ImageCropper` / `ImageCropper.Root` | Root group that owns crop state, transforms, ARIA labels, and runtime CSS variables. |
| `ImageCropper.RootProvider`          | Root rendered from a `useImageCropper` instance created outside the component tree.  |
| `ImageCropper.Viewport`              | Surface for moving the image and clipping anything outside the viewport.             |
| `ImageCropper.Image`                 | Image element that Ark transforms as the user edits the crop.                        |
| `ImageCropper.Selection`             | Focusable crop area and keyboard interaction target.                                 |
| `ImageCropper.Grid`                  | Horizontal or vertical crop guide lines.                                             |
| `ImageCropper.Handle`                | Resize handle for each position in `ImageCropper.handles`.                           |
| `ImageCropper.CropArea`              | Ready-made crop area with both grids and every resize handle.                        |

## Composition

### Recommended composition

For most use cases, use `ImageCropper.CropArea`. It keeps the Ark part tree intact and removes the
repeated markup for the selection, grids, and handles. Pass `className`, `gridClassName`, or
`handleClassName` to style those parts. `CropArea` creates its child structure itself, so switch to
the explicit `Selection`, `Grid`, and `Handle` parts when you need a different structure. In that
case, do not use `children` or `asChild` on `CropArea`.

### When to go custom

Use `ImageCropper.Context` for a toolbar inside the root. If a toolbar, crop preview, or form
integration needs the cropper API outside the component tree, create a moduix `useImageCropper`
instance and pass it to `ImageCropper.RootProvider`. For one state instance, render either `Root` or
`RootProvider`, not both.

### Default props

| Prop                     | Default                                  | Notes                                                        |
| ------------------------ | ---------------------------------------- | ------------------------------------------------------------ |
| `cropShape`              | `"rectangle"`                            | Use `"circle"` for avatar crops.                             |
| `defaultZoom`            | `1`                                      | Initial image zoom.                                          |
| `defaultRotation`        | `0`                                      | Initial image rotation in degrees.                           |
| `defaultFlip`            | `{ horizontal: false, vertical: false }` | Initial horizontal and vertical flip state.                  |
| `minZoom`                | `1`                                      | Minimum zoom factor.                                         |
| `maxZoom`                | `5`                                      | Maximum zoom factor.                                         |
| `minWidth` / `minHeight` | `40`                                     | Minimum crop area size.                                      |
| `fixedCropArea`          | `false`                                  | When true, users move the image beneath a fixed crop area.   |

### Behavioral notes

Ark handles pointer dragging, panning, wheel and pinch zoom, keyboard movement, generated IDs, ARIA
labels, and crop output helpers. Arrow keys move the crop area, `Alt` plus an arrow key resizes it,
`Shift` and `Ctrl`/`Cmd` use the nudge-step props, and `+` / `-` change the zoom. In controlled mode,
`onCropChange`, `onZoomChange`, `onRotationChange`, and `onFlipChange` receive Ark detail objects.

### Styling hooks

Target stable `data-slot` hooks such as `image-cropper-root`, `image-cropper-viewport`,
`image-cropper-image`, `image-cropper-selection`, `image-cropper-grid`, and
`image-cropper-handle`. Ark also exposes `data-scope="image-cropper"`, `data-part` values,
`data-fixed`, `data-shape`, `data-pinch`, `data-ready`, `data-disabled`, `data-measured`,
`data-dragging`, `data-panning`, `data-axis`, and `data-position`.

Ark writes `--crop-width`, `--crop-height`, `--crop-x`, `--crop-y`, `--image-zoom`,
`--image-rotation`, `--image-offset-x`, and `--image-offset-y` on the root. Treat these as
read-only runtime values when synchronizing custom UI. Use the documented `--moduix-image-cropper-*`
properties above for visual overrides.
