## Anatomy

```text
Toc
├─ Toc.Content
└─ Toc.Nav
   ├─ Toc.Title
   └─ Toc.List
      ├─ Toc.Indicator (optional)
      └─ Toc.Item[item]
         └─ Toc.Link
            └─ Toc.Rail (optional)

Toc.RootProvider
└─ same part tree connected to useToc()
```

| Part                                   | Role                                                               |
| -------------------------------------- | ------------------------------------------------------------------ |
| `Toc`                      | Creates Ark tracking state from the heading items.                 |
| `Toc.Content`              | Article containing headings whose IDs match item values.           |
| `Toc.Nav`                  | Navigation region linked to the title.                             |
| `Toc.Title`                | Accessible name and visible heading for the navigation.            |
| `Toc.List`                 | List that contains the heading links and optional indicator.       |
| `Toc.Item`                 | One heading item with Ark depth and active-state attributes.       |
| `Toc.Link`                 | Same-page link that scrolls to its matching heading.               |
| `Toc.Indicator`            | Subtle marker that follows the active item in the list.            |
| `Toc.RootProvider`         | Connects parts to externally created tracking state.               |
| `Toc.Rail`                 | Optional SVG branch that connects neighbouring heading depths.     |

## Composition

### Recommended composition

Create one item for every heading you want to track. `value` is the heading ID without `#`, and `depth` is its heading level. By default, the root observes the page viewport; use `scrollEl` when the content lives in its own scroll container.

Ark manages `activeIds`, `defaultActiveIds`, `onActiveChange(details)`, `rootMargin`, `threshold`, `autoScroll`, `scrollBehavior`, and `ids`. The callback keeps its Ark shape with `details.activeIds` and `details.activeItems`.

### When to go custom

Use `asChild` on `Toc.Link` when a router link should behave like a same-page anchor. Keep a single semantic anchor as the child so Ark can apply `aria-current`, click handling, and focus props.

Use `useToc()` with `RootProvider` when controls outside the part tree need `activeIds`, `setActiveIds`, `scrollTo`, or `getItemState`. `Toc.Context` and `useTocContext` expose the same state inside the tree.

### Default props

| Prop             | Default                 | Notes                                                     |
| ---------------- | ----------------------- | --------------------------------------------------------- |
| `items`          | required                | Pass the tracked heading values and depths.               |
| `rootMargin`     | `-20px 0px -40% 0px`   | Adjusts the effective observer viewport.                  |
| `threshold`      | `0`                     | Activates a heading as soon as it intersects.             |
| `autoScroll`     | `false`                 | Enable only after confirming it cannot scroll an ancestor container. |
| `scrollBehavior` | `smooth`                | Used for link, API, and navigation-list scrolling.        |

### Behavioral notes

- Active links receive `aria-current="location"` and `data-active`.
- Items expose `data-depth`, `data-first`, `data-last`, and the numeric `--depth` variable.
- The indicator uses Ark's measured `--top` and `--height` variables; it is hidden until a non-empty active range exists.
- By default, the article sits beside a sticky navigation panel; below 48rem, the layout becomes a single column.
- Set `Toc.Nav` `placement="left"` or `placement="right"` to choose the desktop sidebar side.
- Moduix disables Ark's automatic scrolling of the navigation list, so tracking does not move the page or an outer container. Turn on `autoScroll` only for a self-contained navigation pane.
- When reduced motion is enabled, CSS smooth scrolling and indicator transitions are disabled. Also pass `scrollBehavior="auto"` if scrolling triggered by Ark should not animate.

### Production checklist

- Use globally unique, stable heading IDs. Keep every `item.value`, heading `id`, and link hash identical.
- Let one element own scrolling in an embedded reader, pass it to `scrollEl`, and add `overscroll-behavior: contain` when scrolling must not continue onto the page.
- Keep `autoScroll` off for document pages and embedded readers. Enable it only after confirming that revealing the active link cannot scroll an ancestor container.
- Keep `depth` aligned with semantic heading levels. The regular list indents nested items; add `Rail` only when a visual connector makes the hierarchy clearer.
- Use `RootProvider` only when controls outside the TOC need the same state. Otherwise, `Toc` is the simplest production composition.

- `data-slot="toc-root"`, `toc-root-provider`, `toc-content`, `toc-nav`, `toc-title`, `toc-list`, `toc-item`, `toc-link`, `toc-indicator`, and `toc-rail`
