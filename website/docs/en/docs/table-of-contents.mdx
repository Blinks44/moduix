## Basic

`Toc` is the shorthand root component. Pass an `items` array with the headings you want to track.
Each item needs a `value` that matches a heading's `id` and a `depth` that matches its semantic
level, such as `2` for `<h2>`. Use the same item when rendering `Toc.Item`, then build the matching
`Toc.Link` fragment from its `value`.

On a regular document page, omit `scrollEl` and the component observes the page viewport. The
preview below uses an inner scroll container, so it passes that element to `scrollEl` to keep
tracking and link navigation inside the preview.

## Anatomy

```text
Toc.Root (also exported as Toc)
├─ Toc.Content
└─ Toc.Nav
   ├─ Toc.Title
   └─ Toc.List
      ├─ Toc.Indicator (optional)
      └─ Toc.Item[item]
         └─ Toc.Link
            └─ Toc.Rail (optional)

Toc.RootProvider
└─ same part tree connected to useToc()
```

| Part               | Role                                                                 |
| ------------------ | -------------------------------------------------------------------- |
| `Toc`              | Shorthand for `Toc.Root`; creates tracking state from the item list. |
| `Toc.Content`      | Article containing headings whose IDs match item values.             |
| `Toc.Nav`          | Navigation region connected to the table of contents title.          |
| `Toc.Title`        | Accessible name and visible heading for the navigation.              |
| `Toc.List`         | List containing heading links and the optional indicator.            |
| `Toc.Item`         | List item bound to one heading, with depth and active-state metadata. |
| `Toc.Link`         | Same-page anchor that scrolls to its matching heading.               |
| `Toc.Indicator`    | Subtle marker that follows the active range in the list.             |
| `Toc.RootProvider` | Connects the parts to tracking state created outside the part tree.  |
| `Toc.Rail`         | Optional SVG branch connecting neighbouring heading depths.           |

## Composition

### Recommended composition

Create one item for every heading you want to track. Put the heading ID without `#` in `value`, and
use its semantic level for `depth`, such as `2` for `<h2>` or `3` for `<h3>`. By default, the root
observes the page viewport. Pass `scrollEl` when the content lives in its own scroll container.

The root exposes Ark's `activeIds`, `defaultActiveIds`, `onActiveChange(details)`, `rootMargin`,
`threshold`, `autoScroll`, `scrollBehavior`, and `ids` options. When active headings change,
`onActiveChange` receives `details.activeIds` and `details.activeItems`.

### When to go custom

Use `asChild` on `Toc.Link` when a router component should render the anchor. Keep one semantic
`<a>` element as the child so Ark can merge its `aria-current`, click handling, and focus props.

Use `Toc.RootProvider` with `useToc()` when controls outside the part tree need `activeIds`,
`setActiveIds`, `scrollTo`, or `getItemState`. Inside the tree, `Toc.Context` and
`useTocContext()` expose the same tracking state.

### Default props

| Prop             | Default              | Notes                                                                |
| ---------------- | -------------------- | -------------------------------------------------------------------- |
| `items`          | required             | Pass the tracked heading values and semantic depths.                 |
| `rootMargin`     | `-20px 0px -40% 0px` | Adjusts the effective observer viewport.                             |
| `threshold`      | `0`                  | Activates a heading as soon as it intersects the root margin area.   |
| `autoScroll`     | `false`              | Moduix default. Enable only after checking ancestor scroll behavior. |
| `scrollBehavior` | `smooth`             | Used for heading links, `scrollTo`, and TOC-list scrolling.           |

### Behavioral notes

- Active links receive `aria-current="location"` and `data-active`.
- `Toc.Item` exposes `data-value`, `data-depth`, `data-active`, `data-first`, `data-last`, and the
  numeric `--depth` variable. `Toc.Link` exposes `data-value`, `data-active`, and
  `aria-current` when active.
- The indicator uses Ark's measured `--top` and `--height` variables. It stays hidden until there
  is a non-empty active range.
- By default, the content and a sticky navigation panel sit side by side. Below 48rem, they stack
  in one column.
- Set `Toc.Nav` `placement="left"` or `placement="right"` to choose the desktop sidebar side.
- Moduix turns off automatic scrolling of the TOC list. This keeps changes in the active heading
  from scrolling an ancestor container. Turn on `autoScroll` only for a self-contained navigation
  pane after checking its scroll behavior.
- When reduced motion is enabled, CSS smooth scrolling and indicator transitions are disabled. Also
  pass `scrollBehavior="auto"` when Ark-triggered scrolling should not animate.

### Production checklist

- Use globally unique, stable heading IDs. Keep every `item.value`, heading `id`, and link hash
  identical.
- Let one element own scrolling in an embedded reader, pass it to `scrollEl`, and add
  `overscroll-behavior: contain` when scrolling must not continue onto the page.
- Keep `autoScroll` off for document pages and embedded readers. Enable it only after confirming
  that revealing the active link cannot scroll an ancestor container.
- Keep `depth` aligned with semantic heading levels. The regular list indents nested items; add
  `Toc.Rail` only when a visual connector makes the hierarchy clearer.
- Use `Toc.RootProvider` only when controls outside the TOC need the same state. Otherwise, `Toc`
  is the simplest production composition.

### Rail

Place `Toc.Rail` inside each link to draw an SVG connector between neighbouring heading depths.
Pass the current, previous, and next depths from the same ordered `items` array. The rail on the
active link uses the indicator colour. Do not render `Toc.Indicator` in the same list.
