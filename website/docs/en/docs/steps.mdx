## Basic

Use `Steps` with `count`, a `Steps.List` containing one `Steps.Item` for each step, matching
`Steps.Content` panels, and the built-in previous and next triggers. Step indexes start at zero.
For example, `count={3}` uses indexes `0`, `1`, and `2`. When the step value reaches `count`,
`Steps.CompletedContent` is shown.

The default `Steps` export is the root component. Use `Steps.Root` when you want the explicit root
part name.

## Anatomy

```text
Steps
├─ Steps.Progress (optional)
├─ Steps.List
│  └─ Steps.Item[index]
│     ├─ Steps.Trigger
│     │  └─ Steps.Indicator
│     └─ Steps.Separator
├─ Steps.Content[index]
├─ Steps.CompletedContent
├─ Steps.PrevTrigger
└─ Steps.NextTrigger

Steps.RootProvider
└─ same part tree connected to a Steps.useSteps() store
```

| Part                                | Role                                                                              |
| ----------------------------------- | --------------------------------------------------------------------------------- |
| `Steps` / `Steps.Root`           | Root state machine for step state, orientation, navigation, validation, and IDs. |
| `Steps.RootProvider`               | Connects the parts to state created with `Steps.useSteps()`.                    |
| `Steps.Progress`                   | Optional visual progress track driven by Ark's `--percent` root variable.       |
| `Steps.List`                       | Tablist containing the step triggers.                                            |
| `Steps.Item`                       | Step item with a required zero-based `index`.                                    |
| `Steps.Trigger`                    | Tab trigger for a step; supports `asChild` for custom semantic elements.         |
| `Steps.Indicator`                  | Visual step marker. Defaults to `index + 1` or a check icon when complete.       |
| `Steps.Separator`                  | Decorative connector between step items.                                         |
| `Steps.Content`                    | Content panel for one step, matched by `index`.                                  |
| `Steps.CompletedContent`           | Panel shown when the current step value equals `count`.                          |
| `Steps.PrevTrigger` / `NextTrigger` | Buttons wired to Ark's previous and next actions.                                |

Use `Steps.useSteps()` with `Steps.RootProvider` when state must be created outside the rendered
part tree. `useStepsContext`, `useStepsItemContext`, `Steps.Context`, and `Steps.ItemContext` are
also exported from `@moduix/react` as low-level Ark-shaped APIs.

## Composition

### Recommended composition

`Steps` owns the state machine. Pass `count`, `defaultStep`, `step`, `onStepChange(details)`,
`onStepComplete`, `linear`, `isStepValid`, `isStepSkippable`, `onStepInvalid(details)`,
`orientation`, and `ids` to the root. Use matching zero-based `index` values on each step item and
content panel. Active steps use indexes from `0` through `count - 1`; the value `count` represents
completion.

Use `Steps.RootProvider` with `Steps.useSteps()` when controls outside the `Steps` part tree need
the same state. The returned object exposes `value`, `setStep`, `goToNextStep`, `goToPrevStep`,
`resetStep`, `percent`, and `getItemState`. Do not render `Steps.Root` and `Steps.RootProvider`
for the same state.

### When to go custom

Use `asChild` on `Steps.Trigger`, `Steps.PrevTrigger`, or `Steps.NextTrigger` when the control
should render as an anchor, router link, or design-system button. Keep exactly one semantic child
so Ark can attach its ARIA, keyboard, and focus behavior to that element.

`Steps.Indicator` has one moduix addition: when it has no children, it renders `index + 1` for
incomplete and current steps and the shared check icon for completed steps. Pass children to take
full control of the marker.

### Default props

| Prop          | Default      | Notes                                                                                  |
| ------------- | ------------ | -------------------------------------------------------------------------------------- |
| `orientation` | `horizontal` | Orientation of the root. Use `vertical` for stacked step navigation.                  |
| `linear`      | `false`      | Set `true` to require users to complete steps in order instead of jumping between them. |
| `count`       | `1`          | Total number of steps. The completed state is represented by the value `count`.       |
| `defaultStep` | `0`          | Initial uncontrolled value. Pass `count` to start with the process completed.         |

### Behavioral notes

- `step`, `defaultStep`, `details.step`, and `Steps.Item index` are zero-based Ark values. Active step indexes range from `0` to `count - 1`; `count` means complete.
- In linear flows, `onStepInvalid(details)` reports the blocked `details.step`, the `details.action` (`'next'` or `'set'`), and the optional `details.targetStep`.
- `Steps.Content` uses `role="tabpanel"` and is hidden when its step is not current. `Steps.CompletedContent` is shown when the current value equals `count`.
- `Steps.List` uses `role="tablist"` with `aria-orientation`; triggers use `role="tab"` and `aria-controls`.
- `Steps.PrevTrigger` and `Steps.NextTrigger` become disabled when Ark reports that there is no previous or next step.
- `ids` can provide stable IDs for the root, list, triggers, and content when the surrounding composition needs them.
- `Steps.Progress` is a visual track driven by Ark's `--percent` variable. Pair it with visible or screen-reader text when progress needs to be announced.

### Styling hooks

The useful public hooks are:

- `className` on `Steps`, `Steps.RootProvider`, `Steps.List`, `Steps.Item`, `Steps.Trigger`, `Steps.Indicator`, `Steps.Separator`, `Steps.Content`, `Steps.CompletedContent`, `Steps.PrevTrigger`, `Steps.NextTrigger`, and `Steps.Progress`
- `data-slot="steps-root"`, `steps-root-provider`, `steps-list`, `steps-item`, `steps-trigger`, `steps-indicator`, `steps-separator`, `steps-content`, `steps-completed-content`, `steps-prev-trigger`, `steps-next-trigger`, and `steps-progress`
- Ark's `data-scope="steps"` and `data-part` values for every primitive part
- `data-orientation="horizontal" | "vertical"` on the root, list, item, trigger, content, and separator parts
- `data-current`, `data-complete`, and `data-incomplete` on indicator, separator, and trigger state surfaces
- `data-state="open" | "closed"` on triggers and content panels
- `data-complete` on `Steps.Progress`
- Ark's `--percent` variable on the root, consumed by `Steps.Progress`
