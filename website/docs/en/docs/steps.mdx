## Usage

<Usage />

Use `Steps` with `count`, a `StepsList` containing one `StepsItem` for each step, matching
`StepsContent` panels, and the built-in previous and next triggers. Step indexes start at zero.
For example, `count={3}` uses indexes `0`, `1`, and `2`. When the step value reaches `count`,
`StepsCompletedContent` is shown.

The `Steps` export is the root component. Use `StepsRootProvider` with `useSteps()` when state must
be created outside the rendered part tree.

React, Solid, and Vue use the same flat value names. In Vue, bind controlled state with
`v-model:step` and pass a `useSteps()` store to `StepsRootProvider` when it is created outside the
rendered part tree.

## Composition

Let `Steps` manage the state. Give every `StepsItem` and matching
`StepsContent` the same zero-based `index`; `count` is the total number of steps and its value
represents completion. Use `StepsRootProvider` only with a store from `useSteps()` when
state needs to be created outside the part tree. Do not render the root and provider for the same
store.

For lower-level state reads, use `useStepsContext` and `useStepsItemContext`, or the flat context
values `StepsContext` and `StepsItemContext`.

`StepsTrigger`, `StepsPrevTrigger`, and `StepsNextTrigger` accept `asChild`. Pass one semantic
child when a control should render as an anchor, router link, or design-system button. When
`StepsIndicator` has no children, it renders the step number or the shared check icon for a
completed step; pass children to control the marker.

## Styling

Style `Steps` with `className` in React or `class` in Solid and Vue, Ark's `data-scope="steps"` and
`data-part` attributes, Ark state attributes, moduix `data-slot` hooks, and the public
`--moduix-steps-*` CSS variables listed below.

The root fills its container; limit it with `max-width` in your own class. The CSS Modules packages
expose two variables because the vertical separator is positioned from them: set
`--moduix-steps-indicator-size` and `--moduix-steps-gap` instead of resizing the indicator or the
vertical list gap with a class. Change colors, typography, and surfaces with a class on the part.

The useful public hooks are:

- `className` in React or `class` in Solid and Vue on `Steps`, `StepsRootProvider`, `StepsList`, `StepsItem`, `StepsTrigger`, `StepsIndicator`, `StepsSeparator`, `StepsContent`, `StepsCompletedContent`, `StepsPrevTrigger`, `StepsNextTrigger`, and `StepsProgress`
- Ark's `data-scope="steps"` and `data-part` values for every primitive part
- `data-orientation="horizontal" | "vertical"` on the root, list, item, trigger, content, and separator parts
- `data-current`, `data-complete`, and `data-incomplete` on indicator, separator, and trigger state surfaces
- `data-skippable` on `StepsItem` when the step is marked skippable
- `data-state="open" | "closed"` on triggers and content panels
- `data-complete` on `StepsProgress`
- Ark's `--percent` variable on the root, consumed by `StepsProgress`

## API reference

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `count` | `number` | — | Total number of steps. |
| `step` | `number` | — | Current step index for controlled use. |
| `defaultStep` | `number` | `0` | Initial step index. |
| `onStepChange` | `(details: StepChangeDetails) => void` | — | Called when the step changes. |
| `onStepComplete` | `() => void` | — | Called when the last step is completed. |
| `linear` | `boolean` | `false` | Requires the steps to be completed in order. |
| `orientation` | `'horizontal' \| 'vertical'` | `'horizontal'` | Layout: `horizontal` or `vertical`. |
| `isStepValid` | `(index: number) => boolean` | `() => true` | Returns `false` to block moving past a step. |
| `isStepSkippable` | `(index: number) => boolean` | `() => false` | Returns `true` for steps that can be skipped. |
| `onStepInvalid` | `(details: StepInvalidDetails) => void` | — | Called when `isStepValid` blocks navigation. |
