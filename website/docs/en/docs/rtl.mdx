# Right-to-left (RTL)

An RTL interface needs two coordinated settings: native `lang` and `dir` attributes for browser layout,
and Moduix `LocaleProvider` for Ark's locale-aware behavior. Set both at the highest scope that owns
the language.

## Configure the document

For an application-wide RTL locale, put `lang` and `dir` on `<html>`:

```html
<html lang="ar" dir="rtl"></html>
```

Wrap the application with the provider from its native adapter:

<Tabs groupId="framework">
  <Tab label="React" value="react">

```tsx
import { LocaleProvider } from '@moduix/react/locale';

<LocaleProvider locale="ar-EG">{children}</LocaleProvider>;
```

  </Tab>
  <Tab label="Solid" value="solid">

```tsx
import { LocaleProvider } from '@moduix/solid/locale';

<LocaleProvider locale="ar-EG">{props.children}</LocaleProvider>;
```

  </Tab>
</Tabs>

`LocaleProvider` derives Ark's direction from the locale, but it does not change native document
attributes. Update `lang`, `dir`, and the provider locale together when users switch languages without
reloading.

## Scope an RTL section

For one RTL area inside an LTR application, put `lang` and `dir` on that area's root and wrap its Moduix
components with `LocaleProvider`.

  </Tab>
  <Tab label="Solid" value="solid">

<CodeBlockRuntime lang="tsx" code={solidSection} />

The collection comes from the matching Ark UI adapter. Select, Button, and LocaleProvider come from
the matching Moduix adapter. Components read direction from the locale context and do not need a
separate RTL prop.

## Handle portals and mixed direction

Portalled content inherits CSS direction from its destination container, not from the trigger. Use
document-level direction for an application-wide locale, or render into a portal container inside the
RTL subtree.

For mixed content:

- use `dir="auto"` for plain text whose direction is unknown;
- use `dir="ltr"` for email addresses, URLs, codes, and telephone numbers that must keep LTR order;
- keep the surrounding application direction on the outer container.

## Use logical styles

Prefer logical properties when a rule follows reading direction:

```css
.item {
  padding-inline: var(--moduix-spacing-4);
  border-inline-start: var(--moduix-border-width-sm) solid var(--moduix-color-border);
  text-align: start;
}
```

Keep physical `left` and `right` only for real screen geometry, measured coordinates, resize edges, or
explicit gesture directions. Mirror directional icons such as back and forward, but not play, check,
download, or brand icons.

## Release checklist

- Test inputs with clear or action buttons.
- Check Select, Combobox, and Date Picker triggers and popups.
- Verify portalled Dialog, Popover, Menu, and Tooltip content.
- Test keyboard navigation, focus order, and directional keys.
- Mix Arabic or Hebrew text with email addresses, numbers, and codes.
- Check directional icons, gestures, and narrow layouts.
