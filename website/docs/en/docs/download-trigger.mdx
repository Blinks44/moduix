Use Ark UI's `DownloadTrigger` to turn file data into a browser download. Pair it with a moduix `Button` when the
action should match the rest of your interface.

## Basic

Pass ready-to-use content through `data`. It accepts a string, `Blob`, or `File`. `fileName` and `mimeType` describe the
file saved by the browser.

There is no built-in loading state or error callback. If generation can take time, manage that state in your
application, disable or replace the trigger while it runs, and handle failures in the function passed to `data`. To
download a remote resource, fetch it in your application and return `response.blob()`. A string is treated as file
contents, not as a URL.

## File metadata

Use a `fileName` extension that matches the content and set the corresponding `mimeType`, such as `application/json`,
`text/csv`, `image/svg+xml`, or `application/pdf`. When you return a `Blob` or `File`, keep its `type` consistent with
the requested MIME type as well.

## Composition

`DownloadTrigger` renders a native button by default. Use `asChild` when a moduix `Button` should own the button element
and its states. React uses a boolean `asChild` prop with a child element; Solid uses a render-function `asChild` prop.
Both compositions keep one accessible button in the DOM.

For QR code images, use `QrCode.DownloadTrigger` on the [QrCode](/docs/qr-code) page. It reads the image from the
nearest QR code and exports it with the required file metadata.
