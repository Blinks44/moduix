## Choosing the right component

Use `Field` when a single form control needs a visible label, helper text, an error message, or shared
`disabled`, `invalid`, `required`, and `readOnly` state.

- Choose **`Field`** for one control with its label and descriptive text.
- Choose **`Fieldset`** when several related fields need one shared legend.
- Use a standalone control when you do not need field-level ARIA wiring or shared state.

## Anatomy

`Field` uses the same parts as Ark UI and keeps their names in the public moduix API.

```text
Field
├─ Field.Label
├─ Field.Input | Field.Textarea | Field.Select | custom control
├─ Field.HelperText
├─ Field.ErrorText
└─ Field.RequiredIndicator
```

| Part                      | Role                                                            |
| ------------------------- | --------------------------------------------------------------- |
| `Field` / `Field.Root`    | Root context that renders a `<div role="group">` by default.   |
| `Field.RootProvider`      | Root backed by a `useField()` instance created outside the rendered tree. |
| `Field.Context`           | Access to the current field state without rendering an extra element. |
| `Field.Label`             | Label linked to the current control id.                         |
| `Field.Input`             | Low-level native input with Ark-compatible props. Prefer `Input` for regular use. |
| `Field.Textarea`          | Low-level textarea with Ark-compatible props. Prefer `Textarea` for regular use. |
| `Field.Select`            | Native select connected to the field's ARIA attributes and state. |
| `Field.HelperText`        | Helper text added to `aria-describedby`.                        |
| `Field.ErrorText`         | Error message rendered only when `Field` is `invalid`.          |
| `Field.RequiredIndicator` | Visual marker for required fields with an optional `fallback`.  |
| `Field.Item`              | Nested field context for grouped controls identified by `value`; its ref points to the rendered row wrapper. |

## Composition

### Recommended composition

Keep one visible label in the root and render one primary moduix control such as `Input`,
`Textarea`, or `NativeSelect`. Add helper or error text when the user needs a description or validation
feedback.

### When to go custom

Use `Field.Item value` with the root `target` prop when a field contains multiple native controls and
the label should target one of them. `Field.Input`, `Field.Textarea`, and `Field.Select` remain
available for low-level Ark composition, but regular application code should use the dedicated moduix
controls.

### Default props

| Surface                | Default | Notes                                                  |
| ---------------------- | ------- | ------------------------------------------------------ |
| `Field` / `Field.Root` | -       | No additional behavior; Ark defaults apply.            |

### Behavioral notes

- `Field.ErrorText` is not rendered until the root is `invalid`.
- Long labels, helper text, and error messages wrap inside the field instead of overflowing its container.
- Pass the value returned by `useField()` from `@moduix/react` to `Field.RootProvider`. Do not nest it
  inside `Field.Root` for the same field instance.
- Use `Field.Context` or `useFieldContext` from `@moduix/react` when a custom control needs the
  current field state. Import Ark directly only for lower-level APIs that moduix does not export.
- `Field.Item` forwards its ref to the row wrapper that moduix renders around its children.
- `Field` does not render a hidden input. Composed controls such as `Checkbox` and `RadioGroup`
  manage their own native form elements.

## Styling

Customize `Field` with `className`, Ark `data-scope="field"` / `data-part="..."` attributes,
moduix `data-slot="field-*"` hooks, and the public `--moduix-field-*` CSS variables shown below.

### Styling hooks

Ark adds `data-disabled`, `data-invalid`, `data-readonly`, and `data-required` to the relevant
parts. `Field.ErrorText` exists only while the current field context is invalid. The helper text id is
included in the control's `aria-describedby`, and the active error text id is included in
`aria-errormessage`. Every DOM part also keeps a stable `data-slot="field-*"` hook.
