## Choosing the right component

Use `Field` when one form control needs an accessible label, helper text, an error message, or shared
`disabled`, `invalid`, `required`, or `readOnly` state.

- Choose **`Field`** for one control and its label or descriptive text.
- Choose **`Fieldset`** when several related controls need one shared legend.
- Use a control on its own when you do not need field-level ARIA relationships or shared state.

## Anatomy

The public `Field` namespace follows Ark UI's part names. Use the low-level `Field.*` controls for
explicit Ark composition. For regular forms, prefer the matching moduix components such as `Input`,
`Textarea`, or `NativeSelect`.

```text
Field
├─ Field.Label
├─ Field.Input | Field.Textarea | Field.Select | custom control
├─ Field.HelperText
├─ Field.ErrorText
└─ Field.RequiredIndicator
```

| Part                     | Role                                                                                             |
| ------------------------ | ------------------------------------------------------------------------------------------------ |
| `Field` / `Field.Root`   | Root context. It renders a `<div role="group">` by default.                                    |
| `Field.RootProvider`     | Root that uses a `useField()` state object created outside the tree.                             |
| `Field.Context`          | Reads the current field state without adding an element to the DOM.                             |
| `Field.Label`            | Accessible label associated with the current control.                                            |
| `Field.Input`            | Low-level native input. Use `Input` for the usual moduix-styled input.                           |
| `Field.Textarea`         | Low-level native textarea. Use `Textarea` for the usual moduix-styled textarea.                 |
| `Field.Select`           | Low-level native select. Use `NativeSelect` for the usual moduix-styled select.                 |
| `Field.HelperText`       | Helper text associated with the control through `aria-describedby`.                              |
| `Field.ErrorText`        | Error text rendered when the root is `invalid`.                                                  |
| `Field.RequiredIndicator` | Visual marker for a required field. Use `fallback` to replace its default marker.               |
| `Field.Item`             | Nested context for a grouped control identified by `value`; its ref points to the local row wrapper. |

## Composition

### Recommended composition

Keep one visible label in the root and place one primary moduix control, such as `Input`, `Textarea`,
or `NativeSelect`, after it. Add helper or error text when the user needs a description or validation
feedback.

Controls with their own compound root, such as `Checkbox`, `RadioGroup`, or `Select`, can also sit
inside `Field`. Those components keep their own state props, so pass `required`, `invalid`, `disabled`,
or `readOnly` to the child root when that control owns the state.

### When to go custom

Use `Field.Item value` with the root `target` prop when a field contains several native controls and
the root label should point to one of them. `Field.Input`, `Field.Textarea`, and `Field.Select` are
available for low-level Ark composition, but application code should usually use the dedicated moduix
controls.

For a custom control that does not consume Ark Field context, use `Field.Context` or
`useFieldContext` from `@moduix/react` to read the field state and wire its ids and ARIA attributes.

### Default props

| Prop       | Default | Notes                                                                                  |
| ---------- | ------- | -------------------------------------------------------------------------------------- |
| `disabled` | `false` | Marks the field disabled and propagates to supported field parts.                      |
| `invalid`  | `false` | Controls `Field.ErrorText`; pass it to a compound child when that child owns validation. |
| `readOnly` | `false` | Marks the field read-only and propagates to supported field parts.                     |
| `required` | `false` | Marks the field required. `Field.RequiredIndicator` is still an explicit child.       |
| `target`   | -       | The `value` of the `Field.Item` that the root label should target.                     |

### Behavioral notes

- `Field.ErrorText` is not rendered until the root is `invalid`.
- The field does not validate values. Application state or a form library decides when `invalid`
  should be `true`.
- Long labels, helper text, and error messages wrap inside the field instead of overflowing its container.
- Pass the value returned by `useField()` from `@moduix/react` to `Field.RootProvider`. Do not render
  `Field.Root` and `Field.RootProvider` for the same field instance.
- Use `Field.Context` or `useFieldContext` from `@moduix/react` when a custom control needs the
  current field state. Ark props such as `ids`, `target`, and `asChild` remain available on the
  corresponding parts.
- `Field.Item` forwards its ref to the row wrapper that moduix renders around its children.
- Composed controls such as `Checkbox` and `RadioGroup` manage their own native form elements. Field
  itself does not render a hidden input.

## Styling

### Styling hooks

Ark adds `data-disabled`, `data-invalid`, `data-readonly`, and `data-required` to the relevant
parts. `Field.ErrorText` exists only while the current field context is invalid. The helper text id
is included in the control's `aria-describedby`, and the active error text id is included in
`aria-errormessage`. Every DOM part also keeps a stable `data-slot="field-*"` hook.
