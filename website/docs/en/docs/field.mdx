## Choosing the right component

Use `Field` when one form control needs an accessible label, helper text, an error message, or shared
`disabled`, `invalid`, `required`, or `readOnly` state.

- Choose **`Field`** for one control and its label or descriptive text.
- Choose **`Fieldset`** when several related controls need one shared legend.
- Use a control on its own when field-level ARIA relationships or shared state are not needed.

## Anatomy

The public `Field` namespace follows Ark UI's part names. Use the low-level `Field.*` controls for
explicit Ark composition. For regular forms, prefer the matching moduix components such as `Input`,
`Textarea`, or `NativeSelect`.

```text
Field
├─ Field.Label
├─ Field.Input | Field.Textarea | Field.Select | custom control
├─ Field.HelperText
├─ Field.ErrorText
└─ Field.RequiredIndicator

Field.RootProvider
└─ same part tree connected to a useField() store
```

| Part                      | Role                                                                                          |
| ------------------------- | --------------------------------------------------------------------------------------------- |
| `Field` / `Field.Root`    | Root context. It renders a `<div role="group">` by default.                                |
| `Field.RootProvider`      | Root that uses a `useField()` state object created outside the tree.                          |
| `Field.Context`           | Reads the current field state without adding an element to the DOM.                          |
| `Field.Label`             | Accessible label associated with the current control.                                         |
| `Field.Input`             | Low-level native input. Use `Input` for the usual moduix-styled input.                       |
| `Field.Textarea`          | Low-level native textarea. Use `Textarea` for the usual moduix-styled textarea.               |
| `Field.Select`            | Low-level native select. Use `NativeSelect` for the usual moduix-styled select.               |
| `Field.HelperText`        | Helper text associated with the control through `aria-describedby`.                           |
| `Field.ErrorText`         | Error text rendered when the root is `invalid`.                                               |
| `Field.RequiredIndicator` | Visual marker for a required field. Use `fallback` to replace its default marker.              |
| `Field.Item`              | Nested context for a grouped control identified by `value`; its ref points to the local row wrapper. |

## Composition

Use the root to combine one control with `Field.Label`, `Field.HelperText`, `Field.ErrorText`, and
`Field.RequiredIndicator`. Compound controls such as `Checkbox`, `RadioGroup`, and `Select` own their
control state, so pass `required`, `invalid`, `disabled`, or `readOnly` to their root when they own it.
For several native controls, wrap each one in `Field.Item value` and set the root `target`. Use
`Field.RootProvider` with `useField()` when state is created outside the rendered tree; custom controls
can read the current state through `Field.Context` or `useFieldContext`.

## Styling

Use `className` in React or `class` in Solid on exported parts for structural styles. For state-based
styles, prefer Ark data attributes such as `data-disabled`, `data-invalid`, `data-readonly`, and
`data-required`, together with moduix `data-slot` selectors. Tailwind variants use native utilities and
consumer classes; the CSS variables below customize the CSS Modules variants.

### Styling hooks

Ark adds `data-disabled`, `data-invalid`, `data-readonly`, and `data-required` to the relevant parts.
`Field.ErrorText` exists only while the current field context is invalid. The helper text id is included
in the control's `aria-describedby`, and the active error text id is included in `aria-errormessage`.
Every DOM part also keeps a stable `data-slot="field-*"` hook.
