Use `Field` as the wrapper for one form control. Put `FieldLabel` before the control, then add
`FieldHelperText` or `FieldErrorText` when the user needs more information.

## Choosing the right component

Use `Field` when one form control needs an accessible label, helper text, an error message, or shared
`disabled`, `invalid`, `required`, or `readOnly` state.

- Choose **`Field`** for one control and its label or descriptive text.
- Choose **`Fieldset`** when several related controls need one shared legend.
- Use a control on its own when field-level ARIA relationships or shared state are not needed.

## Composition

Use the root to combine one control with `FieldLabel`, `FieldHelperText`, `FieldErrorText`, and
`FieldRequiredIndicator`. Compound controls such as `Checkbox`, `RadioGroup`, and `Select` own their
control state, so pass `required`, `invalid`, `disabled`, or `readOnly` to their root when they own it.
For several native controls, wrap each one in `FieldItem value` and set the root `target`. Use
`FieldRootProvider` with `useField()` when state is created outside the rendered tree; custom controls
can read the current state through `FieldContext` or `useFieldContext`.

In Vue, initialize native controls with `v-model` and reset the bound refs in the form's reset handler.
Vue `Input` and `NativeSelect` do not provide React's `defaultValue` prop. Ark currently clears native
uncontrolled defaults on these controls; use `v-model` until that upstream behavior is fixed.

## Anatomy

The public `Field` API uses flat, family-prefixed values. `Field` does not render its own control: put
an `Input`, `Textarea`, `NativeSelect`, or another moduix form control inside it, and the control reads
the field context.

## Styling

A disabled `Field` or `FieldRootProvider` dims the whole field once; the controls inside it do not dim
again, and neither does a `Field` inside a disabled `Fieldset`.

Use `className` in React or `class` in Solid and Vue on exported parts for structural styles. For state-based
styles, prefer Ark data attributes such as `data-disabled`, `data-invalid`, `data-readonly`, and
`data-required`, together with moduix `data-slot` selectors. Tailwind variants use native utilities and
consumer classes. CSS Modules variants build on foundation tokens and have no component variables: a
class on the part overrides the layered component styles. The root fills the width of its container.

### Styling hooks

| Part | `data-slot` |
| --- | --- |
| `Field` | `field-root` |
| `FieldRootProvider` | `field-root-provider` |
| `FieldItem` | `field-item` |
| `FieldLabel` | `field-label` |
| `FieldHelperText` | `field-helper-text` |
| `FieldErrorText` | `field-error-text` |
| `FieldRequiredIndicator` | `field-required-indicator` |

Ark adds `data-disabled`, `data-invalid`, `data-readonly`, and `data-required` to the relevant parts. `FieldErrorText` exists only while the current field context is invalid. The helper text id and the
active error text id are included in the control's `aria-describedby`. Every DOM part also keeps a stable `data-slot="field-*"` hook.
