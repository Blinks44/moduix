## Choosing the right component

Use `PinInput` when a short, fixed-length value should be entered one character at a time in
separate cells.

- Choose **`PinInput`** for one-time codes, PINs, backup codes, and invite codes.
- Choose **`Input`** when one plain text input is enough.
- Choose **`PasswordInput`** when the value is one secret string with a visibility toggle.

## Anatomy

```text
PinInput / PinInput.Root
├─ PinInput.Label
├─ PinInput.Control
│  ├─ PinInput.Input[index=0]
│  ├─ PinInput.Input[index=1]
│  └─ PinInput.Input[index=2]
└─ hidden native input (automatic)
```

| Part                           | Role                                                                  |
| ------------------------------ | --------------------------------------------------------------------- |
| `PinInput` / `PinInput.Root`   | Root state machine, input count, value array, validation, and form options. |
| `PinInput.RootProvider`        | Builds the pin input tree from state returned by `usePinInput`.           |
| `PinInput.Label`               | Label for the pin input group.                                            |
| `PinInput.Control`             | Container for the visible indexed inputs.                                |
| `PinInput.Input`               | One visible character input. Pass a zero-based `index`.                   |
| `PinInput.Inputs`              | Generates the standard indexed inputs from the Ark context.              |
| `PinInput.Separator`           | Decorative moduix helper for grouping. It is not an Ark primitive part.  |
| `usePinInput` / `PinInput.RootProvider` | State management outside the rendered tree and imperative methods. |

## Composition

### Recommended composition

Use the compact `<PinInput>` root API, add a visible `Label`, and place `Inputs` inside `Control`. The root always
adds the hidden native form input, preserving form submission, reset synchronization, and OTP autofill.

### When to use a custom composition

Use explicitly indexed `Input` parts for grouped layouts or per-input props. Use `PinInput.RootProvider` and
`usePinInput` when state must be created outside the rendered tree. Keep Ark input indexes continuous across the
entire code.

### Default props

| Prop             | Default        | Notes                                                               |
| ---------------- | -------------- | ------------------------------------------------------------------- |
| `count`          | -              | Number of inputs. Set it explicitly for predictable SSR output.       |
| `type`           | `numeric`      | `numeric`, `alphabetic`, or `alphanumeric`.                           |
| `placeholder`    | `''` in moduix | Ark defaults to `○`; moduix hides it unless you pass `placeholder`.   |
| `otp`            | `false`        | Enables one-time-code autocomplete behavior.                          |
| `mask`           | `false`        | Masks visible values like password inputs.                             |
| `blurOnComplete` | `false`        | Blurs the last input after completion.                                 |
| `selectOnFocus`  | -              | Selects a focused input's current value when enabled.                  |
| `autoFocus`      | -              | Focuses the first input automatically when enabled.                    |
| `autoSubmit`     | -              | Submits the owning form after all inputs are filled.                    |
| `pattern`        | -              | Custom regular expression for accepted characters.                     |
| `sanitizeValue`  | -              | Sanitizes pasted values before validation, such as by removing spaces or dashes. |
| `defaultValue`   | `[]`           | Uncontrolled initial value as a string array.                           |
| `value`          | -              | Controlled value as a string array.                                     |

### Behavioral notes

`value` and `defaultValue` are string arrays. `onValueChange(details)` and `onValueComplete(details)` provide
`details.value` and `details.valueAsString`. `onValueInvalid(details)` provides the rejected `details.value` and
its `details.index`.

Use `type` and `pattern` for value validation. Use `sanitizeValue` to clean pasted values before validation.
`Field.Root` and `Fieldset.Root` can provide `disabled`, `invalid`, `required`, and `readOnly` state through Ark
context. Ark parts support `asChild`, and `ids` can provide stable element IDs for external labels or descriptions.

Set `autoSubmit` only when completing the code should submit the form that owns the input. Keyboard behavior follows
Ark: arrow keys move between cells, Backspace clears and moves back when needed, Delete clears the current cell, and
pasting fills the remaining cells.

### Styling hooks

- Root and root provider expose `data-slot="pin-input-root"` and `data-slot="pin-input-root-provider"`.
- Ark parts keep `data-scope="pin-input"` and `data-part="root" | "label" | "control" | "input"`.
- Root state styling uses `data-disabled`, `data-invalid`, `data-complete`, and `data-readonly`.
- Input state styling uses `data-disabled`, `data-invalid`, `data-complete`, `data-filled`, and
  `data-index`.
- `PinInput.Separator` exposes `data-slot="pin-input-separator"` and is decorative by default.

## Accessibility

Ark manages focus transfer, paste distribution, keyboard editing, hidden-input form data, and autocomplete behavior.
Add a `Label` so the group has an accessible name. The root adds its hidden native form input automatically; configure
form participation with root props such as `name` and `form`.
