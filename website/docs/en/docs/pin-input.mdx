## Choosing the right component

Use `PinInput` when a short, fixed-length code should be entered one character at a time in separate cells.

- Choose **`PinInput`** for one-time codes, PINs, backup codes, and invite codes.
- Choose **`PinInputInput`** when one plain text field is enough.
- Choose **`PasswordInput`** when the value is a single secret string with a visibility toggle.

## Anatomy

```text
PinInput
├─ PinInputLabel
├─ PinInputControl
│  ├─ PinInputInput[index=0]
│  ├─ PinInputInput[index=1]
│  └─ PinInputInput[index=2]
└─ PinInputHiddenInput (explicit)

PinInputRootProvider
└─ same part tree connected to a usePinInput() store
```

| Part | Role |
| --- | --- |
| `PinInput` | Owns input count, value state, validation, and form options. |
| `PinInputHiddenInput` | Native Ark form control that must be composed explicitly. |
| `PinInputRootProvider` | Connects the parts to state created with `usePinInput()`. |
| `PinInputContext` | Exposes the current root state to descendants through a render prop. |
| `PinInputLabel` | Labels the PIN or code input group. |
| `PinInputControl` | Container for the visible indexed inputs. |
| `PinInputInput` | One visible character input. Pass a zero-based `index`. |
| `PinInputInputs` | Generates one indexed `PinInputInput` for each item in the Ark context. |
| `PinInputSeparator` | Decorative moduix helper for grouping. It is not an Ark primitive part. |
| `usePinInput` | Creates state for use with `PinInputRootProvider`. |
| `usePinInputContext` | Reads the current Pin Input state inside the component tree. |

## Composition

Compose `PinInputHiddenInput` explicitly inside `PinInput` or `PinInputRootProvider` when the value should
participate in native form submission and reset behavior. Set `name` on the root, and set `form` when the form is
outside the component tree.

`PinInputInputs` renders one indexed input for every item in the Ark context. Use explicit `PinInputInput` parts with
continuous zero-based indexes and `PinInputSeparator` when the code needs groups. Values are string arrays. Use
`PinInputRootProvider` with `usePinInput` when state or imperative methods must be owned outside the rendered tree; React
receives a store object, while Solid receives an accessor.

Ark manages focus transfer, paste distribution, keyboard editing, and one-time-code autocomplete; add
`PinInputLabel` so the group has an accessible name. `PinInputSeparator` is decorative and renders with
`aria-hidden` and `role="presentation"`, so keep meaningful text outside it.

### Styling hooks

- The root and `PinInputRootProvider` expose `data-slot="pin-input-root"` and `data-slot="pin-input-root-provider"`.
- `PinInputLabel`, `PinInputControl`, and `PinInputInput` expose `data-slot="pin-input-label"`,
  `data-slot="pin-input-control"`, and `data-slot="pin-input-input"`.
- Ark parts use `data-scope="pin-input"` and `data-part="root" | "label" | "control" | "input"`.
- Root state styling uses `data-disabled`, `data-invalid`, `data-complete`, and `data-readonly`.
- Input state styling uses `data-disabled`, `data-invalid`, `data-complete`, `data-filled`, and `data-index`.
- `PinInputSeparator` exposes `data-slot="pin-input-separator"` and is decorative by default.
