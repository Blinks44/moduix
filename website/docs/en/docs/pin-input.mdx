## Choosing the right component

Use `PinInput` when a short, fixed-length code should be entered one character at a time in separate cells.

- Choose **`PinInput`** for one-time codes, PINs, backup codes, and invite codes.
- Choose **`Input`** when one plain text field is enough.
- Choose **`PasswordInput`** when the value is a single secret string with a visibility toggle.

## Basic

Use `<PinInput>` for the standard layout. It is a shorthand for `<PinInput.Root>`. Set `count` explicitly so the
server-rendered markup and ARIA attributes are predictable.

## Anatomy

```text
PinInput / PinInput.Root
├─ PinInput.Label
├─ PinInput.Control
│  ├─ PinInput.Input[index=0]
│  ├─ PinInput.Input[index=1]
│  └─ PinInput.Input[index=2]
└─ hidden native input (automatic)
```

| Part                                   | Role                                                                                         |
| -------------------------------------- | -------------------------------------------------------------------------------------------- |
| `PinInput` / `PinInput.Root`           | Root state machine, input count, value array, validation, and form options.                  |
| `PinInput.RootProvider`                | Renders the tree from a state object returned by `usePinInput`.                              |
| `PinInput.Context`                     | Exposes the current root state to descendants through a render prop.                        |
| `PinInput.Label`                       | Labels the PIN or code input group.                                                          |
| `PinInput.Control`                     | Container for the visible indexed inputs.                                                    |
| `PinInput.Input`                       | One visible character input. Pass a zero-based `index`.                                      |
| `PinInput.Inputs`                      | Generates one indexed `Input` for each item in the Ark context. Its `className` is applied to each input. |
| `PinInput.Separator`                   | Decorative moduix helper for grouping. It is not an Ark primitive part.                      |
| `usePinInput`                          | Creates state for use with `PinInput.RootProvider`.                                          |
| `usePinInputContext`                    | Reads the current Pin Input state from inside the component tree.                            |

## Composition

### Recommended composition

Use the compact `<PinInput>` root, add a visible `Label`, and place `Inputs` inside `Control`. Use `name` when the
code should be included in form submission.

### When to go custom

Render indexed `Input` parts and `Separator` explicitly when the code needs groups or individual input props. Use
`PinInput.RootProvider` and `usePinInput` when state must be created outside the rendered tree. Keep indexes
zero-based and continuous across the entire composition.

### Default props

| Prop             | Default        | Notes                                                                 |
| ---------------- | -------------- | --------------------------------------------------------------------- |
| `count`          | -              | Number of cells. Set it explicitly for predictable SSR and ARIA output. |
| `type`           | `numeric`      | `numeric`, `alphabetic`, or `alphanumeric`.                           |
| `placeholder`    | `''` in moduix  | Ark uses `○` by default; moduix uses an empty string unless you pass this prop. |
| `otp`            | `false`        | Adds `autocomplete="one-time-code"` to the visible inputs.            |
| `mask`           | `false`        | Masks entered characters like a password input.                       |
| `blurOnComplete` | `false`        | Blurs the last input after all cells are filled.                      |
| `selectOnFocus`  | -              | Selects the current value when an input receives focus.               |
| `autoFocus`      | -              | Focuses the first input when the component mounts.                    |
| `autoSubmit`     | -              | Submits the owning form after all inputs are filled.                  |
| `pattern`        | -              | Custom regular expression for accepted characters.                    |
| `sanitizeValue`  | -              | Cleans pasted values before validation, such as by removing spaces or dashes. |
| `defaultValue`   | `[]`           | Uncontrolled initial value as a string array.                         |
| `value`          | -              | Controlled value as a string array.                                   |

### Behavioral notes

`value` and `defaultValue` are string arrays. `onValueChange(details)` and `onValueComplete(details)` expose
`details.value` and `details.valueAsString`. `onValueInvalid(details)` exposes the rejected value in `details.value`
and its `details.index`.

Use `type` for the built-in character sets and `pattern` for a custom regular expression. `sanitizeValue` receives
pasted text and returns the value to validate.

`Field.Root` and `Fieldset.Root` can provide `disabled`, `invalid`, `required`, and `readOnly` through Ark context.
Pass root options such as `name`, `form`, `ids`, and `translations` to `PinInput`. The root and its parts support
`asChild`.

Pass `className` to `PinInput.Inputs` when every generated input should share the same class. Use explicit `Input`
parts when individual inputs need different props or styles.

Set `autoSubmit` only when completing the code should submit its owning form. Keyboard behavior follows Ark: arrow
keys move between cells, Backspace clears a cell and moves back when needed, Delete clears the current cell, and
pasting fills the remaining cells.

## Accessibility

Ark manages focus transfer, paste distribution, keyboard editing, hidden form data, and one-time-code
autocomplete. Add a `Label` so the group has an accessible name.

`PinInput.Separator` is decorative by default and renders with `aria-hidden` and `role="presentation"`. Keep
meaningful text outside the separator.

For native form submission, pass `name` to the root and use `form` when the component belongs to a form elsewhere in
the document. The root renders the hidden native input automatically.

### Styling hooks

- The root and `RootProvider` expose `data-slot="pin-input-root"` and `data-slot="pin-input-root-provider"`.
- `Label`, `Control`, `Input`, and the hidden input expose `data-slot="pin-input-label"`,
  `data-slot="pin-input-control"`, `data-slot="pin-input-input"`, and `data-slot="pin-input-hidden-input"`.
- Ark parts use `data-scope="pin-input"` and `data-part="root" | "label" | "control" | "input"`.
- Root state styling uses `data-disabled`, `data-invalid`, `data-complete`, and `data-readonly`.
- Input state styling uses `data-disabled`, `data-invalid`, `data-complete`, `data-filled`, and `data-index`.
- `PinInput.Separator` exposes `data-slot="pin-input-separator"` and is decorative by default.
