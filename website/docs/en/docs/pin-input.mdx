`PinInputControl`, and compose `PinInputHiddenInput` when the value must participate in native form behavior.

## Choosing the right component

Use `PinInput` when a short, fixed-length code should be entered one character at a time in separate cells.

- Choose **`PinInput`** for one-time codes, PINs, backup codes, and invite codes.
- Choose **`Input`** when one plain text field is enough.
- Choose **`PasswordInput`** when the value is a single secret string with a visibility toggle.

## Composition

Compose `PinInputHiddenInput` explicitly inside `PinInput` or `PinInputRootProvider` when the value should
participate in native form submission and reset behavior. Set `name` on the root, and set `form` when the form is
outside the component tree.

`PinInputInputs` renders one indexed input for every item in the Ark context. Use explicit `PinInputInput` parts with
continuous zero-based indexes and `PinInputSeparator` when the code needs groups. Values are string arrays. Use
`PinInputRootProvider` with `usePinInput` when state or imperative methods must live outside the rendered tree; React
receives a store object, Solid receives an accessor, and Vue exposes the reactive store directly to the template.

Ark manages focus transfer, paste distribution, keyboard editing, and one-time-code autocomplete; add
`PinInputLabel` so the group has an accessible name. `PinInputSeparator` is decorative and renders with
`aria-hidden`, so keep meaningful text outside it.

## Styling

### CSS variables

Hover or focus a variable to see it in the preview.

<CssPropertiesSection properties={PinInputDocs.pinInputOverrideCssProperties}>
  <AnatomyScene />
</CssPropertiesSection>

CSS Modules packages expose three variables: `--moduix-pin-input-input-size` (applies to every size),
`--moduix-pin-input-gap`, and `--moduix-pin-input-radius`. Colors, borders, typography, and the focus ring
come from foundation tokens; override them with a class on the part. Tailwind packages use native utilities
and consumer `className` or `class` overrides.

### Styling hooks

| Part | `data-slot` |
| --- | --- |
| `PinInput` | `pin-input-root` |
| `PinInputRootProvider` | `pin-input-root-provider` |
| `PinInputLabel` | `pin-input-label` |
| `PinInputControl` | `pin-input-control` |
| `PinInputInput` | `pin-input-input` |
| `PinInputSeparator` | `pin-input-separator` |

- Ark state selectors: `data-required` on the label.

- Ark parts use `data-scope="pin-input"` and `data-part="root" | "label" | "control" | "input"`.
- Root state styling uses `data-disabled`, `data-invalid`, `data-complete`, and `data-readonly`.
- Input state styling uses `data-disabled`, `data-invalid`, `data-complete`, `data-filled`, and `data-index`.
- The root mirrors `size` as `data-size`. A disabled `PinInput` inside a disabled `Field` or `Fieldset` is not
  dimmed a second time.

## Keyboard

| Key | Action |
| --- | --- |
| Characters | Fill the box and move to the next one. |
| `Backspace` | Clears the box and moves to the previous one. |
| `ArrowLeft` / `ArrowRight` | Moves between boxes. |
| `Ctrl+V` | Pastes a whole code across the boxes. |
