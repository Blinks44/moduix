## Anatomy

```text
createToaster()
└─ Toaster / Toast.Toaster (portalled to document.body by default)
   └─ Toast / Toast.Root
      ├─ Toast.Title
      ├─ Toast.Description
      ├─ Toast.ActionTrigger
      └─ Toast.CloseTrigger
```

| Part                       | Role                                                                                      |
| -------------------------- | ----------------------------------------------------------------------------------------- |
| `Toast` / `Toast.Root`     | Root of a visible toast. `Toast.Root` is a compatibility alias for `Toast`.              |
| `Toaster` / `Toast.Toaster` | Renders a toaster store and manages the toast group.                                     |
| `Toast.Title`              | Title part. Uses the current toast `title` when no children are passed.                    |
| `Toast.Description`        | Description part. Uses the current toast `description` when no children are passed.        |
| `Toast.ActionTrigger`      | Action button connected to `toast.action.onClick`. Pass `toast.action.label` as content. |
| `Toast.CloseTrigger`       | Dismiss button. Uses `CloseButton.Root` by default.                                      |
| `Toast.Context`            | Context part for custom composition. Use `useToastContext()` for direct state access.     |

## Composition

`Toaster` renders the notification group through a portal by default. It targets `document.body`;
set `portalled={false}` to keep the group where `Toaster` is mounted, or pass `portalRef` to use a
different container. You do not need a separate `Portal` wrapper.

### Recommended composition

Create the toaster once, outside the component render path when possible, then pass the same object
to `Toaster`. The toaster controls placement, overlap, gap, queue size, duration, remove delay,
idle pausing, and the `Alt+T` focus hotkey.

Use `Toast` as the root of custom toast markup. `Toast.Root` remains available as a compatibility
alias.

Without a render prop, `Toaster` uses the moduix default renderer. It shows the title and description
when they are present, renders an action when one is provided, and includes a close button unless
`closable: false` is set. This is the recommended path for standard application feedback.

### When to go custom

Use the `Toaster` render prop when a toast needs a different layout, an icon, or custom controls.
For example, use it to replace the default close icon. Keep `Toast` as the outer item so Ark can
manage stacking, height measurement, dismissal, pausing, keyboard focus, and type/state attributes.

Rendered Ark parts support `asChild`. When replacing `ActionTrigger` or `CloseTrigger`, use one
semantic child and preserve button behavior.

If a custom child needs direct access to toast state, import `useToastContext()` from
`@moduix/react/toast`.

### Default props

| Prop                            | Default               | Notes                                                                                      |
| ------------------------------- | --------------------- | ------------------------------------------------------------------------------------------ |
| `createToaster.duration`        | Type-dependent         | Default duration for new toasts. Override it for one toast with `duration`.                |
| `createToaster.gap`             | `16`                  | Gap between toast items.                                                                    |
| `createToaster.max`             | `24`                  | New toasts are queued after the visible stack reaches this limit.                          |
| `createToaster.hotkey`          | `["altKey", "KeyT"]` | Moves focus to the toast group.                                                            |
| `createToaster.offsets`         | `"1rem"`              | Offset from the safe edge of the viewport.                                                  |
| `createToaster.overlap`         | `false`               | Use `true` for an overlapping stack.                                                        |
| `createToaster.pauseOnPageIdle` | `false`               | Set to `true` to pause timers while the page is idle.                                       |
| `createToaster.placement`       | `"bottom"`            | `top-start`, `top`, `top-end`, `bottom-start`, `bottom`, or `bottom-end`.                   |
| `createToaster.removeDelay`     | `200`                 | Keeps closed toasts mounted long enough for exit transitions.                              |
| `Toaster.portalled`             | `true`                | Set to `false` to render the group at the `Toaster` mount point.                            |

### Behavioral notes

- Use `toaster.create()` or the convenience methods `success()`, `error()`, `warning()`, `info()`,
  `loading()`, `promise()`, `update()`, `dismiss()`, `remove()`, and `dismissByPlacement()` from
  the toaster store.
- Toasts use Ark's default `type: "info"` when no type is provided. Moduix styles `info`, `success`,
  `warning`, and `error` as card-like status variants that match `Alert`.
- `toast.action` has the shape `{ label, onClick }` and is rendered by `Toast.ActionTrigger`.
- `toast.duration` controls one toast. `createToaster({ duration })` sets the store default.
- `toast.onStatusChange(details)` receives Ark status changes: `visible`, `dismissing`, and
  `unmounted`.
- When creating a toast inside an effect, defer the store call with
  `queueMicrotask(() => toaster.create(...))` to avoid React `flushSync` warnings.
- `Toast` exposes Ark state attributes such as `data-state`, `data-type`, `data-placement`,
  `data-align`, `data-side`, `data-mounted`, `data-paused`, `data-first`, `data-sibling`,
  `data-stack`, and `data-overlap`.

### Accessibility

Ark's live-region behavior, grouping, pause handling, focus hotkey, dismiss lifecycle, and status
callbacks remain intact. Use the `label` prop on `Toaster` when the toast group needs a custom
accessible label.

The default `Toast.CloseTrigger` is a button with the accessible label `Close toast`. If you use
`asChild`, the custom child must keep an accessible name and button semantics. `Toast.ActionTrigger`
also remains a button wired to `toast.action.onClick`.

### Styling hooks

Style the toast surface, border, motion, and type-based variants on `Toast`. Use `Toast.Title`,
`Toast.Description`, `Toast.ActionTrigger`, and `Toast.CloseTrigger` for inner typography and
controls.

Useful Ark selectors:

- `[data-scope='toast'][data-part='group']` on `Toaster`
- `[data-scope='toast'][data-part='root']` on `Toast`
- `[data-scope='toast'][data-part='title']` on `Toast.Title`
- `[data-scope='toast'][data-part='description']` on `Toast.Description`
- `[data-scope='toast'][data-part='action-trigger']` on `Toast.ActionTrigger`
- `[data-scope='toast'][data-part='close-trigger']` on `Toast.CloseTrigger`
- `--x`, `--y`, `--scale`, `--z-index`, `--height`, `--opacity`, and `--gap` on `Toast`

Moduix also adds stable hooks: `data-slot="toast-toaster"`, `data-slot="toast-root"`,
`data-slot="toast-title"`, `data-slot="toast-description"`, `data-slot="toast-action-trigger"`,
and `data-slot="toast-close-trigger"`.

At viewport widths up to `40rem`, the toaster group spans the viewport and each root uses Ark's
`--gap` variable to keep safe inline spacing.
