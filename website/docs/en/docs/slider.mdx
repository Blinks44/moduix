## Choosing the right component

Use `Slider` when users need to adjust a numeric value within defined bounds with a pointer or
keyboard.

- Choose **`Slider`** for volume, brightness, budgets, thresholds, and ranges with multiple thumbs.
- Choose **`Input`** or **`NumberInput`** when users need to type an exact value instead of dragging
  to choose it.
- Choose **`ProgressLinear`** or **`ProgressCircular`** when the value is for display only.

## Composition

### Recommended composition

Use the Ark part tree: root, label, optional value text, control, track, range, and `Slider.Thumbs`.
It creates one thumb per value, and each thumb adds its native form input automatically.

`Slider` is the shorthand root and is equivalent to `Slider.Root`.

### When to go custom

Use `asChild` when a part needs to render as a custom element. Keep one semantic child that can
receive Ark props. Use explicit `Slider.Thumb` when individual thumbs need custom children,
accessible names, or a specific order; it still adds the native form input automatically. For
advanced state access, use `Slider.Context` or `useSliderContext` to read state below the root. To
own the state outside the rendered tree, import `useSlider` from `@moduix/react/slider` and pair
it with `Slider.RootProvider`.

### Default props

| Prop                     | Default      | Notes                                      |
| ------------------------ | ------------ | ------------------------------------------ |
| `defaultValue`           | `[min]`      | Ark stores slider values as `number[]`.    |
| `orientation`            | `horizontal` | Use `vertical` for vertical keyboard axis. |
| `min`                    | `0`          | Lower bound.                               |
| `max`                    | `100`        | Upper bound.                               |
| `step`                   | `1`          | Pointer and keyboard increment.                           |
| `largeStep`              | `10 * step`  | Increment for Page Up, Page Down, and Shift + Arrow keys. |
| `minStepsBetweenThumbs`  | `0`          | Minimum gap between range thumbs.                         |
| `origin`                 | `start`      | Fill origin for a single-value slider.                    |
| `thumbAlignment`         | `contain`    | Use `center` to let the thumb extend past the track.      |
| `thumbCollisionBehavior` | `none`       | Use `push` or `swap` to change range-thumb collisions.    |
| `thumbSize`              | measured     | Override Ark's measured thumb dimensions.                 |

`value`, `defaultValue`, `onValueChange(details)`, and `onValueChangeEnd(details)` use Ark detail
objects. Read the array from `details.value`. `onFocusChange(details)` reports which thumb has
focus. When `defaultValue` is omitted, the initial value is `[min]`, which is `[0]` by default. Use
`ids` to provide stable IDs when other elements need to refer to the slider parts.

### Behavioral notes

`Slider` follows Ark's WAI-ARIA slider pattern. Give every thumb an accessible name with
`Slider.Label`, `aria-label`, or `aria-labelledby`. Horizontal sliders use the left and right
arrow keys; vertical sliders use the up and down arrow keys. `Page Up`, `Page Down`, and
`Shift + ArrowUp` or `Shift + ArrowDown` use `largeStep` (by default, `10 * step`). `Home` and
`End` move the active thumb to the minimum and maximum values.

Every `Slider.Thumb` adds a hidden native form input automatically. It participates in form
submission and reset synchronization. `id`, `asChild`, `disabled`, `invalid`, `readOnly`, `name`,
`form`, `ids`, `aria-label`, `aria-labelledby`, and `getAriaValueText(details)` pass through to Ark.

### Styling hooks

Ark adds `data-scope="slider"` and `data-part` to all rendered parts. moduix also adds
`data-slot` values: `slider-root`, `slider-root-provider`, `slider-label`, `slider-value-text`,
`slider-control`, `slider-track`, `slider-range`, `slider-thumb`, `slider-hidden-input`,
`slider-marker-group`, `slider-marker`, and `slider-dragging-indicator`.

Important Ark state attributes include `data-orientation`, `data-disabled`, `data-invalid`,
`data-focus`, `data-dragging`, marker `data-state`, and dragging-indicator
`data-state="open | closed"`. Ark runtime CSS variables include `--slider-thumb-width`,
`--slider-thumb-height`, `--slider-thumb-transform`, `--slider-range-start`,
`--slider-range-end`, `--translate-x`, and `--translate-y`.

moduix adds `data-readonly` to `Slider` when its `readOnly` prop is set. The default invalid state
uses the destructive color for the track, selected range, thumb, and active markers. Override these
independently with `--moduix-slider-track-border-color-invalid`,
`--moduix-slider-range-bg-invalid`, `--moduix-slider-thumb-border-color-invalid`,
`--moduix-slider-thumb-focus-ring-color-invalid`, and
`--moduix-slider-marker-dot-bg-active-invalid`.

The default thumb focus ring uses `:focus-visible` for keyboard focus and Ark `data-dragging` while
the thumb is pressed. It is removed after pointer release.
