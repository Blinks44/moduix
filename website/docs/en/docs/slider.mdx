## Choosing the right component

Use `Slider` when users need to adjust a numeric value within defined bounds with a pointer or
keyboard.

- Choose **`Slider`** for volume, brightness, budgets, thresholds, and ranges with multiple thumbs.
- Choose **`Input`** or **`NumberInput`** when users need to type an exact value instead of dragging
  to choose it.
- Choose **`ProgressLinear`** or **`ProgressCircular`** when the value is for display only.

## Anatomy

```text
Slider / Slider.Root
├─ Slider.Label
├─ Slider.ValueText
├─ Slider.Control
│  ├─ Slider.Track
│  │  └─ Slider.Range
│  └─ Slider.Thumb[index]
│     ├─ Slider.DraggingIndicator
│     └─ Slider.HiddenInput
└─ Slider.MarkerGroup
   └─ Slider.Marker[value]
```

| Part                                   | Role                                                        |
| -------------------------------------- | ----------------------------------------------------------- |
| `Slider` / `Slider.Root`               | Styled Ark root for controlled and uncontrolled state.       |
| `Slider.HiddenInput` | Native Ark form control; compose explicitly as described below. |
| `Slider.RootProvider`                  | Root connected to an externally created `useSlider` state.  |
| `Slider.Label`                         | Visible label for the slider group.                          |
| `Slider.ValueText`                     | Current value text generated by Ark.                         |
| `Slider.Control`                       | Pointer interaction area.                                    |
| `Slider.Track`                         | Full visual track.                                           |
| `Slider.Range`                         | Filled portion from the configured origin to the value.      |
| `Slider.Thumb`                         | Focusable slider thumb.                                      |
| `Slider.Thumbs`                        | moduix helper that renders one thumb per value.              |
| `Slider.MarkerGroup` / `Slider.Marker` | Optional group of tick marks and individual marks.           |
| `Slider.DraggingIndicator`             | Optional value bubble shown while dragging.                  |

## Composition

Use `Slider.Thumbs` for the standard one-thumb-per-value composition; it also renders one
`Slider.HiddenInput` per thumb. When a thumb needs custom children, an accessible name, or a
specific order, compose `Slider.Thumb` explicitly and place one `Slider.HiddenInput` inside it.
Set `name` on the root for form submission.

For controlled state, store `details.value` from `onValueChange` or `onValueChangeEnd`. Use
`useSliderContext` inside descendants to read state. If state must live outside the rendered
tree, create it with `useSlider` and pass it to `Slider.RootProvider`; do not render another
root for the same store. React reads the store as an object, while Solid reads it through the
returned accessor. `Slider` is an alias for `Slider.Root`.

### Styling hooks

Ark adds `data-scope="slider"` and `data-part` to all rendered parts. moduix also adds
`data-slot` values: `slider-root`, `slider-root-provider`, `slider-label`, `slider-value-text`,
`slider-control`, `slider-track`, `slider-range`, `slider-thumb`,
`slider-marker-group`, `slider-marker`, and `slider-dragging-indicator`.

Important Ark state attributes include `data-orientation`, `data-disabled`, `data-invalid`,
`data-focus`, `data-dragging`, marker `data-state`, and dragging-indicator
`data-state="open | closed"`. Ark runtime CSS variables include `--slider-thumb-width`,
`--slider-thumb-height`, `--slider-thumb-transform`, `--slider-range-start`,
`--slider-range-end`, `--translate-x`, and `--translate-y`.

moduix adds `data-readonly` to `Slider` when its `readOnly` prop is set. The default invalid state
uses the destructive color for the track, selected range, thumb, and active markers. Override these
independently with `--moduix-slider-track-border-color-invalid`,
`--moduix-slider-range-bg-invalid`, `--moduix-slider-thumb-border-color-invalid`,
