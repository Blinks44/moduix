## Anatomy

```text
SignaturePad
├─ SignaturePadLabel
├─ SignaturePadCanvas (moduix ready-made composition)
│  └─ SignaturePadControl
│     ├─ SignaturePadSegment
│     ├─ SignaturePadClearTrigger
│     └─ SignaturePadGuide
└─ SignaturePadHiddenInput value={serializedPaths} (explicit)

SignaturePadRootProvider
└─ same part tree connected to useSignaturePad()
```

| Part                                 | Role                                                                    |
| ------------------------------------ | ----------------------------------------------------------------------- |
| `SignaturePad`             | Owns paths, drawing options, form name, ids, and callbacks.              |
| `SignaturePadHiddenInput`  | Native Ark form control that you compose explicitly.                    |
| `SignaturePadRootProvider` | Renders the same part tree from state created with `useSignaturePad()`. |
| `SignaturePadLabel`        | Associates the visible label with the drawing area and hidden input.    |
| `SignaturePadCanvas`       | Ready-made drawing surface that renders the standard parts and forwards `SignaturePadControl` props. |
| `SignaturePadControl`      | Focusable pointer and touch drawing area.                               |
| `SignaturePadSegment`      | SVG layer for saved strokes and the current in-progress stroke.         |
| `SignaturePadClearTrigger` | Native button that clears paths.                                        |
| `SignaturePadGuide`        | Non-interactive baseline inside the drawing area.                       |

## Composition

Use `SignaturePadLabel` and `SignaturePadCanvas` for the standard composition. `SignaturePadCanvas`
uses a fixed child tree, so switch to `SignaturePadControl`, `SignaturePadSegment`,
`SignaturePadClearTrigger`, and `SignaturePadGuide` when the drawing structure or clear control
needs to change.

`SignaturePadHiddenInput` is not rendered automatically. Add it explicitly and pass a serialized
value, usually read from `SignaturePadContext` or `useSignaturePadContext()`, when the signature
must be submitted by a native form.

Use `defaultPaths` for local uncontrolled state. Use `paths` with `onDraw(details)` when the
application owns the signature data. Use `SignaturePadRootProvider` with `useSignaturePad()` when
state must be created outside the rendered tree or external controls need `paths`, `clear()`, or
`getDataUrl()`.

Unlike Ark, moduix disables `SignaturePadClearTrigger` when `readOnly` comes from the root, a
surrounding `Field`, or `useSignaturePad()`, preventing an irreversible clear while programmatic
`clear()` stays available.

### Styling hooks

Use `className` in React or `class` in Solid on any exported part for local styling. moduix also
adds stable `data-slot` attributes:

| Part                                 | `data-slot`                   |
| ------------------------------------ | ----------------------------- |
| `SignaturePad`             | `signature-pad-root`          |
| `SignaturePadRootProvider` | `signature-pad-root-provider` |
| `SignaturePadLabel`        | `signature-pad-label`          |
| `SignaturePadControl`      | `signature-pad-control`        |
| `SignaturePadSegment`      | `signature-pad-segment`        |
| `SignaturePadGuide`        | `signature-pad-guide`          |
| `SignaturePadClearTrigger` | `signature-pad-clear-trigger` |

Ark attributes remain available for targeted styles. `SignaturePad`, `SignaturePadLabel`,
`SignaturePadControl`, `SignaturePadSegment`, `SignaturePadGuide`, `SignaturePadClearTrigger`, and
the internal segment paths expose `data-scope="signature-pad"` and
`data-part`; `data-disabled` appears on root, label, control, and guide, while `data-required`
appears on label.
