## Basic


Create tour state with `useTour`, define its steps, and pass the returned object to `Tour`. The example starts with a
dialog, moves to a tooltip anchored to a page control, and finishes with a floating step. Keep the parts explicit so
you can adjust the composition when needed. `TourBody` keeps long copy scrollable inside the panel.

## Anatomy

```text
Tour
└─ Overlay subtree (portalled by default)
   ├─ TourBackdrop
   ├─ TourSpotlight
   └─ TourPositioner
      └─ TourContent
         ├─ TourArrow
         ├─ TourCloseIcon / TourCloseTrigger
         ├─ TourBody
         │  ├─ TourTitle
         │  ├─ TourDescription
         │  └─ TourProgressText
         └─ TourControl
            ├─ TourActionList
            └─ TourActions
               └─ TourActionTrigger[action]
```

| Part | Role |
| --- | --- |
| `Tour` | Root bound to the object returned by `useTour`. |
| `TourBackdrop` / `TourSpotlight` | Optional page overlay and highlight for the current target. |
| `TourPositioner` / `TourContent` | Position and render Ark's `alertdialog` surface. |
| `TourArrow` | Renders moduix's `TourArrowTip` by default for tooltip steps. |
| `TourCloseIcon` / `TourCloseTrigger` | Default accessible dismiss control or a custom close control. |
| `TourBody` | Scrollable moduix wrapper for the title, description, and progress text. |
| `TourControl` / `TourActionList` | Recommended action row and the actions from the current step. |
| `TourActions` / `TourActionTrigger` | Custom action UI while preserving each Ark action object. |

## Composition

Create state with `useTour` and pass its return value to `Tour`; in Solid, the return value is an accessor, so call
`tour()` to use methods such as `start()` and `next()`. In Vue, the return value is a ref: templates unwrap it, while
script code calls methods through `tour.value`. Keep the structural parts explicit and include `TourTitle` and
`TourDescription` so the alert dialog has an accessible name and description. `TourBackdrop`, `TourSpotlight`, and `TourPositioner`
are portalled by default; use `portalled={false}` or `portalRef` only when the overlay must stay in or target a specific
container. Use `TourActionList` for the actions declared in `steps`, or replace it with `TourActions` and
`TourActionTrigger asChild` when each action needs custom markup. `lazyMount` and `unmountOnExit` default to `true`; pass
callbacks to `useTour` when surrounding UI or analytics need to react to step or status changes.
In Vue, configure machine callbacks such as `onStepChange` and `onStatusChange` in `useTour`;
`@exit-complete` on `Tour` reports the end of the presence exit animation. Ark Vue currently declares
other root events but does not emit them from a tour object created outside the root.

## Examples

### Events

Use the detail objects from Ark callbacks to update surrounding UI or record analytics. Start the tour, choose Next,
then Done. The status output shows the latest step or final status event.

<Example name="tour/events" />

### Wait for input

Call `tour.next()` from an input handler after the value reaches two characters. For steps that depend on an
asynchronous condition, `waitForElement`, `waitForElementValue`, `waitForEvent`, and `waitForPromise` are also
exported from `@moduix/react/tour`, `@moduix/solid/tour`, and `@moduix/vue/tour`.

<Example name="tour/wait-for-input" />

### With Arrow

Add `TourArrow` to a tooltip step when it needs a visual connection to its target, and enable the step's `arrow`
option so Ark can position it.

<Example name="tour/with-arrow" />

### Advanced customization

Replace `TourActionList` when each action needs its own markup. The example uses custom `Button` children for
Continue, Back, and Skip tour. Each `TourActionTrigger` still receives the original Ark action object, so navigation,
dismissal, and disabled state continue to work. The example also skips the `TourCloseIcon` and `TourBody`
helpers and places the title, description, and progress text directly in `TourContent`.

## Styling

`TourContent` is 20rem wide for tooltip steps, 26rem for dialog steps, and 22rem for floating steps,
within the viewport and Ark's available space. Its height is capped at 24rem: put step copy in
`TourBody` so it scrolls instead of spilling past the surface. Floating steps sit 1.5rem from the
viewport edge named by `placement`, or in the viewport center for `placement: 'center'`. Overlay
layers start at the `--moduix-z-tour` token: the backdrop, the spotlight, and the positioner stack in
that order, above dialogs and popovers and below toasts. `TourCloseTrigger` is unstyled; `TourCloseIcon` is the styled icon-only close button.
Content motion reads the shared `--moduix-popup-motion-*` variables, and backdrop and content
animations are skipped when the user prefers reduced motion.

Use `className` in React or `class` in Solid and Vue on exported parts. Tailwind variants use native
utilities and consumer classes. CSS Modules variants build on foundation tokens and have no component
variables: a class on the part overrides the layered component styles. Pass `className` (or `class`)
to `TourActionList` to style every generated trigger.

### Styling hooks

The main public hooks are `data-slot="tour-backdrop"`, `tour-spotlight`, `tour-positioner`,
`tour-content`, `tour-arrow`, `tour-arrow-tip`, `tour-title`, `tour-description`,
`tour-progress-text`, `tour-body`, `tour-close-trigger`, `tour-close-icon`, `tour-control`, and
`tour-action-trigger`. Ark also adds `data-scope="tour"`, `data-part`, `data-state`, `data-type`,
`data-placement`, `data-side`, `data-step`, and `data-disabled`, plus runtime variables including
`--tour-layer`, `--available-width`, `--available-height`, `--transform-origin`, and the arrow
variables.
