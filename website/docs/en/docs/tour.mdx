## Anatomy

```text
Tour
└─ Overlay subtree (portalled by default)
   ├─ Tour.Backdrop
   ├─ Tour.Spotlight
   └─ Tour.Positioner
      └─ Tour.Content
         ├─ Tour.Arrow
         ├─ Tour.CloseIcon / Tour.CloseTrigger
         ├─ Tour.Body
         │  ├─ Tour.Title
         │  ├─ Tour.Description
         │  └─ Tour.ProgressText
         └─ Tour.Control
            ├─ Tour.ActionList
            └─ Tour.Actions
               └─ Tour.ActionTrigger[action]
```

| Part | Role |
| --- | --- |
| `Tour` | Root bound to a `UseTourReturn` object. `Tour.Root` is an alias. |
| `Tour.Backdrop` / `Tour.Spotlight` | Optional page overlay and highlight for the current target. |
| `Tour.Positioner` / `Tour.Content` | Position and render Ark's `alertdialog` surface. |
| `Tour.Arrow` | Renders moduix's `ArrowTip` by default for tooltip steps. |
| `Tour.CloseIcon` | Accessible icon-only dismiss control. Use `CloseTrigger` for custom markup. |
| `Tour.Body` | Scrollable moduix wrapper for the title, description, and progress text. |
| `Tour.Control` / `Tour.ActionList` | Recommended action row and the actions from the current step. |
| `Tour.Actions` / `Tour.ActionTrigger` | Custom action UI while preserving each Ark action object. |

## Composition

### Recommended composition

`Tour` automatically portals `Backdrop`, `Spotlight`, and `Positioner`. Set `portalled={false}`
only when the overlay must remain inline, or pass `portalRef` to render it in a specific container.
Keep the structural parts explicit. Add `Tour.ActionList` when the actions declared in `steps` suit
your interface; it renders the current step's actions for you.

### When to go custom

Use `Tour.Actions` and `Tour.ActionTrigger` when an action needs custom markup. They keep Ark's
navigation, dismissal, and disabled behavior while letting you render your own controls. Pass
`onStepChange`, `onStepsChange`, or `onStatusChange` to `useTour` when surrounding UI or analytics
need to react to the tour. Inside the tree, use the moduix exports `useTourContext` or
`Tour.Context` to access the active step and navigation methods.

### Default props

The portalled overlay mounts when the tour first opens and unmounts after its exit animation by
default. Set `unmountOnExit={false}` to keep it mounted after the first open. Set both lifecycle
props to `false` only when the overlay must render eagerly.

| Prop | Default | Notes |
| --- | --- | --- |
| `closeOnEscape` | `true` | Escape dismisses the tour. |
| `closeOnInteractOutside` | `true` | Interaction outside the tour dismisses it unless disabled. |
| `keyboardNavigation` | `true` | Left and Right navigate available steps. |
| `preventInteraction` | `false` | Set to `true` to block page interaction while the tour is open. |
| `spotlightOffset` | `{ x: 10, y: 10 }` | Expands the highlighted area around the target. |
| `spotlightRadius` | `4` | Rounds the corners of the spotlight. |
| `lazyMount` | `true` | Defers rendering the overlay until the first open. |
| `unmountOnExit` | `true` | Unmounts the overlay after the closing animation. |

### Behavioral notes

`Tour.Title` gives the alert dialog its accessible name, and `Tour.Description` supplies its
description. Ark manages focus on open and close, Escape, outside interaction, and Left/Right
navigation. Leave `keyboardNavigation` enabled unless a step intentionally uses those keys. In
right-to-left layouts, Ark reverses Left and Right navigation.

### Styling hooks

Use moduix `data-slot` hooks such as `tour-content`, `tour-body`, and `tour-action-trigger` for
local styling. Ark also provides `data-scope="tour"`, `data-part`, `data-state`, `data-type`,
`data-placement`, `data-side`, `data-step`, and `data-disabled`, plus runtime variables including
`--tour-layer`, `--tour-z-index`, `--available-width`, `--available-height`, `--transform-origin`,
and the arrow variables. Pass `className` to `Tour.ActionList` to style every generated trigger.
The stylesheet shortens overlay animations and removes action-button transitions for people who
prefer reduced motion.
