## Choosing the right component

Use `Tabs` to switch between related views in one page region. Selecting a tab shows its matching
content panel and hides the other panels.

- Choose **`Tabs`** when each tab should reveal one associated content panel.
- Choose **`Accordion`** when sections should stay stacked and open independently.
- Choose **`ToggleGroup`** when the control changes a state or mode without owning panel content.

## Anatomy

```text
Tabs / Tabs.Root
├─ Tabs.List
│  ├─ Tabs.Trigger[value]
│  ├─ Tabs.Trigger[value]
│  └─ Tabs.Indicator
└─ Tabs.Content[value]

Tabs.RootProvider
└─ same parts connected to a useTabs() store

Tabs.Context
└─ render prop
```

| Part                  | Role                                                               |
| --------------------- | ------------------------------------------------------------------ |
| `Tabs` / `Tabs.Root`  | Root that owns the selected value, focus, orientation, and mode.   |
| `Tabs.RootProvider`   | Connects the parts to state created with moduix `useTabs()`.       |
| `Tabs.Context`        | Exposes the current tab state through a render prop.              |
| `Tabs.List`           | Groups triggers and manages focus movement between them.          |
| `Tabs.Trigger`        | Interactive tab button, or an `asChild` host, with a required value. |
| `Tabs.Indicator`      | Optional indicator for the selected tab.                           |
| `Tabs.Content`        | Content panel associated with a matching trigger value.            |

## Composition

Use `defaultValue` for an uncontrolled component. When another part of the application owns the
selection, pass `value` and `onValueChange(details)` and read the selected value from
`details.value`.

Use `Tabs.RootProvider` with `useTabs()` when the state must be created outside the rendered tree
or shared with adjacent UI. Pass the store to `RootProvider` and do not render another `Tabs` root
for the same state. Use `asChild` on `Tabs.Trigger` for a link or router component, and render
`Tabs.Indicator` explicitly because `Tabs.List` does not add one automatically.

## Styling

Use `className` in React or `class` in Solid on exported parts for structural styles. For state-based
styles, prefer Ark data attributes such as `data-selected`, `data-disabled`, and `data-orientation`,
together with moduix `data-slot` selectors. Tailwind variants use native utilities and consumer
classes; the variables below customize the CSS Modules variants.

### Styling hooks

Target the part that owns the visual concern:

- `Tabs` for layout width, overall gap, orientation, and variant-level overrides
- `Tabs.List` for list chrome, borders, background, and indicator-container spacing
- `Tabs.Trigger` for label layout, icon spacing, selected and disabled states, and focus styling
- `Tabs.Indicator` for custom indicator color, size, and transitions
- `Tabs.Content` for the panel surface, padding, and focus styling

The main public hooks are `data-slot="tabs-root"`, `data-slot="tabs-root-provider"`,
`data-slot="tabs-list"`, `data-slot="tabs-trigger"`, `data-slot="tabs-indicator"`, and
`data-slot="tabs-content"`.

Useful Ark hooks include `data-scope="tabs"`, `data-part`, `data-orientation`, `data-selected`,
`data-disabled`, `data-focus`, and the indicator variables `--left`, `--top`, `--width`,
`--height`, and `--transition-property`.
