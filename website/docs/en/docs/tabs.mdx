## Choosing the right component

Use `Tabs` to switch between related views in one page region. Selecting a tab shows its matching
content panel and hides the other panels.

- Choose **`Tabs`** when each tab should reveal one associated content panel.
- Choose **`Accordion`** when sections should stay stacked and open independently.
- Choose **`ToggleGroup`** when the control changes a state or mode without owning panel content.

## Anatomy

```text
Tabs
├─ Tabs.List
│  ├─ Tabs.Trigger[value]
│  ├─ Tabs.Trigger[value]
│  └─ Tabs.Indicator
└─ Tabs.Content[value]

Tabs.RootProvider
└─ Tabs.* + useTabs()

Tabs.Context
└─ render prop
```

| Part                | Role                                                               |
| ------------------- | ------------------------------------------------------------------ |
| `Tabs`              | Root that owns the selected value, focus, orientation, and mode.   |
| `Tabs.RootProvider` | Connects the parts to state created with moduix `useTabs()`.       |
| `Tabs.Context`      | Exposes the current tab state through a render prop.               |
| `Tabs.List`         | Groups triggers and manages focus movement between them.          |
| `Tabs.Trigger`      | Interactive tab button, or an `asChild` host, with a required value. |
| `Tabs.Indicator`    | Optional indicator for the selected tab.                            |
| `Tabs.Content`      | Content panel associated with a matching trigger value.            |

## Composition

### Recommended composition

Use `<Tabs>` for the common case. It owns keyboard navigation, focus movement, and the selected
value. Use `defaultValue` for the initial tab, or pass `value` with `onValueChange(details)` when
React state should control the selection. Read the selected value from `details.value`.

The root also accepts `onFocusChange(details)`, `activationMode`, `orientation`, `loopFocus`,
`deselectable`, `lazyMount`, `unmountOnExit`, `ids`, and `navigate`, which pass through to Ark UI.

Keep the part tree explicit. `Tabs.List` groups the triggers but does not render an indicator;
add `Tabs.Indicator` when the selected tab needs a visual marker.

### When to go custom

Use `asChild` on `Tabs.Trigger` when a tab should render a link or a router component. The child
must be one semantic element that preserves Ark's keyboard, focus, and ARIA behavior.

Use `useTabs()` or `Tabs.useTabs()` with `Tabs.RootProvider` when the tab state needs to be created
outside the rendered tree, or when adjacent UI needs to read or update the selection. Do not wrap
the same state instance in another `Tabs` root.

Use `Tabs.Context` for a render-prop pattern, or `useTabsContext()` to read the current state from
descendants of `Tabs` or `Tabs.RootProvider`.

### Default props

| Prop                   | Default      | Notes                                                        |
| ---------------------- | ------------ | ------------------------------------------------------------ |
| `Tabs.variant`         | `default`    | Visual treatment: `default` or `line`.                       |
| `Tabs.activationMode`  | `automatic`  | Focus selects the tab automatically unless set to `manual`. |
| `Tabs.orientation`     | `horizontal` | Horizontal tabs use left/right arrows; vertical tabs use up/down arrows. |
| `Tabs.loopFocus`       | `true`       | Focus wraps from the last trigger back to the first.        |
| `Tabs.lazyMount`       | `false`      | Mounts a panel only after its tab is selected.               |
| `Tabs.unmountOnExit`   | `false`      | Unmounts inactive panels, usually with `lazyMount`.          |

### Behavioral notes

- `Tabs.Trigger` and `Tabs.Content` connect through matching string `value` props.
- With `activationMode="automatic"`, moving focus selects a tab. With `manual`, focus moves first and selection happens on activation.
- `onValueChange` receives Ark's `details` object; the selected value is `details.value`.
- A disabled `Tabs.Trigger` stays visible but cannot receive focus or selection.
- `variant="line"` applies only to horizontal tabs. Vertical `Tabs` and `Tabs.RootProvider` use the filled `default` treatment.
- Ark UI manages the ARIA attributes, tab and tabpanel relationships, keyboard navigation, focus movement, and disabled behavior.

## Styling

Style `Tabs` with `className`, stable `data-slot="tabs-*"` hooks, Ark's `data-scope` and
`data-part` attributes, the root's `data-variant`, and the public `--moduix-tabs-*` CSS variables
listed below.

### Styling hooks

Target the part that owns the visual concern:

- `Tabs` for layout width, overall gap, orientation, and variant-level overrides
- `Tabs.List` for list chrome, borders, background, and indicator-container spacing
- `Tabs.Trigger` for label layout, icon spacing, selected and disabled states, and focus styling
- `Tabs.Indicator` for custom indicator color, size, and transitions
- `Tabs.Content` for the panel surface, padding, and focus styling

The main public hooks are `data-slot="tabs-root"`, `data-slot="tabs-root-provider"`,
`data-slot="tabs-list"`, `data-slot="tabs-trigger"`, `data-slot="tabs-indicator"`, and
`data-slot="tabs-content"`.

Useful Ark hooks include `data-scope="tabs"`, `data-part`, `data-orientation`, `data-selected`,
`data-disabled`, `data-focus`, and the indicator variables `--left`, `--top`, `--width`,
`--height`, and `--transition-property`.
