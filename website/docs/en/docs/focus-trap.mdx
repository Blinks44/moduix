## Basic

Keep the trap mounted and toggle `disabled` when the workflow starts and ends. The example sends focus to **Review details**
with `initialFocus`, keeps `isReviewing` in sync from `onDeactivate`, and restores focus to **Start review** when the trap
is released. The preview uses the React CSS Modules package and reports whether the trap is active. The source tabs show
the same behavior with native React and Solid code.

## Focus lifecycle

### Initial focus

When the trap is activated, focus moves to the first tabbable element by default. `initialFocus` accepts an element, a
selector, or a function returning one. Set it to `false` when activation must not move focus. An element with the
`autofocus` attribute is also respected.

### Empty surfaces

If the surface has no tabbable elements, provide `fallbackFocus` and give its target `tabIndex={-1}`. Activation throws
when it cannot find a tabbable element or fallback target, unless `initialFocus` is `false`.

### Restoring focus

Focus returns to the element that was active before activation by default. Set `returnFocusOnDeactivate={false}` to skip
that behavior, or use `setReturnFocus` to provide an element, a function returning one, or `false`.

`onActivate` and `onDeactivate` are lifecycle callbacks. Use them for side effects and to synchronize application state,
as in the example, not as a replacement for `disabled`.

### Portalled content and custom roots

If interactive content is rendered in a portal outside the trapped surface, pass functions returning those elements in
`persistentElements`. Keep related focusable content inside the surface whenever possible.

`FocusTrap` renders a wrapper by default. Set `asChild` to apply the behavior to one semantic child element that your
application owns.

## Limits and accessibility

`FocusTrap` manages keyboard focus only. It does not add a backdrop or portal, dialog semantics or an accessible name,
inert behavior for the rest of the page, scroll locking, or the open and close state of your surface. Use `Dialog` or
`Drawer` when their complete interaction model fits the task.

Any custom trapped surface needs a clear heading, an accessible description when needed, and a visible action that lets
the user leave the workflow. Do not trap focus in content that cannot be dismissed.
