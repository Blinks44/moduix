## API Reference

`Input` is a styled wrapper around [Ark's `Field.Input`](https://ark-ui.com/docs/components/field).
It follows Ark's guidance for [composition](https://ark-ui.com/docs/guides/composition),
[styling](https://ark-ui.com/docs/guides/styling), and [ref forwarding](https://ark-ui.com/docs/guides/ref).
It renders a native single-line `<input>` and preserves browser form behavior and React's native
event API.

Use `Field` when the control needs a label, helper or error text, generated ids, or shared state.

## Choosing the right component

- Use **`Input`** for an ordinary single-line input.
- Use **`InputGroup`** when the input needs inline content such as a prefix, suffix, or action.
- Use **`PasswordInput`** for a password field with a visibility toggle.
- Use **`NumberInput`** when you need numeric parsing and step controls.
- Use **`Textarea`** for multi-line content.
- Use **`Editable`** when text should appear as a value first and switch into edit mode on demand.

## Anatomy

```text
Field (optional wrapper)
└─ Input / Input.Root
```

| Part                   | Role                                                                  |
| ---------------------- | --------------------------------------------------------------------- |
| `Input` / `Input.Root` | Styled version of Ark's `Field.Input` that renders a native single-line `<input>`. |

`Input.Root` is an alias of `Input`; both render the same control.

## Composition

### Recommended composition

Use `Input` inside `Field` when the field needs an accessible label, helper or error text, generated
ids, or shared `disabled`, `invalid`, `required`, or `readOnly` state. `Fieldset` can disable several
nested fields at once.

Pass native `<input>` props and event handlers directly to `Input`. For a controlled input, pass
`value` and update it from `onChange(event)`; for an uncontrolled input, use `defaultValue`.

### When to go custom

Use `asChild` only when another input-compatible element must be the actual DOM node. Provide one
semantic, focusable input child. Ark merges the component and `Field` props, class, and ref into
that child.

If the control is not input-compatible, use the component that provides the appropriate Ark control
primitive instead of forcing it through `Input`.

### Default props

| Prop       | Default | Notes                                                  |
| ---------- | ------- | ------------------------------------------------------ |
| `size`     | `md`    | Visual size: `xs`, `sm`, `md`, `lg`, or `xl`.          |
| `htmlSize` | Not set | Sets the native `input[size]` value in characters. The input width follows it by default. |
| `asChild`  | `false` | When enabled, passes props into one semantic child through Ark Slot. |

### Behavioral notes

- `ref` points to the real `HTMLInputElement`, so a form library can focus the control after an invalid submission.
- No `HiddenInput` is needed because `Input` is already the native form control.
- Ark `Field` supplies `aria-describedby`, `aria-invalid`, ids, and state props.
- `Input` does not manage the value, its validity, focus, or keyboard navigation.

### Styling hooks

- `data-slot="input-root"`
- `data-size="xs" | "sm" | "md" | "lg" | "xl"`
- `data-scope="field"` and `data-part="input"`
- Ark `data-invalid`, `data-required`, and `data-readonly` inside `Field`
- native `:disabled`, `:read-only`, `:focus-visible`, and `[aria-invalid="true"]`
