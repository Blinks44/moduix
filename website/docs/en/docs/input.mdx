## API Reference

`Input` is a styled wrapper around [Ark's `FieldInput`](https://ark-ui.com/docs/components/field).
It follows Ark's guidance for [composition](https://ark-ui.com/docs/guides/composition),
[styling](https://ark-ui.com/docs/guides/styling), and [ref forwarding](https://ark-ui.com/docs/guides/ref).
It renders a native single-line `<input>` and preserves browser form behavior and each framework's
native event API.

Use `Field` when the control needs a label, helper or error text, generated ids, or shared state.

## Choosing the right component

- Use **`Input`** for an ordinary single-line input.
- Use **`InputGroup`** when the input needs inline content such as a prefix, suffix, or action.
- Use **`PasswordInput`** for a password field with a visibility toggle.
- Use **`NumberInput`** when you need numeric parsing and step controls.
- Use **`Textarea`** for multi-line content.
- Use **`Editable`** when text should appear as a value first and switch into edit mode on demand.

## Basic


Place `Input` inside `Field` when you need a label, helper text, or an error message. `Field`
connects that content to the control, generates the necessary ids, and provides its state.

## Anatomy

```text
Field (optional wrapper)
└─ Input
```

| Part                   | Role                                                                  |
| ---------------------- | --------------------------------------------------------------------- |
| `Input`                | Styled version of Ark's `FieldInput` that renders a native single-line `<input>`. |

## Composition

Use `Field` as the owner of the label, helper or error text, generated ids, and shared `disabled`,
`invalid`, `required`, or `readOnly` state. `Input` remains the native control: use `value` with
`onChange(event)` for controlled React state, `v-model` for controlled Vue state, or `defaultValue`
for an uncontrolled input. It does not manage validation, focus, or keyboard navigation.

In Vue, initialize the input through `v-model` and reset the bound state in the form's reset handler:
native reset does not emit an input event. Ark currently clears the native `defaultValue` when no
model is supplied, so use `v-model` for initial values until that upstream behavior is fixed.

For a standalone control, provide its accessible name yourself. Use `asChild` only with one
focusable, input-compatible child; Ark merges the `Input` and `Field` props, class, and ref into
that DOM node.

## Examples

### Controlled value

Use this pattern when the surrounding component owns the current value. In React, read the next
value from native `onChange(event)`; in Solid, use `onInput`; in Vue, use `v-model`. Pass the current
value back through `value` when the framework uses separate input and value bindings.

<Example name="input/controlled" />

### Disabled and read-only

Use `disabled` when the user must not interact with the control. Use `readOnly` when they can read
and select the value but must not edit it. Set them directly on `Input` for one control, or on
`Field` when the label, supporting text, and input should share the same state.

<Example name="input/disabled-and-readonly" />

### Field validation

Set `invalid` on `Field` when validation fails. Ark adds `aria-invalid` and `data-invalid` to the
input and connects it to the error text.

<Example name="input/field-state" />

### File input

`Input` is enough for a native file chooser in a simple form. Use `FileUpload` when the application
needs to keep selected files in state, show a dropzone, or manage an upload flow.

<Example name="input/file-input" />

### Native attributes

Use native attributes for browser behavior such as validation, input mode, autocomplete, and form
submission. Use `htmlSize` for a character-based width and `size` for visual density in React, Solid,
and Vue.

<Example name="input/native-attributes" />

### Sizes

The moduix `size` prop controls visual density. It is separate from `htmlSize`, which controls the
native character-based width.

<Example name="input/sizes" />

### Standalone input

`Field` is optional. When `Input` is used on its own, provide an accessible name with an HTML
`<label>`, `aria-label`, or `aria-labelledby`. Native props still work, but without `Field` context,
ids are not generated automatically and helper or error text is not connected to the control.

<Example name="input/standalone-input" />

### Advanced Customization

Use `asChild` only when another DOM node must be rendered as the input. Keep one semantic,
focusable input element that can receive the merged props and `ref`.

## Styling

`Input` inherits the `Field` context. Its `size` prop picks a visual size; pass the native numeric
`size` attribute as `htmlSize`. Inside a disabled moduix `Field` or `FieldRootProvider`, the root applies the disabled opacity once.

Use `className` in React or `class` in Solid and Vue on `Input`. Tailwind variants use native
utilities and consumer classes. CSS Modules variants build on foundation tokens and expose only the
three variables below; override colors, padding, and typography with a plain class, which wins over
the layered component styles. Use the shared data attributes and native state selectors when styling
field state.

### Styling hooks

- `data-slot="input-root"`
- `data-size="xs" | "sm" | "md" | "lg" | "xl"`
- `data-scope="field"` and `data-part="input"`
- Ark `data-invalid`, `data-required`, and `data-readonly` inside `Field`
- native `:disabled`, `:read-only`, `:focus-visible`, and `[aria-invalid="true"]`
