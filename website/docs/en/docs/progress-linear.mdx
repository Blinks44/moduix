## Choosing the right component

Use `ProgressLinear` when users need to follow progress along a bar. Use `ProgressCircular` for a
compact status indicator in a card, toolbar, or other space-constrained surface.

## Anatomy

```text
ProgressLinear / ProgressLinear.Root
├─ ProgressLinear.Label
├─ ProgressLinear.ValueText
├─ ProgressLinear.Track
│  └─ ProgressLinear.Range
└─ ProgressLinear.View

ProgressLinear.RootProvider
└─ same part tree connected to ProgressLinear.useProgress()
```

| Part                                     | Role                                                                       |
| ---------------------------------------- | -------------------------------------------------------------------------- |
| `ProgressLinear` / `ProgressLinear.Root` | Owns progress state and passes formatting, IDs, and other props to Ark.    |
| `ProgressLinear.RootProvider`             | Connects parts to the store returned by `ProgressLinear.useProgress()`.    |
| `ProgressLinear.Context`                 | Provides the current progress state to a render prop.                     |
| `ProgressLinear.Label`                   | Visible task label. It is not automatically used as `Track`'s accessible name. |
| `ProgressLinear.ValueText`                | Displays the formatted percentage and announces changes. Use `Context` for custom text. |
| `ProgressLinear.Track`                   | Progressbar surface. Ark adds the role and ARIA value attributes.         |
| `ProgressLinear.Range`                   | Filled portion that reflects the current progress.                        |
| `ProgressLinear.View`                    | Shows content only when its `state` matches the current progress state.   |

## Composition

### Recommended composition

Use `ProgressLinear` or `ProgressLinear.Root` as the root. `ProgressLinear` is a shorthand for
`ProgressLinear.Root`; the visible parts remain explicit so you can control the rendered structure.

Use `defaultValue` for uncontrolled progress. Use `value` with `onValueChange(details)` when your
application owns the current value. Set `defaultValue={null}` or `value={null}` when the task is
running but its progress is unknown.

`ProgressLinear.RootProvider` replaces the root when state is created with
`ProgressLinear.useProgress()`. Do not render `Root` together with `RootProvider`.

### When to go custom

Use `ProgressLinear.RootProvider` with `ProgressLinear.useProgress()` when a parent component or
another part of the application needs to create or control the progress state.

Use `translations.value(details)` when the generated accessible name should describe the task in
more detail. Ark uses the returned string as the generated `aria-label` on `Track`. The default
`ValueText` still displays the formatted percentage, so render `state.valueAsString` through
`ProgressLinear.Context` when the custom wording should also be visible. An explicit `aria-label` or
`aria-labelledby` on `Track` takes precedence when you need to provide the task name yourself.

Use `ids` when a custom composition needs stable, explicit IDs for the label, track, or surrounding
layout. Use `ProgressLinear.View` when supporting content should switch with the Ark progress state
instead of duplicating state checks. Use `ProgressLinear.Context` or
`ProgressLinear.useProgressContext()` when custom UI needs the current state below a root or
provider. Use direct Ark imports only for integrations that cannot use the moduix API.

### Default props

| Prop            | Default                | Notes                                             |
| --------------- | ---------------------- | ------------------------------------------------- |
| `defaultValue`  | `50`                   | Starting value for uncontrolled progress.        |
| `min`           | `0`                    | Minimum used for the percentage and ARIA values. |
| `max`           | `100`                  | Maximum used for the percentage and ARIA values. |
| `formatOptions` | `{ style: 'percent' }` | Options used to format `ValueText`.             |
| `locale`        | `'en-US'`              | Locale passed to `Intl.NumberFormat`.            |
| `orientation`   | `'horizontal'`         | Use `vertical` with a defined height.            |

### Behavioral notes

`ProgressLinear.Track` receives `role="progressbar"`, `aria-valuemin`, `aria-valuemax`, and
`aria-valuenow` from Ark. The root exposes `data-state="indeterminate|loading|complete"` and
`data-orientation`. For indeterminate progress, `aria-valuenow` is omitted.

`ProgressLinear.Label` provides visible context but does not automatically name `Track`. The track
gets a generated value-based accessible name from `translations.value(details)`, or you can provide
`aria-label` or `aria-labelledby` explicitly for a task-specific name. `ProgressLinear.ValueText`
announces changes with `aria-live="polite"`.

All rendered parts support `asChild` through Ark's polymorphic composition. Keep replacement
elements semantic and preserve the progressbar semantics on `Track`. Progress is informational, so
the component has no keyboard interaction or focus management.

Ark adds `data-orientation` to the root, label, track, and range. In RTL, determinate progress
fills from the inline start and indeterminate motion reverses.

## Styling

Use `className` on exported parts for structural styling. For state-based styles, use Ark data
attributes and moduix `data-slot` hooks.

The root has a default width of `12rem`. In vertical mode, its default height is also `12rem`. Use
the public `--moduix-progress-linear-*` variables to adapt the component to your layout.
