## Choosing the right component

Choose `ProgressLinear` when users need to see progress along a linear bar. Choose
`ProgressCircular` for a compact inline status indicator.

## Anatomy

```text
ProgressLinear.Root
├─ ProgressLinear.Label
├─ ProgressLinear.ValueText
└─ ProgressLinear.Track
   └─ ProgressLinear.Range

ProgressLinear.RootProvider
└─ same part tree connected to ProgressLinear.useProgress()
```

| Part                                     | Role                                                                 |
| ---------------------------------------- | -------------------------------------------------------------------- |
| `ProgressLinear` / `ProgressLinear.Root` | Owns progress state, formatting, and ids.                            |
| `ProgressLinear.RootProvider`            | Connects parts to state created with `ProgressLinear.useProgress()`. |
| `ProgressLinear.Context`                 | Render-prop access to the current progress state.                    |
| `ProgressLinear.Label`                   | Visible label for the progressbar.                                   |
| `ProgressLinear.ValueText`               | Visible formatted value text; use `Context` for a custom Ark value string. |
| `ProgressLinear.Track`                   | Linear rail with progressbar role and ARIA value attributes.         |
| `ProgressLinear.Range`                   | Filled range that reflects the current percent.                      |
| `ProgressLinear.View`                    | Conditional view for `indeterminate`, `loading`, or `complete`.      |

## Composition

### Recommended composition

`ProgressLinear` is the shorthand root component. It is equivalent to `ProgressLinear.Root`, and
the child parts stay explicit so the rendered anatomy matches Ark UI.

Use `defaultValue` for uncontrolled progress. For controlled progress, use `value` with
`onValueChange(details)`. For indeterminate progress, set `defaultValue={null}` or `value={null}`.

### When to go custom

Use `ProgressLinear.RootProvider` with `ProgressLinear.useProgress()` when progress state needs to
be created outside the component tree that renders it.

Use `translations.value(details)` to create a custom value string from the Ark state. To show that
string, render `state.valueAsString` inside `ValueText` through `ProgressLinear.Context`.
`translations.value(details)` changes the string available in state, but does not replace the text
rendered by a default `ValueText` on its own. Add an `aria-label` or `aria-labelledby` to `Track` to
give the progressbar a task-specific accessible name. This replaces the legacy `getAriaValueText`
and child render function pattern.

Use `ids` when a custom tree needs stable, explicit IDs for the label, track, or surrounding layout.
Use `ProgressLinear.View` when supporting UI should switch with the Ark progress state instead of
duplicating state checks outside the component. Use `ProgressLinear.Context` or
`ProgressLinear.useProgressContext()` to access state below a root or provider. Use direct Ark imports
only for integrations that intentionally sit outside the moduix API.

### Default props

| Prop            | Default                | Notes                                                  |
| --------------- | ---------------------- | ------------------------------------------------------ |
| `defaultValue`  | `50`                   | Initial uncontrolled value.                            |
| `min`           | `0`                    | Lower bound for percent and ARIA value.                |
| `max`           | `100`                  | Upper bound for percent and ARIA value.                |
| `formatOptions` | `{ style: 'percent' }` | Controls `ValueText` formatting.                       |
| `locale`        | `'en-US'`              | Locale used by `Intl.NumberFormat`.                    |
| `orientation`   | `'horizontal'`         | Ark orientation. Use `vertical` with a defined height. |

### Behavioral notes

`ProgressLinear.Track` receives the progressbar role and ARIA value attributes from Ark. The root
stores progress state and exposes `data-state="indeterminate|loading|complete"`. Ark writes
`data-orientation` on the root, label, track, and range so horizontal and vertical styles can share
the same part tree.

All exported parts support `asChild` through Ark's polymorphic composition. When you replace a
rendered element, keep it semantic and preserve the progressbar semantics on the track.

`ProgressLinear.ValueText` announces changes with `aria-live="polite"`. `ProgressLinear.Label`
provides visible text, while `ProgressLinear.Track` needs its own `aria-label` or `aria-labelledby`
for a task-specific accessible name. In RTL, the determinate range fills from the inline start and
indeterminate motion reverses.
