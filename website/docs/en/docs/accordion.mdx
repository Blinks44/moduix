## Choosing the right component

Use `Accordion` when several related sections should share keyboard navigation and state. Use
`Collapsible` when you need one independent disclosure.

## Basic

Use `Accordion` as the root and give every `Accordion.Item` a stable `value`. Put the interactive
label in `Accordion.ItemTrigger`, the panel in `Accordion.ItemContent`, and the panel's inner
content in `Accordion.ItemBody`. `Accordion.ItemIndicator` is optional and defaults to the moduix
plus icon.

Use `Accordion` as the root in most cases. `Accordion.Root` is an alias for the same root when you
want to make that part explicit in your composition.

## Anatomy

```text
Accordion / Accordion.Root
└─ Accordion.Item[value]
 ├─ Accordion.ItemTrigger
 │  ├─ label
 │  └─ Accordion.ItemIndicator (optional)
 └─ Accordion.ItemContent
    └─ Accordion.ItemBody
       └─ content

Accordion.RootProvider
└─ same item tree connected to a useAccordion() store
```

| Part                           | Role                                                                                         |
| ------------------------------ | -------------------------------------------------------------------------------------------- |
| `Accordion` / `Accordion.Root` | Root part that owns accordion state and keyboard navigation.                                 |
| `Accordion.RootProvider`       | Connects the parts to state created with `useAccordion()`.                                   |
| `Accordion.Item`               | A collapsible item with a required, stable `value`.                                           |
| `Accordion.ItemTrigger`        | The button that opens or closes the item.                                                     |
| `Accordion.ItemIndicator`      | Optional state indicator. Defaults to the moduix plus icon when no children are provided.     |
| `Accordion.ItemContent`        | The collapsible panel, with Ark's size-animation behavior.                                   |
| `Accordion.ItemBody`           | The moduix inner wrapper that provides default panel spacing.                                |

## Composition

### Recommended composition

`Accordion` owns item state and keyboard navigation. Start with `Accordion`, `Accordion.Item`,
`Accordion.ItemTrigger`, `Accordion.ItemContent`, and `Accordion.ItemBody`. Add
`Accordion.ItemIndicator` when a visual state cue is useful.

Root props include `defaultValue`, `value`, `onValueChange(details)`, `onFocusChange(details)`,
`multiple`, `collapsible`, `disabled`, `orientation`, `lazyMount`, `unmountOnExit`, `hideMode`, and
`ids`.

Use `defaultValue` for an uncontrolled accordion. Use `value` with `onValueChange(details)` when
another part of the application owns the state. Both props use `string[]`, even when only one item
can be open.

### When to go custom

Use a custom composition when state needs to live outside the rendered tree, another part of the UI
needs to read or update it, or you need a different semantic host for a part.

Use `Accordion.RootProvider` with `useAccordion()` from `@moduix/react` when the accordion state
must be created outside the rendered tree. Pass the value returned by `useAccordion()` to
`RootProvider`, and do not render `Accordion` or `Accordion.Root` for the same store.

Use `Accordion.Context`, `Accordion.ItemContext`, `useAccordionContext()`, and
`useAccordionItemContext()` from moduix when surrounding UI needs root or item state. Item state
includes Ark's `expanded`, `focused`, and `disabled` booleans.

Set `disabled` on the root to disable every item. Set it on an `Accordion.Item` to disable only that
item while keeping it visible.

`Accordion.Item` requires a stable `value`. `Accordion.ItemIndicator` is optional: when it has no
children, moduix renders `PlusIcon`, and you can replace the indicator content entirely when needed.

Use `asChild` only when another element must own the rendered DOM node. Keep the Ark part tree
explicit instead of hiding it behind convenience wrappers.

### Default props

| Prop                   | Default        | Notes                                                                                 |
| ---------------------- | -------------- | ------------------------------------------------------------------------------------- |
| `collapsible`          | `false`        | The open item cannot close unless another item opens.                                |
| `disabled`             | `false`        | The root or item remains visible but cannot be interacted with.                      |
| `hideMode`             | `display-none` | Controls how mounted, closed content is hidden. `activity` requires React 19.        |
| `lazyMount`            | `false`        | Mounts all item content during the initial render.                                    |
| `multiple`             | `false`        | Allows only one item to be open at a time.                                            |
| `orientation`          | `vertical`     | Uses vertical layout and keyboard navigation.                                        |
| `unmountOnExit`        | `false`        | Keeps content mounted after it closes.                                               |
| `value`/`defaultValue` | not set        | The controlled or initial open values. Always use a `string[]`.                       |

### Behavioral notes

Put spacing on `Accordion.ItemBody`, not on `Accordion.ItemContent`, so Ark can measure the panel
reliably. Ark exposes `--height` for vertical content animation and `--width` for horizontal content
animation.

Each trigger is a native button. Ark links it to its panel with `aria-expanded` and `aria-controls`,
and gives the panel a matching `aria-labelledby`. `Enter` or `Space` opens a closed item and, when
`collapsible` is enabled, closes the open item. In vertical orientation, `ArrowDown` and `ArrowUp`
move between triggers. In horizontal orientation, use `ArrowRight` and `ArrowLeft`. `Home` and `End`
move focus to the first and last trigger.

Every styled part forwards its ref and supports `asChild` when another semantic element should own the
rendered node. A custom trigger must remain keyboard-focusable and behave like a button.

When `lazyMount` is enabled, closed content is mounted only after its first opening. Add
`unmountOnExit` to remove it from the DOM after it closes. `hideMode="activity"` keeps mounted content
in React 19's hidden Activity state and pauses its effects.

When the user prefers reduced motion, Accordion removes trigger and indicator transitions and reduces
panel motion to an effectively instant animation while preserving Ark's lifecycle.

## Styling

Use `className` on exported parts for structural styles. For state-based styles, prefer Ark data
attributes such as `data-state`, `data-disabled`, and `data-orientation`, together with moduix
`data-slot` selectors.

### CSS Properties

<CssPropertiesSection properties={AccordionDocs.accordionOverrideCssProperties} />

### Styling hooks

- Stable `data-slot` selectors: `accordion-root`, `accordion-root-provider`, `accordion-item`,
  `accordion-item-trigger`, `accordion-item-indicator`, `accordion-item-content`, and
  `accordion-item-body`.
- Ark part selectors: `data-scope="accordion"` and
  `data-part="root|item|item-trigger|item-indicator|item-content"`.
- moduix-specific selector: `data-part="item-body"` on `Accordion.ItemBody`.
- Ark state selectors: `data-state="open|closed"`, `data-disabled`, `data-focus`, `data-controls`,
  and `data-orientation="horizontal|vertical"`.
- Ark content variables: `--height` for vertical animation and `--width` for horizontal animation.
