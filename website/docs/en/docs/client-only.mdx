## When to use `ClientOnly`

Use `ClientOnly` for a part of the interface that needs the DOM or browser APIs that are unavailable on the server,
such as `window`, `navigator`, storage, layout measurements, or a browser-only library. During server rendering,
it shows the `fallback`; after hydration, it renders its children instead.

`ClientOnly` is provided by Ark UI. moduix does not wrap or re-export it, so import it directly:

```tsx
import { ClientOnly } from '@ark-ui/react/client-only';
```

If Ark UI is not already a dependency of your application, install it with:

```bash
pnpm add @ark-ui/react
```

## Basic

Keep browser-dependent code in the child rendered by `ClientOnly`. Make the fallback resemble the final moduix UI,
including its approximate height. This gives the server useful content to render and prevents the layout from
shifting when the client takes over.

## Choose a fallback

The `fallback` is the content users see while the page is rendered on the server and until hydration finishes. Use a
`Skeleton`, a static version of the content, or another useful placeholder with roughly the same dimensions as the
client-only content. Include all important rows and controls so the final UI does not change size abruptly. Do not
read browser globals while creating the fallback.

## Keep browser APIs on the client

`ClientOnly` controls when a subtree is rendered; it does not turn an SSR component or module into a client-only
module. Read `window`, `document`, `navigator`, `localStorage`, and layout measurements only in the child rendered
by `ClientOnly`, or in an effect or event handler. Do not move those reads into the parent that creates the
`ClientOnly` boundary, because that parent still renders on the server.

## Use it with moduix

Use moduix components inside the client-only subtree as usual. In the example, `Card` displays values read from the
browser, while `Skeleton` provides a fallback with the same structure. If a moduix component already supports the
server-safe behavior you need, use its documented API instead of adding a separate `ClientOnly` boundary.

## Ownership and scope

Ark UI owns `ClientOnly`, including its hydration behavior and `fallback` prop. moduix documents how to combine it
with moduix components, but does not style the utility or include it in the moduix exports.
