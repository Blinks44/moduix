# Formisch

[Formisch](https://formisch.dev) is a schema-first form library with native framework adapters.
This guide focuses on connecting its Valibot-backed field state to moduix controls.

## Framework support

## Connect controls

Alias Formisch `Field` so it remains distinct from moduix `Field`. The Formisch component connects a
schema path to field state; the moduix component renders the label, error message, and accessible
state.

| Control             | Mapping                                                               |
| ------------------- | --------------------------------------------------------------------- |
| `Input`, `Textarea` | Spread `field.props` and pass the current `field.input`.              |
| `Select`            | Map the scalar input to Ark's string-array `value`.                   |
| `Combobox`          | Map the selected value, keep filtering separate, and forward focus.   |
| `Checkbox`          | Map `details.checked === true` to the boolean input.                  |

Pass `field.props.name` to the moduix root. Keep `HiddenSelect` or `HiddenInput` inside the component
composition, but do not add another registered input for the same value.

## Validation and reset

Pass the Valibot schema directly to `useForm` or `createForm`. Use `validate` for the first validation
point and `revalidate` for later edits. The complete example validates on submit and then revalidates
on input.

Pass `field.errors !== null` to `Field invalid` and render the first message with
`FieldErrorText`. Call Formisch `reset(form)` for controlled values; a DOM reset alone cannot replace
the field store.

## Repeated fields and server errors

Use Formisch `FieldArray` with `insert`, `remove`, and the stable IDs from `fieldArray.items`. The
array index belongs in the schema path, while the stable ID belongs in the framework's keyed render.
Wrap a related list in `Fieldset` and keep each row's message on its own `Field`.

After a failed request, call `setErrors` with a `path` for a field error or without a path for a
form-level error. Keep the current input so the user can correct and resubmit it.

## Focus and behavior

- Forward `field.props.ref`, `onFocus`, and `onBlur` to the element users actually focus.
- In React, use `field.onChange` for compound values. In Solid, use `field.onInput`. In Vue, update
  `field.input` from the component's value-change details, or use `v-model` for native-value controls. In Svelte, call `field.onInput` from the value-change details.
- Keep the current value controlled so `initialInput`, `setInput`, and `reset` update the UI.
- Do not pass an Ark details object to a native event handler from `field.props`.
