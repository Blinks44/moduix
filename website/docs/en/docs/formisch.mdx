# Formisch

[Formisch](https://formisch.dev) and [Valibot](https://valibot.dev) document the complete schema,
store, and validation APIs. This page focuses on connecting the stable v1 release of Formisch to
moduix controls.

Formisch is schema-first: pass a Valibot schema to `useForm`, then render each field with Formisch's
headless `Field` component. Spread `field.props` onto native controls. For a compound control whose
value is managed by its root, pass `field.input` to the control and send its value callback to
`field.onChange`.

```bash
npm install @formisch/react valibot
```

## Connect fields to moduix

Both Formisch and moduix export a component named `Field`. Alias the Formisch import so the two
roles are clear in the same file:

- Formisch `Field` connects a path in the schema to a field store.
- moduix `Field` renders the label, error message, and field-level accessibility state.

`field.props` contains the name, ref, and lifecycle handlers for a native field. `field.input` is
the current value, `field.errors` is either `null` or an array of messages, and `field.onChange`
updates the value for custom controls.

| Control | Formisch wiring |
| --- | --- |
| `Input`, `Textarea` | Spread `field.props` and pass `value={field.input ?? ''}`. |
| `Select` | Pass `name={field.props.name}`, control the string-array `value`, and map `onValueChange` to `field.onChange`. moduix renders the native select for you. |
| `Combobox` | Pass `name={field.props.name}`, control the selected `value`, and map `onValueChange` to `field.onChange`. Pass the lifecycle props to `Combobox.Input`. |
| `Checkbox` | Pass `name={field.props.name}`, control `checked`, and map `onCheckedChange` to `field.onChange`. moduix renders the native input for you. |

Do not add another hidden input for `Select` or `Checkbox`. Their moduix roots already render the
native form control required for submission and reset. `Combobox` keeps its form name on the root.

## Validation and reset

Pass the Valibot schema directly to `useForm`; Formisch v1 does not need a resolver. By default,
the first validation runs on submit and later validation runs on input after the first validation.
Use `validate: 'blur'`, `validate: 'input'`, or `validate: 'initial'` when the form needs a different
first validation point. Set `revalidate` to change when Formisch checks a field again.

The `Form` component prevents the browser's default submit, sets `noValidate`, and calls `onSubmit`
only after the current input passes the schema. An asynchronous handler sets `form.isSubmitting` to
`true`, which is useful for preventing duplicate requests and showing progress in the submit button.

Required string fields start as `''` when they have no `initialInput`. Use `initialInput` for loaded
data or whenever you want to define the initial value explicitly. A controlled field must receive
its value from `field.input`, otherwise a later `reset` or `setInput` call cannot update what the
user sees.

`field.errors` contains the messages for one field. Pass its presence to `Field invalid` and render
the first message with `Field.ErrorText`, as in the example below. To restore the current values to
their initial values, call Formisch's `reset` method instead of resetting only the DOM form:

```tsx
import { reset } from '@formisch/react';

reset(form);
reset(form, { initialInput: { name: '', team: '' } });
```

## Repeated fields

Use `FieldArray` for a list of fields that users can add or remove. Its `items` array contains
stable IDs for React keys. Keep the array index in the Formisch path, but never use that index as
the React key. Put array-level validation on `fieldArray.errors`; use a `Fieldset` when the list
needs a shared legend or group-level error.

The following example is complete: it creates the form, renders the array inside `Form`, and uses
the v1 `insert` and `remove` methods.

```tsx
import { Field as FormischField, FieldArray, Form, insert, remove, useForm } from '@formisch/react';
import { Button } from '@moduix/react/button';
import { Fieldset } from '@moduix/react/fieldset';
import { Field } from '@moduix/react/field';
import { Input } from '@moduix/react/input';
import * as v from 'valibot';

const formSchema = v.object({
  emails: v.pipe(
    v.array(
      v.object({
        address: v.pipe(v.string(), v.email('Enter a valid email address.')),
      }),
    ),
    v.minLength(1, 'Add at least one email address.'),
  ),
});

export default function EmailForm() {
  const form = useForm({
    schema: formSchema,
    initialInput: { emails: [{ address: '' }] },
  });

  return (
    <Form of={form} onSubmit={(values) => console.log(values)}>
      <FieldArray of={form} path={['emails']}>
        {(fieldArray) => (
          <Fieldset invalid={fieldArray.errors !== null}>
            <Fieldset.Legend>Email addresses</Fieldset.Legend>

            {fieldArray.items.map((item, index) => (
              <FormischField key={item} of={form} path={['emails', index, 'address']}>
                {(field) => (
                  <Field invalid={field.errors !== null}>
                    <Field.Label>Email {index + 1}</Field.Label>
                    <Input type="email" {...field.props} value={field.input ?? ''} />
                    <Field.ErrorText>{field.errors?.[0]}</Field.ErrorText>
                    <Button
                      type="button"
                      onClick={() => remove(form, { path: ['emails'], at: index })}
                    >
                      Remove email
                    </Button>
                  </Field>
                )}
              </FormischField>
            ))}

            <Fieldset.ErrorText>{fieldArray.errors?.[0]}</Fieldset.ErrorText>
            <Button
              type="button"
              onClick={() => insert(form, { path: ['emails'], initialInput: { address: '' } })}
            >
              Add email
            </Button>
          </Fieldset>
        )}
      </FieldArray>
    </Form>
  );
}
```

## Server errors

Schema validation handles errors that can be checked in the browser. If the server rejects a
request, call `setErrors` after the request. Give it a `path` for a field-specific message and omit
the path for a form-level message. Clear errors from the previous request before trying again.

`form.errors` contains only form-level errors. Field errors remain on the corresponding
`field.errors`, so render both kinds in their natural place and keep the user's input intact.

```tsx
import { Form, setErrors } from '@formisch/react';

<Form
  of={form}
  onSubmit={async (values) => {
    setErrors(form, { path: ['name'], errors: null });
    setErrors(form, { errors: null });

    const result = await createProject(values);

    if (result.nameError) {
      setErrors(form, { path: ['name'], errors: [result.nameError] });
    }

    if (result.message) {
      setErrors(form, { errors: [result.message] });
    }
  }}
>
  {form.errors ? <p role="alert">{form.errors[0]}</p> : null}
  {/* Fields */}
</Form>;
```

## Behavior and focus

- Spread `field.props` onto `Input` and `Textarea`, then pass `value={field.input ?? ''}` so
  `initialInput`, `setInput`, and `reset` update the visible control.
- Use `field.onChange` for a component that owns its value. Do not send a component's details
  object to the native `field.props.onChange` handler: that handler expects a DOM event and reads
  a string from the element.
- Keep `name`, `form`, and component-specific form options on the moduix root. The root owns the
  native form control for `Select` and `Checkbox`, and `Combobox` uses the root name for submission.
- For `Combobox`, pass `field.props.ref`, `field.props.onFocus`, and `field.props.onBlur` to
  `Combobox.Input`, the element the user actually focuses.
- The moduix `Select` and `Checkbox` wrappers keep their native parts internal. Do not cast
  `field.props.ref` onto their roots. If either control can be the first invalid control and the
  application needs custom invalid-submit focus, keep a ref to its visible trigger or control and
  focus that element in the application's submit flow.
