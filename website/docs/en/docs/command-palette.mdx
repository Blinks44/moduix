Use `CommandPalettePanel` for the standard dialog layout. It renders the backdrop, positioner, and
content for you. Add `CommandPaletteCombobox` inside it, pass a collection, and render the filtered
items in `CommandPaletteList`. `CommandPaletteSearch` adds a search icon, the input, and a clear button that
appears once the user enters a query.

## Composition

Ark UI does not provide a dedicated `command-palette` primitive. `CommandPalette` combines Ark
[`Dialog`](https://ark-ui.com/docs/components/dialog) and
[`Combobox`](https://ark-ui.com/docs/components/combobox), then adds a standard palette shell and
search row. The wrapper follows Ark's guidance for [composition](https://ark-ui.com/docs/guides/composition),
[styling](https://ark-ui.com/docs/guides/styling), and [refs](https://ark-ui.com/docs/guides/ref).

The root manages Dialog state and automatically portals `CommandPaletteBackdrop` and `CommandPalettePositioner`. Set `portalled={false}`
to render them inline, or pass `portalRef` for a custom container. Use `CommandPalettePanel` and `CommandPaletteSearch` for the usual
layout, and render the structural parts directly when the dialog or search controls need a different shape.

Keep collection filtering with the `CommandPaletteCombobox` that renders the list: configure `useListCollection` with `itemToString`,
`itemToValue`, and `groupBy`, then call `filter(details.inputValue)` from `onInputValueChange`. Reset the
filter on close when the collection is managed outside the palette. Use `closeOnSelect={false}` to keep the
palette open after an action, or `CommandPaletteRootProvider` with `useDialog` from the matching framework package when
dialog state must be created outside the rendered tree.

## Styling

Each part ships with defaults built from foundation tokens. Override them with a class on the part,
for example on `CommandPalettePanel` or `CommandPaletteItem`. Two variables cover the values that a
class cannot replace on its own because the viewport also caps them. Backdrops follow the shared
`--moduix-backdrop-bg` and `--moduix-backdrop-filter` tokens, and content motion follows the shared
`--moduix-popup-motion-*` tokens. `CommandPaletteList` remains scrollable, but it does not render a
visible scrollbar track.

- `CommandPaletteList` renders a `ScrollArea`, so the scroll parts keep the `scroll-area-root`, `scroll-area-viewport`, and `scroll-area-content` hooks; target them under `[data-slot='command-palette-list']`.
- Ark Dialog state hooks include `data-scope="dialog"`, `data-part`, and `data-state="open" | "closed"` on dialog parts such as the trigger, backdrop, and content.
- Ark Combobox state hooks include `data-scope="combobox"`, `data-part`, `data-state`, `data-highlighted`, `data-disabled`, `data-invalid`, and `data-empty` where applicable.
- Motion is tied to Ark `data-state`. Legacy `data-starting-style`, `data-ending-style`, and `data-open` attributes are not part of the command-palette contract.

## Keyboard

| Key | Action |
| --- | --- |
| `shortcut` | Opens or closes the palette when the prop is set, for example `mod+k`. |
| `ArrowDown` / `ArrowUp` | Highlights the next or previous command. |
| `Home` / `End` | Highlights the first or last command. |
| `Enter` | Runs the highlighted command. |
| `Esc` | Closes the palette. |

## API reference

Props of `CommandPalette`. It also takes the dialog props `open`, `defaultOpen`, and `onOpenChange`; search props such as `collection` and `onInputValueChange` go on `CommandPaletteCombobox`.

| Prop | Type | Default |
| --- | --- | --- |
| `shortcut` | `false \| string` | `false` |
| `open` | `boolean` | — |
| `defaultOpen` | `boolean` | `false` |
| `onOpenChange` | `(details: OpenChangeDetails) => void` | — |
| `lazyMount` | `boolean` | `true` |
| `unmountOnExit` | `boolean` | `true` |
| `portalled` | `boolean` | `true` |
