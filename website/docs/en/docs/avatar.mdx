## Basic


Use `Avatar`, `AvatarFallback`, and `AvatarImage` together. Keep `AvatarFallback` in the tree so
Ark UI can switch between the fallback and the image as the loading state changes.

React, Solid, and Vue use the same flat value names. Import `Avatar` as the root and import each
additional part directly, such as `AvatarImage` and `AvatarFallback`. The same names work with npm
packages and shadcn registry source.

## Anatomy

```text
Avatar
├─ AvatarFallback
└─ AvatarImage

AvatarRootProvider
└─ same parts connected to a useAvatar() store
```

| Part                | Role                                                               |
| ------------------- | ------------------------------------------------------------------ |
| `Avatar`            | Creates and owns the Ark UI avatar state.                          |
| `AvatarRootProvider` | Renders an avatar from Ark UI state created outside the component. |
| `AvatarFallback`    | Shows consumer-provided content until the image loads.             |
| `AvatarImage`       | Shows the image after it loads successfully.                       |

## Composition

Keep `AvatarFallback` and `AvatarImage` under the same root so Ark can switch their visibility.
When another part of the application owns the state, create it with `useAvatar()` from the matching
framework package and pass it directly to `AvatarRootProvider`; do not render another root for the
same store. React receives the store as an object, while Solid receives a reactive accessor. In Vue,
pass the return value from `useAvatar()` directly to `AvatarRootProvider`. For custom image
renderers, React and Solid can use `useAvatarContext()` and preserve the hidden and visible states
from `getImageProps()`. In Vue, use the `AvatarContext` scoped slot to read the same state. Use
`asChild` with one semantic child when another element must own the root DOM node.

In Solid, assign a ref to the element created inside the `asChild` render function. A ref on `Avatar`
itself is not forwarded through that composition path. Vue refs point to the component instance; use
`$el` to access its rendered host.

## Styling

Use `className` in React or `class` in Solid and Vue on exported parts for structural styles. Tailwind
variants use native utility classes and consumer classes; the CSS Variables reference below applies
to CSS Modules variants. For state-based styles, prefer Ark data attributes together with moduix
`data-slot` selectors.

### CSS Properties

<CssPropertiesSection properties={AvatarDocs.avatarCssProperties} />

### Styling hooks

- `data-slot="avatar-root"`, `avatar-root-provider`, `avatar-image`, and `avatar-fallback`.
- Ark anatomy hooks: `data-scope="avatar"` and
  `data-part="root" | "image" | "fallback"`.
- Ark image state: `data-state="visible" | "hidden"` on `AvatarImage` and
  `AvatarFallback`.
- moduix size state: `data-size="xs" | "sm" | "md" | "lg" | "xl"` on
  `Avatar` and `AvatarRootProvider` when `size` is provided.
