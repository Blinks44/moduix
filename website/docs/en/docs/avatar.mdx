## Anatomy

```text
Avatar.Root | Avatar.RootProvider
├─ Avatar.Fallback
└─ Avatar.Image
```

| Part                     | Role                                                              |
| ------------------------ | ----------------------------------------------------------------- |
| `Avatar` / `Avatar.Root` | Creates and owns the Ark UI avatar state.                         |
| `Avatar.RootProvider`    | Renders an avatar from Ark UI state created outside the component. |
| `Avatar.Fallback`        | Shows initials, an icon, or custom content until the image loads. |
| `Avatar.Image`           | Shows the image after it loads successfully.                     |

## Composition

### Recommended composition

Use `Avatar` for the usual case. `Avatar.Root` remains available when you want the explicit,
Ark-aligned namespace. `onStatusChange(details)` reports the loading state managed by Ark, while
`ids` provides stable IDs for the root, image, and fallback. All DOM parts forward their refs and
support Ark `asChild`.

`Avatar.Image` renders an `img`, so provide meaningful `alt` text when the image conveys identity.
Use `alt=""` when the surrounding link or button already has the accessible name.

`Avatar.Fallback name="Alex T."` uses the first grapheme of the first and last words in the common
case, so initials stay intact for international names and emoji. Pass children when you need custom
fallback content; explicit children take precedence over `name`.

### When to go custom

Use `useAvatar` from `@moduix/react` with `Avatar.RootProvider` when you need to create state
outside the rendered avatar. Do not wrap the same `RootProvider` state instance in `Avatar.Root`.

For framework image components, use `useAvatarContext()` from `@moduix/react` and preserve Ark's
hidden and visible states. Keep the less common Ark-only context APIs and type aliases on
`@ark-ui/react/avatar`.

Use `asChild` with one semantic child when a link, button, or framework component must own a part's
DOM node.

### Default props

| Component                                       | Prop   | Visual default | Values                       |
| ----------------------------------------------- | ------ | -------------- | ---------------------------- |
| `Avatar` / `Avatar.Root`, `Avatar.RootProvider` | `size` | `md`           | `xs`, `sm`, `md`, `lg`, `xl` |

When `size` is omitted, Avatar uses the `md` visual tokens without setting `data-size`. Pass
`size="md"` when your selectors need that attribute.

### Behavioral notes

- Ark controls `data-state="visible" | "hidden"` on `Avatar.Image` and `Avatar.Fallback`.
- `Avatar.Fallback` derives grapheme-safe initials from the first and last words of `name` only when
  no children are provided.
- `Avatar.Fallback` renders a decorative User icon when neither children nor usable `name` initials
  are available.
- `onStatusChange` receives a detail object; read the current value from `details.status`.
- A missing or failed image keeps the fallback visible.
- `Avatar.RootProvider` requires the `value` returned by `useAvatar`.
- `useAvatar` and `useAvatarContext` are available from `@moduix/react`.
- `Avatar.Context` is available from `@moduix/react`; Ark type aliases stay on `@ark-ui/react/avatar`.
- moduix adds only visual defaults, stable `data-slot` hooks, CSS variables, and `size`.

## Styling

Use `className` and moduix CSS variables for visual changes. Use Ark data attributes when styles
depend on image state.

### CSS Properties

<CssPropertiesSection properties={AvatarDocs.avatarCssProperties} />

### Styling hooks

- `data-slot="avatar-root"`, `avatar-root-provider`, `avatar-image`, `avatar-fallback`, and
  `avatar-fallback-icon`.
- Ark anatomy hooks: `data-scope="avatar"` and
  `data-part="root" | "image" | "fallback"`.
- Ark image state: `data-state="visible" | "hidden"` on `Avatar.Image` and
  `Avatar.Fallback`.
- moduix size state: `data-size="xs" | "sm" | "md" | "lg" | "xl"` on
  `Avatar.Root` and `Avatar.RootProvider` when `size` is provided.
