## API Reference

Ark UI does not provide a dedicated table primitive. moduix builds `Table` with the official
[Ark factory](https://ark-ui.com/docs/guides/composition#the-ark-factory), follows Ark's
[composition](https://ark-ui.com/docs/guides/composition), [styling](https://ark-ui.com/docs/guides/styling), and
[ref](https://ark-ui.com/docs/guides/ref) guidance.

Each part renders its corresponding native HTML element by default, accepts native element props and
`className`, forwards its ref, and supports Ark's `asChild`. When using `asChild`, pass one semantic
element as the child. `Table.Empty` is the exception to the usual one-element composition: its
`asChild` replaces only the generated `td`.

## Basic

If the table may be wider than its container, wrap it in `Table.ScrollArea`. Then compose `Table`
with `Table.Header`, `Table.Body`, `Table.Row`, and the matching header and cell parts. This is the
recommended setup for invoices, summaries, and admin-style read-only datasets.

## Anatomy

The normal consumer path stays close to native table markup:

```text
Table.ScrollArea (optional)
└─ Table / Table.Root
   ├─ Table.ColumnGroup (optional)
   │  └─ Table.Column
   ├─ Table.Caption (optional)
   ├─ Table.Header
   │  └─ Table.Row
   │     └─ Table.ColumnHeader
   ├─ Table.Body
   │  ├─ Table.Row
   │  │  └─ Table.Cell
   │  └─ Table.Empty (optional)
   └─ Table.Footer (optional)
```

| Part                   | Role                                                                       |
| ---------------------- | -------------------------------------------------------------------------- |
| `Table` / `Table.Root` | Native `table` root. Owns typography, dividers, and state attributes.      |
| `Table.ScrollArea`     | Optional bordered container with horizontal overflow for the table.       |
| `Table.ColumnGroup`    | Native `colgroup` wrapper for column width distribution.                   |
| `Table.Column`         | Native `col` wrapper. Supports `htmlWidth`.                                |
| `Table.Caption`        | Optional table caption above or below the table via `side`.                |
| `Table.Header`         | Native `thead` wrapper for column headers.                                 |
| `Table.Body`           | Native `tbody` wrapper for body rows.                                      |
| `Table.Footer`         | Native `tfoot` wrapper for summary rows.                                   |
| `Table.Row`            | Native `tr` wrapper with divider behavior.                                 |
| `Table.ColumnHeader`   | Native `th` wrapper. Supports `numeric`.                                   |
| `Table.Cell`           | Native `td` wrapper. Supports `numeric`.                                   |
| `Table.Empty`          | Convenience empty-state row and cell inside `Table.Body`.                 |

## Composition

### Recommended composition

For most read-only data views, use the semantic table parts and add `Table.ScrollArea` when the
table needs a bordered horizontal-scroll container.

Use `numeric` on `Table.ColumnHeader` and `Table.Cell` for amounts, counts, percentages, and latency
columns. Use `Table.Caption` for a short title or description, and `Table.Footer` when the last row
contains totals or rollups. Use `striped`, `interactive`, `showColumnBorder`, `stickyHeader`, and
`size` / `variant` for visual variations without adding table state.

### When to go custom

Skip `Table.ScrollArea` when the parent layout already owns scrolling, padding, borders, or surface
styling. Keep `Table` itself and move the container concerns into your own layout component or
wrapper markup.

`Table` does not manage sorting, filtering, selection, pagination, virtualization, or row action
state. Treat it as the visual and semantic primitive that higher-level table abstractions can build
on. For TanStack Table state and rendering, follow the [Data Table](/recipes/data-table) composition
guide.

### Default props

All parts accept their matching native element props. They also support `className`, forwarded refs,
and `asChild` as described above.

| Component            | Prop               | Default         | Notes                                                      |
| -------------------- | ------------------ | --------------- | ---------------------------------------------------------- |
| `Table`              | `interactive`      | `false`         | Enables body-row hover highlighting.                       |
| `Table`              | `showColumnBorder` | `false`         | Adds borders between visible columns.                      |
| `Table`              | `size`             | `'md'`          | Supports `'sm'`, `'md'`, and `'lg'`.                       |
| `Table`              | `stickyHeader`     | `false`         | Makes `Table.Header` sticky inside a scroll container.     |
| `Table`              | `striped`          | `false`         | Zebra-stripes even body rows, excluding empty rows.        |
| `Table`              | `variant`          | `'line'`        | Supports `'line'` and `'outline'`.                         |
| `Table.Caption`      | `side`             | `'bottom'`      | Supports `'top'` and `'bottom'`.                           |
| `Table.Column`       | `htmlWidth`        | -               | Maps to the native `width` attribute on `col`.             |
| `Table.ColumnHeader` | `numeric`          | `false`         | Aligns content to the inline end and uses tabular nums.    |
| `Table.Cell`         | `numeric`          | `false`         | Aligns content to the inline end and uses tabular nums.    |
| `Table.Empty`        | `colSpan`          | required        | Must match the current body column count.                  |
| `Table.Empty`        | `children`         | `'No results.'` | Text shown when no children are provided.                  |

### Behavioral notes

- `Table.Empty` renders a full table row for the empty state, so pass the body column count through
  `colSpan`. Its `asChild` replaces only the generated cell, so pass one semantic `td`; compose
  `Table.Row` and `Table.Cell` directly when the row itself needs customization. The generated row
  exposes `data-empty` and does not receive striped or interactive styles.
- Header and body rows render a shared bottom divider. The last body row drops its border.
- With `interactive`, body rows get a subtle hover background and retain that context when a
  contained control receives keyboard focus.
- `Table.Caption` inherits muted typography and adds inline padding so it does not sit flush against
  the table edges.

### Accessibility

`Table` uses native table elements, so use standard HTML table attributes for the relationships in
your data. Add `scope="col"` to column headers, use `Table.Caption` for a short accessible name or
description, and use `id` / `headers` when a complex table needs explicit header associations.
`Table` does not add keyboard navigation, selection behavior, or focus management.

### Styling hooks

Use the part that owns the visual concern:

- `className` on `Table.ScrollArea` for shell-wide border, radius, and surface overrides
- `className` on `Table` for table typography and width constraints
- `data-slot="table-root"`, `table-scroll-area`, `table-column-group`, `table-column`,
  `table-caption`, `table-header`, `table-body`, `table-footer`, `table-row`,
  `table-column-header`, `table-cell`, and `table-empty` for part-level targeting
- `data-side="top" | "bottom"` on `Table.Caption` for caption placement styling
- `data-numeric` on `Table.ColumnHeader` and `Table.Cell` for numeric-column targeting
- `data-empty` on the row generated by `Table.Empty` for empty-row targeting
- `data-size`, `data-variant`, `data-striped`, `data-interactive`, `data-sticky-header`, and
  `data-show-column-border` on `Table` for root-level state styling
- `data-sticky="start" | "end"` on `Table.ColumnHeader` and `Table.Cell` for sticky columns
