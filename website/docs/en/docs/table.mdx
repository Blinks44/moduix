If the table may be wider than its container, wrap it in `TableScrollArea`. Then compose `Table`
with `TableHeader`, `TableBody`, `TableRow`, and the matching header and cell parts. This is the
recommended setup for invoices, summaries, and admin-style read-only datasets.

## Examples

### Sizes

Use `size` for density. It changes cell padding and font size. For an outer border without
`TableScrollArea`, add a border class to `Table`.

Use `TableColumnGroup` and `TableColumn` for native column widths, and `showColumnBorder` when

### Sticky header and column

Use `stickyHeader` on the root and `data-sticky="start" | "end"` on cells when a horizontally or

focus row colors.

Use the last column for row-specific actions when the dataset needs lightweight overflow commands.
`Menu` fits this case cleanly without changing the native table structure.

Use `TableEmpty` when a body would otherwise render no rows. Set `colSpan` to the current number of

### Inside Card

`TableScrollArea` fits naturally inside `CardBody` when the table should live on a card surface.

### With ScrollArea

Use `ScrollArea` directly when the table needs styled scrollbars on both axes, fade behavior, or the

Use your own wrapper instead of `TableScrollArea` when the surrounding layout already handles the

## Composition

Each part renders its corresponding native HTML element by default, accepts native element props and
`className` in React or `class` in Solid and Vue, forwards its ref, and supports Ark's `asChild`. When using
`asChild`, pass one semantic element as the child. `TableEmpty` is the exception to the usual
one-element composition: its `asChild` replaces only the generated `td`.

Use `TableScrollArea` when the table needs a bordered horizontal-scroll shell. Skip it when the
parent layout already handles scrolling, padding, borders, or surface styling, and keep the native
table parts inside your own wrapper.

`TableEmpty` renders a full empty row inside `TableBody`, so its required `colSpan` must match the
current body column count. Its `asChild` replaces only the generated `td`; compose `TableRow` and
`TableCell` directly when the row itself needs customization. `Table` handles presentation only:
sorting, filtering, selection, pagination, virtualization, and row action state belong to a
higher-level table composition such as [Data Table](/blocks/data-table).

### Accessibility

`Table` uses native table elements, so use standard HTML table attributes for the relationships in
your data. Add `scope="col"` to column headers, use `TableCaption` for a short accessible name or
description, and use `id` / `headers` when a complex table needs explicit header associations.
`Table` does not add keyboard navigation, selection behavior, or focus management.

## Styling

Style `Table` through `className` in React or `class` in Solid and Vue, the public `data-slot`, `data-scope`,
and `data-part` hooks, the `data-side` and `data-numeric` attributes, and the `--moduix-table-*`
CSS variables shown below. Tailwind variants use native utility classes and consumer classes; the
variables below apply to CSS Modules variants.

### Styling hooks

| Part | `data-slot` |
| --- | --- |
| `Table` | `table-root` |
| `TableScrollArea` | `table-scroll-area` |
| `TableCaption` | `table-caption` |
| `TableColumnGroup` | `table-column-group` |
| `TableColumn` | `table-column` |
| `TableHeader` | `table-header` |
| `TableBody` | `table-body` |
| `TableFooter` | `table-footer` |
| `TableRow` | `table-row` |
| `TableColumnHeader` | `table-column-header` |
| `TableCell` | `table-cell` |
| `TableEmpty` | `table-empty` |

Use the part that renders the element you want to style:

- `className` on `TableScrollArea` for shell-wide border, radius, and surface overrides
- `className` on `Table` for table typography and width constraints
- `data-side="top" | "bottom"` on `TableCaption` for caption placement styling
- `data-numeric` on `TableColumnHeader` and `TableCell` for numeric-column targeting
- `data-empty` on the row generated by `TableEmpty` for empty-row targeting
- `data-size`, `data-striped`, `data-interactive`, `data-sticky-header`, and
  `data-show-column-border` on `Table` for root-level state styling
- `data-sticky="start" | "end"` on `TableColumnHeader` and `TableCell` for sticky columns

## API reference

Props of `Table`. `numeric` goes on `TableColumnHeader` and `TableCell`; `side` (`'top' | 'bottom'`) on `TableCaption`.

| Prop | Type | Default |
| --- | --- | --- |
| `size` | `'sm' \| 'md' \| 'lg'` | `'md'` |
| `striped` | `boolean` | `false` |
| `interactive` | `boolean` | `false` |
| `stickyHeader` | `boolean` | `false` |
| `showColumnBorder` | `boolean` | `false` |
