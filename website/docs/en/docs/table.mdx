## API Reference

Ark UI does not provide a dedicated table primitive. moduix builds `Table` with the official
[Ark factory](https://ark-ui.com/docs/guides/composition#the-ark-factory), follows Ark's
[composition](https://ark-ui.com/docs/guides/composition), [styling](https://ark-ui.com/docs/guides/styling), and
[ref](https://ark-ui.com/docs/guides/ref) guidance.

Each part renders its corresponding native HTML element by default, accepts native element props and
`className` in React or `class` in Solid, forwards its ref, and supports Ark's `asChild`. When using
`asChild`, pass one semantic element as the child. `TableEmpty` is the exception to the usual
one-element composition: its `asChild` replaces only the generated `td`.

## Basic

If the table may be wider than its container, wrap it in `TableScrollArea`. Then compose `Table`
with `TableHeader`, `TableBody`, `TableRow`, and the matching header and cell parts. This is the
recommended setup for invoices, summaries, and admin-style read-only datasets.

## Anatomy

The normal consumer path stays close to native table markup:

```text
TableScrollArea (optional)
└─ Table
   ├─ TableColumnGroup (optional)
   │  └─ TableColumn
   ├─ TableCaption (optional)
   ├─ TableHeader
   │  └─ TableRow
   │     └─ TableColumnHeader
   ├─ TableBody
   │  ├─ TableRow
   │  │  └─ TableCell
   │  └─ TableEmpty (optional)
   └─ TableFooter (optional)
```

| Part                   | Role                                                                       |
| ---------------------- | -------------------------------------------------------------------------- |
| `Table`           | Native `table` root. Owns typography, dividers, and state attributes.      |
| `TableScrollArea`     | Optional bordered container with horizontal overflow for the table.       |
| `TableColumnGroup`    | Native `colgroup` wrapper for column width distribution.                   |
| `TableColumn`         | Native `col` wrapper. Supports `htmlWidth`.                                |
| `TableCaption`        | Optional table caption above or below the table via `side`.                |
| `TableHeader`         | Native `thead` wrapper for column headers.                                 |
| `TableBody`           | Native `tbody` wrapper for body rows.                                      |
| `TableFooter`         | Native `tfoot` wrapper for summary rows.                                   |
| `TableRow`            | Native `tr` wrapper with divider behavior.                                 |
| `TableColumnHeader`   | Native `th` wrapper. Supports `numeric`.                                   |
| `TableCell`           | Native `td` wrapper. Supports `numeric`.                                   |
| `TableEmpty`          | Convenience empty-state row and cell inside `TableBody`.                 |

## Composition

Use `TableScrollArea` when the table needs a bordered horizontal-scroll shell. Skip it when the
parent layout already owns scrolling, padding, borders, or surface styling, and keep the native
table parts inside your own wrapper.

`TableEmpty` owns a full empty row inside `TableBody`, so its required `colSpan` must match the
current body column count. Its `asChild` replaces only the generated `td`; compose `TableRow` and
`TableCell` directly when the row itself needs customization. `Table` owns presentation only:
sorting, filtering, selection, pagination, virtualization, and row action state belong to a
higher-level table composition such as [Data Table](/recipes/data-table).

### Accessibility

`Table` uses native table elements, so use standard HTML table attributes for the relationships in
your data. Add `scope="col"` to column headers, use `TableCaption` for a short accessible name or
description, and use `id` / `headers` when a complex table needs explicit header associations.
`Table` does not add keyboard navigation, selection behavior, or focus management.

## Styling

Style `Table` through `className` in React or `class` in Solid, the public `data-slot`, `data-scope`,
and `data-part` hooks, the `data-side` and `data-numeric` attributes, and the `--moduix-table-*`
CSS variables shown below. Tailwind variants use native utility classes and consumer classes; the
variables below apply to CSS Modules variants.

### Styling hooks

Use the part that owns the visual concern:

- `className` on `TableScrollArea` for shell-wide border, radius, and surface overrides
- `className` on `Table` for table typography and width constraints
- `data-slot="table-root"`, `table-scroll-area`, `table-column-group`, `table-column`,
  `table-caption`, `table-header`, `table-body`, `table-footer`, `table-row`,
  `table-column-header`, `table-cell`, and `table-empty` for part-level targeting
- `data-side="top" | "bottom"` on `TableCaption` for caption placement styling
- `data-numeric` on `TableColumnHeader` and `TableCell` for numeric-column targeting
- `data-empty` on the row generated by `TableEmpty` for empty-row targeting
- `data-size`, `data-variant`, `data-striped`, `data-interactive`, `data-sticky-header`, and
  `data-show-column-border` on `Table` for root-level state styling
- `data-sticky="start" | "end"` on `TableColumnHeader` and `TableCell` for sticky columns
