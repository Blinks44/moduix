## API Reference

Ark UI does not ship a dedicated `Textarea` primitive. moduix builds this component on
[Ark's `Field.Textarea`](https://ark-ui.com/docs/components/field), preserving the native
`textarea` API, `autoresize`, ref forwarding, `asChild`, and Field state inheritance.

## Choosing the right component

Use `Textarea` for plain text that can span multiple lines and should behave like a native browser
`textarea`.

- Choose **`Input`** for short single-line values such as names, URLs, or compact filters.
- Choose **`Textarea`** for notes, comments, descriptions, and other longer free-form content.
- Choose **`Editable`** when text is shown first and edited on demand.
- Choose **`Field` + `Textarea`** when the control needs a declarative label, description, required
  state, or validation.

## Anatomy

The public structure has one component part:

```text
Field (optional wrapper)
└─ Textarea
```

| Part       | Role                                                  |
| ---------- | ----------------------------------------------------- |
| `Textarea` | Native `textarea` with moduix styles and Field state. |

`Textarea` does not export an additional wrapper, compound subcomponents, provider or context hooks,
hidden inputs, or a label or character-counter API.

## Composition

### Recommended composition

Keep `Textarea` as the control for ordinary multiline text entry.

Use it directly with native props such as `rows`, `name`, `placeholder`, `maxLength`, `readOnly`,
`disabled`, `required`, `value`, `defaultValue`, and `form`.

Wrap it with `Field`, `Field.Label`, `Field.HelperText`, and `Field.ErrorText` when it needs a
declarative label, helper text, or validation message. When you use `Textarea` outside `Field`, give
it an accessible name with a native `<label>` or `aria-label`.

### When to go custom

Use `Field.Textarea` only when you need the lower-level `Field` namespace. For ordinary forms,
prefer `Textarea` so multiline controls share the same moduix styling contract.

Use `Editable` for interfaces where text is displayed first and then edited.

### Default props

| Prop         | Default | Notes                                            |
| ------------ | ------- | ------------------------------------------------ |
| `autoresize` | `false` | Ark auto-resize behavior is opt-in per textarea. |

### Behavioral notes

- Use `value` and native `onChange` to control the value from React state.
- Set `name` to include the textarea in native form submission, then read its value from `FormData`.
- A native form reset restores an uncontrolled textarea to `defaultValue`. Use `form` to associate
  it with a form outside the textarea's DOM subtree.
- The forwarded ref points to the real `HTMLTextAreaElement`. With `asChild`, provide one semantic
  textarea host that can receive the merged props and ref.
- Set `autoresize` when the textarea should grow with its content. Ark disables manual resizing
  while it is enabled, so `--moduix-textarea-resize` applies only when `autoresize` is false.
- Use `Editable` for inline flows with preview text, edit triggers, and commit or cancel controls.

### Styling hooks

Use the `Textarea` root for the control's appearance and the surrounding `Field` for layout and
supporting text.

- `Textarea` root for the border, background, placeholder, resize behavior, and focus ring
- `Field` wrapper for width, max width, spacing, label layout, description, and validation text
- `data-slot="textarea-root"` for stable targeting in scoped styles
- `data-autoresize` when `autoresize` is enabled
- `data-invalid`, `[aria-invalid='true']`, `[disabled]`, `data-disabled`, `:read-only`, and
  `data-readonly` for state-aware styling
