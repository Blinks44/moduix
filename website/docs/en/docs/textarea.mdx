## API Reference

Ark UI does not ship a dedicated `Textarea` primitive. moduix builds this component on
[Ark's `FieldTextarea`](https://ark-ui.com/docs/components/field), preserving the native
`textarea` API, `autoresize`, ref forwarding, `asChild`, and Field state inheritance.

## Choosing the right component

Use `Textarea` for plain text that can span multiple lines and should behave like a native browser
`textarea`.

- Choose **`Input`** for short single-line values such as names, URLs, or compact filters.
- Choose **`Textarea`** for notes, comments, descriptions, and other longer free-form content.
- Choose **`Editable`** when text is shown first and edited on demand.
- Choose **`Field` + `Textarea`** when the control needs a declarative label, description, required
  state, or validation.

## Basic

Place `Textarea` inside `Field` when the control needs an accessible label or supporting text. This
is the recommended setup for comments, notes, issue descriptions, and similar content.

## Anatomy

The public structure has one component part:

```text
Field (optional wrapper)
└─ Textarea
```

| Part       | Role                                                  |
| ---------- | ----------------------------------------------------- |
| `Textarea` | Native `textarea` with moduix styles and Field state. |

`Textarea` does not export an additional wrapper, compound subcomponents, provider or context hooks,
hidden inputs, or a label or character-counter API.

## Composition

Use `defaultValue` for an uncontrolled textarea. Use `value` with native `onChange` in React and
Solid, or `v-model` in Vue, when the application owns the content, using the matching framework's
state primitive.

In Vue, bind the native DOM property as `:defaultValue="initialValue"`, not `default-value`.
With `v-model`, reset the bound state in the form's reset handler: native reset does not emit an input event.

Wrap `Textarea` with `Field`, `FieldLabel`, `FieldHelperText`, and `FieldErrorText` when the
control needs a label, supporting text, or validation. Outside `Field`, provide an accessible name
with a native `<label>` or `aria-label`.

Set `autoresize` only when the control should grow with its content. Ark disables manual resizing in
that mode. With `asChild`, provide one semantic textarea host that can receive the merged props and
ref.

### Sizes

The `size` prop sets padding and type for a denser or roomier field. Inline padding and font size
match `Input` of the same size, so stacked controls line up. Height comes from the native `rows`
attribute, so it scales with the font size.

## Styling

Inside a disabled moduix `Field`, `FieldRootProvider`, or `Fieldset`, the root applies the disabled
opacity once; a standalone disabled `Textarea` dims itself.

Use `className` in React or `class` in Solid and Vue on `Textarea`. Tailwind variants use native
utilities and consumer classes. CSS Modules variants build on foundation tokens and expose only the
two variables below; override colors, padding, typography, height, and `resize` with a plain class, which
wins over the layered component styles.

### Styling hooks

- `data-slot="textarea-root"`
- `data-size="xs" | "sm" | "md" | "lg" | "xl"`
- `data-scope="field"` and `data-part="textarea"`
- Ark `data-invalid`, `data-required`, `data-disabled`, and `data-readonly` inside `Field`
- native `:disabled`, `:read-only`, `:focus-visible`, and `[aria-invalid="true"]`
