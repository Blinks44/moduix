## API Reference

Ark UI does not provide a dedicated Card primitive. moduix builds Card with Ark's official
[factory](https://ark-ui.com/docs/guides/composition#the-ark-factory) and follows Ark's guidance for
[composition](https://ark-ui.com/docs/guides/composition), [styling](https://ark-ui.com/docs/guides/styling), and
[refs](https://ark-ui.com/docs/guides/ref).

## Anatomy

```text
Card.Root
├─ Card.Background (optional moduix helper)
├─ Card.Media (optional moduix helper)
├─ Card.Header
│  ├─ Card.Title
│  ├─ Card.Description
│  └─ Card.Action (optional moduix helper)
├─ Card.Body
└─ Card.Footer (optional)
```

`Card` and `Card.Root` refer to the same root component.

| Part                 | Role                                                                                    |
| -------------------- | --------------------------------------------------------------------------------------- |
| `Card` / `Card.Root` | Root container with `size`, `variant`, and `asChild`.                                  |
| `Card.Background`    | Optional full-card background layer for decorative media.                                  |
| `Card.Media`         | Optional edge-to-edge media wrapper that clips the top corners consistently.              |
| `Card.Header`        | Header layout for the title, description, and an optional trailing action.              |
| `Card.Body`          | Main content area.                                                                       |
| `Card.Footer`        | Footer row for actions or metadata. It wraps when needed.                                |
| `Card.Title`         | Heading. Renders `h3` by default; use `asChild` for another heading level.               |
| `Card.Description`   | Supporting text below the title.                                                         |
| `Card.Action`        | Layout slot for an action in the header.                                                 |
| `Card.Link`          | Link whose clickable area expands across the card while leaving other controls usable.     |

## Composition

### Recommended composition

Start with `<Card />` and add only the sections you need. A typical card uses `Card.Header`,
`Card.Title`, `Card.Description`, `Card.Body`, and `Card.Footer`. Use `Card.Media` for leading media
that should reach the card edges with consistent clipping. Use `Card.Background` for decorative media
behind the whole card, then add any overlay and text-contrast styles in your application.

The root defaults to `size="md"` and `variant="outline"`.

### When to go custom

Use `asChild` when a semantic child should provide the DOM element for a part. Ark composition expects
exactly one child that can receive the merged props and ref. If the root is a link, do not put buttons,
inputs, or other links inside it.

Use `Card.Link` inside `Card.Title` when the card needs a navigation target and also contains separate
controls. The visible link stays in the title, while its clickable area expands across the card without
covering the other interactive elements. `Card.Action` only controls layout; it does not create ARIA
relationships.

| Situation                                                                                 | Recommended API                                                |
| ----------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| The whole card is one link and has no nested controls.                     | `Card asChild` with an `<a>` root                             |
| The card navigates but also has separate buttons, menus, or other actions. | `Card.Link` inside `Card.Title`, optionally with `Card.Action` |
| The card only groups content and does not navigate.                         | Plain `Card` composition without link sugar                   |

### Default props

| Part        | Prop      | Default     | Values                                |
| ----------- | --------- | ----------- | ------------------------------------- |
| `Card.Root` | `size`    | `'md'`      | `'sm' \| 'md' \| 'lg'`                |
| `Card.Root` | `variant` | `'outline'` | `'elevated' \| 'outline' \| 'subtle'` |

### Behavioral notes

- The root renders a presentational `div` by default and forwards its ref to the rendered element.
- Every part accepts native props, `className`, `style`, and Ark factory `asChild`.
- `Card.Media` is optional. Leave it out when you need custom media framing or the media is not at the
  top of the card.
- `Card.Background` is an optional helper for decorative media behind the whole card. Keep a background
  image's `alt` empty; use `Card.Media` when the image conveys information and needs alternative text.
- `Card.Title` renders `h3` by default.
- Interactive roots created with `asChild` and `Card.Link` receive the same themeable `:focus-visible` ring.
- Card has no managed state, callbacks, keyboard behavior, provider, context, or hidden input.
- `Card.Body` removes the top margin from its first direct child and the bottom margin from its last one.
- `--moduix-card-spacing`, `--moduix-card-spacing-sm`, and `--moduix-card-spacing-lg` set shared inset
  and section spacing and take precedence over the corresponding size-specific padding fallbacks.

### Styling hooks

- Every part exposes `data-scope="card"` and a matching `data-part`.
- Stable moduix hooks are `data-slot="card-root"`, `card-background`, `card-media`, `card-header`, `card-body`,
  `card-footer`, `card-title`, `card-description`, `card-action`, and `card-link`.
- The root exposes `data-size="sm | md | lg"` and
  `data-variant="elevated | outline | subtle"`.
- Component-wide `--moduix-card-bg`, `--moduix-card-color`, `--moduix-card-border-*`, and
  `--moduix-card-shadow` overrides take precedence over the matching variant-specific variables.
- Card has no interactive state attributes because it owns no state or behavior.
