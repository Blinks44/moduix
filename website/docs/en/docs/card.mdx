## API Reference

Ark UI does not provide a dedicated Card primitive. moduix builds Card with the official
[Ark factory](https://ark-ui.com/docs/guides/composition#the-ark-factory) and follows Ark's guidance for
[composition](https://ark-ui.com/docs/guides/composition), [styling](https://ark-ui.com/docs/guides/styling), and
[refs](https://ark-ui.com/docs/guides/ref).

## Basic

Use `<Card />` as the root and add the namespaced `Card` parts for a standard card.

If you are coming from shadcn, the overall structure stays familiar. The main API difference is that
`CardContent` becomes `Card.Body`; the other parts remain under the `Card` namespace.

## Anatomy

```text
Card.Root
├─ Card.Background (optional moduix sugar)
├─ Card.Media (optional moduix sugar)
├─ Card.Header
│  ├─ Card.Title
│  ├─ Card.Description
│  └─ Card.Action (optional moduix sugar)
├─ Card.Body
└─ Card.Footer (optional)
```

`Card` and `Card.Root` refer to the same root component.

| Part                 | Role                                                                                    |
| -------------------- | --------------------------------------------------------------------------------------- |
| `Card` / `Card.Root` | Root container with `size`, `variant`, and `asChild`.                                  |
| `Card.Background`    | Optional background layer that covers the card for decorative media.                    |
| `Card.Media`         | Optional edge-to-edge media wrapper that clips the top corners consistently.            |
| `Card.Header`        | Header layout for the title, description, and an optional trailing action.              |
| `Card.Body`          | Main content area.                                                                       |
| `Card.Footer`        | Footer row for actions or metadata. It wraps when needed.                                |
| `Card.Title`         | Heading. Renders `h3` by default; use `asChild` for another heading level.               |
| `Card.Description`   | Supporting text below the title.                                                         |
| `Card.Action`        | Layout slot for an action in the header.                                                 |
| `Card.Link`          | Stretched link for a navigable card that also contains separate actions.                |

## Composition

### Recommended composition

Start with `<Card />`, then add `Card.Header`, `Card.Title`, `Card.Description`, `Card.Body`, and
`Card.Footer`. Use `Card.Media` for leading media that should reach the card edges with consistent
clipping. Use `Card.Background` for a decorative image behind the whole card, and define its gradient
and text contrast in your application styles.
The root defaults to `size="md"` and `variant="outline"`.

### When to go custom

Use `asChild` when a semantic child should provide the DOM element for a part. Ark composition expects
exactly one child. If the root is a link, do not place nested buttons, inputs, or links inside it.

Use `Card.Link` inside the title when the card needs a navigation target and also contains separate
controls. The visible link stays in the title, while its hit area expands across the card without
covering the other interactive elements. `Card.Action` only controls layout and does not create ARIA
relationships.

| Situation                                                                                 | Recommended API                                                |
| ----------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| The whole card is one link and has no nested controls.                                    | `Card asChild` with an `<a>` root                              |
| The card should navigate but also has buttons, menus, or other separate actions.          | `Card.Link` inside `Card.Title`, optionally with `Card.Action` |
| The card only groups content and does not navigate.                                       | Plain `Card` composition without link sugar                   |

### Default props

| Part        | Prop      | Default     | Values                                |
| ----------- | --------- | ----------- | ------------------------------------- |
| `Card.Root` | `size`    | `'md'`      | `'sm' \| 'md' \| 'lg'`                |
| `Card.Root` | `variant` | `'outline'` | `'elevated' \| 'outline' \| 'subtle'` |

### Behavioral notes

- The root renders a presentational `div` by default and forwards its ref to the rendered element.
- Every part accepts native props, `className`, `style`, and Ark factory `asChild`.
- `Card.Media` is an optional helper. Leave it out when you need custom media framing or the media is
  not placed at the top of the card.
- `Card.Background` is an optional helper for decorative media behind the whole card. Keep its image's
  `alt=""`; use `Card.Media` when the image conveys information and needs alternative text.
- `Card.Title` renders `h3` by default.
- Interactive roots created with `asChild` and `Card.Link` receive the same themeable `:focus-visible` ring.
- Card has no managed state, callbacks, keyboard behavior, provider, context, or hidden input.
- `Card.Body` resets the margins of its first and last direct children.
- `--moduix-card-spacing`, `--moduix-card-spacing-sm`, and `--moduix-card-spacing-lg` control shared
  inset and section spacing without replacing the more specific `--moduix-card-*` overrides.

### Styling hooks

- Every part exposes `data-scope="card"` and a matching `data-part`.
- Stable moduix hooks are `data-slot="card-root"`, `card-background`, `card-media`, `card-header`, `card-body`,
  `card-footer`, `card-title`, `card-description`, `card-action`, and `card-link`.
- The root exposes `data-size="sm | md | lg"` and
  `data-variant="elevated | outline | subtle"`.
- Component-wide `--moduix-card-bg`, `--moduix-card-color`, `--moduix-card-border-*`, and
  `--moduix-card-shadow` overrides take precedence over the matching variant-specific variables.
- Card has no interactive state attributes because it owns no state or behavior.
