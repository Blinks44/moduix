## API Reference

Ark UI does not provide a dedicated Card primitive. moduix builds Card with Ark's official
[factory](https://ark-ui.com/docs/guides/composition#the-ark-factory) and follows Ark's guidance for
[composition](https://ark-ui.com/docs/guides/composition), [styling](https://ark-ui.com/docs/guides/styling), and
[refs](https://ark-ui.com/docs/guides/ref).

## Basic


Use `Card` as the root and add only the parts you need. Import each additional part directly, such
as `CardHeader` and `CardTitle`. The same names work with npm packages and shadcn registry source.

## Anatomy

```text
Card
├─ CardBackground (optional moduix helper)
├─ CardMedia (optional moduix helper)
├─ CardHeader
│  ├─ CardTitle
│  ├─ CardDescription
│  └─ CardAction (optional moduix helper)
├─ CardBody
└─ CardFooter (optional)
```

| Part                 | Role                                                                                  |
| -------------------- | ------------------------------------------------------------------------------------- |
| `Card`               | Root container with `size`, `variant`, and `asChild`.                                |
| `CardBackground`    | Optional full-card background layer for decorative media.                            |
| `CardMedia`         | Optional edge-to-edge media wrapper that clips the top corners consistently.          |
| `CardHeader`        | Header layout for the title, description, and an optional trailing action.            |
| `CardBody`          | Main content area.                                                                    |
| `CardFooter`        | Footer row for actions or metadata. It wraps when needed.                             |
| `CardTitle`         | Heading. Renders `h3` by default; use `asChild` for another heading level.            |
| `CardDescription`   | Supporting text below the title.                                                      |
| `CardAction`        | Layout slot for an action in the header.                                               |
| `CardLink`          | Link whose clickable area expands across the card while leaving other controls usable. |

## Composition

Card has no managed state, callbacks, provider, context, keyboard behavior, or hidden input. Use
plain parts for presentational content. Use `asChild` when a semantic element should own the root or
another part; it must render exactly one child that can receive the merged props. In Solid, `asChild`
uses a render function such as `asChild={(props) => <a {...props()} />}`.

In Solid, assign a ref to the element created inside the `asChild` render function. A ref on a Card
part itself is not forwarded through that composition path.

When a card is entirely one link and has no nested controls, compose the root with `asChild`. When a
card also contains buttons or other actions, keep `CardLink` inside `CardTitle` and put those
controls in `CardAction`; the link's expanded click area leaves the other interactive elements usable.
Use `CardMedia` for informative leading media and `CardBackground` for decorative media behind the
card content. Give background images an empty `alt` and add any overlay or text-contrast styles in
your application.

## Styling

Use `className` in React or `class` in Solid and Vue on exported parts for structural styles. Tailwind variants
use native utilities and consumer classes; the CSS variables below customize the CSS Modules variants.
Data attributes and `data-slot` hooks are shared by both styling tracks.

### Styling hooks

- Every part exposes `data-scope="card"` and a matching `data-part`.
- Stable moduix hooks are `data-slot="card-root"`, `card-background`, `card-media`, `card-header`, `card-body`,
  `card-footer`, `card-title`, `card-description`, `card-action`, and `card-link`.
- The root exposes `data-size="sm | md | lg"` and `data-variant="elevated | outline | subtle"`.
- The CSS variables override every variant. To theme one variant across the app, set them on
  `[data-slot='card-root'][data-variant='<variant>']`.
- Each section has the same top inset, and the last section also gets it at the bottom. In Tailwind,
  change that bottom inset with `last:pb-*` on the section or `[--card-spacing:…]` on the root.
- Card has no interactive state attributes because it owns no state or behavior.
