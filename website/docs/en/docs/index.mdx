# moduix

moduix is a multi-framework component system built on [Ark UI](https://ark-ui.com/). It pairs Ark's
accessible interaction primitives with considered defaults, explicit composition, and shared design
tokens. Every adapter keeps the public API native to its framework.

Start with [Quick start](/docs/quick-start) to choose an installation method and render your first
component.

## Framework support

React and Solid are available today. Vue and Svelte are planned, and will follow the same component
contracts and styling choices when they ship.

| Framework | Status | Documentation |
| --------- | ------ | ------------- |
| React | Available | Native React source and live previews |
| Solid | Available | Native Solid source alongside the React preview |
| Vue | Planned | Added only after the adapter ships |
| Svelte | Planned | Added only after the adapter ships |

Framework-specific examples use tabs only when the code genuinely differs. Shared concepts stay
outside the tabs, so the documentation remains concise as new adapters are added.

## Choose how you own it

Choose a package when you want updates through your package manager. Choose the shadcn registry
when you want the component source, styles, and supporting utilities inside your repository.

| Workflow                   | Imports                                           | Best fit                                                               |
| -------------------------- | ------------------------------------------------- | ---------------------------------------------------------------------- |
| Package                    | `@moduix/react/*` or `@moduix/solid/*`            | Centralized updates and the smallest amount of application-owned code. |
| Copy-owned shadcn registry | `@/components/ui/*`                               | Direct source ownership and deliberate local changes.                  |

Both workflows expose the same framework-native component contracts and token system. Choose the
runtime and styling track independently from where the source lives:

## Supported versions

The package peer dependencies define the supported framework range:

| Technology | Supported versions | Used by |
| ---------- | ------------------ | ------- |
| React and React DOM | 18 and 19 | `@moduix/react`, `@moduix/react-tailwind` |
| Solid | 1.9 and later 1.x releases | `@moduix/solid`, `@moduix/solid-tailwind` |
| Tailwind CSS | 4.x | Tailwind packages and registries only |
| Ark UI | `^5.37.2` | The matching React or Solid package |

Your package manager checks these ranges during installation. CSS Modules packages do not require
Tailwind CSS.

## What Ark-backed means

Complex components keep the Ark UI model visible: named parts, controlled and uncontrolled state,
callback detail objects, context providers, `asChild` composition, native form controls, and state
attributes. moduix adds component styles, considered defaults, convenience composition, and stable
`data-slot` hooks without hiding the primitive structure you need for advanced product work.

Ark UI remains the source of truth for interaction behavior and accessibility. moduix is the
opinionated product layer that sits on top.

## What shadcn-inspired means

The influence is practical rather than cosmetic:

- polished defaults that feel coherent before customization;
- readable composition, open CSS variables, and source code that is straightforward to inspect;
- a shadcn registry for copy-owned installation.

This influence does not couple CSS Modules to Tailwind or replace Ark anatomy with shadcn-specific
wrapper contracts. Tailwind packages are available for components that have already been ported.

## How styling works

The CSS Modules packages use regular CSS files with locally scoped class names, so component
selectors do not leak into the rest of your application. Their packages deliver component styles
with each imported entry point, while their registries copy the same source and `.module.css` files
into your repository.

The Tailwind packages express the same visual defaults as utility classes and use Tailwind Preflight
instead of the optional moduix reset. Both styling tracks share semantic foundation colors, selected
global tokens, animations, and component behavior:

- import `style.css` once for shared tokens and base layer styles;
- use `className` in React or `class` in Solid on roots and named parts;
- target stable `data-slot` and Ark state attributes when a state-specific rule is needed;
- override `--moduix-*` variables for themes and shared visual decisions.

In the CSS Modules packages, colors, spacing, radii, typography, focus rings, motion, shadows, and
component-specific decisions are expressed as CSS custom properties. Override a semantic token to
change the whole system, a shared family token to tune related components, or a
`--<component>-*` variable for one local exception. Tailwind variants use semantic utilities and
consumer classes instead of reproducing that component-variable API. Choose CSS Modules when you do
not want Tailwind as a dependency; choose Tailwind when utilities should remain directly editable
with copied source. See [Tokens](/docs/tokens) for the full hierarchy and [Themes](/docs/themes) for
ready-made presets.
