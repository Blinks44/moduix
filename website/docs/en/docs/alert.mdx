<Usage />

For a standard inline message, place `AlertTitle` and `AlertDescription` inside `AlertContent`.
Add `AlertIndicator` when an icon helps people scan the message.

## Choosing the right component

Use `Alert` when a message belongs in the page layout and should take up space in the normal document
flow.

- Use **`Alert`** for inline status updates, validation results, and system feedback in forms, panels, or page content.
- Use **`Toast`** for temporary notifications that appear outside the document flow and dismiss themselves.

## Composition

Import `Alert` from `@moduix/react/alert`, `@moduix/solid/alert`, or `@moduix/vue/alert`. `Alert` is
the root part, and the other public parts are `AlertIndicator`, `AlertContent`, `AlertTitle`,
`AlertDescription`, and `AlertActions`.

Every part accepts the usual props for its rendered element, including `className`/`class` and Ark's
`asChild`, and forwards refs to the rendered element. `status` defaults to `info` and controls visual
styling only. Add `role="status"` or `role="alert"` when a dynamically added or updated message needs a
live region. `AlertIndicator` is hidden from assistive technology, so keep the essential meaning in the
title or description.

`Alert` is presentational: the component that renders it controls visibility and dismissal state. It does
not manage focus or keyboard behavior for buttons and links placed inside it. `AlertContent` is
required and contains the title, description, controls, and other message content. Put controls inside
`AlertActions` when they need the default wrapped action-row styling.

When the title needs a different semantic element, use `AlertTitle asChild` with exactly one semantic
child. Solid uses Ark's render-function form of `asChild` as shown in the Custom Heading example. Vue
uses the `as-child` attribute with a single child element.

## Styling

Use `className` or `class` on the root or its parts for local styles. Tailwind variants use native
utilities and consumer classes. In the CSS Modules variants, override `--moduix-alert-*` variables
on the root when the alert needs a local theme.

In CSS Modules, `--moduix-alert-bg`, `--moduix-alert-border-color`, `--moduix-alert-color`, and
`--moduix-alert-indicator-color` override every status, so scope them with
`[data-status='success']` and similar selectors when only one status should change. Spacing, radius,
shadow, and typography come from foundation tokens; override them with a class on the part.

Built-in statuses also read shared palette tokens:

| Status    | Shared token                 | Default                      |
| --------- | ---------------------------- | ---------------------------- |
| `info`    | `--moduix-card`        | theme card                   |
| `success` | `--moduix-success`     | `oklch(0.627 0.194 149.214)` |
| `warning` | `--moduix-warning`     | `oklch(0.795 0.184 86.047)`  |
| `error`   | `--moduix-destructive` | theme destructive            |

### Styling hooks

| Part | `data-slot` |
| --- | --- |
| `Alert` | `alert-root` |
| `AlertIndicator` | `alert-indicator` |
| `AlertContent` | `alert-content` |
| `AlertTitle` | `alert-title` |
| `AlertDescription` | `alert-description` |
| `AlertActions` | `alert-actions` |

- Ark-style selectors: `data-scope="alert"` with `data-part="root"`, `indicator`, `content`, `title`, `description`, or `actions`
- `Alert` writes the selected status to `data-status`

## API reference

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `status` | `'info' \| 'success' \| 'warning' \| 'error'` | `'info'` | Meaning and color: `info`, `success`, `warning`, or `error`. |
| `asChild` | `boolean` | `false` | Renders the root as its single child element. |
