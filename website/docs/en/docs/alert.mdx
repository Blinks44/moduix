## API Reference

Ark UI does not include a dedicated `alert` primitive. moduix builds `Alert` with the official
[Ark factory](https://ark-ui.com/docs/guides/composition#the-ark-factory) and follows Ark's guidance for
[composition](https://ark-ui.com/docs/guides/composition), [styling](https://ark-ui.com/docs/guides/styling), and
[refs](https://ark-ui.com/docs/guides/ref).

Public parts are `Alert.Root`, `Alert.Indicator`, `Alert.Content`, `Alert.Title`,
`Alert.Description`, and `Alert.Actions`.

## Choosing the right component

Use `Alert` when a message should remain in the page layout and take up space in the normal document
flow.

- Use **`Alert`** for inline status updates, validation messages, and system feedback in forms, panels, or page content.
- Use **`Toast`** for transient notifications that appear outside the document flow and dismiss themselves.

## Anatomy

```text
Alert / Alert.Root
├─ Alert.Indicator (optional)
├─ Alert.Title
├─ Alert.Description
└─ Alert.Content (optional)
   ├─ Alert.Title
   ├─ Alert.Description
   ├─ Alert.Actions (optional)
   └─ Extra custom blocks
```

| Part                   | Role                                                          | `data-part`   |
| ---------------------- | ------------------------------------------------------------- | ------------- |
| `Alert` / `Alert.Root` | Root part. Applies status styles and accessibility semantics. | `root`        |
| `Alert.Indicator`      | Optional indicator part. Gives child SVG icons a consistent size. | `indicator`   |
| `Alert.Content`        | Optional column wrapper that keeps grouped text and actions together. | `content`     |
| `Alert.Title`          | Alert title part. Renders a `p` by default.                   | `title`       |
| `Alert.Description`    | Supporting text part.                                        | `description` |
| `Alert.Actions`        | Optional wrapped row for actions inside content.             | `actions`     |

## Composition

### Recommended composition

Use `Alert`, `Alert.Title`, and `Alert.Description` directly for the common inline message.

Use `status` to choose the message type: `info`, `success`, `warning`, or `error`.

Add `Alert.Indicator` when the alert needs an explicit visual cue. The component deliberately keeps
actions in your own markup instead of providing action-specific props or slot collections.

### When to go custom

Add `Alert.Content` when the title, description, and extra controls should stay in one column beside
the indicator. Use `Alert.Actions` for a wrapped action row inside that column. If the document outline
calls for a different heading element, use `Alert.Title asChild`.

For example:

```tsx
<Alert.Title asChild>
  <h2>Billing issue</h2>
</Alert.Title>
```

### Default props

| Prop     | Default   | Values / Notes                                                  |
| -------- | --------- | --------------------------------------------------------------- |
| `status` | `info`    | `info`, `success`, `warning`, `error`                           |
| `role`   | Automatic | `role="status"` by default, `role="alert"` for `status="error"` |

### Behavioral notes

- `Alert.Root` defaults to `role="status"` and switches to `role="alert"` for `status="error"`.
- These roles create live regions with different announcement priorities. Mount the alert before
  updating its message when it needs to be announced. Content that is already present when the page
  loads may not be announced.
- Override `role` when the alert is a static callout rather than live feedback. For supplementary
  static information, use `role="note"`.
- `Alert.Indicator` defaults to `aria-hidden="true"`.
- `Alert.Title` renders `p` by default and uses Ark `asChild` when you need a different heading element.
- Essential meaning should stay in the title or description, because the indicator stays
  `aria-hidden`.
- `Alert.Content` is optional. Use it when title, description, and extra controls should share one
  content column beside the indicator.
- `Alert.Actions` is optional. Use it when buttons or links should share the default wrapped action
  row styling.
- The component is presentational by design. It does not manage dismissal state, focus, or keyboard
  behavior for actions you place inside it.

## Styling

Use `className` on the root or its parts for local styles. Override `--moduix-alert-*` CSS variables on
the root when the alert needs a local theme.

The component-wide `--moduix-alert-bg`, `--moduix-alert-border-color`, `--moduix-alert-color`, and
`--moduix-alert-indicator-color` variables apply to every status. Use the matching
`--moduix-alert-<status>-*` variables when only one status should change.

Built-in statuses also read shared palette tokens:

| Status    | Shared token                 | Default                      |
| --------- | ---------------------------- | ---------------------------- |
| `info`    | `--moduix-color-card`        | theme card                   |
| `success` | `--moduix-color-success`     | `oklch(0.627 0.194 149.214)` |
| `warning` | `--moduix-color-warning`     | `oklch(0.795 0.184 86.047)`  |
| `error`   | `--moduix-color-destructive` | theme destructive            |

### Styling hooks

- Stable `data-slot` selectors: `alert-root`, `alert-indicator`, `alert-content`, `alert-title`,
  `alert-description`, and `alert-actions`
- Ark-style selectors: `data-scope="alert"` with `data-part="root"`, `indicator`, `content`,
  `title`, `description`, or `actions`
- `Alert.Root` writes the selected status to `data-status`
