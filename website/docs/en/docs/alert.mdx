## API Reference

Ark UI does not provide a dedicated `alert` primitive. moduix builds `Alert` with Ark's official
[factory](https://ark-ui.com/docs/guides/composition#the-ark-factory), following Ark's guidance on
[composition](https://ark-ui.com/docs/guides/composition), [styling](https://ark-ui.com/docs/guides/styling), and
[refs](https://ark-ui.com/docs/guides/ref).

Import `Alert` from `@moduix/react/alert` or `@moduix/solid/alert`. The callable `Alert` export and
`Alert.Root` render the same root part. The other public parts are `Alert.Indicator`, `Alert.Content`,
`Alert.Title`, `Alert.Description`, and `Alert.Actions`.

Every part accepts the usual props for its rendered element, including `className`/`class` and Ark's
`asChild`, and forwards refs to the rendered element. `status` defaults to `info`; the root defaults to
`role="status"` and uses `role="alert"` for `status="error"`. `Alert.Indicator` is hidden from assistive
technology, so keep the essential meaning in the title or description.

## Choosing the right component

Use `Alert` when a message belongs in the page layout and should take up space in the normal document
flow.

- Use **`Alert`** for inline status updates, validation results, and system feedback in forms, panels, or page content.
- Use **`Toast`** for temporary notifications that appear outside the document flow and dismiss themselves.

## Anatomy

Use `Alert.Title` and `Alert.Description` directly for a compact message. When an indicator should
sit beside grouped text and controls, put those elements inside `Alert.Content`.

```text
Alert / Alert.Root
├─ Alert.Indicator (optional)
├─ Alert.Title
├─ Alert.Description
└─ Alert.Content (optional)
   ├─ Alert.Title
   ├─ Alert.Description
   ├─ Alert.Actions (optional)
   └─ Extra custom blocks
```

| Part                   | Role                                                               | `data-part`   |
| ---------------------- | ------------------------------------------------------------------ | ------------- |
| `Alert` / `Alert.Root` | Root element. Applies status styles and automatic live-region semantics. | `root`        |
| `Alert.Indicator`      | Optional visual cue. Child SVG icons receive a consistent size.   | `indicator`   |
| `Alert.Content`        | Optional column wrapper for grouped text and actions.              | `content`     |
| `Alert.Title`          | Alert title. Renders a `p` by default.                              | `title`       |
| `Alert.Description`    | Supporting message text.                                           | `description` |
| `Alert.Actions`        | Optional wrapped row for actions inside `Content`.                 | `actions`     |

## Composition

`Alert` is presentational: the component that renders it owns visibility and dismissal state. It does
not manage focus or keyboard behavior for buttons and links placed inside it. Use `Alert.Content` only
when the title, description, and controls should share one column beside `Alert.Indicator`; put those
controls inside `Alert.Actions` when they need the default wrapped action-row styling.

When the title needs a different semantic element, use `Alert.Title asChild` with exactly one semantic
child. Solid uses Ark's render-function form of `asChild` as shown in the Custom Heading example.

## Styling

Use `className` or `class` on the root or its parts for local styles. Tailwind variants use native
utilities and consumer classes. In the CSS Modules variants, override `--moduix-alert-*` variables
on the root when the alert needs a local theme.

In CSS Modules, the component-wide `--moduix-alert-bg`, `--moduix-alert-border-color`,
`--moduix-alert-color`, and `--moduix-alert-indicator-color` variables apply to every status. Use
the matching `--moduix-alert-<status>-*` variables when only one status should change.

Built-in statuses also read shared palette tokens:

| Status    | Shared token                 | Default                      |
| --------- | ---------------------------- | ---------------------------- |
| `info`    | `--moduix-color-card`        | theme card                   |
| `success` | `--moduix-color-success`     | `oklch(0.627 0.194 149.214)` |
| `warning` | `--moduix-color-warning`     | `oklch(0.795 0.184 86.047)`  |
| `error`   | `--moduix-color-destructive` | theme destructive            |

### Styling hooks

- Stable `data-slot` selectors: `alert-root`, `alert-indicator`, `alert-content`, `alert-title`, `alert-description`, and `alert-actions`
- Ark-style selectors: `data-scope="alert"` with `data-part="root"`, `indicator`, `content`, `title`, `description`, or `actions`
- `Alert.Root` writes the selected status to `data-status`
