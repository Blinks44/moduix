## API Reference

Ark UI does not provide a dedicated `alert` primitive. moduix builds `Alert` with Ark's official
[factory](https://ark-ui.com/docs/guides/composition#the-ark-factory), following Ark's guidance on
[composition](https://ark-ui.com/docs/guides/composition), [styling](https://ark-ui.com/docs/guides/styling), and
[refs](https://ark-ui.com/docs/guides/ref).

Import `Alert` from `@moduix/react/alert`. The callable `Alert` export and `Alert.Root` render the
same root part. The other public parts are `Alert.Indicator`, `Alert.Content`, `Alert.Title`,
`Alert.Description`, and `Alert.Actions`.

Every part accepts the usual props for its rendered element, including `className` and Ark's
`asChild`, and forwards refs to the rendered element.

## Choosing the right component

Use `Alert` when a message belongs in the page layout and should take up space in the normal document
flow.

- Use **`Alert`** for inline status updates, validation results, and system feedback in forms, panels, or page content.
- Use **`Toast`** for temporary notifications that appear outside the document flow and dismiss themselves.

## Anatomy

Use `Alert.Title` and `Alert.Description` directly for a compact message. When an indicator should
sit beside grouped text and controls, put those elements inside `Alert.Content`.

```text
Alert / Alert.Root
├─ Alert.Indicator (optional)
├─ Alert.Title
├─ Alert.Description
└─ Alert.Content (optional)
   ├─ Alert.Title
   ├─ Alert.Description
   ├─ Alert.Actions (optional)
   └─ Extra custom blocks
```

| Part                   | Role                                                               | `data-part`   |
| ---------------------- | ------------------------------------------------------------------ | ------------- |
| `Alert` / `Alert.Root` | Root element. Applies status styles and automatic live-region semantics. | `root`        |
| `Alert.Indicator`      | Optional visual cue. Child SVG icons receive a consistent size.   | `indicator`   |
| `Alert.Content`        | Optional column wrapper for grouped text and actions.              | `content`     |
| `Alert.Title`          | Alert title. Renders a `p` by default.                              | `title`       |
| `Alert.Description`    | Supporting message text.                                           | `description` |
| `Alert.Actions`        | Optional wrapped row for actions inside `Content`.                 | `actions`     |

## Composition

### Recommended composition

For the common inline message, compose `<Alert>` with `Alert.Title` and `Alert.Description`.

Use `status` to choose the message type: `info`, `success`, `warning`, or `error`.

Add `Alert.Indicator` when the alert needs an explicit visual cue. Actions remain regular content
that you place inside `Alert.Content`; the component does not create buttons or action slots.

### When to go custom

Add `Alert.Content` when the title, description, and extra controls should stay in one column beside
the indicator. Use `Alert.Actions` for a wrapped action row inside that column. With `asChild`, provide
exactly one semantic child so it can own the rendered DOM element.

If the document outline calls for a different heading element, use `Alert.Title asChild`:

```tsx
<Alert.Title asChild>
  <h2>Billing issue</h2>
</Alert.Title>
```

### Default props

| Prop     | Default   | Values / Notes                                                  |
| -------- | --------- | --------------------------------------------------------------- |
| `status` | `info`    | `info`, `success`, `warning`, `error`                           |
| `role`   | Automatic | `role="status"` by default, `role="alert"` for `status="error"` |

### Behavioral notes

- `Alert.Root` defaults to `role="status"` and switches to `role="alert"` for `status="error"`.
- `role="status"` usually announces updates politely, while `role="alert"` announces them assertively. Mount the alert before updating its message when it needs to be announced. Content that is already present when the page loads may not be announced.
- Override `role` when the alert is a static callout rather than live feedback. For supplementary static information, use `role="note"`.
- `Alert.Indicator` defaults to `aria-hidden="true"`.
- Keep essential meaning in the title or description because the indicator is hidden from assistive technology.
- `Alert.Title` renders a `p` by default. Use Ark's `asChild` when the title needs a different heading element.
- `Alert.Content` is optional. Use it when the title, description, and extra controls should share one content column beside the indicator.
- `Alert.Actions` is optional. Use it when buttons or links should share the default wrapped action-row styling.
- The component is presentational by design. It does not manage dismissal state, focus, or keyboard behavior for actions you place inside it.

## Styling

Use `className` on the root or its parts for local styles. Override `--moduix-alert-*` variables on
the root when the alert needs a local theme.

The component-wide `--moduix-alert-bg`, `--moduix-alert-border-color`, `--moduix-alert-color`, and
`--moduix-alert-indicator-color` variables apply to every status. Use the matching
`--moduix-alert-<status>-*` variables when only one status should change.

Built-in statuses also read shared palette tokens:

| Status    | Shared token                 | Default                      |
| --------- | ---------------------------- | ---------------------------- |
| `info`    | `--moduix-color-card`        | theme card                   |
| `success` | `--moduix-color-success`     | `oklch(0.627 0.194 149.214)` |
| `warning` | `--moduix-color-warning`     | `oklch(0.795 0.184 86.047)`  |
| `error`   | `--moduix-color-destructive` | theme destructive            |

### Styling hooks

- Stable `data-slot` selectors: `alert-root`, `alert-indicator`, `alert-content`, `alert-title`, `alert-description`, and `alert-actions`
- Ark-style selectors: `data-scope="alert"` with `data-part="root"`, `indicator`, `content`, `title`, `description`, or `actions`
- `Alert.Root` writes the selected status to `data-status`
