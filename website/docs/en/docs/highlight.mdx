## Usage

<Usage />

Pass the complete source string through `text` and the term to find through `query`. Place
`Highlight` inside the text component or HTML element that should provide the surrounding layout
and semantics.

## Choosing the right component

Use `Highlight` to emphasize search terms inside text that already has a semantic container. It
renders the matched ranges, but does not add a layout wrapper of its own.

- Choose **`Highlight`** when one or more terms in an existing sentence, label, or text block need emphasis.
- Choose **`Text`** when the whole string only needs typographic styling and no query-based matching.

### Exact match

Set `exactMatch` when partial-word matches are too broad. In this example, `box` matches the
standalone word but not `checkbox` or `combobox`. Matching follows JavaScript word boundaries,
which are reliable for Latin text but do not treat Cyrillic and some other scripts as whole words.

<Example name="highlight/exact-match" />

### Multiple queries

Pass a string array when several terms should be highlighted in the same text. For an array,
`matchAll` defaults to `true`; setting `matchAll={false}` throws an error.

## Composition

`Highlight` is stateless and adds no layout wrapper. Place it inside an existing text container such
as `Text`, a heading, a list item, or a table cell. Control `query` from the parent when search input
changes. A string-array `query`
requires `matchAll` to remain `true`; use custom markup in your own component when each match needs a
different element or interactive behavior.

## Anatomy

`Highlight` has one public root and returns a fragment, not an extra wrapper element. Each matched
range becomes a native `<mark>` element. Text that does not match stays as ordinary text in the
surrounding flow.

## Styling

Matched ranges receive moduix's default `<mark>` styles. Use `className` in React or `class` in Solid
and Vue for a local adjustment. CSS Modules variants also expose the `--moduix-highlight-*` variables;
use Tailwind utilities or consumer classes for Tailwind variants.

### Styling hooks

| Part | `data-slot` |
| --- | --- |
| `Highlight` | `highlight-root` |

- Every matched `<mark>` has `data-scope="highlight"` and `data-part="root"`.
- Props such as `className`/`class`, `style`, `title`, and `data-*` are applied to every matched `<mark>`.
- There is no wrapper element, state attribute, or Ark runtime CSS variable.

## API reference

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `text` | `string` | — | Text to search in. |
| `query` | `string \| string[]` | — | Term or array of terms to mark. |
| `ignoreCase` | `boolean` | `false` | Matches regardless of letter case. |
| `matchAll` | `boolean` | `false` | Marks every match, not only the first. |
| `exactMatch` | `boolean` | `false` | Matches whole words only. |
