## Choosing the right component

Use `Highlight` to emphasize search terms inside text that already has a semantic container.
It renders the matched ranges, but does not add a layout wrapper of its own.

- Choose **`Highlight`** when one or more terms in an existing sentence, label, or text block need emphasis.
- Choose **`Text`** when the whole string only needs typographic styling and no query-based matching.

## Anatomy

`Highlight` has one public root and returns a fragment, not an extra wrapper element. Each matched
range becomes a native `<mark>` element. Text that does not match stays as ordinary text in the
surrounding flow.

```text
Highlight / Highlight.Root
└─ matched ranges rendered as repeated <mark> elements
```

| Part                           | Role                                                                 |
| ------------------------------ | -------------------------------------------------------------------- |
| `Highlight` / `Highlight.Root` | Applies moduix styling to every matched range in the provided text. |

## Composition

### Recommended composition

Use the short `<Highlight>` form inside `Text`, `Heading`, a list item, a table cell, or another
text-owning container. It is equivalent to `<Highlight.Root>`.

### When to go custom

Use `Highlight` when native `<mark>` elements are the right output for every match. If each match
needs a different element, interactive behavior, or custom content, render that markup in your own
component. The moduix component intentionally does not expose a chunk-rendering API.

### Default props

| Prop         | Default                                   | Notes                                                   |
| ------------ | ----------------------------------------- | ------------------------------------------------------- |
| `query`      | -                                         | String or string array of terms to highlight.           |
| `text`       | -                                         | Required complete source string.                        |
| `ignoreCase` | `false`                                   | Matches letters without considering their case.         |
| `matchAll`   | `false` for a string; `true` for an array | Highlights every match. An array cannot be used with `false`. |
| `exactMatch` | `false`                                   | Matches complete words instead of partial words.        |

### Behavioral notes

`className`, `style`, `title`, `id`, and other props for `<mark>` are applied to every matched
segment. When there is no match, `Highlight` renders the source text without any `<mark>` element.

`Highlight` does not add a wrapper or manage state, focus, keyboard interaction, or form behavior.
Each matched mark uses the stable moduix data attributes described in [Styling](#styling).

`exactMatch` uses JavaScript word boundaries. It works reliably for Latin text, but JavaScript word
boundaries do not treat Cyrillic and some other non-ASCII scripts as whole words. If whole-word
matching must work for those scripts, use a locale-aware matcher in your own search logic and render
the result yourself.

## Styling

Matched ranges receive moduix's default `<mark>` styles. Use `className` for a local adjustment,
or set `--moduix-highlight-*` variables when the same treatment should be shared by several
instances.

### CSS Properties

<CssPropertiesSection properties={HighlightDocs.highlightCssProperties} />

### Styling hooks

- Every matched `<mark>` has `data-scope="highlight"` and `data-part="root"`.
- `data-slot="highlight-root"` is the stable moduix selector for each matched mark.
- There is no wrapper element, state attribute, or Ark runtime CSS variable. The output consists
  of ordinary text nodes and matched `<mark>` elements.
