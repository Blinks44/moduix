## Basic


Use `Swap` when one piece of UI needs to switch between two visual states, such as an icon that
changes after an action. Pass the current boolean to `swap`: `false` shows the `off` indicator and
`true` shows the `on` indicator.

## Anatomy

```text
Swap
├─ SwapIndicator type="off"
└─ SwapIndicator type="on"

SwapRootProvider
└─ same indicator tree connected to a useSwap() store
```

| Part                 | Role                                                               |
| -------------------- | ------------------------------------------------------------------ |
| `Swap` | Supplies the `swap` state and stacks both visual states.           |
| `SwapRootProvider`  | Connects the parts to state created with `useSwap()`.         |
| `SwapIndicator`     | Renders the `on` or `off` state selected by its `type` prop.        |

## Composition

`Swap` is presentational. Keep state, interaction, focus, and the accessible name on the surrounding
semantic control. For icon-only indicators, set `aria-hidden="true"`. Render both indicators as
direct children so they share one grid cell and the built-in recipes stay scoped to that `Swap`
instance.

`Swap` uses the `scale` animation by default. Pass `fade`, `scale`, `rotate`, or `flip` to `animation`,
or pass a custom name and define its CSS with the root's `data-animation` and the indicators' Ark
`data-state` attributes. When state must be created outside the rendered tree, pass
`useSwap()` to `SwapRootProvider` and do not render another root for the same store. With
`asChild`, provide exactly one semantic child.

## Styling

In the CSS Modules variants, `--moduix-swap-transition` controls the timing of the built-in recipes.
Tailwind variants use native utility and consumer class overrides. For a different motion, pass a
custom animation name: it disables the built-in recipes, and you can still reuse
`--moduix-swap-transition` in your own CSS.

Ark pins the layout with inline styles: the root gets `display: inline-grid`, and each indicator gets
`grid-area: 1 / 1` and `display: inline-flex`. Class-based `display` and `grid-area` overrides are
no-ops in both tracks, so change these properties through the `style` prop (for example
`style={{ display: 'grid' }}`) instead.

In the Tailwind variants the flip recipe applies `data-[animation=flip]:[perspective:24rem]` on the
root, which out-specifies a plain consumer `perspective` utility, so repeat that documented variant
(for example `data-[animation=flip]:[perspective:32rem]`) to override it.

### Styling hooks

- `Swap` uses `data-slot="swap-root"`.
- `SwapRootProvider` uses `data-slot="swap-root-provider"`.
- `SwapIndicator` uses `data-slot="swap-indicator"`.
- `animation` is exposed as `data-animation` on `Swap` and `SwapRootProvider`.
- In CSS Modules, built-in recipes target only direct `SwapIndicator` children of their root. Tailwind
  recipes read the nearest `group/swap` ancestor, so do not nest one `Swap` inside another.
- Ark adds `data-scope="swap"` and `data-part="root" | "indicator"`.
- Ark adds `data-state="open" | "closed"` to indicators. moduix uses those attributes for its
  built-in animations and for custom recipes.
