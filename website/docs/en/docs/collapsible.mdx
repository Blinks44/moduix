## Choosing the right component

Use `Collapsible` for one independent disclosure. Use `Accordion` when several related sections
need shared keyboard navigation or coordinated state.

## Basic


Use `Collapsible` with `CollapsibleTrigger`, the optional `CollapsibleIndicator`, and `CollapsibleContent` to show and hide one
content region. Put the content inside `CollapsibleBody` when you need the recommended inner
wrapper for spacing and layout.

## Anatomy

```text
Collapsible
├─ CollapsibleTrigger
│  ├─ label
│  └─ CollapsibleIndicator (optional)
└─ CollapsibleContent
   └─ CollapsibleBody
      └─ content

CollapsibleRootProvider
└─ same part tree connected to a useCollapsible() store
```

| Part                      | Role                                                               |
| ------------------------- | ------------------------------------------------------------------ |
| `Collapsible`             | Owns the open state for one disclosure.                            |
| `CollapsibleRootProvider` | Connects the parts to state created with `useCollapsible`.         |
| `CollapsibleTrigger`      | Accessible button that opens or closes the content.                 |
| `CollapsibleIndicator`    | Optional state indicator that renders a moduix chevron by default. |
| `CollapsibleContent`      | Animated region whose dimensions Ark measures.                     |
| `CollapsibleBody`         | Inner wrapper for spacing and content layout.                       |

## Composition

`Collapsible` owns state inside the root. Use `defaultOpen` for an uncontrolled disclosure; use
`open` with `onOpenChange(details)` when another part of the application owns it. In Vue, use
`v-model:open` for the same controlled contract. The callback keeps Ark's details object, so
controlled state reads `details.open`.

Use `CollapsibleRootProvider` with `useCollapsible()` from the matching framework package when the
store must be created outside the rendered tree or shared across composition boundaries. Pass that
store to `CollapsibleRootProvider` and do not render a second `Collapsible` root for the same store.

Keep padding and surface styles on `CollapsibleBody`, not `CollapsibleContent`, so Ark can measure
the animated content part correctly. `CollapsibleIndicator` is optional and defaults to the moduix
chevron.

Use `asChild` only when a consumer-owned semantic element should receive the trigger behavior; it
must remain a keyboard-accessible button. In Solid, pass a render function such as
`asChild={(props) => <button {...props()} />}`.

## Styling

Use `className` in React or `class` in Solid and Vue on exported parts for structural styles. For state-based
styles, prefer Ark data attributes such as `data-state` and `data-disabled`, together with moduix
`data-slot` selectors. Tailwind variants use native utilities and consumer classes; the component
variables below customize the CSS Modules variants. Data attributes and `data-slot` hooks are shared
by both styling tracks.

Put spacing on `CollapsibleBody`, not `CollapsibleContent`, so Ark can measure and animate the
content correctly.

### Styling hooks

- DOM parts expose `data-slot="collapsible-root"`, `collapsible-root-provider`,
  `collapsible-trigger`, `collapsible-indicator`, `collapsible-content`, and `collapsible-body`.
- Ark parts expose `data-scope="collapsible"` and `data-part` values for the root, trigger, indicator,
  and content.
- Ark exposes `data-state="open" | "closed"` on root, trigger, indicator, and content.
- Ark adds `data-collapsible` to the content part.
- `data-disabled` marks disabled trigger, indicator, and content parts.
- `data-has-collapsed-size` marks content configured with `collapsedHeight` or `collapsedWidth`.
- Content animation uses Ark `--height`, `--width`, `--collapsed-height`, and `--collapsed-width`.
