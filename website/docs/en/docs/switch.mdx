## Choosing the right component

Use `Switch` for a setting that takes effect as soon as the user changes it. A switch represents one
boolean value.

- Choose **`Switch`** for settings such as notifications, reminders, or feature flags.
- Choose **`Checkbox`** when the control represents a selection that users submit as part of a form,
  rather than an immediate setting change.
- Choose **`RadioGroup`** when users must choose one option from several mutually exclusive values.

## Anatomy

```text
Switch / Switch.Root
├─ Switch.Control
│  └─ Switch.Thumb
├─ Switch.Label
└─ hidden input (added automatically)
```

| Part                          | Role                                                                 |
| ----------------------------- | -------------------------------------------------------------------- |
| `Switch` / `Switch.Root`      | Root `label` element. Owns switch state, ids, form props, and `size`. |
| `Switch.RootProvider`         | Root `label` driven by state created with `useSwitch()`.             |
| `Switch.Control`              | Visual track and focus-ring target. Adds `Switch.Thumb` by default.  |
| `Switch.Thumb`                | Movable thumb for the default visuals or custom thumb content.       |
| `Switch.Label`                | Ark-connected label text.                                            |

`Switch` and `Switch.Root` are two names for the same root component. `Switch.Context`,
`useSwitchContext`, and `useSwitch` are exported from `@moduix/react` alongside the component.

## Composition

### Recommended composition

Use the short `<Switch>` form for ordinary cases. Put `Switch.Control` and `Switch.Label` inside it.
The root adds the hidden form input automatically, but it does not add a visible control or label.

`Switch.Control` adds the default `Switch.Thumb` when it has no children. Add `Switch.Thumb`
explicitly when the thumb needs custom content or styling.

### When to go custom

Use `asChild` when you need to provide the root DOM element yourself. Its direct child must be a
single label-compatible element so the switch keeps a valid accessible name.

Use `Switch.Context` or `useSwitchContext` when surrounding UI needs to read the switch state. Use
`useSwitch` with `Switch.RootProvider` when the state should be created and controlled outside the
rendered switch tree. Do not render `Switch` and `Switch.RootProvider` for the same state instance.

### Default props

| Prop        | Default     | Notes                                        |
| ----------- | ----------- | -------------------------------------------- |
| `size`      | `md`        | moduix option: `xs`, `sm`, `md`, `lg`, `xl`. |
| `value`     | `on`        | Value submitted by the hidden form input.    |
| `children`  | `undefined` | Compose the visible parts explicitly.        |
| `className` | `undefined` | Applied to the root `label` element.         |

### Behavioral notes

- Use `defaultChecked` for uncontrolled mode. Use `checked` with `onCheckedChange(details)` for
  controlled mode.
- `onCheckedChange` receives a details object. Use `details.checked` as the next boolean state.
- The root always adds the native form input. Set `name`, `value`, `form`, and `required` to control
  its form participation. For an uncontrolled switch, resetting the form restores its initial state.
- `readOnly` preserves the current state and sets `aria-readonly="true"` on the native control.
- The track and thumb respect `prefers-reduced-motion` by disabling their transitions.
- Use `Switch.Context` or `useSwitchContext` for advanced state reads. Use `useSwitch` with
  `Switch.RootProvider` when the state owner lives outside the switch tree.
- With `asChild`, the child must remain a single semantic element that is compatible with `label`.

### Styling hooks

- `Switch` and `Switch.RootProvider` expose `data-slot="switch-root"` /
  `data-slot="switch-root-provider"` and set the moduix `data-size` attribute.
- `Switch.Control` exposes `data-slot="switch-control"` and receives Ark state attributes such as
  `data-state`, `data-focus-visible`, `data-hover`, `data-active`, `data-disabled`, `data-readonly`,
  `data-invalid`, and `data-required`.
- `Switch.Thumb` exposes `data-slot="switch-thumb"` and receives the same Ark state attributes for
  thumb movement and custom content styling.
- `Switch.Label` exposes `data-slot="switch-label"` for typography overrides.
- The native form input exposes `data-slot="switch-hidden-input"` for inspection, but it should
  remain visually hidden by Ark.
