A basic switch has a root, a visual control, a label, and an explicit `SwitchHiddenInput` for native
interaction and form behavior. The control receives a default thumb when it has no children.

## Choosing the right component

Use `Switch` for a setting that takes effect as soon as the user changes it. A switch represents one
boolean value.

- Choose **`Switch`** for settings such as notifications, reminders, or feature flags.
- Choose **`Checkbox`** when the control represents a selection that users submit as part of a form,
  rather than an immediate setting change.
- Choose **`RadioGroup`** when users must choose one option from several mutually exclusive values.

## Composition

Render `SwitchHiddenInput` explicitly inside `Switch` or `SwitchRootProvider`, including when the
switch is not in a form. It provides the native input that Ark uses for focus, keyboard interaction,
accessibility, and form submission.

When `SwitchControl` has no children, it adds the default `SwitchThumb`. Add `SwitchThumb`
explicitly only when it needs custom content or styling.

Use `SwitchContext` or `useSwitchContext` when nearby UI needs to read the switch state. Use
`useSwitch` with `SwitchRootProvider` when the state must be created outside the rendered switch
tree. Do not render `Switch` and `SwitchRootProvider` for the same state instance.

With `asChild`, provide one semantic element compatible with `label` so Ark can keep the switch
accessible.

## Anatomy

```text
Switch
├─ SwitchControl
│  └─ SwitchThumb
├─ SwitchLabel
└─ SwitchHiddenInput (explicit)
```

| Part                          | Role                                                                 |
| ----------------------------- | -------------------------------------------------------------------- |
| `Switch`                 | Root `label` element. Owns switch state, ids, form props, and `size`. |
| `SwitchHiddenInput`           | Native Ark form control; compose explicitly as described below.      |
| `SwitchRootProvider`          | Root `label` driven by state created with `useSwitch()`.             |
| `SwitchControl`               | Visual track and focus-ring target. Adds `SwitchThumb` by default.  |
| `SwitchThumb`                 | Movable thumb for the default visuals or custom thumb content.       |
| `SwitchLabel`                 | Ark-connected label text.                                            |

`Switch` is the root component. `SwitchContext`, `useSwitchContext`, and `useSwitch` are exported
from `@moduix/react` alongside the component. The Vue exports are available from
`@moduix/vue` and `@moduix/vue/switch`.
The matching Solid exports are available from `@moduix/solid` and `@moduix/solid/switch`.

## Styling

Style `Switch` with `className` in React or `class` in Solid and Vue, public `data-slot` hooks, Ark state
attributes, and the public `--moduix-switch-*` CSS variables shown below. Tailwind variants use
utilities and consumer classes; the variables below apply to CSS Modules, while data attributes are
shared by both approaches.

The thumb is sized and placed from the control box, so a `width` or `height` override on
`SwitchControl` (a class in CSS Modules, `w-*` and `h-*` utilities in Tailwind) keeps it square and
flush with both ends. Right-to-left direction comes from Ark: with an RTL [`LocaleProvider`](/docs/rtl),
Ark writes `dir` on every part and the checked thumb moves to the inline end.

### Styling hooks

| Part | `data-slot` |
| --- | --- |
| `Switch` | `switch-root` |
| `SwitchRootProvider` | `switch-root-provider` |
| `SwitchControl` | `switch-control` |
| `SwitchThumb` | `switch-thumb` |
| `SwitchLabel` | `switch-label` |

- `Switch` and `SwitchRootProvider` expose `data-slot="switch-root"` /
  `data-slot="switch-root-provider"` and set the moduix `data-size` attribute.
- `SwitchControl` exposes `data-slot="switch-control"` and receives Ark state attributes such as
  `data-state`, `data-focus-visible`, `data-hover`, `data-active`, `data-disabled`, `data-readonly`,
  `data-invalid`, and `data-required`.
