## Basic

`Frame` renders its children inside the iframe document. Always provide a descriptive `title`, because it becomes the
iframe's accessible name. The example also passes a `<style>` element through `head`, since styles from the host
document do not cross the iframe boundary.

<Example name="frame/basic" />

## Content styles and size

The `head` prop accepts JSX content (a snippet in Svelte) and inserts it into the iframe's `<head>`. Use it for embedded styles, fonts, or
metadata. Styles needed by the embedded UI must also be loaded through this prop.

`Frame` observes the mounted content and writes its size to the iframe as `--width` and `--height` in pixels. Use
`block-size: var(--height, 10rem)` when the iframe should grow with its content. The `--width` variable can be used in
the same way for inline size.

## Lifecycle callbacks

Use `onMount` and `onUnmount` for resources created by the embedded experience. Both callbacks are called without
arguments. A ref gives the application access to the iframe document when setup needs to interact with it; in Svelte, use `bind:ref`.

Only inject scripts that your application controls. Prefer `head` for styles and metadata.

## Static HTML documents

Use `srcDoc` in React or `srcdoc` in Solid, Vue, and Svelte when the iframe should start from a complete HTML document instead of
rendered framework children. These are the native spellings of the same iframe attribute in each framework.

For untrusted HTML, set the native `sandbox` attribute and grant only the permissions the content needs. Keep
`allow-scripts` and `allow-same-origin` out of the same sandbox for untrusted content.
