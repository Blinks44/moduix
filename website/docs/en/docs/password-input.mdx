## Choosing the right component

Use `PasswordInput` when a sensitive value should stay hidden by default but can be shown when
needed.

- Choose **`Input`** for plain text-like fields without a visibility toggle.
- Choose **`PasswordInput`** for passwords, API keys, and other secure strings.
- Choose **`InputGroup`** when the field needs a custom inline action that is not password visibility.

## Basic


Use `PasswordInput` as the root and add `PasswordInputLabel` with `PasswordInputField`. The field
renders the input and visibility button with moduix's default icons while Ark handles state and
accessibility.

## Anatomy

```text
PasswordInput
├─ PasswordInputLabel
└─ PasswordInputField
   └─ PasswordInputControl
      ├─ PasswordInputInput
      └─ PasswordInputVisibilityTrigger
         └─ PasswordInputIndicator

PasswordInputRootProvider
└─ same tree connected to a usePasswordInput() state object
```

| Part                                   | Role                                                                           |
| -------------------------------------- | ------------------------------------------------------------------------------ |
| `PasswordInput` | Root part that owns password visibility and field state.                      |
| `PasswordInputRootProvider`           | Connects the parts to state created with `usePasswordInput()`.                |
| `PasswordInputContext`                | Render-prop access to the root state.                                         |
| `PasswordInputLabel`                  | Labels the input and reflects required, disabled, invalid, and read-only states. |
| `PasswordInputField`                  | Convenience composition of the control, input, visibility trigger, and indicator. |
| `PasswordInputControl`                | Groups the input and visibility trigger together.                              |
| `PasswordInputInput`                  | Native input whose `type` switches between `password` and `text`.             |
| `PasswordInputVisibilityTrigger`      | Button that toggles visibility.                                                |
| `PasswordInputIndicator`              | Shows content for the visible or hidden state; moduix supplies default icons.  |

## Composition

`PasswordInputField` is the convenience composition for the control, input, visibility trigger,
and indicator. Replace it with `PasswordInputControl`, `PasswordInputInput`,
`PasswordInputVisibilityTrigger`, and `PasswordInputIndicator` when the
structure, input props, icons, or part-level styling must differ.

Keep visibility state on the root. Use `defaultVisible` for an uncontrolled initial state, or pair
`visible` with `onVisibilityChange(details)` when application state owns visibility. Use
`usePasswordInput()` with `PasswordInputRootProvider` when a sibling or external control needs the
same state.

Pass value props such as `value`, `defaultValue`, `placeholder`, and `onInput` or `onChange` to
`PasswordInputInput`. The native input participates in form submission and reset, so pass `name`
to `PasswordInput`; this component does not render a separate `HiddenInput`.

`"current-password"` for sign-in forms.

### Ignore Password Managers

Use `ignorePasswordManagers` for API keys or generated secrets instead of login credentials. The
option asks supported password managers not to add their overlays to the field. It currently works
with 1Password, LastPass, Bitwarden, Dashlane, and Proton Pass.

## Styling

CSS Modules packages expose three variables: `--moduix-password-input-width`,
`--moduix-password-input-height`, and `--moduix-password-input-radius`. Colors, borders, spacing,
typography, and the focus ring come from foundation tokens; override them with a class on the part.
Tailwind packages use utility classes and consumer classes instead.

### Styling hooks

- The root and root provider expose `data-slot="password-input-root"` and
  `data-slot="password-input-root-provider"`.
- Ark parts keep `data-scope="password-input"` and `data-part` values for `root`, `label`, `control`,
  `input`, `visibility-trigger`, and `indicator`.
- Use `data-state="visible" | "hidden"` on the input, trigger, and indicator for visibility styles.
  Use `data-disabled`, `data-invalid`, `data-readonly`, and `data-required` where Ark provides them.
  The control receives the disabled, invalid, and read-only state attributes used by the field shell.
- The root mirrors `size` as `data-size`. A disabled `PasswordInput` inside a disabled `Field` or
  `Fieldset` is not dimmed a second time.
