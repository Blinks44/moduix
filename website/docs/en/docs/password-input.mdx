## Choosing the right component

Use `PasswordInput` when a sensitive value should stay hidden by default but can be shown when
needed.

- Choose **`Input`** for plain text-like fields without a visibility toggle.
- Choose **`PasswordInput`** for passwords, API keys, and other secure strings.
- Choose **`InputGroup`** when the field needs a custom inline action that is not password visibility.

## Anatomy

```tsx
<PasswordInput>
  <PasswordInput.Label />
  <PasswordInput.Field />
</PasswordInput>
```

For a custom structure, replace `PasswordInput.Field` with the individual Ark parts:

```tsx
<PasswordInput>
  <PasswordInput.Label />
  <PasswordInput.Control>
    <PasswordInput.Input />
    <PasswordInput.VisibilityTrigger>
      <PasswordInput.Indicator />
    </PasswordInput.VisibilityTrigger>
  </PasswordInput.Control>
</PasswordInput>
```

| Part                                   | Role                                                                           |
| -------------------------------------- | ------------------------------------------------------------------------------ |
| `PasswordInput` / `PasswordInput.Root` | Manages password visibility and field state.                                    |
| `PasswordInput.RootProvider`           | Renders the root from a `usePasswordInput` state object.                        |
| `PasswordInput.Label`                  | Labels the input and reflects required, disabled, invalid, and read-only states. |
| `PasswordInput.Field`                  | Renders the default control, input, visibility trigger, and indicator.          |
| `PasswordInput.Control`                | Groups the input and visibility trigger together.                               |
| `PasswordInput.Input`                  | Native input part whose `type` switches between `password` and `text`.          |
| `PasswordInput.VisibilityTrigger`      | Button that toggles visibility.                                                 |
| `PasswordInput.Indicator`              | Shows content for the visible or hidden state; moduix supplies default icons.   |

## Composition

### Recommended composition

Use `PasswordInput.Field` for the default control, input, visibility trigger, and indicator. Pass
root options such as visibility, form state, IDs, translations, and password-manager settings to
`PasswordInput`.

### When to go custom

Use `Control`, `Input`, `VisibilityTrigger`, and `Indicator` directly when you need a different
structure, different icons, or styling for individual parts. Use `asChild` only when a part needs to
render a specific semantic element.

### Default props

| Prop or part                     | Default              | Notes                                                        |
| -------------------------------- | -------------------- | ------------------------------------------------------------ |
| `autoComplete`                   | `"current-password"` | Applied to the input; defaults to `current-password`.        |
| `defaultVisible`                 | not set              | The field starts hidden; this sets its initial visibility for uncontrolled usage. |
| `visible`                        | not set              | Controls visibility when provided.                           |
| `PasswordInput.Field`            | -                    | Default composition of visible parts; forwards control props. |
| `onVisibilityChange`             | -                    | Called with Ark details; read `details.visible`.             |
| `translations.visibilityTrigger` | Ark default          | Function that returns a localized label for the visibility button. |
| `ignorePasswordManagers`         | `false`              | Adds hints that help supported password managers ignore the field. |

### Behavioral notes

- Set `visible` and `onVisibilityChange(details)` to control visibility.
- Set native `value`, `defaultValue`, `placeholder`, and `onChange` on `PasswordInput.Input` to
  control or initialize the field value.
- Pass root props such as `name`, `required`, `disabled`, `readOnly`, `invalid`, `ids`, and
  `translations` to `PasswordInput`.
- `PasswordInput.Input` is a native input, so it participates in form submission and reset. Set
  `name` on `PasswordInput`; this primitive does not render a separate `HiddenInput`.
- Use `usePasswordInput` with `PasswordInput.RootProvider` when another component needs the same
  visibility state outside the rendered tree.
- `PasswordInput.Input`, `PasswordInput.VisibilityTrigger`, and `PasswordInput.Indicator` expose
  `data-state="visible" | "hidden"` for styling.

### Styling hooks

- The root and root provider expose `data-slot="password-input-root"` and
  `data-slot="password-input-root-provider"`.
- Ark parts keep `data-scope="password-input"` and `data-part` values for `root`, `label`,
  `control`, `input`, `visibility-trigger`, and `indicator`.
- Use `data-state="visible" | "hidden"` on the input, trigger, and indicator for visibility styles.
  Use `data-disabled`, `data-invalid`, `data-readonly`, and `data-required` on the parts where Ark
  provides them. The control receives the disabled, invalid, and read-only state attributes used by
  the field shell.
- Ark does not expose component-specific CSS variables at runtime; moduix adds
  `--moduix-password-input-*` variables for visual defaults.
