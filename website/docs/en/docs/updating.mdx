# Update and migration

Update Moduix according to where the component source lives. Package consumers update dependencies;
registry consumers review and merge source changes into their application.

| Distribution | Source location | Update method |
| --- | --- | --- |
| npm package | `node_modules` | Update the matching Moduix and Ark UI packages. |
| shadcn registry | Application repository | Preview the registry diff, then merge it with local changes. |

If you are moving an existing shadcn application to Moduix, start with
[Migrate from shadcn](/docs/migrate-from-shadcn).

## Identify the installed adapter

Keep framework and styling choices explicit:

| Runtime | CSS Modules | Tailwind CSS |
| --- | --- | --- |
| React | `@moduix/react` | `@moduix/react-tailwind` |
| Solid | `@moduix/solid` | `@moduix/solid-tailwind` |

Do not update a similarly named adapter that the application does not use. Tailwind packages may have
a smaller component catalog while ports are still in progress.

Ark UI is a peer dependency. Before a major update, check the compatible range in the release notes
instead of upgrading both packages blindly. Review the lockfile after installation.

## Update registry components

Registry components are copied into the application and do not change with package updates. Select
the registry namespace that matches both axes:

| Runtime | CSS Modules registry | Tailwind registry |
| --- | --- | --- |
| React | `@moduix-react` | `@moduix-react-tailwind` |
| Solid | `@moduix-solid` | `@moduix-solid-tailwind` |

Preview a component before changing local files: `view` prints the upstream item, while `add
--dry-run` and `add --diff` show what an update would write:

<PackageManagerTabs command="shadcn@latest view @moduix-react/button" dlx />

<PackageManagerTabs command="shadcn@latest add @moduix-react/button --dry-run" dlx />

<PackageManagerTabs command="shadcn@latest add @moduix-react/button --diff" dlx />

Replace the namespace with the installed adapter and `button` with the item being updated. The diff
may include shared foundation files and registry dependencies, so review the complete result.

After reviewing it, run the update from a branch or clean working tree:

<PackageManagerTabs command="shadcn@latest add @moduix-react/button" dlx />

Do not use `--overwrite` until you have decided how to preserve local edits. Merge upstream behavior,
accessibility, and styling changes with the application's product-specific changes.

## Update styles and presets

Package styles and presets update with their package. Registry-owned foundation and preset files must
be reviewed like any other registry item.

Keep the foundation stylesheet imported once from the path created by your registry configuration:

```tsx
import '@/lib/moduix/styles/style.css';
```

Application overrides must load after the foundation and preset so the cascade remains intentional.
When a release changes tokens, density, colors, or motion, review [Themes](/docs/themes),
[Tokens](/docs/tokens), and [Animations](/docs/animations).

## Verify the update

- Review the package manifest and lockfile together.
- Run the application's formatter, lint, typecheck, and tests.
- Exercise the components and interactions named in the changelog.
- Check keyboard behavior, focus return, portals, and reduced motion when relevant.
- Compare local registry changes with the complete upstream diff before shipping.
