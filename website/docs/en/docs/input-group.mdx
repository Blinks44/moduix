## API Reference

`InputGroup` is a moduix composition, not an Ark UI primitive. It combines Ark factory elements
with the Ark-backed moduix `Input` and `Button` components. The composition follows Ark's guidance
on [composition](https://ark-ui.com/docs/guides/composition), [styling](https://ark-ui.com/docs/guides/styling),
and [refs](https://ark-ui.com/docs/guides/ref).

## Choosing the right component

- Use **`Input`** for an ordinary single-line input.
- Use **`InputGroup`** when the input needs inline content such as a prefix, suffix, or action.
- Use **`PasswordInput`** for a password field with a visibility toggle.
- Use **`NumberInput`** when you need numeric behavior and step controls.
- Use **`Textarea`** for multi-line content.
- Use **`Editable`** when text should appear as a value first and switch into edit mode on demand.

## Anatomy

```text
InputGroup
├─ InputGroupAddon (optional)
├─ InputGroupInput or InputGroupTextarea
├─ InputGroupText (optional)
├─ InputGroupButton (optional)
└─ InputGroupClearTrigger (optional)
```

| Part                             | Role                                                        |
| -------------------------------- | ----------------------------------------------------------- |
| `InputGroup`                    | Passive layout wrapper with shared styling and size context. |
| `InputGroupInput`               | Native `<input>` that owns the form value and field state.  |
| `InputGroupTextarea`            | Native `<textarea>` for multi-line values; use it instead of `InputGroupInput`. |
| `InputGroupAddon`               | Filled prefix or suffix.                                   |
| `InputGroupText`                | Inline text without a fill.                                |
| `InputGroupButton`              | Action button associated with the input.                   |
| `InputGroupClearTrigger` | Clear action with a default close icon; clearing is handled by the application. |

## Composition

Keep exactly one `InputGroupInput` in each group. The nested input owns the value, form behavior,
validation state, and input ref, so controlled or uncontrolled props belong there, while labels and
validation messages belong on `Field`. The root `size` is inherited by `InputGroupInput` and
`InputGroupButton`; grouped buttons default to `type="button"` and do not inherit `disabled` from
`Field`. In React, use `onChange`; in Solid, use `onInput`; in Vue, use `v-model` for a controlled
input.

Use `InputGroupAddon` and `InputGroupText` for non-interactive inline content and `InputGroupButton` for actions. The root,
`InputGroupAddon`, and `InputGroupText` support `asChild` with one semantic child that accepts the merged props and ref.
Use `Editable` when the value should switch between read and edit modes.

Set `align="block"` on `InputGroupAddon` or `InputGroupText` to place it as a full-width row
above or below the control instead of beside it; its position follows the DOM order. A group with
a block addon holds one control and only block addons, so put inline content inside the block
addon. Use a regular `Button` there: `InputGroupButton` stretches to the full group height and is
meant for actions beside the control.

### Textarea

Use `InputGroupTextarea` for multi-line input, such as a message composer. It renders the moduix
`Textarea` without its border, inherits the group size unless it gets its own `size`, and keeps
Ark Field state and `autoresize`. Add a toolbar with `InputGroupAddon align="block"` and a regular `Button`.

<Example name="input-group/textarea" />

### Clear Trigger

Use `InputGroupClearTrigger` for a clear action with a default close icon and accessible label.
It inherits the group size and defaults to `type="button"`. Handle value clearing and focus in
`onClick` (Vue: `@click`); render it only when the value is non-empty. It does not clear or hide
automatically. Disable it explicitly for disabled or read-only fields. Override `aria-label`
for your language, or use `aria-labelledby`; children replace the default icon.
The compact hover surface matches the clear buttons in Select and Combobox.

<Example name="input-group/clear-trigger" />

## Styling

Use `className` in React, `class` in Solid, or `class` in Vue on exported parts for structural styles. For state-based
styles, prefer Ark data attributes such as `data-invalid`, `data-disabled`, and `data-readonly`,
together with moduix `data-slot` selectors. Tailwind variants use native utilities and consumer
classes. CSS Modules variants build on foundation tokens and expose only the three variables below;
override colors, padding, and typography with a plain class on the part, which wins over the layered
component styles. Data attributes and `data-slot` hooks are shared by both styling tracks.

### Styling hooks

- `data-slot="input-group-root"` and `data-size="xs" | "sm" | "md" | "lg" | "xl"` on the root
- `data-scope="input-group"` and `data-part="root" | "addon" | "text"` on the Ark factory parts
- `data-slot="input-root"` plus Ark Field input state attributes
- `data-slot="input-group-addon"`
- `data-slot="input-group-clear-trigger"`
- `data-slot="input-group-text"`
- `data-align="inline" | "block"` on `InputGroupAddon` and `InputGroupText`
- `data-slot="textarea-root"` plus Ark Field textarea state attributes on `InputGroupTextarea`
- `data-slot="input-group-button"` on the grouped action button
- Nested `data-invalid`, `aria-invalid="true"`, and `data-disabled`/`:disabled` states are reflected through `:has(...)` on the root

Component-owned `data-slot`, `data-scope`, `data-part`, and root `data-size` hooks stay stable when
consumer props are supplied. `className` in React and `class` in Solid and Vue merge with the component
styles.
