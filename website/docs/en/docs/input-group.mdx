## API Reference

Ark UI does not ship a dedicated input-group primitive. moduix builds this component with Ark's official
[factory](https://ark-ui.com/docs/guides/composition#the-ark-factory) and follows Ark's guidance on
[composition](https://ark-ui.com/docs/guides/composition), [styling](https://ark-ui.com/docs/guides/styling), and
[refs](https://ark-ui.com/docs/guides/ref).

## Choosing the right component

- Choose **`Input`** for a plain single-line field.
- Choose **`InputGroup`** for inline prefixes, suffixes, text, or actions.
- Choose **`Editable`** for text that starts read-only and becomes editable on demand.
- Choose **`PasswordInput`** for the existing composition that controls password visibility.
- Choose **`NumberInput`** when the field needs numeric behavior.

## Anatomy

```text
InputGroup / InputGroup.Root
├─ InputGroup.Addon (optional)
├─ InputGroup.Input
├─ InputGroup.Text (optional)
└─ InputGroup.Button (optional)
```

| Part                             | Role                                                         |
| -------------------------------- | ------------------------------------------------------------ |
| `InputGroup` / `InputGroup.Root` | Ark factory root for shared layout, border, focus, and size. |
| `InputGroup.Input`               | Ark-backed native input that owns the form value.           |
| `InputGroup.Addon`               | Filled prefix or suffix.                                    |
| `InputGroup.Text`                | Inline text without a fill.                                 |
| `InputGroup.Button`              | Native action button with grouped visual defaults.          |

## Composition

### Recommended composition

Use exactly one `InputGroup.Input`. Place addons, text, or buttons before or after it. Wrap the
group in `Field` when the field needs a label, helper text, error text, ids, or shared state.

`InputGroup.Input` uses native input events. Control its value with `value` and `onChange(event)`.
The root `size` is inherited by the input and button.

### When to go custom

`InputGroup`, `InputGroup.Addon`, and `InputGroup.Text` support Ark's `asChild`. The root child must
remain a container; addon and text children should stay presentational and accept forwarded props
and refs.

Use `InputGroup.Button` for actions instead of making an addon interactive. Add `role="group"` and
an accessible name only when the standalone composition needs group semantics.

### Default props

| Part / prop                 | Default             |
| --------------------------- | ------------------- |
| `InputGroup.size`           | `md`                |
| `InputGroup.Input.size`     | inherited from root |
| `InputGroup.Button.size`    | inherited from root |
| `InputGroup.Button.variant` | `ghost`             |
| `InputGroup.Button.type`    | `button`            |

### Behavioral notes

- The input `ref` targets the real `HTMLInputElement`.
- The root does not own the value or validation, provide ARIA ids or context hooks, or render a `HiddenInput`.
- Root styling for invalid, disabled, and read-only states derives from the nested input state.

### Styling hooks

- `data-slot="input-group-root"` and `data-size`
- `data-scope="input-group"` and `data-part="root" | "addon" | "text"` on Ark factory parts
- `data-slot="input-root"` plus Ark Field input state attributes
- `data-slot="input-group-addon"`
- `data-slot="input-group-text"`
- `data-slot="input-group-button"` on the group's action button
- nested `data-invalid`, `aria-invalid`, `disabled`, and `readOnly` state through root `:has(...)`

Component-owned `data-slot`, `data-scope`, `data-part`, and root `data-size` hooks stay stable when
consumer props are supplied. `className` always merges with the component styles.
