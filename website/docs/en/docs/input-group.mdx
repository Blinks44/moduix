## API Reference

`InputGroup` is a moduix composition, not an Ark UI primitive. It combines Ark factory elements
with the Ark-backed moduix `Input` and `Button` components. The composition follows Ark's guidance
on [composition](https://ark-ui.com/docs/guides/composition), [styling](https://ark-ui.com/docs/guides/styling),
and [refs](https://ark-ui.com/docs/guides/ref).

## Choosing the right component

- Use **`Input`** for an ordinary single-line input.
- Use **`InputGroup`** when the input needs inline content such as a prefix, suffix, or action.
- Use **`PasswordInput`** for a password field with a visibility toggle.
- Use **`NumberInput`** when you need numeric behavior and step controls.
- Use **`Textarea`** for multi-line content.
- Use **`Editable`** when text should appear as a value first and switch into edit mode on demand.

## Anatomy

```text
InputGroup
├─ InputGroupAddon (optional)
├─ InputGroupInput
├─ InputGroupText (optional)
└─ InputGroupButton (optional)
```

| Part                             | Role                                                        |
| -------------------------------- | ----------------------------------------------------------- |
| `InputGroup`                    | Passive layout wrapper with shared styling and size context. |
| `InputGroupInput`               | Native `<input>` that owns the form value and field state.  |
| `InputGroupAddon`               | Filled prefix or suffix.                                   |
| `InputGroupText`                | Inline text without a fill.                                |
| `InputGroupButton`              | Action button associated with the input.                   |

## Composition

Keep exactly one `InputGroupInput` in each group. The nested input owns the value, form behavior,
validation state, and input ref, so controlled or uncontrolled props belong there, while labels and
validation messages belong on `Field`. The root `size` is inherited by `InputGroupInput` and
`InputGroupButton`; grouped buttons default to `type="button"` and do not inherit `disabled` from
`Field`.

Use `InputGroupAddon` and `InputGroupText` for non-interactive inline content and `InputGroupButton` for actions. The root,
`InputGroupAddon`, and `InputGroupText` support `asChild` with one semantic child that accepts the merged props and ref.
Use `Editable` when the value should switch between read and edit modes.

## Styling

Use `className` in React or `class` in Solid on exported parts for structural styles. For state-based
styles, prefer Ark data attributes such as `data-invalid`, `data-disabled`, and `data-readonly`,
together with moduix `data-slot` selectors. Tailwind variants use native utilities and consumer
classes; the variables below customize the CSS Modules variants. Data attributes and `data-slot`
hooks are shared by both styling tracks.

### Styling hooks

- `data-slot="input-group-root"` and `data-size="xs" | "sm" | "md" | "lg" | "xl"` on the root
- `data-scope="input-group"` and `data-part="root" | "addon" | "text"` on the Ark factory parts
- `data-slot="input-root"` plus Ark Field input state attributes
- `data-slot="input-group-addon"`
- `data-slot="input-group-text"`
- `data-slot="input-group-button"` on the grouped action button
- Nested `data-invalid`, `aria-invalid="true"`, `data-disabled`/`:disabled`, and `data-readonly`/`:read-only` states are reflected through `:has(...)` on the root

Component-owned `data-slot`, `data-scope`, `data-part`, and root `data-size` hooks stay stable when
consumer props are supplied. `className` in React and `class` in Solid merge with the component
styles.
