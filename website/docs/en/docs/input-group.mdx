## API Reference

`InputGroup` is a moduix composition, not an Ark UI primitive. It combines Ark factory elements
with the Ark-backed moduix `Input` and `Button` components. The composition follows Ark's guidance
on [composition](https://ark-ui.com/docs/guides/composition), [styling](https://ark-ui.com/docs/guides/styling),
and [refs](https://ark-ui.com/docs/guides/ref).

## Choosing the right component

- Use **`Input`** for an ordinary single-line input.
- Use **`InputGroup`** when the input needs inline content such as a prefix, suffix, or action.
- Use **`PasswordInput`** for a password field with a visibility toggle.
- Use **`NumberInput`** when you need numeric behavior and step controls.
- Use **`Textarea`** for multi-line content.
- Use **`Editable`** when text should appear as a value first and switch into edit mode on demand.

## Anatomy

```text
InputGroup / InputGroup.Root
├─ InputGroup.Addon (optional)
├─ InputGroup.Input
├─ InputGroup.Text (optional)
└─ InputGroup.Button (optional)
```

| Part                             | Role                                                        |
| -------------------------------- | ----------------------------------------------------------- |
| `InputGroup` / `InputGroup.Root` | Shared layout, border, focus ring, and size context.       |
| `InputGroup.Input`               | Native `<input>` that owns the form value.                  |
| `InputGroup.Addon`               | Filled prefix or suffix.                                   |
| `InputGroup.Text`                | Inline text without a fill.                                |
| `InputGroup.Button`              | Action button associated with the input.                   |

## Composition

### Recommended composition

Render exactly one `InputGroup.Input`. Place `Addon`, `Text`, or `Button` before or after it. Wrap
the group in `Field` when the input needs a label, helper text, error text, generated ids, or shared
state.

`InputGroup.Input` remains a native input. For a controlled input, pass `value` and update it from
`onChange(event)`. For an uncontrolled input, use `defaultValue`. The root `size` is inherited by
`InputGroup.Input` and `InputGroup.Button`; the other parts follow the same visual density.

### When to go custom

The root, `InputGroup.Addon`, and `InputGroup.Text` support Ark's `asChild`. Pass exactly one child
when using it. The root child must remain a semantic layout container. An addon or text child should
remain presentational and accept the merged props and ref.

Use `InputGroup.Button` for actions instead of making an addon interactive. Add `role="group"` and
an accessible name only when the standalone composition needs group semantics.

### Default props

| Part / prop                 | Default             |
| --------------------------- | ------------------- |
| `InputGroup.size`           | `md`                |
| `InputGroup.Input.size`     | inherited from root |
| `InputGroup.Button.size`    | inherited from root |
| `InputGroup.Button.variant` | `ghost`             |
| `InputGroup.Button.type`    | `button`            |

### Behavioral notes

- The `InputGroup.Input` ref points to the real `HTMLInputElement`.
- The root is a passive composition wrapper. It does not own the value or validation, generate ARIA ids, provide context hooks, or render a `HiddenInput`.
- Root styling for invalid, disabled, and read-only states derives from the nested input state.
- Buttons do not inherit `disabled` from `Field`; disable each action explicitly when it should be unavailable.

### Styling hooks

- `data-slot="input-group-root"` and `data-size="xs" | "sm" | "md" | "lg" | "xl"` on the root
- `data-scope="input-group"` and `data-part="root" | "addon" | "text"` on the Ark factory parts
- `data-slot="input-root"` plus Ark Field input state attributes
- `data-slot="input-group-addon"`
- `data-slot="input-group-text"`
- `data-slot="input-group-button"` on the grouped action button
- Nested `data-invalid`, `aria-invalid="true"`, `data-disabled`/`:disabled`, and `data-readonly`/`:read-only` states are reflected through `:has(...)` on the root

Component-owned `data-slot`, `data-scope`, `data-part`, and root `data-size` hooks stay stable when
consumer props are supplied. `className` always merges with the component styles.
