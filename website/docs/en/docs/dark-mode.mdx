# Dark mode

moduix uses its light token set by default. Add
`data-moduix-color-scheme="dark"` to an element to apply the dark token set to that element and
its descendants. Import the foundation stylesheet once:

```tsx
import '@moduix/react/style.css';
```

## Set the scheme on the document root

For an application-wide theme, put the resolved color scheme on `<html>`. Set
`data-moduix-color-scheme="dark"` for dark mode and `data-moduix-color-scheme="light"` for light
mode. moduix does not track the user's preference, store it, or require a theme provider. Your
application remains in control of how the preference is selected and persisted.

```html
<!-- Dark theme -->
<html data-moduix-color-scheme="dark"></html>
```

Components rendered into a portal, such as Dialog, Popover, and Select, inherit the tokens from
`<html>` as well.

If your app renders on the server, set the attribute before the first paint with your framework's
early theme mechanism. This prevents a brief flash of the light theme while client-side JavaScript
applies a saved preference.

## Add a switch

Keep the user's explicit choice in your application and update the document attribute. If no choice
has been saved, use `matchMedia` to follow the operating-system preference.

```tsx
type ColorScheme = 'light' | 'dark';

export function applyColorScheme(scheme: ColorScheme) {
  document.documentElement.dataset.moduixColorScheme = scheme;
}

export function resolveColorScheme(): ColorScheme {
  const saved = localStorage.getItem('moduix-color-scheme');
  if (saved === 'light' || saved === 'dark') return saved;

  return matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light';
}

export function saveColorScheme(scheme: ColorScheme) {
  localStorage.setItem('moduix-color-scheme', scheme);
  applyColorScheme(scheme);
}
```

Run the equivalent of `applyColorScheme(resolveColorScheme())` in your framework's early theme
script, before the first paint. Have the visible switch call `saveColorScheme` with the value chosen
by the user. This keeps the operating-system preference as the default until the user makes an
explicit choice. Give the switch an accessible name that describes the action, such as
`Switch to dark mode`.

## Use a preset

Color mode and visual presets are separate layers, so you can use both at once. Keep
`data-moduix-color-scheme` and `data-moduix-theme` on the same root element so regular and portalled
components use the same palette, density, radius, and focus tokens.

```tsx
import '@moduix/react/style.css';
import '@moduix/react/presets/dense.css';
```

<div style={{ height: '1rem' }} aria-hidden="true" />

```html
<html data-moduix-color-scheme="dark" data-moduix-theme="dense"></html>
```

Changing the color mode does not change the preset's density. The selected preset remains active in
both modes. See [Themes](/docs/themes) for the preset comparison and custom theme pattern.

## Scope a surface

To apply dark tokens only to a preview or embedded surface, place
`data-moduix-color-scheme="dark"` on a regular wrapper:

```tsx
import { Card } from '@moduix/react/card';
import '@moduix/react/style.css';

export function SettingsPreview() {
  return (
    <section data-moduix-color-scheme="dark">
      <Card>Dark preview</Card>
    </section>
  );
}
```

This is useful for a settings preview or an embedded widget. Portalled content renders outside the
wrapper, so it cannot inherit the wrapper's tokens. If the surface opens overlays, put the attribute
on the portal container, `<body>`, or `<html>` instead.

## Customize tokens

To customize the palette in both schemes, override the same base color tokens in `:root` and
`[data-moduix-color-scheme='dark']`. Semantic aliases such as `--moduix-color-background`,
`--moduix-color-foreground`, and `--moduix-color-border` point to these base tokens, so components
pick up the values consistently across the library.

Load your override stylesheet after `style.css`:

```css
:root {
  --moduix-background: oklch(0.99 0.004 285);
  --moduix-primary: oklch(0.5 0.18 260);
}

[data-moduix-color-scheme='dark'] {
  --moduix-background: oklch(0.16 0.01 285);
  --moduix-primary: oklch(0.76 0.13 260);
}
```

This example changes only the background and primary color. Any token you do not override keeps its
built-in value. Use [Tokens](/docs/tokens) for the system token reference and component pages for
local visual overrides.
