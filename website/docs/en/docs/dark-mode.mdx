# Dark mode

moduix ships light and dark semantic tokens powered by CSS `light-dark()`. By default `:root` sets
`color-scheme: light dark`, so components automatically follow the operating-system color scheme
without any JavaScript or provider. To force a scheme explicitly, set `data-moduix-color-scheme` or
toggle a `.dark` / `.light` class on `<html>` or any scoped container.

## Choose the scope

| Goal | Put the attribute or class on |
| --- | --- |
| Follow OS preference automatically | Nothing required (`:root` defaults to `light dark`) |
| Application-wide explicit theme | `<html>` |
| Embedded surface without portals | The surface wrapper |
| Embedded surface with portals | A portal container inside that surface |

Prefer `<html>` for normal applications. It gives regular and portalled components the same tokens.

## Set the document scheme

Use either the `data-moduix-color-scheme` attribute or standard `.dark` / `.light` classes:

```html
<html data-moduix-color-scheme="dark"></html>
<!-- or -->
<html class="dark"></html>
```

Use `dark` or `light` to override the operating-system preference, or remove the attribute/class to
return to automatic system mode. moduix does not persist a choice or synchronize browser storage;
your application controls persistence.

If the application renders on the server and allows overriding the OS preference, resolve the saved
scheme before the first paint with the early theme mechanism provided by your framework so the first
paint matches the user's choice.

## Resolve and save a preference

Keep the preference logic framework-neutral. The visible switch only needs to call
`saveColorScheme()` with the user's choice.

```ts
type ColorScheme = 'light' | 'dark';

export function applyColorScheme(scheme: ColorScheme) {
  document.documentElement.dataset.moduixColorScheme = scheme;
}

export function resolveColorScheme(): ColorScheme {
  const saved = localStorage.getItem('moduix-color-scheme');
  if (saved === 'light' || saved === 'dark') return saved;

  return matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light';
}

export function saveColorScheme(scheme: ColorScheme) {
  localStorage.setItem('moduix-color-scheme', scheme);
  applyColorScheme(scheme);
}
```

Use the operating-system preference only until the user makes an explicit choice. Give the control an
accessible action label, such as `Switch to dark mode`.

## Use an existing theme switcher

moduix maps `.dark` and `.light` classes to `color-scheme: dark` and `color-scheme: light` out of
the box, so projects using shadcn/ui, `next-themes` with `attribute="class"`, or VueUse `useDark()`
work without extra CSS.

Tailwind's `dark:` variant follows the operating-system preference by default. When you switch with
`data-moduix-color-scheme`, point the variant at the attribute so your utilities and moduix
components change together:

```css title="styles.css"
@custom-variant dark (&:where([data-moduix-color-scheme='dark'], [data-moduix-color-scheme='dark'] *));
```

With a `dark` class, keep the variant your project already defines for that class.

## Combine color mode and presets

Color mode and visual presets are independent. Keep both attributes on the same root:

```html
<html data-moduix-color-scheme="dark" data-moduix-theme="dense"></html>
```

Changing the color mode does not change density, radius, or other preset decisions. See
[Themes](/docs/themes) for preset setup.

Portalled content renders outside a regular wrapper and cannot inherit its tokens. Move the attribute
to the portal container, `<body>`, or `<html>` when the scoped surface opens overlays.

:::warning Keep `light-dark()` native
A scoped surface switches only when the browser runs `light-dark()` natively. Build tools that lower
it for older browsers, such as Lightning CSS in Rsbuild with default targets, leave nested surfaces in
the page's scheme. Set a `browserslist` that matches moduix: Chrome and Edge 123+, Firefox 120+,
Safari 17.5+.
:::

## Customize tokens

Load application overrides after the moduix stylesheet. Set the light and dark values in one
declaration with `light-dark()`:

```css
:root {
  --moduix-background: light-dark(oklch(0.99 0.004 285), oklch(0.16 0.01 285));
  --moduix-primary: light-dark(oklch(0.5 0.18 260), oklch(0.76 0.13 260));
}
```

`light-dark()` follows the color scheme however you switch it: with the attribute, a `dark` class,
or on a scoped surface. Tokens you do not override keep their built-in values.

## Verify the theme

- Test the first server-rendered paint and client hydration.
- Check portalled Dialog, Popover, Menu, and Select content.
- Keep readable contrast for text, borders, focus rings, and disabled states.
- Confirm that a stored choice overrides the system preference.
- Verify both color schemes with every active preset.
