# Dark mode

Moduix ships light and dark semantic tokens. Load the stylesheet for your chosen framework and styling
track, then set `data-moduix-color-scheme` on the element that should own the color scheme. No Moduix
theme provider or runtime state is required.

## Choose the scope

| Goal | Put the attribute on |
| --- | --- |
| Application-wide theme | `<html>` |
| Embedded surface without portals | The surface wrapper |
| Embedded surface with portals | A portal container inside that surface |

Prefer `<html>` for normal applications. It gives regular and portalled components the same tokens.

## Set the document scheme

Use the native document attributes as the source of truth:

```html
<html data-moduix-color-scheme="dark"></html>
```

Use `dark` or `light`. Moduix does not read system preferences, persist a choice, or synchronize
browser state. Your application owns those decisions.

If the application renders on the server, resolve the scheme before the first paint with the early
theme mechanism provided by your framework. This avoids showing the light palette before hydration.

## Resolve and save a preference

Keep the preference logic framework-neutral. The visible switch only needs to call
`saveColorScheme()` with the user's choice.

```ts
type ColorScheme = 'light' | 'dark';

export function applyColorScheme(scheme: ColorScheme) {
  document.documentElement.dataset.moduixColorScheme = scheme;
}

export function resolveColorScheme(): ColorScheme {
  const saved = localStorage.getItem('moduix-color-scheme');
  if (saved === 'light' || saved === 'dark') return saved;

  return matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light';
}

export function saveColorScheme(scheme: ColorScheme) {
  localStorage.setItem('moduix-color-scheme', scheme);
  applyColorScheme(scheme);
}
```

Use the operating-system preference only until the user makes an explicit choice. Give the control an
accessible action label, such as `Switch to dark mode`.

## Combine color mode and presets

Color mode and visual presets are independent. Keep both attributes on the same root:

```html
<html data-moduix-color-scheme="dark" data-moduix-theme="dense"></html>
```

Changing the color mode does not change density, radius, or other preset decisions. See
[Themes](/docs/themes) for preset setup.

## Scope one surface

The component code differs only by the native package import:

<Tabs groupId="framework">
  <Tab label="React" value="react">

<CodeBlockRuntime lang="tsx" code={reactScopedSurface} />

  </Tab>
  <Tab label="Solid" value="solid">

<CodeBlockRuntime lang="tsx" code={solidScopedSurface} />

  </Tab>
</Tabs>

Portalled content renders outside a regular wrapper and cannot inherit its tokens. Move the attribute
to the portal container, `<body>`, or `<html>` when the scoped surface opens overlays.

## Customize tokens

Load application overrides after the Moduix stylesheet and override both schemes deliberately:

```css
:root {
  --moduix-background: oklch(0.99 0.004 285);
  --moduix-primary: oklch(0.5 0.18 260);
}

[data-moduix-color-scheme='dark'] {
  --moduix-background: oklch(0.16 0.01 285);
  --moduix-primary: oklch(0.76 0.13 260);
}
```

Tokens you do not override keep their built-in values.

## Verify the theme

- Test the first server-rendered paint and client hydration.
- Check portalled Dialog, Popover, Menu, and Select content.
- Keep readable contrast for text, borders, focus rings, and disabled states.
- Confirm that a stored choice overrides the system preference.
- Verify both color schemes with every active preset.
