## Basic


Use `Menu` as the root and give every `Menu.Item` a stable `value`. Keep `Menu.Positioner` and
`Menu.Content` explicit, then place items, groups, separators, or nested menus inside the content.
`Menu.Indicator` is optional and defaults to the moduix chevron.

Do not set a custom `id` on `Menu.Item`: Ark identifies items by `value`, and an extra `id` breaks
its item lookup, typeahead, and focus management.

## Anatomy

```text
Menu / Menu.Root
├─ Menu.Trigger
│  ├─ Menu.TriggerIcon
│  └─ Menu.Indicator
├─ Menu.ContextTrigger
└─ Overlay subtree (automatically portalled)
   └─ Menu.Positioner
      └─ Menu.Content
         ├─ Menu.Arrow
         │  └─ Menu.ArrowTip
         └─ Menu.Viewport
            ├─ Menu.Item
            │  ├─ Menu.ItemText
            │  │  ├─ Menu.ItemTextIcon
            │  │  └─ Menu.ItemTextLabel
            │  └─ Menu.ItemShortcut
            ├─ Menu.CheckboxItem
            │  └─ Menu.ItemIndicator
            ├─ Menu.RadioItemGroup
            │  └─ Menu.RadioItem
            ├─ Menu.ItemGroup
            │  └─ Menu.ItemGroupLabel
            ├─ Menu.Separator
            └─ Menu
               └─ Menu.TriggerItem
                  └─ Menu.TriggerItemIcon
```

| Part | Role |
| --- | --- |
| `Menu` / `Menu.Root` | Root that manages open state, positioning, typeahead, focus, and dismissal. |
| `Menu.RootProvider` | Connects a menu to a state instance created with `useMenu`. |
| `Menu.Trigger` | Button that opens the menu. Use `asChild` to provide another semantic element. |
| `Menu.TriggerIcon` | Wrapper for a trigger icon. It renders the default chevron when no child is provided. |
| `Menu.Indicator` | State-aware trigger indicator, usually rendered as a chevron. |
| `Menu.ContextTrigger` | Trigger for right-click and long-press context menus. |
| `Menu.Positioner` | Positions the floating menu layer. |
| `Menu.Content` | Popup surface with the menu role and its item collection. |
| `Menu.Viewport` | Explicit scroll container around the item collection. |
| `Menu.Arrow` / `Menu.ArrowTip` | Optional visual anchor for the popup. |
| `Menu.Item` | Standard command item. |
| `Menu.CheckboxItem` | Item with an independent boolean state. |
| `Menu.RadioItemGroup` / `Menu.RadioItem` | Group and items for choosing one value. |
| `Menu.ItemIndicator` | Selection indicator for checkbox and radio items. |
| `Menu.ItemText` and text helpers | Helpers for composing item text with icons and labels. |
| `Menu.ItemShortcut` | Wrapper for a keyboard shortcut or other trailing hint. |
| `Menu.ItemGroup` / `Menu.ItemGroupLabel` | Group and label for related items. |
| `Menu.Separator` | Divider between groups of items. |
| `Menu.TriggerItem` / `Menu.TriggerItemIcon` | Item and icon for opening a nested menu. |
| `Menu.ItemContext` | Provides item state to content rendered inside an item. |

## Composition

Use `defaultOpen` for an uncontrolled menu. When another part of the application owns the open or
highlighted state, pass `open` or `highlightedValue` with the matching change handler. Use
`useMenu()` with `Menu.RootProvider` when the state store must be created outside the rendered tree;
do not render a second `Menu` root for the same store.

`Menu.Positioner`, `Menu.Content`, and `Menu.Viewport` are separate parts, but the positioner is portalled automatically.
Set `portalled={false}` inside a dialog or scroll container and use
`positioning={{ strategy: 'fixed', hideWhenDetached: true }}` when that container can scroll. Use
`asChild` with exactly one semantic child when a trigger, item, or content host must own the DOM node.
In Solid, assign a ref to the element created inside the `asChild` render function, because a ref on
a `Menu` part itself is not forwarded through that composition path.
A `Menu.Content` must contain `Menu.Viewport` around its scrollable items. Keep an optional
`Menu.Arrow` directly under `Menu.Content`, next to the viewport, so it is not clipped while items scroll.
A nested menu is another `Menu` root inside the parent content, paired with its own `TriggerItem`,
`Positioner`, and `Content`.

## Styling

Use `className` in React or `class` in Solid on exported parts for structural styles. For state-based
styles, prefer Ark data attributes such as `data-state`, `data-disabled`, and `data-highlighted`,
together with moduix `data-slot` selectors. Tailwind variants use native utilities and consumer
classes; the CSS variables below customize the CSS Modules variants. Data attributes and `data-slot`
hooks are shared by both styling tracks.
