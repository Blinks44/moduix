## Choosing the right component

Use `Menu` for command lists opened by a trigger, context menus, simple selections, and nested actions.

- Choose **`Menu`** for additional actions, row actions, and command lists opened from a button or
  context trigger.

## Anatomy

```text
Menu
├─ Menu.Trigger
│  └─ Menu.Indicator
├─ Menu.ContextTrigger
├─ Overlay subtree (automatically portalled)
│  └─ Menu.Positioner
│     └─ Menu.Content
│        ├─ Menu.Arrow
│        │  └─ Menu.ArrowTip
│        ├─ Menu.Item
│        ├─ Menu.CheckboxItem
│        │  ├─ Menu.ItemIndicator
│        │  └─ Menu.ItemText
│        ├─ Menu.RadioItemGroup
│        │  └─ Menu.RadioItem
│        ├─ Menu.ItemGroup
│        │  └─ Menu.ItemGroupLabel
│        └─ Menu
│           └─ Menu.TriggerItem
```

| Part                  | Role                                                        |
| --------------------- | ----------------------------------------------------------- |
| `Menu` / `Menu.Root`  | Ark root for open state, positioning, typeahead, dismissal. |
| `Menu.RootProvider`   | Renders a menu from a `useMenu` state instance.             |
| `Menu.Trigger`        | Button trigger; use `asChild` for a custom host.            |
| `Menu.Indicator`      | Ark state-aware trigger indicator.                          |
| `Menu.ContextTrigger` | Right-click and long-press trigger for context menus.       |
| `Menu.Positioner`     | Floating layer positioner.                                  |
| `Menu.Content`        | Popup surface with menu role and item collection.           |
| `Menu.Item`           | Command row.                                                |
| `Menu.CheckboxItem`   | Boolean option item.                                        |
| `Menu.RadioItemGroup` | Exclusive value group for radio items.                      |
| `Menu.RadioItem`      | Exclusive option item.                                      |
| `Menu.TriggerItem`    | Row that opens a nested `Menu`.                             |
| `Menu.ItemIndicator`  | Check indicator for checkbox and radio rows.                |

## Composition

The root automatically portals `Positioner`. Use `portalled={false}` to keep the menu in its current container,
or `portalRef` to choose a different portal container. Structural parts remain explicit and styleable.

### Recommended composition

Keep the popup structure explicit. `Menu.Content` is the actual Ark content part, and `Menu.Positioner` remains a
separate part.

```tsx
<Menu positioning={{ placement: 'bottom-start', gutter: 8 }}>
  <Menu.Trigger asChild>
    <Button>
      Actions
      <Menu.Indicator />
    </Button>
  </Menu.Trigger>
  <Menu.Positioner>
    <Menu.Content className="menu-content">
      <Menu.Item value="edit">Edit</Menu.Item>
    </Menu.Content>
  </Menu.Positioner>
</Menu>
```

### When to go custom

Use `asChild` when a trigger, item, or content needs to render as another semantic element. Supply one semantic child
so Ark can apply the correct ARIA attributes and manage focus and keyboard behavior. For links, put `asChild` on
`Menu.Item`; for a custom popup container, put it on `Menu.Content`.

A nested menu is a regular `Menu` root inside the parent content. It uses `Menu.TriggerItem`, followed by its own
`Menu.Positioner` and `Menu.Content`.

### Default props

Portalled menu content mounts on demand and unmounts after its exit animation by default. Set
`unmountOnExit={false}` to retain it after the first open. Set `lazyMount={false}` and
`unmountOnExit={false}` only when the content must render immediately.

| Surface                           | Default | Notes                                                  |
| --------------------------------- | ------- | ------------------------------------------------------ |
| `Menu` / `Menu.Root`                  | -       | No additional behavioral defaults; Ark defaults apply. |
| `Menu.CheckboxItem` / `Menu.RadioItem` | `start` | `indicator` controls the indicator column position.    |

### Behavioral notes

- In moduix, `lazyMount` and `unmountOnExit` default to `true`. `open`, `defaultOpen`,
  `onOpenChange(details)`, `highlightedValue`, `onHighlightChange(details)`, `onSelect(details)`,
  `closeOnSelect`, `ids`, and `present` pass through to Ark without additional moduix defaults.
- Use `value`, rather than a custom `id`, to identify a menu item.
- `Menu.CheckboxItem.onCheckedChange` receives the next boolean checked state.
- `Menu.RadioItemGroup.onValueChange` receives `details.value`.
- `Menu.RootProvider` must be used with a `useMenu` instance instead of rendering a second `Menu`
  root for the same state.
- `Menu.Context`, `useMenuContext`, and `useMenuItemContext` expose the Ark state to descendants
  when advanced composition needs it.
- The root automatically portals `Menu.Positioner`. Use `portalled={false}` to keep a menu inside a dialog or scroll
  container. When the container scrolls, add `positioning={{ strategy: 'fixed', hideWhenDetached: true }}`.
- Open and close animations respect `prefers-reduced-motion`.
- `Menu.Indicator` mirrors Ark's indicator part. `Menu.TriggerIcon`, `Menu.TriggerItemIcon`,
  `Menu.ItemShortcut`, and item text helpers are moduix helper components for common content.

### Styling hooks

- Ark attributes: `[data-scope='menu']`, `[data-part='trigger']`, `[data-part='indicator']`,
  `[data-part='content']`, `[data-part='item']`,
  `[data-type='checkbox' | 'radio']`, `[data-state='open' | 'closed' | 'checked' | 'unchecked']`,
  `[data-current]`, `[data-highlighted]`, `[data-disabled]`, `[data-placement]`, and `[data-side]`.
- Ark variables: `--reference-width`, `--available-width`, `--available-height`,
  `--transform-origin`, `--layer-index`, `--arrow-size`, and `--arrow-background`.
- moduix hooks: `data-slot="menu-trigger"`, `menu-content`, `menu-item`, `menu-checkbox-item`,
  `menu-radio-item`, `menu-trigger-item`, `menu-item-indicator`, and `menu-item-shortcut`.
