## Choosing the right component

Use `SegmentGroup` when users choose one value from a small set that is visible at the same time.

- Choose **`Tabs`** when changing the selection should also change a visible content panel.
- Choose **`ToggleGroup`** when the items act like toolbar buttons and may have multiple active values.
- Choose **`RadioGroup`** when the control should keep the familiar visual appearance of radio buttons.
- Choose **`SegmentGroup`** when the interaction is radio-like but the UI should use a compact segmented control.

## Basic

`SegmentGroup` is available for React and Solid in both the CSS Modules and Tailwind packages. The
interactive previews on this page use React and CSS Modules; the framework tabs show native source
for the same public contract.

Use `SegmentGroup` as the root, place `SegmentGroup.Indicator` before the items, and use
`SegmentGroup.Items` when every segment only needs a text label. `Items` creates the item, text,
control, and one synchronized native form input for every entry.

## Anatomy

```text
SegmentGroup / SegmentGroup.Root
├─ SegmentGroup.Label (optional)
├─ SegmentGroup.Indicator
└─ SegmentGroup.Item[value]
   ├─ SegmentGroup.ItemText
   ├─ SegmentGroup.ItemControl
   └─ the native form input

SegmentGroup.RootProvider
└─ the same item tree connected to a useSegmentGroup() store
```

| Part | Role |
| ---- | ---- |
| `SegmentGroup` / `SegmentGroup.Root` | Root part that owns the selected value, keyboard navigation, and form integration. |
| `SegmentGroup.RootProvider` | Connects the parts to state created with `useSegmentGroup()`. |
| `SegmentGroup.Item` | One selectable segment with a required `value`. |
| `SegmentGroup.ItemHiddenInput` | Native Ark form control for an explicit item composition. |
| `SegmentGroup.ItemText` | Visible text for a segment. |
| `SegmentGroup.ItemControl` | Ark control part used for item state and hidden by moduix styles. |
| `SegmentGroup.Items` | Renderer for standard text segments with the native input included. |
| `SegmentGroup.Indicator` | Positions the active-item highlight using Ark CSS variables. |
| `SegmentGroup.Label` | Optional accessible label for the group. |

## Composition

Use `SegmentGroup` with `SegmentGroup.Indicator` before `SegmentGroup.Items` for the usual
composition. `Items` includes `ItemText`, `ItemControl`, and exactly one
`ItemHiddenInput` for every item. When rendering `SegmentGroup.Item` directly, compose those
parts yourself and keep exactly one `ItemHiddenInput` inside each item. The direct child of
`asChild` must remain one semantic `label`.

Use `SegmentGroup.RootProvider` with `useSegmentGroup()` when the state must be created outside
the rendered tree or controlled by another part of the application. React reads the store as an
object, while Solid reads its reactive state through the returned accessor.

## Styling

Use `className` in React or `class` in Solid on exported parts for structural styles. For state-based
styles, prefer Ark data attributes such as `data-state`, `data-disabled`, and `data-orientation`,
together with moduix `data-slot` selectors. Tailwind variants use native utilities and consumer
classes; the component variables below customize the CSS Modules variants. Data attributes and
`data-slot` hooks are shared by both styling tracks.

### CSS Properties

<CssPropertiesSection properties={SegmentGroupDocs.segmentGroupOverrideCssProperties} />

### Styling hooks

- Stable `data-slot` selectors: `segment-group-root`, `segment-group-root-provider`,
  `segment-group-label`, `segment-group-indicator`, `segment-group-item`,
  `segment-group-item-text`, and `segment-group-item-control`.
- Ark part selectors: `data-scope="segment-group"` and `data-part` on the root, label, indicator,
  item, item text, item control, and hidden input.
- Ark state selectors: `data-state="checked|unchecked"`, `data-orientation`, `data-disabled`,
  `data-readonly`, `data-invalid`, `data-required`, and `data-focus-visible`.
- The indicator uses Ark runtime variables `--left`, `--top`, `--width`, and `--height` for its
  size. Its motion uses `--transition-duration` and `--transition-timing-function`, with moduix
  defaults mapped from `--moduix-segment-group-indicator-transition-duration` and
  `--moduix-segment-group-indicator-transition-timing-function`.
