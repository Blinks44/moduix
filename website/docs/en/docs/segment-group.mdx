## Choosing the right component

Use `SegmentGroup` when users choose one value from a small set that is visible at the same time.

- Choose **`Tabs`** when changing the selection should also change a visible content panel.
- Choose **`ToggleGroup`** when the items act like toolbar buttons and may have multiple active values.
- Choose **`RadioGroup`** when the control should keep the familiar visual appearance of radio buttons.
- Choose **`SegmentGroup`** when the interaction is radio-like but the UI should use a compact segmented control.

## Basic


Use `SegmentGroup` as the root, place `SegmentGroupIndicator` before the items, and use
`SegmentGroupItems` when every segment only needs a text label. `SegmentGroupItems` creates the item,
text, and one native form input for every entry. Pass strings when the value and the label are
the same, or `{ value, label, disabled }` objects.

## Anatomy

```text
SegmentGroup
├─ SegmentGroupLabel (optional)
├─ SegmentGroupIndicator
└─ SegmentGroupItem[value]
   ├─ SegmentGroupItemText
   └─ the native form input

SegmentGroupRootProvider
└─ the same item tree connected to a useSegmentGroup() store
```

| Part | Role |
| ---- | ---- |
| `SegmentGroup` | Root part that owns the selected value, keyboard navigation, and form integration. |
| `SegmentGroupRootProvider` | Connects the parts to state created with `useSegmentGroup()`. |
| `SegmentGroupContext` | Render-prop access to the root state for advanced composition. |
| `SegmentGroupItemContext` | Render-prop access to the item state for advanced composition. |
| `SegmentGroupItem` | One selectable segment with a required `value`. |
| `SegmentGroupItemHiddenInput` | Native Ark form control for an explicit item composition. |
| `SegmentGroupItemText` | Visible text for a segment. |
| `SegmentGroupItems` | Renderer for standard text segments with the native input included. |
| `SegmentGroupIndicator` | Positions the active-item highlight using Ark CSS variables. |
| `SegmentGroupLabel` | Optional accessible label for the group. |

## Composition

Use `SegmentGroup` with `SegmentGroupIndicator` before `SegmentGroupItems` for the usual
composition. `SegmentGroupItems` includes `SegmentGroupItemText` and
exactly one `SegmentGroupItemHiddenInput` for every item. When rendering `SegmentGroupItem` directly,
compose those parts yourself and keep exactly one `SegmentGroupItemHiddenInput` inside each item. The direct child of
`asChild` must remain one semantic `label`.

Use `SegmentGroupRootProvider` with `useSegmentGroup()` when the state must be created outside
the rendered tree or controlled by another part of the application. React and Vue read the store as
an object, while Solid reads its reactive state through the returned accessor.

## Examples

### Conditional Mount

Segment groups can be mounted conditionally. When the group appears, Ark recalculates the item
geometry used by the indicator.

<Example name="segment-group/conditional-mount" />

### Controlled

Keep the selected value in application state and update it from `details.value` in
`onValueChange`.

<Example name="segment-group/controlled" />

### Disabled

Set `disabled` on an item when only that segment should be unavailable. Set it on the root to
disable the whole group.

<Example name="segment-group/disabled" />

### Field

Wrap the group in `Field` when its native inputs should be accompanied by helper or error text.
`Field` does not pass its state to the group, so set `invalid`, `required`, `disabled`, or `readOnly`
on `SegmentGroup` as well.

<Example name="segment-group/field" />

### Form Submission

Pass `name` to the root to include the selected value in native form data. `SegmentGroupItems`
adds a native form input to every generated item.

<Example name="segment-group/form-submission" />

### Invalid

Set `invalid` on the root when validation fails. Combine it with `required` and `name` when the
group participates in native form validation.

<Example name="segment-group/invalid" />

### Root Provider

Use `useSegmentGroup()` with `SegmentGroupRootProvider` when controls outside the segment tree need access
to the same state.

<Example name="segment-group/root-provider" />

### Sizes

Set `size` on `SegmentGroup` or `SegmentGroupRootProvider` to `sm`, `md` (default), or `lg`. The
whole group then has the height of a `Button` or `Input` of the same size.

<Example name="segment-group/sizes" />

### Vertical Orientation

Set `orientation="vertical"` when the group should use a vertical layout and vertical arrow-key
navigation.

<Example name="segment-group/vertical-orientation" />

### Advanced Customization

Use `SegmentGroupItem asChild` instead of `SegmentGroupItems` when a custom label layout should
own the item's DOM node.

## Styling

Use `className` in React or `class` in Solid/Vue on exported parts for structural styles. For state-based
styles, prefer Ark data attributes such as `data-state`, `data-disabled`, and `data-orientation`,
together with moduix `data-slot` selectors. Tailwind variants use native utilities and consumer
classes; the component variables below customize the CSS Modules variants. Data attributes and
`data-slot` hooks are shared by both styling tracks.

### Styling hooks

- Stable `data-slot` selectors: `segment-group-root`, `segment-group-root-provider`,
  `segment-group-label`, `segment-group-indicator`, `segment-group-item`,
  and `segment-group-item-text`.
- Ark part selectors: `data-scope="segment-group"` and `data-part` on the root, label, indicator,
  item, item text, and hidden input.
- Ark state selectors: `data-state="checked|unchecked"`, `data-orientation`, `data-disabled`,
  `data-readonly`, `data-invalid`, `data-required`, and `data-focus-visible`.
- The indicator uses Ark runtime variables `--left`, `--top`, `--width`, and `--height` for its
  size. Its motion uses Ark `--transition-duration` and `--transition-timing-function`, set from
  `--moduix-duration-normal` and `--moduix-ease-in-out`. Set them with a class on
  `SegmentGroupIndicator` (in Tailwind, `[--transition-duration:300ms]`); `duration-*` utilities lose
  to the inline transition that Ark writes.
