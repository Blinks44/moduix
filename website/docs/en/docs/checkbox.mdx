Use `Checkbox` when people need to select one or more independent options in a form, settings panel,
or filter list. Use `RadioGroup` when only one option can be selected. Use `Switch` when a setting
should take effect immediately.

## Anatomy

```text
Checkbox
├─ CheckboxControl
│  ├─ CheckboxIndicator
│  └─ CheckboxIndicator[indeterminate] (optional)
├─ CheckboxLabel
└─ CheckboxHiddenInput (explicit)

CheckboxRootProvider
└─ same part tree connected to useCheckbox()

CheckboxGroup
└─ Checkbox[value]
   ├─ CheckboxControl
   ├─ CheckboxLabel
   └─ CheckboxHiddenInput
```

| Part                         | Role                                                                                  |
| ---------------------------- | ------------------------------------------------------------------------------------- |
| `Checkbox`                   | Holds the state for one checkbox and renders its wrapping label.                      |
| `CheckboxHiddenInput`        | Native Ark form control; compose it explicitly inside the root.                       |
| `CheckboxRootProvider`       | Connects the parts to Ark state created outside the rendered tree.                    |
| `CheckboxControl`            | The visible checkbox; empty, it renders the built-in state icons.                     |
| `CheckboxIndicator`          | Optional slot for a custom icon. Pass `indeterminate` for that state.                 |
| `CheckboxLabel`              | The visible label for the checkbox.                                                   |
| `CheckboxGroup`              | Manages the selected values for several checkboxes.                                   |

## Composition

`CheckboxHiddenInput` is Ark's native input. Render it explicitly inside `Checkbox` or
`CheckboxRootProvider`, even outside a form: it owns native focus, keyboard interaction,
accessibility, and form participation. Put `name` and `value` on the root for a standalone field;
for a group, put `name` on `CheckboxGroup` and `value` on each `Checkbox`.

`CheckboxGroup` owns an array of selected values, and each child is a `Checkbox` with its own
`value`. Leave `CheckboxControl` empty for moduix's built-in icons. Add `CheckboxIndicator` inside
`CheckboxControl` only for a custom indicator.

When state must be created outside the rendered tree, create it with `useCheckbox()` and pass the
store to `CheckboxRootProvider`. Do not render `Checkbox` or `Checkbox` for the same store.

## Styling

Use `className` in React or `class` in Solid on exported parts for structural styles. For state-based
styles, prefer Ark data attributes such as `data-state`, `data-disabled`, and `data-invalid`,
together with moduix `data-slot` selectors. Tailwind variants use native utilities and consumer
classes; the variables below customize the CSS Modules variants. Data attributes and `data-slot`
hooks are shared by both styling tracks.

### CSS Properties

<CssPropertiesSection properties={CheckboxDocs.checkboxOverrideCssProperties} />

### Styling hooks

- `Checkbox` exposes `data-slot="checkbox-root"`, `data-size`, and Ark state attributes such as `data-state`, `data-active`, `data-disabled`, `data-readonly`, `data-invalid`, `data-required`, `data-hover`, `data-focus`, and `data-focus-visible`.
- `CheckboxRootProvider` exposes `data-slot="checkbox-root-provider"` and the same root styling contract.
- `CheckboxControl` exposes `data-slot="checkbox-control"` and Ark state attributes including `data-state="checked" | "indeterminate" | "unchecked"` and `data-active`.
- `CheckboxIndicator` exposes `data-slot="checkbox-indicator"` and inherits Ark checkbox state attributes.
- `CheckboxLabel` exposes `data-slot="checkbox-label"` and Ark checkbox state attributes.
- `CheckboxGroup` exposes `data-slot="checkbox-group"`.
