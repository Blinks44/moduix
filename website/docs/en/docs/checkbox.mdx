Use `Checkbox` to let people select one or more independent options in forms, settings, and filter
lists. Choose `RadioGroup` when only one option may be selected, or `Switch` when a setting should
take effect immediately.

## Anatomy

```text
Checkbox.Root
├─ Checkbox.Control
│  ├─ Checkbox.Indicator
│  └─ Checkbox.Indicator[indeterminate] (optional)
├─ Checkbox.Label
└─ native input (automatic)

Checkbox.RootProvider
└─ same part tree connected to useCheckbox()

Checkbox.Group
└─ Checkbox.Root[value]
   ├─ Checkbox.Control
   ├─ Checkbox.Label
   └─ the native form input
```

| Part                         | Role                                                                                     |
| ---------------------------- | ---------------------------------------------------------------------------------------- |
| `Checkbox` / `Checkbox.Root` | Holds the state for one checkbox and renders its wrapping label.                         |
| `Checkbox.RootProvider`      | Connects the parts to Ark state created outside the rendered subtree.                    |
| `Checkbox.Control`           | The visible checkbox. When empty, it renders the built-in state indicators.              |
| `Checkbox.Indicator`         | Optional icon slot for a custom indicator. Use `indeterminate` for that state.           |
| `Checkbox.Label`             | The checkbox's visible label.                                                            |
| `Checkbox.Group`             | Shares the selected values across several checkboxes.                                    |

## Composition

### Recommended composition

Keep the Ark part tree in your markup. `Checkbox.Root` accepts standard Ark root props such as `checked`,
`defaultChecked`, `onCheckedChange(details)`, `disabled`, `readOnly`, `invalid`, `required`,
`name`, `value`, `form`, `ids`, and `asChild`.

`Checkbox.Group` accepts `value`, `defaultValue`, `onValueChange(value)`, `disabled`, `readOnly`,
`invalid`, `maxSelectedValues`, and `name`.

`Checkbox.Control` is the convenient moduix default. Leave it empty to use the built-in icons, or
pass children to create a custom indicator. `size` is the only moduix-specific prop on
`Checkbox.Root` and `Checkbox.RootProvider`.

### When to go custom

Use `Checkbox.RootProvider` when the checkbox state is created outside the rendered subtree. moduix
re-exports `useCheckbox()` for this pattern. `Checkbox.Context`, `useCheckboxContext()`,
`useCheckboxGroup()`, and `useCheckboxGroupContext()` provide access to Ark state for more advanced
compositions. Render `Checkbox.Indicator` explicitly only for custom icons or a different
indicator layout.

### Default props

| Surface                      | Default | Notes                                                   |
| ---------------------------- | ------- | ------------------------------------------------------- |
| `Checkbox` / `Checkbox.Root` | -       | No additional behavioral defaults; Ark defaults apply.  |
| `size`                       | `md`    | Applied on `Checkbox.Root` and `Checkbox.RootProvider`. |

### Behavioral notes

The root adds a native input automatically, so the checkbox works with native form validation,
reset, and submission. For a standalone checkbox, pass `name` and `value` to `Checkbox.Root`. For
a group, pass `name` to `Checkbox.Group` and `value` to each `Checkbox.Root`.

If you are moving from shadcn, `Checkbox.Control` already includes the default icon treatment. The
control and label remain explicit in the tree; the hidden input stays internal.

Ark `Checkbox.Root` renders a `label`. When you use `asChild`, its direct child must also be a
semantic `label`; otherwise the checkbox no longer has a valid form label.

When `readOnly` is set, moduix mirrors that state to `aria-readonly` on the automatic native input
while Ark prevents interaction.

A ref points to the corresponding Ark DOM part. Press <kbd>Space</kbd> to toggle a focused checkbox.

### Styling hooks

- `Checkbox.Root` exposes `data-slot="checkbox-root"`, `data-size`, and Ark state attributes such as `data-state`, `data-disabled`, `data-readonly`, `data-invalid`, `data-required`, `data-hover`, `data-focus`, and `data-focus-visible`.
- `Checkbox.RootProvider` exposes `data-slot="checkbox-root-provider"` and the same root styling contract.
- `Checkbox.Control` exposes `data-slot="checkbox-control"` and Ark state attributes including `data-state="checked" | "indeterminate" | "unchecked"`.
- `Checkbox.Indicator` exposes `data-slot="checkbox-indicator"` and inherits Ark checkbox state attributes.
- `Checkbox.Label` exposes `data-slot="checkbox-label"` and Ark checkbox state attributes.
- `Checkbox.Group` exposes `data-slot="checkbox-group"`.
