Use `Checkbox` when people need to select one or more independent options in a form, settings panel,
or filter list. Use `RadioGroup` when only one option can be selected. Use `Switch` when a setting
should take effect immediately.

## Anatomy

```text
Checkbox.Root
├─ Checkbox.Control
│  ├─ Checkbox.Indicator
│  └─ Checkbox.Indicator[indeterminate] (optional)
├─ Checkbox.Label
└─ native input (automatic)

Checkbox.RootProvider
└─ same part tree connected to useCheckbox()

Checkbox.Group
└─ Checkbox.Root[value]
   ├─ Checkbox.Control
   ├─ Checkbox.Label
   └─ the native form input
```

| Part                         | Role                                                                                     |
| ---------------------------- | ---------------------------------------------------------------------------------------- |
| `Checkbox` / `Checkbox.Root` | Holds the state for one checkbox and renders its wrapping label.                         |
| `Checkbox.RootProvider`      | Connects the parts to Ark state created outside the rendered tree.                        |
| `Checkbox.Control`           | The visible checkbox. When empty, it renders the built-in state icons.                     |
| `Checkbox.Indicator`         | Optional slot for a custom icon. Pass `indeterminate` for that state.                      |
| `Checkbox.Label`             | The visible label for the checkbox.                                                        |
| `Checkbox.Group`             | Manages the selected values for several checkboxes.                                        |

## Composition

### Recommended composition

Keep the Ark part tree in your markup. `Checkbox.Root` accepts standard Ark root props such as `checked`,
`defaultChecked`, `onCheckedChange(details)`, `disabled`, `readOnly`, `invalid`, `required`,
`name`, `value`, `form`, `ids`, and `asChild`. The `checked` and `defaultChecked` props accept
`true`, `false`, or `"indeterminate"`.

`Checkbox.Group` accepts `value`, `defaultValue`, `onValueChange(value)`, `disabled`, `readOnly`,
`invalid`, `maxSelectedValues`, and `name`.

`Checkbox.Control` is moduix's convenient default. Leave it empty to use the built-in icons, or pass
children to provide a custom indicator. `size` is the only moduix-specific prop on `Checkbox.Root`
and `Checkbox.RootProvider`.

### When to go custom

Use `Checkbox.RootProvider` when checkbox state needs to live outside the rendered tree. moduix
re-exports `useCheckbox()` for this pattern. Pass the returned state to `Checkbox.RootProvider` via
its `value` prop. `Checkbox.Context`, `useCheckboxContext()`, `useCheckboxGroup()`, and
`useCheckboxGroupContext()` expose Ark state for more advanced compositions. For a group whose state
lives outside the tree, pair `useCheckboxGroup()` with Ark's `Checkbox.GroupProvider` from
`@ark-ui/react/checkbox`. Render
`Checkbox.Indicator` explicitly only when you need a custom icon or indicator layout.

### Default props

| Surface                      | Default | Notes                                                   |
| ---------------------------- | ------- | ------------------------------------------------------- |
| `Checkbox` / `Checkbox.Root` | -       | No extra behavior is added; Ark defaults apply.         |
| `size`                       | `md`    | Applied to `Checkbox.Root` and `Checkbox.RootProvider`. |

### Behavioral notes

Both `Checkbox.Root` and `Checkbox.RootProvider` always render a native input, so the checkbox can
participate in native form validation, reset, and submission. To include a standalone checkbox in
submitted form data, pass `name` and `value` to `Checkbox.Root`. For a group, pass `name` to
`Checkbox.Group` and `value` to each `Checkbox.Root`.

If you are migrating from shadcn, `Checkbox.Control` already includes the default icon treatment.
`Checkbox.Control` and `Checkbox.Label` remain explicit in the tree, while the hidden input stays
internal.

Ark `Checkbox.Root` and `Checkbox.RootProvider` render a `label`. When you use `asChild`, the direct
child must also be a semantic `label`; otherwise the checkbox no longer has a valid form label.

When `readOnly` is set, moduix mirrors that state to `aria-readonly` on the automatic native input
while Ark prevents interaction.

A ref passed to a part points to the corresponding Ark DOM node. Press <kbd>Space</kbd> to toggle a
focused checkbox.

### Styling hooks

- `Checkbox.Root` exposes `data-slot="checkbox-root"`, `data-size`, and Ark state attributes such as `data-state`, `data-active`, `data-disabled`, `data-readonly`, `data-invalid`, `data-required`, `data-hover`, `data-focus`, and `data-focus-visible`.
- `Checkbox.RootProvider` exposes `data-slot="checkbox-root-provider"` and the same root styling contract.
- `Checkbox.Control` exposes `data-slot="checkbox-control"` and Ark state attributes including `data-state="checked" | "indeterminate" | "unchecked"` and `data-active`.
- `Checkbox.Indicator` exposes `data-slot="checkbox-indicator"` and inherits Ark checkbox state attributes.
- `Checkbox.Label` exposes `data-slot="checkbox-label"` and Ark checkbox state attributes.
- `Checkbox.Group` exposes `data-slot="checkbox-group"`.
