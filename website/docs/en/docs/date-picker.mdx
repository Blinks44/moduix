## Choosing the right component

- Choose **`Input`** for plain date text when calendar behavior is not needed.
- Choose **`DateInput`** for keyboard-first segmented date entry.
- Choose **`DatePicker`** when users need an editable date field with a popup or inline calendar.

## Basic

`DatePicker` keeps Ark's date state and calendar behavior and adds convenience parts for the common
case. Use `DatePicker.Field` for the standard field and its actions, and `DatePicker.DayTable` for
the day grid.

| `DatePicker.ClearTrigger`        | Clears the current value and uses a close icon by default.                 |

| `DatePicker.Content`             | Calendar container for popup or inline mode.                               |
| `DatePicker.View`                | Day, month, or year panel.                                                  |

| `DatePicker.MonthSelect`         | Native month select linked to the focused date.                            |
| `DatePicker.YearSelect`          | Native year select linked to the focused date.                             |
| `DatePicker.PresetTrigger`       | Button for a predefined range.                                              |

## Composition

### Recommended composition

Use `DatePicker.Field` for a standard single-date field, `DatePicker.RangeField` for range fields,
and `DatePicker.DayTable` inside the day view. The root automatically renders `Positioner` in a
portal. Use `portalled={false}` to keep the popup in the current DOM subtree, or `portalRef` to
render it in a custom container. Set `inline` when the calendar should stay in the normal document
flow. The popup parts remain explicit and can be styled individually.

### When to go custom

Use `DatePicker.Control`, `DatePicker.Input`, `DatePicker.Trigger`, `DatePicker.ClearTrigger`, and
the low-level `Table*` parts directly when you need a different field layout or calendar grid. Use
`DatePicker.Context` when custom rendering needs calendar state such as `weekDays`, `weeks`,
`getMonthsGrid()`, `getYearsGrid()`, `getOffset()`, or action helpers.

### Default props

By default, the portalled overlay mounts when the calendar is first opened and unmounts after its
exit animation. Set `lazyMount={false}` to render it immediately, or
`unmountOnExit={false}` to keep it mounted after the first open.

| Prop                                     | Default            | Notes                                             |
| ---------------------------------------- | ------------------ | ------------------------------------------------- |
| `DatePicker.Field.placeholder`           | Ark locale pattern | Replaces the generated input placeholder.             |
| `DatePicker.Field.clearLabel`            | Ark translation    | Replaces the generated clear-trigger label.           |
| `DatePicker.Field.triggerLabel`          | Ark translation    | Replaces the generated open-trigger label.            |
| `DatePicker.RangeField.startPlaceholder` | Ark locale pattern | Replaces the generated start-input placeholder.       |
| `DatePicker.RangeField.endPlaceholder`   | Ark locale pattern | Replaces the generated end-input placeholder.         |
| `DatePicker.DayTable.showHeader`         | `true`             | Renders previous, view, and next controls above the table. |
| `DatePicker.DayTable.showWeekNumbers`    | `false`            | Renders the week-number header and cells.             |

### Behavioral notes

`value`, `defaultValue`, and `onValueChange(details)` use Ark's `DateValue[]` shape. Import
`DatePicker.Context`, `useDatePicker`, and `useDatePickerContext` from `@moduix/react`; import
`parseDate` and Ark date types from `@ark-ui/react/date-picker` when needed. The default width of
the root and popup is `18.75rem` (300px). Override `--moduix-date-picker-width` or
`--moduix-date-picker-content-width` when you need a wider composition.
Because the popup content is portalled, set popup sizing variables on `DatePicker.Content` or
another element inside the overlay subtree, not only on `DatePicker`.

`open`, `defaultOpen`, and `onOpenChange(details)` control the popup state. `view`, `defaultView`,
`minView`, `maxView`, and `onViewChange(details)` control the active calendar panel. When a
composition renders only one panel, set both `minView` and `maxView` to that view.

When nested in a moduix `Field` or `Fieldset`, `DatePicker` inherits `disabled` and `invalid`. A
`Field` also provides `readOnly` and `required`. Props set directly on `DatePicker` take precedence.
`DatePicker.Field` always uses input index `0`. `DatePicker.RangeField` reserves indexes `0` and `1`
for the start and end inputs. Use `Control` and `Input` directly for a different input layout.

Use `selectionMode="single"`, `"range"`, or `"multiple"`. `maxSelectedDates` applies only to
multiple selection. `numOfMonths`, `fixedWeeks`, and `showWeekNumbers` change the calendar table.

Use `min`, `max`, and `isDateUnavailable(date, locale)` to mark dates as unavailable. Use `locale`,
`timeZone`, `format`, `parse`, `translations`, and `createCalendar` to configure localization.

### Styling hooks

Use these `data-slot` hooks to target individual parts:

- `data-slot="date-picker-root"` on the root.
- `data-slot="date-picker-root-provider"` on the provider root.
- `data-slot="date-picker-label"` on the label.
- `data-slot="date-picker-control"` on the input wrapper, `DatePicker.Field`, and `DatePicker.RangeField`.
- `data-slot="date-picker-input"` on the editable input.
- `data-slot="date-picker-trigger"` and `data-slot="date-picker-clear-trigger"` on field actions.
- `data-slot="date-picker-value-text"` on selected-value summaries.
- `data-slot="date-picker-positioner"` and `data-slot="date-picker-content"` on the floating layer.
- `data-slot="date-picker-view"`, `date-picker-view-control`, `date-picker-view-trigger`,
  `date-picker-prev-trigger`, and `date-picker-next-trigger` on calendar navigation.
- `data-slot="date-picker-table-*"` on table parts and `data-slot="date-picker-table-cell-trigger"` on cells.
- `data-slot="date-picker-week-number-*"` on week-number cells.
- `data-slot="date-picker-month-select"` and `data-slot="date-picker-year-select"` on native selects.
- `data-slot="date-picker-preset-trigger"` on range preset buttons.

Ark state attributes include `data-state`, `data-disabled`, `data-readonly`, `data-invalid`,
`data-focus`, `data-selected`, `data-today`, `data-unavailable`, `data-outside-range`,
`data-in-range`, `data-range-start`, `data-range-end`, `data-in-hover-range`,
`data-hover-range-start`, `data-hover-range-end`, and `data-view`.
