Use `ScrollArea` as the root. Put `ScrollAreaViewport` around `ScrollAreaContent`, add one
`ScrollAreaScrollbar` and `ScrollAreaThumb` for

block size so the content has room to scroll.

## Composition

Each scroll axis needs its own `ScrollAreaScrollbar` with a `ScrollAreaThumb`. The vertical
scrollbar is the default; set `orientation="horizontal"` for a horizontal axis. Keep
`ScrollAreaViewport` around `ScrollAreaContent`, and keep a complete independent tree for nested
scroll areas.

Use `ScrollAreaRootProvider` with `useScrollArea()` when controls outside the root need
the scrolling API. Pass the returned store to `ScrollAreaRootProvider`, and do not render `ScrollArea`
and `ScrollAreaRootProvider` for the same store. In Solid, read and call the store through the accessor
returned by `useScrollArea()`.

## Anatomy

```text
ScrollArea
├─ ScrollAreaViewport
│  └─ ScrollAreaContent
│     └─ children
├─ ScrollAreaScrollbar
│  └─ ScrollAreaThumb
└─ ScrollAreaCorner

ScrollAreaRootProvider
└─ same tree connected to a useScrollArea() store
```

| Part                             | Role                                                               |
| -------------------------------- | ------------------------------------------------------------------ |
| `ScrollArea`                     | Root part that owns scroll state and positioning.                  |
| `ScrollAreaRootProvider`        | Connects the parts to state created with `useScrollArea()`.        |
| `ScrollAreaViewport`            | Native scroll container and focus target.                          |
| `ScrollAreaContent`             | Inner content wrapper measured by Ark UI.                          |
| `ScrollAreaScrollbar`           | Styled scrollbar track for one axis.                              |
| `ScrollAreaThumb`               | Draggable thumb inside a scrollbar.                                |
| `ScrollAreaCorner`              | Fills the intersection when both axes overflow.                   |

## Styling

The CSS variable table applies to the CSS Modules packages. Tailwind packages use their native
utilities and consumer `className` or `class` overrides. Set the CSS variables on the root to change
the scrollbar thickness, the thumb color, or the fade depth. The viewport inherits the root
`border-radius`, so a rounded root also rounds the clipped content and the focus ring.

### Styling hooks

| Part | `data-slot` |
| --- | --- |
| `ScrollArea` | `scroll-area-root` |
| `ScrollAreaRootProvider` | `scroll-area-root-provider` |
| `ScrollAreaViewport` | `scroll-area-viewport` |
| `ScrollAreaContent` | `scroll-area-content` |
| `ScrollAreaScrollbar` | `scroll-area-scrollbar` |
| `ScrollAreaThumb` | `scroll-area-thumb` |
| `ScrollAreaCorner` | `scroll-area-corner` |

- `data-fade` is added by the `fade` prop and `data-variant="hover" | "always"` by the `variant`
  prop on `ScrollArea` and `ScrollAreaRootProvider`.
- Ark adds `data-scope="scroll-area"` and `data-part` for every part.
- `data-overflow-x` and `data-overflow-y` are present when the measured content overflows on the
  corresponding axis.
- `data-at-top`, `data-at-bottom`, `data-at-left`, and `data-at-right` are available on
  `ScrollAreaViewport`.
- `data-orientation="vertical"` and `data-orientation="horizontal"` are exposed on scrollbars
  and thumbs.
- `data-hover` and `data-dragging` are available on scrollbar and thumb parts; `data-scrolling` is
  available on scrollbar parts.
- Ark root variables `--corner-width`, `--corner-height`, `--thumb-width`, and `--thumb-height`
  drive the corner offset and thumb dimensions. Ark viewport variables
  `--scroll-area-overflow-x-start`, `--scroll-area-overflow-x-end`,
  `--scroll-area-overflow-y-start`, and `--scroll-area-overflow-y-end` expose edge distances.
