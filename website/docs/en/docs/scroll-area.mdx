## Basic


Use `ScrollArea` as the root. Put `Viewport` around `Content`, add one `Scrollbar` and `Thumb` for
each scroll axis, and add `Corner` when both axes can overflow. Give the root a bounded height or
block size so the content has room to scroll.

## Anatomy

```text
ScrollArea / ScrollArea.Root
├─ ScrollArea.Viewport
│  └─ ScrollArea.Content
│     └─ children
├─ ScrollArea.Scrollbar
│  └─ ScrollArea.Thumb
└─ ScrollArea.Corner

ScrollArea.RootProvider
└─ same tree connected to a useScrollArea() store
```

| Part                             | Role                                                               |
| -------------------------------- | ------------------------------------------------------------------ |
| `ScrollArea` / `ScrollArea.Root` | Root part that owns scroll state and positioning.                  |
| `ScrollArea.RootProvider`        | Connects the parts to state created with `useScrollArea()`.        |
| `ScrollArea.Viewport`            | Native scroll container and focus target.                          |
| `ScrollArea.Content`             | Inner content wrapper measured by Ark UI.                          |
| `ScrollArea.Scrollbar`           | Styled scrollbar track for one axis.                              |
| `ScrollArea.Thumb`               | Draggable thumb inside a scrollbar.                                |
| `ScrollArea.Corner`              | Fills the intersection when both axes overflow.                   |

## Composition

Each scroll axis needs its own `ScrollArea.Scrollbar` with a `ScrollArea.Thumb`. The vertical
scrollbar is the default; set `orientation="horizontal"` for a horizontal axis. Keep
`Viewport` around `Content`, and keep a complete independent tree for nested scroll areas.

Use `ScrollArea.RootProvider` with `ScrollArea.useScrollArea()` when controls outside the root need
the scrolling API. Pass the returned store to `RootProvider`, and do not render `ScrollArea` and
`ScrollArea.RootProvider` for the same store. In Solid, read and call the store through the accessor
returned by `useScrollArea()`.

## Styling

The CSS variable table applies to the CSS Modules packages. Tailwind packages use their native
utilities and consumer `className` or `class` overrides. Use CSS variables on the root when
scrollbar thickness, focus ring treatment, or surface styling needs to change without replacing
the structure.

### Styling hooks

- moduix adds stable `data-slot` hooks with the values `scroll-area-root`, `scroll-area-root-provider`,
  `scroll-area-viewport`, `scroll-area-content`, `scroll-area-scrollbar`, `scroll-area-thumb`, and
  `scroll-area-corner`.
- `data-fade` is added by the `fade` prop and `data-variant="hover" | "always"` by the `variant`
  prop on `ScrollArea` and `ScrollArea.RootProvider`.
- Ark adds `data-scope="scroll-area"` and `data-part` for every part.
- `data-overflow-x` and `data-overflow-y` are present when the measured content overflows on the
  corresponding axis.
- `data-at-top`, `data-at-bottom`, `data-at-left`, and `data-at-right` are available on the
  viewport.
- `data-orientation="vertical"` and `data-orientation="horizontal"` are exposed on scrollbars
  and thumbs.
- `data-hover` and `data-dragging` are available on scrollbar and thumb parts; `data-scrolling` is
  available on scrollbar parts.
- Ark root variables `--corner-width`, `--corner-height`, `--thumb-width`, and `--thumb-height`
  drive the corner offset and thumb dimensions. Ark viewport variables
  `--scroll-area-overflow-x-start`, `--scroll-area-overflow-x-end`,
  `--scroll-area-overflow-y-start`, and `--scroll-area-overflow-y-end` expose edge distances.
