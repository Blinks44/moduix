## Basic

Use `ScrollArea` as the Ark root and compose `Viewport`, `Content`, `Scrollbar`, `Thumb`, and
`Corner` explicitly. The viewport remains a native scroll container, so scrolling with a mouse
wheel, trackpad, touch, or keyboard continues to work. The scrollbar parts add styled controls.
moduix also adds `fade`, which applies a top and bottom mask based on Ark's overflow measurements.

## Anatomy

```text
ScrollArea
├─ ScrollArea.Viewport
│  └─ ScrollArea.Content
│     └─ children
├─ ScrollArea.Scrollbar
│  └─ ScrollArea.Thumb
└─ ScrollArea.Corner
```

| Part                             | Role                                                               |
| -------------------------------- | ------------------------------------------------------------------ |
| `ScrollArea` / `ScrollArea.Root` | State owner and outer positioning container.                       |
| `ScrollArea.RootProvider`        | Root that receives the state returned by `ScrollArea.useScrollArea()`. |
| `ScrollArea.Viewport`            | Native scroll container and focus target.                          |
| `ScrollArea.Content`             | Inner content wrapper measured by Ark UI.                          |
| `ScrollArea.Scrollbar`           | Styled scrollbar track for one axis.                               |
| `ScrollArea.Thumb`               | Draggable thumb inside a scrollbar.                                |
| `ScrollArea.Corner`              | Fills the intersection at the bottom end when both axes overflow. |

## Composition

### Recommended composition

Use `ScrollArea` in most cases. It does not render `Viewport`, `Content`, or `Scrollbar` for you;
add the Ark parts explicitly so each structural node remains configurable. Give the root a bounded
height or block size. Without a size constraint, the content expands the root instead of scrolling.

### When to go custom

Use `ScrollArea.useScrollArea()` with `ScrollArea.RootProvider` when controls outside the root need
to call the scroll area API. The package also exports `useScrollArea` and `useScrollAreaContext`;
`useScrollArea` is also available as `ScrollArea.useScrollArea()`. Use `ScrollArea.Context` or
`useScrollAreaContext()` for advanced state reads. Do not render `ScrollArea` and
`ScrollArea.RootProvider` for the same state object.

### Default props

| Prop                                                    | Default    | Notes                                                                                  |
| ------------------------------------------------------- | ---------- | -------------------------------------------------------------------------------------- |
| `fade` on `ScrollArea` and `ScrollArea.RootProvider`    | `false`    | Adds a top and bottom viewport mask driven by Ark `--scroll-area-overflow-y-*` values. |
| `variant` on `ScrollArea` and `ScrollArea.RootProvider` | `hover`    | Use `always` to keep overflowing scrollbar tracks visible and interactive.             |
| `orientation` on `ScrollArea.Scrollbar`                | `vertical` | Set `orientation="horizontal"` for a horizontal track.                                |
| `asChild`                                               | `false`    | Available on every Ark part for composing a single child as the host element.         |
| `ids` on `ScrollArea`                                   | generated  | Use when separate code needs stable root, viewport, content, scrollbar, or thumb IDs.  |

### Behavioral notes

- Render one `ScrollArea.Scrollbar` per axis you want to expose.
- Pass Ark's `dir="rtl"` to the root for right-to-left scrolling; moduix uses logical positioning
  so the vertical scrollbar follows the inline-end edge.
- Ark adds `data-overflow-x` and `data-overflow-y`; moduix hides scrollbar tracks until the matching
  axis actually overflows.
- Set `variant="always"` when the matching overflowing scrollbar should remain visible and
  interactive at rest.
- The viewport styles hide native browser scrollbars with `scrollbar-width: none` and the WebKit
  scrollbar rule required by Ark UI.
- In forced-colors mode, moduix disables the optional fade mask so it cannot obscure content and
  uses system colors for the viewport focus ring and scrollbar thumb.
- Refs are forwarded to the underlying DOM element of every wrapped part. In particular, the ref on
  `ScrollArea` points to the root element and the ref on `ScrollArea.Viewport` points to the native
  scroll container.

## Styling

Use CSS variables on the root when scrollbar thickness, focus ring treatment, or surface styling
needs to change without replacing the structure. The default thumb uses the border token color,
and the scrollbar grows by `2px` on hover or drag, so the thumb grows with it. Customize the amount
with `--moduix-scroll-area-thumb-hover-increase` and the timing with
`--moduix-scroll-area-thumb-hover-transition`.

### Styling hooks

- moduix adds stable `data-slot` hooks with the values `scroll-area-root`, `scroll-area-root-provider`,
  `scroll-area-viewport`, `scroll-area-content`, `scroll-area-scrollbar`, `scroll-area-thumb`, and
  `scroll-area-corner`.
- `data-fade` is added by the `fade` prop and `data-variant="hover" | "always"` by the `variant`
  prop on `ScrollArea` and `ScrollArea.RootProvider`.
- Ark adds `data-scope="scroll-area"` and `data-part` for every part.
- `data-overflow-x` and `data-overflow-y` are present when the measured content overflows on the
  corresponding axis.
- `data-at-top`, `data-at-bottom`, `data-at-left`, and `data-at-right` are available on the viewport.
- `data-orientation="vertical"` and `data-orientation="horizontal"` are exposed on scrollbars and
  thumbs.
- `data-hover` and `data-dragging` are available on scrollbar and thumb parts; `data-scrolling` is
  available on scrollbar parts.
- Ark root variables `--corner-width`, `--corner-height`, `--thumb-width`, and `--thumb-height`
  drive the corner offset and thumb dimensions. Ark viewport variables
  `--scroll-area-overflow-x-start`, `--scroll-area-overflow-x-end`,
  `--scroll-area-overflow-y-start`, and `--scroll-area-overflow-y-end` expose edge distances.
