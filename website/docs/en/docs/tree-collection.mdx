# Tree Collection

A tree collection stores hierarchical data for `TreeView` and custom tree interfaces. It has no UI,
selection, focus, or keyboard behavior. Use it to create a typed hierarchy, query relationships,
traverse and filter nodes, and produce immutable updates.

## Basic

`createTreeCollection` accepts a `rootNode`. The default node shape reads `value`, `label`,
`children`, and the optional `disabled` property. The root is a container and is not included in
`getValues()`.

Use the collection as the data source for `TreeView`. Render `collection.rootNode.children` and pass
each node's numeric position as its `indexPath`.

## Query and navigation

An `indexPath` is the numeric position of a node at each level below the root. Values are stable
identifiers; use them in application state and resolve index paths when an operation needs one.

```tsx
const treePath = collection.getIndexPath('src/components/Tree.tsx')!; // [0, 1, 1]

collection.findNode('src');
collection.findNodes(['src', 'public']);
collection.at(treePath);
collection.getValue(treePath); // 'src/components/Tree.tsx'
collection.getValuePath(treePath); // ['src', 'src/components', 'src/components/Tree.tsx']
collection.getDepth('src/components/Tree.tsx'); // 3
collection.getValues(); // descendant values in traversal order
```

| API                              | Result                                           |
| -------------------------------- | ------------------------------------------------ |
| `findNode(value, rootNode?)`     | First node with the value, or `undefined`.       |
| `findNodes(values, rootNode?)`   | Nodes matching several values.                   |
| `getIndexPath(valueOrValuePath)` | Numeric path for a value or explicit value path. |
| `at(indexPath)`                  | Node at an index path, or `undefined`.           |
| `getValue(indexPath)`             | Value at an index path, or `undefined`.          |
| `getValuePath(indexPath)`         | Ancestor values followed by the target value.    |
| `getDepth(value)`                 | Node depth below the root.                       |
| `getValues(rootNode?)`            | Descendant values in traversal order.            |

Use the normalized accessors when the node shape is custom:

| API                          | Result                                    |
| ---------------------------- | ----------------------------------------- |
| `getNodeChildren(node)`      | Child nodes.                              |
| `getNodeChildrenCount(node)` | Known child count, or `undefined`.        |
| `getNodeValue(node)`         | Node value.                               |
| `stringifyNode(node)`        | Node display text.                        |
| `stringify(value)`           | Display text for a value, or `null`.      |
| `getNodeDisabled(node)`      | Disabled state.                           |
| `isRootNode(node)`           | Whether the node is the collection root.  |
| `isSameNode(node, other)`    | Whether two nodes have the same value.    |

Navigate the tree in traversal order or by sibling relationships:

```tsx
collection.getFirstNode();
collection.getLastNode();
collection.getNextNode('src');
collection.getPreviousNode('README.md');

collection.getParentNode('src/components/Tree.tsx');
collection.getParentNodes('src/components/Tree.tsx');
collection.getDescendantNodes('src');
collection.getDescendantValues('src');

collection.getNextSibling(treePath);
collection.getPreviousSibling(treePath);
collection.getSiblingNodes(treePath);
collection.contains(collection.getIndexPath('src')!, treePath);
```

`getFirstNode`, `getLastNode`, `getNextNode`, and `getPreviousNode` accept `{ skip }`. The callback
receives `{ value, node, indexPath }` and skips a node when it returns `true`. Pass
`{ withBranch: true }` to `getDescendantNodes` or `getDescendantValues` when branch nodes should be
included.

`sort(values)` orders values by their position in the tree. `isEqual(other)` compares collections,
and `toJSON()` returns the collection's descendant values.

## Traversal and filtering

Use `isBranchNode` and `getBranchValues` to inspect branches. `getBranchValues` also accepts a
`depth` filter and the same `skip` callback as the navigation methods.

```tsx
const src = collection.findNode('src');

if (src) collection.isBranchNode(src);
collection.getBranchValues();

const flatNodes = collection.flatten();
// Each result keeps the original node fields and adds _index, _parent, and _children.

collection.visit({
  onEnter(node, indexPath) {
    console.log(collection.getNodeValue(node), indexPath.length);

    if (collection.getNodeValue(node) === 'src') return 'skip';
  },
});
```

`visit` calls `onEnter` for each node. Return `'skip'` to omit a branch's descendants or `'stop'` to
end the traversal. `filter(predicate)` returns a new collection, keeps the hierarchy needed to reach
matching nodes, and passes `(node, indexPath)` to the predicate:

```tsx
const filteredTree = collection.filter((node) =>
  collection.stringifyNode(node).toLocaleLowerCase().includes('tree'),
);
```

## Immutable updates

Update methods return a new collection and leave the original unchanged. Index paths belong to one
collection snapshot. After inserting, removing, replacing, or moving nodes, resolve paths again from
the returned collection instead of reusing old numeric paths.

```tsx
const buttonPath = collection.getIndexPath('src/components/Button.tsx')!;
const readmePath = collection.getIndexPath('README.md')!;
const srcPath = collection.getIndexPath('src')!;

const withFile = collection.insertAfter(buttonPath, [
  { value: 'src/components/Select.tsx', label: 'Select.tsx' },
]);
const withoutReadme = collection.remove([readmePath]);
const renamed = collection.replace(buttonPath, {
  value: 'src/components/Button.new.tsx',
  label: 'Button.new.tsx',
});
const moved = collection.move([readmePath], srcPath);
```

`insertBefore` and `insertAfter` return `undefined` when the target path is invalid. Guard paths that
come from dynamic data before using them.

| API                         | Operation                                    |
| --------------------------- | -------------------------------------------- |
| `copy(rootNode)`            | Create a collection from a replacement root. |
| `replace(indexPath, node)`  | Replace one node.                            |
| `remove(indexPaths)`        | Remove one or more subtrees.                 |
| `insertBefore(path, nodes)` | Insert siblings before a node.               |
| `insertAfter(path, nodes)`  | Insert siblings after a node.                |
| `move(fromPaths, toPath)`   | Move subtrees to another location.           |
| `filter(predicate)`         | Return a filtered tree.                      |

When the collection is rendered by `TreeView`, store the collection returned by an update in the
state that owns the tree and render its new `rootNode`.

## Integration and accessibility

The collection manages hierarchy only. Use `TreeView` for tree semantics, focus, keyboard
navigation, expansion, and selection. A custom renderer must provide those behaviors itself. Keep
stable node values in application state, and resolve fresh index paths from the current collection
after an immutable update.
