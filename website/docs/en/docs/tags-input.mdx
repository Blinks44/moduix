## Choosing the right component

Use `TagsInput` when users need to enter and manage a list of editable string values in one form
control.

- Choose **`TagsInput`** for labels, skills, filters, recipients, topics, and other free-form string lists.
- Choose **`Tag`** when the interface only displays an existing token and may offer a separate remove action.
- Choose **`Combobox`** when users should select from a known collection and filtering is the main interaction.

## Basic

standard editable tag structure. The root also adds the hidden native form input automatically, so
pass root props such as `name` when the tags should be submitted with a form.

## Anatomy

```text
TagsInput / TagsInput.Root
├─ TagsInput.Label
├─ TagsInput.Control
│  ├─ TagsInput.Items
│  └─ TagsInput.Item[index, value]
│     ├─ TagsInput.ItemPreview
│     │  ├─ TagsInput.ItemText
│     │  └─ TagsInput.ItemDeleteTrigger
│     └─ TagsInput.ItemInput
│  ├─ TagsInput.Input
│  └─ TagsInput.ClearTrigger
└─ hidden native form input (automatic)
```

| Part                                   | Role                                                                 |
| -------------------------------------- | -------------------------------------------------------------------- |
| `TagsInput` / `TagsInput.Root`         | Root state, tag values, entry input, validation, and form integration. |
| `TagsInput.RootProvider`               | Renders the tags input from state returned by Ark `useTagsInput`.     |
| `TagsInput.Label`                      | Accessible label for the tags input.                                 |
| `TagsInput.Control`                    | Visible shell containing tags, the entry input, and the clear trigger. |
| `TagsInput.Items`                      | Standard editable tag renderer for the current root values.          |
| `TagsInput.Item`                       | One tag. Pass `index` and `value`.                                    |
| `TagsInput.ItemContext`                | Render-prop access to the current tag's state.                       |
| `TagsInput.ItemPreview`                | Visible tag content outside edit mode.                                |
| `TagsInput.ItemText`                   | Visible tag text.                                                     |
| `TagsInput.ItemDeleteTrigger`          | Removes one tag; moduix supplies a compact close icon by default.    |
| `TagsInput.ItemInput`                  | Input used when a tag is edited in place.                             |
| `TagsInput.Input`                      | Entry input for new tags.                                             |
| `TagsInput.ClearTrigger`               | Clears all tags; moduix uses the shared `CloseButton.Root` by default. |
| `TagsInput.Context`                    | Render-prop access to the root state inside the component tree.       |
| `useTagsInputContext`                  | Accesses root state and methods from a descendant component.          |
| `useTagsInputItemContext`              | Accesses the current tag's state inside an item.                     |
| `moduix useTagsInput` + `RootProvider` | External state ownership and imperative methods.                     |

## Composition

### Recommended composition

Use the short `<TagsInput>` form, which is equivalent to `<TagsInput.Root>`. Place
`TagsInput.Items`, `TagsInput.Input`, and `TagsInput.ClearTrigger` inside `TagsInput.Control`.
This gives you the standard editable tag behavior and keeps the hidden native form input in place.

To participate in a form, pass `name` to the root. Use `form` when the associated form is outside
the component's DOM subtree.

### When to go custom

Use `TagsInput.Context` and the lower-level item parts when tags need custom content or actions.
Map `tagsInput.value` to `TagsInput.Item`, pass its `index` and `value`, and keep `ItemInput` inside
the item so inline editing continues to work. Use `ItemContext` or `useTagsInputItemContext` when
custom item content depends on the current tag state.

Use `TagsInput.RootProvider` with moduix `useTagsInput` when state or imperative methods such as
`addValue`, `setValue`, `clearValue`, `setInputValue`, or `focus` must be available outside the
rendered tags input tree. Use `ids` when `TagsInput` shares an input or control with another Ark
primitive, such as `Combobox`.

Every primitive part supports `asChild` with one semantic child that forwards its props and `ref`.
When the root uses `asChild`, that child must also render its children so moduix can append the
automatic hidden form input. `TagsInput.Items` is a convenience renderer and does not accept part
props; use the lower-level parts for custom item markup.

### Default props

| Prop                | Default                   | Notes                                                                 |
| ------------------- | ------------------------- | --------------------------------------------------------------------- |
| `defaultValue`      | `[]`                      | Initial tag array for uncontrolled usage.                             |
| `value`             | -                         | Controlled tag array. Update it from `onValueChange(details).value`.  |
| `defaultInputValue` | `''`                      | Initial entry input value for uncontrolled usage.                     |
| `inputValue`        | -                         | Controlled entry input value.                                         |
| `delimiter`         | `','`                     | String or regular expression used for delimiter keys and paste splitting. |
| `max`               | `Infinity`                | Maximum number of tags.                                               |
| `maxLength`         | -                         | Maximum number of characters accepted by the entry input.             |
| `allowOverflow`     | `false`                   | Allows more than `max` tags while marking the root invalid.           |
| `allowDuplicates`   | `false`                   | Allows the same string value to be added more than once.              |
| `editable`          | `true`                    | Allows a tag to enter edit mode after focus, Enter, or a double click. |
| `addOnPaste`        | `false`                   | Splits pasted text into tags using `delimiter`.                       |
| `blurBehavior`      | -                         | Set to `"add"` to commit the entry value on blur or `"clear"` to discard it. |
| `sanitizeValue`     | `(value) => value.trim()` | Normalizes each value before validation and addition.                 |

The `disabled`, `invalid`, `readOnly`, `required`, and `autoFocus` options are off unless you set
them. Use `placeholder` for the entry input and `translations` for accessible labels.

### Behavioral notes

`onValueChange(details)`, `onInputValueChange(details)`, `onHighlightChange(details)`, and
`onValueInvalid(details)` receive Ark detail objects. `validate(details)` accepts or rejects the
pending tag, while `sanitizeValue(value)` normalizes it before validation and addition. The
outside-interaction callbacks `onFocusOutside`, `onInteractOutside`, and `onPointerDownOutside`
receive their corresponding events.

`Field.Root` and `Fieldset.Root` can provide `disabled`, `invalid`, `required`, and `readOnly`
state through Ark context. The default clear trigger uses `CloseButton.Root` through Ark
`asChild`; item deletion keeps a smaller tag-level icon button.

### Styling hooks

- The root and root provider expose `data-slot="tags-input-root"` and `data-slot="tags-input-root-provider"`.
- Ark parts keep `data-scope="tags-input"` and their `data-part` values from the anatomy.
- State styling can use `data-disabled`, `data-readonly`, `data-invalid`, `data-focus`, `data-empty`,
  `data-required`, `data-value`, and `data-highlighted` on the parts where Ark emits them.
- Delete and clear triggers expose stable `data-slot` hooks. Item deletion uses a compact close icon;
  clear-all uses the shared `CloseButton.Root` styling.
- `TagsInput.ClearTrigger` stays at the inline end of the control when tag rows wrap.
- In read-only state, moduix hides the entry input and clear trigger, leaving only the immutable tag
  values visible.

## Accessibility

Ark wires the label, tag highlighting, inline edit mode, deletion, paste handling, and hidden form
input. The root's hidden input serializes the tag list for native form submission; pass `name` and,
when needed, `form` to associate it with a form.

### Keyboard support

- `Enter` in the entry input adds its current value. `Enter` on a highlighted tag enters edit mode.
- Double-clicking a tag also enters edit mode when `editable` is `true`.
- When the entry input is empty or the caret is at its start, `ArrowLeft` and `ArrowRight` move visual focus between tags.
- `Backspace` and `Delete` remove the highlighted tag. `Backspace` also removes the last tag when the entry input is empty.
- With `addOnPaste`, `Control+V` adds pasted values after splitting them with `delimiter`.
