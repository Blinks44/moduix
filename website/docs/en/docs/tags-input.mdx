## Choosing the right component

Use `TagsInput` when users need to enter and manage a list of editable string values in one form
control.

- Choose **`TagsInput`** for labels, skills, filters, recipients, topics, and other free-form string lists.
- Choose **`Tag`** when the interface only displays an existing token and may offer a separate remove action.
- Choose **`Combobox`** when users should select from a known collection and filtering is the main interaction.

## Anatomy

```text
TagsInput
├─ TagsInputLabel
├─ TagsInputControl
│  ├─ TagsInputItems
│  └─ TagsInputItem[index, value]
│     ├─ TagsInputItemPreview
│     │  ├─ TagsInputItemText
│     │  └─ TagsInputItemDeleteTrigger
│     └─ TagsInputItemInput
│  ├─ TagsInputInput
│  └─ TagsInputClearTrigger
└─ TagsInputHiddenInput (explicit)

TagsInputRootProvider
└─ same part tree connected to a useTagsInput() store
```

| Part | Role |
| --- | --- |
| `TagsInput` | Root state, tag values, entry input, validation, and form integration. |
| `TagsInputRootProvider` | Connects the parts to state returned by `useTagsInput()`. |
| `TagsInputLabel` | Accessible label for the tags input. |
| `TagsInputControl` | Visible shell containing tags, the entry input, and the clear trigger. |
| `TagsInputItems` | Standard editable tag renderer for the current root values. |
| `TagsInputItem` | One tag. Pass `index` and `value` when rendering custom items. |
| `TagsInputItemContext` | Render-prop access to the state of the current item inside the component tree. |
| `TagsInputItemPreview` | Visible tag content outside edit mode. |
| `TagsInputItemText` | Visible tag text. |
| `TagsInputItemDeleteTrigger` | Removes one tag and provides a compact close icon by default. |
| `TagsInputItemInput` | Input used when a tag is edited in place. |
| `TagsInputInput` | Entry input for new tags. |
| `TagsInputClearTrigger` | Clears all tags and uses the shared close-button visual by default. |
| `TagsInputHiddenInput` | Explicit native input for form submission. |
| `TagsInputContext` | Render-prop access to the root state inside the component tree. |

## Composition

Use the short `<TagsInput>` form for the standard composition. Keep `TagsInputItems`,
`TagsInputInput`, and `TagsInputClearTrigger` inside `TagsInputControl`. Add
`TagsInputHiddenInput` explicitly and pass `name` to the root when the tags must be submitted with
a form. Use `form` when the associated form is outside the component tree.

For custom tag content or actions, use `TagsInputContext` and map its values to
`TagsInputItem` with `index` and `value`. Keep `TagsInputItemInput` inside each item when inline
editing should remain available. Use `TagsInputRootProvider` with `useTagsInput()` only when state
or methods such as `addValue`, `clearValue`, or `focus` must be used outside the component tree.
In Solid, the store is an accessor, so read `tagsInput().value` and call `tagsInput().addValue()`.
When combining `TagsInput` with `Combobox`, share the input and control IDs and compose the inputs
with `asChild`.

### Styling hooks

- The root and root provider expose `data-slot="tags-input-root"` and `data-slot="tags-input-root-provider"`.
- Ark parts keep `data-scope="tags-input"` and their `data-part` values from the anatomy.
- State styling can use `data-disabled`, `data-readonly`, `data-invalid`, `data-focus`, `data-empty`, `data-required`, `data-value`, and `data-highlighted` where Ark emits them.
- Delete and clear triggers expose stable `data-slot` hooks. Item deletion uses a compact close icon; clear-all uses the shared close-button styling.
- CSS Modules use the documented `--moduix-tags-input-*` variables. Tailwind variants use native utilities and consumer class overrides.
- In read-only state, moduix hides the entry input, item delete triggers, and the clear trigger, leaving only immutable tag values visible.

## Accessibility

Ark wires the label, tag highlighting, inline edit mode, deletion, paste handling, and hidden form
input. The explicit hidden input serializes the tag list for native form submission; pass `name` and,
when needed, `form` to associate it with a form.

### Keyboard support

- `Enter` in the entry input adds its current value. `Enter` on a highlighted tag enters edit mode.
- Double-clicking a tag also enters edit mode when `editable` is `true`.
- When the entry input is empty or the caret is at its start, `ArrowLeft` and `ArrowRight` move visual focus between tags.
- `Backspace` and `Delete` remove the highlighted tag. `Backspace` also removes the last tag when the entry input is empty.
- With `addOnPaste`, `Control+V` adds pasted values after splitting them with `delimiter`.
