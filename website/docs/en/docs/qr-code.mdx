## Basic

Use `QrCode` for the usual case. Pass the content to encode with `defaultValue`, then render
`QrCode.Frame` and `QrCode.Pattern` to display the generated SVG. Give `QrCode.Frame` an accessible
name when the QR code conveys information.

## Anatomy

```text
QrCode / QrCode.Root
├─ QrCode.Frame
│  └─ QrCode.Pattern
├─ QrCode.Overlay
└─ QrCode.DownloadTrigger

QrCode.RootProvider
└─ same part tree connected to useQrCode() from @moduix/react
```

| Part                     | Role                                                                    |
| ------------------------ | ----------------------------------------------------------------------- |
| `QrCode` / `QrCode.Root` | Owns the encoded value and generation options, and provides QR state.   |
| `QrCode.RootProvider`    | Connects the parts to a `useQrCode()` state object created outside them. |
| `QrCode.Frame`           | SVG element that contains the generated QR code.                       |
| `QrCode.Pattern`         | SVG path that draws the QR modules.                                     |
| `QrCode.Overlay`         | Centered content rendered over the QR code.                             |
| `QrCode.DownloadTrigger` | Button that downloads the current QR code as an image.                  |

## Composition

### Recommended composition

`QrCode` is the short root form of `QrCode.Root`. Use either one with `QrCode.Frame` and
`QrCode.Pattern` kept explicit. Use `defaultValue` for an uncontrolled QR code. When the value comes
from application state, use `value` with `onValueChange(details)` instead.

Add `QrCode.Overlay` only when the covered area is small enough for the code to remain scannable. Set
`encoding={{ ecc: 'H' }}` for an overlay and test the final code with the scanners your users rely on.

### When to go custom

Use `QrCode.RootProvider` when QR state must be created outside the rendered tree or when external
controls need access to the QR API. Create the state with `useQrCode()` from `@moduix/react/qr-code`,
then pass it to `RootProvider`. Use `QrCode.Context` or `useQrCodeContext()` when a descendant needs
the current value or the QR API. Do not render `QrCode` and `QrCode.RootProvider` for the same state
object.

Use `asChild` on an Ark part only when another element should be the rendered host. Keep the replacement
child semantic and single. Use `ids` when a custom composition needs stable ids for the root or frame.

### Common props

The table lists the props most consumers need. Every part also accepts its corresponding DOM props,
including `className` and `asChild` where supported. See the API reference for the complete Ark
surface.

| Part            | Prop            | Notes                                                                  |
| --------------- | --------------- | ---------------------------------------------------------------------- |
| Root            | `defaultValue`  | Initial value for uncontrolled usage.                                  |
| Root            | `value`         | Controlled value to encode.                                            |
| Root            | `onValueChange` | Receives Ark's details object. Read the new value from `details.value`. |
| Root            | `encoding`      | Generator options such as `ecc` and `boostEcc`.                        |
| Root            | `pixelSize`     | Pixel size passed to the QR generator.                                 |
| Root            | `id`            | Stable machine id forwarded to Ark.                                    |
| Root            | `ids`           | Stable ids for the root and frame elements.                            |
| RootProvider    | `value`         | Required state object returned by `useQrCode()`.                       |
| DownloadTrigger | `fileName`      | Required name of the downloaded file.                                  |
| DownloadTrigger | `mimeType`      | Required image type, such as `image/png` or `image/svg+xml`.            |
| DownloadTrigger | `quality`       | Optional image quality passed to the generator.                        |

### Behavioral notes

`onValueChange(details)` keeps the controlled value in sync with the QR state. It uses Ark's original
details object, so read the encoded value from `details.value`.

`QrCode.Context` and `useQrCodeContext()` expose the nearest QR API to descendants. The API includes
the current `value`, `setValue`, and `getDataUrl()` for generating a data URL.

The QR code is not a form control and does not render a hidden input. It also has no QR-specific
arrow-key navigation or roving focus. `QrCode.DownloadTrigger` is a native button, so it keeps normal
button focus, keyboard activation, and disabled behavior.

The SVG is visual content. Add `role="img"` and an `aria-label` to `QrCode.Frame` when the code
conveys information. If it repeats nearby text, use adjacent text and `aria-hidden="true"` on the
frame instead.

### Error Correction

Use `encoding.ecc` to choose how much damaged data the QR code can recover. Higher levels help when
an overlay covers part of the code or when the code may be scratched or distorted.

- `L`: recovers up to 7% of damaged data.
- `M`: recovers up to 15%.
- `Q`: recovers up to 25%.
- `H`: recovers up to 30%.

## Styling

Moduix adds token-backed styles for the QR size, spacing, fill, overlay, and download trigger. Use
`className` for component-specific styles and the stable `data-slot` attributes for shared selectors.
The CSS Variables panel lists the complete public variable set.

Ark also sets `--qrcode-pixel-size`, `--qrcode-width`, and `--qrcode-height` on the root at runtime.
These variables describe the generated frame and can be useful when integrating custom styles.

### Styling hooks

- `QrCode.Root` -> `data-slot="qr-code-root"`
- `QrCode.RootProvider` -> `data-slot="qr-code-root-provider"`
- `QrCode.Frame` -> `data-slot="qr-code-frame"`
- `QrCode.Pattern` -> `data-slot="qr-code-pattern"`
- `QrCode.Overlay` -> `data-slot="qr-code-overlay"`
- `QrCode.DownloadTrigger` -> `data-slot="qr-code-download-trigger"`
- Ark hooks: `data-scope="qr-code"` and `data-part="root|frame|pattern|overlay|download-trigger"`
