Build a splitter from `Splitter`, `SplitterPanel`, and `SplitterResizeTrigger`. The `panels` prop
lists the panel ids and their size constraints. Each rendered `SplitterPanel` must use one of those
ids. When you omit the trigger's children, moduix renders a resize indicator for you.

### Collapsible panels

Set `collapsible: true` and choose a `collapsedSize` for a panel that can turn into a narrow rail. Set
`minSize` to the same value when pointer resizing should remain continuous to the collapsed size. If
`minSize` is larger, the splitter snaps between the expanded minimum and the collapsed rail.

## Composition

Use `size` with `onResize(details)` when the application controls the current panel sizes. Use
`SplitterRootProvider` with `useSplitter()` when the store or its controls must live outside the
rendered panel tree, and choose one root for each store. For nested splitters that should resize
together at handle intersections, create one `createSplitterRegistry()` and pass it to every root.
Numeric `defaultSize`, `size`, and `minSize` values are percentages expected to total 100, and Ark
also accepts CSS lengths for these sizes.

Use `asChild` only with one interactive child that keeps button semantics, focus behavior, and
keyboard interaction; it replaces the default resize indicator. In Solid, `useSplitter()` returns an
accessor, so pass it to `value` and read the API as `splitter()`.

In Vue, use `v-model:size` for the Ark-controlled size contract. `useSplitter()` returns a reactive
store that can be passed directly to `SplitterRootProvider`; read its methods in the template without
creating a second state container.

## Styling

Use `className` in React or `class` in Solid and Vue on exported parts to change their styles. A class
also changes the root size: moduix removes Ark's inline `width` and `height`, and the root fills its container
with `width: 100%` and `height: 100%`, like Ark. Give the root a height when its parent has none.

Ark sets `overflow: hidden` inline on every panel so content cannot change panel sizes. Put long content
in a scroll container inside the panel, for example `ScrollArea`.

The resize trigger reserves a `1px` divider in the layout and draws a thinner `0.5px` line over it.
Its transparent hit area makes the handle easier to use, and the rounded indicator sits on top of the
line. Hover and dragging darken the line and the indicator border and raise the indicator shadow. The
line and the hit area are pseudo-elements, so the CSS Modules variants expose them as the variables
below.

| Part | `data-slot` |
| --- | --- |
| `Splitter` | `splitter-root` |
| `SplitterRootProvider` | `splitter-root-provider` |
| `SplitterPanel` | `splitter-panel` |
| `SplitterResizeTriggerIndicator` | `splitter-resize-trigger-indicator` |
| `SplitterResizeTrigger` | `splitter-resize-trigger` |

Ark writes `data-scope="splitter"` and `data-part` to the rendered parts.

Useful part-specific attributes include `data-id` and `data-index` on panels, plus
`data-orientation`, `data-dragging`, `data-focus`, and `data-disabled` on the relevant parts.

## Accessibility

`SplitterResizeTrigger` renders a `type="button"` button, so it never submits a surrounding form, and provides pointer and keyboard resizing according to the WAI-ARIA
Window Splitter pattern. Give each trigger an accessible name, for example with
`aria-label="Resize panels"`, when its visual handle has no text label. If you use `asChild`, the
custom host must keep button semantics, focus behavior, and keyboard interaction.

Ark exposes state through attributes such as `data-orientation`, `data-dragging`, `data-focus`, and
`data-disabled`. Use these attributes when styling interaction states.

## Keyboard

| Key | Action |
| --- | --- |
| `ArrowLeft` / `ArrowRight` | Resizes the panels from the focused handle; ArrowUp and ArrowDown when vertical. |
| `Home` / `End` | Moves the handle to its minimum or maximum. |
| `Enter` | Collapses or expands a collapsible panel. |
| `F6` | Moves focus to the next resize handle. |
