## Basic

Build a splitter from three parts: `Splitter`, `Splitter.Panel`, and `Splitter.ResizeTrigger`. The
`panels` prop lists the panel ids and their size constraints. Each rendered `Splitter.Panel` must use
one of those ids. When you omit the trigger's children, moduix renders a resize indicator for you.

## Anatomy

```text
Splitter
├─ Splitter.Panel[id]
├─ Splitter.ResizeTrigger[id="panel-a:panel-b"]
│  └─ Splitter.ResizeTriggerIndicator (default, customizable)
└─ Splitter.Panel[id]
```

| Part                              | Role                                                                           |
| --------------------------------- | ------------------------------------------------------------------------------ |
| `Splitter` / `Splitter.Root`      | Manages panel definitions, sizes, orientation, callbacks, and splitter state. |
| `Splitter.Panel`                  | Resizable region whose `id` must match an entry in `panels`.                  |
| `Splitter.ResizeTrigger`          | Accessible button for resizing the two adjacent panels.                       |
| `Splitter.ResizeTriggerIndicator` | Default visual handle. Custom trigger children replace it.                   |
| `Splitter.RootProvider`           | Renders the same parts using state created with `useSplitter()`.              |

## Composition

### Recommended composition

Place panels and resize triggers in the same order in which they appear on screen. Give each trigger
an id in the `"left:right"` format so Ark can connect the two adjacent panels. Leave the trigger's
children out to use the default resize indicator. Add children only when you need custom content.

### When to customize

Use a controlled `size` value with `onResize(details)` when the current panel sizes need to live in
application state. Use `useSplitterContext()` for imperative methods inside the splitter subtree.
Create state with `useSplitter()` and pass it to `Splitter.RootProvider` when the state or its controls
need to live outside the rendered part tree. For nested splitters that should resize together at
handle intersections, create one registry with `createSplitterRegistry()` and pass it to every root.

Choose either `Splitter` or `Splitter.RootProvider` for a splitter instance. Do not render both roots
for the same state.

Use `asChild` only when another element must be the rendered host. A custom resize trigger must keep
button semantics, focus behavior, and keyboard interaction. With `asChild`, provide exactly one
interactive trigger child. The default resize indicator is not added in this mode.

### Default props

| Prop               | Default          | Notes                                                                  |
| ------------------ | ---------------- | ---------------------------------------------------------------------- |
| `orientation`      | `"horizontal"`   | Use `"vertical"` for stacked panels.                                  |
| `defaultSize`      | omitted          | Ark calculates the initial sizes. Percentage values are SSR-friendly. |
| `keyboardResizeBy` | omitted          | Uses Ark's default number of pixels for keyboard resizing.             |
| `size`             | omitted          | Uncontrolled mode. Pair it with `onResize(details)` to control sizes.  |
| `disabled`         | `false`          | Set it on `ResizeTrigger` to disable one resize handle.                |
| `registry`         | omitted          | Pass a shared registry to nested splitters for multi-drag support.     |

### Behavior

`panels` is required. Each entry can define constraints such as `minSize`, `maxSize`, `collapsible`,
and `collapsedSize`. Numeric `defaultSize` and controlled `size` values are percentages and should add
up to `100`. Ark also accepts CSS lengths for initial and constraint sizes. These lengths are measured
in the browser, so the layout can settle differently after hydration.

The callbacks keep Ark's detail objects: `onResize(details)`, `onResizeEnd(details)`,
`onCollapse(details)`, and `onExpand(details)`. `onResizeStart()` runs when resizing begins.

`minSize` to the same value when pointer resizing should remain continuous all the way to the collapsed
size. If `minSize` is larger, the splitter snaps between the expanded minimum and the collapsed rail.

## Accessibility

`ResizeTrigger` renders a button and provides pointer and keyboard resizing according to the WAI-ARIA
Window Splitter pattern. Give each trigger an accessible name, for example with `aria-label="Resize
panels"`, when its visual handle has no text label. If you use `asChild`, the custom host must keep
button semantics, focus behavior, and keyboard interaction.

Ark exposes state through attributes such as `data-orientation`, `data-dragging`, `data-focus`, and
`data-disabled`. Use these attributes when styling interaction states.

## Styling

Style `Splitter` with `className`, Ark attributes, stable `data-slot="splitter-*"` hooks, and the
public moduix CSS variables below. `Splitter.Root` and `Splitter.RootProvider` set the default
`--moduix-splitter-width` and `--moduix-splitter-height` values through inline styles, so those
variables can override Ark's root layout size. The default surface is applied to the root, while
panels stay flat and flush inside it.

The resize trigger reserves a `1px` divider in the layout and draws a thinner `0.5px` line over it.
Its transparent hit area makes the handle easier to use, and the rounded indicator sits on top of the
line. Hover and dragging states strengthen the line, border, and shadow. Override the corresponding
`--moduix-splitter-resize-trigger-*` variables when the surrounding theme needs a different treatment.

### Styling hooks

Ark writes `data-scope="splitter"` and `data-part` to the rendered parts. moduix also writes these
`data-slot` values: `splitter-root`, `splitter-root-provider`, `splitter-panel`,
`splitter-resize-trigger`, and `splitter-resize-trigger-indicator`.

Useful part-specific attributes include `data-id` and `data-index` on panels, plus
`data-orientation`, `data-dragging`, `data-focus`, and `data-disabled` on the relevant parts.
