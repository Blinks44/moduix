## Choosing the right component

Choose `ColorPicker` when users need to pick or fine-tune a color. Choose `Input` when they only need
to enter a known value and do not need to manipulate the color directly.

## Anatomy

```text
ColorPicker
├─ ColorPicker.Label
├─ ColorPicker.Control
│  ├─ ColorPicker.ChannelInput[channel]
│  └─ ColorPicker.Trigger
│     ├─ ColorPicker.TransparencyGrid
│     └─ ColorPicker.ValueSwatch
├─ Overlay subtree (automatically portalled)
│  └─ ColorPicker.Positioner
│     └─ ColorPicker.Content
│        ├─ ColorPicker.Area
│        │  ├─ ColorPicker.AreaBackground
│        │  └─ ColorPicker.AreaThumb
│        ├─ ColorPicker.EyeDropperTrigger
│        ├─ ColorPicker.ChannelSlider[channel]
│        │  ├─ ColorPicker.TransparencyGrid
│        │  ├─ ColorPicker.ChannelSliderTrack
│        │  └─ ColorPicker.ChannelSliderThumb
│        ├─ ColorPicker.SwatchGroup
│        │  └─ ColorPicker.SwatchTrigger[value]
│        │     └─ ColorPicker.Swatch[value]
│        │        └─ ColorPicker.SwatchIndicator
│        └─ ColorPicker.View[format]
│           └─ ColorPicker.ChannelInput[channel]
└─ native input (automatic)
```

| Part                               | Role                                                                   |
| ---------------------------------- | ---------------------------------------------------------------------- |
| `ColorPicker`                      | Owns color value, format, popup state, and form integration.           |
| `ColorPicker.Control`              | Groups visible inputs and trigger.                                     |
| `ColorPicker.Trigger`              | Button that opens the popup and renders the current swatch by default. |
| `ColorPicker.Content`              | Actual Ark popup content part.                                         |
| `ColorPicker.Area`                 | Two-dimensional color interaction surface.                             |
| `ColorPicker.ChannelSlider`        | One-dimensional channel control for hue, alpha, or other channels.     |
| `ColorPicker.Sliders`              | Styled hue and alpha slider pair.                                      |
| `ColorPicker.ChannelInput`         | Text or numeric input for a specific color channel.                    |
| `ColorPicker.SwatchTrigger`        | Selectable preset color button.                                        |
| `ColorPicker.ValueSwatch`          | Visual swatch for the current value.                                   |

`ColorPicker.RootProvider`, `parseColor`, `useColorPicker`, and `useColorPickerContext` cover the
normal advanced state path. Import Ark-only type helpers directly when needed as an escape hatch.

## Composition

`ColorPicker.Positioner` renders through a portal by default. Set `portalled={false}` to render it
in the current document structure, or pass `portalRef` to use a custom container. Structural parts
remain explicit and styleable.

### Recommended composition

Keep `ColorPicker.Positioner` and `ColorPicker.Content` explicit for popup-based pickers. `Content`
is the Ark part that contains the popup, while `Positioner` places it in the configured portal.

Leave `Trigger`, `Area`, `ChannelSlider`, and `SwatchTrigger` without children to use their default
visual composition. Use `ColorPicker.Sliders` for the usual hue and alpha pair. Style its channels
through `data-channel` or CSS variables, and pass children only when a part needs custom structure.
Add `data-fit-content` when the trigger should size to custom content such as a swatch plus
`ValueText`.

To include the color in native form submission and reset behavior, pass `name` to `ColorPicker`.
It renders and synchronizes the native input automatically, so `FormData` and `form.reset()` need
no extra setup.

### When to go custom

Use `inline` on `ColorPicker` when the area, sliders, inputs, and swatches should stay visible in a
panel instead of a popup. Use `ColorPicker.View` to show inputs for one format at a time.

Use `useColorPicker` with `ColorPicker.RootProvider` when the state needs to live outside the
rendered subtree. Do not render `Root` and `RootProvider` for the same state instance.

Use `asChild` on exported Ark parts when another semantic element must own the DOM node. The child
must stay a single element and preserve the required focus and interaction behavior.

### Default props

By default, the portalled overlay content mounts on first open and unmounts after its exit
animation. Set `unmountOnExit={false}` to keep it mounted after the first open. Set both lifecycle
props to `false` only when eager initial rendering is needed.

| Surface / Prop                           | Default                 | Notes                                         |
| ---------------------------------------- | ----------------------- | --------------------------------------------- |
| `defaultValue`                           | `parseColor("#000000")` | Ark default color value.                      |
| `defaultFormat`                          | `"rgba"`                | Ark default format.                           |
| `ColorPicker.Content` width              | `16rem`                 | Prevents collapse to trigger swatch width.    |
| `ColorPicker.EyeDropperTrigger`          | moduix pipette icon     | Used when children are omitted.               |
| `ColorPicker.Trigger` children           | current swatch          | Renders `TransparencyGrid` and `ValueSwatch`. |
| `ColorPicker.Area` children              | background and thumb    | Used when children are omitted.               |
| `ColorPicker.ChannelSlider` children     | track and thumb         | Alpha sliders also render `TransparencyGrid`. |
| `ColorPicker.Sliders`                    | hue and alpha pair      | Style with `data-channel` or CSS variables.   |
| `ColorPicker.SwatchTrigger` children     | swatch and indicator    | Uses the trigger `value` for the swatch.      |
| `ColorPicker.SwatchIndicator`            | moduix check icon       | Used when children are omitted.               |
| `ColorPicker` width                      | `16rem` (max `100%`)    | Styled root width defaults.                   |

### Behavioral notes

- `value` and `defaultValue` use Ark `Color` objects. Use `parseColor()` for string defaults.
- `onValueChange(details)` and `onValueChangeEnd(details)` preserve Ark detail objects.
- `onFormatChange(details)` and `onOpenChange(details)` preserve Ark detail objects.
- `ids` is forwarded to Ark for shared accessibility IDs across custom compositions.
- Field and fieldset state can flow through Ark-compatible `disabled`, `invalid`, `required`, and
  `readOnly` root props.
- Use `positioning`, `initialFocusEl`, and `openAutoFocus` when popup placement or focus needs to
  follow a surrounding workflow.
- `lazyMount` and `unmountOnExit` default to `true`; `present` and `onExitComplete` preserve Ark's
  presence lifecycle for custom mount or exit-animation control.
- All Ark DOM parts preserve `asChild`.

## Styling

Style `ColorPicker` through `className`, stable `data-slot="color-picker-*"` hooks, Ark
`data-scope` / `data-part` attributes, and the public `--moduix-color-picker-*` CSS variables shown
below.

### CSS Properties

<CssPropertiesSection properties={ColorPickerDocs.colorPickerOverrideCssProperties} />

### Styling hooks

Use the part that owns the visual concern:

- `ColorPicker` for width, gap, shared color, and disabled opacity
- `ColorPicker.Control`, `ChannelInput`, `Trigger`, `FormatSelect`, and `FormatTrigger` for the
  visible field controls
- `ColorPicker.Positioner` and `ColorPicker.Content` for popup layering, width, padding, radius,
  shadow, and state animations
- `ColorPicker.Area`, `AreaBackground`, and `AreaThumb` for the two-dimensional color surface
- `ColorPicker.ChannelSlider`, `ChannelSliderTrack`, `ChannelSliderThumb`, and `Sliders` for hue,
  alpha, and other channel sliders
- `ColorPicker.SwatchGroup`, `SwatchTrigger`, `Swatch`, and `SwatchIndicator` for preset color
  grids
- `ColorPicker.ValueSwatch`, `ValueText`, `View`, and `TransparencyGrid` for value display and
  format-specific layouts

The main state hooks are `data-state`, `data-focus`, `data-invalid`, `data-disabled`,
`data-readonly`, `data-required`, `data-channel`, `data-orientation`, `data-value`,
`data-placement`, and `data-side`. Ark runtime variables include `--color`, `--value`,
`--available-width`, `--available-height`, and `--transform-origin`.

When `prefers-reduced-motion` is enabled, popup entry and exit animations use a 1ms duration so Ark
can complete its exit lifecycle without visible motion.
