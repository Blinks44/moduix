## Choosing the right component

Choose `ColorPicker` when users need to pick or fine-tune a color. Choose `Input` when they only need
to enter a known value and do not need to manipulate the color directly.

## Anatomy

```text
ColorPicker
├─ ColorPickerLabel
├─ ColorPickerControl
│  ├─ ColorPickerChannelInput[channel]
│  └─ ColorPickerTrigger
│     ├─ ColorPickerTransparencyGrid
│     └─ ColorPickerValueSwatch
├─ Overlay subtree (automatically portalled)
│  └─ ColorPickerPositioner
│     └─ ColorPickerContent
│        ├─ ColorPickerArea
│        │  ├─ ColorPickerAreaBackground
│        │  └─ ColorPickerAreaThumb
│        ├─ ColorPickerEyeDropperTrigger
│        ├─ ColorPickerChannelSlider[channel]
│        │  ├─ ColorPickerTransparencyGrid
│        │  ├─ ColorPickerChannelSliderTrack
│        │  └─ ColorPickerChannelSliderThumb
│        ├─ ColorPickerSwatchGroup
│        │  └─ ColorPickerSwatchTrigger[value]
│        │     └─ ColorPickerSwatch[value]
│        │        └─ ColorPickerSwatchIndicator
│        └─ ColorPickerView[format]
│           └─ ColorPickerChannelInput[channel]
└─ ColorPickerHiddenInput (explicit)
```

| Part                               | Role                                                                   |
| ---------------------------------- | ---------------------------------------------------------------------- |
| `ColorPicker` | Owns color value, format, popup state, and form integration.           |
| `ColorPickerHiddenInput` | Native Ark form control; compose explicitly as described below. |
| `ColorPickerLabel` | Accessible label for the visible picker controls. |
| `ColorPickerControl`              | Groups visible inputs and trigger.                                     |
| `ColorPickerTrigger`              | Button that opens the popup and renders the current swatch by default. |
| `ColorPickerPositioner` | Floating layer that positions the popup and exposes Ark positioning CSS variables. |
| `ColorPickerContent`              | Actual Ark popup content part.                                         |
| `ColorPickerArea`                 | Two-dimensional color interaction surface.                             |
| `ColorPickerAreaBackground` | Background layer that captures pointer input for the color area. |
| `ColorPickerEyeDropperTrigger` | Samples a color from the screen; rendered only where the browser supports the EyeDropper API. |
| `ColorPickerChannelSlider`        | One-dimensional channel control for hue, alpha, or other channels.     |
| `ColorPickerTransparencyGrid` | Checkerboard backdrop that makes alpha visible behind a trigger or channel slider. |
| `ColorPickerSliders`              | Styled hue and alpha slider pair.                                      |
| `ColorPickerChannelInput`         | Text or numeric input for a specific color channel.                    |
| `ColorPickerSwatchTrigger`        | Selectable preset color button.                                        |
| `ColorPickerSwatch` | Colored surface rendered inside a swatch trigger or value swatch. |
| `ColorPickerSwatchIndicator` | Optional marker inside a swatch, such as a check for the selected preset. |
| `ColorPickerValueSwatch`          | Visual swatch for the current value.                                   |
| `ColorPickerValueText` | Read-only text of the formatted value. |

`ColorPickerRootProvider`, `parseColor`, `useColorPicker`, and `useColorPickerContext` cover the
normal advanced state path.

## Composition

Use `defaultValue` for local state. When application state owns the selected color or popup, pass `value` with `onValueChange(details)` or `open` with `onOpenChange(details)`. In Vue, bind the same state with `v-model`, `v-model:open`, and `v-model:format`. For state created outside the rendered tree, pass `useColorPicker()` to `ColorPickerRootProvider`; do not render `ColorPicker` and `ColorPickerRootProvider` for the same store.

`ColorPickerPositioner` is portalled by default. Set `portalled={false}` for an overlay inside another stacking context. To submit the color with a native form, set `name` on the root and render `ColorPickerHiddenInput` explicitly. Parts such as `ColorPickerArea`, `ColorPickerChannelSlider`, and `ColorPickerSwatchTrigger` provide default visual children; pass children only when changing their structure.

In Solid, assign a ref to the element created inside the `asChild` render function. A ref on a
ColorPicker part itself is not forwarded through that composition path. In Vue, use the ordinary
template `ref` on a part and read the rendered element through `$el`.

### Styling hooks

Use the part that owns the visual concern:

- `ColorPicker` for width, gap, shared color, and disabled opacity
- `ColorPickerControl`, `ColorPickerChannelInput`, `ColorPickerTrigger`, `ColorPickerFormatSelect`, and `ColorPickerFormatTrigger` for the
  visible field controls
- `ColorPickerPositioner` and `ColorPickerContent` for popup layering, width, padding, radius,
  shadow, and state animations
- `ColorPickerArea`, `ColorPickerAreaBackground`, and `ColorPickerAreaThumb` for the two-dimensional color surface
- `ColorPickerChannelSlider`, `ColorPickerChannelSliderTrack`, `ColorPickerChannelSliderThumb`, and `ColorPickerSliders` for hue,
  alpha, and other channel sliders
- `ColorPickerSwatchGroup`, `ColorPickerSwatchTrigger`, `ColorPickerSwatch`, and `ColorPickerSwatchIndicator` for preset color
  grids
- `ColorPickerValueSwatch`, `ColorPickerValueText`, `ColorPickerView`, and `ColorPickerTransparencyGrid` for value display and
  format-specific layouts

The main state hooks are `data-state`, `data-focus`, `data-invalid`, `data-disabled`,
`data-readonly`, `data-required`, `data-channel`, `data-orientation`, `data-value`,
`data-placement`, and `data-side`. Ark runtime variables include `--color`, `--value`,
`--available-width`, `--available-height`, and `--transform-origin`.

When `prefers-reduced-motion` is enabled, popup entry and exit animations use a 1ms duration so Ark
can complete its exit lifecycle without visible motion.
