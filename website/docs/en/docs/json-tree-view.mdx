## Choosing the right component

Use `JsonTreeView` when you already have a JavaScript value and need to inspect it without writing a recursive
renderer. Choose `TreeView` when you own the node model and need custom labels, icons, links, renaming, or branch
content.

## Basic

Pass any JSON-like JavaScript value through `data`, then render `<JsonTreeView.Tree />` inside the component.
`JsonTreeView` generates the object, array, and value nodes for you. moduix styles the rows, indentation, focus
states, and default disclosure icon.

The example starts with two levels expanded. Use `defaultExpandedDepth` to choose how much of a response or
configuration should be visible on the first render.

## Anatomy

```text
JsonTreeView / JsonTreeView.Root
└─ JsonTreeView.Tree
   └─ generated JSON branches and items
```

| Part | Role |
| --- | --- |
| `JsonTreeView` / `JsonTreeView.Root` | Owns the data, generated tree collection, and Ark tree state. |
| `JsonTreeView.RootProvider` | Connects a `useJsonTreeView` state instance created outside the rendered tree. |
| `JsonTreeView.Tree` | Renders the generated object, array, and value nodes. |

## Composition

### Recommended composition

Use the `<JsonTreeView>` shorthand with `<JsonTreeView.Tree />` for a regular data inspector. It is equivalent to
`<JsonTreeView.Root>`, while `Tree` renders the JSON nodes automatically.

### When to go custom

Use `TreeView` when the application needs to decide how branches and items are rendered. If the generated structure
is right but individual values need a different presentation, use `renderValue` on `JsonTreeView.Tree`.

### RootProvider

Use `useJsonTreeView` when controls outside the tree need to read or change its state, such as the expanded or
selected nodes. Pass the returned state to `RootProvider` and render `Tree` inside it. Do not render `Root` and
`RootProvider` for the same state instance.

```tsx
import { JsonTreeView, useJsonTreeView } from '@moduix/react/json-tree-view';

function InspectResponse({ data }: { data: unknown }) {
  const tree = useJsonTreeView({ data });

  return (
    <JsonTreeView.RootProvider value={tree}>
      <JsonTreeView.Tree />
    </JsonTreeView.RootProvider>
  );
}
```

### Common options

| Prop | Use it for |
| --- | --- |
| `defaultExpandedDepth` | Choose the initial number of expanded levels. |
| `maxPreviewItems` | Limit the number of items shown in object and array previews. |
| `collapseStringsAfterLength` | Shorten long string previews until a node is expanded. |
| `groupArraysAfterLength` | Group items in long array previews. |
| `renderValue` | Replace the default rendering for individual values. |
| `translations` | Provide localized accessible labels and state text. |

### Behavioral notes

Ark supports objects, arrays, primitives, and JavaScript values such as `Date`, `Map`, `Set`, `Error`, functions,
and regular expressions. The component follows the WAI-ARIA tree pattern with roving focus, arrow-key navigation,
expansion, and selection. When the application owns state, control `expandedValue`, `selectedValue`, `checkedValue`,
or `focusedValue` and update it from the corresponding change callback.

## Styling

Use `className` on `Root`, `RootProvider`, or `Tree` for local layout changes. `JsonTreeView.Tree` uses the
`ChevronRightIcon` supplied by moduix when `arrow` is omitted; pass your own `arrow` when the inspection surface
needs a different disclosure icon.

Generated nodes preserve Ark's `data-scope="json-tree-view"` and `data-part` attributes. moduix adds the stable
`data-slot="json-tree-view-root"`, `json-tree-view-root-provider`, and `json-tree-view-tree` hooks.

The component uses foundation tokens directly, without a separate `--moduix-json-tree-view-*` variable layer. Add a
`className` or target Ark part attributes when an inspection surface needs different styling.
