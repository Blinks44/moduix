## Usage

<Usage />

Start with `AngleSliderDial`, which combines the circular track, the centered value, and the thumb. The track
fills from the top as the angle grows. `AngleSlider` accepts one angle
from 0 to 360 degrees. Add a visible `AngleSliderLabel` when possible. If the dial has no visible label, add
`aria-label` to the root.

## Choosing the right component

Use `AngleSlider` when users need to set a direction or rotation on a circular dial.

- Choose **`AngleSlider`** for rotation, heading, spotlight direction, and other angular values.
- Choose **`Slider`** when the value is easier to understand on a linear scale.
- Choose **`NumberInput`** when entering an exact degree value matters more than direct manipulation.

## Composition

Use `defaultValue` for an uncontrolled slider and `value` with `onValueChange(details)` when
another part of the application controls the angle. Use `AngleSliderRootProvider` with
`useAngleSlider()` from the matching framework package only when the store must be created outside
the rendered slider tree; do not render the root and `AngleSliderRootProvider` for the same
state instance. In Solid and Svelte, read the provider store through its accessor or getter, for example `angleSlider().value`. Svelte also supports `bind:value` on `AngleSlider` for a controlled angle.

`AngleSliderDial` and `AngleSliderMarks` are convenience compositions. Use `AngleSliderControl` with
`AngleSliderThumb`, or `AngleSliderMarkerGroup` with `AngleSliderMarker`, when you need custom
children, a different order, or per-marker props.
Compose `AngleSliderHiddenInput` explicitly for native forms. Set `name` on the root for a form in the same
tree, or set `form` on `AngleSliderHiddenInput` when the form is elsewhere.

## Styling

Use `className` in React or `class` in Solid, Vue, and Svelte on exported parts for structural styles. For state-based
styles, prefer Ark data attributes such as `data-state`, `data-disabled`, `data-invalid`, and
`data-readonly`, together with moduix `data-slot` selectors. Tailwind variants use native utilities
and consumer classes; the component variables below customize the CSS Modules variants. Ark runtime
variables and the listed data hooks remain available in both styling tracks.

## Keyboard

| Key | Action |
| --- | --- |
| `ArrowRight` / `ArrowDown` | Increases the angle by one step. |
| `ArrowLeft` / `ArrowUp` | Decreases the angle by one step. |
| `Shift` + arrows | Changes the angle by a large step. |
| `Home` / `End` | Sets the angle to 0 or 360. |

## API reference

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `value` | `number` | — | Angle in degrees for controlled use. |
| `defaultValue` | `number` | `0` | Initial angle in degrees. |
| `onValueChange` | `(details: ValueChangeDetails) => void` | — | Called while the angle changes. |
| `onValueChangeEnd` | `(details: ValueChangeDetails) => void` | — | Called once the user finishes changing the value. |
| `step` | `number` | `1` | Step in degrees. |
| `name` | `string` | — | Form field name of the underlying input. |
| `disabled` | `boolean` | `false` | Disables the control. |
| `readOnly` | `boolean` | `false` | Shows the value but prevents changes. |
| `invalid` | `boolean` | `false` | Marks the control as invalid. |
| `required` | `boolean` | `false` | Requires a value before form submission. |
| `aria-label` | `string` | — | Accessible name when there is no visible label. |
| `aria-labelledby` | `string` | — | Id of the element that labels the control. |
