## Choosing the right component

Use `AngleSlider` when users need to set a direction or rotation on a circular dial.

- Choose **`AngleSlider`** for rotation, heading, spotlight direction, and other angular values.
- Choose **`Slider`** when the value is easier to understand on a linear scale.
- Choose **`NumberInput`** when entering an exact degree value matters more than direct manipulation.

## Basic

Start with the smallest useful composition: `Dial`. `AngleSlider` accepts one angle from 0 to 360

## Anatomy

```text
AngleSlider.Root
├─ AngleSlider.Label
├─ AngleSlider.Control
│  ├─ AngleSlider.MarkerGroup
│  │  └─ AngleSlider.Marker[value]
│  └─ AngleSlider.Thumb
├─ AngleSlider.ValueText
└─ hidden native form input (added automatically)
```

| Part                               | Role                                                                  |
| ---------------------------------- | --------------------------------------------------------------------- |
| `AngleSlider` / `AngleSlider.Root` | Styled root that holds controlled or uncontrolled slider state.       |
| `AngleSlider.RootProvider`         | Connects the parts to Ark state created outside the rendered tree.    |
| `AngleSlider.Label`                | Associates a visible label with the slider.                           |
| `AngleSlider.Control`              | Provides the circular pointer interaction area.                       |
| `AngleSlider.Dial`                 | Composition of `Control` and `Thumb`; accepts children and `thumbClassName`.             |
| `AngleSlider.MarkerGroup`          | Contains optional reference markers.                                  |
| `AngleSlider.Marker`               | Places a numeric marker and exposes its relation to the current value. |
| `AngleSlider.Marks`                | Convenience composition that creates markers from a `values` array.    |
| `AngleSlider.Thumb`                | Focusable handle that indicates the current angle.                     |
| `AngleSlider.ValueText`            | Displays the current value in degrees.                                |

moduix adds the hidden native form input automatically when you use `Root` or `RootProvider`. You
do not need to render `HiddenInput` yourself.

## Composition

### Recommended composition

Start with `Dial`, then add only the parts you need:

- add `Label` or `aria-label` to give the control an accessible name
- add `Marks` when users need reference points around the dial
- add `ValueText` when the numeric angle should remain visible
- set `name` when the angle should be included in native form submission
- set `form` when the native input belongs to a form that does not contain the slider

### When to go custom

Use explicit `Control`, `Thumb`, `MarkerGroup`, and `Marker` parts when you need custom children,
per-marker props, or a different order. Use `useAngleSlider()` from `@moduix/react/angle-slider`
with `AngleSlider.RootProvider` when state must be available outside the rendered slider tree. To
read the state in a descendant, use `AngleSlider.Context` or `useAngleSliderContext()` from
`@moduix/react/angle-slider`. Do not render `Root` and `RootProvider` for the same state instance.

Ark DOM parts support `asChild`; provide one compatible child that preserves their keyboard, focus,
ARIA, and pointer behavior. `Dial` and `Marks` always render a fixed multi-part composition, so they
do not accept `asChild`. With `Root` or `RootProvider`, use a container that can hold the internally
rendered hidden input and slider parts. Use `ids` on `Root` when composed elements need stable shared
IDs. Refs are forwarded to the DOM element rendered by each wrapped Ark part.

### Default props

| Prop           | Default | Notes                                      |
| -------------- | ------- | ------------------------------------------ |
| `defaultValue` | `0`     | Initial angle in uncontrolled mode         |
| `step`         | `1`     | Keyboard and pointer increment             |
| `disabled`     | `false` | Prevents focus and interaction             |
| `readOnly`     | `false` | Keeps the value visible but prevents changes |
| `invalid`      | `false` | Exposes invalid state to ARIA and styling  |

### Behavioral notes

- `value` is a single number. `onValueChange(details)` and `onValueChangeEnd(details)` receive Ark
  callback objects with `details.value` and `details.valueAsDegree`.
- The thumb supports Ark's slider keyboard behavior and pointer dragging around the circular control.
- `AngleSlider.Marks` renders the same marker DOM and styling hooks as explicit `MarkerGroup` /
  `Marker` composition.
- `Root` and `RootProvider` render a hidden native form input automatically. Set `name` to include
  the angle in form submission and `form` to associate it with an external form. A native reset
  returns an uncontrolled `Root` to `defaultValue` and a `RootProvider` to the value it had when it
  mounted. In controlled mode, the external owner remains authoritative.
- `ValueText` renders Ark's degree string when no custom children are provided.
- `data-disabled`, `data-invalid`, `data-readonly`, marker `data-state`, `--value`, `--angle`,
  `--marker-value`, and `--marker-display-value` remain available for styling.

## Styling

Style the component with `className`, stable `data-slot="angle-slider-*"` hooks, Ark
`data-scope="angle-slider"` / `data-part` attributes, state attributes, and the public CSS
variables below.

### CSS Properties

### Styling hooks

- `data-slot="angle-slider-root"` and `data-slot="angle-slider-root-provider"` provide shared layout.
- `data-slot="angle-slider-control"` styles the dial and receives `data-disabled`, `data-invalid`,
  and `data-readonly`.
- `data-slot="angle-slider-thumb"` styles the focusable rotating indicator and can be targeted with
  `:focus-visible`.
- `data-slot="angle-slider-marker"` exposes `data-value` and
  `data-state="under-value | at-value | over-value"`.
- `AngleSlider.Marks` renders the same `data-slot="angle-slider-marker-group"` and
  `data-slot="angle-slider-marker"` hooks as the explicit marker parts.
- Ark root variables `--value` and `--angle` and marker variables `--marker-value` and
  `--marker-display-value` remain available.
- Hover and active ring colors apply only while the dial is interactive. Thumb motion is removed
  when the user prefers reduced motion.
