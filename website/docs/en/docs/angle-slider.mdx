## Choosing the right component

Use `AngleSlider` when users need to set a direction or rotation on a circular dial.

- Choose **`AngleSlider`** for rotation, heading, spotlight direction, and other angular values.
- Choose **`Slider`** when the value is easier to understand on a linear scale.
- Choose **`NumberInput`** when entering an exact degree value matters more than direct manipulation.

## Basic


Start with `Dial`, which combines the circular control and thumb. `AngleSlider` accepts one angle
from 0 to 360 degrees. Add a visible `Label` when possible. If the dial has no visible label, add

## Anatomy

```text
AngleSlider / AngleSlider.Root
├─ AngleSlider.Label
├─ AngleSlider.Dial
│  └─ AngleSlider.Thumb
├─ AngleSlider.Marks (optional)
│  └─ AngleSlider.Marker[value]
├─ AngleSlider.ValueText
└─ AngleSlider.HiddenInput (explicit)

AngleSlider.RootProvider
└─ same part tree connected to a useAngleSlider() store
```

| Part                               | Role                                                                  |
| ---------------------------------- | --------------------------------------------------------------------- |
| `AngleSlider` / `AngleSlider.Root` | Styled root that owns controlled or uncontrolled slider state.        |
| `AngleSlider.RootProvider`         | Connects the parts to state created with `useAngleSlider()`.          |
| `AngleSlider.Label`                | Associates a visible label with the slider.                           |
| `AngleSlider.Control`              | Provides the circular pointer interaction area.                       |
| `AngleSlider.Dial`                 | Convenience composition of `Control` and `Thumb`.                     |
| `AngleSlider.Thumb`                | Focusable handle that indicates the current angle.                     |
| `AngleSlider.MarkerGroup`          | Contains optional reference markers.                                  |
| `AngleSlider.Marker`               | Places a numeric marker around the dial.                               |
| `AngleSlider.Marks`                | Convenience composition that creates markers from a `values` array.    |
| `AngleSlider.ValueText`             | Displays the current value in degrees.                                |
| `AngleSlider.HiddenInput`           | Native form control; compose it explicitly when submitting the value. |

## Composition

Use `defaultValue` for an uncontrolled slider and `value` with `onValueChange(details)` when
another part of the application owns the angle. Use `AngleSlider.RootProvider` with
`useAngleSlider()` from the matching framework package only when the store must be created outside
the rendered slider tree; do not render `Root` and `RootProvider` for the same state instance. In
Solid, read the provider store through its accessor, for example `angleSlider().value`.

`Dial` and `Marks` are convenience compositions. Use `Control` with `Thumb`, or
`MarkerGroup` with `Marker`, when you need custom children, a different order, or per-marker props.
Compose `HiddenInput` explicitly for native forms. Set `name` on the root for a form in the same
tree, or set `form` on `HiddenInput` when the form is elsewhere.

## Styling

Use `className` in React or `class` in Solid on exported parts for structural styles. For state-based
styles, prefer Ark data attributes such as `data-state`, `data-disabled`, `data-invalid`, and
`data-readonly`, together with moduix `data-slot` selectors. Tailwind variants use native utilities
and consumer classes; the component variables below customize the CSS Modules variants. Ark runtime
variables and the listed data hooks remain available in both styling tracks.

### Styling hooks

- Stable `data-slot` selectors include `angle-slider-root`, `angle-slider-root-provider`,
  `angle-slider-label`, `angle-slider-control`, `angle-slider-thumb`, `angle-slider-marker-group`,
  `angle-slider-marker`, and `angle-slider-value-text`.
- Ark part selectors use `data-scope="angle-slider"` and `data-part`.
- `AngleSlider.Marks` renders the same marker hooks as the explicit `MarkerGroup` and `Marker`
  parts.
- Root variables `--value` and `--angle`, and marker variables `--marker-value` and
  `--marker-display-value`, remain available for styling.
- Thumb motion is removed when the user prefers reduced motion.
