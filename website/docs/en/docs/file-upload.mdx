`useFileUploadContext` are also exported from `@moduix/react`.

## Basic

Start with `FileUpload` as the root. Add a `Label`, then use `Trigger` for a compact control or `Dropzone` for
drag-and-drop. Put `Items` inside `ItemGroup` to show accepted files. The root renders the hidden native file input
automatically. `Items` uses an image thumbnail only when the file has an `image/*` MIME type; otherwise it uses the
generic file preview.

## Anatomy

```text
FileUpload / FileUpload.Root
├─ FileUpload.Label
├─ FileUpload.Dropzone (optional)
│  ├─ FileUpload.DropzoneIcon
│  └─ FileUpload.Trigger
├─ FileUpload.Trigger (when no dropzone is used)
├─ FileUpload.ItemGroup[type]
│  ├─ FileUpload.Items
│  └─ FileUpload.Context
│     └─ FileUpload.Item[file]
│        ├─ FileUpload.ItemPreview[type]
│        │  ├─ FileUpload.ItemPreviewImage
│        │  └─ FileUpload.ItemPreviewIcon
│        ├─ FileUpload.ItemName
│        ├─ FileUpload.ItemMetadata[file]
│        ├─ FileUpload.ItemSizeText
│        └─ FileUpload.ItemDeleteTrigger
├─ FileUpload.ClearTrigger
└─ hidden native file input (automatic)
```

| Part                             | Role                                                                   |
| -------------------------------- | ---------------------------------------------------------------------- |
| `FileUpload` / `FileUpload.Root` | Owns file state and handles validation, drag-and-drop, paste, and form integration. |
| `FileUpload.RootProvider`        | Connects the upload tree to state returned by the `useFileUpload` hook.              |
| `FileUpload.Label`               | Accessible label for the hidden file input and upload controls.                     |
| `FileUpload.Dropzone`            | Drag-and-drop target. Pass `disableClick` when it contains a nested trigger.        |
| `FileUpload.DropzoneIcon`        | Decorative upload icon for a `Dropzone`.                                            |
| `FileUpload.Trigger`             | Button that opens the native file picker.                                           |
| `FileUpload.ItemGroup`           | List for accepted or rejected files.                                                 |
| `FileUpload.Items`               | Convenience component that renders image cards and file rows with previews, metadata, and delete controls. |
| `FileUpload.Context`             | Ark-compatible render-prop context for custom file rows.                             |
| `FileUpload.Item`                | File row. Pass it the current `file` object.                                         |
| `FileUpload.ItemPreview`         | Preview slot that matches a file by MIME type.                                       |
| `FileUpload.ItemPreviewImage`    | Image preview inside `ItemPreview`.                                                  |
| `FileUpload.ItemPreviewIcon`     | Generic file icon for a fallback preview inside `ItemPreview`.                      |
| `FileUpload.ItemName`            | File name text.                                                                      |
| `FileUpload.ItemMetadata`        | File type and localized size. Pass it the current `file` object.                    |
| `FileUpload.ItemSizeText`        | Localized file-size text.                                                            |
| `FileUpload.ItemDeleteTrigger`   | Removes one file. Defaults to the moduix trash icon.                                |
| `FileUpload.ClearTrigger`        | Clears selected files. Defaults to the moduix close icon.                           |

## Composition

### Recommended composition

Keep the Ark part tree explicit in your markup. Use `Trigger` on its own for a compact upload control and
`Dropzone` for a drag-and-drop area. When `Trigger` is nested inside `Dropzone`, pass `disableClick` to `Dropzone`
so the native file picker opens only once.

The root always renders the hidden native file input. Use `Items` inside `ItemGroup` for a compact list of accepted
files. When you need custom rows, read accepted files from `FileUpload.Context.acceptedFiles` and rejected files from
`FileUpload.Context.rejectedFiles`.

Use `FileUpload.Context`, `useFileUpload()`, and `useFileUploadContext()` when you need advanced access to state.
The context and hooks are direct Ark re-exports, so callback details and the state contract are unchanged.

### When to go custom

`Items` renders image files as compact vertical cards and other files as horizontal rows with metadata. Use explicit
`Context` composition for custom rows. `ItemPreview.type` is a regular-expression predicate, not a priority list,
so render exactly one preview for each file. For example, use `file.type.startsWith("image/")` to choose
`ItemPreviewImage`. For other files, render `ItemPreviewIcon`, then compose `ItemName`, `ItemMetadata file={file}`, and
`ItemDeleteTrigger`. Use `asChild` only when the child is a single semantic element that preserves the required
button, label, or input behavior.

### Default props

| Prop                  | Default | Notes                                                        |
| --------------------- | ------- | ------------------------------------------------------------ |
| `allowDrop`           | `true`  | Allows dropping files on `Dropzone`.                                      |
| `maxFiles`            | `1`     | Increase the value or remove the limit to accept multiple files or directories. |
| `minFileSize`         | `0`     | Smallest accepted file size in bytes.                                    |
| `maxFileSize`         | `∞`     | Largest accepted file size in bytes.                                     |
| `preventDocumentDrop` | `true`  | Prevents accidental navigation when a file is dropped outside the target. |
| `locale`              | `en-US` | Locale used to format file sizes.                                        |

### Behavioral notes

`acceptedFiles`, `defaultAcceptedFiles`, and `onFileChange(details)` follow Ark's controlled and uncontrolled
state model. `onFileChange` is called when the value changes, whether files are accepted or rejected. The
`onFileAccept(details)` and `onFileReject(details)` callbacks receive Ark's original detail objects, including
rejected-file errors. `Field.Root` and `Fieldset.Root` can provide `disabled`, `invalid`, `required`, and `readOnly`
state. Use `ids` when separate labels or descriptions need stable accessibility associations.

Target stable moduix slots such as `[data-slot="file-upload-dropzone"]`,
`[data-slot="file-upload-item"]`, and `[data-slot="file-upload-item-delete-trigger"]`.
Ark also exposes `data-scope="file-upload"`, part-specific `data-part`, and state attributes such as
`data-disabled`, `data-readonly`, `data-invalid`, `data-required`, `data-dragging`, and `data-type`.
