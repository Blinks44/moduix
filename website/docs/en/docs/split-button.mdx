## API Reference

Ark UI does not provide a dedicated split-button primitive. moduix composes this component with the official
[Ark factory](https://ark-ui.com/docs/guides/composition#the-ark-factory), follows Ark's guidance on
[composition](https://ark-ui.com/docs/guides/composition), [styling](https://ark-ui.com/docs/guides/styling), and
[refs](https://ark-ui.com/docs/guides/ref), and preserves the behavior of
[Ark Menu](https://ark-ui.com/docs/components/menu).

## Choosing the right component

Use `SplitButton` when one action should stay immediately available and related alternatives belong in a menu.
Use `Button` for a single action. Use `Menu` when the available actions are peers and none of them should be primary.

## Basic

Use the short `<SplitButton>` form, which is equivalent to `<SplitButton.Root>`, and keep the menu structure explicit with
`SplitButton.Action`, `SplitButton.Trigger`, `SplitButton.Positioner`, and `SplitButton.Content`.
The primary action follows the same `onClick` contract as `Button`.

## Anatomy

```text
SplitButton
├─ SplitButton.Action
├─ SplitButton.Trigger
└─ Popup subtree (automatically portalled)
   └─ SplitButton.Positioner
      └─ SplitButton.Content
         ├─ Menu.Item
         ├─ Menu.Separator
         └─ other shared Menu parts
```

| Part                               | Role                                                                  |
| ---------------------------------- | --------------------------------------------------------------------- |
| `SplitButton`                     | Manages Ark Menu state and the semantic group around the two buttons. |
| `SplitButton.Action`              | Primary Button action. Inherits root `variant` and `size` by default. |
| `SplitButton.Trigger`             | Ark Menu trigger rendered as a moduix Button with a chevron by default. |
| `SplitButton.Positioner`           | Positions the Ark Menu popup and exposes its placement variables.    |
| `SplitButton.Content`              | Ark Menu content surface for shared `Menu.*` parts.                  |

## Composition

By default, `SplitButton` places the menu `Positioner` in a portal. Set `portalled={false}` to keep it in the
current container, or pass `portalRef` to choose a custom portal container. `Positioner` and `Content` remain
explicit and styleable.

### Recommended composition

`SplitButton` forwards Ark `Menu.Root` props such as `open`, `defaultOpen`, `onOpenChange(details)`,
`onSelect(details)`, `closeOnSelect`, `positioning`, `ids`, `lazyMount`, `unmountOnExit`, and `typeahead`.

Use `SplitButton.Action` for the primary path. Put alternate actions in `SplitButton.Content` with the shared
`Menu.Item`, `Menu.Separator`, `Menu.ItemGroup`, `Menu.CheckboxItem`, and `Menu.RadioItem` parts.

### When to go custom

Use `asChild` on `SplitButton.Action` when the primary action should render as a semantic link or another compatible
element.

Pass custom visible content through `SplitButton.Trigger` `children`. The trigger keeps one built-in Button element,
so Ark Menu trigger behavior and moduix button styles apply to the same element.

Use `positioning` on `SplitButton` to control where the popup opens. Keep `SplitButton.Positioner` and
`SplitButton.Content` explicit when you need to style or configure the popup without rebuilding the component.

When the menu needs advanced state access, compose directly with `Menu.RootProvider` and `useMenu()` from the shared
`Menu` API instead of adding split-button-specific state wrappers.

### Default props

| Surface               | Prop          | Default                                  | Notes                                                  |
| --------------------- | ------------- | ---------------------------------------- | ------------------------------------------------------ |
| `SplitButton`         | `variant`     | `'default'`                              | Shared default for `Action` and `Trigger`.             |
| `SplitButton`         | `size`        | `'md'`                                   | Shared default for `Action` and `Trigger`.             |
| `SplitButton`         | `positioning` | `{ placement: 'bottom-end', gutter: 4 }` | Aligns the popup with the trigger edge.               |
| `SplitButton`         | `aria-label`  | -                                        | Gives the related button group an accessible name.     |
| `SplitButton`         | `aria-labelledby` | -                                     | Uses another element to name the related button group. |
| `SplitButton.Trigger` | `aria-label`  | `'More actions'` when icon-only          | Override it with a more specific accessible name.     |
| `SplitButton.Trigger` | `children`    | `ChevronDownIcon`                        | Replace it when the trigger needs custom visible content. |

### Behavioral notes

- `SplitButton` renders the attached controls in a `role="group"`. Give the group a contextual accessible name with
  `aria-label` or `aria-labelledby` when the surrounding content does not already identify it.
- Every exported DOM part forwards its `ref` to the element it renders.
- `SplitButton.Action` follows the shared moduix `Button` `asChild` contract.
- `SplitButton.Trigger` renders a moduix `Button` as the Ark Menu trigger element. It keeps
  `data-slot="split-button-trigger"` and receives Ark trigger ARIA and state attributes such as `aria-expanded`,
  `aria-controls`, and `data-state`. Custom trigger visuals go through `children` instead of another `asChild` layer.
- `SplitButton.Positioner` receives Ark Menu CSS variables such as `--reference-width`, `--available-height`, `--x`,
  `--y`, `--z-index`, and `--transform-origin`.
- `lazyMount` and `unmountOnExit` keep the shared `Menu` defaults, so popup content mounts when needed and unmounts
  after its close transition.
- Root `variant` excludes the `link` Button variant because a grouped link-style split button is not a coherent
  control.
- Root `size` excludes icon-only Button sizes because the default path expects a visible label on the primary action.

## Styling

`SplitButton` uses moduix `Button` and `Menu` styles, with split-button-specific slots for the joined-button appearance.

The separator between the two buttons and the trigger's horizontal padding are configurable through
`--moduix-split-button-separator-*` and `--moduix-split-button-trigger-padding-x-*`. Their defaults use shared border
and spacing tokens, so density presets stay aligned with `Button` while `Menu` continues to control popup row styles.

### Styling hooks

- `data-scope="split-button"` and `data-part="root"` target the `role="group"` wrapper.
- `data-slot="split-button-root"` targets the grouped wrapper.
- `data-slot="split-button-action"` targets the primary action side.
- `data-slot="split-button-trigger"` targets the dropdown trigger side.
- `data-slot="split-button-positioner"` targets the Ark Menu positioner wrapper.
- `data-slot="split-button-content"` targets the Ark Menu content surface.
- `SplitButton.Trigger` renders through the shared `Button` element and carries Ark Menu trigger ARIA and state
  attributes, including `data-state="open" | "closed"`.
- `SplitButton.Content` carries Ark Menu content attributes including `data-state`, `data-side`, `data-placement`,
  `data-nested`, and `data-has-nested`.
