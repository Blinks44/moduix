## API Reference

Ark UI does not include a dedicated `bleed` primitive. moduix builds `Bleed` with the official
[Ark factory](https://ark-ui.com/docs/guides/composition#the-ark-factory) and follows Ark's guidance on
[composition](https://ark-ui.com/docs/guides/composition), [styling](https://ark-ui.com/docs/guides/styling), and
[refs](https://ark-ui.com/docs/guides/ref).

Use [Container](/docs/container) to keep the main content at a readable width. Put `Bleed` inside it when
only a media block, background, divider, or banner should extend beyond the container.

Import `Bleed` from the matching runtime and styling package: `@moduix/react/bleed`,
`@moduix/solid/bleed`, or `@moduix/vue/bleed` for CSS Modules, and the corresponding
`@moduix/react-tailwind/bleed`, `@moduix/solid-tailwind/bleed`, or `@moduix/vue-tailwind/bleed`
subpath for Tailwind.

## Anatomy

`Bleed` renders one root element that follows Ark's conventions. It uses negative margins on the inline
and/or block axis, without adding an inner wrapper.

```text
Bleed
└─ root[data-scope="bleed"][data-part="root"][data-slot="bleed-root"]
   └─ children
```

| Part                   | Role                                                                   |
| ---------------------- | ---------------------------------------------------------------------- |
| `Bleed`                | Root component for extending content along the inline and block axes. |

## Composition

`Bleed` is presentational and owns no state. It has one root part, so there are no child parts to coordinate.
The defaults are `inline="full"`, `block="none"`, and `asChild={false}`.
When `asChild` should give the rendered root to one semantic element, provide exactly one child that accepts DOM
props and a ref in React, or use the Solid render-function form. React refs target the rendered root or child;
the Solid form does not forward the component ref through the custom host.
In Vue, Ark's factory renders one semantic child for `asChild`; read a component ref's rendered host through `$el`.

Combine `inline` and `block` when a surface should extend through padding on both logical axes. `inline="full"`
is viewport-relative: it assumes the constrained parent is centered in the viewport. Inside a nested or off-center
shell, use a fixed amount that matches the shell padding, or set your own margins as shown in Custom Styling.

## Styling

`Bleed` exposes stable data attributes on its root. Use `className` in React or `class` in Solid and Vue for
structural styles. The fixed amounts follow the spacing tokens (`xs` to `xl` map to `--moduix-spacing-1`, `2`, `3`,
`4`, and `6`), so presets change them together with the rest of the spacing. For a custom amount, set `margin-inline`
or `margin-block` in your own class. Data attributes and `data-slot` hooks are shared by both styling tracks.
Ancestors with `overflow: hidden` or `overflow: clip` can crop the bleed.

`inline="full"` uses `100vi`, which includes the width of a classic (non-overlay) vertical scrollbar. On such
systems, add `overflow-x: clip` to the page root to avoid a horizontal scrollbar.

### Styling hooks

- `data-scope="bleed"` and `data-part="root"` provide Ark-aligned hooks on the exported root.
- `data-slot="bleed-root"` is the stable moduix selector on the exported root.
- `data-inline` shows the current inline bleed mode: `none`, `xs`, `sm`, `md`, `lg`, `xl`, or `full`.
- `data-block` shows the current block bleed mode: `none`, `xs`, `sm`, `md`, `lg`, or `xl`.
