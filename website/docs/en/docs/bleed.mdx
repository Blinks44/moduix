## API Reference

Ark UI does not include a dedicated `bleed` primitive. moduix builds `Bleed` with the official
[Ark factory](https://ark-ui.com/docs/guides/composition#the-ark-factory) and follows Ark's guidance on
[composition](https://ark-ui.com/docs/guides/composition), [styling](https://ark-ui.com/docs/guides/styling), and
[refs](https://ark-ui.com/docs/guides/ref).

Use [Container](/docs/container) to keep the main content at a readable width. Put `Bleed` inside it when
only a media block, background, divider, or banner should extend beyond the container.

## Anatomy

`Bleed` renders one root element that follows Ark's conventions. It uses negative margins on the inline
and/or block axis, without adding an inner wrapper.

```text
Bleed.Root
└─ root[data-scope="bleed"][data-part="root"][data-slot="bleed-root"]
   └─ children
```

| Part                   | Role                                                                    |
| ---------------------- | ----------------------------------------------------------------------- |
| `Bleed` / `Bleed.Root` | Root component for extending content along the inline and block axes.  |
| `Bleed`                | Short form of `Bleed.Root`, usable directly as a component.             |

## Composition

### Recommended composition

Use the shorter `Bleed` form when the layout needs one wrapper with controlled negative margins.
`Bleed.Root` exposes the same root through a namespace form for codebases that follow Ark's naming pattern.
Use either form for full-width media, section backgrounds, dividers, and banners inside centered or padded shells.

### When to go custom

Use `className` and local `--moduix-bleed-*` overrides when a side panel, nested scroll area, or application shell
needs the content to extend to its own boundaries rather than the viewport.

### Default props

| Property    | Default | Values / Notes                               |
| ----------- | ------- | -------------------------------------------- |
| `inline`    | `full`  | `none`, `xs`, `sm`, `md`, `lg`, `xl`, `full` |
| `block`     | `none`  | `none`, `xs`, `sm`, `md`, `lg`, `xl`         |
| `asChild`   | `false` | Ark factory composition                      |
| `className` | not set | Applied to the root                          |

### Behavioral notes

- `Bleed.Root` renders a single root element and accepts the supported Ark factory `div` props.
- `ref` targets the rendered root element. With `asChild`, it targets the single child element.
- `asChild` requires a single semantic child that accepts DOM props and a ref.
- Use `inline` to extend through inline-axis padding. Add `block` when a surface should also extend
  through block-axis padding. These logical axes follow the document's writing mode.
- Use one of the fixed scale values when content only needs to extend through container padding rather than
  reach the viewport edge.
- `inline="full"` is viewport-relative, so nested shells may need local overrides for
  `--moduix-bleed-inline-full` and `--moduix-bleed-inline-full-size`.
- Ancestors with `overflow: hidden` or `overflow: clip` can crop the bleed.
- `Bleed` is presentational only. It does not manage state, add ARIA behavior, handle keyboard or focus
  interactions, or portal its content.

## Styling

`Bleed` exposes CSS variables and stable data attributes on its root. Use the variables to adjust how far
it extends, and use `className` to style the surface itself.

### CSS Properties

<CssPropertiesSection properties={BleedDocs.bleedCssProperties} />

### Styling hooks

- `data-scope="bleed"` and `data-part="root"` provide Ark-aligned hooks on the exported root.
- `data-slot="bleed-root"` is the stable moduix selector on the exported root.
- `data-inline` shows the current inline bleed mode: `none`, `xs`, `sm`, `md`, `lg`, `xl`, or `full`.
- `data-block` shows the current block bleed mode: `none`, `xs`, `sm`, `md`, `lg`, or `xl`.
- The public `--moduix-bleed-*` CSS API covers both scale-based bleed amounts and the viewport sizing
  used by `inline="full"`.
