## API Reference

Ark UI does not include a dedicated `bleed` primitive. moduix builds `Bleed` with the official
[Ark factory](https://ark-ui.com/docs/guides/composition#the-ark-factory) and follows Ark's guidance on
[composition](https://ark-ui.com/docs/guides/composition), [styling](https://ark-ui.com/docs/guides/styling), and
[refs](https://ark-ui.com/docs/guides/ref).

Use [Container](/docs/container) to keep the main layout at a readable width. Place `Bleed` inside it when
only a media block, background, divider, or banner should extend beyond the container.

## Basic

Use the default `inline="full"` when a media block, banner, or section accent should extend to the viewport
edges while remaining in the normal document flow.

## Anatomy

`Bleed` renders one root element that follows Ark's conventions. The root uses negative margins on the
inline and/or block axis.

```text
Bleed.Root
└─ root[data-scope="bleed"][data-part="root"][data-slot="bleed-root"]
   └─ children
```

| Part                   | Role                                                                            |
| ---------------------- | ------------------------------------------------------------------------------- |
| `Bleed` / `Bleed.Root` | Root layout wrapper that extends content along the inline and block axes.      |
| `Bleed`                | Short form of `Bleed.Root`, usable directly as a component.                    |

## Composition

### Recommended composition

Use the shorter `Bleed` form when the layout only needs one wrapper with controlled negative margins.
`Bleed.Root` exposes the same root through a namespace form for codebases that prefer Ark's naming pattern.
Use it for full-width media, section backgrounds, dividers, and banners inside centered or padded shells.

### When to go custom

Use `className` and local `--moduix-bleed-*` overrides when a side panel, nested scroll area, or application shell
needs full-bleed behavior relative to its own boundaries rather than the viewport.

### Default props

| Property    | Default | Values / Notes                               |
| ----------- | ------- | -------------------------------------------- |
| `inline`    | `full`  | `none`, `xs`, `sm`, `md`, `lg`, `xl`, `full` |
| `block`     | `none`  | `none`, `xs`, `sm`, `md`, `lg`, `xl`         |
| `asChild`   | `false` | Ark factory composition                      |
| `className` | -       | Applied to the root                          |

### Behavioral notes

- `Bleed.Root` renders a single root element and forwards the supported Ark factory `div` props to it.
- `ref` targets the rendered root element. With `asChild`, it targets the single child element.
- `asChild` requires a single semantic child that accepts DOM props and a ref.
- Use `inline` to extend through inline-axis padding. Add `block` when a surface should also extend
  through block-axis padding. These logical axes follow the document's writing mode.
- The old `as` prop was removed during the Ark migration. Use `asChild` when a semantic element
  should own the DOM node.
- Use one of the fixed scale values when content only needs to extend through container padding rather than
  reach the viewport edge.
- `inline="full"` is viewport-relative, so nested shells may need local overrides for
  `--moduix-bleed-inline-full` and `--moduix-bleed-inline-full-size`.
- Ancestors with `overflow: hidden` or `overflow: clip` can crop the bleed.
- Unlike Chakra's layout primitive, moduix intentionally exposes token-based `inline` and `block`
  modes instead of separate `inlineStart`, `inlineEnd`, `blockStart`, and `blockEnd` props.

### Custom Styling

Override `--moduix-bleed-inline-full` locally when a nested shell should size the bleed to its own
content area instead of the viewport.

<style>{`
      .bleed-demo-shell {
        inline-size: 100%;
        padding: var(--moduix-spacing-6);
        background-color: var(--moduix-color-muted);
      }

      .bleed-demo-shell-content {
        display: flex;
        flex-direction: column;
        gap: var(--moduix-spacing-4);
        padding: var(--moduix-spacing-4);
        border: var(--moduix-border-width-sm) dashed var(--moduix-color-border);
        background-color: var(--color-bg);
      }

      .bleed-demo-custom-surface {
        --moduix-bleed-inline-full: calc(var(--moduix-spacing-4) * -1);
        --moduix-bleed-inline-full-size: calc(100% + var(--moduix-spacing-8));
        display: flex;
        flex-direction: column;
        align-items: center;
        padding: var(--moduix-spacing-4);
        background-color: var(--moduix-color-accent);
        color: var(--moduix-color-accent-contrast);
        text-align: center;
      }
    `}</style>

## Styling

`Bleed` exposes a small set of CSS variables and stable data attributes on its root. Use variables to
adjust how far it extends, and use `className` to style the surface itself.

### CSS Properties

<CssPropertiesSection properties={BleedDocs.bleedCssProperties} />

### Styling hooks

- `data-scope="bleed"` and `data-part="root"` provide Ark-aligned hooks on the exported root.
- `data-slot="bleed-root"` is the stable moduix selector on the exported root.
- `data-inline` shows the current inline bleed mode: `none`, `xs`, `sm`, `md`, `lg`, `xl`, or `full`.
- `data-block` shows the current block bleed mode: `none`, `xs`, `sm`, `md`, `lg`, or `xl`.
- The public `--moduix-bleed-*` CSS API covers both scale-based bleed amounts and the viewport sizing
  used by `inline="full"`.
