## Choosing the right component

Use `Toggle` when the control should behave like a button and expose whether it is pressed.

- Choose **`Toggle`** for favorites, saved items, formatting controls, and compact toolbar actions.
- Choose **`Switch`** for settings presented as on/off preference rows.
- Choose **`Checkbox`** for selections that are submitted with a list or form.
- Choose **`ToggleGroup`** when several toggles should share one selection model.

## Anatomy

```text
Toggle / Toggle.Root
└─ Toggle.Indicator (optional)

Toggle.Context (state reader, not a DOM part)
```

| Part                     | Role                                                                              |
| ------------------------ | --------------------------------------------------------------------------------- |
| `Toggle` / `Toggle.Root` | Two-state button root that handles pressed, focus, disabled, and `asChild` behavior. |
| `Toggle.Indicator`       | Renders content when pressed and optional `fallback` content when the toggle is off.   |
| `Toggle.Context`         | Reads the nearest toggle state for custom descendants; it does not render a DOM part.    |

## Composition

### Recommended composition

Use `Toggle` for the standard root. It forwards refs to Ark's button element and supports
`pressed`, `defaultPressed`, `onPressedChange(pressed)`, `disabled`, `asChild`, and regular button
attributes.

`Toggle.Indicator` is optional. Use it when the content inside the button should change with its
pressed state.

### When to go custom

Use `asChild` when you need the toggle behavior on a different button element. Pass a single
button-like child so Ark can merge its required props and behavior into that element.

For a custom descendant that reads state, use `Toggle.Context` or `useToggleContext()` from
`@moduix/react/toggle`. Both read the nearest toggle state without a direct Ark import.

Use `ToggleGroup` instead of coordinating standalone toggles yourself when several pressed buttons
belong to the same choice set.

### Default props

| Prop      | Default   | Notes                                                                                     |
| --------- | --------- | ----------------------------------------------------------------------------------------- |
| `variant` | `default` | moduix visual treatment: filled secondary `default`, bordered `outline`, or transparent `ghost`. |
| `size`    | `md`      | Spacing for text toggles or square geometry for icon-only toggles.                                |

### Behavioral notes

- Icon-only toggles need an accessible name such as `aria-label="Favorite"`.
- `disabled` keeps the current visual state but prevents interaction.
- Ark writes `data-state="on" | "off"`, `data-pressed`, and `data-disabled` for styling.
- Ark Toggle does not expose `RootProvider` or a hidden form input.
- `Toggle.Context` and `useToggleContext()` are available from `@moduix/react/toggle`.
- Legacy `render` and `nativeButton` are not part of the Ark-backed API; use `asChild`.
- Refs on `Toggle` and `Toggle.Root` target the rendered button. Refs on `Toggle.Indicator` target
  the rendered indicator element.

## Styling

`Toggle` exposes a styled root, an optional indicator part, and the full set of
`--moduix-toggle-*` tokens for variants, sizes, focus ring, spacing, and icon sizing.

### Styling hooks

- `data-slot="toggle-root"` is the stable selector on the root.
- `data-slot="toggle-indicator"` is the stable selector on `Toggle.Indicator`.
- `data-scope="toggle"` and `data-part="root" | "indicator"` come from Ark UI.
- `data-state="on" | "off"` reflects pressed state on root and indicator.
- `data-pressed` is present when the toggle is pressed.
- `data-variant` reflects the moduix visual variant.
- `data-size` reflects the moduix size, including `icon-sm`, `icon-md`, and `icon-lg`.
- `data-disabled` drives disabled styles; Ark also preserves the native `disabled` attribute.
- Direct icon children and icons inside `Toggle.Indicator` are sized through
  `--moduix-toggle-icon-size`.
