## Choosing the right component

Use `FloatingPanel` for a floating, non-modal workspace such as an inspector or utility window.
Choose `Popover` for compact content anchored to a trigger, `Dialog` for modal tasks, and `Drawer`
for panels attached to an edge with swipe or snap-point behavior.

## Anatomy

```text
FloatingPanel / FloatingPanel.Root
├─ FloatingPanel.Trigger
└─ Overlay subtree (automatically portalled)
   └─ FloatingPanel.Positioner
      └─ FloatingPanel.Content
         ├─ FloatingPanel.DragTrigger
         │  └─ FloatingPanel.Header
         │     ├─ FloatingPanel.Title
         │     │  └─ FloatingPanel.DragIndicator (optional)
         │     └─ FloatingPanel.Control
         │        ├─ FloatingPanel.StageTrigger
         │        └─ FloatingPanel.CloseTrigger / CloseIcon
         ├─ FloatingPanel.Body
         ├─ FloatingPanel.Footer
         └─ FloatingPanel.ResizeTrigger / ResizeTriggerGroup
```

| Part                                       | Role                                                                     |
| ------------------------------------------ | ------------------------------------------------------------------------ |
| `FloatingPanel` / `FloatingPanel.Root`     | Owns open, position, size, drag, resize, and stage state.                |
| `FloatingPanel.Trigger`                    | Opens or toggles the panel.                                              |
| `FloatingPanel.Positioner`                 | Applies Ark's position, size, transform, and z-index values.             |
| `FloatingPanel.Content`                    | Visible floating window surface.                                         |
| `FloatingPanel.DragTrigger`                | Marks the draggable region, usually around the header.                   |
| `FloatingPanel.Header`                     | Ark header part and recommended layout for the drag handle.              |
| `FloatingPanel.Title`                      | Provides the panel's accessible title.                                    |
| `FloatingPanel.Control`                    | Groups stage and close controls.                                         |
| `FloatingPanel.StageTrigger`               | Switches to `default`, `minimized`, or `maximized`.                      |
| `FloatingPanel.CloseTrigger` / `CloseIcon` | Closes the panel.                                                        |
| `FloatingPanel.Body`                       | Scrollable content region.                                               |
| `FloatingPanel.Footer`                     | Optional footer for secondary actions or status text.                   |
| `FloatingPanel.ResizeTrigger`              | Resize handle for one Ark axis.                                          |
| `FloatingPanel.ResizeTriggerGroup`         | moduix helper that renders all or selected resize axes.                  |
| `FloatingPanel.RootProvider`               | Connects parts to state created with `FloatingPanel.useFloatingPanel()`. |

`FloatingPanel.DragIndicator`, `FloatingPanel.CloseIcon`, `FloatingPanel.Footer`, and
`FloatingPanel.ResizeTriggerGroup` are moduix helpers. They complement Ark's structural parts;
they do not replace them.

## Composition

The root automatically portals `Positioner`. Set `portalled={false}` to render it in place, or use
`portalRef` to choose a custom container. The structural parts remain explicit and can be styled
individually.

### Recommended composition

Use `FloatingPanel` to manage state and behavior. Render `Positioner` and `Content` explicitly,
then wrap the header in `DragTrigger` so dragging starts from a predictable area.

Use `StageTrigger` with `stage="minimized"`, `stage="maximized"`, and `stage="default"` to render
built-in icon buttons for minimizing, maximizing, and restoring the panel. Ark keeps the restore
button hidden until the panel is minimized or maximized. When `asChild` is set on a trigger or
control, pass one semantic child. moduix adds default icons only when the trigger uses Ark's default
button host.

### When to go custom

Apply `className` directly to any exported part. Use `asChild` with exactly one semantic child for
custom trigger, close trigger, or stage trigger hosts. Pass `axes` to `ResizeTriggerGroup` to render
only the handles you need, or use individual `ResizeTrigger` parts when each axis needs its own
styling.

Use `FloatingPanel.Context` or `FloatingPanel.useFloatingPanelContext()` inside the panel tree. If
state is created outside that tree, create it with `FloatingPanel.useFloatingPanel()` and pass it to
`RootProvider`. Do not render `Root` and `RootProvider` for the same state instance.

### Default props

By default, overlay content rendered in a portal mounts lazily and unmounts after its exit animation. Set
`unmountOnExit={false}` to keep it mounted after the first open. Set both lifecycle props to `false`
only when you need eager initial rendering.

| Prop            | Default | Notes                                                                      |
| --------------- | ------- | -------------------------------------------------------------------------- |
| `closeOnEscape` | `true`  | Closes the focused topmost panel; set `false` to opt out.                  |
| `persistRect`   | `true`  | Keeps the last position and size available while close animations finish. |
| `draggable`     | Ark     | Passed through unchanged; Ark defaults it to `true`.                       |
| `resizable`     | Ark     | Passed through unchanged; Ark defaults it to `true`.                       |
| `strategy`      | Ark     | Passed through unchanged; Ark defaults to fixed positioning.               |
| Lifecycle props | moduix  | `lazyMount` and `unmountOnExit` default to `true`; remaining props pass through. |

### Behavioral notes

- `onOpenChange(details)` provides `details.open`.
- `onPositionChange(details)` and `onPositionChangeEnd(details)` provide `details.position`.
- `onSizeChange(details)` and `onSizeChangeEnd(details)` provide `details.size`.
- `onStageChange(details)` provides the Ark stage details object.
- `position` and `size` are controlled independently; use `defaultPosition` and `defaultSize` for
  uncontrolled initialization.
- `getAnchorPosition(details)` can derive the initial position from the trigger rect.
- Ark handles Escape from the focused topmost `Content`. Use `autoFocus` when the panel should
  receive focus as soon as it opens.
- `ids`, `translations`, `getBoundaryEl`, `lockAspectRatio`, and `gridSize` pass through to Ark
  unchanged.
- `Content` has `role="dialog"`. When it has focus, Arrow keys move the panel in `gridSize`
  increments and honor `dir`; use `initialFocusEl`, `finalFocusEl`, and `restoreFocus` for explicit
  focus handoff.
- Set `persistRect` to `false` if you do not want the last position and size preserved. It defaults
  to `true` so close animations can use them.
- The panel is non-modal and does not trap focus or block outside interaction.

### Styling hooks

Ark parts retain `data-scope="floating-panel"` and their `data-part` values. moduix adds
`data-slot="floating-panel-*"` to rendered wrappers. Target `data-state="open|closed"`,
`data-dragging`, `data-disabled`, `data-stage`, `data-topmost`, `data-behind`, `data-minimized`,
`data-maximized`, `data-staged`, and `data-axis` for state-aware styling.

`Positioner` exposes `--width`, `--height`, `--x`, `--y`, `--reference-width`,
`--reference-height`, `--available-width`, `--available-height`, `--z-index`, and
`--transform-origin`. Keep sizing and transform logic in Ark's runtime variables instead of
duplicating measurements in application code.
