## Choosing the right component

Use `FloatingPanel` for a floating, non-modal workspace such as an inspector, a property panel, or
a utility window. Use `Popover` for compact content anchored to a trigger, `Dialog` for modal tasks,
and `Drawer` for a panel attached to an edge of the viewport with gesture or snap-point behavior.

## Basic


Keep the Ark UI parts explicit. `FloatingPanelPositioner` applies the position and size calculated
by Ark, while `FloatingPanelContent` is the visible window surface. The header acts as the drag
handle, and `FloatingPanelResizeTriggerGroup` adds the resize handles around the panel.

## Anatomy

```text
FloatingPanel
├─ FloatingPanelTrigger
└─ Overlay subtree (automatically portalled)
   └─ FloatingPanelPositioner
      └─ FloatingPanelContent
         ├─ FloatingPanelDragTrigger
         │  └─ FloatingPanelHeader
         │     ├─ FloatingPanelTitle
         │     │  └─ FloatingPanelDragIndicator (optional)
         │     └─ FloatingPanelControl
         │        ├─ FloatingPanelStageTrigger
         │        └─ FloatingPanelCloseTrigger / FloatingPanelCloseIcon
         ├─ FloatingPanelBody
         ├─ FloatingPanelFooter
         └─ FloatingPanelResizeTrigger / FloatingPanelResizeTriggerGroup
```

| Part                                       | Role                                                                    |
| ------------------------------------------ | ----------------------------------------------------------------------- |
| `FloatingPanel`                           | Owns open, position, size, drag, resize, and stage state.               |
| `FloatingPanelTrigger`                    | Opens the panel or toggles its open state.                               |
| `FloatingPanelPositioner`                 | Applies Ark's calculated position, size, transform, and z-index values. |
| `FloatingPanelContent`                    | Visible surface of the floating window.                                 |
| `FloatingPanelDragTrigger`                | Defines the draggable area, usually the header.                          |
| `FloatingPanelHeader`                     | Ark header part and wrapper for the drag handle.                         |
| `FloatingPanelTitle`                      | Gives the panel an accessible name.                                     |
| `FloatingPanelControl`                    | Groups stage and close controls.                                         |
| `FloatingPanelStageTrigger`               | Switches between `default`, `minimized`, and `maximized`.               |
| `FloatingPanelCloseTrigger` / `FloatingPanelCloseIcon` | Closes the panel.                                             |
| `FloatingPanelBody`                       | Main scrollable content area.                                           |
| `FloatingPanelFooter`                     | Optional bottom area for actions or status text.                         |
| `FloatingPanelResizeTrigger`              | Resize handle for one Ark axis.                                         |
| `FloatingPanelResizeTriggerGroup`         | Renders all or selected resize handles.                                 |
| `FloatingPanelRootProvider`               | Connects parts to state from `useFloatingPanel()`.        |

`FloatingPanelDragIndicator`, `FloatingPanelCloseIcon`, `FloatingPanelFooter`, and
`FloatingPanelResizeTriggerGroup` are moduix helpers. They complement Ark's structural parts
without replacing them.

## Composition

Use `FloatingPanel` for local state. Keep `FloatingPanelPositioner` and `FloatingPanelContent` explicit, wrap the header in
`FloatingPanelDragTrigger`, and include `FloatingPanelTitle` for an accessible name. `FloatingPanelPositioner` is portalled by default;
set `portalled={false}` or pass `portalRef` when the panel belongs in another container.

When state must live outside the panel tree, create it with `useFloatingPanel()` and
pass it to `FloatingPanelRootProvider`. Do not render `FloatingPanel` and `FloatingPanelRootProvider` for the same state
instance. `position` and `size` are controlled independently. Use `FloatingPanelResizeTriggerGroup axes` or
individual `FloatingPanelResizeTrigger` parts only when the default set of handles is not appropriate. With
`asChild`, pass one semantic child; Solid uses the render-function form of this prop.

### Styling hooks

Ark parts retain `data-scope="floating-panel"` and their `data-part` values. moduix adds
`data-slot="floating-panel-*"` to rendered wrappers. Use `data-state="open|closed"`, `data-dragging`,
`data-disabled`, `data-stage`, `data-topmost`, `data-behind`, `data-minimized`, `data-maximized`,
`data-staged`, and `data-axis` for state-aware styling on the relevant parts.

`FloatingPanelPositioner` exposes `--width`, `--height`, `--x`, `--y`, `--reference-width`, `--reference-height`,
`--available-width`, `--available-height`, `--z-index`, and `--transform-origin`. Keep sizing and
transform logic in Ark's runtime variables instead of duplicating measurements in application code.
