## Choosing the right component

Use `FloatingPanel` for a floating, non-modal workspace such as an inspector, a property panel, or
a utility window. Use `Popover` for compact content anchored to a trigger, `Dialog` for modal tasks,
and `Drawer` for a panel attached to an edge of the viewport with gesture or snap-point behavior.

## Basic

Keep the Ark UI parts explicit. `FloatingPanel.Positioner` applies the position and size calculated
by Ark, while `FloatingPanel.Content` is the visible window surface. The header acts as the drag
handle, and `ResizeTriggerGroup` adds the resize handles around the panel.

## Anatomy

```text
FloatingPanel / FloatingPanel.Root
├─ FloatingPanel.Trigger
└─ Overlay subtree (automatically portalled)
   └─ FloatingPanel.Positioner
      └─ FloatingPanel.Content
         ├─ FloatingPanel.DragTrigger
         │  └─ FloatingPanel.Header
         │     ├─ FloatingPanel.Title
         │     │  └─ FloatingPanel.DragIndicator (optional)
         │     └─ FloatingPanel.Control
         │        ├─ FloatingPanel.StageTrigger
         │        └─ FloatingPanel.CloseTrigger / CloseIcon
         ├─ FloatingPanel.Body
         ├─ FloatingPanel.Footer
         └─ FloatingPanel.ResizeTrigger / ResizeTriggerGroup
```

| Part                                       | Role                                                                     |
| ------------------------------------------ | ------------------------------------------------------------------------ |
| `FloatingPanel` / `FloatingPanel.Root`     | Owns open, position, size, drag, resize, and stage state.                |
| `FloatingPanel.Trigger`                    | Opens the panel or toggles its open state.                                |
| `FloatingPanel.Positioner`                 | Applies Ark's calculated position, size, transform, and z-index values.  |
| `FloatingPanel.Content`                    | Visible surface of the floating window.                                  |
| `FloatingPanel.DragTrigger`                | Defines the draggable area, usually the header.                           |
| `FloatingPanel.Header`                     | Ark header part and recommended wrapper for the drag handle.              |
| `FloatingPanel.Title`                      | Gives the panel an accessible name.                                      |
| `FloatingPanel.Control`                    | Groups stage and close controls.                                          |
| `FloatingPanel.StageTrigger`               | Switches between `default`, `minimized`, and `maximized`.                |
| `FloatingPanel.CloseTrigger` / `CloseIcon` | Closes the panel.                                                         |
| `FloatingPanel.Body`                       | Main scrollable content area.                                            |
| `FloatingPanel.Footer`                     | Optional bottom area for secondary actions or status text.                |
| `FloatingPanel.ResizeTrigger`              | Resize handle for one Ark axis.                                          |
| `FloatingPanel.ResizeTriggerGroup`         | moduix helper that renders all or selected resize handles.               |
| `FloatingPanel.RootProvider`               | Connects the parts to state created with `FloatingPanel.useFloatingPanel()`. |

`FloatingPanel.DragIndicator`, `FloatingPanel.CloseIcon`, `FloatingPanel.Footer`, and
`FloatingPanel.ResizeTriggerGroup` are moduix helpers. They complement Ark's structural parts;
they do not replace them.

## Composition

`FloatingPanel` and `FloatingPanel.RootProvider` configure how `Positioner` is rendered. It is
portalled by default. Set `portalled={false}` to render it in place, or pass `portalRef` to choose a
custom container. The structural parts remain explicit and can be styled independently.

### Recommended composition

Use `FloatingPanel` to manage state and behavior. Keep `Positioner` and `Content` explicit, then
wrap the header in `DragTrigger` so dragging starts from a predictable area. Include
`FloatingPanel.Title` to give the window an accessible name.

Use `StageTrigger` with `stage="minimized"`, `stage="maximized"`, and `stage="default"` to render
the built-in controls for minimizing, maximizing, and restoring the panel. Ark hides the restore
control until the panel is minimized or maximized. When `asChild` is set on a trigger or control,
pass one semantic child. moduix adds default icons only when the trigger renders Ark's default
button host.

### When to go custom

Apply `className` directly to any exported part. Use `asChild` with exactly one semantic child when
you need a custom trigger, close control, stage control, or other part host. Pass `axes` to
`ResizeTriggerGroup` to render only the handles you need, or use individual `ResizeTrigger` parts
when each axis needs its own placement or styling.

Use `FloatingPanel.Context` or `FloatingPanel.useFloatingPanelContext()` inside the panel tree. If
state is created outside that tree, create it with `FloatingPanel.useFloatingPanel()` and pass it to
`RootProvider`. Do not render `Root` and `RootProvider` for the same state instance.

### Default props

The moduix root and `RootProvider` mount portalled content lazily and remove it after the exit animation. Set
`unmountOnExit={false}` to keep the content mounted after its first open. Set both lifecycle props
to `false` only when eager initial rendering is needed.

| Prop             | Default | Notes                                                                       |
| ---------------- | ------- | --------------------------------------------------------------------------- |
| `allowOverflow`  | `true`  | Allows dragging beyond the boundary. Set `false` with `getBoundaryEl` to constrain the panel. |
| `closeOnEscape`  | `true`  | Closes the focused topmost panel when Escape is pressed.                   |
| `defaultOpen`    | `false` | The panel starts closed.                                                    |
| `draggable`      | `true`  | The panel can be dragged.                                                   |
| `gridSize`       | `1`     | Arrow-key movement and the snap grid use this step.                        |
| `lazyMount`      | `true`  | moduix waits until the first open before mounting the content.              |
| `persistRect`    | `true`  | Keeps the last position and size available during the exit animation.      |
| `resizable`      | `true`  | The panel can be resized.                                                   |
| `strategy`       | `fixed` | Ark positions the panel relative to the viewport.                           |
| `unmountOnExit`  | `true`  | Removes the content after the exit animation.                               |

### Behavioral notes

- `onOpenChange(details)` provides `details.open`.
- `onPositionChange(details)` and `onPositionChangeEnd(details)` provide `details.position`.
- `onSizeChange(details)` and `onSizeChangeEnd(details)` provide `details.size`.
- `onStageChange(details)` provides the Ark stage details object.
- `position` and `size` are controlled independently. Use `defaultPosition` and `defaultSize` for
  uncontrolled initialization.
- `getAnchorPosition(details)` can derive the initial position from the trigger rectangle.
- `Content` has `role="dialog"`. Include `Title` or provide another accessible name for the
  window.
- Use `autoFocus` on `Content` when the panel should receive focus as soon as it opens. Use
  `initialFocusEl`, `finalFocusEl`, and `restoreFocus` for explicit focus handoff.
- When `Content` has focus, Arrow keys move the panel in `gridSize` increments and honor `dir`.
- `ids`, `translations`, `getBoundaryEl`, `lockAspectRatio`, and `gridSize` pass through to Ark
  unchanged. Stage values are `default`, `minimized`, and `maximized`.
- Ark handles Escape from the focused topmost `Content`. Set `closeOnEscape={false}` to opt out.
- The panel is non-modal: it does not trap focus, lock scrolling, or block interaction outside the
  panel.

### Styling hooks

Ark parts retain `data-scope="floating-panel"` and their `data-part` values. moduix adds
`data-slot="floating-panel-*"` to rendered wrappers. Use `data-state="open|closed"`,
`data-dragging`, `data-disabled`, `data-stage`, `data-topmost`, `data-behind`, `data-minimized`,
`data-maximized`, `data-staged`, and `data-axis` for state-aware styling on the relevant parts.

`Positioner` exposes `--width`, `--height`, `--x`, `--y`, `--reference-width`,
`--reference-height`, `--available-width`, `--available-height`, `--z-index`, and
`--transform-origin`. Keep sizing and transform logic in Ark's runtime variables instead of
duplicating measurements in application code.
