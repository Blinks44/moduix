Compose the drawer from Ark's structural parts. This example opens at a compact snap point, then lets
the user drag it to full height. `DrawerContent` is the interactive surface, `DrawerPositioner`
places it, and `DrawerBackdrop` provides the modal layer.

## Choosing the right component

Use `Drawer` for a panel that slides in from the edge of the viewport. It works well for navigation,
forms, mobile bottom sheets, and workflows where users need to drag the panel or move between snap
points. Choose `Dialog` for a centered surface that does not need to be dragged.

### Sizes

Set `size` on `DrawerContent` to `sm`, `md` (default), `lg`, or `xl` to choose the width of a
`start` or `end` drawer: 18rem, 22rem, 28rem, or 36rem. On narrow screens the drawer still leaves
a gap at the opposite edge. Top and bottom drawers take the full width, and their height comes from
snap points.

## Composition

`Drawer` owns its state by default and renders `DrawerBackdrop` and `DrawerPositioner` through a portal. Keep
those structural parts explicit. Set `portalled={false}` to render them inline, or pass `portalRef`
to use a custom container.

When state must be created outside the drawer tree, create one store with `useDrawer()` and pass it to
one `DrawerRootProvider`. Do not render `Drawer` for that same store. Nested drawers
use separate stores and separate `DrawerRootProvider` trees so each drawer keeps its own focus and open state.

Wrap surfaces that should move together in `DrawerStack`, then pair `DrawerIndentBackground` with
`DrawerIndent`. Use `asChild` for a custom trigger or close host: React receives one focusable child,
Solid uses a render function that spreads `props()` onto the child, and Vue uses the `as-child`
attribute with a single child element. Ark callbacks receive detail
objects, such as `details.open`, `details.snapPoint`, and `details.value`.

## Styling

Use `className` in React or `class` in Solid and Vue on exported parts for structural styles. For state-based
styles, prefer Ark data attributes such as `data-state`, `data-swipe-direction`, and `data-dragging`,
together with moduix `data-slot` selectors. Tailwind variants use native utilities and consumer
classes; the component variables below customize the CSS Modules variants. Data attributes and
`data-slot` hooks are shared by both styling tracks.

  presentation is active.
- Ark part hooks: `data-scope="drawer"` with `data-part`.
- State hooks: `data-state="open|closed"`, `data-swipe-direction`, `data-swiping`,
  `data-dragging`, `data-expanded`, `data-current`, `data-value`, `data-disabled`,
  `data-nested-drawer-open`, and `data-nested-drawer-swiping`.
- Runtime variables: `--drawer-translate`, `--drawer-translate-x`, `--drawer-translate-y`,
  `--drawer-snap-point-offset-x`, `--drawer-snap-point-offset-y`, `--drawer-swipe-movement-x`,
  `--drawer-swipe-movement-y`, `--drawer-swipe-progress`, `--drawer-swipe-strength`,
  `--drawer-height`, `--drawer-frontmost-height`, `--nested-drawers`, `--nested-layer-count`,
  and `--layer-index`.
- `DrawerTrigger` and `DrawerCloseTrigger` are unstyled. Compose them with `asChild` and a `Button`,
  or style the native button with a class.
- Colors, borders, spacing, and typography come from foundation tokens. Change them for one drawer
  with a class on the part. The backdrop reads the shared `--moduix-backdrop-bg` and
  `--moduix-backdrop-filter`.
- Top and bottom drawers are capped at `max-height: 80dvh`; set another `max-height` with a class on
  `DrawerContent`.

## Keyboard

| Key | Action |
| --- | --- |
| `Enter` / `Space` | Opens it from the focused trigger. |
| `Tab` / `Shift+Tab` | Moves focus between controls; focus stays inside while open. |
| `Esc` | Closes it and returns focus to the trigger. |
