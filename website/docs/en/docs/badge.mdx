## Usage

<Usage />

Start with a plain `<Badge>`. The component renders a presentational `span` by default. Set `variant`
to choose `default`, `secondary`, `destructive`, `outline`, `ghost`, or `link`, set `size` to `sm`,
`md`, or `lg`, and add `BadgeDot` only when the status benefits from a visual indicator.

## Choosing the right component

Use `Badge` to show brief information about an item. It is presentational, so it is not a replacement
for a control that lets the user select or edit a value.

- Choose **`Badge`** for short metadata such as status, category, version, or count.
- Choose **`Tag`** for selected values, filters, assignments, or labels that are part of the current interface state.

The Vue exports are available from `@moduix/vue/badge` for CSS Modules and `@moduix/vue-tailwind/badge` for Tailwind CSS.

## Composition

`Badge` is presentational and has no state. Direct text remains unchanged; use `BadgeLabel`
explicitly when a constrained label must truncate or when combining text with `BadgeDot` or an
icon. For a semantic link or button, use `asChild` with exactly one child in React. In Solid, pass
a render function to `asChild`; the rendered child keeps its native semantics.

In Solid, assign a ref to the element created inside the `asChild` render function. A ref on `Badge`
itself is not forwarded through that composition path.

In Vue, place exactly one child in the default slot when using `as-child`; the child keeps its native semantics.

## Styling

Start with a built-in variant and size. The CSS Modules variables override the background, border,
and text color of every variant; to theme one variant across the application, set them on
`[data-slot='badge-root'][data-variant='<variant>']`. Size, spacing, typography, radius, and icon and
dot sizes use foundation tokens; change them with a class on the part. These CSS variables apply to the
CSS Modules packages; Tailwind packages use native utilities and consumer classes instead.

Use `className` in React or `class` in Solid and Vue on exported parts. The stable `data-slot` hooks and
Ark data attributes are shared by all styling tracks.

### Styling hooks

| Part | `data-slot` |
| --- | --- |
| `Badge` | `badge-root` |
| `BadgeLabel` | `badge-label` |
| `BadgeDot` | `badge-dot` |

- `Badge` also exposes `data-scope="badge"` and `data-part="root"`. `BadgeLabel` and `BadgeDot` expose `data-part="label"` and `data-part="dot"`.
- `Badge` writes the selected variant to `data-variant` and the selected size to `data-size`.
- Focusable hosts rendered through `Badge asChild` receive the root focus-visible styling. Anchor roots also receive the variant hover and pointer-cursor styles; button-specific interaction styles remain up to the application.
- Direct child `svg` icons inherit `currentColor`, do not receive pointer events, and are 12px unless a class on the icon sets another size.
- Badge has no dedicated Ark primitive or behavior machine, so it does not expose Ark-managed states or runtime CSS variables.

## API reference

Also accepts the native props of its element and `asChild`.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `variant` | `'default' \| 'secondary' \| 'destructive' \| 'outline' \| 'ghost' \| 'link'` | `'default'` | Visual style: `default`, `secondary`, `destructive`, `outline`, `ghost`, or `link`. |
| `size` | `'sm' \| 'md' \| 'lg'` | `'md'` | Badge size: `sm`, `md`, or `lg`. |
