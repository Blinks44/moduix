## API Reference

Ark UI does not provide a dedicated `Badge` primitive. moduix builds `Badge` with the official
[Ark factory](https://ark-ui.com/docs/guides/composition#the-ark-factory) and follows Ark's guidance for
[composition](https://ark-ui.com/docs/guides/composition), [styling](https://ark-ui.com/docs/guides/styling), and
[refs](https://ark-ui.com/docs/guides/ref).

## Choosing the right component

Use `Badge` to show brief information about an item. It is presentational, so it is not a replacement
for a control that lets the user select or edit a value.

- Choose **`Badge`** for short metadata such as status, category, version, or count.
- Choose **`Tag`** for selected values, filters, assignments, or labels that are part of the current interface state.

The Vue exports are available from `@moduix/vue/badge` for CSS Modules and `@moduix/vue-tailwind/badge` for Tailwind CSS.

## Anatomy

`Badge` is the root component. It keeps the public API small and exposes only the parts you can see.

```text
Badge
├─ BadgeLabel (optional; use explicitly for truncation)
├─ BadgeDot (optional)
└─ svg icon (optional)
```

| Part         | Role                                                                                 |
| ------------ | ------------------------------------------------------------------------------------ |
| `Badge`      | Root part. Applies the variant, border, and spacing.                                |
| `BadgeLabel` | Explicit text part. Keeps a composed label truncatable.                              |
| `BadgeDot`   | Optional decorative part. Renders a circular marker that inherits the text color.    |

## Composition

`Badge` is presentational and owns no state. Direct text remains unchanged; use `BadgeLabel`
explicitly when a constrained label must truncate or when combining text with `BadgeDot` or an
icon. For a semantic link or button, use `asChild` with exactly one child in React. In Solid, pass
a render function to `asChild`; the rendered child keeps its native semantics.

In Solid, assign a ref to the element created inside the `asChild` render function. A ref on `Badge`
itself is not forwarded through that composition path.

In Vue, place exactly one child in the default slot when using `as-child`; the child keeps its native semantics.

## Styling

Start with a built-in variant. For a one-off size or style change, set the public
`--moduix-badge-*` variables on the badge through a class or inline style. Use
`--moduix-badge-<variant>-*` variables to theme a variant across the application. The shared
`--moduix-badge-bg`, `--moduix-badge-border-color`, and `--moduix-badge-color` variables override
the variant-specific values for an individual badge. These CSS variables apply to the CSS Modules
packages; Tailwind packages use native utilities and consumer classes instead.

Use `className` in React or `class` in Solid and Vue on exported parts. The stable `data-slot` hooks and
Ark data attributes are shared by all styling tracks.

### Styling hooks

- `data-slot="badge-root"`, `data-slot="badge-label"`, and `data-slot="badge-dot"` are stable selectors for styling the exported parts.
- `Badge` also exposes `data-scope="badge"` and `data-part="root"`. `BadgeLabel` and `BadgeDot` expose `data-part="label"` and `data-part="dot"`.
- `Badge` writes the selected variant to `data-variant`.
- Focusable hosts rendered through `Badge asChild` receive the root focus-visible styling. Anchor roots also receive the variant hover and pointer-cursor styles; button-specific interaction styles remain application-owned.
- Direct child `svg` icons inherit `currentColor`, do not receive pointer events, and use `--moduix-badge-icon-size`.
- Badge has no dedicated Ark primitive or behavior machine, so it does not expose Ark-managed states or runtime CSS variables.
