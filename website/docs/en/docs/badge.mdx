## API Reference

Ark UI does not ship a dedicated `Badge` primitive. moduix builds this component with the official
[Ark factory](https://ark-ui.com/docs/guides/composition#the-ark-factory) and follows Ark's guidance for
[composition](https://ark-ui.com/docs/guides/composition), [styling](https://ark-ui.com/docs/guides/styling), and
[refs](https://ark-ui.com/docs/guides/ref).

## Choosing the right component

Use `Badge` to show brief information about another object, rather than a value selected by the
user.

- Choose **`Badge`** for short metadata such as status, category, version, or count.
- Choose **`Tag`** when the UI is showing selected values, filters, assignments, or labels that belong to the current state of the interface.

## Anatomy

`Badge` keeps its public API small and exposes only the parts you can see.

```text
Badge / Badge.Root
├─ Badge.Label (optional; direct text is wrapped automatically)
├─ Badge.Dot (optional)
└─ svg icon (optional)
```

| Part                   | Role                                                                                 |
| ---------------------- | ------------------------------------------------------------------------------------ |
| `Badge` / `Badge.Root` | Root part. Applies the variant, border, spacing, and text truncation.                |
| `Badge.Label`          | Explicit text part. Keeps a composed label truncatable.                              |
| `Badge.Dot`            | Optional indicator part. Renders a circular marker that inherits the text color.     |

## Composition

### Recommended composition

For most status labels, categories, version labels, and short counters, use `Badge` directly.

Use `variant` for the built-in styles: `default`, `secondary`, `destructive`, `outline`, `ghost`,
and `link`.

Place `Badge.Dot` or a direct child icon next to `Badge.Label` when a composed badge needs an extra
visual cue. Plain text is wrapped in `Badge.Label` automatically.

`Badge.Root`, `Badge.Label`, and `Badge.Dot` forward refs to their rendered DOM elements.

### When to go custom

Use `Badge asChild` when another semantic element needs to become the root DOM node. Ark composition
requires exactly one child. Interactive children keep their native semantics and receive the badge's
default cursor, hover, and keyboard-focus treatment.

Use local CSS variables or `className` overrides when you need a custom size or a different style.

### Default props

| Prop      | Default   | Values / Notes                                                    |
| --------- | --------- | ----------------------------------------------------------------- |
| `variant` | `default` | `default`, `secondary`, `destructive`, `outline`, `ghost`, `link` |
| `asChild` | `false`   | Ark factory composition with exactly one child                    |

### Behavioral notes

- `Badge` only displays information by default and renders a `span`.
- `Badge.Dot` is decorative and hidden from assistive technology, so the visible text must carry the status meaning.
- `Badge` does not add interaction or link or button semantics of its own.
- Semantic links and buttons rendered through `asChild` keep their native semantics and receive the default cursor, hover, and focus-visible styling.
- Disabled buttons and elements with `aria-disabled="true"` keep their semantics, skip hover styling, and use the public disabled-opacity hook.
- Long labels stay on one line and are truncated by the root. `title` exposes the complete value on
  pointer hover; on touch-first interfaces, choose a label that fits the available space.
- Direct text is wrapped in `Badge.Label` automatically. Use `Badge.Label` explicitly when text is
  composed with a dot, icon, or another element.
- Direct child `svg` icons inherit `currentColor` and use `--moduix-badge-icon-size`.
- Numeric content uses tabular figures, and badge text is not selectable by default.
- Chakra's size recipe is intentionally represented by public CSS variables instead of a `size`
  prop.

## Styling

Start with a built-in variant. Use local CSS variables for one-off size and style changes.
Use `--moduix-badge-<variant>-*` variables to theme a variant across the application. The shared
`--moduix-badge-bg`, `--moduix-badge-border-color`, and `--moduix-badge-color` variables have higher
priority when you need to customize one badge.

### Styling hooks

- `data-slot="badge-root"`, `data-slot="badge-label"`, and `data-slot="badge-dot"` are stable selectors for styling the exported parts.
- `Badge.Root` also exposes `data-scope="badge"` and `data-part="root"`. `Badge.Label` and `Badge.Dot` expose `data-part="label"` and `data-part="dot"`.
- `Badge.Root` writes the selected variant to `data-variant`.
- Semantic links and buttons rendered through `Badge asChild` or `Badge.Root asChild` receive the root's default focus-visible styling.
- Direct child `svg` icons inherit `currentColor`, do not receive pointer events, and use `--moduix-badge-icon-size`.
- There are no Ark-managed states or runtime CSS variables because Badge has no dedicated Ark
  primitive or behavior machine.
