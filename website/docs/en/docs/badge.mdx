## API Reference

Ark UI does not provide a dedicated `Badge` primitive. moduix builds `Badge` with the official
[Ark factory](https://ark-ui.com/docs/guides/composition#the-ark-factory) and follows Ark's guidance for
[composition](https://ark-ui.com/docs/guides/composition), [styling](https://ark-ui.com/docs/guides/styling), and
[refs](https://ark-ui.com/docs/guides/ref).

## Choosing the right component

Use `Badge` to show brief information about an item. It is presentational, so it is not a replacement
for a control that lets the user select or edit a value.

- Choose **`Badge`** for short metadata such as status, category, version, or count.
- Choose **`Tag`** for selected values, filters, assignments, or labels that are part of the current interface state.

## Anatomy

`Badge` is the shorthand for `Badge.Root`. It keeps the public API small and exposes only the parts
you can see.

```text
Badge / Badge.Root
├─ Badge.Label (optional; direct text is wrapped automatically)
├─ Badge.Dot (optional)
└─ svg icon (optional)
```

| Part                   | Role                                                                                 |
| ---------------------- | ------------------------------------------------------------------------------------ |
| `Badge` / `Badge.Root` | Root part. Applies the variant, border, spacing, and text truncation.             |
| `Badge.Label`          | Explicit text part. Keeps a composed label truncatable.                           |
| `Badge.Dot`            | Optional decorative part. Renders a circular marker that inherits the text color. |

## Composition

### Recommended composition

For most short status labels, categories, version labels, and counters, use `<Badge>` directly.
`Badge.Root` is the namespaced equivalent.

Use `variant` for the built-in styles: `default`, `secondary`, `destructive`, `outline`, `ghost`,
and `link`.

Place `Badge.Dot` or a direct child icon next to `Badge.Label` when the badge needs an extra visual
cue. Direct text is wrapped in `Badge.Label` automatically.

`Badge.Root`, `Badge.Label`, and `Badge.Dot` forward refs to their rendered DOM elements.

### When to go custom

Use `Badge asChild` when a semantic element such as an `<a>` or `<button>` should become the root DOM
node. Ark composition requires exactly one child. The child keeps its native semantics, and links,
buttons, and elements with `role="button"` receive the badge's default cursor, hover, and focus-visible
styles.

Use a local CSS variable or `className` override when you need a custom size or a different style.
There is no `size` prop; adjust the dimensions through the public CSS variables.

### Default props

| Prop      | Default   | Values / Notes                                                    |
| --------- | --------- | ----------------------------------------------------------------- |
| `variant` | `default` | `default`, `secondary`, `destructive`, `outline`, `ghost`, `link` |
| `asChild` | `false`   | Render exactly one child as the root element                       |

### Behavioral notes

- `Badge` only displays information by default and renders a `span`.
- `Badge.Dot` is decorative and hidden from assistive technology, so the visible text must carry the status meaning.
- `Badge` does not add interaction or link or button semantics of its own.
- Semantic links and buttons rendered through `asChild` keep their native semantics and receive the default cursor, hover, and focus-visible styling.
- Disabled buttons and elements with `aria-disabled="true"` keep their semantics, skip hover styling, and use the public disabled-opacity variable.
- Long labels stay on one line and are truncated by the root. Add `title` to expose the complete value
  on pointer hover. On touch-first interfaces, choose a label that fits the available space.
- Direct text is wrapped in `Badge.Label` automatically. Use `Badge.Label` explicitly when text is
  composed with a dot, icon, or another element.
- Direct child `svg` icons inherit `currentColor` and use `--moduix-badge-icon-size`.
- Numeric content uses tabular figures, and badge text is not selectable by default.

## Styling

Start with a built-in variant. For a one-off size or style change, set the public
`--moduix-badge-*` variables on the badge through a class or inline style. Use
`--moduix-badge-<variant>-*` variables to theme a variant across the application. The shared
`--moduix-badge-bg`, `--moduix-badge-border-color`, and `--moduix-badge-color` variables override
the variant-specific values for an individual badge.

### Styling hooks

- `data-slot="badge-root"`, `data-slot="badge-label"`, and `data-slot="badge-dot"` are stable selectors for styling the exported parts.
- `Badge.Root` also exposes `data-scope="badge"` and `data-part="root"`. `Badge.Label` and `Badge.Dot` expose `data-part="label"` and `data-part="dot"`.
- `Badge.Root` writes the selected variant to `data-variant`.
- Semantic links and buttons rendered through `Badge asChild` or `Badge.Root asChild` receive the root's default focus-visible styling.
- Direct child `svg` icons inherit `currentColor`, do not receive pointer events, and use `--moduix-badge-icon-size`.
- Badge has no dedicated Ark primitive or behavior machine, so it does not expose Ark-managed states
  or runtime CSS variables.
