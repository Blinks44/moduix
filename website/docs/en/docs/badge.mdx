## API Reference

Ark UI does not ship a dedicated badge primitive. moduix builds this component with the official
[Ark factory](https://ark-ui.com/docs/guides/composition#the-ark-factory), follows Ark's
[composition](https://ark-ui.com/docs/guides/composition), [styling](https://ark-ui.com/docs/guides/styling), and
[ref](https://ark-ui.com/docs/guides/ref) guidance.

## Choosing the right component

Use `Badge` when the UI is showing metadata about something else rather than the selected value
itself.

- Choose **`Badge`** for short metadata such as status, category, version, or count.
- Choose **`Tag`** when the UI is showing selected values, filters, assignments, or labels that belong to the current state of the interface.

## Anatomy

`Badge` keeps the public surface small and exposes only the visible parts.

```text
Badge / Badge.Root
├─ Badge.Label (optional; direct text is wrapped automatically)
├─ Badge.Dot (optional)
└─ svg icon (optional)
```

| Part                   | Role                                                                                 |
| ---------------------- | ------------------------------------------------------------------------------------ |
| `Badge` / `Badge.Root` | Root slot. Applies variant, border, spacing, and text truncation.                    |
| `Badge.Label`          | Explicit text slot. Keeps composed labels eligible for truncation.                  |
| `Badge.Dot`            | Optional indicator slot. Renders a circular marker that inherits current text color. |

## Composition

### Recommended composition

Stay with `Badge` directly for most status labels, categories, version pills, and short
counters.

Use `variant` for the built-in tones: `default`, `secondary`, `destructive`, `outline`, `ghost`,
and `link`.

Place `Badge.Dot` or a direct child icon next to `Badge.Label` when a composed badge needs an extra
visual cue. Plain text is wrapped in `Badge.Label` automatically.

`Badge.Root`, `Badge.Label`, and `Badge.Dot` forward refs to their rendered DOM elements.

### When to go custom

Use `Badge asChild` when another semantic element must own the DOM node. Ark composition requires
exactly one child. Interactive children keep their native semantics and inherit the badge's default
cursor, hover, and keyboard-focus treatment.

Switch to local CSS variables or `className` overrides when the surface needs custom sizing or a
different tone.

### Default props

| Prop      | Default   | Values / Notes                                                    |
| --------- | --------- | ----------------------------------------------------------------- |
| `variant` | `default` | `default`, `secondary`, `destructive`, `outline`, `ghost`, `link` |
| `asChild` | `false`   | Ark factory composition with exactly one child                    |

### Behavioral notes

- `Badge` is presentational by default and renders a `span`.
- `Badge.Dot` is decorative and hidden from assistive technology, so the visible text must carry the status meaning.
- `Badge` does not add managed interaction or link/button semantics of its own.
- Semantic links and buttons rendered through `asChild` keep their native semantics and get default cursor, hover, and focus-visible styling.
- Disabled buttons and elements with `aria-disabled="true"` keep their semantics, skip hover styling, and use the public disabled-opacity hook.
- Long labels stay on one line and are truncated by the root; `title` exposes the complete value on
  pointer hover, while touch-first interfaces need a label that fits the available space.
- Direct text is wrapped in `Badge.Label` automatically. Use `Badge.Label` explicitly when text is
  composed with a dot, icon, or another element.
- Direct child `svg` icons inherit `currentColor` and use `--moduix-badge-icon-size`.
- Numeric content uses tabular figures, and badge text is not selectable by default.
- Chakra's size recipe is intentionally represented by public CSS variables instead of a `size`
  prop.

## Styling

Prefer built-in variants first, then local CSS variables for one-off sizing and tone changes.
Use `--moduix-badge-<variant>-*` variables to theme a variant across the application; the shared
`--moduix-badge-bg`, `--moduix-badge-border-color`, and `--moduix-badge-color` variables remain
the higher-priority one-off overrides.

### Styling hooks

- `data-slot="badge-root"`, `data-slot="badge-label"`, and `data-slot="badge-dot"` are stable selectors on the exported parts.
- `Badge.Root` also exposes `data-scope="badge"` and `data-part="root"`. `Badge.Label` and `Badge.Dot` expose `data-part="label"` and `data-part="dot"`.
- `Badge.Root` writes the selected tone to `data-variant`.
- Semantic links and buttons rendered through `Badge asChild` or `Badge.Root asChild` receive default focus-visible styling from the root.
- Direct child `svg` icons inherit `currentColor`, do not receive pointer events, and are sized with `--moduix-badge-icon-size`.
- There are no Ark-managed states or runtime CSS variables because Badge has no dedicated Ark
  primitive or behavior machine.
