## API Reference

Ark UI does not provide a dedicated list primitive. moduix uses the official
[Ark factory](https://ark-ui.com/docs/guides/composition#the-ark-factory) to compose native `ul`, `ol`, and
`li` elements. See Ark's guides to [composition](https://ark-ui.com/docs/guides/composition),
[styling](https://ark-ui.com/docs/guides/styling), and [refs](https://ark-ui.com/docs/guides/ref) for the
underlying model.

## Choosing the right component

Use `List` for static grouped content such as steps, features, or metadata. It keeps native `ul` and `ol`
semantics while adding controls for spacing, typography, tone, and markers.

If users need to navigate with the keyboard and select one or more options, use [Listbox](/docs/listbox).
`Listbox` manages focus, the collection, and selection.

## Basic

`List` renders a semantic `<ul>` by default. Use `List.Item` when you need the stable item part and its
styling hooks, or use native `<li>` children when you do not need the wrapper. The root controls spacing,
typography, tone, and markers.

## Anatomy

The usual composition is simple:

```text
List / List.Root
└─ List.Item | li
```

| Part                 | Role                                                                                       |
| -------------------- | ------------------------------------------------------------------------------------------ |
| `List` / `List.Root` | Semantic list root that renders `ul` or `ol` and controls markers, spacing, size, and tone. |
| `List.Item`          | Optional item part that renders `li`, forwards native attributes and refs, and supports `asChild`. |

## Composition

### Recommended composition

Use `<List>` for unordered content and `<List as="ol">` for ordered content. Native ordered-list props such
as `start`, `reversed`, and `type` are forwarded to the root. Use `List.Item` when you need its stable
styling hooks or `asChild`; otherwise, native `li` elements are enough.

### When to go custom

Use `asChild` only with a component that renders one semantic element and forwards the props and ref it
receives. A root child must preserve `ul` or `ol`; an item child must preserve `li`.

`List` does not provide a state machine, nested-list helpers, or a marker rendering API. For ordinary item
styling, use `className` and native CSS such as `li::marker`.

Keep each item as a direct child of the list. The built-in spacing and marker styling apply only to direct
list items.

### Default props

The props below apply to the `List` root. `List.Item` accepts native `li` props plus `className` and `asChild`.

| Prop      | Default                | Notes                                                                                                      |
| --------- | ---------------------- | ---------------------------------------------------------------------------------------------------------- |
| `gap`     | `sm`                   | Spacing between direct list items.                                                                         |
| `size`    | `md`                   | Typography size from the design scale.                                                                     |
| `tone`    | `default`              | Semantic color used for text and markers.                                                                  |
| `marker`  | `auto` (semantic mode) | `auto` uses `disc` for `ul` and the browser's default markers for `ol`. Use `disc`, `decimal`, or `none` to set a marker explicitly. |
| `as`      | `ul`                   | Renders the root as the native `ul` or `ol` element.                                                       |
| `asChild` | `false`                | Uses one child from your code as the rendered semantic list element.                                      |

### Behavioral notes

- Native root attributes are forwarded to the rendered `ul` or `ol`, and native item attributes are forwarded to `List.Item`.
- Refs point to the rendered semantic root or item element.
- Use `marker="none"` to hide markers while keeping list semantics. When markers are disabled, `List` adds
  `role="list"` unless you explicitly provide another `role`.
- Root spacing uses flex `gap` with a column direction by default. If your CSS changes the direction or enables wrapping, `gap` follows that layout.
- `List.Item` is optional. Use plain `li` elements when you do not need the exported item part.

### Styling hooks

`List` exposes the following public styling hooks:

- root: `data-scope="list"`, `data-part="root"`, `data-slot="list-root"`
- item: `data-scope="list"`, `data-part="item"`, `data-slot="list-item"`
- `data-gap="xs" | "sm" | "md" | "lg" | "xl" | "2xl"` for spacing-based styles
- `data-marker="auto" | "disc" | "decimal" | "none"` for marker-based styles
- `data-size="xs" | "sm" | "md" | "lg" | "xl"` for size-specific typography styles
- `data-tone="default" | "muted" | "subtle" | "primary" | "destructive"` for semantic color styles
- native `li::marker` targeting for marker-specific color or weight overrides
