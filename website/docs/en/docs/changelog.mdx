# Changelog

<ChangelogNewsItem version="v3.2" dateTime="2026-11">

## Svelte joins React, Solid, and Vue

<SvelteReleaseHero />

moduix now supports Svelte 5. [`@moduix/svelte`](/docs/quick-start) and `@moduix/svelte-tailwind`
include every component from the other adapters, with the same flat names, tokens, and themes.

Components work the way Svelte code usually does: runes, snippets, and `bind:`. The packages ship
`.svelte` source, so your own Svelte compiler builds them, and SvelteKit renders them on the server
without extra configuration. To keep the source in your repository instead, use the `@moduix-svelte`
and `@moduix-svelte-tailwind` registries.

[Quick Start](/docs/quick-start), [SvelteKit setup](/docs/installation/sveltekit),
[form integrations](/docs/forms), and [blocks](/blocks) now cover Svelte.
</ChangelogNewsItem>

<ChangelogNewsItem version="v3.0" dateTime="2026-10-13">

## Vue joins React and Solid

<VueReleaseHero />

Vue joins React and Solid as a native moduix adapter. [`@moduix/vue`](/docs/quick-start) and
`@moduix/vue-tailwind` provide the full component catalog with shared tokens and themes.

### Breaking changes in 3.0

All components now use flat named exports across React, Solid, and Vue, in both CSS Modules and
Tailwind. This applies to npm packages and registry source. When upgrading from 2.x, update your
imports and component names:

| Before | Now |
| --- | --- |
| `Dialog.Root` | `Dialog` |
| `Dialog.Trigger` | `DialogTrigger` |
| `Dialog.Content` | `DialogContent` |
| `Dialog.RootProvider` | `DialogRootProvider` |
| `Dialog.Context` | `DialogContext` |

The same naming pattern applies to every component family. Compound exports such as `Dialog.*`
and duplicate root aliases such as `DialogRoot` have been removed. Hooks such as `useDialog`
remain top-level named exports.

### Native Vue composition

Use flat named exports in SFCs with `script setup`, native props, events, `v-model`, and scoped slots.
The `@moduix-vue` and `@moduix-vue-tailwind` registries copy authored Vue source into your application.

[Quick Start](/docs/quick-start), [form integrations](/docs/forms), and [blocks](/blocks) now include
Vue alongside React and Solid in all three documentation languages. Component pages document genuine
Ark adapter differences and version-specific upstream limitations. Svelte remains planned.

### Installable blocks

The former recipes are now [blocks](/blocks) that you can install through the shadcn registry.
All 12 blocks include React, Solid, and Vue source, a layout stylesheet, and the required UI components.
Choose CSS Modules or Tailwind for the components; both tracks use the same CSS Module for the block layout.

After [registry setup](/docs/quick-start), add a block with one command:

<PackageManagerTabs command="shadcn@latest add @moduix-react/login-simple" dlx />

See each block’s installation section for the matching Solid, Vue, and Tailwind commands.
</ChangelogNewsItem>

## Tailwind for the whole catalog

<TailwindReleaseHero />

Tailwind is now available for the whole moduix catalog. [`@moduix/react-tailwind`](/docs/quick-start)
and `@moduix/solid-tailwind` cover the same components as the CSS Modules packages.

The public API and component behavior stay the same, so choosing Tailwind does not change how the
components are composed.

Your `className` or `class` values are merged after the defaults with `tailwind-merge`. The
`@moduix-react-tailwind` and `@moduix-solid-tailwind` registry namespaces include the base
stylesheet, so the installed files are ready to customize.
</ChangelogNewsItem>

<ChangelogNewsItem version="Solid 1.0" dateTime="2026-09-13">

## The full catalog for Solid

<SolidReleaseHero />

The full moduix catalog is now available for Solid. [`@moduix/solid`](/docs/quick-start) and
`@moduix/solid-tailwind` use native Solid APIs and Ark UI primitives.

Solid components use `class` and native Solid composition. Their public contracts match the React
packages, while the implementation follows Solid's own rendering model.

CSS Modules and Tailwind are both available for Solid. They share tokens, themes, and the
`@moduix-solid` and `@moduix-solid-tailwind` registry namespaces.
</ChangelogNewsItem>

<ChangelogNewsItem version="v2.5" dateTime="2026-08-27">

## Follow readers through long pages

<TableOfContentsHero />

[Table of Contents](/docs/table-of-contents) follows the headings in view and marks the current
section. Pass it the headings you want to track, and each entry links to its matching heading.

Use `TocContent` for the reading area and `TocNav` for the list of headings. The active entry
updates as the reader moves through the page.

Use `TocIndicator` or `TocRail` to show the hierarchy. Add `TocRootProvider` when controls outside
the table of contents need to share its state.
</ChangelogNewsItem>

<ChangelogNewsItem version="v2.4" dateTime="2026-08-25">

## Group links without hiding destinations

<NavigationMenuHero />

[Navigation Menu](/docs/navigation-menu) separates direct destinations from groups of related links.
Use it when the top-level navigation needs both kinds of entries.

Use `NavigationMenuLink` for a direct destination. For a group of links, combine
`NavigationMenuTrigger` with `NavigationMenuContent`.

Add `NavigationMenuViewport` when several panels should animate inside one shared surface. Ark UI
handles keyboard interaction, focus, and the open value. `NavigationMenuArrow` is optional.
</ChangelogNewsItem>

<ChangelogNewsItem version="v2.3" dateTime="2026-08-20">

## Charts with a consistent figure

<ChartHero />

[Chart](/docs/chart) adds an accessible `figure` around TanStack Charts. Define the chart with
TanStack, then add the moduix header, legend, compact tooltip, and motion settings.

TanStack still controls the marks, scales, interactions, and callbacks. Compose the chart with
`ChartHeader`, `ChartPlot`, and `ChartLegend` for a consistent figure structure.

TanStack also controls keyboard navigation and the tooltip lifecycle. The moduix motion preset
respects reduced-motion preferences, and `motion={false}` disables the animation.
</ChangelogNewsItem>

## Ark UI now powers component behavior

<V2MigrationHero />

The component system now uses Ark UI for state, interaction, and accessibility when a matching
primitive is available. moduix keeps its CSS Modules, design tokens, and both installation paths.

Components with an Ark UI primitive use it for state and interaction. This also gives them the
accessibility behavior provided by Ark UI.

Public composition and low-level props follow Ark contracts. Install the package, or copy the source
into your application when you need to own the implementation.
</ChangelogNewsItem>
