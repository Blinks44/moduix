## Anatomy

```text
Carousel
├─ CarouselItemGroup
│  └─ CarouselItem[index]
├─ CarouselControl
│  ├─ CarouselPrevTrigger
│  └─ CarouselNextTrigger
├─ CarouselIndicatorGroup
│  └─ CarouselIndicator[index]
└─ CarouselProgressText

CarouselRootProvider
└─ same part tree connected to a useCarousel() store
```

| Part                     | Role                                                             |
| ------------------------ | ---------------------------------------------------------------- |
| `Carousel`               | Owns carousel state, navigation, and the slide collection.       |
| `CarouselRootProvider`   | Connects the parts to state created with `useCarousel()`.        |
| `CarouselControl`        | Container for navigation buttons and other controls.             |
| `CarouselItemGroup`      | Slide track that contains `CarouselItem` parts.                  |
| `CarouselItem`           | A single slide with a stable `index`.                            |
| `CarouselPrevTrigger`    | Button that moves to the previous page.                          |
| `CarouselNextTrigger`    | Button that moves to the next page.                              |
| `CarouselIndicators`     | moduix convenience component that renders the default page dots. |
| `CarouselIndicatorGroup` | Container for custom page indicators.                            |
| `CarouselIndicator`      | Button that moves to the page with the given index.              |
| `CarouselProgressText`   | Text showing the current page and the total number of pages.     |

## Composition

`Carousel` owns state inside the root. Use `defaultPage` for an uncontrolled carousel; use `page`
with `onPageChange(details)` when routing, filters, or another part of the application owns the
current page. `slideCount` is required and must stay in sync with rendered items when the collection
changes.

Use `CarouselRootProvider` with `useCarousel()` when the store must be created outside the rendered
tree or shared across composition boundaries. Pass that store to `CarouselRootProvider` and do not
render a second `Carousel` root for the same store.

`CarouselIndicators` reads `pageSnapPoints` from context and creates the standard indicators. For
custom indicator content, render `CarouselIndicatorGroup` and `CarouselIndicator` inside
`CarouselContext`; use the context API's `pageSnapPoints` when the number of indicators must match
the calculated pages.

In Solid, assign a ref to the element created inside the `asChild` render function. A ref on a
Carousel part itself is not forwarded through that composition path.

In Vue, a template ref on a part resolves to its rendered host through `$el`, including an `asChild`
replacement host.

## Styling

Use `className` in React or `class` in Solid and Vue on exported parts for structural styling. For
state-based styles, prefer Ark data attributes such as `data-orientation`, `data-current`, and
`data-dragging`,
together with moduix `data-slot` selectors. Tailwind variants use native utility classes and consumer
class overrides; the CSS Properties reference below applies to the CSS Modules packages.

### CSS Properties

<CssPropertiesSection properties={CarouselDocs.carouselOverrideCssProperties} />

### Styling hooks

- `data-slot="carousel-root"`, `carousel-root-provider`, `carousel-control`, `carousel-item-group`,
  `carousel-item`, `carousel-prev-trigger`, `carousel-next-trigger`, `carousel-indicator-group`,
  `carousel-indicator`, `carousel-autoplay-trigger`, `carousel-autoplay-indicator`, and
  `carousel-progress-text` are stable selectors for the exported parts.
- Ark also adds `data-scope="carousel"` and `data-part` names to the rendered nodes.
- `data-orientation="horizontal" | "vertical"` is available on the root and structural parts.
- `CarouselItemGroup` exposes `data-dragging` while a drag interaction is active.
- `CarouselIndicator` exposes `data-current`, while `CarouselItem` exposes `data-index` and
  `data-inview`.
- `CarouselIndicator` exposes `data-readonly`, while `CarouselAutoplayTrigger` exposes
  `data-pressed`.
