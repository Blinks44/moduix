## Anatomy

```text
Carousel / Carousel.Root
├─ Carousel.ItemGroup
│  └─ Carousel.Item[index]
├─ Carousel.Control
│  ├─ Carousel.PrevTrigger
│  └─ Carousel.NextTrigger
├─ Carousel.IndicatorGroup
│  └─ Carousel.Indicator[index]
└─ Carousel.ProgressText
```

| Part                         | Role                                                               |
| ---------------------------- | ------------------------------------------------------------------ |
| `Carousel` / `Carousel.Root` | Owns carousel state, navigation, and the slide collection.         |
| `Carousel.RootProvider`      | Connects the parts to state created with `useCarousel()`.          |
| `Carousel.Control`           | Container for navigation buttons and other controls.               |
| `Carousel.ItemGroup`         | Slide track that contains `Carousel.Item` parts.                   |
| `Carousel.Item`              | A single slide with a stable `index`.                              |
| `Carousel.PrevTrigger`       | Button that moves to the previous page.                            |
| `Carousel.NextTrigger`       | Button that moves to the next page.                                |
| `Carousel.Indicators`        | moduix convenience component that renders the default page dots.   |
| `Carousel.IndicatorGroup`    | Container for custom page indicators.                               |
| `Carousel.Indicator`         | Button that moves to the page with the given index.                 |
| `Carousel.ProgressText`      | Text showing the current page and the total number of pages.        |

`Carousel.Indicators` reads `pageSnapPoints` from context and renders one `Carousel.Indicator` per
page. Use it instead of manually rendering `Carousel.IndicatorGroup` when the default indicators
are enough. It also accepts `indicatorClassName` for styling the generated indicators.

For advanced compositions, these parts are also available:

- `Carousel.Context`
- `Carousel.AutoplayTrigger`
- `Carousel.AutoplayIndicator`
- `Carousel.RootProvider`

`Carousel`, `useCarousel`, and `useCarouselContext` are available from `@moduix/react`. The
component can also be imported from `@moduix/react/carousel`.

## Composition

### Recommended composition

Use `Carousel` as the root, `Carousel.ItemGroup` as the slide track, and `Carousel.Control` for
navigation. Add `Carousel.Indicators` when the default dot indicators are enough.

`Carousel.Control` is usually a sibling of `Carousel.ItemGroup` and works as a toolbar. For a
compact inline layout, you can place `Carousel.ItemGroup` inside `Carousel.Control` instead.

`Carousel.Root` is an explicit alias for `Carousel`. Use it when you prefer the namespaced form in
your code.

### When to go custom

Use `Carousel.Context` with `Carousel.IndicatorGroup` and `Carousel.Indicator` when you need a
custom pager, thumbnail indicators, or direct access to `pageSnapPoints`.

Use `Carousel.RootProvider` with `useCarousel()` when carousel state must be created outside the
rendered subtree and shared across composition boundaries.

Use `useCarouselContext()` inside custom child components that need the carousel API without
passing a render function as a child.

Use `Carousel.AutoplayTrigger` and `Carousel.AutoplayIndicator` when autoplay controls should be
visible in the UI instead of being configured only through a root prop.

### Default props

| Prop         | Default | Notes                                                                                  |
| ------------ | ------- | -------------------------------------------------------------------------------------- |
| `slideCount` | -       | Required on `Carousel` / `Carousel.Root`; pass it to `useCarousel()` for `RootProvider`. |

### Behavioral notes

- `onPageChange(details)` uses Ark's callback shape and exposes the active page as `details.page`.
- Give `Carousel` or `Carousel.RootProvider` an `aria-label` or `aria-labelledby` so the carousel
  landmark has an accessible name.
- `spacing`, `padding`, `slidesPerPage`, `slidesPerMove`, and `autoSize` use Ark's sizing and
  snap-point behavior directly.
- Vertical carousels use the same public API. The default moduix chevrons rotate automatically,
  and `--moduix-carousel-height` controls the root height in vertical orientation.
- With `dir="rtl"`, default horizontal triggers mirror automatically.
- `Carousel.ProgressText` keeps the numeric `current / total` order readable in RTL carousels.
- `--moduix-carousel-indicator-size` controls the compact indicator button, so its focus ring
  follows the dot or current capsule geometry.
- With `prefers-reduced-motion: reduce`, the track scrolls immediately, and moduix disables
  transitions for controls and indicators.

## Styling

Use `className` on exported parts for structural styling. For state styles, prefer Ark data
attributes (`data-part`, `data-orientation`, `data-current`, `data-dragging`) and moduix `data-slot`
hooks.

### CSS Properties

<CssPropertiesSection properties={CarouselDocs.carouselOverrideCssProperties} />

### Styling hooks

- `data-slot="carousel-root"`, `carousel-root-provider`, `carousel-control`, `carousel-item-group`,
  `carousel-item`, `carousel-prev-trigger`, `carousel-next-trigger`, `carousel-indicator-group`,
  `carousel-indicator`, `carousel-autoplay-trigger`, `carousel-autoplay-indicator`, and
  `carousel-progress-text` are stable selectors for the exported parts.
- Ark also adds `data-scope="carousel"` and `data-part` names to the rendered nodes.
- `data-orientation="horizontal" | "vertical"` is available on the root and structural parts.
- `Carousel.ItemGroup` exposes `data-dragging` while a drag interaction is active.
- `Carousel.Indicator` exposes `data-current`, while `Carousel.Item` exposes `data-index` and
  `data-inview`.
- `Carousel.Indicator` exposes `data-readonly`, while `Carousel.AutoplayTrigger` exposes
  `data-pressed`.
