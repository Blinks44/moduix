## What `LocaleProvider` does

`LocaleProvider` gives a part of your application a locale and text direction. Ark formatters and locale-aware
components read this context when they format values or choose a direction. Without a provider, Ark falls back to
`en-US` and left-to-right (`ltr`).

moduix re-exports the provider and its context hook from a dedicated public entry point:

```tsx
import { LocaleProvider, useLocaleContext } from '@moduix/react/locale';
```

## Document language and direction

`LocaleProvider` derives the direction used by Ark from the locale, but it does not change the document's HTML
attributes. If the whole application uses one locale, set the matching `lang` and `dir` values on the document root,
especially for a right-to-left language.

```tsx
import type { ReactNode } from 'react';
import { LocaleProvider } from '@moduix/react/locale';

export function Document({ children }: { children: ReactNode }) {
  return (
    <html dir="rtl" lang="ar">
      <body>
        <LocaleProvider locale="ar-EG">{children}</LocaleProvider>
      </body>
    </html>
  );
}
```

For a smaller region with a different writing direction, set its `lang` value and apply the `dir` value from
`useLocaleContext` to the region's root element. See [Right-to-left (RTL)](/docs/rtl) for guidance on layout, portals,
and directional icons.

## Use it with moduix

Place one `LocaleProvider` around the part of the interface that shares a locale. Ark `Format` utilities and
locale-aware primitives inside that subtree then read the same context.

`Format.Number`, `Format.Time`, and the other `Format` utilities remain Ark imports. moduix provides interface
components and re-exports the locale context; it does not add a second formatting API.

## Responsibilities

Ark UI handles locale resolution, text direction, and the provider API. moduix re-exports `LocaleProvider` and
`useLocaleContext` from `@moduix/react/locale` through its public locale entry point.
