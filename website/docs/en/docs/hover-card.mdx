## Anatomy

```text
HoverCard
├─ HoverCard.Trigger
└─ Overlay subtree (automatically portalled)
   └─ HoverCard.Positioner
      └─ HoverCard.Content
         ├─ HoverCard.Arrow
         │  └─ HoverCard.ArrowTip
         └─ content

HoverCard.RootProvider
└─ same part tree connected to a moduix useHoverCard() store
```

| Part                           | Role                                                                     |
| ------------------------------ | ------------------------------------------------------------------------ |
| `HoverCard`                    | Root state, delays, positioning, ids, presence, and outside interaction. |
| `HoverCard.RootProvider`       | Renders the same hover-card tree from moduix `useHoverCard()` state.    |
| `HoverCard.Trigger`            | Hover and focus target. Use `asChild` for a link or custom semantic element. |
| `HoverCard.Positioner`         | Floating layer that exposes Ark positioning CSS variables.               |
| `HoverCard.Content`            | Visible popup surface that closes on outside interaction.                |
| `HoverCard.Arrow`              | Positioned arrow wrapper. Renders `HoverCard.ArrowTip` by default.       |
| `HoverCard.ArrowTip`           | Arrow tip element styled through Ark arrow variables.                    |

`HoverCard.Root` remains available as a compatibility alias. In application code, use the short
`HoverCard` root form.

## Composition

The root automatically portals `HoverCard.Positioner`. Set `portalled={false}` to keep it in the
current DOM tree, or pass `portalRef` to choose a different container. Keep the structural parts
explicit so you can configure the position, content, and arrow independently.

### When to go custom

Use `asChild` on `HoverCard.Trigger` for a link or your own semantic button. Render
`HoverCard.ArrowTip` directly only when you need to customize its markup. Use `HoverCard.RootProvider`
with moduix `useHoverCard()` when state must be shared with controls outside the card tree. Use
`HoverCard.Context` or `useHoverCardContext()` to read state from within the tree.

### Default props

By default, the portalled overlay content mounts on first open and unmounts after its exit animation.
Set `unmountOnExit={false}` to keep it mounted after the first open. Set both lifecycle props to
`false` only when the content must render eagerly.

| Prop                   | Default | Notes                                                              |
| ---------------------- | ------- | ------------------------------------------------------------------ |
| `closeDelay`           | `300`   | Delay in ms between leaving the trigger or content and closing.    |
| `openDelay`            | `600`   | Delay in ms between entering the trigger and opening.              |
| `lazyMount`            | `true`  | Mounts the content only when it first opens.                       |
| `unmountOnExit`        | `true`  | Removes the content after its exit animation.                      |
| `skipAnimationOnMount` | `false` | Runs the initial presence animation by default.                    |

### Behavioral notes

`onOpenChange` receives an Ark detail object such as `{ open }`; read the state from `details.open`.
For multiple triggers, use `Trigger value` with `onTriggerValueChange`. Use `ids` to set stable IDs
for the trigger, content, positioner, and arrow when you need to compose the parts accessibly. Ark
presence props, including `present`, `immediate`, and `onExitComplete`, pass through unchanged.

Hover Card disables trigger and content motion when the user prefers reduced motion. Long unbroken
words wrap inside the content instead of overflowing it.

Hover cards are for supplementary previews only. Keep the information required to understand or
complete a task visible without opening the card.

### Styling hooks

Every rendered part accepts `className`. Moduix also adds `data-slot="hover-card-*"` hooks to the
trigger, positioner, content, arrow, and arrow tip. `HoverCard` and `HoverCard.RootProvider` provide
state without rendering DOM elements, so they have no styling hook. Ark adds
`data-scope="hover-card"` and `data-part` to its parts. For state-aware styling, target
`data-state="open|closed"`, `data-placement`, `data-side`, `data-value`, `data-current`,
`data-nested`, and `data-has-nested`.

`HoverCard.Positioner` exposes `--reference-width`, `--reference-height`, `--available-width`,
`--available-height`, `--x`, `--y`, `--z-index`, and `--transform-origin`. `HoverCard.Content`
exposes `--layer-index` and `--nested-layer-count`; `HoverCard.Arrow` exposes
`--arrow-size`, `--arrow-size-half`, `--arrow-background`, and `--arrow-offset`.
