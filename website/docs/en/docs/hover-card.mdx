## Choosing the right component

Use `Tooltip` for short, non-interactive hints. Use `Popover` when the popup contains richer
content or actions. Use `HoverCard` when you need a supplementary preview tied to a trigger, such as
a profile or article summary.

## Basic

Compose the card from explicit Ark parts. `HoverCard.Trigger` opens the card, while
`HoverCard.Positioner` and `HoverCard.Content` define its floating content. The basic composition
does not include an arrow.

## Anatomy

```text
HoverCard / HoverCard.Root
├─ HoverCard.Trigger
└─ Overlay subtree (automatically rendered in a portal)
   └─ HoverCard.Positioner
      └─ HoverCard.Content
         ├─ HoverCard.Arrow
         │  └─ HoverCard.ArrowTip
         └─ content

HoverCard.RootProvider
└─ same part tree connected to a moduix useHoverCard() store
```

| Part                           | Role                                                                  |
| ------------------------------ | --------------------------------------------------------------------- |
| `HoverCard` / `HoverCard.Root`  | Owns state, lifecycle, delays, positioning, ids, and outside interaction. |
| `HoverCard.RootProvider`        | Connects the parts to state created with `useHoverCard()`.            |
| `HoverCard.Context`             | Exposes current state through a render prop for descendants.         |
| `HoverCard.Trigger`             | Interactive element that opens the card on hover or focus. Use `asChild` for a link or another semantic element. |
| `HoverCard.Positioner`          | Positions the floating layer and exposes Ark positioning variables.  |
| `HoverCard.Content`             | Visible card surface that closes on outside interaction.              |
| `HoverCard.Arrow`               | Optional positioned arrow wrapper that renders `HoverCard.ArrowTip` by default. |
| `HoverCard.ArrowTip`             | Arrow tip element styled through Ark arrow variables.                 |

`HoverCard` is the short root form, and `HoverCard.Root` is its namespace alias. Use the short form
in application code.

## Composition

The root automatically renders `HoverCard.Positioner` in a portal. Set `portalled={false}` to keep
it in the current DOM tree, or pass `portalRef` to choose a different portal container. Keep the
structural parts explicit so you can style and configure the positioner, content, and arrow
independently.

### Recommended composition

For most hover cards, use `HoverCard` with `HoverCard.Trigger`, `HoverCard.Positioner`, and
`HoverCard.Content`. Add `HoverCard.Arrow` only when the popup needs a visual pointer to its
trigger.

### When to go custom

Use `asChild` on `HoverCard.Trigger` when the trigger should be a link or another semantic element.
Pass one focusable child that can preserve the trigger behavior. Use `HoverCard.RootProvider` with
`useHoverCard()` when state must be shared with controls outside the card tree. Use
`HoverCard.Context` or `useHoverCardContext()` to read state inside the tree. Render
`HoverCard.ArrowTip` directly only when you need to customize its markup.

### Default props

Portalled content mounts on first open and is removed after its exit animation by default. Set
`unmountOnExit={false}` to keep it mounted after the first open. Set both lifecycle props to
`false` only when the content must render eagerly.

| Prop                   | Default | Notes                                                                    |
| ---------------------- | ------- | ------------------------------------------------------------------------ |
| `openDelay`            | `600`   | Delay before opening after the trigger is hovered or focused.            |
| `closeDelay`           | `300`   | Delay before closing after the pointer leaves the trigger or content.    |
| `lazyMount`            | `true`  | Mounts the content only after its first opening.                         |
| `unmountOnExit`        | `true`  | Removes the content after its exit animation.                            |
| `skipAnimationOnMount` | `false` | Keeps the initial presence animation enabled.                            |
| `portalled`            | `true`  | Renders the positioner in a portal.                                     |
| `portalRef`            | `-`     | Targets a custom portal container.                                      |
| `positioning`          | `-`     | Ark positioning options.                                                 |
| `ids`                  | `-`     | Stable IDs for the trigger, content, positioner, and arrow.             |
| `defaultOpen`          | `-`     | Initial open state for uncontrolled usage.                              |
| `open`                 | `-`     | Controlled open state.                                                    |
| `disabled`             | `false` | Disables hover-card interaction.                                         |

### Behavioral notes

- `onOpenChange(details)` receives an object such as `{ open }`. Read the next open state from
  `details.open`.
- Give each trigger a `value` and use `onTriggerValueChange(details)` when several triggers share
  one content area. Read the active trigger from `details.value`.
- `HoverCard.RootProvider`, `HoverCard.Context`, `useHoverCard`, and `useHoverCardContext` are
  available for advanced state access. Create the store with `useHoverCard()` when state belongs
  outside the rendered card tree, then pass it to `RootProvider` through its `value` prop.
- Ark presence props such as `present`, `immediate`, and `onExitComplete` pass through unchanged.
- `HoverCard.Trigger` receives moduix's default trigger styling only when `asChild` is not used.
  With `asChild`, the child element owns its styling.
- Trigger and content motion is disabled when the user prefers reduced motion. Long unbroken words
  wrap inside the content instead of overflowing it.
- Hover cards are for supplementary previews. Keep information required to understand or complete a
  task visible without opening the card.

### Styling hooks

Every rendered part accepts `className`. Moduix also adds `data-slot="hover-card-*"` hooks to the
trigger, positioner, content, arrow, and arrow tip. `HoverCard` and `HoverCard.RootProvider` only
provide state and do not render DOM elements, so they have no styling hooks. Ark adds
`data-scope="hover-card"` and `data-part` to its parts. For state-aware styling, target
`data-state="open|closed"`, `data-placement`, `data-side`, `data-value`, `data-current`,
`data-nested`, and `data-has-nested`.

`HoverCard.Positioner` exposes `--reference-width`, `--reference-height`, `--available-width`,
`--available-height`, `--x`, `--y`, `--z-index`, and `--transform-origin`. `HoverCard.Content`
exposes `--layer-index` and `--nested-layer-count`. `HoverCard.Arrow` exposes `--arrow-size`,
`--arrow-size-half`, `--arrow-background`, and `--arrow-offset`.
