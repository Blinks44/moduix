## Basic lifecycle

`Presence` is an Ark UI utility for application-owned content. It renders one child subtree while
`present` is `true`, and adds `data-state="open"` or `data-state="closed"` for state-based styles.

Use `unmountOnExit` when the subtree should be removed after its exit animation. Without it, the root stays mounted
and Ark hides it with the `hidden` attribute when `present` becomes `false`.

## Lazy mount

Add `lazyMount` when the content should not be mounted before its first appearance. Combine it with
`unmountOnExit` when the content should be absent both before the first open and after it closes.

`lazyMount` only delays the first mount. It does not remove a subtree after closing on its own.

## Exit animations and callbacks

When `unmountOnExit` is enabled, Ark keeps the root mounted while the CSS exit animation runs. Target
`data-state="open"` and `data-state="closed"` in the same stylesheet as the root class. Use `onEnterComplete` and
`onExitComplete` when surrounding UI or analytics must react after an animation finishes.

Set `skipAnimationOnMount` when the initial appearance should be immediate. Set `immediate` when a `present` change
must be applied immediately instead of being deferred to the next frame.

## Options that affect rendering

| Option | Behavior |
| --- | --- |
| `present` | Controls whether the subtree is present. |
| `lazyMount` | Delays the first mount until `present` is `true`. |
| `unmountOnExit` | Removes the root after the closed-state animation finishes. |
| `onEnterComplete` / `onExitComplete` | Run after the enter or exit animation completes. |
| `skipAnimationOnMount` | Skips the initial presence animation. |
| `immediate` | Applies a `present` change immediately instead of waiting for the next frame. |
| `hideMode` | React only. Use `display-none` for `hidden` behavior or `activity` to pause effects with React 19 `Activity`. |

The shared lifecycle options and callbacks have the same meaning in React and Solid. Ark Solid does not expose
`hideMode`; mounted but non-present content uses the `hidden` attribute.

## Composition and accessibility

Use `Presence` when the application owns the lifecycle of a panel, notice, card, or other subtree. It does not add
focus management, dismissal, positioning, or dialog semantics. For Dialog, Drawer, Menu, Popover, Tooltip, Tour, and
other interactive roots, use that component's own presence options so its interaction model stays coordinated.

`Presence` renders a `<div>` by default with `data-scope="presence"` and `data-part="root"`. Use `asChild` when one
existing element should receive those props instead of adding a wrapper. The React child must accept the forwarded ref,
`hidden`, `data-*`, and class name. Solid uses Ark's render-function form:
`asChild={(props) => <article {...props()} />}`. In either framework, keep one semantic root and preserve its accessible
name and content. Do not use `opacity` alone as a replacement for the hidden behavior when inactive content must leave
the accessibility tree.
