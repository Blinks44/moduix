## What Presence does

`Presence` is an Ark UI utility, not a component exported by `@moduix/react`. It controls one child subtree with the
`present` prop. Depending on its render-strategy props, that subtree can stay mounted while hidden, mount only when it
is first shown, or unmount after its exit animation.

By default, Presence renders a `<div>` root with `data-scope="presence"` and `data-part="root"`. The root also gets
`data-state="open"` or `data-state="closed"`, which lets you style enter and exit states with CSS. Use `asChild` when
an existing child element should receive Presence's props instead of adding a wrapper.

Import it directly from Ark UI:

```tsx
import { Presence } from '@ark-ui/react/presence';
```

## When to use it

Use standalone `Presence` for application-controlled panels, notices, cards, or other content whose mount lifecycle
needs explicit control.

For Dialog, Drawer, Lightbox, Menu, Popover, Tooltip, Tour, and similar moduix roots, use the presence props exposed by
those components. They already coordinate presence with focus management, positioning, and dismissal. Use standalone
`Presence` when the lifecycle belongs to your application rather than to an existing moduix root.

## Mount on demand

Combine `lazyMount` and `unmountOnExit` when content should be absent before its first appearance and after it closes.
`lazyMount` delays the first mount; by itself it does not remove content on close. `unmountOnExit` handles that part.

## Exit animations

When `unmountOnExit` is enabled, Presence keeps the root in the DOM while its CSS exit animation runs. Target
`data-state="open"` and `data-state="closed"` to define the enter and exit styles. Use `onExitComplete` when other
work must wait until the exit animation has finished.

```tsx
import { Presence } from '@ark-ui/react/presence';
import { Card } from '@moduix/react/card';

export function ActivityPanel({ open }: { open: boolean }) {
  return (
    <Presence className="activity-panel" present={open} unmountOnExit>
      <Card>Saved filters will apply to the next refresh.</Card>
    </Presence>
  );
}
```

```css
@keyframes activity-panel-enter {
  from {
    opacity: 0;
    transform: translateY(-0.25rem);
  }
}

@keyframes activity-panel-exit {
  to {
    opacity: 0;
    transform: translateY(-0.25rem);
  }
}

.activity-panel[data-state='open'] {
  animation: activity-panel-enter 160ms ease-out;
}

.activity-panel[data-state='closed'] {
  animation: activity-panel-exit 120ms ease-in;
}
```

Set `skipAnimationOnMount` when the first appearance should be immediate. Set `immediate` when the `present` change
should be applied immediately instead of being deferred to the next frame.

## Hiding mounted content

When content stays mounted, `hideMode` controls how Ark hides it:

- `display-none` is the default. It uses the `hidden` attribute, so effects in the subtree continue to run.
- `activity` uses React 19's `Activity` component with `mode="hidden"`, which pauses effects while the content is
  hidden. This option requires React 19 or later. If `Activity` is not available, Ark falls back to the `hidden`
  attribute.

Choose `lazyMount` and `unmountOnExit` when the subtree should not exist outside its active lifecycle. Choose
`hideMode` when it should stay mounted but needs a different hidden-state behavior.

## Composition

### Recommended composition

Keep `Presence` close to the content whose mount lifecycle it controls. It can wrap a moduix component or a semantic
HTML element. Pass `className` to the Presence root when that container needs layout or animation styles.

### When to use `asChild`

Use `asChild` when you already have one suitable root element and want Presence to merge its props into that element.
Make sure the child can receive a ref, `hidden`, `data-*`, and the forwarded class name. Do not use `asChild` with
multiple children.

## Using moduix

Place any moduix component inside `Presence`: cards, buttons, forms, and custom panels keep their regular styling and
behavior. Presence only manages the mount lifecycle and state attributes; it does not replace the child's semantics or
interaction model.

## Ark UI and moduix

Ark UI provides the `Presence` API, mount strategy, and animation lifecycle. `@moduix/react` does not re-export `Presence`,
so import it from `@ark-ui/react/presence` and use moduix components inside it. Moduix roots that manage their own
expandable or overlay behavior expose equivalent presence props where appropriate.

If you use the standalone utility with moduix, install both packages:

```bash
pnpm add @ark-ui/react @moduix/react
```
