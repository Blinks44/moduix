# TanStack Form

[TanStack Form](https://tanstack.com/form/latest) provides typed, headless form state with native
framework-native adapters. This guide focuses on mapping that state to Moduix controls.

## Connect controls

TanStack fields use controlled values. Read the current value, pass it to the Moduix control, and send
the next value to `field.handleChange`.

| Control             | Mapping                                                               |
| ------------------- | --------------------------------------------------------------------- |
| `Input`, `Textarea` | Pass the scalar value and update it from the native input event.      |
| `Select`            | Convert the scalar value to and from Ark's string-array `value`.      |
| `Combobox`          | Map the selected value and keep text filtering separate.              |
| `Checkbox`          | Map `details.checked === true` to the boolean field value.            |

Define every field in `defaultValues`. Forward `handleBlur` from the real interaction boundary and
keep the required `HiddenSelect` or `HiddenInput` in the Moduix composition.

## Validation and reset

Use field validators for local rules and form validators for schema or cross-field rules. Pass
`!field.state.meta.isValid` to `Field invalid` and render the errors with `FieldErrorText` after the
chosen validation lifecycle runs.

Add `noValidate` only when TanStack Form owns the visible errors. Call `form.reset()` for controlled
fields so form state and Moduix controls reset together.

## Repeated fields and server errors

Use an array-mode field for add, remove, and reorder operations. Give every row a stable application
ID for keyed rendering and keep the array index only in the nested field name.

Return `fields` from an asynchronous form validator for server errors tied to specific values, and
use the optional `form` message for a form-level failure. The usual field error rendering can then
display both client and server results.

## Focus and behavior

- Use `onSubmitInvalid` to focus the first rendered control marked with `aria-invalid="true"`.
- In React, read `field.state`; in Solid, read `field().state`.
- In React, subscribe values are passed directly; in Solid, read them from the subscription accessor.
- Use the native input event for Solid text controls and map Ark detail objects explicitly.
- Submit through the native `<form>` handler after `preventDefault()` and call `form.handleSubmit()`.
