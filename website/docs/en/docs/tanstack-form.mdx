# TanStack Form

[TanStack Form documentation](https://tanstack.com/form/latest/docs/framework/react/overview) covers
the complete React API and validation model. This page shows how to connect moduix controls to a
TanStack form.

TanStack Form fields use controlled values. Pass `field.state.value` to the control, then send the
value from its change callback to `field.handleChange`. `Select`, `Checkbox`, `DateInput`, and
`SignaturePad` create the native form control they need for form submission. Do not add a second
hidden input for these components. `Combobox` is different: it does not create an additional hidden
input. Its visible input can participate in `FormData`, but serialize `field.state.value` yourself
when the submitted value must be the selected item.

```bash
npm install @tanstack/react-form
```

## Mapping

| Control                          | TanStack Form wiring                                                              |
| -------------------------------- | --------------------------------------------------------------------------------- |
| `Input`, `Textarea`, `Field.Select` | Pass the scalar `field.state.value` and call `field.handleChange` from `onChange`. |
| `Select`                         | Convert the scalar field value to and from Ark's string-array `value`.             |
| `Combobox`                       | Use the same value mapping and keep filtering in `onInputValueChange`.             |
| `Checkbox`                       | Map `details.checked === true` to the boolean field value.                         |
| `DateInput`, `SignaturePad`      | Pass form props such as `name` or `form` to the root; the component owns the input. |

The same native-input rule applies to `AngleSlider`, `ColorPicker`, `FileUpload`, `PinInput`,
`RadioGroup`, `RatingGroup`, `SegmentGroup`, `Slider`, `Switch`, and `TagsInput`. Pass form-related
props such as `name`, `form`, `required`, and `disabled` to their semantic root.

Define every field in `defaultValues`. Call `field.handleBlur` from the actual interaction
boundary so touched state and blur validation remain accurate.

Subscribe to `state.canSubmit` and `state.isSubmitting` for the submit button, as the complete
example does. Keep the form state as the source of truth, block invalid submission, and disable
duplicate submissions until the async `onSubmit` handler settles.

## Validation and reset

Use a field validator for local rules and a form-level Standard Schema validator for shared or
cross-field rules. The control mapping stays the same. The complete example validates on submit. If
you validate on blur or input, render `Field.ErrorText` and set the `invalid` prop on `Field` only
after the user has interacted with the field, so initially empty required fields are not all shown as
invalid.

Use `noValidate` only when TanStack Form owns the visible error flow. Otherwise leave native
constraint validation enabled. Use `form.reset()` for controlled fields so the library state and
moduix controls reset together; a DOM reset alone cannot replace the controlled value stored by the
form.

## Repeated fields

Use an array-mode field to own add and remove operations, then render a nested field for each item.
Give every item, including items created on the client, a stable `id`. Use it as the React key while
the index remains part of the nested field name. Wrap the list in `Fieldset` when it has a shared
label. Render this fragment in the component where `form` was created.

```tsx
const newEmail = () => ({ id: crypto.randomUUID(), address: '' });

<form.Field name="emails" mode="array">
  {(arrayField) => (
    <>
      {arrayField.state.value.map((item, index) => (
        <form.Field key={item.id} name={`emails[${index}].address`}>
          {(field) => (
            <Field invalid={!field.state.meta.isValid}>
              <Field.Label>Email {index + 1}</Field.Label>
              <Input
                name={field.name}
                type="email"
                value={field.state.value}
                onBlur={field.handleBlur}
                onChange={(event) => field.handleChange(event.currentTarget.value)}
              />
              <Field.ErrorText>{field.state.meta.errors.join(', ')}</Field.ErrorText>
              <Button type="button" onClick={() => arrayField.removeValue(index)}>
                Remove email
              </Button>
            </Field>
          )}
        </form.Field>
      ))}

      <Button type="button" onClick={() => arrayField.pushValue(newEmail())}>
        Add email
      </Button>
    </>
  )}
</form.Field>;
```

Use an ID already returned by your API when editing persisted items; `newEmail()` is only for
creating new client-side rows.

## Server errors

To display errors returned by the server, add an asynchronous submit validator to the form. Return
`fields` with the exact rejected field names and an optional `form` message for errors that do not
belong to one field. The usual `field.state.meta.errors` rendering then shows field errors without a
separate error store.

```tsx
type ProjectFormValues = {
  name: string;
  emails: { address: string; id: string }[];
};

const form = useForm<ProjectFormValues>({
  defaultValues: { name: '', emails: [] },
  validators: {
    onSubmitAsync: async ({ value }) => {
      const result = await validateProjectOnServer(value);

      if (!result.ok) {
        return {
          form: result.message,
          // For example: { name: 'Already in use.', 'emails[0].address': 'Cannot be used.' }
          fields: result.fieldErrors,
        };
      }

      return null;
    },
  },
  onSubmit: ({ value }) => saveProject(value),
});

<form.Subscribe selector={(state) => [state.errorMap.onSubmit] as const}>
  {([error]) => (error ? <p role="alert">{error}</p> : null)}
</form.Subscribe>;
```

## Focus management

TanStack Form does not manage DOM focus or choose a focus target. Use `onSubmitInvalid` to move focus
to the first rendered control that your `Field` configuration marks with `aria-invalid="true"`:

```tsx
function focusFirstInvalid(formId: string) {
  requestAnimationFrame(() => {
    const formElement = document.getElementById(formId);
    const control = formElement?.querySelector<HTMLElement>(
      '[aria-invalid="true"]:not([hidden])',
    );
    control?.focus();
  });
}

const form = useForm({
  defaultValues: { email: '' },
  onSubmit: ({ value }) => console.log(value),
  onSubmitInvalid: () => focusFirstInvalid('project-form'),
});

<form
  id="project-form"
  onSubmit={(event) => {
    event.preventDefault();
    void form.handleSubmit();
  }}
>
  {/* fields */}
</form>;
```

Forward focus to the actual control: the native Input, `Select.Trigger`, or `Combobox.Input`.

## Behavioral notes

- Wrap `form.handleSubmit()` in the native form submit handler, after calling `preventDefault()`;
  the complete form shows this boundary explicitly.
- For single selection, pass `field.state.value ? [field.state.value] : []` and read
  `details.value[0] ?? ""`.
- Call `field.handleBlur` from `Select.onInteractOutside` or `Combobox.Input.onBlur` so TanStack
  Form can update touched state.
- `Select` renders its native select automatically for native semantics and reset synchronization.
- Map `Checkbox` checked state to a boolean field value; its root renders the native input
  automatically.
- `name={field.name}` enables native `FormData` semantics but does not replace the field's controlled
  `state.value` and `handleChange` mapping.
- `Combobox` does not render a hidden input. Its visible input can be part of `FormData`; add an
  explicit input when the submitted value must be the selected item, or submit the controlled form
  state instead.
- For controls with special form options, keep the configuration on their roots: `DateInput` uses a
  two-item `names` tuple for distinct indexed range keys, `Select` uses
  `nativeFormControl="input"` for virtualized collections, and `SignaturePad` uses `getFormValue`
  for custom serialization.
- Do not spread a field object onto `Select` or `Combobox`. Their values and callbacks use Ark detail
  objects, so map them explicitly as shown above.
- Use `form.Subscribe` for derived form state instead of reading `form.state` during render.
