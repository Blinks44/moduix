## Choosing the right component

Use `NavigationMenu` for primary site or product navigation when some top-level items open groups of
related destinations.

- Choose **`NavigationMenu`** when a top-level item can reveal a group of related links.
- Choose **`Menu`** for contextual actions rather than navigation.
- Choose **`Tabs`** when each selected control switches the content shown in one area of the current page.

## Anatomy

```text
NavigationMenu
├─ NavigationMenuList
│  ├─ NavigationMenuItem[value]
│  │  └─ NavigationMenuLink
│  └─ NavigationMenuItem[value]
│     ├─ NavigationMenuTrigger
│     ├─ NavigationMenuItemIndicator (optional)
│     └─ NavigationMenuContent
│        └─ NavigationMenuLink
│  └─ NavigationMenuIndicator > NavigationMenuArrow (optional)
└─ NavigationMenuViewportPositioner (optional)
   └─ NavigationMenuViewport

NavigationMenuRootProvider
└─ same part tree connected to a useNavigationMenu() store

NavigationMenuContext
└─ advanced render-prop access to the current navigation state
```

| Part | Role |
| --- | --- |
| `NavigationMenu` | Root `nav` element that owns the open value, delays, focus behavior, and orientation. |
| `NavigationMenuRootProvider` | Connects the parts to a store created with `useNavigationMenu()`. |
| `NavigationMenuContext` | Exposes the current navigation state through a render prop. |
| `NavigationMenuList` | Groups top-level navigation items. |
| `NavigationMenuItem` | Requires a unique `value` and connects an item's trigger, content, and links. |
| `NavigationMenuTrigger` | Button that opens or closes the item's disclosure panel. |
| `NavigationMenuContent` | Disclosure panel for an item. It can render beside the item or inside a shared `NavigationMenuViewport`. |
| `NavigationMenuLink` | Anchor for a direct destination or a link inside a disclosure panel. |
| `NavigationMenuItemIndicator` | Optional visual marker for the current item. |
| `NavigationMenuIndicator` | Optional marker for the active trigger; render it inside `NavigationMenuList`. Use `NavigationMenuArrow` with a shared `NavigationMenuViewport`. |
| `NavigationMenuViewportPositioner` | Positions a shared `NavigationMenuViewport`. |
| `NavigationMenuViewport` | Shared animated surface for the currently open content. |

## Composition

Use `defaultValue` for an uncontrolled menu. When another part of the application owns the open
item, pass `value` with `onValueChange(details)`; `details.value` is the open item's value or an
empty string when all panels are closed. Create the store with `useNavigationMenu()` and pass it
to `NavigationMenuRootProvider` when it must live outside the rendered tree; do not render another
root for that store. React reads the store as an object; Solid reads its reactive state through
the returned accessor. Use `NavigationMenuContext` when a descendant needs the current state
through a render prop instead of a store.

Without a shared viewport, `NavigationMenuContent` renders beside its item. Add
`NavigationMenuViewportPositioner` and `NavigationMenuViewport` when several panels should share one
animated surface; the positioner's `align` prop (`"start" | "center" | "end"`, default `"center"`)
aligns the viewport against the value positioner. Use `asChild` for router links or custom
triggers only when the child remains one interactive, focusable element.

## Styling

Use `className` in React or `class` in Solid on exported parts for structural styles. For state-based
styles, prefer Ark data attributes such as `data-state`, `data-current`, and `data-orientation`,
together with moduix `data-slot` selectors. Tailwind variants use native utilities and consumer
classes; the variables below customize the CSS Modules variants. Data attributes and `data-slot`
hooks are shared by both styling tracks.

### Styling hooks

Target the part that owns the visual concern:

- `NavigationMenu` for root width, text color, and layout position.
- `NavigationMenuList` for top-level spacing and orientation.
- `NavigationMenuTrigger` and `NavigationMenuLink` for navigation controls, current state, and focus.
- `NavigationMenuContent` for disclosure panel surfaces and their links.
- `NavigationMenuIndicator` and `NavigationMenuItemIndicator` for optional active-state decoration; use `NavigationMenuArrow` with a shared `NavigationMenuViewport`.
- `NavigationMenuViewportPositioner` and `NavigationMenuViewport` for a shared animated panel surface.

The main public hooks are `data-slot="navigation-menu-root"`,
`data-slot="navigation-menu-root-provider"`, `data-slot="navigation-menu-list"`,
`data-slot="navigation-menu-item"`, `data-slot="navigation-menu-trigger"`,
`data-slot="navigation-menu-content"`, `data-slot="navigation-menu-link"`,
`data-slot="navigation-menu-indicator"`, `data-slot="navigation-menu-item-indicator"`,
`data-slot="navigation-menu-arrow"`, `data-slot="navigation-menu-viewport-positioner"`, and
`data-slot="navigation-menu-viewport"`.

Useful Ark hooks include `data-scope="navigation-menu"`, `data-part`, `data-state`, `data-current`,
`data-disabled`, `data-orientation`, and `data-motion`. At runtime, Ark writes `--trigger-x`,
`--trigger-y`, `--trigger-width`, `--trigger-height`, `--viewport-x`, `--viewport-y`,
`--viewport-width`, and `--viewport-height`.
