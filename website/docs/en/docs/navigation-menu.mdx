## API Reference

Ark UI does not currently publish dedicated documentation for Navigation Menu. This component follows
the [Ark React source](https://github.com/chakra-ui/ark/tree/main/packages/react/src/components/navigation-menu)
and preserves its parts and state model.

## Choosing the right component

Use `NavigationMenu` for primary product or site navigation with a small number of related links and
disclosure panels.

- Choose **`NavigationMenu`** when a top-level item can reveal a compact panel of related links.
- Choose **`Menu`** for contextual actions rather than destinations.
- Choose **`Tabs`** when each selected control shows its matching content panel on the current page.

## Anatomy

```text
NavigationMenu
├─ NavigationMenu.List
│  ├─ NavigationMenu.Item[value]
│  │  └─ NavigationMenu.Link
│  └─ NavigationMenu.Item[value]
│     ├─ NavigationMenu.Trigger
│     └─ NavigationMenu.Content
│        ├─ NavigationMenu.Indicator > NavigationMenu.Arrow (optional without viewport)
│        └─ NavigationMenu.Link
└─ NavigationMenu.ViewportPositioner (optional)
   ├─ NavigationMenu.Indicator > NavigationMenu.Arrow (optional with viewport)
   └─ NavigationMenu.Viewport

NavigationMenu.RootProvider
└─ same part tree connected to a useNavigationMenu() store

NavigationMenu.Context
└─ advanced render-prop access to the current navigation state
```

| Part                                | Role                                                               |
| ----------------------------------- | ------------------------------------------------------------------ |
| `NavigationMenu`                    | Root `nav`; controls the open value, delays, focus, and direction. |
| `NavigationMenu.RootProvider`       | Connects parts to state created with `useNavigationMenu()`.        |
| `NavigationMenu.Context`            | Advanced render-prop access to the current navigation state.      |
| `NavigationMenu.List`               | Groups top-level navigation items.                                |
| `NavigationMenu.Item`               | Associates a required `value` with its trigger, link, and content. |
| `NavigationMenu.Trigger`            | Button that opens its item's navigation panel.                    |
| `NavigationMenu.Content`            | Disclosure panel for an item; can move into a viewport.           |
| `NavigationMenu.Link`               | Navigation anchor, including direct top-level destinations.       |
| `NavigationMenu.Indicator` / `Arrow` | Optional pointer inside standalone content or the viewport list. |
| `NavigationMenu.ItemIndicator`      | Optional visual indicator for the current item.                   |
| `NavigationMenu.ViewportPositioner` | Positions an optional shared viewport.                            |
| `NavigationMenu.Viewport`           | Animated shared surface for open content.                         |

## Composition

### Recommended composition

Keep the Ark parts explicit in your markup. Give every `NavigationMenu.Item` a stable `value`; its
`Trigger` and `Content` use that value automatically. Use `NavigationMenu.Link` for both direct
destinations and links inside a disclosure panel.

The root accepts Ark's `value`, `defaultValue`, `onValueChange(details)`, `openDelay`, `closeDelay`,
`orientation`, `disableClickTrigger`, `disableHoverTrigger`, `disablePointerLeaveClose`, `ids`,
`lazyMount`, and `unmountOnExit` props.

### When to go custom

Use `asChild` on `NavigationMenu.Trigger` or `NavigationMenu.Link` when a router link or custom
semantic host must receive Ark's behavior. The child must remain one interactive, focusable element.

Add `NavigationMenu.ViewportPositioner` and `NavigationMenu.Viewport` when several panels should share
one animated surface. When a pointer to the active trigger is useful, place one `Indicator` with an
`Arrow` before the `Viewport` inside `ViewportPositioner`. The viewport then animates its measured width
and height as content moves in the navigation direction. Without it, `Content` remains next to its item
as a compact disclosure panel and can include an optional indicator.

Use `useNavigationMenu()` with `NavigationMenu.RootProvider` when navigation state must exist outside
the rendered tree. Use `NavigationMenu.Context` or `useNavigationMenuContext()` when surrounding UI
needs to read that state.

### Behavioral notes

- `onValueChange` receives Ark's detail object; read the open item from `details.value`.
- `NavigationMenu` renders a semantic `nav`; Ark manages disclosure ARIA attributes, hover and click
  behavior, and keyboard interaction.
- `Content` and `Viewport` preserve Ark presence attributes, so `lazyMount` and `unmountOnExit` work
  unchanged with the default exit animation.
- The wrapper does not add a trigger icon or a viewport. Render both only when the composition needs them.
- Arrows are opt-in and are not part of the recommended basic composition.

### Styling hooks

- `NavigationMenu` controls root width, text color, and layout positioning.
- `NavigationMenu.List` controls top-level spacing and orientation.
- `NavigationMenu.Trigger` and `NavigationMenu.Link` control navigation controls, current state, and focus.
- `NavigationMenu.Content` controls disclosure panel surfaces and links.
- `NavigationMenu.Indicator`, `ItemIndicator`, and `Arrow` control optional active-state decoration.
- `NavigationMenu.ViewportPositioner` and `Viewport` control a shared animated panel surface.

The main public hooks include `data-slot="navigation-menu-root"`,
`data-slot="navigation-menu-root-provider"`, `data-slot="navigation-menu-list"`,
`data-slot="navigation-menu-item"`, `data-slot="navigation-menu-trigger"`,
`data-slot="navigation-menu-content"`, `data-slot="navigation-menu-link"`,
`data-slot="navigation-menu-indicator"`, `data-slot="navigation-menu-item-indicator"`,
`data-slot="navigation-menu-arrow"`, `data-slot="navigation-menu-viewport-positioner"`, and
`data-slot="navigation-menu-viewport"`.

Useful Ark hooks include `data-scope="navigation-menu"`, `data-part`, `data-state`, `data-current`,
`data-disabled`, `data-orientation`, and `data-motion`. Ark writes `--trigger-x`, `--trigger-y`,
`--trigger-width`, `--trigger-height`, `--viewport-x`, `--viewport-y`, `--viewport-width`, and
`--viewport-height` at runtime.
