## Usage

<Usage />

Use `NavigationMenu` with `NavigationMenuList` and `NavigationMenuItem`. Give every item a unique
`value`. For a group of links, place `NavigationMenuTrigger` and `NavigationMenuContent` inside
the same item. Use `NavigationMenuLink` for direct top-level destinations and for links inside a
panel.

## Choosing the right component

Use `NavigationMenu` for primary site or product navigation when some top-level items open groups of
related destinations.

- Choose **`NavigationMenu`** when a top-level item can reveal a group of related links.
- Choose **`Menu`** for contextual actions rather than navigation.
- Choose **`Tabs`** when each selected control switches the content shown in one area of the current page.

## Composition

Use `defaultValue` for an uncontrolled menu. When another part of the application controls the open
item, pass `value` with `onValueChange(details)`, use Vue's `v-model:value`, or use Svelte's `bind:value`; `details.value` is the
open item's value or an empty string when all panels are closed. Create the store with
`useNavigationMenu()` and pass it to `NavigationMenuRootProvider` when it must live outside the
rendered tree; do not render another root for that store. React reads the store as an object; Solid
reads its reactive state through the returned accessor; Vue exposes the reactive store through refs
and template bindings; Svelte returns a getter, so read the state with `navigationMenu().value`. Use `NavigationMenuContext` when a descendant needs the current state through
a render prop instead of a store.

Without a shared viewport, `NavigationMenuContent` renders beside its item. Add
`NavigationMenuViewportPositioner` and `NavigationMenuViewport` when several panels should share one
animated surface; the positioner's `align` prop (`"start" | "center" | "end"`, default `"center"`)
aligns the viewport against the value positioner. Use `asChild` for router links or custom
triggers only when the child remains one interactive, focusable element.

## Styling

Use `className` in React or `class` in Solid, Vue, and Svelte on exported parts for structural styles. For state-based
styles, prefer Ark data attributes such as `data-state`, `data-current`, and `data-orientation`,
together with moduix `data-slot` selectors. Tailwind variants use native utilities and consumer
classes. CSS Modules variants take colors, spacing, and typography from foundation tokens and expose
only the panel and viewport size limits as CSS variables; override other styles with a class on the
part. Panel and viewport motion follow the shared `--moduix-popup-motion-*` variables. Data
attributes and `data-slot` hooks are shared by both styling tracks.

| Part | `data-slot` |
| --- | --- |

| `NavigationMenuArrow` | `navigation-menu-arrow` |
| `NavigationMenuViewportPositioner` | `navigation-menu-viewport-positioner` |
| `NavigationMenuViewport` | `navigation-menu-viewport` |

Target the part that renders the element you want to style:

- `NavigationMenu` for root width, text color, and layout position.
- `NavigationMenuList` for top-level spacing and orientation.
- `NavigationMenuTrigger` and `NavigationMenuLink` for navigation controls, current state, and focus.
- `NavigationMenuContent` for disclosure panel surfaces and their links.
- `NavigationMenuIndicator` and `NavigationMenuItemIndicator` for optional active-state decoration; use `NavigationMenuArrow` with a shared `NavigationMenuViewport`.
- `NavigationMenuViewportPositioner` and `NavigationMenuViewport` for a shared animated panel surface.

Useful Ark hooks include `data-scope="navigation-menu"`, `data-part`, `data-state`, `data-current`,
`data-disabled`, `data-orientation`, and `data-motion`. At runtime, Ark writes `--trigger-x`,
`--trigger-y`, `--trigger-width`, `--trigger-height`, `--viewport-x`, `--viewport-y`,
`--viewport-width`, and `--viewport-height`.

## Keyboard

| Key | Action |
| --- | --- |
| `Tab` / `Shift+Tab` | Moves between top-level triggers and links. |
| `Enter` / `Space` | Opens or closes the panel of the focused trigger. |
| `ArrowLeft` / `ArrowRight` | Moves to the previous or next trigger, or between links in an open panel; ArrowUp and ArrowDown when vertical. |
| `Home` / `End` | Moves to the first or last trigger or link. |
| `Esc` | Closes the open panel and returns focus to its trigger. |

## API reference

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `value` | `string` | — | Open item for controlled use. |
| `defaultValue` | `string` | — | Initially open item. |
| `onValueChange` | `(details: ValueChangeDetails) => void` | — | Called when another item opens or the menu closes. |
| `openDelay` | `number` | `200` | Hover delay before opening, in milliseconds. |
| `closeDelay` | `number` | `300` | Delay before closing after the pointer leaves, in milliseconds. |
| `disableClickTrigger` | `boolean` | `false` | Turns off opening by click. |
| `disableHoverTrigger` | `boolean` | `false` | Turns off opening on hover. |
| `disablePointerLeaveClose` | `boolean` | `false` | Keeps the menu open when the pointer leaves. |
| `translations` | `IntlTranslations` | — | Localized strings for accessibility labels. |
| `orientation` | `'horizontal' \| 'vertical'` | `'horizontal'` | Layout and arrow-key direction: `horizontal` or `vertical`. |
