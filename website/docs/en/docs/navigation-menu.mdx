## Choosing the right component

Use `NavigationMenu` for primary site or product navigation when some top-level items open groups of
related destinations.

- Choose **`NavigationMenu`** when a top-level item can reveal a group of related links.
- Choose **`Menu`** for contextual actions rather than navigation.
- Choose **`Tabs`** when each selected control switches the content shown in one area of the current page.

## Anatomy

```text
NavigationMenu / NavigationMenu.Root
├─ NavigationMenu.List
│  ├─ NavigationMenu.Item[value]
│  │  └─ NavigationMenu.Link
│  └─ NavigationMenu.Item[value]
│     ├─ NavigationMenu.Trigger
│     ├─ NavigationMenu.ItemIndicator (optional)
│     └─ NavigationMenu.Content
│        └─ NavigationMenu.Link
│  └─ NavigationMenu.Indicator > NavigationMenu.Arrow (optional)
└─ NavigationMenu.ViewportPositioner (optional)
   └─ NavigationMenu.Viewport

NavigationMenu.RootProvider
└─ same part tree connected to a useNavigationMenu() store

NavigationMenu.Context
└─ advanced render-prop access to the current navigation state
```

| Part | Role |
| --- | --- |
| `NavigationMenu` / `NavigationMenu.Root` | Root `nav` element that owns the open value, delays, focus behavior, and orientation. |
| `NavigationMenu.RootProvider` | Connects the parts to a store created with `useNavigationMenu()`. |
| `NavigationMenu.Context` | Exposes the current navigation state through a render prop. |
| `NavigationMenu.List` | Groups top-level navigation items. |
| `NavigationMenu.Item` | Requires a unique `value` and connects an item's trigger, content, and links. |
| `NavigationMenu.Trigger` | Button that opens or closes the item's disclosure panel. |
| `NavigationMenu.Content` | Disclosure panel for an item. It can render beside the item or inside a shared `Viewport`. |
| `NavigationMenu.Link` | Anchor for a direct destination or a link inside a disclosure panel. |
| `NavigationMenu.ItemIndicator` | Optional visual marker for the current item. |
| `NavigationMenu.Indicator` | Optional marker for the active trigger; render it inside `List`. Use `Arrow` with a shared `Viewport`. |
| `NavigationMenu.ViewportPositioner` | Positions a shared `Viewport`. |
| `NavigationMenu.Viewport` | Shared animated surface for the currently open content. |

## Composition

Use `defaultValue` for an uncontrolled menu. When another part of the application owns the open
item, pass `value` and `onValueChange(details)`; `details.value` is the open item's value or an
empty string when all panels are closed. Use `NavigationMenu.RootProvider` with
`useNavigationMenu()` when the store must be created outside the rendered tree. Pass the returned
store to `RootProvider` and do not render another root for that store. React reads the store as an
object; Solid reads its reactive state through the returned accessor.

Add `ViewportPositioner` and `Viewport` when several panels should share one animated surface. The
positioner accepts Ark's `align` prop (`"start" | "center" | "end"`, default `"center"`) to align the
viewport against the value positioner. Keep
`Indicator` inside `List`, and add `Arrow` there only with a shared viewport. Without a shared
viewport, `Content` renders beside its item. Use `asChild` for router links or custom triggers only
when the child remains one interactive, focusable element.

## Styling

Use `className` in React or `class` in Solid on exported parts for structural styles. For state-based
styles, prefer Ark data attributes such as `data-state`, `data-current`, and `data-orientation`,
together with moduix `data-slot` selectors. Tailwind variants use native utilities and consumer
classes; the variables below customize the CSS Modules variants. Data attributes and `data-slot`
hooks are shared by both styling tracks.

### Styling hooks

Target the part that owns the visual concern:

- `NavigationMenu` for root width, text color, and layout position.
- `NavigationMenu.List` for top-level spacing and orientation.
- `NavigationMenu.Trigger` and `NavigationMenu.Link` for navigation controls, current state, and focus.
- `NavigationMenu.Content` for disclosure panel surfaces and their links.
- `NavigationMenu.Indicator` and `ItemIndicator` for optional active-state decoration; use `Arrow` with a shared `Viewport`.
- `NavigationMenu.ViewportPositioner` and `Viewport` for a shared animated panel surface.

The main public hooks are `data-slot="navigation-menu-root"`,
`data-slot="navigation-menu-root-provider"`, `data-slot="navigation-menu-list"`,
`data-slot="navigation-menu-item"`, `data-slot="navigation-menu-trigger"`,
`data-slot="navigation-menu-content"`, `data-slot="navigation-menu-link"`,
`data-slot="navigation-menu-indicator"`, `data-slot="navigation-menu-item-indicator"`,
`data-slot="navigation-menu-arrow"`, `data-slot="navigation-menu-viewport-positioner"`, and
`data-slot="navigation-menu-viewport"`.

Useful Ark hooks include `data-scope="navigation-menu"`, `data-part`, `data-state`, `data-current`,
`data-disabled`, `data-orientation`, and `data-motion`. At runtime, Ark writes `--trigger-x`,
`--trigger-y`, `--trigger-width`, `--trigger-height`, `--viewport-x`, `--viewport-y`,
`--viewport-width`, and `--viewport-height`.
