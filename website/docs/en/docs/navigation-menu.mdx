## API Reference

Ark UI does not currently publish dedicated Navigation Menu documentation. This component follows
the [Ark React source](https://github.com/chakra-ui/ark/tree/main/packages/react/src/components/navigation-menu)
and preserves its parts and state model.

## Choosing the right component

Use `NavigationMenu` for primary product or site navigation when a small set of related links includes
disclosure panels.

- Choose **`NavigationMenu`** when a top-level item can open a compact panel of related links.
- Choose **`Menu`** for contextual actions rather than destinations.
- Choose **`Tabs`** when each selected control shows its associated content panel on the current page.

## Anatomy

```text
NavigationMenu
├─ NavigationMenu.List
│  ├─ NavigationMenu.Item[value]
│  │  └─ NavigationMenu.Link
│  └─ NavigationMenu.Item[value]
│     ├─ NavigationMenu.Trigger
│     └─ NavigationMenu.Content
│        ├─ NavigationMenu.Indicator > NavigationMenu.Arrow (optional without viewport)
│        └─ NavigationMenu.Link
└─ NavigationMenu.ViewportPositioner (optional)
   ├─ NavigationMenu.Indicator > NavigationMenu.Arrow (optional with viewport)
   └─ NavigationMenu.Viewport

NavigationMenu.RootProvider
└─ same part tree connected to a useNavigationMenu() store

NavigationMenu.Context
└─ advanced render-prop access to the current navigation state
```

| Part                                | Role                                                               |
| ----------------------------------- | ------------------------------------------------------------------ |
| `NavigationMenu`                    | Root `nav` that controls the open value, delays, focus, and direction. |
| `NavigationMenu.RootProvider`       | Connects the parts to a store created with `useNavigationMenu()`. |
| `NavigationMenu.Context`            | Advanced render-prop access to the current navigation state.     |
| `NavigationMenu.List`               | Groups top-level navigation items.                                |
| `NavigationMenu.Item`               | Requires a `value` and connects it to the item's trigger, link, and content. |
| `NavigationMenu.Trigger`            | Button that opens the item's panel.                               |
| `NavigationMenu.Content`            | Disclosure panel for an item; can render in a shared viewport.    |
| `NavigationMenu.Link`               | Navigation link, including direct top-level destinations.         |
| `NavigationMenu.Indicator` / `Arrow` | Optional visual pointer in standalone content or a shared viewport. |
| `NavigationMenu.ItemIndicator`      | Optional visual indicator for the current item.                   |
| `NavigationMenu.ViewportPositioner` | Positions an optional shared viewport.                            |
| `NavigationMenu.Viewport`           | Shared animated surface for open content.                         |

## Composition

### Recommended composition

Keep the Ark parts explicit in your markup. Give every `NavigationMenu.Item` a stable `value`; its
`Trigger` and `Content` use that value automatically. Use `NavigationMenu.Link` for direct destinations
and for links inside a disclosure panel.

The root accepts Ark's `value`, `defaultValue`, `onValueChange(details)`, `openDelay`, `closeDelay`,
`orientation`, `disableClickTrigger`, `disableHoverTrigger`, `disablePointerLeaveClose`, `ids`,
`lazyMount`, and `unmountOnExit` props.

### When to go custom

Use `asChild` on `NavigationMenu.Trigger` or `NavigationMenu.Link` when a router link or another
semantic host should receive Ark's behavior. The child must remain a single interactive, focusable element.

Add `NavigationMenu.ViewportPositioner` and `NavigationMenu.Viewport` when several panels should open
inside one animated surface. If the active trigger needs a visual pointer, put one `Indicator` with an
`Arrow` before the `Viewport` inside `ViewportPositioner`. The shared viewport measures each panel and
animates its width and height as you move between triggers. Without a shared viewport, `Content` stays
beside its `Item` as a compact disclosure panel and may include its own `Indicator`.

Use `useNavigationMenu()` with `NavigationMenu.RootProvider` when navigation state needs to live outside
the rendered component tree. Use `NavigationMenu.Context` or `useNavigationMenuContext()` when surrounding
UI needs to read that state.

### Behavioral notes

- `onValueChange` receives Ark's detail object; `details.value` identifies the currently open item.
- `NavigationMenu` renders a semantic `nav`. Ark manages disclosure ARIA attributes, hover and click
  behavior, and keyboard interaction.
- `Content` and `Viewport` preserve Ark presence attributes, so `lazyMount` and `unmountOnExit` work
  with the default exit animation.
- The wrapper does not add a trigger icon or a viewport. Add them only when your composition needs them.
- Arrows are opt-in and are not part of the recommended basic composition.

### Styling hooks

- `NavigationMenu` styles the root width, text color, and layout position.
- `NavigationMenu.List` styles top-level spacing and orientation.
- Use `NavigationMenu.Trigger` and `NavigationMenu.Link` to style navigation controls, current state, and focus.
- `NavigationMenu.Content` styles disclosure panel surfaces and their links.
- `NavigationMenu.Indicator`, `ItemIndicator`, and `Arrow` style optional active-state decoration.
- `NavigationMenu.ViewportPositioner` and `Viewport` style a shared animated panel surface.

The main public hooks are `data-slot="navigation-menu-root"`,
`data-slot="navigation-menu-root-provider"`, `data-slot="navigation-menu-list"`,
`data-slot="navigation-menu-item"`, `data-slot="navigation-menu-trigger"`,
`data-slot="navigation-menu-content"`, `data-slot="navigation-menu-link"`,
`data-slot="navigation-menu-indicator"`, `data-slot="navigation-menu-item-indicator"`,
`data-slot="navigation-menu-arrow"`, `data-slot="navigation-menu-viewport-positioner"`, and
`data-slot="navigation-menu-viewport"`.

Useful Ark hooks include `data-scope="navigation-menu"`, `data-part`, `data-state`, `data-current`,
`data-disabled`, `data-orientation`, and `data-motion`. At runtime, Ark writes `--trigger-x`,
`--trigger-y`, `--trigger-width`, `--trigger-height`, `--viewport-x`, `--viewport-y`,
`--viewport-width`, and `--viewport-height`.
