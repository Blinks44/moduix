## Choosing the right component

Use `NavigationMenu` for primary site or product navigation when some top-level items open groups of
related destinations.

- Choose **`NavigationMenu`** when a top-level item can reveal a group of related links.
- Choose **`Menu`** for contextual actions rather than navigation.
- Choose **`Tabs`** when each selected control switches the content shown in one area of the current page.

## Basic

Use `NavigationMenu` with `NavigationMenu.List` and `NavigationMenu.Item`. Give every item a unique
`value`. For a group of links, place `NavigationMenu.Trigger` and `NavigationMenu.Content` inside
the same item. Use `NavigationMenu.Link` for direct top-level destinations and for links inside a panel.

## Anatomy

```text
NavigationMenu (NavigationMenu.Root)
├─ NavigationMenu.List
│  ├─ NavigationMenu.Item[value]
│  │  └─ NavigationMenu.Link
│  └─ NavigationMenu.Item[value]
│     ├─ NavigationMenu.Trigger
│     ├─ NavigationMenu.ItemIndicator (optional)
│     └─ NavigationMenu.Content
│        ├─ NavigationMenu.Indicator > NavigationMenu.Arrow (optional without a shared Viewport)
│        └─ NavigationMenu.Link
└─ NavigationMenu.ViewportPositioner (optional)
   ├─ NavigationMenu.Indicator > NavigationMenu.Arrow (optional with a shared Viewport)
   └─ NavigationMenu.Viewport

NavigationMenu.RootProvider
└─ same part tree connected to a useNavigationMenu() store

NavigationMenu.Context
└─ advanced render-prop access to the current navigation state
```

| Part | Role |
| --- | --- |
| `NavigationMenu` | The root `nav` element that owns the open value, delays, focus behavior, and orientation. |
| `NavigationMenu.RootProvider` | Connects the parts to a store created with `useNavigationMenu()`. |
| `NavigationMenu.Context` | Exposes the current navigation state through a render prop. |
| `NavigationMenu.List` | Groups top-level navigation items. |
| `NavigationMenu.Item` | Requires a unique `value` and connects an item's trigger, content, and links. |
| `NavigationMenu.Trigger` | Button that opens or closes the item's disclosure panel. |
| `NavigationMenu.Content` | Disclosure panel for an item. It can render beside the item or inside a shared `Viewport`. |
| `NavigationMenu.Link` | Anchor for a direct destination or a link inside a disclosure panel. |
| `NavigationMenu.ItemIndicator` | Optional visual marker for the current item. |
| `NavigationMenu.Indicator` / `NavigationMenu.Arrow` | Optional pointer for an active item in standalone content or a shared `Viewport`. |
| `NavigationMenu.ViewportPositioner` | Positions a shared `Viewport` and its optional indicator. |
| `NavigationMenu.Viewport` | Shared animated surface for the currently open content. |

## Composition

### Recommended composition

Keep the Ark parts explicit in your markup. Give every `NavigationMenu.Item` a stable, unique `value`.
Its `Trigger` and `Content` are connected through the enclosing item, so they do not need matching
`value` props. Use `NavigationMenu.Link` for direct destinations and for links inside a disclosure panel.

The root accepts Ark props such as `value`, `defaultValue`, `onValueChange(details)`, `openDelay`,
`closeDelay`, `orientation`, `disableClickTrigger`, `disableHoverTrigger`,
`disablePointerLeaveClose`, `ids`, `translations`, `lazyMount`, `unmountOnExit`, and `hideMode`.

### When to go custom

Use `asChild` on `NavigationMenu.Trigger` or `NavigationMenu.Link` when a router link or another
semantic host should receive Ark's behavior. The child must remain a single interactive, focusable
element so that Ark can preserve its keyboard, focus, and ARIA behavior.

Add `NavigationMenu.ViewportPositioner` and `NavigationMenu.Viewport` when several panels should open
inside one animated surface. Put an `Indicator` with an `Arrow` before the `Viewport` inside
`ViewportPositioner` when the active panel should point back to its trigger. The shared viewport measures
each panel and animates its width and height as you move between triggers. Without a shared viewport,
`Content` renders beside its item as a compact disclosure panel and can contain its own `Indicator`.

Use `useNavigationMenu()` with `NavigationMenu.RootProvider` when the navigation state must be created
outside the rendered component tree. Use `NavigationMenu.Context` or `useNavigationMenuContext()` when
the surrounding UI needs to read that state. Pass the hook result to the required `value` prop of
`NavigationMenu.RootProvider`.

### Default props

| Prop | Default | Notes |
| --- | --- | --- |
| `NavigationMenu.openDelay` | `200` | Delay before a panel opens on hover. |
| `NavigationMenu.closeDelay` | `300` | Delay before the open panel closes. |
| `NavigationMenu.orientation` | `horizontal` | Sets the direction used by layout and keyboard navigation. |
| `NavigationMenu.lazyMount` | `false` | Mounts content only after it is first opened. |
| `NavigationMenu.unmountOnExit` | `false` | Removes inactive content from the DOM after it closes. |
| `NavigationMenu.hideMode` | `display-none` | Hides mounted content with the `hidden` attribute. React 19 also supports `activity`. |
| `NavigationMenu.Link.closeOnClick` | `true` | Closes the menu after the link is selected. |
| `NavigationMenu.ViewportPositioner.align` | `center` | Aligns the shared viewport with the trigger. |

### Behavioral notes

- `onValueChange` receives Ark's detail object. `details.value` contains the value of the currently open item, or an empty string when all panels are closed.
- By default, a mouse hover or a click on a trigger opens its panel. Use `disableHoverTrigger`, `disableClickTrigger`, and `disablePointerLeaveClose` to change that behavior.
- `NavigationMenu` renders a semantic `nav`. Ark manages the disclosure ARIA attributes, focus movement, and keyboard interaction between triggers and panels.
- Set `current` on `NavigationMenu.Link` to mark the current destination. The link exposes the corresponding current-state attribute for styling.
- `Content` and `Viewport` preserve Ark's presence attributes, so `lazyMount`, `unmountOnExit`, and the default exit animation work together.
- The wrapper does not add a trigger icon or a shared `Viewport`. Add them only when your composition needs them.
- `Indicator` and `Arrow` are optional and are not part of the recommended basic composition.

### Styling hooks

Target the part that owns the visual concern:

- `NavigationMenu` for root width, text color, and layout position.
- `NavigationMenu.List` for top-level spacing and orientation.
- `NavigationMenu.Trigger` and `NavigationMenu.Link` for navigation controls, current state, and focus.
- `NavigationMenu.Content` for disclosure panel surfaces and their links.
- `NavigationMenu.Indicator`, `ItemIndicator`, and `Arrow` for optional active-state decoration.
- `NavigationMenu.ViewportPositioner` and `Viewport` for a shared animated panel surface.

The main public hooks are `data-slot="navigation-menu-root"`,
`data-slot="navigation-menu-root-provider"`, `data-slot="navigation-menu-list"`,
`data-slot="navigation-menu-item"`, `data-slot="navigation-menu-trigger"`,
`data-slot="navigation-menu-content"`, `data-slot="navigation-menu-link"`,
`data-slot="navigation-menu-indicator"`, `data-slot="navigation-menu-item-indicator"`,
`data-slot="navigation-menu-arrow"`, `data-slot="navigation-menu-viewport-positioner"`, and
`data-slot="navigation-menu-viewport"`.

Useful Ark hooks include `data-scope="navigation-menu"`, `data-part`, `data-state`, `data-current`,
`data-disabled`, `data-orientation`, and `data-motion`. At runtime, Ark writes `--trigger-x`,
`--trigger-y`, `--trigger-width`, `--trigger-height`, `--viewport-x`, `--viewport-y`,
`--viewport-width`, and `--viewport-height`.
