## Basic


Create the data collection with `createTreeCollection`, then pass it to `TreeView`.
`TreeViewNode` gives each recursive render callback the current `node`, `indexPath`, and `state`, so
you can render a branch or a leaf while keeping the part structure explicit.

React, Solid, and Vue use the same flat TreeView names; the examples below keep each framework's native composition.

## Anatomy

```text
TreeView
├─ TreeViewLabel
└─ TreeViewTree
   └─ TreeViewNode or TreeViewNodeProvider
      ├─ TreeViewBranch
      │  ├─ TreeViewBranchControl
      │  │  ├─ TreeViewBranchIndicator
      │  │  └─ TreeViewBranchText
      │  ├─ TreeViewBranchTrigger (optional, dedicated trigger)
      │  └─ TreeViewBranchContent
      │     ├─ TreeViewBranchIndentGuide
      │     └─ nested nodes
      └─ TreeViewItem
         └─ TreeViewItemText
```

| Part                             | Role                                                                  |
| -------------------------------- | --------------------------------------------------------------------- |
| `TreeView`                  | Stores the collection and manages expansion, selection, focus, checking, and renaming. |
| `TreeViewRootProvider`          | Connects tree parts to an instance returned by `useTreeView`.        |
| `TreeViewLabel`                 | Gives the tree an accessible name.                                    |
| `TreeViewTree`                  | Renders the ARIA tree container.                                      |
| `TreeViewNode`                  | A convenience provider that exposes `{ node, indexPath, state }`.    |
| `TreeViewNodeProvider`          | The low-level Ark context boundary for custom composition.           |
| `TreeViewBranch*`               | An expandable node, its control, indicator, text, and child content. |
| `TreeViewItem*`                 | A leaf node and its optional selected-state indicator.               |
| `TreeViewNodeCheckbox*`         | The checkbox control and its checked or indeterminate indicator.     |
| `TreeViewNodeRenameInput`       | The inline input shown while a node is being renamed.                |

## Composition

Use `TreeViewNode` for recursive renderers. It supplies `node`, `indexPath`, and the current node
`state` while you choose the `TreeViewBranch` or `TreeViewItem` parts. If a custom recursive component needs direct
node context, use `TreeViewNodeProvider` directly. When controls outside the tree
own its state, create it with `useTreeView` and pass it to `TreeViewRootProvider`; do not render a
second root for the same store. If a branch has a separate `TreeViewBranchTrigger`, set `role="none"` on
`TreeViewBranchControl`.

In Vue, `TreeViewNode` exposes its render data through a scoped default slot. Control values with
`v-model:expanded-value`, `v-model:selected-value`, `v-model:checked-value`, and
`v-model:focused-value`; events such as `@selection-change` keep Ark's detail objects. Keep a
replaceable collection in a `shallowRef` so Vue preserves its class instance.

## Styling

Use `className` in React, `class` in Solid, or `class` in Vue on any exported part for structural styling. Branch
parts expose `data-state="open|closed"`; checkbox parts expose
`data-state="checked|unchecked|indeterminate"`; and node parts expose `data-focus`, `data-selected`,
`data-disabled`, `data-loading`, `data-renaming`, `data-depth`, `data-path`, and `data-value`. The
wrapper respects Ark's `--depth` indentation and `--height` collapse-measurement variables, and it
disables branch animation when reduced motion is preferred.

Tailwind variants use native utilities and consumer classes. The CSS Modules variants expose the
documented `--moduix-tree-view-*` variables below.
