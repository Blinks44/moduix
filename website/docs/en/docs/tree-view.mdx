## Basic

TreeView ships for React and Solid in both the CSS Modules and Tailwind packages. The rendered
preview on this page uses the React CSS Modules package; the framework tabs show native source for
the same public contract.

Create the data collection with `createTreeCollection`, then pass it to `TreeView`.
`TreeView.Node` gives each recursive render callback the current `node`, `indexPath`, and `state`, so
you can render a branch or a leaf while keeping the part structure explicit.

## Anatomy

```text
TreeView / TreeView.Root
├─ TreeView.Label
└─ TreeView.Tree
   └─ TreeView.Node or TreeView.NodeProvider
      ├─ TreeView.Branch
      │  ├─ TreeView.BranchControl
      │  │  ├─ TreeView.BranchIndicator
      │  │  └─ TreeView.BranchText
      │  └─ TreeView.BranchContent
      │     ├─ TreeView.BranchIndentGuide
      │     └─ nested nodes
      └─ TreeView.Item
         └─ TreeView.ItemText
```

| Part                             | Role                                                                  |
| -------------------------------- | --------------------------------------------------------------------- |
| `TreeView` / `TreeView.Root`     | Stores the collection and manages expansion, selection, focus, checking, and renaming. |
| `TreeView.RootProvider`          | Connects tree parts to an instance returned by `useTreeView`.        |
| `TreeView.Label`                 | Gives the tree an accessible name.                                    |
| `TreeView.Tree`                  | Renders the ARIA tree container.                                      |
| `TreeView.Node`                  | A convenience provider that exposes `{ node, indexPath, state }`.    |
| `TreeView.NodeProvider`          | The low-level Ark context boundary for custom composition.           |
| `TreeView.Branch*`               | An expandable node, its control, indicator, text, and child content. |
| `TreeView.Item*`                 | A leaf node and its optional selected-state indicator.               |
| `TreeView.NodeCheckbox*`         | The checkbox control and its checked or indeterminate indicator.     |
| `TreeView.NodeRenameInput`       | The inline input shown while a node is being renamed.                |

## Composition

Use `TreeView.Node` for recursive renderers. It supplies `node`, `indexPath`, and the current node
`state` while you choose the `Branch` or `Item` parts. If a custom recursive component needs direct
node context, use `TreeView.NodeProvider` instead of wrapping `Node`. When controls outside the tree
own its state, create it with `useTreeView` and pass it to `TreeView.RootProvider`; do not render a
second root for the same store. If a branch has a separate `BranchTrigger`, set `role="none"` on
`BranchControl`.

## Styling

Use `className` in React or `class` in Solid on any exported part for structural styling. Branch
parts expose `data-state="open|closed"`; checkbox parts expose
`data-state="checked|unchecked|indeterminate"`; and node parts expose `data-focus`, `data-selected`,
`data-disabled`, `data-loading`, `data-renaming`, `data-depth`, `data-path`, and `data-value`. The
wrapper respects Ark's `--depth` indentation and `--height` collapse-measurement variables, and it
disables branch animation when reduced motion is preferred.

Tailwind variants use native utilities and consumer classes. The CSS Modules variants expose the
documented `--moduix-tree-view-*` variables below.
