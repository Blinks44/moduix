## API Reference

<PrimitiveReference href="https://ark-ui.com/docs/components/dialog" />

Ark UI does not provide a dedicated `lightbox` primitive. moduix builds this component on top of
`Dialog`, follows Ark's guidance for [composition](https://ark-ui.com/docs/guides/composition),
[styling](https://ark-ui.com/docs/guides/styling), and
[refs](https://ark-ui.com/docs/guides/ref), and uses `Dialog` as the source of truth for behavior.

## Choosing the right component

Use `Lightbox` when you primarily need to view images or other media in a modal window.

- Choose **`Lightbox`** for zoomed-in image previews, product galleries, and other media-focused views.
- Choose **`Dialog`** for general application UI such as forms, actions, or mixed content.
- Compose **`Carousel` inside `LightboxGallery`** when the preview needs slides or navigation arrows.

## Anatomy

```text
Lightbox
├─ LightboxTrigger
├─ LightboxBind
└─ Overlay subtree (automatically portalled)
   ├─ LightboxBackdrop
   └─ LightboxPositioner
      ├─ LightboxCloseTrigger or LightboxCloseIcon
      └─ LightboxContent
         ├─ LightboxHeader (optional)
         │  ├─ LightboxTitle
         │  └─ LightboxDescription
         ├─ LightboxBody
         │  └─ LightboxImage
         └─ LightboxFooter (optional)

LightboxRootProvider
└─ the same part tree connected to useLightbox()
```

| Part                         | Role                                                                           |
| ---------------------------- | ------------------------------------------------------------------------------ |
| `Lightbox`                  | Ark Dialog root that manages open state, focus lifecycle, dismissal, and accessibility. |
| `LightboxRootProvider`      | Provides state created with `useLightbox()`.                                   |
| `LightboxTrigger`           | Ark trigger. Use `asChild` for custom semantic buttons or links.               |
| `LightboxBackdrop`          | Modal backdrop with Ark `data-state` and layer variables.                      |
| `LightboxPositioner`        | Fixed, centered overlay container.                                             |
| `LightboxContent`           | The actual Ark dialog content node.                                            |
| `LightboxTitle`             | Optional accessible title.                                                      |
| `LightboxDescription`       | Optional accessible description.                                               |
| `LightboxCloseTrigger`      | Low-level Ark close trigger.                                                   |
| `LightboxCloseIcon`         | Convenience wrapper that combines `CloseButton` with the Ark close trigger. |
| `LightboxHeader` / `LightboxBody` | Optional layout helpers for text and media regions inside the content.         |
| `LightboxFooter`            | Optional layout helper for actions or status below the media.                  |
| `LightboxImage`             | Styled native image that forwards an `HTMLImageElement` ref.                   |
| `LightboxGallery`           | Layout and styling boundary for a composed `Carousel`.                         |
| `LightboxBind`              | Renderless behavior part that connects external image markup to the root.       |

## Composition

`Lightbox` owns Dialog state, while `LightboxBackdrop`, `LightboxPositioner`, and `LightboxContent` stay explicit. The
overlay parts are portalled by default. Use `portalled={false}` to keep them in place or `portalRef`
to target a custom container. Keep `LightboxCloseIcon` beside `LightboxContent` inside `LightboxPositioner` when it should
stay pinned to the viewport rather than follow content transforms. Use `asChild` with one semantic
element; in Solid, `asChild` is a render function that receives the props for that element.

For galleries, keep the selected image and Carousel page in application state. Pass the image key to
`LightboxTrigger value` and update that state from `onTriggerValueChange(details)` or
`Carousel`'s page callback. Use `LightboxRootProvider` with `useLightbox()` when state or the opener lives
outside the root, and read child state with `useLightboxContext()`. `LightboxBind` is renderless and only
selects an image from external markup, so the surrounding Lightbox still needs its explicit overlay
parts. `LightboxImage closeOnClick` is the shortcut for closing after an image click.

## Examples

### Bind CMS Content

Use `LightboxBind` when preview images come from a CMS or third-party markup that you cannot render
directly with `LightboxTrigger`. Point it at a container with `rootRef` or `rootSelector`, choose a
`selector`, and handle the resolved `{ src, alt, element }` through `onImageSelect`. `LightboxBind` opens its
parent Lightbox but renders no overlay structure, so the backdrop, content, close controls, and image
layout remain yours to compose. It reads the source from `data-lightbox-src`, then `currentSrc`, then
`src`, and preloads it on pointer hover or keyboard focus. Use a semantic button or link for the
matched `selector` so native keyboard activation produces the click that opens the Lightbox. If your
server already returns a structured image array, prefer the `LightboxGallery + Carousel` composition.

### Styling hooks

- moduix slots: `lightbox-trigger`, `lightbox-backdrop`, `lightbox-positioner`,
  `lightbox-content`, `lightbox-title`, `lightbox-description`, `lightbox-close-trigger`,
  `lightbox-close-icon`, `lightbox-header`, `lightbox-body`, `lightbox-footer`, `lightbox-image`,
  and `lightbox-gallery`.
- Ark state and anatomy hooks: `data-scope="dialog"`, `data-part`, `data-state="open|closed"`,
  `data-nested`, `data-has-nested`, `--layer-index`, and `--nested-layer-count`.
- Local hooks: `LightboxImage` exposes `data-slot="lightbox-image"` and optional
  `data-close-on-click`; `LightboxGallery` exposes `data-slot="lightbox-gallery"` and styles
  nested Carousel slots.
- Motion is driven by Ark `data-state`; use `present` only when JavaScript animation control needs
  to keep the content mounted.
- With `prefers-reduced-motion: reduce`, the backdrop and content use a 1ms animation so exit
  lifecycle cleanup remains intact without visible motion.
