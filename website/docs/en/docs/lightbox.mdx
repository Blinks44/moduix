## Usage

<Usage />

Build the explicit Ark UI dialog structure with `Lightbox`, `LightboxTrigger`,
`LightboxBackdrop`, `LightboxPositioner`, and `LightboxContent`. Use `asChild` with a single
semantic trigger element.

## Choosing the right component

Use `Lightbox` when you primarily need to view images or other media in a modal window.

- Choose **`Lightbox`** for zoomed-in image previews, product galleries, and other media-focused views.
- Choose **`Dialog`** for general application UI such as forms, actions, or mixed content.
- Compose **`Carousel` inside `LightboxGallery`** when the preview needs slides or navigation arrows.

## Examples

### Gallery

When a CMS or API returns a structured array of images, keep the selected image and Carousel page in
React, Solid, Vue, or Svelte state, then compose `Carousel` inside `LightboxGallery`. Use `LightboxTrigger.value`
to choose the initial slide and keep the Carousel page in sync as the user navigates.

<Example name="lightbox/gallery" />

### Multiple triggers

Use `LightboxTrigger.value` and `onTriggerValueChange(details)` for gallery thumbnails. The
component does not maintain a hidden image registry.

<Example name="lightbox/multiple-triggers" />

### Click to close image

Use `LightboxImage closeOnClick` when clicking the previewed image should dismiss the overlay. The
close icon remains available and keeps the same Ark close semantics.

<Example name="lightbox/click-to-close-image" />

### Non-modal

Set `modal={false}` for rare previews that should leave the page interactive. Ark disables focus
trapping and scroll prevention in this mode. Omit `LightboxBackdrop` so background actions remain available
while the image is open.

<Example name="lightbox/non-modal" />

### Bind CMS content

Use `LightboxBind` when preview images come from a CMS or third-party markup that you cannot render
directly with `LightboxTrigger`. Point it at a container with `rootRef` or `rootSelector`, choose a
`selector`, and handle the resolved `{ src, alt, element }` through `onImageSelect`. `LightboxBind` opens its
parent Lightbox but renders no overlay structure, so the backdrop, content, close controls, and image
layout remain yours to compose. It reads the source from `data-lightbox-src`, then `currentSrc`, then
`src`, and preloads it on pointer hover or keyboard focus. Use a semantic button or link for the
matched `selector` so native keyboard activation produces the click that opens the Lightbox. If your
server already returns a structured image array, prefer the `LightboxGallery + Carousel` composition.

<Example name="lightbox/bind-cms-content" />

### Custom styling

Pass classes to the backdrop, content, and close button and override their tokens when the media
surface needs its own look.

<Example name="lightbox/custom-styling" />

### Controlled

Use Ark's `onOpenChange(details)` callback when synchronizing lightbox state with React or Solid, or
use `v-model:open` in Vue and `bind:open` in Svelte. See [Control state from the application](/docs/composition-patterns#controlled-state).

<Example name="lightbox/controlled" />

### Focus and IDs

Use Ark's `initialFocusEl`, `finalFocusEl`, and `ids` when a lightbox needs explicit focus targets
or stable element IDs for external accessibility relationships. The return target is highlighted
after close so the focus handoff is visible.

<Example name="lightbox/focus-and-ids" />

### Root provider

Create state with `useLightbox()` when the opener is outside the root. Read the state inside a child
component with `useLightboxContext()`. The external opener is a regular moduix `Button`. See [Share state outside the tree](/docs/composition-patterns#root-provider).

<Example name="lightbox/root-provider-and-context" />

## Composition

Ark UI does not provide a dedicated `lightbox` primitive. moduix builds this component on top of
`Dialog`, follows Ark's guidance for [composition](https://ark-ui.com/docs/guides/composition),
[styling](https://ark-ui.com/docs/guides/styling), and
[refs](https://ark-ui.com/docs/guides/ref), and uses `Dialog` as the source of truth for behavior.

`Lightbox` manages Dialog state, while `LightboxBackdrop`, `LightboxPositioner`, and `LightboxContent` stay explicit. The
overlay parts are portalled by default. Use `portalled={false}` to keep them in place or `portalRef`
to target a custom container. Render `LightboxCloseIcon` inside `LightboxContent`, outside `LightboxBody`,
so it remains accessible and part of the focus trap. Content fades; Body scales and translates while
the close icon stays pinned to the viewport. Without Body, the content only fades. Use `asChild` with one semantic
element; in Solid, `asChild` is a render function that receives the props for that element. In Vue,
use the boolean `as-child` prop and place the semantic element in the slot. In Svelte, pass an
`asChild` snippet that receives a props getter and spread `{...props()}` onto the semantic element.

For galleries, keep the selected image and Carousel page in application state. Pass the image key to
`LightboxTrigger value` and update that state from `onTriggerValueChange(details)` or
`Carousel`'s page callback. Use `LightboxRootProvider` with `useLightbox()` when state or the opener lives
outside the root, and read child state with `useLightboxContext()`. `LightboxBind` is renderless and only
selects an image from external markup, so the surrounding Lightbox still needs its explicit overlay
parts. `LightboxImage closeOnClick` is the shortcut for closing after an image click.

| `LightboxGallery` | `lightbox-gallery` |
| `LightboxHeader` | `lightbox-header` |
| `LightboxBody` | `lightbox-body` |
| `LightboxFooter` | `lightbox-footer` |

- Ark state and anatomy hooks: `data-scope="dialog"`, `data-part`, `data-state="open|closed"`,
  `data-nested`, `data-has-nested`, `--layer-index`, and `--nested-layer-count`.
- Local hooks: `LightboxImage` exposes `data-slot="lightbox-image"` and optional
  `data-close-on-click`; `LightboxGallery` exposes `data-slot="lightbox-gallery"` and styles
  nested Carousel slots.
- Motion is driven by Ark `data-state`; use `present` only when JavaScript animation control needs
  to keep the content mounted.
- With `prefers-reduced-motion: reduce`, the backdrop and content animations are disabled; the
  lightbox still unmounts cleanly after closing.
- Colors, spacing, and typography come from foundation tokens. Change them for one lightbox with a
  class on the part. The backdrop reads the shared `--moduix-backdrop-bg` and
  `--moduix-backdrop-filter`, content motion reads `--moduix-popup-motion-*` on `LightboxContent`,
  and `LightboxCloseIcon` reads the `--moduix-close-button-*` variables.

## Keyboard

| Key | Action |
| --- | --- |
| `Enter` / `Space` | Opens it from the focused trigger. |
| `Tab` / `Shift+Tab` | Moves focus between controls; focus stays inside while open. |
| `Esc` | Closes it and returns focus to the trigger. |

## API reference

`Lightbox` takes the same props as `Dialog`. `LightboxImage` adds `closeOnClick` (`boolean`, default `false`).

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `open` | `boolean` | — | Open state for controlled use. |
| `defaultOpen` | `boolean` | `false` | Initial open state when it is not controlled. |
| `onOpenChange` | `(details: OpenChangeDetails) => void` | — | Called when it opens or closes. |
| `modal` | `boolean` | `true` | Blocks interaction outside and hides the rest of the page from assistive technology. |
| `role` | `'dialog' \| 'alertdialog'` | `'dialog'` | `dialog`, or `alertdialog` for urgent confirmations. |
| `closeOnEscape` | `boolean` | `true` | Closes on Escape. |
| `closeOnInteractOutside` | `boolean` | `true` | Closes on a click outside. |
| `trapFocus` | `boolean` | `true` | Keeps keyboard focus inside while open. |
| `preventScroll` | `boolean` | `true` | Locks page scroll while open. |
| `initialFocusEl` | `() => HTMLElement \| null \| false` | — | Returns the element to focus on open. |
| `finalFocusEl` | `() => HTMLElement \| null` | — | Returns the element to focus on close. |
| `lazyMount` | `boolean` | `true` | Mounts the content on first open. |
| `unmountOnExit` | `boolean` | `true` | Unmounts the content after it closes. |
| `portalled` | `boolean` | `true` | Renders the popup in a portal at the end of `body`. |
