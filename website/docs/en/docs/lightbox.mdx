## API Reference

<PrimitiveReference href="https://ark-ui.com/docs/components/dialog" />

Ark UI does not provide a dedicated `lightbox` primitive. moduix builds this component on top of
`Dialog`, follows Ark's guidance for [composition](https://ark-ui.com/docs/guides/composition),
[styling](https://ark-ui.com/docs/guides/styling), and
[refs](https://ark-ui.com/docs/guides/ref), and uses `Dialog` as the source of truth for behavior.

## Choosing the right component

Use `Lightbox` when the overlay is mainly for viewing images or other media.

- Choose **`Lightbox`** for zoomed-in image previews, product galleries, and media-focused modal previews.
- Choose **`Dialog`** for general application UI such as forms, actions, or mixed content.
- Compose **`Carousel` inside `Lightbox.Gallery`** when the preview needs slides or navigation arrows.

## Anatomy

```text
Lightbox / Lightbox.Root
├─ Lightbox.Trigger
├─ Lightbox.Bind
└─ Overlay subtree (automatically portalled)
   ├─ Lightbox.Backdrop
   └─ Lightbox.Positioner
      ├─ Lightbox.CloseTrigger or Lightbox.CloseIcon
      └─ Lightbox.Content
         ├─ Lightbox.Header (optional)
         │  ├─ Lightbox.Title
         │  └─ Lightbox.Description
         ├─ Lightbox.Body
         │  └─ Lightbox.Image
         └─ Lightbox.Footer (optional)

Lightbox.RootProvider
└─ the same part tree connected to useLightbox()
```

| Part                         | Role                                                                           |
| ---------------------------- | ------------------------------------------------------------------------------ |
| `Lightbox` / `Lightbox.Root` | Ark Dialog root that manages open state, focus lifecycle, dismissal, and accessibility. |
| `Lightbox.RootProvider`      | Provides state created with `useLightbox()`.                                   |
| `Lightbox.Trigger`           | Ark trigger. Use `asChild` for custom semantic buttons or links.               |
| `Lightbox.Backdrop`          | Modal backdrop with Ark `data-state` and layer variables.                      |
| `Lightbox.Positioner`        | Fixed, centered overlay container.                                             |
| `Lightbox.Content`           | The actual Ark dialog content node.                                            |
| `Lightbox.Title`             | Optional accessible title.                                                     |
| `Lightbox.Description`       | Optional accessible description.                                               |
| `Lightbox.CloseTrigger`      | Low-level Ark close trigger.                                                   |
| `Lightbox.CloseIcon`         | Convenience wrapper that combines `CloseButton.Root` with the Ark close trigger. |
| `Lightbox.Header` / `Body`   | Optional layout helpers for text and media regions inside the content.         |
| `Lightbox.Footer`            | Optional layout helper for actions or status below the media.                  |
| `Lightbox.Image`             | Styled native image that forwards an `HTMLImageElement` ref.                   |
| `Lightbox.Gallery`           | Layout and styling boundary for a composed `Carousel`.                         |
| `Lightbox.Bind`              | Renderless behavior part that connects external image markup to the root.       |

## Composition

The root automatically portals `Backdrop` and `Positioner`. Use `portalled={false}` to render
inline, or `portalRef` to target a custom container. The structural parts remain explicit and
styleable.

### Recommended composition

Keep the overlay structure explicit. `Lightbox.Content` is the actual Ark content part. It does not
render a backdrop, positioner, image, gallery, or close button for you.

Use `Lightbox.Image` for a single image. It renders a native `<img>`, accepts native image props,
and forwards its ref to the `HTMLImageElement`. `Lightbox.Header`, `Body`, and `Footer` are optional
layout helpers that keep text, media, and actions visually separated.

Wrap `Carousel` in `Lightbox.Gallery` for a known image collection. It provides the lightbox-specific
viewport, arrow alignment, media sizing, and indicator layout while Carousel continues to manage all
slide behavior.

Render `Lightbox.CloseIcon` as a sibling of `Lightbox.Content` inside `Lightbox.Positioner` when
you want it pinned to the viewport corner. Rendering it inside `Lightbox.Content` makes it inherit
content transforms during entry and exit motion.

### When to go custom

Render custom content directly inside `Lightbox.Content` when it is not a single media frame or a
`Carousel` gallery. Use `Lightbox.Bind` only when the source markup cannot render
`Lightbox.Trigger`. For structured image arrays, use explicit triggers and `Lightbox.Gallery`.

### Default props

By default, portalled overlay content mounts lazily and unmounts after its exit animation. Set
`unmountOnExit={false}` to retain it after the first open. Set both lifecycle props to `false` only
when the content must render eagerly on the initial page load.

| Prop                     | Default    | Notes                                                               |
| ------------------------ | ---------- | ------------------------------------------------------------------- |
| `closeOnEscape`          | `true`     | Inherited from Ark Dialog.                                          |
| `closeOnInteractOutside` | `true`     | Inherited from Ark Dialog.                                          |
| `defaultOpen`            | `false`    | Uncontrolled initial state.                                         |
| `modal`                  | `true`     | Prevents outside interaction and hides content below the lightbox.  |
| `preventScroll`          | `true`     | Locks page scroll while the lightbox is open.                       |
| `role`                   | `"dialog"` | Use `aria-label` or `Lightbox.Title` for an accessible name; `ids` only makes those relationships stable. |
| `trapFocus`              | `true`     | Keeps keyboard focus inside the lightbox while it is open.          |
| `lazyMount`              | `true`     | Defers heavy media until the first open.                             |
| `unmountOnExit`          | `true`     | Removes overlay nodes after the exit animation.                     |

### Behavioral notes

`onOpenChange` and `onTriggerValueChange` use Ark's detail-object callback shape. Read
`details.open` for controlled open state and `details.value` for multiple-trigger galleries.

Use `useLightbox()` with `Lightbox.RootProvider` when controls live outside the rendered root.
Read dialog state in child components with `useLightboxContext()`. Both APIs are available from
`@moduix/react` and on the `Lightbox` namespace.

`Lightbox.Image closeOnClick` is the supported shortcut when clicking the image should dismiss the
overlay. `Lightbox.Bind` is the renderless binding helper for CMS or third-party markup that cannot
be wrapped in `Lightbox.Trigger`. It must be rendered inside `Lightbox` and reports the selected
image through `onImageSelect(details)`. The details contain `src`, optional `alt`, and the source
`HTMLImageElement` as `element`. `selector` is required and must match a semantic button or link so
every preview remains keyboard-accessible.

Other inherited Dialog props pass through unchanged, including `id`, `ids`, `initialFocusEl`,
`finalFocusEl`, `persistentElements`, `restoreFocus`, `present`, `immediate`,
`skipAnimationOnMount`, and outside-interaction callbacks.

## Examples

### Bind CMS Content

Use `Lightbox.Bind` when previewable images come from CMS or third-party markup that you do not
render directly with `Lightbox.Trigger`. Point it at a container with `rootRef` or `rootSelector`,
choose a `selector`, and handle the resolved `{ src, alt, element }` through `onImageSelect`.
`Bind` opens its parent Lightbox but renders no overlay structure, so the backdrop, content, close
controls, and image layout remain fully composable. It reads `data-lightbox-src`, then `currentSrc`,
then `src`, and preloads that source on pointer hover or keyboard focus. Use a semantic button or
link as the matched `selector` so native keyboard activation produces the click that opens the
Lightbox. If your server already returns a structured image array, prefer the
`Lightbox.Gallery + Carousel` composition above.

### Styling hooks

- moduix slots: `lightbox-trigger`, `lightbox-backdrop`, `lightbox-positioner`,
  `lightbox-content`, `lightbox-title`, `lightbox-description`, `lightbox-close-trigger`,
  `lightbox-close-icon`, `lightbox-header`, `lightbox-body`, `lightbox-footer`, `lightbox-image`,
  and `lightbox-gallery`.
- Ark state and anatomy hooks: `data-scope="dialog"`, `data-part`, `data-state="open|closed"`,
  `data-nested`, `data-has-nested`, `--layer-index`, and `--nested-layer-count`.
- Local hooks: `Lightbox.Image` exposes `data-slot="lightbox-image"` and optional
  `data-close-on-click`; `Lightbox.Gallery` exposes `data-slot="lightbox-gallery"` and styles
  nested Carousel slots.
- Motion is driven by Ark `data-state`; use `present` only when JavaScript animation control needs
  to keep the content mounted.
- With `prefers-reduced-motion: reduce`, the backdrop and content use a 1ms animation so exit
  lifecycle cleanup remains intact without visible motion.
