## Choosing the right component

Use `Combobox` when users select from known values and typing helps filter the available options.
Use `Select` when the same predefined choice does not need an editable input.

## Basic

Create an Ark collection with `useListCollection`, pass it to `Combobox`, and keep the popup structure
explicit. Use `Combobox.Option` for ordinary rows; use `Combobox.Item` when a row needs custom structure.
`onInputValueChange` receives an Ark details object.

## Anatomy

```text
Combobox / Combobox.Root[collection]
├─ Combobox.Label
├─ Combobox.Control
│  ├─ Combobox.Input
│  ├─ Combobox.ClearTrigger
│  └─ Combobox.Trigger
└─ Overlay subtree (automatically portalled)
 └─ Combobox.Positioner
    └─ Combobox.Content
       ├─ Combobox.Empty
       ├─ Combobox.Status
       ├─ Combobox.List
       │  ├─ Combobox.Option[item]
       │  └─ Combobox.Item[item]
       │     ├─ Combobox.ItemText
       │     └─ Combobox.ItemIndicator
       └─ Combobox.ItemGroup
          ├─ Combobox.ItemGroupLabel
          └─ Combobox.Item
```

| Part                         | Role                                                               |
| ---------------------------- | ------------------------------------------------------------------ |
| `Combobox` / `Combobox.Root` | Owns combobox state, filtering, highlighting, and selected values. |
| `Combobox.Control`           | Wrapper for input and trigger controls.                            |
| `Combobox.Input`             | Text input that drives search and selection.                       |
| `Combobox.Trigger`           | Opens and closes the popup list.                                   |
| `Combobox.ClearTrigger`      | Clears current value and/or input.                                 |
| `Combobox.Positioner`        | Floating positioner for popup content.                             |
| `Combobox.Content`           | Popup content container.                                           |
| `Combobox.Status`            | Styled consumer-owned loading, error, or guidance message.         |
| `Combobox.List`              | Option list wrapper.                                               |
| `Combobox.Option`            | Convenience row for simple options with text and an indicator.     |
| `Combobox.Item`              | Selectable option row.                                             |
| `Combobox.ItemText`          | Text label slot inside an item.                                    |
| `Combobox.ItemIndicator`     | Selected/highlight indicator slot for an item.                     |
| `Combobox.Context`           | Renderless access to the current combobox state.                   |
| `Combobox.ItemContext`       | Renderless access to the current item state.                       |

`Combobox.RootProvider` renders the same styled root for state created with moduix's `useCombobox`.
Read combobox state inside the tree with `Combobox.Context` or `useComboboxContext`; use
`Combobox.ItemContext` or `useComboboxItemContext` for item state.

## Composition

The root automatically renders `Positioner` through a portal. Set `portalled={false}` to render the popup in the current
tree, or pass `portalRef` to use a specific container. You still compose `Positioner` and `Content`
explicitly, and can style each part independently.

### Recommended composition

Use `createListCollection` for static data. Use `useListCollection` when filtering or other updates
change the collection. Object collections should define `itemToString` and `itemToValue`.

Keep `Combobox.Positioner` and `Combobox.Content` in your JSX. `Content` is the actual Ark content part;
the root only manages where it is rendered.

If you repeat this popup structure, extract a small local helper. Use `Combobox.Option` for simple
rows and keep `Combobox.Item` for links, rich rows, or custom indicator placement:

```tsx
function FruitComboboxPopup({ items }: { items: Array<{ label: string; value: string }> }) {
  return (
    <Combobox.Positioner>
      <Combobox.Content>
        <Combobox.Empty>No fruits found.</Combobox.Empty>
        <Combobox.List>
          {items.map((item) => (
            <Combobox.Option key={item.value} item={item}>
              {item.label}
            </Combobox.Option>
          ))}
        </Combobox.List>
      </Combobox.Content>
    </Combobox.Positioner>
  );
}
```

### When to go custom

Use controlled `value` and Ark detail callbacks when another part of the interface needs the selected
values. If state must be created outside the rendered subtree, create it with moduix's `useCombobox`
and render `Combobox.RootProvider`. Use moduix `Combobox.ItemContext` or `useComboboxItemContext` for
item state; import only collection helpers and types that moduix does not expose from Ark.

Multiple selection does not provide combobox-specific chips. Render tags or another value summary from
controlled state; the combobox still owns selection behavior through `multiple`.

Ark does not expose a combobox status part. moduix `Combobox.Status` is a styled `div` for messages
owned by your application. It does not manage loading or error state and does not add an ARIA role.

### Default props

By default, the portalled content mounts on first open and unmounts after its exit animation. Set
`unmountOnExit={false}` to retain it after the first open. Keep both lifecycle props set to `false`
only when eager initial rendering is needed.

| Surface                            | Default               | Notes                                                                  |
| ---------------------------------- | --------------------- | ---------------------------------------------------------------------- |
| `Combobox.Trigger`                 | moduix chevron icon   | Used when children are omitted.                                        |
| `Combobox.ClearTrigger`            | moduix close icon     | Used when children are omitted.                                        |
| `Combobox.ItemIndicator`           | moduix check icon     | Used when children are omitted.                                        |
| `Combobox.Option.indicator`        | check icon            | Pass `false` to hide it or a React node to replace the icon.           |
| `Combobox` `portalled`             | `true`                | Renders `Positioner` through a portal automatically.                    |
| `Combobox` `portalRef`             | -                     | Optional container for the portal.                                     |
| `Combobox` `lazyMount`             | `true`                | Mounts popup content when it is first opened.                           |
| `Combobox` `unmountOnExit`         | `true`                | Removes popup content after its exit animation.                        |
| `Combobox` width                   | `16rem` (max `100%`)  | Styled root width defaults.                                            |
| `Combobox.Positioner` variables    | Ark runtime variables | Uses `--reference-width`, `--available-height`, `--transform-origin`.  |

### Behavioral notes

- `collection` is required.
- `value` and `defaultValue` are string arrays, including single selection.
- `onValueChange(details)` reads the current values from `details.value`.
- `onInputValueChange(details)` reads input text from `details.inputValue` and its source from
  `details.reason`.
- `onOpenChange`, `onHighlightChange`, and `onSelect` keep their Ark detail shapes.
- All Ark DOM parts support `asChild`. `Combobox.Option` is the exception: it is a convenience
  wrapper for simple rows and does not accept `asChild`.
- `Combobox.Input asChild` keeps Ark input behavior but leaves visual styling to the child element.
- The current Ark Combobox package does not expose a `HiddenInput` part. Use the root `name` and
  `form` props for Ark's built-in form submission behavior.
- `Combobox.RootProvider` preserves moduix root styling and portal configuration for externally
  created Ark state. Use moduix `useCombobox`, `Combobox.Context`, `useComboboxContext`,
  `Combobox.ItemContext`, and `useComboboxItemContext` for provider and context paths.
- Ark `Field.Root` state inheritance remains available through the Ark-backed moduix `Field.Root`;
  `readOnly` and `required` keep their Ark behavior.
- Use `ids` when externally composed parts need shared accessibility IDs. `lazyMount` and
  `unmountOnExit` default to `true`; `present` keeps Ark's presence lifecycle for exit animations.
- `selectionBehavior` and `closeOnSelect` pass through to Ark. In multiple mode, Ark clears the
  input after selection.

### Migrating from shadcn

Keep the Ark-shaped moduix API and map common shadcn conveniences explicitly:

| shadcn pattern          | moduix path                                                          |
| ----------------------- | -------------------------------------------------------------------- |
| `items` on the root     | `createListCollection()` or `useListCollection()`, then `collection` |
| `itemToStringValue`     | `itemToString` and usually `itemToValue` on the collection           |
| `showClear`             | Render `Combobox.ClearTrigger` when needed                           |
| Plain `ComboboxItem`    | Use `Combobox.Option`; use `Combobox.Item` for custom row structure  |
| Built-in chips surface  | Controlled `value` plus custom tags, or `TagsInput` composition      |
| `ComboboxContent` sugar | Explicit `Combobox.Positioner` and `Combobox.Content`                |

### Styling hooks

- Ark parts keep `data-scope="combobox"` and their `data-part` values. moduix adds stable `data-slot`
  hooks to the styled parts.
- Stable slots include `combobox-root`, `combobox-root-provider`, `combobox-label`, `combobox-control`,
  `combobox-input`, `combobox-clear-trigger`, `combobox-trigger`, `combobox-positioner`,
  `combobox-content`, `combobox-empty`, `combobox-status`, `combobox-list`, `combobox-item-group`,
  `combobox-item-group-label`, `combobox-item`, `combobox-item-text`, and `combobox-item-indicator`.
  `Combobox.Option` reuses the item slots instead of adding its own styling hook.
- Ark state hooks include `data-state="open|closed"`, `data-focus`, `data-invalid`,
  `data-disabled`, `data-highlighted`, `data-empty`, `data-placement`, and `data-side`.
- Ark positioning variables include `--reference-width`, `--available-width`,
  `--available-height`, `--transform-origin`, `--z-index`, and `--layer-index`. The shared theme
  registers neutral initial values for tooling and unpositioned content; Ark replaces them with
  measured values on `Positioner`.
