## Choosing the right component

Use `Combobox` when users select from known values and typing helps filter the available options.
Use `Select` when the same predefined choice does not need an editable input.

## Basic


Create an Ark collection with `useListCollection`, pass it to `Combobox`, and keep the popup structure
explicit. Use `ComboboxOption` for ordinary rows; use `ComboboxItem` when a row needs custom structure.
`onInputValueChange` receives an Ark details object.
The Vue examples use native SFC syntax with `script setup`, refs, slots, and `v-model` where the
component contract exposes a Vue model.

## Anatomy

```text
Combobox[collection]
├─ ComboboxLabel
├─ ComboboxControl
│  ├─ ComboboxInput
│  ├─ ComboboxClearTrigger
│  └─ ComboboxTrigger
└─ Overlay subtree (automatically portalled)
 └─ ComboboxPositioner
    └─ ComboboxContent
       ├─ ComboboxEmpty
       ├─ ComboboxStatus
       ├─ ComboboxList
       │  ├─ ComboboxOption[item]
       │  └─ ComboboxItem[item]
       │     ├─ ComboboxItemText
       │     └─ ComboboxItemIndicator
       └─ ComboboxItemGroup
          ├─ ComboboxItemGroupLabel
          └─ ComboboxItem
```

| Part                         | Role                                                               |
| ---------------------------- | ------------------------------------------------------------------ |
| `Combobox` | Owns combobox state, filtering, highlighting, and selected values. |
| `ComboboxControl`           | Wrapper for input and trigger controls.                            |
| `ComboboxInput`             | Text input that drives search and selection.                       |
| `ComboboxTrigger`           | Opens and closes the popup list.                                   |
| `ComboboxClearTrigger`      | Clears current value and/or input.                                 |
| `ComboboxPositioner`        | Floating positioner for popup content.                             |
| `ComboboxContent`           | Popup content container.                                           |
| `ComboboxStatus`            | Styled consumer-owned loading, error, or guidance message.         |
| `ComboboxList`              | Option list wrapper.                                               |
| `ComboboxOption`            | Convenience row for simple options with text and an indicator.     |
| `ComboboxItem`              | Selectable option row.                                             |
| `ComboboxItemText`          | Text label slot inside an item.                                    |
| `ComboboxItemIndicator`     | Selected/highlight indicator slot for an item.                     |
| `ComboboxContext`           | Renderless access to the current combobox state.                   |
| `ComboboxItemContext`       | Renderless access to the current item state.                       |

`ComboboxRootProvider` renders the same styled root for state created with moduix's `useCombobox`.
Read combobox state inside the tree with `ComboboxContext` or `useComboboxContext`; use
`ComboboxItemContext` or `useComboboxItemContext` for item state.

## Composition

Use `createListCollection` for static items and `useListCollection` when filtering or other updates
change the collection. For object items, provide `itemToString` and `itemToValue`.

`Combobox` portals `ComboboxPositioner` automatically, but `ComboboxPositioner` and `ComboboxContent` stay explicit in the
composition. Set `portalled={false}` to keep the popup in the current tree, or pass `portalRef` for
a specific container. Use `ComboboxOption` for simple rows and `ComboboxItem` with `asChild` for
custom rows.

Keep selection in `value` when other UI needs it. When state is created outside the rendered tree,
pass `useCombobox` to `ComboboxRootProvider`. In multiple mode, tags and other value summaries are
application-owned; compose with `TagsInput` when they should share one field. `ComboboxStatus` is
also an application-owned message container and does not manage loading or error state.

## Examples

### Async Search

Replace collection items with async results and render `ComboboxStatus` while a request is pending.
Use `details.reason` to distinguish typed input from machine-driven updates. When the query is empty,
show a `Start typing to search…` status so the popup remains informative.

<Example name="combobox/async-search" />

### Auto Highlight

Set `inputBehavior="autohighlight"` to highlight the first matching item while the user types, so
Enter can select it without an extra arrow-key press.

<Example name="combobox/auto-highlight" />

### Controlled

Control the selected string array and read the next value from `details.value`.

<Example name="combobox/controlled" />

### Creatable

Combine `allowCustomValue` with collection mutation to expose a temporary “Create” item, then
replace that sentinel value with the user-entered value after selection.

<Example name="combobox/creatable" />

### Custom Objects and Grouping

Map object labels and values on the collection, then render Ark item groups from
`collection.group()`. Group labels stick to the top edge of the popup while its results scroll.

<Example name="combobox/custom-objects-and-grouping" />

### Dynamic

Build the collection from the current input when suggestions do not exist until the user starts
typing. Check `details.reason` to avoid rebuilding it after selection-driven input changes.

<Example name="combobox/dynamic" />

### Inline Autocomplete

Set `inputBehavior="autocomplete"` and filter with `startsWith` to complete the input from the
first matching item while preserving Ark keyboard navigation.

<Example name="combobox/inline-autocomplete" />

### Limit Results

Set `limit` on `useListCollection` when the full matching set is unnecessary or would make the
popup harder to scan. Filtering still runs against the complete initial collection.

<Example name="combobox/limit-results" />

### Multiple

Enable `multiple` and render selected objects from controlled `value`. Tags belong to the application;
when they must live inside the same field shell, compose `Combobox` with `TagsInput`.

<Example name="combobox/multiple" />

### Root Provider

Create the state with moduix's `useCombobox` when external controls need imperative methods or shared
state before the root renders. `ComboboxRootProvider` preserves the moduix root styling and portal
configuration.

<Example name="combobox/root-provider" />

### Virtualized

For large collections, render only visible rows with TanStack Virtual. Use
`@tanstack/react-virtual` with React, `@tanstack/solid-virtual` with Solid, and
`@tanstack/vue-virtual` with Vue, then connect Ark keyboard navigation through `scrollToIndexFn`.
Keep `aria-setsize` and `aria-posinset` on virtualized rows.

<Example name="combobox/virtualized" />

### With TagsInput

Use `Combobox` with `TagsInput` when users need filtered suggestions but the selected values should
live inside one editable chip field.

<Example name="combobox/with-tags-input" />

### Advanced Customization

Use the full item composition when a row needs a custom semantic element or layout. This example

## Styling

Use `className` in React or `class` in Solid and Vue on exported parts for structural styles. Tailwind
variants use native utilities and consumer classes; the CSS variables below customize CSS Modules
variants. Data attributes and `data-slot` hooks are shared by both styling tracks.

### Styling hooks

- Ark parts keep `data-scope="combobox"` and their `data-part` values. moduix adds stable `data-slot`
  hooks to the styled parts.
- Stable slots include `combobox-root`, `combobox-root-provider`, `combobox-label`, `combobox-control`,
  `combobox-input`, `combobox-clear-trigger`, `combobox-trigger`, `combobox-positioner`,
  `combobox-content`, `combobox-empty`, `combobox-status`, `combobox-list`, `combobox-item-group`,
  `combobox-item-group-label`, `combobox-item`, `combobox-item-text`, and `combobox-item-indicator`.
  `ComboboxOption` reuses the item slots instead of adding its own styling hook.
- Ark state hooks include `data-state="open|closed"`, `data-focus`, `data-invalid`,
  `data-disabled`, `data-highlighted`, `data-empty`, `data-placement`, and `data-side`.
- Ark positioning variables include `--reference-width`, `--available-width`,
  `--available-height`, `--transform-origin`, `--z-index`, and `--layer-index`. The shared theme
  registers neutral initial values for tooling and unpositioned content; Ark replaces them with
  measured values on `Positioner`.
