## Choosing the right component

Use `Tooltip` for short, non-essential information that appears on hover or focus.

- Choose **`Tooltip`** for brief labels and contextual hints without interaction.
- Choose **`Popover`** when the popup needs richer content, actions, or form controls.
- Choose **`HoverCard`** when the popup should show a supplementary preview tied to its trigger.

## Basic

Use `Tooltip.Trigger` for the element that opens the tooltip and `Tooltip.Body` for its content.
`Tooltip.Body` is a convenience wrapper around `Tooltip.Positioner` and `Tooltip.Content`.
Give the trigger an accessible name of its own. Tooltip content is supplemental and does not replace
visible text or an `aria-label`.

## Anatomy

```text
Tooltip / Tooltip.Root
├─ Tooltip.Trigger
└─ Overlay subtree (automatically rendered in a portal)
   └─ Tooltip.Positioner
      └─ Tooltip.Content
         └─ content
```

Add `Tooltip.Arrow` as the first child of the content when the popup should point to its trigger.
`Tooltip.Arrow` renders `Tooltip.ArrowTip` by default.

```text
Tooltip / Tooltip.Root
├─ Tooltip.Trigger
└─ Overlay subtree (automatically rendered in a portal)
   └─ Tooltip.Positioner
      └─ Tooltip.Content
         ├─ Tooltip.Arrow
         │  └─ Tooltip.ArrowTip
         └─ content
```

| Part | Role |
| --- | --- |
| `Tooltip` / `Tooltip.Root` | Owns tooltip state, opening and closing, delays, positioning, and lifecycle. |
| `Tooltip.RootProvider` | Renders a tooltip from a `useTooltip()` state object created outside the tree. |
| `Tooltip.Context` | Exposes current tooltip state through a render prop for custom descendants. |
| `Tooltip.Body` | Convenience wrapper that renders `Tooltip.Positioner` and `Tooltip.Content` together. |
| `Tooltip.Trigger` | Interactive element that opens the tooltip on hover or focus. |
| `Tooltip.DisabledTrigger` | Focusable wrapper for one disabled native control that still needs an explanation. |
| `Tooltip.Positioner` | Positions the content and exposes Ark positioning variables. |
| `Tooltip.Content` | Visible tooltip surface. |
| `Tooltip.Arrow` | Optional positioned arrow wrapper that renders `Tooltip.ArrowTip` by default. |
| `Tooltip.ArrowTip` | Arrow tip element. |

## Composition

By default, the root renders `Positioner` in a portal. Set `portalled={false}` to keep it in the
current DOM tree, or pass `portalRef` to choose a custom portal container. The structural parts
remain explicit and styleable.

### Recommended composition

For most tooltips, use `Tooltip.Trigger` with `Tooltip.Body`. This keeps the positioning API on the
root while expanding the content into `Tooltip.Positioner` and `Tooltip.Content`. The explicit Ark
parts remain available when you need to control that structure yourself.

When migrating from shadcn, `Tooltip.Body` is the closest moduix equivalent to the usual
`TooltipContent` step.

### When to go custom

Use `asChild` on `Tooltip.Trigger` when the trigger should render as a moduix `Button`, a link, or
another semantic control. The child must remain one focusable element that supports the trigger
interaction.

Use `Tooltip.DisabledTrigger` around exactly one disabled native control that needs a short
explanation. Give the wrapper its own accessible name. The wrapper can receive focus while the
disabled child remains non-interactive, so the explanation is still available to keyboard and
pointer users.

Use `positioning` on `Tooltip` for placement, strategy, offset, collision handling, and other Ark
positioning options. Use explicit `Tooltip.Positioner` and `Tooltip.Content` when you need
positioner-specific styling or lower-level control of the Ark-shaped structure. Use `ids` when
separate tooltip parts need stable shared IDs.

### Default props

The portalled content mounts lazily and is removed after its exit animation by default. Set
`unmountOnExit={false}` to keep it mounted after the first open. Set both lifecycle props to
`false` only when the content must render eagerly.

| Prop | Default | Notes |
| --- | --- | --- |
| `openDelay` | `400` | Delay before opening on hover or focus. |
| `closeDelay` | `150` | Delay before closing after hover or focus leaves. |
| `closeOnClick` | `true` | Closes the tooltip when the trigger is clicked. |
| `closeOnEscape` | `true` | Closes the tooltip when Escape is pressed. |
| `closeOnPointerDown` | `true` | Closes the tooltip on pointer down. |
| `closeOnScroll` | `true` | Closes the tooltip when the user scrolls. |
| `interactive` | `false` | Keeps the tooltip open while its content is hovered. |
| `lazyMount` | `true` | Mounts the content only after the first open. |
| `unmountOnExit` | `true` | Removes the content after its exit animation. |
| `skipAnimationOnMount` | `false` | Keeps the first presence animation enabled. |
| `portalled` | `true` | Renders the positioner in a portal. |
| `portalRef` | `-` | Targets a custom portal container. |
| `positioning` | `-` | Ark positioning options. |
| `ids` | `-` | Stable IDs for tooltip parts. |
| `defaultOpen` | `-` | Initial open state for uncontrolled usage. |
| `open` | `-` | Controlled open state. |
| `disabled` | `false` | Disables tooltip interactions. |

### Behavioral notes

- `onOpenChange(details)` receives an object. Read the next open state from `details.open`.
- `defaultOpen` sets the initial state for uncontrolled usage. `disabled` turns off tooltip
  interaction without changing the trigger's own semantics.
- Ark presence props such as `present`, `immediate`, `onExitComplete`, `lazyMount`, and
  `unmountOnExit` pass through unchanged.
- `Tooltip.RootProvider`, `Tooltip.Context`, `useTooltip`, and `useTooltipContext` are available
  from `@moduix/react` for advanced state access. Use the provider and `useTooltip` when state is
  created outside the rendered tooltip tree.
- `Tooltip.Trigger` receives the moduix trigger styling only when `asChild` is not used. With
  `asChild`, the child element owns its styling.
- `Tooltip.DisabledTrigger` is intended for one disabled direct child. Use it instead of repeating
  a focusable `span`, `tabIndex`, and pointer-events override for every disabled control.
- `Tooltip.Body` forwards its props, children, and ref to `Tooltip.Content`. It does not add a DOM
  part or a separate positioning API.
- `Tooltip.Content` owns the visible surface and z-index. `Tooltip.Positioner` owns floating
  positioning and exposes Ark variables such as `--available-width`, `--available-height`, and
  `--transform-origin`.
- Ark emits `data-state="open" | "closed"` on the trigger and content. With trigger values, it also
  emits `data-value`, `data-current`, and `data-expanded` on the trigger. Content exposes placement
  attributes such as `data-placement` and `data-side`.
- Trigger transitions and content animations are disabled when the user prefers reduced motion.
- Tooltip content wraps long unbroken strings. Use `Popover` or `HoverCard` for long or interactive
  content instead of turning a tooltip into a scrollable surface.

### Styling hooks

Style the part that owns the visual concern:

- `Tooltip.Body` does not create a DOM node. When you use the explicit composition, style
  `Tooltip.Positioner` and `Tooltip.Content` separately.
- `Tooltip.Trigger` controls trigger chrome, hover and open feedback, and focus styling.
- `Tooltip.DisabledTrigger` controls the disabled-control wrapper and its direct disabled child.
- `Tooltip.Positioner` controls floating layout constraints.
- `Tooltip.Content` controls the popup surface.
- `Tooltip.Arrow` and `Tooltip.ArrowTip` control the arrow size, background, and stroke.

The main public hooks are `data-slot="tooltip-trigger"`, `data-slot="tooltip-positioner"`,
`data-slot="tooltip-content"`, `data-slot="tooltip-disabled-trigger"`,
`data-slot="tooltip-arrow"`, and `data-slot="tooltip-arrow-tip"`.

Ark also adds `data-scope="tooltip"`, `data-part`, `data-state="open" | "closed"`, `data-value`,
`data-current`, `data-expanded`, `data-instant`, `data-placement`, and `data-side` to the relevant
parts. The positioner exposes runtime CSS variables including `--available-width`,
`--available-height`, `--reference-width`, `--reference-height`, `--x`, `--y`, `--z-index`, and
`--transform-origin`.
