Use `TooltipTrigger` for the element that opens the tooltip and `TooltipBody` for its content.
`TooltipBody` combines `TooltipPositioner` and `TooltipContent`. Give the trigger an accessible
name of its own. Tooltip content is supplemental and does not replace visible text or an
`aria-label`.

## Choosing the right component

Use `Tooltip` for short, non-essential information that appears on hover or focus.

- Choose **`Tooltip`** for brief labels and contextual hints without interaction.
- Choose **`Popover`** when the popup needs richer content, actions, or form controls.
- Choose **`HoverCard`** when the popup should show a supplementary preview tied to its trigger.

## Composition

Use `TooltipBody` for the standard `Trigger` plus content composition. It combines
`TooltipPositioner` and `TooltipContent`; use those parts explicitly when they need independent
styling or structure. The root owns state, so use `defaultOpen` for an uncontrolled tooltip or
`open` with `onOpenChange(details)` when another part of the application owns it. Use
`TooltipRootProvider` with `useTooltip()` when the store is created outside the rendered tree, and
use `TooltipContext` or `useTooltipContext()` when a descendant needs that state. `asChild` requires
one focusable child; Solid uses a render function. `TooltipDisabledTrigger` is for one disabled
native control. Portalling is enabled by default, so set `portalled={false}` or pass `portalRef`
only when the tooltip must stay within a specific DOM boundary. In Vue, use `v-model:open` for
controlled state and Vue event names such as `@open-change`.

Content mounts on first open and unmounts after its exit animation by default. Set
`unmountOnExit` to `false` to retain it after the first open; set `lazyMount` to `false` as well
for eager rendering. In Vue, bind these options as `:unmount-on-exit="false"` and
`:lazy-mount="false"`.

## Styling

`TooltipTrigger` without `asChild` renders as an outlined button; when several valued triggers share
one tooltip, only the current one shows the open state. `TooltipContent` is at most 20rem wide within
the available viewport space, wraps long unbroken strings, and grows with its text. Content motion
reads the shared `--moduix-popup-motion-*` variables and is skipped when Ark switches the tooltip
instantly between triggers (`data-instant`) or the user prefers reduced motion.

Use `className` in React or `class` in Solid and Vue on exported parts. Tailwind variants use native
utilities and consumer classes. CSS Modules variants build on foundation tokens and have no component
variables: a class on the part overrides the layered component styles. Data attributes and
`data-slot` hooks are shared by both styling tracks.

### Styling hooks

| Part | `data-slot` |
| --- | --- |
| `TooltipTrigger` | `tooltip-trigger` |
| `TooltipDisabledTrigger` | `tooltip-disabled-trigger` |
| `TooltipPositioner` | `tooltip-positioner` |
| `TooltipContent` | `tooltip-content` |
| `TooltipArrow` | `tooltip-arrow` |
| `TooltipArrowTip` | `tooltip-arrow-tip` |

- `TooltipBody` does not create a DOM node. When using the explicit composition, style
  `TooltipPositioner` and `TooltipContent` separately.
- `TooltipTrigger` controls trigger chrome, hover and open feedback, and focus styling.
- `TooltipDisabledTrigger` controls the disabled-control wrapper and its direct disabled child.
- `TooltipPositioner` controls floating layout constraints.
- `TooltipContent` controls the popup surface.
- `TooltipArrow` and `TooltipArrowTip` control the arrow size, background, and stroke.

Ark also adds `data-scope="tooltip"`, `data-part`, `data-state="open" | "closed"`, `data-value`,
`data-current`, `data-expanded`, `data-instant`, `data-placement`, and `data-side` to the relevant
parts. The positioner exposes runtime CSS variables including `--available-width`,
`--available-height`, `--reference-width`, `--reference-height`, `--x`, `--y`, `--z-index`, and
`--transform-origin`.

## Keyboard

| Key | Action |

| `Esc` | Hides the tooltip. |
