# Quick start

moduix supports two equivalent ways to use it in an application:

- Install the moduix package for your runtime and styling track for package-managed updates.
- Install with the shadcn CLI for component source, styles, and utilities inside your repository.

Both workflows use the same framework-native implementations, Ark-aligned contracts, and token
system. Choose based on where you want the source to live and how you plan to update it.

To get started, choose React 18 or 19 with `@ark-ui/react`, or Solid 1.9 with `@ark-ui/solid`. Your
framework or bundler must import CSS from npm packages. Interactive components must render inside a
client boundary when the application framework requires one.

Accessibility is a shared responsibility: Ark UI provides primitive behavior, moduix defines wrapper
contracts and defaults, and your application supplies labels, content, validation messages, and product
flow.

## Choose your framework

Choose a framework-native package and registry namespace. React and Solid CSS Modules packages have
the complete component catalog; the Tailwind packages currently expose only components that have
completed the Tailwind port.

| Runtime | CSS Modules | Tailwind CSS |
| ------- | ----------- | ------------ |
| React   | `@moduix/react` / `@moduix-react` | `@moduix/react-tailwind` / `@moduix-react-tailwind` |
| Solid   | `@moduix/solid` / `@moduix-solid` | `@moduix/solid-tailwind` / `@moduix-solid-tailwind` |

The guides below call out their supported runtimes. Astro, Rsbuild, TanStack Start, and Vite cover
both React and Solid; SolidStart has its own guide, while Next.js and React Router remain React-only.

## Install as a package

Use this path when you want moduix to stay in `node_modules` and receive updates through normal
package management.

### 1. Install the package

The components, CSS, and design tokens are shipped together. Install moduix and the listed
dependencies for your runtime:

<Tabs groupId="framework">
  <Tab label="React" value="react">

<PackageManagerTabs command="install @moduix/react @ark-ui/react" />

  </Tab>
  <Tab label="Solid" value="solid">

<PackageManagerTabs command="install @moduix/solid @ark-ui/solid solid-js" />

  </Tab>
</Tabs>

The framework runtime and matching Ark UI package stay in your application bundle, so moduix does
not ship duplicate framework or primitive runtimes.

### 2. Add styles

Import the required foundation stylesheet once in your application entry point:

<Tabs groupId="framework">
  <Tab label="React" value="react">

```tsx
import '@moduix/react/style.css';
```

  </Tab>
  <Tab label="Solid" value="solid">

```tsx
import '@moduix/solid/style.css';
```

  </Tab>
</Tabs>

This stylesheet is required. It provides the shared design tokens and base layer styles that
component CSS depends on. Component styles are still loaded alongside the components you import.

All moduix design tokens use the `--moduix-*` namespace. Your project can keep its own token names
and selectively map them in a stylesheet that loads after `style.css`; see [Tokens](/docs/tokens).

If you want the optional reset, import it explicitly before the main stylesheet:

<Tabs groupId="framework">
  <Tab label="React" value="react">

```tsx
import '@moduix/react/reset.css';
import '@moduix/react/style.css';
```

  </Tab>
  <Tab label="Solid" value="solid">

```tsx
import '@moduix/solid/reset.css';
import '@moduix/solid/style.css';
```

  </Tab>
</Tabs>

That keeps `style.css` focused on the global foundation, while unused component CSS can stay out of
the consuming bundle.

For a curated visual starting point, import one optional preset after `style.css`; see
[Themes](/docs/themes).

### 3. Use a component

Import each component from its framework package subpath:

<Tabs groupId="framework">
  <Tab label="React" value="react">

```tsx
import { Button } from '@moduix/react/button';
import { Dialog } from '@moduix/react/dialog';

export function Example() {
  return (
    <Dialog>
      <Dialog.Trigger asChild>
        <Button>Open dialog</Button>
      </Dialog.Trigger>
      <Dialog.Backdrop />
      <Dialog.Positioner>
        <Dialog.Content>
          <Dialog.Header>
            <Dialog.Title>Project settings</Dialog.Title>
            <Dialog.Description>Review the settings for this project.</Dialog.Description>
          </Dialog.Header>
          <Dialog.Footer>
            <Dialog.CloseTrigger asChild>
              <Button variant="outline">Close</Button>
            </Dialog.CloseTrigger>
          </Dialog.Footer>
        </Dialog.Content>
      </Dialog.Positioner>
    </Dialog>
  );
}
```

  </Tab>
  <Tab label="Solid" value="solid">

```tsx
import { Button } from '@moduix/solid/button';
import { Dialog } from '@moduix/solid/dialog';

export function Example() {
  return (
    <Dialog>
      <Dialog.Trigger
        asChild={(triggerProps) => <Button {...triggerProps()}>Open dialog</Button>}
      />
      <Dialog.Backdrop />
      <Dialog.Positioner>
        <Dialog.Content>
          <Dialog.Header>
            <Dialog.Title>Project settings</Dialog.Title>
            <Dialog.Description>Review the settings for this project.</Dialog.Description>
          </Dialog.Header>
          <Dialog.Footer>
            <Dialog.CloseTrigger
              asChild={(triggerProps) => (
                <Button {...triggerProps()} variant="outline">
                  Close
                </Button>
              )}
            />
          </Dialog.Footer>
        </Dialog.Content>
      </Dialog.Positioner>
    </Dialog>
  );
}
```

  </Tab>
</Tabs>

The setup is working when the button uses moduix styles, opens the dialog from keyboard and pointer
input, and focus returns to the button after the dialog closes.

### Tailwind package setup

Use the Tailwind package only for components already available in that track. It requires Tailwind
CSS v4 and uses Preflight instead of the optional moduix reset.

<Tabs groupId="framework">
  <Tab label="React" value="react">

<PackageManagerTabs command="install @moduix/react-tailwind @ark-ui/react tailwindcss" />

```css title="styles.css"
@import '@moduix/react-tailwind/style.css';
@import 'tailwindcss';

@source '../node_modules/@moduix/react-tailwind/dist/components';
```

  </Tab>
  <Tab label="Solid" value="solid">

<PackageManagerTabs command="install @moduix/solid-tailwind @ark-ui/solid solid-js tailwindcss" />

```css title="styles.css"
@import '@moduix/solid-tailwind/style.css';
@import 'tailwindcss';

@source '../node_modules/@moduix/solid-tailwind/dist/components';
```

  </Tab>
</Tabs>

Resolve `@source` relative to your stylesheet and keep it limited to the package's
`dist/components` directory.

## Install with the shadcn CLI

Use this method when you want component source and styles in your repository. The shadcn CLI reads
the moduix registry, resolves dependencies, and writes the files to your configured aliases.

### 1. Configure shadcn

Create `components.json` in your project root and choose the configuration for your styling track:

<Tabs groupId="styling">
  <Tab label="CSS Modules" value="css-modules">

<CodeBlockRuntime lang="json" title="components.json" code={componentsCssModules} />

  </Tab>
  <Tab label="Tailwind" value="tailwind">

<CodeBlockRuntime lang="json" title="components.json" code={componentsTailwind} />

  </Tab>
</Tabs>

The Tailwind example assumes that the application's Tailwind CSS v4 entry point is
`src/styles.css`. Keep `tailwind.config` empty for v4 and change `tailwind.css` if your global
stylesheet lives elsewhere. The CSS Modules registries do not require Tailwind; their configuration
uses the empty values required by the shadcn schema.

`rsc` applies to React registry items. Keep it `false` for Solid and ordinary React applications.
Set it to `true` in a React Server Components application; the CLI then adds `use client` to client
components from the registry. Add the directive yourself to React wrappers when they own state,
effects, or event handlers.

Make sure your project resolves the `@/*` alias to its source directory. A typical `src` layout uses:

```json
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "@/*": ["./src/*"]
    }
  }
}
```

This gives the `shadcn` CLI the aliases and registry URL it needs to place generated files in your
source tree instead of a literal `@` directory. Your [framework setup](#choose-your-framework)
shows whether the same alias also belongs in the bundler config and which source root to use.

### 2. Inspect a registry item

Before writing source files, inspect the current configuration and registry item:

<Tabs groupId="framework">
  <Tab label="React" value="react">

```bash
npx shadcn@latest info --json
npx shadcn@latest search @moduix-react --query "dialog"
npx shadcn@latest view @moduix-react/dialog
npx shadcn@latest add @moduix-react/dialog --dry-run
```

  </Tab>
  <Tab label="Solid" value="solid">

```bash
npx shadcn@latest info --json
npx shadcn@latest search @moduix-solid --query "dialog"
npx shadcn@latest view @moduix-solid/dialog
npx shadcn@latest add @moduix-solid/dialog --dry-run
```

  </Tab>
</Tabs>

Search by the interface you need rather than a familiar library name. The registry contains
components, themes, and their declared dependencies. See the [AI guide](/docs/ai) to use
the same discovery flow through shadcn MCP.

### 3. Add a component

Add registry items from the moduix registry:

<Tabs groupId="framework">
  <Tab label="React" value="react">

<PackageManagerTabs command="shadcn@latest add @moduix-react/button" dlx />

  </Tab>
  <Tab label="Solid" value="solid">

<PackageManagerTabs command="shadcn@latest add @moduix-solid/button" dlx />

  </Tab>
</Tabs>

Run the same command with another registry item name, such as `accordion`, under the selected
namespace to add more components.

For a component available in the Tailwind track, use `@moduix-react-tailwind/<name>` or
`@moduix-solid-tailwind/<name>` instead. The CLI also installs the local `cn` helper and its declared
dependencies.

The registry installs only the shared runtime files each component needs. It does not add a global
font, so typography continues to inherit from your application.

### 4. Import generated styles

Import the generated foundation stylesheet from the files that `shadcn` added to your project:

```tsx
import '@/lib/moduix/styles/style.css';
```

If you want the optional reset with this method, install its separate registry item:

<Tabs groupId="framework">
  <Tab label="React" value="react">

```bash
npx shadcn@latest add @moduix-react/reset
```

  </Tab>
  <Tab label="Solid" value="solid">

```bash
npx shadcn@latest add @moduix-solid/reset
```

  </Tab>
</Tabs>

Then import it before the main stylesheet:

```tsx
import '@/lib/moduix/styles/reset.css';
import '@/lib/moduix/styles/style.css';
```

The examples below assume `@/components` and `@/lib`. If your project uses different aliases,
update `components.json` and import the generated files from the matching paths.

For a Tailwind registry installation, load the same generated foundation before Tailwind instead:

```css title="styles.css"
@import './lib/moduix/styles/style.css';
@import 'tailwindcss';
```

Tailwind Preflight supplies the reset for that track; do not install or import the moduix reset.

### 5. Use the generated component

Import components from the generated files in your own project:

```tsx
import { Button } from '@/components/ui/button';
import { Accordion } from '@/components/ui/accordion';
```

Most components are built from named parts. This keeps behavior accessible while letting you control
markup, layout, and styling in your application.

This source-ownership model is inspired by [shadcn/ui](https://ui.shadcn.com/), while component anatomy
and interaction behavior remain aligned with [Ark UI](https://ark-ui.com/).

## Configure portal layering

This setup applies to both installation methods. Components such as `Dialog`, `Popover`, `Menu`, and
`Select` render overlay content in portals. Isolate the application root so portalled backdrops and
popups consistently render above the rest of the page without competing with local `z-index`
values.

```html title="index.html"
<body>
  <div id="app-root"></div>
</body>
```

```css title="styles.css"
#app-root {
  isolation: isolate;
}
```

If your application supports Safari on iOS 26, test a scrolled modal while Safari's browser UI is
visible. If content remains visible below the backdrop, set `body` to `position: relative` so an
absolutely positioned backdrop can cover the full visual viewport.

```css title="styles.css"
body {
  position: relative;
}
```

## Styling

moduix works with the styling approach your project already uses:

- Native CSS with global selectors, cascade layers, and CSS variables.
- CSS Modules through React `className` or Solid `class` and component slot class props.
- Tailwind CSS utility classes for layout and one-off styling.
- CSS-in-JS libraries that attach classes or pass scoped styles through your own wrappers.

In the default density, primary controls use `--moduix-size-md: 36px` and popup rows use
`--moduix-size-sm: 32px`. Because components consume the shared scale, changing those tokens updates
related inputs, triggers, buttons, and menu-like items together.

Component pages list their public CSS variables and styling hooks. Use shared semantic tokens for
system-wide changes and component variables only for deliberate exceptions. See
[Tokens](/docs/tokens) for the complete hierarchy and [Animations](/docs/animations) for motion
recipes.

## Troubleshooting

| Symptom                                  | Check                                                                                 |
| ---------------------------------------- | ------------------------------------------------------------------------------------- |
| Components render without styles         | Follow the import order for your styling track; use the optional reset only with CSS Modules. |
| A generated component import is unresolved | Verify the `@/*` alias in TypeScript and your bundler, then check `components.json`.    |
| A popup appears below page content       | Add `isolation: isolate` to the application root and avoid unrelated global z-indexes. |
| Server rendering reports client APIs     | Keep interactive components inside a client boundary in frameworks that require one.  |
