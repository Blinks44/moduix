## Choosing the right component

Use `Fieldset` when several related controls belong to one group and need a shared legend, such as
contact details or notification preferences. Use `Field` when one control needs its own label, helper
text, and validation message.

## Basic

Fieldset ships for React and Solid in both the CSS Modules and Tailwind packages. The rendered preview
on this page uses the React CSS Modules package; the framework tabs show native source for the same
public contract.

Import `Fieldset` from `@moduix/react/fieldset` or `@moduix/solid/fieldset` for CSS Modules, and from
`@moduix/react-tailwind/fieldset` or `@moduix/solid-tailwind/fieldset` for Tailwind CSS.

Build a group with `Fieldset`, `Fieldset.Legend`, the related controls, and optional helper or error
text. The shorter `<Fieldset>` syntax is equivalent to `<Fieldset.Root>`.

## Anatomy

```text
Fieldset.Root | Fieldset.RootProvider
├─ Fieldset.Legend
├─ grouped controls
├─ Fieldset.HelperText (optional)
└─ Fieldset.ErrorText (optional)
```

| Part                         | Role                                                                  |
| ---------------------------- | --------------------------------------------------------------------- |
| `Fieldset` / `Fieldset.Root` | Creates state and renders a native `fieldset`.                                             |
| `Fieldset.RootProvider`      | Renders a native `fieldset` with state created by `useFieldset`.                             |
| `Fieldset.Context`           | Exposes the current fieldset state to descendants without rendering an extra DOM element.    |
| `Fieldset.Legend`            | Native `legend` that provides the accessible name for the group.                             |
| `Fieldset.HelperText`        | Description linked to the root through `aria-describedby`.                                   |
| `Fieldset.ErrorText`         | Validation message announced through `aria-live="polite"` and rendered only when `invalid` is `true`. |

## Composition

Keep one visible `Fieldset.Legend` inside the root, then place related controls and their `Field`
parts inside the same composition. Set `invalid` on the root for a group-level error and on nested
`Field` components when individual controls need their own validation state. A disabled fieldset
passes its state to native controls and Ark-aware descendants.

Use `useFieldset` with `Fieldset.RootProvider` when state must be created outside the rendered tree or
shared with sibling controls. Use `Fieldset.Context` or `useFieldsetContext()` to read that state in a
descendant, and do not render `Fieldset.Root` together with `Fieldset.RootProvider` for the same store.
Use `asChild` with one semantic child when replacing a part's rendered element.

### Styling hooks

Every DOM part has Ark's `data-scope="fieldset"` and a `data-part` that matches the anatomy. The root
and legend expose `data-disabled` and `data-invalid`; moduix also adds `data-slot="fieldset-*"` hooks.
Use `className` in React or `class` in Solid for local overrides. CSS Modules packages use the
`--moduix-fieldset-*` variables below for theme-level customization, while Tailwind packages use
utilities and consumer class overrides.
