## Choosing the right component

Use `Fieldset` when several related form controls belong to one group and need a shared legend, such
as contact details or notification preferences. Use `Field` when a single control needs its own label,
description, and validation message.

## Basic

Build a group with `Fieldset`, `Fieldset.Legend`, the related controls, and optional helper or error
text. The short `<Fieldset>` form is equivalent to `<Fieldset.Root>`, which remains available for the
Ark-compatible API.

## Anatomy

```text
Fieldset.Root | Fieldset.RootProvider
├─ Fieldset.Legend
├─ grouped controls
├─ Fieldset.HelperText (optional)
└─ Fieldset.ErrorText (optional)
```

| Part                         | Role                                                                  |
| ---------------------------- | --------------------------------------------------------------------- |
| `Fieldset` / `Fieldset.Root` | Creates state and renders a native `fieldset`.                                             |
| `Fieldset.RootProvider`      | Renders a native `fieldset` with state created by `useFieldset`.                             |
| `Fieldset.Legend`            | Native `legend` that provides the accessible name for the group.                             |
| `Fieldset.HelperText`        | Description linked to the root through `aria-describedby`.                                   |
| `Fieldset.ErrorText`         | Validation message announced without interrupting the user and rendered only when `invalid` is `true`. |

## Composition

### Recommended composition

Keep exactly one visible `Fieldset.Legend` inside the root, preferably before the controls. Pass
`disabled`, `invalid`, and `id` directly to the root. Ark links the legend, helper text when present,
and active error text to the fieldset.

The root, provider, legend, helper text, and error text forward refs to their rendered DOM elements.
Use `asChild` with one semantic child when you need to replace the HTML element rendered for a part.

### When to go custom

Use `useFieldset` from `@moduix/react` with `Fieldset.RootProvider` when state must be created outside
the JSX tree or shared with sibling controls and reusable descendants. Use `useFieldsetContext()` or
`Fieldset.Context` in a descendant that needs to read that state. Do not use `Fieldset.Root` together
with `Fieldset.RootProvider` for the same state instance.

### Default props

| Part            | Prop       | Default |
| --------------- | ---------- | ------- |
| `Fieldset.Root` | `disabled` | `false` |
| `Fieldset.Root` | `invalid`  | `false` |

### Behavioral notes

- `Fieldset.Legend` renders a native `legend`, not a wrapper.
- The browser disables native controls inside a disabled fieldset.
- Ark `Field` descendants inherit the fieldset's disabled state. Set `invalid` on nested `Field`
  components when individual controls also need invalid state.
- `Fieldset.ErrorText` is not rendered until `invalid` is `true`.
- Long legends, helper text, and error text wrap inside the fieldset instead of overflowing it.
- `useFieldsetContext()` and `Fieldset.Context` expose the same Ark state as `useFieldset` to
  descendants.
- Fieldset does not manage a value, keyboard navigation, callbacks, or a `HiddenInput` of its own.
- The legacy `render` prop and flat exports such as `FieldsetLegend` are not supported. Use `asChild`
  and the namespace parts instead.

### Styling hooks

Every DOM part has Ark's `data-scope="fieldset"` and a `data-part` that matches the anatomy. The root
and legend expose `data-disabled` and `data-invalid`; moduix also adds `data-slot="fieldset-*"` hooks.
Use `className` for local overrides and `--moduix-fieldset-*` variables for theme-level customization,
especially legend spacing and root border tokens.
