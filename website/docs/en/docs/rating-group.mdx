## Anatomy

```text
RatingGroup
├─ RatingGroupLabel
└─ RatingGroupControl
   ├─ RatingGroupItems
   │  └─ RatingGroupItem[index]
   │     └─ RatingGroupItemIndicator
   ├─ RatingGroupContext
   │  └─ RatingGroupItem[index]
   │     └─ RatingGroupItemIndicator
   └─ RatingGroupHiddenInput (explicit)

RatingGroupRootProvider
└─ same part tree connected to a moduix useRatingGroup() store
```

| Part                               | Role                                                               |
| ---------------------------------- | ------------------------------------------------------------------ |
| `RatingGroup`                    | Owns rating state, keyboard navigation, focus, and form integration. |
| `RatingGroupHiddenInput`          | Native Ark form control that must be composed explicitly.          |
| `RatingGroupRootProvider`          | Connects the parts to state created with `useRatingGroup()`.       |
| `RatingGroupContext`               | Render-prop access to the current root state.                      |
| `RatingGroupItemContext`           | Render-prop access to the current item state.                      |
| `RatingGroupLabel`                 | Accessible label for the rating group.                             |
| `RatingGroupControl`               | Groups the interactive rating items.                               |
| `RatingGroupItems`                 | Creates one item for each value and supplies the default star.     |
| `RatingGroupItem`                  | One selectable rating item; requires a numeric `index`.            |
| `RatingGroupItemIndicator`         | The default moduix star visual for an item.                        |

## Composition

Use `RatingGroupItems` for the standard generated item tree. To replace the repeated visual, pass a
custom `RatingGroupItemIndicator` as its child. `RatingGroupHiddenInput` is independent of
`Items`, so compose it explicitly inside the root or `RatingGroupRootProvider`; set `name` on the
root when the value should be submitted by a native form.

For a custom item tree, use `RatingGroupContext` with `RatingGroupItem`; use
`RatingGroupRootProvider` with `useRatingGroup()` when the store must be created outside the
rendered tree. React reads the store as an object, while Solid reads its reactive state through the
returned accessor.

## Styling

Use `className` in React or `class` in Solid on exported parts for structural styles. Ark also exposes
`data-scope="rating-group"` and `data-part` attributes. For state-based styles, use data attributes such as `data-disabled`, `data-readonly`, `data-checked`,
`data-highlighted`, and `data-half`, together with moduix `data-slot` hooks. Tailwind variants use
native utilities and consumer classes; the CSS Modules variants also expose the registered
`--moduix-rating-group-*` variables.

### Styling hooks

- `data-slot="rating-group-root"` and `data-slot="rating-group-root-provider"`
- `data-slot="rating-group-label"`
- `data-slot="rating-group-control"`
- `data-slot="rating-group-item"`
- `data-slot="rating-group-item-indicator"`
- `data-slot="rating-group-item-indicator-bg"` and `data-slot="rating-group-item-indicator-fg"`
- `data-size="xs" | "sm" | "md" | "lg" | "xl"` on the root or root provider
- Ark label attributes: `data-disabled` and `data-required`
- Ark control attributes: `data-disabled` and `data-readonly`
- Ark item attributes: `data-checked`, `data-highlighted`, `data-half`, `data-disabled`, and `data-readonly`
