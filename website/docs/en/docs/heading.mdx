`Heading` renders an `h1` by default. Use it for document headings and choose the `as` value that
matches the heading's place in the document outline. Set `size` separately when the visual emphasis
should differ from the semantic level.

## Composition

`Heading` is a root-only, stateless component, so it does not need a provider or coordinated parts.
Use `<Heading>`, pass `as` for the semantic `h1` through `h6` level, and set `size` independently
when visual emphasis should differ. Without an explicit `size`,
`as` selects the scale from `2xl` for `h1` through `xs` for `h6`; `weight` defaults to
`semibold`. Use `asChild` only when a custom semantic heading host must own the rendered DOM node.

## Styling

Use `className` in React or `class` in Solid and Vue on `Heading`. Tailwind variants use native
utilities and consumer classes. CSS Modules variants build on foundation typography tokens and have no
component variables: a class on the root overrides the layered component styles.

### Styling hooks

| Part | `data-slot` |
| --- | --- |
| `Heading` | `heading-root` |

- `data-scope="heading"` and `data-part="root"` identify the Ark-aligned root.
- `data-size` reflects the resolved size: the explicit `size` or the default for `as`.
- `data-weight` reflects `regular`, `medium`, `semibold`, or `bold`.
- `Heading` owns these attributes. Matching `data-*` props cannot replace its styling contract.
- Use `className` or `class` for consumer utility or local style overrides.

## API reference

Also accepts the native props of its element and `asChild`.

| Prop | Type | Default |
| --- | --- | --- |
| `as` | `'h1' \| 'h2' \| 'h3' \| 'h4' \| 'h5' \| 'h6'` | `'h1'` |
| `size` | `'xs' \| 'sm' \| 'md' \| 'lg' \| 'xl' \| '2xl'` | — |
| `weight` | `'regular' \| 'medium' \| 'semibold' \| 'bold'` | `'semibold'` |
