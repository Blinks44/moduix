## API Reference

Ark UI does not provide a dedicated heading primitive. moduix implements `Heading` with the official
[Ark factory](https://ark-ui.com/docs/guides/composition#the-ark-factory) and follows Ark guidance for
[composition](https://ark-ui.com/docs/guides/composition), [styling](https://ark-ui.com/docs/guides/styling), and
[ref forwarding](https://ark-ui.com/docs/guides/ref).

## Basic

`Heading` renders an `h1` by default. Use it for document headings and choose the `as` value that
matches the heading's place in the document outline. Set `size` separately when the visual emphasis
should differ from the semantic level.

## Anatomy

`Heading` renders one native heading element. `<Heading>` and `<Heading.Root>` are equivalent forms.

```text
Heading / Heading.Root
└─ text or inline content
```

| Part                       | Role                                                    |
| -------------------------- | ------------------------------------------------------- |
| `Heading` / `Heading.Root` | Native semantic heading with moduix typography styling. |

## Composition

### Recommended composition

Use `<Heading>` for the common `h1` case. For another semantic level, pass an `as` value from
`h2` through `h6`:

```tsx
import { Heading } from '@moduix/react/heading';

<Heading as="h2" size="2xl">
  Page title rendered as h2
</Heading>
```

Use `asChild` for factory composition when a single semantic heading child should own the rendered
DOM node. The child receives the component's props, class name, data attributes, and forwarded ref.

### When to go custom

Use `className` and the public `--moduix-heading-*` variables for local visual adjustments. Use
`Text` for body copy, helper text, or inline text instead of a document heading.

### Default props

| Prop        | Default             | Values / Notes                          |
| ----------- | ------------------- | --------------------------------------- |
| `as`        | `h1`                | `h1` through `h6`                       |
| `size`      | by rendered element | `xs`, `sm`, `md`, `lg`, `xl`, `2xl`     |
| `weight`    | `semibold`          | `regular`, `medium`, `semibold`, `bold` |
| `asChild`   | `false`             | Ark factory composition                 |
| `className` | -                   | Applied to the rendered heading root    |

### Behavioral notes

- When `size` is omitted, the rendered element determines the visual size: `h1 -> 2xl`, `h2 -> xl`,
  `h3 -> lg`, `h4 -> md`, `h5 -> sm`, and `h6 -> xs`.
- An explicit `size` overrides the element-based default without changing semantics.
- The root forwards its ref to the rendered heading element.
- Native heading elements provide the required semantics and need no additional ARIA attributes. Do not
  pass a non-heading child to `asChild`.
- `Heading` manages no state and exposes no callbacks, keyboard interactions, providers, or context hooks.

### Styling hooks

- `data-scope="heading"` and `data-part="root"` identify the Ark-aligned root.
- `data-slot="heading-root"` is the stable moduix selector.
- `data-size` is present when `size` is explicitly set.
- `data-weight` reflects `regular`, `medium`, `semibold`, or `bold`.
- `Heading` owns these attributes. Matching `data-*` props cannot replace its styling contract.
- Use `className` and `--moduix-heading-*` variables for local visual adjustments.
