## API Reference

`Sidebar` is moduix's layout for application navigation. It combines navigation parts with
[Ark UI Splitter](https://ark-ui.com/docs/components/splitter), which provides resizing, collapse
state, keyboard interaction, and accessibility. The exposed state and callbacks follow the Splitter
contract.

<PrimitiveReference href="https://ark-ui.com/docs/components/splitter" />

## Choosing the right component

- Choose **`Sidebar`** for application navigation that should resize, collapse to an icon rail, and
  sit beside the main content.
- Choose **`Splitter`** when you need generic resizable panels rather than a navigation panel and a
  main content inset.

## Basic


Compose the navigation panel, resize handle, and main content panel as direct children of the root.
The default ids and constraints cover the usual left-sidebar layout. Wrap icon-only navigation
buttons in `Sidebar.Tooltip` so their labels remain available after collapse.

## Anatomy

```text
Sidebar / Sidebar.Root
├─ Sidebar.Panel[id="sidebar"]
│  ├─ Sidebar.Header
│  │  ├─ Sidebar.Label
│  │  └─ Sidebar.Input
│  ├─ Sidebar.Content
│  │  └─ Sidebar.Group
│  │     ├─ Sidebar.GroupHeader
│  │     │  ├─ Sidebar.GroupLabel
│  │     │  └─ Sidebar.GroupAction
│  │     └─ Sidebar.NavigationList
│  │        └─ Sidebar.NavigationItem
│  │           ├─ Sidebar.NavigationButton
│  │           ├─ Sidebar.NavigationBadge (optional)
│  │           ├─ Sidebar.ExpandedContent
│  │           ├─ Sidebar.CollapsedContent
│  │           └─ Sidebar.NavigationSubList
│  │              └─ Sidebar.NavigationSubItem
│  │                 ├─ Sidebar.NavigationSubButton
│  │                 └─ Sidebar.NavigationBadge (optional)
│  └─ Sidebar.Footer
│     └─ Sidebar.Separator
├─ Sidebar.ResizeTrigger
├─ Sidebar.Trigger
└─ Sidebar.Inset[id="content"]
```

| Part | Role |
| --- | --- |
| `Sidebar` / `Sidebar.Root` | Ark Splitter root with defaults for a two-panel sidebar. |
| `Sidebar.Panel` | Collapsible navigation panel; its default id is `"sidebar"`. |
| `Sidebar.Inset` | Main content panel; its default id is `"content"`. |
| `Sidebar.ResizeTrigger` | Accessible line for pointer and keyboard resizing. |
| `Sidebar.Trigger` | Side-aware control for collapsing and expanding the panel. |
| `Sidebar.Header` | Non-scrolling top region. |
| `Sidebar.Content` | Scrolling middle region. |
| `Sidebar.Footer` | Non-scrolling bottom region. |
| `Sidebar.Group` | Semantic navigation section. |
| `Sidebar.NavigationButton` | Button or `asChild` link with active and size states. |
| `Sidebar.NavigationBadge` | Optional counter beside a simple navigation button or sub-button. |
| `Sidebar.ExpandedContent` | Content shown while the panel is expanded. |
| `Sidebar.CollapsedContent` | Content shown while the panel is collapsed. |
| `Sidebar.Tooltip` | Collapsed-only label helper with side-aware placement. |
| `Sidebar.NavigationSubList` | Nested navigation list. |

## Composition

`Sidebar` owns the Splitter layout state, while nested `Collapsible`, popup `Menu`, and
`Sidebar.Tooltip` instances own their own state. Keep `Panel`, `ResizeTrigger`, `Trigger`, and
`Inset` as direct children in visual order: `Panel` first for a left sidebar, and `Inset` first for
a right sidebar. `ExpandedContent` and `CollapsedContent` only switch which composition is visible;
use them to pair inline `Collapsible` links with a collapsed `Menu` without moving state into
Sidebar. For a persisted width, control `size`, update it from `onResize(details)`, and save it from
`onResizeEnd(details)`. In Solid, `asChild` uses a render function that receives the merged props.
Place `NavigationBadge` after a simple `NavigationButton` or `NavigationSubButton`; it reserves
trailing space for the counter and hides with the other trailing affordances in the compact rail.

## Styling

Every semantic part accepts `className` in React and `class` in Solid and exposes a stable
`data-slot="sidebar-*"` hook. `Sidebar.Panel` adds `data-state="expanded"` or `"collapsed"`, and
layout parts expose `data-side`. `NavigationButton` and `NavigationSubButton` expose
`data-active`; `NavigationButton` also exposes `data-size`.

When collapsed, labels and group labels leave the visual layout while remaining available to
assistive technology. Nested lists, inputs, actions, badges, and indicators are hidden to keep the
icon rail compact. Mark non-SVG visual anchors such as `Avatar` or a brand mark with
`data-sidebar-icon`.

Panel widths are Ark state rather than visual CSS. Override `defaultSize` or controlled `size` for
the current width. Use the public `--moduix-sidebar-*` variables for internal spacing, item
dimensions, colors, and the trigger offset.

### Styling hooks

Sidebar shell parts also expose `data-scope="sidebar"` and `data-part`. `Sidebar.Input` and
`Sidebar.Separator` retain the scopes of their underlying primitives, while Ark-backed layout parts
retain Splitter state attributes such as `data-focus`, `data-dragging`, `data-disabled`, and
`data-orientation`.
