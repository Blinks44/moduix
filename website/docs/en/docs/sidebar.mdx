## API Reference

`Sidebar` is moduix's layout for application navigation. It combines navigation parts with
[Ark UI Splitter](https://ark-ui.com/docs/components/splitter), which provides resizing, collapse
state, keyboard interaction, and accessibility. The exposed state and callbacks follow the Splitter
contract.

<PrimitiveReference href="https://ark-ui.com/docs/components/splitter" />

## Choosing the right component

- Choose **`Sidebar`** for application navigation that should resize, collapse to an icon rail, and
  sit beside the main content.
- Choose **`Splitter`** when you need generic resizable panels rather than a navigation panel and a
  main content inset.

## Basic


Compose the navigation panel, resize handle, and main content panel as direct children of the root.
The default ids and constraints cover the usual left-sidebar layout. Wrap icon-only navigation
buttons in `SidebarTooltip` so their labels remain available after collapse.

## Anatomy

```text
Sidebar
├─ SidebarPanel[id="sidebar"]
│  ├─ SidebarHeader
│  │  ├─ SidebarLabel
│  │  └─ SidebarInput
│  ├─ SidebarContent
│  │  └─ SidebarGroup
│  │     ├─ SidebarGroupHeader
│  │     │  ├─ SidebarGroupLabel
│  │     │  └─ SidebarGroupAction
│  │     └─ SidebarNavigationList
│  │        └─ SidebarNavigationItem
│  │           ├─ SidebarNavigationButton
│  │           ├─ SidebarNavigationBadge (optional)
│  │           ├─ SidebarExpandedContent
│  │           ├─ SidebarCollapsedContent
│  │           └─ SidebarNavigationSubList
│  │              └─ SidebarNavigationSubItem
│  │                 ├─ SidebarNavigationSubButton
│  │                 └─ SidebarNavigationBadge (optional)
│  └─ SidebarFooter
│     └─ SidebarSeparator
├─ SidebarResizeTrigger
├─ SidebarTrigger
└─ SidebarInset[id="content"]
```

| Part | Role |
| --- | --- |
| `Sidebar` | Ark Splitter root with defaults for a two-panel sidebar. |
| `SidebarPanel` | Collapsible navigation panel; its default id is `"sidebar"`. |
| `SidebarInset` | Main content panel; its default id is `"content"`. |
| `SidebarResizeTrigger` | Accessible handle line for pointer and keyboard resizing; it renders the shared `SplitterResizeTriggerIndicator` by default, and custom children replace it. |
| `SidebarTrigger` | Side-aware control for collapsing and expanding the panel. |
| `SidebarHeader` | Non-scrolling top region. |
| `SidebarContent` | Scrolling middle region. |
| `SidebarFooter` | Non-scrolling bottom region. |
| `SidebarGroup` | Semantic navigation section. |
| `SidebarNavigationButton` | Button or `asChild` link with active and size states. |
| `SidebarNavigationBadge` | Optional counter beside a simple navigation button or sub-button. |
| `SidebarExpandedContent` | Content shown while the panel is expanded. |
| `SidebarCollapsedContent` | Content shown while the panel is collapsed. |
| `SidebarTooltip` | Collapsed-only label helper with side-aware placement. |
| `SidebarNavigationSubList` | Nested navigation list. |

## Composition

`Sidebar` owns the Splitter layout state, while nested `Collapsible`, popup `Menu`, and
`SidebarTooltip` instances own their own state. Keep `SidebarPanel`, `SidebarResizeTrigger`, `SidebarTrigger`, and
`SidebarInset` as direct children in visual order: `SidebarPanel` first for a left sidebar, and `SidebarInset` first for
a right sidebar. `SidebarExpandedContent` and `SidebarCollapsedContent` only switch which composition is visible;
use them to pair inline `Collapsible` links with a collapsed `Menu` without moving state into
Sidebar. For a persisted width, control `size`, update it from `onResize(details)`, and save it from
`onResizeEnd(details)`. In Solid, `asChild` uses a render function that receives the merged props.
In Vue, use `as-child` with a single element in the default slot and a template ref to access the component instance.
For controlled sizes, use `v-model:size` or handle `@resize`; persist the final value with `@resize-end`.
Place `SidebarNavigationBadge` after a simple `SidebarNavigationButton` or `SidebarNavigationSubButton`; it reserves
trailing space for the counter and hides with the other trailing affordances in the compact rail.

`useSidebar()` from the matching framework package exposes the sidebar state as `collapsed`, `side`,
and `state`, plus a `toggleSidebar()` callback. In Solid these are accessors read as
`collapsed()` and friends. It reads the Splitter context created by `Sidebar`, so
use it only inside the sidebar tree.
In Vue, the state values are refs: read `collapsed.value`, `side.value`, and `state.value`
in script; templates unwrap them automatically.

With Ark Vue 5.39.3 / Zag 1.45.0, the first controlled collapse can update `size` without
emitting `@collapse`. The model and `useSidebar().collapsed` still reflect the new state.

## Styling

Every semantic part accepts `className` in React and `class` in Solid and Vue and exposes a stable
`data-slot="sidebar-*"` hook. `SidebarPanel` adds `data-state="expanded"` or `"collapsed"`, and
layout parts expose `data-side`. `SidebarNavigationButton` and `SidebarNavigationSubButton` expose
`data-active`; `SidebarNavigationButton` also exposes `data-size`.

When collapsed, labels and group labels leave the visual layout while remaining available to
assistive technology. Nested lists, inputs, actions, badges, and indicators are hidden to keep the
icon rail compact. Mark non-SVG visual anchors such as `Avatar` or a brand mark with
`data-sidebar-icon`.

Panel widths are Ark state rather than visual CSS. Override `defaultSize` or controlled `size` for
the current width. Colors come from the foundation sidebar tokens (`--moduix-color-sidebar`,
`--moduix-color-sidebar-foreground`, `--moduix-color-sidebar-accent`,
`--moduix-color-sidebar-accent-foreground`, `--moduix-color-sidebar-border`, and
`--moduix-color-sidebar-ring`), so themes and presets restyle every sidebar at once. The root keeps
`--moduix-sidebar-width`, `--moduix-sidebar-height`, and `--moduix-sidebar-trigger-offset-y`; change
spacing, radius, shadow, or item sizes with a class on the part.

Wrap navigation text in `SidebarLabel`, including inside `SidebarNavigationSubButton`, so long labels
truncate and leave the collapsed rail.

### Styling hooks

Sidebar shell parts also expose `data-scope="sidebar"` and `data-part`. `SidebarInput` and
`SidebarSeparator` retain the scopes of their underlying primitives, while Ark-backed layout parts
retain Splitter state attributes such as `data-focus`, `data-dragging`, `data-disabled`, and
`data-orientation`.
