## Usage

<Usage />

Use `Dialog` as the root and compose its structural parts explicitly. `DialogBackdrop` is the
modal background, `DialogPositioner` places the dialog, and `DialogContent` contains its surface.

## Choosing the right component

Use `Dialog` for forms, confirmations, details, and other tasks that should keep the user on the
current page. Use `Drawer` when the panel should stay attached to the edge of the viewport or
support dragging.

## Examples

### Sizes

Set `size` on `DialogContent` to `sm`, `md` (default), `lg`, `xl`, or `full`. Use `placement="top"`
or `placement="bottom"` to move the surface away from the center, and `scrollBehavior="inside"` to
cap the dialog at the viewport height and scroll `DialogBody` instead of the positioner.

<Example name="dialog/sizes" />

### Alert dialog

Use `role="alertdialog"` for decisions with serious consequences. Include a clear cancel action
and a separate action that confirms the decision.

<Example name="dialog/alert-dialog" />

### Confirmation

Intercept the parent dialog's close request when a form contains unsaved changes and ask whether the
user wants to discard them.

<Example name="dialog/confirmation" />

### Inside scroll

Make only the main content scrollable when the title and actions should remain visible. Set
`scrollBehavior="inside"` on `DialogContent`: the dialog stops at the viewport height and
`DialogBody` scrolls.

<Example name="dialog/inside-scroll" />

### Outside scroll

Let `DialogPositioner` scroll the whole dialog when long content should keep its natural height.
This is the default `scrollBehavior`; `placement="top"` starts the dialog at the top of the viewport.

<Example name="dialog/outside-scroll" />

### Non-modal

Set `modal={false}` and omit the backdrop when users should still be able to interact with the page
outside the dialog.

<Example name="dialog/non-modal" />

### Nested

Use separate `useDialog()` stores for nested dialogs. Ark UI manages the layer stack, and moduix
uses the resulting state to make the parent recede while the nested dialog is open.

<Example name="dialog/nested" />

### Multiple triggers

Share one dialog between several triggers by giving each trigger a `value` and handling
`onTriggerValueChange(details)`.

### Open from menu

Control `open` from a menu item when a contextual action should open a confirmation dialog.

<Example name="dialog/open-from-menu" />

### Controlled

Pass `open` and `onOpenChange` (`v-model:open` in Vue) and read `details.open` to keep the dialog in
sync with the rest of the application. See [Control state from the application](/docs/composition-patterns#controlled-state).

<Example name="dialog/controlled" />

### Mounting and focus lifecycle

Use `lazyMount` and `unmountOnExit` for the presence lifecycle. Use `initialFocusEl` and
`finalFocusEl` when focus should move to specific elements on open and close.

<Example name="dialog/mounting-and-focus-lifecycle" />

### Root provider

Create the state with `useDialog()` when controls live outside the dialog. Connect it with
`DialogRootProvider`, then read it with `DialogContext` or `useDialogContext()` in reusable
components. See [Share state outside the tree](/docs/composition-patterns#root-provider).

## Composition

Dialog manages its open state by default. Use `open` with `onOpenChange(details)` when another part of
the application controls that state. When state must live outside the dialog tree, create one
`useDialog()` store and pass it to `DialogRootProvider`; do not render another root for the same
store.

The root automatically portals `DialogBackdrop` and `DialogPositioner`. Set `portalled={false}`
to keep them in the current tree, or pass `portalRef` to use a custom container. Keep the part tree
explicit, and use `DialogHeader`, `DialogBody`, and `DialogFooter` only when their layout
helpers fit the composition.

## Styling

Use `className` in React or `class` in Solid and Vue on exported parts for structural styles. For
state-based styles, prefer Ark data attributes such as `data-state` and `data-has-nested`, together with moduix
`data-slot` selectors. Tailwind variants use native utilities and consumer classes; the component
variables below customize the CSS Modules variants. Data attributes and `data-slot` hooks are shared
by both styling tracks.

| `DialogFooter` | `dialog-footer` |

- Ark attributes: `data-scope="dialog"` and
  `data-part="trigger|backdrop|positioner|content|title|description|close-trigger"`.
- State attributes: `data-state="open|closed"`, `data-has-nested`, `data-nested`, `data-current`,
  and `data-value`.
- Runtime variables: `--layer-index` and `--nested-layer-count`.
- `DialogCloseIcon` is positioned against the corner of `DialogContent`, so its placement does
  not depend on `DialogHeader`.
- Colors, borders, spacing, and typography come from foundation tokens. Change them for one dialog
  with a class on the part, and change motion with `--moduix-popup-motion-*` on `DialogContent`.

## Keyboard

| Key | Action |
| --- | --- |
| `Enter` / `Space` | Opens it from the focused trigger. |
| `Tab` / `Shift+Tab` | Moves focus between controls; focus stays inside while open. |
| `Esc` | Closes it and returns focus to the trigger. |

## API reference

Props of `Dialog`. `size` (`'sm' | 'md' | 'lg' | 'xl' | 'full'`, default `'md'`), `placement` (`'center' | 'top' | 'bottom'`, default `'center'`), and `scrollBehavior` (`'outside' | 'inside'`, default `'outside'`) go on `DialogContent`.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `open` | `boolean` | — | Open state for controlled use. |
| `defaultOpen` | `boolean` | `false` | Initial open state when it is not controlled. |
| `onOpenChange` | `(details: OpenChangeDetails) => void` | — | Called when it opens or closes. |
| `modal` | `boolean` | `true` | Blocks interaction outside and hides the rest of the page from assistive technology. |
| `role` | `'dialog' \| 'alertdialog'` | `'dialog'` | `dialog`, or `alertdialog` for urgent confirmations. |
| `closeOnEscape` | `boolean` | `true` | Closes on Escape. |
| `closeOnInteractOutside` | `boolean` | `true` | Closes on a click outside. |
| `trapFocus` | `boolean` | `true` | Keeps keyboard focus inside while open. |
| `preventScroll` | `boolean` | `true` | Locks page scroll while open. |
| `initialFocusEl` | `() => HTMLElement \| null \| false` | — | Returns the element to focus on open. |
| `finalFocusEl` | `() => HTMLElement \| null` | — | Returns the element to focus on close. |
| `lazyMount` | `boolean` | `true` | Mounts the content on first open. |
| `unmountOnExit` | `boolean` | `true` | Unmounts the content after it closes. |
| `portalled` | `boolean` | `true` | Renders the popup in a portal at the end of `body`. |
| `restoreFocus` | `boolean` | — | Returns focus to the previously focused element on close. |
| `aria-label` | `string` | — | Accessible name when the dialog has no visible title. |
| `triggerValue` | `string \| null` | — | Active trigger for controlled use when several triggers share one popup. |
| `defaultTriggerValue` | `string \| null` | — | Initially active trigger. |
| `onTriggerValueChange` | `(details: TriggerValueChangeDetails) => void` | — | Called when another trigger becomes active. |
