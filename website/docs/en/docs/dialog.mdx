## Choosing the right component

Use `Dialog` for forms, confirmations, details, and other tasks that should keep the user on the
current page. Use `Drawer` when the panel should stay attached to the edge of the viewport or
support dragging.

## Basic

Use `Dialog` as the root and compose its structural parts explicitly. `Dialog.Backdrop` is the
modal background, `Dialog.Positioner` places the dialog, and `Dialog.Content` contains its surface.

## Anatomy

```text
Dialog / Dialog.Root
├─ Dialog.Trigger
└─ Overlay content (automatically portalled)
   ├─ Dialog.Backdrop (optional)
   └─ Dialog.Positioner
      └─ Dialog.Content
         ├─ Dialog.CloseTrigger or Dialog.CloseIcon
         ├─ Dialog.Title
         ├─ Dialog.Description
         ├─ Dialog.Header (moduix layout helper)
         ├─ Dialog.Body (moduix layout helper)
         └─ Dialog.Footer (moduix layout helper)

Dialog.RootProvider
└─ the same part tree connected to state from moduix useDialog()

Dialog.Context
└─ a render function with the current dialog state and methods
```

| Part                     | Role                                                                 |
| ------------------------ | -------------------------------------------------------------------- |
| `Dialog` / `Dialog.Root` | Owns the open state, focus management, and dismissal behavior.        |
| `Dialog.RootProvider`    | Connects the parts to state created with `useDialog()`.              |
| `Dialog.Trigger`         | Opens the dialog.                                                     |
| `Dialog.Backdrop`        | Optional background layer for a modal dialog.                        |
| `Dialog.Positioner`      | Positions the dialog content.                                        |
| `Dialog.Content`         | Contains the visible dialog surface.                                 |
| `Dialog.Title`           | Gives the dialog an accessible title.                                |
| `Dialog.Description`     | Provides supporting accessible text.                                 |
| `Dialog.CloseTrigger`    | Closes the dialog.                                                    |
| `Dialog.CloseIcon`       | Moduix close-button helper that also closes the dialog.              |
| `Dialog.Header`          | Moduix layout helper for the header.                                 |
| `Dialog.Body`            | Moduix layout helper for the main content.                           |
| `Dialog.Footer`          | Moduix layout helper for actions.                                    |
| `Dialog.Context`         | Renders children with the current state and dialog methods.          |

Import `useDialog()` when the dialog state needs to live outside the rendered dialog tree. Read or
update that state with `Dialog.Context` or `useDialogContext()` from `@moduix/react`.

## Composition

The root automatically portals `Dialog.Backdrop` and `Dialog.Positioner`. Set `portalled={false}`
to render them in the current tree, or pass `portalRef` to use a custom container. Keep the
structural parts explicit so each part can be styled or customized independently.

### Recommended composition

Render `Dialog.Backdrop`, `Dialog.Positioner`, and `Dialog.Content` explicitly. Add the backdrop for
modal dialogs and leave it out when the dialog should be non-modal.

Use `Dialog.Trigger asChild` and `Dialog.CloseTrigger asChild` with one semantic child element. The
child must be able to receive focus and keep the behavior of a button. `Dialog.CloseIcon` is a
moduix helper that combines Ark's close trigger with the library close button.

### When to go custom

Use `open` with `onOpenChange(details)` when React should own the open state. The callback receives
an Ark details object, so read the next state from `details.open`.

Use `useDialog()` with `Dialog.RootProvider` when the state or methods must be available outside the
dialog tree. Do not render a second `Dialog` for the same store. Use `Dialog.Context` or
`useDialogContext()` when a reusable child needs to read that state.

Use `ids` when separately composed parts need stable, shared accessibility IDs. Use `initialFocusEl`
and `finalFocusEl` to choose explicit focus targets. Set `role="alertdialog"` for destructive or
otherwise critical decisions.

Keep the root mounted when the open state changes. Use `lazyMount` and `unmountOnExit` to control
when the portalled content enters and leaves the DOM. Set `present` only when JavaScript-controlled
presence is needed for a custom exit animation.

### Default props

The first two defaults come from moduix. The remaining defaults are inherited from Ark UI.

| Prop                    | Default | Notes                                                        |
| ----------------------- | ------- | ------------------------------------------------------------ |
| `lazyMount`             | `true`  | Mounts the portalled content only after its first open.      |
| `unmountOnExit`          | `true`  | Removes the content after its exit animation.                |
| `modal`                  | `true`  | Prevents interaction with content outside the dialog.        |
| `preventScroll`          | `true`  | Prevents the page from scrolling while the dialog is open.   |
| `trapFocus`              | `true`  | Keeps focus inside a modal dialog.                            |
| `closeOnEscape`          | `true`  | Closes the dialog when the user presses `Escape`.             |
| `closeOnInteractOutside` | `true`  | Closes the dialog after interaction outside it.               |
| `role`                   | `"dialog"` | Uses the regular dialog semantics by default.                |

### Behavioral notes

- A modal dialog traps focus, prevents page scrolling, hides content behind the dialog from
  assistive technologies, and restores focus after it closes.
- Set `modal={false}` to disable focus trapping and scroll prevention. Leave out
  `Dialog.Backdrop` in this mode so the page remains interactive.
- `closeOnEscape`, `closeOnInteractOutside`, `trapFocus`, `preventScroll`, `restoreFocus`,
  `persistentElements`, and the outside-interaction callbacks are passed through to Ark UI.
- Render `Dialog.Title` or set `aria-label` on the root to give the dialog an accessible name. Use
  `Dialog.Description` for supporting text when it helps users understand the task.
- When the user prefers reduced motion, moduix shortens the entry and exit animations while Ark UI
  still completes the normal presence lifecycle.
- If a dialog has more than one close control, give each `Dialog.CloseTrigger` an explicit, unique
  `id`. A single `Dialog.CloseIcon` does not need one.
- For nested dialogs, the parent content receives `data-has-nested` and
  `--nested-layer-count`. Moduix uses them to scale the parent back and move it down while the
  nested dialog is active.
- Do not conditionally unmount the root to close the dialog. Keep it mounted and control `open`, or
  use `lazyMount` and `unmountOnExit` when the portalled content should not stay in the DOM.

### Styling hooks

- Moduix `data-slot` values: `dialog-trigger`, `dialog-backdrop`, `dialog-positioner`,
  `dialog-content`, `dialog-title`, `dialog-description`, `dialog-close-trigger`,
  `dialog-close-icon`, `dialog-header`, `dialog-body`, and `dialog-footer`.
- Ark attributes: `data-scope="dialog"` and `data-part="trigger|backdrop|positioner|content|title|description|close-trigger"`.
- State attributes: `data-state="open|closed"`, `data-has-nested`, `data-nested`, `data-current`,
  and `data-value`.
- Runtime variables: `--layer-index` and `--nested-layer-count`.
- `Dialog.CloseIcon` is positioned against the corner of `Dialog.Content`, so its placement does
  not depend on `Dialog.Header`.
