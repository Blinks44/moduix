Use this header when your application has one main navigation level and a small set of global actions.
Its open layout keeps the product identity, current workspace, navigation, and account controls easy to
scan.

This is a copy-ready composition, not an `AppHeader` component exported by moduix. It combines
`CommandPalette`, `Menu`, and other moduix components. Install the block with its dependencies,
then replace the sample navigation and account data with your own.

## Block contents

- Main navigation with `aria-current="page"` on the active destination.
- A `CommandPalette` that filters navigation items and workspace actions by group.
- An account menu with links to the profile, workspace settings, and help.
- A separate `Menu` for the main navigation on small screens.
- Accessible names for icon-only controls and an avatar fallback while the image loads.

The React, Solid, Vue, and Svelte implementations share one stylesheet.

## Use the block in your application

The demo uses anchors such as `#overview`, and selecting a command updates `window.location.hash`, so
it works without a router. Replace the anchors and command-selection handler with your router's
navigation. Place the block in the layout that handles primary navigation and account state.

## Customize

The block uses ordinary links for navigation and `aria-current="page"` for the active destination.
Replace the fixtures with values from your router and account state. The `CommandPalette` is covered
in the [Command Palette docs](/docs/command-palette).

| Replace this fixture       | With your application value                                             |
| -------------------------- | ----------------------------------------------------------------------- |
| Orbit and Acme Studio      | Product home link and current workspace                                |
| Navigation anchors         | Router links; set `aria-current="page"` from the current route         |
| Search control             | A Command Palette trigger with routes and actions for your application |
| Account image and details  | Authenticated user data and an image URL from your application              |
| Account menu links         | Profile, settings, help, and other routes your users actually need      |

When your router provides a `Link` component, pass it through `Button asChild` or `MenuItem asChild`
instead of nesting interactive elements. Keep the avatar fallback so the account control remains
identifiable while its image loads or when no image is available.

## Responsive behavior

The CSS module defines three breakpoints:

- Below 64rem, the workspace label and status indicator are hidden to make room for the main controls.
- Below 48rem, the inline navigation moves into a button that opens `Menu`.
- Below 36rem, the account name, role, and chevron are hidden while the avatar stays visible.

Adjust these breakpoints and the mobile navigation pattern if your application has more links or
nested routes.
