# App header

Use this header when an application needs one clear navigation level and only a few global actions.
The spacious layout keeps the product identity, current workspace, navigation, and account controls
easy to scan without turning the header into a toolbar.

## Adapt it to your app

The recipe uses real links for every navigation action and `aria-current="page"` for the active
destination. Replace the fixtures with values from your router and account state.

| Replace this fixture       | With your application value                                             |
| -------------------------- | ----------------------------------------------------------------------- |
| Orbit and Acme Studio      | Product home link and current workspace                                |
| Navigation anchors         | Router links; set `aria-current="page"` from the current route         |
| Search control             | A Command Palette trigger with routes and actions for your application |
| Account image and details | Authenticated user data and an application-owned image URL              |
| Account menu links         | Profile, settings, help, and other routes your users actually need      |

When your router exposes a Link component, pass it through `Button asChild` or `Menu.Item asChild`
instead of nesting one interactive element inside another. Keep the avatar fallback so the account
control remains identifiable while its image loads or when no image is available.

## Responsive behavior

Below 48rem, the centered navigation moves into a real `Menu` rather than disappearing. Below
36rem, workspace and account labels collapse while icon controls keep accessible names. For deeper
navigation with groups or nested routes, replace the compact menu with the
[Mobile drawer navigation](/recipes/mobile-drawer-navigation) recipe.
