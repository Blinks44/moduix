# File upload manager

Use this recipe when a form or workflow needs a clear place to add and review attachments. It accepts
PDF, DOC, DOCX, PNG, and JPG files up to 10 MB, shows up to five accepted files, and lets users remove
one file or clear the whole list. Rejected files stay visible with their validation errors.

The recipe manages selection and the local file list only. It does not send files to a server or track
upload progress. Connect `onFileChange` to the form or upload request in the feature that owns the data.

The live preview uses the React package. The source tabs show native React and Solid implementations that share the same stylesheet.

## Connect an upload request

`FileUpload` keeps the selected files in its local state. Add `onFileChange(details)` to the root when
your form or upload request needs the current selection, and pass `details.acceptedFiles` to that logic.
Track progress and completion alongside the real request instead of simulating them in the recipe.

Browser-side validation improves feedback, but it does not replace server-side validation. The server
must validate the file type, size, content, and authorization again. Treat every selected `File` as
untrusted input.

| Upload state | Show to the user                                                        |
| ------------ | ----------------------------------------------------------------------- |
| Selected     | File name, size, a removal action, and an explicit upload or form submit. |
| Uploading    | Progress when known, a pending status, and disabled duplicate submission. |
| Failed       | The server message when safe, plus retry and remove actions.               |
| Complete     | A stable success state with the file identifier stored by the server.     |

If files upload immediately after selection, assign an ID to each request in your application. A retry
can then update the same row, and removing one file does not cancel the others.
