# Справа налево (RTL)

Для RTL-интерфейса нужно настроить две вещи:

- нативный атрибут `dir`, который задаёт направление текста и CSS в браузере;
- `LocaleProvider` из moduix, который передаёт Ark локаль и соответствующее направление.

## Настройка направления документа

Если весь интерфейс использует язык с письмом справа налево, задайте `lang` и `dir` на корневом элементе документа.
В приложении с SSR компонент, который формирует оболочку документа, может выглядеть так:

```tsx
import type { ReactNode } from 'react';
import { LocaleProvider } from '@moduix/react/locale';

export function Document({ children }: { children: ReactNode }) {
  return (
    <html lang="ar" dir="rtl">
      <body>
        <LocaleProvider locale="ar-EG">{children}</LocaleProvider>
      </body>
    </html>
  );
}
```

`LocaleProvider` вычисляет направление Ark по локали, поэтому компоненты Ark, учитывающие локаль, и форматтеры Ark
используют один и тот же контекст. Провайдер не меняет нативные атрибуты документа. Оставьте `lang` и `dir` на
`<html>`, чтобы браузер применял это направление к тексту, логическим CSS-свойствам и содержимому, отрисованному
через портал.

Если пользователи могут переключать локаль с LTR на RTL без перезагрузки страницы, одновременно с `locale` в
`LocaleProvider` обновляйте `lang` и `dir` документа.

## Пример компонента

Если RTL-раздел находится внутри приложения с направлением слева направо, задайте `dir` и `lang` на корневом
элементе этого раздела и оберните его компоненты moduix в `LocaleProvider`. Если RTL используется во всём документе,
достаточно настройки выше, и дополнительная оболочка не нужна.

```tsx
import { createListCollection } from '@ark-ui/react/collection';
import { Button } from '@moduix/react/button';
import { LocaleProvider } from '@moduix/react/locale';
import { Select } from '@moduix/react/select';

const cities = createListCollection({
  items: [
    { label: 'القاهرة', value: 'cairo' },
    { label: 'الإسكندرية', value: 'alexandria' },
  ],
});

export function ArabicPreferences() {
  return (
    <div dir="rtl" lang="ar">
      <LocaleProvider locale="ar-EG">
        <Select collection={cities}>
          <Select.Label>المدينة</Select.Label>
          <Select.Field placeholder="اختر مدينة" />
          <Select.Positioner>
            <Select.Content>
              <Select.ItemGroup>
                {cities.items.map((city) => (
                  <Select.Item key={city.value} item={city}>
                    <Select.ItemText>{city.label}</Select.ItemText>
                    <Select.ItemIndicator />
                  </Select.Item>
                ))}
              </Select.ItemGroup>
            </Select.Content>
          </Select.Positioner>
        </Select>
        <Button>حفظ</Button>
      </LocaleProvider>
    </div>
  );
}
```

Коллекция в примере создаётся с помощью Ark UI, а `Select`, `Button` и `LocaleProvider` импортируются из moduix.
Компоненты получают направление из контекста локали, поэтому отдельный RTL-проп им не нужен.

## Порталы и смешанное направление

Оверлей, отрисованный через портал, наследует направление CSS от DOM-контейнера, в который он помещён, а не от
триггера. Для RTL всего приложения задайте `dir` на `<html>`. Если используется свой контейнер портала, разместите
его внутри RTL-поддерева.

Когда в интерфейсе встречается текст с разным направлением, оставьте направление приложения на внешнем контейнере и
переопределяйте его только для нужных значений. Используйте `dir="auto"` для обычного текста с неизвестным
направлением и `dir="ltr"` для значений, которые должны сохранять направление слева направо, например для адресов
электронной почты, URL, кода и телефонных номеров.

## Стили

Используйте логические CSS-свойства, если правило зависит от начала или конца строки. Например, задавайте
`padding-inline`, `inset-inline-end`, `border-inline-start` и `text-align: start`. Тогда одни и те же стили будут
работать при любом направлении текста.

Оставляйте физические `left` и `right`, только если они описывают геометрию экрана: например, координату индикатора,
край изменения размера или явное направление свайпа. Не заменяйте их механически: они могут описывать измеренное
положение или жест, а не порядок чтения.

Зеркально отражайте иконки, смысл которых зависит от направления строки: «назад», «вперёд», «отменить» или «повторить».
Не отражайте иконки с фиксированным значением, например «воспроизвести», «проверить», «скачать» или логотип бренда.
Если в библиотеке иконок есть RTL-вариант, используйте его. В противном случае применяйте трансформацию только
внутри RTL-области.

## Чек-лист перед выпуском

После изменения кода компоновки проверьте интерфейс с RTL-локалью, особенно:

- поля ввода с кнопками очистки или действий;
- триггеры select, combobox и date picker;
- диалоги, popover, меню и tooltip, отрисованные через портал;
- клавиатурную навигацию и видимый порядок фокуса;
- арабский или ивритский текст вместе с адресами электронной почты, числами и кодом;
- направленные иконки, жесты свайпа и выравнивание по началу или концу строки на узких экранах.

`LocaleProvider` и контекст локали переэкспортируются из Ark UI через moduix. См. страницу [Locale](/docs/locale), где
описаны контекст локали и форматирование, а также [документацию Ark Locale](https://ark-ui.com/docs/utilities/locale) с
описанием API провайдера.
