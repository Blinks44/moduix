# Справа налево (RTL)

Для RTL нужны две настройки: направление документа в браузере и контекст локали Ark. Установите `dir="rtl"` на
корневом элементе документа, затем оберните приложение в `LocaleProvider` из moduix.

```tsx
import type { ReactNode } from 'react';
import { LocaleProvider } from '@moduix/react/locale';

export function Document({ children }: { children: ReactNode }) {
  return (
    <html lang="ar" dir="rtl">
      <body>
        <LocaleProvider locale="ar-EG">{children}</LocaleProvider>
      </body>
    </html>
  );
}
```

`LocaleProvider` определяет значение `dir` для Ark по локали, поэтому примитивы с поддержкой локали и форматтеры
Ark используют единый источник истины. Нативный атрибут `dir` всё равно необходим: он задаёт направление текста и
работу логических CSS-свойств в браузере.

## Пример компонента

Добавьте провайдер один раз рядом с корнем приложения - отдельным компонентам moduix специальный RTL-проп не нужен.

```tsx
import { createListCollection } from '@ark-ui/react/collection';
import { Button } from '@moduix/react/button';
import { LocaleProvider } from '@moduix/react/locale';
import { Select } from '@moduix/react/select';

const cities = createListCollection({
  items: [
    { label: 'القاهرة', value: 'cairo' },
    { label: 'الإسكندرية', value: 'alexandria' },
  ],
});

export function ArabicPreferences() {
  return (
    <div dir="rtl" lang="ar">
      <LocaleProvider locale="ar-EG">
        <Select collection={cities}>
          <Select.Label>المدينة</Select.Label>
          <Select.Field placeholder="اختر مدينة" />
          <Select.Positioner>
            <Select.Content>
              <Select.ItemGroup>
                {cities.items.map((city) => (
                  <Select.Item key={city.value} item={city}>
                    <Select.ItemText>{city.label}</Select.ItemText>
                    <Select.ItemIndicator />
                  </Select.Item>
                ))}
              </Select.ItemGroup>
            </Select.Content>
          </Select.Positioner>
        </Select>
        <Button>حفظ</Button>
      </LocaleProvider>
    </div>
  );
}
```

Для оверлеев, отрисовываемых через портал, установите `dir` на `<html>` или используйте контейнер портала внутри
RTL-поддерева. Тогда текст оверлея, позиционирование по строке и токены останутся в той же области, что и триггер.

Для контента со смешанным направлением задавайте направление приложения на внешнем контейнере и переопределяйте его
только для пользовательских значений, которым это действительно нужно. Используйте `dir="auto"` для обычного текста
с неизвестным направлением и `dir="ltr"` для значений, чей физический порядок нужно сохранить: адресов электронной
почты, URL, кода и телефонных номеров.

## Стили

Для RTL-совместимых стилей используйте логические CSS-свойства, когда правило означает «начало» или «конец»:
например, `padding-inline`, `inset-inline-end`, `border-inline-start` и `text-align: start`. Тогда один и тот же
макет компонента будет следовать окружающему направлению.

Оставляйте физические `left` и `right`, только если они обозначают реальную геометрию экрана: например, координаты
индикатора Ark, край изменения размера или явное направление свайпа. Не заменяйте их механически - они описывают
измеренное положение или жест, а не порядок чтения.

Зеркально отражайте иконки, выражающие направление в строке: «назад», «вперёд», «отменить» или «повторить». Не
отражайте иконки с фиксированным значением, такие как «воспроизвести», «проверить», «скачать» или логотип бренда.
Если библиотека иконок предоставляет RTL-вариант, используйте его; в противном случае применяйте трансформацию
только внутри RTL-области.

## Чек-лист

Перед выпуском проверяйте интерфейс с RTL-локалью после изменения кода макета, особенно:

- поля ввода с кнопками очистки или действий;
- триггеры select, combobox и date-picker;
- диалоги, popover, меню и tooltip, отрисовываемые через портал;
- клавиатурную навигацию и видимый порядок фокуса;
- смешанный арабский или ивритский текст с адресами электронной почты, числами и кодом;
- направленные иконки, жесты свайпа и выравнивание по началу/концу при узкой ширине.

Ark отвечает за направление в примитивах. API провайдера и контекст локали описаны в
[документации Ark Locale](https://ark-ui.com/docs/utilities/locale).
