# Справа налево (RTL)

Для RTL нужны две небольшие настройки: направление документа в браузере и контекст локали Ark. Установите
`dir="rtl"` на корневом элементе документа, затем оберните приложение в `LocaleProvider` из moduix.

```tsx
import type { ReactNode } from 'react';
import { LocaleProvider } from '@moduix/react/locale';

export function Document({ children }: { children: ReactNode }) {
  return (
    <html lang="ar" dir="rtl">
      <body>
        <LocaleProvider locale="ar-EG">{children}</LocaleProvider>
      </body>
    </html>
  );
}
```

`LocaleProvider` определяет значение `dir` Ark по локали, поэтому примитивы с поддержкой локали и
форматтеры Ark используют единый источник истины. Нативный атрибут `dir` всё равно необходим: он управляет
направлением текста и логическими CSS-свойствами в браузере.

## Пример компонента

Используйте провайдер один раз рядом с корнем приложения; отдельным компонентам moduix не нужен
специальный RTL-проп.

```tsx
import { createListCollection } from '@ark-ui/react/collection';
import { Button } from '@moduix/react/button';
import { LocaleProvider } from '@moduix/react/locale';
import { Select } from '@moduix/react/select';

const cities = createListCollection({
  items: [
    { label: 'القاهرة', value: 'cairo' },
    { label: 'الإسكندرية', value: 'alexandria' },
  ],
});

export function ArabicPreferences() {
  return (
    <div dir="rtl" lang="ar">
      <LocaleProvider locale="ar-EG">
        <Select collection={cities}>
          <Select.Label>المدينة</Select.Label>
          <Select.Field placeholder="اختر مدينة" />
          <Select.Positioner>
            <Select.Content>
              <Select.ItemGroup>
                {cities.items.map((city) => (
                  <Select.Item key={city.value} item={city}>
                    <Select.ItemText>{city.label}</Select.ItemText>
                    <Select.ItemIndicator />
                  </Select.Item>
                ))}
              </Select.ItemGroup>
            </Select.Content>
          </Select.Positioner>
        </Select>
        <Button>حفظ</Button>
      </LocaleProvider>
    </div>
  );
}
```

Для оверлеев, отрисовываемых через портал, установите `dir` на `<html>` или используйте контейнер
портала внутри RTL-поддерева. Так текст оверлея, позиционирование по строке и токены останутся в той же
области, что и его триггер.

Для контента со смешанным направлением сохраняйте направление приложения на внешнем контейнере и
устанавливайте наименьшее корректное переопределение для значений, предоставляемых пользователями.
Используйте `dir="auto"` для неизвестного обычного текста и `dir="ltr"` для значений, которым необходимо
сохранить физический порядок, например адресов электронной почты, URL, кода и телефонных номеров.

## Контракт стилизации

Новые стили moduix используют логические CSS-свойства, когда правило означает «начало» или «конец»:
например, `padding-inline`, `inset-inline-end`, `border-inline-start` и `text-align: start`. Благодаря
этому один и тот же макет компонента следует окружающему направлению.

Сохраняйте физические `left` и `right`, только если они обозначают фактическую геометрию экрана, например
координаты индикатора Ark, край изменения размера или явное направление свайпа. Не заменяйте эти значения
механически: они описывают измеренное положение или жест, а не порядок чтения.

Отражайте зеркально иконки, выражающие направление в строке, например «назад», «вперёд», «отменить» или
«повторить». Не отражайте иконки с фиксированным значением, такие как «воспроизвести», «проверить»,
«скачать» или логотип бренда. Если библиотека иконок предоставляет вариант для RTL, используйте его; в
противном случае применяйте трансформацию только внутри RTL-области.

## Проверьте перед выпуском

Проверяйте интерфейс с RTL-локалью после изменения кода макета, особенно:

- поля ввода с кнопками очистки или действий;
- триггеры select, combobox и date-picker;
- диалоги, popover, меню и tooltip, отрисовываемые через портал;
- клавиатурную навигацию и видимый порядок фокуса;
- смешанный арабский или ивритский текст с адресами электронной почты, числами и кодом;
- направленные иконки, жесты свайпа и выравнивание по началу/концу при узкой ширине.

Ark отвечает за поведение направления в примитивах. API провайдера и контракт контекста локали описаны в
[документации Ark Locale](https://ark-ui.com/docs/utilities/locale).
