# Переход с shadcn на moduix

Если приложение уже использует shadcn, переход на moduix можно выполнять по одному компоненту.
Пока вы переносите отдельные экраны или семейства компонентов, обе библиотеки могут работать
рядом.

Главный выбор касается исходников компонентов. Подключите npm-пакет, если хотите получать
обновления через пакетный менеджер. Выберите совместимый с shadcn реестр, если исходники и стили
должны храниться в вашем репозитории.
Выбирайте React для замены компонентов внутри существующего приложения shadcn. Solid подходит,
только если приложение уже работает на Solid или переход также включает осознанную смену фреймворка.

## Где хранить исходники компонентов

| Способ установки moduix | Подходит, если | Как приходят обновления |
| --- | --- | --- |
| npm-пакет | Компоненты должны оставаться зависимостью, а импорты идти из `@moduix/react/*` или `@moduix/solid/*`. | Обновляйте пакет через пакетный менеджер. |
| Реестр, совместимый с shadcn | Вы хотите хранить исходники в приложении, просматривать их и менять напрямую. | Проверяйте и объединяйте каждое обновление реестра вручную. |

Полная настройка описана в [Быстром старте](/docs/quick-start). Если в проекте уже настроены CLI
shadcn и `components.json`, оставьте их. Добавьте реестр moduix и алиасы из инструкции.

## Установите moduix рядом с существующими компонентами shadcn

Сохраняйте текущие импорты shadcn и переносите компоненты постепенно. При установке через npm
подключайте каждый компонент из отдельного подпути:

<Tabs groupId="framework">
  <Tab label="React" value="react">

```tsx
import { Dialog } from '@moduix/react/dialog';
```

  </Tab>
  <Tab label="Solid" value="solid">

```tsx
import { Dialog } from '@moduix/solid/dialog';
```

  </Tab>
</Tabs>

При установке с исходниками сначала выполните [настройку CLI shadcn](/docs/quick-start#установить-через-shadcn-cli),
а затем добавляйте элементы реестра по одному:

<Tabs groupId="framework">
  <Tab label="React" value="react">

<PackageManagerTabs command="shadcn@latest add @moduix-react/dialog" dlx />

  </Tab>
  <Tab label="Solid" value="solid">

<PackageManagerTabs command="shadcn@latest add @moduix-solid/dialog" dlx />

  </Tab>
</Tabs>

CLI запишет исходники компонента и нужные зависимости moduix по алиасам из `components.json`.
Импортируйте созданный компонент из приложения:

```tsx
import { Dialog } from '@/components/ui/dialog';
```

## Найдите ближайший эквивалент

В moduix компонент обычно назван по взаимодействию, которое он реализует. В таблице указаны
соответствия с привычными именами shadcn и изменения, важные при переходе.

| Знакомое имя shadcn | Используйте в moduix | Что изменить |
| --- | --- | --- |
| Accordion | [`Accordion`](/docs/accordion) | Используйте именованные части, например `AccordionItem` и `AccordionItemContent`. |
| Alert Dialog | [`Dialog`](/docs/dialog) | Для критического подтверждения укажите `role="alertdialog"` на `DialogContent`. |
| Avatar | [`Avatar`](/docs/avatar) | Поместите резервное содержимое и изображение в `AvatarFallback` и `AvatarImage`. |
| Breadcrumb | [`Breadcrumbs`](/docs/breadcrumbs) | Название семейства стоит во множественном числе; сохраните семантические ссылки и отметку текущей страницы. |
| Calendar | [`DatePicker`](/docs/date-picker) или [`DateInput`](/docs/date-input) | Выберите `DatePicker` для календаря, а `DateInput`, если нужны только редактируемые сегменты даты. |
| Carousel | [`Carousel`](/docs/carousel) | Соберите управление, индикаторы и группу элементов из именованных частей. |
| Collapsible | [`Collapsible`](/docs/collapsible) | В `onOpenChange(details)` читайте `details.open`, а не принимайте boolean. |
| Combobox | [`Combobox`](/docs/combobox) | Создайте коллекцию Ark и задайте значения элементов, если элементы представлены объектами. |
| Command | [`CommandPalette`](/docs/command-palette) | Используйте компонент для команд, а не общий псевдоним списка. |
| Context Menu | [`MenuContextTrigger`](/docs/menu) | Оставьте семейство `Menu` и используйте его контекстный триггер. |
| Data Table | [`Table`](/docs/table) и [рецепт Data Table](/recipes/data-table) | Сортировку, фильтрацию и серверное состояние оставьте в коде приложения. |
| Date Picker | [`DatePicker`](/docs/date-picker) | Используйте составное семейство для ввода даты и календаря. |
| Dropdown Menu | [`Menu`](/docs/menu) | Соберите обычный вариант через `MenuTrigger`. |
| Form | [`Field`](/docs/field) и [`Fieldset`](/docs/fieldset) | Используйте их для структуры полей, а валидацию и отправку оставьте библиотеке форм или приложению. |
| Hover Card | [`HoverCard`](/docs/hover-card) | Проверьте на странице компонента явные части для позиционирования и закрытия. |
| Input OTP | [`PinInput`](/docs/pin-input) | Сохраните его настройку для нативных форм и SSR. |
| Progress | [`ProgressLinear`](/docs/progress-linear) или [`ProgressCircular`](/docs/progress-circular) | Явно выберите нужный вид индикатора. |
| Resizable | [`Splitter`](/docs/splitter) | Задайте панелям стабильные id и храните состояние раскладки явно. |
| Select | [`Select`](/docs/select) | Используйте коллекцию Ark, а не произвольный массив объектов option. |
| Sheet | [`Drawer`](/docs/drawer) | Используйте компонент боковой панели с жизненным циклом, согласованным с Dialog. |
| Sidebar | [`Sidebar`](/docs/sidebar) | Оставьте структуру продуктовой и адаптивной навигации в приложении. |
| Sonner / Toast | [`Toast`](/docs/toast) и [`Toaster`](/docs/toast) | Текст уведомлений и момент их показа должны контролироваться приложением. |
| Tabs | [`Tabs`](/docs/tabs) | Используйте плоские части `TabsList` и `TabsTrigger` для того же взаимодействия. |
| Toggle Group | [`ToggleGroup`](/docs/toggle-group) | Используйте значения элементов и состояние группы из контракта Ark. |
| Tooltip | [`Tooltip`](/docs/tooltip) | Явно задайте триггер и содержимое, которое рендерится через портал. |

Для Navigation Menu и Menubar не нужно искать обязательную замену один к одному. Выберите
`Sidebar`, `Menu`, `Breadcrumbs` или обычные ссылки в зависимости от нужного взаимодействия.

## Адаптируйте импорты

В shadcn части компонента обычно экспортируются как отдельные локальные символы:

```tsx
import { Dialog, DialogContent, DialogTitle, DialogTrigger } from '@/components/ui/dialog';
```

В moduix все фреймворки используют одинаковые плоские экспорты с префиксом семейства:

```tsx
import { Accordion, AccordionItem, AccordionItemContent, AccordionItemTrigger } from '@moduix/react/accordion';

export function FrequentlyAskedQuestions() {
  return (
    <Accordion defaultValue={['first']}>
      <AccordionItem value="first">
        <AccordionItemTrigger>What is moduix?</AccordionItemTrigger>
        <AccordionItemContent>A multi-framework component system.</AccordionItemContent>
      </AccordionItem>
    </Accordion>
  );
}
```

В Solid меняется только путь импорта:

```tsx
import { Accordion, AccordionItem, AccordionItemContent, AccordionItemTrigger } from '@moduix/solid/accordion';
```

При установке с исходниками сохраните композицию и замените только путь импорта:

```tsx
import { Accordion, AccordionItem, AccordionItemContent, AccordionItemTrigger } from '@/components/ui/accordion';
```

Имя семейства обозначает корневой компонент. Каждое дополнительное значение экспортируется отдельно
с префиксом семейства, без объекта-пространства имён и обращения через точку.

## Сохраните привычный подход к стилям

moduix поставляет готовые стили компонентов и общие токены `--moduix-*`. Подключите базовую
таблицу стилей один раз, а свои переопределения размещайте в CSS, который загружается после неё.

При установке npm-пакета на CSS Modules:

<Tabs groupId="framework">
  <Tab label="React" value="react">

```tsx
import '@moduix/react/style.css';
```

  </Tab>
  <Tab label="Solid" value="solid">

```tsx
import '@moduix/solid/style.css';
```

  </Tab>
</Tabs>

При установке через реестр на CSS Modules:

```tsx
import '@/lib/moduix/styles/style.css';
```

Семантические токены можно настроить в собственном CSS:

```css title="app.css"
:root {
  --moduix-color-accent: oklch(58% 0.18 260deg);
  --moduix-radius-md: 0.625rem;
}
```

Tailwind можно оставить в приложении для раскладки и отдельных утилитарных классов при переходе на
пакеты с CSS Modules. Если стили компонентов должны остаться на Tailwind, используйте отдельный
React- или Solid-пакет там, где нужный компонент уже доступен. На его странице указаны стабильные
слоты, CSS-переменные и свойства `className` или `class`.

## Адаптируйте обработчики Ark и коллекции

Обработчики Ark получают объект `details`. Доставайте нужное значение из него, а не переносите
колбэк shadcn, который ожидает позиционный аргумент:

```tsx
import { useState } from 'react';
import { Accordion, AccordionItem, AccordionItemContent, AccordionItemTrigger } from '@moduix/react/accordion';

export function ControlledAccordion() {
  const [value, setValue] = useState<string[]>([]);

  return (
    <Accordion value={value} onValueChange={(details) => setValue(details.value)}>
      <AccordionItem value="first">
        <AccordionItemTrigger>What is moduix?</AccordionItemTrigger>
        <AccordionItemContent>A multi-framework component system.</AccordionItemContent>
      </AccordionItem>
    </Accordion>
  );
}
```

В Solid `useState` заменяется на `createSignal` из `solid-js`, значение сигнала читается как `value()`,
а импорты меняются соответствующим образом:

```tsx
import { createSignal } from 'solid-js';
import { Accordion, AccordionItem, AccordionItemContent, AccordionItemTrigger } from '@moduix/solid/accordion';
```

Компоненты с коллекциями, например `Combobox` и `Select`, используют явное состояние коллекции
Ark. Для элементов-объектов задайте через `itemToString` и `itemToValue`, как получить видимый
текст и стабильное значение. Перед переносом массива `options` или обработчика из shadcn
проверьте страницу целевого компонента.

## Переносите интерфейс по частям

1. Подключите базовые стили moduix и разместите импорт раньше собственных переопределений.
2. Начните с компонентов с небольшим числом зависимостей: `Button`, `Badge`, `Avatar` и `Separator`.
3. Переносите всплывающие и коллекционные компоненты по одному семейству, включая части портала и обработчики состояния.
4. Используйте [рецепт](/recipes), только если описанный в нём сценарий экрана подходит вашему продукту.
5. Проверьте клавиатурное управление, возврат фокуса, подписи и важные ARIA-роли, затем удалите старые исходники и стили компонента.

Прикладная логика должна оставаться в приложении. Подписи, сообщения валидации, права доступа,
запросы к серверу и сценарии продукта не нужно прятать в общем компоненте-обёртке. Ark отвечает
за поведение примитива, а moduix предоставляет API компонентов, стили и настройки по умолчанию.

Для последующих обновлений пакета или реестра используйте [Обновление и миграция](/docs/updating).
Об адаптации существующих обёрток читайте в разделе [Паттерны композиции](/docs/composition-patterns).
