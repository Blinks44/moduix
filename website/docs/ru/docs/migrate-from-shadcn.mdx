# Переход с shadcn на moduix

Если приложение уже использует shadcn, переход на moduix можно выполнять по одному компоненту.
Пока вы переносите отдельные экраны или семейства компонентов, обе библиотеки могут работать
рядом.

Главный выбор касается исходников компонентов. Подключите npm-пакет, если хотите получать
обновления через пакетный менеджер. Выберите совместимый с shadcn реестр, если исходники и стили
должны храниться в вашем репозитории.

## Где хранить исходники компонентов

| Способ установки moduix | Подходит, если | Как приходят обновления |
| --- | --- | --- |
| npm-пакет | Компоненты должны оставаться зависимостью, а импорты идти из `@moduix/react/*`. | Обновляйте пакет через пакетный менеджер. |
| Реестр, совместимый с shadcn | Вы хотите хранить исходники в приложении, просматривать их и менять напрямую. | Проверяйте и объединяйте каждое обновление реестра вручную. |

Полная настройка описана в [Быстром старте](/docs/quick-start). Если в проекте уже настроены CLI
shadcn и `components.json`, оставьте их. Добавьте реестр moduix и алиасы из инструкции.

## Установите moduix рядом с существующими компонентами shadcn

Сохраняйте текущие импорты shadcn и переносите компоненты постепенно. При установке через npm
подключайте каждый компонент из отдельного подпути:

```tsx
import { Dialog } from '@moduix/react/dialog';
```

При установке с исходниками сначала выполните [настройку CLI shadcn](/docs/quick-start#установить-через-shadcn-cli),
а затем добавляйте элементы реестра по одному:

```bash
npx shadcn@latest add @moduix-react/dialog
```

CLI запишет исходники компонента и нужные зависимости moduix по алиасам из `components.json`.
Импортируйте созданный компонент из приложения:

```tsx
import { Dialog } from '@/components/moduix/dialog';
```

## Найдите ближайший эквивалент

В moduix компонент обычно назван по взаимодействию, которое он реализует. В таблице указаны
соответствия с привычными именами shadcn и изменения, важные при переходе.

| Знакомое имя shadcn | Используйте в moduix | Что изменить |
| --- | --- | --- |
| Accordion | `Accordion` | Используйте именованные части, например `Accordion.Item` и `Accordion.Content`. |
| Alert Dialog | `Dialog` | Для критического подтверждения укажите `role="alertdialog"` на `Dialog.Content`. |
| Avatar | `Avatar` | Поместите резервное содержимое и изображение в `Avatar.Fallback` и `Avatar.Image`. |
| Breadcrumb | `Breadcrumbs` | Название семейства стоит во множественном числе; сохраните семантические ссылки и отметку текущей страницы. |
| Calendar | `DatePicker` или `DateInput` | Выберите `DatePicker` для календаря, а `DateInput`, если нужны только редактируемые сегменты даты. |
| Carousel | `Carousel` | Соберите управление, индикаторы и группу элементов из именованных частей. |
| Collapsible | `Collapsible` | В `onOpenChange(details)` читайте `details.open`, а не принимайте boolean. |
| Combobox | `Combobox` | Создайте коллекцию Ark и задайте значения элементов, если элементы представлены объектами. |
| Command | `CommandPalette` | Используйте компонент для команд, а не общий псевдоним списка. |
| Context Menu | `Menu.ContextTrigger` | Оставьте семейство `Menu` и используйте его контекстный триггер. |
| Data Table | `Table` и рецепт Data Table | Сортировку, фильтрацию и серверное состояние оставьте в коде приложения. |
| Date Picker | `DatePicker` | Используйте составное семейство для ввода даты и календаря. |
| Dropdown Menu | `Menu` | Соберите обычный вариант через `Menu.Trigger`. |
| Form | `Field` и `Fieldset` | Используйте их для структуры полей, а валидацию и отправку оставьте библиотеке форм или приложению. |
| Hover Card | `HoverCard` | Проверьте на странице компонента явные части для позиционирования и закрытия. |
| Input OTP | `PinInput` | Сохраните его настройку для нативных форм и SSR. |
| Progress | `ProgressLinear` или `ProgressCircular` | Явно выберите нужный вид индикатора. |
| Resizable | `Splitter` | Задайте панелям стабильные id и храните состояние раскладки явно. |
| Select | `Select` | Используйте коллекцию Ark, а не произвольный массив объектов option. |
| Sheet | `Drawer` | Используйте компонент боковой панели с жизненным циклом, согласованным с Dialog. |
| Sidebar | `Sidebar` | Оставьте структуру продуктовой и адаптивной навигации в приложении. |
| Sonner / Toast | `Toast` и `Toaster` | Текст уведомлений и момент их показа должны контролироваться приложением. |
| Tabs | `Tabs` | Соберите то же взаимодействие из именованных составных частей. |
| Toggle Group | `ToggleGroup` | Используйте значения элементов и состояние группы из контракта Ark. |
| Tooltip | `Tooltip` | Явно задайте триггер и содержимое, которое рендерится через портал. |

Для Navigation Menu и Menubar не нужно искать обязательную замену один к одному. Выберите
`Sidebar`, `Menu`, `Breadcrumbs` или обычные ссылки в зависимости от нужного взаимодействия.

## Адаптируйте импорты

В shadcn части компонента обычно экспортируются как отдельные локальные символы:

```tsx
import { Dialog, DialogContent, DialogTitle, DialogTrigger } from '@/components/ui/dialog';
```

В moduix всё семейство собрано под одним пространством имён:

```tsx
import { Dialog } from '@moduix/react/dialog';

export function ProjectSettingsDialog() {
  return (
    <Dialog>
      <Dialog.Trigger>Open settings</Dialog.Trigger>
      <Dialog.Backdrop />
      <Dialog.Positioner>
        <Dialog.Content>
          <Dialog.Title>Project settings</Dialog.Title>
          <Dialog.CloseTrigger>Close</Dialog.CloseTrigger>
        </Dialog.Content>
      </Dialog.Positioner>
    </Dialog>
  );
}
```

При установке с исходниками сохраните композицию и замените только путь импорта:

```tsx
import { Dialog } from '@/components/moduix/dialog';
```

Явные части `Backdrop`, `Positioner` и `Content` показывают, кто отвечает за портал,
позиционирование и поверхность диалога. Их можно настраивать независимо.

## Сохраните привычный подход к стилям

moduix поставляет готовые стили компонентов и общие токены `--moduix-*`. Подключите базовую
таблицу стилей один раз, а свои переопределения размещайте в CSS, который загружается после неё.

При установке npm-пакета:

```tsx
import '@moduix/react/style.css';
```

При установке через реестр shadcn:

```tsx
import '@/lib/moduix/styles/style.css';
```

Семантические токены можно настроить в собственном CSS:

```css title="app.css"
:root {
  --moduix-color-accent: oklch(58% 0.18 260deg);
  --moduix-radius-md: 0.625rem;
}
```

Tailwind можно оставить в приложении для раскладки и отдельных utility-классов. Перед заменой
компонента не нужно переписывать все существующие классы. На странице нужного компонента ищите
стабильные слоты, CSS-переменные и свойства `className`.

## Адаптируйте обработчики Ark и коллекции

Обработчики Ark получают объект `details`. Доставайте нужное значение из него, а не переносите
колбэк shadcn, который ожидает позиционный аргумент:

```tsx
import { useState } from 'react';
import { Dialog } from '@moduix/react/dialog';

export function ControlledDialog() {
  const [open, setOpen] = useState(false);

  return (
    <Dialog open={open} onOpenChange={(details) => setOpen(details.open)}>
      <Dialog.Trigger>Open dialog</Dialog.Trigger>
      <Dialog.Backdrop />
      <Dialog.Positioner>
        <Dialog.Content>
          <Dialog.Title>Project settings</Dialog.Title>
          <Dialog.CloseTrigger>Close</Dialog.CloseTrigger>
        </Dialog.Content>
      </Dialog.Positioner>
    </Dialog>
  );
}
```

Компоненты с коллекциями, например `Combobox` и `Select`, используют явное состояние коллекции
Ark. Для элементов-объектов задайте через `itemToString` и `itemToValue`, как получить видимый
текст и стабильное значение. Перед переносом массива `options` или обработчика из shadcn
проверьте страницу целевого компонента.

## Переносите интерфейс по частям

1. Подключите базовые стили moduix и разместите импорт раньше собственных переопределений.
2. Начните с компонентов с небольшим числом зависимостей: `Button`, `Badge`, `Avatar` и `Separator`.
3. Переносите всплывающие и коллекционные компоненты по одному семейству, включая части портала и обработчики состояния.
4. Используйте [рецепт](/recipes), только если описанный в нём сценарий экрана подходит вашему продукту.
5. Проверьте клавиатурное управление, возврат фокуса, подписи и важные ARIA-роли, затем удалите старые исходники и стили компонента.

Прикладная логика должна оставаться в приложении. Подписи, сообщения валидации, права доступа,
запросы к серверу и сценарии продукта не нужно прятать в общем wrapper-компоненте. Ark отвечает
за поведение примитива, а moduix предоставляет API компонентов, стили и настройки по умолчанию.

Для последующих обновлений пакета или реестра используйте [Обновление и миграция](/docs/updating).
Об адаптации существующих обёрток читайте в разделе [Паттерны композиции](/docs/composition-patterns).
