# Переход с shadcn

moduix сохраняет привычные стороны shadcn, которые упрощают внедрение: исходный код в проекте, `components.json` и
установку из реестра. Основные отличия - единообразные названия компонентов, составные API в стиле Ark и CSS на
основе токенов, не зависящий от Tailwind.

Не нужно переносить всё приложение за один раз. Начните с одного экрана или семейства компонентов: пока переход
идёт, shadcn и moduix могут использоваться рядом.

## Выберите способ владения кодом

| Вариант moduix | Выберите его, если | Как обновлять |
| --- | --- | --- |
| npm-пакет | Вам нужны обновления через менеджер пакетов и стабильные импорты из `@moduix/react/*`. | Обновляйте пакет. |
| Реестр, совместимый с shadcn | Исходный код и стили должны находиться в вашем репозитории. | Просматривайте и применяйте обновления из реестра. |

Полная настройка описана в [Быстром старте](/docs/quick-start). Если вы уже используете shadcn, оставьте CLI и
`components.json`, а затем добавьте реестр moduix и указанные там алиасы.

## Найдите эквивалентный компонент

moduix обычно называет компоненты по взаимодействию, лежащему в их основе, а не использует узкие продуктовые
псевдонимы.

| Знакомое имя в shadcn | Используйте в moduix | Примечание по миграции |
| --- | --- | --- |
| Accordion | `Accordion` | То же взаимодействие, оформленное через составные части в одном пространстве имён. |
| Alert Dialog | `Dialog` | Укажите `role="alertdialog"`; отдельный псевдоним не нужен. |
| Avatar | `Avatar` | Перенесите fallback и изображение в части `Avatar`. |
| Breadcrumb | `Breadcrumbs` | Название семейства во множественном числе; сохраните семантические ссылки и состояние текущей страницы. |
| Calendar | `DatePicker` | Используйте представление календаря; не создавайте второе публичное семейство. |
| Carousel | `Carousel` | Управление, индикаторы и группа элементов устроены в стиле Ark. |
| Collapsible | `Collapsible` | Используйте объект `details` из `onOpenChange` вместо колбэка, получающего один boolean. |
| Combobox | `Combobox` | Состояние коллекции и значения элементов следуют контрактам Ark. |
| Command | `CommandPalette` | Готовый интерфейс для поиска и команд, а не общий псевдоним списка. |
| Context Menu | `Menu.ContextTrigger` | То же семейство `Menu` с контекстным триггером. |
| Data Table | `Table` + рецепт Data Table | Сортировку, фильтрацию и серверное состояние оставьте в коде приложения. |
| Date Picker | `DatePicker` | Единое составное семейство для ввода даты и календаря. |
| Dropdown Menu | `Menu` | Используйте обычный вариант `Menu.Trigger`. |
| Form | `Field` и `Fieldset` | Валидацию и отправку оставьте библиотеке форм или приложению. |
| Hover Card | `HoverCard` | Та же задача, но с деталями позиционирования и жизненного цикла Ark. |
| Input OTP | `PinInput` | Нативная работа с формами и SSR входят в контракт компонента. |
| Progress | `ProgressLinear` или `ProgressCircular` | Явно выберите визуальную форму. |
| Resizable | `Splitter` | Панели используют стабильные идентификаторы и явное состояние макета. |
| Select | `Select` | Элементы используют коллекцию Ark вместо произвольных объектов option. |
| Sheet | `Drawer` | Панель у края экрана с жизненным циклом, согласованным с Dialog. |
| Sidebar | `Sidebar` | Сохраняйте составную структуру адаптивной навигации продукта. |
| Sonner / Toast | `Toast` | Единая поверхность уведомлений с сообщениями, которыми управляет приложение. |
| Tabs | `Tabs` | То же взаимодействие с именованными составными частями. |
| Toggle Group | `ToggleGroup` | Значения элементов и состояние группы берите из контракта Ark. |
| Tooltip | `Tooltip` | Триггер и содержимое в портале остаются явными. |

Не стоит искусственно искать точные соответствия для Navigation Menu и Menubar. Выбирайте `Sidebar`, `Menu`,
`Breadcrumbs` или обычные ссылки в зависимости от нужного взаимодействия.

## Измените организацию импортов

shadcn обычно экспортирует каждую часть отдельным локальным символом:

```tsx
import { Dialog, DialogContent, DialogTitle, DialogTrigger } from '@/components/ui/dialog';
```

moduix собирает семейство компонентов в одном пространстве имён:

```tsx
import { Dialog } from '@moduix/react/dialog';

<Dialog>
  <Dialog.Trigger>Open</Dialog.Trigger>
  <Dialog.Backdrop />
  <Dialog.Positioner>
    <Dialog.Content>
      <Dialog.Title>Project settings</Dialog.Title>
    </Dialog.Content>
  </Dialog.Positioner>
</Dialog>;
```

При установке с исходным кодом в проекте меняется только путь импорта:

```tsx
import { Dialog } from '@/components/moduix/dialog';
```

Явно описанные части `Backdrop`, `Positioner` и `Content` упрощают настройку портала и макета.

## Перенесите стили без полной переработки

moduix поставляет готовые стили и общие токены `--moduix-*`. Подключите базовый файл стилей один раз, а затем
настройте семантические токены в CSS, который загружается после неё:

```css title="app.css"
:root {
  --moduix-color-accent: oklch(58% 0.18 260deg);
  --moduix-radius-md: 0.625rem;
}
```

Tailwind можно оставить в приложении для макета и единичных утилитарных классов. Он не нужен moduix, и перед заменой
компонента не требуется переносить каждую существующую утилиту. На страницах компонентов перечислены стабильные
слоты, CSS-переменные и свойства `className` для локальных исключений.

## Приведите обработчики состояния к формату Ark

Ark передаёт в обработчики объект `details`, чтобы контракт можно было расширять без позиционных аргументов:

```tsx
<Dialog open={open} onOpenChange={(details) => setOpen(details.open)}>
  {/* parts */}
</Dialog>
```

Компоненты с коллекциями также используют стабильные значения элементов и явное состояние коллекции. Прежде чем
копировать колбэк shadcn или структуру `option` без изменений, проверьте страницу целевого компонента.

## Мигрируйте небольшими шагами

1. Добавьте таблицу стилей основы и токены moduix.
2. Замените компоненты с небольшим числом зависимостей: Button, Badge, Avatar и Separator.
3. Переносите оверлеи и коллекции по одному семейству, включая их части портала и состояния.
4. Заменяйте паттерны на уровне экрана [рецептами](/recipes), только если они соответствуют сценарию продукта.
5. После проверки экрана удалите старые исходники компонента и его стили.

Не переносите в библиотеку то, что должно оставаться в приложении: метки, сообщения валидации, разрешения, серверные
вызовы и продуктовый сценарий. Ark отвечает за поведение примитивов, а moduix - за контракт обёртки, стили и
значения по умолчанию.

Для последующих обновлений пакета или реестра используйте [Обновление и миграция](/docs/updating), а при адаптации
существующих обёрток - [Паттерны композиции](/docs/composition-patterns).
