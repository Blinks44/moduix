# Переход с shadcn

moduix сохраняет то, что упрощает внедрение shadcn: исходный код в проекте, `components.json` и установку из реестра.
Главные различия - системные имена компонентов, составные API в стиле Ark и CSS на основе токенов, которому не нужен
Tailwind.

Не обязательно мигрировать всё приложение сразу. Начните с одного экрана или семейства компонентов и оставьте
компоненты shadcn рядом с moduix, пока работа продолжается.

## Выберите модель владения

| Способ работы с moduix | Выберите его, если | Обновления |
| --- | --- | --- |
| npm-пакет | Вам нужны обновления через менеджер пакетов и стабильные импорты из `@moduix/react/*`. | Обновляйте пакет. |
| Реестр, совместимый с shadcn | Исходный код и стили должны находиться в вашем репозитории. | Просматривайте и применяйте обновления из реестра. |

Полная настройка описана в [Быстром старте](/docs/quick-start). Пользователи shadcn могут оставить CLI и
`components.json`: добавьте реестр moduix и алиасы, показанные там.

## Найдите эквивалентный компонент

moduix обычно использует имя базового взаимодействия вместо специфичного для продукта псевдонима.

| Знакомое имя в shadcn | Используйте в moduix | Примечание по миграции |
| --- | --- | --- |
| Accordion | `Accordion` | То же взаимодействие, выраженное через части в пространстве имён. |
| Alert Dialog | `Dialog` | Задайте `role="alertdialog"`; отдельный псевдоним не нужен. |
| Avatar | `Avatar` | Переместите fallback и изображение в части `Avatar`. |
| Breadcrumb | `Breadcrumbs` | Множественное имя семейства; сохраните семантические ссылки и состояние текущей страницы. |
| Calendar | `DatePicker` | Используйте его представление календаря, не создавая второе публичное семейство. |
| Carousel | `Carousel` | Элементы управления, индикаторы и группа элементов в стиле Ark. |
| Collapsible | `Collapsible` | Используйте объект `details` из `onOpenChange` вместо колбэка с одним boolean-значением. |
| Combobox | `Combobox` | Состояние коллекции и значения элементов следуют контрактам Ark. |
| Command | `CommandPalette` | Готовый сценарий поиска и команд, а не универсальный псевдоним списка. |
| Context Menu | `Menu.ContextTrigger` | То же семейство `Menu` с контекстным триггером. |
| Data Table | `Table` + рецепт Data Table | Сортировку, фильтрацию и серверное состояние оставьте в коде приложения. |
| Date Picker | `DatePicker` | Одно составное семейство ввода дат и календаря. |
| Dropdown Menu | `Menu` | Используйте обычный путь `Menu.Trigger`. |
| Form | `Field` и `Fieldset` | Валидацию и отправку формы оставьте библиотеке форм или приложению. |
| Hover Card | `HoverCard` | Похожее назначение с деталями позиционирования и жизненного цикла Ark. |
| Input OTP | `PinInput` | Нативная форма и поведение SSR входят в контракт компонента. |
| Progress | `ProgressLinear` или `ProgressCircular` | Явно выберите визуальную форму. |
| Resizable | `Splitter` | Панели используют стабильные id и явное состояние макета. |
| Select | `Select` | Элементы используют коллекцию Ark вместо специальных объектов option. |
| Sheet | `Drawer` | Панель у края экрана с жизненным циклом, согласованным с Dialog. |
| Sidebar | `Sidebar` | Сохраните композицию адаптивной навигации продукта. |
| Sonner / Toast | `Toast` | Одна поверхность уведомлений с сообщениями, которыми владеет приложение. |
| Tabs | `Tabs` | То же взаимодействие с составными частями в пространстве имён. |
| Toggle Group | `ToggleGroup` | Используйте значения элементов и состояние группы из контракта Ark. |
| Tooltip | `Tooltip` | Триггер и содержимое, отрендеренное через портал, остаются явными. |

Для Navigation Menu и Menubar не нужны принудительные взаимно однозначные псевдонимы. Выбирайте `Sidebar`, `Menu`,
`Breadcrumbs` или обычные ссылки по фактическому взаимодействию.

## Измените форму импорта

shadcn обычно экспортирует каждую часть отдельным локальным символом:

```tsx
import { Dialog, DialogContent, DialogTitle, DialogTrigger } from '@/components/ui/dialog';
```

moduix хранит семейство компонентов в одном пространстве имён:

```tsx
import { Dialog } from '@moduix/react/dialog';

<Dialog>
  <Dialog.Trigger>Open</Dialog.Trigger>
  <Dialog.Backdrop />
  <Dialog.Positioner>
    <Dialog.Content>
      <Dialog.Title>Project settings</Dialog.Title>
    </Dialog.Content>
  </Dialog.Positioner>
</Dialog>;
```

При установке с исходным кодом в проекте меняется только источник импорта:

```tsx
import { Dialog } from '@/components/moduix/dialog';
```

Явные части фона, позиционера и содержимого упрощают понимание и настройку владения порталом и макета.

## Перенесите стили без переписывания

moduix поставляет готовый CSS и общие токены `--moduix-*`. Один раз импортируйте таблицу стилей основы, затем
настройте семантические токены в CSS, который загружается после неё:

```css title="app.css"
:root {
  --moduix-color-accent: oklch(58% 0.18 260deg);
  --moduix-radius-md: 0.625rem;
}
```

Tailwind можно оставить в приложении для макета и единичных классов. Он не требуется moduix, и не нужно переносить
каждую существующую утилиту перед заменой компонента. На страницах компонентов перечислены стабильные слоты,
CSS-переменные и class props для локальных исключений.

## Адаптируйте колбэки состояния в стиле Ark

Колбэки Ark получают объект `details`, чтобы контракт можно было расширять без позиционных аргументов:

```tsx
<Dialog open={open} onOpenChange={(details) => setOpen(details.open)}>
  {/* parts */}
</Dialog>
```

Компоненты коллекций также предпочитают стабильные значения элементов и явное состояние коллекции. Перед копированием
shadcn-колбэка или формы option без изменений проверьте страницу целевого компонента.

## Мигрируйте небольшими группами

1. Добавьте таблицу стилей основы и токены moduix.
2. Замените компоненты с небольшим числом зависимостей: Button, Badge, Avatar и Separator.
3. Переносите оверлеи и коллекции по одному семейству, включая их части портала и состояния.
4. Заменяйте паттерны уровня экрана [рецептами](/recipes), только если соответствует продуктовый сценарий.
5. Удалите прежние исходный код компонента и стили после проверки этого экрана.

Ответственности приложения должны оставаться там, где они уже находятся: метки, сообщения валидации, разрешения,
серверные вызовы и продуктовый сценарий остаются за пределами библиотеки компонентов. Ark предоставляет поведение
примитивов; moduix - контракт обёртки, стили и значения по умолчанию.

Для последующих обновлений пакета или реестра используйте [Обновление и миграция](/docs/updating), а при адаптации
существующих обёрток - [Паттерны композиции](/docs/composition-patterns).
