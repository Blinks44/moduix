# Async List

## Справочник API

<PrimitiveReference href="https://ark-ui.com/docs/collections/async-list" />

`useAsyncList` представляет собой хук Ark UI, который хранит загруженные элементы и состояние запросов. С его
помощью можно перезагружать список, подгружать дополнительные элементы, фильтровать и сортировать
данные, а также отменять запросы. Хук не создаёт разметку: компонент сам решает, как показывать
список, состояние загрузки, пустой результат и ошибку.

Хук поставляется в пакете `@ark-ui/react/collection`. `@moduix/react` не экспортирует этот хук, но в
примерах ниже используются его компоненты `Button` и `Input`.

Если Ark UI ещё не установлен в приложении, установите его:

```bash
npm install @ark-ui/react
```

```tsx
import { useAsyncList } from '@ark-ui/react/collection';
```

## Загрузка

Установите `autoReload: true`, если первый запрос нужно запустить после монтирования компонента.
По умолчанию это значение равно `false`. Без этой опции вызовите `list.reload()`, когда приложение
будет готово загружать данные.

Передавайте `signal`, полученный в `load`, в `fetch` или любой другой инструмент с поддержкой отмены.
Так хук сможет отменить запрос, если его заменит новая загрузка.

В исполняемом примере используются небольшой локальный набор данных и короткая задержка. Он
показывает начальную загрузку и обновление, а также содержит ветки для пустого списка и ошибки,
которые можно подключить к своей функции загрузки.


`reload()` сначала очищает текущие элементы, а затем запускает новую загрузку. Поэтому полное
состояние загрузки стоит показывать, когда `list.loading` имеет значение `true`, а элементов ещё
нет. Во время фильтрации и сортировки текущие элементы остаются доступными, пока выполняется новая
операция.

## Конфигурация

| Параметр               | Назначение                                               | По умолчанию |
| ---------------------- | -------------------------------------------------------- | ------------ |
| `load`                 | Обязательная функция, которая загружает данные.          | -            |
| `sort`                 | Необязательная синхронная или асинхронная сортировка на клиенте. | -            |
| `autoReload`           | Запускает начальную загрузку при монтировании компонента. | `false`      |
| `initialItems`         | Элементы, которые показываются до первой успешной загрузки. | `[]`         |
| `dependencies`         | Значения, изменение которых запускает загрузку заново.  | `[]`         |
| `initialFilterText`    | Начальное значение, передаваемое в `load` как `filterText`. | `''`         |
| `initialSortDescriptor` | Начальный дескриптор сортировки `{ column, direction }`. | `undefined`  |
| `onSuccess`            | Вызывается с `{ items }` после успешной загрузки или сортировки. | -            |
| `onError`              | Вызывается с `{ error }` после ошибки загрузки или сортировки. | -            |

В `dependencies` можно передавать значения типов `string`, `number`, `boolean`, `null` и
`undefined`. Не добавляйте туда объекты и массивы. Вместо них получайте стабильные примитивные
значения.

## `load`

Функция `load` получает текущее состояние списка и возвращает следующую порцию элементов.

Каждый вызов получает:

| Значение         | Назначение                                                  |
| ---------------- | ----------------------------------------------------------- |
| `signal`         | Сигнал отмены активного запроса. Может иметь значение `undefined`. |
| `filterText`     | Текущий текст, установленный через `setFilterText`.        |
| `cursor`         | Курсор предыдущего результата при дозагрузке элементов.    |
| `sortDescriptor` | Текущие поле и направление сортировки.                     |

Возвращайте объект с `items` и, если доступны дополнительные данные, с `cursor` для следующей
загрузки:

```tsx
const list = useAsyncList<User, string>({
  autoReload: true,
  async load({ cursor, signal }) {
    const params = new URLSearchParams();

    if (cursor != null) params.set('cursor', cursor);

    const response = await fetch(`/api/users?${params}`, { signal });
    if (!response.ok) throw new Error('Could not load users');

    const data: { users: User[]; nextCursor?: string } = await response.json();
    return {
      items: data.users,
      cursor: data.nextCursor,
    };
  },
});
```

`sortDescriptor.column` имеет тип ключа элемента, а `direction` может быть `'ascending'` или
`'descending'`.

## Состояние и действия

| Состояние        | Значение                                      |
| ---------------- | --------------------------------------------- |
| `items`          | Текущие элементы списка.                      |
| `filterText`     | Текущий текст фильтра.                        |
| `cursor`         | Курсор следующей страницы.                    |
| `sortDescriptor` | Текущий дескриптор сортировки.                |
| `loading`        | Выполняется загрузка данных.                  |
| `sorting`        | Выполняется сортировка.                       |
| `empty`          | Текущий массив элементов пуст.                |
| `hasMore`        | Есть курсор для следующей страницы.           |
| `error`          | Ошибка последней неудачной загрузки.          |

| Действие               | Назначение                                      |
| ---------------------- | ---------------------------------------------- |
| `reload()`             | Очищает элементы и запускает новую загрузку.    |
| `loadMore()`           | Загружает текущий курсор и добавляет результат.  |
| `abort()`              | Отменяет активный запрос.                       |
| `setFilterText(value)` | Устанавливает фильтр и запускает новую загрузку. |
| `clearFilter()`        | Очищает текст фильтра.                          |
| `sort(descriptor)`     | Применяет дескриптор сортировки.                |

## Фильтрация

Хук не фильтрует элементы сам. Он хранит `filterText` и передаёт его в `load`, поэтому фильтрацию
можно выполнять на сервере или в приложении:

```tsx
import { Input } from '@moduix/react/input';

function UserSearch() {
  const list = useAsyncList<User>({
    autoReload: true,
    async load({ filterText, signal }) {
      const params = new URLSearchParams({ query: filterText });
      const response = await fetch(`/api/users?${params}`, { signal });

      if (!response.ok) throw new Error('Search failed');
      return { items: await response.json() };
    },
  });

  return (
    <Input
      type="search"
      aria-label="Search users"
      value={list.filterText}
      onChange={(event) => list.setFilterText(event.currentTarget.value)}
    />
  );
}
```

`setFilterText` сразу запускает загрузку. Если не нужно отправлять запрос после каждого символа,
добавьте в приложение задержку перед загрузкой. Хук отменяет запросы, которые были заменены новыми,
а правила поиска и максимальное число результатов определяются вашей функцией загрузки или сервером.

## Постраничная загрузка

Возвращайте курсор, пока доступны дополнительные данные, а затем вызывайте `loadMore()`:

```tsx
import { Button } from '@moduix/react/button';

{
  list.hasMore && (
    <Button type="button" onClick={() => list.loadMore()} loading={list.loading}>
      {list.loading ? 'Loading…' : 'Load more'}
    </Button>
  );
}
```

`hasMore` определяется по курсору из последнего результата. Не вычисляйте его отдельно.

## Сортировка

Для сортировки на сервере читайте `sortDescriptor` внутри `load`:

```tsx
function useServerSortedUsers() {
  return useAsyncList<User>({
    autoReload: true,
    async load({ sortDescriptor, signal }) {
      const params = new URLSearchParams();

      if (sortDescriptor) {
        params.set('sort', String(sortDescriptor.column));
        params.set('direction', sortDescriptor.direction);
      }

      const response = await fetch(`/api/users?${params}`, { signal });
      if (!response.ok) throw new Error('Could not sort users');

      return { items: await response.json() };
    },
  });
}
```

Для сортировки на клиенте передайте функцию `sort`:

```tsx
function useClientSortedUsers() {
  return useAsyncList<User>({
    autoReload: true,
    async load({ signal }) {
      const response = await fetch('/api/users', { signal });
      if (!response.ok) throw new Error('Could not load users');
      return { items: await response.json() };
    },
    sort({ items, descriptor }) {
      const direction = descriptor.direction === 'ascending' ? 1 : -1;

      return {
        items: items.toSorted(
          (a, b) =>
            String(a[descriptor.column]).localeCompare(String(b[descriptor.column])) * direction,
        ),
      };
    },
  });
}
```

Функция `sort` получает текущие `items`, `descriptor` и `filterText`. Отсортированные элементы
можно вернуть сразу или из промиса.

Сортировка на клиенте затрагивает только уже загруженные элементы. Если сервер также отвечает за
разбиение на страницы, лучше сортировать там: сортировка одной загруженной страницы может исказить
результаты.

## Зависимости

Используйте `dependencies`, когда внешний фильтр должен заново загружать список:

```tsx
function useDepartmentUsers(department: string) {
  return useAsyncList<User>({
    autoReload: true,
    dependencies: [department],
    async load({ signal }) {
      const params = new URLSearchParams({ department });
      const response = await fetch(`/api/users?${params}`, { signal });

      if (!response.ok) throw new Error('Could not load users');
      return { items: await response.json() };
    },
  });
}
```

## Ошибки

Обрабатывайте ошибки и запросы, которые были заменены более новыми, отдельно. Передавайте `signal`
в запросы, поддерживающие отмену, а для повтора после ошибки используйте `reload()`.

- Проверяйте `response.ok`: `fetch` не отклоняет промис из-за HTTP-статусов ошибок.
- Передавайте `signal` в каждый запрос, который можно отменить.
- Во время фильтрации и сортировки текущие элементы остаются доступными. `reload()` очищает их
  перед загрузкой нового результата.
- Хук игнорирует запросы, завершившиеся ошибкой `AbortError`: они не записываются в `error` и не
  вызывают `onError`.
- Используйте `reload()` для действий повтора.
- Рассматривайте `error` как данные приложения с неизвестным типом и проверяйте его перед чтением
  `.message`.
- Используйте `onSuccess` и `onError` для внешних эффектов, а не для дублирования состояния элементов
  или ошибок, которым управляет хук.
