# Async List

`useAsyncList` управляет асинхронными данными коллекции и состоянием запросов, не создавая
разметку. Хук хранит элементы, фильтрацию, сортировку, постраничную загрузку, состояния загрузки
и ошибки, а компонент сам выбирает структуру списка и отображение этих состояний.

`useAsyncList` не является компонентом Moduix. Его нет среди экспортов и registry manifests пакетов
`@moduix/react`, `@moduix/solid`, `@moduix/react-tailwind` и `@moduix/solid-tailwind`. Поэтому
CSS Modules и Tailwind не меняют API hook. Стилизуйте окружающую разметку выбранным способом или
используйте нативные элементы, как в примерах ниже.

## Список с загрузкой с сервера

Используйте аргументы `load`, чтобы передать API текущий фильтр, курсор, дескриптор сортировки и
сигнал отмены. Возвращайте текущую страницу в `items`, а `cursor` добавляйте только при наличии
следующей страницы. `setFilterText` сразу запускает новую загрузку, а `loadMore()` добавляет
следующую страницу к уже загруженным элементам.

Копируемый пример ожидает, что `GET /api/users?query=...&cursor=...&sort=...&direction=...`
вернёт `{ users: User[], nextCursor?: string }`. При фильтрации, сортировке и загрузке следующей
страницы уже полученные элементы остаются на экране. Передавайте `signal` в `fetch`, чтобы отменять
заменённые запросы.

Для серверной сортировки читайте `sortDescriptor` внутри `load`, как в примере. Для сортировки на
клиенте передайте `sort`. Она получает текущие `items`, выбранный `descriptor` и `filterText` и
может вернуть `{ items }` сразу или из промиса. Клиентская сортировка меняет только элементы в
памяти, поэтому при серверной пагинации обычно лучше сортировать на сервере.

## Основные части API

### Конфигурация

| Параметр                | Назначение                                                     | По умолчанию |
| ----------------------- | -------------------------------------------------------------- | ------------ |
| `load`                  | Обязательная функция, возвращающая `{ items, cursor }`.       | -            |
| `sort`                  | Необязательная синхронная или асинхронная сортировка на клиенте. | -          |
| `autoReload`            | Загружает начальные элементы при монтировании компонента.     | `false`     |
| `initialItems`          | Элементы до первой успешной загрузки.                         | `[]`         |
| `dependencies`          | Стабильные примитивы, изменения которых запускают загрузку.  | `[]`         |
| `initialFilterText`     | Начальное значение, передаваемое в `load` как `filterText`.   | `''`         |
| `initialSortDescriptor` | Начальный дескриптор `{ column, direction }`.                 | `undefined`  |
| `onSuccess`             | Callback с `{ items }` после успешной загрузки или сортировки. | -          |
| `onError`               | Callback с `{ error }` после ошибки загрузки или сортировки.  | -            |

Передавайте в `dependencies` стабильные примитивные значения. Если зависимость берётся из объекта
или массива, сначала получите значение, которое действительно должно запускать новую загрузку.

### Контракт `load`

`load` получает контекст текущего запроса:

| Значение         | Назначение                                                    |
| ---------------- | ------------------------------------------------------------- |
| `signal`         | `AbortSignal` активного запроса или `undefined`.              |
| `filterText`     | Текущее значение, установленное через `setFilterText`.       |
| `cursor`         | Курсор страницы, которую запросил `loadMore()`.               |
| `sortDescriptor` | Текущая пара `{ column, direction }`, если она задана.       |

Возвращайте `{ items }` для последней страницы или `{ items, cursor }`, если доступна следующая.
В дескрипторе сортировки `column` является ключом элемента, а `direction` равен `'ascending'` или
`'descending'`.

### Состояние и действия

| Состояние        | Значение                                               |
| ---------------- | ------------------------------------------------------ |
| `items`          | Текущие элементы списка.                               |
| `filterText`     | Текущий текст фильтра.                                 |
| `cursor`         | Курсор из последнего результата.                       |
| `sortDescriptor` | Текущий дескриптор сортировки.                         |
| `loading`        | Выполняется загрузка или сортировка.                   |
| `sorting`        | Выполняется сортировка.                                |
| `empty`          | Массив `items` пуст.                                   |
| `hasMore`        | Последний результат содержит курсор.                   |
| `error`          | Ошибка последней неудачной загрузки или сортировки.    |

| Действие               | Назначение                                          |
| ---------------------- | --------------------------------------------------- |
| `reload()`             | Очищает элементы и запускает новую загрузку.        |
| `loadMore()`           | Загружает текущий курсор и добавляет результат.     |
| `abort()`              | Отменяет активный запрос.                            |
| `setFilterText(value)` | Устанавливает фильтр и запускает новую загрузку.    |
| `clearFilter()`        | Очищает фильтр и запускает новую загрузку.          |
| `sort(descriptor)`     | Применяет дескриптор сортировки.                    |

## Интеграция и доступность

- По умолчанию `autoReload` равен `false`. Вызовите `reload()`, если начальный запрос нужно
  запускать вручную.
- `reload()` очищает текущие элементы перед загрузкой. Полное состояние загрузки показывайте,
  только если элементов ещё нет; при фильтрации, сортировке и `loadMore()` сохраняйте список на
  экране.
- Передавайте `signal` в каждый запрос, который поддерживает отмену. `AbortError` от заменённого
  запроса hook игнорирует: ошибка не попадёт в `error`, а `onError` не вызовется.
- `fetch` не отклоняет промис из-за HTTP-ошибок. Проверяйте `response.ok` и выбрасывайте ошибку из
  `load`, если ответ нельзя использовать.
- Подписывайте поля поиска, показывайте сообщения о загрузке через `role="status"`, а ошибки через
  `role="alert"`. Для списка, который остаётся видимым во время фоновой загрузки, используйте
  `aria-busy`.
- Если фильтр не должен отправлять запрос после каждого символа, добавьте debounce в приложении.

Хук отвечает только за данные и состояние запросов. Для CSS Modules используйте stylesheet
приложения, а для Tailwind - native utilities и классы потребителя. У `async-list` нет CSS
variables, экспортов Moduix или registry-команд.
