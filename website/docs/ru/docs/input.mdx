Поместите `Input` в `Field`, если полю нужны метка, пояснение или сообщение об ошибке. `Field` свяжет эти элементы с полем, автоматически создаст нужные идентификаторы и передаст его состояние.

## Выбор подходящего компонента

- Используйте **`Input`** для обычного однострочного поля ввода.
- Используйте **`InputGroup`**, если к полю нужно добавить префикс, суффикс, дополнительный текст или действие в одной строке.
- Используйте **`PasswordInput`** для поля пароля с переключателем видимости.
- Используйте **`NumberInput`**, если нужен числовой ввод с изменением значения по шагам и соответствующими кнопками.
- Используйте **`Textarea`** для многострочного текста.
- Используйте **`Editable`**, если значение сначала должно отображаться как текст, а затем переходить в режим редактирования.

## Примеры

### Размеры

Свойство moduix `size` управляет визуальным размером. Оно не связано с `htmlSize`, которое задаёт
нативную ширину в символах.

<Example name="input/sizes" />

### Автономное поле

`Field` необязателен. Если `Input` используется отдельно, задайте доступное имя с помощью HTML
`<label>`, `aria-label` или `aria-labelledby`. Нативные свойства по-прежнему работают, но без
контекста `Field` идентификаторы не создаются автоматически, а поясняющий текст и сообщение об
ошибке не связываются с полем.

<Example name="input/standalone-input" />

### Отключённое поле и режим только для чтения

Используйте `disabled`, если с полем нельзя взаимодействовать. Используйте `readOnly`, если
значение можно просматривать и выделять, но нельзя изменять. Для одного элемента задавайте эти
свойства непосредственно на `Input`. Если метка, поясняющий текст и поле должны иметь одно
состояние, задавайте свойства на `Field`.

<Example name="input/disabled-and-readonly" />

### Валидация поля

Задавайте `invalid` на `Field`, когда значение не проходит проверку. Ark добавит к `Input`
`aria-invalid` и `data-invalid` и свяжет его с текстом ошибки.

<Example name="input/field-state" />

### Нативные атрибуты

Используйте нативные атрибуты для управления поведением браузера: валидацией, режимом ввода,
автозаполнением и отправкой формы. Задавайте `htmlSize` для ширины в символах, а `size` для
изменения визуального размера в React, Solid и Vue.

<Example name="input/native-attributes" />

### Выбор файла

Для простой формы `Input` достаточно, чтобы открыть нативный диалог выбора файла. Используйте
`FileUpload`, если приложение должно хранить выбранные файлы в состоянии, показывать область
перетаскивания или управлять процессом загрузки.

<Example name="input/file-input" />

### Управляемое значение

Используйте этот вариант, когда внешняя логика должна управлять текущим значением. В React читайте
новое значение из нативного события `onChange(event)`, в Solid используйте `onInput`, а в Vue используйте
`v-model`. Передавайте текущее значение обратно через `value`, если фреймворк использует отдельные
привязки для события и значения.

### Пользовательский элемент

Используйте `asChild` только тогда, когда вместо стандартного элемента `Input` должен быть отрисован другой DOM-элемент.
Передавайте один семантически корректный элемент, который может получить фокус, объединённые

## Композиция

Компонент `Input` основан на стилизованном [`FieldInput` из Ark UI](https://ark-ui.com/docs/components/field). Он следует рекомендациям Ark по [композиции](https://ark-ui.com/docs/guides/composition), [стилизации](https://ark-ui.com/docs/guides/styling) и [передаче ref](https://ark-ui.com/docs/guides/ref). Компонент отрисовывает нативный однострочный `<input>` и сохраняет стандартное поведение браузера в формах и нативный API событий каждого фреймворка.

Используйте `Field`, если полю нужны метка, поясняющий текст или сообщение об ошибке, автоматически
созданные идентификаторы или общее состояние.

`Field` владеет меткой, поясняющим текстом или сообщением об ошибке, автоматически созданными
идентификаторами и общим состоянием `disabled`, `invalid`, `required` или `readOnly`. `Input` остаётся
нативным элементом: в управляемом поле React используйте `value` и `onChange(event)`, а в Vue
используйте `v-model`. Для неуправляемого поля в React задайте `defaultValue`. Компонент не управляет валидацией, фокусом
или навигацией с клавиатуры.

Во Vue задавайте начальное значение через `v-model` и сбрасывайте связанное состояние в обработчике
сброса формы: нативный сброс не вызывает событие ввода. Сейчас Ark очищает нативный `defaultValue`,
если модель не задана, поэтому до исправления используйте `v-model` для начальных значений.

Для автономного поля задайте доступное имя самостоятельно. Используйте `asChild` только с одним
фокусируемым элементом, совместимым с полем ввода: Ark объединит в этом DOM-узле свойства `Input` и
`Field`, класс и `ref`.

## Стилизация

`Input` получает контекст `Field`. Свойство `size` выбирает визуальный размер, а нативный числовой
атрибут `size` передаётся как `htmlSize`. Внутри отключённого moduix `Field` или `FieldRootProvider` прозрачность
применяется один раз, на корневом элементе.

Используйте `className` в React и `class` в Solid и Vue, чтобы стилизовать `Input`. Варианты на
Tailwind используют нативные utility-классы и классы потребителя. Варианты с CSS Modules построены на
токенах foundation и поддерживают только три переменные ниже; цвета, отступы и типографику
переопределяйте обычным классом, он сильнее стилей компонента в слое. Для стилей состояний
используйте общие data-атрибуты и нативные селекторы состояния.

### Хуки стилизации

| Часть | `data-slot` |
| --- | --- |
| `Input` | `input-root` |

- `data-size="xs" | "sm" | "md" | "lg" | "xl"`
- `data-scope="field"` и `data-part="input"`
- `data-invalid`, `data-required` и `data-readonly` Ark внутри `Field`
- нативные `:disabled`, `:read-only`, `:focus-visible` и `[aria-invalid="true"]`

## Справочник API

Также принимает нативные пропсы своего элемента.

| Проп | Тип | По умолчанию |
| --- | --- | --- |
| `size` | `'xs' \| 'sm' \| 'md' \| 'lg' \| 'xl'` | `'md'` |
| `htmlSize` | `number` | — |
| `asChild` | `boolean` | `false` |
