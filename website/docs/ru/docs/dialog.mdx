Используйте `Dialog` как корневой компонент и явно соберите его структурные части.
`DialogBackdrop` отвечает за модальный фон, `DialogPositioner` размещает диалог, а
`DialogContent` содержит его поверхность.

## Какой компонент выбрать

Используйте `Dialog` для форм, подтверждений, просмотра деталей и других задач, которые пользователь
выполняет на текущей странице. Выбирайте `Drawer`, если панель должна быть прикреплена к краю
экрана или поддерживать перетаскивание.

## Примеры

### Alert Dialog

Используйте `role="alertdialog"` для решений с серьёзными последствиями. Добавьте понятное действие
отмены и отдельное действие для подтверждения.

<Example name="dialog/alert-dialog" />

### Подтверждение

Если в форме есть несохранённые изменения, перехватите запрос на закрытие родительского диалога и
спросите пользователя, нужно ли их отменить.

<Example name="dialog/confirmation" />

### Управляемое состояние

Храните `open` в состоянии React, сигнале Solid или ref Vue и читайте `details.open` из
`onOpenChange` (либо используйте `v-model:open`), чтобы синхронизировать диалог с остальным приложением.

<Example name="dialog/controlled" />

### Прокрутка содержимого

Сделайте прокручиваемым только основное содержимое, если заголовок и действия должны оставаться
видимыми. Задайте `scrollBehavior="inside"` у `DialogContent`: диалог ограничится высотой экрана,
а прокручиваться будет `DialogBody`.

<Example name="dialog/inside-scroll" />

### Жизненный цикл монтирования и фокуса

Используйте `lazyMount` и `unmountOnExit` для управления жизненным циклом присутствия. Укажите
`initialFocusEl` и `finalFocusEl`, если при открытии или закрытии фокус должен переходить на
определённые элементы.

<Example name="dialog/mounting-and-focus-lifecycle" />

### Несколько триггеров

Свяжите один диалог с несколькими триггерами: задайте каждому `value` и обработайте
`onTriggerValueChange(details)`.

<Example name="dialog/multiple-triggers" />

### Вложенные диалоги

Используйте отдельные хранилища `useDialog()` для вложенных диалогов. Ark UI управляет слоями, а
moduix использует это состояние, чтобы отодвинуть родительский диалог, пока открыт вложенный.

<Example name="dialog/nested" />

### Немодальный диалог

Укажите `modal={false}` и не добавляйте backdrop, если пользователь должен взаимодействовать со
страницей за пределами диалога.

<Example name="dialog/non-modal" />

### Открытие из меню

Управляйте `open` из пункта меню, если контекстное действие должно открыть диалог подтверждения.

<Example name="dialog/open-from-menu" />

### Прокрутка позиционера

Позвольте `DialogPositioner` прокручивать весь диалог, если длинное содержимое должно сохранять
естественную высоту. Это `scrollBehavior` по умолчанию; `placement="top"` начинает диалог от верхнего
края экрана.

<Example name="dialog/outside-scroll" />

### Root Provider

Создайте состояние через `useDialog()`, если элементы управления находятся за пределами диалога.
Подключите его с помощью `DialogRootProvider`, а затем читайте через `DialogContext` или
`useDialogContext()` в переиспользуемых компонентах.

<Example name="dialog/root-provider-and-ark-context-hooks" />

### Размеры

Задайте `size` у `DialogContent`: `sm`, `md` (по умолчанию), `lg`, `xl` или `full`. `placement="top"`
и `placement="bottom"` смещают окно от центра, а `scrollBehavior="inside"` ограничивает диалог высотой
экрана и прокручивает `DialogBody` вместо позиционера.

<Example name="dialog/sizes" />

### Сборка из частей

Тот же диалог, что в Basic, но без `DialogHeader` и `DialogCloseIcon`: обычный элемент шапки и
`DialogCloseTrigger` вокруг `CloseButton` с явной иконкой. Начинайте с него, если дизайн меняет
раскладку или кнопку закрытия.

## Композиция

По умолчанию `Dialog` сам управляет состоянием открытия. Используйте `open` и
`onOpenChange(details)`, если состояние принадлежит другой части приложения. Если состояние нужно
создать за пределами дерева диалога, создайте одно хранилище через `useDialog()` и передайте его в
`DialogRootProvider`; не создавайте для того же хранилища второй корневой компонент.

Корневой компонент автоматически переносит `DialogBackdrop` и `DialogPositioner` в portal.
Укажите `portalled={false}`, чтобы оставить их в текущем дереве, или передайте `portalRef` для
своего контейнера. Держите дерево частей явным, а `DialogHeader`, `DialogBody` и `DialogFooter`
используйте только тогда, когда их готовая разметка подходит композиции.

## Стилизация

Для структурных стилей передавайте экспортируемым частям `className` в React или `class` в Solid и Vue.
Для стилей состояний используйте атрибуты данных Ark, например `data-state` и `data-has-nested`,
вместе с селекторами `data-slot` moduix. Варианты на Tailwind настраиваются обычными утилитами и
пользовательскими классами; перечисленные ниже переменные относятся к вариантам с CSS Modules.
Атрибуты данных и селекторы `data-slot` общие для обоих подходов.

### Хуки стилизации

| Часть | `data-slot` |
| --- | --- |
| `DialogTrigger` | `dialog-trigger` |
| `DialogBackdrop` | `dialog-backdrop` |
| `DialogPositioner` | `dialog-positioner` |
| `DialogContent` | `dialog-content` |
| `DialogTitle` | `dialog-title` |
| `DialogDescription` | `dialog-description` |
| `DialogCloseTrigger` | `dialog-close-trigger` |
| `DialogCloseIcon` | `dialog-close-icon` |
| `DialogHeader` | `dialog-header` |
| `DialogBody` | `dialog-body` |
| `DialogFooter` | `dialog-footer` |

- Атрибуты Ark: `data-scope="dialog"` и
  `data-part="trigger|backdrop|positioner|content|title|description|close-trigger"`.
- Атрибуты состояния: `data-state="open|closed"`, `data-has-nested`, `data-nested`, `data-current`,
  `data-value`.
- Переменные рантайма: `--layer-index` и `--nested-layer-count`.
- `DialogCloseIcon` позиционируется относительно угла `DialogContent`, поэтому его размещение не
  зависит от `DialogHeader`.
- Цвета, рамки, отступы и типографика берутся из токенов foundation. Для одного диалога меняйте их
  классом на нужной части, а анимацию задавайте через `--moduix-popup-motion-*` на `DialogContent`.

## Клавиатура

| Клавиша | Действие |
| --- | --- |
| `Enter` / `Space` | Открывает с кнопки в фокусе. |
| `Tab` / `Shift+Tab` | Перемещает фокус между элементами; пока открыто, фокус не выходит наружу. |
| `Esc` | Закрывает и возвращает фокус на кнопку. |

## Справочник API

Пропсы `Dialog`. `size` (`'sm' | 'md' | 'lg' | 'xl' | 'full'`, по умолчанию `'md'`), `placement` (`'center' | 'top' | 'bottom'`, по умолчанию `'center'`) и `scrollBehavior` (`'outside' | 'inside'`, по умолчанию `'outside'`) задаются на `DialogContent`.

| --- | --- | --- |

| `defaultOpen` | `boolean` | `false` |
| `onOpenChange` | `(details: OpenChangeDetails) => void` | — |
| `modal` | `boolean` | `true` |
| `role` | `'dialog' \| 'alertdialog'` | `'dialog'` |

| `lazyMount` | `boolean` | `true` |

| `restoreFocus` | `boolean` | — |
| `aria-label` | `string` | — |
