## Выбор подходящего компонента

Используйте `Dialog` для форм, подтверждений, просмотра подробной информации и второстепенных задач, не покидая текущую
страницу. Используйте `Drawer`, когда панель должна оставаться прикреплённой к краю окна.

## Анатомия

```text
Dialog
├─ Dialog.Trigger
└─ Дерево оверлея (автоматически помещается в портал)
   ├─ Dialog.Backdrop
   └─ Dialog.Positioner
      └─ Dialog.Content
         ├─ Dialog.CloseTrigger или Dialog.CloseIcon
         ├─ Dialog.Title
         ├─ Dialog.Description
         ├─ Dialog.Header (помощник компоновки moduix)
         ├─ Dialog.Body (помощник компоновки moduix)
         └─ Dialog.Footer (помощник компоновки moduix)

Dialog.RootProvider
└─ то же дерево содержимого в портале, подключённое к useDialog() из moduix

Dialog.Context
└─ функция рендера с текущим состоянием и методами диалога
```

| Часть                    | Назначение                                                       |
| ------------------------ | ---------------------------------------------------------------- |
| `Dialog`                 | Отвечает за состояние диалога, жизненный цикл фокуса и его закрытие. |
| `Dialog.Trigger`         | Открывает диалог.                                                |
| `Dialog.Backdrop`        | Необязательный фоновый слой модального окна.                     |
| `Dialog.Positioner`      | Плавающий контейнер, который позиционирует содержимое.           |
| `Dialog.Content`         | Контейнер содержимого диалога.                                   |
| `Dialog.Title`           | Заголовок диалога для средств доступности.                       |
| `Dialog.Description`     | Вспомогательное описание для средств доступности.                |
| `Dialog.CloseTrigger`    | Закрывает диалог.                                                |
| `Dialog.Context`         | Передаёт дочерним элементам текущее состояние и методы диалога.  |
| `Dialog.RootProvider`    | Подключает части к состоянию, созданному через `useDialog()` из moduix. |

Импортируйте `useDialog()`, когда состояние диалога должно храниться вне дерева, в котором он отрисован. В переиспользуемых
дочерних компонентах читайте это состояние через `Dialog.Context` или `useDialogContext()` из `@moduix/react`.

## Композиция

Корневой компонент автоматически помещает `Backdrop` и `Positioner` в портал. Чтобы отрисовать их в текущем дереве,
используйте `portalled={false}`, а для собственного контейнера передайте `portalRef`. Структурные части остаются явными,
и их можно стилизовать независимо.

### Рекомендуемая композиция

Оставляйте `Backdrop`, `Positioner` и `Content` явно заданными. Так сохраняются точки настройки структуры, а композиция
остаётся совместимой с Ark UI. Для немодального диалога не добавляйте `Backdrop`.

Используйте `Dialog.Trigger asChild` и `Dialog.CloseTrigger asChild` с одним дочерним элементом, который сохраняет
семантику кнопки. `Dialog.CloseIcon` представляет собой помощник moduix: он объединяет Ark `CloseTrigger` с кнопкой
закрытия библиотеки.

### Когда нужна собственная композиция

Чтобы управлять состоянием диалога из React, используйте `open` с `onOpenChange(details)`. Колбэк получает объект `details`
от Ark UI, поэтому читайте значение из `details.open`.

Используйте `useDialog()` из moduix вместе с `Dialog.RootProvider`, когда состояние и методы должны находиться вне дерева
диалога. Не создавайте второй `Dialog` для того же хранилища.

Используйте `ids`, когда отдельно скомпонованным частям нужны стабильные общие идентификаторы для доступности.
`initialFocusEl` и `finalFocusEl` задают элементы, на которые нужно перевести фокус. Используйте
`role="alertdialog"` для подтверждения опасных или критических действий.

Используйте `lazyMount` и `unmountOnExit` вместо условного рендеринга корневого компонента. Задавайте `present` только
когда анимация выхода под управлением JavaScript должна определять, остаётся ли содержимое смонтированным.

### Свойства по умолчанию

По умолчанию содержимое оверлея в портале монтируется при первом открытии и размонтируется после анимации выхода. Задайте
`unmountOnExit={false}`, чтобы не размонтировать его после первого открытия. Устанавливайте оба свойства жизненного цикла
в `false`, только когда нужен немедленный первоначальный рендеринг.

| Поверхность              | По умолчанию | Примечания                                         |
| ------------------------ | ------- | ------------------------------------------------------ |
| `Dialog`                 | -       | Дополнительных настроек поведения нет; применяются значения Ark. |

### Особенности поведения

- Модальные диалоги удерживают фокус внутри окна, блокируют прокрутку фона, скрывают содержимое за окном от
  вспомогательных технологий и возвращают фокус после закрытия.
- `modal={false}` отключает удержание фокуса и блокировку прокрутки. В этом режиме фон не нужен.
- `closeOnEscape`, `closeOnInteractOutside`, `trapFocus`, `preventScroll`, `restoreFocus`, `persistentElements` и
  колбэки внешнего взаимодействия передаются в Ark UI без изменений.
- Для доступного имени укажите `Dialog.Title` или задайте `aria-label` на корневом компоненте.
- Если пользователь предпочитает уменьшенное движение, Dialog сокращает анимации появления и закрытия, сохраняя жизненный
  цикл присутствия Ark UI.
- У каждого отрисованного элемента управления закрытием должен быть уникальный идентификатор. В базовой рекомендуемой
  композиции используется один `Dialog.CloseIcon`. Если нужны несколько элементов закрытия, задайте каждой дополнительной
  части явный уникальный `id`.
- Вложенное содержимое получает `data-has-nested` и `--nested-layer-count`. moduix использует эти значения, чтобы уменьшить
  родительский диалог и сместить его вниз, поэтому активный вложенный диалог выглядит отдельным слоем.
- Примеры открытия из меню и быстрых изменений состояния используют управляемый контракт `open`. Для подтверждения
  несохранённых изменений применяются два хранилища `useDialog()` из moduix, а `onOpenChange` родительского хранилища
  перехватывается.

### Хуки стилизации

- Слоты moduix: `dialog-trigger`, `dialog-backdrop`, `dialog-positioner`, `dialog-content`,
  `dialog-title`, `dialog-description`, `dialog-close-trigger`, `dialog-close-icon`,
  `dialog-header`, `dialog-body` и `dialog-footer`.
- Анатомия Ark: `data-scope="dialog"` с `data-part="trigger|backdrop|positioner|content|title|description|close-trigger"`.
- Состояние: `data-state="open|closed"`, `data-has-nested`, `data-nested`, `data-current` и
  `data-value`.
- Переменные времени выполнения: `--layer-index` и `--nested-layer-count`.
- `Dialog.CloseIcon` позиционируется абсолютно относительно `Dialog.Content`; его размещение не зависит от
  `Dialog.Header`.
