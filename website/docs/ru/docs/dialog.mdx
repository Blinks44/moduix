## Какой компонент выбрать

Используйте `Dialog` для форм, подтверждений, просмотра деталей и других задач, которые пользователь
выполняет на текущей странице. Выбирайте `Drawer`, если панель должна быть прикреплена к краю
экрана или поддерживать перетаскивание.

## Базовый пример


Используйте `Dialog` как корневой компонент и явно соберите его структурные части.
`Dialog.Backdrop` отвечает за модальный фон, `Dialog.Positioner` размещает диалог, а
`Dialog.Content` содержит его поверхность.

## Анатомия

```text
Dialog / Dialog.Root
├─ Dialog.Trigger
└─ Содержимое overlay (автоматически переносится в portal)
   ├─ Dialog.Backdrop (необязательно)
   └─ Dialog.Positioner
      └─ Dialog.Content
         ├─ Dialog.CloseTrigger или Dialog.CloseIcon
         ├─ Dialog.Title
         ├─ Dialog.Description
         ├─ Dialog.Header (вспомогательная часть moduix для разметки)
         ├─ Dialog.Body (вспомогательная часть moduix для разметки)
         └─ Dialog.Footer (вспомогательная часть moduix для разметки)

Dialog.RootProvider
└─ то же дерево частей, подключённое к состоянию из moduix useDialog()

Dialog.Context
└─ render-функция с текущим состоянием и методами диалога
```

| Часть                    | Назначение                                                          |
| ------------------------ | ------------------------------------------------------------------- |
| `Dialog` / `Dialog.Root` | Управляет состоянием открытия, фокусом и закрытием.                 |
| `Dialog.RootProvider`    | Подключает части к состоянию, созданному с помощью `useDialog()`.   |
| `Dialog.Trigger`         | Открывает диалог.                                                    |
| `Dialog.Backdrop`        | Необязательный фон модального диалога.                              |
| `Dialog.Positioner`      | Размещает содержимое диалога.                                        |
| `Dialog.Content`         | Содержит видимую поверхность диалога.                               |
| `Dialog.Title`           | Задаёт доступное имя диалога.                                       |
| `Dialog.Description`     | Добавляет дополнительный доступный текст.                           |
| `Dialog.CloseTrigger`    | Закрывает диалог.                                                    |
| `Dialog.CloseIcon`       | Вспомогательная кнопка moduix, которая закрывает диалог.             |
| `Dialog.Header`          | Вспомогательная часть moduix для разметки заголовка.                 |
| `Dialog.Body`            | Вспомогательная часть moduix для основного содержимого.              |
| `Dialog.Footer`          | Вспомогательная часть moduix для действий.                          |
| `Dialog.Context`         | Передаёт дочерним элементам состояние и методы диалога.             |

Импортируйте `useDialog()`, если состояние диалога должно находиться за пределами его дерева.
Читайте или обновляйте это состояние через `Dialog.Context` или `useDialogContext()` из выбранного
пакета.

## Композиция

По умолчанию `Dialog` сам управляет состоянием открытия. Используйте `open` и
`onOpenChange(details)`, если состояние принадлежит другой части приложения. Если состояние нужно
создать за пределами дерева диалога, создайте одно хранилище через `useDialog()` и передайте его в
`Dialog.RootProvider`; не создавайте для того же хранилища второй корневой компонент.

Корневой компонент автоматически переносит `Dialog.Backdrop` и `Dialog.Positioner` в portal.
Укажите `portalled={false}`, чтобы оставить их в текущем дереве, или передайте `portalRef` для
своего контейнера. Держите дерево частей явным, а `Dialog.Header`, `Dialog.Body` и `Dialog.Footer`
используйте только тогда, когда их готовая разметка подходит композиции.

## Стилизация

Для структурных стилей передавайте экспортируемым частям `className` в React или `class` в Solid.
Для стилей состояний используйте атрибуты данных Ark, например `data-state` и `data-has-nested`,
вместе с селекторами `data-slot` moduix. Варианты на Tailwind настраиваются обычными утилитами и
пользовательскими классами; перечисленные ниже переменные относятся к вариантам с CSS Modules.
Атрибуты данных и селекторы `data-slot` общие для обоих подходов.

### Хуки стилизации

- Значения `data-slot` moduix: `dialog-trigger`, `dialog-backdrop`, `dialog-positioner`,
  `dialog-content`, `dialog-title`, `dialog-description`, `dialog-close-trigger`,
  `dialog-close-icon`, `dialog-header`, `dialog-body` и `dialog-footer`.
- Атрибуты Ark: `data-scope="dialog"` и
  `data-part="trigger|backdrop|positioner|content|title|description|close-trigger"`.
- Атрибуты состояния: `data-state="open|closed"`, `data-has-nested`, `data-nested`, `data-current`,
  `data-value`.
- Переменные рантайма: `--layer-index` и `--nested-layer-count`.
- `Dialog.CloseIcon` позиционируется относительно угла `Dialog.Content`, поэтому его размещение не
  зависит от `Dialog.Header`.
