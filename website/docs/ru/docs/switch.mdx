## Выбор подходящего компонента

Используйте `Switch` для настройки, которая применяется сразу после изменения. Переключатель представляет одно
булево значение.

- Выбирайте **`Switch`** для таких настроек, как уведомления, напоминания или функции приложения.
- Выбирайте **`Checkbox`**, когда значение нужно отправить вместе с формой,
  а не применить сразу как настройку.
- Выбирайте **`RadioGroup`**, когда пользователь должен выбрать один вариант из нескольких взаимоисключающих значений.

## Анатомия

```text
Switch / Switch.Root
├─ Switch.Control
│  └─ Switch.Thumb
├─ Switch.Label
└─ Switch.HiddenInput (explicit)
```

| Часть                         | Назначение                                                              |
| ----------------------------- | ----------------------------------------------------------------------- |
| `Switch` / `Switch.Root`      | Корневой элемент `label`. Хранит состояние, ID, свойства формы и `size`. |
| `Switch.HiddenInput`          | Нативное поле Ark; правила явной композиции описаны ниже.               |
| `Switch.RootProvider`         | Корневой элемент с состоянием, созданным через `useSwitch()`.            |
| `Switch.Control`              | Визуальная дорожка и цель для кольца фокуса. По умолчанию добавляет бегунок. |
| `Switch.Thumb`                | Подвижный бегунок для стандартного вида или пользовательского содержимого. |
| `Switch.Label`                | Подпись, связанная с переключателем через Ark.                         |

`Switch` и `Switch.Root` - два имени одного и того же корневого компонента. `Switch.Context`,
`useSwitchContext` и `useSwitch` экспортируются из `@moduix/react` вместе с компонентом.
Соответствующие экспорты Solid доступны из `@moduix/solid` и `@moduix/solid/switch`.

## Композиция

Явно добавляйте `Switch.HiddenInput` внутрь `Switch` или `Switch.RootProvider`, даже если
переключатель находится не в форме. Это нативное поле, которое Ark использует для фокуса, работы с клавиатурой,
доступности и отправки формы.

Если у `Switch.Control` нет дочерних элементов, он добавляет стандартный `Switch.Thumb`. Добавляйте `Switch.Thumb`
явно только при необходимости настроить содержимое или стили бегунка.

Используйте `Switch.Context` или `useSwitchContext`, когда соседнему интерфейсу нужно читать состояние переключателя. Используйте
`useSwitch` вместе с `Switch.RootProvider`, когда состояние нужно создать вне дерева переключателя.
Не рендерите `Switch` и `Switch.RootProvider` для одного экземпляра состояния.

При использовании `asChild` передавайте один семантический элемент, совместимый с `label`, чтобы Ark сохранял
доступность переключателя.

## Стилизация

Стилизуйте `Switch` с помощью `className` в React или `class` в Solid, публичных хуков `data-slot` и атрибутов состояния Ark,
а также публичных CSS-переменных `--moduix-switch-*`, показанных ниже. Варианты Tailwind настраиваются
обычными утилитами и пользовательскими классами. Переменные ниже относятся к CSS Modules, а атрибуты данных
общие для обоих подходов.

### Хуки стилизации

- `Switch` и `Switch.RootProvider` предоставляют `data-slot="switch-root"` /
  `data-slot="switch-root-provider"` и добавляют атрибут `data-size` от moduix.
- `Switch.Control` предоставляет `data-slot="switch-control"` и получает атрибуты состояния Ark, включая
  `data-state`, `data-focus-visible`, `data-hover`, `data-active`, `data-disabled`, `data-readonly`,
  `data-invalid` и `data-required`.
- `Switch.Thumb` предоставляет `data-slot="switch-thumb"` и получает те же атрибуты состояния Ark для
  движения бегунка и стилизации пользовательского содержимого.
- `Switch.Label` предоставляет `data-slot="switch-label"` для переопределения типографики.
