# Паттерны композиции

Moduix сохраняет явную модель частей Ark. Начните с готовых частей, реэкспортируйте их для стабильных
локальных импортов и добавляйте обертку только для повторяющегося решения на уровне продукта.

Эта модель одинаково работает во всех выпущенных адаптерах, с npm-пакетом и кодом из реестра shadcn. Во вкладках
ниже разделены только действительно отличающиеся детали фреймворков.

## Выберите уровень владения

| Задача | С чего начать |
| --- | --- |
| Стандартное поведение компонента | Готовые части Moduix |
| Локальные пути импортов продукта | Прямые реэкспорты |
| Повторяющееся визуальное правило или расположение | Узкая обертка над отвечающей за него частью |
| Состояние вне дерева компонента | `use<Component>()` вместе с `<Family>RootProvider` |

Выбирайте самый простой уровень, который решает повторяющуюся задачу. Единичный класс или callback не
требует нового API компонента.

## Начните с дерева частей

Перед созданием обертки изучите Anatomy на странице компонента. Не скрывайте структурные части, чтобы
ответственность за позиционирование, прокрутку, фокус и стили оставалась явной.

```text
Dialog
├─ DialogTrigger
└─ Overlay subtree, automatically portalled
   ├─ DialogBackdrop
   └─ DialogPositioner
      └─ DialogContent
         ├─ DialogTitle
         ├─ DialogDescription
         └─ DialogCloseTrigger
```

Используйте `portalled={false}` для встроенной отрисовки и `portalRef` для собственного контейнера,
если компонент поддерживает эти свойства. `DialogRootProvider` нужен только для состояния, созданного вне
отрисованного дерева.

## Скомпонуйте семантический элемент

Используйте `asChild`, когда существующий элемент должен остаться DOM-узлом, а часть Moduix только
добавляет к нему поведение. React принимает единственный дочерний элемент. Solid принимает render
function, а свойства Ark нужно передать возвращаемому элементу.

отбрасывает, клавиатурное управление и связи доступности могут нарушиться.

## Сначала реэкспортируйте

Реэкспорты создают стабильный импорт продукта, не меняя поведение:

  <Tab label="React" value="react">


  </Tab>

  </Tab>

Так переход между импортами из пакета и кодом из реестра останется простым.

`tone` и преобразует его в публичные переменные Dialog. Остальное дерево частей не меняется.

## Выносите состояние только вместе с ответственностью

Используйте `DialogContext` для разового чтения внутри дерева, а `useDialogContext()` в переиспользуемых
потомках. Создавайте состояние через `useDialog()` и подключайте его к `DialogRootProvider`, только
если оно нужно элементам за пределами Dialog.

## Проверьте композицию

- Сохраняйте стандартные части, пока продукт не вводит повторяющееся правило.
- Реэкспортируйте API до создания обертки.
- Передавайте исходные свойства, классы и ref.
- Не создавайте верхнеуровневое свойство для единичного решения.
- После обертки проверяйте клавиатуру, возврат фокуса, порталы и управляемое состояние.
