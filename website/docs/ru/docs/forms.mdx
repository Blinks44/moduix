# Формы

Moduix предоставляет доступные поля, элементы управления и интеграцию с нативными формами.
Начинайте с `<form>` и добавляйте библиотеку состояния, только если она нужна для валидации,
повторяющихся полей или управления отправкой.

## Поддержка фреймворков

| Подход          | React | Solid | Когда использовать                                 |
| --------------- | ----- | ----- | -------------------------------------------------- |
| Нативная форма  | Да    | Да    | Небольшие формы с браузерной валидацией.           |
| Formisch        | Да    | Да    | Схемы Valibot и компактное реактивное состояние.   |
| React Hook Form | Да    | Нет   | React-формы с упором на неуправляемые поля.        |
| TanStack Form   | Да    | Да    | Явное управляемое состояние и типизация сценариев. |

React Hook Form намеренно документируется только для React. В Solid используйте нативную форму,
Formisch или TanStack Form, а не слой совместимости для React-хуков.

## Основные правила

1. Оборачивайте элемент управления в `Field`, если ему нужны подпись, подсказка, ошибка или общее состояние.
2. Используйте `Fieldset` для связанной группы с одной видимой легендой.
3. Оставляйте подписи видимыми и задавайте `name` каждому отправляемому элементу.
4. Передавайте `invalid`, `required`, `disabled` и `readOnly` через поле или корневой компонент Moduix.
5. Добавляйте каждую необходимую нативную часть формы ровно один раз.

| Компонент      | Нативная часть формы                                              |
| -------------- | ----------------------------------------------------------------- |
| `Checkbox`     | `HiddenInput`                                                     |
| `RadioGroup`   | `ItemHiddenInput` для каждого явно составленного элемента        |
| `SegmentGroup` | `ItemHiddenInput` для каждого явно составленного элемента        |
| `Select`       | `HiddenSelect`                                                    |
| `Slider`       | `HiddenInput` для каждого отправляемого ползунка                 |
| `DateInput`    | Индексированные `HiddenInput`, если диапазону нужны разные имена |
| `SignaturePad` | `HiddenInput` с сериализованным приложением значением            |
| Другие элементы Ark со скрытой частью | Соответствующий `HiddenInput` внутри корня      |

Не создавайте второй скрытый input для того же значения. `Combobox` получает имя формы через корень
и не требует дополнительной скрытой части.

## Валидация и сброс

Сохраняйте нативные ограничения, если проверкой управляет браузер. Если ошибки показывает
библиотека, добавьте `noValidate`, передайте результат в `Field invalid` и выводите понятный
`FieldErrorText` после запуска выбранного сценария валидации.

Нативный сброс восстанавливает неуправляемые элементы. Для управляемых полей вызывайте API сброса
библиотеки, чтобы ее состояние и значения Moduix оставались синхронизированы. При ошибке переводите
фокус на настоящий элемент: `Input`, `Textarea`, `SelectTrigger` или `ComboboxInput`.

## Отправка и серверные ошибки

Явно показывайте готовность, отправку, ошибку и успех. На время асинхронного запроса блокируйте
повторную отправку, а после ошибки сохраняйте введенные значения и возможность повторить запрос.

Ошибку конкретного значения связывайте с `FieldErrorText`, а общую ошибку запроса выводите через
`role="alert"`. Для повторяющихся полей используйте стабильные идентификаторы. Всегда повторно
нормализуйте и проверяйте данные на сервере. Подробнее о поведении Ark читайте в
[руководстве Ark UI по формам](https://ark-ui.com/docs/guides/forms).
