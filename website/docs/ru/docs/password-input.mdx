## Какой компонент выбрать

Используйте `PasswordInput`, если конфиденциальное значение нужно скрывать по умолчанию и показывать
только по запросу пользователя.

- Выберите **`Input`** для обычного текстового поля без кнопки показа.
- Выберите **`PasswordInput`** для паролей, ключей API и других конфиденциальных строк.
- Выберите **`InputGroup`**, если полю нужно произвольное встроенное действие, не связанное с показом пароля.

## Анатомия

```text
PasswordInput / PasswordInput.Root
├─ PasswordInput.Label
└─ PasswordInput.Field
   └─ PasswordInput.Control
      ├─ PasswordInput.Input
      └─ PasswordInput.VisibilityTrigger
         └─ PasswordInput.Indicator

PasswordInput.RootProvider
└─ та же структура, подключённая к состоянию usePasswordInput()
```

| Часть                                  | Роль                                                                            |
| -------------------------------------- | ------------------------------------------------------------------------------ |
| `PasswordInput` / `PasswordInput.Root` | Корневая часть, которая управляет видимостью пароля и состоянием поля.          |
| `PasswordInput.RootProvider`           | Подключает части к состоянию, созданному через `usePasswordInput()`.            |
| `PasswordInput.Label`                  | Подписывает поле и отражает состояния required, disabled, invalid и read-only.  |
| `PasswordInput.Field`                  | Готовая композиция из контейнера, поля ввода, кнопки показа и индикатора.        |
| `PasswordInput.Control`                | Объединяет поле ввода и кнопку показа.                                          |
| `PasswordInput.Input`                  | Нативное поле, у которого `type` меняется между `password` и `text`.            |
| `PasswordInput.VisibilityTrigger`      | Кнопка, которая переключает видимость.                                          |
| `PasswordInput.Indicator`              | Показывает содержимое для видимого или скрытого состояния; moduix добавляет иконки по умолчанию. |

## Композиция

`PasswordInput.Field` это готовая композиция из контейнера, поля ввода, кнопки показа и индикатора.
Замените её на `Control`, `Input`, `VisibilityTrigger` и `Indicator`, если нужно изменить структуру,
свойства поля, иконки или стилизацию отдельных частей.

Храните состояние видимости в корневом компоненте. Используйте `defaultVisible` для начального состояния
без внешнего управления или передайте `visible` вместе с `onVisibilityChange(details)`, если видимостью
управляет состояние приложения. Используйте `usePasswordInput()` с `PasswordInput.RootProvider`, если
соседнему или внешнему элементу нужен доступ к тому же состоянию.

Передавайте свойства значения, например `value`, `defaultValue`, `placeholder` и `onInput` или `onChange`,
в `PasswordInput.Input`. Нативное поле участвует в отправке и сбросе формы, поэтому `name` нужно передать
в `PasswordInput`; отдельной части `HiddenInput` этот компонент не создаёт.

## Стилизация

Пакеты с CSS Modules предоставляют переменные `--moduix-password-input-*` для оболочки контейнера,
области ввода и кнопки показа поверх общих стилей `Input`. В пакетах Tailwind используются utility-классы
и классы потребителя, а не эти CSS-переменные компонента.

### Хуки стилизации

- Корневая часть и провайдер корня предоставляют `data-slot="password-input-root"` и
  `data-slot="password-input-root-provider"`.
- Части Ark сохраняют `data-scope="password-input"` и значения `data-part` для `root`, `label`, `control`,
  `input`, `visibility-trigger` и `indicator`.
- Для стилизации видимости используйте `data-state="visible" | "hidden"` на поле, кнопке и индикаторе.
  Используйте `data-disabled`, `data-invalid`, `data-readonly` и `data-required` там, где Ark их добавляет.
  Контейнер получает атрибуты disabled, invalid и read-only, используемые оболочкой поля.
- Ark не предоставляет CSS-переменные, специфичные для этого компонента во время выполнения; moduix добавляет
  `--moduix-password-input-*` для визуальных настроек в пакетах с CSS Modules.
