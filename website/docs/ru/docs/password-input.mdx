## Какой компонент выбрать

Используйте `PasswordInput`, если конфиденциальное значение нужно скрывать по умолчанию и показывать
только по запросу пользователя.

- Выберите **`Input`** для обычного текстового поля без кнопки показа.
- Выберите **`PasswordInput`** для паролей, ключей API и других конфиденциальных строк.
- Выберите **`InputGroup`**, если полю нужно произвольное встроенное действие, не связанное с показом пароля.

## Базовый пример


Используйте `PasswordInput` как корневой компонент и добавьте `PasswordInputLabel` с
`PasswordInputField`. Поле отрисовывает ввод и кнопку показа с иконками moduix по умолчанию, а Ark
управляет состоянием и доступностью.

## Анатомия

```text
PasswordInput
├─ PasswordInputLabel
└─ PasswordInputField
   └─ PasswordInputControl
      ├─ PasswordInputInput
      └─ PasswordInputVisibilityTrigger
         └─ PasswordInputIndicator

PasswordInputRootProvider
└─ та же структура, подключённая к состоянию usePasswordInput()
```

| Часть                                  | Роль                                                                            |
| -------------------------------------- | ------------------------------------------------------------------------------ |
| `PasswordInput`                    | Корневая часть, которая управляет видимостью пароля и состоянием поля.          |
| `PasswordInputRootProvider`           | Подключает части к состоянию, созданному через `usePasswordInput()`.            |
| `PasswordInputContext`                | Даёт доступ к состоянию корневого компонента через render prop.                 |
| `PasswordInputLabel`                  | Подписывает поле и отражает состояния required, disabled, invalid и read-only.  |
| `PasswordInputField`                  | Готовая композиция из контейнера, поля ввода, кнопки показа и индикатора.        |
| `PasswordInputControl`                | Объединяет поле ввода и кнопку показа.                                          |
| `PasswordInputInput`                  | Нативное поле, у которого `type` меняется между `password` и `text`.            |
| `PasswordInputVisibilityTrigger`      | Кнопка, которая переключает видимость.                                          |
| `PasswordInputIndicator`              | Показывает содержимое для видимого или скрытого состояния; moduix добавляет иконки по умолчанию. |

## Композиция

`PasswordInputField` это готовая композиция из контейнера, поля ввода, кнопки показа и индикатора.
Замените её на `PasswordInputControl`, `PasswordInputInput`, `PasswordInputVisibilityTrigger` и
`PasswordInputIndicator`, если нужно изменить структуру,
свойства поля, иконки или стилизацию отдельных частей.

Храните состояние видимости в корневом компоненте. Используйте `defaultVisible` для начального состояния
без внешнего управления или передайте `visible` вместе с `onVisibilityChange(details)`, если видимостью
управляет состояние приложения. Используйте `usePasswordInput()` с `PasswordInputRootProvider`, если
соседнему или внешнему элементу нужен доступ к тому же состоянию.

Передавайте свойства значения, например `value`, `defaultValue`, `placeholder` и `onInput` или `onChange`,
в `PasswordInputInput`. Нативное поле участвует в отправке и сбросе формы, поэтому `name` нужно передать
в `PasswordInput`; отдельной части `HiddenInput` этот компонент не создаёт.

## Примеры

### Автозаполнение

Укажите `autoComplete="new-password"`, если пользователь создаёт или меняет пароль. Для формы входа
по умолчанию используется `"current-password"`.

<Example name="password-input/autocomplete" />

### Контролируемая видимость

Используйте объект `details` из Ark, когда видимостью должна управлять внешняя логика приложения.

<Example name="password-input/controlled-visibility" />

### Игнорирование менеджеров паролей

Используйте `ignorePasswordManagers` для ключей API и сгенерированных секретов, а не для данных входа.
Опция просит поддерживаемые менеджеры паролей не добавлять поверх поля свои элементы. Сейчас она работает
с 1Password, LastPass, Bitwarden, Dashlane и Proton Pass.

<Example name="password-input/ignore-password-managers" />

### Размеры

Проп `size` на корне подгоняет высоту и размер текста под `Input`. По умолчанию `md`; кнопка показа и
иконка масштабируются вместе с ним.

<Example name="password-input/sizes" />

### Root Provider

Используйте `usePasswordInput` и `PasswordInputRootProvider`, если соседнему элементу управления или индикатору
состояния нужен доступ к тому же объекту состояния Ark.

<Example name="password-input/root-provider" />

### Индикатор надёжности

Храните значение пароля в `PasswordInputInput`, а дополнительные элементы интерфейса размещайте под
контейнером поля.

<Example name="password-input/strength-meter" />

### С Field

Используйте `Field` вокруг `PasswordInput`, если полю нужны поясняющий текст, сообщение об ошибке или
общее состояние невалидности в составе формы.

<Example name="password-input/with-field" />

### С валидацией

Используйте `FieldErrorText`, чтобы связать сообщение об ошибке с полем. Ark передаёт состояние
`invalid` подписи, полю ввода, контейнеру и индикатору.

<Example name="password-input/with-validation" />

### Расширенная настройка

Собирайте части Ark напрямую, если нужно изменить поле ввода, переключатель видимости, индикатор или
структуру, отличную от стандартной композиции `PasswordInputField`.

<Example name="password-input/advanced-customization" />

## Стилизация

Пакеты с CSS Modules предоставляют три переменные: `--moduix-password-input-width`,
`--moduix-password-input-height` и `--moduix-password-input-radius`. Цвета, рамки, отступы, типографика
и focus ring берутся из токенов foundation; переопределяйте их классом на нужной части. В пакетах
Tailwind используются utility-классы и классы потребителя.

### Хуки стилизации

- Корневая часть и провайдер корня предоставляют `data-slot="password-input-root"` и
  `data-slot="password-input-root-provider"`.
- Части Ark сохраняют `data-scope="password-input"` и значения `data-part` для `root`, `label`, `control`,
  `input`, `visibility-trigger` и `indicator`.
- Для стилизации видимости используйте `data-state="visible" | "hidden"` на поле, кнопке и индикаторе.
  Используйте `data-disabled`, `data-invalid`, `data-readonly` и `data-required` там, где Ark их добавляет.
  Контейнер получает атрибуты disabled, invalid и read-only, используемые оболочкой поля.
- Корень дублирует `size` в `data-size`. Отключённый `PasswordInput` внутри отключённого `Field` или
  `Fieldset` не затемняется второй раз.
