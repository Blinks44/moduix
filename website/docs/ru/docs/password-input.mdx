## Выбор подходящего компонента

Используйте `PasswordInput`, когда одно безопасное значение должно оставаться замаскированным по умолчанию, но при этом разрешается
действие раскрытия, контролируемое пользователем.

- Выберите **`Input`** для полей в виде простого текста без переключателя видимости.
- Выберите **`PasswordInput`** для паролей, ключей API и других защищенных строк.
- Выберите **`InputGroup`**, если для поля требуется настраиваемое встроенное действие, не связанное с видимостью пароля.

## Анатомия

```tsx
<PasswordInput>
  <PasswordInput.Label />
  <PasswordInput.Field />
</PasswordInput>
```

Для расширенной настройки замените `PasswordInput.Field` его явными частями Ark:

```tsx
<PasswordInput>
  <PasswordInput.Label />
  <PasswordInput.Control>
    <PasswordInput.Input />
    <PasswordInput.VisibilityTrigger>
      <PasswordInput.Indicator />
    </PasswordInput.VisibilityTrigger>
  </PasswordInput.Control>
</PasswordInput>
```

|Часть|Роль|
| -------------------------------------- | ------------------------------------------------------------------------------ |
|`PasswordInput` / `PasswordInput.Root`|Управляет видимостью пароля и состоянием поля.|
|`PasswordInput.RootProvider`|Отображает корневой элемент из состояния, созданного через `usePasswordInput`.|
|`PasswordInput.Label`|Связывает подпись с полем и получает состояния required, disabled, invalid и read-only.|
|`PasswordInput.Field`|Отображает стандартную композицию: поле, кнопку видимости и индикатор.|
|`PasswordInput.Control`|Располагает триггер ввода и видимости вместе.|
|`PasswordInput.Input`|Собственная входная часть, `type` которой переключается между `password` и `text`.|
|`PasswordInput.VisibilityTrigger`|Кнопка, которая переключает состояние видимости.|
|`PasswordInput.Indicator`|Показывает видимый/скрытый контент; moduix предоставляет значки по умолчанию.|

## Композиция

### Рекомендуемая композиция

Используйте `PasswordInput.Field` для стандартной композиции поля, кнопки видимости и индикатора. Передавайте в
`PasswordInput` состояние видимости, состояние формы, идентификаторы, переводы и свойства менеджера паролей.

### Когда нужна собственная композиция

Используйте `Control`, `Input`, `VisibilityTrigger` и `Indicator` напрямую, если структура, значки или оформление
должны отличаться от `PasswordInput.Field`. Применяйте `asChild`, только когда часть должна отображаться собственным
семантическим элементом.

### Свойства по умолчанию

|Опора|По умолчанию|Примечания|
| -------------------------------- | -------------------- | ------------------------------------------------------ |
|`autoComplete`|`"current-password"`|Ставим на вход через корневую машину.|
|`defaultVisible`|`false`|Начальное состояние неконтролируемой видимости.|
|`visible`|неконтролируемый|Состояние контролируемой видимости.|
|`PasswordInput.Field`| -                    |Отображает стандартные видимые части и передаёт управляющие свойства.|
|`onVisibilityChange`| -                    |Получает объект Ark `details`; текущее значение находится в `details.visible`.|
|`translations.visibilityTrigger`|значение Ark|Функция для локализации доступного названия кнопки видимости.|
|`ignorePasswordManagers`|`false`|Добавляет подсказки по игнорированию поддерживаемого менеджера паролей.|

### Особенности поведения

- Управляйте видимостью с помощью `visible` и `onVisibilityChange(details)`.
- Управляйте значением поля непосредственно на `PasswordInput.Input` с помощью встроенных `value` и `onChange`.
- Используйте корневые свойства, такие как `name`, `required`, `disabled`, `readOnly`, `invalid`, `ids` и
`translations` прямо из пользовательского интерфейса Ark.
- Используйте `usePasswordInput` с `PasswordInput.RootProvider`, когда то же самое требуется другому компоненту.
состояние видимости за пределами визуализированного дерева.
- `PasswordInput.Input`, `PasswordInput.VisibilityTrigger` и `PasswordInput.Indicator` открывают
`data-state="visible" | "hidden"` для стайлинга.

## Стилизация

`PasswordInput` настраивает оболочку управления, область ввода текста и триггер видимости с помощью
Токены `--moduix-password-input-*`, наложенные на контракт общего ввода.

### Хуки стилизации

- Корневой элемент и корневой провайдер предоставляют `data-slot="password-input-root"` и
`data-slot="password-input-root-provider"`.
- Детали Ark сохраняют значения `data-scope="password-input"` и `data-part` для `root`, `label`,
`control`, `input`, `visibility-trigger` и `indicator`.
- Стилизация состояния использует `data-state="visible" | "hidden"` на входе, триггере и индикаторе, а также
`data-disabled`, `data-invalid`, `data-readonly` и `data-required`, где их предоставляет Ark.
- Ark не предоставляет переменные runtime CSS-переменные, специфичные для ввода пароля; moduix добавляет
Переменные `--moduix-password-input-*` для визуальных настроек по умолчанию.
