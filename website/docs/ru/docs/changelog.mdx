## Svelte присоединяется к React, Solid и Vue

<SvelteReleaseHero />

moduix теперь поддерживает Svelte 5. В [`@moduix/svelte`](/docs/quick-start) и
`@moduix/svelte-tailwind` есть все компоненты остальных адаптеров с теми же плоскими именами,
токенами и темами.

Компоненты устроены так, как принято в Svelte: руны, сниппеты и `bind:`. Пакеты публикуют исходники
`.svelte`, поэтому их собирает компилятор Svelte вашего приложения, а SvelteKit рендерит их на сервере
без дополнительной настройки. Если хотите держать исходники в своём репозитории, используйте реестры
`@moduix-svelte` и `@moduix-svelte-tailwind`.

Svelte добавлен в [быстрый старт](/docs/quick-start), [настройку SvelteKit](/docs/installation/sveltekit),
[интеграции форм](/docs/forms), [блоки](/blocks) и [готовые проекты](/docs/starters).
</ChangelogNewsItem>

## Vue присоединяется к React и Solid

<VueReleaseHero />

Vue стал нативным адаптером moduix наряду с React и Solid. [`@moduix/vue`](/docs/quick-start) и
`@moduix/vue-tailwind` предоставляют полный каталог компонентов с общими токенами и темами.

### Несовместимые изменения в 3.0

Все компоненты теперь используют плоские именованные экспорты в React, Solid и Vue, как в CSS Modules,
так и в Tailwind. Это касается npm-пакетов и исходников из реестра. При обновлении с 2.x замените
импорты и имена компонентов:

| Раньше | Теперь |
| --- | --- |
| `Dialog.Root` | `Dialog` |
| `Dialog.Trigger` | `DialogTrigger` |
| `Dialog.Content` | `DialogContent` |
| `Dialog.RootProvider` | `DialogRootProvider` |
| `Dialog.Context` | `DialogContext` |

Такая схема имён действует для всех групп компонентов. Составные экспорты вида `Dialog.*`
и дублирующие имена корневых компонентов вроде `DialogRoot` удалены. Хуки, например `useDialog`,
по-прежнему доступны как отдельные именованные экспорты.

### Нативная композиция Vue

Используйте плоские именованные экспорты в SFC с `script setup`, нативными свойствами, событиями,
`v-model` и scoped slots. Реестры `@moduix-vue` и `@moduix-vue-tailwind` копируют Vue-исходники в приложение.

[Быстрый старт](/docs/quick-start), [интеграции форм](/docs/forms) и [блоки](/blocks) теперь
содержат Vue вместе с React и Solid во всех трёх языках документации. Страницы компонентов описывают
реальные различия адаптеров Ark и ограничения конкретных версий upstream. Svelte остаётся в планах.

### Установка блоков

Бывшие рецепты стали [блоками](/blocks), которые можно установить через реестр shadcn.
Все 12 блоков содержат исходники для React, Solid и Vue, стили разметки и необходимые UI-компоненты.
Для компонентов можно выбрать CSS Modules или Tailwind; разметка блока в обоих вариантах использует общий CSS Module.

После [настройки реестра](/docs/quick-start) добавьте блок одной командой:

<PackageManagerTabs command="shadcn@latest add @moduix-react/login-simple" dlx />

Команды для Solid, Vue и Tailwind приведены в секции установки каждого блока.
</ChangelogNewsItem>

## Tailwind для всего каталога

<TailwindReleaseHero />

Полный каталог moduix теперь доступен в варианте Tailwind. [`@moduix/react-tailwind`](/docs/quick-start)
и `@moduix/solid-tailwind` содержат те же компоненты, что и пакеты на CSS Modules.

Публичный API и поведение компонентов не меняются, поэтому выбор Tailwind не влияет на их
композицию.

Ваши значения `className` или `class` объединяются с настройками по умолчанию последними с помощью
`tailwind-merge`. Пространства имён реестра `@moduix-react-tailwind` и `@moduix-solid-tailwind`
содержат базовый файл стилей, поэтому установленные файлы можно сразу настраивать.
</ChangelogNewsItem>

## Полный каталог для Solid

<SolidReleaseHero />

Полный каталог moduix теперь доступен для Solid. [`@moduix/solid`](/docs/quick-start) и
`@moduix/solid-tailwind` используют нативные API Solid и примитивы Ark UI.

Компоненты Solid используют `class` и нативную композицию Solid. Их публичные контракты совпадают с
React-пакетами, а реализация учитывает модель рендеринга Solid.

Для Solid доступны CSS Modules и Tailwind. Оба варианта используют общие токены и темы, а также
пространства имён реестра `@moduix-solid` и `@moduix-solid-tailwind`.
</ChangelogNewsItem>

## Оглавление для длинных страниц

<TableOfContentsHero />

[Table of Contents](/docs/table-of-contents) следит за заголовками в области просмотра и выделяет
текущий раздел. Передайте ему нужные заголовки, и каждый пункт будет связан с соответствующим
заголовком.

Используйте `TocContent` для области чтения и `TocNav` для списка заголовков. Активный пункт
будет меняться по мере прокрутки страницы.

Для иерархии используйте `TocIndicator` или `TocRail`. Добавляйте `TocRootProvider`, если
внешним элементам нужно использовать состояние оглавления.
</ChangelogNewsItem>

## Группы ссылок без скрытых переходов

<NavigationMenuHero />

[Navigation Menu](/docs/navigation-menu) разделяет прямые переходы и группы связанных ссылок. Это
удобно для верхнего уровня навигации сайта или продукта.

Для прямого перехода используйте `NavigationMenuLink`. Для группы ссылок соедините
`NavigationMenuTrigger` и `NavigationMenuContent`.

Если несколько панелей должны анимироваться в одной области, добавьте `NavigationMenuViewport`.
Ark UI отвечает за клавиатурное взаимодействие, фокус и открытый пункт. `NavigationMenuArrow` необязателен.
</ChangelogNewsItem>

## Единая оболочка для графиков

<ChartHero />

[Chart](/docs/chart) добавляет доступную HTML-оболочку `figure` вокруг TanStack Charts. Опишите график
через TanStack, а затем добавьте заголовок, легенду, компактную подсказку и настройки анимации moduix.

TanStack по-прежнему отвечает за метки, шкалы, взаимодействия и колбэки. Соберите график с
`ChartHeader`, `ChartPlot` и `ChartLegend`, чтобы получить единую структуру `figure`.

TanStack также управляет клавиатурной навигацией и жизненным циклом подсказки. Анимация moduix
учитывает настройку «Уменьшение движения», а `motion={false}` отключает её.
</ChangelogNewsItem>

## Ark UI отвечает за поведение компонентов

<V2MigrationHero />

Система компонентов теперь использует Ark UI для состояния, взаимодействия и доступности, если для
компонента есть соответствующий примитив. moduix сохраняет CSS Modules, дизайн-токены и оба способа
установки.

Компоненты с примитивом Ark UI используют его для состояния и взаимодействия. Вместе с этим они
получают готовое поведение для доступных интерфейсов.

Публичная композиция и низкоуровневые свойства следуют контрактам Ark. Установите пакет или
скопируйте исходный код в приложение, если хотите сами отвечать за реализацию.
</ChangelogNewsItem>
