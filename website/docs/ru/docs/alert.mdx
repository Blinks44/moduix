## Справочник API

Ark UI не предоставляет отдельный примитив `alert`. moduix собирает `Alert` с помощью официальной
[фабрики Ark](https://ark-ui.com/docs/guides/composition#the-ark-factory) и следует рекомендациям Ark по
[композиции](https://ark-ui.com/docs/guides/composition), [стилизации](https://ark-ui.com/docs/guides/styling) и
[работе с ref](https://ark-ui.com/docs/guides/ref).

Публичные части: `Alert.Root`, `Alert.Indicator`, `Alert.Content`, `Alert.Title`,
`Alert.Description` и `Alert.Actions`.

## Выбор подходящего компонента

Используйте `Alert`, когда сообщение должно оставаться в разметке страницы и занимать место в обычном
потоке документа.

- Используйте **`Alert`** для встроенных сообщений о статусе, результатах валидации и системных событиях
  в формах, панелях или содержимом страницы.
- Используйте **`Toast`** для временных уведомлений, которые появляются вне потока документа и закрываются сами.

## Анатомия

```text
Alert / Alert.Root
├─ Alert.Indicator (optional)
├─ Alert.Title
├─ Alert.Description
└─ Alert.Content (optional)
   ├─ Alert.Title
   ├─ Alert.Description
   ├─ Alert.Actions (optional)
   └─ Extra custom blocks
```

| Часть                  | Назначение                                                            | `data-part`   |
| ---------------------- | --------------------------------------------------------------------- | ------------- |
| `Alert` / `Alert.Root` | Корневая часть. Применяет стили и семантику, соответствующие статусу. | `root`        |
| `Alert.Indicator`      | Необязательная часть для индикатора. Приводит дочерние SVG-иконки к единому размеру. | `indicator`   |
| `Alert.Content`        | Необязательная обёртка-колонка, которая объединяет текст и действия. | `content`     |
| `Alert.Title`          | Часть с заголовком уведомления. По умолчанию рендерится как `p`.    | `title`       |
| `Alert.Description`    | Часть с дополнительным текстом сообщения.                          | `description` |
| `Alert.Actions`        | Необязательная строка действий с переносом внутри `Content`.       | `actions`     |

## Композиция

### Рекомендуемая композиция

Для обычного встроенного сообщения используйте непосредственно `Alert`, `Alert.Title` и `Alert.Description`.

С помощью `status` задайте тип сообщения: `info`, `success`, `warning` или `error`.

Добавьте `Alert.Indicator`, если рядом с текстом нужен явный визуальный ориентир. Компонент намеренно
не добавляет специальные свойства или наборы слотов для действий.

### Когда нужна собственная композиция

Добавьте `Alert.Content`, если заголовок, описание и дополнительные элементы управления должны оставаться
в одной колонке рядом с индикатором. Используйте `Alert.Actions` для строки действий с переносом внутри
этой колонки. Если в структуре документа нужен другой уровень заголовка, используйте `Alert.Title asChild`.

Например:

```tsx
<Alert.Title asChild>
  <h2>Billing issue</h2>
</Alert.Title>
```

### Свойства по умолчанию

| Свойство | По умолчанию | Значения и примечания                                             |
| -------- | ------------ | ----------------------------------------------------------------- |
| `status` | `info`       | `info`, `success`, `warning`, `error`                            |
| `role`   | Определяется автоматически | По умолчанию `role="status"`; при `status="error"` используется `role="alert"` |

### Особенности поведения

- `Alert.Root` по умолчанию использует `role="status"` и переключается на `role="alert"` при `status="error"`.
- Эти роли создают области живого обновления с разным приоритетом. `status` сообщает об изменениях
  ненавязчиво, а `alert` объявляет их сразу. Если сообщение должно быть озвучено, сначала добавьте
  уведомление в документ, а затем обновите его текст. Содержимое, которое уже было на странице при
  загрузке, может не озвучиваться.
- Переопределите `role`, если компонент служит статическим информационным блоком, а не сообщает об изменении.
  Для дополнительной статической информации используйте `role="note"`.
- Для `Alert.Indicator` по умолчанию задан `aria-hidden="true"`.
- `Alert.Title` по умолчанию рендерится как `p`, а с помощью Ark `asChild` позволяет использовать другой
  элемент заголовка.
- Существенный смысл должен быть указан в заголовке или описании, поскольку индикатор остаётся
  `aria-hidden`.
- `Alert.Content` необязателен. Используйте его, если заголовок, описание и дополнительные элементы управления должны находиться в одной
  колонке содержимого рядом с индикатором.
- `Alert.Actions` необязателен. Используйте его, если кнопки или ссылки должны использовать стили строки действий с переносом по умолчанию.
- Компонент отвечает только за отображение. Он не управляет состоянием закрытия, фокусом и поведением
  клавиатуры для действий, которые вы в него добавляете.

## Стилизация

Используйте `className` на корневой части или на отдельных частях для локальных стилей. Переопределяйте
CSS-переменные `--moduix-alert-*` на корневой части, если уведомлению нужна локальная тема.

Общие переменные `--moduix-alert-bg`, `--moduix-alert-border-color`, `--moduix-alert-color` и
`--moduix-alert-indicator-color` переопределяют оформление всех статусов. Используйте соответствующие
переменные `--moduix-alert-<status>-*`, если нужно изменить только один статус.

Встроенные статусы также используют общие токены палитры:

| Статус     | Общий токен                  | По умолчанию                 |
| ---------- | ---------------------------- | ---------------------------- |
| `info`     | `--moduix-color-card`        | карточка темы                 |
| `success`  | `--moduix-color-success`     | `oklch(0.627 0.194 149.214)` |
| `warning`  | `--moduix-color-warning`     | `oklch(0.795 0.184 86.047)`  |
| `error`    | `--moduix-color-destructive` | деструктивный цвет темы      |

### Хуки стилизации

- Стабильные селекторы `data-slot`: `alert-root`, `alert-indicator`, `alert-content`, `alert-title`,
  `alert-description` и `alert-actions`
- Селекторы в стиле Ark: `data-scope="alert"` с `data-part="root"`, `indicator`, `content`,
  `title`, `description` или `actions`
- `Alert.Root` записывает выбранный статус в `data-status`
