## Базовый пример

Используйте `Swap`, когда элемент интерфейса должен переключаться между двумя визуальными состояниями,
например когда иконка меняется после действия пользователя. Передайте текущее логическое значение в
`swap`: при `false` отображается индикатор `off`, при `true` индикатор `on`. Внешний элемент управления отвечает
за взаимодействие и доступное имя.

## Анатомия

```text
Swap / Swap.Root
├─ Swap.Indicator type="off"
└─ Swap.Indicator type="on"
```

| Часть                | Назначение                                                        |
| -------------------- | ----------------------------------------------------------------- |
| `Swap` / `Swap.Root` | Передаёт состояние `swap` из Ark и размещает оба визуальных состояния в одной ячейке. |
| `Swap.RootProvider`  | Предоставляет состояние, созданное с помощью `Swap.useSwap()` вне поддерева.            |
| `Swap.Indicator`     | Отрисовывает состояние `on` или `off`, выбранное свойством `type`.                       |

Размещайте оба индикатора непосредственными дочерними элементами корня. Они используют одну ячейку
сетки, а встроенные рецепты анимации остаются в пределах этого экземпляра `Swap`.

## Композиция

### Рекомендуемая композиция

`Swap` отвечает только за визуальную часть, а не за кнопку или переключатель. Поместите его внутрь
семантической кнопки, ссылки или элемента, который сообщает статус. Состояние, обработчики событий,
фокус и доступное имя оставьте у родительского элемента. Если индикаторы содержат только иконки,
добавьте им `aria-hidden="true"`.

### Когда использовать собственную анимацию

Используйте `animation`, чтобы выбрать один из встроенных рецептов: `fade`, `scale`, `rotate` или
`flip`. Свойство также принимает любое пользовательское имя. moduix записывает его в
`data-animation` и не применяет встроенную анимацию, поэтому переход можно полностью описать в CSS
с помощью атрибутов `data-state` от Ark.

### Свойства по умолчанию

| Свойство        | По умолчанию | Описание                                                               |
| --------------- | ------------ | ---------------------------------------------------------------------- |
| `swap`          | `false`      | Показывает индикатор `off`.                                           |
| `animation`     | `scale`      | Использует пресет moduix с затуханием и масштабированием.             |
| `lazyMount`     | `false`      | Сразу монтирует оба индикатора, не откладывая неактивный.              |
| `unmountOnExit` | `false`      | Оставляет индикатор в DOM после завершения его анимации выхода.        |

### Особенности поведения

- `swap` управляется извне. `Swap` сам не реагирует на наведение или клики и по умолчанию отрисовывает
  элемент `span`.
- Presence от Ark добавляет индикаторам `data-state="open" | "closed"`, чтобы CSS мог различать
  состояния появления и выхода. Используйте `lazyMount` или `unmountOnExit`, если нужно управлять
  моментом добавления неактивных индикаторов в DOM и их удаления.
- `Swap.RootProvider` принимает состояние, возвращённое `Swap.useSwap()`, а `useSwapContext()` позволяет
  потомку прочитать состояние ближайшего провайдера.
- `asChild` доступен для каждой отрисовываемой части. Передавайте ровно один семантический дочерний
  элемент, чтобы Ark мог объединить с ним свои свойства и ref.

## Стилизация

Встроенные рецепты используют перечисленные ниже CSS-переменные. Пользовательское имя анимации отключает
эти рецепты, но в собственном CSS по-прежнему можно использовать `--moduix-swap-transition`.

### Хуки стилизации

- `Swap.Root` использует `data-slot="swap-root"`.
- `Swap.RootProvider` использует `data-slot="swap-root-provider"`.
- `Swap.Indicator` использует `data-slot="swap-indicator"`.
- `animation` доступно как `data-animation` на `Swap` и `Swap.RootProvider`.
- Встроенные рецепты нацелены только на непосредственных потомков `Swap.Indicator` своего корня.
- Ark добавляет `data-scope="swap"` и `data-part="root" | "indicator"`.
- Ark добавляет индикаторам `data-state="open" | "closed"`. moduix использует эти атрибуты во
  встроенных и пользовательских рецептах анимации.
