# AI

moduix спроектирован так, чтобы оставаться понятным и людям, и AI-ассистентам. Сначала предоставьте ассистенту минимально необходимую документацию, а затем попросите его работать с публичным API компонентов, который уже используется в вашем проекте.

## Выберите подходящий контекст

| Что вам нужно | Что предоставить ассистенту |
| --- | --- |
| Обзор продукта или задача по поиску компонента | [`llms.txt`](/llms.txt) |
| Помощь с одним компонентом, руководством или ошибкой | Функцию **Copy Markdown** этой страницы |
| Широкий обзор репозитория | [`llms-full.txt`](/llms-full.txt) |

У каждой MDX-страницы документации есть канонический URL Markdown, например
`https://moduix.dev/docs/button.md`. Он содержит содержимое страницы без интерфейса документации, поэтому это лучший контекст по умолчанию для целевой задачи по реализации или отладке.

## Спросите о текущей странице

Используйте **Copy Markdown** под заголовком любой страницы, когда ассистенту нужно содержимое страницы без интерфейса документации. На страницах компонентов также есть меню **Open** с быстрым доступом к GitHub, **View as Markdown**, ChatGPT и Claude.

Используйте URL, а затем конкретно опишите свою задачу. Например:

```text
Read https://moduix.dev/docs/dialog.md. Add a confirmation dialog to our delete action.
We use @moduix/react/dialog from the npm package. Keep the Ark composition explicit and make the
trigger a button.
```

## Устанавливайте компоненты с помощью AI-ассистента

Прежде чем ассистент начнёт писать импорты или команды установки, сообщите ему, какую модель владения компонентами moduix использует проект:

| Модель проекта | Что сообщить ассистенту |
| --- | --- |
| Компоненты, управляемые пакетным менеджером | Импорты `@moduix/react/*` и `@moduix/react/style.css` |
| Компоненты, исходный код которых принадлежит проекту | Настроенный реестр `@moduix-react`, `components.json` проекта и его CLI |

В проекте, исходный код компонентов которого принадлежит проекту, ассистенту следует прочитать страницу компонента и проверить `components.json` перед добавлением элемента реестра. В руководстве [«Быстрый старт»](/docs/quick-start) приведена полная настройка реестра.

## Используйте Skill moduix

Установите публичный Skill с помощью Skills.sh:

```bash
npx skills add https://github.com/Blinks44/moduix --skill moduix
```

Установщик настраивает Skill для поддерживаемого агента. Перед изменением кода он проверяет существующие импорты и `components.json`, а затем использует каноническую документацию, поиск через shadcn и безопасную проверку различий для обновлений компонентов, исходный код которых принадлежит проекту. Установка компонентов через пакетный менеджер и копирование компонентов через shadcn остаются равноправными вариантами. В агентах с поддержкой Skills используйте `$moduix`.

## Используйте shadcn MCP server

shadcn MCP server работает с уже существующим реестром moduix. moduix не запускает отдельный MCP server: настройте реестр в потребляющем проекте, а затем позвольте shadcn предоставить его вашему AI-клиенту.

### 1. Настройте реестр

В `components.json` потребляющего проекта должен быть указан URL реестра moduix:

```json
{
  "registries": {
    "@moduix-react": "https://moduix.dev/r/react/{name}.json"
  }
}
```

Полная настройка `components.json` описана в руководстве [«Быстрый старт»](/docs/quick-start).

### 2. Подключите AI-клиент

Для клиентов, поддерживаемых инициализатором shadcn, запустите его в потребляющем проекте и выберите нужный клиент. Например:

```bash
npx shadcn@latest mcp init --client cursor
```

Сейчас Codex использует ручную настройку MCP. Добавьте сервер в `~/.codex/config.toml`, а затем перезапустите Codex:

```toml
[mcp_servers.shadcn]
command = "npx"
args = ["shadcn@latest", "mcp"]
```

В [руководстве по shadcn MCP](https://ui.shadcn.com/docs/mcp) приведена актуальная настройка для Claude Code, Cursor, VS Code, Codex и других поддерживаемых клиентов.

### 3. Найдите нужный элемент перед установкой

Попросите ассистента проверить подходящий элемент moduix до того, как он изменит файлы. Эти запросы подходят для компонентов, блоков и тем:

```text
Find the moduix component for an editable text field. Show the component documentation and registry
item before proposing code.
```

```text
Find a moduix sign-in block. Show its registry dependencies and responsive behavior, but do not
install it yet.
```

```text
Find a high-contrast moduix theme. Show how it is applied before changing the project.
```

### 4. Проверьте вариант с CLI

Используйте CLI, когда MCP недоступен или вам нужен журнал действий в командной строке. В проекте, исходный код компонентов которого принадлежит проекту, проверьте текущую конфигурацию, найдите элемент по потребности продукта, изучите элемент, а затем предварительно просмотрите изменения:

```bash
npx shadcn@latest info --json
npx shadcn@latest search @moduix-react -q "confirmation dialog"
npx shadcn@latest view @moduix-react/dialog
npx shadcn@latest add @moduix-react/dialog --dry-run
```

Для уже установленного элемента просмотрите различия в сгенерированном файле перед его обновлением:

```bash
npx shadcn@latest add @moduix-react/dialog --diff src/components/moduix/dialog.tsx
```

Запускайте `add` без флагов предварительного просмотра только после того, как проверите элемент, зависимости, целевые пути и модель владения. Не используйте `--overwrite`, пока явно не решите заменить локальные изменения.

## Проверьте сгенерированный код

Относитесь к сгенерированному коду как к черновику. Перед слиянием убедитесь, что он:

- использует задокументированные части moduix и объекты `details`, которые получают колбэки, а не выдуманные псевдонимы;
- сохраняет правильную модель владения - пакетную или реестровую;
- проходит обычную проверку типов, тесты и проверку доступности.

MCP может находить оба варианта владения, но команды `add` реестра следует использовать только в проектах, исходный код компонентов которых принадлежит проекту. В проектах с пакетным управлением сохраняются импорты `@moduix/react/*`, а обновления выполняются через пакетный менеджер. В руководстве [«Обновление и миграция»](/docs/updating) объяснён процесс обновления компонентов, исходный код которых принадлежит проекту.
