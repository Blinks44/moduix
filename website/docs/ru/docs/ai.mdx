# AI

Используйте это руководство, когда AI-ассистент читает документацию moduix или меняет проект, в котором используется moduix.

Эта страница описывает рабочий процесс, а не API библиотеки. В moduix нет отдельной AI-утилиты, пакета или хука. Ассистенту достаточно публичной документации, а для копируемых компонентов ещё и реестров moduix.

## Выберите подходящий контекст

Передавайте ассистенту только ту документацию, которая нужна для задачи.

| Задача | Контекст |
| --- | --- |
| Посмотреть доступную документацию | [llms.txt](/llms.txt) |
| Работать с одним компонентом или руководством | Нажмите **Скопировать страницу** на нужной странице или добавьте `.md` к её URL |
| Проверить несколько связанных разделов | [llms-full.txt](/llms-full.txt) |

В запросе укажите фреймворк, систему стилей, способ подключения moduix и ожидаемое изменение:

```text
Read https://moduix.dev/docs/button.md. Add a destructive action to our React application.
We use @moduix/react with CSS Modules. Import Button from @moduix/react/button and show the
proposed diff before changing files.
```

## Установите Skill moduix

moduix публикует Agent Skill `moduix` для пользователей библиотеки, он лежит в каталоге `skills/moduix` репозитория. Skill помогает совместимым агентам ещё до правок определить фреймворк проекта, вариант стилей и способ установки (пакет или реестр). Skill содержит только инструкции: он не устанавливает пакеты moduix и не копирует компоненты из реестра.

Установите из репозитория только Skill `moduix`:

<PackageManagerTabs command="skills add https://github.com/Blinks44/moduix --skill moduix" dlx />

Запускайте команду в проекте, где агент будет работать с moduix. Если CLI не сработал, установите Skill
вручную: скопируйте файл `skills/moduix/SKILL.md` из [репозитория moduix](https://github.com/Blinks44/moduix)
в каталог skills вашего агента. Некоторые агенты позволяют вызывать Skill явно, например через `$moduix`.

## Укажите способ подключения moduix

moduix можно подключить двумя способами:

- **Пакет:** проект импортирует публичный пакет `@moduix/*`, а обновления приходят через менеджер пакетов.
- **Копия исходников:** shadcn CLI копирует элемент из реестра moduix в проект. Дальше проект сам поддерживает эти файлы.

Выберите пакет и реестр под конфигурацию проекта:

| Конфигурация | Импорт из пакета | Пространство имён реестра |
| --- | --- | --- |
| React и CSS Modules | `@moduix/react/<component>` | `@moduix-react/<name>` |
| Solid и CSS Modules | `@moduix/solid/<component>` | `@moduix-solid/<name>` |
| Vue и CSS Modules | `@moduix/vue/<component>` | `@moduix-vue/<name>` |
| Svelte и CSS Modules | `@moduix/svelte/<component>` | `@moduix-svelte/<name>` |
| React и Tailwind CSS | `@moduix/react-tailwind/<component>` | `@moduix-react-tailwind/<name>` |
| Solid и Tailwind CSS | `@moduix/solid-tailwind/<component>` | `@moduix-solid-tailwind/<name>` |
| Vue и Tailwind CSS | `@moduix/vue-tailwind/<component>` | `@moduix-vue-tailwind/<name>` |
| Svelte и Tailwind CSS | `@moduix/svelte-tailwind/<component>` | `@moduix-svelte-tailwind/<name>` |

Установка пакетов и настройка реестров описаны в [Быстром старте](./quick-start). Если проект подключает moduix пакетом и вы не собираетесь это менять, не просите ассистента копировать исходники из реестра.

## Подключите MCP-сервер shadcn

Необязательный MCP-сервер поставляет shadcn, а не moduix. С его помощью AI-ассистент может просматривать и устанавливать элементы из совместимых с shadcn реестров, указанных в `components.json` проекта.

Для Codex добавьте сервер в `~/.codex/config.toml`:

```toml
[mcp_servers.shadcn]
command = "npx"
args = ["shadcn@latest", "mcp"]
```

После изменения конфигурации перезапустите Codex. Настройка других клиентов описана в [документации shadcn MCP](https://ui.shadcn.com/docs/mcp).

## Проверьте созданные изменения

Прежде чем принять изменения, убедитесь, что ассистент:

- выбрал правильные фреймворк, систему стилей и способ установки
- использовал документированные публичные импорты и API
- не перезаписал локальные изменения
- сохранил доступность и состояние, которым управляет приложение
- запустил точечные проверки типов, линтер и тесты проекта

Документация и метаданные реестров дают ассистенту контекст, но за данные, маршрутизацию, обработчики и финальную проверку по-прежнему отвечает приложение.
