# AI

moduix сохраняет публичный API и структуру исходного кода понятными и разработчикам, и
AI-ассистентам. Дайте ассистенту ровно ту часть документации, которая нужна для задачи, и сразу
скажите, где в проекте должен находиться код moduix.

## Выберите нужный контекст

| Задача | Что дать ассистенту |
| --- | --- |
| Обзор библиотеки или поиск компонента | [`llms.txt`](/llms.txt) |
| Помощь с одним компонентом, руководством или ошибкой | **Copy Markdown** нужной страницы |
| Полный обзор репозитория | [`llms-full.txt`](/llms-full.txt) |

У каждой MDX-страницы есть канонический URL в Markdown, например
`https://moduix.dev/docs/button.md`. Это страница без интерфейса документации, поэтому для
конкретной задачи по реализации или отладке она лучше всего подходит в качестве контекста.

## Спросите о текущей странице

Если ассистенту нужен текст одной страницы без интерфейса документации, используйте **Copy Markdown**
под её заголовком. На страницах компонентов есть и меню **Open** со ссылками на GitHub,
**View as Markdown**, ChatGPT и Claude.

Передайте ассистенту URL и конкретно опишите цель. Например:

```text
Read https://moduix.dev/docs/dialog.md. Add a confirmation dialog to our delete action.
We use @moduix/react/dialog from the npm package. Keep the Ark composition explicit and make the
trigger a button.
```

## Установка с помощью AI-ассистента

Прежде чем ассистент начнёт писать импорт или команду установки, скажите, где должен находиться код
moduix:

| Модель проекта | Что использовать ассистенту |
| --- | --- |
| Компоненты из пакета | Импорты `@moduix/react/*` и `@moduix/react/style.css` |
| Компоненты, исходный код которых хранится в проекте | Настроенный реестр `@moduix-react`, `components.json` проекта и его CLI |

Если исходный код компонентов хранится в проекте, ассистенту нужно прочитать страницу компонента и
проверить `components.json` перед добавлением элемента реестра. Полная настройка реестра описана в
руководстве [«Быстрый старт»](/docs/quick-start).

## Подключите Skill moduix

Skill moduix и реестр shadcn решают разные задачи. Skill добавляет инструкции для AI-агента, а
реестр shadcn добавляет в проект исходный код компонентов, стили и утилиты.

Установите Skill из репозитория с помощью Skills CLI:

```bash
npx skills add https://github.com/Blinks44/moduix --skill moduix
```

Перед изменением кода Skill проверяет существующие импорты и `components.json`, читает каноническую
документацию, а для обновлений компонентов из реестра использует поиск shadcn и безопасную проверку
через `--dry-run` или `--diff`. Skill не выбирает модель владения за вас. В агентах с поддержкой
Skills вызывайте его как `$moduix`.

## Подключите shadcn MCP

Сервер shadcn MCP может использовать размещённый реестр moduix. Отдельный MCP-сервер для moduix не
нужен: настройте реестр в потребляющем проекте, а затем подключите shadcn к своему AI-клиенту.

### 1. Настройте реестр

Добавьте URL реестра moduix в `components.json` потребляющего проекта:

```json
{
  "registries": {
    "@moduix-react": "https://moduix.dev/r/react/{name}.json"
  }
}
```

В реестре есть компоненты, темы и общие служебные элементы. Рецепты остаются документацией:
устанавливайте перечисленные в них компоненты. Полная настройка `components.json` описана в
руководстве [«Быстрый старт»](/docs/quick-start).

### 2. Подключите AI-клиент

Для клиентов, которые поддерживает инициализатор shadcn, запустите его в потребляющем проекте и
выберите нужный клиент. Например:

```bash
npx shadcn@latest mcp init --client cursor
```

Сейчас для Codex нужна ручная настройка MCP. Добавьте сервер в `~/.codex/config.toml` и перезапустите
Codex:

```toml
[mcp_servers.shadcn]
command = "npx"
args = ["shadcn@latest", "mcp"]
```

В [руководстве по shadcn MCP](https://ui.shadcn.com/docs/mcp) есть актуальные настройки для Claude
Code, Cursor, VS Code, Codex и других поддерживаемых клиентов.

### 3. Найдите нужный элемент до установки

Попросите ассистента проверить подходящую документацию и элемент реестра до изменения файлов. Эти
запросы подходят для компонентов, тем и многокомпонентных рецептов:

```text
Find the moduix component for an editable text field. Show the component documentation and registry
item before proposing code.
```

```text
Read https://moduix.dev/recipes/login-simple.md. List the moduix components it uses and the
application code I need to connect before proposing changes.
```

```text
Find a high-contrast moduix theme. Show how it is applied before changing the project.
```

### 4. Используйте CLI при необходимости

Используйте CLI, если MCP недоступен или нужен журнал действий в командной строке. Если проект хранит
исходный код компонентов, проверьте конфигурацию, найдите решение по потребности продукта, изучите
элемент и предварительно просмотрите изменение:

```bash
npx shadcn@latest info --json
npx shadcn@latest search @moduix-react --query "confirmation dialog"
npx shadcn@latest view @moduix-react/dialog
npx shadcn@latest add @moduix-react/dialog --dry-run
```

Перед обновлением уже установленного элемента просмотрите diff сгенерированных файлов:

```bash
npx shadcn@latest add @moduix-react/dialog --diff src/components/moduix/dialog.tsx
```

Запускайте `add` без флагов предварительного просмотра только после проверки элемента, зависимостей,
целевых путей и модели владения. Не используйте `--overwrite`, пока явно не решите заменить локальные
изменения.

## Проверьте сгенерированный код

Считайте сгенерированный код черновиком. Перед слиянием убедитесь, что он:

- использует задокументированные части moduix и объекты `details`, которые получают колбэки, а не выдуманные псевдонимы;
- сохраняет правильную модель владения, пакетную или реестровую;
- проходит обычную проверку типов, тесты и проверку доступности.

MCP умеет находить оба варианта владения, но команды `add` реестра нужны только проектам, где исходный
код компонентов хранится локально. В проектах с пакетным управлением остаются импорты
`@moduix/react/*`, а обновления выполняются через пакетный менеджер. Процесс обновления локальных
компонентов описан в руководстве [«Обновление и миграция»](/docs/updating).
