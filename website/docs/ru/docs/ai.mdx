# AI

Используйте это руководство, когда AI-ассистент читает документацию moduix или меняет проект, в котором используется moduix.

Эта страница описывает рабочий процесс, а не runtime API. moduix не экспортирует отдельную AI-утилиту, пакет или hook. Источником информации служит публичная документация, а для копируемых компонентов также registry moduix.

## Выберите подходящий контекст

Передавайте ассистенту только ту документацию, которая нужна для задачи.

| Задача | Контекст |
| --- | --- |
| Посмотреть доступную документацию | [llms.txt](/llms.txt) |
| Работать с одним компонентом или руководством | Используйте **Copy Markdown** на нужной странице или добавьте `.md` к её URL |
| Проверить несколько связанных разделов | [llms-full.txt](/llms-full.txt) |

В запросе укажите framework, систему стилей, способ подключения moduix и ожидаемое изменение:

```text
Read https://moduix.dev/docs/button.md. Add a destructive action to our React application.
We use @moduix/react with CSS Modules. Import Button from @moduix/react/button and show the
proposed diff before changing files.
```

## Установите Skill moduix

moduix публикует пользовательский Agent Skill `moduix` из каталога `skills/moduix` в репозитории. Он помогает совместимым агентам определить framework проекта, вариант стилей и модель владения кодом до внесения изменений. Skill содержит только инструкции: он не устанавливает пакеты moduix и не копирует компоненты из registry.

Установите из репозитория только Skill `moduix`:

<PackageManagerTabs command="skills add https://github.com/Blinks44/moduix --skill moduix" dlx />

Запускайте команду в проекте, где агент будет работать с moduix. Если CLI не сработал, установите Skill
вручную: скопируйте файл `skills/moduix/SKILL.md` из [репозитория moduix](https://github.com/Blinks44/moduix)
в каталог skills вашего агента. Некоторые агенты позволяют вызывать Skill явно, например через `$moduix`.

## Укажите способ подключения moduix

moduix поддерживает две модели владения кодом:

- **Управление через пакет:** проект импортирует публичный пакет `@moduix/*`. Обновления приходят через package manager.
- **Владение копией:** shadcn CLI копирует элемент из registry moduix в проект. После этого проект сам поддерживает созданные файлы.

Выбирайте пакет и registry, соответствующие проекту:

| Конфигурация | Импорт из пакета | Namespace registry |
| --- | --- | --- |
| React и CSS Modules | `@moduix/react/<component>` | `@moduix-react/<name>` |
| Solid и CSS Modules | `@moduix/solid/<component>` | `@moduix-solid/<name>` |
| React и Tailwind CSS | `@moduix/react-tailwind/<component>` | `@moduix-react-tailwind/<name>` |
| Solid и Tailwind CSS | `@moduix/solid-tailwind/<component>` | `@moduix-solid-tailwind/<name>` |

Установка пакетов и настройка registry описаны в [Quick Start](./quick-start). Не просите ассистента копировать исходники из registry в проект с пакетным подключением, если не собираетесь менять модель владения кодом.

## Подключите MCP-сервер shadcn

Необязательный MCP-сервер поставляет shadcn, а не moduix. С его помощью AI-ассистент может просматривать и устанавливать элементы из совместимых с shadcn registry, настроенных в `components.json` проекта.

Для Codex добавьте сервер в `~/.codex/config.toml`:

```toml
[mcp_servers.shadcn]
command = "npx"
args = ["shadcn@latest", "mcp"]
```

После изменения конфигурации перезапустите Codex. Настройка других клиентов описана в [документации shadcn MCP](https://ui.shadcn.com/docs/mcp).

## Проверьте созданные изменения

Перед применением изменений убедитесь, что ассистент:

- выбрал правильные framework, систему стилей и модель владения кодом
- использовал документированные публичные импорты и API
- не перезаписал локальные изменения
- сохранил доступность и состояние, которым управляет приложение
- запустил точечные проверки типов, lint и тесты проекта

Документация и метаданные registry дают ассистенту контекст, но данные, роутинг, обработчики и финальная проверка остаются ответственностью приложения.
