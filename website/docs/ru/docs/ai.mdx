# AI

moduix устроен так, чтобы быть понятным и людям, и AI-ассистентам. Сначала дайте ассистенту минимально
необходимую документацию, затем попросите его работать с публичным API компонентов, который уже использует проект.

## Контекст

| Задача | Что дать ассистенту |
| --- | --- |
| Обзор продукта или поиск компонента | [`llms.txt`](/llms.txt) |
| Помощь с одним компонентом, руководством или ошибкой | **Copy Markdown** нужной страницы |
| Большая ревизия репозитория | [`llms-full.txt`](/llms-full.txt) |

У каждой MDX-страницы есть канонический Markdown URL, например `https://moduix.dev/docs/button.md`. В нём
содержится страница без интерфейса документации, поэтому для конкретной задачи по реализации или отладке это
лучший контекст по умолчанию.

## Текущая страница

Используйте **Copy Markdown** под заголовком страницы, если ассистенту нужен её текст без интерфейса
документации. На страницах компонентов есть и меню **Open** с быстрым доступом к GitHub,
**View as Markdown**, ChatGPT и Claude.

Передайте URL и конкретно опишите задачу. Например:

```text
Read https://moduix.dev/docs/dialog.md. Add a confirmation dialog to our delete action.
We use @moduix/react/dialog from the npm package. Keep the Ark composition explicit and make the
trigger a button.
```

## Установка с AI

Прежде чем ассистент начнёт писать импорты или команды установки, сообщите ему, какая модель владения
компонентами moduix используется в проекте:

| Модель проекта | Что использовать ассистенту |
| --- | --- |
| Компоненты из пакета | Импорты `@moduix/react/*` и `@moduix/react/style.css` |
| Компоненты, исходный код которых хранится в проекте | Настроенный реестр `@moduix-react`, `components.json` проекта и его CLI |

Если исходный код компонентов хранится в проекте, ассистенту нужно прочитать страницу компонента и проверить
`components.json` перед добавлением элемента реестра. Полная настройка реестра есть в руководстве
[«Быстрый старт»](/docs/quick-start).

## Используйте Skill moduix

Установите публичный Skill с помощью Skills.sh:

```bash
npx skills add https://github.com/Blinks44/moduix --skill moduix
```

Установщик настраивает Skill для поддерживаемого агента. Перед изменением кода тот проверяет существующие
импорты и `components.json`, затем использует каноническую документацию, поиск shadcn и безопасную проверку
изменений для обновления компонентов, исходный код которых хранится в проекте. Установка через пакетный
менеджер и копирование через shadcn - равноправные варианты. В агентах с поддержкой Skills используйте `$moduix`.

## shadcn MCP

shadcn MCP server работает с существующим реестром moduix. Отдельный MCP server для moduix не нужен:
настройте реестр в потребляющем проекте, а shadcn предоставит его AI-клиенту.

### 1. Реестр

В `components.json` потребляющего проекта укажите URL реестра moduix:

```json
{
  "registries": {
    "@moduix-react": "https://moduix.dev/r/react/{name}.json"
  }
}
```

Полная настройка `components.json` описана в руководстве [«Быстрый старт»](/docs/quick-start).

### 2. AI-клиент

Для клиентов, которые поддерживает инициализатор shadcn, запустите его в потребляющем проекте и выберите
нужный клиент. Например:

```bash
npx shadcn@latest mcp init --client cursor
```

Сейчас Codex использует ручную настройку MCP. Добавьте сервер в `~/.codex/config.toml` и перезапустите Codex:

```toml
[mcp_servers.shadcn]
command = "npx"
args = ["shadcn@latest", "mcp"]
```

В [руководстве по shadcn MCP](https://ui.shadcn.com/docs/mcp) есть актуальные настройки для Claude Code,
Cursor, VS Code, Codex и других поддерживаемых клиентов.

### 3. Поиск

Попросите ассистента проверить подходящий элемент moduix до изменения файлов. Эти запросы подходят для
компонентов, блоков и тем:

```text
Find the moduix component for an editable text field. Show the component documentation and registry
item before proposing code.
```

```text
Find a moduix sign-in block. Show its registry dependencies and responsive behavior, but do not
install it yet.
```

```text
Find a high-contrast moduix theme. Show how it is applied before changing the project.
```

### 4. CLI

Используйте CLI, если MCP недоступен или нужен журнал действий в командной строке. Если исходный код компонентов
хранится в проекте, проверьте текущую конфигурацию, найдите элемент по потребности продукта, изучите его и затем
предварительно просмотрите изменения:

```bash
npx shadcn@latest info --json
npx shadcn@latest search @moduix-react -q "confirmation dialog"
npx shadcn@latest view @moduix-react/dialog
npx shadcn@latest add @moduix-react/dialog --dry-run
```

Перед обновлением уже установленного элемента просмотрите различия в сгенерированном файле:

```bash
npx shadcn@latest add @moduix-react/dialog --diff src/components/moduix/dialog.tsx
```

Запускайте `add` без флагов предварительного просмотра только после проверки элемента, зависимостей, целевых
путей и модели владения. Не используйте `--overwrite`, пока явно не решите заменить локальные изменения.

## Проверка кода

Считайте сгенерированный код черновиком. Перед слиянием убедитесь, что он:

- использует задокументированные части moduix и объекты `details`, которые получают колбэки, а не выдуманные псевдонимы;
- сохраняет правильную модель владения - пакетную или реестровую;
- проходит обычную проверку типов, тесты и проверку доступности.

MCP может находить оба варианта владения, но команды `add` реестра нужны только проектам, где исходный код
компонентов хранится локально. В проектах с пакетным управлением остаются импорты `@moduix/react/*`, а обновления
выполняются через пакетный менеджер. Процесс обновления локальных компонентов описан в руководстве
[«Обновление и миграция»](/docs/updating).
