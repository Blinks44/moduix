## Выбор подходящего компонента

Используйте `Highlight`, чтобы выделить поисковые термины внутри текста, у которого уже есть
семантический контейнер. Компонент выводит совпавшие фрагменты, но не добавляет собственную обёртку
для разметки.

- Выбирайте **`Highlight`**, когда нужно выделить один или несколько терминов в готовом предложении, подписи или текстовом блоке.
- Выбирайте **`Text`**, когда всей строке нужно только типографическое оформление, без поиска совпадений.

## Анатомия

У `Highlight` одна публичная корневая часть. Компонент возвращает фрагмент и не добавляет отдельную
обёртку. Каждый совпавший фрагмент становится нативным элементом `<mark>`, а текст без совпадений
остаётся обычным текстом в окружающей разметке.

```text
Highlight / Highlight.Root
└─ совпавшие фрагменты в отдельных элементах <mark>
```

| Часть                          | Назначение                                                        |
| ------------------------------ | ----------------------------------------------------------------- |
| `Highlight` / `Highlight.Root` | Применяет стили moduix к каждому совпадению в переданном тексте. |

## Композиция

### Рекомендуемая композиция

Используйте короткую форму `<Highlight>` внутри `Text`, `Heading`, элемента списка, ячейки таблицы
или другого контейнера, который отвечает за текст. Она равнозначна `<Highlight.Root>`.

### Когда нужна собственная композиция

Используйте `Highlight`, если для каждого совпадения подходит нативный `<mark>`. Если совпадениям
нужны разные элементы, интерактивное поведение или собственное содержимое, выведите такую разметку
в отдельном компоненте. Компонент moduix намеренно не предоставляет API для отдельного рендеринга
фрагментов.

### Свойства по умолчанию

| Свойство     | По умолчанию                         | Примечания                                                      |
| ------------ | ------------------------------------ | --------------------------------------------------------------- |
| `query`      | -                                    | Строка или массив строк для поиска.                             |
| `text`       | -                                    | Полная исходная строка. Свойство обязательно.                   |
| `ignoreCase` | `false`                              | Игнорирует регистр при поиске.                                  |
| `matchAll`   | `false` для строки; `true` для массива | Выделяет все совпадения. Для массива значение `false` вызывает ошибку. |
| `exactMatch` | `false`                              | Ищет целые слова, а не фрагменты слов.                          |

### Особенности поведения

`className`, `style`, `title`, `id` и другие свойства элемента `<mark>` применяются ко всем
совпавшим сегментам. Если совпадений нет, `Highlight` выводит исходный текст без элементов `<mark>`.

`Highlight` не добавляет обёртку и не управляет состоянием, фокусом, клавиатурными взаимодействиями
или поведением формы. Стабильные data-атрибуты moduix для совпавших элементов описаны в разделе
[Стилизация](#стилизация).

`exactMatch` использует границы слов JavaScript. Для латинского текста это работает надёжно, но
границы слов JavaScript не распознают кириллицу и некоторые другие системы письма как целые слова.
Если поиск целых слов должен работать для таких систем письма, выполняйте его с учётом языка в своей
логике и выводите результат самостоятельно.

## Стилизация

Совпавшие фрагменты получают стандартные стили moduix для `<mark>`. Используйте `className` для
локальной правки или переменные `--moduix-highlight-*`, если одинаковое оформление должно применяться
к нескольким экземплярам компонента.

### Хуки стилизации

- Каждый совпавший `<mark>` получает `data-scope="highlight"` и `data-part="root"`.
- `data-slot="highlight-root"` - стабильный селектор moduix для каждого совпавшего `mark`.
- Компонент не создаёт обёртку, не добавляет атрибут состояния и не задаёт CSS-переменных Ark. На выходе только обычные текстовые узлы и совпавшие элементы `<mark>`.
