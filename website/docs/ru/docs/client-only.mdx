## Когда использовать

Используйте `ClientOnly`, если части интерфейса нужны API браузера: `window`, `navigator`, доступ к хранилищу,
измерения разметки или библиотека, которая работает только в браузере. При серверном рендеринге он выводит
`fallback`, а после гидратации — дочерние элементы.

Импортируйте утилиту напрямую из Ark UI: moduix не делает для неё обёртку.

```tsx
import { ClientOnly } from '@ark-ui/react/client-only';
```

## Запасной контент

`fallback` — не просто индикатор загрузки, а единственное содержимое этого поддерева, которое может отрисовать
сервер. Добавьте `Skeleton`, статичную сводку или другой полезный элемент-заполнитель примерно того же размера,
что и интерфейс после гидратации. При создании `fallback` не обращайтесь к глобальным объектам браузера.

## Браузерные API

`ClientOnly` откладывает отрисовку, но не превращает SSR-компонент в модуль, работающий только в браузере.
Обращайтесь к `window`, `document`, `navigator`, `localStorage` и измерениям только внутри дочернего компонента,
который он отрисовывает, либо в эффекте или обработчике события. Эта граница явно отделяет часть интерфейса,
недоступную на сервере.

## Использование с moduix

Внутри `ClientOnly` компоненты moduix работают как обычно. Например, `Card` может показывать данные из браузера,
а `Skeleton` в `fallback` сохраняет похожую структуру. Если у компонента moduix уже есть API для безопасной
работы на сервере, используйте его вместо отдельной границы `ClientOnly`.

## Ответственность

Ark UI отвечает за `ClientOnly`, его поведение при гидратации и API `fallback`. moduix показывает, как сочетать
утилиту со своими компонентами, но не стилизует и не реэкспортирует её.
