# Анимации

Используйте анимацию, чтобы объяснить смену состояния, а не украшать каждое действие. Начните со
стандартного поведения Moduix, меняйте общее правило только для всей системы, а единичные исключения
задавайте на той визуальной части компонента, которой принадлежит анимация.

Ark передает состояния появления и скрытия через атрибуты `data-state` и оставляет закрывающееся
содержимое в DOM до завершения анимации. Foundation также сокращает общую анимацию при включенном
`prefers-reduced-motion`.

## Выберите способ стилизации

| Способ | Рекомендуемый подход |
| --- | --- |
| CSS Modules | Переопределяйте документированные общие переменные или переменные отдельного компонента. |
| Tailwind CSS | Используйте анимации из Tailwind-компонента, а для исключений переопределяйте классы потребителя или код из реестра. |

Переменные ниже относятся к CSS Modules-пакетам всех выпущенных фреймворков. React и Solid используют
одинаковые имена. Tailwind-пакеты строят анимации на utility-классах и не предоставляют контракт
локальных переменных CSS Modules.

## Настройте общую анимацию popup-элементов

Задайте `--moduix-popup-motion-*` на `:root`, если поддерживаемые popup-элементы должны использовать
одинаковые длительность, easing, прозрачность, масштаб или смещение. Значения `starting` отвечают за
появление, а `ending` за скрытие.

```css
:root {
  --moduix-popup-motion-duration: 220ms;
  --moduix-popup-motion-easing: cubic-bezier(0.22, 1, 0.36, 1);
  --moduix-popup-motion-starting-opacity: 0;
  --moduix-popup-motion-ending-opacity: 0;
  --moduix-popup-motion-starting-scale: 0.96;
  --moduix-popup-motion-ending-scale: 0.98;
  --moduix-popup-motion-starting-translate-y: 0.5rem;
  --moduix-popup-motion-ending-translate-y: 0.5rem;
}
```

Для обычных портальных элементов используйте `:root`. Переменная на локальном контейнере дойдет до
оверлея только тогда, когда он отрисован внутри этого контейнера, например с `portalled={false}` или
собственным portal-контейнером.

Общие переменные действуют на содержимое Popover, Menu, Tooltip, Hover Card, Floating Panel, Dialog,
Command Palette, Lightbox, Tour, Navigation Menu, Select, Combobox, Date Picker и Color Picker.

## Добавьте локальное исключение

Переменные компонента имеют приоритет над общими значениями. Назначайте их визуальной части, которой
принадлежит анимация.

| Поверхность | Часть | Семейство переменных |
| --- | --- | --- |
| Popover | `Popover.Content` | `--moduix-popover-content-*` |
| Dialog | `DialogContent` | `--moduix-dialog-content-*` |
| Select | `Select.Content` | `--moduix-select-content-*` |
| Navigation Menu | `NavigationMenuContent` | `--moduix-navigation-menu-content-*` |

Например, один Select можно открывать с более мягким масштабированием:

```css
.softScalePicker {
  --moduix-select-transition: 180ms cubic-bezier(0.22, 1, 0.36, 1);
  --moduix-select-content-closed-opacity: 0;
  --moduix-select-content-closed-scale: 0.96;
}
```

Полный список переменных находится на странице компонента. Backdrop модальных компонентов использует
собственные переменные перехода, прозрачности и размытия, а не масштаб и смещение popup-элементов.

## Не смешивайте разные типы анимации

Некоторые взаимодействия связаны с геометрией или жизненным циклом и намеренно имеют отдельный
контракт.

| Компонент | Почему используется отдельная система |
| --- | --- |
| Accordion и Collapsible | Переход зависит от высоты содержимого и состояния раскрытия. |
| Drawer | Преобразование зависит от направления перетаскивания. |
| Swap | Появляющийся и исчезающий Indicator анимируются отдельно. |
| Tree View | Раскрытие ветки имеет собственные настройки времени. |
| Toast | Переменные Ark координируют расположение и скрытие элементов. |

Не заменяйте преобразования Drawer или переменные расположения Toast рецептами для popup-элементов.

## Проверьте анимацию

- Проверьте появление и скрытие, а не только открытие.
- Протестируйте портальные элементы и локальные переопределения в реальном контейнере.
- Убедитесь, что анимация не задерживает и не скрывает клавиатурный фокус.
- Включите режим сокращения анимации в системе.
- Делайте появление и скрытие симметричными, если различие не объясняет направление или иерархию.
