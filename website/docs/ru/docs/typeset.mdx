## Справочник API

`Typeset` задаёт единый ритм чтения семантическому HTML внутри своего контейнера. Он не разбирает и
не рендерит Markdown, не фильтрует небезопасный контент и не задаёт ширину текста. Всё это остаётся
за приложением.

`Typeset` и `Typeset.Scroll` построены с помощью
[фабрики Ark](https://ark-ui.com/docs/guides/composition#the-ark-factory), поэтому поддерживают
нативные свойства `div`, ref и композицию через `asChild`.

CSS-first контракт Typeset следует подходу из [документации shadcn/typeset](https://ui.shadcn.com/docs/typeset).
Как и там, ритм чтения задают три переменные, а рендеринг контента и его ширина остаются
ответственностью приложения. moduix добавляет нативные компоненты для React и Solid и
`Typeset.Scroll`.

## Анатомия

```text
Typeset / Typeset.Root
└─ Typeset.Scroll (необязательно)
```

| Часть | Назначение |
| --- | --- |
| `Typeset` / `Typeset.Root` | Корневой контейнер, который стилизует семантические дочерние элементы. |
| `Typeset.Scroll` | Фокусируемая область с горизонтальной прокруткой для широкого отрендеренного блока. |

## Композиция

`Typeset` не владеет состоянием, не разбирает и не фильтрует контент и не задаёт его размер.
Помещайте отрендеренные семантические элементы внутрь корня, используйте `asChild`, когда корень
должен быть `article` или `section`, и добавляйте `Typeset.Scroll` вокруг широкого блока, который
лучше прокручивать, чем сжимать. Держите `Typeset.Scroll` внутри границы `Typeset` или `Typeset.Root`:
горизонтальную прокрутку, интервалы потока и расширение таблиц для обёрнутого блока задают правила
элементов Typeset. Если вложенный фрагмент принадлежит приложению и должен иметь свой
стиль, добавьте к нему `.not-typeset` или `data-not-typeset`. Пользовательская область прокрутки
должна иметь доступное имя, а `Typeset.Scroll` по умолчанию доступен для фокуса с клавиатуры.

### CSS-свойства

Ритм чтения задают `--moduix-typeset-size`, `--moduix-typeset-leading` и
`--moduix-typeset-flow`. Переменные шрифта необязательны, а цвета, границы и радиус берутся из
активной темы moduix. Правила элементов находятся в каскадном слое `components`, а дефолты
переменных - в слое `base`; они используют низкоспецифичные селекторы `:where()`, поэтому обычный CSS
приложения может переопределять отдельные элементы без `!important`.

Для структурных стилей используйте `className` в React и `class` в Solid. Варианты Tailwind
поставляют тот же CSS Module и объединяют классы через `cn` вместо utility-классов, поэтому шесть
CSS-переменных работают в обоих вариантах.

### Хуки стилизации

- `data-slot="typeset"` выбирает корневой контейнер.
- `data-slot="typeset-scroll"` выбирает необязательную обёртку переполнения и её состояние при фокусе.
- `[data-scope="typeset"][data-part="root"]` и `[data-part="scroll"]` дают стабильные хуки для
  частей компонента.
