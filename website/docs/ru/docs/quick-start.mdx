# Быстрый старт

moduix можно использовать в приложении двумя равнозначными способами:

- Установить пакет moduix для выбранного фреймворка и способа стилизации и получать обновления через пакетный менеджер.
- Добавить компоненты через shadcn CLI, чтобы хранить их исходный код, стили и утилиты в своём репозитории.

Оба способа используют одинаковые нативные реализации для каждого фреймворка, согласованные с Ark UI
контракты и систему токенов. Выбирайте исходя из того, где должен находиться исходный код и как вы
планируете его обновлять.

Начинайте с существующего приложения на React или Solid. Для Tailwind-пакета или реестра в проекте
уже должен быть настроен Tailwind CSS v4.

Для начала выберите React 18 или 19 с `@ark-ui/react` либо Solid 1.9 с `@ark-ui/solid`.
Фреймворк или сборщик должен уметь импортировать CSS из npm-пакетов. Если окружение этого требует,
размещайте интерактивные компоненты в клиентской границе.

За доступность отвечают все участники: Ark UI реализует поведение примитивов, moduix задаёт контракты обёрток и
настройки по умолчанию, а приложение предоставляет подписи элементов, контент, сообщения валидации и сценарий
взаимодействия.

## Выберите фреймворк

Выберите нативные для фреймворка пакет и пространство имён реестра. Пакеты на CSS Modules для React
и Solid содержат полный каталог, а Tailwind-пакеты содержат только компоненты с завершённым переносом стилей.

| Среда | CSS Modules | Tailwind CSS |
| --- | --- | --- |
| React | `@moduix/react` / `@moduix-react` | `@moduix/react-tailwind` / `@moduix-react-tailwind` |
| Solid | `@moduix/solid` / `@moduix-solid` | `@moduix/solid-tailwind` / `@moduix-solid-tailwind` |

В каждой инструкции ниже указаны поддерживаемые фреймворки. Astro, Rsbuild, TanStack Start и Vite
описаны для React и Solid; у SolidStart есть отдельная страница, а Next.js и React Router остаются
вариантами только для React.

## Установить как пакет

Выберите этот способ, если хотите оставить moduix в `node_modules` и обновлять его через обычный менеджер пакетов.

Выберите подход к стилям. В каждой вкладке приведена полная настройка.

### CSS Modules

Выберите этот вариант, если хотите получать стили вместе с пакетом и не добавлять Tailwind в зависимости.

#### 1. Установите пакет

Компоненты, CSS и дизайн-токены поставляются вместе. Установите moduix и указанные зависимости для
выбранного фреймворка:

<Tabs groupId="framework">
  <Tab label="React" value="react">

<PackageManagerTabs command="install @moduix/react @ark-ui/react" />

  </Tab>
  <Tab label="Solid" value="solid">

<PackageManagerTabs command="install @moduix/solid @ark-ui/solid" />

  </Tab>
</Tabs>

Среда выполнения и соответствующий пакет Ark UI остаются в приложении, поэтому moduix не добавляет
их отдельные копии.

#### 2. Добавьте стили

Один раз импортируйте обязательный базовый файл стилей в точке входа приложения:

<Tabs groupId="framework">
  <Tab label="React" value="react">

```tsx
import '@moduix/react/style.css';
```

  </Tab>
  <Tab label="Solid" value="solid">

```tsx
import '@moduix/solid/style.css';
```

  </Tab>
</Tabs>

Этот файл задаёт общие дизайн-токены и базовый слой, от которого зависят стили компонентов. Стили конкретных
компонентов подключаются вместе с самими компонентами.

Все дизайн-токены moduix используют пространство имён `--moduix-*`. В проекте можно сохранить собственные имена
токенов и выборочно сопоставить их в файле стилей, который загружается после `style.css`; см. [Токены](/docs/tokens).

Если нужен дополнительный сброс стилей, импортируйте `reset.css` перед основным файлом:

<Tabs groupId="framework">
  <Tab label="React" value="react">

```tsx
import '@moduix/react/reset.css';
import '@moduix/react/style.css';
```

  </Tab>
  <Tab label="Solid" value="solid">

```tsx
import '@moduix/solid/reset.css';
import '@moduix/solid/style.css';
```

  </Tab>
</Tabs>

Так `style.css` отвечает только за глобальную основу, а стили неиспользуемых компонентов не попадут в бандл.

Если нужна готовая визуальная основа, импортируйте один из необязательных пресетов после `style.css`; см. [Темы](/docs/themes).

#### 3. Используйте компонент

Accordion доступен в каждом выпущенном фреймворке и варианте стилей, поэтому по нему удобно проверить любой подход к стилям:

<Tabs groupId="framework">
  <Tab label="React" value="react">

```tsx
import { Accordion } from '@moduix/react/accordion';

export function Example() {
  return (
    <Accordion defaultValue={['first']}>
      <Accordion.Item value="first">
        <Accordion.ItemTrigger>Что такое moduix?</Accordion.ItemTrigger>
        <Accordion.ItemContent>
          <Accordion.ItemBody>Библиотека нативных компонентов на базе Ark UI.</Accordion.ItemBody>
        </Accordion.ItemContent>
      </Accordion.Item>
    </Accordion>
  );
}
```

  </Tab>
  <Tab label="Solid" value="solid">

```tsx
import { Accordion } from '@moduix/solid/accordion';

export function Example() {
  return (
    <Accordion defaultValue={['first']}>
      <Accordion.Item value="first">
        <Accordion.ItemTrigger>Что такое moduix?</Accordion.ItemTrigger>
        <Accordion.ItemContent>
          <Accordion.ItemBody>Библиотека нативных компонентов на базе Ark UI.</Accordion.ItemBody>
        </Accordion.ItemContent>
      </Accordion.Item>
    </Accordion>

```

  </Tab>
</Tabs>

Установка завершена, если триггер оформлен стилями moduix, а панель открывается с клавиатуры и мыши.
  </Tab>

### Tailwind CSS

Выберите этот вариант, если приложение уже использует Tailwind CSS v4, а стили компонентов должны
оставаться видимыми в виде утилитарных классов. Сброс стилей предоставляет Tailwind Preflight.

#### 1. Установите пакет

<Tabs groupId="framework">
  <Tab label="React" value="react">

<PackageManagerTabs command="install @moduix/react-tailwind @ark-ui/react" />

  </Tab>
  <Tab label="Solid" value="solid">

<PackageManagerTabs command="install @moduix/solid-tailwind @ark-ui/solid" />

  </Tab>
</Tabs>

#### 2. Добавьте стили

Импортируйте сгенерированную основу перед Tailwind и укажите в `@source` каталог компонентов пакета:

<Tabs groupId="framework">
  <Tab label="React" value="react">

```css title="styles.css"
@import '@moduix/react-tailwind/style.css';
@import 'tailwindcss';

@source '../node_modules/@moduix/react-tailwind/dist/components';
```

  </Tab>
  <Tab label="Solid" value="solid">

```css title="styles.css"
@import '@moduix/solid-tailwind/style.css';
@import 'tailwindcss';

@source '../node_modules/@moduix/solid-tailwind/dist/components';
```

  </Tab>
</Tabs>

Путь `@source` разрешается относительно файла стилей и должен охватывать только каталог
`dist/components` выбранного пакета. Не добавляйте reset moduix: его роль выполняет Tailwind Preflight.

#### 3. Используйте компонент

<Tabs groupId="framework">

```tsx
        </Accordion.ItemContent>
      </Accordion.Item>
    </Accordion>
  );
}
```

  </Tab>
  <Tab label="Solid" value="solid">

```tsx
import { Accordion } from '@moduix/solid-tailwind/accordion';

  return (
    <Accordion defaultValue={['first']}>

        <Accordion.ItemContent>
          <Accordion.ItemBody>Библиотека нативных компонентов на базе Ark UI.</Accordion.ItemBody>
```

</Tabs>

## Установить через shadcn CLI

Выберите этот способ, если хотите хранить исходный код компонентов и стили в своём репозитории. shadcn CLI читает
реестр moduix, подтягивает зависимости и размещает файлы по настроенным алиасам.

### 1. Настройте shadcn

Создайте `components.json` в корне проекта и выберите конфигурацию для своего способа стилизации:

<Tabs groupId="styling">
  <Tab label="CSS Modules" value="css-modules">

<CodeBlockRuntime lang="json" title="components.json" code={componentsCssModules} />

  </Tab>
  <Tab label="Tailwind" value="tailwind">

<CodeBlockRuntime lang="json" title="components.json" code={componentsTailwind} />

  </Tab>
</Tabs>

В примере для Tailwind предполагается, что входной файл Tailwind CSS v4 находится по пути
`src/styles.css`. Для версии 4 оставьте `tailwind.config` пустым и измените `tailwind.css`, если
глобальные стили проекта лежат в другом месте. Реестрам CSS Modules Tailwind не нужен, поэтому в их
конфигурации используются пустые значения, обязательные для схемы shadcn.

`rsc` относится только к элементам React-реестра. Оставьте `false` для Solid и обычных
React-приложений. В приложении с React Server Components установите `true`: тогда CLI добавит
`use client` к клиентским компонентам из реестра.

Проверьте, что проект разрешает алиас `@/*` к каталогу с исходным кодом. Типичная структура с `src` использует:

```json
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "@/*": ["./src/*"]
    }
  }
}
```

Благодаря этому `shadcn` CLI использует алиасы и URL реестра, чтобы поместить сгенерированные файлы в каталог исходного
кода, а не в буквальную папку `@`. В [настройке фреймворка](#выберите-фреймворк) указано, нужен ли этот алиас также
в конфигурации сборщика и какую корневую папку исходного кода выбрать.

### 2. Добавьте компонент

<Tabs groupId="framework">
  <Tab label="React" value="react">

<ShadcnInstallOptions
  options={[
    { label: 'CSS Modules', command: 'shadcn@latest add @moduix-react/accordion' },
    { label: 'Tailwind CSS', command: 'shadcn@latest add @moduix-react-tailwind/accordion' },
  ]}
/>

  </Tab>
  <Tab label="Solid" value="solid">

<ShadcnInstallOptions
  options={[
    { label: 'CSS Modules', command: 'shadcn@latest add @moduix-solid/accordion' },
    { label: 'Tailwind CSS', command: 'shadcn@latest add @moduix-solid-tailwind/accordion' },
  ]}
/>

  </Tab>
</Tabs>

Чтобы добавить другой компонент, замените его имя в выбранном пространстве имён. Tailwind-реестры
содержат только уже перенесённые компоненты.

Реестр добавляет только общие служебные файлы, необходимые компонентам. Глобальный шрифт он не
добавляет, поэтому типографика продолжает наследоваться от приложения.

### 3. Импортируйте сгенерированные стили

Выберите импорт для своего подхода к стилям:

<Tabs groupId="styling">
  <Tab label="CSS Modules" value="css-modules">

```tsx
import '@/lib/moduix/styles/style.css';
```

Если нужен дополнительный сброс стилей, добавьте соответствующий элемент реестра:

<Tabs groupId="framework">
  <Tab label="React" value="react">

<PackageManagerTabs command="shadcn@latest add @moduix-react/reset" dlx />

  </Tab>
  <Tab label="Solid" value="solid">

<PackageManagerTabs command="shadcn@latest add @moduix-solid/reset" dlx />

  </Tab>
</Tabs>

Затем импортируйте его перед основным файлом:

```tsx
import '@/lib/moduix/styles/reset.css';
import '@/lib/moduix/styles/style.css';
```

  </Tab>
  <Tab label="Tailwind CSS" value="tailwind">

Загрузите сгенерированную основу перед Tailwind в основном файле стилей приложения:

```css title="styles.css"
@import './lib/moduix/styles/style.css';
@import 'tailwindcss';
```

В этом варианте reset предоставляет Tailwind Preflight; не устанавливайте reset moduix.

  </Tab>
</Tabs>

В примерах ниже используются `@/components` и `@/lib`. Если проект использует другие алиасы,
обновите `components.json` и импортируйте сгенерированные файлы по соответствующим путям.

### 4. Используйте созданные компоненты

Импортируйте компоненты из созданных файлов в своём проекте:

```tsx
import { Button } from '@/components/ui/button';
import { Accordion } from '@/components/ui/accordion';
```

Большинство компонентов собрано из именованных частей. Такая структура сохраняет доступное поведение и позволяет
управлять разметкой, компоновкой и стилями в приложении.

Подход к хранению исходного кода вдохновлён [shadcn/ui](https://ui.shadcn.com/), а структура компонентов и их
поведение соответствуют [Ark UI](https://ark-ui.com/).

## Настройте слои порталов

Эта настройка нужна при обоих способах установки. `Dialog`, `Popover`, `Menu`, `Select` и другие компоненты
выводят содержимое оверлеев через порталы. Изолируйте корневой элемент приложения, чтобы подложки и всплывающие
элементы всегда были поверх страницы и не конфликтовали с локальными значениями `z-index`.

```html title="index.html"
<body>
  <div id="app-root"></div>
</body>
```

```css title="styles.css"
#app-root {
  isolation: isolate;
}
```

Если приложение поддерживает Safari на iOS 26, проверьте прокручиваемое модальное окно при видимой панели браузера.
Если контент виден под подложкой, задайте `body` значение `position: relative`, чтобы абсолютно позиционированная
подложка могла закрыть всю видимую область.

```css title="styles.css"
body {
  position: relative;
}
```

## Стилизация

moduix совместим с подходом к стилям, который уже используется в проекте:

- Обычный CSS с глобальными селекторами, каскадными слоями и CSS-переменными.
- CSS Modules с React-свойством `className` или Solid-свойством `class` и классами слотов компонентов.
- Утилитарные классы Tailwind CSS для компоновки и точечных изменений.
- CSS-in-JS-библиотеки, которые добавляют классы или передают стили через собственные обёртки.

В вариантах с CSS Modules стандартная плотность задаётся через `--moduix-size-md: 36px` для основных
элементов управления и `--moduix-size-sm: 32px` для строк всплывающих списков. Изменение этих токенов
обновляет связанные компоненты одновременно. В Tailwind-вариантах размеры задаются утилитами и
переопределяются пользовательскими классами.

На страницах компонентов перечислены общие точки настройки стилей и публичные переменные, доступные
в CSS Modules. Tailwind-варианты используют семантические утилиты и пользовательские классы, а не
повторяют эти компонентные переменные. Полная иерархия описана в [Токенах](/docs/tokens), а
настройка движения описана в [Анимациях](/docs/animations).

## Устранение неполадок

| Проблема | Что проверить |
| --- | --- |
| Компоненты отображаются без стилей | Проверьте порядок импортов для выбранного способа стилизации; дополнительный сброс используйте только с CSS Modules. |
| Сборщик не находит импорт созданного компонента | Проверьте алиас `@/*` в TypeScript и сборщике, затем `components.json`. |
| Всплывающий элемент отображается под содержимым страницы | Добавьте `isolation: isolate` корневому элементу приложения и избегайте несвязанных глобальных значений `z-index`. |
| При серверном рендеринге появляются ошибки о клиентских API | В нужных фреймворках размещайте интерактивные компоненты в клиентском компоненте. |
