# Быстрый старт

moduix можно подключить к production-проекту двумя равнозначными способами:

- Установить `@moduix/react` и управлять обновлениями через менеджер пакетов.
- Добавить компоненты через shadcn CLI, чтобы их исходный код, стили и утилиты оказались в вашем репозитории.

В обоих случаях доступны те же компоненты, контракты Ark UI и система токенов. Выбор зависит от того, хотите ли вы
хранить код в зависимости проекта или полностью контролировать его у себя в репозитории.

Вам нужны React 18 или 19, `@ark-ui/react` и фреймворк или сборщик, способный импортировать CSS из npm-пакетов.
Интерактивные компоненты должны рендериться внутри клиентской границы, если фреймворк этого требует.

Доступность обеспечивается вместе: Ark UI отвечает за поведение примитивов, moduix - за контракты обёрток и
настройки по умолчанию, а приложение - за подписи, контент, сообщения валидации и пользовательский сценарий.

## Выберите фреймворк

Пакет и реестр работают одинаково в любом React-стеке. Выберите свой фреймворк, чтобы узнать, куда подключать
стили, как настроить алиас для исходного кода и где проходит граница между клиентским и серверным рендерингом.

## Установить как пакет

Выберите этот способ, если хотите оставить moduix в `node_modules` и обновлять его обычными средствами менеджера
пакетов.

### 1. Установите пакет

Компоненты, CSS и дизайн-токены поставляются одним пакетом. React 18 или 19 и Ark UI указаны как peer dependencies:

<PackageManagerTabs command="install @moduix/react @ark-ui/react" />

`react`, `react-dom` и `@ark-ui/react` остаются зависимостями приложения, поэтому moduix не дублирует runtime
React или примитивов.

### 2. Добавьте стили

Один раз импортируйте обязательную базовую таблицу стилей в точке входа приложения:

```tsx
import '@moduix/react/style.css';
```

Этот файл обязателен: в нём определены общие дизайн-токены и базовый слой, от которого зависят стили компонентов.
Стили самих компонентов по-прежнему подключаются вместе с импортируемыми компонентами.

Все дизайн-токены moduix используют пространство имён `--moduix-*`. В проекте можно сохранить собственные имена
токенов и выборочно сопоставить их в таблице стилей, которая загружается после `style.css`; см. [Токены](/docs/tokens).

Если нужен необязательный reset, импортируйте его явно перед основной таблицей стилей:

```tsx
import '@moduix/react/reset.css';
import '@moduix/react/style.css';
```

Так `style.css` содержит только глобальную основу, а CSS неиспользуемых компонентов не обязан попадать в бандл.

Для готовой визуальной отправной точки импортируйте один необязательный пресет после `style.css`; см.
[Темы](/docs/themes).

### 3. Используйте компонент

Импортируйте каждый компонент из соответствующего подпути `@moduix/react/*`:

```tsx
import { Button } from '@moduix/react/button';
import { Dialog } from '@moduix/react/dialog';

export function Example() {
  return (
    <Dialog>
      <Dialog.Trigger asChild>
        <Button>Open dialog</Button>
      </Dialog.Trigger>
      <Dialog.Backdrop />
      <Dialog.Positioner>
        <Dialog.Content>
          <Dialog.Header>
            <Dialog.Title>Project settings</Dialog.Title>
            <Dialog.Description>Review the settings for this project.</Dialog.Description>
          </Dialog.Header>
          <Dialog.Footer>
            <Dialog.CloseTrigger asChild>
              <Button variant="outline">Close</Button>
            </Dialog.CloseTrigger>
          </Dialog.Footer>
        </Dialog.Content>
      </Dialog.Positioner>
    </Dialog>
  );
}
```

Настройка завершена, если кнопка оформлена стилями moduix, открывает Dialog с клавиатуры и указателя, а после
закрытия фокус возвращается к кнопке.

## Установить через shadcn CLI

Этот способ подойдёт, если вы хотите хранить исходный код компонентов и стили в репозитории. shadcn CLI читает
реестр moduix, находит зависимости и размещает файлы по настроенным алиасам.

### 1. Настройте shadcn

Создайте `components.json` в корне проекта с конфигурацией реестра moduix:

```json title="components.json"
{
  "$schema": "https://ui.shadcn.com/schema.json",
  "style": "new-york",
  "rsc": false,
  "tsx": true,
  "tailwind": {
    "config": "",
    "css": "",
    "baseColor": "",
    "cssVariables": true,
    "prefix": ""
  },
  "aliases": {
    "components": "@/components",
    "ui": "@/components/ui",
    "lib": "@/lib",
    "hooks": "@/hooks",
    "utils": "@/lib/utils"
  },
  "registries": {
    "@moduix-react": "https://moduix.dev/r/react/{name}.json"
  }
}
```

Объект `tailwind` требуется схемой конфигурации shadcn, но moduix не использует Tailwind и не требует его установки.
Пустые пути и `baseColor` не дают CLI искать файлы Tailwind или загружать палитру shadcn.

Для приложений с клиентским рендерингом оставьте `rsc: false`. Если приложение использует React Server Components,
установите `rsc: true`: CLI shadcn сохранит директивы `use client`, уже указанные в исходных файлах реестра. CLI не
определяет сам, каким компонентам нужна эта директива.

Проверьте, что проект разрешает алиас `@/*` к каталогу с исходным кодом. Типичная структура с `src` использует:

```json
{
  "compilerOptions": {
    "paths": {
      "@/*": ["./src/*"]
    }
  }
}
```

Благодаря этому `shadcn` CLI использует алиасы и URL реестра, чтобы поместить сгенерированные файлы в исходный код,
а не в буквальную папку `@`. В [настройке фреймворка](#выберите-фреймворк) указано, нужен ли этот алиас также в
конфигурации сборщика и какую корневую папку исходного кода выбрать.

### 2. Проверьте элемент реестра

Перед записью исходных файлов проверьте текущую конфигурацию и элемент реестра:

```bash
npx shadcn@latest info --json
npx shadcn@latest search @moduix-react --query "confirmation dialog"
npx shadcn@latest view @moduix-react/dialog
npx shadcn@latest add @moduix-react/dialog --dry-run
```

Ищите нужный интерфейс, а не знакомое название библиотеки. В реестре есть компоненты, темы и их объявленные
зависимости. Тот же поиск через shadcn MCP описан в [руководстве по AI](/docs/ai).

### 3. Добавьте компонент

Добавляйте элементы из реестра moduix:

<PackageManagerTabs command="shadcn@latest add @moduix-react/button" dlx />

Чтобы добавить больше компонентов, выполните ту же команду с именем другого элемента реестра, например
`@moduix-react/accordion`.

Реестр устанавливает только общие runtime-файлы, необходимые компонентам. Глобальный шрифт он не добавляет, поэтому
типографика продолжает наследоваться от приложения.

### 4. Импортируйте сгенерированные стили

Импортируйте базовую таблицу стилей из файлов, которые `shadcn` добавил в проект:

```tsx
import '@/lib/moduix/styles/style.css';
```

Если при таком способе установки нужен необязательный reset, установите его отдельным элементом реестра:

```bash
npx shadcn@latest add @moduix-react/reset
```

Затем импортируйте его перед основной таблицей стилей:

```tsx
import '@/lib/moduix/styles/reset.css';
import '@/lib/moduix/styles/style.css';
```

В примерах ниже предполагаются `@/components` и `@/lib`. Если проект использует другие алиасы, обновите
`components.json` и импортируйте сгенерированные файлы по соответствующим путям.

### 5. Используйте сгенерированный компонент

Импортируйте компоненты из сгенерированных файлов в своём проекте:

```tsx
import { Button } from '@/components/moduix/button';
import { Accordion } from '@/components/moduix/accordion';
```

Большинство компонентов состоят из именованных частей. Такое устройство сохраняет доступное поведение и позволяет
управлять разметкой, компоновкой и стилями в самом приложении.

Процесс владения исходным кодом вдохновлён [shadcn/ui](https://ui.shadcn.com/), а анатомия компонентов и поведение
взаимодействий остаются согласованными с [Ark UI](https://ark-ui.com/).

## Настройте слои порталов

Эта настройка нужна при обоих способах установки. `Dialog`, `Popover`, `Menu`, `Select` и другие компоненты
выводят оверлеи через порталы. Изолируйте корень приложения, чтобы подложки и всплывающие элементы всегда
оказывались поверх страницы и не конфликтовали с локальными `z-index`.

```tsx title="layout.tsx"
<body>
  <div className="root">{children}</div>
</body>
```

```css title="styles.css"
.root {
  isolation: isolate;
}
```

Если приложение поддерживает Safari на iOS 26, проверьте прокручиваемое модальное окно вместе с элементами браузера.
Если контент виден под подложкой, не меняйте позиционирование `body`: абсолютно позиционированная подложка тогда
сможет закрыть всю видимую область.

```css title="styles.css"
body {
  position: relative;
}
```

## Стилизация

moduix подходит для любого способа стилизации, который уже принят в проекте:

- Нативный CSS с глобальными селекторами, каскадными слоями и CSS-переменными.
- CSS Modules с помощью `className` и свойств классов слотов компонентов.
- Утилитарные классы Tailwind CSS для компоновки и разовой стилизации.
- CSS-in-JS-библиотеки, которые добавляют классы или передают ограниченные областью действия стили через собственные обёртки.

По умолчанию основные элементы управления имеют размер `--moduix-size-md: 36px`, а строки всплывающих списков -
`--moduix-size-sm: 32px`. Компоненты используют общую шкалу, поэтому изменение этих токенов одновременно обновит
связанные поля ввода, триггеры, кнопки и элементы наподобие пунктов меню.

На страницах компонентов перечислены их публичные CSS-переменные и хуки стилизации. Для изменений во всей системе
используйте общие семантические токены, а переменные компонентов оставьте для точечных исключений. Полная иерархия
описана в [Токенах](/docs/tokens), а рецепты анимации - в [Анимациях](/docs/animations).

## Устранение неполадок

| Симптом | Проверка |
| --- | --- |
| Компоненты рендерятся без стилей | Один раз импортируйте корректную точку входа `style.css` после необязательного reset. |
| Не удаётся найти импорт с исходным кодом в проекте | Проверьте алиас `@/*` в TypeScript и сборщике, затем `components.json`. |
| Всплывающий элемент отображается под содержимым страницы | Добавьте `isolation: isolate` корневому элементу приложения и избегайте несвязанных глобальных `z-index`. |
| Серверный рендеринг сообщает о клиентских API | В фреймворках, где это необходимо, размещайте интерактивные компоненты ниже клиентской границы. |
