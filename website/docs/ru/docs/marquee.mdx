## Анатомия

```text
Marquee
├─ MarqueeEdge (необязательно)
├─ MarqueeViewport
│  └─ MarqueeContent
│     └─ MarqueeItem
└─ MarqueeEdge (необязательно)

MarqueeRootProvider
└─ то же дерево частей, подключённое к состоянию, созданному useMarquee() из moduix
```

| Часть                       | Назначение                                                                  |
| -------------------------- | --------------------------------------------------------------------------- |
| `Marquee` / `Marquee` | Состояние компонента, метки, идентификаторы, ориентация, состояние паузы и CSS-переменные. |
| `MarqueeRootProvider`     | Выводит дерево компонента на основе состояния, возвращённого `useMarquee()`.              |
| `MarqueeViewport`         | Область просмотра, которая скрывает содержимое за своими границами.                      |
| `MarqueeContent`          | Обёртка анимированного содержимого. При необходимости Ark клонирует её.                  |
| `MarqueeItem`             | Отдельный элемент внутри содержимого.                                                     |
| `MarqueeEdge`             | Необязательный градиент, создающий эффект затухания у края. Передайте `side`, чтобы выбрать край. |
| `MarqueeContext`          | Доступ к контексту родительского компонента `Marquee` для расширенных сценариев.          |

## Композиция

Используйте `Marquee` с явными частями `MarqueeViewport`, `MarqueeContent` и `MarqueeItem`. Добавляйте `MarqueeEdge` внутрь того же
корня, если содержимое должно плавно исчезать на фоне страницы; для каждой границы нужно указать `side`.

Используйте `defaultPaused` для начального состояния без внешнего управления. Если воспроизведением управляет другая
часть приложения, передавайте `paused` и `onPauseChange(details)`. Для внешних элементов управления создайте состояние
через `useMarquee()` и передайте его в `MarqueeRootProvider`; не используйте `Marquee` и `MarqueeRootProvider` для одного
состояния. Элементы управления внутри дерева могут получить текущий API через `MarqueeContext` или
`useMarqueeContext()`.

### Пауза при взаимодействии

Используйте `pauseOnInteraction`, чтобы приостанавливать прокрутку, когда пользователь наводит указатель на компонент
или переводит фокус на его содержимое.

Бегущая строка движется постоянно, поэтому экранные дикторы не могут надёжно прочитать содержимое в движении, а само
движение может отвлекать или вредить. Считайте содержимое некритичным: задайте описательную подпись, предоставьте
способ поставить прокрутку на паузу (`pauseOnInteraction` или явные элементы управления паузой) и никогда не
размещайте важную информацию только внутри бегущей строки.

## Стилизация

В `Marquee` уже есть ключевые кадры, необходимые для анимации содержимого. Используйте атрибуты состояния Ark для
стилей, зависящих от поведения, и выберите модель кастомизации вашего registry-варианта:

- Варианты CSS Modules: используйте переменные `--moduix-marquee-*` для размеров, цвета, расстояний и затухания по
  краям, а `className` для раскладки и оформления элементов. Псевдонимы `--marquee-edge-color` и `--marquee-edge-size`
  сохраняют совместимость с Chakra; переменные `--moduix-marquee-edge-*` имеют приоритет над ними.
- Варианты Tailwind: используйте `className` (React) или `class` (Solid) с утилитами Tailwind для тех же задач.
  В Tailwind-пакетах Marquee не предоставляет CSS-переменные.

По умолчанию `Marquee` прозрачен и не добавляет границу, фон, внутренние отступы или скругление. Если нужен
контейнер с фоном или границей, задайте его оформление в CSS приложения.

### Хуки стилизации

- `data-slot="marquee-root"`, `marquee-root-provider`, `marquee-viewport`, `marquee-content`, `marquee-item` и `marquee-edge`.
- Атрибуты Ark: `data-scope="marquee"`, `data-part="root|viewport|content|item|edge"`, `data-state="paused|idle"`, `data-orientation`, `data-side`, `data-index`, `data-paused`, `data-reverse` и `data-clone`.
- CSS-переменные Ark: `--marquee-duration`, `--marquee-spacing`, `--marquee-delay`, `--marquee-loop-count` и `--marquee-translate`.
