# React Hook Form

[Документация React Hook Form](https://react-hook-form.com/get-started) охватывает полный API, режимы
валидации, resolver и поддержку TypeScript. Здесь показано, как подключать компоненты moduix.

Используйте `register` для нативных полей ввода. Используйте `Controller`, когда компонент Ark работает
с контролируемым значением и передаёт его через detail-колбэки. Если составному компоненту Ark нужен
нативный элемент формы, он создаёт его сам. Не добавляйте и не регистрируйте отдельное скрытое поле.

```bash
npm install react-hook-form
```

## Сопоставление

| Элемент управления | Подключение React Hook Form |
| ------------------ | --------------------------- |
| `Input`, `Textarea`, `Field.Select` | Передайте `register(name, rules)` через spread в нативный элемент. |
| `Select` | Используйте `Controller`; сопоставьте строковое значение со строковым массивом `value` Ark. |
| `Combobox` | Используйте `Controller`; сопоставьте `value`, а фильтрацию оставьте в `onInputValueChange`. |
| `Checkbox` | Используйте `Controller`; сопоставьте `details.checked === true` с булевым значением. |
| Встроенные нативные элементы | Передавайте семантические пропсы корневому элементу, например `name` или `form`; поле создаёт moduix. |

Всегда задавайте `defaultValues` для контролируемых полей. React Hook Form использует их для начального
состояния, отслеживания изменений и `reset()`.

Для состояния ожидания используйте `formState.isSubmitting`. Блокируйте только повторную отправку,
не скрывайте значения полей, а текст кнопки пусть отражает текущий запрос. `handleSubmit` сохраняет
`isSubmitting` равным true, пока не завершится асинхронный обработчик отправки.

## Валидация и сброс

Используйте `rules` для небольшой валидации одного поля. Для общей проверки нескольких полей или
валидации по схеме добавьте resolver; подключение компонентов moduix останется тем же. Когда видимыми
ошибками управляет React Hook Form, добавьте `noValidate` к нативной форме, а `Field invalid` и
`Field.ErrorText` выводите на основе `fieldState`. Не добавляйте `noValidate`, если сначала должна
сработать встроенная валидация браузера.

Вызовите `reset()`, чтобы восстановить те же `defaultValues`, с которыми была инициализирована форма.
Одного `form.reset()` недостаточно для контролируемых полей `Controller`: иначе React Hook Form снова
отрисует в элементе moduix предыдущее значение.

## Полная форма

В форме зарегистрированные `Input` и `Textarea` сочетаются с контролируемыми `Select`, `Combobox` и
`Checkbox`. В этом примере `noValidate` передаёт React Hook Form управление сообщениями об ошибках.
Не добавляйте его, если хотите показать встроенный интерфейс валидации браузера.

## Повторяющиеся поля

Используйте `useFieldArray` для списка, который можно редактировать. Он даёт стабильный `id` для каждой
строки: используйте его как ключ React, но не текущий индекс. Индекс нужен только в пути
зарегистрированного поля. Если элементы списка объединены общей задачей, оставьте метку группы в
`Fieldset`. Этот фрагмент предназначен для компонента, где вызывается `useForm`; отрисовывайте строки и
кнопки внутри его формы.

```tsx
import { Button } from '@moduix/react/button';
import { Field } from '@moduix/react/field';
import { useFieldArray, useForm } from 'react-hook-form';

type EmailFormValues = {
  emails: { address: string }[];
};

const { control, register } = useForm<EmailFormValues>({
  defaultValues: { emails: [{ address: '' }] },
});
const { fields, append, remove } = useFieldArray({ control, name: 'emails' });

{
  fields.map((item, index) => (
    <Field key={item.id}>
      <Field.Label>Email {index + 1}</Field.Label>
      <Input type="email" {...register(`emails.${index}.address` as const)} />
      <Button type="button" onClick={() => remove(index)}>
        Remove email
      </Button>
    </Field>
  ));
}

<Button type="button" onClick={() => append({ address: '' })}>
  Add email
</Button>;
```

## Ошибки сервера

После запроса передавайте ошибки поля через `setError`, а общую ошибку формы — через пространство имён
`root`. Сопоставление `errors.name` по-прежнему управляет `Field invalid` и `Field.ErrorText`; корневое
сообщение достаточно вывести один раз рядом с заголовком формы или кнопкой отправки.

```tsx
const {
  handleSubmit,
  setError,
  formState: { errors },
} = useForm<{ name: string }>({
  defaultValues: { name: '' },
});

const onSubmit = handleSubmit(async (values) => {
  const result = await createProject(values);

  if (result.nameError) {
    setError('name', {
      type: 'server',
      message: result.nameError,
    });
  }

  if (result.message) {
    setError('root.server', {
      type: 'server',
      message: result.message,
    });
  }
});

{
  errors.root?.server?.message ? <p role="alert">{errors.root.server.message}</p> : null;
}
```

## Примечания

- Не передавайте объект поля `Controller` через spread в `Select` или `Combobox`: формы их значений и
  колбэков не соответствуют нативным событиям поля ввода.
- Для одиночного выбора передайте `field.value ? [field.value] : []` и прочитайте
  `details.value[0] ?? ""`.
- Вызывайте `field.onBlur` из `Select.onInteractOutside` или `Combobox.Input.onBlur`, чтобы состояние
  посещения поля и валидация при потере фокуса соответствовали действиям пользователя.
- Передавайте `field.ref` в `Select.Trigger` или `Combobox.Input`. Это позволяет React Hook Form
  переводить фокус на первое невалидное поле.
- `Select` автоматически отрисовывает нативный select для нативной семантики, автозаполнения и
  синхронизации сброса.
- Сопоставляйте состояние `Checkbox` с булевым значением поля; его корневой элемент автоматически
  отрисовывает нативное поле ввода.
- `name={field.name}` включает нативную семантику `FormData`, но не заменяет `Controller` как источник
  значения поля. Сохраняйте контролируемое значение и сопоставление колбэка, показанные выше.
- У остальных встроенных элементов нестандартную конфигурацию формы задавайте на корневом элементе:
  `DateInput` использует кортеж `names` из двух элементов для отдельных индексированных ключей диапазона,
  `Select` — `nativeFormControl="input"` для виртуализированных коллекций, а `SignaturePad` —
  `getFormValue` для пользовательской сериализации.
