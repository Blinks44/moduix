# React Hook Form

[Документация React Hook Form](https://react-hook-form.com/get-started) описывает полный API,
режимы валидации, resolver и поддержку TypeScript. На этой странице показано, как подключать эту
библиотеку к компонентам moduix.

React Hook Form хранит значения полей, выполняет валидацию и управляет состоянием отправки формы.
moduix отвечает за доступную разметку, семантику полей и нативный элемент формы, который нужен
составному компоненту.

Используйте `register`, когда компонент предоставляет нативный input, textarea или select.
Используйте `Controller`, когда составной компонент передаёт контролируемое значение через пропсы и
колбэки с объектом detail. Составной компонент, который участвует в отправке формы, уже сам
сам отвечает за участие в форме, поэтому не добавляйте и не регистрируйте второе скрытое поле.

```bash
npm install react-hook-form
```

## Выберите способ подключения

| Компонент moduix | Подключение к React Hook Form |
| ---------------- | ----------------------------- |
| `Input`, `Textarea`, `NativeSelect`, `Field.Input`, `Field.Textarea`, `Field.Select` | Передайте результат `register(name, rules)` через spread в нативный элемент. |
| `Select` | Используйте `Controller`: преобразуйте скалярное значение поля в строковый массив `value` компонента. |
| `Combobox` | Используйте `Controller`: сопоставьте выбранное значение, а фильтрацию оставьте в `onInputValueChange`. |
| `Checkbox` | Используйте `Controller`: преобразуйте `details.checked === true` в булево значение поля. |
| Другие составные компоненты с поддержкой формы | Передавайте семантические пропсы корневому элементу, например `name` или `form`; используйте `Controller`, если управляете значением компонента. |

Для каждого контролируемого поля задавайте значение в `defaultValues`. React Hook Form использует
его при первом рендере, для отслеживания изменений и при вызове `reset()`.

Для интерфейса ожидания используйте `formState.isSubmitting`. Не допускайте повторной отправки,
оставляйте значения полей видимыми, а текст кнопки связывайте с выполняемым запросом.
`handleSubmit` сохраняет `isSubmitting` равным `true`, пока не завершится асинхронный обработчик.

## Валидация и сброс

Используйте `rules` для проверок, относящихся к одному полю. Для общей, межполеевой или схемной
валидации добавьте resolver. Подключение к moduix при этом не меняется: для контролируемых полей
передавайте `fieldState.invalid` в `Field`, а `fieldState.error?.message` выводите через
`Field.ErrorText`. Для зарегистрированных контролов сообщение берите из `formState.errors`.

Добавляйте `noValidate` к нативной форме только тогда, когда React Hook Form должен управлять
видимыми сообщениями об ошибках. Если первой должна сработать встроенная валидация браузера,
оставьте этот атрибут выключенным.

Для сброса контролируемых полей вызывайте `reset()` из React Hook Form. Одного
`form.reset()` недостаточно для полей с `Controller`: при следующем рендере компонент moduix может
снова получить старое значение из состояния формы.

## Повторяющиеся поля

Используйте `useFieldArray` для списка, в который пользователь может добавлять, удалять и
перемещать строки. В каждом элементе `fields` есть стабильный `id`: используйте его как ключ React,
а текущий индекс только в пути зарегистрированного поля. Общую подпись поместите в `Fieldset`, а
для каждой строки задайте свой `Field`, подпись и сообщение об ошибке.

```tsx
import { Button } from '@moduix/react/button';
import { Field } from '@moduix/react/field';
import { Fieldset } from '@moduix/react/fieldset';
import { Input } from '@moduix/react/input';
import { useFieldArray, useForm } from 'react-hook-form';

type EmailFormValues = {
  emails: { address: string }[];
};

export function EmailListForm() {
  const {
    control,
    handleSubmit,
    register,
    formState: { errors },
  } = useForm<EmailFormValues>({
    defaultValues: { emails: [{ address: '' }] },
  });
  const { fields, append, remove } = useFieldArray({ control, name: 'emails' });

  return (
    <form onSubmit={handleSubmit((values) => console.log(values))}>
      <Fieldset>
        <Fieldset.Legend>Email addresses</Fieldset.Legend>
        <Fieldset.HelperText>Add one address per row.</Fieldset.HelperText>

        {fields.map((item, index) => (
          <Field
            key={item.id}
            invalid={Boolean(errors.emails?.[index]?.address)}
            required
          >
            <Field.Label>
              Email {index + 1}
              <Field.RequiredIndicator />
            </Field.Label>
            <Input
              type="email"
              {...register(`emails.${index}.address` as const, {
                required: 'Enter an email address.',
              })}
            />
            <Field.ErrorText>{errors.emails?.[index]?.address?.message}</Field.ErrorText>
            <Button type="button" onClick={() => remove(index)}>
              Remove email
            </Button>
          </Field>
        ))}

        <Button type="button" onClick={() => append({ address: '' })}>
          Add email
        </Button>
      </Fieldset>
    </form>
  );
}
```

## Ошибки сервера

После завершения запроса передавайте ошибки, которые вернул сервер. Для ошибки конкретного поля
используйте `setError`, а для ошибки всей формы пространство имён `root`. Сопоставление с `Field`
остаётся таким же, как для клиентской валидации. Функция запроса передаётся в компонент, чтобы
пример был сосредоточен на обработке ошибок.

```tsx
import { Field } from '@moduix/react/field';
import { Input } from '@moduix/react/input';
import { useForm } from 'react-hook-form';

type ProjectFormValues = {
  name: string;
};

type CreateProjectResult = {
  nameError?: string;
  message?: string;
};

type ProjectFormProps = {
  createProject: (values: ProjectFormValues) => Promise<CreateProjectResult>;
};

export function ProjectForm({ createProject }: ProjectFormProps) {
  const {
    handleSubmit,
    register,
    setError,
    formState: { errors },
  } = useForm<ProjectFormValues>({
    defaultValues: { name: '' },
  });

  const onSubmit = handleSubmit(async (values) => {
    const result = await createProject(values);

    if (result.nameError) {
      setError('name', {
        type: 'server',
        message: result.nameError,
      });
    }

    if (result.message) {
      setError('root.server', {
        type: 'server',
        message: result.message,
      });
    }
  });

  return (
    <form noValidate onSubmit={onSubmit}>
      <Field invalid={Boolean(errors.name)}>
        <Field.Label>Project name</Field.Label>
        <Input
          {...register('name', {
            required: 'Enter a project name.',
          })}
        />
        <Field.ErrorText>{errors.name?.message}</Field.ErrorText>
      </Field>

      {errors.root?.server?.message ? (
        <p role="alert">{errors.root.server.message}</p>
      ) : null}

      <button type="submit">Create project</button>
    </form>
  );
}
```

## Важные детали

- Не передавайте объект поля `Controller` через spread в `Select` или `Combobox`: формы их значений
  и колбэков не соответствуют нативным событиям ввода.
- Для одиночного значения `Select` или `Combobox` передавайте `field.value ? [field.value] : []`,
  а в обработчике значения читайте `details.value[0] ?? ""`.
- Вызывайте `field.onBlur`, когда взаимодействие с компонентом завершилось: для `Select` используйте
  `Select.onInteractOutside`, а для `Combobox` `Combobox.Input.onBlur`. Так состояние посещения поля
  и валидация при потере фокуса остаются синхронизированными.
- Передавайте `field.ref` в `Select.Trigger` или `Combobox.Input`. React Hook Form использует эту
  ссылку, чтобы перевести фокус на первое невалидное поле.
- `Select` автоматически создаёт нативный `<select>`, а `Checkbox` автоматически создаёт свой
  нативный input. Передавайте `name` и `form` корневому элементу, но не добавляйте второе скрытое
  поле.
- Для `Combobox` также задавайте `name` и `form` на корневом элементе. У него нет части
  `HiddenInput`, и для подключения к форме дополнительный input не нужен.
- Для очень большой виртуализированной коллекции `Select` можно задать
  `nativeFormControl="input"`. Тогда вместо нативного select используются лёгкие скрытые поля.
  Сброс и отправка формы сохраняются, но пропадают автозаполнение, нативная валидация и
  прогрессивное улучшение, которые даёт select.
- Для остальных компонентов с автоматическим участием в форме оставляйте специальные настройки на
  корневом элементе. `DateInput` использует кортеж `names` из двух элементов для разных ключей
  диапазона, а `SignaturePad` использует `getFormValue` для собственной сериализации.
