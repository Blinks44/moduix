## Использование

<Usage />

Используйте `RadioGroup` как корневой компонент и задайте `value` для каждого варианта.
`RadioGroupOption` выводит элемент с подписью, управлением, текстом и нативным полем.

## Какой компонент выбрать

Используйте `RadioGroup`, когда пользователь должен выбрать ровно один вариант из видимого списка,
например фреймворк, тариф или тип аккаунта. Для независимых вариантов используйте `Checkbox`, а для
настройки, которая применяется сразу, `Switch`.

## Примеры

### Размеры

Передайте свойство `size` из moduix в `RadioGroup` или `RadioGroupRootProvider`, чтобы изменить диаметр всех
радиокнопок группы. Поддерживаются значения `xs`, `sm`, `md` (по умолчанию), `lg` и `xl`.

<Example name="radio-group/sizes" />

### Ориентация

Задайте `orientation="horizontal"`, если клавиши со стрелками должны перемещаться по горизонтальной
группе. Для горизонтальной визуальной раскладки разместите варианты в строчном контейнере.

<Example name="radio-group/orientation" />

### Начальное значение

Задайте `defaultValue`, если выбранный при инициализации вариант известен, а дальше группа должна
управлять изменениями самостоятельно.

<Example name="radio-group/initial-value" />

### Индикатор

Используйте `RadioGroupIndicator`, если для активного варианта нужен дополнительный измеряемый
фон. Держите индикатор и радиокнопки в одном контексте позиционирования, чтобы индикатор следовал
геометрии вариантов.

<Example name="radio-group/indicator" />

### Отключённая группа

Задайте `disabled` на корневом компоненте, чтобы сделать все варианты недоступными и сохранить
видимым выбранное значение.

<Example name="radio-group/disabled" />

### Отключённый элемент

Задайте `disabled` на отдельном `RadioGroupItem` или `RadioGroupOption`, если недоступным должен быть только один
вариант.

<Example name="radio-group/item-disabled" />

### С Field

Используйте `Field`, если группе нужны собственные подпись, вспомогательный текст или сообщение
об ошибке. Передайте `invalid` также в `RadioGroup`, потому что `Field` не меняет состояние
валидации группы.

<Example name="radio-group/with-field" />

### С Fieldset

Оберните группу в `Fieldset`, если несколько вариантов используют одну легенду и относятся к одному
разделу формы. `Fieldset` также может передать вложенной группе состояния `disabled` и `invalid`.

<Example name="radio-group/with-fieldset" />

### Форма

Передайте `name` корневому компоненту, если выбранное значение нужно отправлять в форму.
`RadioGroupOption` уже содержит поле ввода, а в каждом пользовательском `RadioGroupItem` нужно добавить
`RadioGroupItemHiddenInput`.

<Example name="radio-group/form" />

### Управляемое состояние

Передайте `value` и `onValueChange` (`v-model` во Vue, `bind:value` в Svelte), если выбранное значение зависит от маршрута,
фильтров или соседнего интерфейса. Подробнее в разделе [Управляйте состоянием из приложения](/docs/composition-patterns#controlled-state).

<Example name="radio-group/controlled" />

### asChild

Используйте `RadioGroupItem asChild`, когда карточка или пользовательская разметка подписи должны
стать DOM-узлом варианта. Прямым дочерним элементом оставляйте семантический `label`.

<Example name="radio-group/aschild" />

### Root Provider

Используйте `RadioGroupRootProvider`, когда хранилище `useRadioGroup()` нужно разделить с элементами за
пределами дерева группы. Пример также показывает, как изменить выбранное значение извне. Подробнее в разделе [Выносите состояние за пределы дерева](/docs/composition-patterns#root-provider).

Та же группа, что в Basic, но без `RadioGroupOption`: каждый `RadioGroupItem` содержит

## Композиция

`RadioGroup` следует примитиву radio-group из Ark UI и добавляет стили moduix, стабильные атрибуты
`data-slot` и вспомогательный компонент `RadioGroupOption`. Компонент экспортируется из
`@moduix/react/radio-group`, `@moduix/solid/radio-group`, `@moduix/vue/radio-group` и `@moduix/svelte/radio-group`.

Используйте `defaultValue` для неконтролируемой группы. Если выбранное значение хранит другая часть
приложения, используйте `value` и `onValueChange(details)`. Когда состояние нужно создать вне дерева
группы, используйте `RadioGroupRootProvider` с `useRadioGroup()` из соответствующего пакета. Не используйте
`RadioGroup` и `RadioGroupRootProvider` для одного экземпляра состояния одновременно. В React
состояние доступно как объект. В Solid вызывайте возвращённую функцию доступа, а в Vue читайте
реактивное состояние непосредственно в шаблоне. В Svelte хук возвращает геттер: читайте состояние как `radioGroup().value`.

`RadioGroupOption` уже содержит `RadioGroupItemHiddenInput` в фиксированной композиции. При прямой композиции
`RadioGroupItem` добавьте `RadioGroupItemHiddenInput` самостоятельно. Используйте явное дерево
частей, когда вложенным частям нужны собственное размещение или свойства, либо когда `asChild` должен
передать DOM-узел варианта другому элементу. В Solid `asChild` принимает render-функцию, а в Vue используется
`as-child`; в Svelte передаётся сниппет `asChild`, а `props()` разворачиваются на элементе; во всех случаях прямым дочерним элементом должен оставаться семантический `label`.

`Field` предоставляет видимую подпись, вспомогательный текст и сообщение об ошибке, но не
передаёт своё состояние в `RadioGroup`. Передавайте `disabled`, `invalid`, `readOnly` и `required`
самой группе. `Fieldset` передаёт вложенным группам состояние Ark `disabled` и `invalid`.

## Стилизация

Используйте `className` в React или `class` в Solid на экспортируемых частях для структурных стилей.
Для стилей состояний используйте атрибуты Ark, например `data-state`, `data-disabled` и
`data-orientation`, вместе с селекторами moduix `data-slot`. Варианты Tailwind используют нативные
утилиты и классы потребителя, а переменные ниже настраивают варианты CSS Modules. Атрибуты данных и
хуки `data-slot` общие для обоих способов стилизации.

### Хуки стилизации

| Часть | `data-slot` |
| --- | --- |
| `RadioGroup` | `radio-group-root` |
| `RadioGroupRootProvider` | `radio-group-root-provider` |
| `RadioGroupLabel` | `radio-group-label` |
| `RadioGroupItem` | `radio-group-item` |
| `RadioGroupItemControl` | `radio-group-item-control` |
| `RadioGroupItemText` | `radio-group-item-text` |
| `RadioGroupIndicator` | `radio-group-indicator` |

- Анатомия Ark: `data-scope="radio-group"` и `data-part` на корне, подписи, варианте,
  управлении, тексте, скрытом поле и индикаторе.
- Состояния Ark: `data-state="checked|unchecked"`, `data-disabled`, `data-readonly`,
  `data-invalid`, `data-required`, `data-focus`, `data-focus-visible`, `data-hover`,
  `data-active` и `data-orientation`.
- Переменные индикатора Ark: `--transition-property`, `--left`, `--top`, `--width` и `--height`.

## Клавиатура

| Клавиша | Действие |
| --- | --- |
| `Tab` | Переводит фокус в группу, на выбранную опцию. |
| `ArrowDown` / `ArrowUp` / `ArrowLeft` / `ArrowRight` | Переходит к следующей или предыдущей опции и выбирает её. |
| `Space` | Выбирает опцию в фокусе. |

## Справочник API

| Проп | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `value` | `string \| null` | — | Выбранное значение в управляемом режиме. |
| `defaultValue` | `string \| null` | — | Изначально выбранное значение. |
| `onValueChange` | `(details: ValueChangeDetails) => void` | — | Вызывается при выборе другого варианта. |
| `orientation` | `'horizontal' \| 'vertical'` | `'vertical'` | Раскладка и направление стрелок: `horizontal` или `vertical`. |
| `size` | `'xs' \| 'sm' \| 'md' \| 'lg' \| 'xl'` | `'md'` | Размер: `xs`, `sm`, `md`, `lg` или `xl`. |
| `name` | `string` | — | Общее имя поля формы для всех радиокнопок. |
| `disabled` | `boolean` | `false` | Отключает элемент управления. |
| `readOnly` | `boolean` | `false` | Показывает значение, но не даёт его менять. |
| `invalid` | `boolean` | `false` | Помечает поле как невалидное. |
| `required` | `boolean` | `false` | Требует значение перед отправкой формы. |
| `form` | `string` | — | Id формы, к которой относится внутренний input. |
