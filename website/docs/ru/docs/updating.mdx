# Обновление и миграция

moduix можно подключить двумя способами. Порядок обновления зависит от того, где находится
исходный код компонента:

| Установка | Где находится исходный код | Как обновлять |
| --- | --- | --- |
| Пакет `@moduix/react` | В `node_modules` | Обновляйте пакет и его peer-зависимости через менеджер пакетов. |
| Реестр shadcn | В репозитории приложения | Сначала изучите изменения в реестре, затем объедините их с локальным исходным кодом. |

Если вы переносите существующее приложение с shadcn на moduix, прочитайте раздел [Миграция с shadcn](/docs/migrate-from-shadcn).

## Обновление npm-пакета

Выбирайте этот способ, если хотите хранить moduix в зависимостях приложения и получать обновления
через менеджер пакетов.

Перед сменой версий прочитайте [Историю изменений](/docs/changelog). Используйте `npm update` для
совместимых обновлений в пределах диапазонов версий, уже указанных в `package.json`:

Ниже приведены команды для npm. Если вы используете pnpm, Yarn или другой менеджер пакетов,
замените их на соответствующие команды своего инструмента.

```bash
npm update @moduix/react @ark-ui/react
```

Чтобы выбрать версии явно и изменить указанные диапазоны, установите нужные релизы:

```bash
npm install @moduix/react@latest @ark-ui/react@latest
```

`@ark-ui/react` - peer-зависимость `@moduix/react`. Перед мажорным обновлением проверьте в
примечаниях к релизу совместимый диапазон Ark UI, а не обновляйте оба пакета вслепую. Осознанно
выберите мажорную версию moduix и выполните шаги миграции из соответствующей записи в истории
изменений.

После обновления проверьте lockfile, запустите проверку типов и тесты приложения, а также проверьте
компоненты, упомянутые в истории изменений. Если в релизе изменилась композиция или стили, перед
публикацией сравните документацию компонента с его реализацией в приложении.

## Обновление компонентов из реестра

Компоненты из реестра копируются в репозиторий приложения. Обновление `@moduix/react` их не
затрагивает, поэтому каждый элемент реестра нужно обновлять отдельно.

Перед изменением локальных файлов изучите актуальный элемент и сравните его с вашей копией:

```bash
npx shadcn@latest view @moduix-react/button
npx shadcn@latest add @moduix-react/button --dry-run
npx shadcn@latest add @moduix-react/button --diff
```

Замените `button` на нужный элемент. Команда `view` показывает текущий исходный код в реестре,
`--dry-run` предварительно показывает файлы, которые будут изменены, а `--diff` сравнивает версию
из реестра с файлами в проекте. В diff могут попасть общие файлы основы moduix и другие зависимости
реестра, поэтому их тоже нужно проверить.

После просмотра diff выполните обновление в отдельной ветке или в чистом рабочем дереве:

```bash
npx shadcn@latest add @moduix-react/button
```

Не используйте `--overwrite`, пока не решите, как сохранить локальные изменения. Если вы меняли
компонент в приложении, объедините изменения из реестра со своей версией, а затем проверьте
поведение компонента, доступность и стили.

Повторите эту процедуру для каждого используемого элемента реестра. CLI автоматически подтягивает
общую основу moduix и объявленные зависимости элементов. Импортируйте сгенерированную таблицу
стилей основы один раз в точке входа приложения:

```tsx
import '@/lib/moduix/styles/style.css';
```

## Обновление пресетов

Пресеты, которые входят в `@moduix/react`, обновляются вместе с пакетом. Обращайтесь к разделам
[Темы](/docs/themes) и [Токены](/docs/tokens), если релиз меняет плотность, цвета или другие общие
визуальные настройки по умолчанию.

Пресет, скопированный из реестра, проверяйте и обновляйте так же, как любой другой элемент:

```bash
npx shadcn@latest view @moduix-react/theme-soft
npx shadcn@latest add @moduix-react/theme-soft --dry-run
npx shadcn@latest add @moduix-react/theme-soft --diff
```

После просмотра diff установите пресет без `--dry-run`, а переопределения приложения оставьте после
его импорта. Так сохраняется каскад, даже если в пресете появится новый токен:

```tsx
import '@/lib/moduix/styles/style.css';
import '@/lib/moduix/presets/soft.css';
```
