## Справочник API

<PrimitiveReference href="https://ark-ui.com/docs/components/toast" />

Moduix экспортирует `Toast`, `ToastToaster`, `createToaster` и `useToastContext` из
`@moduix/react/toast`, `@moduix/solid/toast` и `@moduix/vue/toast`. Полный API хранилища и его
частей приведён в справочнике Ark.

## Базовый пример


Один раз создайте toaster через `createToaster()`, добавляйте уведомления его методами и выведите

## Анатомия

```text
createToaster()
└─ ToastToaster (portalled to document.body by default)
   └─ Toast
      ├─ ToastTitle
      ├─ ToastDescription
      ├─ ToastActionTrigger
      └─ ToastCloseTrigger
```

| Часть                          | Назначение                                                                            |
| ------------------------------ | ------------------------------------------------------------------------------------- |
| `Toast`               | Корень видимого уведомления.                                      |
| `ToastToaster`        | Выводит хранилище toaster и управляет группой уведомлений.       |
| `ToastTitle`          | Заголовок. Если дочерние элементы не переданы, использует `title` текущего уведомления. |
| `ToastDescription`    | Описание. Если дочерние элементы не переданы, использует `description` текущего уведомления. |
| `ToastActionTrigger`  | Кнопка действия, связанная с `toast.action.onClick`.             |
| `ToastCloseTrigger`   | Кнопка закрытия. По умолчанию использует `CloseButton`.          |
| `ToastContext`        | Контекстная часть для собственной композиции и прямого доступа к состоянию уведомления. |

## Композиция

Создайте toaster один раз и передайте тот же экземпляр в `ToastToaster`. В Vue создавайте его внутри
`<script setup>`, чтобы у каждого экземпляра компонента было своё хранилище; общее для приложения
хранилище можно вынести в отдельный модуль. При серверном рендеринге создавайте отдельное хранилище
для каждого запроса. Хранилище управляет размещением, стеком, очередью, таймерами и фокусом.
По умолчанию `ToastToaster`
выводит группу через портал в `document.body`; используйте `portalled={false}` или `portalRef`,
если группа должна находиться в другом контейнере. Отдельная обёртка `Portal` не нужна.

Для обычного уведомления используйте стандартный рендерер `ToastToaster`: он выводит заголовок, описание,
действие и кнопку закрытия. Для другой разметки или собственных элементов управления передайте
render prop в React/Solid или основной scoped slot в Vue, оставьте `Toast` внешним элементом и
соберите внутри его части. Слот Vue получает параметры уведомления; `useToastContext()` возвращает
computed ref. Для `asChild` у кнопок действия и закрытия используйте семантический элемент-кнопку,
а `useToastContext()`
подключайте, когда собственному элементу нужен прямой доступ к текущему уведомлению.

В `@ark-ui/vue@5.39.3` свойство `asChild` у `Toast` переносит атрибуты корня на внутренний
вспомогательный элемент, а `ToastToaster` игнорирует `asChild`. Используйте их стандартные элементы
до исправления этих вариантов композиции в upstream. Композиция с `asChild` у заголовка,
описания, кнопки действия и кнопки закрытия поддерживается.

## Примеры

### Действие

Добавьте `action: { label, onClick }`, если уведомление должно предложить одно прямое действие.

<Example name="toast/action" />

### Длительность

Задайте `duration` в миллисекундах, если уведомление должно исчезнуть раньше, оставаться дольше или
ждать ручного закрытия. Для последнего варианта используйте `Infinity`.

<Example name="toast/duration" />

### Максимум видимых

Установите `max` на toaster, если всплески уведомлений должны вставать в очередь, а не заполнять
экран.

<Example name="toast/max-toasts" />

### Стек без перекрытия

Задайте `overlap: false`, если каждое уведомление должно оставаться полностью видимым. Это настройка
toaster, а не отдельный режим компонента.

<Example name="toast/always-expanded" />

### Размещение

Выберите один из шести вариантов Ark, если группа уведомлений должна появляться у определённого
края окна.

<Example name="toast/placement" />

### Promise

Используйте `toaster.promise()`, чтобы одно уведомление переходило из состояния загрузки в состояние
успеха или ошибки после завершения асинхронной операции. Пока у уведомления тип `loading`, стандартная
разметка показывает декоративный `Spinner` перед заголовком.

<Example name="toast/promise-toast" />

### Типы

Используйте типизированные методы toaster для вариантов, зависящих от статуса. Moduix оформляет
`info`, `success`, `warning` и `error` через `data-type`.

<Example name="toast/types" />

### Обновление

Сохраните идентификатор, который возвращает создание уведомления, и передайте его в
`toaster.update()`, если существующее уведомление нужно изменить на месте.

<Example name="toast/update" />

### Расширенная настройка

Используйте render prop, чтобы заменить стандартную разметку `ToastToaster`, добавить иконку, изменить
иконку закрытия и применить CSS-переменные компонента.

<Example name="toast/custom-composition" />

## Стилизация

Стилизуйте `Toast` с помощью атрибутов частей Ark, хуков `data-slot` и классов на частях. Варианты с
CSS Modules также читают четыре переменные ниже; `--moduix-toast-bg`, `--moduix-toast-border-color` и
`--moduix-toast-color` переопределяют все типы, поэтому для одного типа задавайте их внутри
`[data-type='success']` и похожих селекторов. Варианты Tailwind используют нативные утилиты и классы
приложения.

### Хуки стилизации

На корневом элементе задавайте стили поверхности, границы, анимации и вариантов по типу. Для
внутренней типографики и элементов управления используйте `ToastTitle`, `ToastDescription`,
`ToastActionTrigger` и `ToastCloseTrigger`.

Полезные селекторы Ark:

- `[data-scope='toast'][data-part='group']` на `ToastToaster`
- `[data-scope='toast'][data-part='root']` на `Toast`
- `[data-scope='toast'][data-part='title']` на `ToastTitle`
- `[data-scope='toast'][data-part='description']` на `ToastDescription`
- `[data-scope='toast'][data-part='action-trigger']` на `ToastActionTrigger`
- `[data-scope='toast'][data-part='close-trigger']` на `ToastCloseTrigger`
- `--x`, `--y`, `--scale`, `--z-index`, `--height`, `--opacity` и `--gap` на `Toast`

Moduix также добавляет стабильные хуки: `data-slot="toast-toaster"`, `data-slot="toast-root"`,
`data-slot="toast-title"`, `data-slot="toast-description"`, `data-slot="toast-action-trigger"`
и `data-slot="toast-close-trigger"`.

При ширине окна до `40rem` любое размещение центрируется по горизонтали. Уведомления сохраняют ширину
`20rem` и сужаются, чтобы поместиться между `offsets` Ark и горизонтальными безопасными зонами экрана.
