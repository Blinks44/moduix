## Анатомия

```text
createToaster()
└─ Toaster / Toast.Toaster (portalled to document.body by default)
   └─ Toast / Toast.Root
      ├─ Toast.Title
      ├─ Toast.Description
      ├─ Toast.ActionTrigger
      └─ Toast.CloseTrigger
```

| Часть                         | Назначение                                                                                  |
| ----------------------------- | -------------------------------------------------------------------------------------------- |
| `Toast` / `Toast.Root`        | Корень видимого уведомления. `Toast.Root` - алиас `Toast` для совместимости.                 |
| `Toaster` / `Toast.Toaster`   | Подключает экземпляр toaster и управляет группой уведомлений.                              |
| `Toast.Title`                 | Заголовок. Если дочерние элементы не переданы, использует `title` текущего уведомления.      |
| `Toast.Description`           | Описание. Если дочерние элементы не переданы, использует `description` текущего уведомления. |
| `Toast.ActionTrigger`         | Кнопка действия, связанная с `toast.action.onClick`. Передайте `toast.action.label` как содержимое. |
| `Toast.CloseTrigger`          | Кнопка закрытия. По умолчанию использует `CloseButton.Root`.                                |
| `Toast.Context`               | Контекстная часть для собственной композиции. Для доступа к состоянию используйте `useToastContext()`. |

## Композиция

По умолчанию `Toaster` выводит группу уведомлений через портал в `document.body`. Установите
`portalled={false}`, чтобы оставить группу в месте, где смонтирован `Toaster`, или передайте
`portalRef`, чтобы использовать другой контейнер. Отдельная обёртка `Portal` не нужна.

### Рекомендуемая композиция

Создайте toaster один раз, по возможности вне тела компонента, и передайте тот же объект в
`Toaster`. Он управляет размещением, перекрытием, расстоянием, размером очереди, длительностью,
задержкой удаления, паузой при бездействии и горячей клавишей фокуса `Alt+T`.

В собственной разметке, которую возвращает render prop, используйте `Toast` как корневой элемент.
`Toast.Root` остаётся доступен как алиас для совместимости.

Если render prop не передан, `Toaster` использует стандартную разметку moduix. Она показывает
заголовок и описание, если они есть, добавляет действие, когда оно задано, и кнопку закрытия, если
не установлено `closable: false`. Для обычных уведомлений приложения это рекомендуемый вариант.

### Когда нужна собственная композиция

Передайте render prop в `Toaster`, если уведомлению нужны другая разметка, иконка или собственные
элементы управления. Например, так можно заменить стандартную иконку закрытия. Оставьте `Toast`
внешним элементом, чтобы Ark мог управлять стеком, измерением высоты, закрытием, паузой,
клавиатурным фокусом и атрибутами типа и состояния.

Части Ark, которые выводят элементы интерфейса, поддерживают `asChild`. Если вы заменяете
`ActionTrigger` или `CloseTrigger`, используйте один семантически подходящий дочерний элемент и
сохраните поведение кнопки.

Если дочернему элементу нужен прямой доступ к состоянию уведомления, импортируйте
`useToastContext()` из `@moduix/react/toast`.

### Свойства по умолчанию

| Свойство                       | По умолчанию         | Примечания                                                                                 |
| ------------------------------ | -------------------- | ------------------------------------------------------------------------------------------ |
| `createToaster.duration`       | Зависит от типа      | Длительность новых уведомлений по умолчанию. Для одного уведомления задайте `duration`.    |
| `createToaster.gap`            | `16`                 | Расстояние между уведомлениями.                                                            |
| `createToaster.max`            | `24`                 | Новые уведомления встают в очередь, когда видимый стек достигает этого лимита.             |
| `createToaster.hotkey`         | `["altKey", "KeyT"]` | Перемещает фокус на группу уведомлений.                                                   |
| `createToaster.offsets`        | `"1rem"`             | Отступ от безопасного края окна.                                                          |
| `createToaster.overlap`        | `false`              | Установите `true`, чтобы уведомления перекрывались в стеке.                               |
| `createToaster.pauseOnPageIdle`| `false`              | Установите `true`, чтобы при бездействии страницы приостанавливать таймеры.                |
| `createToaster.placement`      | `"bottom"`           | `top-start`, `top`, `top-end`, `bottom-start`, `bottom` или `bottom-end`.                  |
| `createToaster.removeDelay`    | `200`                | Оставляет закрытые уведомления смонтированными на время анимации выхода.                  |
| `Toaster.portalled`            | `true`               | Установите `false`, чтобы выводить группу в месте монтирования `Toaster`.                  |

### Особенности поведения

- Вызывайте `toaster.create()` или вспомогательные методы `success()`, `error()`, `warning()`,
  `info()`, `loading()`, `promise()`, `update()`, `dismiss()`, `remove()` и `dismissByPlacement()`
  у экземпляра toaster.
- Если `type` не задан, используется значение Ark по умолчанию `type: "info"`. В moduix типы
  `info`, `success`, `warning` и `error` оформлены как карточные варианты, согласованные с `Alert`.
- `toast.action` имеет форму `{ label, onClick }` и выводится через `Toast.ActionTrigger`.
- `toast.duration` задаёт длительность одного уведомления. `createToaster({ duration })` задаёт
  значение по умолчанию для toaster.
- `toast.onStatusChange(details)` получает изменения статуса Ark: `visible`, `dismissing` и
  `unmounted`.
- При создании уведомления внутри эффекта отложите вызов метода toaster через
  `queueMicrotask(() => toaster.create(...))`, чтобы избежать предупреждений React `flushSync`.
- `Toast` предоставляет атрибуты состояния Ark, включая `data-state`, `data-type`,
  `data-placement`, `data-align`, `data-side`, `data-mounted`, `data-paused`, `data-first`,
  `data-sibling`, `data-stack` и `data-overlap`.

### Доступность

Ark сохраняет поведение live region, группировку уведомлений, паузу, горячую клавишу фокуса,
жизненный цикл закрытия и колбэки статуса. Если группе уведомлений нужно собственное доступное
имя, передайте его через свойство `label` компонента `Toaster`.

`Toast.CloseTrigger` по умолчанию является кнопкой с доступным именем `Close toast`. При
использовании `asChild` дочерний элемент должен сохранять доступное имя и семантику кнопки.
`Toast.ActionTrigger` также остаётся кнопкой, связанной с `toast.action.onClick`.

### Хуки стилизации

На `Toast` задавайте стили поверхности уведомления, границы, анимации и вариантов по типу. Для
внутренней типографики и элементов управления используйте `Toast.Title`, `Toast.Description`,
`Toast.ActionTrigger` и `Toast.CloseTrigger`.

Полезные селекторы Ark:

- `[data-scope='toast'][data-part='group']` на `Toaster`
- `[data-scope='toast'][data-part='root']` на `Toast`
- `[data-scope='toast'][data-part='title']` на `Toast.Title`
- `[data-scope='toast'][data-part='description']` на `Toast.Description`
- `[data-scope='toast'][data-part='action-trigger']` на `Toast.ActionTrigger`
- `[data-scope='toast'][data-part='close-trigger']` на `Toast.CloseTrigger`
- `--x`, `--y`, `--scale`, `--z-index`, `--height`, `--opacity` и `--gap` на `Toast`

Moduix также добавляет стабильные хуки: `data-slot="toast-toaster"`, `data-slot="toast-root"`,
`data-slot="toast-title"`, `data-slot="toast-description"`, `data-slot="toast-action-trigger"`
и `data-slot="toast-close-trigger"`.

При ширине окна до `40rem` группа уведомлений занимает всю ширину окна, а каждый корневой элемент
использует переменную Ark `--gap`, чтобы сохранить безопасные внутренние отступы.
