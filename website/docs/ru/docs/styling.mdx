# Стилизация

Moduix выпускает отдельные CSS Modules- и Tailwind-пакеты для каждого текущего фреймворка. Выберите
способ, который уже используется в приложении, и вносите изменения на самом верхнем уровне, которому
принадлежит решение.

Руководство предполагает, что нужный пакет и stylesheet уже подключены по инструкции
[Быстрый старт](/docs/quick-start).

## Выберите способ стилизации

| Способ | React | Solid | Vue | Когда подходит |
| --- | --- | --- | --- | --- |
| CSS Modules | `@moduix/react` | `@moduix/solid` | `@moduix/vue` | Готовые стили компонентов с переопределениями через токены и локальные классы |
| Tailwind CSS | `@moduix/react-tailwind` | `@moduix/solid-tailwind` | `@moduix/vue-tailwind` | Компоненты на utility-классах в приложении с Tailwind v4 |

CSS Modules и Tailwind являются равноправными вариантами поставки, а не слоями одного компонента.
Пакет должен соответствовать и фреймворку, и способу стилизации.

## Выберите уровень изменения

Вносите изменение на самом верхнем уровне, которому оно принадлежит. Чем ниже по списку, тем меньше
компонентов затронуто и тем больше кода нужно.

| Задача | Где менять |
| --- | --- |
| Задать общее визуальное направление | Готовый [пресет темы](/docs/themes) |
| Изменить цвет бренда, радиус, интервалы или размер элементов везде | [Семантический токен](/docs/tokens) |
| Перестилизовать один вариант, например все outline-кнопки | [Переменные компонента на селекторе варианта](#один-вариант-во-всём-приложении) |
| Перестилизовать компоненты в одной области | [Переменные компонента на контейнере](#одна-область) |
| Перестилизовать один экземпляр | [Класс или встроенные переменные](#один-экземпляр) |
| Добавить свой вид, например фирменную кнопку | [Класс и небольшая обёртка](#свой-вариант) |
| Изменить раскладку или вложенную часть одной композиции | [Классы на экспортированных частях](#стилизуйте-экспортированные-части) |

## Почему ваши стили побеждают

Стили Moduix лежат в каскадных слоях CSS, объявленных в таком порядке:

```css
@layer theme, base, moduix.reset, moduix.tokens, moduix.base, components, moduix.components, utilities;
```

Отсюда два правила:

- Ваш CSS вне слоя всегда побеждает стили компонентов, какой бы ни была специфичность. Хватит
  одного класса, `!important` не нужен.
- Утилиты Tailwind лежат в более позднем слое `utilities`, поэтому тоже побеждают стили компонентов.
  Кроме того, Tailwind-пакеты объединяют ваш `className` или `class` через `tailwind-merge`: утилита,
  которая конфликтует с утилитой по умолчанию, заменяет её, а не спорит с ней.

## Настройте компонент

На странице каждого CSS Modules-компонента в разделе **CSS-свойства** перечислены его публичные
переменные. Они намеренно общие: у Button есть `--moduix-button-bg`, `--moduix-button-height` и
`--moduix-button-padding-x`, а не отдельная переменная на каждый вариант и размер. Значения вариантов
и размеров по умолчанию скрыты, а публичная переменная перебивает их там, где вы её задали. Насколько
широко действует изменение, решает селектор.

### Один экземпляр

Задайте переменные в классе или во встроенном стиле, если значение вычисляется:

```css
.save {
  --moduix-button-bg: var(--moduix-color-success);
  --moduix-button-radius: var(--moduix-radius-full);
}
```

Передайте класс в `className` в React или в `class` в Solid и Vue.

### Один вариант во всём приложении

Используйте стабильный `data-slot` вместе с атрибутом варианта. Подключите этот файл стилей после
`style.css`:

```css
[data-slot='button-root'][data-variant='outline'] {
  --moduix-button-border-color: var(--moduix-color-primary);
  --moduix-button-bg-hover: color-mix(in oklab, var(--moduix-color-primary) 12%, transparent);
}
```

Так же можно настроить размер через `data-size` и состояние через атрибуты Ark, например
`data-disabled` или `data-state`.

### Одна область

CSS-переменные наследуются, поэтому значения на контейнере действуют на все подходящие компоненты
внутри него:

```css
.toolbar {
  --moduix-button-height: var(--moduix-size-sm);
  --moduix-button-padding-x: var(--moduix-spacing-2-5);
}
```

Содержимое в портале, например поповер или меню, отрисовывается вне контейнера. Для него задайте
значения на самой портальной части или на `:root`.

### Свой вариант

Встроенные варианты покрывают типовые роли. Для особого вида возьмите ближайший вариант, добавьте
класс с нужными переменными и оберните кнопку в компонент, чтобы у решения было одно имя в коде:

## Стилизуйте экспортированные части

Назначайте класс той части, которой принадлежит визуальное изменение. Для состояния сочетайте его с
атрибутами Ark, например `data-state` или `data-disabled`. Не завязывайтесь на сгенерированные классы
или порядок DOM.

## Осторожно обращайтесь со скрытыми частями

Если обертка продукта намеренно скрывает внутреннюю часть, используйте ее стабильный `data-slot` как
запасной путь:

```css
.root {
  [data-slot='accordion-item-trigger'] {
    padding-inline: var(--moduix-spacing-4);

    &[data-state='open'] {
      color: var(--moduix-color-primary);
    }
  }
}
```

Если часть доступна, предпочитайте прямой класс. Назначайте классы и локальные переменные портальным
частям напрямую или задавайте их на portal-контейнере.

## Стилизуйте с помощью Panda CSS

Panda CSS может генерировать классы потребителя для каждого поддерживаемого фреймворка. Имена токенов в таком коде
принадлежат теме Panda, а не Moduix. Передавайте готовую строку через `className` в React или `class` в
Solid.

```ts
import { css } from '../styled-system/css';

const trigger = css({
  display: 'grid',
  gridTemplateColumns: 'minmax(0, 1fr) auto',
  px: '4',
  py: '4',
  _hover: { bg: 'blue.100' },
  '&[data-state=open]': { color: 'blue.700' },
});
```

## Стилизуйте с помощью Tailwind CSS

Tailwind-пакеты уже содержат стандартные utility-стили компонента. Добавляйте классы потребителя к
конкретной части, которую нужно изменить:

Чтобы переиспользовать вид в Tailwind-пакете, вынесите утилиты в свою обёртку, как в разделе
[Свой вариант](#свой-вариант). Благодаря `tailwind-merge` утилита вроде `bg-violet-600` заменяет фон
по умолчанию, а не спорит с ним.

Сохраняйте `@source` для выбранного пакета, чтобы Tailwind сгенерировал его классы. Полная настройка
stylesheet описана в [Быстром старте](/docs/quick-start).

## Проверьте каскад

| Симптом | Что проверить |
| --- | --- |
| Переменная не действует | Есть ли она в разделе CSS-свойства страницы компонента и задана ли на самом компоненте или его предке. |
| Класс проигрывает стилям компонента | Не обёрнут ли ваш файл стилей в более ранний `@layer`: CSS вне слоя побеждает всегда. |
| Popup игнорирует значение контейнера | Задайте значение портальной части, корню или portal-контейнеру. |
| Селектор состояния не срабатывает | Проверьте точный атрибут Ark на нужной части. |
| Класс действует на корень, но не на вложенную часть | Назначьте его экспортированной части, которой принадлежит свойство. |
| Tailwind-классы отсутствуют | Проверьте stylesheet пакета, путь `@source` и порядок классов потребителя. |

Перед повышением специфичности изучите часть, ее `data-slot`, атрибуты состояния и вычисленные стили.
