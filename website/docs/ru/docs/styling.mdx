# Стилизация компонентов

moduix поставляет готовые стили компонентов и общую CSS-основу, но не требует конкретного инструмента. Используйте
привычный для приложения подход: CSS Modules, Panda CSS, Tailwind CSS, обычный CSS или другое решение. API компонентов
во всех случаях остаётся одинаковым.

Подключите базовую таблицу стилей один раз в точке входа приложения:

```tsx
import '@moduix/react/style.css';
```

moduix не устанавливает Panda CSS или Tailwind CSS за вас. В примерах ниже одна и та же композиция `ProjectChecklist`
оформлена с помощью каждого инструмента, поэтому меняется только синтаксис стилей. Предполагается, что нужный
инструмент уже настроен в приложении.

## Выберите уровень переопределения

| Цель | Рекомендуемый уровень |
| --- | --- |
| Применить целостное визуальное оформление | Готовый [пресет темы](/docs/themes) |
| Изменить цвет, размер, радиус или отступ во всей системе | Примитивный или семантический токен из раздела [Токены](/docs/tokens) |
| Согласовать семейство элементов управления или строки в меню и других всплывающих компонентах | Общий токен семейства, например `--moduix-popup-item-min-height` |
| Намеренно изменить один компонент | Документированный алиас `--moduix-<component>-*` |
| Оформить одну композицию интерфейса | `className` на каждой части, которую нужно стилизовать, предпочтительно с локальным CSS |

Выбирайте самый высокий уровень, соответствующий области изменения. Используйте токен, если изменение должно затронуть
несколько компонентов, и переходите к отрисованной части, если оно относится только к одной композиции.

## Стилизуйте части

Добавьте `className` к части, которая отвечает за визуальное изменение. Так структура компонента остаётся понятной, а
правило действует только внутри нужной композиции. Для состояний сочетайте этот класс с документированными атрибутами
Ark `data-*` на той же части. Используйте публичную CSS-переменную, если компонент предоставляет нужное значение.

Ниже показан пример Accordion с CSS Modules, где стили применяются непосредственно к его экспортируемым частям.

## CSS Modules

CSS Modules подходят как базовый вариант без дополнительных зависимостей. В этом `ProjectChecklist` каждый класс
назначен непосредственно той части, которую он оформляет.

### Скрытые части

Если композиция скрыта внутри компонента приложения и одна из внутренних частей недоступна через props, обращайтесь к
ней по стабильному `data-slot`. Тогда внутренний триггер можно стилизовать, не завязываясь на порядок элементов в DOM
или имена сгенерированных классов:

```css
.root {
  [data-slot='accordion-item-trigger'] {
    padding-inline: var(--moduix-spacing-4);

    &[data-state='open'] {
      color: var(--moduix-color-primary);
    }
  }
}
```

Это запасной вариант, а не замена `className`. Такие части, как `Dialog.Content` и `Tooltip.Content`, по умолчанию
рендерятся в портале. Поэтому передавайте `className` самой части, а переменные при необходимости задавайте контейнеру
портала.

## Panda CSS

Если в приложении уже настроен Panda CSS, сгенерируйте классы для тех же частей `ProjectChecklist`. Имена токенов в
этом примере принадлежат вашей теме Panda, а не moduix.

```tsx
import { Accordion } from '@moduix/react/accordion';
import { css } from '../styled-system/css';

const root = css({
  maxW: '2xl',
  p: '3',
  borderWidth: '1px',
  borderColor: 'blue.200',
  borderRadius: 'xl',
  bg: 'blue.50',
});
const accordion = css({ display: 'flex', flexDirection: 'column', gap: '3' });
const item = css({
  overflow: 'hidden',
  borderWidth: '1px',
  borderColor: 'blue.200',
  borderRadius: 'lg',
  bg: 'white',
  transition: 'colors',
  '&[data-state=open]': { borderColor: 'blue.500', boxShadow: 'lg' },
});
const trigger = css({
  display: 'grid',
  gridTemplateColumns: 'minmax(0, 1fr) auto',
  gap: '3',
  alignItems: 'center',
  w: 'full',
  px: '4',
  py: '4',
  bg: 'blue.50',
  color: 'gray.950',
  fontWeight: 'semibold',
  textAlign: 'left',
  transition: 'colors',
  _hover: { bg: 'blue.100' },
  _focusVisible: { outlineWidth: '2px', outlineColor: 'blue.500', outlineOffset: '-1px' },
  '&[data-state=open]': { bg: 'blue.100', color: 'blue.700' },
});
const triggerCopy = css({ display: 'flex', gap: '3', alignItems: 'center', minW: '0' });
const step = css({
  display: 'grid',
  flexShrink: '0',
  placeItems: 'center',
  w: '7',
  h: '7',
  borderWidth: '1px',
  borderColor: 'blue.300',
  borderRadius: 'xl',
  bg: 'blue.100',
  color: 'blue.700',
  fontSize: 'xs',
  fontWeight: 'semibold',
});
const title = css({ minW: '0' });
const indicator = css({ flexShrink: '0', color: 'blue.700' });
const content = css({
  borderTopWidth: '1px',
  borderColor: 'blue.200',
  bg: 'blue.50',
  color: 'gray.950',
});
const body = css({ px: '4', py: '4', color: 'gray.700', lineHeight: '6' });

export function ProjectChecklist() {
  return (
    <section className={root}>
      <Accordion className={accordion} collapsible defaultValue={['outcome']}>
        <Accordion.Item className={item} value="outcome">
          <Accordion.ItemTrigger className={trigger}>
            <span className={triggerCopy}>
              <span className={step}>01</span>
              <span className={title}>Define the project outcome</span>
            </span>
            <Accordion.ItemIndicator className={indicator} />
          </Accordion.ItemTrigger>
          <Accordion.ItemContent className={content}>
            <Accordion.ItemBody className={body}>
              <p>
                Write one sentence that makes the next decision obvious to everyone on the project.
              </p>
            </Accordion.ItemBody>
          </Accordion.ItemContent>
        </Accordion.Item>
      </Accordion>
    </section>
  );
}
```

## Tailwind CSS

Если приложение уже использует Tailwind CSS, применяйте утилиты и варианты состояния к тем же частям `ProjectChecklist`.
Для moduix не нужны отдельный плагин или специальная конфигурация Tailwind.

```tsx
import { Accordion } from '@moduix/react/accordion';

export function ProjectChecklist() {
  return (
    <section className="max-w-2xl rounded-xl border border-blue-200 bg-blue-50 p-3">
      <Accordion className="flex flex-col gap-3" collapsible defaultValue={['outcome']}>
        <Accordion.Item
          className="overflow-hidden rounded-lg border border-blue-200 bg-white transition-[border-color,box-shadow] data-[state=open]:border-blue-500 data-[state=open]:shadow-lg"
          value="outcome"
        >
          <Accordion.ItemTrigger className="grid w-full grid-cols-[minmax(0,1fr)_auto] items-center gap-3 bg-blue-50 p-4 text-left font-semibold text-slate-950 transition-colors hover:bg-blue-100 focus-visible:outline-2 focus-visible:outline-blue-500 focus-visible:outline-offset-[-1px] data-[state=open]:bg-blue-100 data-[state=open]:text-blue-700">
            <span className="flex min-w-0 items-center gap-3">
              <span className="grid size-7 shrink-0 place-items-center rounded-xl border border-blue-300 bg-blue-100 text-xs font-semibold text-blue-700">
                01
              </span>
              <span className="min-w-0">Define the project outcome</span>
            </span>
            <Accordion.ItemIndicator className="shrink-0 text-blue-700" />
          </Accordion.ItemTrigger>
          <Accordion.ItemContent className="border-t border-blue-200 bg-blue-50 text-slate-950">
            <Accordion.ItemBody className="p-4 leading-6 text-slate-700">
              <p>
                Write one sentence that makes the next decision obvious to everyone on the project.
              </p>
            </Accordion.ItemBody>
          </Accordion.ItemContent>
        </Accordion.Item>
      </Accordion>
    </section>
  );
}
```

## Если что-то не работает

| Симптом | Наиболее вероятная проверка |
| --- | --- |
| Переменная не влияет на результат | Проверьте, что она описана на странице компонента, а ваше переопределение загружается после `style.css`. |
| Всплывающий компонент игнорирует значение, заданное в контейнере | Возможно, компонент отрисовывается в портале. Задайте переменную на его части, корневом элементе или контейнере портала. |
| Селектор состояния не срабатывает | Проверьте точный атрибут Ark, например `data-state` или `data-disabled`. |
| Класс попадает на корневой элемент, но не на часть | Поместите `className` на экспортируемую часть, которая отвечает за визуальное свойство. |
| Утилитарный класс переопределяется CSS компонента | Сначала попробуйте документированную CSS-переменную или проверьте порядок каскада локального класса. |

Прежде чем повышать специфичность селектора, откройте инструменты разработчика в браузере и проверьте отрисованную
часть, её `data-slot`, атрибуты состояния и вычисленные пользовательские свойства.
