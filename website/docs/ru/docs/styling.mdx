# Стилизация

Moduix выпускает отдельные CSS Modules- и Tailwind-пакеты для каждого текущего фреймворка. Выберите
способ, который уже используется в приложении, и вносите изменения на самом верхнем уровне, которому
принадлежит решение.

Руководство предполагает, что нужный пакет и stylesheet уже подключены по инструкции
[Быстрый старт](/docs/quick-start).

## Выберите способ стилизации

| Способ | React | Solid | Когда подходит |
| --- | --- | --- | --- |
| CSS Modules | `@moduix/react` | `@moduix/solid` | Готовые стили компонентов с переопределениями через токены и локальные классы |
| Tailwind CSS | `@moduix/react-tailwind` | `@moduix/solid-tailwind` | Компоненты на utility-классах в приложении с Tailwind v4 |

CSS Modules и Tailwind являются равноправными вариантами поставки, а не слоями одного компонента.
Пакет должен соответствовать и фреймворку, и способу стилизации.

## Выберите уровень изменения

| Задача | Предпочтительный уровень |
| --- | --- |
| Задать общее визуальное направление | Готовый [пресет темы](/docs/themes) |
| Изменить цвет, размер, радиус или интервал во всей системе | Семантический токен из раздела [Токены](/docs/tokens) |
| Согласовать семейство компонентов | Общий токен семейства |
| Изменить один CSS Modules-компонент | Документированная переменная компонента |
| Стилизовать композицию продукта | Классы потребителя на нужных частях |

Системные решения начинайте с токенов. Переходите к отрисованной части, только если изменение
относится к одной композиции.

## Стилизуйте экспортированные части

Назначайте класс той части, которой принадлежит визуальное изменение. Для состояния сочетайте его с
атрибутами Ark, например `data-state` или `data-disabled`. Не завязывайтесь на сгенерированные классы
или порядок DOM.

Предпросмотр работает на React, потому что сайт документации использует React. Solid-версия ниже
использует тот же stylesheet и нативные свойства `class`.

## Осторожно обращайтесь со скрытыми частями

Если обертка продукта намеренно скрывает внутреннюю часть, используйте ее стабильный `data-slot` как
запасной путь:

```css
.root {
  [data-slot='accordion-item-trigger'] {
    padding-inline: var(--moduix-spacing-4);

    &[data-state='open'] {
      color: var(--moduix-color-primary);
    }
  }
}
```

Если часть доступна, предпочитайте прямой класс. Назначайте классы и локальные переменные портальным
частям напрямую или задавайте их на portal-контейнере.

## Стилизуйте с помощью Panda CSS

Panda CSS может генерировать классы потребителя для каждого поддерживаемого фреймворка. Имена токенов в таком коде
принадлежат теме Panda, а не Moduix. Передавайте готовую строку через `className` в React или `class` в
Solid.

```ts
import { css } from '../styled-system/css';

const trigger = css({
  display: 'grid',
  gridTemplateColumns: 'minmax(0, 1fr) auto',
  px: '4',
  py: '4',
  _hover: { bg: 'blue.100' },
  '&[data-state=open]': { color: 'blue.700' },
});
```

## Стилизуйте с помощью Tailwind CSS

Tailwind-пакеты уже содержат стандартные utility-стили компонента. Добавляйте классы потребителя к
конкретной части, которую нужно изменить:

<Tabs groupId="framework">
  <Tab label="React" value="react">

```tsx
import { Accordion } from '@moduix/react-tailwind/accordion';

<Accordion collapsible>
  <AccordionItem value="shipping" className="rounded-lg border data-[state=open]:border-blue-500">
    <AccordionItemTrigger className="px-4">Shipping</AccordionItemTrigger>
    <AccordionItemContent className="px-4">Usually 2 to 4 days.</AccordionItemContent>
  </AccordionItem>
</Accordion>;
```

  </Tab>
  <Tab label="Solid" value="solid">

```tsx
import { Accordion } from '@moduix/solid-tailwind/accordion';

<Accordion collapsible>
  <AccordionItem value="shipping" class="rounded-lg border data-[state=open]:border-blue-500">
    <AccordionItemTrigger class="px-4">Shipping</AccordionItemTrigger>
    <AccordionItemContent class="px-4">Usually 2 to 4 days.</AccordionItemContent>
  </AccordionItem>
</Accordion>;
```

  </Tab>
</Tabs>

Сохраняйте `@source` для выбранного пакета, чтобы Tailwind сгенерировал его классы. Полная настройка
stylesheet описана в [Быстром старте](/docs/quick-start).

## Проверьте каскад

| Симптом | Что проверить |
| --- | --- |
| Переменная не действует | Есть ли она в документации компонента и загружается ли переопределение после `style.css`. |
| Popup игнорирует значение контейнера | Задайте значение портальной части, корню или portal-контейнеру. |
| Селектор состояния не срабатывает | Проверьте точный атрибут Ark на нужной части. |
| Класс действует на корень, но не на вложенную часть | Назначьте его экспортированной части, которой принадлежит свойство. |
| Tailwind-классы отсутствуют | Проверьте stylesheet пакета, путь `@source` и порядок классов потребителя. |

Перед повышением специфичности изучите часть, ее `data-slot`, атрибуты состояния и вычисленные стили.
