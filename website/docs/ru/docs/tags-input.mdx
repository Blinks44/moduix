## Как выбрать компонент

Используйте `TagsInput`, когда пользователю нужно вводить и редактировать список строковых
значений в одном элементе управления формой.

- Выбирайте **`TagsInput`** для меток, навыков, фильтров, получателей, тем и других списков строк, которые пользователь вводит сам.
- Выбирайте **`Tag`**, когда интерфейс только показывает уже существующий токен и, возможно, предлагает отдельное действие удаления.
- Выбирайте **`Combobox`**, когда пользователь должен выбирать значения из известного списка, а основное взаимодействие связано с фильтрацией.

## Базовый пример

Начните с корневого компонента, подписи, `Control`, `Items`, поля ввода и кнопки очистки.

## Анатомия

```text
TagsInput / TagsInput.Root
├─ TagsInput.Label
├─ TagsInput.Control
│  ├─ TagsInput.Items
│  └─ TagsInput.Item[index, value]
│     ├─ TagsInput.ItemPreview
│     │  ├─ TagsInput.ItemText
│     │  └─ TagsInput.ItemDeleteTrigger
│     └─ TagsInput.ItemInput
│  ├─ TagsInput.Input
│  └─ TagsInput.ClearTrigger
└─ скрытое нативное поле формы (добавляется автоматически)
```

| Часть                                  | Назначение                                                               |
| -------------------------------------- | ------------------------------------------------------------------------ |
| `TagsInput` / `TagsInput.Root`         | Управляет состоянием, значениями тегов, вводом, проверкой и формой.      |
| `TagsInput.RootProvider`               | Подключает разметку к состоянию, которое вернул Ark `useTagsInput`.       |
| `TagsInput.Label`                      | Доступная подпись поля тегов.                                            |
| `TagsInput.Control`                    | Видимая область с тегами, полем ввода и кнопкой очистки.                 |
| `TagsInput.Items`                      | Стандартно отображает редактируемые теги из текущего состояния.          |
| `TagsInput.Item`                       | Один тег. Передайте ему `index` и `value`.                               |
| `TagsInput.ItemContext`                | Доступ к состоянию текущего тега через render prop.                      |
| `TagsInput.ItemPreview`                | Отображение тега вне режима редактирования.                              |
| `TagsInput.ItemText`                   | Видимый текст тега.                                                       |
| `TagsInput.ItemDeleteTrigger`          | Удаляет один тег; moduix по умолчанию добавляет компактный значок закрытия. |
| `TagsInput.ItemInput`                  | Поле, которое используется для редактирования тега на месте.            |
| `TagsInput.Input`                      | Поле ввода новых тегов.                                                   |
| `TagsInput.ClearTrigger`               | Удаляет все теги; по умолчанию moduix использует общий `CloseButton.Root`. |
| `TagsInput.Context`                    | Render prop с состоянием корневого компонента внутри его дерева.         |
| `useTagsInputContext`                  | Даёт дочернему компоненту доступ к состоянию и методам корня.             |
| `useTagsInputItemContext`              | Даёт доступ к состоянию текущего тега внутри `TagsInput.Item`.            |
| `moduix useTagsInput` + `RootProvider` | Внешнее управление состоянием и императивными методами.                  |

## Композиция

### Рекомендуемая композиция

Используйте короткую форму `<TagsInput>`, которая эквивалентна `<TagsInput.Root>`. Поместите
`TagsInput.Items`, `TagsInput.Input` и `TagsInput.ClearTrigger` внутрь `TagsInput.Control`.
Так вы получите стандартное поведение редактируемых тегов, а скрытое нативное поле формы останется
на месте.

Чтобы участвовать в отправке формы, передайте корню свойство `name`. Используйте `form`, если
связанная форма находится за пределами DOM-дерева компонента.

### Когда нужна собственная композиция

Используйте `TagsInput.Context` и части для отдельных тегов, если им нужны собственное содержимое
или дополнительные действия. Пройдитесь по `tagsInput.value`, для каждого значения создайте
`TagsInput.Item` с `index` и `value`, а внутри него оставьте `ItemInput`, если редактирование на
месте должно продолжать работать. Если содержимое зависит от состояния тега, используйте
`ItemContext` или `useTagsInputItemContext`.

Сочетайте `TagsInput.RootProvider` с moduix `useTagsInput`, когда состояние или императивные методы,
например `addValue`, `setValue`, `clearValue`, `setInputValue` и `focus`, должны быть доступны за
пределами дерева отрисованного поля. Свойство `ids` пригодится при совместной работе с другим
примитивом Ark, например `Combobox`, когда компоненты используют один и тот же идентификатор
поля или элемента управления.

Каждая примитивная часть поддерживает `asChild` с одним семантическим дочерним элементом, который
пробрасывает свойства и `ref`. Если `asChild` используется у корня, дочерний элемент также должен
отрисовывать свои `children`, чтобы moduix мог добавить скрытое поле формы. `TagsInput.Items` это
готовый компонент для отображения тегов без собственных свойств частей; для своей разметки тегов
используйте отдельные части.

### Свойства по умолчанию

| Свойство            | По умолчанию             | Примечание                                                                |
| ------------------- | ------------------------ | ------------------------------------------------------------------------- |
| `defaultValue`      | `[]`                     | Начальный массив тегов в неконтролируемом режиме.                         |
| `value`             | -                        | Управляемый массив тегов. Обновляйте его из `onValueChange(details).value`. |
| `defaultInputValue` | `''`                     | Начальное значение поля ввода в неконтролируемом режиме.                  |
| `inputValue`        | -                        | Управляемое значение поля ввода.                                          |
| `delimiter`         | `','`                    | Строка или регулярное выражение для клавиши-разделителя и разделения вставленного текста. |
| `max`               | `Infinity`               | Максимальное количество тегов.                                            |
| `maxLength`         | -                        | Максимальное число символов, принимаемых полем ввода.                     |
| `allowOverflow`     | `false`                  | Разрешает превысить `max`, но помечает корень как невалидный.              |
| `allowDuplicates`   | `false`                  | Разрешает добавлять одну и ту же строку несколько раз.                    |
| `editable`          | `true`                   | Разрешает перейти к редактированию тега после фокуса, Enter или двойного щелчка. |
| `addOnPaste`        | `false`                  | Разделяет вставленный текст на теги с помощью `delimiter`.                |
| `blurBehavior`      | -                        | Задайте `"add"`, чтобы добавить значение при потере фокуса, или `"clear"`, чтобы его отбросить. |
| `sanitizeValue`     | `(value) => value.trim()` | Нормализует значение перед проверкой и добавлением.                       |

Свойства `disabled`, `invalid`, `readOnly`, `required` и `autoFocus` не включены, пока вы не
зададите их явно. Для подсказки в поле ввода используйте `placeholder`, а для доступных названий
действий задайте `translations`.

### Особенности поведения

`onValueChange(details)`, `onInputValueChange(details)`, `onHighlightChange(details)` и
`onValueInvalid(details)` получают объекты `details` от Ark. Функция `validate(details)` принимает
или отклоняет новый тег, а `sanitizeValue(value)` нормализует его перед проверкой и
добавлением. Обработчики `onFocusOutside`, `onInteractOutside` и `onPointerDownOutside` получают
соответствующие события взаимодействия за пределами компонента.

Через контекст Ark компоненты `Field.Root` и `Fieldset.Root` могут передавать состояния `disabled`,
`invalid`, `required` и `readOnly`. Стандартная кнопка очистки использует `CloseButton.Root` через
Ark `asChild`, а для удаления отдельного тега остаётся компактная кнопка со значком.

### Хуки стилизации

- Корневой компонент и `RootProvider` предоставляют `data-slot="tags-input-root"` и `data-slot="tags-input-root-provider"`.
- Части Ark сохраняют `data-scope="tags-input"` и значения `data-part` из анатомии.
- Для стилизации состояний используйте `data-disabled`, `data-readonly`, `data-invalid`, `data-focus`, `data-empty`, `data-required`, `data-value` и `data-highlighted` на тех частях, где их добавляет Ark.
- Кнопки удаления и очистки имеют стабильные `data-slot`. Для отдельного тега используется компактный значок закрытия, а очистка всех тегов использует оформление общего `CloseButton.Root`.
- `TagsInput.ClearTrigger` остаётся у края элемента управления, даже когда строки тегов переносятся.
- В режиме только для чтения moduix скрывает поле ввода и кнопку очистки, оставляя видимыми только неизменяемые значения тегов.

## Доступность

Ark связывает подпись с полем, управляет выделением и редактированием тегов, удалением, вставкой и
скрытым полем формы. Скрытое поле корня сериализует список тегов для нативной отправки формы;
передайте `name`, а при необходимости и `form`, чтобы связать его с нужной формой.

### Поддержка клавиатуры

- `Enter` в поле ввода добавляет его текущее значение. `Enter` на выделенном теге переводит его в режим редактирования.
- Двойной щелчок по тегу также включает редактирование, если `editable` имеет значение `true`.
- Когда поле ввода пусто или курсор стоит в его начале, `ArrowLeft` и `ArrowRight` перемещают визуальный фокус между тегами.
- `Backspace` и `Delete` удаляют выделенный тег. `Backspace` также удаляет последний тег, если поле ввода пусто.
- При включённом `addOnPaste` сочетание `Control+V` добавляет вставленные значения после разделения их по `delimiter`.
