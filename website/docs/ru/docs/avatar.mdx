## Базовый пример


Используйте вместе `Avatar`, `AvatarFallback` и `AvatarImage`. Не убирайте `AvatarFallback` из
дерева, чтобы Ark UI мог переключаться между ним и изображением при изменении состояния загрузки.

В React, Solid и Vue действуют одинаковые плоские имена значений. Импортируйте `Avatar` как корень и
каждую дополнительную часть отдельно, например `AvatarImage` и `AvatarFallback`. Эти же имена
работают и с npm-пакетами, и с исходниками из shadcn-реестра.

## Анатомия

```text
Avatar
├─ AvatarFallback
└─ AvatarImage

AvatarRootProvider
└─ те же части, подключённые к хранилищу useAvatar()

AvatarGroup
└─ Avatar, Avatar, ...
```

| Часть                 | Назначение                                                             |
| --------------------- | ---------------------------------------------------------------------- |
| `Avatar`              | Создаёт корневой элемент и хранит состояние аватара Ark UI.            |
| `AvatarRootProvider`  | Подключает состояние Ark UI, созданное за пределами компонента.        |
| `AvatarFallback`      | Показывает переданное потребителем содержимое до загрузки изображения.  |
| `AvatarImage`         | Показывает изображение после успешной загрузки.                        |
| `AvatarGroup`         | Выстраивает аватары с перекрытием и кольцом цвета фона.                |

## Композиция

Размещайте `AvatarFallback` и `AvatarImage` внутри одного корневого компонента, чтобы Ark мог
переключать их видимость. Если состояние должно принадлежать другой части приложения, создайте его
с помощью `useAvatar()` из пакета нужного фреймворка и напрямую передайте в `AvatarRootProvider`;
не добавляйте для того же хранилища ещё один корневой компонент. В React хранилище передаётся как
объект, а Solid предоставляет реактивную функцию доступа. В Vue напрямую передавайте результат
`useAvatar()` в `AvatarRootProvider`. В React и Solid для пользовательского изображения используйте
`useAvatarContext()` и сохраняйте состояния `hidden` и `visible`, возвращаемые `getImageProps()`.
В Vue `AvatarContext` предоставляет эти данные через слот. Применяйте `asChild` только с одним
семантически подходящим дочерним элементом, если другой элемент должен владеть корневым DOM-узлом.

В Solid назначайте ref элементу, который создаётся внутри функции рендеринга `asChild`: ref на самом
`Avatar` через эту композицию не передаётся. В Vue ref указывает на экземпляр компонента; используйте
`$el`, чтобы получить отрендеренный элемент.

## Примеры

### Пользовательское резервное содержимое

Резервным содержимым может быть иконка или другое компактное обозначение пользователя. Задайте
доступное имя, если по этому содержимому нужно понять что-то, чего нет в окружающем тексте.

<Example name="avatar/custom-fallback" />

### Пользовательское изображение

Используйте `useAvatarContext()` из пакета moduix для React или Solid, если компонент изображения
или пользовательский рендерер должен подключиться к жизненному циклу загрузки Ark. В Vue состояние
изображения доступно через слот `AvatarContext`.

<Example name="avatar/custom-image" />

### События

Используйте `onStatusChange(details)`, если интерфейсу вокруг аватара нужно реагировать на жизненный
цикл изображения.

<Example name="avatar/events" />

### Root Provider

Создайте состояние с помощью `useAvatar` из соответствующего пакета, если внешним элементам управления
нужно работать с аватаром. Передайте его в `AvatarRootProvider` вместо `Avatar`.

<Example name="avatar/root-provider" />

### Размеры и аватар без изображения

Свойство `size` в moduix задаёт один из распространённых размеров дизайн-токенов для любого корневого
компонента. Аватар только с резервным содержимым подходит, если источника изображения нет.

<Example name="avatar/sizes-and-fallback-only" />

### Группа

Оберните аватары в `AvatarGroup`, чтобы выстроить их с перекрытием. Каждый аватар после первого
заходит под соседа, а корень каждого аватара получает кольцо цвета фона страницы. Аватар `+N` для
сокращённого списка добавьте сами.

<Example name="avatar/group" />

### Индикатор статуса

Корень аватара не обрезает дочерние элементы, поэтому абсолютно позиционированный элемент внутри
`Avatar` может показывать статус или бейдж. Дайте ему доступное имя, если статус не указан в тексте
рядом.

<Example name="avatar/status" />

### Расширенная настройка

Используйте `asChild`, если сам аватар должен быть интерактивным элементом, например ссылкой. Это
заменяет стандартный корневой DOM-узел, сохраняя состояние Ark, поведение резервного содержимого и
явную композицию частей.

<Example name="avatar/custom-composition" />

## Стилизация

Для структурных стилей используйте `className` в React или `class` в Solid и Vue на экспортируемых частях.
Варианты Tailwind используют обычные утилитарные классы и классы потребителя; приведённый ниже список
CSS-переменных относится к вариантам с CSS Modules. Если стиль зависит от состояния изображения,
используйте атрибуты данных Ark вместе с селекторами `data-slot` moduix.

### Хуки стилизации

- `data-slot="avatar-root"`, `avatar-root-provider`, `avatar-image`, `avatar-fallback` и
  `avatar-group`.
- Атрибуты анатомии Ark: `data-scope="avatar"` и
  `data-part="root" | "image" | "fallback"`.
- Состояние изображения Ark: `data-state="visible" | "hidden"` на `AvatarImage` и
  `AvatarFallback`.
- Состояние размера moduix: `data-size="xs" | "sm" | "md" | "lg" | "xl"` на
  `Avatar` и `AvatarRootProvider`, по умолчанию `md`.
