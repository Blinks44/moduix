# TanStack Form

[Документация TanStack Form](https://tanstack.com/form/latest/docs/framework/react/overview) описывает
полный React API и модель валидации. Здесь показано, как подключить компоненты moduix к форме
TanStack Form.

Поля TanStack Form работают с управляемыми значениями. Передавайте `field.state.value` в компонент,
а значение, полученное в обработчике изменений, передавайте в `field.handleChange`. `Select`, `Checkbox`,
`DateInput` и `SignaturePad` сами добавляют нативный элемент формы, который нужен для отправки данных.
Не добавляйте к ним второе скрытое поле. `Combobox` устроен иначе: он не добавляет дополнительное
скрытое поле. Его видимое поле может попасть в `FormData`, но если отправлять нужно значение
выбранного элемента, сериализуйте `field.state.value` самостоятельно.

```bash
npm install @tanstack/react-form
```

## Сопоставление

| Компонент | Подключение к TanStack Form |
| --------- | -------------------------- |
| `Input`, `Textarea`, `Field.Select` | Передавайте скалярное `field.state.value` и вызывайте `field.handleChange` из `onChange`. |
| `Select` | Преобразуйте скалярное значение поля в строковый массив `value` Ark и обратно. |
| `Combobox` | Используйте такое же преобразование значения, а фильтрацию выполняйте в `onInputValueChange`. |
| `Checkbox` | Передавайте в поле значение `details.checked === true`. |
| `DateInput`, `SignaturePad` | Передавайте корневому компоненту параметры формы, например `name` или `form`; компонент сам добавит нужное поле. |

То же правило действует для `AngleSlider`, `ColorPicker`, `FileUpload`, `PinInput`, `RadioGroup`,
`RatingGroup`, `SegmentGroup`, `Slider`, `Switch` и `TagsInput`. Передавайте параметры формы, например
`name`, `form`, `required` и `disabled`, в их семантический корневой компонент.

Определяйте каждое поле в `defaultValues`. Вызывайте `field.handleBlur` там, где пользователь
действительно заканчивает взаимодействие с полем, чтобы корректно обновлялись состояние `touched` и
валидация по blur.

Подписывайтесь на `state.canSubmit` и `state.isSubmitting`, чтобы управлять кнопкой отправки, как в
полном примере. Используйте состояние формы как источник истины, не позволяйте отправить невалидную
форму и отключайте повторные отправки, пока не завершится асинхронный обработчик `onSubmit`.

## Валидация и сброс

Используйте валидатор поля для локальных правил, а валидатор формы на основе Standard Schema - для
общих правил и правил, зависящих от нескольких полей. Подключение компонентов при этом не меняется.
В полном примере валидация выполняется при отправке. Если вы проверяете поле при потере фокуса или во
время ввода, показывайте `Field.ErrorText` и задавайте проп `invalid` у `Field` только после
взаимодействия пользователя с полем, чтобы пустые обязательные поля не подсвечивались сразу.

Используйте `noValidate` только тогда, когда TanStack Form сам показывает ошибки. В остальных случаях
оставьте включённой нативную проверку ограничений. Для управляемых полей вызывайте `form.reset()`,
чтобы состояние библиотеки и компоненты moduix сбрасывались вместе. Одного сброса DOM недостаточно,
чтобы изменить значение, которое хранится в форме.

## Полная форма

В этом примере вместе используются `Input`, `Select`, `Combobox`, `Textarea` и `Checkbox`. Он
проверяет данные при отправке, переводит фокус на первый невалидный элемент и подписывается только на
то, разрешена ли отправка и выполняется ли она. `noValidate` оставляет обработку ошибок внутри
TanStack Form. Уберите этот атрибут, если сначала должна сработать нативная валидация браузера.

## Повторяющиеся поля

Используйте поле в режиме массива для операций добавления и удаления, а для каждого элемента создавайте
вложенное поле. У каждого элемента, в том числе добавленного на клиенте, должен быть стабильный `id`.
Используйте его как ключ React, а индекс включайте в имя вложенного поля. Если у списка есть общая
подпись, оберните его в `Fieldset`. Вставьте этот фрагмент в компонент, где создана `form`.

```tsx
const newEmail = () => ({ id: crypto.randomUUID(), address: '' });

<form.Field name="emails" mode="array">
  {(arrayField) => (
    <>
      {arrayField.state.value.map((item, index) => (
        <form.Field key={item.id} name={`emails[${index}].address`}>
          {(field) => (
            <Field invalid={!field.state.meta.isValid}>
              <Field.Label>Email {index + 1}</Field.Label>
              <Input
                name={field.name}
                type="email"
                value={field.state.value}
                onBlur={field.handleBlur}
                onChange={(event) => field.handleChange(event.currentTarget.value)}
              />
              <Field.ErrorText>{field.state.meta.errors.join(', ')}</Field.ErrorText>
              <Button type="button" onClick={() => arrayField.removeValue(index)}>
                Remove email
              </Button>
            </Field>
          )}
        </form.Field>
      ))}

      <Button type="button" onClick={() => arrayField.pushValue(newEmail())}>
        Add email
      </Button>
    </>
  )}
</form.Field>;
```

При редактировании сохранённых элементов используйте ID, уже возвращённый вашим API; `newEmail()`
нужен только для создания новых строк на клиенте.

## Ошибки сервера

Чтобы показать ошибки, которые вернул сервер, добавьте в форму асинхронный валидатор отправки.
Верните `fields` с точными именами полей с ошибками и необязательное сообщение `form` для ошибок,
которые не относятся к одному полю. После этого обычный вывод `field.state.meta.errors` покажет
ошибки полей без отдельного хранилища.

```tsx
type ProjectFormValues = {
  name: string;
  emails: { address: string; id: string }[];
};

const form = useForm<ProjectFormValues>({
  defaultValues: { name: '', emails: [] },
  validators: {
    onSubmitAsync: async ({ value }) => {
      const result = await validateProjectOnServer(value);

      if (!result.ok) {
        return {
          form: result.message,
          // For example: { name: 'Already in use.', 'emails[0].address': 'Cannot be used.' }
          fields: result.fieldErrors,
        };
      }

      return null;
    },
  },
  onSubmit: ({ value }) => saveProject(value),
});

<form.Subscribe selector={(state) => [state.errorMap.onSubmit] as const}>
  {([error]) => (error ? <p role="alert">{error}</p> : null)}
</form.Subscribe>;
```

## Управление фокусом

TanStack Form не управляет фокусом в DOM и не выбирает его цель. Используйте `onSubmitInvalid`, чтобы
перевести фокус на первый отрисованный элемент, которому конфигурация `Field` добавляет атрибут
`aria-invalid="true"`:

```tsx
function focusFirstInvalid(formId: string) {
  requestAnimationFrame(() => {
    const formElement = document.getElementById(formId);
    const control = formElement?.querySelector<HTMLElement>(
      '[aria-invalid="true"]:not([hidden])',
    );
    control?.focus();
  });
}

const form = useForm({
  defaultValues: { email: '' },
  onSubmit: ({ value }) => console.log(value),
  onSubmitInvalid: () => focusFirstInvalid('project-form'),
});

<form
  id="project-form"
  onSubmit={(event) => {
    event.preventDefault();
    void form.handleSubmit();
  }}
>
  {/* fields */}
</form>;
```

Переводите фокус на сам элемент управления: нативный `Input`, `Select.Trigger` или `Combobox.Input`.

## Особенности поведения

- В обработчике отправки нативной формы сначала вызовите `preventDefault()`, затем
  `form.handleSubmit()`. Полная форма выше явно показывает эту границу.
- Для одиночного выбора передавайте `field.state.value ? [field.state.value] : []`, а значение
  получайте через `details.value[0] ?? ""`.
- Вызывайте `field.handleBlur` из `Select.onInteractOutside` или `Combobox.Input.onBlur`, чтобы TanStack
  Form мог обновлять состояние `touched`.
- `Select` автоматически добавляет скрытый нативный `select` для нативной семантики и синхронизации
  сброса.
- `Checkbox` сопоставляет состояние флажка с булевым значением поля, а его корневой элемент сам
  добавляет нативное поле ввода.
- `name={field.name}` включает нативную семантику `FormData`, но не заменяет управляемые
  сопоставления `state.value` и `handleChange` поля.
- `Combobox` не добавляет скрытое поле. Его видимое поле может попасть в `FormData`; если отправлять
  нужно значение выбранного элемента, добавьте отдельное поле или отправляйте управляемое состояние
  формы.
- Для компонентов с дополнительными параметрами формы задавайте конфигурацию на корневом элементе:
  `DateInput` использует кортеж `names` из двух элементов для разных
  индексированных ключей диапазона, `Select` использует `nativeFormControl="input"` для
  виртуализированных коллекций, а `SignaturePad` использует `getFormValue` для пользовательской
  сериализации.
- Не передавайте объект `field` в `Select` или `Combobox` через spread-оператор. Их значения и
  колбэки используют объекты `details` от Ark, поэтому сопоставляйте их явно, как показано выше.
- Используйте `form.Subscribe` для производного состояния формы вместо чтения `form.state` во время
  рендера.
