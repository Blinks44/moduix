# TanStack Form

[TanStack Form](https://tanstack.com/form/latest) предоставляет типизированное состояние форм и
нативные адаптеры для разных фреймворков. Здесь показано, как связать это состояние с компонентами moduix.

## Подключение компонентов

Поля TanStack Form используют управляемые значения. Прочитайте текущее значение, передайте его
компоненту moduix и отправьте следующее значение в `field.handleChange`.

| Компонент           | Подключение                                                           |
| ------------------- | --------------------------------------------------------------------- |
| `Input`, `Textarea` | Передайте скаляр и обновляйте его из нативного события input.         |
| `Select`            | Преобразуйте скаляр в строковый массив Ark и обратно.                 |
| `Combobox`          | Свяжите выбранное значение, а фильтрацию оставьте отдельной.          |
| `Checkbox`          | Преобразуйте `details.checked === true` в boolean поля.               |

Задайте все поля в `defaultValues`. Передавайте `handleBlur` от реальной границы взаимодействия и
оставляйте необходимый `HiddenSelect` или `HiddenInput` в композиции moduix.

## Валидация и сброс

Используйте валидаторы поля для локальных правил, а валидаторы формы для схем и межполевых правил.
Передавайте `!field.state.meta.isValid` в `Field invalid` и выводите ошибки через `FieldErrorText`
после запуска выбранного цикла валидации.

Добавляйте `noValidate`, только если видимыми ошибками управляет TanStack Form. Для управляемых полей
вызывайте `form.reset()`, чтобы состояние формы и компоненты moduix сбрасывались вместе.

## Полная форма

В примере объединены `Input`, `Select`, `Combobox`, `Textarea` и `Checkbox`, проверяется отправка и
фокусируется первый невалидный элемент. Поддерживаемые адаптеры используют одинаковое поведение и стили.

## Повторяющиеся поля и серверные ошибки

Для добавления, удаления и перестановки элементов используйте поле в режиме массива. Дайте каждой
строке стабильный ID для отслеживаемой отрисовки, а индекс оставьте только во вложенном имени поля.

Из асинхронного валидатора формы возвращайте `fields` для серверных ошибок конкретных значений и
необязательное сообщение `form` для общей ошибки. Обычный вывод ошибок поля покажет результаты
клиентской и серверной проверки в одном месте.

## Фокус и поведение

- Через `onSubmitInvalid` фокусируйте первый видимый элемент с `aria-invalid="true"`.
- В React читайте `field.state`, а в Solid `field().state`.
- В React значения подписки передаются напрямую, а в Solid читаются из accessor.
- Для текстовых полей Solid используйте нативное событие input, а объекты деталей Ark преобразуйте явно.
- Вызывайте `form.handleSubmit()` из обработчика нативной формы после `preventDefault()`.
