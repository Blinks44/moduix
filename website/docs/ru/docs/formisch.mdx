# Formisch

[Formisch](https://formisch.dev) представляет собой библиотеку форм с нативными адаптерами и
валидацией по схемам. Здесь показано, как связать ее состояние на базе Valibot с компонентами moduix.

## Подключение компонентов

Задайте псевдоним для Formisch `Field`, чтобы отличать его от moduix `Field`. Компонент Formisch
связывает путь схемы с состоянием, а компонент moduix выводит подпись, ошибку и состояние доступности.

| Компонент           | Подключение                                                          |
| ------------------- | -------------------------------------------------------------------- |
| `Input`, `Textarea` | Передайте `field.props` и текущее значение `field.input`.            |
| `Select`            | Преобразуйте скалярное значение в строковый массив Ark.              |
| `Combobox`          | Отдельно свяжите выбор, фильтрацию и фокус.                           |
| `Checkbox`          | Преобразуйте `details.checked === true` в логическое значение.       |

Передавайте `field.props.name` корневому компоненту moduix. Оставляйте `HiddenSelect` или
`HiddenInput` в композиции, но не добавляйте еще один input для того же значения.

## Валидация и сброс

Передайте схему Valibot непосредственно в `useForm` или `createForm`. Параметр `validate` определяет
первую проверку, а `revalidate` последующие. Полный пример проверяет форму при отправке, а затем
повторно проверяет измененные значения при вводе.

Передайте `field.errors !== null` в `Field invalid` и выведите первую ошибку через
`FieldErrorText`. Для управляемых значений вызывайте `reset(form)`, поскольку сброс DOM не заменяет
состояние Formisch.

## Полная форма

В примере объединены `Input`, `Select`, `Combobox`, `Textarea` и `Checkbox`. Каждый поддерживаемый адаптер использует
одну схему, одинаковое поведение, композицию moduix и стили. Интерактивный пример работает на React.

## Повторяющиеся поля и серверные ошибки

Используйте Formisch `FieldArray` вместе с `insert`, `remove` и стабильными идентификаторами из
`fieldArray.items`. Индекс нужен в пути схемы, а стабильный идентификатор в механизме keyed-рендеринга
фреймворка. Связанную группу оборачивайте в `Fieldset`.

После неудачного запроса вызывайте `setErrors` с `path` для ошибки поля или без пути для общей ошибки
формы. Сохраняйте введенные значения, чтобы пользователь мог исправить их и повторить отправку.

## Фокус и поведение

- Передавайте `field.props.ref`, `onFocus` и `onBlur` элементу, который действительно получает фокус.
- В React используйте `field.onChange` для составных значений, а в Solid `field.onInput`. В Vue обновляйте
  `field.input` из объекта `details` события изменения значения или используйте `v-model` для нативных значений. В Svelte вызывайте `field.onInput` из объекта `details` события изменения значения.
- Оставляйте значение управляемым, чтобы `initialInput`, `setInput` и `reset` обновляли интерфейс.
- Не передавайте объект `details` от Ark нативному обработчику событий из `field.props`.
