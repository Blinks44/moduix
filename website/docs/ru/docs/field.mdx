## Выбор подходящего компонента

Используйте `Field`, когда одному элементу формы нужны видимая метка, поясняющий текст, сообщение об ошибке
или общее состояние `disabled`, `invalid`, `required` и `readOnly`.

- Выбирайте **`Field`** для одного элемента управления, которому нужны метка и поясняющий текст.
- Выбирайте **`Fieldset`**, когда нескольким связанным полям нужна одна общая легенда.
- Используйте отдельный элемент управления, если ARIA-связи на уровне поля и общее состояние не нужны.

## Базовый пример

## Анатомия

`Field` использует те же части, что и Ark UI, и сохраняет их имена в публичном API moduix.

```text
Field
├─ Field.Label
├─ Field.Input | Field.Textarea | Field.Select | custom control
├─ Field.HelperText
├─ Field.ErrorText
└─ Field.RequiredIndicator
```

| Часть                     | Назначение                                                                 |
| ------------------------- | -------------------------------------------------------------------------- |
| `Field` / `Field.Root`    | Корневой контекст. По умолчанию рендерит `<div role="group">`.             |
| `Field.RootProvider`      | Корневой элемент, которому передаётся экземпляр `useField()`, созданный вне отрисовываемого дерева. |
| `Field.Context`           | Доступ к текущему состоянию поля без добавления элемента в DOM.             |
| `Field.Label`             | Метка, связанная с идентификатором текущего элемента управления.            |
| `Field.Input`             | Нативный текстовый элемент низкого уровня с API Ark. В обычном коде используйте `Input`. |
| `Field.Textarea`          | Нативная текстовая область низкого уровня с API Ark. В обычном коде используйте `Textarea`. |
| `Field.Select`            | Нативный select, связанный с ARIA-атрибутами и состоянием поля.             |
| `Field.HelperText`        | Поясняющий текст, добавляемый в `aria-describedby`.                          |
| `Field.ErrorText`         | Текст ошибки, который рендерится только при состоянии `invalid` у `Field`.  |
| `Field.RequiredIndicator` | Визуальный маркер обязательного поля с необязательным `fallback`.            |
| `Field.Item`              | Контекст поля для групповых элементов управления через `value`; ref указывает на отрисованную обёртку строки. |

## Композиция

### Рекомендуемая композиция

Оставляйте в корне одну видимую метку и один основной элемент управления moduix, например `Input`,
`Textarea` или `NativeSelect`. Добавляйте поясняющий текст или текст ошибки, если пользователю нужно описание или результат валидации.

### Когда нужна собственная композиция

Используйте `Field.Item value` вместе с пропом `target` у корневого `Field`, когда поле содержит несколько нативных элементов управления,
а метка должна быть связана только с одним из них. `Field.Input`, `Field.Textarea` и `Field.Select` доступны для
низкоуровневой композиции в стиле Ark, но в прикладном коде лучше использовать отдельные компоненты moduix.

### Свойства по умолчанию

| Элемент                  | По умолчанию | Примечания                                                |
| ------------------------ | ------------ | --------------------------------------------------------- |
| `Field` / `Field.Root`   | -            | Дополнительного поведения нет, применяются значения Ark по умолчанию. |

### Особенности поведения

- `Field.ErrorText` не рендерится в DOM, пока у корня не установлен `invalid`.
- Длинные метки, поясняющие тексты и сообщения об ошибках переносятся внутри поля и не выходят за пределы контейнера.
- Передайте в `Field.RootProvider` значение, возвращённое `useField()` из `@moduix/react`. Не вкладывайте
  `Field.RootProvider` в `Field.Root` для одного и того же экземпляра поля.
- Используйте `Field.Context` или `useFieldContext` из `@moduix/react`, когда пользовательскому элементу управления нужен
  доступ к текущему состоянию поля. Прямой импорт из Ark нужен только для низкоуровневых API, которых нет в экспорте moduix.
- `Field.Item` передаёт ref обёртке строки moduix, которую рендерит вокруг дочерних элементов.
- `Field` не рендерит скрытый input. Составные компоненты, такие как `Checkbox` и `RadioGroup`, сами управляют
  своими нативными элементами формы.

## Стилизация

Настраивайте внешний вид `Field` через `className`, атрибуты Ark `data-scope="field"` / `data-part="..."`,
хуки moduix `data-slot="field-*"` и публичные CSS-переменные `--moduix-field-*`, приведённые ниже.

### Хуки стилизации

Ark добавляет `data-disabled`, `data-invalid`, `data-readonly` и `data-required` к соответствующим частям.
`Field.ErrorText` рендерится только при невалидном текущем контексте поля. Идентификатор поясняющего текста
входит в `aria-describedby` элемента управления, а идентификатор активного сообщения об ошибке передаётся в
`aria-errormessage`. Каждая часть DOM также сохраняет стабильный хук `data-slot="field-*"`.
