## Какой компонент выбрать

Используйте `Field`, когда одному элементу управления формы нужны доступная метка, поясняющий текст,
сообщение об ошибке или общее состояние `disabled`, `invalid`, `required` либо `readOnly`.

- Выбирайте **`Field`** для одного элемента управления с меткой или поясняющим текстом.
- Выбирайте **`Fieldset`**, когда нескольким связанным элементам управления нужен общий заголовок группы.
- Используйте элемент управления отдельно, если связи ARIA на уровне поля и общее состояние не нужны.

## Анатомия

Публичный API `Field` использует плоские имена с префиксом семейства. Для явной композиции Ark
используйте низкоуровневые части `Field*`. В обычных формах лучше выбирать соответствующие компоненты
moduix, например `Input`, `Textarea` или `NativeSelect`.

```text
Field
├─ FieldLabel
├─ FieldInput | FieldTextarea | FieldSelect | custom control
├─ FieldHelperText
├─ FieldErrorText
└─ FieldRequiredIndicator

FieldRootProvider
└─ то же дерево частей, подключённое к состоянию из useField()
```

| Часть                     | Назначение                                                                                       |
| ------------------------ | ------------------------------------------------------------------------------------------------- |
| `Field`                  | Корневой контекст. По умолчанию рендерит `<div role="group">`.                                   |
| `FieldRootProvider`     | Корень, использующий состояние `useField()`, созданное вне дерева компонентов.                  |
| `FieldContext`          | Даёт доступ к текущему состоянию поля, не добавляя элемент в DOM.                                |
| `FieldLabel`            | Доступная метка, связанная с текущим элементом управления.                                       |
| `FieldInput`            | Низкоуровневый нативный input. Для обычного стилизованного поля используйте `Input`.             |
| `FieldTextarea`         | Низкоуровневая нативная текстовая область. Для обычной используйте `Textarea`.                   |
| `FieldSelect`           | Низкоуровневый нативный select. Для обычного используйте `NativeSelect`.                         |
| `FieldHelperText`       | Поясняющий текст, связанный с элементом через `aria-describedby`.                                |
| `FieldErrorText`        | Текст ошибки, который рендерится при состоянии корня `invalid`.                                  |
| `FieldRequiredIndicator` | Визуальный маркер обязательного поля. С помощью `fallback` можно заменить маркер по умолчанию.  |
| `FieldItem`             | Вложенный контекст для группового элемента с `value`; ref указывает на локальную обёртку строки. |

## Композиция

Используйте корень, чтобы объединить один элемент управления с `FieldLabel`, `FieldHelperText`,
`FieldErrorText` и `FieldRequiredIndicator`. Составные компоненты `Checkbox`, `RadioGroup` и `Select`
управляют собственным состоянием, поэтому передавайте `required`, `invalid`, `disabled` или `readOnly`
в их корень, когда состояние принадлежит им. Для нескольких нативных элементов оберните каждый в
`FieldItem value` и задайте корню `target`. Используйте `FieldRootProvider` с `useField()`, если
состояние создаётся вне дерева компонентов; пользовательские элементы могут читать его через
`FieldContext` или `useFieldContext`.

## Стилизация

Используйте `className` в React или `class` в Solid для структурной стилизации экспортируемых частей.
Для стилей состояний применяйте атрибуты Ark, такие как `data-disabled`, `data-invalid`, `data-readonly`
и `data-required`, вместе с селекторами moduix `data-slot`. Варианты на Tailwind используют нативные
утилиты и классы потребителя, а CSS Modules настраиваются с помощью переменных ниже.

### Хуки стилизации

Ark добавляет `data-disabled`, `data-invalid`, `data-readonly` и `data-required` к соответствующим
частям. `FieldErrorText` существует только пока текущий контекст поля находится в состоянии `invalid`.
Идентификатор поясняющего текста входит в `aria-describedby` элемента управления, а активный идентификатор
текста ошибки входит в `aria-errormessage`. У каждой DOM-части также есть стабильный хук
`data-slot="field-*"`.
