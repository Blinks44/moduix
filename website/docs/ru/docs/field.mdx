## Выбор подходящего компонента

Используйте `Field`, когда одному элементу управления формы нужны видимая метка, пояснение, сообщение об ошибке
или общее состояние `disabled`, `invalid`, `required` либо `readOnly`.

- Выбирайте **`Field`** для одного элемента управления с меткой или поясняющим текстом.
- Выбирайте **`Fieldset`**, когда нескольким связанным элементам управления нужен общий заголовок группы.
- Используйте элемент управления отдельно, если связи ARIA на уровне поля и общее состояние не нужны.

## Анатомия

Публичное пространство имён `Field` сохраняет названия частей из Ark UI. Используйте части `Field.*` для
явной композиции Ark. В обычных формах лучше выбирать соответствующие компоненты moduix, например `Input`,
`Textarea` или `NativeSelect`.

```text
Field
├─ Field.Label
├─ Field.Input | Field.Textarea | Field.Select | custom control
├─ Field.HelperText
├─ Field.ErrorText
└─ Field.RequiredIndicator
```

| Часть                     | Назначение                                                                                           |
| ------------------------- | ----------------------------------------------------------------------------------------------------- |
| `Field` / `Field.Root`    | Корневой контекст. По умолчанию рендерит `<div role="group">`.                                        |
| `Field.RootProvider`      | Корень, использующий объект состояния `useField()`, созданный вне дерева компонентов.                |
| `Field.Context`           | Даёт доступ к текущему состоянию поля, не добавляя элемент в DOM.                                     |
| `Field.Label`             | Метка, связанная с текущим элементом управления.                                                      |
| `Field.Input`             | Низкоуровневый нативный input. Для обычного стилизованного поля используйте `Input`.                  |
| `Field.Textarea`          | Низкоуровневая нативная текстовая область. Для обычной текстовой области moduix используйте `Textarea`. |
| `Field.Select`            | Низкоуровневый нативный select. Для обычного стилизованного select используйте `NativeSelect`.        |
| `Field.HelperText`        | Поясняющий текст, связанный с элементом через `aria-describedby`.                                     |
| `Field.ErrorText`         | Текст ошибки, который рендерится, когда корень находится в состоянии `invalid`.                       |
| `Field.RequiredIndicator` | Визуальный маркер обязательного поля. С помощью `fallback` можно заменить маркер по умолчанию.        |
| `Field.Item`              | Вложенный контекст для группового элемента управления с `value`; ref указывает на локальную обёртку строки. |

## Композиция

### Рекомендуемая композиция

Оставьте в корне одну видимую метку, а под ней разместите основной элемент управления moduix, например `Input`,
`Textarea` или `NativeSelect`. Добавьте поясняющий текст или сообщение об ошибке, если пользователю нужны дополнительные
сведения или результат валидации.

Компоненты со своей составной корневой частью, например `Checkbox`, `RadioGroup` или `Select`, тоже можно размещать
внутри `Field`. У таких компонентов собственные свойства состояния, поэтому передавайте `required`, `invalid`,
`disabled` или `readOnly` в корень дочернего компонента, если именно он управляет этим состоянием.

### Когда нужна собственная композиция

Используйте `Field.Item value` вместе с пропом `target` у корня, когда в поле несколько нативных элементов управления,
а корневая метка должна быть связана только с одним из них. `Field.Input`, `Field.Textarea` и `Field.Select` доступны
для низкоуровневой композиции в стиле Ark, но в прикладном коде обычно лучше использовать отдельные компоненты moduix.

Если пользовательский элемент управления не работает с контекстом Ark Field, используйте `Field.Context` или
`useFieldContext` из `@moduix/react`, чтобы получить состояние поля и настроить его идентификаторы и ARIA-атрибуты.

### Свойства по умолчанию

| Свойство   | По умолчанию | Примечания                                                                                          |
| ---------- | ------------ | --------------------------------------------------------------------------------------------------- |
| `disabled` | `false`      | Помечает поле как отключённое и передаёт состояние поддерживаемым частям поля.                      |
| `invalid`  | `false`      | Управляет `Field.ErrorText`; передавайте свойство и составному дочернему компоненту, если он сам управляет валидацией. |
| `readOnly` | `false`      | Помечает поле доступным только для чтения и передаёт состояние поддерживаемым частям.               |
| `required` | `false`      | Помечает поле как обязательное. `Field.RequiredIndicator` по-прежнему нужно добавить явно.            |
| `target`   | -            | Значение `value` у `Field.Item`, на которое должна указывать корневая метка.                            |

### Особенности поведения

- `Field.ErrorText` не появляется в DOM, пока корень не находится в состоянии `invalid`.
- Поле не проверяет значения. Приложение или библиотека форм сами решают, когда нужно установить `invalid` в `true`.
- Длинные подписи, поясняющие тексты и сообщения об ошибках переносятся внутри поля и не выходят за пределы контейнера.
- Передайте в `Field.RootProvider` значение, возвращённое `useField()` из `@moduix/react`. Не используйте `Field.Root`
  и `Field.RootProvider` для одного и того же экземпляра поля.
- Используйте `Field.Context` или `useFieldContext` из `@moduix/react`, когда пользовательскому элементу управления нужно
  текущее состояние поля. Свойства Ark, например `ids`, `target` и `asChild`, доступны у соответствующих частей.
- `Field.Item` передаёт ref обёртке строки moduix, которую рендерит вокруг дочерних элементов.
- Составные компоненты, такие как `Checkbox` и `RadioGroup`, сами управляют своими нативными элементами формы. Сам `Field`
  не рендерит скрытый input.

### Хуки стилизации

Ark добавляет `data-disabled`, `data-invalid`, `data-readonly` и `data-required` к соответствующим частям.
`Field.ErrorText` существует только пока текущий контекст поля находится в невалидном состоянии. Идентификатор
поясняющего текста входит в `aria-describedby` элемента управления, а идентификатор активного сообщения об ошибке
передаётся в `aria-errormessage`. Каждая часть DOM также сохраняет стабильный хук `data-slot="field-*"`.
