## Использование

<Usage />

Используйте `Field` как оболочку для одного элемента управления формы. Разместите `FieldLabel` перед
ним, а затем при необходимости добавьте `FieldHelperText` или `FieldErrorText`.

## Какой компонент выбрать

Используйте `Field`, когда одному элементу управления формы нужны доступная метка, поясняющий текст,
сообщение об ошибке или общее состояние `disabled`, `invalid`, `required` либо `readOnly`.

- Выбирайте **`Field`** для одного элемента управления с меткой или поясняющим текстом.
- Выбирайте **`Fieldset`**, когда нескольким связанным элементам управления нужен общий заголовок группы.
- Используйте элемент управления отдельно, если связи ARIA на уровне поля и общее состояние не нужны.

## Композиция

Используйте корень, чтобы объединить один элемент управления с `FieldLabel`, `FieldHelperText`,
`FieldErrorText` и `FieldRequiredIndicator`. Составные компоненты `Checkbox`, `RadioGroup` и `Select`
управляют собственным состоянием, поэтому передавайте `required`, `invalid`, `disabled` или `readOnly`
в их корень, когда состояние принадлежит им. Для нескольких нативных элементов оберните каждый в
`FieldItem value` и задайте корню `target`. Используйте `FieldRootProvider` с `useField()`, если
состояние создаётся вне дерева компонентов; пользовательские элементы могут читать его через
`FieldContext` или `useFieldContext`.

Во Vue задавайте начальные значения нативных элементов через `v-model` и сбрасывайте связанные refs
в обработчике сброса формы. У Vue-компонентов `Input` и `NativeSelect` нет React-подобного свойства `defaultValue`.
Сейчас Ark очищает нативные начальные значения этих элементов без модели; до исправления используйте `v-model`.

В Svelte управляемые нативные элементы привязывайте через `bind:value`.

## Анатомия

Публичный API `Field` использует плоские имена с префиксом семейства. `Field` не рисует собственный
элемент ввода: поместите внутрь `Input`, `Textarea`, `NativeSelect` или другой элемент формы moduix, и он
прочитает контекст поля.

Наведите на часть или выберите её, чтобы найти её в превью.

## Стилизация

Отключённый `Field` или `FieldRootProvider` приглушает всё поле один раз: элементы ввода внутри него
не приглушаются повторно, как и `Field` внутри отключённого `Fieldset`.

Используйте `className` в React или `class` в Solid, Vue и Svelte для структурной стилизации экспортируемых частей.
Для стилей состояний применяйте атрибуты Ark, такие как `data-disabled`, `data-invalid`, `data-readonly`
и `data-required`, вместе с селекторами moduix `data-slot`. Варианты на Tailwind используют нативные
утилиты и классы потребителя. Варианты на CSS Modules построены на токенах foundation и не имеют
переменных компонента: класс на части перекрывает стили компонента из слоя. Корень занимает всю ширину
контейнера.

### Хуки стилизации

| Часть | `data-slot` |
| --- | --- |
| `Field` | `field-root` |
| `FieldRootProvider` | `field-root-provider` |
| `FieldItem` | `field-item` |
| `FieldLabel` | `field-label` |
| `FieldHelperText` | `field-helper-text` |
| `FieldErrorText` | `field-error-text` |
| `FieldRequiredIndicator` | `field-required-indicator` |

Ark добавляет `data-disabled`, `data-invalid`, `data-readonly` и `data-required` к соответствующим
частям. `FieldErrorText` существует только пока текущий контекст поля находится в состоянии `invalid`. Идентификаторы поясняющего текста и активного сообщения об ошибке входят в `aria-describedby`
элемента управления. У каждой DOM-части также есть стабильный хук
`data-slot="field-*"`.

## Справочник API

| Проп | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `disabled` | `boolean` | `false` | Отключает вложенный элемент управления и приглушает подпись. |
| `readOnly` | `boolean` | `false` | Делает вложенный элемент только для чтения. |
| `invalid` | `boolean` | `false` | Помечает поле невалидным и показывает `FieldErrorText`. |
| `required` | `boolean` | `false` | Делает вложенный элемент обязательным и показывает индикатор. |
| `asChild` | `boolean` | `false` | Отрисовывает корень через единственный дочерний элемент. |
