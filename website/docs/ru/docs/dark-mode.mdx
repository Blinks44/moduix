# Тёмная тема

По умолчанию moduix использует светлые токены, а тёмный набор включается атрибутом
`data-moduix-color-scheme="dark"`. Один раз импортируйте базовую таблицу стилей. Выбор темы остаётся за
приложением, а moduix применяет итоговую схему.

```tsx
import '@moduix/react/style.css';
```

## Корень документа

Для темы всего приложения задавайте итоговую схему на корневом элементе документа. Когда менеджер темы выбирает
тёмный режим, установите `data-moduix-color-scheme="dark"` на `<html>`; для светлого режима используйте `light`.
moduix не требует провайдера, не хранит настройку и не навязывает пакет темы, поэтому не вмешивается в уже
существующие селекторы и токены приложения.

```html
<!-- Dark theme -->
<html data-moduix-color-scheme="dark"></html>
```

Компоненты, отрисовываемые через портал, например Dialog, Popover и Select, тоже наследуют токены с `<html>`.

При серверном рендеринге используйте механизм раннего применения темы, чтобы итоговый атрибут появился до показа
страницы. Так светлая тема не успеет кратко мигнуть до того, как клиентский JavaScript применит сохранённую настройку.

## Переключатель

Храните явный выбор пользователя в приложении и обновляйте атрибут документа. Если выбора ещё нет, определяйте
системную настройку с помощью `matchMedia`.

```tsx
type ColorScheme = 'light' | 'dark';

export function applyColorScheme(scheme: ColorScheme) {
  document.documentElement.dataset.moduixColorScheme = scheme;
}

export function resolveColorScheme(): ColorScheme {
  const saved = localStorage.getItem('color-scheme');
  if (saved === 'light' || saved === 'dark') return saved;

  return matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light';
}

export function saveColorScheme(scheme: ColorScheme) {
  localStorage.setItem('color-scheme', scheme);
  applyColorScheme(scheme);
}
```

Выполните эквивалент `applyColorScheme(resolveColorScheme())` в раннем inline-скрипте темы вашего фреймворка - до
первой отрисовки. Видимый переключатель должен вызывать `saveColorScheme` со следующим значением. Системная
настройка останется значением по умолчанию, пока пользователь не выберет тему сам. Дайте переключателю доступное
имя, описывающее действие, например `Switch to dark mode`.

## Пресет

Цветовая схема и визуальные пресеты - независимые слои, поэтому их можно комбинировать. Задайте
`data-moduix-color-scheme` и `data-moduix-theme` на одном корневом элементе, чтобы обычные и портализированные
компоненты использовали одну палитру, плотность, радиусы и токены фокуса.

```tsx
import '@moduix/react/style.css';
import '@moduix/react/presets/dense.css';
```

<div style={{ height: '1rem' }} aria-hidden="true" />

```html
<html data-moduix-color-scheme="dark" data-moduix-theme="dense"></html>
```

Смена цветовой схемы не влияет на плотность. Выбранный пресет сохраняет масштаб элементов управления и всплывающих
компонентов в обоих режимах. Сравнение пресетов и создание собственной темы описаны в разделе [Темы](/docs/themes).

## Локальная тема

Если тёмные токены нужны только для предпросмотра или встроенной поверхности, установите
`data-moduix-color-scheme="dark"` на обычный контейнер:

```tsx
<section data-moduix-color-scheme="dark">
  <Card>Dark preview</Card>
</section>
```

Так можно оформить предпросмотр настроек или встроенный виджет. Контент, отрисованный через портал, находится за
пределами контейнера. Поэтому, если поддерево открывает оверлеи, задавайте атрибут на `<html>`, `body` или контейнере
портала.

## Настройка токенов

Чтобы настроить обе схемы, переопределяйте одни и те же семантические токены в `:root` и
`[data-moduix-color-scheme='dark']`. Компоненты используют алиасы вроде `--moduix-color-background`,
`--moduix-color-foreground` и `--moduix-color-border`, поэтому значения остаются согласованными во всей библиотеке.

```css
:root {
  --moduix-background: oklch(0.99 0.004 285);
  --moduix-primary: oklch(0.5 0.18 260);
}

[data-moduix-color-scheme='dark'] {
  --moduix-background: oklch(0.16 0.01 285);
  --moduix-primary: oklch(0.76 0.13 260);
}
```

Справочник системных токенов приведён в разделе [Токены](/docs/tokens), а локальные визуальные переопределения - на
страницах компонентов.
