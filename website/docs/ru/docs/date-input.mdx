## Выбор подходящего компонента

- Выберите **`Input`** для обычных текстовых значений.
- Выберите **`DateInput`**, когда пользователям нужно вводить дату с клавиатуры по отдельным сегментам.
- Выберите **`DatePicker`**, когда нужен встроенный или всплывающий календарь. `DateInput` рассчитан
  на ввод с клавиатуры и не содержит календаря.

## Базовый пример

`DateInput` отображает сегменты даты с учётом локали, которые можно редактировать с клавиатуры. Поместите
`DateInputSegments` внутрь `DateInputControl` для стандартной композиции.

## Анатомия

```text
DateInput
├─ DateInputLabel
├─ DateInputControl
│  ├─ DateInputSegments
│  └─ DateInputSeparator (необязательно, для диапазонов)
└─ DateInputHiddenInput[index] (явно, по одному на отправляемую дату)

Расширенная настройка:

DateInputSegmentGroup
└─ DateInputSegmentContext
   └─ DateInputSegment

DateInputRootProvider
└─ то же дерево частей, подключённое к состоянию из useDateInput()
```

| Часть | Назначение |
| ---- | ---- |
| `DateInput` | Отвечает за значения дат, форматирование с учётом локали, фокус сегментов и валидацию. |
| `DateInputHiddenInput` | Нативное поле Ark, которое для отправки формы нужно добавить явно. |
| `DateInputRootProvider` | Подключает части к состоянию из `useDateInput()`. |
| `DateInputLabel` | Подпись поля даты, доступная вспомогательным технологиям. |
| `DateInputControl` | Визуальная рамка вокруг одной или нескольких групп сегментов. |
| `DateInputSegmentGroup` | Объединяет сегменты для одного индекса даты. |
| `DateInputSegment` | Редактируемый или фиксированный сегмент, предоставляемый Ark UI. |
| `DateInputSegments` | Отображает одну группу сегментов с учётом локали для обычного сценария. |
| `DateInputSeparator` | Текстовый разделитель между группами диапазона. |
| `DateInputContext` | Даёт доступ к текущему состоянию поля без собственной разметки. |
| `DateInputSegmentContext` | Помогает отображать сегменты с учётом локали. |

## Композиция

Для обычного поля используйте `DateInput` с `DateInputControl` и `DateInputSegments`. Оставьте состояние
неконтролируемым через `defaultValue`, управляйте им через `value` и `onValueChange(details)` или создайте
его с помощью `useDateInput()` и подключите части через `DateInputRootProvider`. В Vue для управляемого
значения используйте `v-model`. Значения имеют форму
`DateInputDateValue[]` из `@internationalized/date`, а не строк.

`DateInputHiddenInput` нужно добавлять явно: корневой компонент не создаёт нативные поля. Добавьте по одному
скрытому полю на каждую отправляемую дату, а для диапазона используйте соответствующие значения `index`.
Используйте `DateInputSegmentGroup`, `DateInputSegmentContext` и `DateInputSegment` только тогда, когда
стандартного отображения `DateInputSegments` недостаточно.

## Примеры

### Управляемое состояние

Передавайте массив значений через `value` и обновляйте его из `details.value` в `onValueChange`.

<Example name="date-input/controlled" />

### Отключённое состояние и только для чтения

Используйте `disabled`, чтобы запретить взаимодействие, и `readOnly`, чтобы оставить значение доступным для
фокуса, но запретить редактирование.

<Example name="date-input/disabled-and-read-only" />

### Состояние поля

Оберните `DateInput` в `Field`, чтобы добавить к полю вспомогательный текст. Передавайте `required`, `disabled`
или `invalid` непосредственно в `DateInput`, если атрибуты состояния Ark UI должны появляться на самом поле.

<Example name="date-input/field-state" />

### Гранулярность

Укажите `granularity`, чтобы добавить в поле сегменты времени.

<Example name="date-input/granularity" />

### Ведущие нули

Укажите `shouldForceLeadingZeros={false}`, если числовые сегменты не должны дополняться ведущими нулями.

<Example name="date-input/leading-zeros" />

### Локаль

Укажите на корневом компоненте `locale`, `timeZone`, `hourCycle` или `granularity`, если порядок сегментов и
их подписи должны соответствовать региональным правилам.

<Example name="date-input/locale" />

### Минимальная, максимальная и недоступные даты

Используйте `min`, `max` и `isDateUnavailable`, чтобы ограничить даты правилами приложения и отмечать
недопустимые значения.

<Example name="date-input/min-max-and-unavailable-dates" />

### Диапазон

Используйте `selectionMode="range"`, передайте `index` каждой группе сегментов и добавьте соответствующие
индексированные `DateInputHiddenInput`, если значения отправляются вместе с формой.

<Example name="date-input/range" />

### Справа налево

Укажите `dir="rtl"` вместе с RTL-локалью, чтобы сохранить направление и порядок сегментов локали.

<Example name="date-input/right-to-left" />

### Root Provider

Используйте `useDateInput()` из `@moduix/react`, `@moduix/solid` или `@moduix/vue` вместе с `DateInputRootProvider`, когда
методы управления состоянием нужны за пределами дерева корневого компонента.

<Example name="date-input/root-provider" />

### Только время

Используйте форматтер, настроенный только на время, с гранулярностью минут или секунд, если дата не входит в
значение, которое редактирует пользователь.

<Example name="date-input/time-only" />

### Расширенная настройка

Используйте полную композицию сегментов, если отображение должно зависеть от данных сегмента Ark UI.
Для стандартного отображения остаётся `DateInputSegments`.

## Стилизация

В React используйте `className`, а в Solid и Vue `class` на экспортируемых частях для структурных стилей. Варианты
Tailwind используют обычные utility-классы и классы потребителя. Варианты CSS Modules также предоставляют
перечисленные ниже переменные компонентов. Атрибуты данных и хуки `data-slot` общие для обоих вариантов.

Корень подстраивается под содержимое, а контрол заполняет корень. Чтобы растянуть поле в форме, задайте
`--moduix-date-input-width: 100%` в CSS Modules или добавьте корню `w-full` в Tailwind.

### Хуки стилизации

- Стабильные селекторы `data-slot`: `date-input-root`, `date-input-root-provider`, `date-input-label`,
  `date-input-control`, `date-input-segment-group`, `date-input-segment` и `date-input-separator`.
- Селекторы частей Ark UI используют `data-scope="date-input"` и соответствующие значения `data-part`.
- Атрибуты состояния Ark UI включают `data-disabled`, `data-readonly`, `data-invalid` и `data-focus` на
  control и группах сегментов, а также `data-type`, `data-editable` и `data-placeholder-shown` на сегментах.
