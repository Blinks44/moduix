## Справочник API

В Ark UI нет отдельного примитива `bleed`. В moduix компонент `Bleed` построен на официальной
[фабрике Ark](https://ark-ui.com/docs/guides/composition#the-ark-factory) и следует рекомендациям Ark по
[композиции](https://ark-ui.com/docs/guides/composition), [стилизации](https://ark-ui.com/docs/guides/styling) и
[работе с ref](https://ark-ui.com/docs/guides/ref).

Используйте [Container](/docs/container), чтобы сохранить удобную для чтения ширину основного содержимого.
Размещайте внутри него `Bleed`, если за границы контейнера должен выйти только медиаблок, фон, разделитель или баннер.

Импортируйте `Bleed` из пакета, соответствующего фреймворку и способу стилизации. Для CSS Modules используйте
`@moduix/react/bleed`, `@moduix/solid/bleed` или `@moduix/vue/bleed`, а для Tailwind -
`@moduix/react-tailwind/bleed`, `@moduix/solid-tailwind/bleed` или `@moduix/vue-tailwind/bleed`.

## Анатомия

`Bleed` отрисовывает один корневой элемент в соответствии с соглашениями Ark. Он применяет отрицательные внешние
отступы по строчной и/или блочной оси и не добавляет внутреннюю обёртку.

```text
Bleed
└─ root[data-scope="bleed"][data-part="root"][data-slot="bleed-root"]
   └─ children
```

| Часть  | Назначение                                                            |
| ------ | ---------------------------------------------------------------------- |
| `Bleed` | Корневой компонент для выхода содержимого по строчной и блочной оси.  |

## Композиция

`Bleed` отвечает только за визуальное оформление и не владеет состоянием. У него одна корневая часть, поэтому
дополнительные части не нужно согласовывать. По умолчанию `inline` равен
`full`, `block` - `none`, а `asChild` выключен. Если через `asChild` корневым элементом должен стать другой
семантический элемент, передайте в React ровно одного дочернего элемента, который принимает DOM-свойства и ref,
или используйте функцию рендера в Solid. В React ref указывает на отрисованный корневой или дочерний элемент;
функция рендера Solid не передаёт ref от компонента к пользовательскому элементу.
Во Vue `asChild` передаёт корневой элемент одному семантическому потомку через фабрику Ark; DOM-узел компонента
доступен через `$el`.

Сочетайте `inline` и `block`, если поверхность должна выйти за отступы по обеим логическим осям. `inline="full"`
рассчитывается относительно окна браузера, поэтому во вложенной оболочке могут понадобиться локальные переопределения
`--moduix-bleed-inline-full` и `--moduix-bleed-inline-full-size`.

## Стилизация

`Bleed` предоставляет CSS-переменные и стабильные data-атрибуты на корневом элементе. Для структурных стилей
используйте `className` в React и `class` в Solid или Vue. Варианты Tailwind используют обычные utility-классы и классы
приложения, а переменные ниже настраивают варианты с CSS Modules. Data-атрибуты и `data-slot` общие для обоих
способов стилизации. Предки с `overflow: hidden` или `overflow: clip` могут обрезать выход за границы.

### Хуки стилизации

- `data-scope="bleed"` и `data-part="root"` служат хуками стилизации, согласованными с Ark, на экспортируемом корневом элементе.
- `data-slot="bleed-root"` - стабильный селектор moduix на экспортируемом корневом элементе.
- `data-inline` показывает текущий режим выхода по строчной оси: `none`, `xs`, `sm`, `md`, `lg`, `xl` или `full`.
- `data-block` показывает текущий режим выхода по блочной оси: `none`, `xs`, `sm`, `md`, `lg` или `xl`.
- Публичный CSS API `--moduix-bleed-*` включает значения фиксированной шкалы и расчёт ширины до краёв окна
  браузера, который используется при `inline="full"`.
