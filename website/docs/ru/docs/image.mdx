## Справочник API

`Image` - компонент moduix, оборачивающий `<img>` из [Unpic React](https://unpic.pics/img/react/).
В Ark UI нет отдельного примитива для изображений, поэтому `Image` сохраняет нативную композицию `<img>` и
`<picture>`, а не адаптирует часть Ark. Нативную модель элементов описывает [руководство Ark по
композиции](https://ark-ui.com/react/docs/guides/composition).

## Базовый пример

Используйте `Image` с URL поддерживаемого CDN для изображений и укажите размеры для стандартной ограниченной
раскладки. Unpic генерирует адаптивные `srcSet` и `sizes`, а браузер заранее резервирует место для изображения.

## Анатомия

```text
Image / Image.Root
└─ img

picture (native)
├─ Image.Source
└─ Image / Image.Root
```

| Часть                   | Роль                                                                      |
| ----------------------- | ------------------------------------------------------------------------ |
| `Image` / `Image.Root` | Адаптивное нативное изображение; Unpic генерирует `srcSet`, `sizes` и стили. |
| `Image.Source`         | Адаптивный `<source>` для нативного элемента `<picture>`.                  |

## Композиция

### Рекомендуемая композиция

`Image` - сокращённая форма корневого компонента, эквивалентная `Image.Root`. Используйте `width` и `height` со
стандартным `layout="constrained"`, чтобы сохранить соотношение сторон изображения и избежать сдвигов раскладки. Для
удалённых URL поддерживаемых провайдеров Unpic определяет провайдера и автоматически генерирует преобразованные
значения `srcSet`.

Используйте `priority` только для изображений, которые должны загрузиться сразу, например для главного hero-блока в
первом экране. Свойство включает eager-загрузку и высокий приоритет получения, если явно не переданы нативный
`loading` или React-свойство `fetchPriority` в camelCase.

### Когда нужна собственная композиция

Используйте нативный `<picture>` с `Image.Source`, когда нужны адаптивное кадрирование или источники для разных
media queries. Оставляйте `Image` последним дочерним элементом для резервного изображения. Передавайте `fallback`,
`options` или `operations`, если нераспознанный URL должен обрабатываться определённым провайдером Unpic.

Для выбора формата разместите `Image.Source` со значением `type` перед эквивалентным источником без `type`: браузер
использует первый поддерживаемый формат.

### Свойства по умолчанию

| Свойство                | По умолчанию                      | Примечания                                                          |
| ---------------------- | --------------------------- | ----------------------------------------------------------------------- |
| `layout`                | `constrained`                    | Вписывается в переданные размеры и уменьшается при необходимости.   |
| `loading`               | `lazy`                           | Становится `eager`, когда задан `priority`.                         |
| `decoding`              | `async` для изображений без `priority` | Нативное значение сохраняется; с `priority` по умолчанию не задаётся. |
| `fetchPriority`         | `high` с `priority`              | Нативное значение переопределяет значение от `priority`.            |
| `objectFit`             | `cover`                          | Применяется встроенными стилями, которые генерирует Unpic.          |
| `--moduix-image-radius` | `var(--moduix-radius-md)`        | Видимый радиус moduix по умолчанию.                                  |

### Особенности поведения

- `fixed` сохраняет заданные размеры в CSS-пикселях и может выйти за границы более узкого родителя, а `fullWidth`
  заполняет ширину контейнера.
- `alt` обязателен для содержательных изображений. Для декоративных используйте `alt=""`: тогда Unpic применяет
  `role="presentation"`, если вы явно не переопределите роль.
- Unpic генерирует `srcSet` из URL источника. Используйте `breakpoints`, когда его стандартные адаптивные
  ширины не подходят.
- Нативные `loading`, `decoding` и React-свойство `fetchPriority` в camelCase остаются доступными, если сгенерированные
  значения не соответствуют нужному поведению загрузки.
- `background="auto"` создаёт низкоразрешённый фон у поддерживаемых провайдеров. Он остаётся после загрузки, поэтому
  используйте его только для непрозрачных изображений или задайте вместо него осознанное значение фона.
- `unstyled` отключает встроенные стили раскладки, которые генерирует Unpic; стили отображения, радиуса и хуки
  `data-slot` moduix остаются доступными. Используйте его, когда источникам с адаптивным кадрированием нужны другие
  правила раскладки, а затем задайте их в собственном CSS.

## Примеры

### Адаптивное кадрирование

Используйте `Image.Source`, чтобы на больших экранах показать более широкий вид офиса, а на меньших - портретное
резервное изображение. Первый источник для настольных устройств запрашивает AVIF, а эквивалентный источник служит
резервным вариантом для браузеров без поддержки AVIF. `Image.Source` должен оставаться внутри нативного `<picture>`.

### Фиксированный размер

Используйте `layout="fixed"`, когда изображение должно сохранять точные размеры в CSS-пикселях. Убедитесь, что у его
родителя достаточно места: фиксированные изображения не уменьшаются, чтобы поместиться в более узком контейнере.

Используйте `layout="fullWidth"` для hero-блока или полосы с медиа, которая должна заполнить ширину родительской
раскладки. Передайте `height`, если высота кадрирования должна оставаться фиксированной.

### Хуки стилизации

- `data-slot="image-root"` стилизует отрисованный `<img>`.
- `data-slot="image-source"` выбирает узел источника внутри нативного `<picture>`.
- `className` на `Image` - рекомендуемый способ локальной стилизации. Корневой элемент по умолчанию блочный.
