## Базовый пример

Оставьте ловушку смонтированной и переключайте `disabled` при начале и завершении сценария. В примере `initialFocus`
переводит фокус на **Review details**, `isReviewing` синхронизируется через `onDeactivate`, а после отключения ловушки
фокус возвращается на **Start review**. В интерактивном примере через `PreviewMeta` показано, активна ли ловушка. Вкладки
с исходным кодом показывают одинаковое поведение с нативными примерами для React и Solid.

## Жизненный цикл фокуса

### Начальный фокус

При активации ловушки фокус по умолчанию переходит на первый элемент, доступный по клавише `Tab`. `initialFocus`
принимает элемент, селектор или функцию, которая возвращает элемент. Укажите `false`, если активация не должна менять
фокус. Элемент с атрибутом `autofocus` также учитывается.

### Если в области нет доступных элементов

Если внутри области нет элементов, доступных по клавише `Tab`, передайте `fallbackFocus` и добавьте целевому элементу
`tabIndex={-1}`. При активации будет выброшена ошибка, если Ark не найдёт доступный элемент или запасную цель, кроме
случая, когда `initialFocus` равен `false`.

### Возврат фокуса

По умолчанию фокус возвращается на элемент, который был активен до включения ловушки. Укажите
`returnFocusOnDeactivate={false}`, чтобы отключить это поведение, или используйте `setReturnFocus`, передав элемент,
функцию, которая его возвращает, либо `false`.

`onActivate` и `onDeactivate` - это callback-функции жизненного цикла. Используйте их для побочных действий и синхронизации
состояния приложения, как в примере, а не вместо управления `disabled`.

### Портальное содержимое и собственный корневой элемент

Если интерактивное содержимое рендерится в портале за пределами области, передайте в `persistentElements` функции,
возвращающие эти элементы. По возможности размещайте связанные элементы, доступные по Tab, внутри самой области.

По умолчанию `FocusTrap` создаёт обёртку. Укажите `asChild`, чтобы передать поведение одному семантически подходящему
дочернему элементу, которым управляет приложение.

## Ограничения и доступность

`FocusTrap` управляет только фокусом при навигации с клавиатуры. Он не создаёт подложку или портал, не добавляет
семантику диалога и доступное имя, не делает остальную страницу недоступной для взаимодействия, не блокирует прокрутку
и не управляет состоянием открытия и закрытия области. Используйте `Dialog` или `Drawer`, если их полная модель
взаимодействия подходит для задачи.

Пользовательская область с удержанием фокуса должна иметь понятный заголовок, доступное описание при необходимости и
видимое действие для выхода из сценария. Не удерживайте фокус в содержимом, которое нельзя закрыть.
