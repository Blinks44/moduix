Используйте `Editable` как корневой компонент и составьте его из `EditableLabel`, `EditableArea`,
`EditableInput` и `EditablePreview`. Добавьте `EditableControls` для стандартного сценария
редактирования, сохранения и отмены. moduix добавляет стили, хуки `data-slot` и иконки по умолчанию
для кнопок управления. По умолчанию режим редактирования включается двойным щелчком, что помогает
избежать случайных изменений.

## Какой компонент выбрать

- Выбирайте **`Input`** или **`Textarea`**, если значение всегда должно быть доступно для редактирования.
- Выбирайте **`Editable`**, если значение обычно доступно только для чтения, а редактирование должно быть явным действием.
- Оберните **`Editable`** в **`Field`**, если вспомогательный текст, сообщение об ошибке или общее состояние формы должны отображаться
  за пределами компонента.

### Редактирование по щелчку

Корневой компонент принимает основные свойства Ark: режим активации, автоматическое изменение размера,
максимальную длину, разные плейсхолдеры для режима просмотра и редактирования и локализованные подписи
элементов управления. В этом примере `activationMode` изменён на `click`, чтобы показать, как заменить
двойной щелчок, используемый в moduix по умолчанию.

### Root Provider

Используйте `useEditable()` и `EditableRootProvider` из moduix, когда элементам управления за пределами
дерева компонента нужен доступ к состоянию и методам `Editable`. Передайте в хук
`activationMode: 'dblclick'`, чтобы сохранить режим активации, установленный по умолчанию у корневого
компонента. Для этого экземпляра состояния provider заменяет `Editable`.

<Example name="editable/root-provider" />

### Textarea

Используйте `EditableInput asChild` с нативным `<textarea>` для многострочного текста. У textarea есть
минимальная высота, предпросмотр сохраняет переносы строк, а кнопки остаются у верхнего края.
Сохранение по Cmd/Ctrl + Enter, Enter добавляет новую строку.

Начинайте с него, если дизайн меняет кнопки или их иконки.

## Композиция

Размещайте `EditableInput` и `EditablePreview` рядом внутри `EditableArea`, а `EditableControls`
добавляйте после области для стандартного сценария редактирования, сохранения и отмены. Используйте
`EditableRootProvider` вместо `Editable`, если состояние из `useEditable()` должны разделять
элементы управления за пределами дерева. Для своего содержимого, зависящего от режима редактирования,
используйте `EditableContext` или `useEditableContext()`. В Solid состояние из `useEditable()` и
контекста представлено реактивной функцией, поэтому его можно читать как `editable().editing`.

## Стилизация

Для структурных стилей передавайте `className` в React или `class` в Solid и Vue на экспортируемые
части. Tailwind-варианты используют обычные utility-классы и классы потребителя. Варианты с CSS Modules
дополнительно предоставляют переменную ниже: она держит одинаковую высоту у области и квадратных
кнопок. Data-атрибуты и хуки `data-slot` общие для обоих вариантов.

Корень занимает ширину контейнера, поэтому переключение между предпросмотром и полем ввода не сдвигает
разметку. С `autoResize` корень подстраивается под ширину текста. Чтобы ограничить ширину, задайте
`max-width` корню через класс.

### Хуки стилизации

| Часть | `data-slot` |
| --- | --- |
| `Editable` | `editable-root` |
| `EditableRootProvider` | `editable-root-provider` |
| `EditableLabel` | `editable-label` |
| `EditableArea` | `editable-area` |
| `EditableInput` | `editable-input` |
| `EditablePreview` | `editable-preview` |
| `EditableControl` | `editable-control` |
| `EditableEditTrigger` | `editable-edit-trigger` |
| `EditableSubmitTrigger` | `editable-submit-trigger` |
| `EditableCancelTrigger` | `editable-cancel-trigger` |

- Селекторы частей Ark: `data-scope="editable"` и
  `data-part="root|area|label|preview|input|edit-trigger|submit-trigger|cancel-trigger|control"`.
- Селекторы состояния Ark: `data-disabled`, `data-focus`, `data-invalid`, `data-readonly`,
  `data-required`, `data-placeholder-shown` и `data-autoresize`.
- `EditableControls` использует слот `editable-control` вместе с `EditableControl`.

## Клавиатура

| Клавиша | Действие |
| --- | --- |
| `Enter` | Сохраняет значение, если это разрешает submitMode. |
| `Esc` | Отменяет правку и возвращает прежнее значение. |
