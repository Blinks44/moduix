## Выбор подходящего компонента

- Выберите **`Input`** или **`Textarea`**, если значение всегда должно выглядеть как поле для редактирования.
- Выберите **`Editable`**, если значение обычно доступно только для чтения, а редактирование запускается намеренно.
- Оберните **`Editable`** в **`Field`**, если пояснение, сообщение об ошибке или общее состояние формы должны отображаться
  за пределами структуры `Editable`.

## Базовый пример

Используйте части Ark: `Editable`, `Editable.Label`, `Editable.Area`, `Editable.Input` и
`Editable.Preview`. Добавьте `Editable.Controls`, чтобы получить стандартный сценарий с кнопками редактирования,
подтверждения и отмены. Обёртка moduix добавляет стили, атрибуты `data-slot` и иконки триггеров по умолчанию.
По умолчанию moduix включает режим редактирования двойным щелчком, что помогает избежать случайных изменений.

## Анатомия

```text
Editable.Root
├─ Editable.Label
├─ Editable.Area
│  ├─ Editable.Input
│  └─ Editable.Preview
├─ Editable.Control или Editable.Controls
│  ├─ Editable.EditTrigger
│  ├─ Editable.SubmitTrigger
│  └─ Editable.CancelTrigger

Editable.RootProvider
└─ то же дерево частей, связанное с состоянием Ark `useEditable()`
```

| Часть                        | Назначение                                                        |
| ---------------------------- | ----------------------------------------------------------------- |
| `Editable` / `Editable.Root` | Состояние компонента, колбэки, свойства формы и связь с механизмами доступности. |
| `Editable.RootProvider`      | Корневой компонент, связанный с экземпляром `useEditable()`.         |
| `Editable.Label`             | Видимая подпись поля ввода и предпросмотра.                          |
| `Editable.Area`              | Общий контейнер для поля ввода и предпросмотра.                       |
| `Editable.Input`             | Поле ввода, отображаемое во время редактирования.                    |
| `Editable.Preview`           | Значение или плейсхолдер вне режима редактирования.                  |
| `Editable.Control`           | Необязательный контейнер для кнопок редактирования, подтверждения и отмены. |
| `Editable.Controls`          | Готовая группа кнопок для стандартного сценария редактирования, подтверждения и отмены. |
| `Editable.EditTrigger`       | Кнопка перехода в режим редактирования.                              |
| `Editable.SubmitTrigger`     | Кнопка подтверждения текущего значения.                              |
| `Editable.CancelTrigger`     | Кнопка отмены текущего значения.                                     |

## Композиция

### Рекомендуемая композиция

Размещайте `Input` и `Preview` рядом внутри `Area`, а `Controls` ставьте после `Area`, чтобы использовать
стандартную схему кнопок. В однострочном поле кнопки появляются справа и выравниваются по центру высоты.
Для textarea используется та же структура. Задайте
`--moduix-editable-control-align: start`, чтобы выровнять кнопки по верхнему краю многострочной области.

### Когда нужна собственная композиция

Используйте `Editable.Context` или `useEditableContext()` из moduix, когда повторно используемым дочерним частям
или встроенному коду нужен доступ к состоянию редактирования. Используйте `useEditable()` и `Editable.RootProvider`,
если состояние или методы должны управляться за пределами дерева `Editable`. Применяйте `asChild`, когда для поля
нужен другой семантически подходящий элемент, например textarea.

### Свойства по умолчанию

| Свойство         | По умолчанию | Примечания                                                                                                           |
| ---------------- | ------------ | -------------------------------------------------------------------------------------------------------------------- |
| `activationMode` | `dblclick`   | По умолчанию moduix использует двойной щелчок. Передайте `focus`, `click` или `none`, чтобы выбрать другой режим активации Ark. |
| `selectOnFocus`  | `true`       | Ark выделяет текст поля при получении фокуса.                                                                        |
| `submitMode`     | `both`       | По умолчанию `Enter` и потеря фокуса подтверждают значение. Используйте `none`, если подтверждение должно происходить только по явной кнопке. |

### Особенности поведения

`value` и `defaultValue` задают текстовое значение. `edit` и `defaultEdit` управляют режимом редактирования.
Колбэки Ark сохраняют объект `details`, поэтому `onValueChange`, `onValueCommit`, `onValueRevert` и
`onEditChange` получают те же данные и имеют те же полезные поля, что и в Ark UI.

`Enter` подтверждает изменения, а `Escape` отменяет их. Если через `asChild` `Editable.Input` используется с textarea,
Cmd/Ctrl + Enter подтверждает значение. `name` и `form` передаются в Ark для нативной отправки формы.
`disabled` блокирует активацию, а `readOnly` оставляет значение видимым, но не позволяет его изменить.

Задайте `translations.input`, если полю ввода нужно контекстное доступное имя. `Editable.Label` остаётся видимой подписью.

### Хуки стилизации

- `data-slot="editable-root"`, `editable-root-provider`, `editable-label`, `editable-area`,
  `editable-input`, `editable-preview`, `editable-control`, `editable-edit-trigger`,
  `editable-submit-trigger` и `editable-cancel-trigger`.
- Ark также добавляет атрибуты `data-scope="editable"` и `data-part` для каждой примитивной части.
- Селекторы состояния включают `data-focus` на `Label` и `Area`; `data-disabled` на `Area`, `Input`
  и `Preview`; `data-readonly` / `aria-readonly` на элементах управления только для чтения; `data-invalid` на
  `Label`, `Input` и `Preview`; `data-required` на `Label`; `data-placeholder-shown` на `Area`
  и `Preview`; а также `data-autoresize` на `Input` и `Preview`.
