## Какой компонент выбрать

- Выбирайте **`Input`** или **`Textarea`**, если значение всегда должно быть доступно для редактирования.
- Выбирайте **`Editable`**, если значение обычно доступно только для чтения, а редактирование должно быть явным действием.
- Оберните **`Editable`** в **`Field`**, если вспомогательный текст, сообщение об ошибке или общее состояние формы должны отображаться
  за пределами компонента.

## Базовый пример

`Editable` доступен для React и Solid в пакетах с CSS Modules и в вариантах на Tailwind. Интерактивный
пример на странице использует пакет React с CSS Modules, а вкладки показывают нативный исходный код
с тем же публичным контрактом.

Используйте `Editable` как корневой компонент и составьте его из `Editable.Label`, `Editable.Area`,
`Editable.Input` и `Editable.Preview`. Добавьте `Editable.Controls` для стандартного сценария
редактирования, сохранения и отмены. moduix добавляет стили, хуки `data-slot` и иконки по умолчанию
для кнопок управления. По умолчанию режим редактирования включается двойным щелчком, что помогает
избежать случайных изменений.

## Анатомия

```text
Editable.Root
├─ Editable.Label
├─ Editable.Area
│  ├─ Editable.Input
│  └─ Editable.Preview
├─ Editable.Control или Editable.Controls
│  ├─ Editable.EditTrigger
│  ├─ Editable.SubmitTrigger
│  └─ Editable.CancelTrigger

Editable.RootProvider
└─ то же дерево частей, подключённое к состоянию Ark из `useEditable()`
```

| Часть                        | Назначение                                             |
| ---------------------------- | ------------------------------------------------------ |
| `Editable` / `Editable.Root` | Состояние компонента, callbacks, свойства формы и доступность. |
| `Editable.RootProvider`      | Корневая часть, подключённая к экземпляру `useEditable()`. |
| `Editable.Label`             | Видимая подпись поля и отображаемого значения.         |
| `Editable.Area`              | Общий контейнер для поля ввода и отображаемого значения. |
| `Editable.Input`             | Текстовое поле в режиме редактирования.               |
| `Editable.Preview`           | Значение или плейсхолдер вне режима редактирования.    |
| `Editable.Control`           | Необязательный контейнер кнопок редактирования, сохранения и отмены. |
| `Editable.Controls`           | Удобная обёртка стандартного сценария управления.     |
| `Editable.EditTrigger`       | Кнопка перехода в режим редактирования.               |
| `Editable.SubmitTrigger`     | Кнопка сохранения текущего значения.                   |
| `Editable.CancelTrigger`     | Кнопка отмены текущих изменений.                       |

## Композиция

Размещайте `Editable.Input` и `Editable.Preview` рядом внутри `Editable.Area`, а `Editable.Controls`
добавляйте после области для стандартного сценария редактирования, сохранения и отмены. Используйте
`Editable.RootProvider` вместо `Editable.Root`, если состояние из `useEditable()` должны разделять
элементы управления за пределами дерева. Для своего содержимого, зависящего от режима редактирования,
используйте `Editable.Context` или `useEditableContext()`. В Solid состояние из `useEditable()` и
контекста представлено реактивной функцией, поэтому его можно читать как `editable().editing`.

### Root Provider

Используйте `useEditable()` и `Editable.RootProvider` из moduix, когда элементам управления за пределами
дерева компонента нужен доступ к состоянию и методам `Editable`. Передайте в хук
`activationMode: 'dblclick'`, чтобы сохранить режим активации, установленный по умолчанию у корневого
компонента. Для этого экземпляра состояния provider заменяет `Editable.Root`.
