## Выбор подходящего компонента

- Выберите **`Input`** или **`Textarea`**, если значение всегда должно быть доступно для редактирования.
- Выберите **`Editable`**, если значение обычно доступно только для чтения, а редактирование должно запускаться отдельным действием.
- Поместите **`Editable`** внутрь **`Field`**, если пояснение, сообщение об ошибке или общее состояние формы должны отображаться
  за пределами компонента.

## Базовый пример

Используйте `Editable` как корневой компонент и составьте его из `Editable.Label`, `Editable.Area`,
`Editable.Input` и `Editable.Preview`. Добавьте `Editable.Controls`, чтобы получить готовый сценарий
с кнопками редактирования, подтверждения и отмены. Обёртка moduix добавляет стили, атрибуты `data-slot`
и встроенные иконки для кнопок. По умолчанию пользователь переходит в режим редактирования двойным
щелчком, что помогает избежать случайных изменений.

## Анатомия

```text
Editable.Root
├─ Editable.Label
├─ Editable.Area
│  ├─ Editable.Input
│  └─ Editable.Preview
├─ Editable.Control или Editable.Controls
│  ├─ Editable.EditTrigger
│  ├─ Editable.SubmitTrigger
│  └─ Editable.CancelTrigger

Editable.RootProvider
└─ то же дерево частей, подключённое к состоянию Ark `useEditable()`
```

| Часть                        | Назначение                                                        |
| ---------------------------- | ----------------------------------------------------------------- |
| `Editable` / `Editable.Root` | Корневой компонент, который управляет состоянием, колбэками, свойствами формы и доступностью. |
| `Editable.RootProvider`      | Корневой компонент, подключённый к экземпляру `useEditable()`.                               |
| `Editable.Label`             | Видимая подпись поля ввода и отображаемого значения.                                             |
| `Editable.Area`              | Общая область для поля ввода и отображаемого значения.                                            |
| `Editable.Input`             | Поле ввода, которое появляется в режиме редактирования.                                         |
| `Editable.Preview`           | Значение или плейсхолдер, отображаемый вне режима редактирования.                                |
| `Editable.Control`           | Необязательная обёртка для кнопок редактирования, подтверждения и отмены.                         |
| `Editable.Controls`          | Готовая группа для стандартного сценария редактирования, подтверждения и отмены.                 |
| `Editable.EditTrigger`       | Кнопка перехода в режим редактирования.                                                          |
| `Editable.SubmitTrigger`     | Кнопка подтверждения текущего значения.                                                          |
| `Editable.CancelTrigger`     | Кнопка отмены текущего значения.                                                                 |

## Композиция

### Рекомендуемая композиция

Разместите `Editable.Input` и `Editable.Preview` рядом внутри `Editable.Area`. Поместите
`Editable.Controls` после области, чтобы использовать стандартную схему кнопок. В однострочном поле
кнопки появляются справа и выравниваются по вертикальному центру. Для многострочного поля структура
та же. Задайте `--moduix-editable-control-align: start`, чтобы выровнять кнопки по верхнему краю области.

### Когда нужна собственная композиция

Используйте `Editable.Context` или `useEditableContext()` из moduix, когда переиспользуемым дочерним
элементам или собственному содержимому нужен доступ к текущему состоянию редактирования. Используйте
`useEditable()` и `Editable.RootProvider`, если состояние или методы должны находиться за пределами
отрисованного дерева `Editable`. `RootProvider` заменяет `Editable.Root` для этого экземпляра состояния.
Применяйте `asChild`, когда поле нужно отрисовать другим семантически подходящим элементом, например
нативным `<textarea>`.

### Свойства по умолчанию

| Свойство         | По умолчанию | Примечания                                                                                                           |
| ---------------- | ------------ | -------------------------------------------------------------------------------------------------------------------- |
| `activationMode` | `dblclick`   | По умолчанию moduix использует двойной щелчок. Передайте `focus`, `click` или `none`, чтобы выбрать другой режим активации Ark. |
| `selectOnFocus`  | `true`       | Ark выделяет текст поля при получении фокуса.                                                                                |
| `submitMode`     | `both`       | По умолчанию значение подтверждается при нажатии `Enter` и при потере фокуса. Используйте `none`, если подтверждать его должна только явная кнопка. |

### Особенности поведения

Свойства `value` и `defaultValue` задают текстовое значение. Свойства `edit` и `defaultEdit` управляют
режимом редактирования. Колбэки Ark сохраняют объект `details`, поэтому `onValueChange`, `onValueCommit`,
`onValueRevert` и `onEditChange` получают данные в том же формате, что и в Ark UI.

Нажмите `Enter`, чтобы подтвердить значение, и `Escape`, чтобы отменить изменения. Если через `asChild`
`Editable.Input` отрисован как `<textarea>`, сочетание Cmd/Ctrl + Enter подтверждает значение.
Свойства `name` и `form` передаются в Ark и позволяют отправлять значение через нативную форму.
`disabled` запрещает взаимодействие, а `readOnly` оставляет значение видимым, но запрещает его изменять.

Задайте `translations.input`, чтобы передать полю ввода доступное имя, подходящее для конкретного контекста.
`Editable.Label` при этом остаётся видимой подписью.

### Хуки стилизации

- `data-slot="editable-root"`, `editable-root-provider`, `editable-label`, `editable-area`,
  `editable-input`, `editable-preview`, `editable-control`, `editable-edit-trigger`,
  `editable-submit-trigger` и `editable-cancel-trigger`.
- Ark также добавляет атрибуты `data-scope="editable"` и `data-part` для каждой примитивной части.
- Селекторы состояния включают `data-focus` на `Label` и `Area`; `data-disabled` на `Area`, `Input`
  и `Preview`; `data-readonly` / `aria-readonly` на элементах управления только для чтения; `data-invalid` на
  `Label`, `Input` и `Preview`; `data-required` на `Label`; `data-placeholder-shown` на `Area`
  и `Preview`; а также `data-autoresize` на `Input` и `Preview`.
