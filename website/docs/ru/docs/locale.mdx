`LocaleProvider` передаёт локаль и направление текста всему поддереву. Форматтеры Ark и локализованное содержимое
читают этот контекст.

## Импорт

Импортируйте утилиту из соответствующего пакета moduix: он реэкспортирует провайдер локали Ark UI:

<Tabs
  groupId="framework"
  values={[
    { label: 'React', value: 'react' },
    { label: 'Solid', value: 'solid' },
    { label: 'Vue', value: 'vue' },
  ]}
  className="docs-tabs"
>
  <Tab value="react">

```tsx
import { LocaleProvider, useLocaleContext } from '@moduix/react/locale';
```

  </Tab>
  <Tab value="solid">

```tsx
import { LocaleProvider, useLocaleContext } from '@moduix/solid/locale';
```

  </Tab>
  <Tab value="vue">

```ts
import { LocaleProvider, useLocaleContext } from '@moduix/vue/locale';
```

  </Tab>
</Tabs>

`Format.Number`, `Format.Time` и другие утилиты `Format` по-прежнему импортируются из `@ark-ui/react` или
`@ark-ui/solid` или `@ark-ui/vue`.

## Задайте локаль

Оберните часть интерфейса, в которой используется одна локаль. Форматтеры и компоненты, учитывающие локаль, ниже
провайдера будут читать общий контекст.

<Example name="locale/basic" />

`LocaleProvider` принимает строку локали в формате BCP 47, например `fr-FR`. Без провайдера Ark использует `en-US` и
`ltr`.

## Прочитайте контекст локали

`useLocaleContext` возвращает `locale` и `dir` из ближайшего провайдера. Используйте их, если собственная разметка
должна следовать тому же языку и направлению, что и компоненты, учитывающие локаль. В React значения читаются
напрямую, а в Solid доступны через accessor-функцию. Vue возвращает computed ref: в setup используйте
`.value`, а шаблон автоматически раскрывает ref.

## Задайте язык и направление документа

`LocaleProvider` вычисляет направление `dir` для Ark по локали, но не меняет нативные атрибуты документа `lang` и
`dir`. Если всё приложение использует одно направление, задайте оба атрибута на корневом элементе документа:

<div className="docs-reference">
  <Tabs
    groupId="framework"
    values={[
      { label: 'React', value: 'react' },
      { label: 'Solid', value: 'solid' },
      { label: 'Vue', value: 'vue' },
    ]}
    className="docs-tabs"
  >
    <Tab value="react">

```tsx pure file="../../../src/components/examples/locale/document.tsx"
```

    </Tab>
    <Tab value="solid">

<CodeBlockRuntime lang="tsx" code={localeSolidDocument} />

    </Tab>
  <Tab value="vue">

<CodeBlockRuntime lang="vue" code={localeVueDocument} />

    </Tab>
  </Tabs>
</div>

Для RTL-раздела внутри приложения с направлением слева направо задайте `lang` и соответствующий `dir` на корневом
элементе этого раздела, как в примере с контекстом. Если пользователи могут переключать LTR и RTL без перезагрузки
страницы, обновляйте атрибуты документа одновременно с `locale`. Подробнее о порталах, логических CSS-свойствах и
направленных иконках читайте в разделе [Справа налево (RTL)](/docs/rtl).

## Переведите подписи по умолчанию

`LocaleProvider` не переводит текст. Кнопки с одной иконкой и несколько ориентиров, например кнопки закрытия и очистки,
`Spinner` и `Breadcrumbs`, по умолчанию получают английские доступные имена вроде `Close` или `Clear search`. В
интерфейсе на другом языке замените их одним из двух способов.

Передайте `aria-label` или `aria-labelledby` там, где используется компонент. Заданное имя всегда заменяет значение по
умолчанию:

```tsx
<DialogCloseIcon aria-label="Закрыть" />
<CommandPaletteSearch aria-label="Поиск команд" />
```

При установке исходников через shadcn значения по умолчанию лежат в `@/lib/moduix/a11yLabels.ts`. Переведите значения в
этом файле, чтобы сменить все подписи сразу:

```ts
export const a11yLabels = {
  closeDialog: 'Закрыть',
  clearSearch: 'Очистить поиск',
  // ...
} as const;
```
