# Токены

Стили moduix построены на CSS-переменных. Начните с семантических цветовых токенов для поверхностей, текста, границ,
колец фокуса и оверлеев. Если дизайн-системе нужен другой ритм, настройте интервалы, радиусы, размеры, типографику,
анимации, тени и слои.

Если вы используете moduix как npm-пакет, один раз импортируйте `@moduix/react/style.css`. При установке исходников
через `shadcn` один раз импортируйте `@/lib/moduix/styles/style.css`. Обе точки входа загружают одну и ту же основу
токенов.

Сброс стилей необязателен в обоих вариантах. При использовании npm импортируйте `@moduix/react/reset.css` перед
`style.css`. Если исходный код находится в проекте, сначала выполните `npx shadcn@latest add @moduix-react/reset`,
затем импортируйте `@/lib/moduix/styles/reset.css` перед `style.css`.

Для готовой отправной точки используйте [Темы](/docs/themes). Пресеты переопределяют небольшой слой семантических
токенов после `style.css`. Здесь описаны системные и общие токены, а на страницах компонентов - локальные алиасы и
селекторы состояний, которые можно безопасно настраивать.

## Выберите уровень переопределения

1. Измените примитив темы, например `--moduix-primary`, для визуального решения уровня всего продукта.
2. Измените общее значение семейства, если связанные компоненты должны меняться вместе.
3. Изменяйте алиас компонента, только когда этот компонент должен намеренно отличаться.
4. Ограничьте переменную контейнером конкретной функции для единичного локального исключения.

Если не уверены, начинайте выше в списке. Небольшое семантическое переопределение проще поддерживать, чем повторять
одно и то же значение во множестве алиасов компонентов.

## Модель токенов

Токены разделены на слои, чтобы общие изменения оставались небольшими и осознанными:

| Слой | Примеры | Подходит для |
| --- | --- | --- |
| Примитивы темы | `--moduix-primary`, `--moduix-spacing-2`, `--moduix-size-md`, `--moduix-radius` | Задания визуального языка приложения или пресета. |
| Семантические алиасы | `--moduix-color-primary`, `--moduix-spacing-md`, `--moduix-radius-md` | Использования вычисленных значений в компонентах и стилях приложения. |
| Общие значения семейства | `--moduix-popup-item-min-height`, `--moduix-focus-ring-width` | Согласования связанных контролов, строк всплывающих списков и состояний. |
| Алиасы компонентов | `--moduix-input-height`, `--moduix-select-item-min-height` | Создания осознанного исключения для одного компонента или его экземпляра. |

Предпочитайте наиболее высокий подходящий слой. Переопределяйте `--moduix-primary`, когда меняется цвет бренда,
`--moduix-popup-item-min-height`, когда всем поверхностям в стиле меню нужна другая плотность, и
`--moduix-select-item-min-height`, только если Select должен намеренно отличаться.

Алиасы компонентов используют цепочки резервных значений, а не скопированные числа. Поэтому тема может
переопределить небольшую группу примитивов, а типографика, геометрия иконок, кольца фокуса и размеры компонентов
останутся согласованными.

## Использование moduix с существующей дизайн-системой

moduix управляет только переменными `--moduix-*`. Ваши токены `--primary`, `--space-2` и другие не считываются, не
перезаписываются и не сбрасываются. Свяжите нужные значения в файле стилей, который загружается после `style.css`:

```css
:root {
  --moduix-primary: var(--product-action-primary);
  --moduix-primary-foreground: var(--product-action-on-primary);
  --moduix-background: var(--product-surface-canvas);
  --moduix-foreground: var(--product-text-primary);
  --moduix-radius: var(--product-radius-md);
  --moduix-spacing-2: var(--product-space-2);
  --moduix-size-md: var(--product-control-height-md);
}
```

Можно связать только те токены, за которые отвечает ваша система: остальные значения moduix по умолчанию продолжат
работать. Для исключений на уровне компонентов действует то же правило, например `--moduix-dialog-*` и
`--moduix-button-*`.

Исключение - переменные состояния, которые Ark UI задаёт во время работы: `--height`, `--available-width` и
`--transform-origin` остаются без префикса, поскольку Ark записывает их в соответствующие части компонентов. moduix
не объявляет эти значения на `:root`.

Используйте эту страницу для системных решений, а страницу нужного компонента - для локальных алиасов. Ни один вариант
установки не требует отдельной таблицы со справочником переменных во время выполнения.

## Плотность и шкала элементов управления

Шкала по умолчанию компактна, но не слишком тесная:

| Токен | Значение по умолчанию | Предназначение |
| --- | --- | --- |
| `--moduix-size-xs` | `24px` | Небольших контролов с иконками и компактных действий. |
| `--moduix-size-sm` | `32px` | Строк всплывающих списков и вторичных компактных контролов. |
| `--moduix-size-md` | `36px` | Стандартных полей ввода, кнопок, триггеров, пагинации и составных контролов. |
| `--moduix-size-lg` | `40px` | Намеренно более просторных контролов. |
| `--moduix-size-xl` | `48px` | Выразительных контролов и интерфейсов, ориентированных на касание. |

Большинство основных контролов используют `--moduix-size-md`; элементы меню, Select, Combobox, палитр команд и
похожих всплывающих списков - `--moduix-size-sm`. Так триггер и его список выглядят связанными, но строки списка
остаются немного компактнее.

```css
:root {
  --moduix-size-md: 36px;
  --moduix-size-sm: 32px;
}

[data-moduix-theme='compact'] {
  --moduix-size-md: 34px;
  --moduix-popup-item-min-height: 30px;
}
```

## Общие переопределения стилей

Некоторые переменные определены выше уровня отдельных компонентов. Их изменение обновляет сразу несколько компонентов,
пока компонентная переменная `--moduix-<component>-*` не переопределит резервное значение.

| Группа переменных | Что изменяет | Типичные потребители |
| --- | --- | --- |
| <code>--moduix-backdrop-bg</code><br /><code>--moduix-backdrop-filter</code> | Цвет и размытие фона по умолчанию | Command Palette, Dialog, Drawer, Lightbox, Tour |
| <code>--moduix-duration-\*</code><br /><code>--moduix-ease-\*</code><br /><code>--moduix-transition-\*</code> | Общая длительность и easing анимаций | Контролы, оверлеи, вкладки, аккордеоны, поля ввода, toast |
| <code>--moduix-popup-motion-\*</code> | Длительность и фазы анимации содержимого всплывающих окон | Popover, Menu, Tooltip, Hover Card, Floating Panel, модальные поверхности и пикеры |
| <code>--moduix-scale-popup</code><br /><code>--moduix-scale-dropdown</code> | Масштаб открытия и закрытия всплывающих окон по умолчанию | Dialog, Popover, Tooltip, Menu, Toast, Select, Combobox |
| <code>--moduix-popup-\*</code> | Общая плотность и интервалы списков всплывающих окон | Menu, Select, Combobox, CommandPalette |
| <code>--moduix-spacing-\*</code><br /><code>--moduix-size-\*</code> | Общая плотность и шкала контролов | Контролы, геометрия иконок, строки всплывающих списков, ритм макета |
| <code>--moduix-focus-ring-\*</code><br /><code>--moduix-color-ring</code> | Общая геометрия и цвет кольца фокуса | Кнопки, поля ввода, составные контролы, триггеры всплывающих окон |

Используйте эти токены, когда нужно масштабное визуальное изменение всей системы. Используйте токены, специфичные для
компонента, например `--moduix-dialog-backdrop-bg` или `--moduix-popover-transition`, когда один компонент должен
отличаться.

Краткая таблица выше - сводный указатель по компонентам. В подробном обзоре ниже те же токены собраны в
соответствующих разделах: анимация - в Motion, масштаб - в Elevation & Layers, а общие значения фона, всплывающих
списков и их анимации - в Shared Component Defaults.

```css
:root {
  --moduix-backdrop-bg: oklch(0.12 0.03 250 / 0.34);
  --moduix-transition-default: 240ms cubic-bezier(0.22, 1, 0.36, 1);
  --moduix-scale-popup: 0.96;
  --moduix-popup-motion-duration: 220ms;
  --moduix-popup-motion-easing: cubic-bezier(0.22, 1, 0.36, 1);
}

.command-surface {
  --moduix-popup-item-min-height: var(--moduix-size-sm);
}
```

Дробные токены интервалов, например `--moduix-spacing-1-5` и `--moduix-spacing-3-5`, получаются из соседних
примитивных шагов. Пресету плотности достаточно переопределить целочисленные примитивы: промежуточные отступы
компонентов, геометрия иконок и смещения фокуса изменятся автоматически.

## Область переопределения

Задавайте токены уровня проекта в `:root`. Значение на `[data-moduix-color-scheme='dark']` или другом родительском
контейнере наследуют только компоненты, отрисованные внутри него. Для оверлеев, которые по умолчанию рендерятся в
портале, значение нужно указать на корне документа, `body` или контейнере портала в этой области.

```css
:root {
  --moduix-primary: oklch(0.52 0.18 145);
  --moduix-radius: 0.75rem;
  --moduix-backdrop-filter: blur(4px);
}

.dense-panel {
  --moduix-spacing-1: 3px;
  --moduix-spacing-2: 6px;
  --moduix-spacing-3: 10px;
  --moduix-size-sm: 30px;
  --moduix-size-md: 34px;
}
```

Для повторно используемой темы храните переопределения в отдельном файле стилей, который загружается после
`style.css`. Если несколько тем должны сосуществовать, ограничьте файл атрибутом, например
`[data-moduix-theme='brand']`. Разовые настройки компонента держите рядом с соответствующей функцией, чтобы они не
превращались незаметно в глобальные решения дизайн-системы.
