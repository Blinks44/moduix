## Справочник API

`Sidebar` - компонент moduix для компоновки навигации приложения. Он объединяет части навигации с
[Ark UI Splitter](https://ark-ui.com/docs/components/splitter), который отвечает за изменение размера,
сворачивание, работу с клавиатурой и доступность. Состояние и колбэки компонента соответствуют API
`Splitter`.

<PrimitiveReference href="https://ark-ui.com/docs/components/splitter" />

## Выбор подходящего компонента

- Выбирайте **`Sidebar`**, если навигация должна менять ширину, сворачиваться в ряд иконок и
  располагаться рядом с основным содержимым.
- Выбирайте **`Splitter`**, если нужны две обычные изменяемые панели, а не панель навигации и
  основная область содержимого.

## Базовый пример

Соберите панель навигации, линию изменения размера и основную область содержимого в качестве прямых
потомков корня. Стандартных id и ограничений достаточно для обычного макета с левой боковой панелью,
поэтому дополнительная настройка не нужна. В примере также показано, как сохранить подписи у кнопок
только с иконками после сворачивания: оберните `Sidebar.NavigationButton` в
`Sidebar.Tooltip`. Всплывающей подсказкой управляет сам Tooltip.

## Композиция

### Рекомендуемая композиция

Размещайте каждую часть макета прямым потомком корня. Для левой боковой панели используйте порядок
`Panel`, `ResizeTrigger`, `Trigger`, затем `Inset`. Для правой панели используйте обратный
визуальный порядок: `Inset`, `Trigger`, `ResizeTrigger`, затем `Panel`. Триггер располагается
поверх линии изменения размера и обычного разделителя верхней панели содержимого. Он не занимает места
в макете и не обрезается панелями. Если высота верхней панели отличается, настройте
`--moduix-sidebar-trigger-offset-y`.

Для вложенных пунктов меню в развёрнутой панели используйте `Collapsible`, а для действий с
учётной записью - `Menu + Avatar`. Если `Menu.Trigger asChild` оборачивает
`Sidebar.NavigationButton`, добавьте `Menu.Indicator` его прямым дочерним элементом в конце
строки. В свёрнутом ряду он скрывается. `Sidebar.Input`, `Sidebar.GroupAction`,
`Sidebar.NavigationAction`, `Sidebar.NavigationBadge` и `Sidebar.Separator` покрывают
распространённые элементы оболочки приложения, не добавляя Sidebar отдельный слой состояния.

Для навигационных кнопок только с иконкой используйте `Sidebar.Tooltip`, чтобы подпись оставалась
доступной при наведении. Обычно нужны два приёма:

1. **Подписи в свёрнутом ряду:** `Sidebar.Tooltip` вокруг `Sidebar.NavigationButton`.
2. **Сохранение ширины:** храните ширину в управляемом `size`, обновляйте её из
   `onResize(details)`, а значение после завершения изменения сохраняйте из
   `onResizeEnd(details)` в состоянии приложения или хранилище.

`Sidebar` - короткая запись для `Sidebar.Root`.

Обычно `Sidebar.NavigationList` является прямым потомком `Sidebar.Group`; используйте
`Sidebar.GroupContent` только для дополнительного пользовательского контейнера. Для вложенной
навигации есть два явных варианта: разместите `Collapsible` со встроенными ссылками в
`Sidebar.ExpandedContent`, а во `Sidebar.CollapsedContent` добавьте всплывающее `Menu` со
ссылками, если дочерние пункты должны оставаться доступными. Эти части только выбирают содержимое
по состоянию панели Ark. Они не управляют состоянием Menu или Collapsible и не превращают один
примитив в другой. Используйте `useSidebar().collapsed` только тогда, когда приложению нужно
изменить собственное React-дерево. Если у родительского пункта есть полезная обзорная страница,
в свёрнутом ряду можно оставить ссылку на неё.

### Когда нужна собственная композиция

Передавайте `defaultSize`, управляемый `size` и колбэки, если стандартный макет с CSS-размерами
не подходит. `useSidebar()` предоставляет `collapsed`, `state`, `side` и `toggleSidebar`.
Используйте `Splitter` напрямую, если нужны другие ограничения панелей, низкоуровневые API
провайдера или реестра, либо больше двух панелей.

`panelId` меняет id панели навигации по умолчанию и id связанной с ней линии изменения размера;
id inset остаётся `"content"`. Части макета Sidebar намеренно не принимают отдельные id. Благодаря
этому панели, триггер и `useSidebar()` используют один и тот же контракт панели Ark. Используйте
`Splitter` напрямую, если нужен собственный id inset или больше двух панелей.

Используйте `asChild` на кнопках навигации и вложенной навигации, чтобы передать управление
переходом ссылке роутера. Передавайте один семантический дочерний элемент, который принимает
объединённые props и ref.

Держите связанные со Splitter части внутри `Sidebar`: `Panel`, `Inset`,
`ResizeTrigger`, `Trigger` и `useSidebar()`.

### Свойства по умолчанию

| Значение | По умолчанию |
| --- | --- |
| Id панелей | `"sidebar"` и `"content"` |
| Начальная ширина боковой панели | `"16rem"` (256px) |
| Ограничения боковой панели | `minSize: "3rem"`, `maxSize: "18rem"`, `collapsedSize: "3rem"` |
| Ограничения содержимого | Без минимального размера |
| Сторона | `"left"` |
| Ориентация | `"horizontal"` (фиксирована для макета sidebar/inset) |
| Корневой `panelId` | `"sidebar"` |
| Размер кнопки навигации `size` | `"md"` |

### Особенности поведения

Ark принимает проценты и CSS-длины для размеров панелей. CSS-длины измеряются в браузере, поэтому
после гидратации серверный макет может немного сдвинуться. Если для SSR важна стабильная геометрия,
используйте проценты. `Trigger` выставляет `aria-expanded`, сначала вызывает ваш `onClick` и
не переключает состояние, если обработчик вызвал `preventDefault()`.

Ark сохраняет перетаскивание указателем, изменение размера стрелками, состояние фокуса и объекты
details в колбэках: `onResize(details)`, `onResizeEnd(details)`, `onCollapse(details)` и
`onExpand(details)`.

Размер панели при сворачивании и разворачивании меняется сразу в соответствии с состоянием Ark.
Sidebar намеренно не анимирует ширину панели: CSS-переход для flex отставал бы от изменения размера
указателем и клавиатурой. Содержимое Collapsible, всплывающие слои, подсказки и иконка триггера
сохраняют собственные переходы.

## Стилизация

Панель навигации использует токены карточки, а inset - фон приложения. Стандартная конфигурация
панели оставляет ряд иконок шириной `3rem`. В свёрнутом состоянии `Sidebar.Label` и заголовки
групп исключаются из визуальной раскладки с помощью приёма визуального скрытия, вложенные списки
навигации и `Sidebar.Input` скрываются, а SVG и элементы с `data-sidebar-icon` выравниваются
по центру. Подписи остаются доступными для вспомогательных технологий и не занимают место во
flex-раскладке. Отмечайте `data-sidebar-icon` визуальные элементы без SVG, например Avatar,
значок рабочего пространства Select или логотип, чтобы сохранить их размеры. Помещайте в
`Sidebar.Label` текст, значения и подписи, которые должны исчезать из визуальной раскладки.
Индикаторы оставляйте прямыми потомками примитива, отвечающего за их размещение. Действия групп и
навигации в конце строки автоматически скрываются в свёрнутом режиме только с иконками. Кнопки
навигации и вложенной навигации обрезают прямой текст при любой ширине Sidebar. Используйте
`Sidebar.Label`, если текст или значения должны исчезать и из свёрнутого ряда.

При небольшой ширине развёрнутой панели, меньше `7rem`, Sidebar также скрывает действия групп и
навигации, счётчики и индикаторы, пока они не начали пересекаться с основной иконкой. Панель
остаётся развёрнутой, её состояние Ark и подписи не меняются.

Ширина панели является состоянием Ark, а не визуальным свойством CSS. Переопределяйте
`defaultSize` и управляемый `size`, чтобы задать текущую ширину Sidebar; используйте
`Splitter`, если должны отличаться ограничения развёрнутого, минимального, максимального или
свёрнутого состояния. `panelId` меняет id панели навигации по умолчанию. Для внутренних отступов,
размеров элементов, цветов и вертикального смещения триггера используйте публичные переменные
`--moduix-sidebar-*`.

Плавающий триггер находится там, где линия изменения размера пересекается с обычным разделителем
верхней панели содержимого, и не закрывает заголовок навигации. Стандартное смещение `40px`
подходит для верхней панели inset высотой `3.5rem`; для другой высоты задайте
`--moduix-sidebar-trigger-offset-y`. Интерфейс изменения размера намеренно состоит только из
линии. В обычном состоянии её цвет совпадает с цветом границы, при наведении и перетаскивании он
немного смещается в сторону `--moduix-color-muted-foreground`, а при фокусе с клавиатуры
используется цвет кольца фокуса Sidebar. Переопределяйте переменные
`--moduix-splitter-resize-trigger-line-color-*`, только если нужен более заметный отклик.

### Хуки стилизации

Каждая семантическая часть принимает `className` и предоставляет стабильный хук
`data-slot="sidebar-*"`. Части оболочки Sidebar также предоставляют `data-scope="sidebar"` и
`data-part`. `Sidebar.Input` и `Sidebar.Separator` сохраняют scope своих исходных примитивов,
а части макета на базе Ark сохраняют атрибуты состояния Splitter.

`Sidebar.Panel` добавляет `data-state="expanded"` или `"collapsed"`.
`Sidebar.ExpandedContent` и `Sidebar.CollapsedContent` предоставляют
`data-slot="sidebar-expanded-content"` и `data-slot="sidebar-collapsed-content"` для стилизации
по состоянию. Корень, панель, inset, линия изменения размера и плавающий триггер предоставляют
`data-side`. `NavigationButton` и `NavigationSubButton` предоставляют `data-active`,
а `NavigationButton` также предоставляет `data-size`. Остальные части оболочки сохраняют
стабильные хуки `data-slot="sidebar-*"` для пользовательского макета и темы. Состояние изменения
размера остаётся доступно через атрибуты Ark `data-focus`, `data-dragging`, `data-disabled`
и `data-orientation`.
