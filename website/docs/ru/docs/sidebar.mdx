## Справочник API

`Sidebar` использует [Ark UI Splitter](https://ark-ui.com/docs/components/splitter) для изменения размера,
состояния сворачивания, взаимодействия с клавиатурой и доступности. Его семантическая анатомия навигации
основана на [Sidebar из shadcn/ui](https://ui.shadcn.com/docs/components/sidebar), а контракт состояния
сохраняет форму Ark.

<PrimitiveReference href="https://ark-ui.com/docs/components/splitter" />

## Выбор подходящего компонента

- Выбирайте **`Sidebar`** для навигации приложения, которая должна менять ширину, сворачиваться до
  ряда иконок и располагаться рядом с основным содержимым.
- Выбирайте **`Splitter`**, когда обе панели являются обычными областями содержимого, а не парой навигации
  и inset.

## Базовый пример

Отрендерите панель навигации, разделитель для изменения размера из Ark и основную область содержимого
отдельными частями. Стандартных id и ограничений достаточно для обычной левой боковой панели — настраивать

## Композиция

### Рекомендуемая композиция

Держите все части раскладки прямыми потомками корня. Для левой боковой панели порядок такой: `Panel`,
`ResizeTrigger`, `Trigger`, затем `Inset`; для правой — `Inset`, `Trigger`, `ResizeTrigger`, затем
`Panel`. Триггер располагается поверх линии изменения размера и обычного разделителя заголовка основной
области: он не занимает место в раскладке и не обрезается панелями. Если высота заголовка другая,
переопределите `--moduix-sidebar-trigger-offset-y`.

Для вложенных пунктов меню используйте `Collapsible`, а для действий с учётной записью — `Menu + Avatar`.
`Menu.Indicator` добавляйте прямо в `Sidebar.MenuButton`: он выравнивается по правому краю и скрывается
при сворачивании панели. `Input`, `GroupAction`, `GroupContent`, `MenuAction`, `MenuBadge` и `Separator`
покрывают частые элементы оболочки приложения, не добавляя Sidebar отдельное состояние.

Чтобы подписи были доступны при наведении на кнопки с иконками, оборачивайте `Sidebar.MenuButton` в
`Sidebar.Tooltip`. Обычно достаточно двух приёмов:

1. **Подписи свёрнутой панели:** `Sidebar.Tooltip` вокруг `Sidebar.MenuButton`.
2. **Сохранение:** храните ширину в управляемом `size`, обновляйте её из `onResize(details)` и сохраняйте
   из `onResizeEnd(details)` в состоянии приложения или хранилище.

`Sidebar` — короткая запись для `Sidebar.Root`.

### Когда нужна собственная композиция

Передавайте `defaultSize`, управляемый `size` и колбэки, если стандартная раскладка с CSS-размерами не
подходит. `useSidebar()` предоставляет `collapsed`, `state`, `side` и `toggleSidebar`. Используйте
`Splitter` напрямую, если нужны другие ограничения панелей, его низкоуровневые API, больше двух панелей
или полный API контекста.

`panelId` меняет стандартный id навигации вместе с соответствующим handle изменения размера; id inset
остаётся `"content"`. Части раскладки Sidebar намеренно не принимают отдельные id: это сохраняет один
контракт панели Ark для отрендеренных панелей, триггера и `useSidebar()`. Используйте `Splitter` напрямую,
когда раскладке нужен пользовательский id inset или более двух панелей.

Используйте `asChild` на кнопках меню и подменю, чтобы отрисовать ссылки роутера. Передавайте один
семантический дочерний элемент, который принимает объединённые props и ref.

Держите части, связанные со Splitter, внутри `Sidebar`: `Panel`, `Inset`, `ResizeTrigger`, `Trigger` и
`useSidebar()`.

### Свойства по умолчанию

| Значение                  | По умолчанию                                                    |
| ------------------------- | ---------------------------------------------------------------- |
| Id панелей                | `"sidebar"` и `"content"`                                      |
| Начальный размер sidebar  | `"16rem"` (256px)                                                |
| Ограничения Sidebar       | `minSize: "3rem"`, `maxSize: "18rem"`, `collapsedSize: "3rem"`  |
| Ограничения содержимого   | Нет минимума                                                     |
| Сторона                   | `"left"`                                                         |
| Ориентация                | `"horizontal"` (фиксирована для раскладки sidebar/inset)        |
| Корневой `panelId`        | `"sidebar"`                                                      |
| `size` кнопки меню        | `"md"`                                                           |

### Особенности поведения

Ark принимает проценты и CSS-длины для размеров панелей. CSS-длины измеряются в браузере, поэтому после
гидратации серверная раскладка может немного сдвинуться. Если для SSR важна стабильная геометрия,
используйте проценты. `Trigger` выставляет `aria-expanded`, сначала вызывает ваш `onClick` и не меняет
состояние, если обработчик вызвал `preventDefault()`.

Ark сохраняет перетаскивание указателем, изменение размера стрелками, состояние фокуса и объекты details
колбэков: `onResize(details)`, `onResizeEnd(details)`, `onCollapse(details)` и `onExpand(details)`.

Сворачивание и разворачивание панелей сразу следует размерам Ark. Sidebar намеренно не анимирует ширину
панели, поскольку CSS-переход flex отставал бы от изменения размера указателем и клавиатурой. Содержимое
Collapsible, всплывающее содержимое, подсказки и иконка триггера сохраняют собственные переходы.

## Стилизация

Панель навигации использует токены card, а inset - фон приложения. Стандартные данные панели настраивают
панель `3rem`. Свёрнутые панели исключают из раскладки `Sidebar.Label` и подписи групп с помощью
визуально скрытого паттерна, скрывают вложенные меню и `Sidebar.Input`, а SVG и элементы с
`data-sidebar-icon` центрируют. Подписи остаются доступны вспомогательным технологиям, не занимая место
во flex-раскладке. Помечайте не-SVG-якоря, например Avatar, метку рабочего пространства Select или метку
бренда, атрибутом `data-sidebar-icon`; их собственные размеры сохраняются. Помещайте сворачиваемый текст,
значения, метки и индикаторы в `Sidebar.Label`, если они должны покинуть визуальную раскладку в свёрнутой
панели. Завершающие элементы групп и меню автоматически скрываются в состоянии только с иконками.
Кнопки меню и вложенного меню сокращают прямой текст с многоточием при любой ширине Sidebar. Используйте
`Sidebar.Label`, когда текст, значения, метки или индикаторы также должны покидать свёрнутую панель.

Ширина панели - состояние Ark, а не визуальный CSS. Переопределяйте `defaultSize` и управляемый `size`
для текущей ширины Sidebar; если нужны другие развёрнутая, минимальная, максимальная или свёрнутая ширины,
используйте `Splitter`. `panelId` меняет стандартный id навигации. Используйте публичные переменные
`--moduix-sidebar-*` для внутренних отступов, размеров элементов, цветов и вертикального смещения триггера.

Плавающий триггер расположен на пересечении линии изменения размера и типичного разделителя topbar в
inset, поэтому не перекрывает заголовок навигации. Его смещение по умолчанию `40px` рассчитано на
topbar inset высотой `3.5rem`; для другой высоты заголовка переопределите
`--moduix-sidebar-trigger-offset-y`. Интерфейс изменения размера намеренно состоит только из линии. Её
цвет покоя совпадает с границей, при наведении и
перетаскивании он немного сдвигается к `--moduix-color-muted-foreground`, а фокус с клавиатуры использует
цвет focus-ring Sidebar. Переопределяйте переменные
`--moduix-splitter-resize-trigger-line-color-*`, только когда продукту нужна более заметная обратная связь.

### Хуки стилизации

Каждая семантическая часть принимает `className` и предоставляет стабильный атрибут
`data-slot="sidebar-*"`. Части оболочки Sidebar также имеют `data-scope="sidebar"` и `data-part`.
`Sidebar.Input` и `Sidebar.Separator` сохраняют области видимости базовых примитивов, а части раскладки
на Ark — атрибуты состояния Splitter.

`Sidebar.Panel` добавляет `data-state="expanded"` или `"collapsed"`. Корневой элемент, панель, inset, триггер
изменения размера и плавающий триггер предоставляют `data-side`. `MenuButton` и `MenuSubButton`
предоставляют `data-active`, `MenuButton` предоставляет `data-size`, а дополнительные части оболочки
сохраняют стабильные хуки `data-slot="sidebar-*"` для пользовательской раскладки или темы. Состояние
изменения размера по-прежнему доступно через Ark `data-focus`, `data-dragging`, `data-disabled` и
`data-orientation`.
