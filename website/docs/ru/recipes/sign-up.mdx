# Регистрация

Используйте этот рецепт как основу для экрана регистрации. В нём сочетаются `Card`, `Field`, `Input`,
`Checkbox` и `Button`. Браузер проверяет заполнение обязательных полей, формат адреса электронной почты и
наличие согласия с условиями. Рецепт не содержит интеграции с сервисом аутентификации и не сравнивает два
пароля, поэтому добавьте эту логику в обработчик `onSubmit`.

Живое превью использует React-пакет. Во вкладках исходников приведены нативные реализации для React и Solid с общими стилями.

## Использование в маршруте

Скопируйте исходный код рецепта и CSS из вкладок выше, затем импортируйте `SignUp` из скопированного
файла. Браузер проверяет нативные ограничения до вызова `onSubmit`. В обработчике сравните два пароля
и отправьте данные формы на сервер регистрации.

их значения можно получить из `FormData`. Замените `/api/sign-up` и путь импорта на значения из своего
приложения.

## Перед запуском

Исходный код рецепта намеренно оставлен небольшим. Добавьте в него поведение и отображение ошибок,
которые нужны вашему приложению:

- Показывайте требования к паролю и при необходимости добавьте к скопированным полям ограничения
  `minLength` или `pattern`. Те же правила обязательно проверяйте на сервере.
- На время запроса блокируйте повторную отправку формы. Если запрос завершился ошибкой, сохраняйте
  введённые значения, чтобы пользователь мог исправить их и повторить попытку.
- Показывайте ошибку сервера рядом с соответствующим полем. Ошибки сети и непредвиденные сбои выводите
  на уровне формы в элементе с `role="alert"` и оставляйте возможность повторить запрос.
- Замените `/terms`, `/privacy` и `/sign-in` маршрутами своего приложения.
- После успешной регистрации выполните следующий шаг сценария: авторизуйте пользователя, попросите его
  подтвердить адрес электронной почты или перенаправьте на страницу подтверждения.
