# Таблица данных

`Data Table` - это способ собрать таблицу, а не отдельный компонент, который экспортирует moduix. Используйте
семантические и стилизованные части `Table` для разметки, а TanStack Table v9 - для управления состоянием и
поведением таблицы. Храните данные и состояние таблицы в том экране или модуле приложения, которому они
принадлежат, особенно если состояние влияет на маршрут или серверный
запрос. У разных частей продукта свои столбцы, фильтры, действия со строками и контракты с сервером, поэтому
держите эту логику рядом с нужной функциональностью.

Полный рецепт ниже повторяет интерактивную таблицу с главной страницы. В нём показаны поиск, сортировка,
управление видимостью столбцов, выбор строк, действия и пагинация. Скопируйте код и замените демонстрационные
записи и действия данными своего продукта.

## Начните с простого случая

| Задача                                           | С чего начать                                                                        |
| ------------------------------------------------ | ------------------------------------------------------------------------------------ |
| Таблица только для чтения                        | Семантический компонент [Table](/docs/table)                                         |
| Локальная сортировка или фильтрация небольшого набора | `Table` и подходящая модель строк TanStack                                        |
| Сортировка, фильтрация или пагинация на сервере  | Управляемое состояние запроса и параметры TanStack для ручного управления ниже       |
| Виртуализация строк                               | Добавляйте виртуализацию только после замера реальной проблемы с производительностью |

Подключайте только те элементы управления, которые нужны таблице. Уберите выбор, настройку видимости
столбцов, действия или пагинацию, если пользователю не нужна соответствующая возможность.

## Настройка

Установите TanStack Table в приложение или функциональный модуль, который отвечает за логику таблицы:

```bash
npm install @tanstack/react-table@^9.2.3
```

`Table` доступен в `@moduix/react/table`. TanStack Table намеренно не входит в этот пакет, поэтому приложениям,
которым нужна только семантическая таблица, не приходится загружать лишнюю логику таблицы данных.

## Базовый пример

Объявите набор возможностей через `tableFeatures()`, опишите типизированные столбцы
`ColumnDef<typeof features, Payment>` и создайте экземпляр таблицы с помощью `useTable`. Отобразите группы
заголовков и видимые ячейки в анатомии таблицы moduix. Для заголовков и ячеек используйте `flexRender`,
поскольку определения столбцов могут содержать простые значения или React-функции рендеринга.

В примере используются методы для отображения видимых столбцов и ячеек, поэтому он регистрирует
`columnVisibilityFeature`. Остальные возможности подключайте только при необходимости.

## Стабильные ссылки

В примерах `features`, `payments` и `columns` объявлены вне компонентов, поэтому TanStack Table получает одни
и те же ссылки при каждом рендере. Если данные или столбцы зависят от свойств компонента или состояния,
создавайте итоговый массив через `useMemo`, а не внутри компонента и не передавайте `data.filter(...)`
напрямую в `useTable`. Новый массив на каждом рендере заставляет TanStack Table пересчитывать состояние и
может привести к циклу рендеринга React. Подробнее об этом написано в [FAQ](https://tanstack.com/table/latest/docs/faq)
TanStack.

## Ширина столбцов

Для столбцов, ширина которых должна оставаться неизменной, используйте `Table.ColumnGroup` и
`Table.Column htmlWidth`. Добавьте `table-layout: fixed` корневому элементу таблицы. Оставшийся столбец займёт
доступное пространство, а изменяющийся значок сортировки не повлияет на ширину своего столбца.

## Управление таблицей

Подключайте только те возможности TanStack и модели строк, которые нужны таблице. В интерактивном примере
состояния сортировки, фильтров столбцов и выбора хранятся в React. Фильтр применяется к столбцу электронной
почты, для строк используются стабильные ID платежей через `getRowId`, а на странице показывается пять строк.

Импортируйте только используемые встроенные функции фильтрации и сортировки и зарегистрируйте их в
`tableFeatures()`. Так неиспользуемые функции не попадут в итоговую сборку. В рецепте зарегистрированы `includesString`,
`alphanumeric` и `text`, а не весь реестр.

Для сортируемого заголовка используйте обычную кнопку внутри `Table.ColumnHeader`. В примере у значков Lucide
единый размер, а сортируемые заголовки получают `aria-sort="none" | "ascending" | "descending"`. В столбце

не найдены, используйте `Table.Empty` и передайте `colSpan={table.getVisibleLeafColumns().length}`.

## Данные с сервера

Если API отвечает за фильтрацию, сортировку или разбиение записей по страницам, храните эти параметры в
состоянии запроса функционального модуля. Передавайте TanStack Table страницу из ответа и отключайте
соответствующие преобразования на клиенте. Эта конфигурация заменяет клиентские модели строк из
интерактивного примера:

```tsx
const features = tableFeatures({
  columnFilteringFeature,
  rowPaginationFeature,
  rowSortingFeature,
});

const table = useTable({
  features,
  data: response.rows,
  columns,
  manualFiltering: true,
  manualPagination: true,
  manualSorting: true,
  rowCount: response.rowCount,
  onColumnFiltersChange: setColumnFilters,
  onPaginationChange: setPagination,
  onSortingChange: setSorting,
  state: { columnFilters, pagination, sorting },
});
```

Если преобразованием управляет сервер, не добавляйте соответствующую `filteredRowModel`, `sortedRowModel` или
`paginatedRowModel` в `features`: TanStack считает, что `response.rows` уже соответствует запросу. Передавайте
`pageCount` вместо `rowCount`, если API возвращает количество страниц. `manualPagination` также отключает
обычный сброс страницы. Поэтому при изменении серверного фильтра или сортировки сбрасывайте
`pagination.pageIndex` в `0`, иначе API может вернуть пустую страницу. Подробнее о слое запросов читайте в
руководствах TanStack по [фильтрации](https://tanstack.com/table/latest/docs/guide/global-filtering),
[сортировке](https://tanstack.com/table/latest/docs/guide/sorting) и
[пагинации](https://tanstack.com/table/latest/docs/guide/pagination).

Показывайте состояние запроса рядом с таблицей, а не в несвязанных ячейках:

| Состояние запроса | Что показать |
| ----------------- | ------------ |
| Первичная загрузка | Оставьте заголовки столбцов видимыми и покажите строку загрузки с понятной подписью или скелетон. |
| Повторный запрос | Сохраните текущие строки, покажите, что панель занята, и не отправляйте повторные запросы. |
| Пустой результат | Объясните, нет ли записей вовсе или фильтры исключили все совпадения. |
| Ошибка | Оставьте элементы управления запросом доступными и предложите повторить тот же запрос. |

## Добавление возможностей

TanStack Table не содержит готового интерфейса и разметки для этих возможностей. Выбирайте состояние и модели
строк для конкретного представления данных, а не включайте все функции таблицы по умолчанию.

| Задача | Что добавить |
| ------ | ------------ |
| Действия со строками | Отобразите `Menu` в столбце действий, а обработчики оставьте в функциональном модуле. |
| Выбор строк | Управляйте `rowSelection`, настройте `getRowId` на постоянный ID записи и добавьте moduix `Checkbox` в столбец выбора. |
| Видимость столбцов | Управляйте `columnVisibility` и вызывайте `column.toggleVisibility()` из `Menu`. |
| Данные с сервера | Храните состояние запроса в маршруте или слое данных. Используйте `manualFiltering`, `manualSorting` и `manualPagination` только для преобразований, которыми управляет API, затем передавайте строки ответа с `rowCount` или `pageCount`. |
| Большие объёмы данных | Добавляйте виртуализацию только к телу таблицы и лишь после замеров. Сохраняйте нативную семантику `table`, `thead`, `tbody`, `tr`, `th` и `td`. |

В [руководстве по моделям строк](https://tanstack.com/table/latest/docs/guide/row-models) TanStack Table
описаны доступные преобразования на клиенте. [Руководство по выбору строк](https://tanstack.com/table/latest/docs/guide/row-selection)
объясняет управляемое состояние выбора и выбор на уровне страницы. В [React-адаптере](https://tanstack.com/table/latest/docs/framework/react/react-table)
описан `useTable`. На странице moduix [Table](/docs/table) описаны итоговая структура и доступные хуки стилизации.

При `manualPagination` сохраняйте полное состояние `rowSelection` для действий, затрагивающих несколько страниц.
Модели выбранных строк TanStack возвращают только записи, переданные таблице в данный момент, даже если состояние
выбора содержит ID с других страниц.

## Повторное использование

Если одна и та же продуктовая таблица нужна в нескольких местах, вынесите её столбцы, панель управления или
элементы пагинации в локальные компоненты функционального модуля. Сохраняйте API специфичным для продукта.
`PaymentsTable` проще поддерживать, чем универсальный компонент `DataTable`, который пытается предусмотреть
каждый фильтр, ответ сервера, действие и правило выбора.

## Доступность

Сохраняйте нативную семантику таблицы в итоговой разметке. Используйте `Table.ColumnHeader` для заголовков,
`Table.Cell` для данных и короткий `Table.Caption`, если соседний заголовок не объясняет содержимое таблицы.
Элементам управления внутри ячеек нужны понятные доступные имена, а сортируемые заголовки должны сообщать
текущее направление через `aria-sort`. У поля фильтра и элементов выбора в интерактивном примере есть явные
доступные имена, а не только текст подсказки или значок.
