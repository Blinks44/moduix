# Таблица данных

`Data Table` — паттерн композиции, а не компонент, который экспортирует moduix. Используйте семантические и
стилизованные части `Table` для разметки, а TanStack Table v9 — для состояния таблицы. Данные и состояние
таблицы должны оставаться у продуктовой функции, если от них зависят маршрут или серверный запрос. У каждого
продукта свои столбцы, фильтры, действия со строками и контракт с сервером, поэтому не выносите это поведение
далеко от места, где оно нужно.

Готовый к копированию рецепт ниже — та же интерактивная таблица, что показана на главной странице. В ней есть
поиск, сортировка, настройка видимости столбцов, выбор строк, действия и пагинация. Замените демонстрационные
записи и действия данными своего продукта.

## Начните с простого

| Задача | С чего начать |
| ----- | ------------ |
| Строки и столбцы только для чтения | Семантический компонент [Table](/docs/table) |
| Локальная сортировка или фильтрация небольшого набора | Table и подходящая модель строк TanStack |
| Сортировка, фильтрация или пагинация на сервере | Управляемое состояние запроса и параметры TanStack для ручного управления ниже |
| Виртуализированные строки | Добавляйте виртуализацию только после замера реальной проблемы с производительностью |

Не копируйте все элементы управления из полного рецепта без необходимости. Уберите выбор, настройку видимости
столбцов, действия или пагинацию, если пользователю эта возможность недоступна.

## Настройка

Установите TanStack Table в приложение, которому принадлежит логика таблицы:

```bash
npm install @tanstack/react-table@^9
```

`Table` уже входит в `@moduix/react/table`. TanStack Table намеренно не включён в пакет, поэтому приложения,
которым достаточно семантической таблицы, не получают лишнюю логику таблицы данных.

## Основы

Опишите типизированные записи `ColumnDef<typeof features, Payment>`, объявите нужные возможности через
`tableFeatures()` и создайте экземпляр таблицы с `useTable`. Затем отрисуйте группы заголовков и видимые ячейки
в анатомии таблицы moduix. Для заголовков и ячеек используйте `flexRender`: определения столбцов могут содержать
простые значения или React-функции рендеринга.

## Стабильные ссылки

В примерах `payments` и `columns` объявлены вне компонентов, поэтому TanStack Table получает одни и те же
ссылки между рендерами. Если данные или столбцы зависят от props либо состояния, мемоизируйте итоговый массив
через `useMemo`, а не создавайте его внутри компонента и не передавайте `data.filter(...)` напрямую в `useTable`.
Новые ссылки заставляют TanStack Table пересчитывать состояние и могут вызвать цикл рендеринга React. Подробнее
— в [FAQ](https://tanstack.com/table/latest/docs/faq) TanStack.

## Ширина столбцов

Для столбцов с фиксированной шириной используйте нативные `Table.ColumnGroup` и `Table.Column htmlWidth`.
Добавьте `table-layout: fixed` корневому элементу таблицы: оставшийся столбец займёт доступное пространство,
а меняющийся значок сортировки не повлияет на ширину своего столбца.

## Управление таблицей

Добавляйте только те возможности TanStack и модели строк, которые нужны таблице. В примере ниже состояние React
управляет сортировкой и фильтрами столбцов; фильтруется столбец электронной почты, строки выбираются по стабильным
ID платежей и на странице показывается по пять строк.

TanStack Table v9 исключает из бандла неиспользуемые функции фильтрации и сортировки. Регистрируйте в
`tableFeatures()` только те встроенные функции, которые нужны таблице: этот рецепт добавляет `includesString`,
`alphanumeric` и `text`, а не полный реестр.

## Серверные данные

Если API фильтрует, сортирует или разбивает записи на страницы, храните эти параметры в состоянии запроса
продуктовой функции. Передавайте TanStack Table страницу из ответа и отключайте соответствующие преобразования
на клиенте. Эта конфигурация заменяет клиентские модели строк из интерактивного примера:

```tsx
const features = tableFeatures({
  columnFilteringFeature,
  rowPaginationFeature,
  rowSortingFeature,
});

const table = useTable({
  features,
  data: response.rows,
  columns,
  manualFiltering: true,
  manualPagination: true,
  manualSorting: true,
  rowCount: response.rowCount,
  onColumnFiltersChange: setColumnFilters,
  onPaginationChange: setPagination,
  onSortingChange: setSorting,
  state: { columnFilters, pagination, sorting },
});
```

Не добавляйте `filteredRowModel`, `sortedRowModel` или `paginatedRowModel` в `features` для поведения, которым
управляет сервер: TanStack считает, что `response.rows` уже соответствует запросу. Передавайте `pageCount` вместо
`rowCount`, если API возвращает именно его. `manualPagination` также отключает обычный сброс страницы, поэтому
при изменении удалённого фильтра или сортировки сбрасывайте `pagination.pageIndex` на `0`, иначе API может вернуть
пустую страницу. Руководства TanStack по
[фильтрации](https://tanstack.com/table/latest/docs/guide/global-filtering),
[сортировке](https://tanstack.com/table/latest/docs/guide/sorting) и
[пагинации](https://tanstack.com/table/latest/docs/guide/pagination) описывают слой запросов.

Показывайте состояние запроса рядом с таблицей, а не в несвязанных ячейках:

| Состояние запроса | Что показать |
| ----------------- | ----------- |
| Первичная загрузка | Оставьте заголовки столбцов видимыми и покажите строку загрузки с подписью или skeleton. |
| Повторный запрос | Сохраните текущие строки, отметьте панель как занятую и не допускайте повторных запросов. |
| Пустой результат | Объясните, нет ли записей вовсе или все совпадения исключили фильтры. |
| Ошибка | Оставьте элементы управления доступными и предложите повторить тот же запрос. |

## Добавление возможностей

TanStack Table не содержит UI. Выбирайте состояние и модели строк для конкретного представления данных, а не
включайте все возможности таблицы по умолчанию.

| Задача | Что добавить |
| ----- | ------------ |
| Действия со строками | Отрисуйте `Menu` в столбце действий; обработчики остаются в продуктовой функции. |
| Выбор строк | Управляйте `rowSelection`, настройте `getRowId` на постоянный ID записи и добавьте moduix `Checkbox` в столбец выбора. |
| Видимость столбцов | Управляйте `columnVisibility` и вызывайте `column.toggleVisibility()` из `Menu`. |
| Серверные данные | Храните состояние запроса в маршруте или слое данных. `manualFiltering`, `manualSorting` и `manualPagination` используйте только для преобразований API, затем передавайте строки ответа с `rowCount` или `pageCount`. |
| Большие наборы данных | Добавляйте виртуализацию только к телу таблицы и лишь после замеров; сохраняйте семантику `table`, `thead`, `tbody`, `tr`, `th` и `td`. |

В [руководстве по моделям строк](https://tanstack.com/table/latest/docs/guide/row-models) TanStack Table перечислены
доступные клиентские преобразования. [Руководство по выбору строк](https://tanstack.com/table/latest/docs/guide/row-selection)
объясняет управляемое состояние выбора и выбор на уровне страницы, а [React adapter](https://tanstack.com/table/latest/docs/framework/react/react-table)
описывает `useTable`. На странице moduix [Table](/docs/table) есть отрендеренная структура и хуки стилизации.

При `manualPagination` сохраняйте полное состояние `rowSelection` для действий, затрагивающих несколько страниц.
Модели выбранных строк TanStack возвращают только записи, которые сейчас переданы таблице, даже если в состоянии
выбора есть ID с других страниц.

## Повторное использование

Если одна и та же таблица появляется в нескольких местах, вынесите её столбцы, панель или элементы пагинации в
локальные компоненты продуктовой функции. Оставьте API специфичным для продукта: `PaymentsTable` проще
поддерживать, чем общий wrapper `DataTable`, который пытается предусмотреть каждый фильтр, ответ сервера,
действие и правило выбора.

## Доступность

Сохраняйте нативные элементы таблицы в итоговой разметке. Используйте `Table.ColumnHeader` для заголовков,
`Table.Cell` для данных и короткую подпись, если заголовок рядом не объясняет, какие это данные. Интерактивным
элементам внутри ячеек нужны понятные доступные имена, а сортируемые заголовки должны сообщать текущее направление
через `aria-sort`. У поля фильтра и элементов выбора в интерактивном примере есть явные доступные имена, а не
только placeholder или текст значка.
