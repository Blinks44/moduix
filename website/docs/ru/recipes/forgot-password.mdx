# Восстановление пароля

Используйте эту заготовку как основу для страницы восстановления пароля. Она объединяет `Card`, `Field`,
`Input` и `Button`. До вызова `onSubmit` браузер проверяет, что адрес заполнен и имеет корректный формат.
Заготовка не обращается к сервису сброса и не показывает состояния успеха и ошибки, поэтому добавьте эту
логику в приложение.

Живое превью использует React-пакет. Во вкладках исходников приведены нативные реализации для React и Solid с общими стилями.

<ExampleFrame variant="recipe" clientOnly>
  <PreviewFrame maxWidth="sm">

  </PreviewFrame>
</ExampleFrame>

В превью обработчик `onSubmit` только вызывает `event.preventDefault()`, поэтому настоящее письмо не
отправляется. Скопируйте заготовку и CSS в приложение, затем подключите её к API восстановления пароля.

## Подключение в маршруте

Скопируйте заготовку и CSS из вкладок выше, затем импортируйте `ForgotPassword` из скопированного файла.
Разместите компонент в маршруте, где пользователь запрашивает сброс пароля. Браузер проверяет нативные
ограничения поля до вызова `onSubmit`. Прочитайте адрес из `FormData` и отправьте его в API восстановления:

<Tabs
  groupId="framework"
  values={[
    { label: 'React', value: 'react' },
    { label: 'Solid', value: 'solid' },
  ]}
>
  <Tab value="react">

<CodeBlockRuntime lang="tsx" code={forgotPasswordRouteReact} />

  </Tab>
  <Tab value="solid">

<CodeBlockRuntime lang="tsx" code={forgotPasswordRouteSolid} />

  </Tab>
</Tabs>

В объекте `FormData` будет ключ `email`. Замените `/api/forgot-password` и путь импорта значениями из своего
приложения.

## Перед публикацией

Скопированный код намеренно остаётся минимальным. Добавьте необходимое приложению поведение и отображение
ошибок:

- Пока выполняется запрос, блокируйте кнопку отправки, чтобы не допустить повторных запросов. Используйте
  у `Button` свойство `loading` или `disabled`.
- После успешного ответа показывайте одинаковое нейтральное сообщение для любого адреса, например:
  `Если учётная запись с таким адресом существует, мы отправим письмо для сброса пароля.` Не сообщайте,
  существует ли учётная запись.
- Если сервер ограничил частоту запросов, укажите пользователю, когда можно повторить попытку. Фактическое
  ограничение должен обеспечивать сервер.
- При ошибке сохраните адрес, покажите общую ошибку формы с `role="alert"` и дайте пользователю повторить
  запрос.
- В скопированном коде замените ссылку `/sign-in` маршрутом своего приложения.
