# Сброс пароля

Пользователь может выбрать новый пароль после перехода по проверенной ссылке для сброса. Нативная валидация
проверяет, что оба поля заполнены; совпадение паролей подтвердите в обработчике `onSubmit`.

## В маршруте

Рендерите `ResetPassword` в маршруте, на который ведёт проверенная ссылка для сброса, и передайте ему реальный
обработчик отправки формы. Замените ссылку `/sign-in` маршрутом своего приложения.

Проверяйте токен сброса на сервере до сохранения пароля. Просроченный или уже использованный токен показывайте
как отдельное состояние страницы со ссылкой для запроса нового письма. Во время отправки блокируйте повторные
запросы, проверяйте поле подтверждения и выводите безопасную ошибку сервера в форме. После успеха аннулируйте
токен и направьте пользователя ко входу или в авторизованную сессию — в соответствии с политикой продукта.
