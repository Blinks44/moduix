# Сброс пароля

Используйте этот рецепт на странице, которую пользователь открывает по ссылке для сброса пароля. В карточке
есть два обязательных поля: новый пароль и его подтверждение, а также ссылка для входа. Рецепт отвечает только
за интерфейс: он не проверяет токен сброса, не сравнивает введённые значения и не обращается к API. Передайте
обработчик `onSubmit`, чтобы подключить форму к своему маршруту.

Живое превью использует React-пакет. Во вкладках исходников приведены нативные реализации для React и Solid с общими стилями.

## Добавьте рецепт в маршрут

Рендерите `ResetPassword` только после того, как сервер проверил токен сброса, и передайте ему реальный
обработчик отправки формы. В `onSubmit` приходит нативное событие формы. Получите значения через
`new FormData(event.currentTarget)`: имена полей - `password` и `confirm-password`. Если отправляете данные
через `fetch` или механизм действий вашего фреймворка, отмените стандартную отправку формы в обработчике.
Замените ссылку `/sign-in` маршрутом своего приложения.

| Состояние | Что делать |
| --------- | ---------- |
| Неверный или просроченный токен | Покажите сообщение на уровне маршрута и ссылку для запроса нового письма. Не показывайте активную форму. |
| Пароли не совпадают | Покажите ошибку рядом с полем подтверждения и не отправляйте запрос. |
| Отправка | Блокируйте повторную отправку и сохраняйте введённые значения, если запрос завершится ошибкой. |
| Ошибка сервера | Покажите безопасное сообщение у поля или на уровне формы, не раскрывая подробности токена. |
| Успех | Сразу пометьте токен использованным, затем отправьте пользователя на страницу входа или создайте сессию по правилам вашего приложения. |

Показывайте требования к паролю до отправки формы и проверяйте их на сервере. Клиентская проверка помогает
быстрее показать ошибку, но не заменяет серверную защиту.
