# Загрузка файлов

сообщением, если файл не принят. Рецепт управляет только локальным списком. Там, где продукт отправляет файлы
на сервер, подключите собственную мутацию загрузки.

## Загрузка

`FileUpload` хранит выбранные файлы в локальном состоянии. Если маршруту нужно передать
`details.acceptedFiles` в действие формы или мутацию загрузки, добавьте `onFileChange` к корневому элементу.
Состояния прогресса и завершения держите рядом с реальным запросом, а не имитируйте их в рецепте.

Проверка на клиенте улучшает обратную связь, но сервер всё равно должен проверить тип, размер, содержимое и
права на загрузку файла. Считайте выбранный `File` недоверенным входным значением.

| Состояние | Что показать пользователю |
| --------- | ------------------------- |
| Выбран | Имя и размер файла, кнопку удаления и явную загрузку либо отправку формы. |
| Загружается | Прогресс, если он известен, понятный статус и заблокированную повторную отправку. |
| Ошибка | Безопасное для показа сообщение сервера, а также действия повтора и удаления. |
| Завершено | Устойчивое состояние успеха с ID файла, сохранённого на сервере. |

Если файлы загружаются сразу после выбора, сохраняйте ID каждого запроса, назначенный приложением. Тогда повторная
попытка обновит ту же строку, а удаление одного файла не отменит остальные.
