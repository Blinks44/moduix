# Загрузка файлов

Используйте этот блок в форме или рабочем сценарии, где пользователю нужно добавлять и проверять вложения.
Пример принимает файлы PDF, DOC, DOCX, PNG и JPG размером до 10 МБ, показывает до пяти принятых файлов и
позволяет удалить отдельный файл или очистить весь список. Отклонённые файлы остаются в списке вместе с
сообщениями о причинах отказа.

Блок отвечает только за выбор файлов и локальное состояние списка. Он не отправляет файлы на сервер и не
отслеживает прогресс загрузки. Подключите `onFileChange` к форме или запросу на загрузку в той части приложения,
которой принадлежат эти данные.

Превью работает на React. Во вкладках приведён код для React, Solid и Vue с общей таблицей стилей.

## Подключение загрузки на сервер

`FileUpload` хранит выбранные файлы в локальном состоянии. Если форме или запросу на загрузку нужен текущий список,
добавьте `onFileChange(details)` к корневому элементу и передайте `details.acceptedFiles` обработчику формы или загрузки.
Храните состояние прогресса и завершения рядом с реальным запросом, а не имитируйте их в блоке.

Проверка в браузере помогает быстрее показать ошибку, но не заменяет проверку на сервере. Сервер должен заново
проверить тип, размер, содержимое и права на загрузку. Считайте каждый выбранный `File` недоверенным входом.

| Состояние | Что показывать пользователю |
| --------- | -------------------------- |
| Выбран | Имя и размер файла, действие удаления и явную загрузку либо отправку формы. |
| Загружается | Прогресс, если он известен, статус ожидания и заблокированную повторную отправку. |
| Ошибка | Безопасное сообщение сервера, а также действия для повтора и удаления. |
| Завершено | Состояние успешной загрузки и идентификатор файла, сохранённого на сервере. |

Если загрузка начинается сразу после выбора, присваивайте каждому запросу идентификатор на стороне приложения. Тогда
повторная попытка обновит ту же строку, а удаление одного файла не затронет остальные.
