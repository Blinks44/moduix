# Réinitialisation du mot de passe

Utilisez cette recette sur la page vers laquelle l’utilisateur arrive après avoir suivi un lien de
réinitialisation du mot de passe. La carte contient deux champs obligatoires pour saisir le nouveau mot de passe
et le confirmer, ainsi qu’un lien de connexion. La recette fournit uniquement l’interface : elle ne
vérifie pas le jeton, ne compare pas les deux valeurs et n’appelle pas votre API. Passez un gestionnaire
`onSubmit` pour relier le formulaire à votre route.

## Dans une route

Affichez `ResetPassword` uniquement après que votre serveur a validé le jeton de réinitialisation, puis
transmettez-lui votre gestionnaire d’envoi. `onSubmit` reçoit l’événement natif du formulaire. Utilisez
`new FormData(event.currentTarget)` pour lire les champs `password` et `confirm-password`. Si vous envoyez
les données avec `fetch` ou une action de votre framework, annulez l’envoi natif dans le gestionnaire.
Remplacez le lien `/sign-in` par la route de votre application.

| État | Recommandation |
| ---- | -------------- |
| Jeton invalide ou expiré | Affichez un message au niveau de la route et un lien pour demander un nouvel e-mail de réinitialisation. Ne laissez pas le formulaire actif. |
| Mots de passe différents | Affichez l’erreur près du champ de confirmation et n’envoyez pas la demande. |
| Envoi en cours | Désactivez les envois en double et conservez les valeurs saisies si la requête échoue. |
| Erreur du serveur | Affichez un message au niveau du champ ou du formulaire, sans divulguer les détails du jeton. |
| Réussite | Invalidez immédiatement le jeton, puis redirigez vers la connexion ou créez une session selon le parcours prévu par votre produit. |

Affichez les exigences du mot de passe avant l’envoi et appliquez les mêmes règles côté serveur. La vérification
côté client permet d’afficher les erreurs plus vite, mais ne remplace pas la protection côté serveur.
