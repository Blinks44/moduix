# Connexion

Cette recette propose un formulaire de connexion compact avec validation native du navigateur,
autocomplétion de l’e-mail et du mot de passe, ainsi que des liens pour récupérer l’accès au compte et
pour s’inscrire. Elle utilise les composants moduix `Card`, `Field`, `Input`, `Checkbox` et `Button`.
Elle ne gère ni l’authentification ni l’état de la requête. Branchez ces éléments dans votre application
via `onSubmit`.

## Connecter le formulaire à l’authentification

`LoginSimple` transmet `onSubmit` à l’élément `<form>` natif. Le gestionnaire reçoit l’événement habituel
du formulaire : appelez `event.preventDefault()`, créez un `FormData` à partir de `event.currentTarget`,
puis envoyez-le à votre API. Les champs du formulaire s’appellent `email`, `password` et `remember` ;
`remember` n’est envoyé que si la case est cochée.

```tsx
import type { FormEvent } from 'react';
import { LoginSimple } from './login-simple';

export function SignInRoute() {
  async function handleSubmit(event: FormEvent<HTMLFormElement>) {
    event.preventDefault();

    const response = await fetch('/api/sign-in', {
      method: 'POST',
      body: new FormData(event.currentTarget),
    });

    if (!response.ok) {
      // Show a form-level error and keep the entered email.
      return;
    }

    window.location.assign('/dashboard');
  }

  return <LoginSimple onSubmit={handleSubmit} />;
}
```

Remplacez `/api/sign-in` et `/dashboard` par les routes de votre application. Dans la recette copiée,
remplacez également les liens `/forgot-password` et `/sign-up`.

## À prévoir en production

| Situation | À faire |
| --------- | ------- |
| Requête en cours | Désactivez le bouton d’envoi et empêchez les envois en double pendant la requête. |
| Identifiants incorrects | Affichez un message général au niveau du formulaire, sans préciser si l’e-mail ou le mot de passe est incorrect. |
| Erreur réseau | Conservez l’e-mail saisi et permettez une nouvelle tentative. N’effacez le mot de passe que si les règles de sécurité de votre application l’exigent. |
| Connexion réussie | Redirigez vers une route sûre ou remplacez l’entrée courante dans l’historique, selon le parcours de votre application. |

Si votre application accepte un paramètre `returnTo` ou une URL de redirection, validez cette valeur côté serveur avant toute navigation.
