# Tableau de données

`Data Table` est un modèle de composition, pas un composant exporté par moduix. Utilisez les parties
sémantiques et stylées de `Table` pour le balisage, puis TanStack Table v9 pour gérer l’état de la grille.
Les enregistrements et l’état du tableau doivent rester dans la fonctionnalité produit lorsqu’ils pilotent
une route ou une requête serveur. Chaque produit a ses propres colonnes, filtres, actions de ligne et
contrats serveur : gardez ce comportement près de l’endroit où il est utilisé.

La recette prête à copier ci-dessous est le même tableau interactif que celui de la page d’accueil. Elle
comprend la recherche, le tri, la visibilité des colonnes, la sélection des lignes, les actions et la
pagination. Remplacez les enregistrements et actions de démonstration par les données du produit.

## Commencez simple

| Besoin | Point de départ |
| ------ | --------------- |
| Lignes et colonnes en lecture seule | Le composant sémantique [Table (documentation en anglais)](https://moduix.dev/docs/table) |
| Tri ou filtrage local d’un petit jeu de données | Table et le modèle de lignes TanStack adapté |
| Tri, filtrage ou pagination côté serveur | État de requête contrôlé et options manuelles de TanStack ci-dessous |
| Lignes virtualisées | N’ajoutez la virtualisation qu’après avoir mesuré un problème de performances réel |

Ne copiez pas tous les contrôles de la recette complète par défaut. Retirez la sélection, la visibilité
des colonnes, les actions ou la pagination si cette capacité n’est pas utile à la personne qui utilise la table.

## Configuration

Installez TanStack Table dans l’application qui porte la logique de la grille de données :

```bash
npm install @tanstack/react-table@^9
```

`Table` est déjà fourni par `@moduix/react/table`. TanStack Table n’est volontairement pas inclus, afin que
les applications qui n’ont besoin que d’un tableau sémantique n’embarquent pas de logique de grille inutile.

## Principes de base

Définissez des entrées `ColumnDef<typeof features, Payment>` typées, déclarez les fonctionnalités requises
avec `tableFeatures()`, puis créez une instance avec `useTable`. Rendez ses groupes d’en-têtes et ses cellules
visibles dans l’anatomie de tableau moduix. Utilisez `flexRender` pour les en-têtes et les cellules : les
définitions de colonnes peuvent contenir des valeurs simples ou des fonctions de rendu React.

## Références stables

Dans les exemples, `payments` et `columns` sont définis hors des composants : TanStack Table reçoit donc les
mêmes références entre les rendus. Si les données ou les colonnes dépendent des props ou de l’état, mémorisez le
tableau obtenu avec `useMemo` au lieu de le créer dans le composant ou de transmettre `data.filter(...)` directement
à `useTable`. De nouvelles références font recalculer TanStack Table et peuvent provoquer des boucles de rendu React.
Consultez la [FAQ](https://tanstack.com/table/latest/docs/faq) de TanStack pour plus de détails.

## Largeur des colonnes

Pour les colonnes dont la largeur doit rester fixe, utilisez les éléments natifs `Table.ColumnGroup` et
`Table.Column htmlWidth`. Ajoutez `table-layout: fixed` à la racine du tableau : la colonne restante occupe
l’espace disponible, sans qu’une icône de tri changeante redimensionne sa colonne.

## Contrôles du tableau

Ajoutez uniquement les fonctionnalités et modèles de lignes TanStack dont le tableau a besoin. Dans l’exemple,
l’état React contrôle le tri et les filtres de colonnes ; la colonne d’e-mail est filtrée, les lignes sont
sélectionnées selon leurs identifiants de paiement stables et cinq lignes sont affichées par page.

TanStack Table v9 exclut les fonctions de filtrage et de tri inutilisées du bundle. Enregistrez dans
`tableFeatures()` uniquement celles dont le tableau a besoin : cette recette ajoute `includesString`,
`alphanumeric` et `text`, plutôt qu’un registre complet.

## Données du serveur

Lorsque l’API filtre, trie ou pagine les enregistrements, conservez ces paramètres dans l’état de requête de la
fonctionnalité. Transmettez à TanStack Table la page renvoyée et désactivez les transformations correspondantes
côté client. Cette configuration remplace les modèles de lignes client de l’exemple interactif :

```tsx
const features = tableFeatures({
  columnFilteringFeature,
  rowPaginationFeature,
  rowSortingFeature,
});

const table = useTable({
  features,
  data: response.rows,
  columns,
  manualFiltering: true,
  manualPagination: true,
  manualSorting: true,
  rowCount: response.rowCount,
  onColumnFiltersChange: setColumnFilters,
  onPaginationChange: setPagination,
  onSortingChange: setSorting,
  state: { columnFilters, pagination, sorting },
});
```

N’ajoutez pas `filteredRowModel`, `sortedRowModel` ou `paginatedRowModel` à `features` pour le comportement géré
par le serveur : TanStack suppose que `response.rows` reflète déjà la requête. Transmettez `pageCount` plutôt que
`rowCount` si l’API le fournit. `manualPagination` désactive aussi la réinitialisation habituelle de la page :
remettez donc `pagination.pageIndex` à `0` à chaque changement de filtre ou de tri distant, sinon l’API peut
renvoyer une page vide. Consultez
les guides TanStack sur le [filtrage](https://tanstack.com/table/latest/docs/guide/global-filtering),
le [tri](https://tanstack.com/table/latest/docs/guide/sorting) et la
[pagination](https://tanstack.com/table/latest/docs/guide/pagination) pour la couche de requête.

Affichez l’état de la requête près du tableau, et non dans des cellules sans rapport :

| État de la requête | Résultat recommandé |
| ------------------ | ------------------- |
| Chargement initial | Gardez les en-têtes de colonnes visibles et affichez une ligne de chargement étiquetée ou un squelette. |
| Nouvelle requête | Conservez les lignes actuelles, marquez la barre d’outils comme occupée et empêchez les requêtes en double. |
| Résultat vide | Expliquez s’il n’existe aucun enregistrement ou si les filtres ont supprimé toutes les correspondances. |
| Erreur | Gardez les contrôles de requête accessibles et proposez de répéter la même requête. |

## Ajouter des fonctionnalités

TanStack Table ne fournit pas d’interface. Choisissez l’état et les modèles de lignes qui correspondent à cette
vue de données, au lieu d’activer toutes les fonctionnalités d’une grille par défaut.

| Besoin | À ajouter à ce tableau |
| ------ | ---------------------- |
| Actions de ligne | Affichez un `Menu` dans une colonne d’actions ; les gestionnaires restent dans la fonctionnalité produit. |
| Sélection de lignes | Contrôlez `rowSelection`, configurez `getRowId` avec un identifiant d’enregistrement durable et affichez les contrôles moduix `Checkbox` dans une colonne de sélection. |
| Visibilité des colonnes | Contrôlez `columnVisibility` et exposez `column.toggleVisibility()` via un `Menu`. |
| Données du serveur | Conservez l’état de requête dans la route ou la couche de données. Utilisez `manualFiltering`, `manualSorting` et `manualPagination` uniquement pour les transformations gérées par l’API, puis transmettez les lignes de la réponse avec `rowCount` ou `pageCount`. |
| Grands jeux de données | N’ajoutez la virtualisation au corps du tableau qu’après l’avoir mesurée ; conservez la sémantique native de `table`, `thead`, `tbody`, `tr`, `th` et `td`. |

Le [guide des modèles de lignes](https://tanstack.com/table/latest/docs/guide/row-models) de TanStack
Table présente les transformations disponibles côté client. Son
[guide de sélection des lignes](https://tanstack.com/table/latest/docs/guide/row-selection) explique
l’état de sélection contrôlé et la sélection au niveau de la page, tandis que
l’[adaptateur React](https://tanstack.com/table/latest/docs/framework/react/react-table) documente
`useTable`. La page moduix [Table (en anglais)](https://moduix.dev/docs/table) décrit la structure
rendue et ses hooks de style.

Avec `manualPagination`, conservez l’état `rowSelection` complet pour les actions portant sur
plusieurs pages. Les modèles de lignes sélectionnées de TanStack ne peuvent renvoyer que les
enregistrements actuellement fournis au tableau, même lorsque l’état de sélection contient aussi des
identifiants provenant d’autres pages.

## Réutilisation

Si le même tableau produit apparaît à plusieurs endroits, extrayez ses colonnes, sa barre d’outils ou ses
contrôles de pagination dans des composants locaux à la fonctionnalité. Gardez une API propre au produit :
`PaymentsTable` est plus facile à maintenir qu’un `DataTable` généraliste qui tente d’anticiper chaque filtre,
réponse serveur, action ou règle de sélection.

## Accessibilité

Conservez les éléments natifs du tableau dans le rendu. Utilisez `Table.ColumnHeader` pour les en-têtes,
`Table.Cell` pour les données et une légende courte lorsque le titre voisin n’identifie pas les données. Les
contrôles interactifs dans les cellules nécessitent des noms accessibles descriptifs et les en-têtes triables
doivent exposer leur direction actuelle via `aria-sort`. Le champ de filtrage et les contrôles de sélection de
l’exemple interactif ont des noms accessibles explicites, plutôt que de dépendre du texte indicatif ou d’une icône.
