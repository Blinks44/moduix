# Tableau de données

`Data Table` est un modèle de composition, pas un composant exporté par moduix. Utilisez les parties
sémantiques et stylées de `Table` pour le balisage, puis TanStack Table v9 pour modéliser l’état de la
grille de données. La fonctionnalité produit possède ses enregistrements et contrôle l’état du tableau
lorsque celui-ci pilote une route ou une requête serveur. Chaque produit a des colonnes, des filtres,
des actions de ligne et des contrats serveur différents : gardez donc ce comportement près de la
fonctionnalité qui en a besoin.

La recette prête à copier ci-dessous est le même tableau interactif que celui de la page d’accueil.
Elle comprend la recherche, le tri, la visibilité des colonnes, la sélection des lignes, les actions
et la pagination ; remplacez ses enregistrements et actions d’exemple par les données de votre produit.

## Choisissez le tableau le plus simple qui convient

| Besoin | Point de départ |
| ------ | --------------- |
| Lignes et colonnes en lecture seule | Le composant sémantique [Table (documentation en anglais)](https://moduix.dev/docs/table) |
| Tri ou filtrage local d’un petit jeu de données | Table avec le modèle de lignes TanStack correspondant |
| Tri, filtrage ou pagination côté serveur | État de requête contrôlé avec les options manuelles de TanStack ci-dessous |
| Lignes virtualisées | Ajoutez la virtualisation uniquement après avoir mesuré un véritable problème de performances |

Ne copiez pas par défaut tous les contrôles de la recette complète. Supprimez la sélection, la
visibilité des colonnes, les actions ou la pagination si l’utilisateur ne peut pas exploiter cette
fonctionnalité.

## Construisez le modèle vous-même

Installez TanStack Table dans l’application qui possède le comportement de la grille de données :

```bash
npm install @tanstack/react-table@^9
```

`Table` provient déjà de `@moduix/react/table`. Il n’inclut volontairement pas TanStack Table, afin
que les applications qui n’ont besoin que d’un tableau sémantique ne paient pas le coût de la logique
d’une grille de données.

## Exemple de base

Définissez des entrées `ColumnDef<typeof features, Payment>` typées, déclarez les fonctionnalités
requises avec `tableFeatures()`, puis créez une instance de tableau avec `useTable`. Projetez ses
groupes d’en-têtes et ses cellules visibles dans l’anatomie du tableau moduix. Utilisez `flexRender`
pour les en-têtes et les cellules : les définitions de colonnes peuvent contenir des valeurs simples
ou des fonctions de rendu React.

## Conservez des données et des colonnes stables

Dans les exemples, `payments` et `columns` sont définis hors des composants, afin que TanStack Table
reçoive les mêmes références entre les rendus. Lorsque les données ou les colonnes dépendent des
props ou de l’état, utilisez `useMemo` pour le tableau résultant au lieu de le créer directement dans
le composant ou de transmettre `data.filter(...)` à `useTable`. De nouvelles références forcent
TanStack Table à recalculer et peuvent provoquer des boucles de rendu React. Consultez la
[FAQ](https://tanstack.com/table/latest/docs/faq) de TanStack pour l’explication complète.

## Largeurs de colonnes stables

Utilisez les éléments natifs `Table.ColumnGroup` et `Table.Column htmlWidth` pour les colonnes dont la
largeur doit rester stable. Associez-les à `table-layout: fixed` sur la racine du tableau : la colonne
restante occupe l’espace disponible, tandis qu’une icône de tri changeante ne peut pas redimensionner
sa colonne.

## Tri, filtrage, pagination et sélection

Ajoutez uniquement les fonctionnalités et les modèles de lignes TanStack nécessaires au tableau. Dans
l’exemple ci-dessous, le tri et les filtres de colonnes sont contrôlés dans l’état React, la colonne
d’e-mail est filtrée, les lignes sont sélectionnées selon leurs identifiants de paiement stables et
cinq lignes sont affichées par page.

TanStack Table v9 supprime les fonctions de filtrage et de tri inutilisées. Enregistrez dans
`tableFeatures()` uniquement les fonctions intégrées utilisées par le tableau : cette recette ajoute
`includesString`, `alphanumeric` et `text`, plutôt qu’un registre complet.

## Données du serveur

Lorsque l’API filtre, trie ou pagine les enregistrements, conservez ces valeurs dans l’état de requête
de la fonctionnalité. Transmettez la page renvoyée à TanStack Table et désactivez les transformations
correspondantes côté client. Cette configuration remplace les modèles de lignes côté client de
l’exemple interactif :

```tsx
const features = tableFeatures({
  columnFilteringFeature,
  rowPaginationFeature,
  rowSortingFeature,
});

const table = useTable({
  features,
  data: response.rows,
  columns,
  manualFiltering: true,
  manualPagination: true,
  manualSorting: true,
  rowCount: response.rowCount,
  onColumnFiltersChange: setColumnFilters,
  onPaginationChange: setPagination,
  onSortingChange: setSorting,
  state: { columnFilters, pagination, sorting },
});
```

N’ajoutez pas `filteredRowModel`, `sortedRowModel` ou `paginatedRowModel` à `features` pour le
comportement correspondant géré par le serveur : TanStack suppose que `response.rows` reflète déjà la requête.
Transmettez `pageCount` à la place de `rowCount` si c’est ce que fournit l’API. `manualPagination`
désactive aussi la réinitialisation habituelle de la page : remettez donc `pagination.pageIndex` à `0`
chaque fois qu’un filtre ou un tri distant change, sinon l’API peut renvoyer une page vide. Consultez
les guides TanStack sur le [filtrage](https://tanstack.com/table/latest/docs/guide/global-filtering),
le [tri](https://tanstack.com/table/latest/docs/guide/sorting) et la
[pagination](https://tanstack.com/table/latest/docs/guide/pagination) pour la couche de requête.

Affichez l’état de la requête près du tableau, et non dans des cellules sans rapport :

| État de la requête | Résultat recommandé |
| ------------------ | ------------------- |
| Chargement initial | Gardez les en-têtes de colonnes visibles et affichez une ligne de chargement étiquetée ou un squelette. |
| Nouvelle requête | Conservez les lignes actuelles, marquez la barre d’outils comme occupée et empêchez les requêtes en double. |
| Résultat vide | Expliquez s’il n’existe aucun enregistrement ou si les filtres ont supprimé toutes les correspondances. |
| Erreur | Gardez les contrôles de requête accessibles et proposez de répéter la même requête. |

## Ajoutez des fonctionnalités de manière réfléchie

TanStack Table ne fournit pas d’interface. Choisissez l’état et les modèles de lignes correspondant au
comportement de cette vue de données précise, au lieu d’activer par défaut toutes les fonctionnalités
d’une grille.

| Besoin | À ajouter à ce tableau |
| ------ | ---------------------- |
| Actions de ligne | Affichez un `Menu` dans une colonne d’actions ; les gestionnaires restent dans la fonctionnalité produit. |
| Sélection de lignes | Contrôlez `rowSelection`, configurez `getRowId` avec un identifiant d’enregistrement durable et affichez les contrôles moduix `Checkbox` dans une colonne de sélection. |
| Visibilité des colonnes | Contrôlez `columnVisibility` et exposez `column.toggleVisibility()` via un `Menu`. |
| Données du serveur | Conservez l’état de requête dans la route ou la couche de données. Utilisez `manualFiltering`, `manualSorting` et `manualPagination` uniquement pour les transformations gérées par l’API, puis transmettez les lignes de la réponse avec `rowCount` ou `pageCount`. |
| Grands jeux de données | N’ajoutez la virtualisation au corps du tableau qu’après l’avoir mesurée ; conservez la sémantique native de `table`, `thead`, `tbody`, `tr`, `th` et `td`. |

Le [guide des modèles de lignes](https://tanstack.com/table/latest/docs/guide/row-models) de TanStack
Table présente les transformations disponibles côté client. Son
[guide de sélection des lignes](https://tanstack.com/table/latest/docs/guide/row-selection) explique
l’état de sélection contrôlé et la sélection au niveau de la page, tandis que
l’[adaptateur React](https://tanstack.com/table/latest/docs/framework/react/react-table) documente
`useTable`. La page moduix [Table (en anglais)](https://moduix.dev/docs/table) décrit la structure
rendue et ses hooks de style.

Avec `manualPagination`, conservez l’état `rowSelection` complet pour les actions portant sur
plusieurs pages. Les modèles de lignes sélectionnées de TanStack ne peuvent renvoyer que les
enregistrements actuellement fournis au tableau, même lorsque l’état de sélection contient aussi des
identifiants provenant d’autres pages.

## Réutilisation après stabilisation du modèle

Si le même tableau produit apparaît à plusieurs endroits, extrayez ses colonnes, sa barre d’outils ou
ses contrôles de pagination dans des composants locaux à la fonctionnalité. Gardez l’API obtenue
propre au produit : `PaymentsTable` est plus facile à maintenir qu’un composant `DataTable` généraliste
qui tente d’anticiper chaque filtre, réponse serveur, action ou règle de sélection.

## Accessibilité

Conservez les parties natives du tableau dans le rendu. Utilisez `Table.ColumnHeader` pour les
en-têtes, `Table.Cell` pour les données et une légende courte lorsque le titre environnant
n’identifie pas les données. Les contrôles interactifs dans les cellules nécessitent des noms
accessibles descriptifs et les en-têtes triables doivent exposer leur direction actuelle via
`aria-sort`. Le champ de filtrage et les contrôles de sélection de l’exemple interactif ont des noms
accessibles explicites au lieu de dépendre du texte indicatif ou du texte d’une icône.
