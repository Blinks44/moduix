# Code de vérification

Utilisez cette recette lorsque votre application envoie un code à usage unique à l’adresse e-mail de
l’utilisateur. Elle réunit `Card`, `Field`, `Button` et `PinInput` pour former un formulaire complet.
`PinInput` conserve la valeur dans un champ natif masqué du formulaire, gère la navigation au clavier et
le collage, et active le remplissage automatique du code à usage unique sur mobile. Envoyez le formulaire
avec moins de six chiffres pour afficher l’erreur intégrée au champ. Cette vérification confirme uniquement
que les six chiffres ont été saisis. Votre application doit toujours vérifier le code sur le serveur.

## Utiliser la recette dans une route

Copiez le composant `VerificationCode` et sa feuille de styles, puis affichez-le dans la route qui gère la
vérification de l’adresse e-mail. Affichez le formulaire après avoir envoyé le code. `onSubmit` reçoit
l’événement natif du formulaire. Si vous envoyez le code à votre API depuis le navigateur, appelez
`event.preventDefault()`, lisez `new FormData(event.currentTarget).get('code')`, puis envoyez cette valeur
au serveur. Remplacez le lien `/sign-in` par la route de votre application.

L’aperçu interactif n’envoie volontairement aucune requête au serveur. Son gestionnaire appelle
`event.preventDefault()` afin de rester sur la page. Dans la recette copiée, passez le gestionnaire qui
connecte le formulaire à votre API.

## Gérer les états en production

- Pendant la vérification, désactivez le bouton d’envoi pour éviter les requêtes en double.
- Si le serveur refuse le code, conservez les chiffres saisis et affichez l’erreur via `Field`. L’erreur
  intégrée à cet exemple vérifie uniquement que les six chiffres sont présents.
- Si le code a expiré, indiquez à l’utilisateur qu’il doit en demander un nouveau et ajoutez une action de
  renvoi. Prévoyez un court délai, annoncez l’envoi du nouveau code et faites respecter la limite de
  tentatives par le serveur. Le compte à rebours côté client ne remplace pas la vérification du serveur.
