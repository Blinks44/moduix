# Inscription

Utilisez cette recette comme point de départ pour un écran d’inscription. Elle associe `Card`, `Field`,
`Input`, `Checkbox` et `Button`, et confie au navigateur la validation des champs obligatoires, du format
de l’adresse e-mail et de l’acceptation des conditions. La recette ne se connecte à aucun service
d’authentification et ne compare pas les deux mots de passe : ajoutez cette logique dans le gestionnaire
`onSubmit`.

L’aperçu interactif utilise le paquet React. Les onglets de code présentent des implémentations natives pour React et Solid avec les mêmes styles.

## Utiliser la recette dans une route

Copiez le code source et le CSS de la recette depuis les onglets ci-dessus, puis importez `SignUp` depuis
le fichier copié. Le navigateur vérifie les contraintes natives avant d’appeler `onSubmit`. Utilisez ce
gestionnaire pour comparer les deux mots de passe et envoyer les données à votre serveur d’inscription.

Les champs portent les noms `name`, `email`, `password`, `confirm-password` et `terms`, qui sont donc
les clés disponibles dans `FormData`. Remplacez `/api/sign-up` et le chemin d’importation par ceux de
votre application.

## Avant la mise en production

Le code source copié reste volontairement minimal. Ajoutez le comportement et l’affichage des erreurs
nécessaires à votre application :

- Affichez clairement les exigences liées au mot de passe et ajoutez, si nécessaire, des contraintes comme
  `minLength` ou `pattern` aux champs copiés. Appliquez les mêmes règles côté serveur.
- Désactivez le bouton d’envoi pendant la requête. En cas d’échec, conservez les valeurs saisies pour permettre à
  l’utilisateur de les corriger et de réessayer.
- Affichez l’erreur renvoyée par le serveur à côté du champ concerné. Affichez les erreurs réseau ou
  inattendues au niveau du formulaire dans un élément doté de `role="alert"` et laissez la possibilité de
  réessayer.
- Remplacez `/terms`, `/privacy` et `/sign-in` par les routes de votre application.
- Après une inscription réussie, enchaînez avec l’étape prévue par votre parcours : connectez l’utilisateur,
  demandez la vérification de l’adresse e-mail ou redirigez vers une page de confirmation.
