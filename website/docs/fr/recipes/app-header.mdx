# En-tête d’application

Utilisez cet en-tête lorsque l’application n’a qu’un niveau de navigation clair et quelques actions
globales. Sa mise en page aérée permet de repérer rapidement le produit, l’espace de travail actif,
la navigation et les contrôles du compte, sans transformer l’en-tête en barre d’outils.

## Personnalisation

La recette utilise de vrais liens pour chaque action de navigation et `aria-current="page"` pour la
destination active. Remplacez les données de démonstration par les valeurs de votre routeur et de
l’état du compte.

| À remplacer | Par la valeur de votre application |
| ----------- | ---------------------------------- |
| Orbit et Acme Studio | Le lien vers l’accueil du produit et l’espace de travail actif |
| Liens de navigation | Les liens du routeur ; définissez `aria-current="page"` selon la route actuelle |
| Contrôle de recherche | Un déclencheur de Command Palette avec les routes et actions de l’application |
| Avatar et informations du compte | Les données de l’utilisateur authentifié et une URL d’image gérée par l’application |
| Liens du menu du compte | Les routes du profil, des paramètres, de l’aide et les autres pages réellement utiles aux utilisateurs |

Si votre routeur fournit un composant Link, passez-le via `Button asChild` ou `Menu.Item asChild` plutôt que
d’imbriquer deux éléments interactifs. Conservez le fallback de l’avatar afin que le contrôle du compte reste
identifiable pendant le chargement de l’image ou lorsqu’aucune image n’est disponible.

## Comportement adaptatif

Sous 48rem, la navigation centrée passe dans un véritable `Menu` au lieu de disparaître. Sous 36rem,
les libellés de l’espace de travail et du compte sont masqués, tandis que les boutons à icône conservent
un nom accessible. Choisissez le modèle de navigation adapté à votre application pour les groupes ou les
routes imbriquées.
