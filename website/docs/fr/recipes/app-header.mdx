# En-tête d’application

Cette recette montre comment composer un en-tête d’application responsive avec `Avatar`, `Button`,
`CommandPalette` et `Menu`. Elle réunit le lien vers le produit, l’espace de travail actif, la
navigation principale, la recherche et les actions du compte dans une mise en page compacte.

## Contenu de la recette

- Une navigation principale qui marque la destination active avec `aria-current="page"`.
- Une `CommandPalette` qui filtre les éléments de navigation et les actions de l’espace de travail par groupe.
- Un menu de compte avec des liens vers le profil, les paramètres de l’espace de travail et l’aide.
- Un `Menu` distinct pour la navigation principale sur les petits écrans.
- Des noms accessibles pour les contrôles composés uniquement d’une icône et un affichage de secours pour l’avatar.

L’aperçu interactif utilise le paquet React. Les onglets de code présentent des implémentations natives pour React et Solid avec les mêmes styles.

## Installation

Installez les composants moduix utilisés par la recette ainsi que `lucide-react` pour les icônes. Les
onglets « Composant » et « Styles » contiennent les fichiers à copier dans votre application.

## Dans votre application

La démonstration utilise des ancres comme `#overview`, et la sélection d’une commande met à jour
`window.location.hash`. L’exemple peut ainsi fonctionner sans routeur. Remplacez les ancres et le
gestionnaire de sélection par la navigation de votre routeur.

Placez la recette dans la mise en page qui gère la navigation principale et l’état du compte.
Conservez `aria-current="page"` uniquement sur le lien correspondant à la route actuelle.

## Personnalisation

Remplacez les données de démonstration par vos routes, l’état de l’espace de travail et les données
de l’utilisateur authentifié.

| À remplacer | Par la valeur de votre application |
| ----------- | ---------------------------------- |
| Orbit et Acme Studio | Le lien vers l’accueil du produit et le nom de l’espace de travail actif |
| Ancres comme `#overview` | Vos routes et la navigation du routeur lors de la sélection d’une commande |
| Liens de navigation | Les liens du routeur avec `aria-current="page"` selon la route actuelle |
| Commandes de recherche | Les routes et actions utiles à vos utilisateurs, regroupées de façon claire |
| Avatar et informations du compte | Les données de l’utilisateur authentifié et une URL d’image gérée par l’application |
| Liens du menu du compte | Les routes du profil, des paramètres, de l’aide et les autres pages utiles aux utilisateurs |

Si votre routeur fournit un composant `Link`, utilisez `Button asChild` ou `MenuItem asChild` pour
que le lien du routeur reste l’élément interactif. N’imbriquez pas un lien dans un bouton. Conservez
`AvatarFallback` afin que le contrôle du compte reste identifiable pendant le chargement de l’image
ou lorsqu’aucune image n’est disponible.

## Comportement adaptatif

Le module CSS définit trois seuils :

- Sous `64rem`, l’espace de travail et son indicateur sont masqués pour laisser plus de place aux contrôles principaux.
- Sous `48rem`, la navigation en ligne est remplacée par un bouton qui ouvre `Menu`.
- Sous `36rem`, le nom, le rôle et la flèche du compte sont masqués, tandis que l’avatar reste visible.

Adaptez ces seuils et le modèle de navigation mobile si votre application comporte davantage de liens
ou des routes imbriquées.
