## Référence de l’API

Ark UI ne fournit pas de primitive dédiée aux tableaux. moduix construit `Table` avec la
[fabrique Ark](https://ark-ui.com/docs/guides/composition#the-ark-factory) officielle et suit les recommandations
d’Ark concernant la [composition](https://ark-ui.com/docs/guides/composition), les
[styles](https://ark-ui.com/docs/guides/styling) et les [refs](https://ark-ui.com/docs/guides/ref).

Chaque partie rend par défaut l’élément HTML natif correspondant, accepte ses propriétés et
`className`, transmet sa ref et prend en charge `asChild`. Avec `asChild`, fournissez un seul
élément sémantique. `Table.Empty` fait exception à cette composition habituelle : `asChild` y remplace
uniquement la cellule `td` générée.

## Exemple de base

Si le tableau risque de dépasser la largeur de son conteneur, enveloppez-le dans `Table.ScrollArea`. Composez
ensuite `Table` avec `Table.Header`, `Table.Body`, `Table.Row` et les parties correspondantes pour les en-têtes et
les cellules. Cette approche convient aux factures, aux synthèses et aux jeux de données en lecture seule des
interfaces d’administration.

## Anatomie

La composition recommandée reste proche du balisage natif des tableaux :

```text
Table.ScrollArea (optional)
└─ Table / Table.Root
   ├─ Table.ColumnGroup (optional)
   │  └─ Table.Column
   ├─ Table.Caption (optional)
   ├─ Table.Header
   │  └─ Table.Row
   │     └─ Table.ColumnHeader
   ├─ Table.Body
   │  ├─ Table.Row
   │  │  └─ Table.Cell
   │  └─ Table.Empty (optional)
   └─ Table.Footer (optional)
```

| Partie                  | Rôle                                                                            |
| ----------------------- | ------------------------------------------------------------------------------- |
| `Table` / `Table.Root`  | Racine native `table`. Gère la typographie, les séparateurs et les attributs d’état. |
| `Table.ScrollArea`      | Conteneur facultatif avec bordure et défilement horizontal.                    |
| `Table.ColumnGroup`     | Élément natif `colgroup` pour définir la largeur des colonnes.                 |
| `Table.Column`          | Élément natif `col`. Accepte `htmlWidth`.                                      |
| `Table.Caption`         | Légende facultative au-dessus ou au-dessous du tableau via `side`.             |
| `Table.Header`          | Élément natif `thead` pour les en-têtes de colonne.                             |
| `Table.Body`            | Élément natif `tbody` pour les lignes de données.                               |
| `Table.Footer`          | Élément natif `tfoot` pour les lignes de synthèse.                              |
| `Table.Row`             | Élément natif `tr` avec des séparateurs.                                        |
| `Table.ColumnHeader`    | Élément natif `th`. Accepte `numeric`.                                          |
| `Table.Cell`            | Élément natif `td`. Accepte `numeric`.                                          |
| `Table.Empty`           | Ligne et cellule d’état vide pratiques dans `Table.Body`.                      |

## Composition

### Composition recommandée

Pour la plupart des tableaux de données en lecture seule, utilisez les parties sémantiques et ajoutez
`Table.ScrollArea` lorsque le tableau a besoin d’un conteneur bordé avec défilement horizontal.

Utilisez `numeric` sur `Table.ColumnHeader` et `Table.Cell` pour les montants, les quantités, les pourcentages, les
latences et autres valeurs numériques. Utilisez `Table.Caption` pour un titre ou une description courte, et
`Table.Footer` lorsque la dernière ligne contient des totaux ou des agrégats. Utilisez `striped`, `interactive`,
`showColumnBorder`, `stickyHeader` et `size` / `variant` pour modifier l’affichage sans ajouter d’état au tableau.

### Quand créer une composition personnalisée

N’utilisez pas `Table.ScrollArea` lorsque le conteneur parent gère déjà le défilement, les espacements, la bordure ou
le fond. Conservez `Table` et gérez ces responsabilités dans votre propre composant ou balisage d’enveloppe.

`Table` ne gère ni le tri, ni le filtrage, ni la sélection, ni la pagination, ni la virtualisation, ni l’état des
actions de ligne. Considérez-le comme la base visuelle et sémantique sur laquelle des abstractions de tableau de
plus haut niveau peuvent s’appuyer. Pour l’état et le rendu de TanStack Table, consultez le guide de composition
[Data Table](/recipes/data-table).

### Propriétés par défaut

Toutes les parties acceptent les propriétés natives de l’élément correspondant, ainsi que `className` et `asChild`,
comme indiqué plus haut. Elles transmettent également les refs à l’élément rendu.

| Composant            | Propriété          | Par défaut     | Remarques                                                           |
| -------------------- | ------------------ | -------------- | ------------------------------------------------------------------- |
| `Table`              | `interactive`      | `false`        | Active la mise en évidence au survol des lignes de contenu.         |
| `Table`              | `showColumnBorder` | `false`        | Ajoute des bordures entre les colonnes visibles.                    |
| `Table`              | `size`             | `'md'`         | Accepte `'sm'`, `'md'` et `'lg'`.                                   |
| `Table`              | `stickyHeader`     | `false`        | Rend `Table.Header` fixe dans un conteneur défilant.                |
| `Table`              | `striped`          | `false`        | Alterne le fond des lignes de contenu paires, sauf les lignes vides. |
| `Table`              | `variant`          | `'line'`       | Accepte `'line'` et `'outline'`.                                    |
| `Table.Caption`      | `side`             | `'bottom'`     | Accepte `'top'` et `'bottom'`.                                      |
| `Table.Column`       | `htmlWidth`        | -              | Correspond à l’attribut natif `width` de `col`.                     |
| `Table.ColumnHeader` | `numeric`          | `false`        | Aligne le contenu en fin de ligne et utilise des chiffres tabulaires. |
| `Table.Cell`         | `numeric`          | `false`        | Aligne le contenu en fin de ligne et utilise des chiffres tabulaires. |
| `Table.Empty`        | `colSpan`          | obligatoire    | Doit correspondre au nombre actuel de colonnes.                      |
| `Table.Empty`        | `children`         | `'No results.'` | Texte affiché en l’absence de contenu.                              |

### Comportement

- `Table.Empty` affiche une ligne complète pour l’état vide : transmettez donc le nombre de colonnes du corps via
  `colSpan`. Son option `asChild` remplace uniquement la cellule générée : fournissez donc un unique `td`
  sémantique ; composez directement `Table.Row` et `Table.Cell` lorsque la ligne doit être personnalisée.
  La ligne générée expose `data-empty` et ne reçoit ni les rayures ni les styles interactifs.
- Les lignes d’en-tête et de contenu affichent un séparateur inférieur commun. La dernière ligne de contenu n’a pas
  de bordure.
- Avec `interactive`, les lignes de contenu reçoivent un arrière-plan discret au survol et conservent ce contexte
  lorsqu’un contrôle qu’elles contiennent reçoit le focus au clavier.
- `Table.Caption` hérite d’une typographie atténuée et ajoute un padding inline afin de ne pas toucher les bords du
  tableau.

### Accessibilité

`Table` utilise des éléments de tableau natifs : utilisez donc les attributs HTML habituels pour exprimer les
relations entre les en-têtes et les cellules. Ajoutez `scope="col"` aux en-têtes de colonne, utilisez
`Table.Caption` pour un nom ou une description accessible courte, et utilisez `id` / `headers` lorsqu’un tableau
complexe nécessite des associations explicites. `Table` n’ajoute ni navigation au clavier, ni sélection, ni gestion
particulière du focus.

### Points d’accroche CSS

Utilisez la partie ou l’attribut qui contrôle l’aspect visuel concerné :

- `className` sur `Table.ScrollArea` pour remplacer la bordure, le rayon et le fond du conteneur
- `className` sur `Table` pour la typographie du tableau et les contraintes de largeur
- `data-slot="table-root"`, `table-scroll-area`, `table-column-group`, `table-column`, `table-caption`,
  `table-header`, `table-body`, `table-footer`, `table-row`, `table-column-header`, `table-cell` et `table-empty` pour
  cibler chaque partie
- `data-side="top" | "bottom"` sur `Table.Caption` pour styliser la position de la légende
- `data-numeric` sur `Table.ColumnHeader` et `Table.Cell` pour cibler les colonnes numériques
- `data-empty` sur la ligne générée par `Table.Empty` pour cibler la ligne vide
- `data-size`, `data-variant`, `data-striped`, `data-interactive`, `data-sticky-header` et
  `data-show-column-border` sur `Table` pour les styles d’état au niveau de la racine
- `data-sticky="start" | "end"` sur `Table.ColumnHeader` et `Table.Cell` pour les colonnes fixes
