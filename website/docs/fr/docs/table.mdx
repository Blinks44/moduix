## Référence de l’API

Ark UI ne fournit pas de primitive dédiée aux tableaux. moduix construit `Table` avec la
[fabrique Ark](https://ark-ui.com/docs/guides/composition#the-ark-factory) officielle et suit les recommandations
d’Ark concernant la [composition](https://ark-ui.com/docs/guides/composition), les
[styles](https://ark-ui.com/docs/guides/styling) et les [refs](https://ark-ui.com/docs/guides/ref).

Chaque partie rend par défaut l’élément HTML natif correspondant, accepte ses propriétés, `className`
en React ou `class` en Solid, transmet sa ref et prend en charge `asChild`. Avec `asChild`, fournissez
un seul élément sémantique. `TableEmpty` fait exception à cette composition habituelle : `asChild` y
remplace uniquement la cellule `td` générée.

## Anatomie

La composition recommandée reste proche du balisage natif des tableaux :

```text
TableScrollArea (optional)
└─ Table
   ├─ TableColumnGroup (optional)
   │  └─ TableColumn
   ├─ TableCaption (optional)
   ├─ TableHeader
   │  └─ TableRow
   │     └─ TableColumnHeader
   ├─ TableBody
   │  ├─ TableRow
   │  │  └─ TableCell
   │  └─ TableEmpty (optional)
   └─ TableFooter (optional)
```

| Partie                  | Rôle                                                                            |
| ----------------------- | ------------------------------------------------------------------------------- |
| `Table`            | Racine native `table`. Gère la typographie, les séparateurs et les attributs d’état. |
| `TableScrollArea`      | Conteneur facultatif avec bordure et défilement horizontal.                    |
| `TableColumnGroup`     | Élément natif `colgroup` pour définir la largeur des colonnes.                 |
| `TableColumn`          | Élément natif `col`. Accepte `htmlWidth`.                                      |
| `TableCaption`         | Légende facultative au-dessus ou au-dessous du tableau via `side`.             |
| `TableHeader`          | Élément natif `thead` pour les en-têtes de colonne.                             |
| `TableBody`            | Élément natif `tbody` pour les lignes de données.                               |
| `TableFooter`          | Élément natif `tfoot` pour les lignes de synthèse.                              |
| `TableRow`             | Élément natif `tr` avec des séparateurs.                                        |
| `TableColumnHeader`    | Élément natif `th`. Accepte `numeric`.                                          |
| `TableCell`            | Élément natif `td`. Accepte `numeric`.                                          |
| `TableEmpty`           | Ligne et cellule d’état vide pratiques dans `TableBody`.                      |

## Composition

Utilisez `TableScrollArea` lorsque le tableau a besoin d’un conteneur bordé avec défilement horizontal.
Ne l’utilisez pas si la mise en page parente gère déjà le défilement, les espacements, la bordure ou
la surface ; placez alors les parties natives du tableau dans votre propre conteneur.

`TableEmpty` crée une ligne vide complète dans `TableBody`, son `colSpan` obligatoire doit donc
correspondre au nombre actuel de colonnes. Son `asChild` remplace uniquement le `td` généré ; composez
directement `TableRow` et `TableCell` lorsque la ligne elle-même doit être personnalisée. `Table`
gère uniquement la présentation : le tri, le filtrage, la sélection, la pagination, la virtualisation
et les actions de ligne appartiennent à une composition de niveau supérieur, comme [Data Table](/recipes/data-table).

### Accessibilité

`Table` utilise des éléments de tableau natifs : utilisez donc les attributs HTML habituels pour exprimer les
relations entre les en-têtes et les cellules. Ajoutez `scope="col"` aux en-têtes de colonne, utilisez
`TableCaption` pour un nom ou une description accessible courte, et utilisez `id` / `headers` lorsqu’un tableau
complexe nécessite des associations explicites. `Table` n’ajoute ni navigation au clavier, ni sélection, ni gestion
particulière du focus.

`data-scope` et `data-part`, les attributs `data-side` et `data-numeric`, ainsi que les variables
CSS `--moduix-table-*` présentées ci-dessous. Les variantes Tailwind utilisent des classes utilitaires
natives et les classes du consommateur ; les variables ci-dessous s’appliquent aux variantes CSS Modules.

### Points d’accroche CSS

Utilisez la partie ou l’attribut qui contrôle l’aspect visuel concerné :

- `className` sur `TableScrollArea` pour remplacer la bordure, le rayon et le fond du conteneur
- `className` sur `Table` pour la typographie du tableau et les contraintes de largeur
- `data-slot="table-root"`, `table-scroll-area`, `table-column-group`, `table-column`, `table-caption`,
  `table-header`, `table-body`, `table-footer`, `table-row`, `table-column-header`, `table-cell` et `table-empty` pour
  cibler chaque partie
- `data-side="top" | "bottom"` sur `TableCaption` pour styliser la position de la légende
- `data-numeric` sur `TableColumnHeader` et `TableCell` pour cibler les colonnes numériques
- `data-empty` sur la ligne générée par `TableEmpty` pour cibler la ligne vide
- `data-size`, `data-variant`, `data-striped`, `data-interactive`, `data-sticky-header` et
  `data-show-column-border` sur `Table` pour les styles d’état au niveau de la racine
- `data-sticky="start" | "end"` sur `TableColumnHeader` et `TableCell` pour les colonnes fixes
