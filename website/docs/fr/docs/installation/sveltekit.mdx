# SvelteKit

Ce guide part d’une application SvelteKit 3 existante, créée avec `sv create`. SvelteKit rend les
composants Svelte sur le serveur et les hydrate dans le navigateur.

## Choisir votre configuration

- **Framework :** Svelte 5.29 ou une version ultérieure de la branche 5.x, fourni par SvelteKit.
- **Styles :** CSS Modules ou Tailwind CSS v4, déjà configuré dans l’application.
- **Distribution :** paquet ou code source copié avec la CLI shadcn.

Choisissez Svelte dans la [configuration du paquet](/docs/quick-start#installer-le-paquet) ou la
[configuration shadcn](/docs/quick-start#installer-avec-la-cli-shadcn) commune. SvelteKit utilise
`@moduix/svelte` et `@moduix/svelte-tailwind`, ou les espaces de noms de registre `@moduix-svelte` et
`@moduix-svelte-tailwind`.

Les paquets Svelte publient le code source `.svelte` sous la condition d’export `svelte`. Le plugin
Vite de SvelteKit le compile avec l’application pour le serveur et le navigateur, CSS Modules des
composants compris : le paquet n’a donc besoin d’aucune configuration Vite ou SSR supplémentaire.

## Installation avec la CLI shadcn

Effectuez la [configuration shadcn](/docs/quick-start#installer-avec-la-cli-shadcn) commune avec
l’espace de noms Svelte correspondant à vos styles. Conservez `rsc: false` ; utilisez la CLI `shadcn`
présentée ici avec le registre moduix.

Le code du registre importe les fichiers partagés via `@/lib/moduix`, tandis que SvelteKit fournit
`#lib` pour `src/lib`. Associez `@/*` à `src/*` dans le fichier racine `tsconfig.json` pour
TypeScript et la CLI, et conservez la configuration générée par SvelteKit dans `extends` :

```json title="tsconfig.json"
{
  "extends": "$app/tsconfig",
  "compilerOptions": {
    "strict": true,
    "paths": {
      "@/*": ["./src/*"]
    }
  },
  "include": ["src", "vite.config.ts"]
}
```

SvelteKit 3 lit sa configuration dans `sveltekit({...})` de `vite.config.ts`, et non dans
`svelte.config.js`. Ajoutez l’alias d’exécution à la configuration Vite en conservant les options
existantes du plugin :

```ts title="vite.config.ts"
import { fileURLToPath, URL } from 'node:url';
import { sveltekit } from '@sveltejs/kit/vite';
import { defineConfig } from 'vite';

export default defineConfig({
  plugins: [
    sveltekit({
      // Keep your adapter and other SvelteKit options here.
    }),
  ],
  resolve: {
    alias: {
      '@': fileURLToPath(new URL('./src', import.meta.url)),
    },
  },
});
```

Pour Tailwind, définissez `tailwind.css` sur `src/routes/layout.css` dans `components.json` avant
d’ajouter un composant, et laissez `tailwind.config` vide pour la v4.

## Vérifier

Démarrez le serveur de développement, puis compilez l’application pour la production et vérifiez-la
en mode aperçu. La réponse initiale du serveur doit contenir l’Accordion et ses styles. Dans le
navigateur, le composant doit s’hydrater sans avertissement et répondre au clavier et au pointeur.
Avec le registre, vérifiez que les imports se résolvent dans `src/components` et `src/lib`.

Consultez la documentation officielle de SvelteKit sur la
[création de projet](https://svelte.dev/docs/kit/creating-a-project), la
[configuration](https://svelte.dev/docs/kit/configuration) et les
[adaptateurs](https://svelte.dev/docs/kit/adapters).
