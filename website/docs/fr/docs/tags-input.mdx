## Choisir le bon composant

Utilisez `TagsInput` lorsque l’utilisateur doit saisir et modifier une liste de valeurs textuelles
dans un même contrôle de formulaire.

- Choisissez **`TagsInput`** pour des libellés, compétences, filtres, destinataires, sujets et autres listes de chaînes saisies librement.
- Choisissez **`Tag`** lorsque l’interface affiche seulement un tag existant et peut proposer une action de suppression distincte.
- Choisissez **`Combobox`** lorsque l’utilisateur doit sélectionner des valeurs dans une collection connue et que le filtrage est l’interaction principale.

## Anatomie

```text
TagsInput / TagsInput.Root
├─ TagsInput.Label
├─ TagsInput.Control
│  ├─ TagsInput.Items
│  └─ TagsInput.Item[index, value]
│     ├─ TagsInput.ItemPreview
│     │  ├─ TagsInput.ItemText
│     │  └─ TagsInput.ItemDeleteTrigger
│     └─ TagsInput.ItemInput
│  ├─ TagsInput.Input
│  └─ TagsInput.ClearTrigger
└─ champ de formulaire natif masqué (automatique)
```

| Partie                                  | Rôle                                                                    |
| --------------------------------------- | ----------------------------------------------------------------------- |
| `TagsInput` / `TagsInput.Root`          | Gère l’état, les valeurs, la saisie, la validation et l’intégration au formulaire. |
| `TagsInput.RootProvider`                | Rend le champ à partir de l’état renvoyé par `useTagsInput` d’Ark.      |
| `TagsInput.Label`                       | Libellé accessible du champ de tags.                                    |
| `TagsInput.Control`                     | Conteneur visible des tags, du champ de saisie et du déclencheur d’effacement. |
| `TagsInput.Items`                       | Rendu standard des tags modifiables à partir des valeurs courantes.    |
| `TagsInput.Item`                        | Un tag. Transmettez `index` et `value`.                                 |
| `TagsInput.ItemContext`                 | État du tag courant accessible via un render prop.                      |
| `TagsInput.ItemPreview`                 | Affichage du tag en dehors du mode d’édition.                           |
| `TagsInput.ItemText`                    | Texte visible du tag.                                                   |
| `TagsInput.ItemDeleteTrigger`           | Supprime un tag ; moduix fournit par défaut une icône de fermeture compacte. |
| `TagsInput.ItemInput`                   | Champ utilisé pour modifier un tag sur place.                           |
| `TagsInput.Input`                       | Champ de saisie des nouveaux tags.                                      |
| `TagsInput.ClearTrigger`                | Efface tous les tags ; moduix utilise par défaut le `CloseButton.Root` partagé. |
| `TagsInput.Context`                     | Accès à l’état racine dans l’arborescence du composant via un render prop. |
| `useTagsInputContext`                   | Donne accès à l’état et aux méthodes de la racine depuis un descendant. |
| `useTagsInputItemContext`               | Donne accès à l’état du tag courant dans `TagsInput.Item`.              |
| `useTagsInput` de moduix + `RootProvider` | Gestion externe de l’état et méthodes impératives.                     |

## Composition

### Composition recommandée

Utilisez la forme courte `<TagsInput>`, équivalente à `<TagsInput.Root>`. Placez
`TagsInput.Items`, `TagsInput.Input` et `TagsInput.ClearTrigger` dans `TagsInput.Control`.
Vous obtenez ainsi le comportement standard des tags modifiables et conservez le champ de formulaire
natif masqué.

Pour participer à l’envoi d’un formulaire, transmettez `name` à la racine. Utilisez `form` lorsque
le formulaire associé se trouve en dehors de l’arborescence DOM du composant.

### Quand personnaliser la composition

Utilisez `TagsInput.Context` et les parties de bas niveau lorsque les tags nécessitent un contenu ou
des actions personnalisés. Parcourez `tagsInput.value`, créez un `TagsInput.Item` pour chaque valeur
en lui passant `index` et `value`, puis conservez `ItemInput` dans l’élément si la modification sur
place doit rester disponible. Utilisez `ItemContext` ou `useTagsInputItemContext` lorsque le contenu
personnalisé dépend de l’état du tag courant.

Utilisez `TagsInput.RootProvider` avec `useTagsInput` de moduix lorsque l’état ou des méthodes
impératives comme `addValue`, `setValue`, `clearValue`, `setInputValue` ou `focus` doivent être
accessibles en dehors de l’arborescence visible du champ. Utilisez `ids` lorsque `TagsInput` partage
un champ ou un contrôle avec une autre primitive Ark, comme `Combobox`.

Chaque partie primitive prend en charge `asChild` avec un seul enfant sémantique qui relaie ses
propriétés et sa `ref`. Lorsque la racine utilise `asChild`, cet enfant doit aussi rendre ses
`children` afin que moduix puisse ajouter le champ de formulaire natif masqué. `TagsInput.Items`
est un rendu pratique qui n’accepte pas les propriétés des parties ; utilisez les parties de bas
niveau pour personnaliser la structure des tags.

### Propriétés par défaut

| Propriété            | Valeur par défaut         | Remarques                                                               |
| -------------------- | ------------------------- | ----------------------------------------------------------------------- |
| `defaultValue`       | `[]`                      | Tableau initial de tags en mode non contrôlé.                            |
| `value`              | -                         | Tableau contrôlé de tags. Mettez-le à jour avec `onValueChange(details).value`. |
| `defaultInputValue`  | `''`                      | Valeur initiale du champ en mode non contrôlé.                           |
| `inputValue`         | -                         | Valeur contrôlée du champ de saisie.                                     |
| `delimiter`          | `','`                     | Chaîne ou expression régulière utilisée pour les touches séparatrices et le fractionnement du texte collé. |
| `max`                | `Infinity`                | Nombre maximal de tags.                                                  |
| `maxLength`          | -                         | Nombre maximal de caractères acceptés par le champ de saisie.            |
| `allowOverflow`      | `false`                   | Autorise le dépassement de `max` tout en marquant la racine comme invalide. |
| `allowDuplicates`    | `false`                   | Autorise l’ajout plusieurs fois d’une même chaîne.                       |
| `editable`           | `true`                    | Permet de modifier un tag après lui avoir donné le focus, avec Entrée ou par double-clic. |
| `addOnPaste`         | `false`                   | Fractionne le texte collé en tags avec `delimiter`.                      |
| `blurBehavior`       | -                         | Définissez `"add"` pour ajouter la valeur saisie à la perte du focus ou `"clear"` pour l’abandonner. |
| `sanitizeValue`      | `(value) => value.trim()` | Normalise chaque valeur avant sa validation et son ajout.                |

Les options `disabled`, `invalid`, `readOnly`, `required` et `autoFocus` sont désactivées par défaut.
Utilisez `placeholder` pour le champ de saisie et `translations` pour
les libellés accessibles.

### Comportement

`onValueChange(details)`, `onInputValueChange(details)`, `onHighlightChange(details)` et
`onValueInvalid(details)` reçoivent les objets `details` d’Ark. `validate(details)` accepte ou rejette
le nouveau tag, tandis que `sanitizeValue(value)` le normalise avant sa validation et son ajout.
Les callbacks `onFocusOutside`, `onInteractOutside` et `onPointerDownOutside` reçoivent les événements
correspondants déclenchés en dehors du composant.

`Field.Root` et `Fieldset.Root` peuvent transmettre les états `disabled`, `invalid`, `required` et
`readOnly` via le contexte Ark. Le déclencheur d’effacement par défaut utilise `CloseButton.Root`
via la composition `asChild` d’Ark ; la suppression d’un tag conserve un bouton à icône plus compact.

### Sélecteurs de style

- La racine et `RootProvider` exposent `data-slot="tags-input-root"` et `data-slot="tags-input-root-provider"`.
- Les parties Ark conservent `data-scope="tags-input"` et leurs valeurs `data-part` de l’anatomie.
- Pour cibler les états, utilisez `data-disabled`, `data-readonly`, `data-invalid`, `data-focus`, `data-empty`, `data-required`, `data-value` et `data-highlighted` sur les parties où Ark les émet.
- Les déclencheurs de suppression et d’effacement exposent des sélecteurs `data-slot` stables. La suppression d’un tag utilise une icône compacte ; l’effacement complet reprend le style partagé de `CloseButton.Root`.
- `TagsInput.ClearTrigger` reste à l’extrémité du contrôle lorsque les lignes de tags passent à la ligne.
- En lecture seule, moduix masque le champ de saisie et le déclencheur d’effacement ; seuls les tags en lecture seule restent visibles.

## Accessibilité

Ark gère le lien avec le libellé, la mise en évidence et la modification des tags, leur suppression,
le collage et le champ de formulaire masqué. Le champ masqué de la racine sérialise la liste des tags
pour l’envoi natif du formulaire ; transmettez `name` et, si nécessaire, `form` pour l’associer au
bon formulaire.

### Prise en charge du clavier

- `Entrée` dans le champ de saisie ajoute sa valeur courante. `Entrée` sur un tag mis en évidence lance son édition.
- Un double-clic sur un tag lance également son édition lorsque `editable` vaut `true`.
- Lorsque le champ de saisie est vide ou que le curseur se trouve au début, `Flèche gauche` et `Flèche droite` déplacent le focus visuel entre les tags.
- `Retour arrière` et `Suppr` suppriment le tag mis en évidence. `Retour arrière` supprime aussi le dernier tag lorsque le champ est vide.
- Avec `addOnPaste`, `Control+V` ajoute les valeurs collées après les avoir séparées avec `delimiter`.
