## Choisir le bon composant

Utilisez `TagsInput` lorsqu’un utilisateur doit saisir et gérer une liste de valeurs texte modifiables
dans un même contrôle de formulaire.

- Choisissez **`TagsInput`** pour des libellés, compétences, filtres, destinataires, sujets et autres listes saisies librement.
- Choisissez **`Tag`** lorsque l’interface affiche uniquement un token existant, avec éventuellement une action de suppression séparée.
- Choisissez **`Combobox`** lorsque l’utilisateur sélectionne une valeur dans une collection connue et que le filtrage est central.

## Anatomie

```text
TagsInput
├─ TagsInputLabel
├─ TagsInputControl
│  ├─ TagsInputItems
│  └─ TagsInputItem[index, value]
│     ├─ TagsInputItemPreview
│     │  ├─ TagsInputItemText
│     │  └─ TagsInputItemDeleteTrigger
│     └─ TagsInputItemInput
│  ├─ TagsInputInput
│  └─ TagsInputClearTrigger
└─ TagsInputHiddenInput (explicit)

TagsInputRootProvider
└─ same part tree connected to a useTagsInput() store
```

| Partie | Rôle |
| --- | --- |
| `TagsInput` | Racine qui gère l’état, les valeurs, la saisie, la validation et l’intégration au formulaire. |
| `TagsInputRootProvider` | Relie les parties à l’état renvoyé par `useTagsInput()`. |
| `TagsInputLabel` | Libellé accessible du champ de tags. |
| `TagsInputControl` | Conteneur visible des tags, du champ de saisie et du déclencheur d’effacement. |
| `TagsInputItems` | Rendu standard des tags modifiables de la racine. |
| `TagsInputItem` | Un tag. Transmettez `index` et `value` pour un rendu personnalisé. |
| `TagsInputItemContext` | Accès par render prop à l’état de l’élément courant dans l’arbre du composant. |
| `TagsInputItemPreview` | Contenu visible d’un tag hors du mode d’édition. |
| `TagsInputItemText` | Texte visible du tag. |
| `TagsInputItemDeleteTrigger` | Supprime un tag et fournit par défaut une petite icône de fermeture. |
| `TagsInputItemInput` | Champ utilisé pour modifier un tag sur place. |
| `TagsInputInput` | Champ de saisie des nouveaux tags. |
| `TagsInputClearTrigger` | Supprime tous les tags et utilise par défaut le style partagé du bouton de fermeture. |
| `TagsInputHiddenInput` | Champ natif explicite pour l’envoi du formulaire. |
| `TagsInputContext` | Accès render prop à l’état de la racine dans l’arbre du composant. |

## Composition

Utilisez la forme courte `<TagsInput>` pour la composition standard. Gardez `TagsInputItems`,
`TagsInputInput` et `TagsInputClearTrigger` dans `TagsInputControl`. Ajoutez explicitement
`TagsInputHiddenInput` et transmettez `name` à la racine lorsque les tags doivent être envoyés avec
un formulaire. Utilisez `form` lorsque le formulaire associé se trouve en dehors de l’arbre du
composant.

Pour personnaliser le contenu ou les actions des tags, utilisez `TagsInputContext` et associez ses
valeurs à `TagsInputItem` avec `index` et `value`. Gardez `TagsInputItemInput` dans chaque élément
pour conserver l’édition sur place. Utilisez `TagsInputRootProvider` avec `useTagsInput()` seulement
lorsque l’état ou des méthodes comme `addValue`, `clearValue` et `focus` doivent être utilisés en
dehors de l’arbre du composant. En Solid, le store est un accessor : lisez `tagsInput().value` et
appelez `tagsInput().addValue()`. Avec `Combobox`, partagez les identifiants du champ et du contrôle,
puis composez les champs avec `asChild`.

### Hooks de style

- `TagsInput` et `TagsInputRootProvider` exposent `data-slot="tags-input-root"` et `data-slot="tags-input-root-provider"`.
- Les parties Ark conservent `data-scope="tags-input"` et les valeurs `data-part` de l’anatomie.
- Les états peuvent utiliser `data-disabled`, `data-readonly`, `data-invalid`, `data-focus`, `data-empty`, `data-required`, `data-value` et `data-highlighted` lorsque Ark les émet.
- Les déclencheurs de suppression et d’effacement exposent des hooks `data-slot` stables. La suppression d’un tag utilise une petite icône ; l’effacement global reprend le style partagé du bouton de fermeture.
- CSS Modules exposent trois variables : `--moduix-tags-input-width`, `--moduix-tags-input-min-height` et `--moduix-tags-input-radius`. Les couleurs, les espacements, la typographie et la géométrie des tags utilisent les tokens de foundation ; modifiez-les avec une classe sur la partie. Les variantes Tailwind utilisent les utilitaires natifs et les classes ajoutées par le consommateur.
- En lecture seule, moduix masque le champ de saisie, les déclencheurs de suppression des tags et le déclencheur d’effacement, en laissant visibles uniquement les valeurs immuables.

## Accessibilité

Ark relie le libellé au champ et gère la sélection, l’édition sur place, la suppression, le collage et
le champ de formulaire masqué. Ce champ explicite sérialise la liste pour l’envoi natif ; transmettez
`name` et, si nécessaire, `form` pour l’associer à un formulaire.

### Prise en charge du clavier

- `Enter` dans le champ de saisie ajoute sa valeur courante. `Enter` sur un tag sélectionné ouvre son mode d’édition.
- Un double-clic sur un tag ouvre également l’édition lorsque `editable` vaut `true`.
- Lorsque le champ est vide ou que le curseur est au début, `ArrowLeft` et `ArrowRight` déplacent le focus visuel entre les tags.
- `Backspace` et `Delete` suppriment le tag sélectionné. `Backspace` supprime aussi le dernier tag lorsque le champ est vide.
- Avec `addOnPaste`, `Control+V` ajoute les valeurs collées après leur séparation avec `delimiter`.
