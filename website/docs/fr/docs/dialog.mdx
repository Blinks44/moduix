## Choisir le bon composant

Utilisez `Dialog` pour les formulaires, les confirmations, l’affichage de détails et les tâches secondaires qui doivent
rester dans le contexte de la page actuelle. Utilisez `Drawer` lorsque le panneau doit rester attaché à un bord de la fenêtre.

## Anatomie

```text
Dialog
├─ Dialog.Trigger
└─ Arborescence de superposition (placée automatiquement dans un portail)
   ├─ Dialog.Backdrop
   └─ Dialog.Positioner
      └─ Dialog.Content
         ├─ Dialog.CloseTrigger ou Dialog.CloseIcon
         ├─ Dialog.Title
         ├─ Dialog.Description
         ├─ Dialog.Header (utilitaire de mise en page moduix)
         ├─ Dialog.Body (utilitaire de mise en page moduix)
         └─ Dialog.Footer (utilitaire de mise en page moduix)

Dialog.RootProvider
└─ la même arborescence de contenu placée dans un portail et reliée à useDialog() de moduix

Dialog.Context
└─ une fonction de rendu qui reçoit l’état et les méthodes actuels du dialogue
```

| Partie                  | Rôle |
| ----------------------- | ---- |
| `Dialog`                | Gère l’état d’ouverture, le cycle du focus et la fermeture du dialogue. |
| `Dialog.Trigger`        | Ouvre le dialogue. |
| `Dialog.Backdrop`       | Couche d’arrière-plan facultative de la fenêtre modale. |
| `Dialog.Positioner`     | Conteneur flottant qui positionne le contenu. |
| `Dialog.Content`        | Conteneur visuel du dialogue. |
| `Dialog.Title`          | Titre accessible du dialogue. |
| `Dialog.Description`    | Description complémentaire accessible. |
| `Dialog.CloseTrigger`   | Ferme le dialogue. |
| `Dialog.Context`        | Rend ses enfants avec l’état et les méthodes actuels du dialogue. |
| `Dialog.RootProvider`   | Relie les parties à l’état créé avec `useDialog()` de moduix. |

Importez `useDialog()` lorsque l’état du dialogue doit être géré en dehors de l’arbre rendu. Lisez cet état dans des enfants
réutilisables avec `Dialog.Context` ou `useDialogContext()` depuis `@moduix/react`.

## Composition

Le composant racine place automatiquement `Backdrop` et `Positioner` dans un portail. Définissez `portalled={false}`
pour les afficher dans l’arbre courant, ou transmettez `portalRef` pour utiliser un conteneur personnalisé. Les parties
structurelles restent explicites et peuvent être stylées séparément.

### Composition recommandée

Conservez `Backdrop`, `Positioner` et `Content` explicites. Vous gardez ainsi des points de personnalisation structurelle
et une composition alignée sur Ark UI. Pour un dialogue non modal, ne rendez pas `Backdrop`.

Utilisez `Dialog.Trigger asChild` et `Dialog.CloseTrigger asChild` avec un seul élément enfant qui conserve la sémantique
d’un bouton. `Dialog.CloseIcon` est un assistant moduix qui associe le `CloseTrigger` Ark au bouton de fermeture de la
bibliothèque.

### Quand créer une composition personnalisée

Pour laisser React contrôler l’état du dialogue, utilisez `open` avec `onOpenChange(details)`. Le callback reçoit un objet
`details` d’Ark ; lisez donc la valeur dans `details.open`.

Utilisez `useDialog()` de moduix avec `Dialog.RootProvider` lorsque l’état et les méthodes doivent vivre en dehors de
l’arbre rendu du dialogue. Ne rendez pas un second `Dialog` pour le même store.

Utilisez `ids` lorsque des parties composées séparément ont besoin d’identifiants d’accessibilité stables et communs.
`initialFocusEl` et `finalFocusEl` permettent de choisir précisément les cibles du focus. Utilisez
`role="alertdialog"` pour les confirmations d’actions dangereuses ou critiques.

Utilisez `lazyMount` et `unmountOnExit` plutôt qu’un rendu conditionnel du composant racine. Définissez `present` uniquement
lorsqu’une animation de sortie pilotée par JavaScript doit contrôler le maintien du contenu dans le DOM.

### Propriétés par défaut

Par défaut, le contenu de la superposition placé dans le portail est monté à la demande, puis démonté après l’animation de
sortie. Définissez `unmountOnExit={false}` pour le conserver après la première ouverture. Ne définissez les deux propriétés
du cycle de vie sur `false` que si un rendu initial immédiat est nécessaire.

| Surface  | Valeur par défaut | Remarques |
| -------- | ----------------- | --------- |
| `Dialog` | -                 | Aucun réglage comportemental supplémentaire ; les valeurs Ark s’appliquent. |

### Comportement

- Les dialogues modaux retiennent le focus dans la fenêtre, empêchent le défilement de l’arrière-plan, masquent le contenu
  situé derrière la fenêtre pour les technologies d’assistance et restaurent le focus après la fermeture.
- `modal={false}` désactive la rétention du focus et le verrouillage du défilement. Dans ce mode, ne rendez pas l’arrière-plan.
- `closeOnEscape`, `closeOnInteractOutside`, `trapFocus`, `preventScroll`, `restoreFocus`, `persistentElements` et les
  callbacks d’interaction extérieure sont transmis à Ark UI sans modification.
- Pour donner un nom accessible au dialogue, rendez `Dialog.Title` ou définissez `aria-label` sur le composant racine.
- Lorsque l’utilisateur préfère réduire les mouvements, Dialog raccourcit ses animations d’entrée et de sortie tout en
  conservant le cycle de présence d’Ark UI.
- Chaque partie de fermeture rendue doit avoir un identifiant unique. La composition de base recommandée utilise un seul
  `Dialog.CloseIcon`. Si plusieurs contrôles de fermeture sont nécessaires, attribuez un `id` explicite et unique à chaque
  partie supplémentaire.
- Le contenu imbriqué reçoit `data-has-nested` et `--nested-layer-count`. moduix utilise ces points d’accroche pour réduire
  le dialogue parent et le décaler vers le bas, afin que le dialogue imbriqué actif forme toujours un niveau distinct.
- Les exemples d’ouverture depuis un menu et de changements rapides d’état utilisent le contrat contrôlé `open`. La
  confirmation de modifications non enregistrées utilise deux stores `useDialog()` de moduix et intercepte le
  `onOpenChange` du store parent.

### Points d’accroche CSS

- Slots moduix : `dialog-trigger`, `dialog-backdrop`, `dialog-positioner`, `dialog-content`,
  `dialog-title`, `dialog-description`, `dialog-close-trigger`, `dialog-close-icon`,
  `dialog-header`, `dialog-body` et `dialog-footer`.
- Anatomie Ark : `data-scope="dialog"` avec `data-part="trigger|backdrop|positioner|content|title|description|close-trigger"`.
- État : `data-state="open|closed"`, `data-has-nested`, `data-nested`, `data-current` et `data-value`.
- Variables d’exécution : `--layer-index` et `--nested-layer-count`.
- `Dialog.CloseIcon` est positionné de manière absolue par rapport à `Dialog.Content` ; son emplacement ne dépend pas de
  `Dialog.Header`.
