## Choisir le bon composant

Utilisez `Dialog` pour les formulaires, les confirmations, l’affichage de détails et les autres tâches qui doivent rester
dans le contexte de la page actuelle. Préférez `Drawer` lorsque le panneau doit rester fixé à un bord de la fenêtre ou
pouvoir être déplacé.

## Anatomie

```text
Dialog / Dialog.Root
├─ Dialog.Trigger
└─ Contenu superposé (rendu automatiquement dans un portail)
   ├─ Dialog.Backdrop (facultatif)
   └─ Dialog.Positioner
      └─ Dialog.Content
         ├─ Dialog.CloseTrigger ou Dialog.CloseIcon
         ├─ Dialog.Title
         ├─ Dialog.Description
         ├─ Dialog.Header (aide de mise en page moduix)
         ├─ Dialog.Body (aide de mise en page moduix)
         └─ Dialog.Footer (aide de mise en page moduix)

Dialog.RootProvider
└─ la même arborescence reliée à l’état créé avec useDialog() de moduix

Dialog.Context
└─ une fonction de rendu qui reçoit l’état et les méthodes actuels du dialogue
```

| Partie                  | Rôle                                                                  |
| ----------------------- | --------------------------------------------------------------------- |
| `Dialog` / `Dialog.Root` | Gère l’état d’ouverture, le focus et la fermeture du dialogue.         |
| `Dialog.RootProvider`   | Relie les parties à l’état créé avec `useDialog()`.                    |
| `Dialog.Trigger`        | Ouvre le dialogue.                                                     |
| `Dialog.Backdrop`       | Couche d’arrière-plan facultative du dialogue modal.                  |
| `Dialog.Positioner`     | Positionne le contenu du dialogue.                                     |
| `Dialog.Content`        | Contient la surface visible du dialogue.                              |
| `Dialog.Title`          | Donne au dialogue un titre accessible.                                |
| `Dialog.Description`    | Ajoute un texte complémentaire accessible.                            |
| `Dialog.CloseTrigger`   | Ferme le dialogue.                                                     |
| `Dialog.CloseIcon`      | Bouton de fermeture moduix qui ferme aussi le dialogue.               |
| `Dialog.Header`         | Aide moduix pour organiser l’en-tête.                                 |
| `Dialog.Body`           | Aide moduix pour organiser le contenu principal.                      |
| `Dialog.Footer`         | Aide moduix pour organiser les actions.                               |
| `Dialog.Context`        | Rend ses enfants avec l’état et les méthodes actuels du dialogue.      |

Importez `useDialog()` lorsque l’état doit être géré en dehors de l’arbre rendu du dialogue. Lisez-le ou mettez-le à jour
avec `Dialog.Context` ou `useDialogContext()` depuis `@moduix/react`.

## Composition

Le composant racine place automatiquement `Dialog.Backdrop` et `Dialog.Positioner` dans un portail. Définissez
`portalled={false}` pour les afficher dans l’arbre courant, ou transmettez `portalRef` pour utiliser un conteneur
personnalisé. Gardez les parties structurelles explicites afin de pouvoir les styliser et les personnaliser séparément.

### Composition recommandée

Rendez explicitement `Dialog.Backdrop`, `Dialog.Positioner` et `Dialog.Content`. Ajoutez l’arrière-plan pour un dialogue
modal et omettez-le lorsque le dialogue doit être non modal.

Utilisez `Dialog.Trigger asChild` et `Dialog.CloseTrigger asChild` avec un seul élément enfant sémantique. Cet élément doit
pouvoir recevoir le focus et conserver le comportement d’un bouton. `Dialog.CloseIcon` est une aide moduix qui associe le
`CloseTrigger` d’Ark au bouton de fermeture de la bibliothèque.

### Quand créer une composition personnalisée

Utilisez `open` et `onOpenChange(details)` lorsque React doit gérer l’état d’ouverture. Le callback reçoit un objet
`details` d’Ark ; lisez donc le nouvel état dans `details.open`.

Utilisez `useDialog()` avec `Dialog.RootProvider` lorsque l’état ou les méthodes doivent être accessibles en dehors de
l’arbre du dialogue. Ne rendez pas un second `Dialog` pour la même instance. Si un composant enfant réutilisable doit lire
cet état, utilisez `Dialog.Context` ou `useDialogContext()`.

Utilisez `ids` lorsque des parties composées séparément ont besoin d’identifiants d’accessibilité stables et communs.
Utilisez `initialFocusEl` et `finalFocusEl` pour choisir explicitement les cibles du focus. Définissez
`role="alertdialog"` pour les décisions dangereuses ou particulièrement critiques.

Gardez la racine montée lorsque l’état d’ouverture change. Utilisez `lazyMount` et `unmountOnExit` pour contrôler le
moment où le contenu placé dans le portail entre dans le DOM et en sort. Définissez `present` uniquement lorsqu’une
animation de sortie pilotée par JavaScript doit contrôler le maintien du contenu dans le DOM.

### Propriétés par défaut

Les deux premières valeurs sont définies par moduix. Les autres sont héritées d’Ark UI.

| Propriété                 | Valeur par défaut | Remarques                                                         |
| ------------------------- | ----------------- | ----------------------------------------------------------------- |
| `lazyMount`               | `true`            | Monte le contenu placé dans le portail à la première ouverture.   |
| `unmountOnExit`            | `true`            | Démonte le contenu après son animation de sortie.                 |
| `modal`                    | `true`            | Empêche les interactions avec le contenu situé hors du dialogue.  |
| `preventScroll`            | `true`            | Empêche le défilement de la page lorsque le dialogue est ouvert.  |
| `trapFocus`                | `true`            | Retient le focus dans un dialogue modal.                          |
| `closeOnEscape`            | `true`            | Ferme le dialogue lorsque l’utilisateur appuie sur `Escape`.      |
| `closeOnInteractOutside`   | `true`            | Ferme le dialogue après une interaction extérieure.               |
| `role`                     | `"dialog"`        | Utilise par défaut la sémantique d’un dialogue ordinaire.         |

### Comportement

- Un dialogue modal retient le focus, empêche le défilement de la page, masque le contenu situé derrière lui aux
  technologies d’assistance et restaure le focus après sa fermeture.
- Définissez `modal={false}` pour désactiver la rétention du focus et le blocage du défilement. Dans ce mode, omettez
  `Dialog.Backdrop` afin que la page reste interactive.
- `closeOnEscape`, `closeOnInteractOutside`, `trapFocus`, `preventScroll`, `restoreFocus`, `persistentElements` et les
  callbacks d’interaction extérieure sont transmis à Ark UI.
- Rendez `Dialog.Title` ou définissez `aria-label` sur la racine pour donner au dialogue un nom accessible. Utilisez
  `Dialog.Description` lorsque les utilisateurs ont besoin d’une explication complémentaire.
- Lorsque la préférence système de réduction des animations est activée, moduix raccourcit les animations d’entrée et de
  sortie, tandis qu’Ark UI termine normalement le cycle de présence.
- Si un dialogue contient plusieurs contrôles de fermeture, donnez à chaque `Dialog.CloseTrigger` un `id` explicite et
  unique. Un seul `Dialog.CloseIcon` n’en a pas besoin.
- Pour les dialogues imbriqués, le contenu parent reçoit `data-has-nested` et `--nested-layer-count`. moduix s’en sert
  pour réduire le parent et le décaler vers le bas tant que le dialogue imbriqué est ouvert.
- Ne démontez pas la racine conditionnellement pour fermer le dialogue. Gardez-la montée et contrôlez `open`, ou utilisez
  `lazyMount` et `unmountOnExit` lorsque le contenu placé dans le portail ne doit pas rester dans le DOM.

### Points d’accroche CSS

- Valeurs `data-slot` de moduix : `dialog-trigger`, `dialog-backdrop`, `dialog-positioner`, `dialog-content`,
  `dialog-title`, `dialog-description`, `dialog-close-trigger`, `dialog-close-icon`, `dialog-header`, `dialog-body` et
  `dialog-footer`.
- Attributs Ark : `data-scope="dialog"` et `data-part="trigger|backdrop|positioner|content|title|description|close-trigger"`.
- Attributs d’état : `data-state="open|closed"`, `data-has-nested`, `data-nested`, `data-current` et `data-value`.
- Variables d’exécution : `--layer-index` et `--nested-layer-count`.
- `Dialog.CloseIcon` est positionné par rapport à l’angle de `Dialog.Content`, et son emplacement ne dépend donc pas de
  `Dialog.Header`.
