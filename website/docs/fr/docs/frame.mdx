## Styles et dimensions du contenu

La prop `head` accepte du contenu JSX et l’insère dans le `<head>` de l’iframe. Utilisez-la pour les styles, les polices
et les métadonnées. Les feuilles de style nécessaires au contenu intégré doivent également être chargées via cette prop.

`Frame` observe la taille du contenu monté et l’écrit en pixels dans les propriétés CSS personnalisées `--width` et
`--height` de l’iframe. Utilisez `block-size: var(--height, 10rem)` lorsque l’iframe doit suivre la hauteur de son
contenu. La variable `--width` peut être utilisée de la même manière pour sa dimension inline.

## Callbacks du cycle de vie

Utilisez `onMount` et `onUnmount` pour les ressources gérées par l’expérience intégrée. Ces deux callbacks sont appelés
sans argument. Une `ref` permet à l’application d’accéder au document de l’iframe lorsque la configuration doit
interagir avec celui-ci.

N’injectez que des scripts contrôlés par votre application. Pour les styles et les métadonnées, préférez `head`.

## Documents HTML statiques

Utilisez `srcDoc` en React ou `srcdoc` en Solid lorsque l’iframe doit commencer par un document HTML complet plutôt que
par des enfants rendus par le framework. Ce sont les écritures natives du même attribut d’iframe dans chaque framework.

Pour du HTML non fiable, définissez l’attribut natif `sandbox` et n’accordez que les permissions nécessaires au contenu.
N’associez pas `allow-scripts` et `allow-same-origin` dans une sandbox destinée à du contenu non fiable.
