Un switch de base comprend une racine, un contrôle visuel, un libellé et `SwitchHiddenInput` explicitement rendu pour les interactions
natives et les formulaires. Le contrôle reçoit un thumb par défaut lorsqu’il n’a pas d’enfants.

## Choisir le bon composant

Utilisez `Switch` pour un réglage qui s’applique dès que l’utilisateur le modifie. Un switch représente une
valeur booléenne.

- Choisissez **`Switch`** pour des réglages comme les notifications, les rappels ou l’activation de fonctionnalités.
- Choisissez **`Checkbox`** lorsque le contrôle représente un choix envoyé avec un formulaire,
  plutôt qu’un réglage appliqué immédiatement.
- Choisissez **`RadioGroup`** lorsque l’utilisateur doit sélectionner une option parmi plusieurs valeurs mutuellement exclusives.

## Composition

Rendez `SwitchHiddenInput` explicitement à l’intérieur de `Switch` ou `SwitchRootProvider`, y compris lorsque le
switch ne se trouve pas dans un formulaire. Il fournit le champ natif qu’Ark utilise pour le focus, le clavier,
l’accessibilité et l’envoi du formulaire.

Lorsque `SwitchControl` n’a pas d’enfants, il ajoute `SwitchThumb` par défaut. Ajoutez `SwitchThumb`
explicitement uniquement lorsque le thumb a besoin d’un contenu ou de styles personnalisés.

Utilisez `SwitchContext` ou `useSwitchContext` lorsque l’interface voisine doit lire l’état du switch. Utilisez
`useSwitch` avec `SwitchRootProvider` lorsque l’état doit être créé en dehors de l’arbre rendu du switch.
Ne rendez pas `Switch` et `SwitchRootProvider` pour la même instance d’état.

Avec `asChild`, fournissez un seul élément sémantique compatible avec `label` afin qu’Ark conserve l’accessibilité
du switch.

## Styles

Stylisez `Switch` avec `className` en React ou `class` en Solid et Vue, les hooks publics `data-slot` et les attributs d’état Ark,
ainsi que les variables CSS publiques `--moduix-switch-*` présentées ci-dessous. Les variantes Tailwind utilisent
des utilitaires et des classes supplémentaires ; les variables ci-dessous concernent CSS Modules, tandis que les attributs de données sont
communs aux deux approches.

Le thumb tire sa taille et sa position de la boîte du contrôle : un remplacement de `width` ou de
`height` sur `SwitchControl` (une classe en CSS Modules, les utilitaires `w-*` et `h-*` en Tailwind) le
garde carré et aligné sur les deux bords. La direction de droite à gauche vient d’Ark : dans un
[`LocaleProvider`](/docs/rtl) RTL, Ark écrit `dir` sur chaque partie et le thumb coché se place en fin de ligne.

### Points d’accroche CSS

| Partie | `data-slot` |
| --- | --- |
| `Switch` | `switch-root` |
| `SwitchRootProvider` | `switch-root-provider` |
| `SwitchControl` | `switch-control` |
| `SwitchThumb` | `switch-thumb` |
| `SwitchLabel` | `switch-label` |

- `Switch` et `SwitchRootProvider` exposent `data-slot="switch-root"` /
  `data-slot="switch-root-provider"` et définissent l’attribut `data-size` de moduix.
- `SwitchControl` expose `data-slot="switch-control"` et reçoit les attributs d’état Ark comme
  `data-state`, `data-focus-visible`, `data-hover`, `data-active`, `data-disabled`, `data-readonly`,
  `data-invalid` et `data-required`.
