## Choisir le bon composant

Utilisez `Switch` pour un réglage qui prend effet dès que l’utilisateur le modifie. Un interrupteur représente une
seule valeur booléenne.

- Choisissez **`Switch`** pour des réglages comme les notifications, les rappels ou l’activation de fonctionnalités.
- Choisissez **`Checkbox`** lorsque le contrôle représente une sélection à envoyer avec un formulaire plutôt qu’un
  réglage appliqué immédiatement.
- Choisissez **`RadioGroup`** lorsque les utilisateurs doivent sélectionner une option parmi plusieurs valeurs
  mutuellement exclusives.

## Exemple de base

Un interrupteur de base se compose d’une racine, d’un contrôle visuel et d’un libellé. Le contrôle ajoute le curseur

## Anatomie

```text
Switch / Switch.Root
├─ Switch.Control
│  └─ Switch.Thumb
├─ Switch.Label
└─ input masqué (ajouté automatiquement)
```

| Partie                    | Rôle                                                                    |
| ------------------------- | ----------------------------------------------------------------------- |
| `Switch` / `Switch.Root`  | Élément `label` racine. Gère l’état, les ID, les props de formulaire et `size`. |
| `Switch.RootProvider`     | Élément racine piloté par l’état créé avec `useSwitch()`.               |
| `Switch.Control`          | Piste visuelle et cible de l’anneau de focus. Ajoute un curseur par défaut. |
| `Switch.Thumb`            | Curseur mobile pour l’apparence par défaut ou un contenu personnalisé.  |
| `Switch.Label`            | Libellé relié à l’interrupteur par Ark.                                 |

`Switch` et `Switch.Root` sont deux noms pour la même racine. `Switch.Context`, `useSwitchContext` et `useSwitch`
sont exportés depuis `@moduix/react` avec le composant.

## Composition

### Composition recommandée

Pour les cas courants, utilisez la forme courte `<Switch>` avec `Switch.Control` et `Switch.Label`. La racine ajoute
automatiquement l’input de formulaire masqué, mais pas les parties visibles du composant.

Lorsque `Switch.Control` n’a pas d’enfants, il ajoute le `Switch.Thumb` par défaut. Ajoutez `Switch.Thumb` explicitement
lorsque le curseur nécessite un contenu ou des styles personnalisés.

### Quand créer une composition personnalisée

Utilisez `asChild` lorsque vous devez fournir vous-même l’élément DOM racine. Son enfant direct doit être un seul
élément compatible avec `label`, afin que l’interrupteur conserve un nom accessible valide.

Utilisez `Switch.Context` ou `useSwitchContext` lorsque l’interface environnante doit lire l’état de l’interrupteur.
Utilisez `useSwitch` avec `Switch.RootProvider` lorsque l’état doit être créé et contrôlé en dehors de l’arbre rendu.
Ne rendez pas `Switch` et `Switch.RootProvider` pour la même instance d’état.

### Propriétés par défaut

| Propriété   | Par défaut  | Remarques                                                    |
| ----------- | ----------- | ------------------------------------------------------------ |
| `size`      | `md`        | Facilitation moduix : `xs`, `sm`, `md`, `lg`, `xl`.          |
| `value`     | `on`        | Valeur envoyée par l’input de formulaire masqué.      |
| `children`  | `undefined` | Composez explicitement les parties visibles.          |
| `className` | `undefined` | Appliquée à l’élément `label` racine.                 |

### Comportement

- Utilisez `defaultChecked` en mode non contrôlé. Utilisez `checked` avec `onCheckedChange(details)` en mode contrôlé.
- `onCheckedChange` reçoit un objet de détails. Utilisez `details.checked` pour obtenir le prochain état booléen.
- La racine ajoute toujours l’input de formulaire natif. Les props `name`, `value`, `form` et `required` configurent
  sa participation au formulaire. Pour un interrupteur non contrôlé, la réinitialisation du formulaire restaure son état initial.
- `readOnly` préserve l’état actuel et définit `aria-readonly="true"` sur le contrôle natif.
- La piste et le curseur désactivent leurs transitions lorsque l’utilisateur préfère réduire les animations (`prefers-reduced-motion`).
- Utilisez `Switch.Context` ou `useSwitchContext` pour les lectures d’état avancées. Lorsque le propriétaire de l’état
  se trouve en dehors de l’arbre, utilisez `useSwitch` avec `Switch.RootProvider`.
- Avec `asChild`, l’enfant doit rester un unique élément sémantique compatible avec `label`.

### Points d’accroche CSS

- `Switch` et `Switch.RootProvider` exposent `data-slot="switch-root"` / `data-slot="switch-root-provider"` et
  définissent l’attribut `data-size` de moduix.
- `Switch.Control` expose `data-slot="switch-control"` et reçoit les attributs d’état Ark comme `data-state`,
  `data-focus-visible`, `data-hover`, `data-active`, `data-disabled`, `data-readonly`, `data-invalid` et `data-required`.
- `Switch.Thumb` expose `data-slot="switch-thumb"` et reçoit les mêmes attributs d’état Ark pour le déplacement du
  curseur et les styles du contenu personnalisé.
- `Switch.Label` expose `data-slot="switch-label"` pour remplacer les styles typographiques.
- L’input de formulaire natif expose `data-slot="switch-hidden-input"` à des fins d’inspection, mais doit rester
  visuellement masqué par Ark.
