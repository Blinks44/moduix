## Choisir le bon composant

Utilisez `Switch` pour un réglage qui s’applique dès que l’utilisateur le modifie. Un switch représente une
valeur booléenne.

- Choisissez **`Switch`** pour des réglages comme les notifications, les rappels ou l’activation de fonctionnalités.
- Choisissez **`Checkbox`** lorsque le contrôle représente un choix envoyé avec un formulaire,
  plutôt qu’un réglage appliqué immédiatement.
- Choisissez **`RadioGroup`** lorsque l’utilisateur doit sélectionner une option parmi plusieurs valeurs mutuellement exclusives.

## Anatomie

```text
Switch / Switch.Root
├─ Switch.Control
│  └─ Switch.Thumb
├─ Switch.Label
└─ Switch.HiddenInput (explicit)
```

| Partie                        | Rôle                                                                    |
| ----------------------------- | ----------------------------------------------------------------------- |
| `Switch` / `Switch.Root`      | Élément `label` racine. Gère l’état, les identifiants, les props de formulaire et `size`. |
| `Switch.HiddenInput`          | Contrôle de formulaire natif d’Ark ; composez-le explicitement comme indiqué ci-dessous. |
| `Switch.RootProvider`         | Élément `label` racine piloté par l’état créé avec `useSwitch()`.     |
| `Switch.Control`              | Piste visuelle et cible de l’anneau de focus. Ajoute `Switch.Thumb` par défaut. |
| `Switch.Thumb`                | Thumb mobile pour l’apparence par défaut ou un contenu personnalisé.  |
| `Switch.Label`                | Texte du libellé relié à Ark.                                         |

`Switch` et `Switch.Root` sont deux noms pour la même racine. `Switch.Context`,
`useSwitchContext` et `useSwitch` sont exportés depuis `@moduix/react` avec le composant.
Les exports Solid correspondants sont disponibles depuis `@moduix/solid` et `@moduix/solid/switch`.

## Composition

Rendez `Switch.HiddenInput` explicitement à l’intérieur de `Switch` ou `Switch.RootProvider`, y compris lorsque le
switch ne se trouve pas dans un formulaire. Il fournit le champ natif qu’Ark utilise pour le focus, le clavier,
l’accessibilité et l’envoi du formulaire.

Lorsque `Switch.Control` n’a pas d’enfants, il ajoute `Switch.Thumb` par défaut. Ajoutez `Switch.Thumb`
explicitement uniquement lorsque le thumb a besoin d’un contenu ou de styles personnalisés.

Utilisez `Switch.Context` ou `useSwitchContext` lorsque l’interface voisine doit lire l’état du switch. Utilisez
`useSwitch` avec `Switch.RootProvider` lorsque l’état doit être créé en dehors de l’arbre rendu du switch.
Ne rendez pas `Switch` et `Switch.RootProvider` pour la même instance d’état.

Avec `asChild`, fournissez un seul élément sémantique compatible avec `label` afin qu’Ark conserve l’accessibilité
du switch.

## Styles

Stylisez `Switch` avec `className` en React ou `class` en Solid, les hooks publics `data-slot` et les attributs d’état Ark,
ainsi que les variables CSS publiques `--moduix-switch-*` présentées ci-dessous. Les variantes Tailwind utilisent
des utilitaires et des classes supplémentaires ; les variables ci-dessous concernent CSS Modules, tandis que les attributs de données sont
communs aux deux approches.

### Points d’accroche CSS

- `Switch` et `Switch.RootProvider` exposent `data-slot="switch-root"` /
  `data-slot="switch-root-provider"` et définissent l’attribut `data-size` de moduix.
- `Switch.Control` expose `data-slot="switch-control"` et reçoit les attributs d’état Ark comme
  `data-state`, `data-focus-visible`, `data-hover`, `data-active`, `data-disabled`, `data-readonly`,
  `data-invalid` et `data-required`.
- `Switch.Thumb` expose `data-slot="switch-thumb"` et reçoit les mêmes attributs d’état Ark pour
  le déplacement du thumb et le style de son contenu personnalisé.
- `Switch.Label` expose `data-slot="switch-label"` pour personnaliser la typographie.
