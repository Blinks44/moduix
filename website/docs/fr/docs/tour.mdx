## Anatomie

```text
Tour / Tour.Root
└─ Éléments superposés (rendus dans un portail par défaut)
   ├─ Tour.Backdrop
   ├─ Tour.Spotlight
   └─ Tour.Positioner
      └─ Tour.Content
         ├─ Tour.Arrow
         ├─ Tour.CloseIcon / Tour.CloseTrigger
         ├─ Tour.Body
         │  ├─ Tour.Title
         │  ├─ Tour.Description
         │  └─ Tour.ProgressText
         └─ Tour.Control
            ├─ Tour.ActionList
            └─ Tour.Actions
               └─ Tour.ActionTrigger[action]
```

| Partie | Rôle |
| --- | --- |
| `Tour` / `Tour.Root` | Composant racine associé à l’objet renvoyé par `useTour`. |
| `Tour.Backdrop` / `Tour.Spotlight` | Voile d’arrière-plan facultatif et mise en évidence de la cible active. |
| `Tour.Positioner` / `Tour.Content` | Positionnent et affichent la boîte de dialogue `alertdialog` d’Ark. |
| `Tour.Arrow` | Affiche par défaut l’`ArrowTip` de moduix pour les étapes de type infobulle. |
| `Tour.CloseIcon` / `Tour.CloseTrigger` | Contrôle de fermeture accessible par défaut ou balisage personnalisé. |
| `Tour.Body` | Conteneur moduix défilant pour le titre, la description et le texte de progression. |
| `Tour.Control` / `Tour.ActionList` | Rangée d’actions recommandée et actions de l’étape en cours. |
| `Tour.Actions` / `Tour.ActionTrigger` | Interface d’actions personnalisée qui conserve chaque objet d’action Ark. |

## Composition

Créez l’état avec `useTour` et transmettez-le à `Tour`. En Solid, la valeur renvoyée est un accessor : appelez donc
`tour()` pour utiliser des méthodes comme `start()` et `next()`. Gardez les parties structurelles explicites et
incluez `Title` et `Description` pour donner un nom et une description accessibles à `alertdialog`. `Backdrop`,
`Spotlight` et `Positioner` sont rendus dans un portail par défaut ; utilisez `portalled={false}` ou `portalRef` seulement
si la couche doit rester dans le balisage ou rejoindre un conteneur précis. Utilisez `ActionList` pour les actions
déclarées dans `steps`, ou remplacez-le par `Actions` et `ActionTrigger asChild` lorsque chaque action demande son
propre balisage. `lazyMount` et `unmountOnExit` valent `true` par défaut ; transmettez des callbacks à `useTour` si une
autre partie de l’interface ou votre outil d’analyse doit réagir aux changements d’étape ou de statut.

### Hooks de style

Utilisez les attributs `data-slot` de moduix, comme `tour-content`, `tour-body` et `tour-action-trigger`, pour le style
local. Ark fournit aussi `data-scope="tour"`, `data-part`, `data-state`, `data-type`, `data-placement`, `data-side`,
`data-step` et `data-disabled`, ainsi que des variables d’exécution comme `--tour-layer`, `--tour-z-index`,
`--available-width`, `--available-height`, `--transform-origin` et les variables de la flèche. Passez `className` à
`Tour.ActionList` pour styliser chaque déclencheur généré. La feuille de style raccourcit les animations de la couche et
supprime les transitions des boutons d’action lorsque l’utilisateur préfère réduire les animations.
