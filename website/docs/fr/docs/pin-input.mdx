## Choisir le bon composant

Utilisez `PinInput` lorsqu’un code court de longueur fixe doit être saisi un caractère à la fois dans plusieurs cases.

- Choisissez **`PinInput`** pour les codes à usage unique, les codes PIN, les codes de secours et les codes d’invitation.
- Choisissez **`Input`** lorsqu’un seul champ de texte simple suffit.
- Choisissez **`PasswordInput`** lorsque la valeur est une chaîne confidentielle unique avec un bouton de visibilité.

## Anatomie

```text
PinInput / PinInput.Root
├─ PinInput.Label
├─ PinInput.Control
│  ├─ PinInput.Input[index=0]
│  ├─ PinInput.Input[index=1]
│  └─ PinInput.Input[index=2]
└─ champ natif masqué (ajouté automatiquement)
```

| Partie                         | Rôle                                                                  |
| ------------------------------ | --------------------------------------------------------------------- |
| `PinInput` / `PinInput.Root`   | Machine à états de la racine : nombre de cases, tableau de valeurs, validation et options de formulaire. |
| `PinInput.RootProvider`        | Construit l’arborescence Pin Input à partir de l’état renvoyé par `usePinInput`.                 |
| `PinInput.Label`               | Libellé du groupe de saisie du code.                                                            |
| `PinInput.Control`             | Conteneur des champs indexés visibles.                                                          |
| `PinInput.Input`               | Champ visible qui accepte un caractère. Fournissez un `index` commençant à zéro.               |
| `PinInput.Inputs`              | Génère les champs indexés standard à partir du contexte Ark.                                   |
| `PinInput.Separator`           | Séparateur décoratif pour grouper les champs. C’est une aide moduix, pas une partie du primitif Ark. |
| `usePinInput` / `PinInput.RootProvider` | Gestion de l’état hors de l’arbre rendu et méthodes impératives.                      |

## Composition

### Composition recommandée

Utilisez la forme abrégée `<PinInput>`, ajoutez un `Label` visible et placez `Inputs` dans `Control`. La racine ajoute
toujours un champ de formulaire natif masqué, ce qui préserve la soumission du formulaire, la synchronisation de la
réinitialisation et l’autocomplétion OTP.

### Quand utiliser une autre composition

Utilisez des parties `Input` avec des index explicites lorsqu’un séparateur doit diviser le code en groupes ou lorsque
chaque champ nécessite ses propres propriétés. Utilisez `PinInput.RootProvider` et `usePinInput` lorsque l’état doit
être créé en dehors de l’arbre rendu. Les index Ark doivent rester consécutifs dans tout le code.

### Propriétés par défaut

| Propriété        | Valeur par défaut | Remarques                                                              |
| ---------------- | ----------------- | ---------------------------------------------------------------------- |
| `count`          | -                 | Nombre de cases. Indiquez-le explicitement pour obtenir un rendu SSR prévisible.               |
| `type`           | `numeric`         | `numeric`, `alphabetic` ou `alphanumeric`.                                                     |
| `placeholder`    | `''` dans moduix  | Ark utilise `○` par défaut ; moduix le masque sans `placeholder`.                              |
| `otp`            | `false`           | Active l’autocomplétion des codes à usage unique.                                              |
| `mask`           | `false`           | Masque les caractères saisis comme dans un champ de mot de passe.                              |
| `blurOnComplete` | `false`           | Retire le focus du dernier champ lorsque le code est complet.                                  |
| `selectOnFocus`  | -                 | Sélectionne la valeur actuelle d’un champ lorsqu’il reçoit le focus.                           |
| `autoFocus`      | -                 | Place automatiquement le focus dans le premier champ.                                          |
| `autoSubmit`     | -                 | Soumet le formulaire lorsque tous les champs sont remplis.                                     |
| `pattern`        | -                 | Expression régulière personnalisée pour les caractères acceptés.                               |
| `sanitizeValue`  | -                 | Nettoie les valeurs collées avant validation, par exemple en supprimant espaces et tirets.     |
| `defaultValue`   | `[]`              | Valeur initiale non contrôlée, sous forme de tableau de chaînes.                                |
| `value`          | -                 | Valeur contrôlée, sous forme de tableau de chaînes.                                            |

### Comportement

`value` et `defaultValue` sont des tableaux de chaînes. `onValueChange(details)` et `onValueComplete(details)`
fournissent `details.value` et `details.valueAsString`. `onValueInvalid(details)` fournit la valeur rejetée
`details.value` et son index `details.index`.

Utilisez `type` et `pattern` pour valider la valeur. `sanitizeValue` permet de nettoyer le texte collé avant la
validation. `Field.Root` et `Fieldset.Root` peuvent transmettre les états `disabled`, `invalid`, `required` et
`readOnly` via le contexte Ark. Les parties Ark acceptent `asChild`, et `ids` permet de définir des identifiants
stables pour les libellés ou descriptions externes.

Activez `autoSubmit` uniquement si le code complet doit soumettre le formulaire auquel le champ appartient. Le clavier
suit le comportement Ark : les touches fléchées passent d’une case à l’autre, `Backspace` efface la case et revient en
arrière si nécessaire, `Delete` efface la case courante et le collage remplit les cases restantes.

### Points d’accroche CSS

- La racine et `RootProvider` exposent `data-slot="pin-input-root"` et `data-slot="pin-input-root-provider"`.
- Les parties Ark conservent `data-scope="pin-input"` et `data-part="root" | "label" | "control" | "input"`.
- Les styles de l’état racine utilisent `data-disabled`, `data-invalid`, `data-complete` et `data-readonly`.
- Les styles d’état du champ utilisent `data-disabled`, `data-invalid`, `data-complete`, `data-filled` et `data-index`.
- `PinInput.Separator` expose `data-slot="pin-input-separator"` et est décoratif par défaut.

## Accessibilité

Ark gère le transfert du focus, la répartition du contenu collé, la modification au clavier, les données du formulaire
dans le champ masqué et l’autocomplétion. Ajoutez un `Label` pour donner un nom accessible au groupe. La racine ajoute
automatiquement son champ de formulaire natif masqué ; configurez sa participation au formulaire avec des propriétés
de la racine telles que `name` et `form`.
