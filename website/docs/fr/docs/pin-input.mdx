## Choisir le bon composant

Utilisez `PinInput` lorsqu’un code court de longueur fixe doit être saisi un caractère à la fois dans des cases
distinctes.

- Choisissez **`PinInput`** pour les codes à usage unique, les codes PIN, les codes de secours et les codes d’invitation.
- Choisissez **`Input`** lorsqu’un seul champ de texte simple suffit.
- Choisissez **`PasswordInput`** lorsque la valeur est une chaîne secrète unique avec un bouton de visibilité.

## Anatomie

```text
PinInput / PinInput.Root
├─ PinInput.Label
├─ PinInput.Control
│  ├─ PinInput.Input[index=0]
│  ├─ PinInput.Input[index=1]
│  └─ PinInput.Input[index=2]
└─ champ natif masqué (ajouté automatiquement)
```

| Partie                                  | Rôle                                                                                                  |
| --------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `PinInput` / `PinInput.Root`            | Machine à états racine, nombre de cases, tableau de valeurs, validation et options de formulaire.    |
| `PinInput.RootProvider`                 | Rend l’arborescence à partir de l’état renvoyé par `usePinInput`.                                     |
| `PinInput.Context`                      | Expose l’état racine aux descendants via une fonction de rendu.                                       |
| `PinInput.Label`                        | Libellé du groupe de saisie du code PIN ou du code de vérification.                                   |
| `PinInput.Control`                      | Conteneur des champs visibles indexés.                                                                |
| `PinInput.Input`                        | Champ visible qui accepte un caractère. Fournissez un `index` commençant à zéro.                     |
| `PinInput.Inputs`                       | Génère un `Input` indexé pour chaque élément du contexte Ark. Son `className` est appliqué à chaque champ. |
| `PinInput.Separator`                    | Composant décoratif moduix pour regrouper les champs. Ce n’est pas une partie du primitif Ark.       |
| `usePinInput`                           | Crée l’état à utiliser avec `PinInput.RootProvider`.                                                  |
| `usePinInputContext`                    | Lit l’état actuel de Pin Input dans l’arborescence du composant.                                     |

## Composition

### Composition recommandée

Utilisez la syntaxe compacte `<PinInput>`, ajoutez un `Label` visible et placez `Inputs` dans `Control`. Passez
`name` lorsque le code doit être inclus dans la soumission d’un formulaire.

### Quand créer une composition personnalisée

Rendez explicitement les parties `Input` indexées et `Separator` lorsque le code doit être divisé en groupes ou que
les champs ont besoin de propriétés différentes. Utilisez `PinInput.RootProvider` et `usePinInput` lorsque l’état
doit être créé en dehors de l’arborescence rendue. Les index doivent commencer à zéro et rester consécutifs dans
toute la composition.

### Propriétés par défaut

| Propriété        | Valeur par défaut | Remarques                                                                                          |
| ---------------- | ----------------- | -------------------------------------------------------------------------------------------------- |
| `count`          | -                 | Nombre de cases. Indiquez-le explicitement pour rendre prévisibles le SSR et les attributs ARIA.   |
| `type`           | `numeric`         | `numeric`, `alphabetic` ou `alphanumeric`.                                                         |
| `placeholder`    | `''` dans moduix  | Ark utilise `○` par défaut ; moduix utilise une chaîne vide tant que la propriété est absente.    |
| `otp`            | `false`           | Ajoute `autocomplete="one-time-code"` aux champs visibles.                                         |
| `mask`           | `false`           | Masque les caractères saisis comme dans un champ de mot de passe.                                  |
| `blurOnComplete` | `false`           | Retire le focus du dernier champ lorsque toutes les cases sont remplies.                          |
| `selectOnFocus`  | -                 | Sélectionne la valeur actuelle lorsqu’un champ reçoit le focus.                                    |
| `autoFocus`      | -                 | Place le focus sur le premier champ au montage du composant.                                      |
| `autoSubmit`     | -                 | Soumet le formulaire associé lorsque tous les champs sont remplis.                                |
| `pattern`        | -                 | Expression régulière personnalisée pour les caractères acceptés.                                  |
| `sanitizeValue`  | -                 | Nettoie les valeurs collées avant validation, par exemple en supprimant les espaces ou les tirets. |
| `defaultValue`   | `[]`              | Valeur initiale non contrôlée, sous forme de tableau de chaînes.                                   |
| `value`          | -                 | Valeur contrôlée, sous forme de tableau de chaînes.                                                |

### Comportement

`value` et `defaultValue` sont des tableaux de chaînes. Les callbacks `onValueChange(details)` et
`onValueComplete(details)` exposent `details.value` et `details.valueAsString`. Le callback
`onValueInvalid(details)` expose la valeur rejetée dans `details.value` et son `details.index`.

Utilisez `type` pour les jeux de caractères intégrés et `pattern` pour une expression régulière personnalisée.
`sanitizeValue` reçoit le texte collé et renvoie la valeur à valider.

`Field.Root` et `Fieldset.Root` peuvent fournir les états `disabled`, `invalid`, `required` et `readOnly` via le
contexte Ark. Passez à `PinInput` les options de la racine telles que `name`, `form`, `ids` et `translations`. La racine
et ses parties acceptent `asChild`.

Passez `className` à `PinInput.Inputs` lorsque tous les champs générés doivent partager la même classe. Utilisez
des parties `Input` explicites lorsque les champs doivent avoir des propriétés ou des styles différents.

Activez `autoSubmit` uniquement si la saisie complète doit soumettre le formulaire associé. Le comportement clavier
est celui d’Ark : les touches fléchées passent d’une case à l’autre, la touche Backspace efface une case et revient
en arrière si nécessaire, la touche Delete efface la case courante et le collage remplit les cases restantes.

## Accessibilité

Ark gère le transfert du focus, la répartition du texte collé, la modification au clavier, les données de formulaire
et le remplissage automatique des codes à usage unique. Ajoutez un `Label` pour donner un nom accessible au groupe.

`PinInput.Separator` est décoratif par défaut et rend les attributs `aria-hidden` et `role="presentation"`. Placez
tout texte porteur de sens en dehors du séparateur.

Pour la soumission native d’un formulaire, passez `name` à la racine. Utilisez aussi `form` lorsque le composant
appartient à un formulaire situé ailleurs dans le document. La racine rend automatiquement le champ natif masqué.

### Points d’accroche CSS

- La racine et `RootProvider` exposent `data-slot="pin-input-root"` et `data-slot="pin-input-root-provider"`.
- `Label`, `Control`, `Input` et le champ masqué exposent respectivement `data-slot="pin-input-label"`,
  `data-slot="pin-input-control"`, `data-slot="pin-input-input"` et `data-slot="pin-input-hidden-input"`.
- Les parties Ark utilisent `data-scope="pin-input"` et `data-part="root" | "label" | "control" | "input"`.
- Les styles de l’état racine utilisent `data-disabled`, `data-invalid`, `data-complete` et `data-readonly`.
- Les styles d’état du champ utilisent `data-disabled`, `data-invalid`, `data-complete`, `data-filled` et
  `data-index`.
- `PinInput.Separator` expose `data-slot="pin-input-separator"` et est décoratif par défaut.
