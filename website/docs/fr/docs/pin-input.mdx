## Choisir le bon composant

Utilisez `PinInput` lorsqu’un code court de longueur fixe doit être saisi caractère par caractère dans des cases séparées.

- Choisissez **`PinInput`** pour les codes à usage unique, les codes PIN, les codes de récupération et les codes d’invitation.
- Choisissez **`Input`** lorsqu’un seul champ de texte suffit.
- Choisissez **`PasswordInput`** lorsque la valeur est une chaîne secrète unique avec un bouton d’affichage.

## Exemple de base

Utilisez `PinInput` comme racine et définissez explicitement `count`. Ajoutez `PinInputLabel` pour donner un nom accessible
au groupe, placez `PinInputInputs` dans `PinInputControl` et composez `PinInputHiddenInput` lorsque la valeur doit participer au comportement
d’un formulaire natif.

## Anatomie

```text
PinInput
├─ PinInputLabel
├─ PinInputControl
│  ├─ PinInputInput[index=0]
│  ├─ PinInputInput[index=1]
│  └─ PinInputInput[index=2]
└─ PinInputHiddenInput (explicite)

PinInputRootProvider
└─ même arbre de parties relié à un store usePinInput()
```

| Partie | Rôle |
| --- | --- |
| `PinInput` | Gère le nombre de cases, l’état de la valeur, la validation et les options du formulaire. |
| `PinInputHiddenInput` | Contrôle de formulaire natif Ark à composer explicitement. |
| `PinInputRootProvider` | Relie les parties à l’état créé avec `usePinInput()`. |
| `PinInputContext` | Expose l’état de la racine aux descendants via une render prop. |
| `PinInputLabel` | Donne un libellé au groupe de saisie du code PIN ou de vérification. |
| `PinInputControl` | Conteneur des cases visibles indexées. |
| `PinInputInput` | Une case visible pour un caractère. Utilisez un `index` commençant à zéro. |
| `PinInputInputs` | Génère une partie `PinInputInput` indexée pour chaque élément du contexte Ark. |
| `PinInputSeparator` | Aide décorative de moduix pour les groupes, et non une partie du primitif Ark. |
| `usePinInput` | Crée l’état à utiliser avec `PinInputRootProvider`. |
| `usePinInputContext` | Lit l’état courant de Pin Input dans l’arbre du composant. |

## Composition

Composez explicitement `PinInputHiddenInput` dans `PinInput` ou `PinInputRootProvider` lorsque la valeur doit
être envoyée par un formulaire natif et être réinitialisée avec lui. Définissez `name` sur la racine et utilisez
`form` lorsque le formulaire se trouve en dehors de l’arbre du composant.

`PinInputInputs` génère une case indexée pour chaque élément du contexte Ark. Utilisez des parties `PinInputInput` explicites
avec des index continus commençant à zéro, ainsi que `PinInputSeparator` lorsque le code doit être divisé en groupes. Les
valeurs sont des tableaux de chaînes. Utilisez `PinInputRootProvider` avec `usePinInput` lorsque l’état ou les méthodes
impératives doivent être gérés en dehors de l’arbre rendu ; React reçoit un objet store, Solid reçoit un accessor
réactif, et Vue expose directement le store réactif au template.

Ark gère le transfert du focus, la répartition du texte collé, la saisie au clavier et le remplissage automatique
des codes à usage unique ; ajoutez `PinInputLabel` pour donner un nom accessible au groupe. `PinInputSeparator`
est décoratif et rend `aria-hidden` ; placez tout texte porteur de sens en dehors
du séparateur.

## Exemples

### Retirer le focus à la fin

Définissez `blurOnComplete` lorsque le focus doit quitter le dernier champ une fois toutes les cases remplies.

<Example name="pin-input/blur-on-complete" />

### Événements de changement

Conservez le tableau de valeurs dans l’état et lisez `details.value` ou `details.valueAsString` dans les callbacks Ark.

<Example name="pin-input/change-events" />

### Field

Placez `PinInput` dans `Field` lorsque le libellé, le texte d’aide, le message d’erreur et l’état du champ doivent
être associés aux cases visibles par les mécanismes d’accessibilité des formulaires d’Ark.

<Example name="pin-input/field" />

### Disposition groupée

Utilisez des parties `PinInputInput` indexées explicites et `PinInputSeparator` lorsqu’un séparateur doit diviser le code en groupes.
Gardez des index continus dans toute la composition.

<Example name="pin-input/grouped-layout" />

### Masquage

Définissez `mask` lorsque le code saisi est sensible et ne doit pas être affiché en clair.

<Example name="pin-input/masking" />

### Mode OTP

Définissez `otp` pour ajouter `autocomplete="one-time-code"` aux champs visibles et activer les suggestions de
codes à usage unique sur les navigateurs mobiles compatibles.

<Example name="pin-input/otp-mode" />

### Placeholder

Passez `placeholder` pour afficher un caractère dans chaque case vide. Par défaut, moduix laisse le placeholder vide.

<Example name="pin-input/placeholder" />

### Root Provider

Utilisez `usePinInput` avec `PinInputRootProvider` lorsque l’état et les méthodes impératives doivent être gérés en dehors
de l’arbre rendu. Cet exemple remplace `PinInputInputs` par des parties `PinInputInput` indexées explicites.

<Example name="pin-input/root-provider" />

### Tailles

Utilisez la prop `size` sur la racine pour aligner la taille des cases sur la hauteur des contrôles `Input`
et `Button`. La valeur par défaut est `md` ; le texte des cases suit la taille.

<Example name="pin-input/sizes" />

## Styles

### Propriétés CSS

<CssPropertiesSection properties={PinInputDocs.pinInputOverrideCssProperties} />

Les paquets CSS Modules exposent trois variables : `--moduix-pin-input-input-size` (valable pour toutes les
tailles), `--moduix-pin-input-gap` et `--moduix-pin-input-radius`. Les couleurs, bordures, la typographie et
l’anneau de focus viennent des jetons de foundation ; remplacez-les avec une classe sur la partie. Les variantes
Tailwind utilisent des classes utilitaires natives et les remplacements de l’utilisateur via `className` ou `class`.

### Points d’accroche CSS

- La racine et `PinInputRootProvider` exposent `data-slot="pin-input-root"` et `data-slot="pin-input-root-provider"`.
- `PinInputLabel`, `PinInputControl` et `PinInputInput` exposent `data-slot="pin-input-label"`, `data-slot="pin-input-control"` et
  `data-slot="pin-input-input"`.
- Les parties Ark utilisent `data-scope="pin-input"` et `data-part="root" | "label" | "control" | "input"`.
- Les styles de l’état racine utilisent `data-disabled`, `data-invalid`, `data-complete` et `data-readonly`.
- Les styles d’état des cases utilisent `data-disabled`, `data-invalid`, `data-complete`, `data-filled` et
  `data-index`.
- `PinInputSeparator` expose `data-slot="pin-input-separator"` et est décoratif par défaut.
- La racine reflète `size` dans `data-size`. Un `PinInput` désactivé dans un `Field` ou un `Fieldset` désactivé
  n’est pas assombri une seconde fois.
