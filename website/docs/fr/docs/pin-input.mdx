## Choisir le bon composant

Utilisez `PinInput` lorsqu’un code court de longueur fixe doit être saisi caractère par caractère dans des cases séparées.

- Choisissez **`PinInput`** pour les codes à usage unique, les codes PIN, les codes de récupération et les codes d’invitation.
- Choisissez **`Input`** lorsqu’un seul champ de texte suffit.
- Choisissez **`PasswordInput`** lorsque la valeur est une chaîne secrète unique avec un bouton d’affichage.

## Anatomie

```text
PinInput / PinInput.Root
├─ PinInput.Label
├─ PinInput.Control
│  ├─ PinInput.Input[index=0]
│  ├─ PinInput.Input[index=1]
│  └─ PinInput.Input[index=2]
└─ PinInput.HiddenInput (explicite)

PinInput.RootProvider
└─ même arbre de parties relié à un store usePinInput()
```

| Partie | Rôle |
| --- | --- |
| `PinInput` / `PinInput.Root` | Gère le nombre de cases, l’état de la valeur, la validation et les options du formulaire. |
| `PinInput.HiddenInput` | Contrôle de formulaire natif Ark à composer explicitement. |
| `PinInput.RootProvider` | Relie les parties à l’état créé avec `usePinInput()`. |
| `PinInput.Context` | Expose l’état de la racine aux descendants via une render prop. |
| `PinInput.Label` | Donne un libellé au groupe de saisie du code PIN ou de vérification. |
| `PinInput.Control` | Conteneur des cases visibles indexées. |
| `PinInput.Input` | Une case visible pour un caractère. Utilisez un `index` commençant à zéro. |
| `PinInput.Inputs` | Génère une partie `Input` indexée pour chaque élément du contexte Ark. |
| `PinInput.Separator` | Aide décorative de moduix pour les groupes, et non une partie du primitif Ark. |
| `usePinInput` | Crée l’état à utiliser avec `PinInput.RootProvider`. |
| `usePinInputContext` | Lit l’état courant de Pin Input dans l’arbre du composant. |

## Composition

Composez explicitement `PinInput.HiddenInput` dans `PinInput` ou `PinInput.RootProvider` lorsque la valeur doit
être envoyée par un formulaire natif et être réinitialisée avec lui. Définissez `name` sur la racine et utilisez
`form` lorsque le formulaire se trouve en dehors de l’arbre du composant.

`PinInput.Inputs` génère une case indexée pour chaque élément du contexte Ark. Utilisez des parties `Input` explicites
avec des index continus commençant à zéro, ainsi que `Separator` lorsque le code doit être divisé en groupes. Les
valeurs sont des tableaux de chaînes. Utilisez `RootProvider` avec `usePinInput` lorsque l’état ou les méthodes
impératives doivent être gérés en dehors de l’arbre rendu ; React reçoit un objet store, tandis que Solid reçoit un
accessor réactif.

## Accessibilité

Ark gère le transfert du focus, la répartition du texte collé, la saisie au clavier, les données du formulaire et
le remplissage automatique des codes à usage unique. Ajoutez `Label` pour donner un nom accessible au groupe.

`PinInput.Separator` est décoratif par défaut et rend `aria-hidden` ainsi que `role="presentation"`. Placez tout
texte porteur de sens en dehors du séparateur.

### Points d’accroche CSS

- La racine et `RootProvider` exposent `data-slot="pin-input-root"` et `data-slot="pin-input-root-provider"`.
- `Label`, `Control` et `Input` exposent `data-slot="pin-input-label"`, `data-slot="pin-input-control"` et
  `data-slot="pin-input-input"`.
- Les parties Ark utilisent `data-scope="pin-input"` et `data-part="root" | "label" | "control" | "input"`.
- Les styles de l’état racine utilisent `data-disabled`, `data-invalid`, `data-complete` et `data-readonly`.
- Les styles d’état des cases utilisent `data-disabled`, `data-invalid`, `data-complete`, `data-filled` et
  `data-index`.
- `PinInput.Separator` expose `data-slot="pin-input-separator"` et est décoratif par défaut.
