## Anatomie

```text
SignaturePad
├─ SignaturePadLabel
├─ SignaturePadCanvas (composition prête à l’emploi de moduix)
│  └─ SignaturePadControl
│     ├─ SignaturePadSegment
│     ├─ SignaturePadClearTrigger
│     └─ SignaturePadGuide
└─ SignaturePadHiddenInput value={serializedPaths} (explicite)

SignaturePadRootProvider
└─ même arbre de parties connecté à l’état de useSignaturePad()
```

| Partie                               | Rôle                                                                    |
| ------------------------------------ | ----------------------------------------------------------------------- |
| `SignaturePad`             | Gère les tracés, les options de dessin, le nom du champ, les identifiants et les rappels. |
| `SignaturePadHiddenInput`  | Champ natif d’Ark à composer explicitement.                             |
| `SignaturePadRootProvider` | Rend le même arbre de parties à partir de l’état créé avec `useSignaturePad()`. |
| `SignaturePadLabel`        | Associe le libellé visible à la zone de dessin et au champ masqué.      |
| `SignaturePadCanvas`       | Surface prête à l’emploi qui rend les parties standard et transmet les propriétés de `SignaturePadControl`. |
| `SignaturePadControl`      | Zone de dessin au pointeur et au toucher, pouvant recevoir le focus.     |
| `SignaturePadSegment`      | Calque SVG pour les traits enregistrés et le trait en cours.            |
| `SignaturePadClearTrigger` | Bouton natif qui efface les tracés.                                     |
| `SignaturePadGuide`        | Ligne repère non interactive dans la zone de dessin.                    |

## Composition

Pour la composition standard, utilisez `SignaturePadLabel` et `SignaturePadCanvas`.
`SignaturePadCanvas` utilise une arborescence d’enfants fixe ; utilisez donc `SignaturePadControl`,
`SignaturePadSegment`, `SignaturePadClearTrigger` et `SignaturePadGuide` si la structure de
la zone de dessin ou le bouton d’effacement doit changer.

`SignaturePadHiddenInput` n’est pas rendu automatiquement. Ajoutez-le explicitement et transmettez
une valeur sérialisée, généralement lue avec `SignaturePadContext` ou
`useSignaturePadContext()`, lorsque la signature doit être envoyée par un formulaire natif.

Utilisez `defaultPaths` pour un état local non contrôlé. Utilisez `paths` avec
`onDraw(details)` lorsque l’application possède les données de la signature. Utilisez
`SignaturePadRootProvider` avec `useSignaturePad()` lorsque l’état doit être créé en dehors de l’arborescence
rendue ou que des contrôles externes doivent accéder à `paths`, `clear()` ou `getDataUrl()`.
Dans Vue, contrôlez les tracés avec `v-model:paths` et utilisez `@draw` ou `@draw-end`
pour recevoir les détails du dessin.

Avec Ark Vue 5.39.3, `drawEnd.paths` peut contenir la valeur précédente en mode contrôlé.
`v-model:paths` reçoit les tracés terminés.

Contrairement à Ark, moduix masque `SignaturePadClearTrigger` lorsque `readOnly` provient de la racine, d’un
`Field` englobant ou de `useSignaturePad()`, ce qui empêche un effacement irréversible tandis que
le `clear()` programmatique reste disponible.

## Exemples

### État contrôlé

Utilisez `paths` en mode contrôlé pour conserver la signature dans l’état de l’application et la
coordonner avec des contrôles de réinitialisation ou une logique d’enregistrement automatique.

<Example name="signature-pad/controlled" />

### Dessin

Transmettez `drawing` lorsque l’épaisseur, la couleur du trait ou le comportement de la pression
doivent différer des valeurs par défaut. La valeur par défaut à l’exécution est
`{ size: 2, simulatePressure: false }` (la page de documentation d’Ark montre
`simulatePressure: true`), la simulation de pression est donc à activer explicitement.

<Example name="signature-pad/drawing" />

### Champ de formulaire

Utilisez `Field` autour de `SignaturePad` lorsque le texte d’aide, le message d’erreur, l’état
obligatoire ou le message de validation concernent un même contrôle de formulaire.

<Example name="signature-pad/field" />

### Sérialisation du formulaire

Sérialisez dans le consommateur la valeur transmise à `SignaturePadHiddenInput` lorsque le serveur
attend un autre format. Cet exemple envoie un tableau JSON.

<Example name="signature-pad/form-serialization" />

### Aperçu de l’image

Utilisez `onDrawEnd` pour exporter la signature et l’afficher avant son enregistrement.

<Example name="signature-pad/image-preview" />

### Root Provider

Créez l’état avec `useSignaturePad()` et transmettez-le à `SignaturePadRootProvider` lorsque des contrôles
situés en dehors de l’arborescence rendue doivent accéder directement à `paths`, `clear()` ou
`getDataUrl()`.

<Example name="signature-pad/root-provider" />

### Personnalisation avancée

Utilisez les parties explicites à la place de `SignaturePadCanvas` lorsque vous devez contrôler l’arborescence
des parties de dessin ou fournir votre propre bouton d’effacement.

<Example name="signature-pad/advanced-customization" />

### Points d’accroche CSS

Utilisez `className` dans React ou `class` dans Solid et Vue sur toute partie exportée pour appliquer des
styles locaux. moduix ajoute également des attributs `data-slot` stables :

| Partie                               | `data-slot`                   |
| ------------------------------------ | ----------------------------- |
| `SignaturePad`             | `signature-pad-root`          |
| `SignaturePadRootProvider` | `signature-pad-root-provider` |
| `SignaturePadLabel`        | `signature-pad-label`          |
| `SignaturePadControl`      | `signature-pad-control`        |
| `SignaturePadSegment`      | `signature-pad-segment`        |
| `SignaturePadGuide`        | `signature-pad-guide`          |
| `SignaturePadClearTrigger` | `signature-pad-clear-trigger` |

Les attributs Ark restent disponibles pour cibler les styles. `SignaturePad`, `SignaturePadLabel`,
`SignaturePadControl`, `SignaturePadSegment`, `SignaturePadGuide`, `SignaturePadClearTrigger` et les
tracés internes du segment fournissent `data-scope="signature-pad"`
et `data-part` ; `data-disabled` apparaît sur la racine, le libellé, la zone de dessin et la ligne
repère, tandis que `data-required` apparaît sur le libellé.
