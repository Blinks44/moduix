## Choisir le bon composant

Utilisez `SegmentGroup` lorsque l’utilisateur choisit une valeur dans un petit ensemble visible en
même temps.

- Choisissez **`Tabs`** lorsque la sélection doit également modifier un panneau de contenu visible.
- Choisissez **`ToggleGroup`** lorsque les éléments se comportent comme des boutons de barre d’outils et que plusieurs valeurs peuvent être actives.
- Choisissez **`RadioGroup`** lorsque le contrôle doit conserver l’apparence familière des boutons radio.
- Choisissez **`SegmentGroup`** lorsque l’interaction ressemble à celle d’un groupe de boutons radio, mais que l’interface doit rester compacte et segmentée.

## Exemple de base

Utilisez `SegmentGroup.Items` lorsque chaque segment n’a besoin que d’un libellé textuel. Le composant
crée pour chaque entrée les parties Ark `item`, `text` et `control`, ainsi qu’un champ de formulaire
natif synchronisé.

## Anatomie

```text
SegmentGroup / SegmentGroup.Root
├─ SegmentGroup.Label (facultatif)
├─ SegmentGroup.Indicator
└─ SegmentGroup.Item[value]
   ├─ SegmentGroup.ItemText
   ├─ SegmentGroup.ItemControl
   └─ champ de formulaire natif

SegmentGroup.RootProvider
└─ même arborescence d’éléments reliée à un store moduix useSegmentGroup()

SegmentGroup.Context / SegmentGroup.ItemContext
└─ accès avancé à l’état Ark via render prop
```

| Partie                                | Rôle                                                                  |
| ------------------------------------- | --------------------------------------------------------------------- |
| `SegmentGroup` / `SegmentGroup.Root`  | Gère la valeur sélectionnée, la navigation au clavier et les formulaires. |
| `SegmentGroup.RootProvider`            | Relie les parties à l’état créé avec `useSegmentGroup()` de moduix.   |
| `SegmentGroup.Context`                 | Donne un accès avancé à l’état racine via render prop.                |
| `SegmentGroup.ItemContext`             | Donne un accès avancé à l’état de l’élément courant via render prop.  |
| `SegmentGroup.Label`                   | Libellé accessible facultatif du groupe.                              |
| `SegmentGroup.Indicator`               | Positionne la mise en évidence de l’élément actif avec les variables CSS d’Ark. |
| `SegmentGroup.Items`                   | Méthode recommandée pour afficher des segments textuels standard.     |
| `SegmentGroup.Item`                    | Segment sélectionnable ; rend un `label` par défaut.                  |
| `SegmentGroup.ItemText`                | Libellé visible du segment.                                           |
| `SegmentGroup.ItemControl`             | Partie Ark utilisée pour l’état de l’élément, masquée par les styles moduix. |

## Composition

### Composition recommandée

Dans le cas courant, utilisez la forme racine courte `<SegmentGroup>` avec `SegmentGroup.Items`.
Placez `SegmentGroup.Indicator` avant les éléments afin que la mise en évidence mesurée apparaisse
derrière le segment sélectionné. `Items` conserve un champ de formulaire natif dans chaque élément
créé, ce qui permet la soumission et la réinitialisation d’un formulaire natif.

### Quand utiliser une composition personnalisée

Utilisez `SegmentGroup.Item` lorsqu’un segment nécessite un contenu personnalisé, sa propre classe ou
`asChild`. L’enfant direct de `asChild` doit rester un unique `label` sémantique. Utilisez
`SegmentGroup.RootProvider` avec `useSegmentGroup()` depuis `@moduix/react` lorsque des contrôles
situés en dehors de l’arborescence des segments doivent appeler des méthodes comme `setValue`,
`clearValue` ou `focus`. Pour créer un rendu personnalisé piloté par l’état, utilisez
`SegmentGroup.Context`, `SegmentGroup.ItemContext`, `useSegmentGroupContext` ou
`useSegmentGroupItemContext` depuis `@moduix/react`.

`ItemHiddenInput` est interne à moduix. Chaque `SegmentGroup.Item` rend déjà exactement un champ natif de type radio
natif synchronisé, y compris avec `asChild`. N’ajoutez pas une seconde fois `ItemHiddenInput` d’Ark.

### Propriétés par défaut

| Propriété       | Valeur par défaut | Remarques                                                               |
| --------------- | ----------------- | ----------------------------------------------------------------------- |
| `defaultValue`  | non définie      | Valeur initiale d’un groupe non contrôlé.                              |
| `value`         | non définie      | Valeur sélectionnée d’un groupe contrôlé.                               |
| `orientation`   | `horizontal`     | Valeur par défaut de moduix ; définissez `vertical` pour un groupe vertical. |
| `disabled`      | `false`           | Désactive tout le groupe lorsqu’elle est définie sur la racine.         |
| `readOnly`      | `false`           | Empêche les modifications tout en laissant la valeur visible.          |
| `required`      | `false`           | Rend les champs natifs obligatoires lors de la validation du formulaire. |
| `invalid`       | `false`           | Ajoute les attributs d’état invalide d’Ark pour le style et ARIA.       |

### Comportement

`onValueChange(details)` conserve la forme du rappel d’Ark. La valeur sélectionnée se trouve dans
`details.value`. Ark gère la valeur sélectionnée, le déplacement du focus, la navigation avec les
flèches, les états `disabled`, `readOnly`, `invalid` et `required`, ainsi que la soumission et la
réinitialisation du formulaire.

La touche <kbd>Tab</kbd> place le focus sur l’élément sélectionné ou, si aucune valeur n’est
sélectionnée, sur le premier élément. Les touches fléchées déplacent le focus et sélectionnent
l’élément suivant ou précédent. La touche <kbd>Espace</kbd> sélectionne l’élément qui a le focus.
Définissez `name` sur la racine pour inclure la valeur sélectionnée dans les données natives de
`FormData`.

`Root`, `RootProvider`, `Label`, `Item`, `ItemControl`, `ItemText` et `Indicator` transmettent leurs
refs aux parties DOM correspondantes d’Ark. Utilisez `Field` ou `Fieldset` lorsque leur état partagé
doit s’appliquer au groupe : `Field` transmet les états `disabled`, `invalid`, `required` et
`readOnly`, tandis que `Fieldset` transmet `disabled` et `invalid`. Utilisez `ids` lorsque des
libellés ou contrôles composés ont besoin d’identifiants d’accessibilité déterministes.

Stylisez `SegmentGroup` avec `className`, les hooks stables `data-slot="segment-group-*"`, les
attributs Ark `data-scope`, `data-part` et d’état, ainsi que les variables CSS publiques
`--moduix-segment-group-*` listées ci-dessous.

### Hooks de style

- Hooks d’anatomie Ark : `data-scope="segment-group"` et `data-part` sur la racine, le libellé,
  l’indicateur, l’élément, le texte de l’élément, son contrôle et le champ masqué.
- Hooks d’état Ark : `data-state="checked" | "unchecked"`, `data-orientation`, `data-disabled`,
  `data-readonly`, `data-invalid`, `data-required`, `data-active` et `data-focus-visible`.
- Hooks moduix : `data-slot="segment-group-root"`, `segment-group-root-provider`,
  `segment-group-label`, `segment-group-indicator`, `segment-group-item`,
  `segment-group-item-text`, `segment-group-item-control` et `segment-group-item-hidden-input`.
- L’indicateur utilise les variables d’exécution Ark `--left`, `--top`, `--width` et `--height`
  pour sa taille. Son animation utilise `--transition-duration` et `--transition-timing-function`,
  avec les valeurs par défaut de moduix définies par `--moduix-segment-group-indicator-transition-duration`
  et `--moduix-segment-group-indicator-transition-timing-function`.
