# Mise à jour et migration

moduix propose deux façons d’installer ses composants. La procédure de mise à jour dépend de
l’emplacement du code source du composant :

| Installation | Emplacement du code source | Procédure de mise à jour |
| --- | --- | --- |
| Package `@moduix/react` | Dans `node_modules` | Mettez à jour le package et ses dépendances peer avec votre gestionnaire de paquets. |
| Registre shadcn | Dans le dépôt de votre application | Examinez les changements du registre, puis fusionnez-les avec votre code source local. |

Si vous migrez une application shadcn existante vers moduix, consultez [Migrer depuis shadcn](/docs/migrate-from-shadcn).

## Mettre à jour le package npm

Choisissez cette méthode si vous voulez conserver moduix dans les dépendances de votre application
et recevoir les mises à jour avec votre gestionnaire de paquets.

Avant de modifier les versions, consultez le [Journal des modifications](/docs/changelog). Utilisez
`npm update` pour les mises à jour compatibles qui restent dans les plages de versions déjà
déclarées dans `package.json` :

Les exemples ci-dessous utilisent npm. Si vous utilisez pnpm, Yarn ou un autre gestionnaire de
paquets, remplacez-les par les commandes équivalentes de votre outil.

```bash
npm update @moduix/react @ark-ui/react
```

Pour choisir explicitement les versions et modifier les plages déclarées, installez les versions
souhaitées :

```bash
npm install @moduix/react@latest @ark-ui/react@latest
```

`@ark-ui/react` est une dépendance peer de `@moduix/react`. Avant une mise à niveau majeure, vérifiez
dans les notes de version la plage compatible avec Ark UI. Ne mettez pas les deux packages à niveau
sans cette vérification. Choisissez soigneusement la version majeure de moduix, puis suivez les étapes
de migration indiquées dans son journal des modifications.

Après la mise à jour, vérifiez le lockfile, lancez la vérification des types et les tests de votre
application, puis testez les composants cités dans le journal des modifications. Si la version modifie
la composition ou les styles, comparez la documentation du composant avec votre implémentation avant
de publier la mise à jour.

## Mettre à jour les composants du registre

Les composants du registre sont copiés dans le dépôt de votre application. Ils ne sont pas mis à jour
avec `@moduix/react` : examinez donc chaque élément du registre séparément.

Avant de modifier les fichiers locaux, examinez l’élément actuel et comparez-le avec votre copie :

```bash
npx shadcn@latest view @moduix-react/button
npx shadcn@latest add @moduix-react/button --dry-run
npx shadcn@latest add @moduix-react/button --diff
```

Remplacez `button` par l’élément à mettre à jour. `view` affiche le code source actuel du registre,
`--dry-run` prévisualise les fichiers qui seraient modifiés et `--diff` compare la version du registre
avec les fichiers de votre projet. Le diff peut inclure des fichiers communs de la base moduix et d’autres
dépendances du registre : examinez-les également.

Après avoir examiné le diff, lancez la mise à jour depuis une branche ou avec un arbre de travail propre :

```bash
npx shadcn@latest add @moduix-react/button
```

N’utilisez pas `--overwrite` avant d’avoir décidé comment conserver vos modifications locales. Si vous
avez modifié un composant dans votre application, fusionnez les changements du registre avec votre
version, puis vérifiez son comportement, son accessibilité et ses styles.

Répétez cette procédure pour chaque élément du registre que vous utilisez. Le CLI résout
automatiquement la fondation partagée de moduix et les dépendances déclarées des éléments. Importez
une seule fois la feuille de styles de fondation générée dans le point d’entrée de votre application :

```tsx
import '@/lib/moduix/styles/style.css';
```

## Mettre à jour les presets

Les presets fournis avec `@moduix/react` sont mis à jour avec le package. Consultez [Thèmes](/docs/themes)
et [Tokens](/docs/tokens) si une version modifie la densité, les couleurs ou d’autres valeurs visuelles
partagées par défaut.

Pour un preset copié depuis le registre, examinez-le et mettez-le à jour comme n’importe quel autre élément :

```bash
npx shadcn@latest view @moduix-react/theme-soft
npx shadcn@latest add @moduix-react/theme-soft --dry-run
npx shadcn@latest add @moduix-react/theme-soft --diff
```

Après avoir examiné le diff, installez le preset sans `--dry-run` et placez vos redéfinitions après
son import. La cascade reste ainsi prévisible lorsqu’un nouveau token est ajouté au preset :

```tsx
import '@/lib/moduix/styles/style.css';
import '@/lib/moduix/presets/soft.css';
```
