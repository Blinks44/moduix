# Mise à jour et migration

La méthode dépend de l’emplacement du code source. Les utilisateurs des packages mettent leurs
dépendances à jour ; ceux du registre examinent les changements et les fusionnent avec le code de
l’application.

| Distribution | Emplacement du code | Méthode de mise à jour |
| --- | --- | --- |
| Package npm | `node_modules` | Mettre à jour les packages Moduix et Ark UI correspondants. |
| Registre shadcn | Dépôt de l’application | Examiner le diff du registre, puis le fusionner avec les changements locaux. |

Pour migrer une application shadcn existante, commencez par
[Migrer depuis shadcn](/docs/migrate-from-shadcn).

## Identifier l’adaptateur installé

Gardez le framework et la méthode de style explicites :

| Environnement | CSS Modules | Tailwind CSS |
| --- | --- | --- |
| React | `@moduix/react` | `@moduix/react-tailwind` |
| Solid | `@moduix/solid` | `@moduix/solid-tailwind` |

Ne mettez pas à jour un adaptateur au nom proche que l’application n’utilise pas. Le catalogue
Tailwind peut rester plus réduit pendant la migration des composants.

Ark UI est une peer dependency. Avant une version majeure, vérifiez la plage compatible dans les
notes de version au lieu de mettre les deux packages à jour sans contrôle. Examinez ensuite le
lockfile.

## Mettre les composants du registre à jour

Les composants du registre sont copiés dans l’application et ne suivent pas les packages. Choisissez
le namespace qui correspond aux deux axes :

| Environnement | Registre CSS Modules | Registre Tailwind |
| --- | --- | --- |
| React | `@moduix-react` | `@moduix-react-tailwind` |
| Solid | `@moduix-solid` | `@moduix-solid-tailwind` |

Prévisualisez un composant avant de modifier les fichiers locaux :

<PackageManagerTabs command="shadcn@latest view @moduix-react/button" dlx />

<PackageManagerTabs command="shadcn@latest add @moduix-react/button --dry-run" dlx />

<PackageManagerTabs command="shadcn@latest add @moduix-react/button --diff" dlx />

Remplacez le namespace par l’adaptateur installé et `button` par l’élément concerné. Le diff peut
inclure des fichiers de fondation et des dépendances du registre, il faut donc l’examiner entièrement.

Après cette revue, lancez la mise à jour dans une branche ou un arbre de travail propre :

<PackageManagerTabs command="shadcn@latest add @moduix-react/button" dlx />

N’utilisez pas `--overwrite` avant d’avoir décidé comment conserver les modifications locales.
Fusionnez les changements de comportement, d’accessibilité et de style avec les décisions du produit.

## Mettre les styles et presets à jour

Les styles et presets d’un package suivent sa version. Les fichiers de fondation et de preset copiés
depuis le registre doivent être examinés comme les autres éléments.

Importez une seule fois la feuille de fondation créée par la configuration du registre :

```tsx
import '@/lib/moduix/styles/style.css';
```

Les redéfinitions de l’application doivent venir après la fondation et le preset. Si une version
modifie les tokens, la densité, les couleurs ou les animations, consultez [Thèmes](/docs/themes),
[Tokens](/docs/tokens) et [Animations](/docs/animations).

## Vérifier la mise à jour

- Examinez ensemble le manifeste du package et le lockfile.
- Lancez le formatage, le lint, le typecheck et les tests de l’application.
- Testez les composants et interactions cités dans le Changelog.
- Vérifiez le clavier, le retour du focus, les portails et la réduction des animations si nécessaire.
- Comparez les changements locaux du registre au diff amont complet avant la publication.
