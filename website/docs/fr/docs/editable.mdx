## Choisir le bon composant

- Choisissez **`Input`** ou **`Textarea`** lorsque la valeur doit toujours se présenter comme modifiable.
- Choisissez **`Editable`** lorsque la valeur est généralement en lecture seule et que l’utilisateur passe volontairement en mode de modification.
- Placez **`Editable`** dans **`Field`** lorsque le texte d’aide, le message d’erreur ou l’état global du formulaire doivent s’afficher
  en dehors de la structure d’`Editable`.

## Exemple de base

Utilisez les parties Ark : `Editable`, `Editable.Label`, `Editable.Area`, `Editable.Input` et
`Editable.Preview`. Ajoutez `Editable.Controls` pour obtenir le fonctionnement standard avec les boutons de modification,
de validation et d’annulation. Le composant moduix ajoute les styles, les attributs `data-slot` et les icônes par défaut

## Anatomie

```text
Editable.Root
├─ Editable.Label
├─ Editable.Area
│  ├─ Editable.Input
│  └─ Editable.Preview
├─ Editable.Control ou Editable.Controls
│  ├─ Editable.EditTrigger
│  ├─ Editable.SubmitTrigger
│  └─ Editable.CancelTrigger

Editable.RootProvider
└─ le même arbre de parties, relié à l’état Ark `useEditable()`
```

| Partie                       | Rôle                                                                                 |
| ---------------------------- | ------------------------------------------------------------------------------------ |
| `Editable` / `Editable.Root` | État du composant, callbacks, propriétés de formulaire et liaison avec l’accessibilité. |
| `Editable.RootProvider`      | Composant racine relié à une instance de `useEditable()`.                                |
| `Editable.Label`             | Libellé visible du champ et de l’aperçu.                                                  |
| `Editable.Area`              | Conteneur commun du champ de saisie et de l’aperçu.                                       |
| `Editable.Input`             | Champ de texte affiché pendant la modification.                                           |
| `Editable.Preview`           | Valeur affichée ou espace réservé affiché hors du mode de modification.                   |
| `Editable.Control`           | Conteneur facultatif pour les boutons de modification, de validation et d’annulation.     |
| `Editable.Controls`          | Groupe prêt à l’emploi pour le parcours standard de modification, de validation et d’annulation. |
| `Editable.EditTrigger`       | Bouton qui active le mode de modification.                                                |
| `Editable.SubmitTrigger`     | Bouton qui valide la valeur actuelle.                                                      |
| `Editable.CancelTrigger`     | Bouton qui rétablit la valeur précédente.                                                  |

## Composition

### Composition recommandée

Gardez `Input` et `Preview` côte à côte dans `Area`, puis placez `Controls` après `Area` pour la disposition standard des boutons.
Pour un champ sur une ligne, les boutons apparaissent à droite et sont centrés verticalement. Avec une textarea, la structure
reste la même. Définissez `--moduix-editable-control-align: start` pour aligner les contrôles en haut de la zone multiligne.

### Quand créer une composition personnalisée

Utilisez `Editable.Context` de moduix ou `useEditableContext()` lorsque des enfants réutilisables ou du code intégré à l’arbre
doivent accéder à l’état de modification. Utilisez `useEditable()` avec `Editable.RootProvider` lorsque l’état ou les méthodes
doivent être gérés en dehors de l’arbre `Editable` rendu. Utilisez `asChild` lorsque le champ doit utiliser un autre élément
sémantiquement adapté, par exemple une textarea.

### Propriétés par défaut

| Propriété        | Valeur par défaut | Remarques                                                                                                                      |
| ---------------- | ----------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `activationMode` | `dblclick`        | moduix utilise le double-clic par défaut. Passez `focus`, `click` ou `none` pour choisir un autre mode d’activation Ark.       |
| `selectOnFocus`  | `true`            | Ark sélectionne le texte du champ lorsqu’il reçoit le focus.                                                                  |
| `submitMode`     | `both`            | `Enter` et la perte de focus valident la valeur par défaut. Utilisez `none` si seule une commande explicite doit valider la valeur. |

### Comportement

`value` et `defaultValue` définissent la valeur textuelle. `edit` et `defaultEdit` contrôlent le mode de modification. Les callbacks
Ark conservent leur objet `details` : `onValueChange`, `onValueCommit`, `onValueRevert` et `onEditChange` reçoivent donc les
mêmes données et les mêmes propriétés utiles qu’avec Ark UI.

`Enter` valide les modifications et `Escape` les annule. Lorsque `Editable.Input` est rendu comme une textarea avec `asChild`,
Cmd/Ctrl + Enter valide la valeur. `name` et `form` sont transmis à Ark pour permettre la soumission native du formulaire.
`disabled` bloque l’activation, tandis que `readOnly` garde la valeur visible sans permettre sa modification.

Définissez `translations.input` lorsque le champ nécessite un nom accessible adapté au contexte. `Editable.Label` reste le libellé visible.

### Points d’accroche CSS

- `data-slot="editable-root"`, `editable-root-provider`, `editable-label`, `editable-area`,
  `editable-input`, `editable-preview`, `editable-control`, `editable-edit-trigger`,
  `editable-submit-trigger` et `editable-cancel-trigger`.
- Ark ajoute également les attributs `data-scope="editable"` et `data-part` à chaque partie primitive.
- Les sélecteurs d’état comprennent `data-focus` sur `Label` et `Area` ; `data-disabled` sur `Area`, `Input`
  et `Preview` ; `data-readonly` / `aria-readonly` sur les contrôles en lecture seule ; `data-invalid` sur
  `Label`, `Input` et `Preview` ; `data-required` sur `Label` ; `data-placeholder-shown` sur `Area`
  et `Preview` ; ainsi que `data-autoresize` sur `Input` et `Preview`.
