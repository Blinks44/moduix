## Choisir le bon composant

- Choisissez **`Input`** ou **`Textarea`** lorsque la valeur doit toujours être disponible pour la modification.
- Choisissez **`Editable`** lorsque la valeur est généralement en lecture seule et que la modification doit être une action explicite.
- Utilisez **`Editable`** dans **`Field`** lorsque le texte d’aide, le message d’erreur ou l’état partagé du formulaire doivent s’afficher
  en dehors du composant.

## Exemple de base

Utilisez `Editable` comme composant racine, puis composez-le avec `Editable.Label`, `Editable.Area`,
`Editable.Input` et `Editable.Preview`. Ajoutez `Editable.Controls` pour obtenir le parcours standard
avec les boutons de modification, de validation et d’annulation. moduix ajoute les styles, les attributs
`data-slot` et les icônes intégrées des boutons. Par défaut, un double-clic permet de passer en mode de
modification, ce qui limite les changements accidentels.

## Anatomie

```text
Editable.Root
├─ Editable.Label
├─ Editable.Area
│  ├─ Editable.Input
│  └─ Editable.Preview
├─ Editable.Control ou Editable.Controls
│  ├─ Editable.EditTrigger
│  ├─ Editable.SubmitTrigger
│  └─ Editable.CancelTrigger

Editable.RootProvider
└─ le même arbre de parties, relié à l’état Ark créé par `useEditable()`
```

| Partie                       | Rôle                                                                                 |
| ---------------------------- | ------------------------------------------------------------------------------------ |
| `Editable` / `Editable.Root` | Composant racine qui gère l’état, les callbacks, les propriétés du formulaire et l’accessibilité. |
| `Editable.RootProvider`      | Composant racine relié à une instance de `useEditable()`.                                      |
| `Editable.Label`             | Libellé visible du champ et de la valeur affichée.                                               |
| `Editable.Area`              | Zone commune du champ de saisie et de la valeur affichée.                                        |
| `Editable.Input`             | Champ de saisie affiché pendant la modification.                                                 |
| `Editable.Preview`           | Valeur ou espace réservé affiché hors du mode de modification.                                   |
| `Editable.Control`           | Conteneur facultatif pour les boutons de modification, de validation et d’annulation.           |
| `Editable.Controls`          | Groupe pratique pour le parcours standard de modification, de validation et d’annulation.       |
| `Editable.EditTrigger`       | Bouton qui active le mode de modification.                                                       |
| `Editable.SubmitTrigger`     | Bouton qui valide la valeur actuelle.                                                             |
| `Editable.CancelTrigger`     | Bouton qui annule les modifications en cours.                                                    |

## Composition

### Composition recommandée

Placez `Editable.Input` et `Editable.Preview` côte à côte dans `Editable.Area`. Placez `Editable.Controls`
après cette zone pour utiliser la disposition standard des boutons. Pour un champ sur une ligne, les
boutons apparaissent à droite et sont centrés verticalement. Avec une textarea, la structure reste la
même. Définissez `--moduix-editable-control-align: start` pour aligner les contrôles en haut de la zone multiligne.

### Quand créer une composition personnalisée

Utilisez `Editable.Context` de moduix ou `useEditableContext()` lorsque des enfants réutilisables ou un
contenu personnalisé doivent accéder à l’état actuel de modification. Utilisez `useEditable()` avec
`Editable.RootProvider` lorsque l’état ou les méthodes doivent vivre en dehors de l’arbre `Editable` rendu.
`RootProvider` remplace `Editable.Root` pour cette instance d’état. Utilisez `asChild` lorsque le champ
doit être rendu sous la forme d’un autre élément sémantique, par exemple un `<textarea>` natif.

### Propriétés par défaut

| Propriété        | Valeur par défaut | Remarques                                                                                                                      |
| ---------------- | ----------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `activationMode` | `dblclick`        | moduix utilise le double-clic par défaut. Passez `focus`, `click` ou `none` pour choisir un autre mode d’activation Ark.       |
| `selectOnFocus`  | `true`            | Ark sélectionne le texte du champ lorsqu’il reçoit le focus.                                                           |
| `submitMode`     | `both`            | `Enter` et la perte de focus valident la valeur par défaut. Utilisez `none` si seule une commande explicite doit la valider. |

### Comportement

Les propriétés `value` et `defaultValue` définissent la valeur textuelle. Les propriétés `edit` et
`defaultEdit` contrôlent le mode de modification. Les callbacks Ark conservent l’objet `details` :
`onValueChange`, `onValueCommit`, `onValueRevert` et `onEditChange` reçoivent donc la même structure de
données qu’avec Ark UI.

Appuyez sur `Enter` pour valider la valeur et sur `Escape` pour annuler les modifications. Lorsque
`Editable.Input` est rendu sous la forme d’un `<textarea>` avec `asChild`, Cmd/Ctrl + Enter valide la
valeur. `name` et `form` sont transmis à Ark pour permettre la soumission native du formulaire.
`disabled` bloque les interactions, tandis que `readOnly` garde la valeur visible sans permettre sa modification.

Définissez `translations.input` pour fournir au champ un nom accessible adapté au contexte.
`Editable.Label` reste le libellé visible.

### Points d’accroche CSS

- `data-slot="editable-root"`, `editable-root-provider`, `editable-label`, `editable-area`,
  `editable-input`, `editable-preview`, `editable-control`, `editable-edit-trigger`,
  `editable-submit-trigger` et `editable-cancel-trigger`.
- Ark ajoute également les attributs `data-scope="editable"` et `data-part` à chaque partie primitive.
- Les sélecteurs d’état comprennent `data-focus` sur `Label` et `Area` ; `data-disabled` sur `Area`, `Input`
  et `Preview` ; `data-readonly` / `aria-readonly` sur les contrôles en lecture seule ; `data-invalid` sur
  `Label`, `Input` et `Preview` ; `data-required` sur `Label` ; `data-placeholder-shown` sur `Area`
  et `Preview` ; ainsi que `data-autoresize` sur `Input` et `Preview`.
