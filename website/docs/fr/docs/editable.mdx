## Choisir le bon composant

- Choisissez **`Input`** ou **`Textarea`** lorsque la valeur doit toujours être disponible pour la modification.
- Choisissez **`Editable`** lorsque la valeur est généralement en lecture seule et que la modification doit être une action explicite.
- Utilisez **`Editable`** dans **`Field`** lorsque le texte d’aide, le message d’erreur ou l’état partagé du formulaire doivent s’afficher
  en dehors du composant.

## Anatomie

```text
Editable.Root
├─ Editable.Label
├─ Editable.Area
│  ├─ Editable.Input
│  └─ Editable.Preview
├─ Editable.Control ou Editable.Controls
│  ├─ Editable.EditTrigger
│  ├─ Editable.SubmitTrigger
│  └─ Editable.CancelTrigger

Editable.RootProvider
└─ même arbre de parties relié à l’état Ark fourni par `useEditable()`
```

| Partie                       | Rôle                                                   |
| --------------------------- | ------------------------------------------------------ |
| `Editable` / `Editable.Root` | Racine qui gère l’état, les callbacks, les propriétés du formulaire et l’accessibilité. |
| `Editable.RootProvider`      | Racine reliée à une instance de `useEditable()`.       |
| `Editable.Label`             | Libellé visible du champ et de la valeur affichée.     |
| `Editable.Area`              | Conteneur commun du champ de saisie et de l’aperçu.    |
| `Editable.Input`             | Champ de saisie affiché pendant la modification.      |
| `Editable.Preview`           | Valeur ou espace réservé affiché hors modification.    |
| `Editable.Control`           | Conteneur facultatif des boutons de modification, validation et annulation. |
| `Editable.Controls`          | Groupe pratique pour le parcours standard.            |
| `Editable.EditTrigger`       | Bouton qui active le mode de modification.            |
| `Editable.SubmitTrigger`     | Bouton qui valide la valeur actuelle.                  |
| `Editable.CancelTrigger`     | Bouton qui annule les modifications en cours.          |

## Composition

Gardez `Editable.Input` et `Editable.Preview` comme éléments frères dans `Editable.Area`, puis placez
`Editable.Controls` après cette zone pour utiliser le parcours standard de modification, validation et
annulation. Utilisez `Editable.RootProvider` à la place de `Editable.Root` lorsque l’état créé par
`useEditable()` doit être partagé avec des commandes situées en dehors de l’arbre rendu. Utilisez
`Editable.Context` ou `useEditableContext()` pour un contenu personnalisé qui dépend du mode actuel.
Dans Solid, l’état exposé par `useEditable()` et le contexte est accessible via un accesseur : il se
lit avec `editable().editing`.

### Root Provider

Utilisez `useEditable()` de moduix et `Editable.RootProvider` lorsque des commandes placées en dehors

`activationMode: 'dblclick'` au hook pour conserver le comportement par défaut de la racine moduix.
Pour cette instance d’état, le provider remplace `Editable.Root`.
