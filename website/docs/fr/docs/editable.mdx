Utilisez `Editable` comme racine, puis composez-le avec `EditableLabel`, `EditableArea`,
`EditableInput` et `EditablePreview`. Ajoutez `EditableControls` pour le parcours standard de
modification, de validation et d’annulation. moduix ajoute les styles, les attributs `data-slot` et
les icônes par défaut des boutons de commande. Par défaut, un double-clic active le mode de
modification, ce qui limite les changements accidentels.

## Choisir le bon composant

- Choisissez **`Input`** ou **`Textarea`** lorsque la valeur doit toujours être disponible pour la modification.
- Choisissez **`Editable`** lorsque la valeur est généralement en lecture seule et que la modification doit être une action explicite.
- Utilisez **`Editable`** dans **`Field`** lorsque le texte d’aide, le message d’erreur ou l’état partagé du formulaire doivent s’afficher
  en dehors du composant.

### Édition au clic

Le composant racine accepte les options courantes d’Ark, notamment le mode d’activation, le redimensionnement
automatique, la longueur maximale, des espaces réservés différents selon le mode et les libellés localisés

### Root Provider

Utilisez `useEditable()` de moduix et `EditableRootProvider` lorsque des commandes placées en dehors
de l’arbre du composant doivent accéder à l’état et aux méthodes d’`Editable`. Passez
`activationMode: 'dblclick'` au hook pour conserver le comportement par défaut de la racine moduix.
Pour cette instance d’état, le provider remplace `Editable`.

haut. Cmd/Ctrl + Entrée enregistre ; Entrée insère une nouvelle ligne.

## Composition

Gardez `EditableInput` et `EditablePreview` comme éléments frères dans `EditableArea`, puis placez
`EditableControls` après cette zone pour utiliser le parcours standard de modification, validation et
annulation. Utilisez `EditableRootProvider` à la place de `Editable` lorsque l’état créé par
`useEditable()` doit être partagé avec des commandes situées en dehors de l’arbre rendu. Utilisez
`EditableContext` ou `useEditableContext()` pour un contenu personnalisé qui dépend du mode actuel.
Dans Solid, l’état exposé par `useEditable()` et le contexte est accessible via un accesseur : il se
lit avec `editable().editing`.

## Styles

Utilisez `className` en React ou `class` en Solid et Vue sur les parties exportées pour les styles
structurels. Les variantes Tailwind utilisent des utilitaires natifs et les classes du consommateur.
Les variantes CSS Modules exposent aussi la variable ci-dessous, qui garde la même hauteur pour la
zone et les déclencheurs carrés. Les attributs de données et les points d’accroche `data-slot` sont
partagés par les deux variantes.

La racine occupe la largeur de son conteneur, si bien que le passage entre l’aperçu et la saisie ne
décale pas la mise en page. Avec `autoResize`, la racine suit la largeur du texte. Pour limiter la
largeur, appliquez `max-width` à la racine avec une classe.

### Points d’accroche CSS

| Partie | `data-slot` |
| --- | --- |
| `Editable` | `editable-root` |
| `EditableRootProvider` | `editable-root-provider` |
| `EditableLabel` | `editable-label` |
| `EditableArea` | `editable-area` |
| `EditableInput` | `editable-input` |
| `EditablePreview` | `editable-preview` |
| `EditableControl` | `editable-control` |
| `EditableEditTrigger` | `editable-edit-trigger` |
| `EditableSubmitTrigger` | `editable-submit-trigger` |
| `EditableCancelTrigger` | `editable-cancel-trigger` |

- Sélecteurs des parties Ark : `data-scope="editable"` et
  `data-part="root|area|label|preview|input|edit-trigger|submit-trigger|cancel-trigger|control"`.
- Sélecteurs d’état Ark : `data-disabled`, `data-focus`, `data-invalid`, `data-readonly`,
  `data-required`, `data-placeholder-shown` et `data-autoresize`.
- `EditableControls` partage le slot `editable-control` avec `EditableControl`.

## Clavier

| Touche | Action |
| --- | --- |
| `Enter` | Valide la valeur si submitMode le permet. |
| `Esc` | Annule et rétablit la valeur précédente. |
