## Choisir le bon composant

Utilisez `Field` lorsqu’un contrôle de formulaire a besoin d’un libellé accessible, d’un texte d’aide,
d’un message d’erreur ou d’un état partagé `disabled`, `invalid`, `required` ou `readOnly`.

- Choisissez **`Field`** pour un contrôle et son libellé ou ses textes descriptifs.
- Choisissez **`Fieldset`** lorsque plusieurs contrôles associés doivent partager une même légende.
- Utilisez le contrôle seul lorsque les relations ARIA au niveau du champ et l’état partagé ne sont pas nécessaires.

## Exemple de base

Utilisez `Field` comme conteneur d’un contrôle de formulaire. Placez `Field.Label` avant le contrôle,
puis ajoutez un texte d’aide ou d’erreur lorsque l’utilisateur a besoin d’informations supplémentaires.

## Anatomie

L’espace de noms public `Field` reprend les noms de parties d’Ark UI. Utilisez les parties `Field.*` pour
une composition Ark explicite. Pour les formulaires courants, préférez les composants moduix correspondants,
comme `Input`, `Textarea` ou `NativeSelect`.

```text
Field
├─ Field.Label
├─ Field.Input | Field.Textarea | Field.Select | custom control
├─ Field.HelperText
├─ Field.ErrorText
└─ Field.RequiredIndicator
```

| Partie                    | Rôle                                                                                                  |
| ------------------------ | ----------------------------------------------------------------------------------------------------- |
| `Field` / `Field.Root`   | Contexte racine. Il rend par défaut un `<div role="group">`.                                         |
| `Field.RootProvider`     | Racine qui utilise un objet d’état `useField()` créé en dehors de l’arbre de rendu.                  |
| `Field.Context`          | Permet de lire l’état courant du champ sans ajouter d’élément au DOM.                                |
| `Field.Label`            | Libellé accessible associé au contrôle courant.                                                        |
| `Field.Input`            | Champ natif de bas niveau. Pour un champ standard, préférez `Input`.                               |
| `Field.Textarea`         | Zone de texte native de bas niveau. Pour le composant standard, préférez `Textarea`.               |
| `Field.Select`           | Select natif de bas niveau. Pour un select standard, préférez `NativeSelect`.                       |
| `Field.HelperText`       | Texte d’aide associé au contrôle via `aria-describedby`.                                               |
| `Field.ErrorText`        | Message d’erreur rendu lorsque la racine est dans l’état `invalid`.                                  |
| `Field.RequiredIndicator` | Marqueur visuel d’un champ obligatoire. Utilisez `fallback` pour remplacer le marqueur par défaut. |
| `Field.Item`             | Contexte imbriqué pour un contrôle groupé identifié par `value` ; sa ref pointe vers le wrapper de ligne local. |

## Composition

### Composition recommandée

Gardez un seul libellé visible dans la racine et placez ensuite un contrôle moduix principal, par exemple
`Input`, `Textarea` ou `NativeSelect`. Ajoutez un texte d’aide ou d’erreur lorsque l’utilisateur a besoin
d’une description ou d’un message de validation.

Les contrôles qui possèdent leur propre racine composée, comme `Checkbox`, `RadioGroup` ou `Select`,
peuvent également être placés dans `Field`. Ils conservent leurs propres propriétés d’état : transmettez
`required`, `invalid`, `disabled` ou `readOnly` à la racine enfant lorsque le contrôle gère cet état.

### Quand créer une composition personnalisée

Utilisez `Field.Item value` avec la prop `target` de la racine lorsqu’un champ contient plusieurs contrôles
natifs et que le libellé racine doit cibler l’un d’eux. `Field.Input`, `Field.Textarea` et `Field.Select`
restent disponibles pour une composition bas niveau basée sur Ark, mais le code applicatif doit en général
préférer les contrôles moduix dédiés.

Pour un contrôle personnalisé qui ne consomme pas le contexte Ark Field, utilisez `Field.Context` ou
`useFieldContext` depuis `@moduix/react` pour lire l’état du champ et relier ses identifiants et ses attributs ARIA.

### Propriétés par défaut

| Propriété  | Valeur par défaut | Remarques                                                                                             |
| ---------- | ----------------- | ----------------------------------------------------------------------------------------------------- |
| `disabled` | `false`           | Marque le champ comme désactivé et se propage aux parties de champ compatibles.                      |
| `invalid`  | `false`           | Contrôle `Field.ErrorText` ; transmettez aussi cette propriété à un contrôle composé qui gère sa propre validation. |
| `readOnly` | `false`           | Marque le champ en lecture seule et se propage aux parties compatibles.                              |
| `required` | `false`           | Marque le champ comme obligatoire. `Field.RequiredIndicator` reste un enfant explicite.             |
| `target`   | -                 | Valeur `value` du `Field.Item` que le libellé racine doit cibler.                                     |

### Comportement

- `Field.ErrorText` n’est pas présent dans le DOM tant que la racine n’est pas dans l’état `invalid`.
- Le champ ne valide pas les valeurs. L’application ou la bibliothèque de formulaires décide quand `invalid` doit être
  défini à `true`.
- Les libellés, textes d’aide et messages d’erreur longs passent à la ligne dans le champ sans déborder de son conteneur.
- Passez à `Field.RootProvider` la valeur renvoyée par `useField()` depuis `@moduix/react`. N’utilisez pas
  `Field.Root` et `Field.RootProvider` pour une même instance de champ.
- Utilisez `Field.Context` ou `useFieldContext` depuis `@moduix/react` lorsqu’un contrôle personnalisé a besoin de
  l’état courant du champ. Les props Ark comme `ids`, `target` et `asChild` restent disponibles sur les parties concernées.
- `Field.Item` transmet sa ref au wrapper de ligne que moduix rend autour de ses enfants.
- Les contrôles composés comme `Checkbox` et `RadioGroup` gèrent eux-mêmes leurs éléments natifs de formulaire. Field
  ne rend pas d’input caché.

### Points d’accroche CSS

Ark ajoute `data-disabled`, `data-invalid`, `data-readonly` et `data-required` aux parties concernées.
`Field.ErrorText` existe uniquement lorsque le contexte du champ courant est invalide. L’identifiant du texte d’aide
est inclus dans `aria-describedby` du contrôle, et celui du message d’erreur actif dans `aria-errormessage`. Chaque
partie DOM conserve également un point d’accroche stable `data-slot="field-*"`.
