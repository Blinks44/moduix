## Utilisation

<Usage />

Utilisez `Field` comme conteneur d’un contrôle de formulaire. Placez `FieldLabel` avant le contrôle,
puis ajoutez `FieldHelperText` ou `FieldErrorText` lorsque l’utilisateur a besoin d’informations
supplémentaires.

## Choisir le bon composant

Utilisez `Field` lorsqu’un contrôle de formulaire a besoin d’un libellé accessible, d’un texte d’aide,
d’un message d’erreur ou d’un état partagé `disabled`, `invalid`, `required` ou `readOnly`.

- Choisissez **`Field`** pour un contrôle et son libellé ou ses textes descriptifs.
- Choisissez **`Fieldset`** lorsque plusieurs contrôles associés doivent partager une même légende.
- Utilisez le contrôle seul lorsque les relations ARIA au niveau du champ et l’état partagé ne sont pas nécessaires.

## Composition

Utilisez la racine pour associer un contrôle à `FieldLabel`, `FieldHelperText`, `FieldErrorText` et
`FieldRequiredIndicator`. Les contrôles composés comme `Checkbox`, `RadioGroup` et `Select` gèrent leur
propre état : transmettez `required`, `invalid`, `disabled` ou `readOnly` à leur racine lorsqu’ils en
sont responsables. Pour plusieurs contrôles natifs, entourez chacun d’un `FieldItem value` et définissez
`target` sur la racine. Utilisez `FieldRootProvider` avec `useField()` lorsque l’état est créé en dehors
de l’arbre rendu ; les contrôles personnalisés peuvent lire l’état via `FieldContext` ou `useFieldContext`.

Dans Vue, initialisez les contrôles natifs avec `v-model` et réinitialisez les refs liées dans le
gestionnaire de réinitialisation du formulaire. Dans Vue, `Input` et `NativeSelect` ne proposent pas la prop
`defaultValue` de React. Ark efface actuellement les valeurs initiales natives de ces contrôles sans
modèle ; utilisez `v-model` en attendant la correction.

## Anatomie

L’API publique `Field` utilise des valeurs plates préfixées par le nom de la famille. `Field` ne rend
pas son propre contrôle : placez-y un `Input`, un `Textarea`, un `NativeSelect` ou un autre contrôle de
formulaire moduix, qui lit le contexte du champ.

## Styles

Un `Field` ou `FieldRootProvider` désactivé atténue l’ensemble du champ une seule fois : les
contrôles qu’il contient ne sont pas atténués à nouveau, pas plus qu’un `Field` dans un `Fieldset` désactivé.

Utilisez `className` en React ou `class` en Solid et Vue sur les parties exportées pour la structure. Pour les
styles liés à l’état, préférez les attributs de données Ark comme `data-disabled`, `data-invalid`,
`data-readonly` et `data-required`, avec les sélecteurs `data-slot` de moduix. Les variantes Tailwind
utilisent les utilitaires natifs et les classes du consommateur. Les variantes CSS Modules s’appuient sur
les jetons de foundation et n’ont pas de variables de composant : une classe sur la partie remplace les
styles du composant placés dans un calque. La racine occupe toute la largeur de son conteneur.

### Points d’accroche CSS

| Partie | `data-slot` |
| --- | --- |
| `Field` | `field-root` |
| `FieldRootProvider` | `field-root-provider` |
| `FieldItem` | `field-item` |
| `FieldLabel` | `field-label` |
| `FieldHelperText` | `field-helper-text` |
| `FieldErrorText` | `field-error-text` |
| `FieldRequiredIndicator` | `field-required-indicator` |

Ark ajoute `data-disabled`, `data-invalid`, `data-readonly` et `data-required` aux parties concernées. `FieldErrorText` n’existe que lorsque le contexte courant du champ est invalide. Les identifiants du texte
d’aide et du message d’erreur actif sont inclus dans `aria-describedby` du contrôle. Chaque partie DOM conserve également un point d’accroche stable
`data-slot="field-*"`.

## Référence de l’API

| Prop | Type | Défaut | Description |
| --- | --- | --- | --- |
| `disabled` | `boolean` | `false` | Désactive le contrôle imbriqué et atténue le libellé. |
| `readOnly` | `boolean` | `false` | Passe le contrôle imbriqué en lecture seule. |
| `invalid` | `boolean` | `false` | Marque le champ invalide et affiche `FieldErrorText`. |
| `required` | `boolean` | `false` | Rend le contrôle imbriqué obligatoire et affiche l’indicateur. |
| `asChild` | `boolean` | `false` | Rend la racine avec son unique élément enfant. |
