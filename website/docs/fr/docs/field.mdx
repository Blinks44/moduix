## Choisir le bon composant

Utilisez `Field` lorsqu’un contrôle de formulaire a besoin d’un libellé accessible, d’un texte d’aide,
d’un message d’erreur ou d’un état partagé `disabled`, `invalid`, `required` ou `readOnly`.

- Choisissez **`Field`** pour un contrôle et son libellé ou ses textes descriptifs.
- Choisissez **`Fieldset`** lorsque plusieurs contrôles associés doivent partager une même légende.
- Utilisez le contrôle seul lorsque les relations ARIA au niveau du champ et l’état partagé ne sont pas nécessaires.

## Anatomie

L’espace de noms public `Field` reprend les noms de parties d’Ark UI. Utilisez les parties `Field.*`
pour une composition Ark explicite. Pour les formulaires courants, préférez les composants moduix
correspondants, comme `Input`, `Textarea` ou `NativeSelect`.

```text
Field
├─ Field.Label
├─ Field.Input | Field.Textarea | Field.Select | custom control
├─ Field.HelperText
├─ Field.ErrorText
└─ Field.RequiredIndicator

Field.RootProvider
└─ même arbre de parties relié à l’état fourni par useField()
```

| Partie                    | Rôle                                                                                           |
| ------------------------ | ---------------------------------------------------------------------------------------------- |
| `Field` / `Field.Root`   | Contexte racine. Il rend par défaut un `<div role="group">`.                                 |
| `Field.RootProvider`     | Racine utilisant un état `useField()` créé en dehors de l’arbre de rendu.                      |
| `Field.Context`          | Permet de lire l’état courant du champ sans ajouter d’élément au DOM.                          |
| `Field.Label`            | Libellé accessible associé au contrôle courant.                                                |
| `Field.Input`            | Champ natif de bas niveau. Pour le champ standard, préférez `Input`.                          |
| `Field.Textarea`         | Zone de texte native de bas niveau. Pour la version standard, préférez `Textarea`.             |
| `Field.Select`           | Select natif de bas niveau. Pour la version standard, préférez `NativeSelect`.                 |
| `Field.HelperText`       | Texte d’aide associé au contrôle via `aria-describedby`.                                       |
| `Field.ErrorText`        | Message d’erreur rendu lorsque la racine est dans l’état `invalid`.                           |
| `Field.RequiredIndicator` | Marqueur visuel d’un champ obligatoire. Utilisez `fallback` pour remplacer le marqueur par défaut. |
| `Field.Item`             | Contexte imbriqué pour un contrôle groupé identifié par `value` ; sa ref pointe vers le wrapper local. |

## Composition

Utilisez la racine pour associer un contrôle à `Field.Label`, `Field.HelperText`, `Field.ErrorText` et
`Field.RequiredIndicator`. Les contrôles composés comme `Checkbox`, `RadioGroup` et `Select` gèrent leur
propre état : transmettez `required`, `invalid`, `disabled` ou `readOnly` à leur racine lorsqu’ils en
sont responsables. Pour plusieurs contrôles natifs, entourez chacun d’un `Field.Item value` et définissez
`target` sur la racine. Utilisez `Field.RootProvider` avec `useField()` lorsque l’état est créé en dehors
de l’arbre rendu ; les contrôles personnalisés peuvent lire l’état via `Field.Context` ou `useFieldContext`.

## Styles

Utilisez `className` en React ou `class` en Solid sur les parties exportées pour la structure. Pour les
styles liés à l’état, préférez les attributs de données Ark comme `data-disabled`, `data-invalid`,
`data-readonly` et `data-required`, avec les sélecteurs `data-slot` de moduix. Les variantes Tailwind
utilisent les utilitaires natifs et les classes du consommateur ; les variables CSS ci-dessous personnalisent
les variantes CSS Modules.

### Points d’accroche CSS

Ark ajoute `data-disabled`, `data-invalid`, `data-readonly` et `data-required` aux parties concernées.
`Field.ErrorText` n’existe que lorsque le contexte courant du champ est invalide. L’identifiant du texte
d’aide est inclus dans `aria-describedby` du contrôle et l’identifiant du message d’erreur actif dans
`aria-errormessage`. Chaque partie DOM conserve également un point d’accroche stable
`data-slot="field-*"`.
