## Choisir le bon composant

Utilisez `Field` lorsqu’un seul contrôle de formulaire a besoin d’un libellé visible, d’un texte d’aide,
d’un message d’erreur ou des états partagés `disabled`, `invalid`, `required` et `readOnly`.

- Choisissez **`Field`** pour un contrôle unique, avec son libellé et ses textes descriptifs.
- Choisissez **`Fieldset`** lorsque plusieurs champs associés nécessitent une légende commune.
- Utilisez un contrôle autonome lorsque les relations ARIA au niveau du champ ou l’état partagé ne sont pas nécessaires.

## Anatomie

`Field` reprend les parties d’Ark UI et conserve leurs noms dans l’API publique de moduix.

```text
Field
├─ Field.Label
├─ Field.Input | Field.Textarea | Field.Select | custom control
├─ Field.HelperText
├─ Field.ErrorText
└─ Field.RequiredIndicator
```

| Partie | Rôle |
| ------------------------- | -------------------------------------------------------------------------- |
| `Field` / `Field.Root` | Contexte racine qui rend par défaut un `<div role="group">`. |
| `Field.RootProvider` | Élément racine qui utilise une instance de `useField()` créée en dehors de l’arbre rendu. |
| `Field.Context` | Accès à l’état actuel du champ sans ajouter d’élément au DOM. |
| `Field.Label` | Libellé associé à l’ID du contrôle courant. |
| `Field.Input` | Champ texte natif bas niveau, compatible avec Ark. Préférez `Input` pour un usage courant. |
| `Field.Textarea` | Zone de texte native bas niveau, compatible avec Ark. Préférez `Textarea` pour un usage courant. |
| `Field.Select` | Select natif relié aux attributs ARIA et à l’état du champ. |
| `Field.HelperText` | Texte d’aide ajouté à `aria-describedby`. |
| `Field.ErrorText` | Message d’erreur rendu uniquement lorsque `Field` est dans l’état `invalid`. |
| `Field.RequiredIndicator` | Marqueur visuel indiquant qu’un champ est obligatoire, avec un `fallback` facultatif. |
| `Field.Item` | Contexte de champ pour les contrôles groupés, identifié par `value` ; sa ref pointe vers le wrapper de ligne rendu. |

## Composition

### Composition recommandée

Placez un seul libellé visible dans la racine et un seul contrôle moduix principal, par exemple `Input`,
`Textarea` ou `NativeSelect`. Ajoutez un texte d’aide ou un message d’erreur si l’utilisateur a besoin d’une description ou d’un retour de validation.

### Quand créer une composition personnalisée

Utilisez `Field.Item value` avec la prop `target` de la racine lorsque le champ contient plusieurs contrôles natifs
et que le libellé doit cibler l’un d’eux. `Field.Input`, `Field.Textarea` et `Field.Select` restent disponibles pour
une composition bas niveau basée sur Ark, mais, dans le code applicatif courant, préférez les composants moduix dédiés.

### Propriétés par défaut

| Élément | Par défaut | Remarques |
| ------------------------ | ------------ | --------------------------------------------------------- |
| `Field` / `Field.Root` | - | Aucun comportement supplémentaire ; les valeurs par défaut d’Ark s’appliquent. |

### Comportement

- `Field.ErrorText` n’est pas présent dans le DOM tant que la racine n’a pas l’état `invalid`.
- Les libellés, textes d’aide et messages d’erreur longs passent à la ligne dans le champ sans déborder de son conteneur.
- Passez à `Field.RootProvider` la valeur renvoyée par `useField()` depuis `@moduix/react`. N’imbriquez pas
  `Field.RootProvider` dans `Field.Root` pour une même instance de champ.
- Utilisez `Field.Context` ou `useFieldContext` de `@moduix/react` lorsqu’un contrôle personnalisé a besoin de l’état actuel
  du champ. N’importez Ark directement que pour les API de bas niveau que moduix n’exporte pas.
- `Field.Item` transmet sa ref au wrapper de ligne que moduix rend autour de ses enfants.
- `Field` ne génère pas d’input caché. Les composants composés, comme `Checkbox` et `RadioGroup`, gèrent eux-mêmes
  leurs éléments natifs de formulaire.

### Points d’accroche CSS

Ark ajoute `data-disabled`, `data-invalid`, `data-readonly` et `data-required` aux parties concernées.
`Field.ErrorText` n’est rendu que lorsque le contexte du champ courant est invalide. L’identifiant du texte d’aide
est inclus dans `aria-describedby` du contrôle, et celui du message d’erreur actif dans `aria-errormessage`.
Chaque partie DOM conserve également le point d’accroche stable `data-slot="field-*"`.
