## Référence de l’API

Ark UI ne fournit pas de primitive `bleed` dédiée. Dans moduix, `Bleed` repose sur la
[fabrique Ark](https://ark-ui.com/docs/guides/composition#the-ark-factory) et suit les recommandations d’Ark pour la
[composition](https://ark-ui.com/docs/guides/composition), les [styles](https://ark-ui.com/docs/guides/styling) et les
[références](https://ark-ui.com/docs/guides/ref).

Utilisez [Container](/docs/container) pour conserver une colonne de contenu agréable à lire. Placez `Bleed` à
l’intérieur lorsque seul un bloc média, un arrière-plan, un séparateur ou une bannière doit dépasser les limites du
conteneur.


Importez `Bleed` depuis le sous-chemin qui correspond au framework et au style choisi. Pour CSS Modules, utilisez
`@moduix/react/bleed`, `@moduix/solid/bleed` ou `@moduix/vue/bleed`. Pour Tailwind, utilisez
`@moduix/react-tailwind/bleed`, `@moduix/solid-tailwind/bleed` ou `@moduix/vue-tailwind/bleed`.
## Exemple de base

La valeur par défaut `inline="full"` permet à un bloc média, une bannière ou un élément décoratif de section
d’atteindre les bords de la fenêtre tout en restant dans le flux normal du document.

## Anatomie

`Bleed` rend un seul élément racine conforme aux conventions d’Ark. Il applique des marges négatives sur l’axe en
ligne et/ou l’axe de bloc, sans ajouter d’enveloppe interne.

```text
Bleed
└─ root[data-scope="bleed"][data-part="root"][data-slot="bleed-root"]
   └─ children
```

| Partie | Rôle                                                                                 |
| ------ | ------------------------------------------------------------------------------------ |
| `Bleed` | Composant racine qui permet au contenu de dépasser sur les axes en ligne et de bloc. |

## Composition

`Bleed` est un composant de présentation sans état. Il ne possède qu’une partie racine ; il n’y a donc aucune partie enfant à coordonner. Les valeurs par défaut sont `inline="full"`, `block="none"` et `asChild={false}`. Lorsque `asChild` doit confier la racine rendue à un élément sémantique, fournissez exactement un enfant capable de recevoir les propriétés DOM et une ref en React, ou utilisez la fonction de rendu Solid. Les refs React ciblent la racine ou l’enfant rendu ; la forme Solid ne transmet pas la ref du composant à l’hôte personnalisé. Dans Vue, `asChild` transmet la racine à un unique enfant sémantique via la fabrique Ark. La ref du composant donne accès à l’élément rendu avec `$el`.

Combinez `inline` et `block` lorsqu’une surface doit dépasser les marges internes sur les deux axes logiques. `inline="full"` est relatif à la fenêtre d’affichage ; dans une enveloppe imbriquée, il peut donc être nécessaire de redéfinir localement `--moduix-bleed-inline-full` et `--moduix-bleed-inline-full-size`.

## Styles

`Bleed` expose des variables CSS et des attributs de données stables sur son élément racine. Utilisez `className` en
React ou `class` en Solid et Vue pour styliser la surface. Tailwind s’appuie sur ses utilitaires natifs et les classes
fournies par l’application ; les variables ci-dessous concernent CSS Modules. Les ancêtres avec `overflow: hidden`
ou `overflow: clip` peuvent couper le débordement.

### Points d’accroche CSS

- `data-scope="bleed"` et `data-part="root"` fournissent des points d’accroche conformes à Ark sur l’élément racine exporté.
- `data-slot="bleed-root"` est un sélecteur moduix stable sur l’élément racine exporté.
- `data-inline` indique le mode de dépassement actuel sur l’axe en ligne : `none`, `xs`, `sm`, `md`, `lg`, `xl` ou `full`.
- `data-block` indique le mode de dépassement actuel sur l’axe de bloc : `none`, `xs`, `sm`, `md`, `lg` ou `xl`.
- L’API CSS publique `--moduix-bleed-*` couvre les valeurs de dépassement fondées sur l’échelle ainsi que la largeur
  calculée jusqu’aux bords de la fenêtre pour `inline="full"`.
