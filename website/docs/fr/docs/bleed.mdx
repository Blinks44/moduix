## Référence de l’API

Ark UI ne fournit pas de primitive `bleed` dédiée. Dans moduix, `Bleed` repose sur l’outil officiel
[Ark factory](https://ark-ui.com/docs/guides/composition#the-ark-factory) et suit les recommandations d’Ark pour la
[composition](https://ark-ui.com/docs/guides/composition), les [styles](https://ark-ui.com/docs/guides/styling) et les
[refs](https://ark-ui.com/docs/guides/ref).

Utilisez [Container](/docs/container) pour limiter la largeur de la mise en page. Placez `Bleed` à l’intérieur lorsque
seul un bloc média, un arrière-plan, un séparateur ou une bannière doit dépasser les limites du conteneur.

## Exemple de base

Utilisez le comportement par défaut `inline="full"` lorsqu’un bloc média, une bannière ou un accent de section doit
s’étendre jusqu’aux bords de la fenêtre, tout en restant dans le flux normal du document.

## Anatomie

`Bleed` rend un seul élément racine conforme aux conventions d’Ark. Cet élément reçoit des marges négatives sur l’axe
en ligne et/ou l’axe de bloc.

```text
Bleed.Root
└─ root[data-scope="bleed"][data-part="root"][data-slot="bleed-root"]
   └─ children
```

| Partie                 | Rôle                                                                                 |
| ---------------------- | ------------------------------------------------------------------------------------ |
| `Bleed` / `Bleed.Root` | Enveloppe racine qui permet au contenu de dépasser sur les axes en ligne et de bloc. |
| `Bleed`                | Forme courte de `Bleed.Root`, utilisable directement comme composant.               |

## Composition

### Composition recommandée

Utilisez la forme courte `Bleed` lorsque la mise en page a seulement besoin d’une enveloppe avec des marges négatives
contrôlées. `Bleed.Root` expose le même composant dans un espace de noms, selon la convention d’Ark.
C’est l’option recommandée pour les médias pleine largeur, les arrière-plans de sections imbriquées, les séparateurs et
les bannières à l’intérieur d’enveloppes centrées ou dotées d’un espacement intérieur.

### Quand créer une composition personnalisée

Utilisez `className` et des remplacements locaux de `--moduix-bleed-*` lorsqu’un panneau latéral, une zone de défilement
imbriquée ou une enveloppe d’application doit étendre le contenu par rapport à ses propres limites plutôt qu’à celles
de la fenêtre.

### Propriétés par défaut

| Propriété   | Valeur par défaut | Valeurs / remarques                            |
| ----------- | ----------------- | ---------------------------------------------- |
| `inline`    | `full`            | `none`, `xs`, `sm`, `md`, `lg`, `xl`, `full`  |
| `block`     | `none`            | `none`, `xs`, `sm`, `md`, `lg`, `xl`          |
| `asChild`   | `false`           | Composition Ark factory                        |
| `className` | -                 | Appliqué à l’élément racine                    |

### Comportement

- `Bleed.Root` rend un seul élément racine et lui transmet les propriétés `div` prises en charge par l’Ark factory.
- La `ref` pointe vers l’élément racine affiché. Avec `asChild`, elle pointe vers l’unique élément enfant.
- `asChild` exige un seul enfant sémantique capable d’accepter les propriétés DOM et une ref.
- Utilisez `inline` pour dépasser l’espacement intérieur sur l’axe en ligne. Ajoutez `block` lorsque la surface doit
  également dépasser l’espacement de l’axe de bloc. Ces axes logiques suivent le mode d’écriture du document.
- L’ancienne propriété `as` a été supprimée lors de la migration vers Ark. Utilisez `asChild` lorsqu’un élément sémantique doit posséder le nœud DOM.
- Utilisez une valeur fixe de l’échelle lorsque le contenu doit seulement dépasser l’espacement intérieur du conteneur,
  sans aller jusqu’au bord de la fenêtre.
- `inline="full"` se base sur la fenêtre ; les enveloppes imbriquées peuvent donc nécessiter des remplacements locaux
  de `--moduix-bleed-inline-full` et `--moduix-bleed-inline-full-size`.
- Les ancêtres avec `overflow: hidden` ou `overflow: clip` peuvent couper le bleed.
- Contrairement à la primitive de mise en page Chakra, moduix propose volontairement des modes `inline` et `block`
  fondés sur les tokens, plutôt que des propriétés distinctes `inlineStart`, `inlineEnd`, `blockStart` et `blockEnd`.

## Styles

`Bleed` expose un petit ensemble de variables CSS et des attributs de données stables sur son élément racine. Utilisez
les variables pour ajuster l’extension du composant et `className` pour styliser la surface elle-même.

### Propriétés CSS

<CssPropertiesSection properties={BleedDocs.bleedCssProperties} />

### Points d’accroche CSS

- `data-scope="bleed"` et `data-part="root"` fournissent des points d’accroche conformes à Ark sur l’élément racine exporté.
- `data-slot="bleed-root"` est un sélecteur moduix stable sur l’élément racine exporté.
- `data-inline` indique le mode de bleed actuel sur l’axe en ligne : `none`, `xs`, `sm`, `md`, `lg`, `xl` ou `full`.
- `data-block` indique le mode de bleed actuel sur l’axe de bloc : `none`, `xs`, `sm`, `md`, `lg` ou `xl`.
- L’API CSS publique `--moduix-bleed-*` couvre les valeurs de bleed fondées sur l’échelle ainsi que la largeur calculée
  jusqu’aux bords de la fenêtre pour `inline="full"`.
