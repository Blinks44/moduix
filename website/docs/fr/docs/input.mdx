## Référence de l’API

`Input` est un composant stylé fondé sur [`Field.Input` d’Ark UI](https://ark-ui.com/docs/components/field). Il suit les recommandations d’Ark pour la [composition](https://ark-ui.com/docs/guides/composition), le [style](https://ark-ui.com/docs/guides/styling) et le [transfert de la ref](https://ark-ui.com/docs/guides/ref). Il rend un `<input>` natif sur une seule ligne et conserve le comportement du navigateur dans les formulaires ainsi que l’API native des événements React.

Utilisez `Field` lorsque le champ doit être relié à un libellé, à un texte d’aide ou d’erreur, recevoir des identifiants générés ou partager un état.

## Choisir le bon composant

- Utilisez **`Input`** pour un champ de saisie natif ordinaire sur une seule ligne.
- Utilisez **`InputGroup`** lorsque le champ doit intégrer un préfixe, un suffixe, du texte complémentaire ou une action sur la même ligne.
- Utilisez **`PasswordInput`** pour un champ de mot de passe avec bouton d’affichage ou de masquage.
- Utilisez **`NumberInput`** lorsque vous devez gérer des valeurs numériques et les modifier par incréments avec des boutons dédiés.
- Utilisez **`Textarea`** pour le contenu multiligne.
- Utilisez **`Editable`** lorsque le texte doit d’abord s’afficher comme une valeur, puis passer en mode édition à la demande.

## Anatomie

```text
Field (conteneur facultatif)
└─ Input / Input.Root
```

| Partie                 | Rôle                                                                                          |
| ---------------------- | --------------------------------------------------------------------------------------------- |
| `Input` / `Input.Root` | Version stylée du `Field.Input` d’Ark UI, qui rend un `<input>` natif sur une seule ligne.                 |

`Input.Root` est un alias de `Input` : les deux rendent le même contrôle.

## Composition

### Composition recommandée

Placez `Input` dans `Field` lorsque le champ a besoin d’un libellé accessible, d’un texte d’aide ou d’erreur, d’identifiants générés ou d’un état partagé `disabled`, `invalid`, `required` ou `readOnly`. `Fieldset` peut désactiver plusieurs champs imbriqués en une seule fois.

Transmettez directement à `Input` les propriétés et gestionnaires d’événements natifs de `<input>`. Pour un champ contrôlé, utilisez `value` et mettez-le à jour dans `onChange(event)`. Pour un champ non contrôlé, utilisez `defaultValue`.

### Quand créer une composition personnalisée

Utilisez `asChild` uniquement lorsqu’un autre élément compatible avec un champ de saisie doit devenir le véritable nœud DOM. Fournissez un seul élément enfant sémantique et focusable. Ark fusionne dans cet élément les propriétés du composant et de `Field`, la classe et la `ref`.

Si l’élément n’est pas compatible avec un champ de saisie, préférez le composant qui fournit la primitive Ark adaptée au lieu de le forcer dans `Input`.

### Propriétés par défaut

| Propriété   | Valeur par défaut | Remarques                                                                                     |
| ----------- | ----------------- | --------------------------------------------------------------------------------------------- |
| `size`      | `md`              | Taille visuelle : `xs`, `sm`, `md`, `lg` ou `xl`.                                             |
| `htmlSize`  | Non défini        | Définit la valeur native de `input[size]` en caractères. Par défaut, la largeur du champ est calculée à partir de cette valeur. |
| `asChild`   | `false`           | Lorsqu’il est activé, transmet les propriétés à un seul enfant sémantique via Ark Slot.                 |

### Comportement

- La `ref` pointe vers le véritable `HTMLInputElement`, ce qui permet à une bibliothèque de formulaires
  de lui donner le focus après l’échec de la soumission.
- Aucun `HiddenInput` n’est nécessaire : `Input` est déjà un contrôle de formulaire natif.
- `Field` d’Ark fournit `aria-describedby`, `aria-invalid`, les identifiants et les propriétés d’état.
- `Input` ne gère pas la valeur, sa validité, le focus ni la navigation au clavier.

### Champ autonome

`Field` est facultatif. Lorsque `Input` est utilisé seul, donnez-lui un nom accessible au moyen d’un
élément `<label>` HTML, de `aria-label` ou de `aria-labelledby`. Les propriétés natives fonctionnent
toujours, mais sans contexte `Field`, les identifiants ne sont pas générés automatiquement et les
textes d’aide ou d’erreur ne sont pas associés au champ.

### Points d’accroche CSS

- `data-slot="input-root"`
- `data-size="xs" | "sm" | "md" | "lg" | "xl"`
- `data-scope="field"` et `data-part="input"`
- `data-invalid`, `data-required` et `data-readonly` d’Ark dans `Field`
- les sélecteurs natifs `:disabled`, `:read-only`, `:focus-visible` et `[aria-invalid="true"]`
