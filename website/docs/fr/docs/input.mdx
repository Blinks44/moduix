Placez `Input` dans `Field` lorsque vous avez besoin d’un libellé, d’un texte d’aide ou d’un message d’erreur. `Field` relie ces éléments au champ, génère les identifiants nécessaires et lui transmet son état.

## Choisir le bon composant

- Utilisez **`Input`** pour un champ de saisie natif ordinaire sur une seule ligne.
- Utilisez **`InputGroup`** lorsque le champ doit intégrer un préfixe, un suffixe, du texte complémentaire ou une action sur la même ligne.
- Utilisez **`PasswordInput`** pour un champ de mot de passe avec bouton d’affichage ou de masquage.
- Utilisez **`NumberInput`** lorsque vous devez gérer des valeurs numériques et les modifier par incréments avec des boutons dédiés.
- Utilisez **`Textarea`** pour le contenu multiligne.
- Utilisez **`Editable`** lorsque le texte doit d’abord s’afficher comme une valeur, puis passer en mode édition à la demande.

## Exemples

### Tailles

La propriété `size` de moduix contrôle la taille visuelle. `htmlSize` est indépendante et définit la
largeur native exprimée en caractères.

<Example name="input/sizes" />

### Champ autonome

`Field` est facultatif. Lorsque `Input` est utilisé seul, donnez-lui un nom accessible au moyen d’un
élément `<label>` HTML, de `aria-label` ou de `aria-labelledby`. Les propriétés natives fonctionnent
toujours, mais sans contexte `Field`, les identifiants ne sont pas générés automatiquement et les
textes d’aide ou d’erreur ne sont pas associés au champ.

<Example name="input/standalone-input" />

### Désactivé et en lecture seule

Utilisez `disabled` lorsque l’utilisateur ne doit pas interagir avec le contrôle. Utilisez `readOnly`
lorsqu’il peut consulter et sélectionner la valeur, sans pouvoir la modifier. Définissez-les
directement sur `Input` pour un seul contrôle, ou sur `Field` lorsque le libellé, le texte associé et
le champ doivent partager le même état.

<Example name="input/disabled-and-readonly" />

### Validation du champ

Définissez `invalid` sur `Field` lorsque la validation échoue. Ark ajoute `aria-invalid` et
`data-invalid` à `Input` et l’associe au message d’erreur.

<Example name="input/field-state" />

### Attributs natifs

Utilisez les attributs natifs pour les comportements du navigateur, comme la validation, le mode
de saisie, l’autocomplétion et l’envoi du formulaire. Utilisez `htmlSize` pour définir une largeur
en caractères et `size` pour modifier la taille visuelle dans React, Solid et Vue.

<Example name="input/native-attributes" />

### Sélection de fichier

Dans un formulaire simple, `Input` suffit pour proposer le sélecteur de fichiers natif. Utilisez
`FileUpload` lorsque l’application doit conserver les fichiers sélectionnés dans son état, afficher
une zone de dépôt ou gérer le processus de téléversement.

<Example name="input/file-input" />

### Valeur contrôlée

Utilisez cet exemple lorsque le composant parent doit piloter la valeur courante. Dans React, lisez la
nouvelle valeur dans l’événement natif `onChange(event)` ; dans Solid, utilisez `onInput` ; dans Vue,
utilisez `v-model`. Transmettez la valeur courante via `value` lorsque le framework sépare les
liaisons de l’événement et de la valeur.

### Élément personnalisé

Utilisez `asChild` uniquement lorsqu’un autre nœud DOM doit être rendu à la place de l’élément du
champ. Fournissez un seul élément sémantique et focusable, capable de recevoir les propriétés

## Composition

`Input` est un composant stylé fondé sur [`FieldInput` d’Ark UI](https://ark-ui.com/docs/components/field). Il suit les recommandations d’Ark pour la [composition](https://ark-ui.com/docs/guides/composition), le [style](https://ark-ui.com/docs/guides/styling) et le [transfert de la ref](https://ark-ui.com/docs/guides/ref). Il rend un `<input>` natif sur une seule ligne et conserve le comportement du navigateur dans les formulaires ainsi que l’API native des événements de chaque framework.

Utilisez `Field` lorsque le champ doit être relié à un libellé, à un texte d’aide ou d’erreur, recevoir des identifiants générés ou partager un état.

`Field` prend en charge le libellé, le texte d’aide ou d’erreur, les identifiants générés et l’état
partagé `disabled`, `invalid`, `required` ou `readOnly`. `Input` reste le contrôle natif : pour un
champ React contrôlé, utilisez `value` avec `onChange(event)`, `v-model` pour un champ Vue contrôlé,
ou `defaultValue` pour un champ non contrôlé. Le composant ne gère ni la validation, ni le focus, ni
la navigation au clavier.

Dans Vue, initialisez le champ avec `v-model` et réinitialisez l’état lié dans le gestionnaire de
réinitialisation du formulaire : la réinitialisation native ne déclenche pas d’événement de saisie.
Ark efface actuellement le `defaultValue` natif sans modèle ; utilisez donc `v-model` pour les valeurs
initiales en attendant la correction.

Pour un champ autonome, fournissez vous-même son nom accessible. Utilisez `asChild` uniquement avec
un seul enfant focusable et compatible avec un champ de saisie ; Ark fusionne les propriétés de
`Input` et de `Field`, la classe et la `ref` dans ce nœud DOM.

## Styles

`Input` bénéficie du contexte `Field`. Sa prop `size` choisit une taille visuelle ; passez l’attribut
natif numérique `size` via `htmlSize`. Dans un `Field` ou `FieldRootProvider` moduix désactivé, seule la racine
applique l’opacité de l’état désactivé.

Utilisez `className` dans React ou `class` dans Solid et Vue sur `Input`. Les variantes Tailwind
utilisent les classes utilitaires natives et les classes du consommateur. Les variantes CSS Modules
reposent sur les tokens de la fondation et n’exposent que les trois variables ci-dessous ; remplacez
les couleurs, les espacements et la typographie avec une simple classe, qui l’emporte sur les styles
du composant placés dans une couche. Pour les états du champ, utilisez les attributs de données
partagés et les sélecteurs d’état natifs.

### Points d’accroche CSS

| Partie | `data-slot` |
| --- | --- |
| `Input` | `input-root` |

- `data-size="xs" | "sm" | "md" | "lg" | "xl"`
- `data-scope="field"` et `data-part="input"`
- `data-invalid`, `data-required` et `data-readonly` d’Ark dans `Field`
- les sélecteurs natifs `:disabled`, `:read-only`, `:focus-visible` et `[aria-invalid="true"]`

## Référence de l’API

Accepte aussi les props natives de son élément.

| Prop | Type | Défaut |
| --- | --- | --- |
| `size` | `'xs' \| 'sm' \| 'md' \| 'lg' \| 'xl'` | `'md'` |
| `htmlSize` | `number` | — |
| `asChild` | `boolean` | `false` |
