## Référence de l’API

`Input` est un composant stylé fondé sur [`FieldInput` d’Ark UI](https://ark-ui.com/docs/components/field). Il suit les recommandations d’Ark pour la [composition](https://ark-ui.com/docs/guides/composition), le [style](https://ark-ui.com/docs/guides/styling) et le [transfert de la ref](https://ark-ui.com/docs/guides/ref). Il rend un `<input>` natif sur une seule ligne et conserve le comportement du navigateur dans les formulaires ainsi que l’API native des événements de chaque framework.

Utilisez `Field` lorsque le champ doit être relié à un libellé, à un texte d’aide ou d’erreur, recevoir des identifiants générés ou partager un état.

## Choisir le bon composant

- Utilisez **`Input`** pour un champ de saisie natif ordinaire sur une seule ligne.
- Utilisez **`InputGroup`** lorsque le champ doit intégrer un préfixe, un suffixe, du texte complémentaire ou une action sur la même ligne.
- Utilisez **`PasswordInput`** pour un champ de mot de passe avec bouton d’affichage ou de masquage.
- Utilisez **`NumberInput`** lorsque vous devez gérer des valeurs numériques et les modifier par incréments avec des boutons dédiés.
- Utilisez **`Textarea`** pour le contenu multiligne.
- Utilisez **`Editable`** lorsque le texte doit d’abord s’afficher comme une valeur, puis passer en mode édition à la demande.

## Anatomie

```text
Field (conteneur facultatif)
└─ Input / Input.Root
```

| Partie                 | Rôle                                                                                          |
| ---------------------- | --------------------------------------------------------------------------------------------- |
| `Input` / `Input.Root` | Version stylée du `FieldInput` d’Ark UI, qui rend un `<input>` natif sur une seule ligne.                 |

`Input.Root` est un alias de `Input` : les deux rendent le même contrôle.

## Composition

`Field` prend en charge le libellé, le texte d’aide ou d’erreur, les identifiants générés et l’état
partagé `disabled`, `invalid`, `required` ou `readOnly`. `Input` reste le contrôle natif : pour un
champ React contrôlé, utilisez `value` avec `onChange(event)`, ou `defaultValue` pour un champ non
contrôlé. Le composant ne gère ni la validation, ni le focus, ni la navigation au clavier.

Pour un champ autonome, fournissez vous-même son nom accessible. Utilisez `asChild` uniquement avec
un seul enfant focusable et compatible avec un champ de saisie ; Ark fusionne les propriétés de
`Input` et de `Field`, la classe et la `ref` dans ce nœud DOM.

### Champ autonome

`Field` est facultatif. Lorsque `Input` est utilisé seul, donnez-lui un nom accessible au moyen d’un
élément `<label>` HTML, de `aria-label` ou de `aria-labelledby`. Les propriétés natives fonctionnent
toujours, mais sans contexte `Field`, les identifiants ne sont pas générés automatiquement et les
textes d’aide ou d’erreur ne sont pas associés au champ.

## Styles

Utilisez `className` dans React ou `class` dans Solid sur `Input`. Les variantes CSS Modules
exposent les variables ci-dessous, tandis que les variantes Tailwind utilisent les classes utilitaires
natives et les classes du consommateur. Pour les états du champ, utilisez les attributs de données
partagés et les sélecteurs d’état natifs.

### Points d’accroche CSS

- `data-slot="input-root"`
- `data-size="xs" | "sm" | "md" | "lg" | "xl"`
- `data-scope="field"` et `data-part="input"`
- `data-invalid`, `data-required` et `data-readonly` d’Ark dans `Field`
- les sélecteurs natifs `:disabled`, `:read-only`, `:focus-visible` et `[aria-invalid="true"]`
