## Référence de l’API

Ark UI ne fournit pas de primitive `Skeleton` dédiée. moduix construit `Skeleton` à partir de la
[fabrique Ark](https://ark-ui.com/docs/guides/composition#the-ark-factory) officielle et suit les recommandations
d’Ark pour la [composition](https://ark-ui.com/docs/guides/composition), les
[styles](https://ark-ui.com/docs/guides/styling) et les [refs](https://ark-ui.com/docs/guides/ref).

## Anatomie

`Skeleton` ne comporte qu’une seule partie visuelle. La mise en page se fait dans le balisage qui l’entoure.

```text
Skeleton
└─ children (facultatifs, affichés lorsque loading={false})
```

| Partie                        | Rôle                                                                                                                  |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `Skeleton` | Bloc d’attente. Rend par défaut un élément de la fabrique Ark ; avec `asChild`, un autre élément sémantique peut devenir la racine. |

## Composition

`Skeleton` ne gère pas l’état de chargement. La zone de données ou de page qui porte la requête transmet `loading`
et doit porter `aria-busy` ; l’espace réservé est décoratif. Définissez `loading={false}` (`:loading="false"` en Vue) pour afficher les enfants
dans le même élément racine.

`Skeleton` ne comporte qu’une seule partie visuelle : composez les cartes, les objets média et les mises en page
responsives dans un conteneur de votre choix. `Stack` est disponible dans les deux variantes de style ;
avec Tailwind, vous pouvez aussi utiliser les utilitaires flex et grid natifs. Utilisez `asChild` uniquement
lorsqu’un autre élément sémantique doit devenir la racine. En Solid, `asChild` reçoit une fonction de rendu ;
en Vue, utilisez `as-child` avec un seul élément sémantique dans le slot par défaut.

## Styles

Utilisez `className` en React ou `class` en Solid ou Vue pour les styles structurels et les classes utilitaires de votre
application. Les variantes Tailwind utilisent les utilitaires natifs et les classes du consommateur ; les variantes
CSS Modules exposent les variables ci-dessous. Les attributs d’état et les hooks `data-slot` sont communs aux deux
modes de style.

### Sélecteurs et attributs de style

- `[data-scope="skeleton"][data-part="root"]` cible l’élément racine exporté.
- `data-slot="skeleton-root"` est le sélecteur stable de moduix pour cet élément.
- `data-state="loading"` et `data-state="loaded"` reflètent la propriété `loading`.
- `data-variant="pulse"` et `data-variant="none"` reflètent la variante choisie.
- `data-loading` n’est présent que lorsque les styles d’attente sont actifs.
