# Thèmes

Les thèmes moduix sont de simples couches CSS de tokens. `Calm` offre une base équilibrée ; `Dense`,
`Soft` et `Contrast` proposent d’autres directions visuelles. Un préréglage peut modifier la palette,
les rayons, l’espacement, la densité des contrôles et les ombres, sans modifier les API des composants
ni ajouter de runtime de thème.

## Choisissez un préréglage

| Préréglage | Contrôles / lignes de liste | Idéal pour |
| --- | --- | --- |
| Calm | 36px / 32px | La plupart des interfaces produit, avec un rythme neutre et des surfaces apaisées. |
| Dense | 34px / 30px | Les outils riches en données, lorsque la densité d’information à l’écran compte. |
| Soft | 40px / 34px | Les interfaces spacieuses ou tactiles, avec une direction visuelle plus chaleureuse. |
| Contrast | 36px / 32px | Les interfaces qui ont besoin de bordures plus nettes et d’un focus bien distinct. |

La démo utilise de vrais contrôles moduix. Ouvrez le Select et naviguez entre les champs au clavier
pour comparer la densité des déclencheurs, la hauteur des lignes de liste, les libellés, les surfaces
et le comportement du focus. Les noms des préréglages décrivent une direction visuelle, sans garantir
l’accessibilité. Avant la mise en production, testez avec votre contenu et les surcharges de votre
application le contraste du texte, la visibilité du focus, le zoom et la taille des cibles.

## Comment fonctionnent les couches

Le fichier de styles de base définit le contrat complet des tokens et les valeurs par défaut `Calm`.
Un préréglage redéfinit une partie de ce contrat ; l’application ne modifie ensuite que les décisions
liées à votre marque. Les composants utilisent des alias sémantiques et propres aux composants : une
modification de la palette ou de la densité se propage donc aux contrôles associés, au lieu de devenir
une série de règles ponctuelles.

```text
foundation tokens → optional preset → application overrides → component aliases
```

Le CSS de chaque préréglage reste compact, lisible et facile à retirer. Consultez [Tokens](/docs/tokens)
pour voir quelles variables font partie de l’API publique de thématisation.

## Utilisation avec le paquet npm

Importez d’abord le socle, puis un préréglage. Ajoutez `data-moduix-theme` sur `<html>` pour que les
composants rendus dans un portail héritent des mêmes tokens. Définissez
`data-moduix-color-scheme="dark"` sur cet élément pour la palette sombre de moduix.

```tsx
import '@moduix/react/style.css';
import '@moduix/react/presets/soft.css';
```

```html
<html data-moduix-theme="soft" data-moduix-color-scheme="dark"></html>
```

Choisissez l'un de ces chemins à la place de `soft.css` :

```text
@moduix/react/presets/dense.css
@moduix/react/presets/contrast.css
```

## Utilisation avec le registre

Installez un préréglage dont vous gardez le code source dans le projet, puis importez son CSS généré
après le fichier de styles de base.

```bash
npx shadcn@latest add @moduix-react/theme-dense
```

```tsx
import '@/lib/moduix/styles/style.css';
import '@/lib/moduix/presets/dense.css';
```

```html
<html data-moduix-theme="dense"></html>
```

Remplacez `dense` par `soft` ou `contrast` pour utiliser un autre préréglage.

## Changer de thème à l’exécution

Conservez le thème choisi sur l’élément document, afin que le contenu ordinaire et les overlays dans
un portail reçoivent les mêmes tokens. Ne mémorisez son nom que si votre produit doit retenir ce choix.

```tsx
function setTheme(theme: 'calm' | 'dense' | 'soft' | 'contrast') {
  document.documentElement.dataset.moduixTheme = theme;
  localStorage.setItem('moduix-theme', theme);
}
```

Appliquez la valeur enregistrée avant le rendu de l’application pour éviter un changement de thème
visible au démarrage.

## Personnaliser un préréglage

Le préréglage n’est qu’une couche de variables CSS. Redéfinissez-le dans votre propre fichier de
styles, chargé après le préréglage. Modifiez les tokens sémantiques pour les décisions à l’échelle du
système, et les alias de composants uniquement pour les exceptions choisies en connaissance de cause.

```css
[data-moduix-theme='soft'] {
  --moduix-primary: oklch(0.5 0.17 285);
  --moduix-radius: 0.875rem;
}
```

## Créer un thème personnalisé

Créez un fichier de styles chargé après le socle et définissez le nom du thème sur `<html>`. Commencez
par les tokens qui déterminent votre direction visuelle : les tokens omis conservent leurs valeurs de
base. N’ajoutez des tokens de taille ou d’espacement que si votre thème modifie volontairement la
densité. Utilisez un préréglage comme référence si vous souhaitez remplacer toute la palette,
l’espacement et les ombres.

```tsx
import '@moduix/react/style.css';
import './brand.css';
```

```css
/* brand.css */
[data-moduix-theme='brand'] {
  --moduix-background: oklch(0.98 0.01 260);
  --moduix-foreground: oklch(0.2 0.02 260);
  --moduix-card: oklch(1 0 0);
  --moduix-card-foreground: oklch(0.2 0.02 260);
  --moduix-primary: oklch(0.5 0.18 260);
  --moduix-primary-foreground: oklch(0.99 0.002 260);
  --moduix-border: oklch(0.86 0.02 260);
  --moduix-input: oklch(0.82 0.025 260);
  --moduix-ring: oklch(0.58 0.15 260);
  --moduix-radius: 0.875rem;
  --moduix-size-sm: 2rem;
  --moduix-size-md: 2.25rem;
}

[data-moduix-theme='brand'][data-moduix-color-scheme='dark'] {
  --moduix-background: oklch(0.17 0.02 260);
  --moduix-foreground: oklch(0.97 0.004 260);
  --moduix-card: oklch(0.22 0.024 260);
  --moduix-card-foreground: oklch(0.97 0.004 260);
  --moduix-primary: oklch(0.78 0.13 260);
  --moduix-primary-foreground: oklch(0.18 0.024 260);
  --moduix-border: oklch(0.76 0.03 260 / 0.28);
  --moduix-input: oklch(0.76 0.03 260 / 0.34);
  --moduix-ring: oklch(0.74 0.12 260);
}
```

```html
<html data-moduix-theme="brand" data-moduix-color-scheme="dark"></html>
```

Consultez [Tokens](/docs/tokens) pour la référence des tokens système et [Mode sombre](/docs/dark-mode)
pour le commutateur clair/sombre géré par l’application.
