# Thèmes

Les thèmes moduix sont des couches de tokens CSS. `Calm` correspond aux valeurs par défaut du
socle ; `Dense`, `Soft` et `Contrast` sont des préréglages facultatifs pour d’autres directions
visuelles. Un préréglage peut modifier la palette, les rayons, l’espacement, la densité des
contrôles et les ombres sans changer l’API des composants ni dépendre d’un moteur de thème distinct.
Tous les adaptateurs publiés utilisent les mêmes fichiers de thème et le même contrat de tokens.

## Choisir un préréglage

| Préréglage | Contrôle principal / ligne de liste contextuelle | Bon point de départ pour                                                             |
| ---------- | ------------------------------------------------ | ------------------------------------------------------------------------------------ |
| Calm       | 36px / 32px                         | La plupart des interfaces produit : rythme neutre et surfaces discrètes.            |
| Dense      | 34px / 30px                         | Les outils d’administration riches en données, où chaque information compte.        |
| Soft       | 40px / 34px                         | Les parcours spacieux ou tactiles, avec des surfaces arrondies et un accent plus chaleureux. |
| Contrast   | 36px / 32px                         | Les interfaces qui ont besoin de bordures nettes et d’une séparation claire du focus. |

Les valeurs du tableau correspondent à la hauteur par défaut du contrôle principal et des lignes de
liste contextuelle de chaque préréglage. Utilisez l’aperçu pour comparer la densité, les surfaces et
les styles de focus avec de vrais composants moduix.

Les noms des préréglages indiquent une direction visuelle, mais ne constituent pas une garantie
d’accessibilité. Avant la mise en production, testez avec votre contenu et les redéfinitions de votre
application le contraste du texte, la visibilité du focus, le zoom et la taille des cibles
interactives.

## Comment fonctionnent les couches

La feuille de styles du socle définit le contrat complet des tokens et les valeurs par défaut de
`Calm`. Un préréglage redéfinit certaines valeurs, puis votre application peut ne modifier que les
choix qui lui appartiennent. Les composants utilisent des alias sémantiques et propres aux
composants : une modification de la palette ou de la densité se propage aux contrôles associés,
au lieu de devenir une série de règles ponctuelles.

```text
foundation tokens → optional preset → application overrides → component aliases
```

Les fichiers CSS des préréglages ne contiennent que leurs redéfinitions, ce qui les rend faciles à
inspecter et à retirer. Consultez [Tokens](/docs/tokens) pour voir quelles variables font partie de
l’API publique de thématisation.

## Utiliser le paquet npm

Importez le socle une fois, puis un préréglage. Si les utilisateurs peuvent passer d’un préréglage
à l’autre, chargez à l’avance le CSS de chacun d’eux. `Calm` utilise les valeurs du socle et ne
possède pas de fichier `calm.css`.

Définissez `data-moduix-theme` et le mode de couleur sur `<html>` afin qu’ils s’appliquent au contenu
ordinaire comme aux composants rendus dans un portail. Vous pouvez omettre
`data-moduix-color-scheme` en mode clair.

## Utiliser le registre

Les préréglages sont indépendants du framework. La même URL du registre commun fonctionne avec React
ou Solid, quelle que soit l’approche de stylisation. La CLI copie le fichier CSS dans votre projet :

<PackageManagerTabs command="shadcn@latest add https://moduix.dev/r/foundation/theme-dense.json" dlx />

```tsx
import '@/lib/moduix/styles/style.css';
import '@/lib/moduix/presets/dense.css';
```

```html
<html data-moduix-theme="dense"></html>
```

Remplacez `dense` par `soft` ou `contrast` pour utiliser un autre préréglage. Si les utilisateurs
peuvent changer de préréglage, installez et importez chacun de ceux qu’ils peuvent sélectionner.

Avec Tailwind, conservez ces imports avant `@import 'tailwindcss'`, comme dans la
[configuration du paquet Tailwind](/docs/quick-start#tailwind-css). N’ajoutez pas la réinitialisation
de moduix.

## Changer de thème à l’exécution

Le changement de thème modifie uniquement l’attribut `data-moduix-theme`. Conservez le nom choisi sur
l’élément racine du document afin que le contenu ordinaire et les superpositions rendues dans un
portail reçoivent les mêmes tokens. Ne mémorisez ce nom que si votre produit doit retenir le choix de
l’utilisateur.

```tsx
type Theme = 'calm' | 'dense' | 'soft' | 'contrast';

function setTheme(theme: Theme) {
  document.documentElement.dataset.moduixTheme = theme;
}
```

La valeur `calm` conserve les valeurs du socle. Le CSS de chaque autre préréglage disponible doit déjà
être chargé. Si votre produit mémorise la sélection, enregistrez-la et appliquez-la avant le premier
rendu pour éviter un changement de thème visible au démarrage.

## Personnaliser un préréglage

Un préréglage n’est qu’une couche de variables CSS. Chargez votre propre feuille de styles après le
préréglage et redéfinissez les valeurs à modifier. Préférez les tokens sémantiques pour les choix à
l’échelle du produit et les alias de composants pour les exceptions ciblées.

```css
[data-moduix-theme='soft'] {
  --moduix-primary: oklch(0.5 0.17 285);
  --moduix-radius: 0.875rem;
}
```

## Créer un thème personnalisé

Si les préréglages fournis ne conviennent pas, créez une feuille de styles chargée après le socle et
utilisez une nouvelle valeur pour `data-moduix-theme`. Commencez par les tokens qui définissent
votre direction visuelle. Les tokens que vous ne précisez pas conservent les valeurs du socle.
N’ajoutez des tokens de taille ou d’espacement que si votre thème modifie volontairement la densité.
Utilisez un préréglage comme référence si vous souhaitez remplacer toute la palette, l’espacement
et les ombres.
