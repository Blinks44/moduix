## Utilisation

<Usage />

`Toc` est le composant racine de l’API plate. Passez-lui un tableau `items` contenant les titres à
suivre. Chaque élément doit avoir une `value` correspondant à l’attribut `id` d’un titre et un
`depth` correspondant à son niveau sémantique, par exemple `2` pour `<h2>`. Utilisez le même objet
pour rendre `TocItem`, puis construisez le fragment de `TocLink` à partir de sa `value`.

Sur une page classique, omettez `scrollEl` et le composant observe la fenêtre. L’aperçu ci-dessous
utilise sa propre zone de défilement. Passez cet élément à `scrollEl` pour que le suivi et la
navigation par lien restent dans l’aperçu.

## Exemples

### Rail

Placez `TocRail` dans chaque lien pour tracer un connecteur SVG entre les niveaux de titres voisins.
Transmettez les profondeurs courante, précédente et suivante depuis le même tableau `items` ordonné.
Le rail du lien actif reprend la couleur de l’indicateur. N’ajoutez pas `TocIndicator` dans cette
même liste.

<Example name="table-of-contents/rail" />

### Avec une navigation repliable

Placez la liste de navigation dans `Collapsible` lorsque le lecteur doit pouvoir masquer le sommaire
complet. `TocContext` fournit le titre de l’élément actif au bouton et à l’anneau de progression,
tandis que les liens ciblent toujours la même zone de lecture.

<Example name="table-of-contents/with-collapsible" />

### Root Provider

Utilisez `useToc()` lorsqu’un autre contrôle doit lire les titres actifs ou faire défiler la zone de
lecture. Voir [Partager l’état hors de l’arbre](/docs/composition-patterns#root-provider).

## Composition

Passez un élément pour chaque titre suivi. `item.value`, l’attribut `id` du titre et le fragment de
`TocLink` doivent être identiques, tandis que `depth` doit correspondre au niveau sémantique du
titre. Omettez `scrollEl` lorsque la fenêtre gère le défilement ; passez la zone de lecture lorsqu’elle
possède son propre conteneur défilant.

Contrairement à Ark UI, `autoScroll` vaut `false` par défaut, à la fois pour `Toc` et pour
`useToc()`. Passez `autoScroll` pour l’activer uniquement lorsque la révélation automatique de
l’élément de navigation actif ne peut pas faire défiler un conteneur ancêtre.

Utilisez `TocRootProvider` avec `useToc()` uniquement lorsque des contrôles extérieurs à l’arbre
ont besoin du même état de suivi, par exemple `activeIds` ou `scrollTo`. React expose le store comme
un objet ; Solid donne accès à son état réactif au moyen de la fonction retournée, tandis que Vue
expose directement cet état réactif au modèle. Utilisez `TocContext` si une composition environnante,
comme `Collapsible`, a besoin des éléments actifs.
Pour les liens d’un routeur, utilisez `TocLink asChild` avec un seul enfant `<a>` sémantique ; en
Solid, transmettez cet enfant avec la fonction de rendu attendue par `asChild`. Choisissez
`TocIndicator` pour marquer la plage active ou `TocRail` pour montrer la hiérarchie de chaque
lien ; ne rendez pas les deux dans la même liste.

:::warning Limites des bibliothèques sous-jacentes
Avec Ark UI Vue 5.39.3 et Zag 1.45.0, une modification de `activeIds` contrôlé renvoie les ID
demandés dans `activeChange`. `TocNav` réutilise encore l’ID de la racine lorsque les deux parties
sont rendues, ce qui crée des ID dupliqués. Cette limite est suivie dans
[Ark #4187](https://github.com/chakra-ui/ark/issues/4187).
:::

## Styles

Utilisez `className` en React ou `class` en Solid et en Vue sur n’importe quel élément exporté. Les variantes
Tailwind utilisent des classes utilitaires et vos propres classes. Les variantes CSS Modules s’appuient sur les
jetons de foundation et n’ont pas de variables propres : une classe sur un élément, ou un sélecteur `data-slot`,
remplace les styles du composant placés dans une couche. Pour modifier la colonne de navigation, remplacez
`grid-template-columns` sur `Toc`.

### Points d’accroche CSS

| Partie | `data-slot` |
| --- | --- |
| `Toc` | `toc-root` |
| `TocRootProvider` | `toc-root-provider` |
| `TocContent` | `toc-content` |
| `TocNav` | `toc-nav` |
| `TocTitle` | `toc-title` |
| `TocList` | `toc-list` |
| `TocItem` | `toc-item` |
| `TocLink` | `toc-link` |
| `TocIndicator` | `toc-indicator` |
| `TocRail` | `toc-rail` |

- Les attributs Ark `data-scope="toc"` et `data-part` sur les parties primitives
- Les attributs et variables de `TocItem` : `data-value`, `data-depth`, `data-active`, `data-first`,
  `data-last` et `--depth` ; `TocLink` expose `data-value`, `data-active` et `aria-current`
- Les variables d’exécution Ark `--top`, `--left`, `--width` et `--height` sur la racine

## Référence de l’API

| Prop | Type | Défaut | Description |
| --- | --- | --- | --- |
| `items` | `TocItem[]` | — | Titres suivis, chacun avec `value` (id du titre) et `depth`. |
| `scrollEl` | `() => HTMLElement \| null` | — | Renvoie le conteneur de défilement ; la page par défaut. |
| `rootMargin` | `string` | `'-20px 0px -40% 0px'` | Marge de l’IntersectionObserver qui décide quand un titre est actif. |
| `threshold` | `number \| number[]` | `0` | Seuil de l’IntersectionObserver. |
| `autoScroll` | `boolean` | `false` | Fait défiler la liste pour garder l’élément actif visible. |
| `scrollBehavior` | `ScrollBehavior` | `'smooth'` | Comportement de défilement pour `autoScroll`. |
| `activeIds` | `string[]` | — | Id des titres actifs en mode contrôlé. |
| `defaultActiveIds` | `string[]` | — | Titres actifs au départ. |
| `onActiveChange` | `(details: ActiveChangeDetails) => void` | — | Appelé lorsque les titres visibles changent. |
