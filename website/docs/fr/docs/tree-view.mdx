## Anatomie

```text
TreeView / TreeView.Root
├─ TreeView.Label
└─ TreeView.Tree
   └─ TreeView.Node ou TreeView.NodeProvider
      ├─ TreeView.Branch
      │  ├─ TreeView.BranchControl
      │  │  ├─ TreeView.BranchIndicator
      │  │  └─ TreeView.BranchText
      │  └─ TreeView.BranchContent
      │     ├─ TreeView.BranchIndentGuide
      │     └─ nœuds imbriqués
      └─ TreeView.Item
         └─ TreeView.ItemText
```

| Partie                           | Rôle                                                                  |
| -------------------------------- | --------------------------------------------------------------------- |
| `TreeView` / `TreeView.Root`     | Conserve la collection et gère l’ouverture, la sélection, le focus, les cases à cocher et le renommage. |
| `TreeView.RootProvider`          | Relie les parties de l’arborescence à une instance créée par `useTreeView`. |
| `TreeView.Label`                 | Donne un nom accessible à l’arborescence.                            |
| `TreeView.Tree`                  | Crée le conteneur d’arborescence ARIA.                               |
| `TreeView.Node`                  | Un provider pratique qui expose `{ node, indexPath, state }`.        |
| `TreeView.NodeProvider`          | La limite de contexte Ark de bas niveau pour une composition personnalisée. |
| `TreeView.Branch*`               | Un nœud dépliable, son contrôle, son indicateur, son texte et son contenu enfant. |
| `TreeView.Item*`                 | Une feuille et son indicateur facultatif de sélection.               |
| `TreeView.NodeCheckbox*`         | La case à cocher et son indicateur coché ou indéterminé.             |
| `TreeView.NodeRenameInput`       | Le champ affiché pendant le renommage d’un nœud.                     |

## Composition

Utilisez `TreeView.Node` pour le rendu récursif. Il fournit `node`, `indexPath` et l’état courant du
nœud, tandis que vous choisissez les parties `Branch` ou `Item`. Si votre composant récursif doit
accéder directement au contexte du nœud, utilisez `TreeView.NodeProvider` au lieu d’ajouter une
enveloppe autour de `Node`. Lorsque des contrôles externes doivent gérer l’état de l’arborescence,
créez-le avec `useTreeView` et transmettez-le à `TreeView.RootProvider` ; ne rendez pas un second root
pour la même instance. Si une branche utilise un `BranchTrigger` distinct, ajoutez `role="none"` à
`BranchControl`.

## Styles

Utilisez `className` en React ou `class` en Solid sur chaque partie exportée pour les styles
structurels. Les parties de branche exposent `data-state="open|closed"`, celles des cases à cocher
`data-state="checked|unchecked|indeterminate"`, et celles des nœuds exposent `data-focus`,
`data-selected`, `data-disabled`, `data-loading`, `data-renaming`, `data-depth`, `data-path` et
`data-value`. Le composant respecte les variables Ark `--depth` pour l’indentation et `--height` pour
la hauteur pendant le repli, et désactive l’animation des branches si l’utilisateur préfère réduire
les mouvements.

Les variantes Tailwind utilisent des classes utilitaires natives et les classes de l’application. Les
variantes CSS Modules exposent les variables documentées `--moduix-tree-view-*` ci-dessous.
