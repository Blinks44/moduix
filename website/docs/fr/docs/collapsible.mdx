## Choisir le bon composant

Utilisez `Collapsible` pour une seule section indépendante. Préférez `Accordion` lorsque plusieurs
sections liées doivent partager la navigation au clavier ou un état coordonné.

## Anatomie

```text
Collapsible
├─ CollapsibleTrigger
│  ├─ libellé
│  └─ CollapsibleIndicator (facultatif)
└─ CollapsibleContent
   └─ CollapsibleBody
       └─ contenu

CollapsibleRootProvider
└─ même arbre de parties relié à un store useCollapsible()
```

| Partie                    | Rôle                                                                    |
| ------------------------- | ----------------------------------------------------------------------- |
| `Collapsible`             | Gère l’état d’une seule section repliable.                              |
| `CollapsibleRootProvider` | Relie les parties à l’état créé avec `useCollapsible`.                  |
| `CollapsibleTrigger`      | Bouton accessible qui déplie ou replie le contenu.                       |
| `CollapsibleIndicator`    | Indicateur facultatif qui affiche par défaut un chevron moduix.         |
| `CollapsibleContent`      | Zone animée dont Ark mesure les dimensions.                             |
| `CollapsibleBody`         | Conteneur interne pour les espacements et la mise en page du contenu.    |

## Composition

`Collapsible` conserve son état dans la racine. Utilisez `defaultOpen` pour une zone non contrôlée, ou
`open` avec `onOpenChange(details)` lorsqu’une autre partie de l’application gère l’état. En Vue,
utilisez `v-model:open` pour ce même contrat contrôlé. Le callback conserve l’objet `details` d’Ark :
l’état contrôlé se lit donc avec `details.open`.

Utilisez `CollapsibleRootProvider` avec `useCollapsible()` du paquet correspondant au framework lorsque
le store doit être créé en dehors de l’arbre rendu ou partagé entre plusieurs limites de composition.
Transmettez ce store à `CollapsibleRootProvider` et ne rendez pas une seconde racine `Collapsible` pour le même état.

Placez les espacements et les styles de surface sur `CollapsibleBody`, et non sur
`CollapsibleContent`, afin qu’Ark puisse mesurer correctement la partie animée. `CollapsibleIndicator`
est facultatif et affiche par défaut le chevron moduix.

Utilisez `asChild` uniquement lorsqu’un élément sémantique appartenant à l’application doit recevoir le
comportement du déclencheur ; il doit rester un bouton accessible au clavier. Avec Solid, transmettez une
fonction de rendu, par exemple `asChild={(props) => <button {...props()} />}`.

## Styles

Utilisez `className` avec React ou `class` avec Solid sur les parties exportées pour les styles
structurels. Pour les styles qui dépendent de l’état, privilégiez les attributs de données Ark tels
que `data-state` et `data-disabled`, ainsi que les sélecteurs `data-slot` de moduix. Les variantes
Tailwind utilisent les utilitaires natifs et les classes de l’application ; les variables ci-dessous
personnalisent les variantes CSS Modules. Les attributs de données et les hooks `data-slot` sont
communs aux deux modes de style.

Placez les espacements sur `CollapsibleBody`, et non sur `CollapsibleContent`, afin qu’Ark puisse
mesurer et animer correctement le contenu.

### Points d’accroche CSS

- Les parties DOM exposent `data-slot="collapsible-root"`, `collapsible-root-provider`,
  `collapsible-trigger`, `collapsible-indicator`, `collapsible-content` et `collapsible-body`.
- Les parties Ark exposent `data-scope="collapsible"` et les valeurs `data-part` de la racine, du
  déclencheur, de l’indicateur et du contenu.
- Ark ajoute `data-state="open" | "closed"` à la racine, au déclencheur, à l’indicateur et au contenu.
- Ark ajoute `data-collapsible` à la partie `CollapsibleContent`.
- `data-disabled` marque les parties déclencheur, indicateur et contenu lorsqu’elles sont désactivées.
- `data-has-collapsed-size` marque le contenu configuré avec `collapsedHeight` ou `collapsedWidth`.
- L’animation du contenu utilise les variables Ark `--height`, `--width`, `--collapsed-height` et `--collapsed-width`.
