Utilisez `NavigationMenu` avec `NavigationMenuList` et `NavigationMenuItem`. Attribuez une valeur
`value` unique à chaque élément. Pour un groupe de liens, placez `NavigationMenuTrigger` et
`NavigationMenuContent` dans le même élément. Utilisez `NavigationMenuLink` pour les destinations
directes du premier niveau et pour les liens à l’intérieur d’un panneau.

## Choisir le bon composant

Utilisez `NavigationMenu` pour la navigation principale d’un site ou d’un produit lorsque certains
éléments de premier niveau ouvrent des groupes de destinations associées.

- Choisissez **`NavigationMenu`** lorsqu’un élément de premier niveau peut afficher un groupe de liens associés.
- Choisissez **`Menu`** pour les actions contextuelles plutôt que pour la navigation.
- Choisissez **`Tabs`** lorsque chaque contrôle sélectionné change le contenu affiché dans une zone de la page courante.

## Exemples

### Viewport partagé

Utilisez une zone `NavigationMenuViewport` partagée lorsque les panneaux ont des tailles différentes, mais doivent
s’animer dans une même surface. Cet exemple utilise un panneau à deux colonnes et des panneaux de
largeurs différentes, afin de rendre visibles les animations de largeur et de hauteur de `NavigationMenuViewport`
lors du passage d’un déclencheur à l’autre.

<Example name="navigation-menu/viewport" />

### Ouverture au clic

Définissez `disableHoverTrigger` lorsque les panneaux doivent s’ouvrir uniquement au clic ou au
clavier, et non au survol. Cela convient aux interfaces tactiles et aux en-têtes denses où le survol
ouvrirait les panneaux par accident.

### Valeur contrôlée

Passez `value` et `onValueChange` (`v-model:value` en Vue) lorsque le panneau ouvert pilote aussi
l’interface voisine. La sortie sous l’exemple affiche la valeur de l’élément ouvert. Voir [Contrôler l’état depuis l’application](/docs/composition-patterns#controlled-state).

## Composition

Utilisez `defaultValue` pour un menu non contrôlé. Lorsqu’une autre partie de l’application gère
l’élément ouvert, transmettez `value` avec `onValueChange(details)` ; `details.value` contient la valeur
de l’élément ouvert ou une chaîne vide lorsque tous les panneaux sont fermés. Créez le store avec
`useNavigationMenu()` et transmettez-le à `NavigationMenuRootProvider` lorsqu’il doit vivre en dehors de
l’arbre rendu ; ne rendez pas une autre racine pour ce même store. React lit le store comme un objet,
tandis que Solid lit son état réactif via la fonction retournée, et Vue expose son état réactif via des
refs et des liaisons de template. Dans Vue, utilisez `v-model:value` pour contrôler la valeur. Utilisez
`NavigationMenuContext` lorsqu’un descendant a besoin de l’état courant via une fonction de rendu plutôt
que via le store.

Sans zone `NavigationMenuViewport` partagée, `NavigationMenuContent` s’affiche à côté de son élément.
Ajoutez `NavigationMenuViewportPositioner` et `NavigationMenuViewport` lorsque plusieurs panneaux doivent
partager une même surface animée ; la prop `align` du positioner (`"start" | "center" | "end"`,
`"center"` par défaut) aligne la zone par rapport au positionneur de la valeur. Utilisez `asChild`
pour les liens de routeur ou les déclencheurs personnalisés uniquement si l’enfant reste un seul élément
interactif pouvant recevoir le focus.

## Styles

Utilisez `className` dans React, `class` dans Solid ou `class` dans Vue sur les parties exportées pour les styles
structurels. Pour les styles liés à l’état, privilégiez les attributs de données Ark comme `data-state`,
`data-current` et `data-orientation`, avec les sélecteurs moduix `data-slot`. Les variantes Tailwind
utilisent des utilitaires natifs et les classes du consommateur. Les variantes CSS Modules prennent les
couleurs, les espacements et la typographie dans les jetons foundation et n’exposent en variables CSS
que les limites de taille du panneau et du viewport ; remplacez le reste avec une classe sur la partie.
L’animation du panneau et du viewport suit les variables partagées `--moduix-popup-motion-*`. Les attributs de données et les points d’accroche `data-slot` sont communs
aux deux modes de style.

### Points d’accroche CSS

| Partie | `data-slot` |
| --- | --- |
| `NavigationMenu` | `navigation-menu-root` |
| `NavigationMenuRootProvider` | `navigation-menu-root-provider` |
| `NavigationMenuList` | `navigation-menu-list` |
| `NavigationMenuItem` | `navigation-menu-item` |
| `NavigationMenuTrigger` | `navigation-menu-trigger` |
| `NavigationMenuContent` | `navigation-menu-content` |
| `NavigationMenuLink` | `navigation-menu-link` |
| `NavigationMenuIndicator` | `navigation-menu-indicator` |
| `NavigationMenuItemIndicator` | `navigation-menu-item-indicator` |
| `NavigationMenuArrow` | `navigation-menu-arrow` |
| `NavigationMenuViewportPositioner` | `navigation-menu-viewport-positioner` |
| `NavigationMenuViewport` | `navigation-menu-viewport` |

Ciblez la partie responsable de l’aspect que vous souhaitez modifier :

- `NavigationMenu` pour la largeur de la racine, la couleur du texte et sa position dans la mise en page
- `NavigationMenuList` pour l’espacement et l’orientation des éléments de premier niveau
- `NavigationMenuTrigger` et `NavigationMenuLink` pour les contrôles de navigation, l’état courant et le focus
- `NavigationMenuContent` pour l’apparence des panneaux dépliables et de leurs liens
- `NavigationMenuIndicator` et `NavigationMenuItemIndicator` pour les décorations facultatives de l’état actif ; utilisez `NavigationMenuArrow` avec une zone `NavigationMenuViewport` partagée
- `NavigationMenuViewportPositioner` et `NavigationMenuViewport` pour une zone de panneau partagée et animée

Parmi les attributs Ark utiles figurent `data-scope="navigation-menu"`, `data-part`, `data-state`,
`data-current`, `data-disabled`, `data-orientation` et `data-motion`. À l’exécution, Ark définit les
variables `--trigger-x`, `--trigger-y`, `--trigger-width`, `--trigger-height`, `--viewport-x`,
`--viewport-y`, `--viewport-width` et `--viewport-height`.

## Clavier

| Touche | Action |
| --- | --- |
| `Tab` / `Shift+Tab` | Passe d’un déclencheur ou lien de premier niveau à l’autre. |
| `Enter` / `Space` | Ouvre ou ferme le panneau du déclencheur ayant le focus. |
| `ArrowLeft` / `ArrowRight` | Passe au déclencheur précédent ou suivant, ou d’un lien à l’autre dans un panneau ouvert ; ArrowUp et ArrowDown en orientation verticale. |
| `Home` / `End` | Passe au premier ou au dernier déclencheur ou lien. |
| `Esc` | Ferme le panneau ouvert et rend le focus à son déclencheur. |
