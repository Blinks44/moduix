## Référence de l’API

Ark UI ne fournit pas de primitive `Badge` dédiée. moduix construit `Badge` avec la [factory Ark](https://ark-ui.com/docs/guides/composition#the-ark-factory)
officielle et suit les recommandations d’Ark pour la [composition](https://ark-ui.com/docs/guides/composition), les
[styles](https://ark-ui.com/docs/guides/styling) et les [références](https://ark-ui.com/docs/guides/ref).

## Choisir le bon composant

Utilisez `Badge` pour afficher une information courte sur un élément. C’est un composant de présentation : il ne remplace
pas un contrôle qui permet à l’utilisateur de sélectionner ou de modifier une valeur.

- Choisissez **`Badge`** pour de courtes métadonnées comme un statut, une catégorie, une version ou un nombre.
- Choisissez **`Tag`** pour des valeurs sélectionnées, des filtres, des affectations ou des libellés qui font partie de l’état actuel de l’interface.

## Exemple de base

Commencez par un `<Badge>` simple. Par défaut, le composant rend un `span` de présentation. Définissez `variant` pour
choisir un style intégré et ajoutez `Badge.Dot` uniquement lorsqu’un statut a besoin d’un indicateur visuel.

## Anatomie

`Badge` est le raccourci de `Badge.Root`. Son API publique reste volontairement réduite aux parties visibles.

```text
Badge / Badge.Root
├─ Badge.Label (facultatif ; le texte direct est automatiquement placé dans Badge.Label)
├─ Badge.Dot (facultatif)
└─ icône svg (facultative)
```

| Partie                 | Rôle                                                                                  |
| ---------------------- | ------------------------------------------------------------------------------------- |
| `Badge` / `Badge.Root` | Partie racine. Applique la variante, la bordure, les espacements et la troncature du texte. |
| `Badge.Label`          | Partie de texte explicite. Permet de tronquer correctement un badge composé.          |
| `Badge.Dot`            | Partie décorative. Affiche un marqueur circulaire qui reprend la couleur du texte.    |

## Composition

### Composition recommandée

Pour la plupart des statuts courts, catégories, versions et compteurs, utilisez directement `<Badge>`.
`Badge.Root` est son équivalent dans l’espace de noms `Badge`.

Utilisez `variant` pour les styles intégrés : `default`, `secondary`, `destructive`, `outline`, `ghost` et `link`.

Lorsque le badge a besoin d’un point ou d’une icône, placez `Badge.Dot` ou une icône enfant directe à côté de
`Badge.Label`. Le texte fourni directement est automatiquement placé dans `Badge.Label`.

`Badge.Root`, `Badge.Label` et `Badge.Dot` transmettent leur `ref` aux éléments DOM qu’ils rendent.

### Quand créer une composition personnalisée

Utilisez `Badge asChild` lorsqu’un élément sémantique, comme `<a>` ou `<button>`, doit devenir l’élément racine du DOM.
La composition Ark exige un seul enfant. Celui-ci conserve sa sémantique native, et les liens, boutons et éléments
portant `role="button"` reçoivent les styles par défaut du badge pour le curseur, le survol et le focus visible.

Utilisez une variable CSS locale ou redéfinissez `className` lorsque le badge nécessite une taille ou un style personnalisé.
Il n’existe pas de prop `size` : ajustez les dimensions avec les variables CSS publiques.

### Propriétés par défaut

| Propriété | Valeur par défaut | Valeurs / remarques                                         |
| --------- | ----------------- | ----------------------------------------------------------- |
| `variant` | `default`         | `default`, `secondary`, `destructive`, `outline`, `ghost`, `link` |
| `asChild` | `false`           | Rend un enfant unique à la place de l’élément racine `span` |

### Comportement

- Par défaut, `Badge` sert uniquement à afficher une information et rend un `span`.
- `Badge.Dot` est décoratif et masqué pour les technologies d’assistance ; le texte visible doit donc transmettre la signification du statut.
- `Badge` n’ajoute à lui seul ni interaction ni sémantique de lien ou de bouton.
- Les liens, boutons et autres éléments sémantiques rendus avec `asChild` conservent leur sémantique native et reçoivent les styles par défaut du curseur, du survol et du focus visible.
- Les boutons désactivés et les éléments avec `aria-disabled="true"` conservent leur sémantique, n’appliquent pas les styles de survol et utilisent la variable publique d’opacité dédiée à l’état désactivé.
- Les libellés longs restent sur une seule ligne et sont tronqués par l’élément racine. Ajoutez `title` pour rendre la valeur complète visible au survol. Dans les interfaces tactiles, choisissez un libellé qui tient dans l’espace disponible.
- Le texte fourni directement est automatiquement placé dans `Badge.Label`. Utilisez explicitement `Badge.Label` lorsque le texte est composé avec un point, une icône ou un autre élément.
- Les icônes `svg` placées directement comme enfants héritent de `currentColor` et utilisent `--moduix-badge-icon-size`.
- Le contenu numérique utilise des chiffres tabulaires et, par défaut, le texte du badge n’est pas sélectionnable.

## Styles

Commencez avec une variante intégrée. Pour une modification ponctuelle de taille ou de style, définissez les variables
`--moduix-badge-*` publiques sur le badge via une classe ou un style en ligne. Utilisez les variables
`--moduix-badge-<variant>-*` pour personnaliser une variante dans toute l’application. Les variables générales
`--moduix-badge-bg`, `--moduix-badge-border-color` et `--moduix-badge-color` remplacent les valeurs propres à la variante
pour un badge donné.

### Points d’accroche CSS

- `data-slot="badge-root"`, `data-slot="badge-label"` et `data-slot="badge-dot"` sont des sélecteurs stables pour cibler les parties exportées en CSS.
- `Badge.Root` expose également `data-scope="badge"` et `data-part="root"`. `Badge.Label` et `Badge.Dot` exposent `data-part="label"` et `data-part="dot"`.
- `Badge.Root` indique la variante sélectionnée dans l’attribut `data-variant`.
- Les liens et boutons sémantiques rendus avec `Badge asChild` ou `Badge.Root asChild` reçoivent les styles par défaut du focus visible définis par la racine.
- Les icônes `svg` placées directement comme enfants héritent de `currentColor`, ne capturent pas les événements du pointeur et utilisent `--moduix-badge-icon-size`.
- `Badge` ne dispose ni d’une primitive Ark dédiée ni d’une machine de comportement ; il n’expose donc aucun état géré par Ark ni aucune variable CSS d’exécution.
