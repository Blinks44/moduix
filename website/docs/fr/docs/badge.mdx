## Utilisation

<Usage />

Commencez par un `<Badge>` simple. Par défaut, le composant rend un `span` de présentation. Définissez `variant` pour
choisir un style intégré, `size` pour choisir `sm`, `md` ou `lg`, et ajoutez `BadgeDot` uniquement lorsqu’un statut
a besoin d’un indicateur visuel.

## Choisir le bon composant

Utilisez `Badge` pour afficher une information courte sur un élément. C’est un composant de présentation : il ne remplace
pas un contrôle qui permet à l’utilisateur de sélectionner ou de modifier une valeur.

- Choisissez **`Badge`** pour de courtes métadonnées comme un statut, une catégorie, une version ou un nombre.
- Choisissez **`Tag`** pour des valeurs sélectionnées, des filtres, des affectations ou des libellés qui font partie de l’état actuel de l’interface.

Les exports Vue sont disponibles depuis `@moduix/vue/badge` pour CSS Modules et `@moduix/vue-tailwind/badge` pour Tailwind CSS. Les exports Svelte sont disponibles depuis `@moduix/svelte/badge` pour CSS Modules et `@moduix/svelte-tailwind/badge` pour Tailwind CSS. Les exports Solid restent disponibles depuis `@moduix/solid/badge`.

## Composition

`Badge` est un composant de présentation et ne gère aucun état. Le texte direct reste inchangé ; utilisez `BadgeLabel` lorsqu’un libellé contraint doit être tronqué ou lorsqu’il est combiné avec `BadgeDot` ou une icône. Pour un lien ou un bouton sémantique, utilisez `asChild` avec exactement un enfant en React. En Solid, passez une fonction de rendu à `asChild` ; l’enfant rendu conserve ses sémantiques natives.

En Vue, placez exactement un enfant dans le slot par défaut avec `as-child` ; l’enfant conserve ses sémantiques natives. En Svelte, passez un snippet `asChild` et répartissez les propriétés reçues sur exactement un élément.

## Styles

Commencez avec une variante et une taille intégrées. Les variables CSS Modules remplacent le fond, la
bordure et la couleur du texte de toutes les variantes ; pour personnaliser une variante dans toute
l’application, définissez-les sur `[data-slot='badge-root'][data-variant='<variant>']`. La taille, les
espacements, la typographie, l’arrondi et la taille de l’icône et du point utilisent les tokens de
foundation ; modifiez-les avec une classe sur la partie.

Ces variables CSS s’appliquent aux packages CSS Modules ; les packages Tailwind utilisent des utilitaires natifs et les classes du consommateur. Utilisez `className` en React ou `class` en Solid, Vue et Svelte sur les parties exportées. Les hooks `data-slot` et les attributs Ark sont communs aux deux approches de style et aux trois frameworks.

### Points d’accroche CSS

| Partie | `data-slot` |
| --- | --- |
| `Badge` | `badge-root` |
| `BadgeLabel` | `badge-label` |
| `BadgeDot` | `badge-dot` |

- `Badge` expose également `data-scope="badge"` et `data-part="root"`. `BadgeLabel` et `BadgeDot` exposent `data-part="label"` et `data-part="dot"`.
- `Badge` indique la variante sélectionnée dans l’attribut `data-variant` et la taille dans `data-size`.
- Les hôtes focalisables rendus avec `Badge asChild` reçoivent le style de focus visible. Les racines de type lien reçoivent aussi le survol de la variante et le curseur pointeur ; les styles propres aux boutons restent gérés par l’application.
- Les icônes `svg` placées directement comme enfants héritent de `currentColor`, ne capturent pas les événements du pointeur et mesurent 12px sauf si une classe sur l’icône définit une autre taille.
- `Badge` ne dispose ni d’une primitive Ark dédiée ni d’une machine de comportement ; il n’expose donc aucun état géré par Ark ni aucune variable CSS d’exécution.

## Référence de l’API

Accepte aussi les props natives de son élément et `asChild`.

| Prop | Type | Défaut | Description |
| --- | --- | --- | --- |
| `variant` | `'default' \| 'secondary' \| 'destructive' \| 'outline' \| 'ghost' \| 'link'` | `'default'` | Style visuel : `default`, `secondary`, `destructive`, `outline`, `ghost` ou `link`. |
| `size` | `'sm' \| 'md' \| 'lg'` | `'md'` | Taille du badge : `sm`, `md` ou `lg`. |
