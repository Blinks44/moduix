## Choisir le bon composant

Utilisez `Popover` pour un contenu interactif compact qui s’ouvre depuis un déclencheur. Utilisez
`Tooltip` pour les indications courtes et non interactives, et `Dialog` pour les parcours plus
longs qui demandent toute l’attention de l’utilisateur.

## Anatomie

```text
Popover / Popover.Root
├─ Popover.Anchor (facultatif)
├─ Popover.Trigger
│  └─ Popover.Indicator (facultatif)
└─ Sous-arbre de superposition (rendu automatiquement dans un portail)
   └─ Popover.Positioner
      └─ Popover.Content
         ├─ Popover.Arrow
         │  └─ Popover.ArrowTip
         ├─ Popover.Header
         │  ├─ Popover.Title
         │  └─ Popover.Description
         ├─ Popover.Body
         ├─ Popover.Footer
         └─ Popover.CloseTrigger / Popover.CloseIcon

Popover.RootProvider
└─ même arborescence reliée à l’état moduix créé avec usePopover()

Popover.Context
└─ fonction de rendu avec l’état courant de la fenêtre contextuelle
```

| Partie                       | Rôle                                                                  |
| --------------------------- | --------------------------------------------------------------------- |
| `Popover` / `Popover.Root`   | Gère l’état, l’ouverture et la fermeture, le focus, la fermeture lors d’une interaction extérieure et le positionnement. |
| `Popover.RootProvider`       | Relie les parties à l’état créé avec `usePopover()`.                 |
| `Popover.Context`            | Expose l’état courant aux descendants via une fonction de rendu.      |
| `Popover.Anchor`             | Élément de référence facultatif utilisé pour le positionnement.       |
| `Popover.Trigger`            | Bouton qui ouvre ou ferme la fenêtre et peut recevoir une `value`.     |
| `Popover.Indicator`          | Indicateur facultatif de l’état du déclencheur.                       |
| `Popover.Positioner`         | Calque flottant qui expose les variables CSS de positionnement d’Ark. |
| `Popover.Content`            | Surface interactive visible de la fenêtre contextuelle.              |
| `Popover.Arrow` / `ArrowTip` | Flèche positionnée facultative et sa pointe visible.                  |
| `Popover.Title`              | Titre accessible associé au contenu.                                 |
| `Popover.Description`        | Description accessible associée au contenu.                          |
| `Popover.CloseTrigger`       | Déclencheur bas niveau qui ferme la fenêtre.                          |
| `Popover.CloseIcon`          | Aide moduix qui associe le déclencheur de fermeture Ark à un bouton avec icône. |
| `Popover.Header` / `Body`    | Aides de mise en page moduix avec des slots stables.                  |
| `Popover.Footer`             | Aide moduix pour la rangée d’actions avec un slot stable.             |

Dans le code de l’application, utilisez la forme courte `Popover`. `Popover.Root` reste disponible
lorsque le nom explicite de la racine rend la composition plus lisible.

## Composition

Par défaut, la racine rend `Positioner` dans un portail. Définissez `portalled={false}` pour le
conserver dans l’arbre DOM courant, ou passez `portalRef` pour choisir un conteneur de portail
personnalisé. Gardez les parties structurelles explicites afin de pouvoir les styliser et les
configurer séparément.

### Composition recommandée

Dans le cas général, utilisez `Popover` avec `Popover.Trigger`, `Popover.Positioner` et
`Popover.Content`. Configurez le placement, la gestion des collisions et les décalages via la
propriété `positioning` de la racine. Définissez `positioning.sameWidth` lorsque la fenêtre doit
avoir la même largeur que son élément de référence.

### Quand personnaliser la composition

Utilisez `Anchor` lorsqu’un autre élément que le déclencheur doit déterminer la position de la
fenêtre. Utilisez `asChild` avec un seul enfant sémantique lorsque votre propre élément doit rendre
le déclencheur, l’ancre, le contenu ou le déclencheur de fermeture. Définissez `portalled={false}`
lorsqu’une fenêtre contextuelle placée dans une autre superposition doit rester dans son arbre DOM
parent.

La racine active déjà `lazyMount` et `unmountOnExit`. Ne modifiez ces propriétés que si le contenu
doit être monté dès le départ ou rester dans le DOM après sa fermeture.

### Propriétés par défaut

Par défaut, le contenu de la fenêtre est monté à la première ouverture, puis retiré après son
animation de sortie. Définissez `unmountOnExit={false}` pour le conserver après cette première
ouverture. Ne définissez les deux propriétés de cycle de vie sur `false` que si le contenu doit
être rendu dès le départ.

| Propriété                 | Valeur par défaut | Remarques                                                        |
| ------------------------ | ----------------- | ---------------------------------------------------------------- |
| `autoFocus`              | `true`            | Place le focus sur le premier élément pouvant le recevoir à l’ouverture. |
| `closeOnEscape`           | `true`            | Ferme la fenêtre lorsque l’utilisateur appuie sur Échap.          |
| `closeOnInteractOutside`  | `true`            | Ferme la fenêtre après une interaction extérieure.               |
| `lazyMount`               | `true`            | Diffère le montage du contenu jusqu’à la première ouverture.     |
| `modal`                   | `false`           | Piège le focus, verrouille le défilement et masque le contenu extérieur aux technologies d’assistance. |
| `portalled`               | `true`            | Rend le positionneur dans un portail.                            |
| `portalRef`               | `-`               | Cible un conteneur de portail personnalisé.                      |
| `skipAnimationOnMount`    | `false`           | Conserve l’animation d’entrée initiale.                          |
| `unmountOnExit`           | `true`            | Retire le contenu après son animation de sortie.                 |
| `defaultOpen`             | `-`               | État initial ouvert en mode non contrôlé.                         |
| `open`                    | `-`               | État ouvert contrôlé.                                             |
| `ids`                     | `-`               | Identifiants stables du déclencheur, du contenu, du titre, de la description, de l’ancre et du déclencheur de fermeture. |
| `initialFocusEl`          | `-`               | Fonction qui renvoie l’élément à cibler à l’ouverture.            |
| `positioning`             | `-`               | Options de positionnement flottant d’Ark.                        |
| `present`                 | `-`               | Contrôle la présence pour les cycles d’animation pilotés par JavaScript. |

### Comportement

- Les `ref` pointent vers les parties DOM Ark sous-jacentes. `Trigger` et `CloseTrigger` pointent
  vers des boutons, tandis que `Anchor`, `Positioner`, `Content`, `Arrow`, `ArrowTip`, `Title`,
  `Description`, `Indicator`, `Header`, `Body` et `Footer` pointent vers leurs éléments rendus.
- `onOpenChange` reçoit un objet de détails tel que `{ open }`. Lisez le nouvel état dans
  `details.open`, et non dans un argument positionnel.
- Lorsque plusieurs déclencheurs partagent une même fenêtre, attribuez une `value` à chacun et
  utilisez `onTriggerValueChange(details)`. Le déclencheur actif est disponible dans
  `details.value`, et Ark le signale avec `data-current`.
- La propriété `modal` est booléenne. Lorsqu’elle vaut `true`, elle piège le focus, verrouille le
  défilement, bloque les interactions extérieures et masque le contenu extérieur aux technologies
  d’assistance. En mode modal, le Popover est toujours rendu dans un portail, même si `portalled={false}` est
  transmis à la racine.
- Utilisez `Popover.Title` pour donner un nom accessible à la fenêtre et `Popover.Description` pour
  le texte complémentaire. Ark relie ces parties à `Content` via leurs identifiants.
- Créez l’état externe avec `usePopover()` et transmettez-le à `Popover.RootProvider`. N’utilisez
  pas la même instance d’état avec `Popover` ou `Popover.Root`.
- `Popover.Context` et `usePopoverContext()` exposent le même état Ark aux descendants. Utilisez le
  hook lorsqu’un composant enfant a besoin de cet état, ou `Popover.Context` lorsqu’une fonction de
  rendu rend la composition plus claire.
- `Popover.Arrow` rend `ArrowTip` par défaut. Rendez `ArrowTip` explicitement uniquement lorsque
  vous devez le personnaliser.
- `Popover.CloseIcon` utilise `aria-label="Close popover"` par défaut et se place dans l’angle du
  contenu. Passez votre propre nom accessible lorsque l’action nécessite une autre formulation.
- Par défaut, Échap et les interactions extérieures ferment la fenêtre. Les callbacks de fermeture
  reçoivent les objets d’événement Ark sans modification, et chaque comportement peut être désactivé
  séparément.
- Utilisez `ids` lorsque des parties composées séparément ont besoin d’identifiants stables pour le
  déclencheur, le contenu, le titre, la description, l’ancre ou le déclencheur de fermeture.
- Les animations CSS de sortie ciblent l’état de présence Ark `data-state="closed"`. Utilisez
  `present` lorsque le cycle de présence est piloté par JavaScript.
- Lorsque le contenu peut dépasser la hauteur disponible, placez la zone défilable dans
  `Popover.Body`.

### Ciblage des styles

Chaque partie rendue accepte `className`. Les parties Ark conservent `data-scope="popover"` et
leurs valeurs `data-part`, tandis que moduix ajoute `data-slot="popover-*"` aux conteneurs rendus.
`Popover` et `Popover.RootProvider` fournissent l’état, mais ne rendent pas d’éléments DOM. Pour
adapter les styles à l’état, ciblez `data-state="open|closed"`, `data-placement`, `data-side`,
`data-value`, `data-nested`, `data-has-nested`, `data-expanded` et `data-current` lorsque plusieurs
déclencheurs avec une `value` partagent une même fenêtre.

`Positioner` expose `--reference-width`, `--reference-height`, `--available-width`,
`--available-height`, `--x`, `--y`, `--z-index` et `--transform-origin`. `Content` expose
`--layer-index` et `--nested-layer-count`. `Arrow` expose les variables de mesure de la flèche Ark.
Le contenu renvoie les longues chaînes sans séparateur à la ligne et désactive ses animations
lorsque l’utilisateur préfère réduire les animations.
