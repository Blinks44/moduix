## Référence de l’API

Ark UI ne fournit pas de primitive `alert` dédiée. moduix construit `Alert` à partir de la
[fabrique Ark](https://ark-ui.com/docs/guides/composition#the-ark-factory) officielle et suit ses recommandations pour la
[composition](https://ark-ui.com/docs/guides/composition), les [styles](https://ark-ui.com/docs/guides/styling) et les
[refs](https://ark-ui.com/docs/guides/ref).

Les parties publiques sont `Alert.Root`, `Alert.Indicator`, `Alert.Content`, `Alert.Title`,
`Alert.Description` et `Alert.Actions`.

## Choisir le bon composant

Utilisez `Alert` lorsque le message doit rester intégré à la page et occuper sa place dans le flux normal
du document.

- Utilisez **`Alert`** pour les messages de statut, de validation et les messages système dans les formulaires,
  les panneaux ou le contenu de la page.
- Utilisez **`Toast`** pour les notifications temporaires qui apparaissent hors du flux du document et se ferment automatiquement.

## Anatomie

```text
Alert / Alert.Root
├─ Alert.Indicator (optional)
├─ Alert.Title
├─ Alert.Description
└─ Alert.Content (optional)
   ├─ Alert.Title
   ├─ Alert.Description
   ├─ Alert.Actions (optional)
   └─ Extra custom blocks
```

| Partie | Rôle | `data-part` |
| ---------------------- | ------------------------------------------------------------- | ------------- |
| `Alert` / `Alert.Root` | Partie racine. Applique les styles et la sémantique du statut. | `root` |
| `Alert.Indicator` | Partie indicateur facultative. Uniformise la taille des icônes SVG qu’elle contient. | `indicator` |
| `Alert.Content` | Conteneur de colonne facultatif qui regroupe le texte et les actions. | `content` |
| `Alert.Title` | Partie titre de l’alerte. Rend un `p` par défaut. | `title` |
| `Alert.Description` | Partie contenant le texte complémentaire. | `description` |
| `Alert.Actions` | Ligne d’actions facultative avec retour à la ligne dans `Content`. | `actions` |

## Composition

### Composition recommandée

Pour le cas courant d’un message intégré à la page, utilisez directement `Alert`, `Alert.Title` et `Alert.Description`.

Utilisez `status` pour indiquer le type de message : `info`, `success`, `warning` ou `error`.

Ajoutez `Alert.Indicator` lorsque l’alerte a besoin d’un repère visuel explicite. Le composant n’impose
volontairement aucune propriété spéciale ni aucun ensemble de slots pour les actions.

### Quand créer une composition personnalisée

Ajoutez `Alert.Content` lorsque le titre, la description et les contrôles supplémentaires doivent rester regroupés
dans une même colonne à côté de l’indicateur. Utilisez `Alert.Actions` pour une ligne d’actions avec retour à la ligne
dans cette colonne. Si la structure du document exige un autre niveau de titre, utilisez `Alert.Title asChild`.

Par exemple :

```tsx
<Alert.Title asChild>
  <h2>Billing issue</h2>
</Alert.Title>
```

### Propriétés par défaut

| Propriété | Par défaut | Valeurs et remarques |
| -------- | --------- | --------------------------------------------------------------- |
| `status` | `info` | `info`, `success`, `warning`, `error` |
| `role` | Automatique | `role="status"` par défaut, `role="alert"` pour `status="error"` |

### Comportement

- `Alert.Root` est par défaut `role="status"` et passe à `role="alert"` pour `status="error"`.
- Ces rôles créent des régions dynamiques avec des priorités d’annonce différentes. `status` annonce les mises à jour
  sans interrompre l’utilisateur, tandis que `alert` les annonce immédiatement. Si le message doit être annoncé,
  montez l’alerte avant de mettre son contenu à jour. Un contenu déjà présent au chargement de la page peut ne pas être annoncé.
- Remplacez `role` lorsque l’alerte est un encart statique et non un message signalant une mise à jour. Pour une
  information statique complémentaire, utilisez `role="note"`.
- `Alert.Indicator` est par défaut `aria-hidden="true"`.
- `Alert.Title` rend un `p` par défaut et utilise `asChild` d’Ark lorsque vous avez besoin d’un autre élément de titre.
- La signification essentielle doit rester dans le titre ou la description, car l'indicateur reste
`aria-hidden`.
- `Alert.Content` est facultatif. Utilisez-le lorsque le titre, la description et les contrôles supplémentaires doivent en partager un
colonne de contenu à côté de l’indicateur.
- `Alert.Actions` est facultatif. Utilisez-le lorsque des boutons ou des liens doivent partager l'action encapsulée par défaut
style de ligne.
- Le composant se charge uniquement de l’affichage. Il ne gère ni l’état de fermeture, ni le focus, ni le
  comportement clavier des actions que vous placez à l’intérieur.

## Styles

Utilisez `className` sur la racine ou sur les différentes parties pour appliquer des styles locaux. Remplacez les variables
CSS `--moduix-alert-*` sur la racine lorsque l’alerte nécessite un thème local.

Les variables `--moduix-alert-bg`, `--moduix-alert-border-color`, `--moduix-alert-color` et
`--moduix-alert-indicator-color` s’appliquent à tous les statuts. Utilisez les variables correspondantes
`--moduix-alert-<status>-*` lorsqu’un seul statut doit changer.

Les statuts intégrés lisent également les jetons de palette partagée :

| Statut | Jeton partagé | Par défaut |
| --------- | ---------------------------- | ---------------------------- |
| `info` | `--moduix-color-card` | carte du thème |
| `success` | `--moduix-color-success` | `oklch(0.627 0.194 149.214)` |
| `warning` | `--moduix-color-warning` | `oklch(0.795 0.184 86.047)` |
| `error` | `--moduix-color-destructive` | thème destructeur |

### Points d’accroche CSS

- Sélecteurs `data-slot` stables : `alert-root`, `alert-indicator`, `alert-content`, `alert-title`,
`alert-description` et `alert-actions`
- Sélecteurs de style Ark : `data-scope="alert"` avec `data-part="root"`, `indicator`, `content`,
`title`, `description` ou `actions`
- `Alert.Root` écrit l'état sélectionné dans `data-status`
