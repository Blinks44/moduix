# Tree Collection

## API

<PrimitiveReference href="https://ark-ui.com/docs/collections/tree-collection" />

Une collection arborescente transforme les données hiérarchiques en une structure cohérente pour
`TreeView` et vos interfaces arborescentes. Elle permet de rechercher des nœuds par valeur, d'examiner
leurs relations avec leurs parents et leurs descendants, d'utiliser des chemins d'index, de parcourir
l'arbre et d'appliquer des mises à jour immuables.

```tsx
import { createFileTreeCollection, createTreeCollection } from '@moduix/react/tree-view';
```

## Créer une collection

La structure par défaut utilise les propriétés `value`, `label`, `children` et, éventuellement, `disabled` :

```tsx
const tree = createTreeCollection({
  rootNode: {
    value: 'root',
    label: 'Project',
    children: [
      {
        value: 'src',
        label: 'src',
        children: [
          { value: 'button', label: 'Button.tsx' },
          { value: 'input', label: 'Input.tsx' },
        ],
      },
      { value: 'readme', label: 'README.md' },
    ],
  },
});
```

Le nœud racine sert de conteneur. Il n'est donc pas inclus dans `getValues()`. Passez la collection
directement à `TreeView`, puis affichez les nœuds à partir de `collection.rootNode.children`.

## Tree View

La collection stocke la hiérarchie. `TreeView` gère l'ouverture des branches, le focus, la navigation
au clavier et la sélection. Affichez chaque branche récursivement à partir du nœud et du chemin d'index
fournis par la collection.

## Nœuds personnalisés

Si vos nœuds utilisent d'autres noms de champs, indiquez à la collection comment les lire :

```tsx
type NavigationNode = {
  id: string;
  name: string;
  items?: NavigationNode[];
  unavailable?: boolean;
};

const navigation: NavigationNode = {
  id: 'root',
  name: 'Documentation',
  items: [
    {
      id: 'guides',
      name: 'Guides',
      items: [{ id: 'getting-started', name: 'Getting started' }],
    },
    { id: 'components', name: 'Components' },
  ],
};

const tree = createTreeCollection<NavigationNode>({
  rootNode: navigation,
  nodeToValue: (node) => node.id,
  nodeToString: (node) => node.name,
  nodeToChildren: (node) => node.items ?? [],
  nodeToChildrenCount: (node) => node.items?.length,
  isNodeDisabled: (node) => node.unavailable ?? false,
});
```

| Option                | Rôle                                                             |
| --------------------- | ---------------------------------------------------------------- |
| `rootNode`            | Conteneur racine de toute la hiérarchie.                         |
| `nodeToValue`         | Renvoie une valeur de chaîne stable pour un nœud.                |
| `nodeToString`        | Renvoie le texte affiché et utilisé pour la recherche.           |
| `nodeToChildren`      | Renvoie les nœuds enfants.                                       |
| `nodeToChildrenCount` | Renvoie le nombre connu d'enfants, y compris pour un chargement différé. |
| `isNodeDisabled`      | Indique si le nœud est désactivé.                                |

## Rechercher un nœud

Utilisez les valeurs pour retrouver les nœuds et les chemins d'index pour repérer leur position. Un
chemin d'index décrit la position numérique d'un nœud à chaque niveau de l'arborescence :

```tsx
const path = tree.getIndexPath('input')!; // [0, 1]
tree.at(path); // Input.tsx node
tree.getValue(path); // 'input'
tree.getValuePath(path); // ['src', 'input']
tree.getDepth('input'); // 2
```

| API | Résultat |
| -------------------------------- | ------------------------------------------------ |
| `findNode(value)` | Premier nœud avec la valeur. |
| `findNodes(values)` | Nœuds correspondant à plusieurs valeurs. |
| `getIndexPath(valueOrValuePath)` | Chemin numérique pour une valeur ou un chemin de valeur explicite. |
| `at(indexPath)` | Nœud correspondant à un chemin d'index. |
| `getValue(indexPath)` | Valeur correspondant à un chemin d'index. |
| `getValuePath(indexPath)` | Valeurs des ancêtres suivies de la valeur cible. |
| `getDepth(value)` | Profondeur du nœud en dessous de la racine. |
| `getValues(rootNode?)` | Toutes les valeurs descendantes dans l'ordre de parcours. |
| `getNodeChildren(node)` | Nœuds enfants normalisés. |
| `getNodeChildrenCount(node)` | Nombre connu d'enfants, ou `undefined`. |
| `getNodeValue(node)` | Valeur de nœud normalisée. |
| `stringifyNode(node)` | Texte de nœud normalisé. |
| `stringify(value)` | Texte du nœud pour une valeur, ou `null` si le nœud est introuvable. |
| `getNodeDisabled(node)` | État désactivé normalisé. |
| `isRootNode(node)` | Indique si le nœud est la racine de la collection. |
| `isSameNode(node, other)` | Indique si deux nœuds ont la même valeur. |

`sort(values)` classe les valeurs selon leur position dans l'arborescence. `isEqual(other)` compare les
collections et `toJSON()` renvoie les valeurs de la collection.

## Navigation

Déplacez-vous entre les nœuds et examinez leurs relations avec leurs parents, ancêtres et descendants :

```tsx
tree.getFirstNode();
tree.getLastNode();
tree.getNextNode('button');
tree.getPreviousNode('input');

tree.getParentNode('input'); // src node
tree.getParentNodes('input'); // ancestor nodes
tree.getDescendantNodes('src'); // Button.tsx and Input.tsx nodes
tree.getDescendantValues('src'); // ['button', 'input']
```

`getFirstNode`, `getLastNode`, `getNextNode` et `getPreviousNode` acceptent un objet d'options avec une
fonction `skip`. Cette fonction exclut certains nœuds du parcours.

Les méthodes relatives aux nœuds frères utilisent les chemins d'index :

```tsx
const path = tree.getIndexPath('button')!;

tree.getNextSibling(path);
tree.getPreviousSibling(path);
tree.getSiblingNodes(path);
```

Utilisez `contains(parentPath, valuePath)` pour vérifier si un chemin d'index en contient un autre.
`getDescendantNodes` et `getDescendantValues` acceptent `{ withBranch: true }` pour inclure les
nœuds de branche avec les feuilles.

## Parcours

Examinez les branches, aplatissez l'arbre ou visitez chaque nœud :

```tsx
const src = tree.findNode('src');

if (src) tree.isBranchNode(src);
tree.getBranchValues();
tree.flatten();
```

`flatten()` renvoie les nœuds avec les métadonnées `_index`, `_parent` et `_children`, utiles pour un
affichage virtualisé ou à plat.

Utilisez `visit` lorsque chaque nœud doit être traité :

```tsx
tree.visit({
  onEnter(node, indexPath) {
    console.log(tree.getNodeValue(node), indexPath.length);

    if (tree.getNodeValue(node) === 'src') {
      return 'skip';
    }
  },
});
```

## Filtrage

`filter` renvoie une nouvelle arborescence contenant les nœuds correspondants tout en conservant la
hiérarchie nécessaire pour les atteindre :

```tsx
const filteredTree = tree.filter((node) =>
  tree.stringifyNode(node).toLocaleLowerCase().includes('input'),
);
```

Utilisez la collection renvoyée pour le rendu. L'arbre d'origine est inchangé.

## Mises à jour

Chaque modification est immuable : les méthodes renvoient une nouvelle `TreeCollection` sans modifier la
collection d'origine. Dans les exemples ci-dessous, chaque opération part de `tree`. Pour enchaîner les
modifications, utilisez la collection renvoyée par l'opération précédente :

```tsx
const srcPath = tree.getIndexPath('src')!;
const buttonPath = tree.getIndexPath('button')!;
const readmePath = tree.getIndexPath('readme')!;

const withFile = tree.insertAfter(buttonPath, [{ value: 'select', label: 'Select.tsx' }]);

const withoutReadme = tree.remove([readmePath]);
const renamed = tree.replace(buttonPath, {
  value: 'button',
  label: 'Button.new.tsx',
});
const moved = tree.move([readmePath], srcPath);
```

Les chemins d'index décrivent des positions dans une version précise de la collection. Après une
insertion, une suppression, une réorganisation ou un déplacement de nœuds, supprimez les chemins
mémorisés et recalculez-les à partir de la collection renvoyée avant l'opération suivante. Stockez des
valeurs de nœud stables dans l'état de l'application plutôt que des chemins numériques.

`insertBefore` et `insertAfter` peuvent renvoyer `undefined` lorsque le chemin cible n'est pas valide.
Validez les chemins provenant de données dynamiques avant d'appeler ces méthodes.

| API | Fonctionnement |
| --------------------------- | -------------------------------------------- |
| `copy(rootNode)` | Crée une collection à partir d'une racine de remplacement. |
| `replace(indexPath, node)` | Remplace un nœud. |
| `remove(indexPaths)` | Supprime un ou plusieurs sous-arbres. |
| `insertBefore(path, nodes)` | Insère des nœuds frères avant un nœud. |
| `insertAfter(path, nodes)` | Insère des nœuds frères après un nœud. |
| `move(fromPaths, toPath)` | Déplace des sous-arbres vers un autre emplacement. |
| `filter(predicate)` | Renvoie une arborescence filtrée. |

## Arborescence de fichiers

Utilisez `createFileTreeCollection` lorsque vos données se présentent déjà sous la forme d'une liste de chemins :

```tsx
const files = createFileTreeCollection([
  'src/components/Button.tsx',
  'src/components/Input.tsx',
  'src/utils/format.ts',
  'README.md',
]);

files.getBranchValues(); // ['src', 'components', 'utils']
```

Pour découvrir la composition complète de `TreeView`, l'ouverture, la sélection, le chargement différé
et les nœuds récursifs, consultez [Tree View](/docs/tree-view). Pour les nœuds distants, consultez son
exemple de chargement asynchrone et mettez à jour la collection uniquement après une réponse réussie.
