# Tree Collection

Une collection arborescente stocke des données hiérarchiques pour `TreeView` et vos interfaces
arborescentes. Elle ne rend aucune interface et ne gère ni la sélection, ni le focus, ni la navigation
au clavier. Utilisez-la pour créer une hiérarchie typée, interroger les relations entre les nœuds,
parcourir et filtrer l'arbre, puis produire des mises à jour immuables.

`children` et, facultativement, `disabled`. Le nœud racine sert de conteneur et n'est pas inclus dans
`getValues()`.

`collection.rootNode.children` et transmettez à chaque nœud sa position numérique comme `indexPath`.

| `rootNode`            | Conteneur racine de toute la hiérarchie.                         |

## Requêtes et navigation

Un `indexPath` contient la position numérique d'un nœud à chaque niveau sous la racine. Les valeurs
sont des identifiants stables : stockez-les dans l'état de l'application et recalculez les chemins
d'index lorsqu'une opération en a besoin.

```tsx
const treePath = collection.getIndexPath('src/components/Tree.tsx')!; // [0, 1, 1]

collection.findNode('src');
collection.findNodes(['src', 'public']);
collection.at(treePath);
collection.getValue(treePath); // 'src/components/Tree.tsx'
collection.getValuePath(treePath); // ['src', 'src/components', 'src/components/Tree.tsx']
collection.getDepth('src/components/Tree.tsx'); // 3
collection.getValues(); // descendant values in traversal order
```

| API                              | Résultat                                           |
| -------------------------------- | -------------------------------------------------- |
| `findNode(value, rootNode?)`     | Premier nœud correspondant, ou `undefined`.       |
| `findNodes(values, rootNode?)`   | Nœuds correspondant à plusieurs valeurs.          |
| `getIndexPath(valueOrValuePath)` | Chemin numérique d'une valeur ou d'un chemin explicite. |
| `at(indexPath)`                  | Nœud du chemin d'index, ou `undefined`.            |
| `getValue(indexPath)`             | Valeur du chemin d'index, ou `undefined`.         |
| `getValuePath(indexPath)`         | Valeurs des ancêtres suivies de la valeur cible.  |
| `getDepth(value)`                 | Profondeur du nœud sous la racine.                |
| `getValues(rootNode?)`            | Valeurs descendantes dans l'ordre du parcours.    |

Pour une structure personnalisée, utilisez les accesseurs normalisés :

| API                          | Résultat                                          |
| ---------------------------- | ------------------------------------------------- |
| `getNodeChildren(node)`      | Nœuds enfants.                                    |
| `getNodeChildrenCount(node)` | Nombre connu d'enfants, ou `undefined`.           |
| `getNodeValue(node)`         | Valeur du nœud.                                   |
| `stringifyNode(node)`        | Texte d'affichage du nœud.                        |
| `stringify(value)`           | Texte d'une valeur, ou `null`.                    |
| `getNodeDisabled(node)`      | État désactivé.                                   |
| `isRootNode(node)`           | Indique si le nœud est la racine de la collection. |
| `isSameNode(node, other)`    | Indique si deux nœuds ont la même valeur.         |

Parcourez l'arbre dans l'ordre de parcours ou parmi les nœuds frères :

```tsx
collection.getFirstNode();
collection.getLastNode();
collection.getNextNode('src');
collection.getPreviousNode('README.md');

collection.getParentNode('src/components/Tree.tsx');
collection.getParentNodes('src/components/Tree.tsx');
collection.getDescendantNodes('src');
collection.getDescendantValues('src');

collection.getNextSibling(treePath);
collection.getPreviousSibling(treePath);
collection.getSiblingNodes(treePath);
collection.contains(collection.getIndexPath('src')!, treePath);
```

`getFirstNode`, `getLastNode`, `getNextNode` et `getPreviousNode` acceptent `{ skip }`. La fonction
reçoit `{ value, node, indexPath }` et exclut le nœud lorsqu'elle renvoie `true`. Passez
`{ withBranch: true }` à `getDescendantNodes` ou `getDescendantValues` pour inclure les nœuds de
branche.

`sort(values)` ordonne les valeurs selon leur position dans l'arborescence. `isEqual(other)` compare
les collections et `toJSON()` renvoie les valeurs descendantes.

## Parcours et filtrage

Utilisez `isBranchNode` et `getBranchValues` pour inspecter les branches. `getBranchValues` accepte
également un filtre `depth` et la même fonction `skip` que les méthodes de navigation.

```tsx
const src = collection.findNode('src');

if (src) collection.isBranchNode(src);
collection.getBranchValues();

const flatNodes = collection.flatten();
// Each result keeps the original node fields and adds _index, _parent, and _children.

collection.visit({
  onEnter(node, indexPath) {
    console.log(collection.getNodeValue(node), indexPath.length);

    if (collection.getNodeValue(node) === 'src') return 'skip';
  },
});
```

`visit` appelle `onEnter` pour chaque nœud. Renvoyez `'skip'` pour ignorer les descendants d'une
branche ou `'stop'` pour terminer le parcours. `filter(predicate)` renvoie une nouvelle collection,
conserve la hiérarchie nécessaire pour atteindre les nœuds correspondants et transmet `(node,
indexPath)` à la fonction de prédicat :

```tsx
const filteredTree = collection.filter((node) =>
  collection.stringifyNode(node).toLocaleLowerCase().includes('tree'),
);
```

## Mises à jour immuables

Les méthodes de mise à jour renvoient une nouvelle collection sans modifier l'originale. Les chemins
d'index appartiennent à une version précise de la collection. Après une insertion, suppression,
modification ou déplacement, recalculez les chemins depuis la collection renvoyée au lieu de réutiliser
les anciens chemins numériques.

```tsx
const buttonPath = collection.getIndexPath('src/components/Button.tsx')!;
const readmePath = collection.getIndexPath('README.md')!;
const srcPath = collection.getIndexPath('src')!;

const withFile = collection.insertAfter(buttonPath, [
  { value: 'src/components/Select.tsx', label: 'Select.tsx' },
]);
const withoutReadme = collection.remove([readmePath]);
const renamed = collection.replace(buttonPath, {
  value: 'src/components/Button.new.tsx',
  label: 'Button.new.tsx',
});
const moved = collection.move([readmePath], srcPath);
```

`insertBefore` et `insertAfter` renvoient `undefined` lorsque le chemin cible est invalide. Validez
les chemins issus de données dynamiques avant d'appeler ces méthodes.

| API                         | Fonctionnement                              |
| --------------------------- | ------------------------------------------- |
| `copy(rootNode)`            | Crée une collection à partir d'une nouvelle racine. |
| `replace(indexPath, node)`  | Remplace un nœud.                            |
| `remove(indexPaths)`        | Supprime un ou plusieurs sous-arbres.        |
| `insertBefore(path, nodes)` | Insère des nœuds frères avant un nœud.       |
| `insertAfter(path, nodes)`  | Insère des nœuds frères après un nœud.       |
| `move(fromPaths, toPath)`   | Déplace des sous-arbres.                     |
| `filter(predicate)`         | Renvoie une arborescence filtrée.            |

Lorsque la collection est rendue par `TreeView`, stockez le résultat de la mise à jour dans l'état
qui possède l'arbre et rendez son nouveau `rootNode`.

## Intégration et accessibilité

La collection gère uniquement la hiérarchie. Utilisez `TreeView` pour la sémantique d’arbre, le
focus, la navigation au clavier, l’ouverture et la sélection. Un rendu personnalisé doit fournir
lui-même ces comportements. Conservez des valeurs de nœud stables dans l’état de l’application et
recalculez les chemins d’index depuis la collection courante après une mise à jour immuable.
