## Choisir le bon composant

Utilisez `Fieldset` lorsque plusieurs contrôles associés doivent former un groupe avec une légende commune, par exemple
pour des coordonnées ou des préférences de notification. Utilisez `Field` lorsqu’un seul contrôle a besoin de son propre
libellé, texte d’aide et message de validation.

## Anatomie

```text
Fieldset.Root | Fieldset.RootProvider
├─ Fieldset.Legend
├─ grouped controls
├─ Fieldset.HelperText (optional)
└─ Fieldset.ErrorText (optional)
```

| Partie                        | Rôle                                                                                              |
| ----------------------------- | ------------------------------------------------------------------------------------------------- |
| `Fieldset` / `Fieldset.Root`  | Crée l’état et rend un élément `fieldset` natif.                                                  |
| `Fieldset.RootProvider`       | Rend un `fieldset` natif avec l’état créé par `useFieldset`.                                      |
| `Fieldset.Context`            | Expose l’état courant du groupe aux descendants sans rendre d’élément DOM supplémentaire.       |
| `Fieldset.Legend`             | Élément `legend` natif qui fournit le nom accessible du groupe.                                   |
| `Fieldset.HelperText`         | Description associée à la racine via `aria-describedby`.                                         |
| `Fieldset.ErrorText`          | Message de validation annoncé via `aria-live="polite"` et rendu uniquement quand `invalid` vaut `true`. |

## Composition

Gardez une seule `Fieldset.Legend` visible dans la racine, puis placez les contrôles associés et leurs parties `Field` dans
la même composition. Définissez `invalid` sur la racine pour une erreur de groupe et sur les composants `Field` imbriqués
lorsque des contrôles individuels ont besoin de leur propre état de validation. Un fieldset désactivé transmet son état aux
contrôles natifs et aux descendants compatibles avec Ark.

Utilisez `useFieldset` du package correspondant (`@moduix/react` ou `@moduix/solid`) avec `Fieldset.RootProvider` lorsque
l’état doit être créé en dehors de l’arbre rendu ou partagé avec des contrôles voisins. Utilisez `Fieldset.Context` ou
`useFieldsetContext()` pour lire cet état dans un descendant, et ne rendez pas `Fieldset.Root` avec `Fieldset.RootProvider`
pour la même instance. Utilisez `asChild` avec un seul enfant sémantique pour remplacer l’élément rendu par une partie.

### Points d’accroche CSS

Chaque partie DOM possède les attributs Ark `data-scope="fieldset"` et `data-part` correspondant à l’anatomie. La racine et
la légende exposent `data-disabled` et `data-invalid` ; moduix ajoute également les attributs `data-slot="fieldset-*"`.
Utilisez `className` en React ou `class` en Solid pour les ajustements locaux. Les packages CSS Modules utilisent les
variables `--moduix-fieldset-*` pour personnaliser le thème, tandis que les packages Tailwind utilisent des classes
utilitaires et les classes de l’application.
