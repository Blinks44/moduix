# Démarrage rapide

moduix offre deux façons équivalentes de l’intégrer à un projet de production :

- Installez `@moduix/react` et gérez ses mises à jour avec votre gestionnaire de paquets.
- Ajoutez les composants avec la CLI shadcn afin de conserver leur code source, leurs styles et leurs utilitaires
  dans votre dépôt.

Les deux méthodes donnent accès aux mêmes composants, aux contrats d’Ark UI et au même système de tokens. Choisissez
selon que vous préférez une dépendance gérée ou garder le contrôle complet du code dans votre dépôt.

Vous avez besoin de React 18 ou 19, de `@ark-ui/react` et d'un framework ou bundler capable d'importer du CSS depuis
des paquets npm. Les composants interactifs doivent être rendus dans une limite client lorsque le framework l'exige.

L’accessibilité est une responsabilité partagée : Ark UI gère le comportement des primitives, moduix les contrats des
wrappers et les valeurs par défaut, et l’application les libellés, le contenu, les messages de validation et le
parcours utilisateur.

## Choisir votre framework

Le paquet et le registre fonctionnent de la même façon avec toutes les piles React. Choisissez votre framework pour
savoir où importer les styles, comment définir l’alias de code source et où placer la frontière client ou SSR.

## Installer comme paquet

Choisissez cette méthode si vous préférez laisser moduix dans `node_modules` et le mettre à jour avec votre
gestionnaire de paquets.

### 1. Installer le paquet

Les composants, le CSS et les design tokens sont livrés ensemble. React 18 ou 19 et Ark UI sont des dépendances de
pair :

<PackageManagerTabs command="install @moduix/react @ark-ui/react" />

`react`, `react-dom` et `@ark-ui/react` restent des dépendances de votre application : moduix ne duplique donc ni le
runtime React ni celui des primitives.

### 2. Ajouter les styles

Importez une seule fois la feuille de style de base requise dans le point d'entrée de votre application :

```tsx
import '@moduix/react/style.css';
```

Cette feuille est indispensable : elle définit les design tokens partagés et la couche de base dont dépendent les
styles des composants. Les styles propres à chaque composant restent chargés avec les composants importés.

Tous les design tokens moduix utilisent l'espace de noms `--moduix-*`. Votre projet peut conserver ses propres noms
de tokens et les associer sélectivement dans une feuille de style chargée après `style.css` ; consultez
[Tokens](/docs/tokens).

Si vous souhaitez le reset facultatif, importez-le explicitement avant la feuille de style principale :

```tsx
import '@moduix/react/reset.css';
import '@moduix/react/style.css';
```

Ainsi, `style.css` ne contient que le socle global et le CSS des composants inutilisés peut rester hors du bundle.

Pour un point de départ visuel sélectionné, importez un préréglage facultatif après `style.css` ; consultez
[Thèmes](/docs/themes).

### 3. Utiliser un composant

Importez chaque composant depuis son sous-chemin `@moduix/react/*` :

```tsx
import { Button } from '@moduix/react/button';
import { Dialog } from '@moduix/react/dialog';

export function Example() {
  return (
    <Dialog>
      <Dialog.Trigger asChild>
        <Button>Open dialog</Button>
      </Dialog.Trigger>
      <Dialog.Backdrop />
      <Dialog.Positioner>
        <Dialog.Content>
          <Dialog.Header>
            <Dialog.Title>Project settings</Dialog.Title>
            <Dialog.Description>Review the settings for this project.</Dialog.Description>
          </Dialog.Header>
          <Dialog.Footer>
            <Dialog.CloseTrigger asChild>
              <Button variant="outline">Close</Button>
            </Dialog.CloseTrigger>
          </Dialog.Footer>
        </Dialog.Content>
      </Dialog.Positioner>
    </Dialog>
  );
}
```

La configuration est prête lorsque le bouton adopte les styles moduix, ouvre la boîte de dialogue au clavier comme
à la souris et récupère le focus après sa fermeture.

## Installer avec la CLI shadcn

Choisissez cette méthode si vous voulez conserver le code source et les styles des composants dans votre dépôt. La
CLI shadcn lit le registre moduix, résout les dépendances et écrit les fichiers aux emplacements définis par vos alias.

### 1. Configurer shadcn

Créez `components.json` à la racine de votre projet avec la configuration du registre moduix :

```json title="components.json"
{
  "$schema": "https://ui.shadcn.com/schema.json",
  "style": "new-york",
  "rsc": false,
  "tsx": true,
  "tailwind": {
    "config": "",
    "css": "",
    "baseColor": "",
    "cssVariables": true,
    "prefix": ""
  },
  "aliases": {
    "components": "@/components",
    "ui": "@/components/ui",
    "lib": "@/lib",
    "hooks": "@/hooks",
    "utils": "@/lib/utils"
  },
  "registries": {
    "@moduix-react": "https://moduix.dev/r/react/{name}.json"
  }
}
```

L'objet `tailwind` est requis par le schéma de configuration shadcn, mais moduix n'utilise pas Tailwind et ne
nécessite pas son installation. Ses chemins vides et `baseColor` empêchent la CLI de rechercher des fichiers
Tailwind ou de télécharger une palette de couleurs shadcn.

Conservez `rsc: false` pour les applications rendues côté client. Dans une application React Server Components,
définissez `rsc: true` : la CLI shadcn conserve les directives `use client` déjà présentes dans les fichiers source du
registre. Elle ne détermine pas elle-même quels composants en ont besoin.

Assurez-vous que votre projet résout l'alias `@/*` vers son répertoire source. Une structure classique avec `src`
utilise :

```json
{
  "compilerOptions": {
    "paths": {
      "@/*": ["./src/*"]
    }
  }
}
```

La CLI `shadcn` dispose ainsi des alias et de l’URL du registre pour écrire les fichiers générés dans votre
arborescence source plutôt que dans un dossier `@` littéral. La [configuration de framework](#choisir-votre-framework)
indique si le même alias doit aussi être déclaré dans le bundler et quel répertoire source utiliser.

### 2. Examiner un élément du registre

Avant d'écrire des fichiers source, examinez la configuration actuelle et l'élément du registre :

```bash
npx shadcn@latest info --json
npx shadcn@latest search @moduix-react --query "confirmation dialog"
npx shadcn@latest view @moduix-react/dialog
npx shadcn@latest add @moduix-react/dialog --dry-run
```

Recherchez l’interface dont vous avez besoin plutôt qu’un nom de bibliothèque familier. Le registre contient des
composants, des thèmes et leurs dépendances déclarées. Le même parcours via shadcn MCP est décrit dans le
[guide AI](/docs/ai).

### 3. Ajouter un composant

Ajoutez des éléments du registre moduix :

<PackageManagerTabs command="shadcn@latest add @moduix-react/button" dlx />

Exécutez la même commande avec le nom d'un autre élément du registre, par exemple `@moduix-react/accordion`, pour
ajouter d'autres composants.

Le registre installe uniquement les fichiers de runtime partagés nécessaires aux composants. Il n’ajoute pas de police
globale ; la typographie continue donc d’être héritée de votre application.

### 4. Importer les styles générés

Importez la feuille de style de base générée depuis les fichiers que `shadcn` a ajoutés à votre projet :

```tsx
import '@/lib/moduix/styles/style.css';
```

Si vous souhaitez le reset facultatif avec cette méthode, installez son élément de registre distinct :

```bash
npx shadcn@latest add @moduix-react/reset
```

Importez-le ensuite avant la feuille de style principale :

```tsx
import '@/lib/moduix/styles/reset.css';
import '@/lib/moduix/styles/style.css';
```

Les exemples ci-dessous supposent `@/components` et `@/lib`. Si votre projet utilise des alias différents, mettez à
jour `components.json` et importez les fichiers générés depuis les chemins correspondants.

### 5. Utiliser le composant généré

Importez les composants depuis les fichiers générés dans votre propre projet :

```tsx
import { Button } from '@/components/moduix/button';
import { Accordion } from '@/components/moduix/accordion';
```

La plupart des composants se composent de parties nommées. Cette structure préserve leur comportement accessible tout
en vous laissant maîtriser le balisage, la mise en page et les styles dans l’application.

Le flux de possession s'inspire de [shadcn/ui](https://ui.shadcn.com/), tandis que l'anatomie des composants et le
comportement d'interaction restent alignés sur [Ark UI](https://ark-ui.com/).

## Configurer la superposition des portails

Cette configuration s’applique aux deux méthodes d’installation. `Dialog`, `Popover`, `Menu`, `Select` et d’autres
composants affichent leurs superpositions dans des portails. Isolez la racine de l’application pour que les fonds et
fenêtres contextuelles restent au-dessus de la page sans entrer en conflit avec des valeurs locales de `z-index`.

```tsx title="layout.tsx"
<body>
  <div className="root">{children}</div>
</body>
```

```css title="styles.css"
.root {
  isolation: isolate;
}
```

Si votre application prend en charge Safari sur iOS 26, testez une modale défilante avec l’interface du navigateur.
Si du contenu apparaît sous le fond, ne changez pas le positionnement du `body` : un fond positionné absolument pourra
alors couvrir toute la zone visible.

```css title="styles.css"
body {
  position: relative;
}
```

## Styles

moduix s’adapte à la méthode de style déjà utilisée dans votre projet :

- CSS natif avec sélecteurs globaux, couches de cascade et variables CSS.
- CSS Modules via `className` et les props de classe des slots de composants.
- Classes utilitaires Tailwind CSS pour la mise en page et le style ponctuel.
- Bibliothèques CSS-in-JS qui attachent des classes ou transmettent des styles limités à leurs wrappers.

Par défaut, les contrôles principaux utilisent `--moduix-size-md: 36px` et les lignes de listes contextuelles
`--moduix-size-sm: 32px`. Les composants partagent cette échelle : modifier ces tokens met donc à jour ensemble les
champs, déclencheurs, boutons et éléments semblables à des éléments de menu.

Les pages de composants répertorient leurs variables CSS publiques et leurs hooks de style. Pour les changements à
l’échelle du système, utilisez les tokens sémantiques partagés ; réservez les variables de composants aux exceptions
ciblées. Consultez [Tokens](/docs/tokens) pour la hiérarchie complète et [Animations](/docs/animations) pour les
recettes de mouvement.

## Résoudre les problèmes

| Symptôme | Vérification |
| --- | --- |
| Les composants s'affichent sans styles | Importez une fois le bon point d'entrée `style.css`, après tout reset facultatif. |
| Un import de code source possédé est introuvable | Vérifiez l'alias `@/*` dans TypeScript et votre bundler, puis vérifiez `components.json`. |
| Une fenêtre contextuelle apparaît sous le contenu de la page | Ajoutez `isolation: isolate` à la racine de l'application et évitez les `z-index` globaux sans rapport. |
| Le rendu serveur signale des API client | Conservez les composants interactifs sous une limite client dans les frameworks qui l'exigent. |
