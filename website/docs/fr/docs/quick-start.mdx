# Démarrage rapide

moduix propose deux façons équivalentes de l’utiliser dans une application :

- Installez le paquet moduix correspondant à votre framework et à votre mode de style pour recevoir les mises à jour via votre gestionnaire de paquets.
- Ajoutez les composants avec la CLI shadcn pour conserver leur code source, leurs styles et leurs utilitaires dans
  votre dépôt.

Les deux méthodes utilisent les mêmes implémentations natives pour chaque framework, les mêmes
contrats alignés sur Ark UI et le même système de tokens. Choisissez selon l’endroit où vous voulez
conserver le code source et la manière dont vous souhaitez le mettre à jour.

Partez d’une application React ou Solid existante. Si vous choisissez un paquet ou un registre
Tailwind, Tailwind CSS v4 doit déjà être configuré dans l’application.

Pour commencer, choisissez React 18 ou 19 avec `@ark-ui/react`, ou Solid 1.9 ou une version 1.x
ultérieure avec `@ark-ui/solid`. Votre framework ou bundler doit pouvoir importer du CSS depuis les paquets installés. Lorsque le framework
l’exige, placez les composants interactifs dans une frontière client.

L’accessibilité est une responsabilité partagée : Ark UI fournit le comportement des primitives, moduix définit les
contrats et les valeurs par défaut des composants, et votre application fournit les libellés, le contenu, les messages de
validation et le parcours utilisateur.

## Choisir votre framework

Choisissez le paquet et le registre natifs de votre framework. Les catalogues de composants React et
Solid sont disponibles avec les deux approches de style. CSS Modules nécessite soit la réinitialisation
de moduix, soit une réinitialisation équivalente fournie par l’application, tandis que Tailwind utilise
Preflight. Les adaptateurs Vue et Svelte sont prévus, mais ne sont pas encore disponibles à l’installation.

| Framework | CSS Modules | Tailwind CSS |
| --- | --- | --- |
| React | `@moduix/react` / `@moduix-react` | `@moduix/react-tailwind` / `@moduix-react-tailwind` |
| Solid | `@moduix/solid` / `@moduix-solid` | `@moduix/solid-tailwind` / `@moduix-solid-tailwind` |

Chaque guide ci-dessous indique les environnements qu’il prend en charge. Astro, Rsbuild, TanStack
Start et Vite couvrent React et Solid ; SolidStart dispose de son propre guide, tandis que Next.js et
React Router restent réservés à React.

## Installer le paquet

Choisissez cette méthode si vous voulez laisser moduix dans `node_modules` et le mettre à jour avec votre gestionnaire
de paquets.

Choisissez le mode de style de votre application. Chaque onglet présente la configuration complète.

<Tabs groupId="styling">
  <Tab label="CSS Modules" value="css-modules">

### CSS Modules

Choisissez ce mode pour recevoir les styles avec le paquet sans ajouter Tailwind aux dépendances.

#### 1. Installer le paquet

Les composants, le CSS et les tokens sont livrés ensemble. Installez moduix et les dépendances
indiquées pour votre framework :

<Tabs groupId="framework">
  <Tab label="React" value="react">

<PackageManagerTabs command="install @moduix/react @ark-ui/react" />

  </Tab>
  <Tab label="Solid" value="solid">

<PackageManagerTabs command="install @moduix/solid @ark-ui/solid" />

  </Tab>
</Tabs>

Le framework et le paquet Ark UI correspondant restent dans votre application. moduix n’en embarque
donc pas de copie supplémentaire.

#### 2. Ajouter les styles

Importez une seule fois le fichier de styles de base requis dans le point d’entrée de votre application :

<Tabs groupId="framework">
  <Tab label="React" value="react">

```tsx
import '@moduix/react/style.css';
```

  </Tab>
  <Tab label="Solid" value="solid">

```tsx
import '@moduix/solid/style.css';
```

  </Tab>
</Tabs>

Ce fichier définit les tokens partagés et la couche de base dont dépendent les styles des composants. Les styles propres
à chaque composant sont ensuite chargés avec le composant importé.

Tous les tokens de design moduix utilisent l'espace de noms `--moduix-*`. Votre projet peut conserver ses propres noms
de tokens et les associer sélectivement dans un fichier de styles chargé après `style.css` ; consultez
[Tokens](/docs/tokens).

Les composants CSS Modules nécessitent une réinitialisation globale. Importez celle de moduix avant le
fichier principal :

<Tabs groupId="framework">
  <Tab label="React" value="react">

```tsx
import '@moduix/react/reset.css';
import '@moduix/react/style.css';
```

  </Tab>
  <Tab label="Solid" value="solid">

```tsx
import '@moduix/solid/reset.css';
import '@moduix/solid/style.css';
```

  </Tab>
</Tabs>

Si votre application possède déjà sa propre réinitialisation correcte, utilisez-la à la place de celle
de moduix.

Ainsi, `style.css` reste limité au socle global et les styles des composants inutilisés peuvent rester hors du bundle.

Pour une base visuelle prête à l’emploi, importez l’un des préréglages facultatifs après `style.css` ; consultez
[Thèmes](/docs/themes).

#### 3. Utiliser un composant

Accordion est disponible dans chaque framework et variante de style publiés. C’est donc un bon premier test, quel que soit le
mode de style choisi :

  <Tab label="React" value="react">

<CodeBlockRuntime lang="tsx" code={reactCssModules} />

  </Tab>
  <Tab label="Solid" value="solid">

<CodeBlockRuntime lang="tsx" code={solidCssModules} />

  </Tab>
</Tabs>

L’installation fonctionne lorsque le déclencheur utilise les styles moduix et que le panneau s’ouvre
au clavier comme à la souris.
  </Tab>
  <Tab label="Tailwind CSS" value="tailwind">

### Tailwind CSS

Choisissez ce mode si votre application utilise déjà Tailwind CSS v4 et si vous souhaitez conserver
les styles des composants sous forme de classes utilitaires. Tailwind Preflight fournit le reset.

#### 1. Installer le paquet

<Tabs groupId="framework">
  <Tab label="React" value="react">

<PackageManagerTabs command="install @moduix/react-tailwind @ark-ui/react" />

  </Tab>
  <Tab label="Solid" value="solid">

<PackageManagerTabs command="install @moduix/solid-tailwind @ark-ui/solid" />

  </Tab>
</Tabs>

#### 2. Ajouter les styles

Importez les fondations générées avant Tailwind et limitez `@source` au dossier des composants du paquet :

<Tabs groupId="framework">
  <Tab label="React" value="react">

```css title="styles.css"
@import '@moduix/react-tailwind/style.css';
@import 'tailwindcss';

@source '../node_modules/@moduix/react-tailwind/dist/components';
```

  </Tab>
  <Tab label="Solid" value="solid">

```css title="styles.css"
@import '@moduix/solid-tailwind/style.css';
@import 'tailwindcss';

@source '../node_modules/@moduix/solid-tailwind/dist/components';
```

  </Tab>
</Tabs>

Résolvez `@source` par rapport à votre feuille de styles et limitez-le au répertoire
`dist/components` du paquet. N’ajoutez pas le reset de moduix : Tailwind Preflight le remplace.

## Installer avec la CLI shadcn

Choisissez cette méthode si vous voulez conserver le code source et les styles des composants dans votre dépôt. La CLI
shadcn lit le registre moduix, résout les dépendances et écrit les fichiers aux emplacements correspondant à vos alias.

### 1. Configurer shadcn

Créez `components.json` à la racine du projet, puis choisissez la configuration correspondant à
votre mode de stylisation :

<Tabs groupId="styling">
  <Tab label="CSS Modules" value="css-modules">

<CodeBlockRuntime lang="json" title="components.json" code={componentsCssModules} />

  </Tab>
  <Tab label="Tailwind" value="tailwind">

<CodeBlockRuntime lang="json" title="components.json" code={componentsTailwind} />

  </Tab>
</Tabs>

L’exemple Tailwind suppose que le point d’entrée Tailwind CSS v4 de l’application se trouve dans
`src/styles.css`. Avec la version 4, laissez `tailwind.config` vide et adaptez `tailwind.css` si votre
feuille de styles globale se trouve ailleurs. Les registres CSS Modules n’ont pas besoin de Tailwind ;
leur configuration conserve les valeurs vides exigées par le schéma shadcn.

`rsc` ne concerne que les éléments React du registre. Conservez `false` avec Solid et dans une
application React classique. Dans une application React Server Components, définissez `true` : la
CLI ajoute alors `use client` aux composants client du registre.

Assurez-vous que votre projet résout l'alias `@/*` vers son répertoire source. Une structure classique avec `src`
utilise l'entrée `paths` suivante, résolue par rapport à `tsconfig.json` :

```json
{
  "compilerOptions": {
    "paths": {
      "@/*": ["./src/*"]
    }
  }
}
```

La CLI `shadcn` dispose ainsi des alias et de l’URL du registre pour écrire les fichiers générés dans votre répertoire
source plutôt que dans un dossier `@` littéral. Le guide du framework choisi ci-dessus précise si le
même alias doit aussi être déclaré dans le bundler et quel répertoire source utiliser.

### 2. Ajouter un composant

<Tabs groupId="framework">
  <Tab label="React" value="react">

<ShadcnInstallOptions
  options={[
    { label: 'CSS Modules', command: 'shadcn@latest add @moduix-react/accordion' },
    { label: 'Tailwind CSS', command: 'shadcn@latest add @moduix-react-tailwind/accordion' },
  ]}
/>

  </Tab>
  <Tab label="Solid" value="solid">

<ShadcnInstallOptions
  options={[
    { label: 'CSS Modules', command: 'shadcn@latest add @moduix-solid/accordion' },
    { label: 'Tailwind CSS', command: 'shadcn@latest add @moduix-solid-tailwind/accordion' },
  ]}
/>

  </Tab>
</Tabs>

Pour ajouter un autre composant, remplacez son nom dans l’espace de noms choisi. Les registres
Tailwind contiennent uniquement les composants dont le portage est terminé.

Le registre n’ajoute que les fichiers partagés nécessaires au composant. Il n’installe aucune police
globale : la typographie continue d’hériter de votre application.

### 3. Importer les styles générés

Choisissez l’import correspondant à votre mode de style :

<Tabs groupId="styling">
  <Tab label="CSS Modules" value="css-modules">

```tsx
import '@/lib/moduix/styles/style.css';
```

Les composants CSS Modules nécessitent une réinitialisation globale. Si votre application n’en fournit
pas déjà une équivalente, installez celle de moduix avec son entrée de registre séparée :

<Tabs groupId="framework">
  <Tab label="React" value="react">

<PackageManagerTabs command="shadcn@latest add @moduix-react/reset" dlx />

  </Tab>
  <Tab label="Solid" value="solid">

<PackageManagerTabs command="shadcn@latest add @moduix-solid/reset" dlx />

  </Tab>
</Tabs>

Importez-le ensuite avant la feuille de styles principale :

```tsx
import '@/lib/moduix/styles/reset.css';
import '@/lib/moduix/styles/style.css';
```

Si votre application possède déjà sa propre réinitialisation correcte, utilisez-la à la place.

  </Tab>
  <Tab label="Tailwind CSS" value="tailwind">

Chargez les fondations générées avant Tailwind dans la feuille de styles principale de l’application :

```css title="styles.css"
@import './lib/moduix/styles/style.css';
@import 'tailwindcss';
```

Tailwind Preflight fournit le reset pour ce mode ; n’installez pas celui de moduix.

  </Tab>
</Tabs>

Les exemples ci-dessous utilisent `@/components` et `@/lib`. Si votre projet emploie d’autres
alias, mettez à jour `components.json` et adaptez les imports.

### 4. Utiliser les composants générés

Importez les composants depuis les fichiers créés dans votre projet :

```tsx
import { Button } from '@/components/ui/button';
import { Accordion } from '@/components/ui/accordion';
```

La plupart des composants sont composés de parties nommées. Cette structure préserve leur comportement accessible tout
en vous laissant maîtriser le balisage, la mise en page et les styles dans votre application.

Le registre est correctement configuré lorsque l’import du composant généré est résolu, que les styles
moduix sont visibles et que l’Accordion s’ouvre au clavier comme au pointeur.

La gestion du code source s’inspire de [shadcn/ui](https://ui.shadcn.com/), tandis que la structure des composants et
leur comportement restent alignés sur [Ark UI](https://ark-ui.com/).

## Configurer la superposition des portails

Cette configuration s’applique aux deux méthodes d’installation. `Dialog`, `Popover`, `Menu`, `Select` et d’autres
composants affichent le contenu des superpositions dans des portails. Isolez la racine de l’application pour que les
fonds et fenêtres contextuelles restent au-dessus de la page sans entrer en conflit avec des valeurs locales de `z-index`.

```html title="index.html"
<body>
  <div id="app-root"></div>
</body>
```

```css title="styles.css"
#app-root {
  isolation: isolate;
}
```

Si votre application prend en charge Safari sur iOS 26, testez une modale défilante avec la barre du navigateur visible.
Si du contenu apparaît sous le fond, définissez `body` avec `position: relative` afin qu’un fond positionné
absolument puisse couvrir toute la zone visible.

```css title="styles.css"
body {
  position: relative;
}
```

## Styles

moduix fonctionne avec l’approche de style déjà utilisée dans votre projet :

- CSS natif avec des sélecteurs globaux, des couches de cascade et des variables CSS.
- CSS Modules via `className` avec React ou `class` avec Solid et les props de classe des slots.
- Classes utilitaires Tailwind CSS pour la mise en page et les modifications ponctuelles.
- Bibliothèques CSS-in-JS qui ajoutent des classes ou transmettent des styles via vos propres composants.

Avec les CSS Modules, la densité par défaut utilise `--moduix-size-md: 36px` pour les contrôles
principaux et `--moduix-size-sm: 32px` pour les lignes des éléments contextuels. Modifier ces tokens
met à jour les composants associés. Dans les variantes Tailwind, les dimensions sont exprimées par
des utilitaires et se remplacent avec les classes de l’application.

Les pages des composants répertorient les points de personnalisation communs et les variables
publiques disponibles avec les CSS Modules. Les variantes Tailwind utilisent des utilitaires
sémantiques et les classes fournies par l’application au lieu de reproduire ces variables. Consultez
[Tokens](/docs/tokens) pour la hiérarchie complète et [Animations](/docs/animations) pour les
réglages d’animation.

## Résoudre les problèmes

| Problème | Vérification |
| --- | --- |
| Les composants s'affichent sans styles | Vérifiez l’ordre des imports du mode de style choisi. |
| Le contenu masqué d’un composant reste visible | Avec CSS Modules, vérifiez que la réinitialisation de moduix ou celle de votre application est chargée. Pour l’approche Tailwind, conservez Preflight. |
| Le bundler ne trouve pas un import de composant généré | Vérifiez l'alias `@/*` dans TypeScript et votre bundler, puis vérifiez `components.json`. |
| Une fenêtre contextuelle apparaît sous le contenu de la page | Ajoutez `isolation: isolate` à la racine de l'application et évitez les `z-index` globaux sans rapport. |
| Le rendu serveur signale des API client | Placez les composants interactifs dans un composant client dans les frameworks qui l'exigent. |
