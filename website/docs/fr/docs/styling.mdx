# Styles

Moduix publie des packages CSS Modules et Tailwind distincts pour chaque framework actuel. Choisissez
la méthode déjà utilisée par l’application, puis placez chaque modification au niveau le plus élevé
qui porte la décision.

Ce guide suppose que le package et la feuille de styles correspondants sont déjà configurés avec le
[Démarrage rapide](/docs/quick-start).

## Choisir une méthode de style

| Méthode | React | Solid | Cas adapté |
| --- | --- | --- | --- |
| CSS Modules | `@moduix/react` | `@moduix/solid` | Styles fournis, avec redéfinitions par tokens et classes locales |
| Tailwind CSS | `@moduix/react-tailwind` | `@moduix/solid-tailwind` | Composants basés sur des utilitaires dans une application Tailwind v4 |

CSS Modules et Tailwind sont deux modes de distribution équivalents, pas deux couches à combiner sur
un même composant. Le package doit correspondre au framework et à la méthode de style.

## Choisir le niveau de modification

| Objectif | Surface recommandée |
| --- | --- |
| Adopter une direction visuelle complète | [Preset de thème](/docs/themes) |
| Modifier une couleur, taille, rayon ou espace dans tout le système | Token sémantique de [Tokens](/docs/tokens) |
| Aligner une famille de composants | Token partagé de cette famille |
| Modifier un composant CSS Modules | Variable documentée du composant |
| Styliser une composition du produit | Classes du consommateur sur les parties responsables |

Commencez par les tokens pour une décision globale. Descendez jusqu’à une partie rendue seulement
lorsque le choix appartient à une composition.

## Styliser les parties exportées

Placez la classe sur la partie qui porte la modification visuelle. Pour un état, associez-la aux
attributs Ark comme `data-state` ou `data-disabled`. Ne dépendez ni des classes générées ni de l’ordre
du DOM.

L’aperçu utilise React, car le site de documentation fonctionne avec React. La source Solid partage la
même feuille de styles et utilise les props `class` natives.

## Cibler les parties masquées avec prudence

Lorsqu’un wrapper du produit masque volontairement une partie interne, utilisez son `data-slot`
stable comme solution de secours :

```css
.root {
  [data-slot='accordion-item-trigger'] {
    padding-inline: var(--moduix-spacing-4);

    &[data-state='open'] {
      color: var(--moduix-color-primary);
    }
  }
}
```

Préférez une classe directe lorsque la partie est disponible. Placez les classes et variables locales
sur les parties rendues dans un portail ou sur leur conteneur de portail.

## Utiliser Panda CSS

Panda CSS peut générer des classes du consommateur pour chaque framework pris en charge. Ses noms de tokens
appartiennent au thème Panda, pas à Moduix. Transmettez la chaîne générée avec `className` en React ou
`class` en Solid.

```ts
import { css } from '../styled-system/css';

const trigger = css({
  display: 'grid',
  gridTemplateColumns: 'minmax(0, 1fr) auto',
  px: '4',
  py: '4',
  _hover: { bg: 'blue.100' },
  '&[data-state=open]': { color: 'blue.700' },
});
```

## Utiliser Tailwind CSS

Les packages Tailwind contiennent déjà les styles utilitaires par défaut. Ajoutez les classes du
consommateur à la partie précise que vous souhaitez modifier :

```tsx
import { Accordion } from '@moduix/react-tailwind/accordion';

<Accordion collapsible>
  <AccordionItem value="shipping" className="rounded-lg border data-[state=open]:border-blue-500">
    <AccordionItemTrigger className="px-4">Shipping</AccordionItemTrigger>
    <AccordionItemContent className="px-4">Usually 2 to 4 days.</AccordionItemContent>
  </AccordionItem>
</Accordion>;
```

  </Tab>
  <Tab label="Solid" value="solid">

```tsx
import { Accordion } from '@moduix/solid-tailwind/accordion';

<Accordion collapsible>
  <AccordionItem value="shipping" class="rounded-lg border data-[state=open]:border-blue-500">
    <AccordionItemTrigger class="px-4">Shipping</AccordionItemTrigger>
    <AccordionItemContent class="px-4">Usually 2 to 4 days.</AccordionItemContent>
  </AccordionItem>
</Accordion>;
```

  </Tab>

Conservez l’entrée `@source` du package choisi afin que Tailwind génère ses classes. Le
[Démarrage rapide](/docs/quick-start) décrit la feuille de styles complète.

## Diagnostiquer la cascade

| Symptôme | Vérification |
| --- | --- |
| Une variable n’a aucun effet | Vérifiez qu’elle est documentée et que la redéfinition arrive après `style.css`. |
| Un popup ignore la valeur d’un conteneur | Placez-la sur la partie rendue dans un portail, la racine ou le conteneur de portail. |
| Un sélecteur d’état ne correspond jamais | Inspectez l’attribut Ark exact sur cette partie. |
| La classe atteint la racine mais pas une partie interne | Appliquez-la à la partie exportée qui porte la propriété. |
| Les utilitaires Tailwind manquent | Vérifiez la feuille du package, le chemin `@source` et l’ordre des classes. |

Inspectez la partie rendue, son `data-slot`, ses attributs d’état et ses valeurs calculées avant
d’augmenter la spécificité.
