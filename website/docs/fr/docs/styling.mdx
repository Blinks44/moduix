# Styles

moduix fournit les styles des composants et une base CSS commune, sans imposer d’outil de création de styles. Utilisez
CSS Modules, Panda CSS, Tailwind CSS ou toute autre stratégie déjà adoptée par votre application. L’API des
composants reste identique.

Importez une seule fois la feuille de styles de base au point d’entrée de l’application :

```tsx
import '@moduix/react/style.css';
```

Panda CSS et Tailwind CSS ne font pas partie des dépendances de moduix ni de ce site de documentation. Dans les
exemples ci-dessous, le même `ProjectChecklist` est stylisé avec chaque outil ; seule la syntaxe change. Ces snippets
s’adressent aux applications dans lesquelles l’outil correspondant est déjà configuré.

## Choisir une redéfinition

| Objectif | Méthode recommandée |
| --- | --- |
| Adopter une direction visuelle complète | Un [preset de thème](/docs/themes) préparé |
| Modifier une couleur, une taille, un rayon ou un espacement dans tout le système | Un token primitif ou sémantique de la section [Tokens](/docs/tokens) |
| Harmoniser une famille de contrôles ou de lignes de composants flottants | Un token de famille partagé, comme `--moduix-popup-item-min-height` |
| Distinguer volontairement un composant | Un alias `--<component>-*` documenté |
| Styliser une composition propre au produit | `className` sur la partie rendue, de préférence avec du CSS local |

Ce tableau maintient des thèmes compacts et un style prévisible des composants. Préférez un token de haut niveau si
la décision doit s’appliquer largement ; rapprochez-vous de la partie rendue lorsque la portée devient locale.

## Styliser les parties

Commencez par placer `className` sur la partie responsable du changement visuel. L’anatomie du composant reste ainsi
visible et les styles restent locaux au produit. Sur cette même partie, utilisez les attributs d’état Ark documentés
pour les états et les variables CSS publiques lorsque le composant expose la valeur à modifier.

Le panneau ci-dessous utilise CSS Modules et stylise directement toutes les parties exportées d’Accordion.

### Parties masquées

Lorsqu’un wrapper du produit possède la composition sans exposer une partie à ses appelants, utilisez un `data-slot`
stable. Vous pourrez ainsi personnaliser le déclencheur interne sans dépendre de l’ordre du DOM ni de noms de classes
générés :

```css
.root {
  [data-slot='accordion-item-trigger'] {
    padding-inline: var(--moduix-spacing-4);

    &[data-state='open'] {
      color: var(--moduix-color-primary);
    }
  }
}
```

Il s’agit d’une solution de dernier recours, pas d’un remplacement de `className`. Pour les parties rendues
automatiquement dans un portail, comme `Dialog.Content` ou `Tooltip.Content`, ajoutez `className` directement à la
partie placée dans le portail.

## Panda CSS

Dans une application où Panda est déjà configuré, générez des classes pour les mêmes parties de `ProjectChecklist`.
Les noms de tokens ci-dessous appartiennent au thème Panda, pas à moduix.

```tsx
import { Accordion } from '@moduix/react/accordion';
import { css } from '../styled-system/css';

const root = css({
  maxW: '2xl',
  p: '3',
  borderWidth: '1px',
  borderColor: 'blue.200',
  borderRadius: 'xl',
  bg: 'blue.50',
});
const accordion = css({ display: 'flex', flexDirection: 'column', gap: '3' });
const item = css({
  overflow: 'hidden',
  borderWidth: '1px',
  borderColor: 'blue.200',
  borderRadius: 'lg',
  bg: 'white',
  transition: 'colors',
  '&[data-state=open]': { borderColor: 'blue.500', boxShadow: 'lg' },
});
const trigger = css({
  display: 'grid',
  gridTemplateColumns: 'minmax(0, 1fr) auto',
  gap: '3',
  alignItems: 'center',
  w: 'full',
  px: '4',
  py: '4',
  bg: 'blue.50',
  color: 'gray.950',
  fontWeight: 'semibold',
  textAlign: 'left',
  transition: 'colors',
  _hover: { bg: 'blue.100' },
  _focusVisible: { outlineWidth: '2px', outlineColor: 'blue.500', outlineOffset: '-1px' },
  '&[data-state=open]': { bg: 'blue.100', color: 'blue.700' },
});
const triggerCopy = css({ display: 'flex', gap: '3', alignItems: 'center', minW: '0' });
const step = css({
  display: 'grid',
  flexShrink: '0',
  placeItems: 'center',
  w: '7',
  h: '7',
  borderWidth: '1px',
  borderColor: 'blue.300',
  borderRadius: 'xl',
  bg: 'blue.100',
  color: 'blue.700',
  fontSize: 'xs',
  fontWeight: 'semibold',
});
const title = css({ minW: '0' });
const indicator = css({ flexShrink: '0', color: 'blue.700' });
const content = css({
  borderTopWidth: '1px',
  borderColor: 'blue.200',
  bg: 'blue.50',
  color: 'gray.950',
});
const body = css({ px: '4', py: '4', color: 'gray.700', lineHeight: '6' });

export function ProjectChecklist() {
  return (
    <section className={root}>
      <Accordion className={accordion} collapsible defaultValue={['outcome']}>
        <Accordion.Item className={item} value="outcome">
          <Accordion.ItemTrigger className={trigger}>
            <span className={triggerCopy}>
              <span className={step}>01</span>
              <span className={title}>Define the project outcome</span>
            </span>
            <Accordion.ItemIndicator className={indicator} />
          </Accordion.ItemTrigger>
          <Accordion.ItemContent className={content}>
            <Accordion.ItemBody className={body}>
              <p>
                Write one sentence that makes the next decision obvious to everyone on the project.
              </p>
            </Accordion.ItemBody>
          </Accordion.ItemContent>
        </Accordion.Item>
      </Accordion>
    </section>
  );
}
```

## Tailwind CSS

Dans une application qui utilise déjà Tailwind, appliquez les utilitaires et les variantes d’état aux mêmes parties
de `ProjectChecklist`. Aucun plugin ni aucune configuration Tailwind spécifique à moduix n’est nécessaire.

```tsx
import { Accordion } from '@moduix/react/accordion';

export function ProjectChecklist() {
  return (
    <section className="max-w-2xl rounded-xl border border-blue-200 bg-blue-50 p-3">
      <Accordion className="flex flex-col gap-3" collapsible defaultValue={['outcome']}>
        <Accordion.Item
          className="overflow-hidden rounded-lg border border-blue-200 bg-white transition-[border-color,box-shadow] data-[state=open]:border-blue-500 data-[state=open]:shadow-lg"
          value="outcome"
        >
          <Accordion.ItemTrigger className="grid w-full grid-cols-[minmax(0,1fr)_auto] items-center gap-3 bg-blue-50 p-4 text-left font-semibold text-slate-950 transition-colors hover:bg-blue-100 focus-visible:outline-2 focus-visible:outline-blue-500 focus-visible:outline-offset-[-1px] data-[state=open]:bg-blue-100 data-[state=open]:text-blue-700">
            <span className="flex min-w-0 items-center gap-3">
              <span className="grid size-7 shrink-0 place-items-center rounded-xl border border-blue-300 bg-blue-100 text-xs font-semibold text-blue-700">
                01
              </span>
              <span className="min-w-0">Define the project outcome</span>
            </span>
            <Accordion.ItemIndicator className="shrink-0 text-blue-700" />
          </Accordion.ItemTrigger>
          <Accordion.ItemContent className="border-t border-blue-200 bg-blue-50 text-slate-950">
            <Accordion.ItemBody className="p-4 leading-6 text-slate-700">
              <p>
                Write one sentence that makes the next decision obvious to everyone on the project.
              </p>
            </Accordion.ItemBody>
          </Accordion.ItemContent>
        </Accordion.Item>
      </Accordion>
    </section>
  );
}
```

## Résolution des problèmes

| Symptôme | Vérification la plus probable |
| --- | --- |
| Une variable n’a aucun effet | Vérifiez qu’elle figure sur la page du composant et que votre règle est chargée après `style.css`. |
| Un composant flottant ignore une valeur définie dans un wrapper | Le composant peut être rendu dans un portail ; placez la valeur sur sa partie, sa racine ou le conteneur du portail. |
| Un sélecteur d’état ne correspond jamais | Vérifiez l’attribut Ark documenté : `data-state`, `data-disabled` ou un autre. |
| La classe atteint la racine, mais pas la partie | Placez `className` sur la partie exportée qui contrôle la propriété visuelle. |
| Une classe utilitaire est supplantée par le CSS du composant | Utilisez une variable CSS documentée ou une classe locale avec un ordre de cascade maîtrisé. |

Avant d’augmenter la spécificité d’un sélecteur, utilisez les outils de développement du navigateur pour inspecter la
partie rendue, son `data-slot`, ses attributs d’état et les propriétés personnalisées calculées.
