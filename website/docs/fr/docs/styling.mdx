# Styliser les composants

moduix fournit les styles de ses composants ainsi qu’une base CSS commune, sans imposer d’outil particulier. Vous pouvez
conserver l’approche déjà utilisée par votre application : CSS Modules, Panda CSS, Tailwind CSS, CSS classique ou toute
autre solution. L’API des composants reste la même dans tous les cas.

Importez la feuille de styles de base une seule fois depuis le point d’entrée de l’application :

```tsx
import '@moduix/react/style.css';
```

moduix n’installe pas Panda CSS ni Tailwind CSS pour vous. Les exemples ci-dessous appliquent chaque outil à la même
composition `ProjectChecklist` : seule la syntaxe de style change. Ils supposent que l’outil correspondant est déjà
configuré dans votre application.

## Choisir où effectuer la modification

| Objectif | Surface recommandée |
| --- | --- |
| Adopter une direction visuelle complète | Un [preset de thème](/docs/themes) préparé |
| Modifier une couleur, une taille, un rayon ou un espacement à l’échelle du système | Un token primitif ou sémantique de la section [Tokens](/docs/tokens) |
| Harmoniser une famille de contrôles ou de lignes dans des composants flottants | Un token partagé par une famille, comme `--moduix-popup-item-min-height` |
| Modifier volontairement un seul composant | Un alias `--moduix-<component>-*` documenté |
| Styliser une composition propre au produit | `className` sur chaque partie à modifier, de préférence avec du CSS local |

Choisissez le niveau le plus élevé qui correspond à la portée de la décision. Utilisez un token si la modification doit
s’appliquer à plusieurs composants. Descendez jusqu’à une partie rendue si elle ne concerne qu’une composition.

## Styliser les parties

Ajoutez `className` à la partie qui porte le changement visuel. L’anatomie du composant reste ainsi explicite et la règle
reste limitée au composant de votre produit. Pour les états, combinez cette classe avec les attributs Ark `data-*`
documentés sur la même partie. Utilisez une variable CSS publique lorsque le composant expose la valeur à modifier.

L’exemple ci-dessous utilise CSS Modules et applique les styles directement aux parties exportées d’Accordion.

### Parties masquées

Si un composant de votre produit gère la composition sans exposer l’une de ses parties internes comme prop, ciblez cette
partie avec son `data-slot` stable. Vous pouvez ainsi styliser un déclencheur interne sans dépendre de l’ordre du DOM ni
de noms de classes générés :

```css
.root {
  [data-slot='accordion-item-trigger'] {
    padding-inline: var(--moduix-spacing-4);

    &[data-state='open'] {
      color: var(--moduix-color-primary);
    }
  }
}
```

Utilisez cette technique en dernier recours, pas comme remplacement de `className`. Les parties telles que
`Dialog.Content` et `Tooltip.Content` sont rendues par défaut dans un portail. Placez donc `className` sur la partie
elle-même ou appliquez ses variables au conteneur du portail.

## Panda CSS

Si votre application utilise déjà Panda CSS, générez des classes pour les mêmes parties de `ProjectChecklist`. Les noms
de tokens de cet exemple viennent de votre thème Panda, pas de moduix.

```tsx
import { Accordion } from '@moduix/react/accordion';
import { css } from '../styled-system/css';

const root = css({
  maxW: '2xl',
  p: '3',
  borderWidth: '1px',
  borderColor: 'blue.200',
  borderRadius: 'xl',
  bg: 'blue.50',
});
const accordion = css({ display: 'flex', flexDirection: 'column', gap: '3' });
const item = css({
  overflow: 'hidden',
  borderWidth: '1px',
  borderColor: 'blue.200',
  borderRadius: 'lg',
  bg: 'white',
  transition: 'colors',
  '&[data-state=open]': { borderColor: 'blue.500', boxShadow: 'lg' },
});
const trigger = css({
  display: 'grid',
  gridTemplateColumns: 'minmax(0, 1fr) auto',
  gap: '3',
  alignItems: 'center',
  w: 'full',
  px: '4',
  py: '4',
  bg: 'blue.50',
  color: 'gray.950',
  fontWeight: 'semibold',
  textAlign: 'left',
  transition: 'colors',
  _hover: { bg: 'blue.100' },
  _focusVisible: { outlineWidth: '2px', outlineColor: 'blue.500', outlineOffset: '-1px' },
  '&[data-state=open]': { bg: 'blue.100', color: 'blue.700' },
});
const triggerCopy = css({ display: 'flex', gap: '3', alignItems: 'center', minW: '0' });
const step = css({
  display: 'grid',
  flexShrink: '0',
  placeItems: 'center',
  w: '7',
  h: '7',
  borderWidth: '1px',
  borderColor: 'blue.300',
  borderRadius: 'xl',
  bg: 'blue.100',
  color: 'blue.700',
  fontSize: 'xs',
  fontWeight: 'semibold',
});
const title = css({ minW: '0' });
const indicator = css({ flexShrink: '0', color: 'blue.700' });
const content = css({
  borderTopWidth: '1px',
  borderColor: 'blue.200',
  bg: 'blue.50',
  color: 'gray.950',
});
const body = css({ px: '4', py: '4', color: 'gray.700', lineHeight: '6' });

export function ProjectChecklist() {
  return (
    <section className={root}>
      <Accordion className={accordion} collapsible defaultValue={['outcome']}>
        <Accordion.Item className={item} value="outcome">
          <Accordion.ItemTrigger className={trigger}>
            <span className={triggerCopy}>
              <span className={step}>01</span>
              <span className={title}>Define the project outcome</span>
            </span>
            <Accordion.ItemIndicator className={indicator} />
          </Accordion.ItemTrigger>
          <Accordion.ItemContent className={content}>
            <Accordion.ItemBody className={body}>
              <p>
                Write one sentence that makes the next decision obvious to everyone on the project.
              </p>
            </Accordion.ItemBody>
          </Accordion.ItemContent>
        </Accordion.Item>
      </Accordion>
    </section>
  );
}
```

## Tailwind CSS

Si votre application utilise déjà Tailwind CSS, appliquez les utilitaires et les variantes d’état aux mêmes parties de
`ProjectChecklist`. Aucun plugin ni aucune configuration Tailwind spécifique à moduix n’est nécessaire.

```tsx
import { Accordion } from '@moduix/react/accordion';

export function ProjectChecklist() {
  return (
    <section className="max-w-2xl rounded-xl border border-blue-200 bg-blue-50 p-3">
      <Accordion className="flex flex-col gap-3" collapsible defaultValue={['outcome']}>
        <Accordion.Item
          className="overflow-hidden rounded-lg border border-blue-200 bg-white transition-[border-color,box-shadow] data-[state=open]:border-blue-500 data-[state=open]:shadow-lg"
          value="outcome"
        >
          <Accordion.ItemTrigger className="grid w-full grid-cols-[minmax(0,1fr)_auto] items-center gap-3 bg-blue-50 p-4 text-left font-semibold text-slate-950 transition-colors hover:bg-blue-100 focus-visible:outline-2 focus-visible:outline-blue-500 focus-visible:outline-offset-[-1px] data-[state=open]:bg-blue-100 data-[state=open]:text-blue-700">
            <span className="flex min-w-0 items-center gap-3">
              <span className="grid size-7 shrink-0 place-items-center rounded-xl border border-blue-300 bg-blue-100 text-xs font-semibold text-blue-700">
                01
              </span>
              <span className="min-w-0">Define the project outcome</span>
            </span>
            <Accordion.ItemIndicator className="shrink-0 text-blue-700" />
          </Accordion.ItemTrigger>
          <Accordion.ItemContent className="border-t border-blue-200 bg-blue-50 text-slate-950">
            <Accordion.ItemBody className="p-4 leading-6 text-slate-700">
              <p>
                Write one sentence that makes the next decision obvious to everyone on the project.
              </p>
            </Accordion.ItemBody>
          </Accordion.ItemContent>
        </Accordion.Item>
      </Accordion>
    </section>
  );
}
```

## Résoudre les problèmes

| Symptôme | Vérification la plus probable |
| --- | --- |
| Une variable n’a aucun effet | Vérifiez qu’elle est documentée sur la page du composant et que votre redéfinition est chargée après `style.css`. |
| Un composant flottant ignore une valeur définie sur son conteneur | Il est peut-être rendu dans un portail. Placez la variable sur sa partie, sa racine ou le conteneur du portail. |
| Le sélecteur d’état ne correspond jamais | Inspectez l’attribut Ark exact, par exemple `data-state` ou `data-disabled`. |
| La classe atteint la racine, mais pas la partie | Placez `className` sur la partie exportée qui contrôle la propriété visuelle. |
| Une classe utilitaire est supplantée par le CSS du composant | Préférez une variable CSS documentée ou vérifiez l’ordre de cascade de votre classe locale. |

Avant d’augmenter la spécificité d’un sélecteur, utilisez les outils de développement du navigateur pour inspecter la
partie rendue, son `data-slot`, ses attributs d’état et les propriétés personnalisées calculées.
