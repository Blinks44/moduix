## Quand utiliser `ClientOnly`

Utilisez `ClientOnly` pour la partie de l’interface qui doit accéder au DOM ou à des API du navigateur indisponibles
côté serveur, comme `window`, `navigator`, le stockage, les mesures de mise en page ou une bibliothèque réservée au
navigateur. Lors du rendu côté serveur, le composant affiche le `fallback`, puis son contenu enfant après
l’hydratation.

`ClientOnly` est fourni par Ark UI. moduix ne l’encapsule pas et ne le réexporte pas : importez-le directement.

```tsx
import { ClientOnly } from '@ark-ui/react/client-only';
```

Si Ark UI ne figure pas déjà parmi les dépendances de votre application, installez-le :

```bash
pnpm add @ark-ui/react
```

## Exemple de base

Placez le code qui dépend du navigateur dans le composant enfant à l’intérieur de `ClientOnly`. Choisissez un
`fallback` proche de l’interface moduix finale et de dimensions comparables. Le serveur affiche ainsi un contenu utile
et la mise en page ne se décale pas brusquement au moment où le client prend le relais.

## Choisir un `fallback`

Le `fallback` est le contenu visible pendant le rendu côté serveur et jusqu’à la fin de l’hydratation. Utilisez un
`Skeleton`, une version statique du contenu ou un autre élément utile de dimensions proches de l’interface finale.
Reproduisez notamment les lignes et les contrôles importants pour éviter un changement de hauteur brutal. N’accédez
pas aux objets globaux du navigateur pour construire le `fallback`.

## Garder les API du navigateur côté client

`ClientOnly` contrôle le rendu de son contenu, mais ne transforme pas un composant ou un module SSR en module client.
Accédez à `window`, `document`, `navigator`, `localStorage` et aux mesures de mise en page uniquement dans le
composant enfant placé dans `ClientOnly`, ou dans un effet ou un gestionnaire d’événements. Ne placez pas ces accès
dans le composant parent qui crée la frontière `ClientOnly` : ce parent est toujours rendu côté serveur.

## Utiliser `ClientOnly` avec moduix

Les composants moduix fonctionnent normalement dans le sous-arbre rendu par `ClientOnly`. Dans l’exemple, `Card`
affiche des informations lues dans le navigateur et `Skeleton` conserve la même structure dans le `fallback`. Si un
composant moduix peut déjà être rendu côté serveur avec le comportement souhaité, utilisez son API documentée au lieu
d’ajouter une frontière `ClientOnly`.

## Responsabilités

Ark UI fournit `ClientOnly`, son comportement d’hydratation et sa propriété `fallback`. moduix explique comment
l’associer à ses composants, mais ne stylise pas l’utilitaire et ne l’inclut pas dans les exports du package.
