## Référence de l’API

<PrimitiveReference href="https://ark-ui.com/docs/components/file-upload" />

`FileUpload` est disponible depuis `@moduix/react/file-upload`. Le composant ainsi que les hooks `useFileUpload` et
`useFileUploadContext` sont également exportés par `@moduix/react`.

## Exemple de base

Commencez par utiliser `FileUpload` comme composant racine. Ajoutez un `Label`, puis utilisez `Trigger` pour un contrôle
compact ou `Dropzone` pour le glisser-déposer. Placez `Items` dans `ItemGroup` pour afficher les fichiers acceptés. Le
composant racine génère automatiquement l’input natif masqué. `Items` affiche une vignette uniquement lorsque le fichier
possède un type MIME `image/*` ; les autres fichiers utilisent un aperçu générique.

## Anatomie

```text
FileUpload / FileUpload.Root
├─ FileUpload.Label
├─ FileUpload.Dropzone (facultatif)
│  ├─ FileUpload.DropzoneIcon
│  └─ FileUpload.Trigger
├─ FileUpload.Trigger (sans `Dropzone`)
├─ FileUpload.ItemGroup[type]
│  ├─ FileUpload.Items
│  └─ FileUpload.Context
│     └─ FileUpload.Item[file]
│        ├─ FileUpload.ItemPreview[type]
│        │  ├─ FileUpload.ItemPreviewImage
│        │  └─ FileUpload.ItemPreviewIcon
│        ├─ FileUpload.ItemName
│        ├─ FileUpload.ItemMetadata[file]
│        ├─ FileUpload.ItemSizeText
│        └─ FileUpload.ItemDeleteTrigger
├─ FileUpload.ClearTrigger
└─ champ de fichier natif masqué (automatique)
```

| Partie | Rôle |
| -------------------------------- | ------------------------------------------------------------------------ |
| `FileUpload` / `FileUpload.Root` | Gère l’état des fichiers, la validation, le glisser-déposer, le collage et l’intégration aux formulaires. |
| `FileUpload.RootProvider` | Relie l’arbre du composant à l’état renvoyé par le hook `useFileUpload`. |
| `FileUpload.Label` | Libellé accessible pour le champ de fichier masqué et les contrôles de téléversement. |
| `FileUpload.Dropzone` | Zone de dépôt. Passez `disableClick` si elle contient un `Trigger` imbriqué, afin de ne pas ouvrir deux fois le sélecteur. |
| `FileUpload.DropzoneIcon` | Icône de téléversement décorative pour une `Dropzone`. |
| `FileUpload.Trigger` | Bouton qui ouvre le sélecteur de fichiers natif. |
| `FileUpload.ItemGroup` | Liste des fichiers acceptés ou rejetés. |
| `FileUpload.Items` | Composant prêt à l’emploi qui affiche des cartes pour les images et des lignes pour les autres fichiers, avec aperçu, métadonnées et suppression. |
| `FileUpload.Context` | Contexte compatible avec Ark et basé sur une fonction de rendu pour créer des lignes personnalisées. |
| `FileUpload.Item` | Ligne de fichier. Transmettez-lui l’objet `file` courant. |
| `FileUpload.ItemPreview` | Emplacement d’aperçu affiché selon le type MIME du fichier. |
| `FileUpload.ItemPreviewImage` | Aperçu d’image à l’intérieur de `ItemPreview`. |
| `FileUpload.ItemPreviewIcon` | Icône de fichier générique pour un aperçu de secours dans `ItemPreview`. |
| `FileUpload.ItemName` | Nom du fichier. |
| `FileUpload.ItemMetadata` | Type du fichier et taille formatée selon la locale. Passez-lui l’objet `file` courant. |
| `FileUpload.ItemSizeText` | Taille du fichier formatée selon la locale. |
| `FileUpload.ItemDeleteTrigger` | Supprime un fichier. Utilise par défaut l’icône de corbeille moduix. |
| `FileUpload.ClearTrigger` | Efface les fichiers sélectionnés. Utilise par défaut l’icône de fermeture moduix. |

## Composition

### Composition recommandée

Gardez l’arbre explicite des parties Ark dans votre balisage. Utilisez `Trigger` seul pour un contrôle compact et
`Dropzone` pour une zone de glisser-déposer. Si `Trigger` est imbriqué dans `Dropzone`, passez `disableClick` à
`Dropzone` afin que le sélecteur de fichiers natif ne s’ouvre qu’une seule fois.

Le composant racine génère toujours le champ de fichier natif masqué. Utilisez `Items` dans `ItemGroup` pour une liste compacte de
fichiers acceptés. Si vous créez des lignes personnalisées, lisez les fichiers acceptés depuis
`FileUpload.Context.acceptedFiles` et les fichiers rejetés depuis `FileUpload.Context.rejectedFiles`.

Utilisez `FileUpload.Context`, `useFileUpload()` et `useFileUploadContext()` lorsque vous avez besoin d’un accès avancé à
l’état. Le contexte et les hooks sont réexportés directement par Ark : les objets `details` des callbacks et le contrat
d’état restent donc inchangés.

### Quand créer une composition personnalisée

`Items` affiche les images sous forme de cartes verticales compactes et les autres fichiers sous forme de lignes horizontales
accompagnées de leurs métadonnées. Utilisez la composition explicite de `Context` pour créer des lignes personnalisées.
`ItemPreview.type` sert de prédicat fondé sur une expression régulière, pas de liste de règles prioritaires ; affichez donc
un seul aperçu par fichier. Par exemple, utilisez `file.type.startsWith("image/")` pour sélectionner `ItemPreviewImage`.
Pour les autres fichiers, affichez `ItemPreviewIcon`, puis composez `ItemName`, `ItemMetadata file={file}` et
`ItemDeleteTrigger`. Utilisez `asChild` uniquement si l’enfant est un seul élément sémantique qui conserve le comportement
requis d’un bouton, d’un libellé ou d’un champ de saisie.

### Propriétés par défaut

| Propriété | Par défaut | Remarques |
| --------------------- | ------------ | ----------------------------------------------------------------- |
| `allowDrop` | `true` | Autorise le glisser-déposer sur `Dropzone`. |
| `maxFiles` | `1` | Augmentez cette valeur ou supprimez la limite pour accepter plusieurs fichiers ou dossiers entiers. |
| `minFileSize` | `0` | Taille minimale du fichier accepté, en octets. |
| `maxFileSize` | `∞` | Taille maximale du fichier accepté, en octets. |
| `preventDocumentDrop` | `true` | Empêche une navigation accidentelle lorsqu’un fichier est déposé en dehors de la zone cible. |
| `locale` | `en-US` | Paramètre régional utilisé pour formater la taille des fichiers. |

### Comportement

`acceptedFiles`, `defaultAcceptedFiles` et `onFileChange(details)` suivent le modèle d’état contrôlé ou non contrôlé d’Ark.
`onFileChange` est appelé lorsque la valeur change, qu’un fichier soit accepté ou rejeté. Les callbacks
`onFileAccept(details)` et `onFileReject(details)` reçoivent les objets `details` d’origine transmis par Ark, notamment
les erreurs associées aux fichiers rejetés. `Field.Root` et `Fieldset.Root` peuvent fournir les états `disabled`, `invalid`,
`required` et `readOnly`. Utilisez `ids` lorsque des libellés ou des descriptions distincts ont besoin d’associations
d’accessibilité stables.

### Points d’accroche CSS

Utilisez des slots moduix stables, comme `[data-slot="file-upload-dropzone"]`,
`[data-slot="file-upload-item"]` et `[data-slot="file-upload-item-delete-trigger"]`.
Ark expose également `data-scope="file-upload"`, `data-part` pour les parties et les attributs d’état tels que
`data-disabled`, `data-readonly`, `data-invalid`, `data-required`, `data-dragging` et `data-type`.
