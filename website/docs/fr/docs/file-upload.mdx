## Référence de l’API

<PrimitiveReference href="https://ark-ui.com/docs/components/file-upload" />

`FileUpload` est disponible depuis `@moduix/react/file-upload` et `@moduix/vue/file-upload`. Le composant ainsi que les hooks `useFileUpload` et
`useFileUploadContext` sont également exportés par `@moduix/react`.

Le même composant est disponible depuis `@moduix/solid/file-upload`, `@moduix/react-tailwind/file-upload`,
`@moduix/solid-tailwind/file-upload` et `@moduix/vue-tailwind/file-upload`. Les six variantes exposent les mêmes parties et le même modèle d’état.
Choisissez le paquet correspondant à votre framework et à votre solution de styles.

## Choisir le bon composant

Utilisez `FileUpload` lorsque l’application doit conserver les fichiers sélectionnés dans son état,
afficher une zone de dépôt ou gérer un flux d’envoi. Un `Input` avec `type="file"` suffit pour un
sélecteur natif dans un formulaire simple.

## Exemple de base


Commencez par utiliser `FileUpload` comme composant racine. Ajoutez un `FileUploadLabel`, puis enveloppez un `Button` dans `FileUploadTrigger asChild` pour un contrôle
compact ou `FileUploadDropzone` pour le glisser-déposer. Ajoutez explicitement `FileUploadHiddenInput` pour
ouvrir le sélecteur natif. Placez `FileUploadItems` dans `FileUploadItemGroup` pour afficher les fichiers acceptés. `FileUploadItems` affiche une vignette uniquement lorsque le fichier
possède un type MIME `image/*` ; les autres fichiers utilisent un aperçu générique.

## Anatomie

```text
FileUpload / FileUploadRootProvider
├─ FileUploadLabel
├─ FileUploadDropzone (facultatif)
│  ├─ FileUploadDropzoneIcon
│  └─ FileUploadTrigger
├─ FileUploadTrigger (sans `FileUploadDropzone`)
├─ FileUploadItemGroup[type]
│  ├─ FileUploadItems
│  └─ FileUploadContext
│     └─ FileUploadItem[file]
│        ├─ FileUploadItemPreview[type]
│        │  ├─ FileUploadItemPreviewImage
│        │  └─ FileUploadItemPreviewIcon
│        ├─ FileUploadItemName
│        ├─ FileUploadItemMetadata[file]
│        ├─ FileUploadItemSizeText
│        └─ FileUploadItemDeleteTrigger
├─ FileUploadClearTrigger
└─ FileUploadHiddenInput (explicite)
```

| Partie | Rôle |
| -------------------------------- | ------------------------------------------------------------------------ |
| `FileUpload` / `FileUploadRootProvider` | Gère l’état des fichiers, la validation, le glisser-déposer, le collage et l’intégration aux formulaires. |
| `FileUploadHiddenInput` | Champ natif d’Ark ; composition explicite décrite ci-dessous. |
| `FileUploadRootProvider` | Relie l’arbre du composant à l’état renvoyé par le hook `useFileUpload`. |
| `FileUploadLabel` | Libellé accessible pour le champ de fichier masqué et les contrôles de téléversement. |
| `FileUploadDropzone` | Zone de dépôt. Passez `disableClick` si elle contient un `FileUploadTrigger` imbriqué, afin de ne pas ouvrir deux fois le sélecteur. |
| `FileUploadDropzoneIcon` | Icône de téléversement décorative pour une `FileUploadDropzone`. |
| `FileUploadTrigger` | Bouton sans style qui ouvre le sélecteur de fichiers natif. Composez-le avec un `Button` via `asChild`. |
| `FileUploadItemGroup` | Liste des fichiers acceptés ou rejetés. |
| `FileUploadItems` | Composant prêt à l’emploi qui affiche des cartes pour les images et des lignes pour les autres fichiers, avec aperçu, métadonnées et suppression. |
| `FileUploadContext` | Contexte compatible avec Ark et basé sur une fonction de rendu pour créer des lignes personnalisées. |
| `FileUploadItem` | Ligne de fichier. Transmettez-lui l’objet `file` courant. |
| `FileUploadItemPreview` | Emplacement d’aperçu affiché selon le type MIME du fichier. |
| `FileUploadItemPreviewImage` | Aperçu d’image à l’intérieur de `FileUploadItemPreview`. |
| `FileUploadItemPreviewIcon` | Icône de fichier générique pour un aperçu de secours dans `FileUploadItemPreview`. |
| `FileUploadItemName` | Nom du fichier. |
| `FileUploadItemMetadata` | Type du fichier et taille formatée selon la locale. Passez-lui l’objet `file` courant. |
| `FileUploadItemSizeText` | Taille du fichier formatée selon la locale. |
| `FileUploadItemDeleteTrigger` | Supprime un fichier. Utilise par défaut l’icône de corbeille moduix ; son nom vient de `translations.deleteFile` d’Ark. |
| `FileUploadClearTrigger` | Bouton sans style qui efface les fichiers acceptés ; masqué tant que la liste est vide. Composez-le avec un `Button` via `asChild`. |

## Composition

`FileUpload` conserve l’état des fichiers en interne par défaut. Utilisez `defaultAcceptedFiles` pour une valeur initiale
non contrôlée, ou associez `acceptedFiles` à `onFileChange(details)` lorsque l’application possède cet état. Utilisez
`useFileUpload()` avec `FileUploadRootProvider` lorsque l’état ou les méthodes doivent être créés en dehors de l’arbre rendu.

Ajoutez explicitement `FileUploadHiddenInput` dans `FileUpload` ou `FileUploadRootProvider`, même hors d’un formulaire, car `FileUploadTrigger` l’utilise
pour ouvrir le sélecteur natif. Définissez `name` sur la racine pour la soumission native du formulaire. Si `FileUploadTrigger` est imbriqué
dans `FileUploadDropzone`, passez `disableClick` afin que le sélecteur ne s’ouvre qu’une seule fois.

Utilisez `FileUploadItems` dans `FileUploadItemGroup` pour les lignes de fichiers par défaut. Pour créer vos propres lignes, rendez
`FileUploadContext` et choisissez un seul aperçu par fichier depuis `acceptedFiles` ou `rejectedFiles`.

## Exemples

### Types de fichiers acceptés

Utilisez `accept` pour restreindre à la fois le sélecteur de fichiers natif et la validation du glisser-déposer. Vous pouvez
indiquer des types MIME ou des extensions de fichiers.

<Example name="file-upload/accepted-file-types" />

### Effacer la liste de fichiers

Utilisez `FileUploadClearTrigger` pour supprimer tous les fichiers acceptés en une seule action.

<Example name="file-upload/clear-trigger" />

### État contrôlé

Contrôlez `acceptedFiles` lorsque les fichiers sélectionnés doivent rester synchronisés avec l’état de l’application ou un
parcours en plusieurs étapes. Mettez la valeur à jour depuis `onFileChange(details)`.

<Example name="file-upload/controlled" />

### Téléversement d’un dossier

Utilisez `directory` pour laisser l’utilisateur sélectionner un dossier. Dans les navigateurs compatibles, le chemin relatif
de chaque fichier est disponible via `file.webkitRelativePath`. Définissez `maxFiles` à une valeur suffisamment élevée, ou
omettez-la si le nombre de fichiers est inconnu.

<Example name="file-upload/directory-upload" />

### Dropzone

Utilisez `FileUploadDropzone` pour le téléversement par glisser-déposer. Gardez un `FileUploadTrigger` imbriqué afin que les utilisateurs puissent
aussi ouvrir le sélecteur au clavier.

<Example name="file-upload/dropzone" />

### Gestion des erreurs

Utilisez `onFileReject(details)` pour afficher un message adapté à l’application. Définissez les contraintes intégrées,
comme `accept`, `maxFiles` et `maxFileSize`, sur le composant racine. Ajoutez `validate(file, details)` pour vos propres contrôles.

<Example name="file-upload/error-handling" />

### Aperçus des fichiers

Cet exemple contient déjà une image SVG et un PDF, ce qui permet de voir immédiatement les deux mises en page. Le bloc
d’aperçu des lignes de fichiers mesure par défaut 2,5rem sur 2,5rem, et les noms longs restent sur une seule ligne. Supprimez
l’un des éléments ou ajoutez vos propres fichiers pour tester ces deux présentations.

<Example name="file-upload/file-previews" />

### Utilisation dans un formulaire

Passez `name` au composant racine et ajoutez `FileUploadHiddenInput` ; les fichiers sélectionnés
participent alors à la soumission et à la réinitialisation du formulaire.

<Example name="file-upload/form-usage" />

### Fichiers initiaux

Utilisez `defaultAcceptedFiles` pour précharger des fichiers, puis laissez le composant gérer la sélection.

<Example name="file-upload/initial-files" />

### Capture avec l’appareil photo

Utilisez `capture` avec une valeur `accept` correspondant à une image ou une vidéo pour suggérer aux navigateurs mobiles
d’ouvrir l’appareil photo. Définissez-le sur `"user"` ou `"environment"` pour suggérer la caméra avant ou arrière. Il
s’agit d’une indication pour le navigateur, pas d’une garantie que l’appareil photo s’ouvrira.

<Example name="file-upload/media-capture" />

### Fichiers rejetés

Affichez `rejectedFiles` dans un groupe distinct `FileUploadItemGroup type="rejected"` lorsque les utilisateurs doivent voir pourquoi
la validation a échoué.

<Example name="file-upload/rejected-files" />

### Root Provider et collage de fichiers

Utilisez `useFileUpload` avec `FileUploadRootProvider` lorsque l’état ou les méthodes doivent être gérés en dehors de l’arbre de
téléversement affiché. Dans cet exemple, `setClipboardFiles` transmet à l’état du composant les fichiers collés dans une
zone de texte.

<Example name="file-upload/root-provider-and-paste" />

### Transformation des fichiers

Utilisez `transformFiles(files)` pour traiter les fichiers de manière asynchrone avant de les ajouter à l’état `acceptedFiles`.

<Example name="file-upload/transform-files" />

### Intégration avec Field

Placez le téléversement dans `Field` lorsque le champ de formulaire doit inclure un texte d’aide ou un message d’erreur,
ou indiquer qu’il est obligatoire ou invalide.

<Example name="file-upload/with-field" />

### Personnalisation avancée

Remplacez `FileUploadItems` par vos propres lignes lorsque vous avez besoin d’aperçus selon le type MIME, de métadonnées supplémentaires
ou d’une autre disposition. La composition explicite avec `FileUploadContext` vous permet de conserver l’accès à l’état Ark
et de choisir un aperçu d’image ou un aperçu de secours pour chaque fichier.

## Styles

Utilisez `className` en React ou `class` en Solid et Vue sur les parties exportées pour les styles structurels. Les variantes Tailwind
utilisent les utilitaires natifs et les classes du consommateur. Les variantes CSS Modules reposent sur les jetons de
foundation et n’ont pas de variables de composant : une classe sur la partie remplace les styles de la couche des composants.
Les deux solutions de styles partagent les attributs d’état d’Ark et les hooks `data-slot` de moduix.

La racine occupe toute la largeur de son conteneur ; limitez-la avec `max-width` dans une classe. Chaque élément est une
grille aux zones nommées `preview`, `name`, `meta` et `delete` : un enfant personnalisé sans zone se place sous le nom du fichier.

### Points d’accroche CSS

Utilisez des slots moduix stables, comme `[data-slot="file-upload-dropzone"]`,
`[data-slot="file-upload-item"]` et `[data-slot="file-upload-item-delete-trigger"]`.
Ark expose également `data-scope="file-upload"`, `data-part` pour les parties et les attributs d’état tels que
`data-disabled`, `data-readonly`, `data-invalid`, `data-required`, `data-dragging` et `data-type`.
