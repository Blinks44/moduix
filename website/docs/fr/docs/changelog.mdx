# Journal des modifications

<ChangelogNewsItem version="v3.2" dateTime="2026-11">

## Svelte rejoint React, Solid et Vue

<SvelteReleaseHero />

moduix prend désormais en charge Svelte 5. [`@moduix/svelte`](/docs/quick-start) et
`@moduix/svelte-tailwind` proposent tous les composants des autres adaptateurs, avec les mêmes noms
plats, les mêmes tokens et les mêmes thèmes.

Les composants s’utilisent comme du code Svelte habituel : runes, snippets et `bind:`. Les paquets
publient les sources `.svelte` : c’est le compilateur Svelte de votre application qui les construit,
et SvelteKit les rend côté serveur sans configuration supplémentaire. Pour garder les sources dans
votre dépôt, utilisez les registres `@moduix-svelte` et `@moduix-svelte-tailwind`.

Le [démarrage rapide](/docs/quick-start), la [configuration de SvelteKit](/docs/installation/sveltekit),
les [intégrations de formulaires](/docs/forms) et les [blocs](/blocks) couvrent désormais Svelte.
</ChangelogNewsItem>

## Vue rejoint React et Solid

<VueReleaseHero />

Vue rejoint React et Solid comme adaptateur natif de moduix. [`@moduix/vue`](/docs/quick-start) et
`@moduix/vue-tailwind` proposent le catalogue complet avec les mêmes tokens et thèmes.

### Changements incompatibles dans la version 3.0

Tous les composants utilisent désormais des exports nommés plats dans React, Solid et Vue, aussi bien
avec CSS Modules qu’avec Tailwind. Ce changement concerne les paquets npm et les sources du registre.
Lors de la mise à jour depuis la version 2.x, adaptez vos imports et les noms des composants :

| Avant | Maintenant |
| --- | --- |
| `Dialog.Root` | `Dialog` |
| `Dialog.Trigger` | `DialogTrigger` |
| `Dialog.Content` | `DialogContent` |
| `Dialog.RootProvider` | `DialogRootProvider` |
| `Dialog.Context` | `DialogContext` |

La même convention de nommage s’applique à toutes les familles de composants. Les exports composés
comme `Dialog.*` et les alias du composant racine comme `DialogRoot` ont été supprimés. Les hooks
comme `useDialog` restent disponibles sous forme d’exports nommés distincts.

### Composition Vue native

Utilisez les exports nommés plats dans des SFC avec `script setup`, des props et événements natifs,
`v-model` et des slots de portée. Les registres `@moduix-vue` et `@moduix-vue-tailwind` copient les sources Vue dans votre application.

Le [démarrage rapide](/docs/quick-start), les [intégrations de formulaires](/docs/forms) et les
[blocs](/blocks) incluent désormais Vue aux côtés de React et Solid dans les trois langues.
Les pages des composants décrivent les différences réelles des adaptateurs Ark et les limitations
upstream propres à certaines versions. Svelte reste prévu.

### Blocs installables

Les anciennes recettes deviennent des [blocs](/blocks) installables via le registre shadcn.
Les 12 blocs comprennent le code source React, Solid et Vue, une feuille de styles pour la mise en page et les
composants UI nécessaires. Choisissez CSS Modules ou Tailwind pour les composants ; les deux variantes utilisent
le même CSS Module pour la mise en page du bloc.

Après la [configuration du registre](/docs/quick-start), ajoutez un bloc avec une seule commande :

<PackageManagerTabs command="shadcn@latest add @moduix-react/login-simple" dlx />

La section d’installation de chaque bloc indique les commandes pour Solid, Vue et Tailwind.
</ChangelogNewsItem>

## Tailwind pour tout le catalogue

<TailwindReleaseHero />

Tailwind est maintenant disponible pour tout le catalogue moduix. [`@moduix/react-tailwind`](/docs/quick-start)
et `@moduix/solid-tailwind` couvrent les mêmes composants que les paquets CSS Modules.

L’API publique et le comportement des composants restent identiques. Le choix de Tailwind ne change
donc pas la manière de les composer.

Vos valeurs `className` ou `class` sont fusionnées après les valeurs par défaut avec `tailwind-merge`.
Les espaces de noms du registre `@moduix-react-tailwind` et `@moduix-solid-tailwind` incluent la
feuille de style de base, prête à être personnalisée.
</ChangelogNewsItem>

## Le catalogue complet pour Solid

<SolidReleaseHero />

Le catalogue complet de moduix est maintenant disponible pour Solid. [`@moduix/solid`](/docs/quick-start)
et `@moduix/solid-tailwind` utilisent les API natives de Solid et les primitives Ark UI.

Les composants Solid utilisent `class` et la composition native de Solid. Leurs contrats publics
correspondent à ceux des paquets React, tout en respectant le modèle de rendu de Solid.

CSS Modules et Tailwind sont tous deux disponibles pour Solid. Les deux variantes partagent les
tokens, les thèmes et les espaces de noms du registre `@moduix-solid` et `@moduix-solid-tailwind`.
</ChangelogNewsItem>

## Un sommaire pour les pages longues

<TableOfContentsHero />

[Table of Contents](/docs/table-of-contents) suit les titres visibles et indique la section active.
Indiquez les titres à suivre pour relier chaque entrée au titre correspondant.

Utilisez `TocContent` pour la zone de lecture et `TocNav` pour la liste des titres. L’entrée active
change au fil du défilement.

Utilisez `TocIndicator` ou `TocRail` pour montrer la hiérarchie. Ajoutez `TocRootProvider` lorsque
des contrôles externes doivent partager l’état du sommaire.
</ChangelogNewsItem>

## Des groupes de liens sans masquer les destinations

<NavigationMenuHero />

[Navigation Menu](/docs/navigation-menu) sépare les destinations directes des groupes de liens
associés. C’est utile pour la navigation principale d’un site ou d’un produit.

Utilisez `NavigationMenuLink` pour une destination directe. Pour un groupe de liens, associez
`NavigationMenuTrigger` à `NavigationMenuContent`.

Ajoutez `NavigationMenuViewport` lorsque plusieurs panneaux doivent s’animer dans une même zone.
Ark UI gère le clavier, le focus et l’élément ouvert. `NavigationMenuArrow` est facultatif.
</ChangelogNewsItem>

## Une figure cohérente pour les graphiques

<ChartHero />

[Chart](/docs/chart) ajoute une balise `figure` accessible autour de TanStack Charts. Définissez le
graphique avec TanStack, puis ajoutez l’en-tête, la légende, l’infobulle compacte et les réglages
d’animation de moduix.

TanStack garde la responsabilité des marques, des échelles, des interactions et des fonctions de
rappel. Composez le graphique avec `ChartHeader`, `ChartPlot` et `ChartLegend` pour obtenir une
structure `figure` cohérente.

TanStack gère aussi la navigation au clavier et le cycle de vie de l’infobulle. L’animation moduix
respecte la préférence pour la réduction des mouvements, et `motion={false}` la désactive.
</ChangelogNewsItem>

## Ark UI gère le comportement des composants

<V2MigrationHero />

Le système de composants utilise maintenant Ark UI pour l’état, les interactions et l’accessibilité
lorsqu’une primitive correspondante existe. moduix conserve ses CSS Modules, ses tokens de design et
ses deux modes d’installation.

Les composants qui disposent d’une primitive Ark UI l’utilisent pour l’état et les interactions. Ils
profitent aussi du comportement d’accessibilité fourni par Ark UI.

La composition publique et les propriétés de bas niveau suivent les contrats Ark. Installez le paquet
ou copiez le code source dans votre application si vous devez garder la main sur l’implémentation.
</ChangelogNewsItem>
