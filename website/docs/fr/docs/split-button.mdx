## Référence de l’API

Ark UI ne propose pas de primitive dédiée aux split buttons. moduix compose ce composant avec la
[fabrique Ark](https://ark-ui.com/docs/guides/composition#the-ark-factory) et préserve le comportement de
[Ark Menu](https://ark-ui.com/docs/components/menu).

## Choisir le bon composant

Utilisez `SplitButton` lorsqu’une action doit rester immédiatement disponible et que les alternatives associées
peuvent être regroupées dans un menu. Utilisez `Button` pour une seule action. Utilisez `Menu` lorsque les actions
sont au même niveau et qu’aucune ne doit être prioritaire.

## Anatomie

```text
SplitButton / SplitButton.Root
├─ SplitButton.Action
├─ SplitButton.Trigger
└─ Sous-arbre de la fenêtre contextuelle (placé automatiquement dans un portail)
   └─ SplitButton.Positioner
      └─ SplitButton.Content
         ├─ Menu.Item
         ├─ Menu.Separator
         └─ autres parties Menu partagées
```

| Partie                            | Rôle                                                                  |
| --------------------------------- | --------------------------------------------------------------------- |
| `SplitButton` / `SplitButton.Root` | Racine qui gère l’état du menu et le groupe sémantique des deux boutons. |
| `SplitButton.Action`              | Action principale `Button`.                                           |
| `SplitButton.Trigger`             | Déclencheur Ark Menu rendu comme un Button moduix, avec un chevron par défaut. |
| `SplitButton.Positioner`          | Positionne la fenêtre contextuelle Ark Menu.                           |
| `SplitButton.Content`              | Surface de contenu Ark Menu pour les parties `Menu.*` partagées.       |

## Composition

`SplitButton` associe une action principale `Action` à un `Trigger`. Gardez l’arbre de la fenêtre contextuelle
explicite : `Positioner` → `Content`, avec les éléments `Menu.*` partagés à l’intérieur de `Content`. Le positionneur
est placé automatiquement dans un portail ; utilisez `portalled={false}` ou `portalRef` uniquement lorsque la
fenêtre doit utiliser un autre conteneur. Les propriétés racine `size` et `variant` fournissent les valeurs par
défaut des deux boutons.

Le menu gère son état en interne par défaut. Passez `open` et `onOpenChange(details)` lorsqu’une autre partie de
l’application doit en être propriétaire. Pour un accès avancé à l’état, utilisez l’API `Menu` partagée plutôt
qu’une nouvelle enveloppe d’état propre à SplitButton. Utilisez `Action asChild` pour un lien ; le contenu visuel
personnalisé du déclencheur passe par `children`, afin que le déclencheur Ark et le Button moduix restent sur un seul
élément.

## Styles

Utilisez `className` en React ou `class` en Solid sur les parties exportées pour appliquer les styles structurels.
Les variantes Tailwind se personnalisent avec des utilitaires et des classes supplémentaires ; les variables
ci-dessous concernent les variantes CSS Modules. Les attributs de données et les hooks `data-slot` sont communs
aux deux modes de style.

L’apparence de boutons attachés associe les styles partagés de `Button` et `Menu` aux slots propres à SplitButton.
Le séparateur et le padding horizontal du déclencheur utilisent les variables
`--moduix-split-button-separator-*` et `--moduix-split-button-trigger-padding-x-*`.

### Points d’accroche CSS

- `data-scope="split-button"` et `data-part="root"` ciblent le groupe sémantique.
- `data-slot="split-button-root"` cible l’enveloppe du groupe.
- `data-slot="split-button-action"` cible l’action principale.
- `data-slot="split-button-trigger"` cible le déclencheur du menu.
- `data-slot="split-button-positioner"` cible le positionneur Ark Menu.
- `data-slot="split-button-content"` cible la surface de contenu Ark Menu.
- `SplitButton.Trigger` reçoit les attributs d’état d’Ark Menu, notamment `aria-expanded`, `aria-controls` et `data-state`.
- `SplitButton.Content` reçoit les attributs Ark Menu tels que `data-state`, `data-side`, `data-placement`,
  `data-nested` et `data-has-nested`.
