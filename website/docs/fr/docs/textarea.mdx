## Référence de l’API

Ark UI ne fournit pas de primitive `Textarea` autonome. Dans moduix, le composant s’appuie sur
[`Field.Textarea` d’Ark UI](https://ark-ui.com/docs/components/field) et conserve l’API native de
`textarea`. Il prend en charge `autoresize` et `asChild`, transfère la ref vers l’élément natif et
hérite de l’état de `Field`.

## Choisir le bon composant

Utilisez `Textarea` pour du texte libre qui peut s’étendre sur plusieurs lignes et doit conserver le
comportement natif d’une zone de texte dans le navigateur.

- Choisissez **`Input`** pour les valeurs courtes sur une ligne : noms, URL ou filtres compacts.
- Choisissez **`Textarea`** pour les notes, commentaires, descriptions et autres contenus longs saisis librement.
- Choisissez **`Editable`** pour un texte d’abord affiché, puis modifiable à la demande.
- Choisissez **`Field` + `Textarea`** lorsque le champ doit exposer de façon déclarative un libellé, une
  description, son caractère obligatoire ou sa validation.

## Utilisation de base

Placez `Textarea` dans `Field` lorsqu’il faut fournir au champ un libellé accessible ou un texte
complémentaire. C’est la configuration recommandée pour les commentaires, notes, descriptions de
tâches et contenus similaires.

## Anatomie

La structure publique se limite à une seule partie :

```text
Field (optional wrapper)
└─ Textarea
```

| Partie    | Rôle                                                              |
| --------- | ----------------------------------------------------------------- |
| `Textarea` | Élément `textarea` natif avec les styles moduix et l’état de `Field`. |

`Textarea` n’exporte ni conteneur supplémentaire, ni sous-composant, ni provider ou hook de contexte,
ni champ masqué, ni libellé ou compteur de caractères.

## Composition

### Composition recommandée

Conservez `Textarea` comme contrôle pour la saisie de texte multiligne ordinaire.

Utilisez-le directement avec des propriétés natives comme `rows`, `name`, `placeholder`, `maxLength`,
`readOnly`, `disabled`, `required`, `value`, `defaultValue` et `form`.

Placez-le dans `Field`, avec `Field.Label`, `Field.HelperText` et `Field.ErrorText`, lorsque le champ
doit exposer un libellé, un texte d’aide ou un message de validation de façon déclarative. En dehors
de `Field`, donnez-lui un nom accessible avec un `<label>` natif ou `aria-label`.

### Quand créer une composition personnalisée

Utilisez `Field.Textarea` uniquement si vous devez composer directement avec l’espace de noms `Field`.
Pour les cas courants, préférez `Textarea` afin que tous les contrôles multiligne partagent le même
contrat de styles moduix.

Pour une interface où le texte est d’abord affiché puis modifié, utilisez `Editable`.

### Propriétés par défaut

| Propriété | Valeur par défaut | Remarques |
| ------------ | ------- | ------------------------------------------------ |
| `autoresize` | `false` | Le redimensionnement automatique d’Ark est activé séparément pour chaque zone de texte. |

### Comportement

- Utilisez `value` et le gestionnaire natif `onChange` lorsque l’état React doit piloter le contenu.
- Définissez `name` pour inclure la zone de texte dans la soumission native du formulaire, puis lisez sa valeur via `FormData`.
- Lors d’une réinitialisation native du formulaire, un champ non contrôlé revient à `defaultValue`.
  Utilisez `form` pour associer la zone de texte à un formulaire situé en dehors de son sous-arbre DOM.
- La ref transmise pointe vers le véritable `HTMLTextAreaElement`. Avec `asChild`, fournissez un seul
  élément sémantique compatible avec `textarea`, capable de recevoir les propriétés fusionnées et la ref.
- Définissez `autoresize` lorsque la zone de texte doit grandir avec son contenu. Ark désactive le
  redimensionnement manuel lorsque cette option est active, donc `--moduix-textarea-resize` ne s’applique que lorsque
  `autoresize` vaut `false`.
- Pour un parcours où le texte est d’abord consulté puis modifié, utilisez `Editable`.

### Points d’accroche CSS

Utilisez la racine `Textarea` pour l’apparence du contrôle et le `Field` environnant pour la mise en
page et le texte complémentaire.

- La racine `Textarea` pour la bordure, l’arrière-plan, le placeholder, le comportement de redimensionnement et l’anneau de focus.
- Le conteneur `Field` pour la largeur, la largeur maximale, l’espacement, la disposition du libellé, la description et le message de validation.
- `data-slot="textarea-root"` pour un ciblage stable dans les styles à portée limitée.
- `data-autoresize` lorsque `autoresize` est activé.
- `data-invalid`, `[aria-invalid='true']`, `[disabled]`, `data-disabled`, `:read-only` et `data-readonly` pour les styles tenant compte de l’état.
