Ark UI ne propose pas de primitive `Stack` dédiée. moduix implémente ce composant avec la [fabrique
officielle d’Ark](https://ark-ui.com/docs/guides/composition#the-ark-factory) et suit ses recommandations pour la
[composition](https://ark-ui.com/docs/guides/composition), les [styles](https://ark-ui.com/docs/guides/styling) et
les [refs](https://ark-ui.com/docs/guides/ref). La documentation de [Stack](https://chakra-ui.com/docs/components/stack)
de Chakra UI sert uniquement de référence pour les noms des propriétés de mise en page.

## Anatomie

`Stack` rend un seul conteneur flex racine, basé sur le modèle de fabrique d’Ark. Il gère la direction, l’espacement,
l’alignement, le retour à la ligne et un simple changement de direction responsive. Gardez les règles de mise en page
plus générales dans votre CSS local.

```text
Stack / Stack.Root
└─ root[data-scope="stack"][data-part="root"][data-slot="stack-root"]
   └─ children
```

| Partie                 | Rôle                                                                    |
| ---------------------- | ----------------------------------------------------------------------- |
| `Stack` / `Stack.Root` | Conteneur flex racine pour la direction, l’espacement, l’alignement et l’écart entre les enfants. |

## Composition

### Composition recommandée

Utilisez la forme courte `<Stack>` pour rendre normalement un `div`. Utilisez `Stack.Root` lorsque la cohérence de
l’espace de noms est utile à côté de composants multipartites.

Utilisez `direction`, `gap`, `align`, `justify` et `wrap` pour les mises en page flex courantes. Utilisez `fill`
lorsqu’un `Stack` imbriqué doit s’étendre en tant qu’élément flex. Ajoutez directement le `Separator` de moduix comme
enfant lorsque la mise en page nécessite un séparateur visuel. Utilisez `asChild` lorsque la racine doit être rendue
sous la forme d’un élément sémantique.

### Quand créer une composition personnalisée

Passez au CSS local si la mise en page nécessite plusieurs conteneurs flex, des espacements différents selon les
points de rupture, des règles propres aux éléments ou un comportement responsive plus complexe que le simple
changement de direction mobile/desktop. Le CSS est également préférable lorsque plusieurs propriétés rendent la
composition difficile à lire.

Utilisez `style` pour remplacer ponctuellement les variables publiques `--moduix-stack-*` ou les propriétés flex
calculées.

### Propriétés par défaut

| Propriété   | Par défaut            | Remarques                                                               |
| ----------- | --------------------- | ----------------------------------------------------------------------- |
| `direction` | `column`              | `row`, `row-reverse`, `column`, `column-reverse` ou objet responsive     |
| `gap`       | valeur du navigateur  | Longueur CSS (`number` = `px`)                                          |
| `align`     | valeur du navigateur  | Toute valeur `align-items` valide                                       |
| `justify`   | valeur du navigateur  | Toute valeur `justify-content` valide                                   |
| `wrap`      | valeur du navigateur  | Toute valeur `flex-wrap` valide                                         |
| `fill`      | `initial`             | `true` définit `flex: 1 1 0` ; `false` définit `flex: initial`          |
| `asChild`   | `false`               | Composition avec la fabrique d’Ark et un seul élément enfant sémantique |

### Comportement

- `Stack` rend exactement une racine et lui transmet les propriétés DOM de la fabrique d’Ark.
- `direction={{ mobile, desktop }}` utilise la valeur desktop à partir de `640px`. Si une seule valeur est fournie,
  `Stack` la réutilise aux deux points de rupture.
- `direction` accepte également `row-reverse` et `column-reverse` pour inverser l’ordre visuel.
- `fill` agit sur le `Stack` en tant qu’élément flex, et non sur ses enfants.
- `Separator` est un enfant ordinaire. Marquez les séparateurs décoratifs avec `aria-hidden`.
- `gap`, `align`, `justify` et `wrap` ne sont écrits inline que lorsqu’ils sont fournis.
- `Stack` expose `data-scope="stack"`, `data-part="root"` et `data-slot="stack-root"` pour un style conforme aux
  conventions d’Ark.
- `Stack` n’ajoute ni enveloppes autour des éléments, ni comportement clavier, ni sémantique ARIA, ni contexte, ni
  état géré.

## Styles

### Propriétés CSS

`Stack` expose des variables CSS publiques sur sa racine. Par défaut, elles prennent les valeurs `column` et
`initial` ; les propriétés `direction` et `fill` écrivent des valeurs inline lorsqu’elles sont fournies, et `style`
peut les remplacer pour une instance donnée.

### Points d’accroche CSS

- `className` applique les styles à l’unique racine pour la largeur, les espacements internes, les bordures, les
  arrière-plans et les autres aspects visuels.
- `data-scope="stack"` et `data-part="root"` alignent l’enveloppe sur les conventions de style d’Ark.
- `data-slot="stack-root"` est le sélecteur moduix stable permettant de cibler la racine dans le CSS local.
- `style` est appliqué en dernier et peut donc remplacer les valeurs calculées de `gap`, `alignItems`,
  `justifyContent`, `flexWrap` et toute variable `--moduix-stack-*` écrite par les propriétés.
- Le contrat public ne contient aucun attribut d’état, aucune variable d’animation CSS et aucune map `slotProps`.
