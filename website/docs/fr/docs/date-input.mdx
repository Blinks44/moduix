## Choisir le bon composant

- Choisissez **`Input`** pour les valeurs textuelles ordinaires.
- Choisissez **`DateInput`** lorsque les utilisateurs doivent saisir une date au clavier et envoyer sa valeur dans un formulaire natif.
- Choisissez **`DatePicker`** lorsqu’ils ont besoin d’un calendrier dans une fenêtre contextuelle. `DateInput` privilégie
  la saisie au clavier et n’inclut pas de calendrier.

## Exemple de base

Utilisez `DateInput.Segments` pour afficher les segments de date dans l’ordre de la locale courante. Ark UI gère leur
ordre, l’édition au clavier, le focus, les espaces réservés et la synchronisation avec le formulaire. moduix fournit
les éléments visuels avec leur style et évite le code répétitif nécessaire dans le cas courant.

## Anatomie

```text
DateInput.Root
├─ DateInput.Label
├─ DateInput.Control
│  └─ DateInput.Segments
└─ champs natifs (automatiques)

Personnalisation avancée :

DateInput.SegmentGroup
└─ DateInput.SegmentContext
   └─ DateInput.Segment

DateInput.RootProvider
└─ le même arbre de parties relié au store créé par `useDateInput()`
```

| Partie                         | Rôle |
| ------------------------------ | ---- |
| `DateInput` / `DateInput.Root` | Gère la valeur de date, le formatage selon la locale, le focus des segments et la validation. |
| `DateInput.RootProvider`       | Relie les parties au store créé avec `useDateInput()`. |
| `DateInput.Label`              | Libellé accessible du champ de date. |
| `DateInput.Control`            | Cadre visuel autour d’un ou plusieurs groupes de segments. |
| `DateInput.SegmentGroup`       | Regroupe les segments pour un index de date. |
| `DateInput.Segment`            | Segment de date modifiable ou texte fixe renvoyé par Ark UI. |
| `DateInput.Segments`           | Affiche un groupe de segments adapté à la locale pour le cas courant. |
| `DateInput.Separator`          | Texte présenté entre les groupes d’une plage. |
| `DateInput.Context`            | Accès à l’état actuel du champ sans ajouter de balisage. |
| `DateInput.SegmentContext`     | Utilitaire de rendu Ark UI pour afficher des segments adaptés à la locale. |

## Composition

### Composition recommandée

Utilisez la forme abrégée du composant racine, `DateInput`, plutôt que `DateInput.Root`. Placez `DateInput.Segments`
dans `DateInput.Control` pour obtenir un groupe de segments standard adapté à la locale.

Le composant racine ajoute automatiquement les champs natifs nécessaires à la soumission et à la réinitialisation du
formulaire. Pour une plage, utilisez des `DateInput.Segments` indexés. Avec un `name="date"` commun, les noms envoyés
sont `date[0]` et `date[1]`. Pour utiliser des noms de base différents, transmettez le tuple `names` à deux éléments,
par exemple `names={['check-in', 'check-out']}`, qui produit `check-in[0]` et `check-out[1]`.

### Quand créer une composition personnalisée

Utilisez directement `DateInput.SegmentGroup`, `DateInput.SegmentContext` et `DateInput.Segment` lorsque les classes
ou l’affichage doivent varier selon le segment.
Utilisez `asChild` sur les parties Ark lorsqu’un élément hôte personnalisé est nécessaire. L’enfant doit être un élément
unique et sémantiquement adapté.
Utilisez `ids` lorsqu’un libellé externe, un texte d’aide ou un autre composant doit partager les mêmes identifiants.

### Propriétés par défaut

| Propriété                         | Valeur par défaut | Remarques |
| --------------------------------- | ----------------- | --------- |
| `DateInput` / `DateInput.Root`    | -                 | Aucun comportement spécifique par défaut ; les valeurs Ark UI s’appliquent. |
| `DateInput.Segments`              | -                 | Affiche un groupe de segments adapté à la locale pour un index donné. |
| `DateInput.names`                 | -                 | Deux noms de base pour les champs d’une plage ; Ark ajoute les index. |
| `DateInput.Separator.aria-hidden` | `true`            | Le texte du séparateur est masqué aux technologies d’assistance. |
| `DateInput.Separator.role`        | `presentation`    | Garde les séparateurs de plage hors de l’arbre d’accessibilité. |

### Comportement

- Les valeurs sont des objets `DateInputDateValue[]` provenant d’Ark et de `@internationalized/date`, et non des chaînes.
- `onValueChange(details)` conserve l’objet `details` d’Ark UI avec `details.value` et `details.valueAsString`.
- `focused`, `defaultFocused` et `onFocusChange(details)` contrôlent le focus de la racine.
- `placeholderValue`, `defaultPlaceholderValue` et `onPlaceholderChange(details)` contrôlent la date utilisée pour les segments vides.
- `selectionMode="range"` active les groupes de segments indexés et les champs natifs ajoutés automatiquement.
- `shouldForceLeadingZeros` détermine si les segments numériques sont complétés par des zéros initiaux.
- `min`, `max` et `isDateUnavailable` valident les dates saisies.
- `locale`, `timeZone`, `hourCycle`, `granularity`, `formatter`, `format`, `translations`, `dir` et
  `createCalendar` sont transmis à Ark UI. Pour une saisie limitée à l’heure, utilisez un formateur configuré sur
  `granularity="minute"` ou `"second"` lorsque la date n’est pas nécessaire.
- Importez `useDateInput()`, `useDateInputContext()` et `DateInputDateValue` depuis `@moduix/react`.
  Utilisez `DateInput.Context` ou `useDateInputContext()` pour lire l’état dans l’arbre de composants, et
  `DateInput.SegmentContext` pour personnaliser les segments. Les imports directs depuis Ark UI sont réservés aux types
  bas niveau et aux utilitaires que moduix n’exporte pas.

### Points d’accroche CSS

- `data-slot="date-input-root"` sur le composant racine.
- `data-slot="date-input-label"` sur le libellé.
- `data-slot="date-input-control"` sur le cadre visuel.
- `data-slot="date-input-segment-group"` sur chaque groupe de segments.
- `data-slot="date-input-segment"` sur les segments modifiables et fixes.
- `data-slot="date-input-hidden-input"` sur le champ natif masqué.
- `data-slot="date-input-separator"` sur le séparateur de plage fourni par moduix.
- Les attributs d’état Ark UI comprennent `data-disabled`, `data-readonly`, `data-invalid` et `data-focus` sur le
  contrôle et les groupes de segments, ainsi que `data-type`, `data-editable` et `data-placeholder-shown`.
