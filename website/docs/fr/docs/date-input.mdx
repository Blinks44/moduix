## Choisir le bon composant

- Choisissez **`Input`** pour les valeurs textuelles simples.
- Choisissez **`DateInput`** lorsque les utilisateurs doivent saisir une date segment par segment au clavier.
- Choisissez **`DatePicker`** lorsqu’un calendrier intégré ou contextuel est nécessaire. `DateInput` est conçu
  pour la saisie au clavier et n’inclut pas de calendrier.

## Anatomie

```text
DateInput / DateInput.Root
├─ DateInput.Label
├─ DateInput.Control
│  ├─ DateInput.Segments
│  └─ DateInput.Separator (facultatif, pour les plages)
└─ DateInput.HiddenInput[index] (explicite, un par date envoyée)

Personnalisation avancée :

DateInput.SegmentGroup
└─ DateInput.SegmentContext
   └─ DateInput.Segment

DateInput.RootProvider
└─ même arborescence reliée à un store useDateInput()
```

| Partie | Rôle |
| ---- | ---- |
| `DateInput` / `DateInput.Root` | Gère les valeurs, le formatage selon la locale, le focus des segments et la validation. |
| `DateInput.HiddenInput` | Contrôle de formulaire natif Ark à composer explicitement pour l’envoi. |
| `DateInput.RootProvider` | Relie les parties à l’état créé avec `useDateInput()`. |
| `DateInput.Label` | Libellé accessible du champ de date. |
| `DateInput.Control` | Cadre visuel autour d’un ou plusieurs groupes de segments. |
| `DateInput.SegmentGroup` | Regroupe les segments d’un index de date. |
| `DateInput.Segment` | Segment modifiable ou littéral fourni par Ark UI. |
| `DateInput.Segments` | Affiche un groupe de segments adapté à la locale pour le cas courant. |
| `DateInput.Separator` | Texte de présentation entre les groupes d’une plage. |
| `DateInput.Context` | Accès sans rendu à l’état courant du champ. |
| `DateInput.SegmentContext` | Aide au rendu des segments selon la locale. |

## Composition

Pour un champ standard, utilisez `DateInput` avec `DateInput.Control` et `DateInput.Segments`. Laissez l’état
non contrôlé avec `defaultValue`, contrôlez-le avec `value` et `onValueChange(details)`, ou créez-le avec
`useDateInput()` puis reliez les parties via `DateInput.RootProvider`. Les valeurs utilisent la forme
`DateInputDateValue[]` de `@internationalized/date`, et non des chaînes.

`DateInput.HiddenInput` est explicite, car la racine n’ajoute pas de champs natifs. Ajoutez un champ masqué pour
chaque date envoyée et utilisez les mêmes valeurs `index` pour une plage. Utilisez
`DateInput.SegmentGroup`, `DateInput.SegmentContext` et `DateInput.Segment` uniquement lorsque le rendu par défaut
de `DateInput.Segments` ne suffit pas.

## Styles

Utilisez `className` en React ou `class` en Solid sur les parties exportées pour les styles structurels. Les
variantes Tailwind utilisent les utilitaires natifs et les classes du consommateur. Les variantes CSS Modules
exposent également les variables de composant ci-dessous. Les attributs de données et les hooks `data-slot` sont
communs aux deux modes de style.

### Propriétés CSS

<CssPropertiesSection properties={DateInputDocs.dateInputOverrideCssProperties} />

### Points d’accroche CSS

- Sélecteurs `data-slot` stables : `date-input-root`, `date-input-root-provider`, `date-input-label`,
  `date-input-control`, `date-input-segment-group`, `date-input-segment` et `date-input-separator`.
- Les sélecteurs de parties Ark utilisent `data-scope="date-input"` et les valeurs `data-part` correspondantes.
- Les attributs d’état Ark incluent `data-disabled`, `data-readonly`, `data-invalid` et `data-focus` sur le control
  et les groupes de segments, ainsi que `data-type`, `data-editable` et `data-placeholder-shown` sur les segments.
