# Async List

`useAsyncList` gère les données asynchrones d’une collection et l’état des requêtes sans générer de
marquage. Il regroupe les éléments, le filtrage, le tri, la pagination, les chargements et les
erreurs, tandis que votre composant choisit la structure de la liste et l’affichage de ses états.

## Liste alimentée par un serveur

Utilisez les arguments de `load` pour transmettre à votre API le filtre, le curseur, le descripteur
de tri et le signal d’annulation courants. Retournez la page dans `items` et ajoutez un `cursor`
uniquement lorsqu’une autre page existe. `setFilterText` lance immédiatement un nouveau chargement,
et `loadMore()` ajoute la page suivante aux éléments déjà présents.

L’exemple copiable attend que `GET /api/users?query=...&cursor=...&sort=...&direction=...` renvoie
`{ users: User[], nextCursor?: string }`. Les éléments déjà chargés restent visibles pendant le
filtrage, le tri et le chargement d’une page supplémentaire. Transmettez `signal` à `fetch` pour
annuler les requêtes remplacées.

Pour un tri côté serveur, lisez `sortDescriptor` dans `load`, comme dans l’exemple. Pour un tri côté
client, fournissez plutôt `sort`. Cette fonction reçoit les `items` déjà chargés, le `descriptor`
choisi et `filterText`, puis peut retourner `{ items }` directement ou via une promesse. Le tri côté
client ne réorganise que les éléments en mémoire ; avec une pagination serveur, le tri serveur est
généralement préférable.

## Les éléments essentiels de l’API

### Configuration

| Option                  | Description                                                       | Valeur par défaut |
| ----------------------- | ----------------------------------------------------------------- | ----------------- |
| `load`                  | Fonction obligatoire qui renvoie `{ items, cursor }`.             | -                 |
| `sort`                  | Fonction de tri côté client, synchrone ou asynchrone.             | -                 |
| `autoReload`            | Charge les premiers éléments au montage du composant.          | `false`           |
| `initialItems`          | Éléments affichés avant le premier chargement réussi.            | `[]`              |
| `dependencies`          | Valeurs primitives stables qui relancent le chargement.           | `[]`              |
| `initialFilterText`     | Valeur initiale transmise à `load` dans `filterText`.             | `''`              |
| `initialSortDescriptor` | Descripteur initial `{ column, direction }`.                     | `undefined`       |
| `onSuccess`             | Callback avec `{ items }` après un chargement ou un tri réussi.   | -                 |
| `onError`               | Callback avec `{ error }` après un chargement ou un tri échoué.   | -                 |

Utilisez des valeurs primitives stables dans `dependencies`. Si une dépendance provient d’un objet
ou d’un tableau, dérivez d’abord la valeur qui doit réellement relancer le chargement.

### Contrat de `load`

`load` reçoit le contexte de la requête courante :

| Valeur            | Rôle                                                            |
| ----------------- | --------------------------------------------------------------- |
| `signal`          | `AbortSignal` de la requête active, ou `undefined`.              |
| `filterText`      | Valeur définie par `setFilterText`.                             |
| `cursor`          | Curseur de la page demandée par `loadMore()`.                   |
| `sortDescriptor`  | Descripteur `{ column, direction }` actuel, s’il existe.        |

Retournez `{ items }` pour la dernière page, ou `{ items, cursor }` lorsqu’une autre page est
disponible. Dans un descripteur, `column` est une clé du type des éléments et `direction` vaut
`'ascending'` ou `'descending'`.

### État et actions

| État             | Signification                                           |
| ---------------- | ------------------------------------------------------- |
| `items`          | Éléments actuellement présents dans la liste.           |
| `filterText`     | Texte du filtre actuel.                                 |
| `cursor`         | Curseur du dernier résultat.                            |
| `sortDescriptor` | Descripteur de tri actuel.                              |
| `loading`        | Un chargement ou un tri est en cours.                    |
| `sorting`        | Une opération de tri est en cours.                      |
| `empty`          | Le tableau `items` est vide.                             |
| `hasMore`        | Le dernier résultat contient un curseur.                 |
| `error`          | Erreur du dernier chargement ou tri échoué.              |

| Action                 | Rôle                                                 |
| ---------------------- | ---------------------------------------------------- |
| `reload()`             | Vide les éléments et lance un nouveau chargement.    |
| `loadMore()`           | Charge le curseur actuel et ajoute le résultat.      |
| `abort()`              | Annule la requête active.                            |
| `setFilterText(value)` | Définit le filtre et lance un nouveau chargement.    |
| `clearFilter()`        | Efface le filtre et lance un nouveau chargement.     |
| `sort(descriptor)`     | Applique un descripteur de tri.                      |

## Intégration et accessibilité

- `autoReload` vaut `false` par défaut. Appelez `reload()` si le chargement initial doit être lancé
  manuellement.
- `reload()` vide les éléments actuels avant le chargement. Affichez un état de chargement complet
  uniquement sans éléments ; conservez la liste pendant le filtrage, le tri et `loadMore()`.
- Transmettez `signal` à toute requête annulable. Une `AbortError` provenant d’une requête remplacée
  est ignorée : elle ne remplit pas `error` et n’appelle pas `onError`.
- `fetch` ne rejette pas sa promesse pour les réponses HTTP en erreur. Vérifiez `response.ok` et
  levez une erreur depuis `load` si la réponse n’est pas utilisable.
- Donnez un libellé accessible aux champs de recherche, exposez le chargement avec `role="status"`
  et les erreurs avec `role="alert"`. Utilisez `aria-busy` sur une liste qui reste visible pendant
  un chargement en arrière-plan.
- Ajoutez un debounce dans l’application si le filtrage doit attendre la fin de la saisie.

Le hook ne gère que les données et l’état des requêtes. Avec CSS Modules, utilisez la feuille de
style de votre application ; avec Tailwind, utilisez les native utilities et les classes du
consommateur. `async-list` ne fournit ni variables CSS, ni export Moduix, ni commande de registry.
