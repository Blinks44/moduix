# Async List

## Référence de l’API

<PrimitiveReference href="https://ark-ui.com/docs/collections/async-list" />

`useAsyncList` est un hook d’Ark UI qui centralise les éléments chargés et l’état des requêtes. Il
propose des actions pour recharger la liste, charger d’autres éléments, filtrer, trier et annuler
une requête. Il ne génère aucune interface : votre composant choisit comment afficher la liste et
ses états de chargement, de liste vide ou d’erreur.

Le hook est fourni par `@ark-ui/react/collection`. `@moduix/react` ne fournit pas ce hook, mais ses
composants `Button` et `Input` sont utilisés dans les exemples ci-dessous.

Si Ark UI n’est pas déjà installé dans votre application, installez-le d’abord :

```bash
npm install @ark-ui/react
```

```tsx
import { useAsyncList } from '@ark-ui/react/collection';
```

## Chargement

Définissez `autoReload: true` lorsque la première requête doit être lancée au montage du composant.
Cette option vaut `false` par défaut. Sans elle, appelez `list.reload()` lorsque l’application est
prête à charger les données.

Transmettez le `signal` reçu par `load` à `fetch` ou à une autre API qui prend en charge
l’annulation. Le hook pourra ainsi annuler une requête lorsqu’un nouveau chargement la remplace.

L’exemple exécutable utilise un petit jeu de données local et un court délai pour montrer le
chargement initial et l’actualisation. Il contient également les branches pour une liste vide et
pour une erreur, que vous pouvez relier à votre propre fonction de chargement.


Comme `reload()` vide les éléments actuels avant de lancer un nouveau chargement, affichez un état
de chargement complet lorsque `list.loading` est vrai et que la liste ne contient aucun élément.
Pendant un filtrage ou un tri, les éléments actuels restent disponibles tant que l’opération est en
cours.

## Configuration

| Paramètre               | Rôle                                                        | Valeur par défaut |
| ----------------------- | ----------------------------------------------------------- | ----------------- |
| `load`                  | Fonction obligatoire qui charge les données.                | -                 |
| `sort`                  | Fonction facultative de tri côté client, synchrone ou asynchrone. | -                |
| `autoReload`            | Lance le chargement initial au montage du composant.       | `false`           |
| `initialItems`          | Éléments affichés avant le premier chargement réussi.      | `[]`              |
| `dependencies`          | Valeurs qui relancent le chargement lorsqu’elles changent.  | `[]`              |
| `initialFilterText`     | Valeur initiale transmise à `load` dans `filterText`.       | `''`              |
| `initialSortDescriptor` | Descripteur de tri initial `{ column, direction }`.        | `undefined`       |
| `onSuccess`             | Appelée avec `{ items }` après un chargement ou un tri réussi. | -               |
| `onError`               | Appelée avec `{ error }` après l’échec d’un chargement ou d’un tri. | -          |

`dependencies` accepte les valeurs `string`, `number`, `boolean`, `null` et `undefined`. N’y
placez pas d’objets ni de tableaux ; dérivez plutôt des valeurs primitives stables.

## `load`

La fonction `load` reçoit l’état actuel de la liste et renvoie les éléments à afficher ensuite.

Chaque appel reçoit les valeurs suivantes :

| Valeur           | Rôle                                                        |
| ---------------- | ----------------------------------------------------------- |
| `signal`         | Signal d’annulation de la requête active. Peut être `undefined`. |
| `filterText`     | Texte actuel défini avec `setFilterText`.                   |
| `cursor`         | Curseur du résultat précédent lors du chargement d’éléments supplémentaires. |
| `sortDescriptor` | Colonne et direction de tri actuelles.                      |

Renvoyez un objet contenant `items` et, si d’autres données sont disponibles, un `cursor` pour le
chargement suivant :

```tsx
const list = useAsyncList<User, string>({
  autoReload: true,
  async load({ cursor, signal }) {
    const params = new URLSearchParams();

    if (cursor != null) params.set('cursor', cursor);

    const response = await fetch(`/api/users?${params}`, { signal });
    if (!response.ok) throw new Error('Could not load users');

    const data: { users: User[]; nextCursor?: string } = await response.json();
    return {
      items: data.users,
      cursor: data.nextCursor,
    };
  },
});
```

`sortDescriptor.column` est une clé du type des éléments, et `direction` vaut soit `'ascending'`,
soit `'descending'`.

## État et actions

| État             | Signification                              |
| ---------------- | ------------------------------------------ |
| `items`          | Éléments actuellement présents dans la liste. |
| `filterText`     | Texte du filtre actuel.                     |
| `cursor`         | Curseur de la page suivante.                |
| `sortDescriptor` | Descripteur de tri actuel.                  |
| `loading`        | Un chargement de données est en cours.      |
| `sorting`        | Une opération de tri est en cours.          |
| `empty`          | Le tableau d’éléments actuel est vide.      |
| `hasMore`        | Un curseur existe pour charger une autre page. |
| `error`          | Erreur du dernier chargement ayant échoué.  |

| Action                 | Rôle                                           |
| ---------------------- | ---------------------------------------------- |
| `reload()`             | Vide les éléments et lance un nouveau chargement. |
| `loadMore()`           | Charge le curseur actuel et ajoute le résultat. |
| `abort()`              | Annule la requête active.                       |
| `setFilterText(value)` | Définit le filtre et lance un nouveau chargement. |
| `clearFilter()`        | Efface le texte du filtre.                      |
| `sort(descriptor)`     | Applique un descripteur de tri.                |

## Filtrage

Le hook ne filtre pas les éléments par lui-même. Il conserve `filterText` et le transmet à `load` :
le filtrage peut donc être effectué côté serveur ou dans l’application.

```tsx
import { Input } from '@moduix/react/input';

function UserSearch() {
  const list = useAsyncList<User>({
    autoReload: true,
    async load({ filterText, signal }) {
      const params = new URLSearchParams({ query: filterText });
      const response = await fetch(`/api/users?${params}`, { signal });

      if (!response.ok) throw new Error('Search failed');
      return { items: await response.json() };
    },
  });

  return (
    <Input
      type="search"
      aria-label="Search users"
      value={list.filterText}
      onChange={(event) => list.setFilterText(event.currentTarget.value)}
    />
  );
}
```

`setFilterText` lance immédiatement un chargement. Ajoutez un mécanisme d’anti-rebond dans
l’application si vous préférez attendre que l’utilisateur cesse de saisir du texte. Le hook annule
les requêtes remplacées par une plus récente ; votre fonction de chargement ou le serveur définit
les règles de correspondance et le nombre maximal de résultats.

## Pagination

Renvoyez un curseur tant que d’autres données sont disponibles, puis appelez `loadMore()` :

```tsx
import { Button } from '@moduix/react/button';

{
  list.hasMore && (
    <Button type="button" onClick={() => list.loadMore()} loading={list.loading}>
      {list.loading ? 'Loading…' : 'Load more'}
    </Button>
  );
}
```

`hasMore` est dérivé du curseur renvoyé par le dernier résultat. Ne le calculez pas séparément.

## Tri

Pour un tri côté serveur, lisez `sortDescriptor` dans `load` :

```tsx
function useServerSortedUsers() {
  return useAsyncList<User>({
    autoReload: true,
    async load({ sortDescriptor, signal }) {
      const params = new URLSearchParams();

      if (sortDescriptor) {
        params.set('sort', String(sortDescriptor.column));
        params.set('direction', sortDescriptor.direction);
      }

      const response = await fetch(`/api/users?${params}`, { signal });
      if (!response.ok) throw new Error('Could not sort users');

      return { items: await response.json() };
    },
  });
}
```

Pour un tri côté client, fournissez `sort` :

```tsx
function useClientSortedUsers() {
  return useAsyncList<User>({
    autoReload: true,
    async load({ signal }) {
      const response = await fetch('/api/users', { signal });
      if (!response.ok) throw new Error('Could not load users');
      return { items: await response.json() };
    },
    sort({ items, descriptor }) {
      const direction = descriptor.direction === 'ascending' ? 1 : -1;

      return {
        items: items.toSorted(
          (a, b) =>
            String(a[descriptor.column]).localeCompare(String(b[descriptor.column])) * direction,
        ),
      };
    },
  });
}
```

La fonction `sort` reçoit les `items`, le `descriptor` et le `filterText` actuels. Elle peut
renvoyer les éléments triés directement ou via une promesse.

Le tri côté client porte uniquement sur les éléments déjà chargés. Préférez le tri côté serveur
lorsque la pagination est également gérée par le serveur ; trier une seule page chargée peut donner
des résultats trompeurs.

## Dépendances

Utilisez `dependencies` lorsqu’un filtre externe doit relancer le chargement de la liste :

```tsx
function useDepartmentUsers(department: string) {
  return useAsyncList<User>({
    autoReload: true,
    dependencies: [department],
    async load({ signal }) {
      const params = new URLSearchParams({ department });
      const response = await fetch(`/api/users?${params}`, { signal });

      if (!response.ok) throw new Error('Could not load users');
      return { items: await response.json() };
    },
  });
}
```

## Erreurs

Traitez séparément les requêtes en échec et celles qui ont été remplacées par une requête plus
récente. Transmettez `signal` aux requêtes annulables et utilisez `reload()` pour réessayer après
une erreur.

- Vérifiez `response.ok` : `fetch` ne rejette pas sa promesse pour les statuts HTTP d’erreur.
- Transmettez `signal` à chaque requête qui peut être annulée.
- Pendant un filtrage ou un tri, les éléments actuels restent disponibles. `reload()` vide les
  éléments avant de charger un nouveau résultat.
- Le hook ignore les requêtes qui se terminent par une erreur `AbortError` : elles ne définissent
  pas `error` et n’appellent pas `onError`.
- Utilisez `reload()` pour les actions de nouvelle tentative.
- Considérez `error` comme une donnée applicative de type inconnu et vérifiez son type avant de lire
  `.message`.
- Utilisez `onSuccess` et `onError` pour les effets externes, pas pour recopier l’état des éléments
  ou des erreurs du hook.
