# moduix

moduix est un système de composants multi-framework fondé sur [Ark UI](https://ark-ui.com/). Il associe
les primitives d’interaction accessibles d’Ark à des valeurs par défaut soignées, une composition
explicite et des tokens de design partagés. Chaque adaptateur conserve une API native pour son framework.

Commencez par le [Démarrage rapide](/docs/quick-start) pour choisir une méthode d’installation et
afficher votre premier composant.

## Prise en charge des frameworks

React et Solid sont disponibles dès maintenant. Vue et Svelte sont prévus et adopteront les mêmes
contrats de composants et les mêmes approches de style lors de leur sortie.

| Framework | Statut | Documentation |
| --------- | ------ | ------------- |
| React | Disponible | Code React natif et aperçus interactifs |
| Solid | Disponible | Code Solid natif aux côtés de l’aperçu React |
| Vue | Prévu | Ajouté après la sortie de l’adaptateur |
| Svelte | Prévu | Ajouté après la sortie de l’adaptateur |

Les onglets par framework apparaissent uniquement lorsque le code diffère réellement. Les concepts
communs restent en dehors des onglets afin de préserver une documentation concise lors de l’ajout de
nouveaux adaptateurs.

## Choisissez votre mode d’intégration

Choisissez un paquet si vous souhaitez recevoir les mises à jour via votre gestionnaire de paquets. Choisissez
le registre shadcn si vous voulez conserver le code source des composants, les styles et les utilitaires dans votre dépôt.

| Mode d’installation | Imports | À privilégier si |
| --- | --- | --- |
| Paquet | `@moduix/react/*` ou `@moduix/solid/*` | Vous voulez des mises à jour centralisées et un minimum de code géré par l’application. |
| Registre shadcn avec code source dans le projet | `@/components/ui/*` | Vous voulez garder la main sur le code source et ses modifications locales. |

Les deux approches exposent la même API, native pour le framework choisi, et le même système de
tokens. Choisissez le framework et l’approche de stylisation indépendamment de l’emplacement du code
source :

## Versions prises en charge

Les plages déclarées dans `peerDependencies` définissent les versions prises en charge :

| Technologie | Versions prises en charge | Utilisée par |
| ----------- | ------------------------- | ----------- |
| React et React DOM | 18 et 19 | `@moduix/react`, `@moduix/react-tailwind` |
| Solid | 1.9 et versions 1.x ultérieures | `@moduix/solid`, `@moduix/solid-tailwind` |
| Tailwind CSS | 4.x | Paquets et registres Tailwind uniquement |
| Ark UI | `^5.37.2` | Le paquet React ou Solid correspondant |

Votre gestionnaire de paquets vérifie ces plages à l’installation. Les paquets CSS Modules ne
requièrent pas Tailwind CSS.

## Ce que signifie « basé sur Ark »

Les composants complexes conservent le modèle Ark UI visible : parties nommées, état contrôlé et non
contrôlé, objets contenant les données de l’événement transmis aux fonctions de rappel, fournisseurs de
contexte, composition `asChild`, contrôles de formulaire natifs et attributs d’état. moduix ajoute les
styles des composants, des valeurs par défaut soignées, des compositions pratiques et des attributs
`data-slot` stables, sans masquer la structure des primitives nécessaire aux scénarios produit avancés.

Ark UI reste la référence pour le comportement des interactions et l’accessibilité. moduix fournit par-dessus une
couche produit avec des styles et des choix assumés.

## Ce que signifie « inspiré de shadcn »

L’influence de shadcn se retrouve dans des choix pratiques :

- des valeurs par défaut soignées qui paraissent cohérentes avant toute personnalisation ;
- une composition lisible, des variables CSS publiques et un code source faciles à inspecter ;
- un registre shadcn pour installer le code source dans le projet.

Cette influence ne lie pas CSS Modules à Tailwind et ne remplace pas l’anatomie Ark par des enveloppes
propres à shadcn. Les paquets Tailwind sont disponibles pour les composants déjà portés.

## Comment fonctionnent les styles

Les paquets CSS Modules utilisent des fichiers CSS classiques dont les noms de classe sont isolés
localement. Le paquet fournit les styles avec chaque point d’entrée, tandis que le registre copie les
mêmes sources et fichiers `.module.css` dans votre dépôt.

Les paquets Tailwind expriment les mêmes valeurs visuelles par défaut avec des classes utilitaires
et utilisent Preflight à la place de la réinitialisation facultative de moduix. Les deux approches
partagent les couleurs sémantiques de base, certains tokens globaux, les animations et le comportement
des composants :

- importez `style.css` une seule fois pour charger les tokens partagés et les styles de base ;
- utilisez `className` avec React ou `class` avec Solid sur la racine et les parties nommées ;
- ciblez les attributs stables `data-slot` et les attributs d’état d’Ark pour les règles liées à un état précis ;
- redéfinissez les variables `--moduix-*` pour définir le thème et les choix visuels partagés.

Dans les paquets CSS Modules, les couleurs, l’espacement, les rayons, la typographie, les anneaux de
focus, les animations, les ombres et les choix propres aux composants sont définis par des propriétés
CSS personnalisées. Remplacez un token sémantique pour modifier tout le système, un token de famille
partagé pour ajuster les composants liés, ou une variable `--<component>-*` pour une exception locale.
Les variantes Tailwind utilisent des utilitaires sémantiques et les classes fournies par
l’application au lieu de reproduire cette API de variables. Choisissez CSS Modules pour ne pas
dépendre de Tailwind, ou Tailwind si les classes utilitaires doivent rester directement modifiables
avec le code copié. Consultez [Tokens](/docs/tokens) pour la hiérarchie complète et
[Thèmes](/docs/themes) pour des préréglages prêts à l’emploi.

## Remerciements

moduix existe grâce au travail et aux idées de ces projets :

- [Ark UI](https://ark-ui.com/) pour les primitives accessibles fondées sur des machines à états,
  qui définissent le socle comportemental.
- [Chakra UI](https://chakra-ui.com/) pour l’ergonomie de composition alignée sur Ark et le
  savoir-faire en design system qui continuent d’inspirer moduix.
- [shadcn/ui](https://ui.shadcn.com/) pour la distribution de code ouvert, les belles valeurs par
  défaut et un style de documentation centré sur la maîtrise concrète du code.
- [Lucide](https://lucide.dev/) pour le jeu d’icônes open source utilisé dans toute la bibliothèque de composants.
- [UnoCSS](https://unocss.dev/) et [Tailwind CSS](https://tailwindcss.com/) pour les bases adaptées
  par le reset optionnel.
- [Rstack](https://rstack.rs/) pour son écosystème Rust : Rspress pour la documentation, Rslib pour
  la construction de la bibliothèque et Rstest pour les tests.
- [VoidZero](https://voidzero.dev/) pour les outils JavaScript utilisés dans tout l’espace de travail.
