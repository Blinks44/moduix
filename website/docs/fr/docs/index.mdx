# moduix

moduix est une bibliothèque de composants natifs pour React et Solid, construite sur
[Ark UI](https://ark-ui.com/). Elle associe les primitives d’interaction accessibles d’Ark à des
valeurs par défaut soignées, une composition explicite et des tokens de design partagés.

Pour l’essayer, choisissez une méthode d’installation dans le [Démarrage rapide](/docs/quick-start), ajoutez
`Button` à votre application, puis revenez ici lorsque vous voudrez comprendre le fonctionnement général du système.

Le langage visuel et le mode de gestion du code source s’inspirent de [shadcn/ui](https://ui.shadcn.com/) : les
composants doivent être soignés sans personnalisation préalable, et leur code source doit rester lisible et facile
à adapter dans votre application.

## Choisissez votre mode d’intégration

Choisissez le paquet npm si vous souhaitez recevoir les mises à jour via votre gestionnaire de paquets. Choisissez
le registre shadcn si vous voulez conserver le code source des composants, les styles et les utilitaires dans votre dépôt.

| Mode d’installation | Imports | À privilégier si |
| --- | --- | --- |
| Paquet npm | `@moduix/react/*` ou `@moduix/solid/*` | Vous voulez des mises à jour centralisées et un minimum de code géré par l’application. |
| Registre shadcn avec code source dans le projet | `@/components/ui/*` | Vous voulez garder la main sur le code source et ses modifications locales. |

Les deux approches exposent les mêmes contrats de composants natifs et le même système de tokens.
Choisissez le framework et le mode de style indépendamment de l’emplacement du code source :

| Framework | CSS Modules | Tailwind CSS |
| --- | --- | --- |
| React | `@moduix/react` | `@moduix/react-tailwind` |
| Solid | `@moduix/solid` | `@moduix/solid-tailwind` |

Les paquets React et Solid fondés sur des CSS Modules contiennent le catalogue complet. Les paquets
Tailwind s’enrichissent composant par composant ; vérifiez la page du composant avant de les choisir.
Le [Démarrage rapide](/docs/quick-start) explique la configuration complète de chaque approche.

## Ce que signifie « basé sur Ark »

Les composants complexes conservent le modèle Ark UI visible : parties nommées, état contrôlé et non contrôlé,
objets `details` transmis aux callbacks, fournisseurs de contexte, composition `asChild`, contrôles de formulaire
natifs et attributs d’état. moduix ajoute les styles des composants, des valeurs par défaut soignées, des compositions
pratiques et des points d’accroche `data-slot` stables, sans masquer la structure des primitives nécessaire aux scénarios produit avancés.

Ark UI reste la référence pour le comportement des interactions et l’accessibilité. moduix fournit par-dessus une
couche produit avec des styles et des choix assumés.

## Ce que signifie « inspiré de shadcn »

L’influence de shadcn se retrouve dans des choix pratiques :

- des valeurs par défaut soignées qui paraissent cohérentes avant toute personnalisation ;
- une composition lisible plutôt que des enveloppes surchargées de configuration ;
- des variables CSS publiques et un code source faciles à inspecter ;
- un registre shadcn pour installer le code source dans le projet ;
- une documentation qui présente d’abord le chemin principal sans masquer les options de bas niveau.

Les paquets CSS Modules ne requièrent pas Tailwind CSS, et aucun mode de style ne remplace l’anatomie
Ark par des contrats propres à shadcn. Tailwind est proposé dans des paquets séparés pour les
composants déjà portés.

## Comment fonctionnent les styles

Les paquets complets pour React et Solid utilisent des CSS Modules : des fichiers CSS classiques dont
les noms de classe sont isolés localement. Le paquet npm fournit les styles avec chaque point
d’entrée, tandis que le registre copie les mêmes sources et fichiers `.module.css` dans votre dépôt.

Les paquets Tailwind expriment le même contrat visuel avec des classes utilitaires et utilisent
Preflight à la place du reset optionnel de moduix. Les deux modes partagent les mêmes tokens,
préréglages, animations et comportements :

- importez `style.css` une seule fois pour charger les tokens partagés et les styles de base ;
- utilisez `className` avec React ou `class` avec Solid sur la racine et les parties nommées ;
- ciblez les attributs stables `data-slot` et les attributs d’état d’Ark pour les règles liées à un état précis ;
- surchargez les variables `--moduix-*` pour définir le thème et les choix visuels partagés.

Votre application peut continuer à utiliser du CSS classique, Tailwind CSS ou un autre outil pour sa
mise en page. Choisissez un paquet CSS Modules pour ne pas dépendre de Tailwind, ou un paquet Tailwind
si les classes utilitaires doivent rester directement modifiables avec le code copié.

## Le contrat de style

Dans l’échelle standard, les principaux contrôles font `36px` de haut et les lignes des éléments contextuels `32px`.
Cette échelle repose sur `--moduix-size-md` et `--moduix-size-sm`. Les champs de saisie, les boutons, les déclencheurs
Select et Combobox, les contrôles de date, la pagination, les éléments de menu et les composants associés la partagent.

Les couleurs, l’espacement, les rayons, la typographie, les anneaux de focus, les animations, les ombres et les choix
propres aux composants sont définis par des propriétés CSS personnalisées. Remplacez un token sémantique pour modifier
tout le système, un token de famille partagé pour ajuster les composants liés, ou une variable `--<component>-*` pour
une exception locale. Consultez [Tokens](/docs/tokens) pour la hiérarchie complète et [Thèmes](/docs/themes) pour des
préréglages prêts à l’emploi.

## Remerciements

moduix existe grâce au travail et aux idées de ces projets :

- [Ark UI](https://ark-ui.com/) pour les primitives accessibles fondées sur des machines à états,
  qui définissent le socle comportemental.
- [Chakra UI](https://chakra-ui.com/) pour l’ergonomie de composition alignée sur Ark et le
  savoir-faire en design system qui continuent d’inspirer moduix.
- [shadcn/ui](https://ui.shadcn.com/) pour la distribution de code ouvert, les belles valeurs par
  défaut et un style de documentation centré sur la maîtrise concrète du code.
- [UnoCSS](https://unocss.dev/) et [Tailwind CSS](https://tailwindcss.com/) pour les bases adaptées
  par le reset optionnel.
- [Rstack](https://rstack.rs/) pour son écosystème Rust : Rspress pour la documentation, Rslib pour
  la construction de la bibliothèque et Rstest pour les tests.
- [VoidZero](https://voidzero.dev/) pour les outils JavaScript utilisés dans tout l’espace de travail.
