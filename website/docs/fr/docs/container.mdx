## Référence de l’API

Ark UI ne fournit pas de primitive `container` dédiée. Dans moduix, `Container` est construit avec la
[fabrique officielle d’Ark](https://ark-ui.com/docs/guides/composition#the-ark-factory) et suit les recommandations d’Ark pour
la [composition](https://ark-ui.com/docs/guides/composition), le [style](https://ark-ui.com/docs/guides/styling) et la
[gestion des refs](https://ark-ui.com/docs/guides/ref).

## Exemple de base

Importez `Container` depuis `@moduix/react/container` lorsque vous avez besoin d’une colonne de contenu centrée et facile

## Anatomie

`Container` rend un seul élément racine et n’ajoute aucune enveloppe supplémentaire.

```text
Container / Container.Root
└─ enfants
```

| Partie                         | Rôle                                                                                  |
| ------------------------------ | ------------------------------------------------------------------------------------- |
| `Container` / `Container.Root` | Élément racine de mise en page. Centre le contenu et gère sa largeur ainsi que ses espacements horizontaux. |

## Composition

### Composition recommandée

Utilisez `Container` pour structurer une page, le corps d’un article, des sections de documentation, des écrans de
réglages et toute autre mise en page qui doit présenter une colonne de contenu centrée avec des espacements latéraux prévisibles.

`Container.Root` désigne le même composant via une notation d’espace de noms. Cette forme peut être utile pour rester
cohérent avec les autres composants qui suivent le modèle d’Ark.

Définissez `size` pour choisir la largeur du contenu et `gutter` pour choisir les espacements horizontaux. La prop
`asChild` remplace le `div` par défaut par un unique élément enfant. Choisissez un élément sémantique comme `main`,
`section` ou `article` lorsque l’enveloppe doit décrire la structure du document. La ref pointe vers l’élément racine
rendu, ou vers cet enfant lorsque `asChild` est utilisé.

Toutes les props standard d’un `<div>` sont transmises, notamment `className` et `style`.

### Quand créer une composition personnalisée

`Container` ne comporte qu’un élément racine, sans sous-parties, slots ni outils de mise en page imbriqués.

Pour les besoins courants, il suffit de choisir l’une des options suivantes :

- passez `className` pour appliquer des styles locaux à la mise en page ou au bloc ;
- surchargez les variables `--moduix-container-*` si la page a besoin d’autres valeurs de largeur ou d’espacement ;
- utilisez `asChild` lorsqu’un autre élément doit devenir le nœud DOM rendu ;
- associez le composant à `Bleed` lorsqu’un enfant doit dépasser les limites de la colonne de texte.

### Propriétés par défaut

| Propriété  | Valeur par défaut | Valeurs / remarques                                      |
| ---------- | ----------------- | -------------------------------------------------------- |
| `size`     | `lg`              | `xs` (40rem), `sm` (48rem), `md` (64rem), `lg` (72rem), `xl` (90rem), `full` (sans limite de largeur maximale) |
| `gutter`   | `md`              | `none`, `sm`, `md`, `lg`                                                             |
| `asChild`  | `false`           | Remplace le `div` racine par un seul élément enfant                                  |

### Comportement

- `Container` ne gère pas les espacements verticaux. Ajoutez-les à l’extérieur du composant ou sur ses enfants.
- `size="full"` supprime uniquement la limite de largeur maximale. Les espacements latéraux choisis restent appliqués,
  sauf avec `gutter="none"`.
- Le calcul de `max-width` inclut les deux espacements horizontaux : l’enveloppe contrainte conserve donc les espacements choisis.
- Avec `asChild`, fournissez exactement un élément enfant. La ref pointe alors vers cet élément.
- `Container` est purement structurel : il n’ajoute ni rôles ARIA, ni libellés, ni gestion du focus ou du clavier. Utilisez
  `asChild` avec `main`, `section` ou `article` lorsque l’enveloppe doit porter une information sémantique.
- L’élément racine expose `data-scope="container"`, `data-part="root"`, `data-slot="container-root"`, `data-size` et
  `data-gutter`, que vous pouvez cibler pour le style et les tests.

## Styles

Surchargez les variables CSS sur l’élément racine si l’enveloppe de page a besoin d’autres valeurs de largeur ou
d’espacement. Utilisez `className` pour les styles locaux du bloc, par exemple les espacements intérieurs, les bordures ou l’arrière-plan.

### Points d’accroche CSS

- `Container` et `Container.Root` exposent `data-slot="container-root"` sur le composant racine.
- `data-scope="container"` et `data-part="root"` suivent les conventions de style d’Ark.
- `data-size` sélectionne le préréglage de largeur : `xs`, `sm`, `md`, `lg`, `xl`, `full`.
- `data-gutter` sélectionne le préréglage d’espacement : `none`, `sm`, `md`, `lg`.
- Les variables `--moduix-container-*` contrôlent uniquement les espacements horizontaux et le calcul de la largeur maximale.
  L’espacement vertical et la disposition des enfants relèvent du CSS de mise en page environnant.
