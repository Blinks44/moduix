## Référence de l’API

`RadioGroup` suit la primitive radio-group d’Ark UI et ajoute les styles moduix, des attributs
`data-slot` stables et le composant pratique `RadioGroupOption`. Il est exporté depuis
`@moduix/react/radio-group`, `@moduix/solid/radio-group` et `@moduix/vue/radio-group`.

<PrimitiveReference href="https://ark-ui.com/docs/components/radio-group" />

## Choisir le bon composant

Utilisez `RadioGroup` lorsqu’une personne doit choisir une seule option parmi plusieurs options
visibles, par exemple un framework, un forfait ou un type de compte. Utilisez `Checkbox` pour des
choix indépendants et `Switch` pour un réglage qui s’applique immédiatement.

## Exemple de base


Utilisez `RadioGroup` comme racine et donnez une valeur à chaque option. `RadioGroupOption` affiche
un élément libellé avec son contrôle, son texte et son champ natif.

## Anatomie

```text
RadioGroup
├─ RadioGroupLabel
├─ RadioGroupIndicator (facultatif)
└─ RadioGroupItem[value]
   ├─ RadioGroupItemControl
   ├─ RadioGroupItemText
   └─ RadioGroupItemHiddenInput (explicite)

RadioGroupRootProvider
└─ le même arbre de parties connecté à useRadioGroup()

RadioGroupOption
└─ RadioGroupItem + RadioGroupItemControl + RadioGroupItemText + RadioGroupItemHiddenInput (composition fixe)
```

| Partie                        | Rôle                                                            |
| ---------------------------- | --------------------------------------------------------------- |
| `RadioGroup`       | Gère la valeur, la navigation au clavier, l’orientation et les formulaires. |
| `RadioGroupRootProvider`    | Relie les parties à l’état créé avec `useRadioGroup()`.         |
| `RadioGroupLabel`           | Libellé accessible du groupe.                                   |
| `RadioGroupItem`             | Une option sélectionnable ; rend un `label` par défaut.         |
| `RadioGroupOption`           | Élément pratique avec contrôle, texte et champ masqué.           |
| `RadioGroupItemControl`      | Contrôle radio visuel ; sa taille vient de `size` sur la racine. |
| `RadioGroupItemText`         | Texte visible de l’option.                                      |
| `RadioGroupItemHiddenInput`  | Champ natif pour la composition explicite de `RadioGroupItem`.             |
| `RadioGroupIndicator`        | Indicateur facultatif de l’élément actif, mesuré par Ark.        |

## Composition

Utilisez `defaultValue` pour un groupe non contrôlé. Utilisez `value` avec `onValueChange(details)`
lorsqu’une autre partie de l’application possède la valeur sélectionnée. Lorsque l’état doit être
créé en dehors de l’arbre rendu, utilisez `RadioGroupRootProvider` avec `useRadioGroup()` depuis le package du
framework correspondant. Ne rendez pas `RadioGroup` et `RadioGroupRootProvider` pour la même instance
d’état. React lit le store comme un objet ; Solid lit son état réactif via l’accessor retourné ; Vue expose le store
réactif directement dans le template.

`RadioGroupOption` inclut `RadioGroupItemHiddenInput` dans sa composition fixe. Avec une composition directe de
`RadioGroupItem`, ajoutez vous-même `RadioGroupItemHiddenInput`. Utilisez l’arbre explicite lorsque
les parties imbriquées doivent être placées ou configurées séparément, ou lorsque `asChild` doit
laisser un autre élément posséder le nœud DOM de l’option. Dans Solid, `asChild` utilise une fonction
de rendu ; dans Vue, utilisez `as-child`. Dans les deux cas, l’enfant direct doit rester un `label` sémantique.

`Field` fournit un libellé visible, un texte d’aide et un message d’erreur, mais ne transmet pas
son état à `RadioGroup`. Passez `disabled`, `invalid`, `readOnly` et `required` directement au groupe.
`Fieldset` transmet ses états Ark `disabled` et `invalid` aux groupes radio imbriqués.

## Exemples

### asChild

Utilisez `RadioGroupItem asChild` lorsqu’une carte ou une mise en page personnalisée doit posséder le
nœud DOM de l’option. Gardez un `label` sémantique comme enfant direct.

<Example name="radio-group/aschild" />

### État contrôlé

Gérez `value` avec `useState` dans React, `createSignal` dans Solid ou `ref` et `v-model` dans Vue lorsque la valeur sélectionnée
doit rester synchronisée avec le routage, les filtres ou l’interface environnante.

<Example name="radio-group/controlled" />

### Groupe désactivé

Définissez `disabled` sur la racine pour rendre toutes les options indisponibles tout en gardant la
valeur sélectionnée visible.

<Example name="radio-group/disabled" />

### Élément désactivé

Définissez `disabled` sur un `RadioGroupItem` ou un `RadioGroupOption` individuel lorsqu’une seule option doit être
indisponible.

<Example name="radio-group/item-disabled" />

### Formulaire

Passez `name` à la racine lorsque la valeur sélectionnée doit être envoyée dans un formulaire.
`RadioGroupOption` contient déjà le champ ; ajoutez `RadioGroupItemHiddenInput` à chaque `RadioGroupItem` personnalisé.

<Example name="radio-group/form" />

### Indicateur

Rendez `RadioGroupIndicator` lorsqu’un surlignage supplémentaire et mesuré est nécessaire pour
l’option active. Gardez l’indicateur et les boutons radio dans le même contexte de positionnement afin
qu’il suive la géométrie des options.

<Example name="radio-group/indicator" />

### Valeur initiale

Définissez `defaultValue` lorsque l’option initialement sélectionnée est connue et que le groupe doit
gérer seul les changements suivants.

<Example name="radio-group/initial-value" />

### Orientation

Définissez `orientation="horizontal"` lorsque la navigation avec les flèches doit suivre un groupe
horizontal. Placez les options dans un conteneur en ligne pour obtenir la même disposition visuelle.

<Example name="radio-group/orientation" />

### Root Provider

Utilisez `RadioGroupRootProvider` lorsqu’un store `useRadioGroup()` doit être partagé avec des contrôles situés
en dehors de l’arbre du groupe. L’exemple montre aussi comment modifier la valeur sélectionnée depuis
l’extérieur du groupe.

<Example name="radio-group/root-provider" />

### Tailles

Passez la prop moduix `size` à `RadioGroup` ou `RadioGroupRootProvider` pour changer le diamètre de tous les
contrôles radio du groupe. Les valeurs prises en charge sont `xs`, `sm`, `md` (par défaut), `lg` et `xl`.

<Example name="radio-group/sizes" />

### Avec Field

Utilisez `Field` lorsqu’un groupe radio a besoin d’un libellé, d’un texte d’aide ou d’un message
d’erreur au niveau du champ. Passez aussi `invalid` à `RadioGroup`, car `Field` ne définit pas
l’état de validation du groupe.

<Example name="radio-group/with-field" />

### Avec Fieldset

Entourez le groupe d’un `Fieldset` lorsque plusieurs options partagent une légende et appartiennent au
même formulaire. `Fieldset` peut également transmettre les états `disabled` et `invalid` au groupe
imbriqué.

<Example name="radio-group/with-fieldset" />

### Personnalisation avancée

Contournez `RadioGroupOption` et utilisez l’arbre complet de `RadioGroupItem` lorsque chaque partie imbriquée doit avoir
son propre placement, ses propres props ou son propre style.

<Example name="radio-group/advanced-customization" />

## Styles

Utilisez `className` dans React ou `class` dans Solid et Vue sur les parties exportées pour les styles
structurels. Pour les styles liés à l’état, préférez les attributs de données Ark comme `data-state`,
`data-disabled` et `data-orientation`, avec les sélecteurs `data-slot` de moduix. Les variantes
Tailwind utilisent les utilitaires natifs et les classes du consommateur ; les variables ci-dessous
personnalisent les variantes CSS Modules. Les attributs de données et les hooks `data-slot` sont
partagés par les deux approches de style.

### Points d’accroche CSS

- Hooks d’anatomie Ark : `data-scope="radio-group"` et `data-part` sur la racine, le libellé,
  l’option, le contrôle, le texte, le champ masqué et l’indicateur.
- Hooks d’état Ark : `data-state="checked|unchecked"`, `data-disabled`, `data-readonly`,
  `data-invalid`, `data-required`, `data-focus`, `data-focus-visible`, `data-hover`,
  `data-active` et `data-orientation`.
- Variables de l’indicateur Ark : `--transition-property`, `--left`, `--top`, `--width` et `--height`.
- Hooks moduix : `data-slot="radio-group-root"`, `radio-group-root-provider`,
  `radio-group-label`, `radio-group-item`, `radio-group-item-control`, `radio-group-item-text` et
  `radio-group-indicator`, ainsi que `data-size` sur la racine et `RadioGroupRootProvider`.
