## Anatomie

```text
createToaster()
└─ ToastToaster (portalled to document.body by default)
   └─ Toast
      ├─ ToastTitle
      ├─ ToastDescription
      ├─ ToastActionTrigger
      └─ ToastCloseTrigger
```

| Partie                         | Rôle                                                                                 |
| ------------------------------ | ------------------------------------------------------------------------------------ |
| `Toast`               | Racine d’une notification visible.                                      |
| `ToastToaster`        | Rend le store du toaster et gère le groupe de notifications.            |
| `ToastTitle`          | Partie du titre. Utilise le `title` de la notification courante sans enfant. |
| `ToastDescription`    | Partie de la description. Utilise la `description` courante sans enfant. |
| `ToastActionTrigger`  | Bouton d’action lié à `toast.action.onClick`.                           |
| `ToastCloseTrigger`   | Bouton de fermeture. Utilise `CloseButton` par défaut.                  |
| `ToastContext`        | Partie de contexte pour une composition personnalisée et l’accès direct à l’état. |

## Composition

Créez le toaster une seule fois, puis passez la même instance à `ToastToaster`. En Vue, créez-le dans
`<script setup>` pour que chaque instance du composant possède son propre store ; un store partagé
par l’application peut résider dans un module séparé. Pour le rendu côté serveur, créez un store
distinct pour chaque requête. Le store gère le placement, la pile, la file d’attente, les minuteurs et le focus. Par
défaut, `ToastToaster` rend le groupe via un portail vers `document.body` ; utilisez `portalled={false}` ou
`portalRef` s’il doit rester dans un autre conteneur. Aucun wrapper `Portal` séparé n’est nécessaire.

Pour une notification standard, utilisez le rendu par défaut de `ToastToaster`, qui affiche le titre, la
description, l’action et le bouton de fermeture. Pour une autre structure ou des contrôles personnalisés,
passez une render prop en React/Solid ou un slot par défaut avec portée en Vue, gardez `Toast`
comme élément extérieur et composez ses parties à l’intérieur. Le slot Vue reçoit les options de
la notification ; `useToastContext()` renvoie une computed ref. Pour `asChild` sur les boutons
d’action et de fermeture, utilisez un enfant bouton sémantique, et
`useToastContext()` lorsqu’un enfant personnalisé doit accéder directement à la notification courante.

Avec `@ark-ui/vue@5.39.3`, `asChild` sur `Toast` applique les attributs de la racine à un élément
interne auxiliaire, et `ToastToaster` ignore `asChild`. Conservez leurs éléments par défaut jusqu’à
la correction de ces compositions en amont. La composition avec `asChild` reste disponible pour
le titre, la description et les boutons d’action et de fermeture.

## Exemples

### Action

Ajoutez `action: { label, onClick }` lorsque la notification doit proposer une action directe.

<Example name="toast/action" />

### Durée

Définissez `duration` en millisecondes lorsqu’une notification doit disparaître plus tôt, rester
visible plus longtemps ou rester affichée jusqu’à sa fermeture manuelle avec `Infinity`.

<Example name="toast/duration" />

### Nombre maximal visible

Définissez `max` sur le toaster lorsque des rafales de notifications doivent être mises en file au
lieu de remplir l’écran.

<Example name="toast/max-toasts" />

### Pile sans chevauchement

Définissez `overlap: false` pour que chaque notification reste entièrement visible. Il s’agit d’un
réglage du toaster, pas d’un mode distinct du composant.

<Example name="toast/always-expanded" />

### Placement

Choisissez l’un des six placements d’Ark lorsque le groupe de notifications doit apparaître près d’un
bord précis de la fenêtre.

<Example name="toast/placement" />

### Promise

Utilisez `toaster.promise()` pour faire passer une même notification du chargement au succès ou à
l’erreur lorsque l’opération asynchrone se termine. Tant que le toast a le type `loading`, le rendu par
défaut affiche un `Spinner` décoratif avant le titre.

<Example name="toast/promise-toast" />

### Types

Utilisez les helpers typés du toaster pour les variantes liées au statut. Moduix applique les styles
`info`, `success`, `warning` et `error` via `data-type`.

<Example name="toast/types" />

### Mise à jour

Conservez l’identifiant renvoyé lors de la création d’une notification et transmettez-le à
`toaster.update()` lorsque la notification existante doit être modifiée sur place.

<Example name="toast/update" />

### Personnalisation avancée

Utilisez la render prop pour remplacer le rendu standard de `ToastToaster`, ajouter une icône, remplacer
l’icône de fermeture et appliquer des variables CSS propres au composant.

## Styles

Personnalisez `Toast` avec les attributs de parties Ark, les points d’accroche `data-slot` et des
classes sur ses parties. Les variantes CSS Modules lisent aussi les quatre variables ci-dessous ;
`--moduix-toast-bg`, `--moduix-toast-border-color` et `--moduix-toast-color` remplacent tous les types,
donc définissez-les dans `[data-type='success']` ou un sélecteur similaire pour un seul type. Les
variantes Tailwind utilisent les utilitaires natifs et les classes de l’application.

### Points d’accroche CSS

Utilisez la racine de `Toast` pour la surface, la bordure, les animations et les variantes par type.
Utilisez `ToastTitle`, `ToastDescription`, `ToastActionTrigger` et `ToastCloseTrigger` pour la
typographie et les contrôles internes.

Sélecteurs Ark utiles :

- `[data-scope='toast'][data-part='group']` sur `ToastToaster`
- `[data-scope='toast'][data-part='root']` sur `Toast`
- `[data-scope='toast'][data-part='title']` sur `ToastTitle`
- `[data-scope='toast'][data-part='description']` sur `ToastDescription`
- `[data-scope='toast'][data-part='action-trigger']` sur `ToastActionTrigger`
- `[data-scope='toast'][data-part='close-trigger']` sur `ToastCloseTrigger`
- `--x`, `--y`, `--scale`, `--z-index`, `--height`, `--opacity` et `--gap` sur `Toast`

Moduix ajoute également des points d’accroche stables : `data-slot="toast-toaster"`,
`data-slot="toast-root"`, `data-slot="toast-title"`, `data-slot="toast-description"`,
`data-slot="toast-action-trigger"` et `data-slot="toast-close-trigger"`.

Jusqu’à une largeur de fenêtre de `40rem`, chaque placement est centré horizontalement. Les toasts
gardent leur largeur de `20rem` et se rétrécissent entre les `offsets` d’Ark et les zones de sécurité
horizontales de l’écran.
