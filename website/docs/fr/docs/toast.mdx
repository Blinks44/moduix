`@moduix/react/toast`. Cette page présente les valeurs par défaut de moduix et les compositions
courantes. La référence Ark décrit l’API complète du gestionnaire de notifications et de ses parties.

## Anatomie

```text
createToaster()
└─ Toaster / Toast.Toaster (portalled to document.body by default)
   └─ Toast / Toast.Root
      ├─ Toast.Title
      ├─ Toast.Description
      ├─ Toast.ActionTrigger
      └─ Toast.CloseTrigger
```

| Partie                      | Rôle                                                                                      |
| --------------------------- | ----------------------------------------------------------------------------------------- |
| `Toast` / `Toast.Root`      | Racine d’une notification visible. `Toast.Root` est un alias de compatibilité de `Toast`. |
| `Toaster` / `Toast.Toaster` | Affiche le groupe de notifications associé au toaster.                                    |
| `Toast.Title`               | Partie du titre. Utilise le `title` de la notification courante si aucun enfant n’est passé. |
| `Toast.Description`         | Partie de la description. Utilise la `description` de la notification courante si aucun enfant n’est passé. |
| `Toast.ActionTrigger`       | Bouton d’action lié à `toast.action.onClick`. Passez `toast.action.label` comme contenu.   |
| `Toast.CloseTrigger`        | Bouton de fermeture. Utilise `CloseButton.Root` par défaut.                              |
| `Toast.Context`             | Partie de contexte pour une composition personnalisée. Utilisez `useToastContext()` pour accéder directement à l’état. |

## Composition

Par défaut, `Toaster` rend le groupe de notifications via un portail vers `document.body`.
Définissez `portalled={false}` pour conserver le groupe à l’emplacement de `Toaster`, ou passez
`portalRef` pour utiliser un autre conteneur. Aucun conteneur `Portal` séparé n’est nécessaire.

### Composition recommandée

Créez le toaster une seule fois, si possible en dehors du rendu du composant, puis passez la même
instance à `Toaster`. Le toaster gère le placement, le chevauchement, l’espacement, la taille de
la file, la durée, le délai de suppression, la mise en pause en cas d’inactivité et le raccourci de
focus `Alt+T`.

Dans une composition personnalisée rendue par la render prop, utilisez `Toast` comme élément racine.
`Toast.Root` reste disponible comme alias de compatibilité.

Sans render prop, `Toaster` utilise la structure standard de moduix. Elle affiche le titre et la
description lorsqu’ils sont présents, ajoute une action lorsqu’elle est définie et inclut un bouton
de fermeture, sauf si `closable: false` est défini. C’est le choix recommandé pour les retours
courants de l’application.

### Quand créer une composition personnalisée

Utilisez la render prop de `Toaster` lorsqu’une notification nécessite une autre structure, une icône
ou des contrôles personnalisés. Elle permet par exemple de remplacer l’icône de fermeture par défaut.
Conservez `Toast` comme élément extérieur afin qu’Ark puisse gérer la pile, la mesure de la hauteur,
la fermeture, la mise en pause, le focus clavier et les attributs de type et d’état.

Les parties Ark qui rendent un élément acceptent `asChild`. Lorsque vous remplacez `ActionTrigger` ou
`CloseTrigger`, utilisez un seul enfant sémantique et préservez le comportement d’un bouton.

Si un enfant personnalisé doit accéder directement à l’état de la notification, importez
`useToastContext()` depuis `@moduix/react/toast`.

### Propriétés par défaut

| Propriété                       | Valeur par défaut     | Remarques                                                                                  |
| ------------------------------- | --------------------- | ------------------------------------------------------------------------------------------ |
| `createToaster.duration`        | Selon le type         | Durée par défaut des nouvelles notifications. Remplacez-la pour une notification avec `duration`. |
| `createToaster.gap`             | `16`                  | Espacement entre les notifications.                                                       |
| `createToaster.max`             | `24`                  | Les nouvelles notifications sont mises en file lorsque la pile visible atteint cette limite. |
| `createToaster.hotkey`          | `["altKey", "KeyT"]` | Déplace le focus vers le groupe de notifications.                                         |
| `createToaster.offsets`         | `"1rem"`              | Décalage par rapport au bord sûr de la fenêtre.                                            |
| `createToaster.overlap`         | `false`               | Définissez `true` pour une pile avec chevauchement.                                        |
| `createToaster.pauseOnPageIdle` | `false`               | Définissez `true` pour suspendre les minuteurs lorsque la page est inactive.                |
| `createToaster.placement`       | `"bottom"`            | `top-start`, `top`, `top-end`, `bottom-start`, `bottom` ou `bottom-end`.                   |
| `createToaster.removeDelay`     | `200`                 | Garde les notifications fermées montées assez longtemps pour l’animation de sortie.       |
| `Toaster.portalled`             | `true`                | Définissez `false` pour rendre le groupe à l’emplacement de `Toaster`.                     |

### Comportement

- Appelez `toaster.create()` ou les helpers `success()`, `error()`, `warning()`, `info()`,
  `loading()`, `promise()`, `update()`, `dismiss()`, `remove()` et `dismissByPlacement()` sur le
  toaster.
- Lorsque `type` n’est pas précisé, Ark utilise `type: "info"` par défaut. Moduix applique aux types
  `info`, `success`, `warning` et `error` des variantes en forme de carte, alignées sur `Alert`.
- `toast.action` suit la forme `{ label, onClick }` et est rendu par `Toast.ActionTrigger`.
- `toast.duration` contrôle la durée d’une notification. `createToaster({ duration })` définit la
  valeur par défaut du toaster.
- `toast.onStatusChange(details)` reçoit les changements de statut Ark : `visible`, `dismissing` et
  `unmounted`.
- Lorsqu’une notification est créée dans un effet, différez l’appel à sa méthode avec
  `queueMicrotask(() => toaster.create(...))` pour éviter les avertissements React `flushSync`.
- `Toast` expose notamment les attributs d’état Ark `data-state`, `data-type`, `data-placement`,
  `data-align`, `data-side`, `data-mounted`, `data-paused`, `data-first`, `data-sibling`,
  `data-stack` et `data-overlap`.

### Accessibilité

Le comportement de région dynamique, le regroupement, la mise en pause, le raccourci de focus, le
cycle de fermeture et les callbacks de statut d’Ark restent disponibles. Utilisez la propriété
`label` de `Toaster` pour donner un nom accessible personnalisé au groupe de notifications.

`Toast.CloseTrigger` est par défaut un bouton dont le nom accessible est `Close toast`. Avec
`asChild`, l’enfant personnalisé doit conserver un nom accessible et la sémantique d’un bouton.
`Toast.ActionTrigger` reste également un bouton relié à `toast.action.onClick`.

### Points d’accroche CSS

Utilisez `Toast` pour la surface, la bordure, les animations et les variantes par type. Utilisez
`Toast.Title`, `Toast.Description`, `Toast.ActionTrigger` et `Toast.CloseTrigger` pour la typographie
et les contrôles internes.

Sélecteurs Ark utiles :

- `[data-scope='toast'][data-part='group']` sur `Toaster`
- `[data-scope='toast'][data-part='root']` sur `Toast`
- `[data-scope='toast'][data-part='title']` sur `Toast.Title`
- `[data-scope='toast'][data-part='description']` sur `Toast.Description`
- `[data-scope='toast'][data-part='action-trigger']` sur `Toast.ActionTrigger`
- `[data-scope='toast'][data-part='close-trigger']` sur `Toast.CloseTrigger`
- `--x`, `--y`, `--scale`, `--z-index`, `--height`, `--opacity` et `--gap` sur `Toast`

Moduix ajoute également des points d’accroche stables : `data-slot="toast-toaster"`, `data-slot="toast-root"`,
`data-slot="toast-title"`, `data-slot="toast-description"`, `data-slot="toast-action-trigger"`
et `data-slot="toast-close-trigger"`.

Jusqu’à une largeur de fenêtre de `40rem`, le groupe de notifications occupe toute la largeur de la
fenêtre et chaque élément racine utilise la variable Ark `--gap` pour conserver un espacement interne
sûr.
