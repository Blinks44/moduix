## Anatomie

```text
createToaster()
└─ Toaster / Toast.Toaster (portalled to document.body by default)
   └─ Toast / Toast.Root
      ├─ Toast.Title
      ├─ Toast.Description
      ├─ Toast.ActionTrigger
      └─ Toast.CloseTrigger
```

| Partie                         | Rôle                                                                                 |
| ------------------------------ | ------------------------------------------------------------------------------------ |
| `Toast` / `Toast.Root`         | Racine d’une notification visible. `Toast.Root` est un alias de compatibilité de `Toast`. |
| `Toaster` / `Toast.Toaster`    | Rend le store du toaster et gère le groupe de notifications.                       |
| `Toast.Title`                  | Partie du titre. Utilise le `title` de la notification courante sans enfant.       |
| `Toast.Description`            | Partie de la description. Utilise la `description` courante sans enfant.           |
| `Toast.ActionTrigger`          | Bouton d’action lié à `toast.action.onClick`.                                      |
| `Toast.CloseTrigger`           | Bouton de fermeture. Utilise `CloseButton` par défaut.                       |
| `Toast.Context`                | Partie de contexte pour une composition personnalisée et l’accès direct à l’état. |

## Composition

Créez le toaster en dehors du rendu du composant lorsque c’est possible, puis passez la même instance
à `Toaster`. Le toaster gère le placement, la pile, la file d’attente, les minuteurs et le focus. Par
défaut, `Toaster` rend le groupe via un portail vers `document.body` ; utilisez `portalled={false}` ou
`portalRef` s’il doit rester dans un autre conteneur. Aucun wrapper `Portal` séparé n’est nécessaire.

Pour une notification standard, utilisez le rendu par défaut de `Toaster`, qui affiche le titre, la
description, l’action et le bouton de fermeture. Pour une autre structure ou des contrôles personnalisés,
passez une render prop, gardez `Toast` ou `Toast.Root` comme élément extérieur et composez ses parties
à l’intérieur. Utilisez `asChild` uniquement avec un enfant bouton sémantique, et
`useToastContext()` lorsqu’un enfant personnalisé doit accéder directement à la notification courante.

### Points d’accroche CSS

Utilisez la racine de `Toast` pour la surface, la bordure, les animations et les variantes par type.
Utilisez `Toast.Title`, `Toast.Description`, `Toast.ActionTrigger` et `Toast.CloseTrigger` pour la
typographie et les contrôles internes.

Sélecteurs Ark utiles :

- `[data-scope='toast'][data-part='group']` sur `Toaster`
- `[data-scope='toast'][data-part='root']` sur `Toast`
- `[data-scope='toast'][data-part='title']` sur `Toast.Title`
- `[data-scope='toast'][data-part='description']` sur `Toast.Description`
- `[data-scope='toast'][data-part='action-trigger']` sur `Toast.ActionTrigger`
- `[data-scope='toast'][data-part='close-trigger']` sur `Toast.CloseTrigger`
- `--x`, `--y`, `--scale`, `--z-index`, `--height`, `--opacity` et `--gap` sur `Toast`

Moduix ajoute également des points d’accroche stables : `data-slot="toast-toaster"`,
`data-slot="toast-root"`, `data-slot="toast-title"`, `data-slot="toast-description"`,
`data-slot="toast-action-trigger"` et `data-slot="toast-close-trigger"`.

Jusqu’à une largeur de fenêtre de `40rem`, le groupe de notifications occupe toute la largeur de la
fenêtre et chaque élément racine utilise la variable Ark `--gap` pour conserver un espacement interne
sûr.
