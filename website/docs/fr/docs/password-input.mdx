## Choisir le bon composant

Utilisez `PasswordInput` lorsqu’une seule valeur sensible doit rester masquée par défaut, tout en pouvant être
affichée à la demande.

- Choisissez **`Input`** pour les valeurs sur une ligne qui n’ont pas besoin d’un bouton de visibilité.
- Choisissez **`PasswordInput`** pour les mots de passe, les clés d’API et les autres valeurs confidentielles.
- Choisissez **`InputGroup`** lorsque le champ nécessite une action intégrée personnalisée sans rapport avec la
  visibilité du mot de passe.

## Exemple de base

Pour un champ de mot de passe courant, utilisez `PasswordInput.Field`. Il rend le champ et le bouton de visibilité
avec les icônes moduix par défaut, tandis qu’Ark gère l’état et l’accessibilité.

## Anatomie

```tsx
<PasswordInput>
  <PasswordInput.Label />
  <PasswordInput.Field />
</PasswordInput>
```

Pour modifier la structure, remplacez `PasswordInput.Field` par les différentes parties Ark :

```tsx
<PasswordInput>
  <PasswordInput.Label />
  <PasswordInput.Control>
    <PasswordInput.Input />
    <PasswordInput.VisibilityTrigger>
      <PasswordInput.Indicator />
    </PasswordInput.VisibilityTrigger>
  </PasswordInput.Control>
</PasswordInput>
```

| Partie                                 | Rôle                                                                             |
| -------------------------------------- | ------------------------------------------------------------------------------ |
| `PasswordInput` / `PasswordInput.Root` | Gère la visibilité du mot de passe et l’état du champ.                          |
| `PasswordInput.RootProvider`           | Rend la racine à partir de l’objet d’état renvoyé par `usePasswordInput`.       |
| `PasswordInput.Label`                  | Associe un libellé au champ et reflète les états required, disabled, invalid et readOnly. |
| `PasswordInput.Field`                  | Rend la composition par défaut : contrôle, champ, bouton de visibilité et indicateur. |
| `PasswordInput.Control`                | Regroupe le champ et le bouton de visibilité.                                   |
| `PasswordInput.Input`                  | Élément `<input>` natif dont le `type` alterne entre `password` et `text`.      |
| `PasswordInput.VisibilityTrigger`      | Bouton qui affiche ou masque la valeur.                                         |
| `PasswordInput.Indicator`              | Affiche un contenu différent selon l’état ; moduix fournit les icônes par défaut. |

## Composition

### Composition recommandée

Utilisez `PasswordInput.Field` pour le contrôle, le champ, le bouton de visibilité et l’indicateur par défaut.
Transmettez à `PasswordInput` les options de la racine, comme la visibilité, l’état du formulaire, les identifiants,
la localisation des libellés et les réglages liés aux gestionnaires de mots de passe.

### Quand créer une composition personnalisée

Utilisez directement `Control`, `Input`, `VisibilityTrigger` et `Indicator` lorsque vous devez modifier la structure,
remplacer les icônes ou styliser les parties séparément. Utilisez `asChild` uniquement lorsqu’une partie doit rendre
un autre élément sémantique.

### Propriétés par défaut

| Propriété ou partie              | Valeur par défaut     | Description                                                    |
| -------------------------------- | --------------------- | ------------------------------------------------------------- |
| `autoComplete`                   | `"current-password"` | Transmis au champ ; vaut `current-password` par défaut.       |
| `defaultVisible`                 | non défini           | Le champ est masqué au départ ; cette propriété définit sa visibilité initiale en mode non contrôlé. |
| `visible`                        | non défini           | Contrôle la visibilité lorsqu’il est fourni.                 |
| `PasswordInput.Field`            | -                    | Composition par défaut des parties visibles ; transmet les propriétés du contrôle. |
| `onVisibilityChange`             | -                    | Reçoit les détails Ark ; utilisez `details.visible`.          |
| `translations.visibilityTrigger` | valeur Ark par défaut | Fonction qui renvoie un libellé localisé pour le bouton de visibilité. |
| `ignorePasswordManagers`         | `false`              | Ajoute des attributs qui permettent aux gestionnaires pris en charge d’ignorer le champ. |

### Comportement

- Pour contrôler la visibilité, associez `visible` à `onVisibilityChange(details)`.
- Pour contrôler ou initialiser la valeur, définissez les propriétés natives `value`, `defaultValue`, `placeholder` et
  `onChange` sur `PasswordInput.Input`.
- Transmettez à `PasswordInput` les propriétés de la racine d’Ark UI telles que `name`, `required`, `disabled`,
  `readOnly`, `invalid`, `ids` et `translations`.
- `PasswordInput.Input` est un élément `input` natif : il participe à la soumission et à la réinitialisation du
  formulaire. Définissez `name` sur `PasswordInput` ; ce composant ne rend pas de partie `HiddenInput` séparée.
- Utilisez `usePasswordInput` avec `PasswordInput.RootProvider` lorsqu’un autre composant doit accéder au même état
  de visibilité en dehors de l’arbre rendu.
- `PasswordInput.Input`, `PasswordInput.VisibilityTrigger` et `PasswordInput.Indicator` exposent
  `data-state="visible" | "hidden"` pour les styles.

## Styles

`PasswordInput` applique des styles à la coque du contrôle, à la zone de saisie et au bouton de visibilité à l’aide des
variables `--moduix-password-input-*`, en complément des styles partagés d’`Input`.

### Points d’accroche CSS

- La racine et le fournisseur de racine exposent `data-slot="password-input-root"` et
  `data-slot="password-input-root-provider"`.
- Les parties Ark utilisent l’attribut `data-scope="password-input"` et les valeurs de `data-part` pour `root`,
  `label`, `control`, `input`, `visibility-trigger` et `indicator`.
- Pour styliser la visibilité, utilisez `data-state="visible" | "hidden"` sur `input`, `trigger` et `indicator`.
  Pour les autres états, utilisez `data-disabled`, `data-invalid`, `data-readonly` et `data-required` sur les parties
  qui les reçoivent d’Ark. Le contrôle reçoit les attributs disabled, invalid et read-only utilisés par la coque du champ.
- Ark n’ajoute pas de variables CSS propres à ce composant. moduix fournit
  `--moduix-password-input-*` pour personnaliser son apparence.
