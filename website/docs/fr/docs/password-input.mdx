## Choisir le bon composant

Utilisez `PasswordInput` lorsqu’une valeur sensible unique doit rester masquée par défaut tout en pouvant être
affichée à la demande.

- Choisissez **`Input`** pour les champs de texte simples sans bouton de visibilité.
- Choisissez **`PasswordInput`** pour les mots de passe, les clés d’API et les autres chaînes confidentielles.
- Choisissez **`InputGroup`** lorsque le champ nécessite une action intégrée personnalisée sans rapport avec la visibilité du mot de passe.

## Utilisation de base

Utilisez `PasswordInput.Field` pour le champ et le bouton de visibilité standard. Il inclut les icônes moduix par
défaut tout en conservant la gestion d’état et le comportement d’accessibilité d’Ark.

## Anatomie

```tsx
<PasswordInput>
  <PasswordInput.Label />
  <PasswordInput.Field />
</PasswordInput>
```

Pour une personnalisation avancée, remplacez `PasswordInput.Field` par ses parties Ark explicites :

```tsx
<PasswordInput>
  <PasswordInput.Label />
  <PasswordInput.Control>
    <PasswordInput.Input />
    <PasswordInput.VisibilityTrigger>
      <PasswordInput.Indicator />
    </PasswordInput.VisibilityTrigger>
  </PasswordInput.Control>
</PasswordInput>
```

| Partie                                 | Rôle                                                                            |
| -------------------------------------- | ------------------------------------------------------------------------------ |
| `PasswordInput` / `PasswordInput.Root` | Gère la visibilité du mot de passe et l’état du champ.                         |
| `PasswordInput.RootProvider`           | Affiche la partie racine à partir d’un objet d’état `usePasswordInput`.         |
| `PasswordInput.Label`                  | Associe un libellé au champ et reflète les états required, disabled, invalid et readOnly. |
| `PasswordInput.Field`                  | Affiche la composition par défaut : contrôle, champ, bouton de visibilité et indicateur. |
| `PasswordInput.Control`                | Regroupe le champ et le bouton de visibilité.                                  |
| `PasswordInput.Input`                  | Champ natif dont le `type` alterne entre `password` et `text`.                 |
| `PasswordInput.VisibilityTrigger`      | Bouton qui bascule la visibilité.                                              |
| `PasswordInput.Indicator`              | Affiche le contenu selon l’état visible ou masqué ; moduix fournit les icônes par défaut. |

## Composition

### Composition recommandée

Utilisez `PasswordInput.Field` pour le contrôle, le champ, le bouton de visibilité et l’indicateur par défaut.
Transmettez à `PasswordInput` les options de visibilité, d’état du formulaire, d’identifiants, de traduction et de
gestion des gestionnaires de mots de passe.

### Quand créer une composition personnalisée

Utilisez directement `Control`, `Input`, `VisibilityTrigger` et `Indicator` lorsque vous avez besoin d’une autre
structure, d’autres icônes ou d’un style différent pour les parties. Utilisez `asChild` uniquement lorsqu’une partie
doit rendre un élément sémantique précis.

### Propriétés par défaut

| Propriété ou partie              | Valeur par défaut     | Description                                                    |
| -------------------------------- | --------------------- | ------------------------------------------------------------- |
| `autoComplete`                   | `"current-password"` | Transmis au champ ; vaut `current-password` par défaut.       |
| `defaultVisible`                 | `false`               | Visibilité initiale en mode non contrôlé.                     |
| `visible`                        | non défini           | Contrôle la visibilité lorsqu’il est fourni.                 |
| `PasswordInput.Field`            | -                     | Composition par défaut des parties visibles ; transmet les props de contrôle. |
| `onVisibilityChange`             | -                     | Appelée avec les détails Ark ; lisez `details.visible`.       |
| `translations.visibilityTrigger` | valeur Ark par défaut | Fonction qui fournit les libellés localisés du bouton de visibilité. |
| `ignorePasswordManagers`         | `false`               | Ajoute les indications qui aident à empêcher les gestionnaires de mots de passe d’afficher une superposition sur le champ. |

### Comportement

- Définissez `visible` et `onVisibilityChange(details)` pour contrôler la visibilité.
- Définissez les propriétés natives `value` et `onChange` sur `PasswordInput.Input` pour contrôler la valeur du champ.
- Transmettez à `PasswordInput` les propriétés racine d’Ark UI telles que `name`, `required`, `disabled`, `readOnly`, `invalid`, `ids` et `translations`.
- Utilisez `usePasswordInput` avec `PasswordInput.RootProvider` lorsqu’un autre composant a besoin du même état de visibilité en dehors de l’arbre affiché.
- `PasswordInput.Input`, `PasswordInput.VisibilityTrigger` et `PasswordInput.Indicator` exposent
  `data-state="visible" | "hidden"` pour les styles.

## Styles

`PasswordInput` applique des styles à la coque du contrôle, à la zone de texte et au bouton de visibilité à l’aide des
tokens `--moduix-password-input-*`, en complément des styles partagés d’`Input`.

### Points d’accroche CSS

- La racine et le fournisseur racine exposent `data-slot="password-input-root"` et
  `data-slot="password-input-root-provider"`.
- Les parties Ark conservent l’attribut `data-scope="password-input"` et les valeurs de `data-part` pour `root`,
  `label`, `control`, `input`, `visibility-trigger` et `indicator`.
- Pour styliser les états, utilisez `data-state="visible" | "hidden"` sur `input`, `trigger` et `indicator`, ainsi
  que `data-disabled`, `data-invalid`, `data-readonly` et `data-required` lorsqu’Ark les fournit.
- Ark n’expose pas de variables CSS propres au composant utilisables à l’exécution ; moduix ajoute
  `--moduix-password-input-*` pour les styles visuels par défaut.
