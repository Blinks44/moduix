## Choisir le bon composant

Utilisez `Slider` lorsque l’utilisateur doit ajuster une valeur numérique dans un intervalle défini, au pointeur ou au clavier.

- Choisissez **`Slider`** pour le volume, la luminosité, les budgets, les seuils et les plages à plusieurs poignées.
- Choisissez **`Input`** ou **`NumberInput`** lorsque l’utilisateur doit saisir une valeur exacte plutôt que la choisir en faisant glisser le curseur.
- Choisissez **`ProgressLinear`** ou **`ProgressCircular`** lorsque la valeur sert uniquement à l’affichage.

## Anatomie

```text
Slider
├─ SliderLabel
├─ SliderValueText
├─ SliderControl
│  ├─ SliderTrack
│  │  └─ SliderRange
│  └─ SliderThumb[index]
│     ├─ SliderDraggingIndicator
│     └─ SliderHiddenInput
└─ SliderMarkerGroup
   └─ SliderMarker[value]
```

| Partie                                  | Rôle                                                                    |
| --------------------------------------- | ----------------------------------------------------------------------- |
| `Slider`               | Racine Ark stylisée pour un état contrôlé ou non contrôlé.              |
| `SliderHiddenInput` | Champ natif d’Ark ; composition explicite décrite ci-dessous. |
| `SliderRootProvider`                  | Racine connectée à un état `useSlider` créé à l’extérieur.             |
| `SliderLabel`                         | Libellé visible du groupe.                                              |
| `SliderValueText`                     | Texte de la valeur actuelle généré par Ark.                             |
| `SliderControl`                       | Zone d’interaction au pointeur.                                         |
| `SliderTrack`                         | Piste visuelle complète.                                                |
| `SliderRange`                         | Partie remplie entre l’origine configurée et la valeur.                 |
| `SliderThumb`                         | Poignée du slider qui peut recevoir le focus.                           |
| `SliderThumbs`                        | Utilitaire moduix qui génère une poignée par valeur.                    |
| `SliderMarkerGroup` / `SliderMarker` | Groupe facultatif de repères et repère individuel.                      |
| `SliderDraggingIndicator`             | Bulle de valeur facultative affichée pendant le glissement.             |

## Composition

Utilisez `SliderThumbs` pour la composition standard avec une poignée par valeur : le composant
ajoute aussi un `SliderHiddenInput` par poignée. Lorsqu’une poignée doit contenir des enfants
personnalisés, porter un nom accessible ou suivre un ordre précis, composez explicitement
`SliderThumb` et placez-y un `SliderHiddenInput`. Définissez `name` sur la racine pour la
soumission du formulaire.

Pour un état contrôlé, stockez `details.value` fourni par `onValueChange` ou
`onValueChangeEnd` ; dans Vue, liez `v-model` à une ref pour le même contrat contrôlé. Utilisez
`useSliderContext` dans les descendants pour lire l’état. Si l’état doit être créé en dehors de
l’arbre rendu, créez-le avec `useSlider` et transmettez-le à `SliderRootProvider` ; ne rendez pas
une autre racine pour le même store. React lit le store comme un objet, Solid via l’accessor
retourné, et Vue expose directement le store réactif dans le template.

### Points d’accroche CSS

Ark ajoute `data-scope="slider"` et `data-part` à toutes les parties affichées. moduix ajoute également les valeurs
`data-slot` suivantes : `slider-root`, `slider-root-provider`, `slider-label`, `slider-value-text`, `slider-control`,
`slider-track`, `slider-range`, `slider-thumb`, `slider-marker-group`, `slider-marker` et
`slider-dragging-indicator`.

Les principaux attributs d’état d’Ark sont `data-orientation`, `data-disabled`, `data-invalid`, `data-focus`,
`data-dragging`, le `data-state` du repère et le `data-state="open | closed"` de l’indicateur de glissement. Les
variables CSS d’exécution d’Ark sont `--slider-thumb-width`, `--slider-thumb-height`, `--slider-thumb-transform`,
`--slider-range-start`, `--slider-range-end`, `--translate-x` et `--translate-y`.

moduix ajoute `data-readonly` à `Slider` lorsque la propriété `readOnly` est définie. Dans l’état invalide, la piste,
la plage sélectionnée, la poignée et les repères actifs utilisent par défaut la couleur destructive. Vous pouvez les
redéfinir séparément avec `--moduix-slider-track-border-color-invalid`, `--moduix-slider-range-bg-invalid`,
`--moduix-slider-thumb-border-color-invalid`, `--moduix-slider-thumb-focus-ring-color-invalid` et
`--moduix-slider-marker-dot-bg-active-invalid`.

L’anneau de focus par défaut de la poignée utilise `:focus-visible` pour le focus clavier et `data-dragging` d’Ark
pendant le glissement. Il disparaît lorsque le pointeur est relâché.
