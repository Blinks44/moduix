## Choisir le bon composant

Utilisez `Slider` lorsque l’utilisateur doit ajuster une valeur numérique dans un intervalle défini, au pointeur ou au clavier.

- Choisissez **`Slider`** pour le volume, la luminosité, les budgets, les seuils et les plages à plusieurs poignées.
- Choisissez **`Input`** ou **`NumberInput`** lorsque l’utilisateur doit saisir une valeur exacte plutôt que la choisir en faisant glisser le curseur.
- Choisissez **`ProgressLinear`** ou **`ProgressCircular`** lorsque la valeur sert uniquement à l’affichage.

## Exemple de base

`Slider.Thumbs` est la solution recommandée pour générer une poignée stylisée par valeur. Chaque poignée,
y compris un `Slider.Thumb` explicite, ajoute automatiquement son champ natif pour le formulaire.

## Anatomie

```text
Slider / Slider.Root
├─ Slider.Label
├─ Slider.ValueText
├─ Slider.Control
│  ├─ Slider.Track
│  │  └─ Slider.Range
│  └─ Slider.Thumbs
│     └─ Slider.Thumb[index]
│        ├─ Slider.DraggingIndicator
│        └─ champ natif (automatique)
└─ Slider.MarkerGroup
   └─ Slider.Marker[value]
```

| Partie                                  | Rôle                                                                    |
| --------------------------------------- | ----------------------------------------------------------------------- |
| `Slider` / `Slider.Root`               | Racine Ark stylisée pour un état contrôlé ou non contrôlé.              |
| `Slider.RootProvider`                  | Racine connectée à un état `useSlider` créé à l’extérieur.             |
| `Slider.Label`                         | Libellé visible du groupe.                                              |
| `Slider.ValueText`                     | Texte de la valeur actuelle généré par Ark.                             |
| `Slider.Control`                       | Zone d’interaction au pointeur.                                         |
| `Slider.Track`                         | Piste visuelle complète.                                                |
| `Slider.Range`                         | Partie remplie entre l’origine configurée et la valeur.                 |
| `Slider.Thumb`                         | Poignée du slider qui peut recevoir le focus.                           |
| `Slider.Thumbs`                        | Utilitaire moduix qui génère une poignée par valeur.                    |
| `Slider.MarkerGroup` / `Slider.Marker` | Groupe facultatif de repères et repère individuel.                      |
| `Slider.DraggingIndicator`             | Bulle de valeur facultative affichée pendant le glissement.             |

## Composition

### Composition recommandée

Utilisez l’arbre de parties Ark : racine, libellé, texte de valeur facultatif, zone de contrôle, piste, plage et
`Slider.Thumbs`. Le composant génère une poignée par valeur ; chaque poignée ajoute automatiquement son champ natif au formulaire.

`Slider` est la forme abrégée de la racine, équivalente à `Slider.Root`.

### Quand créer une composition personnalisée

Utilisez `asChild` lorsqu’une partie doit être rendue avec un élément personnalisé. Conservez un seul enfant sémantique
capable de recevoir les propriétés Ark. Utilisez un `Slider.Thumb` explicite lorsque certaines poignées nécessitent des
enfants personnalisés, des noms accessibles ou un ordre particulier ; le champ natif est toujours ajouté automatiquement.
Pour accéder à l’état de façon avancée, utilisez `Slider.Context` ou `useSliderContext` pour lire l’état sous la racine.
Pour créer l’état en dehors de l’arbre affiché, importez `useSlider` depuis `@moduix/react/slider` et utilisez-le avec
`Slider.RootProvider`.

### Propriétés par défaut

| Propriété                 | Par défaut   | Remarques                                                               |
| ------------------------- | ------------ | ----------------------------------------------------------------------- |
| `defaultValue`            | `[min]`      | Ark stocke les valeurs sous la forme `number[]`.                        |
| `orientation`             | `horizontal` | Utilisez `vertical` pour un axe clavier vertical.                       |
| `min`                     | `0`          | Limite inférieure.                                                      |
| `max`                     | `100`        | Limite supérieure.                                                      |
| `step`                    | `1`          | Pas utilisé par le pointeur et le clavier.                              |
| `largeStep`               | `10 * step`  | Pas utilisé par Page Up, Page Down et les touches Shift + flèche.        |
| `minStepsBetweenThumbs`   | `0`          | Nombre minimal de pas entre les poignées d’une plage.                   |
| `origin`                  | `start`      | Origine du remplissage pour un slider à valeur unique.                  |
| `thumbAlignment`          | `contain`    | Utilisez `center` pour laisser la poignée dépasser de la piste.          |
| `thumbCollisionBehavior`  | `none`       | Utilisez `push` ou `swap` pour modifier les collisions.                 |
| `thumbSize`               | mesuré       | Remplace les dimensions de poignée mesurées par Ark.                    |

`value`, `defaultValue`, `onValueChange(details)` et `onValueChangeEnd(details)` utilisent les objets `details` d’Ark.
Lisez le tableau dans `details.value`. `onFocusChange(details)` indique la poignée qui reçoit le focus. Lorsque
`defaultValue` est omis, la valeur initiale est `[min]`, soit `[0]` par défaut. Utilisez `ids` pour fournir des identifiants
stables lorsque d’autres éléments doivent référencer les parties du slider.

### Comportement

`Slider` suit le modèle WAI-ARIA du slider d’Ark. Donnez à chaque poignée un nom accessible avec `Slider.Label`,
`aria-label` ou `aria-labelledby`. Les sliders horizontaux utilisent les flèches gauche et droite ; les sliders
verticaux utilisent les flèches haut et bas. `Page Up`, `Page Down` et `Shift + ArrowUp` ou `Shift + ArrowDown` utilisent
`largeStep` (par défaut, `10 * step`). `Home` et `End` placent la poignée active sur les valeurs minimale et maximale.

Chaque `Slider.Thumb` ajoute automatiquement un champ de formulaire natif masqué. Il participe à la soumission du
formulaire et à sa réinitialisation. `id`, `asChild`, `disabled`, `invalid`, `readOnly`, `name`, `form`, `ids`,
`aria-label`, `aria-labelledby` et `getAriaValueText(details)` sont transmis à Ark.

### Points d’accroche CSS

Ark ajoute `data-scope="slider"` et `data-part` à toutes les parties affichées. moduix ajoute également les valeurs
`data-slot` suivantes : `slider-root`, `slider-root-provider`, `slider-label`, `slider-value-text`, `slider-control`,
`slider-track`, `slider-range`, `slider-thumb`, `slider-hidden-input`, `slider-marker-group`, `slider-marker` et
`slider-dragging-indicator`.

Les principaux attributs d’état d’Ark sont `data-orientation`, `data-disabled`, `data-invalid`, `data-focus`,
`data-dragging`, le `data-state` du repère et le `data-state="open | closed"` de l’indicateur de glissement. Les
variables CSS d’exécution d’Ark sont `--slider-thumb-width`, `--slider-thumb-height`, `--slider-thumb-transform`,
`--slider-range-start`, `--slider-range-end`, `--translate-x` et `--translate-y`.

moduix ajoute `data-readonly` à `Slider` lorsque la propriété `readOnly` est définie. Dans l’état invalide, la piste,
la plage sélectionnée, la poignée et les repères actifs utilisent par défaut la couleur destructive. Vous pouvez les
redéfinir séparément avec `--moduix-slider-track-border-color-invalid`, `--moduix-slider-range-bg-invalid`,
`--moduix-slider-thumb-border-color-invalid`, `--moduix-slider-thumb-focus-ring-color-invalid` et
`--moduix-slider-marker-dot-bg-active-invalid`.

L’anneau de focus par défaut de la poignée utilise `:focus-visible` pour le focus clavier et `data-dragging` d’Ark
pendant le glissement. Il disparaît lorsque le pointeur est relâché.
