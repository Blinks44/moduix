## Référence de l’API

Ark UI ne fournit pas de primitive dédiée aux titres. moduix s’appuie sur l’[Ark factory](https://ark-ui.com/docs/guides/composition#the-ark-factory) officielle et suit les recommandations d’Ark pour la [composition](https://ark-ui.com/docs/guides/composition), la [mise en forme](https://ark-ui.com/docs/guides/styling) et le [transfert des refs](https://ark-ui.com/docs/guides/ref).

## Anatomie

`Heading` comporte uniquement un élément racine. `Heading.Root` désigne le même composant sous la forme d’un espace de noms conforme aux conventions d’Ark.

```text
Heading / Heading.Root
└─ text or inline content
```

| Partie                     | Rôle                                                               |
| -------------------------- | ------------------------------------------------------------------ |
| `Heading` / `Heading.Root` | Titre sémantique natif avec la mise en forme typographique de moduix. |

## Composition

### Composition recommandée

Utilisez `<Heading>` pour `h1`. Pour choisir un autre niveau sémantique, transmettez `as="h2"`,
`as="h3"`, `as="h4"`, `as="h5"` ou `as="h6"` :

```tsx
<Heading as="h2" size="2xl">
  Page title rendered as h2
</Heading>
```

Utilisez `asChild` uniquement si l’élément enfant, qui doit être un titre sémantique, doit porter le nœud DOM
tout en recevant les props du composant, sa `className`, ses attributs `data-*` et la ref transmise.

### Quand créer une composition personnalisée

Pour modifier l’apparence, utilisez `className` et les variables publiques `--moduix-heading-*`. Si le contenu
est du texte courant ou relève de la typographie générale plutôt que d’un titre de document, utilisez `Text`.

### Propriétés par défaut

| Élément     | Valeur par défaut        | Valeurs et remarques                            |
| ----------- | ------------------------ | ----------------------------------------------- |
| element     | `h1`                     | Utilisez `as` pour `h2`-`h6`                    |
| `size`      | selon l’élément rendu    | `xs`, `sm`, `md`, `lg`, `xl`, `2xl`             |
| `weight`    | `semibold`               | `regular`, `medium`, `semibold`, `bold`         |
| `asChild`   | `false`                  | Composition via l’Ark factory                  |
| `className` | -                        | Appliqué à l’élément racine du titre rendu      |

### Comportement

- La taille visuelle par défaut dépend de l’élément rendu : `h1 -> 2xl`, `h2 -> xl`, `h3 -> lg`,
  `h4 -> md`, `h5 -> sm` et `h6 -> xs`.
- Une valeur `size` explicite remplace cette correspondance sans modifier la sémantique.
- La racine transmet la ref à l’élément de titre rendu.
- Les éléments de titre natifs portent déjà la sémantique nécessaire et n’ont pas besoin d’attribut ARIA supplémentaire.
  Ne transmettez pas à `asChild` un élément qui n’est pas un titre.
- `Heading` ne gère aucun état et n’expose ni callback, ni comportement clavier, ni provider, ni hook de contexte.

### Points d’accroche CSS

- `data-scope="heading"` identifie la portée du composant selon les conventions d’Ark.
- `data-part="root"` identifie l’unique partie racine.
- `data-slot="heading-root"` est un sélecteur moduix stable.
- `data-size` est présent lorsque `size` est défini explicitement.
- `data-weight` indique la graisse choisie : `regular`, `medium`, `semibold` ou `bold`.
- `Heading` définit ces attributs lui-même. Des props `data-*` du même nom ne peuvent pas remplacer le contrat de style du composant.
- Utilisez `className` et les variables `--moduix-heading-*` pour ajuster localement l’apparence.
