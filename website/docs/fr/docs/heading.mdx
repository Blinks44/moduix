## Référence de l’API

Ark UI ne propose pas de primitive dédiée aux titres. moduix implémente `Heading` avec la
[fabrique Ark](https://ark-ui.com/docs/guides/composition#the-ark-factory) officielle et suit les recommandations
d’Ark pour la [composition](https://ark-ui.com/docs/guides/composition), la [mise en forme](https://ark-ui.com/docs/guides/styling)
et le [transfert de ref](https://ark-ui.com/docs/guides/ref).

## Anatomie

`Heading` rend un seul élément de titre natif. Les formes `<Heading>` et `<Heading.Root>` sont équivalentes.

```text
Heading / Heading.Root
└─ texte ou contenu en ligne
```

| Partie                     | Rôle                                                               |
| -------------------------- | ------------------------------------------------------------------ |
| `Heading` / `Heading.Root` | Titre sémantique natif avec la mise en forme typographique de moduix. |

## Composition

### Composition recommandée

Utilisez `<Heading>` dans le cas courant d’un `h1`. Pour choisir un autre niveau sémantique, transmettez
à `as` une valeur de `h2` à `h6` :

```tsx
import { Heading } from '@moduix/react/heading';

<Heading as="h2" size="2xl">
  Page title rendered as h2
</Heading>
```

Utilisez `asChild` pour composer avec la fabrique lorsqu’un unique élément enfant sémantique de titre doit
porter le nœud DOM rendu. L’enfant reçoit les propriétés du composant, sa `className`, ses attributs `data-*`
et la `ref` transmise.

### Quand créer une composition personnalisée

Pour ajuster localement l’apparence, utilisez `className` et les variables publiques `--moduix-heading-*`.
Utilisez `Text` pour le texte courant, les libellés auxiliaires ou le texte en ligne, plutôt que pour un titre
de document.

### Propriétés par défaut

| Propriété   | Valeur par défaut        | Valeurs et remarques                            |
| ----------- | ------------------------ | ----------------------------------------------- |
| `as`        | `h1`                     | `h1` à `h6`                                     |
| `size`      | selon l’élément rendu    | `xs`, `sm`, `md`, `lg`, `xl`, `2xl`             |
| `weight`    | `semibold`               | `regular`, `medium`, `semibold`, `bold`         |
| `asChild`   | `false`                  | Composition via la fabrique Ark                |
| `className` | -                        | Appliqué à l’élément racine du titre rendu      |

### Comportement

- Lorsque `size` n’est pas défini, la taille visuelle dépend de l’élément rendu : `h1 -> 2xl`, `h2 -> xl`,
  `h3 -> lg`, `h4 -> md`, `h5 -> sm` et `h6 -> xs`.
- Une valeur `size` explicite remplace cette correspondance sans modifier la sémantique.
- La racine transmet la ref à l’élément de titre rendu.
- Les éléments de titre natifs fournissent la sémantique requise et n’ont pas besoin d’attribut ARIA supplémentaire.
  Ne transmettez pas à `asChild` un élément qui n’est pas un titre.
- `Heading` ne gère aucun état et n’expose ni callback, ni interaction au clavier, ni provider, ni hook de contexte.

### Points d’accroche CSS

- `data-scope="heading"` et `data-part="root"` identifient la racine selon les conventions d’Ark.
- `data-slot="heading-root"` est un sélecteur moduix stable.
- `data-size` est présent lorsque `size` est défini explicitement.
- `data-weight` indique la graisse choisie : `regular`, `medium`, `semibold` ou `bold`.
- `Heading` définit lui-même ces attributs. Les propriétés `data-*` correspondantes ne peuvent pas remplacer le contrat de style du composant.
- Utilisez `className` et les variables `--moduix-heading-*` pour ajuster localement l’apparence.
