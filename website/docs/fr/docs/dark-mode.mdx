# Mode sombre

moduix fournit des tokens sémantiques clairs et sombres. Chargez la feuille de styles correspondant au
framework et à la méthode de style choisis, puis placez `data-moduix-color-scheme` sur l’élément qui
porte le schéma. Aucun provider de thème ni état moduix n’est nécessaire.

## Choisir la portée

| Objectif | Emplacement de l’attribut |
| --- | --- |
| Thème de toute l’application | `<html>` |
| Surface intégrée sans portail | Conteneur de la surface |
| Surface intégrée avec portails | Conteneur de portail dans cette surface |

Préférez `<html>` pour une application classique afin que les composants ordinaires et portalled
reçoivent les mêmes tokens.

## Définir le schéma du document

Utilisez l’attribut natif comme source de vérité :

```html
<html data-moduix-color-scheme="dark"></html>
```

Les valeurs possibles sont `dark` et `light`. moduix ne lit pas la préférence du système, ne conserve
pas le choix et ne synchronise pas l’état du navigateur. L’application garde cette responsabilité.

Avec un rendu serveur, résolvez le schéma avant le premier affichage grâce au mécanisme précoce du
framework. Vous évitez ainsi un bref passage par la palette claire avant l’hydratation.

## Résoudre et conserver la préférence

La logique peut rester indépendante du framework. Le contrôle visible appelle simplement
`saveColorScheme()` avec le choix de l’utilisateur.

```ts
type ColorScheme = 'light' | 'dark';

export function applyColorScheme(scheme: ColorScheme) {
  document.documentElement.dataset.moduixColorScheme = scheme;
}

export function resolveColorScheme(): ColorScheme {
  const saved = localStorage.getItem('moduix-color-scheme');
  if (saved === 'light' || saved === 'dark') return saved;

  return matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light';
}

export function saveColorScheme(scheme: ColorScheme) {
  localStorage.setItem('moduix-color-scheme', scheme);
  applyColorScheme(scheme);
}
```

Suivez la préférence du système jusqu’à ce que l’utilisateur fasse un choix explicite. Donnez au
contrôle un nom accessible décrivant l’action, par exemple `Switch to dark mode`.

## Brancher un sélecteur de thème existant

Si votre application change déjà de thème avec une classe `dark`, comme les projets shadcn/ui,
next-themes avec `attribute="class"` ou `useDark()` de VueUse, associez cette classe au schéma de
couleurs natif. Les tokens moduix la suivent comme ils suivent l’attribut :

```css
.dark {
  color-scheme: dark;
}
```

Par défaut, la variante `dark:` de Tailwind suit la préférence du système d’exploitation. Si vous
changez de thème avec `data-moduix-color-scheme`, faites pointer la variante vers cet attribut pour
que vos utilitaires et les composants moduix changent ensemble :

```css title="styles.css"
@custom-variant dark (&:where([data-moduix-color-scheme='dark'], [data-moduix-color-scheme='dark'] *));
```

Avec une classe `dark`, conservez la variante que votre projet définit déjà pour cette classe.

## Combiner schéma et preset

Le schéma de couleur et le preset visuel sont indépendants. Placez les deux attributs sur la même
racine :

```html
<html data-moduix-color-scheme="dark" data-moduix-theme="dense"></html>
```

Changer le schéma ne modifie ni la densité ni les rayons. Consultez [Thèmes](/docs/themes) pour les
presets.

  </Tab>

  </Tab>
</Tabs>

Le contenu portalled sort du conteneur et n’en hérite pas les tokens. Si cette surface ouvre des
superpositions, déplacez l’attribut vers le conteneur de portail, `<body>` ou `<html>`.

:::warning Gardez `light-dark()` natif
Une surface délimitée ne change de schéma que si le navigateur exécute `light-dark()` nativement. Les
outils de build qui le remplacent pour les anciens navigateurs, comme Lightning CSS dans Rsbuild avec
les cibles par défaut, laissent les surfaces imbriquées dans le schéma de la page. Définissez un
`browserslist` adapté à moduix : Chrome et Edge 123+, Firefox 120+, Safari 17.5+.
:::

## Personnaliser les tokens

Chargez les redéfinitions de l’application après la feuille de styles moduix. Définissez les valeurs
claire et sombre dans une seule déclaration avec `light-dark()` :

```css
:root {
  --moduix-background: light-dark(oklch(0.99 0.004 285), oklch(0.16 0.01 285));
  --moduix-primary: light-dark(oklch(0.5 0.18 260), oklch(0.76 0.13 260));
}
```

`light-dark()` suit le schéma de couleurs, quelle que soit la façon de le changer : l’attribut, une
classe `dark` ou une surface délimitée. Les tokens non redéfinis conservent leur valeur intégrée.

## Vérifier le thème

- Testez le premier rendu serveur et l’hydratation.
- Ouvrez les contenus portalled de Dialog, Popover, Menu et Select.
- Vérifiez le contraste du texte, des bordures, du focus et des états désactivés.
- Confirmez que le choix enregistré prime sur la préférence du système.
- Testez les deux schémas avec chaque preset actif.
