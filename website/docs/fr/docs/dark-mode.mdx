# Mode sombre

Par défaut, moduix utilise son jeu de tokens clairs. Ajoutez l’attribut
`data-moduix-color-scheme="dark"` à un élément pour appliquer le jeu sombre à cet élément et à ses
descendants. Importez une seule fois la feuille de styles de base :

```tsx
import '@moduix/react/style.css';
```

## Définir le schéma sur la racine du document

Pour appliquer un thème à toute l’application, placez le schéma de couleurs obtenu sur `<html>`. Utilisez
`data-moduix-color-scheme="dark"` pour le mode sombre et `data-moduix-color-scheme="light"` pour le mode
clair. moduix ne détermine pas la préférence de l’utilisateur, ne la mémorise pas et n’impose aucun
fournisseur de thème. L’application garde la main sur la sélection et la persistance de ce réglage.

```html
<!-- Dark theme -->
<html data-moduix-color-scheme="dark"></html>
```

Les composants rendus dans un portail, comme Dialog, Popover et Select, héritent eux aussi des tokens
définis sur `<html>`.

Si votre application est rendue côté serveur, définissez l’attribut avant le premier affichage grâce au
mécanisme d’initialisation anticipée du thème de votre framework. Vous éviterez ainsi un bref affichage
du thème clair pendant que le JavaScript côté client applique la préférence enregistrée.

## Ajouter un sélecteur

Conservez dans l’application le choix explicite de l’utilisateur et mettez à jour l’attribut du document.
En l’absence de choix enregistré, utilisez `matchMedia` pour suivre la préférence du système.

```tsx
type ColorScheme = 'light' | 'dark';

export function applyColorScheme(scheme: ColorScheme) {
  document.documentElement.dataset.moduixColorScheme = scheme;
}

export function resolveColorScheme(): ColorScheme {
  const saved = localStorage.getItem('moduix-color-scheme');
  if (saved === 'light' || saved === 'dark') return saved;

  return matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light';
}

export function saveColorScheme(scheme: ColorScheme) {
  localStorage.setItem('moduix-color-scheme', scheme);
  applyColorScheme(scheme);
}
```

Exécutez l’équivalent de `applyColorScheme(resolveColorScheme())` dans le script d’initialisation
anticipée du thème de votre framework, avant le premier affichage. Le sélecteur visible doit appeler
`saveColorScheme` avec la valeur choisie par l’utilisateur. La préférence du système reste ainsi le
choix par défaut tant qu’aucun choix explicite n’a été fait. Donnez au sélecteur un nom accessible qui
décrit l’action, par exemple `Switch to dark mode`.

## Utiliser un preset

Le schéma de couleurs et les presets visuels sont deux niveaux indépendants, que vous pouvez donc
combiner. Définissez `data-moduix-color-scheme` et `data-moduix-theme` sur la même racine afin que les
composants ordinaires et ceux rendus dans un portail partagent la même palette, la même densité, le même
rayon et les mêmes tokens de focus.

```tsx
import '@moduix/react/style.css';
import '@moduix/react/presets/dense.css';
```

<div style={{ height: '1rem' }} aria-hidden="true" />

```html
<html data-moduix-color-scheme="dark" data-moduix-theme="dense"></html>
```

Changer de schéma de couleurs ne modifie pas la densité du preset. Le preset choisi reste actif dans les
deux modes. La comparaison des presets et la création d’un thème personnalisé sont présentées dans
[Thèmes](/docs/themes).

## Limiter la portée

Si les tokens sombres ne sont nécessaires que pour un aperçu ou une surface intégrée, définissez
`data-moduix-color-scheme="dark"` sur un conteneur ordinaire :

```tsx
import { Card } from '@moduix/react';
import '@moduix/react/style.css';

export function SettingsPreview() {
  return (
    <section data-moduix-color-scheme="dark">
      <Card>Dark preview</Card>
    </section>
  );
}
```

Cette approche convient aux aperçus de réglages et aux widgets intégrés. Le contenu rendu dans un portail
se trouve hors de ce conteneur et n’en hérite donc pas les tokens. Si la surface ouvre des éléments
superposés, placez plutôt l’attribut sur le conteneur du portail, `<body>` ou `<html>`.

## Personnaliser les tokens

Pour modifier la palette dans les deux schémas, redéfinissez les mêmes tokens de couleur de base dans
`:root` et `[data-moduix-color-scheme='dark']`. Les alias sémantiques comme
`--moduix-color-background`, `--moduix-color-foreground` et `--moduix-color-border` renvoient à ces
tokens de base ; les composants utilisent ainsi vos valeurs de manière cohérente dans toute la
bibliothèque.

Chargez la feuille de styles contenant vos redéfinitions après `style.css` :

```css
:root {
  --moduix-background: oklch(0.99 0.004 285);
  --moduix-primary: oklch(0.5 0.18 260);
}

[data-moduix-color-scheme='dark'] {
  --moduix-background: oklch(0.16 0.01 285);
  --moduix-primary: oklch(0.76 0.13 260);
}
```

Dans cet exemple, seuls la couleur d’arrière-plan et la couleur principale changent. Les autres tokens
conservent leurs valeurs intégrées. Consultez [Tokens](/docs/tokens) pour la référence des tokens système
et les pages des composants pour les redéfinitions visuelles locales.
