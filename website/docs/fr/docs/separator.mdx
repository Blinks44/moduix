## Référence de l’API

Ark UI ne fournit pas de primitive dédiée pour les séparateurs. moduix construit ce composant avec la [fabrique Ark](https://ark-ui.com/docs/guides/composition#the-ark-factory) officielle et suit les recommandations d’Ark en matière de [composition](https://ark-ui.com/docs/guides/composition), de [styles](https://ark-ui.com/docs/guides/styling) et de [ref](https://ark-ui.com/docs/guides/ref).

Ses propriétés `orientation`, `variant` et `size` reprennent le modèle familier du `Separator` de Chakra UI. Consultez la [documentation de Chakra UI relative à Separator](https://chakra-ui.com/docs/components/separator), qui a servi de référence pour cette API.

## Anatomie

`Separator` n’expose qu’une seule partie racine.

```text
Separator / Separator.Root
└─ root[data-scope="separator"][data-part="root"][data-slot="separator-root"]
```

| Partie                         | Rôle                                                                   |
| ------------------------------ | ---------------------------------------------------------------------- |
| `Separator` / `Separator.Root` | Élément séparateur racine. Définit l’orientation, les informations d’accessibilité et le style visuel. |

Utilisez `className` et les propriétés CSS `--moduix-separator-*` pour styliser la racine. Utilisez
`asChild` si un autre élément doit héberger le séparateur.

## Composition

### Composition recommandée

Pour la plupart des séparateurs, utilisez la forme courte `<Separator />`. Il s’agit du même composant racine
que `<Separator.Root />` ; vous pouvez donc passer de l’un à l’autre sans modifier le comportement.

### Quand créer une composition personnalisée

Utilisez `asChild` uniquement si vous devez faire porter le séparateur par un autre élément. `Separator` rend
déjà un séparateur sémantique. Son enfant doit être un élément unique capable de recevoir les attributs fusionnés
`role`, ARIA et `data-*`, ainsi que `className` et `ref`.

### Propriétés par défaut

| Propriété      | Valeur par défaut | Remarques                                         |
| -------------- | ----------------- | ------------------------------------------------ |
| `orientation`  | `horizontal`      | `horizontal`, `vertical`                        |
| `variant`      | `solid`           | `solid`, `dashed`, `dotted`                     |
| `size`         | `sm`              | `xs`, `sm`, `md`, `lg`                          |
| `asChild`      | `false`           | Composition avec la fabrique Ark et un enfant unique |
| `role`         | `separator`       | Transmettez `presentation` pour une ligne décorative |

### Comportement

- Lorsque son rôle est `separator`, `Separator` définit `aria-orientation` à partir de `orientation`. Pour un autre rôle, comme `presentation`, il omet `aria-orientation`, même si vous le transmettez vous-même.
- Utilisez `role="presentation"` lorsque la ligne est purement visuelle et n’apporte aucune information de structure aux technologies d’assistance.
- Les séparateurs horizontaux occupent toute la largeur disponible par défaut.
- Les séparateurs verticaux ont par défaut une hauteur de `1em`, ce qui les aligne naturellement sur le texte en ligne et les rangées d’actions compactes.
- `Separator` n’est pas interactif : il n’expose ni état, ni fonction de rappel, ni prise en charge de la désactivation, ni gestion du focus.
- Pour un simple espace, utilisez des primitives de mise en page ou des tokens d’espacement.

### Points d’accroche CSS

- `data-scope="separator"` et `data-part="root"` identifient la partie racine au format Ark.
- `data-slot="separator-root"` est le sélecteur moduix stable.
- `data-orientation="horizontal"` et `data-orientation="vertical"` permettent de cibler les styles propres à chaque axe.
- `data-size="xs|sm|md|lg"` et `data-variant="solid|dashed|dotted"` exposent les paramètres du style visuel.
- `className` et `style` s’appliquent directement à l’élément séparateur racine.
