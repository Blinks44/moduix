`EnvironmentProvider` indique à Ark UI quelle racine DOM, quel `Document` et quelle `Window` utiliser pour les composants fondés sur Ark. Il est utile lorsque l’arbre de composants est rendu en dehors du document principal de la page.

## Référence de l’API

<PrimitiveReference href="https://ark-ui.com/docs/utilities/environment" />

## Configuration de base

Placez `EnvironmentProvider` autour de tout le sous-arbre qui appartient à cet environnement. Sans `value`, il détecte l’environnement dans lequel le provider est rendu. Utilisez `useEnvironmentContext` lorsque le code de votre application doit accéder à la racine, au document ou à la fenêtre résolus.

L’aperçu utilise le document principal, le provider résout donc automatiquement `document`. Dans Solid, `useEnvironmentContext()` renvoie un accesseur : appelez-le avant de lire `getRootNode`, `getDocument` ou `getWindow`.

## Utiliser une racine personnalisée

Passez un objet `Document`, `ShadowRoot` ou une autre racine contrôlée par votre application via `value`. Le provider ne crée pas la racine, ne déplace pas le contenu et ne crée pas de portail. Montez vous-même le sous-arbre dans cette racine et transmettez la même racine à `EnvironmentProvider`.

Utilisez la forme fonctionnelle de `value` lorsque la racine n’est pas disponible au premier rendu, par exemple pendant le chargement d’une iframe ou avant la création d’un Shadow DOM.

Cet exemple ne nécessite que l’API d’environnement d’Ark, un `Button` du package moduix choisi et l’API de portail du framework. Si le framework sépare le rendu serveur et client, exécutez l’exemple dans un composant client :

## Iframes

Si vous utilisez `Frame` d’Ark UI, placez les composants intégrés directement à l’intérieur. `Frame` crée le point de
montage de l’iframe et fournit son document à Ark UI : il n’est donc pas nécessaire d’ajouter un autre
`EnvironmentProvider`. Consultez la page [Frame](/docs/frame) pour les styles, le cycle de vie et la sécurité des
iframes.
