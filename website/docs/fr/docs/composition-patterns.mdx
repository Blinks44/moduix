# Patrons de composition

Moduix conserve le modèle explicite des parties d’Ark. Commencez par les parties fournies,
réexportez-les pour stabiliser les imports du produit et n’ajoutez un wrapper que pour une décision
répétée du produit.

Ce modèle reste identique dans chaque adaptateur publié, avec un package npm ou le registre shadcn. Les onglets
ci-dessous ne séparent que les mécanismes propres au framework.

## Choisir un niveau de contrôle

| Besoin | Point de départ |
| --- | --- |
| Comportement standard | Parties Moduix fournies |
| Imports locaux du produit | Réexportations directes |
| Règle visuelle ou structurelle répétée | Wrapper ciblé autour de la partie responsable |
| État hors de l’arbre rendu | `use<Component>()` avec `<Family>RootProvider` |

Choisissez le niveau le plus simple qui couvre le besoin répété. Une classe ou un callback isolé ne
justifie pas une nouvelle API.

## Commencer par l’arbre des parties

Consultez l’anatomie de la page du composant avant de créer un wrapper. Gardez les parties
structurelles visibles pour préserver la responsabilité du placement, du défilement, du focus et des
styles.

```text
Dialog
├─ DialogTrigger
└─ Overlay subtree, automatically portalled
   ├─ DialogBackdrop
   └─ DialogPositioner
      └─ DialogContent
         ├─ DialogTitle
         ├─ DialogDescription
         └─ DialogCloseTrigger
```

Utilisez `portalled={false}` pour un rendu en ligne et `portalRef` pour un conteneur personnalisé si
le composant les prend en charge. `DialogRootProvider` sert uniquement à un état créé hors de l’arbre rendu.

## Composer un élément sémantique

Utilisez `asChild` lorsque l’élément existant doit rester le nœud DOM. React reçoit un enfant unique.
Solid reçoit une fonction de rendu qui transmet les propriétés d’Ark à l’élément retourné.

## Réexporter avant d’envelopper

Une réexportation stabilise l’import du produit sans modifier le comportement :

<Tabs groupId="framework">
  <Tab label="React" value="react">

```tsx
import { Dialog, DialogContent, DialogTrigger } from '@moduix/react/dialog';

export { Dialog, DialogTrigger, DialogContent };
```

  </Tab>
  <Tab label="Solid" value="solid">

```tsx
import { Dialog, DialogContent, DialogTrigger } from '@moduix/solid/dialog';

export { Dialog, DialogTrigger, DialogContent };
```

  </Tab>
</Tabs>

Le passage entre les imports du package et le code du registre reste alors simple.

## Déplacer l’état avec sa responsabilité

Utilisez `DialogContext` pour une lecture ponctuelle dans l’arbre et `useDialogContext()` dans un descendant
réutilisable. Créez l’état avec `useDialog()` et reliez-le à `DialogRootProvider` uniquement lorsque
des contrôles extérieurs au Dialog en ont besoin.

## Vérifier la frontière

- Gardez `DialogBackdrop`, `DialogPositioner`, `DialogContent` et les autres parties portant du sens visibles.
- Réexportez l’API avant de créer un wrapper.
- Transmettez les propriétés, classes et références d’origine.
- N’ajoutez une propriété publique que pour une décision répétée du produit.
- Testez le clavier, le retour du focus, les portails et l’état contrôlé.
