## Anatomie

```text
Avatar.Root | Avatar.RootProvider
├─ Avatar.Fallback
└─ Avatar.Image
```

| Composant | Rôle |
| ------------------------ | ----------------------------------------------------------------- |
| `Avatar` / `Avatar.Root` | Crée l’élément racine et gère l’état de l’avatar Ark UI. |
| `Avatar.RootProvider` | Relie l’avatar à un état Ark UI créé en dehors de son arbre. |
| `Avatar.Fallback` | Affiche le contenu fourni par le consommateur jusqu’au chargement de l’image. |
| `Avatar.Image` | Affiche l’image après un chargement réussi. |

## Composition

Gardez `Avatar.Fallback` et `Avatar.Image` sous la même racine afin qu’Ark UI puisse gérer leur visibilité. Lorsqu’une autre partie de l’application possède l’état, créez-le avec `useAvatar()` du framework concerné et transmettez-le directement à `Avatar.RootProvider` ; ne rendez pas une seconde racine pour le même store. React reçoit le store comme un objet, tandis que Solid reçoit un accessor réactif. Pour un rendu d’image personnalisé, utilisez `useAvatarContext()` et conservez les états masqué et visible renvoyés par `getImageProps()`. Utilisez `asChild` avec un seul enfant sémantique lorsqu’un autre élément doit porter le nœud DOM racine.

## Styles

Utilisez `className` et les variables CSS de moduix pour modifier l’apparence. Utilisez les attributs de
données fournis par Ark lorsque le style dépend de l’état de l’image.

### Propriétés CSS

<CssPropertiesSection properties={AvatarDocs.avatarCssProperties} />

### Points d’accroche CSS

- `data-slot="avatar-root"`, `avatar-root-provider`, `avatar-image` et `avatar-fallback`.
- Attributs d’anatomie Ark : `data-scope="avatar"` et
  `data-part="root" | "image" | "fallback"`.
- État de l’image géré par Ark : `data-state="visible" | "hidden"` sur `Avatar.Image` et
  `Avatar.Fallback`.
- Attribut de taille de moduix : `data-size="xs" | "sm" | "md" | "lg" | "xl"` sur
  `Avatar.Root` et `Avatar.RootProvider` lorsque `size` est fourni.
