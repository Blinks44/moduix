Utilisez `Avatar`, `AvatarFallback` et `AvatarImage` ensemble. Gardez `AvatarFallback` dans l’arbre
pour qu’Ark UI puisse basculer entre le contenu de remplacement et l’image lorsque l’état de chargement change.

React, Solid et Vue partagent les mêmes noms de valeurs à plat. Importez `Avatar` comme racine et chaque
partie supplémentaire directement, par exemple `AvatarImage` et `AvatarFallback`. Ces mêmes noms
fonctionnent avec les paquets npm et les sources du registre shadcn.

## Exemples

### Tailles et avatar sans image

La propriété `size` de moduix permet de choisir l’une des tailles courantes des tokens de design pour l’un ou
l’autre composant racine. Un avatar avec uniquement un contenu de remplacement convient lorsqu’aucune source
d’image n’est disponible.

<Example name="avatar/sizes-and-fallback-only" />

### Contenu de remplacement personnalisé

Le contenu de remplacement peut être une icône ou un autre élément compact qui représente l’utilisateur. Ajoutez
un nom accessible si ce contenu apporte une information absente du texte voisin.

<Example name="avatar/custom-fallback" />

### Image personnalisée

Utilisez `useAvatarContext()` depuis moduix avec React ou Solid lorsqu’un composant d’image ou un
moteur de rendu personnalisé doit s’intégrer au cycle de chargement géré par Ark. En Vue, le slot de
`AvatarContext` fournit l’état de l’image.

<Example name="avatar/custom-image" />

### Indicateur de statut

La racine de l’avatar ne rogne pas ses enfants : un élément positionné en absolu dans `Avatar` peut
signaler une présence ou un badge. Donnez-lui un nom accessible si le statut n’est pas indiqué dans le
texte voisin.

<Example name="avatar/status" />

### Groupe

Placez les avatars dans `AvatarGroup` pour les empiler avec un chevauchement. Chaque avatar après le
premier passe sous son voisin, et chaque racine d’avatar reçoit un anneau de la couleur du fond de
page. Rendez vous-même l’avatar `+N` lorsque la liste est tronquée.

<Example name="avatar/group" />

### Avatar interactif

Utilisez `asChild` lorsque l’avatar est lui-même un élément interactif, par exemple un lien. Le composant
n’ajoute alors pas son nœud DOM racine par défaut, tout en conservant l’état Ark, le comportement du contenu
de remplacement et la composition explicite des parties.

<Example name="avatar/interactive" />

### Événements

Utilisez `onStatusChange(details)` lorsque l’interface voisine doit réagir au résultat du chargement de l’image.

<Example name="avatar/events" />

### Root Provider

Créez l’état avec `useAvatar` depuis moduix lorsque des contrôles situés en dehors de l’avatar doivent
interagir avec lui. Transmettez-le à `AvatarRootProvider` à la place de `Avatar`. Voir [Partager l’état hors de l’arbre](/docs/composition-patterns#root-provider).

## Composition

Gardez `AvatarFallback` et `AvatarImage` sous la même racine afin qu’Ark UI puisse gérer leur visibilité. Lorsqu’une autre partie de l’application possède l’état, créez-le avec `useAvatar()` du framework concerné et transmettez-le directement à `AvatarRootProvider` ; ne rendez pas une seconde racine pour le même store. React reçoit le store comme un objet, tandis que Solid fournit un accesseur réactif. En Vue, transmettez directement le résultat de `useAvatar()` à `AvatarRootProvider`. React et Solid peuvent utiliser `useAvatarContext()` pour un rendu d’image personnalisé et conserver les états masqué et visible de `getImageProps()`. En Vue, le slot de `AvatarContext` expose le même état. Utilisez `asChild` avec un seul enfant sémantique lorsqu’un autre élément doit porter le nœud DOM racine.

En Solid, attribuez la ref à l’élément créé dans la fonction de rendu `asChild` : une ref posée sur `Avatar` lui-même n’est pas transmise par cette composition. En Vue, les refs pointent vers l’instance du composant ; utilisez `$el` pour accéder à l’élément rendu.

## Styles

Utilisez `className` dans React ou `class` dans Solid et Vue, ainsi que les variables CSS de moduix, pour modifier l’apparence. Utilisez les attributs de
données fournis par Ark lorsque le style dépend de l’état de l’image.

### Points d’accroche CSS

| Partie | `data-slot` |
| --- | --- |
| `Avatar` | `avatar-root` |
| `AvatarRootProvider` | `avatar-root-provider` |
| `AvatarImage` | `avatar-image` |
| `AvatarFallback` | `avatar-fallback` |
| `AvatarGroup` | `avatar-group` |

- Attributs d’anatomie Ark : `data-scope="avatar"` et
  `data-part="root" | "image" | "fallback"`.
- État de l’image géré par Ark : `data-state="visible" | "hidden"` sur `AvatarImage` et
  `AvatarFallback`.
- Attribut de taille de moduix : `data-size="xs" | "sm" | "md" | "lg" | "xl"` sur
  `Avatar` et `AvatarRootProvider`, `md` par défaut.

## Référence de l’API

| --- | --- | --- |
| `size` | `'xs' \| 'sm' \| 'md' \| 'lg' \| 'xl'` | `'md'` |
| `onStatusChange` | `(details: StatusChangeDetails) => void` | — |
| `asChild` | `boolean` | `false` |
