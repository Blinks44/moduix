## Cycle de vie de base

`Presence` est un utilitaire Ark UI pour le contenu dont l’application contrôle le cycle de vie. Il rend un
sous-arbre tant que `present` vaut `true` et ajoute `data-state="open"` ou `data-state="closed"` pour cibler les
états en CSS.

Utilisez `unmountOnExit` lorsque le sous-arbre doit être retiré après son animation de sortie. Sans cette prop, la
racine reste montée et Ark la masque avec l’attribut `hidden` lorsque `present` devient `false`.

## Monter à la demande

Ajoutez `lazyMount` lorsque le contenu ne doit pas être monté avant sa première apparition. Combinez-le avec
`unmountOnExit` lorsque le contenu doit être absent avant la première ouverture comme après sa fermeture.

`lazyMount` retarde uniquement le premier montage. Il ne retire pas le sous-arbre après la fermeture à lui seul.

## Animations de sortie et callbacks

Lorsque `unmountOnExit` est activé, Ark laisse la racine montée pendant l’exécution de l’animation CSS de sortie.
Ciblez `data-state="open"` et `data-state="closed"` dans la même feuille de style que la classe de la racine.
Utilisez `onEnterComplete` et `onExitComplete` lorsque l’interface environnante ou le suivi analytique doit réagir à la fin
d’une animation.

Définissez `skipAnimationOnMount` lorsque la première apparition doit être immédiate. Définissez `immediate` lorsque
le changement de `present` doit s’appliquer immédiatement au lieu d’attendre la frame suivante.

## Options qui influencent le rendu

| Option | Comportement |
| --- | --- |
| `present` | Contrôle la présence du sous-arbre. |
| `lazyMount` | Retarde le premier montage jusqu’à ce que `present` vaille `true`. |
| `unmountOnExit` | Retire la racine après la fin de l’animation à l’état fermé. |
| `onEnterComplete` / `onExitComplete` | S’exécutent après la fin de l’animation d’entrée ou de sortie. |
| `skipAnimationOnMount` | Désactive l’animation initiale de présence. |
| `immediate` | Applique immédiatement un changement de `present`, sans attendre la frame suivante. |
| `hideMode` | React uniquement. `display-none` utilise `hidden`, tandis que `activity` suspend les effets via `Activity` de React 19. |

Les options de cycle de vie communes ont le même sens en React, Solid, Vue et Svelte. Avec Vue, utilisez
`@enter-complete` et `@exit-complete` pour les événements de cycle de vie. Ark Solid, Vue et Svelte n’exposent pas
`hideMode` : un contenu monté mais absent est masqué avec l’attribut `hidden`.

## Composition et accessibilité

Utilisez `Presence` lorsque l’application contrôle le cycle de vie d’un panneau, d’une notification, d’une carte ou
d’un autre sous-arbre. L’utilitaire n’ajoute ni gestion du focus, ni fermeture, ni positionnement, ni sémantique de
dialogue. Pour Dialog, Drawer, Menu, Popover, Tooltip, Tour et les autres racines interactives, utilisez leurs propres
options de présence afin de préserver leur modèle d’interaction.

Par défaut, `Presence` rend un `<div>` avec `data-scope="presence"` et `data-part="root"`. Utilisez `asChild` lorsqu’un
élément existant doit recevoir ces props sans ajouter de conteneur. L’enfant React doit accepter la ref transmise,
`hidden`, `data-*` et la classe. Solid utilise la forme avec fonction de rendu :
`asChild={(props) => <article {...props()} />}`. Vue utilise `<Presence as-child><article>…</article></Presence>`. Svelte utilise un snippet `asChild` : `{#snippet asChild(props)}<article {...props()}>…</article>{/snippet}`.
Dans chaque adaptateur, conservez une seule racine sémantique ainsi
que son nom et son contenu accessibles. Ne remplacez pas le comportement de `hidden` par la seule opacité lorsque le
contenu inactif doit sortir de l’arbre d’accessibilité.
