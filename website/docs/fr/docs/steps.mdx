## Exemple de base

Utilisez `Steps` avec `count`, une `Steps.List` contenant un `Steps.Item` pour chaque étape, des panneaux
`Steps.Content` associés aux mêmes index et les boutons de navigation précédent et suivant intégrés. Les index
commencent à zéro. Avec `count={3}`, utilisez donc les index `0`, `1` et `2`. Lorsque la valeur de l’étape atteint
`count`, `Steps.CompletedContent` s’affiche.

L’export `Steps` par défaut est le composant racine. Utilisez `Steps.Root` lorsque vous souhaitez préciser le nom
de cette partie.

## Anatomie

```text
Steps
├─ Steps.Progress (facultatif)
├─ Steps.List
│  └─ Steps.Item[index]
│     ├─ Steps.Trigger
│     │  └─ Steps.Indicator
│     └─ Steps.Separator
├─ Steps.Content[index]
├─ Steps.CompletedContent
├─ Steps.PrevTrigger
└─ Steps.NextTrigger

Steps.RootProvider
└─ même arbre de parties connecté à l’état créé par Steps.useSteps()
```

| Partie                              | Rôle                                                                                   |
| ----------------------------------- | -------------------------------------------------------------------------------------- |
| `Steps` / `Steps.Root`              | Gère l’état des étapes, l’orientation, la navigation, la validation et les identifiants. |
| `Steps.RootProvider`                | Connecte les parties à l’état créé avec `Steps.useSteps()`.                            |
| `Steps.Progress`                    | Barre visuelle de progression facultative, alimentée par la variable racine Ark `--percent`. |
| `Steps.List`                        | Liste d’onglets contenant les déclencheurs des étapes.                                 |
| `Steps.Item`                        | Élément d’étape dont l’index obligatoire commence à zéro.                              |
| `Steps.Trigger`                     | Déclencheur d’onglet d’une étape ; accepte `asChild` pour un élément sémantique personnalisé. |
| `Steps.Indicator`                   | Repère visuel de l’étape. Affiche par défaut `index + 1` ou une coche une fois l’étape terminée. |
| `Steps.Separator`                   | Liaison décorative entre les étapes.                                                  |
| `Steps.Content`                     | Panneau de contenu d’une étape, associé par son `index`.                              |
| `Steps.CompletedContent`            | Panneau affiché lorsque la valeur courante de l’étape est égale à `count`.             |
| `Steps.PrevTrigger` / `NextTrigger` | Boutons reliés aux actions Ark intégrées pour passer à l’étape précédente ou suivante. |

Utilisez `Steps.useSteps()` avec `Steps.RootProvider` lorsque l’état doit être créé en dehors de l’arbre des
parties `Steps`. `useStepsContext`, `useStepsItemContext`, `Steps.Context` et `Steps.ItemContext` sont également
exportés depuis `@moduix/react` comme API de bas niveau conformes à Ark.

## Composition

### Composition recommandée

`Steps` gère la machine d’état. Définissez à la racine `count`, `defaultStep`, `step`, `onStepChange(details)`,
`onStepComplete`, `linear`, `isStepValid`, `isStepSkippable`, `onStepInvalid(details)`, `orientation` et `ids`.
Utilisez des valeurs `index` commençant à zéro et correspondantes pour chaque élément et panneau. Les étapes actives
utilisent les index de `0` à `count - 1` ; la valeur `count` représente la fin du parcours.

Utilisez `Steps.RootProvider` avec `Steps.useSteps()` lorsque des contrôles situés en dehors de l’arbre `Steps`
doivent accéder au même état. L’objet renvoyé expose `value`, `setStep`, `goToNextStep`, `goToPrevStep`, `resetStep`,
`percent` et `getItemState` pour lire l’état des éléments. Ne rendez pas `Steps.Root` et `Steps.RootProvider` pour un
même état.

### Quand créer une composition personnalisée

Utilisez `asChild` sur `Steps.Trigger`, `Steps.PrevTrigger` ou `Steps.NextTrigger` lorsque le contrôle doit être
rendu sous forme d’ancre, de lien de routeur ou de bouton de votre design system. Conservez exactement un enfant
sémantique afin qu’Ark puisse lui transmettre ses attributs ARIA ainsi que ses comportements liés au clavier et au
focus.

`Steps.Indicator` comporte un ajout propre à moduix : sans contenu enfant, il affiche `index + 1` pour les étapes
incomplètes ou courantes et l’icône de coche partagée pour les étapes terminées. Fournissez un contenu pour contrôler
entièrement le repère.

### Propriétés par défaut

| Propriété     | Par défaut   | Remarques                                                                                 |
| ------------- | ------------ | ------------------------------------------------------------------------------------------ |
| `orientation` | `horizontal` | Orientation du composant racine. Utilisez `vertical` pour une navigation d’étapes empilée. |
| `linear`     | `false`     | Définissez `true` pour imposer un parcours dans l’ordre au lieu d’autoriser les sauts entre étapes. |
| `count`      | `1`        | Nombre total d’étapes. La valeur `count` représente l’état terminé.                       |
| `defaultStep` | `0`        | Valeur initiale en mode non contrôlé. Passez `count` pour afficher directement la fin du parcours. |

### Comportement

- `step`, `defaultStep`, `details.step` et `Steps.Item index` sont des valeurs Ark indexées à partir de zéro. Les étapes actives utilisent les index de `0` à `count - 1` ; `count` indique que le parcours est terminé.
- Dans un parcours linéaire, `onStepInvalid(details)` indique le `details.step` bloqué, l’action `details.action` (`'next'` ou `'set'`) et l’éventuel `details.targetStep`.
- `Steps.Content` utilise `role="tabpanel"` et est masqué lorsque son étape n’est pas courante. `Steps.CompletedContent` s’affiche lorsque la valeur courante est égale à `count`.
- `Steps.List` utilise `role="tablist"` avec `aria-orientation` ; les déclencheurs utilisent `role="tab"` et `aria-controls`.
- `Steps.PrevTrigger` et `Steps.NextTrigger` sont désactivés lorsqu’Ark indique qu’il n’existe pas d’étape précédente ou suivante.
- `ids` permet de fournir des identifiants stables à la racine, à la liste, aux déclencheurs et au contenu lorsque la composition environnante en a besoin.
- `Steps.Progress` est une barre visuelle pilotée par la variable Ark `--percent`. Ajoutez un texte visible ou destiné aux lecteurs d’écran si le pourcentage doit être annoncé.

### Points d’accroche CSS

Les points d’accroche publics utiles sont les suivants :

- `className` sur `Steps`, `Steps.RootProvider`, `Steps.List`, `Steps.Item`, `Steps.Trigger`, `Steps.Indicator`, `Steps.Separator`, `Steps.Content`, `Steps.CompletedContent`, `Steps.PrevTrigger`, `Steps.NextTrigger` et `Steps.Progress`
- `data-slot="steps-root"`, `steps-root-provider`, `steps-list`, `steps-item`, `steps-trigger`, `steps-indicator`, `steps-separator`, `steps-content`, `steps-completed-content`, `steps-prev-trigger`, `steps-next-trigger` et `steps-progress`
- `data-scope="steps"` d’Ark et les valeurs `data-part` de chaque partie primitive
- `data-orientation="horizontal" | "vertical"` sur les parties root, list, item, trigger, content et separator
- `data-current`, `data-complete` et `data-incomplete` sur les indicateurs d’état des parties indicator, separator et trigger
- `data-state="open" | "closed"` sur les déclencheurs et les panneaux de contenu
- `data-complete` sur `Steps.Progress`
- la variable Ark `--percent` sur la racine, utilisée par `Steps.Progress`
