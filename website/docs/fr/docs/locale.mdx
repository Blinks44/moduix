`LocaleProvider` fournit une locale et sa direction d’écriture à un sous-arbre. Les formateurs Ark et le contenu
localisé utilisent ce contexte.

## Importation

Importez l’utilitaire depuis le paquet moduix correspondant, qui réexporte le provider de locale
d’Ark UI :

<Tabs
  groupId="framework"
  values={[
    { label: 'React', value: 'react' },
    { label: 'Solid', value: 'solid' },
    { label: 'Vue', value: 'vue' },
    { label: 'Svelte', value: 'svelte' },
  ]}
  className="docs-tabs"
>
  <Tab value="react">

```tsx
import { LocaleProvider, useLocaleContext } from '@moduix/react/locale';
```

  </Tab>
  <Tab value="solid">

```tsx
import { LocaleProvider, useLocaleContext } from '@moduix/solid/locale';
```

  </Tab>
  <Tab value="vue">

```ts
import { LocaleProvider, useLocaleContext } from '@moduix/vue/locale';
```

  </Tab>
  <Tab value="svelte">

```ts
import { LocaleProvider, useLocaleContext } from '@moduix/svelte/locale';
```

  </Tab>
</Tabs>

`Format.Number`, `Format.Time` et les autres utilitaires `Format` restent importés depuis `@ark-ui/react` ou
`@ark-ui/solid`, `@ark-ui/vue` ou `@ark-ui/svelte`.

## Définir une locale

Entourez la partie de l’interface qui partage une locale. Les formateurs et les composants qui tiennent compte de la
locale lisent alors le même contexte.

<Example name="locale/basic" />

`LocaleProvider` accepte une chaîne de locale au format BCP 47, par exemple `fr-FR`. Sans provider, Ark utilise `en-US`
et `ltr`.

## Lire le contexte de locale

`useLocaleContext` renvoie `locale` et `dir` depuis le provider le plus proche. Utilisez ces valeurs lorsque votre propre
structure doit reprendre la même langue et la même direction que les composants qui tiennent compte de la locale. React
lit directement les valeurs ; Solid les lit via un accessor. Vue renvoie une ref calculée : utilisez
`.value` dans le code setup ; le template la déballe automatiquement. Svelte renvoie un getter : appelez `locale()` pour lire `locale` et `dir`.

## Définir la langue et la direction du document

`LocaleProvider` déduit la direction `dir` d’Ark à partir de la locale, mais ne modifie pas les attributs natifs `lang`
et `dir` du document. Si toute l’application utilise une même direction, définissez les deux attributs sur la racine du
document :

  <Tabs
    groupId="framework"
    values={[
      { label: 'React', value: 'react' },
      { label: 'Solid', value: 'solid' },
      { label: 'Vue', value: 'vue' },
      { label: 'Svelte', value: 'svelte' },
    ]}
    className="docs-tabs"
  >
    <Tab value="react">

```tsx pure file="../../../src/components/examples/locale/document.tsx"
```

    </Tab>
    <Tab value="solid">

<CodeBlockRuntime lang="tsx" code={localeSolidDocument} />

    </Tab>
  <Tab value="vue">

<CodeBlockRuntime lang="vue" code={localeVueDocument} />

    </Tab>
  <Tab value="svelte">

<CodeBlockRuntime lang="svelte" code={localeSvelteDocument} />

    </Tab>
  </Tabs>
</div>

Pour une zone RTL dans une application LTR, définissez `lang` et la valeur correspondante de `dir` sur la racine de
cette zone, comme dans l’exemple de contexte. Si les utilisateurs peuvent passer d’une locale LTR à une locale RTL sans
recharger la page, mettez à jour les attributs du document en même temps que `locale`. Consultez [De droite à gauche
(RTL)](/docs/rtl) pour les portails, les propriétés CSS logiques et les icônes directionnelles.

## Traduire les libellés par défaut

`LocaleProvider` ne traduit pas le texte. Les contrôles composés d’une seule icône et quelques repères, comme les
boutons de fermeture et d’effacement, `Spinner` et `Breadcrumbs`, reçoivent par défaut des noms accessibles en anglais
tels que `Close` ou `Clear search`. Dans une interface dans une autre langue, remplacez-les de l’une des deux façons
suivantes.

Passez `aria-label` ou `aria-labelledby` là où le composant est utilisé. Un nom fourni remplace toujours la valeur par
défaut :

```tsx
<DialogCloseIcon aria-label="Fermer" />
<CommandPaletteSearch aria-label="Rechercher des commandes" />
```

Avec les sources installées par shadcn, les valeurs par défaut se trouvent dans `@/lib/moduix/a11yLabels.ts`.
Traduisez les valeurs de ce fichier pour changer tous les libellés d’un coup :

```ts
export const a11yLabels = {
  closeDialog: 'Fermer',
  clearSearch: 'Effacer la recherche',
  // ...
} as const;
```
