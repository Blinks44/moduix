# Mot de passe oublié

Utilisez cette composition comme point de départ pour un écran de récupération du mot de passe. Elle associe
`Card`, `Field`, `Input` et `Button`. Le navigateur vérifie que l’adresse e-mail est renseignée et
correctement formatée avant d’appeler `onSubmit`. La composition n’appelle aucun service de réinitialisation
et n’affiche pas les états de réussite ou d’erreur : ajoutez cette logique dans votre application.

L’aperçu interactif utilise le paquet React. Les onglets de code présentent des implémentations natives pour React, Solid et Vue avec les mêmes styles.

Dans l’aperçu, le gestionnaire `onSubmit` se contente d’appeler `event.preventDefault()` : aucun e-mail
réel n’est envoyé. Installez le bloc, puis reliez-le à votre API
de réinitialisation.

## Ajouter la composition à une route

Importez `ForgotPassword` depuis le bloc installé. Affichez-le sur la route où l’utilisateur demande
la réinitialisation du mot de passe.
Le navigateur applique les contraintes natives avant d’appeler `onSubmit`. Récupérez l’adresse dans
`FormData` et envoyez-la à votre API de réinitialisation :

## Avant la mise en production

Le code copié reste volontairement minimal. Ajoutez le comportement et l’interface d’erreur nécessaires
à votre application :

- Pendant la requête, désactivez le bouton d’envoi pour éviter les doublons. Utilisez `loading` ou `disabled`
  sur `Button`.
- Après une requête réussie, affichez la même confirmation neutre pour toutes les adresses, par exemple
  `Si un compte correspond à cette adresse, nous enverrons un lien de réinitialisation.` Ne révélez pas si
  le compte existe.
- Si le serveur limite les requêtes, indiquez à l’utilisateur quand réessayer. Faites appliquer la limite
  réelle par le serveur.
- En cas d’échec, conservez l’adresse, affichez une erreur générale avec `role="alert"` et permettez une
  nouvelle tentative.
- Dans le code copié, remplacez le lien `/sign-in` par la route de votre application.
